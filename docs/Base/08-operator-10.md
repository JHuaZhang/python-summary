# 海象运算符

## 1. 介绍

### 1.1 什么是海象运算符

海象运算符（walrus operator）是 Python 3.8 引入的一个语法，写作 `:=`，因为它长得像海象的眼睛和长牙。它的正式名称是**赋值表达式**（assignment expression），作用是在一个表达式内部给变量赋值，同时把这个值作为整个表达式的结果返回。

核心区别在于：普通的 `=` 是**赋值语句**，写完一行赋值后，这行代码本身"没有值"；而 `:=` 是**赋值表达式**，赋完值之后整个表达式本身也有值，可以继续参与运算。换句话说，`:=` 把"赋值"和"取值"压缩成了一步。

它的价值在于消除代码中的**重复**——当某个值需要先算出来存变量、紧接着又在条件或循环中用到时，传统写法要把"算"和"用"分成两行，而 `:=` 让你一行搞定。这在 `while` 循环读数据、`if` 条件判断、列表推导式过滤等场景中特别有用。

### 1.2 在运算符体系中的定位

海象运算符属于"赋值与表达式"这一家族。它和普通赋值 `=` 做的事相似——都是把值绑定到变量名上——但定位不同：`=` 是语句级操作，`:=` 是表达式级的操作。在运算符优先级体系中，`:=` 的优先级非常低，几乎垫底，使用时几乎都需要加括号。

本篇所属的"运算符和表达式"主题中，海象运算符担当的是"边赋值边取值"这一角色，它不参与数值计算，而是改变代码的组织方式。

### 1.3 最简示例

用一个最小例子感受 `:=` 的写法：

```python
# := 赋值的同时返回值，可以继续参与运算
m = (x := 20)
print(f"x = {x}, m = {m}")
```

运行结果：

```text
x = 20, m = 20
```

`x := 20` 先把 `20` 赋给 `x`，然后这个表达式本身的值也是 `20`，于是 `m` 也拿到了 `20`。一行代码完成了两件事：赋值给 `x`，再赋值给 `m`。下面逐个讲透它的语法、经典场景和最佳实践。

## 2. 核心内容

本章先讲赋值表达式与赋值语句的本质区别，再讲 `:=` 在五个经典场景中的用法，最后讲作用域规则和优先级。

### 2.1 赋值表达式与赋值语句的区别

要理解 `:=`，先要弄清"表达式"和"语句"在 Python 中的分界线。

**语句**（statement）是执行一个动作的指令，比如 `if`、`for`、`import`、`x = 5`。语句本身不产生值，它只"做事"。

**表达式**（expression）是能算出一个值的代码片段，比如 `1 + 2`、`len(x)`、`x > 3`。表达式算完会得到一个结果，可以继续被使用。

普通赋值 `=` 是语句——`x = 5` 做了"把 5 绑定到 x"这件事，但 `x = 5` 整体没有值，你不能写 `print(x = 5)`。而 `:=` 是表达式——`(x := 5)` 做了同样的事，但它本身也是 `5`，可以直接用：

```python
# 普通赋值语句：x = 5 整体没有值，不能放进 print
# print(x = 5)   # TypeError: 'x' is an invalid keyword argument

# 赋值表达式：x := 5 整体的值就是 5，可以放进 print
print((x := 5))
print(f"赋值后 x = {x}")
```

运行结果：

```text
5
赋值后 x = 5
```

这条区别决定了 `:=` 能出现在所有"需要值"的位置：函数参数、列表元素、条件判断、推导式内部……而 `=` 只能独占一行。来看几个 `:=` 能去而 `=` 去不了的地方：

```python
# 1. 直接作为函数参数
print((y := 42))

# 2. 放在 if 条件里
if (n := len([1, 2, 3])) > 2:
    print(f"长度 {n}，超过 2")

# 3. 放在 while 条件里
import io
f = io.StringIO("a\nb\nc\n")
while (line := f.readline()):
    print(f"读到: {line.strip()!r}")
```

运行结果：

```text
42
长度 3，超过 2
读到: 'a'
读到: 'b'
读到: 'c'
```

**关键点**

- `=` 是语句，`:=` 是表达式。这是它们最根本的区别。
- `:=` 出现的所有场景，核心需求都是"我要赋一个值，同时还要立刻用到这个值"——如果只是单纯赋值、不需要在赋值的同时使用，用 `=` 就好。
- `:=` 在列表推导式、`if` 条件、`while` 条件、函数参数等"只能写表达式、不能写语句"的位置才有不可替代的价值。

### 2.2 while 循环中的经典场景

`while` 循环逐个读取数据是 `:=` 最经典的用武之地。这里有一个反复出现的模式："先取一个值，循环里用它，循环末尾再取下一个值"。传统写法要把"取值"写两遍，而 `:=` 只需写一次。

**传统写法的痛点**

以逐行读文件为例，`readline()` 读到文件末尾返回空字符串，靠它判断是否结束：

```python
import io

f = io.StringIO("第一行\n第二行\n第三行\n")

# 传统写法：readline 要写两次
line = f.readline()          # 第一次：循环外取值
while line:
    print(f"  读取: {line.strip()!r}")
    line = f.readline()      # 第二次：循环内再取一次
f.close()
```

运行结果：

```text
  读取: '第一行'
  读取: '第二行'
  读取: '第三行'
```

问题很明显：`f.readline()` 出现在两个地方，代码重复，而且容易忘记在循环体内写第二次取值，导致死循环。

**海象运算符写法**

```python
import io

f = io.StringIO("第一行\n第二行\n第三行\n")

while (line := f.readline()):
    print(f"  读取: {line.strip()!r}")
f.close()
```

运行结果：

```text
  读取: '第一行'
  读取: '第二行'
  读取: '第三行'
```

`readline()` 只写一次，赋值和判断合在 `while` 那一行完成。循环体只负责处理 `line`，不再需要操心"取下一个值"。

**分块读取**

不只是逐行，分块读取也适用同样的模式。模拟一个数据流，每次取一块，取空了就结束：

```python
data_stream = list(range(25))   # 0~24 共 25 个数字
chunk_size = 7
idx = 0
while (chunk := data_stream[idx:idx + chunk_size]):
    print(f"  读取块 @{idx}: {chunk}")
    idx += chunk_size
```

运行结果：

```text
  读取块 @0: [0, 1, 2, 3, 4, 5, 6]
  读取块 @7: [7, 8, 9, 10, 11, 12, 13]
  读取块 @14: [14, 15, 16, 17, 18, 19, 20]
  读取块 @21: [21, 22, 23, 24]
```

切片在 `while` 条件中算出结果，`:=` 把它赋给 `chunk`，空列表自然为 `False`，循环自动终止。

**搭配 next + sentinel 模式**

还有一种模式是从迭代器逐个取值，用 `None` 或某个 sentinel 值表示结束：

```python
queue = iter(["任务A", "任务B", "任务C", None])
while (item := next(queue, None)) is not None:
    print(f"  处理: {item}")
print("  遇到 None，结束")
```

运行结果：

```text
  处理: 任务A
  处理: 任务B
  处理: 任务C
  遇到 None，结束
```

`next(queue, None)` 取出元素，`:=` 存到 `item`，同时 `is not None` 判断是否到达终点。一行完成"取值 + 存值 + 判断"。

**关键点**

- `while` 循环的场景中，`:=` 的价值是消除"取值写两遍"的重复——循环外的初始取值和循环内的续取值合并成一行。
- 这个模式适用于所有"反复取值、取空即停"的场景：`readline`、`recv`、分页查询、队列消费等。
- 注意 `while (x := ...) ` 的括号不能省——`:=` 优先级很低，不加括号会导致解析歧义。

### 2.3 条件判断中赋值

`if` 条件判断是 `:=` 的另一个高频场景。模式是："调用一个函数拿到结果，先判断它是否有效，有效则继续使用"——传统写法要把"调用"和"使用"分两行，而 `:=` 让你一行完成。

**基本模式**

```python
def get_value(key):
    store = {"a": 1, "b": 2, "c": 3}
    return store.get(key)

# 传统写法：先取值存变量，再判空
val = get_value("b")
if val is not None:
    print(f"  查到值: {val}")
else:
    print("  没查到")

# 海象写法：赋值和判断一步到位
if (val := get_value("b")) is not None:
    print(f"  查到值: {val}")
else:
    print("  没查到")
```

运行结果：

```text
  查到值: 2
  查到值: 2
```

两种写法效果一样，但海象写法把 `val` 的赋值和 `is not None` 判断合在 `if` 那一行，`val` 的作用范围也更明确——它只在 `if-else` 块内有意义。

**避免重复调用**

当条件需要多分支判断时，传统写法每个分支都要重新调一次函数，而 `:=` 只需调一次：

```python
def expensive_lookup(name):
    print(f"  [调用 expensive_lookup({name!r})]")
    return {"Alice": 90, "Bob": 60}.get(name)

# 传统写法：调用了两次
if expensive_lookup("Alice") is not None:
    score = expensive_lookup("Alice")  # 第二次调用
    print(f"  Alice 成绩: {score}")

# 海象写法：只调用一次
if (score := expensive_lookup("Alice")) is not None:
    print(f"  Alice 成绩: {score}")
```

运行结果：

```text
  [调用 expensive_lookup('Alice')]
  [调用 expensive_lookup('Alice')]
  Alice 成绩: 90
  [调用 expensive_lookup('Alice')]
  Alice 成绩: 90
```

传统写法里 `[调用]` 打印了两次，海象写法只打印一次。如果 `expensive_lookup` 做的是数据库查询或网络请求，省掉一次调用的收益非常实在。

**if-elif 链**

在多分支判断中，`:=` 的优势更明显。查询一次，结果在各个 `elif` 中复用：

```python
def get_status(code):
    return {200: "OK", 404: "Not Found", 500: "Server Error"}.get(code)

code = 404

# 传统写法：每个分支都要重新查
if get_status(code) == "OK":
    print("  请求成功")
elif get_status(code) == "Not Found":
    print("  资源不存在")
elif get_status(code) == "Server Error":
    print("  服务器错误")
else:
    print("  未知状态")

# 海象写法：查一次就够了
if (status := get_status(code)) == "OK":
    print("  请求成功")
elif status == "Not Found":
    print("  资源不存在")
elif status == "Server Error":
    print("  服务器错误")
else:
    print("  未知状态")
```

运行结果：

```text
  资源不存在
  资源不存在
```

**关键点**

- `if (x := func())` 是最常见的模式：调用一次，存值 + 判断一行完成，`if` 块内直接用 `x`。
- 在 `if-elif` 链中，`:=` 在第一个 `if` 里赋值，后续 `elif` 直接用变量，避免每个分支都重新调用。
- 括号包住 `(x := func())` 是标准写法，既明确了优先级，也让"这是一次赋值加判断"一目了然。

### 2.4 列表推导式中避免重复计算

列表推导式是 `:=` 最能发挥价值的场景之一。当你需要"先对元素做一个变换，再根据变换结果过滤，同时还要把变换后的值放进结果列表"时，传统写法要么重复计算，要么牺牲可读性。

**重复计算的痛点**

举个例子：从一组数字中筛选出"平方大于 50"的数，并返回它们的平方值。

```python
nums = [1, 5, 12, 3, 8, 15, 2, 7]

# 传统写法：n*n 算了两遍
result_old = [n * n for n in nums if n * n > 50]
print(f"  传统: {result_old}")

# 海象写法：算一次，复用结果
result_new = [square for n in nums if (square := n * n) > 50]
print(f"  海象: {result_new}")
```

运行结果：

```text
  传统: [144, 64, 225]
  海象: [144, 64, 225]
```

传统写法里 `n * n` 出现在 `if` 条件和结果表达式两处，每个元素平方计算了两遍。海象写法用 `(square := n * n)` 算一次，`if` 条件用它判断，结果列表也用它——计算量减半。

**搭配函数调用**

如果变换涉及函数调用，省掉的重复就更划算。比如过滤一组华氏温度，只要摄氏度大于 0 的，同时返回摄氏度值：

```python
def normalize(x):
    """模拟开销较大的归一化函数（华氏转摄氏）"""
    return (x - 32) * 5 / 9

temps_f = [32, 68, 100, 212, 14, -4]

# 传统写法：normalize 每个元素调两遍
hot_old = [normalize(t) for t in temps_f if normalize(t) > 0]
print(f"  传统: {[round(c, 1) for c in hot_old]}")

# 海象写法：只调一遍
hot_new = [c for t in temps_f if (c := normalize(t)) > 0]
print(f"  海象: {[round(c, 1) for c in hot_new]}")
```

运行结果：

```text
  传统: [20.0, 37.8, 100.0]
  海象: [20.0, 37.8, 100.0]
```

`normalize` 从调用两遍降为一遍。如果它内部有 IO 操作或复杂计算，这个优化效果显著。

**字符串清洗**

过滤一组原始字符串，去除空格后只留非空的：

```python
raw_strings = ["  hello  ", "", "  ", "world", "   foo   ", "  "]

# 传统写法：strip 调两遍
cleaned_old = [s.strip() for s in raw_strings if s.strip()]

# 海象写法：strip 调一次
cleaned_new = [stripped for s in raw_strings if (stripped := s.strip())]
print(f"  传统: {cleaned_old}")
print(f"  海象: {cleaned_new}")
```

运行结果：

```text
  传统: ['hello', 'world', 'foo']
  海象: ['hello', 'world', 'foo']
```

**字典推导式**

字典推导式同样适用。过滤一批单词中长度大于 5 的，同时以长度为值：

```python
words = ["apple", "banana", "cherry", "date", "elderberry"]
word_lens = {w: length for w in words if (length := len(w)) > 5}
print(f"  {word_lens}")
```

运行结果：

```text
  {'banana': 6, 'cherry': 6, 'elderberry': 10}
```

**关键点**

- 推导式中 `:=` 的核心价值是"计算一次，复用两处"——`if` 条件用一次，结果表达式再用一次。
- 这是 `:=` 在性能上收益最明确的场景：当变换涉及函数调用时，能把调用次数减半。
- 写法模式固定：`[value for x in iter if (value := transform(x)) 筛选条件]`，把 `:=` 放在 `if` 条件里，先赋值再判断。

### 2.5 配合正则与 any/all

`:=` 配合正则表达式和 `any`/`all` 函数也很自然，因为这类场景的共性是"匹配成功后要立刻使用匹配结果"。

**配合 re.match / re.search**

正则匹配后拿到 `match` 对象，传统写法要分两步——先匹配、再判断、再用。`:=` 把匹配和判断合为一步：

```python
import re

pattern = re.compile(r"(\d+)-(\w+)")
texts = ["123-hello", "abc-world", "456-python"]

for text in texts:
    if (m := pattern.match(text)):
        print(f"  {text!r} -> 编号={m.group(1)}, 名称={m.group(2)}")
    else:
        print(f"  {text!r} -> 不匹配")
```

运行结果：

```text
  '123-hello' -> 编号=123, 名称=hello
  'abc-world' -> 不匹配
  '456-python' -> 编号=456, 名称=python
```

`m := pattern.match(text)` 在 `if` 条件中执行匹配、把 `match` 对象存到 `m`，同时 `if` 判断 `m` 是否为 `None`（匹配失败时 `match` 返回 `None`）。进入 `if` 块后直接用 `m.group()` 提取捕获组，不需要在外面单独写一行 `m = pattern.match(text)`。

**配合 re.search 在文本中查找**

```python
import re

date_pattern = re.compile(r"(\d{4})-(\d{2})-(\d{2})")
logs = [
    "系统启动于 2024-01-15 08:00",
    "无日期信息",
    "最后更新：2024-06-30，由 admin 操作",
]

for log in logs:
    if (match := date_pattern.search(log)):
        year, month, day = match.group(1), match.group(2), match.group(3)
        print(f"  找到日期: {year}/{month}/{day}")
    else:
        print(f"  无日期")
```

运行结果：

```text
  找到日期: 2024/01/15
  无日期
  找到日期: 2024/06/30
```

**配合 any()：短路时拿到匹配项**

`any()` 遇到第一个 `True` 就短路返回。但传统写法里 `any` 只告诉你"有没有"，不告诉你"是哪个"——要拿到匹配项还得再遍历一次。`:=` 让 `any` 在短路的同时把匹配项存下来：

```python
files = ["readme.txt", "config.json", "main.py", "utils.py"]

# 传统写法：any 判断完，还要再找一次
if any(f.endswith(".py") for f in files):
    py_file = next(f for f in files if f.endswith(".py"))
    print(f"  找到: {py_file}")

# 海象写法：any 判断的同时就把匹配项存下来
if any((py_file := f).endswith(".py") for f in files):
    print(f"  找到: {py_file}")
```

运行结果：

```text
  找到: main.py
  找到: main.py
```

这里 `(py_file := f)` 把当前遍历的元素赋给 `py_file`，`any` 短路时 `py_file` 恰好就是触发 `True` 的那个元素。

**配合 all()：检查全部通过**

`all()` 遇到第一个 `False` 就短路，此时 `:=` 捕获的变量就是第一个不合格的值：

```python
scores = [85, 92, 78, 65, 88]
last = None
if all((last := s) >= 60 for s in scores):
    print(f"  全部及格！最后查看: {last}")
else:
    print(f"  有人不及格: {last}")

scores2 = [85, 92, 55, 65, 88]
last = None
if all((last := s) >= 60 for s in scores2):
    print(f"  全部及格！最后查看: {last}")
else:
    print(f"  有人不及格: {last}")
```

运行结果：

```text
  全部及格！最后查看: 88
  有人不及格: 55
```

第二个例子 `all` 在 `55` 处短路，`last` 正好是 `55`，直接就能定位到不合格的那一项。

**关键点**

- `if (m := pattern.match(text)):` 是正则配合 `:=` 的标准模式，消除"先匹配存变量、再判空、再用"的三步走。
- 配合 `any`/`all` 的价值在于短路时"顺便"拿到匹配项或第一个不合格项，省掉二次遍历。
- 注意 `(py_file := f).endswith(".py")` 这种写法——`:=` 先赋值，再做方法调用判断，一层套一层但逻辑清晰。

### 2.6 作用域与赋值目标

`:=` 赋值的变量，作用域规则和普通赋值 `=` 一致：属于当前所在的作用域。但有一个特殊点值得注意——在推导式内部用 `:=` 赋的值，在推导式结束后仍然可见。

**推导式中的作用域泄漏**

```python
nums = [10, 20, 30, 40, 50]
threshold = 25

passed = [v for v in nums if (kept := v) > threshold]
print(f"  通过的: {passed}")
print(f"  推导式结束后 kept = {kept}")
```

运行结果：

```text
  通过的: [30, 40, 50]
  推导式结束后 kept = 50
```

`kept` 在推导式外仍然可访问，它的值是**最后一个被遍历的元素**——不一定是最后一个通过筛选的。看一个更明显的例子：

```python
vals = [10, 60, 20, 70, 5]
threshold = 25

passed = [v for v in vals if (kept := v) > threshold]
print(f"  通过的: {passed}")
print(f"  推导式结束后 kept = {kept}")
```

运行结果：

```text
  通过的: [60, 70]
  推导式结束后 kept = 5
```

`kept` 是 `5`——最后一个被遍历的元素，不是最后通过的 `70`。这是因为 `:=` 在每次迭代时都会赋值，无论 `if` 条件是否满足。如果你想拿到"最后通过的值"，应该把 `:=` 放在结果表达式里而不是 `if` 条件里。

**函数内部的作用域**

```python
def process(data):
    if (count := len(data)) > 3:
        print(f"  数据较多: {count} 个")
    else:
        print(f"  数据较少: {count} 个")
    return count

process([1, 2, 3, 4, 5])
process([1, 2])
```

运行结果：

```text
  数据较多: 5 个
  数据较少: 2 个
```

`count` 是函数内部的局部变量，函数结束后不可访问，和普通局部变量行为一致。

**`:=` 不能赋值给属性或索引**

`:=` 的赋值目标只能是简单变量名（标识符），不能是属性 `obj.attr`、索引 `d[key]` 或切片 `lst[0:3]`：

```python
# 以下都是语法错误：
# (obj.x := 5)       # 不能赋值给属性
# (d["key"] := 5)    # 不能赋值给索引
# (lst[0] := 5)      # 不能赋值给切片

# 只能赋值给简单变量名
(x := 5)  # 正确
```

如果需要给属性或索引赋值的同时获得返回值，可以先 `:=` 给一个临时变量，再做普通的属性/索引赋值。

**关键点**

- `:=` 赋的变量和普通变量作用域规则相同，属于当前作用域。
- 推导式中的 `:=` 会在推导式外"泄漏"——变量在推导式结束后仍可见，值是最后一次迭代时赋的值（不一定通过筛选）。
- `:=` 只能赋值给简单变量名，不能赋值给属性、索引或切片。

### 2.7 运算符优先级与括号

`:=` 的优先级非常低——比比较运算、逻辑运算都低，只比 `lambda` 略高。这意味着它在表达式中几乎总是需要加括号。

**为什么需要括号**

看一个不加括号出错的例子：

```python
# 不加括号，Python 会把 a := 5 + 3 理解为 a := (5 + 3)
# 在某些上下文中不加括号直接是语法错误，比如 if 条件
# if a := 5 > 3:    # SyntaxError

# 正确写法：用括号明确"先赋值，再比较"
if (a := 5) > 3:
    print(f"  a = {a}，大于 3")
```

运行结果：

```text
  a = 5，大于 3
```

`(a := 5) > 3` 的含义是：先把 `5` 赋给 `a`，表达式的值是 `5`，然后 `5 > 3` 得到 `True`。如果不加括号，`a := 5 > 3` 会被理解为 `a := (5 > 3)`，即把 `True` 赋给 `a`——含义完全不同。

**常见需要加括号的位置**

```python
# 1. if 条件中
if (n := len([1, 2, 3])) > 2:
    pass

# 2. while 条件中
# while (line := f.readline()):

# 3. 推导式 if 条件中
# [x for x in items if (x := transform(x))]

# 4. 函数参数中（天然有括号，不需要额外加）
print((x := 42))

# 5. 与逻辑运算混用
if (y := get_value()) and y > 0:
    pass
```

记住一条简单规则：**凡是 `:=` 出现在更大的表达式中，就用括号把它包起来**。只有当 `:=` 独占一个位置（如 `while` 条件本身就是它）时，括号才可能省略，但加上也无害。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

| 场景 | 推荐写法 | 不推荐写法 | 原因 |
|------|---------|-----------|------|
| while 循环读数据 | `while (line := f.readline()):` | `line = f.readline()` 循环内再赋值 | 消除重复取值 |
| if 中判断后使用 | `if (val := func()) is not None:` | `val = func()` + `if val is not None:` | 赋值和判断合一步 |
| 推导式过滤+变换 | `[v for x in it if (v := f(x))]` | `[f(x) for x in it if f(x)]` | 避免重复计算 |
| 正则匹配后用结果 | `if (m := pat.match(s)):` | `m = pat.match(s)` + `if m:` | 减少一行代码 |
| any 短路拿匹配项 | `any((found := x) for x in it)` | any 后再遍历找 | 消除二次遍历 |
| 简单独立赋值 | `x = 5` | `(x := 5)` | 不需要返回值，用 `=` 更清晰 |
| 多变量同时赋值 | `x, y, z = 1, 2, 3` | `(x := 1) + (y := 2)` | 元组解包更可读 |
| 一行塞多逻辑 | 拆成多行 | `(a := 5) + (b := 3) + (c := a+b)` | 可读性差 |

### 3.2 什么时候不该用海象运算符

`:=` 不是越多用越好。以下场景应该坚持用普通写法：

**简单赋值**

```python
# 不推荐：简单赋值强行用 :=
# (y := 10)        # 语法错误！:= 不能在顶层语句裸用

# 推荐：用普通赋值
y = 10
```

`:=` 在顶层语句中不能裸用——它必须是表达式的一部分。简单的"赋一个值、存一个变量"用 `=` 就好。

**一行塞太多 :=**

```python
# 不推荐：读起来要逐个拆解
result = (a := 5) + (b := 3) + (c := a + b)

# 推荐：拆成多行
a = 5
b = 3
c = a + b
result = a + b + c
```

虽然能跑，但一行塞三个 `:=` 让读者要逐个拆解"谁赋给了谁、谁依赖谁"。拆成多行更清晰。

**逻辑非常简单时**

```python
# 不推荐：为了用 := 而用，逻辑本不需要在表达式中取值
if (flag := True):
    pass

# 推荐：直接写
flag = True
if flag:
    pass
```

只有当你真的需要"在表达式内部拿到赋值的值"时，`:=` 才有意义。否则就是为用而用，徒增阅读负担。

### 3.3 常见错误模式

**错误一：在 if 条件中不加括号**

```python
# 错误：不加括号会导致解析歧义
# if n := len(data) > 3:     # 等价于 n := (len(data) > 3)，n 变成布尔值

# 正确：加括号明确优先级
if (n := len(data)) > 3:
    print(f"  长度 {n}")
```

不加括号时 `:=` 的优先级比 `>` 低，`n := len(data) > 3` 会先算 `len(data) > 3` 得到 `True/False`，再把这个布尔值赋给 `n`——和你想要的完全不同。

**错误二：推导式中放在错误位置导致值不对**

```python
nums = [10, 60, 20, 70, 5]

# 想拿到"最后通过筛选的值"，但 := 放在 if 条件里拿到的是最后遍历的值
passed = [v for v in nums if (last := v) > 25]
print(f"  通过的: {passed}, last = {last}")   # last = 5（最后遍历的，不是最后通过的）
```

运行结果：

```text
  通过的: [60, 70], last = 5
```

如果要拿到"最后通过的值"，应该把 `:=` 放在结果表达式里：

```python
passed = [(last := v) for v in nums if v > 25]
print(f"  通过的: {passed}, last = {last}")   # last = 70（最后通过的）
```

运行结果：

```text
  通过的: [60, 70], last = 70
```

**错误三：赋值给属性或索引**

```python
# 以下都是 SyntaxError：
# (obj.attr := 5)       # 不能赋值给属性
# (d["key"] := 5)       # 不能赋值给索引

# 正确：先 := 给临时变量，再做属性/索引赋值
# (val := func())
# d["key"] = val
```

`:=` 的目标只能是简单变量名。需要给属性或索引赋值时，分两步走：先用 `:=` 拿到值，再用 `=` 赋给属性或索引。

**错误四：在 lambda 中用 :=**

```python
# lambda 中可以用 :=，但容易写出难以理解的代码
# f = lambda: (x := 10)
# f()
# print(x)  # x 泄漏到了 lambda 外部

# 更好的做法：lambda 应该是纯函数，不要有副作用
f = lambda: 10
x = f()
print(x)
```

运行结果：

```text
10
```

`:=` 在 `lambda` 中赋值的变量会泄漏到外部作用域，这通常不是你的意图。`lambda` 应该保持"无副作用"，如果需要赋值，改用 `def` 定义函数。

## 4. 原理：赋值表达式的求值机制

`:=` 看起来只是 `=` 的小变体，但它背后有两条机制值得讲清——它"为什么是表达式"和"作用域如何工作"决定了它能在哪些地方用、又有什么坑。

### 4.1 表达式而非语句：为什么 := 有返回值

Python 的语法明确区分**表达式**和**语句**。`=` 赋值是语句——`x = 5` 执行后，`x` 绑定了 `5`，但 `x = 5` 这个整体不是一个有值的表达式。而 `:=` 被设计成**表达式**——`(x := 5)` 执行后，`x` 绑定了 `5`，且 `(x := 5)` 本身的值也是 `5`。

这条设计决策来自 PEP 572（Python 3.8 引入）。它的动机正是解决"在表达式中需要赋值"的需求——比如推导式的 `if` 条件里想复用计算结果、`while` 条件里想存取到的值，这些位置只能放表达式，放不了语句。如果没有 `:=`，你只能在表达式外先用 `=` 赋值，再在表达式中引用变量，代价就是代码重复或可读性下降。

用例子直观感受" := 能去而 = 去不了"的边界：

```python
# := 能进 if 条件，因为它有返回值
if (n := len([1, 2, 3])) > 2:
    print(f"  长度 {n}")

# = 不能进 if 条件，因为它是语句没有返回值
# if (n = len([1, 2, 3])) > 2:   # SyntaxError
```

运行结果：

```text
  长度 3
```

### 4.2 作用域规则：与普通赋值一致

`:=` 赋值的变量，作用域规则和普通 `=` 完全一致——属于"词法作用域"中的当前作用域。也就是说，在函数内用 `:=` 赋的变量是局部的，在模块顶层用 `:=` 赋的变量是全局的。

唯一需要特别注意的是**推导式中的作用域泄漏**。Python 3 的推导式有自己的作用域，但 `:=` 赋的值会"泄漏"到推导式所在的外层作用域：

```python
nums = [1, 2, 3, 4, 5]
squares = [n * n for n in nums if (caught := n) > 2]
print(f"  squares = {squares}")
print(f"  推导式外 caught = {caught}")
```

运行结果：

```text
  squares = [9, 16, 25]
  推导式外 caught = 5
```

`caught` 在推导式外可访问，值是最后一次迭代赋的 `5`。这是 PEP 572 的设计行为——推导式内部的 `:=` 变量绑定会泄漏到外层。正常的推导式循环变量（如 `n`）在 Python 3 中不会泄漏，但 `:=` 赋的值会。

这个行为既是特性也是陷阱。好处是你可以在推导式后立刻使用 `caught`，不用再写一行赋值；坏处是你可能不经意间创建了一个外层变量，造成命名冲突或意外引用。理解了这条规则，就能正确预判推导式后哪些变量还活着。

### 4.3 优先级设计的取舍

`:=` 的优先级设计为"几乎最低"，只比逗号和 `lambda` 略高。这个设计是刻意的——如果 `:=` 优先级太高，`a := b + c` 就会被理解为 `(a := b) + c`，先赋值再运算，这几乎不是任何人想要的。把 `:=` 的优先级压低，`a := b + c` 理解为 `a := (b + c)`——先算右边整个表达式，再赋值——这才是直觉行为。

代价就是使用时几乎都要加括号：`if (n := len(x)) > 3` 中如果不加括号，`:=` 的低优先级会把 `> 3` 吃进去。加括号虽然多敲两个字符，但让"先赋值、再比较"的意图一目了然，这是合理的取舍。

| 设计选择 | 含义 | 好处 | 代价 |
|---------|------|------|------|
| `:=` 优先级极低 | 先算右边整个表达式再赋值 | `a := b + c` 符合直觉 | 混用运算符需加括号 |
| `:=` 是表达式 | 赋值的同时有返回值 | 能进 if/while/推导式 | 不能裸用于语句位置 |
| 推导式中可泄漏 | 变量在推导式外可见 | 推导式后能直接用 | 可能意外创建变量 |

## 5. 总结

本文围绕海象运算符（`:=`）展开，主要介绍了以下内容：

- 海象运算符 `:=` 是 Python 3.8 引入的赋值表达式，它赋值的同时返回所赋的值，本质是"表达式"而非"语句"
- 赋值表达式与赋值语句的核心区别：`:=` 有返回值能出现在表达式位置（if 条件、while 条件、推导式、函数参数），`=` 无返回值只能独占一行
- while 循环是 `:=` 最经典的场景，消除"取值写两遍"的重复，一行完成赋值和判断
- if 条件判断中用 `:=` 可以一步完成"调用 + 存值 + 判断"，在 if-elif 链中避免每个分支重复调用
- 列表推导式中用 `:=` 避免重复计算，`if` 条件算一次、结果列表复用一次，函数调用场景下性能收益明显
- 配合 `re.match`/`re.search` 消除"先匹配存变量、再判空、再使用"的三步走；配合 `any`/`all` 在短路时顺便拿到匹配项或第一个不合格项
- 作用域规则与普通赋值一致，但推导式中的 `:=` 变量会在推导式外"泄漏"——值是最后一次迭代赋的值，不一定通过筛选
- `:=` 只能赋值给简单变量名，不能赋值给属性、索引或切片
- 优先级极低，使用时几乎都需要加括号——`if (n := len(x)) > 3` 是标准写法
- 最佳实践：简单赋值用 `=` 更清晰，一行塞多个 `:=` 降低可读性，`:=` 的价值在于"赋值同时需要用到这个值"的场景
