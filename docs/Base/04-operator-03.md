## 1. 介绍

### 1.1 什么是赋值运算符

赋值运算符是 Python 中"把值绑定到名字"的操作符,核心是一个等号 `=`。当你写 `x = 10`、`total = 0`、`name = "alice"` 时,`=` 就是赋值运算符,它把右侧的值(或表达式的结果)绑定到左侧的名字上。除了最基本的 `=`,Python 还提供一组**增强赋值运算符**(augmented assignment),如 `+=`、`-=`、`*=`、`/=`、`//=`、`%=`、`**=` 等,它们是"运算后再赋值"的简写形式——`x += 1` 等价于 `x = x + 1`,把"x 加 1 再赋回 x"浓缩成一个运算符。

```python
x = 10              # 基本赋值:x 绑定到 10
x = x + 1           # x 加 1 再赋回:x 变 11
x += 1              # 增强赋值:等价于上一行,x 变 12
total = 0
total += 5          # 等价 total = total + 5 → 5
total *= 2          # 等价 total = total * 2 → 10
total //= 3         # 等价 total = total // 3 → 3
```

理解 Python 赋值,有一个必须先打破的 C/Java 直觉:**Python 的 `=` 是"绑定名字到对象",不是"把值拷进盒子"**。在 C 里 `int x = 10;` 是声明一个装 int 的盒子并放入 10,变量与内存块绑定;而 Python 里 `x = 10` 是创建一个 int 对象 10,把名字 `x` 这张"标签"贴到对象 10 上。`x` 本身不"装"任何东西,它只是对对象的**引用**。这套"名字 → 对象"的引用模型,是理解赋值与增强赋值一切行为的基础(详见《变量赋值机制》)。

这个引用模型直接决定了赋值运算符的两个关键特性:

- **赋值不是表达式,是语句**:Python 的 `x = 10` 没有返回值,不能写 `if (x = 10):` 或 `y = (x = 10)` 这样的"赋值当条件/值用"的 C 风格代码。这避免了 C 经典 bug `if (x = 5)`(本想 `==` 却写成 `=`,把 5 赋给 x 还判定为真)。
- **增强赋值对可变类型可能"就地修改"**:`+=` 对 `int`(`lst += [1]` 不可变)返回新对象并重新绑定,但对 `list`(`lst += [1]`)会**就地扩展**原列表——这是可变类型增强赋值最隐蔽的陷阱。

Python 赋值运算符与 C/Java 的主要差异集中在四处:

- **`=` 是语句不是表达式**:`y = (x = 10)` 非法,不能用赋值当值。C/Java 里赋值是表达式有返回值。
- **没有 `++`/`--` 自增自减运算符**:Python 用 `x += 1` 替代 C 的 `x++`。新手常误写 `x++` 报错。
- **增强赋值对可变类型可能就地改**:`lst += [1]` 改的是原列表,而 `lst = lst + [1]` 创建新列表——两者语义不同。C/Java 没有这种分裂(其值类型语义统一)。
- **多重赋值/解包赋值是语言特性**:`a, b = 1, 2`、`a, b = b, a`、`a, *rest = [1,2,3]` 一行完成多变量绑定与交换,这是 Python 相对 C/Java 的便利特性。

本篇要系统讲透 Python 赋值运算符的完整内容:基本赋值 `=`、11 个算术增强赋值、3 个位运算增强赋值、多重赋值与交换、序列解包赋值(含星号解包)、增强赋值对可变/不可变类型的差异(就地修改陷阱)、海象运算符 `:=`(赋值表达式)、增强赋值与普通赋值的性能差异,以及这些行为背后的实现原理。这是「运算符与表达式」大章节的第三篇,建立在《算术运算符》《除法与整除的区别》之上,与《变量赋值机制》互为补充——前者讲"赋值语句怎么写、有哪些运算符",后者讲"赋值背后名字与对象的引用关系"。

### 1.2 赋值运算符全表

下面这张表是本篇的总纲,后续每节逐一展开。先建立全局认知。

| 运算符 | 名称 | 等价形式 | 示例 | 说明 |
|--------|------|----------|------|------|
| `=` | 基本赋值 | `x = v` | `x = 10` | 把 v 绑定到 x |
| `+=` | 加法增强 | `x = x + v` | `x += 1` | 加后赋回(可变类型可能就地改) |
| `-=` | 减法增强 | `x = x - v` | `x -= 1` | 减后赋回 |
| `*=` | 乘法增强 | `x = x * v` | `x *= 2` | 乘后赋回(可变类型可能就地改) |

| `//=` | 整除增强 | `x = x // v` | `x //= 2` | 整除后赋回 |
| `%=` | 取余增强 | `x = x % v` | `x %= 3` | 取余后赋回 |
| `**=` | 乘方增强 | `x = x ** v` | `x **= 2` | 乘方后赋回 |
| `&=` | 位与增强 | `x = x & v` | `x &= 1` | 见《位运算符》 |
| `\|=` | 位或增强 | `x = x \| v` | `x \|= 1` | 见《位运算符》 |

核心认知:除 `=` 和 `:=` 外,所有增强赋值都遵循"`x OP= v` 等价于 `x = x OP v`"的形式——**先运算,再赋回**。但这个"等价"在可变类型上有重大例外(§2.6),是本篇最大陷阱。12 位运算增强赋值(`&= |= ^= <<= >>=`)的运算逻辑见《位运算符》,本篇只在涉及处点明,不展开位运算细节。

### 1.3 赋值语句的执行顺序与左值规则

理解赋值,要抓住"右侧先求值,再绑定到左侧"这条执行顺序——这是 Python 赋值(含增强赋值、多重赋值)的统一规则。

```python
# 右侧表达式先求值,得结果对象,再绑定到左侧名字
x = 3 + 5       # 先算 3+5 得 8,再把 8 绑定到 x
y = x * 2       # 先取 x 的值 8,算 8*2 得 16,绑定到 y
print(x, y)     # 8 16
```

赋值的左侧必须是**赋值目标(左值)**——一个能被绑定名字的位置。合法左值包括:简单名字(`x`)、带索引的可变对象(`lst[0]`)、带属性的(`obj.attr`)、解包目标(`a, b`)。**字面量和表达式不能作左值**:

```python
x = 10          # ✓ 名字作左值
lst[0] = 99     # ✓ 索引作左值(改列表元素)
obj.name = "a"  # ✓ 属性作左值(改对象属性)
a, b = 1, 2     # ✓ 解包目标作左值

# 10 = x        # ✗ 字面量不能作左值 → SyntaxError
# x + 1 = 5     # ✗ 表达式不能作左值 → SyntaxError: cannot assign to operator
# f() = 5       # ✗ 函数调用不能作左值(除非返回特殊对象)
```

左值规则的本质:赋值是把右侧结果"贴"到左侧某个能存放名字的位置。字面量(`10`)没有"名字槽位",表达式(`x+1`)是临时值没有持久的存储位置,所以都不能接收赋值。这条规则 C/Java 也类似,但 Python 额外支持解包目标作左值(`a, b = ...`),这是 C/Java 没有的便利。

理解"右侧先求值再绑定左侧"+"左值规则"这两条,就抓住了赋值语句的骨架。后续的多重赋值、交换、增强赋值都建立在这两条之上。

## 2. 核心内容

本章详解赋值运算符的完整用法,每节遵循"规则 → demo → 陷阱 → 场景"展开。重点是增强赋值对可变类型的就地修改陷阱、序列解包、海象运算符,因为它们最反直觉、最易在生产环境出问题。

### 2.1 基本赋值 `=`

基本赋值 `=` 把右侧值绑定到左侧名字。它是 Python 最频繁的操作,但有几个易被忽视的细节。

**基本用法**:

```python
x = 10              # 单变量赋值
name = "alice"      # 绑定到字符串
pi = 3.14159        # 绑定到 float
flag = True         # 绑定到 bool
x = "now string"    # 同一名字可重新绑定到不同类型对象(动态类型)
print(x)            # now string
```

**链式赋值**:`a = b = c = value` 把同一对象绑定到多个名字(不是分别拷贝):

```python
a = b = c = 0       # a、b、c 都绑定到同一个 int 对象 0
print(a, b, c)      # 0 0 0
# int 不可变,链式赋值安全;但可变对象链式赋值要警惕(共享同一对象)
a = b = []          # a、b 指向同一个列表!
a.append(1)
print(b)            # [1] —— b 也变了,因为是同一个列表
```

⚠️ **可变对象链式赋值陷阱**:`a = b = []` 让 `a`、`b` 指向**同一个列表对象**,改一个影响另一个。需要独立副本要用 `a = []; b = []` 或 `a = []; b = a.copy()`。这个陷阱根源于"赋值是贴引用不是拷贝",详见《变量赋值机制》。新手写 `rows = cols = []` 想初始化两个独立空列表,实际得到两个指向同一列表的名字,后续逻辑全乱。

**多重赋值(一行多变量)**:`a, b = 1, 2` 把右侧元组解包到左侧多个名字:

```python
a, b = 1, 2         # 等价 a=1; b=2,但一行完成
x, y, z = 10, 20, 30
print(a, b, x, y, z)   # 1 2 10 20 30
```

多重赋值本质是"元组解包",右侧 `1, 2` 是个元组,左侧 `a, b` 是解包目标。它比 `a=1; b=2` 更紧凑,且支持交换(§2.4)。要求左右元素数量匹配(或用星号解包,§2.5)。

**赋值是语句,无返回值**:

```python
# x = 10 是语句,不产生值
# y = (x = 10)      # SyntaxError!赋值不能当值用
# if (x = 10):       # SyntaxError!不能当条件(避免 C 的 if(x=5) bug)
```

`=` 语句化是 Python 有意设计:杜绝 C 的 `if (x = 5)`(本想 `==` 写成 `=`,把 5 赋 x 且判定为真)这类经典 bug。需要"赋值并使用值"的场景,用海象运算符 `:=`(§2.7)。

### 2.2 增强赋值 `+=`(重点)

`+=` 是最常用的增强赋值,等价于 `x = x + v`——把 x 加上 v 后再赋回 x。但它在**不可变类型**与**可变类型**上行为不同,这是本篇最大陷阱。

**不可变类型(int、str、tuple):返回新对象并重新绑定**

```python
x = 10
print(id(x))        # 地址 A
x += 5              # 等价 x = x + 5:int 不可变,创建新 int 15,x 重新绑定
print(id(x))        # 地址 B(不同!)—— x 指向新对象,原 10 对象不变
print(x)            # 15
```

`int` 不可变,`x += 5` 实际是 `x = x + 5`:`x + 5` 创建一个全新的 int 15,`x` 改指向它。这里 `id(x)` 前后不同,证明 x 绑定到了新对象。这与"`+=` 就地修改"无关——不可变类型根本没有就地修改,只能创建新对象。

**可变类型(list):就地修改原对象**

```python
lst = [1, 2, 3]
print(id(lst))      # 地址 C
lst += [4, 5]       # 这是陷阱!:list 的 += 就地 extend,不创建新对象
print(id(lst))      # 地址 C(相同!)—— 同一对象被原地扩展
print(lst)          # [1, 2, 3, 4, 5]
```

`list` 的 `+=` 触发的是 `list.__iadd__`,它**就地扩展**原列表(等价 `lst.extend([4,5])`),返回原列表自己。`id(lst)` 前后相同,证明是同一对象被改了,而非重新绑定到新对象。

⚠️ **核心陷阱:`lst += [x]` 与 `lst = lst + [x]` 行为不同**

```python
# 陷阱演示:函数内增强赋值可能改了外部列表
def add_one(lst):
    lst += [99]        # 就地修改!影响外部传入的列表

data = [1, 2]
add_one(data)
print(data)            # [1, 2, 99] —— 外部列表被改了!

# 对比:用 + 则不影响外部
def add_one_safe(lst):
    lst = lst + [99]   # 创建新列表,lst 重新绑定到新列表(局部),外部不变

data = [1, 2]
add_one_safe(data)
print(data)            # [1, 2] —— 外部列表不变
```

`lst += [99]` 就地修改了传入的列表,函数外的 `data` 被改(副作用);而 `lst = lst + [99]` 创建新列表并让局部 `lst` 指向它,外部 `data` 不受影响。两者语义截然不同——这在写"累加结果列表"的函数时极易出错:本想返回新结果却无意改了输入。

这条差异的根因(详见 §4.2):`+=` 对可变类型调用 `__iadd__`(就地改,返回原对象),对不可变类型回退到 `__add__`(创建新对象);而 `lst = lst + [x]` 永远调用 `__add__`(创建新对象)。`+=` 的"就地优化"对可变类型是真实副作用,不是简写糖。

**`+=` 用于 str 累加(性能差)**:

```python
s = ""
for word in ["a", "b", "c"]:
    s += word         # 每次创建新 str(CPython 有优化,但仍不如 join)
print(s)              # "abc"
# 推荐:大量拼接用 join
s = "".join(["a", "b", "c"])   # 更高效
```

str 不可变,`+=` 每次创建新字符串。CPython 对 `s += word` 做了"原地重用"优化(引用计数为 1 时复用缓冲),所以循环拼接 str 实际不那么慢,但官方仍推荐 `join`(语义清晰、无优化依赖、保证高效)。详见《字符串拼接性能对比》。

### 2.3 其他算术增强赋值 `-=` `*=` `/=` `//=` `%=` `**=`

其余算术增强赋值的规则与 `+=` 一致:等价 `x = x OP v`,对不可变类型创建新对象重新绑定,对可变类型可能就地改(只有 `*=` 对 list 有就地行为)。

**`-=` 减后赋回**:

```python
x = 10
x -= 3              # x = 10 - 3 = 7
total = 100
total -= 5          # 95
```

**`*=` 乘后赋回**(list 的 `*=` 会就地重复扩展,与 `+=` 同理):

```python
x = 3
x *= 4              # x = 3 * 4 = 12
lst = [0]
lst *= 3            # 就地重复:[0] → [0,0,0](list 的 *= 是就地 __imul__)
print(lst, id(lst) is lst)  # [0, 0, 0](仍是原对象,就地扩展)

# 陷阱:嵌套可变对象的 *= 同样共享内部引用
rows = [[]] * 3     # 三个子列表是同一个!([] * 3 重复引用)
rows[0].append(1)
print(rows)         # [[1], [1], [1]] —— 全被改
```

⚠️ `[[]] * 3` 与 `[[]] *= 3` 的嵌套引用陷阱:重复的是**同一个内层列表的引用**,改一个全变。要独立副本用 `[[] for _ in range(3)]`。这是 `*`/`*=` 在嵌套可变对象上的经典坑,根因仍是赋值贴引用,详见《变量赋值机制》。

**`/=` 真除后赋回(类型会变!)**:

```python
x = 10
x /= 2              # x = 10 / 2 = 5.0 —— 注意!类型从 int 变 float
print(x, type(x))   # 5.0 <class 'float'>
# 即使整除,/ 也返回 float,所以 /= 后 x 变 float
```

⚠️ **`/=` 把 int 变 float**:即便 `10 /= 2` 数学上整除,因为 `/` 永远返回 float(详见《除法与整除的区别》),`x /= 2` 后 `x` 类型从 `int` 变 `float`。如果后续逻辑依赖 `x` 是 int(如做索引、`isinstance(x, int)`),会出问题。要保留整数用 `//=`。

**`//=` 整除后赋回**(全 int 保留 int):

```python
x = 17
x //= 5             # x = 17 // 5 = 3 —— 全 int,//= 保留 int
print(x, type(x))   # 3 <class 'int'>
x = 17.0
x //= 5             # 有 float,//= 返回 float
print(x, type(x))   # 3.0 <class 'float'>
```

`//=` 的返回类型跟随操作数(与 `//` 一致):全 int 保留 int,有 float 变 float。需要保留整数类型用 `//=` 而非 `/=`。

**`%=` 取余后赋回**:

```python
x = 17
x %= 5              # x = 17 % 5 = 2
print(x)            # 2
# 匿名化场景:把值限制在 [0, mod) 范围
index = (index + 1) % size   # 环形索引推进,配合 %=
```

**`**=` 乘方后赋回**(负指数会变 float):

```python
x = 2
x **= 10            # x = 2 ** 10 = 1024
print(x)            # 1024
x = 4
x **= 0.5           # x = 4 ** 0.5 = 2.0 —— float 指数,变 float
print(x, type(x))   # 2.0 <class 'float'>
x = 2
x **= -1            # 负指数=x = 2 ** -1 = 0.5 —— 变 float
```

`**=` 的类型规则与 `**` 一致:int 的非负整数指数保留 int,负指数或 float 指数变 float。详见《算术运算符》§2.7。

**位运算增强赋值 `&= |= ^= <<= >>=`:逻辑与对应位运算一致,见《位运算符》。此处只列示例**:

```python
flags = 0b1010
flags |= 0b0010     # 位或:置位 → 0b1010 | 0b0010 = 0b1010 (已置)
print(bin(flags))   # 0b1010
flags &= 0b1110     # 位与:清位
print(bin(flags))   # 0b1010
n = 1
n <<= 3             # 左移3位:n = 1 << 3 = 8
print(n)            # 8
```

位运算增强赋值常用于"标志位管理"——`flags |= MASK` 置位、`flags &= ~MASK` 清位、`flags & MASK` 测位。详见《位运算符》。

### 2.4 多重赋值与变量交换(重点)

Python 的多重赋值最漂亮的用法是**一行交换两个变量**,这是 C/Java 做不到的便利(C 需要临时变量或位运算技巧)。

**变量交换**:

```python
a, b = 1, 2
print(a, b)         # 1 2
a, b = b, a         # 一行交换!a 和 b 的值互换
print(a, b)         # 2 1
```

`a, b = b, a` 交换的原理:右侧 `b, a` 先求值成一个元组 `(2, 1)`,再解包赋给左侧 `a, b`,于是 `a=2, b=1`。整个过程原子性完成——右侧先求值,再统一赋给左侧,不需要临时变量,也不会出现"先把 a 给 b,a 已被覆盖"的问题。

⚠️ **不要用临时变量手动交换,容易出错**:

```python
# 不推荐:手动交换,易因顺序错而覆盖
a, b = 1, 2
temp = a
a = b
b = temp
print(a, b)         # 2 1(正确,但啰嗦)

# 错误写法:顺序错则值丢失
# a = b      # 此时 a 已被 b 覆盖,a 原值丢失
# b = a      # b 得到的是新的 a(即原 b),交换失败

# 推荐:Python 风格直接 a, b = b, a
a, b = b, a
```

**三变量交换与轮转**:

```python
a, b, c = 1, 2, 3
a, b, c = c, a, b   # 轮转:c→a, a→b, b→c
print(a, b, c)      # 3 1 2
# 反向轮转
a, b, c = b, c, a
print(a, b, c)      # 1 2 3
```

多重赋值天然支持任意数量变量的轮转,右侧元组按顺序解包到左侧。这比 C 的三临时变量轮转简洁得多。

**条件赋值 / 解包交换的实战**:

```python
# 翻转字典的键值(值需可哈希)
d = {"a": 1, "b": 2}
flipped = {v: k for k, v in d.items()}   # 多重赋值在推导式里
print(flipped)      # {1: 'a', 2: 'b'}

# 冒泡排序中交换相邻元素
arr = [3, 1, 2]
for i in range(len(arr) - 1):
    if arr[i] > arr[i + 1]:
        arr[i], arr[i + 1] = arr[i + 1], arr[i]   # 一行交换
print(arr)          # [1, 2, 3]
```

冒泡排序里 `arr[i], arr[i+1] = arr[i+1], arr[i]` 一行交换数组相邻元素,是 Python 多重赋值的经典应用,比 C 的临时变量交换可读得多。

### 2.5 序列解包赋值与星号解包(重点)

序列解包(sequence unpacking)把一个序列的元素"拆开"分别赋给多个变量,是 Python 处理序列数据的利器。星号解包(`*`)还能"收取剩余元素"。

**基本解包**:变量数 = 元素数

```python
a, b, c = [1, 2, 3]          # 列表解包
print(a, b, c)                # 1 2 3
x, y = (10, 20)               # 元组解包
print(x, y)                   # 10 20
name, age = "alice", 30       # 等价元组解包
# 任何可迭代对象都能解包
first, second = "ab"          # 字符串解包
print(first, second)          # a b
```

解包不限于元组,任何可迭代对象(列表、字符串、range、生成器等)都能解包。要求左侧变量数与右侧元素数**严格匹配**,否则报错:

```python
# a, b = [1, 2, 3]            # ValueError: too many values to unpack
# a, b, c = [1, 2]            # ValueError: not enough values to unpack
```

**星号解包 `*`**:收取剩余元素成列表

```python
first, *rest = [1, 2, 3, 4, 5]
print(first, rest)            # 1 [2, 3, 4, 5] —— rest 收剩余成 list

*init, last = [1, 2, 3, 4, 5]
print(init, last)             # [1, 2, 3, 4] 5 —— 星号在首,收前面

first, *middle, last = [1, 2, 3, 4, 5]
print(first, middle, last)    # 1 [2, 3, 4] 5 —— 星号在中间
```

星号变量(`*rest`)会把"剩余所有元素"收集成一个**列表**(注意,无论原序列是元组还是 range,收集结果都是 list)。一个赋值语句中最多一个星号变量,且可放任意位置。

⚠️ **星号解包的边界:剩余为空也得列表**

```python
first, *rest = [1]            # rest 收 0 个元素
print(first, rest)            # 1 [] —— rest 是空列表,不是报错

# 但没有非星号变量匹配会报错
# *all = [1, 2, 3]            # SyntaxError —— 星号不能单独使用(3.0 之前禁止)
# Python 3.0+ 允许 *all 单独解包进列表
*all_items = [1, 2, 3]        # 实际不行:SyntaxError(target 必须有非星号部分,或加括号)
```

正确理解:星号解包要求左侧至少有一个"普通变量"配合(或整个就是个 `*` 目标用于强制列表化,但语法上 `*x = ...` 不被支持,要 `*x, = ...` 带尾逗号)。

```python
*x, = [1, 2, 3]               # 带尾逗号,合法:x 收全部成 [1,2,3]
print(x)                       # [1, 2, 3]
```

`*x, = iterable` 是"把可迭代对象强制转成列表"的技巧(`list(iterable)` 的等价写法),利用尾逗号让左侧成为合法的星号目标。

**嵌套解包**:解包支持嵌套结构

```python
# 解包嵌套序列
(a, b), c = (1, 2), 3
print(a, b, c)                # 1 2 3

# 解包带星号的嵌套
point = (1, (2, 3, 4), 5)
x, (y, *z), w = point
print(x, y, z, w)             # 1 2 [3, 4] 5
```

嵌套解包按结构"形状"拆解,把嵌套序列的元素逐层赋给同形的左侧模式。这在处理结构化数据(JSON 树、坐标、配置元组)时非常方便,等价于多次解包的浓缩。

**解包的实战应用**:

```python
# 返回多值的函数
def min_max(items):
    return min(items), max(items)   # 返回元组
lo, hi = min_max([3, 1, 4, 1, 5])  # 解包接收
print(lo, hi)                  # 1 5

# 忽略某些值用 _ 或 *_
_, _, third = (1, 2, 3)        # 下划线作"丢弃"变量
print(third)                   # 3
first, *_ = [10, 20, 30]       # 只要第一个,其余丢弃到 *_
print(first)                   # 10
```

用 `_` 或 `*_` 作"丢弃变量"是 Python 惯例:`_` 表示"这个值我不关心"。函数返回多值(实际返回元组)配合解包接收,是 Python 替代 C/Java "多输出参数"的优雅方式。

### 2.6 增强赋值与普通"运算+赋值"的差异(重点)

这是本篇的核心陷阱,需要彻底厘清:`x += y` 在可变类型上**不等价**于 `x = x + y`。两者的差异源于"就地修改 vs 创建新对象"。

**不可变类型:两者完全等价**

```python
# int(不可变)—— += 与 = + 行为一致
x = 10
x += 5                     # x = x + 5,创建新 int 15
y = 10
y = y + 5                  # 同样创建新 int 15
print(x, y)                # 15 15 —— 完全等价
```

不可变类型无法就地改,`+=` 回退到 `__add__`,等价 `x = x + y`。两者无差别。

**可变类型:两者行为不同**

```python
lst1 = [1, 2]
print(id(lst1))
lst1 += [3]                # __iadd__:就地扩展,同一对象
print(id(lst1))            # 相同!原对象被改

lst2 = [1, 2]
print(id(lst2))
lst2 = lst2 + [3]          # __add__:创建新列表,重新绑定
print(id(lst2))            # 不同!lst2 指向新对象
```

`lst += [3]` 触发 `list.__iadd__`,就地扩展原列表(`id` 不变);`lst = lst + [3]` 触发 `list.__add__`,创建新列表再绑定(`id` 变)。**对可变类型,`+=` 是就地修改,`x = x + y` 是创建新对象**——这是核心差异。

**差异导致的副作用**:

```python
# 就地修改:影响所有引用该对象的变量
shared = [1, 2]
alias = shared            # alias 和 shared 指向同一列表
shared += [3]             # 就地改!alias 也看到
print(alias)              # [1, 2, 3] —— alias 被波及

# 创建新对象:不影响其他引用
shared2 = [1, 2]
alias2 = shared2
shared2 = shared2 + [3]   # 创建新列表,shared2 重新绑定,alias2 不变
print(alias2)             # [1, 2] —— alias2 仍是原列表
```

`shared += [3]` 就地改后,所有指向该列表的名字(`alias`)都看到改动;`shared2 = shared2 + [3]` 重新绑定后,`alias2` 仍指向旧列表不受影响。这种差异在"共享可变对象"场景(默认参数、缓存、多变量引用)会引发隐蔽 bug。

**性能差异:`+=` 对可变类型更高效**

```python
import time
lst = list(range(100000))

# += 就地扩展:O(k),直接把元素加到尾部
t1 = time.perf_counter()
lst += [999999]
# 循环里反复 += 也高效(就地,不拷贝整个列表)

# = + 每次创建新列表:O(n),要拷贝整个旧列表
t2 = time.perf_counter()
lst = lst + [999999]      # 拷贝整个 lst 再加,慢
```

`lst += [x]` 就地扩展,只需把 `x` 追加到尾部,O(k);`lst = lst + [x]` 要创建全新列表、拷贝所有旧元素,O(n)。循环内累加列表时,`+=` 远快于 `= +`(后者每次拷贝整个列表,变成 O(n²))。所以有意识地用 `+=` 对可变类型不仅语义不同,**性能也优**。

**选型总结**:

| 场景 | 推荐 | 原因 |
|------|------|------|
| 累加可变列表(就地) | `lst += [x]` 或 `lst.append(x)` | 就地高效,但注意副作用 |
| 需保留原列表不变 | `lst = lst + [x]` 或 `lst.copy()` 后 `+=` | 创建新对象,原列表不变 |
| 不可变类型累加 | `x += y`(等价 `x = x + y`) | 无差别,`+=` 更简洁 |
| 循环内构建大列表 | `append` + 最后处理,或列表推导 | 避免 `= +` 的 O(n²) |

理解这条差异,就理解了"`+=` 对可变类型不是纯简写糖,而是带副作用的就地操作"。需要无副作用时显式用 `x = x + y` 或先拷贝。

### 2.7 海象运算符 `:=`(赋值表达式,重点)

海象运算符(walrus operator)`:=` 是 Python 3.8(Python 3.8 introduces)引入的**赋值表达式**(assignment expression),它让"赋值"成为有返回值的表达式——`name := value` 把 value 赋给 name,**同时返回 value**。这是对"`=` 只是语句无返回值"规则的补充,专为"赋值并立即使用"的场景设计。

**基本用法:赋值并返回值**

```python
# := 赋值同时返回值,可用于表达式上下文
n = (x := 10)          # x 赋 10,:= 返回 10,n 也得 10
print(x, n)            # 10 10

# 对比:普通 = 是语句,不能这样
# n = (x = 10)         # SyntaxError(= 无返回值)
```

`(x := 10)` 先把 10 赋给 x,整个表达式求值为 10,于是 `n` 也得 10。这是 `:=` 与 `=` 的根本区别——前者是表达式有值,后者是语句无值。

**经典场景一:在 while 条件里赋值(避免重复调用)**

```python
# 传统:重复调用 input/函数
while True:
    chunk = read_chunk()
    if not chunk:
        break
    process(chunk)

# 海象:条件里赋值,避免重复
while (chunk := read_chunk()):
    process(chunk)      # chunk 在循环体里可用
```

`(chunk := read_chunk())` 在 while 条件里赋值并测试,`chunk` 在循环体内可直接用,省去了"先赋值再判断"的重复。这是海象最常见的场景——"读取-判断-处理"模式。

**经典场景二:列表推导式里复用计算结果**

```python
# 传统:重复调用 len(data)
results = [transform(x) for x in data if len(x) > 5]
# transform 里若用到 len(x) 又算一次,或在条件、值里重复算

# 海象:在推导式里赋值并复用
results = [y for x in data if (y := transform(x)) is not None]
# y 赋值后在条件、值里都能用,transform 只算一次
```

推导式里 `(y := transform(x))` 把变换结果赋给 y,条件判断和最终取值都用 y,`transform` 只调用一次。这在"变换-过滤-收集"链里既省计算又清晰。

**经典场景三:if 条件里赋值**

```python
# 传统:先赋值再判断,两行
n = len(data)
if n > 10:
    print(f"数据量 {n} 较大")

# 海象:一行
if (n := len(data)) > 10:
    print(f"数据量 {n} 较大")   # n 在 if 块内可用
```

`(n := len(data)) > 10` 在 if 条件里赋值并比较,`n` 在 if 块内可复用。比"先赋值再判断"紧凑。

⚠️ **海象的语法限制:必须加括号**

```python
# 错误:海象在复杂条件下不加括号会歧义
# if n := len(data) > 10:       # 实际解析为 n := (len(data) > 10),n 变 bool!
#     print(n)                   # n 是 True/False,不是长度!

# 正确:加括号明确赋值范围
if (n := len(data)) > 10:
    print(n)                     # n 是长度
```

`if n := len(data) > 10` 会被解析为 `n := (len(data) > 10)`——`n` 得到的是比较结果 `True/False`,不是长度!所以海象在条件、函数参数等复杂上下文里**必须用括号包裹** `(n := len(data))`,消除歧义。这是海象最易踩的语法坑。

⚠️ **海象不能用于某些语句形式的赋值目标**

```python
# 海象左侧只能是简单名字,不能是属性、索引、解包
# obj.attr := 10        # SyntaxError —— 不能给属性赋值
# lst[0] := 10          # SyntaxError —— 不能给索引赋值
# a, b := 1, 2          # SyntaxError —— 不能解包(只能单个名字)
# x := 10               # SyntaxError —— 也不能当顶层语句(:= 只能用于表达式上下文)

# 合法:海象必须用在表达式上下文(括号内、条件内等),左值是单个名字
n = (x := 10)            # ✓ 括号表达式内,x 是单个名字
print(x, n)              # 10 10
```

海象的左值只能是**单个名字**,不支持属性、索引、解包目标。这是为限制海象的"表达式赋值"能力,避免它取代 `=` 语句造成混乱。需要复杂左值用普通 `=` 语句。

**海象的适用判断**:用海象的判据是"是否避免了重复计算/重复写法,且让代码更清晰"。若用了海象反而难读,就别用。海象是优化工具,不是必须。详见 PEP 572。

### 2.8 综合示例:赋值运算符实战

下面这个片段集中演示赋值运算符的典型用法与易错点,阅读时对照每段行为:

```python
# 1. 基本赋值与类型动态
print("=== 基本赋值 ===")
x = 10
print(f"x = {x} ({type(x).__name__})")
x = "ten"                      # 同名重新绑定到不同类型
print(f"x = {x} ({type(x).__name__})")

# 2. 链式与多重赋值
print("=== 链式/多重 ===")
a = b = c = 5                  # 链式:同一 int 对象(不可变,安全)
print(a, b, c)
x, y, z = 10, 20, 30           # 多重
print(x, y, z)

# 3. 变量交换
print("=== 交换 ===")
a, b = 1, 2
a, b = b, a                    # 一行交换
print(a, b)                    # 2 1
a, b, c = 1, 2, 3
a, b, c = c, a, b              # 轮转
print(a, b, c)                 # 3 1 2

# 4. 增强赋值(不可变类型)
print("=== 增强-int ===")
n = 10
n += 5                         # 15
n *= 2                         # 30
n //= 7                        # 4
n **= 2                        # 16
n %= 5                         # 1
print(n)

# 5. /= 与 //= 的类型差异
print("=== 类型变化 ===")
m = 10
m /= 2                         # 5.0 —— 变 float!
print(f"/= 后: {m} ({type(m).__name__})")
k = 10
k //= 2                        # 5 —— 保留 int
print(f"//= 后: {k} ({type(k).__name__})")

# 6. 增强赋值对 list:就地修改陷阱
print("=== list 增强陷阱 ===")
def add_inplace(lst):
    lst += [99]                # 就地改!影响外部
def add_new(lst):
    lst = lst + [99]           # 创建新列表,外部不变

data = [1, 2]
add_inplace(data)
print(f"inplace 后外部: {data}")   # [1, 2, 99]
data = [1, 2]
add_new(data)
print(f"new 后外部: {data}")       # [1, 2]

# 7. 星号解包
print("=== 星号解包 ===")
first, *rest = [1, 2, 3, 4, 5]
print(first, rest)             # 1 [2, 3, 4, 5]
*init, last = range(5)
print(init, last)              # [0, 1, 2, 3] 4
x, (y, *z), w = (1, (2, 3, 4), 5)  # 嵌套解包
print(x, y, z, w)             # 1 2 [3, 4] 5

# 8. 海象运算符
print("=== 海象 ===")
if (n := len([1, 2, 3, 4])) > 2:
    print(f"长度 {n} 较大")     # 长度 4 较大
# 推导式复用
data = ["a", "bb", "ccc", "dddd"]
long = [s for x in data if (s := len(x)) > 2]
print(long)                    # [3, 4] (用长度)

# 9. 没有自增 ++/--
print("=== 无 ++/-- ===")
i = 0
i += 1                         # Python 用 += 1,不是 i++
print(i)                       # 1
```

跑一遍这段示例,对照输出:动态类型绑定、链式/多重赋值、变量交换与轮转、不可变类型增强赋值、`/=` vs `//=` 的类型变化、list `+=` 就地修改陷阱(影响外部)、星号与嵌套解包、海象在条件与推导式中的应用、Python 无 `++`——赋值运算符的完整图景就清晰了。核心结论:**`=` 是绑定语句无返回值;增强赋值对可变类型就地改(陷阱)、对不可变类型等价 `x=x OP v`;多重赋值与解包是 Python 特性;海象 `:=` 补足"赋值并使用"场景;没有 `++`/`--`**。

## 3. 最佳实践

### 3.1 用 `a, b = b, a` 交换变量,别用临时变量

```python
# 推荐:Python 风格
a, b = b, a
# 排序中交换相邻
arr[i], arr[i + 1] = arr[i + 1], arr[i]

# 不推荐:临时变量啰嗦易错
temp = a
a = b
b = temp
```

Python 多重赋值一行完成交换,原子性(右侧先求值再赋左侧)、无需临时变量、可读性高。C/Java 迁来的临时变量写法在 Python 里是反模式。任意数量变量轮转同理 `a, b, c = c, a, b`。

### 3.2 累加可变列表用 `+=` 或 `append`,注意副作用

```python
# 推荐:就地高效
lst += [item]           # 或更直接
lst.append(item)        # 单个元素 append 更直接

# 不推荐:= + 每次拷贝整个列表,O(n²)
lst = lst + [item]

# 需保留原列表:先拷贝
new = old.copy()
new += [item]           # 只改 new,old 不变
```

循环内累加列表,`+=` 就地扩展 O(k),`= +` 每次拷贝 O(n) 累计 O(n²)。但 `+=` 就地改会影响所有引用该列表的变量(副作用);需要保留原列表先 `.copy()` 再 `+=`,或用 `= +`。单个元素直接 `append` 比 `+= [item]` 更清晰高效。

### 3.3 函数内别用 `lst += [...]` 意外改外部传入列表

```python
# 危险:就地修改,影响调用方
def process(lst):
    lst += [result]         # 改了外部 lst!调用方可能不知情

# 推荐:明确意图
def process(lst):
    return lst + [result]   # 返回新列表,不改输入(无副作用,函数式风格)
# 或确实要就地改,用 append 且文档说明
def process_inplace(lst):
    lst.append(result)      # 就地改,函数名/文档标明 inplace
```

函数内 `lst += [...]` 就地改了传入列表,调用方不易察觉,易引入难追踪的副作用。除非函数明确是"就地修改"语义(如 `list.sort`),否则应返回新结果不改输入(`lst + [result]`),遵循无副作用原则。这是函数设计的可维护性红线。

### 3.4 要保留整数类型用 `//=`,别用 `/=`

```python
# 推荐:要整数用 //=
count = 10
count //= 3                # 3,保留 int

# 危险:/= 会变 float
count = 10
count /= 3                 # 3.333... float!后续若做索引或 int 判断会出问题
```

`/=` 因 `/` 永远返回 float,会把 int 变 float(详见《除法与整除的区别》)。需要保留整数类型(计数、索引、位运算)用 `//=`;确实要小数用 `/=`。这条类型变化是隐式的,易被忽略。

### 3.5 可变对象做默认参数的陷阱,与增强赋值叠加

```python
# 危险:可变默认参数在调用间共享
def add_to(item, lst=[]):   # [] 只创建一次,所有调用共享!
    lst += [item]           # 就地改,污染默认列表
    return lst
print(add_to(1))            # [1]
print(add_to(2))            # [1, 2] —— 不是 [2]!默认列表被污染

# 推荐:用 None 作默认,函数内新建
def add_to(item, lst=None):
    if lst is None:
        lst = []
    lst = lst + [item]      # 或 append 后返回,避免改默认
    return lst
```

可变对象做默认参数是 Python 经典陷阱,与增强赋值就地修改叠加更危险:`lst += [item]` 改了共享的默认 `[]`,导致多次调用间状态泄漏。默认值用 `None` 哨兵,函数内新建列表。详见《变量赋值机制》《函数核心机制》。

### 3.6 海象只在"避免重复且更清晰"时用,条件里必加括号

```python
# 推荐:避免重复调用,清晰
while (line := file.readline()):
    process(line)            # line 在循环体可用
if (n := len(data)) > threshold:
    use(n)                   # n 在 if 块可用

# 不推荐:为用而用,反而难读(嵌套多个海象)
# if (x := compute()) and (y := other()) and x > y:
#     do_something(x, y)

# 必须加括号:否则 n := len() > 5 被解析错
if (n := len(data)) > 5:    # ✓ n 是长度
# if n := len(data) > 5:    # ✗ n 变成 bool!
    use(n)
```

海象用于"赋值并立即使用同一值"且能减少重复计算/重复写法时才用。复杂条件里嵌套多个海象会损害可读性,宁可分步写。海象在条件、函数参数等上下文必须用括号 `(name := expr)` 包裹,消除与比较运算符的歧义。

### 3.7 解包时变量数要匹配,用 `*` 收剩余或 `_` 丢不要的

```python
# 推荐:数量匹配,或用星号/下划线
a, b, c = [1, 2, 3]         # 匹配
first, *rest = items        # 只要首,其余收 rest
_, value = pair             # 丢弃第一个

# 错误:数量不匹配直接报错
# a, b = [1, 2, 3]          # ValueError: too many values
# a, b, c = [1, 2]          # ValueError: not enough values
```

解包要求变量数等于元素数,否则 ValueError。要"取部分"用星号 `*rest` 收剩余、`_` 作丢弃变量(惯例表示"不关心")。函数返回多值时配合解包,比用索引 `result[0]`、`result[1]` 清晰得多。

### 3.8 链式赋值 `a = b = []` 共享同一对象,慎用于可变类型

```python
# 危险:a、b 是同一个列表
a = b = []
a.append(1)
print(b)                    # [1] —— b 也变

# 推荐:分别创建,独立
a = []
b = []
# 或
a, b = [], []               # 多重赋值,创建两个独立列表
```

`a = b = []` 让两个名字指向同一列表对象,改一个影响另一个。需要独立列表分别创建(`a = []; b = []` 或 `a, b = [], []`)。对不可变类型(`a = b = 0`)链式赋值安全(改不了原对象)。判断标准:对象可不可变——不可变链式安全,可变链式共享有坑。

### 3.9 没有 `++`/`--`,用 `+= 1` / `-= 1`

```python
# Python 正确写法
i = 0
i += 1              # 自增(不是 i++)
i -= 1              # 自减(不是 i--)

# 错误:Python 没有 ++/-- 运算符
# i++               # SyntaxError
# ++i               # 不报错但无效:被解析为 +(+i),即正正得正,i 不变!
```

Python 故意没有 C 的 `++`/`--`(它们在 C 里既有"值"又有"副作用",与 Python"语句/表达式分明"的哲学冲突)。自增自减用 `+= 1`/`-= 1`。注意 `++i` 在 Python 不报错——它被解析为两次正号 `+(+i)`,值不变,是无效操作,别误以为自增。

### 3.10 大量字符串拼接用 `join`,别循环 `+=`

```python
# 推荐:join 一次拼接
parts = ["a", "b", "c"]
s = "".join(parts)          # 高效,语义清晰

# 不推荐:循环 += (虽 CPython 有优化,但不保证)
s = ""
for p in parts:
    s += p                  # 每次创建新 str
```

str 不可变,`+=` 每次创建新字符串。CPython 对引用计数为 1 的 `s += word` 做了"原地重用"优化,所以实际没那么慢,但官方推荐 `join`(无优化依赖、保证高效、语义清晰)。大量拼接(尤其循环)必用 `join`。详见《字符串拼接性能对比》。

### 3.11 位运算增强赋值用于标志位管理,语义清晰

```python
# 推荐:增强赋值管理标志位
flags |= READ_ONLY         # 置位:flags = flags | READ_ONLY
flags &= ~READ_ONLY        # 清位:flags = flags & ~READ_ONLY
flags ^= TOGGLE            # 翻转:flags = flags ^ TOGGLE

# 比展开式更紧凑且意图明确
# flags = flags | READ_ONLY   # 等价但啰嗦
```

`flags |= MASK`(置位)、`flags &= ~MASK`(清位)、`flags ^= MASK`(翻转)是标志位管理的标准写法,比 `flags = flags | MASK` 简洁且意图明确。详见《位运算符》。

### 3.12 不要把赋值塞进复杂表达式,海象也要克制

```python
# 不推荐:赋值混在复杂表达式里,难读易错
# result = [(x := a + b) * (y := c + d) for item in items]

# 推荐:分步清晰
x = a + b
y = c + d
result = x * y

# 海象用于真正减少重复的场景
while (line := f.readline()):
    process(line)
```

赋值的本质是"绑定名字",应保持清晰可读。把赋值(尤其多个海象)塞进复杂表达式,虽语法合法,但严重损害可读性。海象用于"读取-判断-处理""变换-过滤-收集"这类明确减少重复的场景;复杂逻辑分步写普通赋值更易维护。可读性优先于花哨。

## 4. 原理

本章讲清赋值运算符行为背后的机制:`=` 为何是语句而非表达式、增强赋值对可变类型为何就地修改(`__iadd__`/`__add__` 分派)、多重赋值与解包的求值顺序、海象运算符作为表达式的实现、`++` 为何不存在。这些是"赋值运算符为何如此"的根基。

### 4.1 `=` 为何是语句而非表达式:Python 的设计哲学

C/Java 里,赋值是**表达式**——`x = 10` 把 10 赋给 x,同时整个表达式求值为 10,所以能写 `y = (x = 10)`(x 得 10,y 也得 10)、`if (x = 5)`(赋值并测试)。这带来一个经典 bug:`if (x = 5)` 本想写 `if (x == 5)`(判断相等),却写成 `=`(赋值),把 5 赋给 x 且判定为真(5 非零即真),逻辑全错还无报错。

Python 选择让 `=` 是**语句**而非表达式——`x = 10` 执行绑定但**不产生值**,不能 `y = (x = 10)`、不能 `if (x = 5)`(直接 SyntaxError)。这从语法层面杜绝了 C 的 `if (x = 5)` bug:把 `=` 写在条件里根本编译不过,逼你用 `==`。

```python
# x = 10 是语句,不产生值
# y = (x = 10)        # SyntaxError: 赋值无返回值
# if x = 10:          # SyntaxError: 语法禁止
if x == 10:           # 只有 == 能进条件,杜绝 = 误写
    ...
```

这个设计是 Python"语句/表达式分明"哲学的体现:**语句执行动作(如赋值、循环、return),表达式求值**。赋值是"动作",不属于"求值",所以不给返回值。好处是消除了 `=`/`==` 误写 bug,代价是"赋值并使用"场景需要更多代码——直到 3.8 引入海象 `:=`(§4.4)才补足这个空缺。

理解这条原理,就理解了"`=` 无返回值不是缺陷而是设计",以及为何 Python 强制 `if` 条件用 `==`。这也解释了为何 Python 没有 `++`/`--`(§4.5):它们在 C 里既是表达式又有副作用,与"语句/表达式分明"冲突。

### 4.2 增强赋值对可变类型就地修改:`__iadd__` 与 `__add__` 的分派

`x += y` 与 `x = x + y` 在可变类型上行为不同,根因是 Python 对增强赋值的**协议分派**:解释器先尝试就地方法 `__iadd__`,失败才回退到 `__add__`。

`x += y` 的执行逻辑(伪代码):

```
1. type(x) 有 __iadd__ 吗?
   有 → x = type(x).__iadd__(x, y)   # 就地修改,返回(通常)原对象
   无 → x = type(x).__add__(x, y)    # 回退:创建新对象
2. 把返回值重新绑定到 x
```

关键:可变类型(如 `list`)定义了 `__iadd__`,它**就地修改**原对象并返回自身;不可变类型(如 `int`、`str`、`tuple`)没有 `__iadd__`(因为无法就地改),回退到 `__add__` 创建新对象。

```python
# list 定义了 __iadd__(就地 extend)
lst = [1, 2]
result = lst.__iadd__([3])   # 就地扩展,返回原 lst
print(result is lst)         # True —— 同一对象
print(lst)                   # [1, 2, 3] —— 原对象被改

# int 没有 __iadd__,回退 __add__(创建新对象)
n = 10
# int 无 __iadd__,所以 n += 5 走 n = n.__add__(5) = 15(新对象)
print(n.__add__(5))          # 15 —— 新对象,原 n 不变
```

而 `x = x + y` 永远调用 `__add__`(创建新对象),不管类型有没有 `__iadd__`。这就是两者差异的根源:`+=` 优先就地,`= +` 总是新建。

```python
# 对比:list 的 += 和 = +
lst = [1, 2]
lst += [3]            # __iadd__:就地,id 不变
print(id(lst))

lst2 = [1, 2]
lst2 = lst2 + [3]     # __add__:新建,id 变
print(id(lst2))
```

`list.__iadd__` 的实现等价于 `self.extend(other); return self`——所以 `lst += [3]` 与 `lst.extend([3])` 行为一致(就地扩展)。这个就地优化对可变类型是**真实副作用**(改变了被多处引用的对象),不是简写糖。理解协议分派,就理解了"增强赋值对可变类型为何就地改",以及为何循环里 `lst += [x]` 比 `lst = lst + [x]` 高效(就地 O(k) vs 拷贝 O(n))。运算符协议方法详见《面向对象 OOP 全套》。

### 4.3 多重赋值与解包的求值顺序:右侧先成元组

`a, b = b, a` 能正确交换、`a, b, c = c, a, b` 能正确轮转,根因是 Python 赋值的严格求值顺序:**右侧整体先求值(通常打包成元组),再解包赋给左侧各个目标**。

以 `a, b = b, a`(初始 `a=1, b=2`)为例:

```
1. 右侧 b, a 先求值:b=2, a=1 → 打包成元组 (2, 1)
2. 左侧 a, b 解包接收:a←2, b←1
结果:a=2, b=1 ✓ 交换成功
```

关键在第 1 步:右侧 `b, a` 在任何左侧赋值发生**之前**就整体求值成元组 `(2, 1)`。所以不存在"先把 a 赋成 b 的值,a 原值丢失"的问题——原值已在元组里保存。这是 Python 多重赋值原子性的保证。

```python
# 如果按"顺序逐个赋值"就会出错(假设错误实现):
a, b = 1, 2
# 错误假想:a = b (a 变 2,原 a=1 丢失) → b = a (b 变 2) → 结果 a=2,b=2 ✗
# 实际 Python:右侧先成 (2,1) → a←2, b←1 → a=2, b=1 ✓
```

**序列解包**的机制:左侧多个目标,Python 把右侧可迭代对象的元素**按顺序**逐一绑定到左侧目标。星号目标 `*rest` 收集"剩余元素"成一个列表(因为剩余数量不定,用可变的 list 容纳)。

```python
first, *rest = [1, 2, 3, 4]
# 机制:first ← 1,rest ← [2, 3, 4](剩余打包成 list)
# rest 为何是 list 而非 tuple?因剩余数量运行时才知,需可变容器;统一用 list 保证类型一致
```

星号收集结果恒为 `list`(无论原序列是 tuple/range/str),是为了"剩余元素数量运行时确定,用 list 这种动态容器收集,且全语言统一类型",避免因原序列类型而异造成混乱。

**嵌套解包**按结构递归:左侧模式的形状与右侧序列嵌套结构匹配,递归地解包每一层。`(a, b), c = (1, 2), 3` 先把右侧打包成 `((1,2), 3)`,左侧 `(a,b), c` 解包:`a,b ← 1,2`、`c ← 3`。理解求值顺序与递归解包,就理解了多重赋值/交换/解包为何能"一行原子完成",这是 Python 相对 C/Java 的语法红利。

### 4.4 海象运算符 `:=`:让赋值成为表达式的实现

海象 `:=`(PEP 572,Python 3.8)是"赋值表达式",它让赋值**有返回值**——这是对 §4.1"`=` 是语句无返回值"规则的受控补充。`name := value` 语义:把 value 赋给 name,整个表达式求值为 value。

```python
# := 既是赋值又是表达式
n = (x := 10)
# 1. x := 10:把 10 赋给 x,表达式求值为 10
# 2. n = 10:n 接收该值
print(x, n)            # 10 10
```

实现上,`:=` 在 AST 层是 `NamedExpr`(命名表达式)节点,它先执行子表达式求值、绑定到目标名字、再返回该值。这与 `=`(语句,`Assign` 节点,无返回)在 AST 层就是不同节点类型。

**为何用 `:=` 而非复用 `=` 让其有返回值**:Python 有意保持 `=` 为无返回值语句(消除 `if (x=5)` bug,§4.1),所以"赋值并返回值"用**新运算符** `:=` 显式表达,而非改变 `=` 语义。这样 `=` 的安全性(语句、条件里禁用)不被破坏,需要"赋值表达式"时显式用 `:=`——两者职责分明:`=` 绑定(语句),`:=` 绑定并求值(表达式)。

⚠️ **左值限制为何比 `=` 严**:`:=` 左侧只能是单个名字(**不能**属性 `obj.attr`、索引 `lst[0]`、解包 `a,b`),且**不能作为顶层语句**(`x := 10` 直接写在模块顶层是 SyntaxError,必须放进括号/条件等表达式上下文,如 `n = (x := 10)` 或 `if (x := 10):`)。这是 PEP 572 的有意限制。原因:海象是表达式,若允许复杂左值(如属性赋值),表达式就会有"修改对象状态"的重副作用,与表达式"应偏纯求值"的预期冲突,且易被滥用取代 `=` 语句;禁止顶层语句用法,则是避免 `:=` 与 `=` 在语句层混淆——顶层绑定一律用 `=` 语句,`:=` 只服务于"赋值并立即在表达式中取值"这一特定场景。两层限制把海象的副作用控制在"在表达式上下文绑定一个名字"这个轻量级别,降低滥用与误读。

**必须加括号的歧义来源**:`if n := len(data) > 10` 被解析为 `n := (len(data) > 10)`,因为 `:=` 的优先级低于比较运算符 `>`(PEP 572 规定 `:=` 优先级极低,仅高于逗号)。所以比较先算,结果(bool)赋给 n。要"先赋值再比较"必须 `(n := len(data)) > 10` 用括号提升 `:=` 的求值优先级。理解优先级,就理解了为何海象在条件里常需括号。

### 4.5 为何没有 `++`/`--`:语句/表达式分明与不可变性

C 的 `++`/`--` 是"既有值又有副作用"的运算符:`++i` 把 i 加 1(副作用)同时返回新值(表达式值),`i++` 返回旧值再加 1。它们在 C 里能写进复杂表达式 `a[i++] = b[++j]`,但也因此臭名昭著(顺序点未定义行为、可读性差)。

Python 没有 `++`/`--`,原因有二:

1. **哲学冲突**:Python 坚持"语句执行动作、表达式求值"的分明(§4.1)。`++` 既是表达式(有值)又有副作用(改 i),打破了这种分明,Python 不接受这种"带副作用的表达式"。自增用 `i += 1`(`+=` 是增强赋值语句,不混进表达式)。

2. **不可变性**:`int` 不可变,`i += 1` 是"创建新 int 11,i 重新绑定",不是"把 i 盒子里的 10 改成 11"。`++i` 的"就地递增"语义在不可变模型下无意义——没有"盒子里的值"可改,只能重新绑定。所以 `++` 在 Python 既无必要也不适配。

```python
i = 5
i += 1              # i 重新绑定到新 int 6(原 5 对象不变)
print(i)            # 6

# ++i 在 Python 的"假象":不报错但无效
print(++i)          # 6 —— 解析为 +(+i),两次正号,值不变!
# i++ 直接 SyntaxError(后置 ++ 无对应语法)
```

`++i` 不报错是个"假象":Python 把它解析为 `+(+i)`(一元正号嵌套),正正得正,i 不变,是无效操作。`i++` 则因后置 `++` 无对应语法直接 SyntaxError。理解这两点,就理解了 Python 为何用 `+= 1` 而非 `++`,以及为何 `++i` "看似能用却无效"。

## 5. 总结

### 5.1 本文内容回顾

- **赋值运算符本质**:`=` 把值绑定到名字(贴引用标签,非拷贝进盒子);Python 的 `=` 是**语句无返回值**(不能 `y=(x=10)`、`if(x=5)`),杜绝 C 的 `=`/`==` 误写 bug。
- **全表**:`=` + 11 个算术增强(`+= -= *= /= //= %= **=`)+ 5 个位运算增强(`&= |= ^= <<= >>=`)+ 海象 `:=`;增强赋值统一形式 `x OP= v` 等价 `x = x OP v`(可变类型有例外)。
- **执行顺序与左值**:右侧先求值再绑定左侧;左值可是名字/索引/属性/解包目标,字面量与表达式不能作左值。
- **基本赋值**:链式 `a=b=c=v`(共享同一对象,可变类型陷阱)、多重 `a,b=1,2`、动态类型(同名可重绑不同类型)。
- **增强赋值 `+=`(重点)**:不可变类型创建新对象重新绑定(`id` 变);可变类型 list 就地扩展(`__iadd__`,`id` 不变);`lst += [x]` 与 `lst = lst + [x]` 行为不同(就地改 vs 新建),函数内 `+=` 改外部列表是隐蔽陷阱。
- **其余算术增强**:`-=` `*=`(list `*=` 就地重复,嵌套 `[[]]*n` 引用陷阱)`/=`(变 float!)`//=`(全 int 保留 int)`%=` `**=`(负/float 指数变 float);位运算增强用于标志位管理。
- **多重赋值与交换(重点)**:`a, b = b, a` 一行原子交换(右侧先成元组再解包);三变量轮转;冒泡排序交换相邻。
- **序列解包与星号(重点)**:变量数=元素数,否则 ValueError;`*rest` 收剩余成 list(可放任意位置,恒为 list);嵌套解包按结构递归;`_`/`*_` 作丢弃变量。
- **海象 `:=`(重点)**:3.8+ 赋值表达式,赋值并返回值;场景为 while 条件赋值、推导式复用、if 条件赋值;左值只能单个名字;条件里**必须加括号** `(n := expr)`(否则 `:=` 优先级低于比较,解析错)。
- **最佳实践**:`a,b=b,a` 交换、可变列表 `+=`/`append` 注意副作用、函数内别 `+=` 改外部、保 int 用 `//=`、可变默认参数陷阱、海象克制+加括号、解包用 `*`/`_`、链式赋值可变慎用、无 `++`/`--` 用 `+=1`、字符串拼接用 `join`、位增强管标志位、赋值别塞复杂表达式。
- **原理**:`=` 语句化(语句/表达式分明哲学,消除 `if(x=5)` bug);增强赋值 `__iadd__`/`__add__` 协议分派(可变就地、不可变新建);多重赋值右侧先成元组再解包(原子性保证);星号收 list(运行时数量、类型统一);海象 `NamedExpr` 节点(赋值表达式,`:=` 低优先级致需括号、左值限单名为控副作用);无 `++`/`--`(哲学冲突 + int 不可变,`++i` 是 `+(+i)` 无效)。

### 5.2 读完本文你应能掌握

- 说明 Python `=` 是"绑定名字到对象"而非"拷值进盒子",指出 `=` 是语句无返回值(不能 `y=(x=10)`、`if(x=5)`),理解这是为消除 C 的 `=`/`==` 误写 bug。
- 列出全部赋值运算符(`=` + 11 算术增强 + 5 位增强 + `:=`),写出 `x OP= v` 的等价形式 `x = x OP v`。
- 说明 `+=` 对不可变类型(创建新对象,`id` 变)与可变类型 list(就地扩展,`id` 不变)的不同行为,解释 `lst += [x]` 与 `lst = lst + [x]` 的语义差异及函数内副作用陷阱。
- 用 `a, b = b, a` 一行交换变量,说明其原子性原理(右侧先成元组再解包),写出三变量轮转。
- 用序列解包(`a,b,c = [1,2,3]`)和星号解包(`first, *rest = items`)处理序列,说明星号收集恒为 list 的原因,用 `_`/`*_` 丢弃变量。
- 说明 `/=` 会把 int 变 float、`//=` 保留 int、`**=` 负/float 指数变 float,在需要保留整数类型时正确选用 `//=`。
- 用海象 `:=` 在 while 条件、推导式、if 条件中"赋值并使用",指出必须加括号 `(n := expr)` 的优先级原因,说明左值只能单个名字的限制。
- 说明链式赋值 `a = b = []` 共享同一可变对象的陷阱,可变默认参数与 `+=` 就地修改叠加的状态泄漏,给出用 `None` 哨兵的修正。
- 说明 Python 无 `++`/`--`(用 `+=1`),指出 `++i` 被解析为 `+(+i)` 无效、`i++` 是 SyntaxError。
- 阐述 `=` 语句化的设计哲学、增强赋值 `__iadd__`/`__add__` 协议分派、多重赋值求值顺序、海象 `NamedExpr` 与 `:=` 低优先级、无 `++`/`--` 的哲学与不可变性原因。
