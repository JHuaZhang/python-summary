## 1. 介绍

### 1.1 什么是列表拷贝

"列表拷贝"指的是**产生一个与原列表内容相同、但彼此独立的新列表对象**。听起来简单,却是新手踩坑最密集的区域之一——因为 Python 里有一句话必须刻在脑子里:

> **`a = b` 不是拷贝,只是给同一个对象起了第二个名字。**

```python
a = [1, 2, 3]
b = a            # ❌ 以为复制了,其实 a、b 指向同一个列表
b.append(4)
print(a)         # [1, 2, 3, 4] —— a 也跟着变了!
print(a is b)    # True —— 它们就是同一个对象
```

为什么?因为 Python 的列表变量里存的不是"列表本身",而是"指向列表对象的引用(指针)"。`b = a` 复制的是这个指针,于是两个名字指向同一个列表对象。改一个,另一个当然跟着变。

要真正拷贝,得显式生成**新对象**。Python 给列表提供了多种拷贝方式:

- **切片**:`b = a[:]` —— 最经典的列表拷贝惯用法
- **`list()` 构造**:`b = list(a)` —— 用构造器从可迭代对象新建
- **`copy` 方法**:`b = a.copy()`(3.3+) —— 语义最直白
- **`copy` 模块**:`b = copy.copy(a)` —— 通用浅拷贝,适用于任意对象
- **解包**:`b = [*a]` —— 利用解包语法展开成新列表

```python
a = [1, 2, 3]
b = a.copy()        # 真拷贝:新对象
b.append(4)
print(a)            # [1, 2, 3] —— a 不受影响
print(b)            # [1, 2, 3, 4]
print(a is b)       # False —— 两个独立对象
```

但!"拷贝"也分层级。上面这些方式都是**浅拷贝(shallow copy)**——只复制了**最外层**的列表壳子,壳子里的元素还是与原列表**共享**的引用。当元素是不可变对象(数字、字符串、元组)时你感觉不到差别;一旦元素是**可变对象(嵌套列表、字典)**,浅拷贝就会露出马脚:

```python
a = [[1, 2], [3, 4]]
b = a.copy()                  # 浅拷贝
b[0].append(99)              # 改的是 b 的"第一个元素(那个内层列表)"
print(a)                      # [[1, 2, 99], [3, 4]] —— a 的内层列表也被改了!
print(a[0] is b[0])          # True —— 浅拷贝下,内层列表是同一个
```

这就是浅拷贝的本质:**复制外壳、共享内层**。要连内层都独立复制,需要**深拷贝(deep copy)**(`copy.deepcopy`),那是下一篇《浅拷贝与深拷贝实战》的主题。本篇只讲清楚"赋值不是拷贝""浅拷贝的各种写法""浅拷贝的嵌套共享陷阱"以及它们的底层原理,为深拷贝打好地基。

### 1.2 基本语法与最小用法

**判断"是不是同一个对象"用 `is`**,判断"内容是否相等"用 `==`。理解拷贝离不开这两个运算符:

```python
a = [1, 2, 3]
b = a.copy()

print(a == b)    # True  —— 内容相等
print(a is b)    # False —— 但不是同一个对象
```

**五种浅拷贝写法一览**(对一维列表,它们效果等价):

```python
a = [1, 2, 3]

b1 = a[:]            # 切片
b2 = list(a)         # 构造器
b3 = a.copy()        # 方法(3.3+)
b4 = [*a]            # 解包
import copy
b5 = copy.copy(a)    # copy 模块

print(b1, b2, b3, b4, b5)   # 都是 [1, 2, 3]
print(b1 == b2 == b3 == b4 == b5 == a)   # True
print(all(b is not a for b in [b1,b2,b3,b4,b5]))  # True —— 都是新对象
```

**速查表:赋值 vs 浅拷贝 vs (预告)深拷贝**

| 操作 | 是否产生新外层对象 | 内层元素是否独立 | 适用 |
|------|------------------|----------------|------|
| `b = a` | ❌ 否(同一对象) | ❌ | 仅想给对象起别名 |
| `a.copy()` / `a[:]` / `list(a)` | ✅ 是 | ❌(内层共享) | 元素不可变,或不需要内层独立 |
| `copy.deepcopy(a)` | ✅ 是 | ✅(递归复制) | 嵌套可变对象需完全独立 |

记住这条主线:**赋值共享一切、浅拷贝共享内层、深拷贝什么都不共享**。本篇聚焦前两行。

### 1.3 为什么 `a = b` 不是拷贝:变量是引用

这是 Python 与 C 等语言最大的心智差异之一。在 C 里,数组变量代表"一段连续内存";在 Python 里,列表是堆上的一个对象,变量只是"贴在对象上的标签":

```python
# 想象 a、b 是两张便利贴,贴在同一个盒子上
a = [1, 2, 3]   # 造一个盒子 [1,2,3],贴标签 a
b = a           # 把标签 b 也贴到同一个盒子上
# 现在盒子上贴着 a、b 两张标签
b.append(4)     # 往盒子里放东西
print(a)        # 看盒子:[1,2,3,4] —— 因为 a 看的是同一个盒子
```

`id()` 能直接看到这个"盒子"的编号:

```python
a = [1, 2, 3]
b = a
print(id(a), id(b), id(a) == id(b))   # 两个数字相同,说明同一对象
```

正因为赋值只复制引用,任何直接的 `=` 都不会产生新列表。这是新手写出"改 b 却把 a 也改了"这类 bug 的根因。**要拷贝,必须调用会产生新对象的操作**(切片、`list()`、`.copy()`、`copy.copy` 等)。

```python
# ❌ 函数内修改参数,外部列表被改(因为形参和实参是同一对象)
def add_one(lst):
    lst.append(1)
    return lst

data = [0]
add_one(data)
print(data)     # [0, 1] —— data 被函数改了

# ✅ 函数内不污染原列表,先拷贝
def add_one_safe(lst):
    lst = lst.copy()    # 拷贝一份再改
    lst.append(1)
    return lst

data = [0]
out = add_one_safe(data)
print(data, out)   # [0] [0, 1] —— 原列表保持不变
```

### 1.4 浅拷贝的边界:复制外壳、共享内层

浅拷贝**(shallow copy)**这个名字的由来就是:它只"浅浅地"复制了最外一层。对新列表里的每个位置,放的是**与原列表对应位置相同的引用**——也就是说,新外壳里的元素和旧外壳里的元素指向同一个对象:

```python
a = [[1, 2], 3]
b = a.copy()

# 外壳是两个不同对象
print(a is b)          # False

# 但第一个元素(那个内层列表)是同一个对象
print(a[0] is b[0])    # True —— 浅拷贝:内层共享

# 第二个元素 3 是不可变的整数,共享也无所谓
print(a[1] is b[1])    # True,但 int 不可变
```

对**不可变**的元素(数字、字符串、元组),共享引用无所谓——因为你无法"修改"一个不可变对象,只能用新对象替换引用,替换不会影响别名。但对**可变**元素(嵌套列表、字典、集合),共享引用就意味着"通过一个名字改了内层,另一个名字也看得到变化":

```python
a = [[1, 2], [3, 4]]
b = a.copy()

b[0].append(99)            # 原地改 b[0](那个内层列表)
print(a)                   # [[1, 2, 99], [3, 4]] —— a[0] 也变了!
print(a[0] is b[0])        # True —— 同一个内层列表

b[1] = [9]                 # 这只是替换 b 的第二个位置,不动原列表
print(a)                   # [[1, 2, 99], [3, 4]] —— a 不变
print(b)                   # [[1, 2, 99], [9]]
```

分辨清楚这两种操作是关键:**"`b[i] = x`"替换的是 b 外壳上的引用,不碰原列表;"`b[i].append(x)`"改的是 b[i] 指向的那个可变对象,而它被 a 共享,所以 a 也变**。前者是浅拷贝能挡住的("分层"在第一层),后者是浅拷贝挡不住的("穿透"到了第二层)。这条边界决定了你何时该从浅拷贝升级到深拷贝——这就是下一篇的主题。

## 2. 核心内容

本章逐节详解:赋值与拷贝的本质差异、五种浅拷贝写法及其等价性、浅拷贝的嵌套共享陷阱、`copy` 模块、`is`/`id` 检验、以及拷贝时机。每节遵循"文字详解 → demo → 运行结果说明 → 陷阱"。

### 2.1 赋值不是拷贝:同一性检验

`is` 运算符判断两个变量是否指向**同一个对象**(同一性 identity),`==` 判断内容是否**相等**(相等性 equality)。拷贝的核心目的是让结果 **`==` 但非 `is`**:

```python
a = [1, 2, 3]
b = a              # 赋值
c = a.copy()       # 拷贝

print(a is b)      # True  —— 赋值,同一对象
print(a is c)      # False —— 拷贝,不同对象

print(a == b)      # True
print(a == c)      # True  —— 内容都相等

# 改 b 会影响 a,改 c 不会
b.append(4)
print(a)           # [1, 2, 3, 4]
c.append(5)
print(a)           # [1, 2, 3, 4] —— c 的改动不波及 a
```

**陷阱**:用 `==` 检验"是否拷贝成功"会被骗——`b == a` 为 `True` 既可能是"拷贝了",也可能是"根本没拷贝"(赋值)。判断拷贝成功只能用 `is not`:

```python
is_real_copy = (copy is not original)   # 正确的检验
looks_equal  = (copy == original)      # 不能区分赋值与拷贝
```

### 2.2 五种浅拷贝写法及等价性

对**一维列表**,以下五种写法产生等价的结果(都是新列表、内容相同):

```python
a = [1, 2, 3]

import copy
b1 = a[:]           # ① 切片
b2 = list(a)        # ② list() 构造器
b3 = a.copy()       # ③ .copy() 方法 (3.3+)
b4 = [*a]           # ④ 解包构造
b5 = copy.copy(a)   # ⑤ copy 模块

# 都是独立的新对象、内容相等
for b in (b1, b2, b3, b4, b5):
    assert b is not a
    assert b == a
```

每种写法的"性格":

- **① 切片 `a[:]`**:最古老通用的惯用法,语义"取全部,造新的",任何 Python 版本都行。
- **② `list(a)`**:构造器,接受任意可迭代对象(包括生成器、字典、集合等),把元素收集成新列表。比切片更通用——`list(some_gen)` 切片做不到。
- **③ `a.copy()`**(3.3+):语义最直白,`x.copy()` 一眼知道是"复制 x"。只适用于有 `copy` 方法的类型(list/dict/set 都有)。
- **④ `[*a]`**:解包语法,也接受任意可迭代对象,且可以与其他元素混用:`[0, *a, 9]`。灵活但可读性见仁见智。
- **⑤ `copy.copy(a)`**:来自 `copy` 模块,对所有类型都有效(连自定义类都行),是**最通用、最"面向对象正确"**的浅拷贝方式。

```python
# ② list() 与 ④ [*x] 能处理切片处理不了的迭代器
import itertools
gen = itertools.count(0)
triple = list(itertools.islice(gen, 3))   # [0, 1, 2],从生成器物化

# ④ 解包可混入其他元素
a = [2, 3]
b = [1, *a, 4]            # [1, 2, 3, 4]
```

**选型建议**:对纯列表,首选 **`a.copy()`**(最直白)或 **`a[:]`**(最通用惯用法);要兼容任意可迭代对象用 `list(a)`;要在不关心元素来源的通用库中拷贝任意对象用 `copy.copy(a)`。

### 2.3 浅拷贝只复制第一层:嵌套共享陷阱

这是浅拷贝最容易出 bug 的地方。一个二维列表(列表的列表)浅拷贝后,**外层是新列表、内层列表仍被共享**:

```python
matrix = [[1, 2], [3, 4]]
shallow = matrix.copy()

# 外层独立
print(shallow is matrix)        # False
shallow.append([5, 6])          # 往 shallow 外层加东西
print(matrix)                   # [[1, 2], [3, 4]] —— 不影响 matrix 外层

# 内层共享
print(shallow[0] is matrix[0])  # True
shallow[0].append(99)           # 原地改 shallow[0] 这个内层列表
print(matrix)                   # [[1, 2, 99], [3, 4]] —— matrix 的内层也被改了!
```

图示浅拷贝后的指针结构:

```
matrix     ──┐   shallow    ──┐
 [1,2,99]     ├─→ [1,2,99] ◄─┤   ← 两个外壳都指向同一个内层列表
 [3,4]  ──────┤    [3,4]   ◄──┤
              │              │   (这是两份外层,但内层是同一份)
```

**两种修改方式的区别**(务必分清):

```python
a = [[1, 2], [3, 4]]
b = a.copy()

b[0] = [9]            # A:替换 b 外层第 0 位的引用
print(a, b)           # a=[[1,2],[3,4]]  b=[[9],[3,4]] —— a 不变

b[1].append(8)        # B:原地修改 b[1] 这个被共享的内层列表
print(a, b)           # a=[[1,2],[3,4,8]] b=[[9],[3,4,8]] —— a[1] 也被改!
```

- **A(`b[i] = x`)**:在浅拷贝的"独立外层"上做替换,只影响 b,不波及 a。浅拷贝能挡住这种改动。
- **B(`b[i].append(x)`)**:穿透外层,改动被共享的内层对象,a 也看得到。浅拷贝挡不住。

要让 B 这种改动也不影响 a,就需要**深拷贝**——把内层列表也复制成新的:

```python
import copy
a = [[1, 2], [3, 4]]
deep = copy.deepcopy(a)         # 深拷贝,连内层也独立
deep[0].append(99)
print(a)                        # [[1, 2], [3, 4]] —— a 完全不受影响
print(deep[0] is a[0])          # False —— 内层也不再共享
```

深拷贝的完整机制、循环引用、自定义 `__copy__`/`__deepcopy__` 等是下一篇《浅拷贝与深拷贝实战》的内容。这里只需记住:**嵌套的可变对象要完全独立,用 `deepcopy`,不要用浅拷贝**。

### 2.4 `copy` 模块:`copy.copy` 浅拷贝任意对象

`copy` 模块提供两个函数:`copy.copy(x)`(浅拷贝)和 `copy.deepcopy(x)`(深拷贝)。`copy.copy` 不依赖对象类型,对所有支持拷贝的对象通用:

```python
import copy

lst = [1, 2, 3]
s = {1, 2, 3}
d = {"a": 1}
t = (1, 2, 3)

print(copy.copy(lst) is lst)   # False
print(copy.copy(s)   is s)     # False
print(copy.copy(d)   is d)     # False
print(copy.copy(t)   is t)     # True!  —— 元组浅拷贝返回原对象(见下)
```

**不可变对象的"拷贝"可能返回原对象**:对元组、字符串等不可变对象,`copy.copy` 经常直接返回原对象(因为它们无法被原地修改,共享即等于拷贝,系统省下分配开销):

```python
import copy
t = (1, 2, 3)
print(copy.copy(t) is t)           # True —— 元组共享即可
print(t[:] is t)                   # True —— 切片对元组也常返回同一对象

# 但如果元组里含可变元素,deepcopy 会进到内层去复制
nested = ([1, 2], [3, 4])
sh = copy.copy(nested)
print(sh is nested)                # False —— 浅拷贝(外层是元组,也确实造了新对象)
print(sh[0] is nested[0])          # True  —— 但内层列表仍共享
```

**`copy.copy` 如何工作**:它优先调用对象自己的 `__copy__` 方法(如果有),否则按对象类型用内置规则(list/dict/set 各有原生拷贝方式)。这让 `copy.copy(x)` 成为写库代码时最稳妥的通用浅拷贝——你不必关心 `x` 是 list、dict 还是自定义类。

### 2.5 各种浅拷贝方式底层等价的证明

`a[:]`、`list(a)`、`a.copy()` 看着不同,但对 list 来说它们都走到同一条"分配新数组 + 复制 n 个引用"的路上。下面用 `is` 检验外层独立、用性能检验它们代价一致:

```python
import timeit, copy

a = list(range(1_000_000))

setup = 'from __main__ import a, copy'

print(timeit.timeit('a[:]',         setup=setup, number=100))   # O(n) 复制
print(timeit.timeit('list(a)',      setup=setup, number=100))   # 与切片相当
print(timeit.timeit('a.copy()',     setup=setup, number=100))   # 与切片相当
print(timeit.timeit('[*a]',         setup=setup, number=100))   # 略慢(解包开销)
print(timeit.timeit('copy.copy(a)', setup=setup, number=100))   # 略慢(查 __copy__)
```

四种"直接"写法(切片、`list()`、`.copy()`、解包)性能几乎相同,因为核心都是 C 层一次性复制 n 个指针。`copy.copy(a)` 多一次"按类型查拷贝方式"的派发开销,略慢但对普通量级可忽略。

**内存上都是 O(n)**:新列表分配一个长度为 n 的指针数组,复制原数组的 n 个引用,空间随元素数线性增长。这意味着拷贝大列表时,内存会"翻一份"——大数据场景下要注意,这也是为什么"只读遍历"应优先考虑不拷贝(直接遍历或用迭代器)。

### 2.6 何时需要拷贝:防御性拷贝的时机

不是所有复制都需要显式拷贝。判断要点:**后续会不会原地改这个列表,以及改了会不会污染不该被改的对象**。

**需要拷贝的典型场景**:

```python
# ① 函数参数不污染调用方的原列表
def normalize(values):
    values = values.copy()      # 先拷贝,避免改到调用方的列表
    values.sort()
    # ... 处理
    return values

# ② 缓存/默认值(可变默认参数陷阱的根治)
def process(data, fixed=None):
    if fixed is None:
        fixed = []              # 不写固定默认 [],而是函数体内新建
    fixed = fixed[:]            # 若调用方传入,拷一份避免改原对象
    fixed.append(data)
    return fixed

# ③ 保留"修改前快照"用于对比或回滚
before = config_items.copy()
apply_changes(config_items)
print("变化项:", [k for k in config_items if k not in before])
```

**可变默认参数陷阱**(经典坑):函数定义时 `def f(x=[])` 里的 `[]` 只求值一次,所有调用共享同一个列表——本质就是"没拷贝":

```python
def f(x=[]):       # ❌ 危险:默认 [] 只创建一次,被各次调用共享
    x.append(1)
    return x

print(f())         # [1]
print(f())         # [1, 1] —— 上次的 1 还在!
print(f())         # [1, 1, 1]

# ✅ 正确:用 None 哨兵,在函数内每次新建
def f(x=None):
    if x is None:
        x = []
    x.append(1)
    return x

print(f())         # [1]
print(f())         # [1] —— 每次独立
```

这个陷阱根源不是拷贝问题,而是"默认参数只求值一次 + 列表是可变对象"。理解了"赋值共享""可变对象会被原地改",就能理解为什么必须用哨兵 + 新建。

**不需要拷贝的场景**:只读遍历(`for x in original`)、传递给承诺不改它的函数、或只是想看一眼内容——直接用引用即可,拷贝反而浪费内存。原则:**没有"独立修改"需求,就不必拷贝**。

## 3. 最佳实践

### 3.1 牢记 `b = a` 不是拷贝,要拷贝必显式

```python
a = [1, 2, 3]
b = a            # ❌ 不是拷贝,是别名
b = a.copy()     # ✅ 真拷贝
```

任何对可变对象的"副本"需求,都不能靠 `=`。养成习惯:想"复制一份并独立修改"时,立刻想到 `a.copy()` / `a[:]` / `list(a)` 之一。

### 3.2 判断拷贝成功用 `is not`,不要用 `==`

```python
# ✅ 正确:必须不是同一对象
assert copy is not original

# ❌ 错误:赋值和拷贝都让 == 为 True,区分不开
# assert copy == original
```

`==` 只能验内容,验不出"是否同一对象"——而那正是拷贝的全部意义。要确认拷贝真的产生了新对象,只能用 `is not` 或比较 `id()`。

### 3.3 一维列表优先 `a.copy()` 或 `a[:]`,通用迭代用 `list(a)`

```python
# 纯列表:最直白
b = a.copy()

# 也惯用
b = a[:]

# 想兼容生成器/迭代器/任意可迭代
b = list(iterable)        # 切片做不到
```

`a.copy()` 读起来最清楚;`a[:]` 是跨版本通用惯用法;`list(a)` 适合"来源不一定是 list"的场景。三者都是浅拷贝,对一维列表等价。

### 3.4 嵌套可变对象浅拷贝会共享内层,要完全独立用 `deepcopy`

```python
import copy

a = [[1, 2], [3, 4]]

# ⚠️ 浅拷贝:内层仍共享
sh = a.copy()
sh[0].append(9)
print(a)            # [[1,2,9],[3,4]] —— a 被波及

# ✅ 深拷贝:连内层都独立
dp = copy.deepcopy(a)
dp[0].append(9)
print(a)            # [[1,2],[3,4]] —— a 完全不受影响
```

只要拓扑里出现"列表的列表""字典的列表"等嵌套可变结构,且你对内层有原地修改需求,浅拷贝就不够——上 `copy.deepcopy`。完整细节见下一篇。

### 3.5 分清"替换外层引用"与"原地改内层对象"

```python
a = [[1, 2], [3, 4]]
b = a.copy()

b[0] = [9]            # 替换外层引用:浅拷贝能挡,a 不变
b[0].append(9)        # 原地改内层(被共享):浅拷贝挡不住,a 也变
```

`b[i] = x` 改的是浅拷贝"独立的外层",安全;`b[i].mutate()` 穿透到被共享的内层对象,危险。写多级嵌套代码时,先想清楚你是在"换引用"还是"改对象",后者在浅拷贝下必然波及原列表。

### 3.6 函数内修改入参前先拷贝(防御性拷贝)

```python
def top_n(items, n):
    items = items.copy()       # 不污染调用方原列表
    items.sort(reverse=True)
    return items[:n]

data = [3, 1, 4, 1, 5]
print(top_n(data, 2))          # [5, 4]
print(data)                    # [3, 1, 4, 1, 5] —— 原列表未变
```

公共 API 想保证"不偷偷改变量传入的对象",进入函数第一件事就是拷一份再处理。这种"防御性拷贝"成本 O(n),换来的是调用方对函数无副作用。

### 3.7 可变默认参数用 `None` 哨兵,别用 `[]`

```python
def f(x=None):          # ✅ 哨兵写法
    if x is None:
        x = []
    x.append(1)
    return x

# def f(x=[]): ...      ❌ 默认值只求值一次,越调用越长
```

根因是默认参数值在函数定义时只求值一次并被共享,结合列表可变就出 bug。哨兵法每次调用新建,从根本上规避。理解这一点,就理解了"默认值共享"是另一类"未拷贝"问题。

### 3.8 只读遍历不要拷贝,避免无谓 O(n) 内存

```python
# ❌ 没"独立修改"需求却拷贝,浪费内存
for x in data.copy():
    print(x)

# ✅ 直接遍历引用即可
for x in data:
    print(x)
```

拷贝要花 O(n) 时间和 O(n) 内存。只是读取/遍历,直接用原列表引用;只有在"要边改边留原样"时才值这个代价。大数据场景尤其要克制。

## 4. 原理

### 4.1 变量是引用:`a = b` 复制的是指针

Python 的列表对象存活在堆(heap)上,变量名到对象的映射由命名空间(局部/全局字典)维护。赋值 `a = b` 做的事,是在命名空间里让 `a` 指向 `b` 当前指向的对象——复制的是"指向",不是"被指的对象":

```c
// 简化示意:赋值在解释器里的本质
a = b;
// 等价于(伪 CPython)
// PyDict_SetItem(locals, "a", PyObject_GetItem(locals, "b"));
// 即:把 b 绑定的对象引用,再绑给 a。对象本身未复制。
```

`id(x)` 返回对象的内存地址(CPython 里就是 `PyObject*` 的值),`a is b` 等价于 `id(a) == id(b)`,即"指针相等":

```c
// 简化示意:is 的实现
int is_operator(a, b) {
    return a == b;   // 两个 PyObject* 直接比地址
}
```

所以 `b = a` 后 `id(a) == id(b)`、`a is b` 为真——它们是同一个指针。这也解释了为何"改 b 影响 a":根本没有两个对象,改的就是唯一那个。

### 4.2 浅拷贝:分配新数组,复制 n 个引用

 各种浅拷贝写法(切片、`list()`、`.copy()`)对 list 来说最终都调用类似的"分配新 `ob_item` 数组 + 逐个复制指针"逻辑:

```c
// 简化示意:list 浅拷贝的核心
PyListObject *list_copy(PyListObject *src) {
    Py_ssize_t n = src->ob_size;
    PyListObject *dst = 新建长度为 n 的列表;        // 分配新数组,O(n) 空间
    for (Py_ssize_t i = 0; i < n; i++) {
        dst->ob_item[i] = src->ob_item[i];          // 复制指针(引用)
        Py_INCREF(dst->ob_item[i]);                 // 引用计数 +1
    }
    return dst;                                     // 返回新对象
}
```

关键点:

- **新外壳、旧内层**:`dst` 是全新的列表对象(新 `ob_item` 数组),所以 `dst is not src`。但数组里每个槽位存的指针,与 `src` 对应槽位**指向同一个元素对象**。这就是"复制外壳、共享内层"。
- **O(n) 时空**:分配 n 个指针的数组 O(n) 空间,复制 n 次 O(n) 时间。元素对象本身不复制(只增引用计数),所以拷贝代价只与列表长度有关,与元素大小无关。
- **不可变元素共享无碍**:若元素是不可变对象(`int`、`str`、`tuple`),共享引用不会出问题,因为不能用原地操作改它,只能换引用;换了也只影响外层那一个壳,不影响另一个壳。

这条"复制指针而非对象"的机制,正是浅拷贝"对一维列表足够、对嵌套可变列表不够"的根源:外壳独立(各自有 `ob_item` 数组),但 `ob_item[i]` 指向的内层对象是同一个,通过 `b[i].append(...)` 走 `ob_item[i]` 这个指针去改那个被共享的内层对象,a 自然能看到变化。

### 4.3 五种写法为何等价:同一条复制路径

我们逐个看五种浅拷贝写法在 CPython 里落到哪里:

```c
// ① 切片 a[:] —— 走 list_subscript → list_slice,内部就是 list_copy 的逻辑

// ② list(a) —— list 构造器对 list 入参有快路径:直接 list_copy

// ③ a.copy() —— list.copy 方法直接调 list_copy

// ④ [*a] —— 解包:遍历 a 的迭代器逐个 append,逻辑上等价,但走迭代器路径

// ⑤ copy.copy(a) —— 先查 a.__copy__,没有则按类型派发到 list_copy
PyObject *copy_copy(x) {
    if (hasattr(x, "__copy__")) return x.__copy__();   // 自定义优先
    if (PyList_Check(x)) return list_copy(x);          // list 快路径
    // ... 其他类型各自处理
}
```

①②③ 都直接命中 `list_copy` 这条快路径,因此性能与行为几乎一致。④ 解包走迭代器逐个 append,多一层迭代开销,略慢但结果相同。⑤ `copy.copy` 多一次"查找 `__copy__` + 类型派发",对 list 也会落到 `list_copy`,略慢但通用性最高。这正是 2.5 节性能基准的底层解释。

### 4.4 浅拷贝共享内层的指针视角

把 2.3 节的二维列表浅拷贝画成指针图:

```
       ob_item[0]          ob_item[1]
matrix ─→ [指针]─┐      ─→ [指针]─┐
                ↓              ↓
shallow──→ [指针]─┘      ─→ [指针]─┘   (ob_item 数组是新的)
                ↓              ↓
              [1,2,99]        [3,4]    (内层列表只有一份,被两侧共享)
```

执行 `shallow[0].append(99)` 时,解析 `shallow[0]` 拿到的是那个共用的内层列表 `[1,2]`,对它调 `append`,内层变成 `[1,2,99]`。由于 matrix 的 `ob_item[0]` 也指向这个内层列表,`matrix` 看到的也是 `[1,2,99]`。**改动通过共享的指针"穿越"了外层独立**。

而 `shallow[0] = [9]` 是改 `shallow` 这个外壳的 `ob_item[0]` 槽位——把它指向新的 `[9]` 对象,`matrix` 的 `ob_item[0]` 仍指原内层,互不干扰。

```c
// 简化示意:两种改动的差异
shallow->ob_item[0]->append(99);   // 改的是共享对象 → matrix 也能看到
shallow->ob_item[0] = new [9];     // 只改 shallow 的槽位 → matrix 不受影响
```

这就把"分层"具象化了:**外层(壳)各自有 `ob_item` 数组,浅拷贝独立;内层(壳里的指针所指对象)是同一份,浅拷贝共享**。深拷贝之所以能挡住第二种改动,是因为它递归地对内层对象也再拷一份,使两侧的内层指针各指各的新对象。

### 4.5 `copy.copy` 对不可变对象的"返回原对象"优化

`copy.copy` 对不可变对象(元组、字符串、数字等)往往**不分配新对象,直接返回原对象**:

```c
// 简化示意:copy 模块对不可变类型的优化
PyObject *copy_copy(x) {
    if (PyList_Check(x))          return list_copy(x);     // 可变:真复制
    if (PyDict_Check(x))          return dict_copy(x);     // 可变:真复制
    if (PySet_Check(x))           return set_copy(x);      // 可变:真复制
    if (PyTuple_Check(x) || PyUnicode_Check(x) || ...)
        return x;                                         // 不可变:返回原对象
}
```

为什么能这么做?因为不可变对象**无法被原地修改**,"共享引用"与"真复制"在行为上完全等价——既然改不了,共享就等于拷贝,省下分配开销。所以:

```python
import copy
t = (1, 2, 3)
print(copy.copy(t) is t)   # True —— 不浪费内存,返回原对象
```

但要注意一个**反直觉点**:元组本身不可变,如果它含可变元素,浅拷贝"返回原元组"意味着那个可变元素也被共享:

```python
import copy
nt = ([1, 2], [3, 4])          # 元组里的元素是可变 list
sh = copy.copy(nt)
print(sh is nt)                # True —— 元组浅拷贝返回原对象
# 于是 sh[0] is nt[0] 也为 True,内层列表被共享
sh[0].append(9)
print(nt)                      # ([1,2,9],[3,4]) —— 透过共享改到了
```

这正是"不可变外壳 + 可变内层"的隐患:外壳说"我不可变",内层却是可变的、被共享的。要彻底独立,仍需 `copy.deepcopy(nt)`——它会对元组里的可变内层递归复制,即便外壳只返回过同一对象。这一机制既是性能优化,也藏着陷阱,是理解浅拷贝边界的最后一块拼图。

### 4.6 防御性拷贝与"可变默认值共享"的同一根源

2.6 节的可变默认参数陷阱,本质上和"赋值不是拷贝"是同一个机制:

```c
// 简化示意:函数默认值只在定义时求值一次
def f(x=[]):
定义函数时,x 的默认值被求值一次,绑定到一个固定对象 obj_default。
此后每次调用未传 x 时,x = obj_default —— 即 x 绑定到"同一对象",
等价于"赋值不是拷贝"。
于是多次调用共享同一默认对象,append 累积,越用越长。
```

可见该陷阱的根因仍是"赋值(默认绑定)只复制引用、不复制对象,且对象可变"。根治办法也别无二致:**避免对可变对象做隐式共享**——用 `None` 哨兵,在函数体内 `x = []` 每次新建,等价于"显式制造新对象"。

把"赋值共享""浅拷贝共享内层""默认值共享"统一到"引用:可变对象 + 共享 = 意外联动"这一条,本篇的全部现象就有了清晰的因果链:**只要存在"被共享的可变对象 + 原地修改",就有人会意外地看到变化**;拷贝(浅或深)的作用,就是在合适的层级上"切断共享",按需选择切断到第几层(浅拷贝切外层、深拷贝切到底)。下一篇《浅拷贝与深拷贝实战》就专门讲"切到底"的完整机制。

## 5. 总结

### 5.1 本文内容回顾

- **赋值不是拷贝**:`b = a` 只是给同一对象起了第二个名字,`a is b` 为 `True`,改一个另一个必变。要拷贝必须调用产生新对象的操作。

- **五种浅拷贝写法**:`a[:]`、`list(a)`、`a.copy()`(3.3+)、`[*a]`、`copy.copy(a)`,对一维列表等价(内容相等、互非同一对象)。`a.copy()` 最直白、`a[:]` 最通用惯用、`list(a)` 兼容任意可迭代、`copy.copy` 通用任意对象。

- **浅拷贝边界**:只复制最外层外壳,内层元素仍是与原列表共享的引用。对**不可变元素**(数字/字符串)无碍;对**可变嵌套元素**(内层 list/dict/set),通过 `b[i].append(...)` 改内层会波及原列表。要彻底独立需 `copy.deepcopy`。

- **替换 vs 原地改**:`b[i] = x` 改的是浅拷贝独立的外层槽位,安全;`b[i].mutate()` 穿透到被共享的内层对象,a 也看得到。这条区分决定浅拷贝够不够。

- **`copy` 模块**:`copy.copy` 对可变对象真复制、对不可变对象常返回原对象(优化);元组含可变元素时,外壳"返回原对象"会让内层被共享,藏坑,需 `deepcopy` 才安全。

- **时机**:函数内修改入参前先拷贝(防御性拷贝)、保留修改前快照、可变默认参数用 `None` 哨兵新建;只读遍历不必拷贝。可变默认参数陷阱与"赋值共享"同源,都是"被共享的可变对象 + 原地修改"。

- **检验**:判断拷贝成功用 `is not`(同一性),不要用 `==`(相等性分不开赋值与拷贝);`id()` 可看对象地址佐证。

- **原理**:变量存的是引用(指针),赋值复制指针不复制对象;浅拷贝分配新 `ob_item` 数组、复制 n 个引用(O(n) 时空),五法对 list 落到同一条 `list_copy` 路径;内层共享是因外壳独立而槽内指针指向同一内层对象;不可变对象浅拷贝返回原对象是性能优化。
