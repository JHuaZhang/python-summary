## 1. 介绍

### 1.1 什么是算术运算符

算术运算符是 Python 中执行数值计算的基础操作符,对应数学里的加减乘除乘方等运算。当你写 `3 + 5`、`price * qty`、`total / count` 时,`+`、`*`、`/` 这些符号就是算术运算符,它们把数值(操作数)组合成表达式,求出一个新的数值结果。算术运算符是任何编程语言数值处理的基石,Python 在此之上做了一个关键设计:**运算结果是新对象,不修改原值**——`int`、`float` 都不可变,每个算术表达式都返回一个新对象。

```python
print(3 + 5)          # 8 —— 加
print(10 - 4)         # 6 —— 减
print(2 * 6)          # 12 —— 乘
print(7 / 2)          # 3.5 —— 真除,返回 float
print(7 // 2)         # 3 —— 地板除,返回整数商
print(7 % 2)          # 1 —— 取余
print(2 ** 10)        # 1024 —— 乘方
print(-5)             # -5 —— 一元负号
print(+5)             # 5 —— 一元正号
```

Python 算术运算符与 C/Java 的主要差异集中在三处,这三处也是新手最容易踩坑的地方:

- **`/` 永远返回 `float`(真除)**,即便两个整数整除。`7 / 2` 是 `3.5`,`8 / 2` 是 `4.0`(不是 `4`)。C/Java 里整数除法 `8 / 2` 得整数 `4`,Python 不会,要整数商必须用 `//`。
- **`//` 是地板除(floor division),向负无穷取整,而非向零截断**。`-7 // 2` 在 Python 是 `-4`(向负无穷),C/Java 的整数除法 `-7 / 2` 是 `-3`(向零截断)。这是 Python 与 C 系语言在负数除法上的本质分歧,会引发隐蔽 bug。
- **`**` 是乘方(Python 独有),`^` 是按位异或不是乘方**。C/Java 没有乘方运算符,新手常误用 `2 ^ 10` 想算 1024,实际得到的是位运算结果 8。

```python
# 三处差异直观对比
print(8 / 2)          # 4.0 —— Python 永远 float,C 里是 int 4
print(-7 // 2)        # -4 —— Python 地板除(向负无穷),C 里 -7/2 是 -3(向零)
print(2 ** 10)        # 1024 —— Python 乘方
print(2 ^ 10)         # 8 —— 注意!这是按位异或,不是乘方
```

算术运算符的所有"诡异行为"几乎都来自这三条规则——尤其是除法(`//` 与 `%` 在负数下的联动)。本篇要系统讲透 Python 7 个二元算术运算符(`+ - * / // % **`)和 2 个一元运算符(`+ -`)的完整用法、返回类型规则、负数下的特殊行为、类型隐式提升、与 `decimal`/`fractions` 的交互,以及这些行为背后的实现原理。这是「运算符与表达式」大章节的首篇,后续的整除区别、赋值运算符、优先级等专题都建立在本篇之上。

### 1.2 算术运算符全表

下面这张表是本篇的总纲,后续每一节都会逐一展开。先建立全局认知,再钻细节。

| 运算符 | 名称 | 示例 | 结果 | 返回类型规则 |
|--------|------|------|------|--------------|
| `+` | 加法 | `3 + 5` | `8` | int+int→int,有 float→float |
| `-` | 减法 | `10 - 4` | `6` | 同上 |
| `*` | 乘法 | `2 * 6` | `12` | 同上 |
| `/` | 真除 | `7 / 2` | `3.5` | 永远 float |
| `//` | 地板除 | `7 // 2` | `3` | 全 int→int,有 float→float |
| `%` | 取余 | `7 % 2` | `1` | 同 // |
| `**` | 乘方 | `2 ** 3` | `8` | int**int→int,负指数→float |
| `+x` | 一元正号 | `+5` | `5` | 同操作数 |
| `-x` | 一元负号 | `-5` | `-5` | 同操作数 |

**返回类型**是理解算术运算结果的首要维度:它是 `int` 还是 `float`,决定了你后续能否用作索引、是否精确、是否带精度误差。Python 的核心类型规则是——**只要有一个操作数是 `float`,结果就是 `float`(隐式提升)**;全 `int` 时,`/` 仍返回 `float`(这是 `/` 的硬规则),其余运算符返回 `int`。这条规则贯穿全篇,理解它就不会对 `4 ** 0.5` 是 `2.0`、`8 / 2` 是 `4.0` 感到意外。

### 1.3 运算符与操作数的类型提升

算术运算的两个操作数类型不必相同,Python 会自动把"较窄"的类型提升为"较宽"的类型再运算,这套机制叫**隐式类型转换(数值提升)**。提升链条是:`bool → int → float → complex`。`bool` 是 `int` 的子类(`True` 即 1、`False` 即 0),`int` 与 `float` 混算提升为 `float`,`float` 与 `complex` 混算提升为 `complex`。

```python
print(True + True)        # 2 —— bool 提升为 int(True=1)
print(True + 2)           # 3 —— bool + int → int
print(3 + 0.5)            # 3.5 —— int + float → float
print(2 * 3.0)            # 6.0 —— 结果 float
print(4 ** 0.5)           # 2.0 —— 0.5 是 float,结果 float(开平方)
print(2.0 + 1j)           # (2+1j) —— float + complex → complex
```

只要运算中有 `float`,结果就是 `float`;有 `complex`,结果就是 `complex`。这是一条优先级递进的规则:向链条中**最宽**的类型看齐。它决定了"何时结果从精确的 `int` 变成近似的 `float`"——一旦混入 `float`,精度特性就发生了根本转变(详见《float 类型与精度问题》《隐式类型转换》)。

⚠️ 注意 `complex` 是这条链条的终点,且 `complex` 不支持 `//`、`%`、`math.floor` 等需要"实数比较"的运算,只能做 `+ - * / **`。本篇主要聚焦 `int` 与 `float` 的算术(日常 99% 的场景),`complex` 仅在涉及处点明。

## 2. 核心内容

本章逐个详解 7 个二元算术运算符和 2 个一元运算符,每节遵循"规则说明 → demo → 陷阱 → 场景"展开。重点放在除法三兄弟(`/`、`//`、`%`)与乘方 `**`,因为它们的行为最反直觉、最易在生产环境出问题。

### 2.1 加法 `+`

加法 `+` 是最朴素的算术运算,返回两数之和。

**返回类型**:遵循隐式提升——`int + int → int`,`int + float → float`。

```python
print(3 + 5)          # 8 —— int + int
print(3 + 5.0)        # 8.0 —— int + float → float
print(0.1 + 0.2)      # 0.30000000000000004 —— float 精度误差(详见 float 篇)
```

**`+` 对非数值类型的多态**:`+` 不止算数字,Python 把它重载成了多种类型的"拼接/合并"操作符:

```python
print("hello" + " " + "world")   # 'hello world' —— 字符串拼接
print([1, 2] + [3, 4])           # [1, 2, 3, 4] —— 列表拼接(返回新列表)
print((1, 2) + (3,))             # (1, 2, 3) —— 元组拼接
# 注:set、dict 不支持 +;int 与 str 不能相加(3 + "5" 抛 TypeError)
```

⚠️ `+` 拼接列表时返回的是**新列表**,不修改原列表(列表虽可变,但 `+` 不就地改)。大量拼接列表用 `+` 性能差(每次复制),应用 `extend` 或 `itertools.chain`。字符串大量拼接同理应用 `join`。这是 `+` 在容器场景的常见性能陷阱。

**`+` 的精度陷阱**:float 加法有精度误差(`0.1 + 0.2 != 0.3`),累加还会放大误差。金额累加务必用 `int` 存最小单位或 `decimal.Decimal`,绝不用 float 直接加。详见《float 类型与精度问题》。

### 2.2 减法 `-`

减法 `-` 返回两数之差,类型规则与加法完全一致。

```python
print(10 - 4)         # 6
print(10 - 4.0)       # 6.0
print(5 - 10)         # -5
print(0.3 - 0.1)      # 0.19999999999999998 —— float 精度误差
```

减法同样对部分类型有多态(如 `set` 的差集用 `-`,但 `set` 不支持算术 `+`)——这属于运算符重载范畴,本篇只在涉及处点明,不展开容器运算。

⚠️ 减法的精度陷阱与加法同源:`0.3 - 0.1` 得 `0.19999...` 而非 `0.2`。任何"先减后比较相等"的逻辑都要警惕 float 误差,改用 `math.isclose`。

### 2.3 乘法 `*`

乘法 `*` 返回两数之积,类型规则遵循隐式提升。

```python
print(2 * 6)          # 12
print(2 * 6.0)        # 12.0
print(-3 * 4)         # -12
print(0.1 * 3)        # 0.30000000000000004 —— float 误差
```

**`*` 对非数值类型的多态**:`*` 重载为"重复"操作,作用在序列与整数上:

```python
print("ab" * 3)       # 'ababab' —— 字符串重复 3 次
print([0] * 4)        # [0, 0, 0, 0] —— 列表重复
print((1,) * 3)       # (1, 1, 1) —— 元组重复
```

⚠️ **`[[]] * 3` 的经典陷阱**:用 `*` 重复嵌套可变对象时,内部是**同一个对象的引用**,改一个会影响所有:

```python
rows = [[]] * 3
rows[0].append(1)
print(rows)           # [[1], [1], [1]] —— 三个子列表是同一个!全被改了
# 正确做法:用列表推导各自创建
rows = [[] for _ in range(3)]
rows[0].append(1)
print(rows)           # [[1], [], []] —— 各自独立
```

这个陷阱根源于"可变对象赋值是引赋引用",详见《变量赋值机制》。算术运算符章节点明此坑,避免新手误用。

### 2.4 真除 `/`(重点)

真除 `/` 是 Python 算术运算符里最该刻进认知的一个——**它永远返回 `float`,无论操作数是不是整数、是否整除**。

```python
print(7 / 2)          # 3.5 —— 整数除整数,得 float
print(8 / 2)          # 4.0 —— 即便整除,也是 float(不是 4!)
print(8.0 / 2)        # 4.0 —— 有 float,自然 float
print(7 / 3)          # 2.3333333333333335
print(1 / 3)          # 0.3333333333333333
```

这条"永远 float"的规则是 Python 3 相对 Python 2 的重大变化。Python 2 里 `8 / 2` 是整数 `4`(整数除法),Python 3 统一改为真除。从 Python 2 迁移来的代码,所有"本想取整数商却用了 `/`"的地方都会悄悄从 `int` 变 `float`,可能破坏后续逻辑(如用作索引、做 `isinstance(x, int)` 判断)。

⚠️ **典型陷阱**:`/` 结果是 `float`,不能用作列表索引:

```python
idx = 8 / 2           # 4.0 —— float
# data[idx]          # TypeError: list indices must be integers, not float
idx = 8 // 2          # 4 —— 要索引必须用 // 得到 int
```

**`/` 与负数**:不涉及取整,直接出真实小数商,没有 `//` 那种向负无穷的困惑:

```python
print(-7 / 2)         # -3.5
print(7 / -2)         # -3.5
print(-8 / 2)         # -4.0
```

**`/` 与零**:Python 的 `/` 除以零一律抛 `ZeroDivisionError`,无论是 int 还是 float:

```python
# print(5 / 0)        # ZeroDivisionError: division by zero
# print(5.0 / 0)      # ZeroDivisionError —— float 除零也报错(不像某些语言返回 inf)
```

这与 JavaScript 等语言不同(JS 的 `5/0` 得 `Infinity`)。Python 坚持除零即错,要求开发者显式处理。

**何时用 `/`**:需要小数精确商、计算平均值、比例、概率时用 `/`。要整数商、向下取整、做索引时用 `//`。

### 2.5 地板除 `//`(重点)

地板除 `//` 返回"向下取整后的商",其行为是 Python 算术运算符里最需要细讲的一个,根因是它对负数的处理与直觉(及 C/Java)不同。

**返回类型**:`//` 的类型规则是"全 int 返回 int,有 float 返回 float"(与 `%` 一致,不同于 `/`):

```python
print(7 // 2)         # 3 —— 全 int,返回 int
print(8 // 2)         # 4 —— int
print(7.0 // 2)       # 3.0 —— 有 float,返回 float(值是整数但类型 float)
print(7 // 2.0)       # 3.0
print(-7.0 // 2)      # -4.0 —— float 地板
```

**核心规则:`//` 是"地板"(floor),向负无穷取整,不是向零截断**。这是与 C/Java 整数除法最大的区别:

```python
print(7 // 2)         # 3   —— 3.5 向负无穷 = 3(正数表现与 C 相同)
print(-7 // 2)        # -4  —— -3.5 向负无穷 = -4(C/Java 是 -3,向零截断!)
print(7 // -2)        # -4  —— -3.5 向负无穷 = -4
print(-7 // -2)       # 3   —— 3.5 向负无穷 = 3
```

理解这条规则的关键:地板除总是把商往**更小**(更负)的方向拉。`-7 / 2` 的真实商是 `-3.5`,向负无穷取整是 `-4`(因为 `-4 < -3.5 < -3`,`-4` 离负无穷更近)。而 C/Java 的整数除法是向零截断,直接丢掉小数部分得 `-3`。这个差异在处理坐标、分页、时间区间等带负数的除法时会引发隐蔽 bug。

**一个直观的记忆法**:`//` 的结果满足"`商 * 除数 <= 被除数`",永远不大于被除数方向。正数时与截断相同,负数时比截断再小 1。

⚠️ **`//` 在 float 时的精度陷阱**:当操作数含 float,`//` 会先做真除再取地板,中间的浮点误差可能让结果"偏一格":

```python
print(0.7 // 0.1)     # 6.0 —— 直觉是 7(0.7/0.1=7),但 0.7/0.1 实际 ≈ 6.999... 取地板得 6
print(0.7 / 0.1)      # 6.999999999999999 —— 看真相
```

`0.7 // 0.1` 得 `6.0` 而非 `7.0`,因为 `0.7 / 0.1` 受 float 精度影响是 `6.999...`,取地板是 6。这是 float 精度与 `//` 取整叠加的复合陷阱——需要精确的整数商时,务必用 int 操作数,或先 `round` 再 `//`,或用 `decimal`。

**`//` 与零**:同样抛 `ZeroDivisionError`:

```python
# print(7 // 0)       # ZeroDivisionError
# print(7.0 // 0)     # ZeroDivisionError
```

**何时用 `//`**:要整数商(分页 `page_index = offset // page_size`)、向下取整(`math.floor` 在 `//` 是 int 时等价)、计算"能完整分成几份"时。要小数商用 `/`。

### 2.6 取余 `%`(重点)

取余 `%` 返回除法的余数,它与 `//` 是一对——`a % b` 的值与 `a // b` 的商共同满足等式 **`a == (a // b) * b + (a % b)`**。理解了这个等式,就理解了 `%` 在负数下的全部行为。

**返回类型**:与 `//` 一致——全 int 返回 int,有 float 返回 float:

```python
print(7 % 2)          # 1 —— int
print(7.0 % 2)        # 1.0 —— float
print(7 % 2.0)        # 1.0
```

**核心规则:`%` 的余数符号与除数(b)相同**。这是 Python `%` 与 C/Java `%` 的关键差异:

```python
print(7 % 3)          # 1 —— 正常
print(-7 % 3)         # 2 —— Python:余数与除数同号(3 正,故余 2)
print(7 % -3)         # -2 —— 除数 -3 负,故余 -2
print(-7 % -3)        # -1 —— 除数负,余数负
```

用等式验证 `-7 % 3`:`-7 == (-7 // 3) * 3 + (-7 % 3)` → `-7 == (-3) * 3 + 2` → `-7 == -9 + 2` → `-7 == -7` ✓。其中 `-7 // 3` 是 `-3`(真实商 `-2.33`,向负无穷取整 `-3`),所以余数要补 `2` 才能让等式成立。这就是"余数与除数同号"的来源——它是地板除规则的数学推论。

⚠️ 而 C/Java 的 `%` 是"截断除法的余数",余数与**被除数**同号:`-7 % 3` 在 C 里是 `-1`。从 C 系语言迁来的开发者常在此处踩坑,尤其在写"环形索引""周期取模"逻辑时。Python 的规则对"环形/周期"场景更友好(见下方),但对"想得到截断余数"的场景需用 `math.fmod`。

**`%` 与 float 的精度陷阱**:与 `//` 同源,余数也受 float 误差干扰:

```python
print(1.0 % 0.1)      # 0.09999999999999995 —— 直觉是 0(1.0 是 0.1 的 10 倍),实际有误差
print(0.7 % 0.1)      # 0.09999999999999995
```

`1.0 % 0.1` 不是 `0` 而是 `0.0999...`,因为 `0.1` 在 float 里略偏大,`1.0 / 0.1` 实际是 `9.999...`,余下 `0.0999...`。需要精确取余时,改用 int(放大成整数单位)或 `decimal`。

**`%` 的经典应用一:奇偶判断**

```python
n = 7
print(n % 2 == 0)     # False —— 偶数为 True,奇数 False
print(n % 2 == 1)     # True
# 负数注意:n%2==1 对负奇数失败(-3 % 2 == 1,成立),但 n%2!=0 更通用
print(-3 % 2)         # 1 —— Python 余数与除数同号,负奇数 %2 仍是 1
print(-3 % 2 == 1)    # True —— Python 下成立(C 里 -3%2 是 -1,会失败)
```

Python 的"余数与除数同号"让 `n % 2 == 1` 对负奇数也成立,这是它比 C 友好的地方。但更稳妥的奇偶判断是 `n % 2 != 0`(奇数),避免依赖具体余数值。

**`%` 的经典应用二:环形索引 / 周期取模**

```python
# 循环列表(用 % 把索引拉回范围内)
items = ['a', 'b', 'c']
for i in range(7):
    print(items[i % len(items)], end=' ')
# 输出:a b c a b c a —— 超出范围的索引被 % 拉回
```

环形索引正是得益于"余数与除数同号且非负(除数为正时)"——无论 `i` 多大或为负,`i % len` 都落在 `[0, len)` 范围内,完美包裹。这是 Python `%` 规则的实战红利。

**`%` 的经典应用三:时间换算**

```python
total_seconds = 3661
hours = total_seconds // 3600          # 1
minutes = (total_seconds % 3600) // 60 # 1
seconds = total_seconds % 60           # 1
print(f"{hours}:{minutes}:{seconds}")  # 1:1:1
```

**`%` 与零**:`b == 0` 抛 `ZeroDivisionError`(包括 `7.0 % 0`);但 `a % 0.0`、`0 % 0` 都是 `ZeroDivisionError`。

**何时不该用 `%`,用 `math.fmod`**:当你需要"截断余数"(余数与被除数同号,即 C 风格行为)时,用 `math.fmod(a, b)`:

```python
import math
print(math.fmod(-7, 3))   # -1.0 —— 截断余数,与被除数同号(C 风格)
print(-7 % 3)             # 2 —— Python 地板余数,与除数同号
```

`math.fmod` 返回 `float`,语义是"截断除法的余数",适合"只想知道两个 float 相差几个完整周期、不关心方向"的场景(如信号处理求相位差)。

### 2.7 乘方 `**`(重点)

乘方 `**` 返回 `a` 的 `b` 次方。Python 把乘方做成运算符(用 `**` 而非函数),写法贴近数学,这是相对 C/Java 的一个易用性优势。

**返回类型**:类型规则比其他运算符更细致,取决于指数:

```python
print(2 ** 3)          # 8 —— int ** int(非负指数)→ int
print(2 ** 0)          # 1 —— 任何数的 0 次方是 1
print(2 ** -1)         # 0.5 —— 负指数 → float(因为结果是分数)
print(2 ** -2)         # 0.25
print(4 ** 0.5)        # 2.0 —— float 指数 → float(开平方)
print(4 ** -0.5)       # 0.5
print(2.0 ** 3)        # 8.0 —— float 底数 → float
print((-2) ** 2)       # 4 —— 负底数 + 整数指数 → int
print(2 ** 100)        # 1267650...024 —— 大整数仍精确(int 任意精度)
```

规则归纳:`int ** int`(指数 ≥ 0)→ `int`;一旦指数为负或为 float,或底数为 float → `float`。负底数配整数指数是合法的 `int`(如 `(-2)**3 = -8`),但负底数配**非整数**指数会得到 `complex`(因为负数开分数次方是复数):

```python
print((-8) ** (1/3))   # (1.732...+1j) —— 负底数 + 分数指数 → complex
# 想求实数立方根需用其他方法,如:
import math
print(-math.copysign(abs(-8) ** (1/3), -8))  # -2.0 —— 手动处理符号
```

⚠️ `**` 的优先级高于一元负号!这是一个高频陷阱:

```python
print(-2 ** 2)         # -4 —— 等价于 -(2**2),不是 (-2)**2
print((-2) ** 2)       # 4 —— 加括号才是 -2 的平方
```

`-2 ** 2` 被解析为 `-(2 ** 2)` = `-4`,因为 `**` 优先级比一元 `-` 高。想要"负 2 的平方"必须写 `(-2) ** 2`。这个细节在数学公式转代码时极易写错,务必加括号。

**`**` 与 `pow()` 的关系**:`pow(a, b)` 与 `a ** b` 等价;`pow(a, b, m)` 是三参数形式,做**模幂运算** `a**b % m`,且对大数高效(内部用快速幂,不生成中间大整数):

```python
print(pow(2, 10))           # 1024 —— 等价 2**10
print(pow(2, 10, 1000))     # 24 —— 2**10 % 1000,高效(密码学/RSA 常用)
print(pow(2, 100, 97))      # 又名模幂,大指数下远快于 (2**100)%97
```

三参数 `pow` 在密码学(模幂运算)、数论(费马小定理、大素数检验)中是标配,因为它避免先算出 `2**100` 这个巨大中间值。日常求幂用 `**`,需要模幂用 `pow(a, b, m)`。

**`0 ** 0` 与 `0 ** 负`**:`0 ** 0` 在 Python 是 `1`(遵循数学约定,虽在数学上有争议);`0 ** -1`(零的负次方)抛 `ZeroDivisionError`(因为等于 `1 / 0`):

```python
print(0 ** 0)          # 1
# print(0 ** -1)      # ZeroDivisionError: 0.0 cannot be raised to a negative power
```

**开方用 `** 0.5` 还是 `math.sqrt`**:`x ** 0.5` 与 `math.sqrt(x)` 对非负数结果一致,但 `math.sqrt` 对负数抛 `ValueError`(实数域),`** 0.5` 对负数返回 `complex`:

```python
import math
print(9 ** 0.5)            # 3.0
print(math.sqrt(9))        # 3.0
# print(math.sqrt(-1))     # ValueError
print((-1) ** 0.5)         # (0+1j) —— 返回复数
```

需要复数结果用 `** 0.5` 或 `cmath.sqrt`;需要纯实数且对负数报错用 `math.sqrt`。性能上 `math.sqrt` 略快(专门优化),但差异通常可忽略。

### 2.8 一元正号 `+x` 与一元负号 `-x`

一元运算符只有一个操作数,写在前面。`-x` 取负,`+x` 取正(几乎不用,主要用于触发数值转换或运算符重载对称性)。

```python
x = 5
print(-x)              # -5 —— 取负
print(+x)              # 5 —— 取正(基本无效果)
y = -3
print(-y)              # 3 —— 负负得正
print(+y)              # -3
```

**返回类型**:一元运算符不改变数值类型,`int` 仍是 `int`,`float` 仍是 `float`:

```python
print(type(-5))        # <class 'int'>
print(type(-5.0))      # <class 'float'>
print(type(+True))     # <class 'int'> —— bool 经一元运算也变 int
```

⚠️ 一个值得注意的细节:`+True` 返回 `int` 而非 `bool`——一元运算符会把 `bool` 提升为 `int`。这有时被用作"`bool` → `int`"的隐式转换技巧,但显式写 `int(True)` 更清晰,不建议依赖此副效应。

**`-x` 的精度**:对 float 取负不引入额外误差(只翻符号位),`-(0.1 + 0.2)` 与 `-0.1 - 0.2` 等价。但对"负零"有个小细节:

```python
print(-0.0)            # -0.0 —— 负零(float 有正零负零之分)
print(-0.0 == 0.0)     # True —— 比较时正负零相等
print(hash(-0.0) == hash(0.0))  # True —— 哈希也相同
```

`-0.0` 在比较和哈希上与 `0.0` 一致,但在 `math.copysign`、字符串显示上能区分。这是 IEEE 754 的特性,日常几乎无感。

### 2.9 算术运算符的优先级

算术运算符之间有固定的优先级(从高到低):

```
一元 + -  >  **  >  * / // %  >  二元 + -
```

即:一元符号和乘方最高,乘除取余次之,加减最低。同级运算从左到右结合(左结合),**但 `**` 是右结合**:

```python
print(2 + 3 * 4)        # 14 —— 先乘后加(* 优先)
print(2 * 3 ** 2)       # 18 —— 先乘方(** 优先于 *)
print(-2 ** 2)          # -4 —— ** 优先于一元 -,即 -(2**2)
print(2 ** 3 ** 2)      # 512 —— ** 右结合,即 2**(3**2) = 2**9
print(2 - 3 - 4)        # -5 —— 同级左结合,即 (2-3)-4
print(10 - 2 * 3 + 4)   # 8 —— 10 - 6 + 4
```

`**` 的右结合(`2 ** 3 ** 2` = `2 ** 9` 而非 `8 ** 2 = 64`)是它最特殊的属性,源自数学中 `a^b^c` 默认右结合的约定。这是新手常误判的点——很多人会以为 `2 ** 3 ** 2` 是 `64`。

**靠括号消除歧义**:优先级规则虽存在,但生产代码不应让人去背它。复杂表达式一律加括号明确意图,提升可读性、避免优先级误判:

```python
# 不推荐:依赖优先级,读者要心算
result = a + b * c ** 2 - d // e % f
# 推荐:括号明确分组
result = a + (b * (c ** 2)) - ((d // e) % f)
```

完整的运算符优先级(含比较、逻辑、位运算等)见本大章节《运算符优先级完整表》。本篇只关注算术运算符内部的优先级。

### 2.10 综合示例:算术运算符实战

下面这个片段集中演示算术运算符的典型用法与易错点,阅读时对照每段的行为:

```python
# 1. 基础四则与类型提升
print("=== 基础运算 ===")
print(f"3 + 5 = {3 + 5}, 类型 {type(3 + 5)}")        # 8, int
print(f"3 + 5.0 = {3 + 5.0}, 类型 {type(3 + 5.0)}")  # 8.0, float
print(f"True + 2 = {True + 2}")                       # 3,bool 提升

# 2. 除法三兄弟
print("=== 除法 ===")
total, count = 17, 5
print(f"真除 {total}/{count} = {total / count}")      # 3.4
print(f"地板 {total}//{count} = {total // count}")    # 3
print(f"取余 {total}%{count} = {total % count}")      # 2
print(f"验证等式: {total} == {(total//count)*count + total%count}")  # True

# 3. 负数下的 // 与 %(与 C 不同)
print("=== 负数除法 ===")
print(f"-7 // 3 = {-7 // 3} (Python 地板,C 是 -3)")   # -3
print(f"-7 % 3 = {-7 % 3} (余数与除数同号)")            # 2
print(f"7 // -3 = {7 // -3}")                          # -3
print(f"7 % -3 = {7 % -3}")                            # -2

# 4. 乘方与优先级陷阱
print("=== 乘方 ===")
print(f"2 ** 10 = {2 ** 10}")                          # 1024
print(f"-2 ** 2 = {-2 ** 2} (是 -(2**2),不是 4!)")    # -4
print(f"(-2) ** 2 = {(-2) ** 2}")                      # 4
print(f"2 ** 3 ** 2 = {2 ** 3 ** 2} (右结合 = 2**9)")  # 512
print(f"4 ** 0.5 = {4 ** 0.5} (开方,返回 float)")     # 2.0
print(f"pow(2,10,1000) = {pow(2, 10, 1000)} (模幂)")  # 24

# 5. 环形索引(利用 % 余数非负)
print("=== 环形索引 ===")
items = ['a', 'b', 'c', 'd']
for i in [-1, 0, 4, 7]:
    print(f"items[{i} % 4] = {items[i % len(items)]}")  # d a a c

# 6. 时间换算(// 与 % 配合)
print("=== 时间换算 ===")
secs = 7384
print(f"{secs}秒 = {secs//3600}时 {(secs%3600)//60}分 {secs%60}秒")  # 2时2分4秒

# 7. float 精度陷阱
print("=== 精度陷阱 ===")
print(f"0.1 + 0.2 == 0.3? {0.1 + 0.2 == 0.3}")         # False
print(f"0.7 // 0.1 = {0.7 // 0.1} (直觉 7,误差致 6)")  # 6.0
print(f"1.0 % 0.1 = {1.0 % 0.1} (直觉 0,误差致 0.099...)")  # 0.099...

# 8. 精确方案:int 存最小单位
print("=== 精确计算 ===")
total_cents = 499 * 3   # 用分,精确
print(f"499分 × 3 = {total_cents}分 = {total_cents/100:.2f}元")
```

跑一遍这段示例,对照输出:类型提升、除法三兄弟的联动、负数下 `//`/`%` 与 C 的差异、乘方优先级陷阱、`%` 的环形索引与时间换算应用、float 精度叠加 `//`/`%` 的复合陷阱、用 int 规避精度的方案——算术运算符的完整图景就清晰了。

## 3. 最佳实践

### 3.1 要整数商用 `//`,要小数商用 `/`,不要混用

```python
# 推荐:语义明确
page_index = offset // page_size      # 整数商,可做索引
avg = total / count                   # 小数商,精确平均

# 不推荐:误用 / 当整数商
idx = 8 / 2          # 4.0 —— float,不能做索引,后续 TypeError
data[8 / 2]          # TypeError: list indices must be integers
```

`/` 永远返回 `float`,`//` 返回符合操作数的类型。需要索引、计数、整数商必用 `//`;需要小数精确商用 `/`。把这两个分清是 Python 算术的头号守则,尤其对从 C/Java 迁来的人(C 的整数 `/` 行为与 Python 完全不同)。

### 3.2 负数取整取余,牢记"地板/除数同号"规则

```python
# Python: // 向负无穷,% 余数与除数同号
print(-7 // 3)   # -3 (不是 C 的 -2?错,Python 是 -3;正确记忆:向负无穷)
print(-7 % 3)    # 2 (余数与除数同号)

# 需要 C 风格截断余数时用 math.fmod
import math
print(math.fmod(-7, 3))  # -1.0
```

写涉及负数的除法/取模逻辑前,先用具体负数测一遍 `//` 和 `%` 的结果,确认与预期一致。需要"截断余数"(被除数同号)用 `math.fmod`。这个坑在分页边界、坐标计算、时间区间里极常见。

### 3.3 负底数乘方必须加括号,避免优先级误判

```python
# 推荐
area = (-x) ** 2          # 明确是 -x 的平方
# 不推荐
area = -x ** 2            # 实际是 -(x**2),数学意图缺失
```

`**` 优先级高于一元 `-`,`-x ** 2` 解析为 `-(x ** 2)`。数学公式中"负量的平方"必须写 `(-x) ** 2`。同理 `2 ** 3 ** 2` 是右结合 `2 ** 9 = 512`,需要 `(2 ** 3) ** 2 = 64` 时加括号。乘方相关的表达式,默认加括号更安全。

### 3.4 float 上的 `//` 和 `%` 会叠加精度误差,慎用

```python
# 危险:float 精度让 //、% 偏一格
print(0.7 // 0.1)    # 6.0 (直觉 7)
print(1.0 % 0.1)     # 0.0999... (直觉 0)

# 推荐:放大成 int 单位再 //、%
print(7 // 1)        # 7 —— 用整数分母
# 或用 Decimal
from decimal import Decimal
print(Decimal('0.7') // Decimal('0.1'))  # 7 —— 精确
```

float 的 `//`、`%` 是"先真除再取整",中间浮点误差会让结果偏离直觉一位。需要精确整数商/余数时,要么用 int 操作数(把量放大成整数单位),要么用 `decimal.Decimal`。绝不要直接对 float 用 `//`、`%` 然后和"理论整数"比较。

### 3.5 金额等精度敏感计算,绝不用 float 算术

```python
# 推荐:int 存最小单位,或 Decimal
total = 4999 * 3                       # int 存分
from decimal import Decimal
total = Decimal('49.99') * 3           # Decimal 精确

# 不推荐:float 算术会丢精度
total_bad = 49.99 * 3                  # 内部 149.9699...,账对不平
print(0.1 + 0.2 == 0.3)                # False
```

`+ - * /` 在 float 上都有精度误差,累加还会放大。货币、利率、税率等精度敏感场景,全体改用 int(存最小单位)或 `Decimal`(精确十进制)。这是算术运算的工程红线。详见《float 类型与精度问题》。

### 3.6 大数乘方与模幂,用三参数 `pow`,不要硬算

```python
# 推荐:模幂运算,高效且不生成巨大中间值
result = pow(base, exp, mod)           # 密码学/数论标配

# 不推荐:先算大幂再取模,内存与时间爆炸
result_bad = (base ** exp) % mod       # base**exp 可能是天文数字
```

`pow(a, b, m)` 内部用快速幂(平方求幂算法),复杂度 O(log b),且不生成 `a**b` 这个可能极巨大的中间整数。密码学(RSA)、大素数检验、组合取模都靠它。日常求大幂也优先 `pow` 而非 `**`(尤其结果巨大时)。

### 3.7 算术运算结果是新对象,不要误以为修改原变量

```python
x = 5
x + 1                 # 这行没有副作用!返回 6 但没赋值,x 仍是 5
print(x)              # 5

# 要更新必须重新赋值
x = x + 1             # 或 x += 1(增强赋值,本质也是重新赋值)
print(x)              # 6
```

`int`、`float` 不可变,算术运算返回新对象,不就地改。`x + 1` 单独一行是无效语句(虽不报错,但白写)。更新变量必须赋值回 `x`。增强赋值 `+=`、`-=` 等是语法糖,本质 `x = x + 1`,见《赋值运算符与增强赋值》。

### 3.8 除以零必须显式处理,不要假设除数非零

```python
# 推荐:检查或捕获
if count != 0:
    avg = total / count
else:
    avg = 0

try:
    ratio = a / b
except ZeroDivisionError:
    ratio = float('inf')   # 或其他业务定义值
```

`/`、`//`、`%` 在除数为零时一律抛 `ZeroDivisionError`,不返回 `inf` 或 `nan`。来自用户输入、配置、统计的除数可能为零,必须显式校验或 `try/except`,不要假设非零。这是健壮算术代码的基本要求。

### 3.9 链式比较与算术混用时,加括号明确意图

```python
# 算术与比较混用,优先级容易模糊
ok = 1 <= x + 1 < 10      # x+1 先算,再链式比较 —— 可读但易错
ok = 1 <= (x + 1) < 10    # 加括号更清晰

# 避免:把副作用运算塞进比较
if (n := compute()) > 0:  # 海象运算符可,但保持简洁
    ...
```

算术运算符优先级高于比较运算符(`+` 高于 `<`),所以 `x + 1 < 10` 无需括号,但复杂表达式加括号能让意图一目了然。详见《运算符优先级完整表》。

### 3.10 用 `divmod` 一次拿到商和余

```python
# 推荐:需要商和余时用 divmod,一次算完
quotient, remainder = divmod(17, 5)
print(quotient, remainder)   # 3 2

# 不推荐:// 和 % 各算一次,底层重复计算
quotient = 17 // 5
remainder = 17 % 5
```

`divmod(a, b)` 返回 `(a // b, a % b)` 元组,内部一次算出商和余,语义清晰且避免重复运算。需要同时用商和余(如分页、时间换算、进制转换)时首选 `divmod`。负数下遵循 Python 地板规则(`divmod(-7, 3)` = `(-3, 2)`)。

### 3.11 开方与特殊次方,选对工具

```python
import math

# 普通 0.5 次方(开平方):** 0.5 或 math.sqrt
print(9 ** 0.5)          # 3.0
print(math.sqrt(9))      # 3.0 (略快,但对负数报错)

# 立方根:负数要用 copysign 处理符号
print(-math.copysign(abs(-8) ** (1/3), -8))  # -2.0

# 复数开方:cmath
import cmath
print(cmath.sqrt(-1))    # 1j
```

`** 0.5` 通用但负数返回复数;`math.sqrt` 实数专用、对负数报错;负数立方根需手动处理符号;复数域用 `cmath`。按需选对工具,避免 `**` 在负数分数次方上意外返回 `complex` 污染后续实数逻辑。

### 3.12 别用 `^` 当乘方,那是按位异或

```python
# 错误:把 ^ 当乘方
print(2 ^ 10)     # 8 —— 这是按位异或!不是 1024

# 正确:乘方是 **
print(2 ** 10)    # 1024
```

Python 没有 C 的 `^` 作乘方(实际上 C 也没有乘方运算符),`^` 是按位异或。从其他语言或数学符号迁来的新手常犯此错。乘方只有 `**`(或 `pow` 函数)。位运算符详见《位运算符》。

## 4. 原理

本章讲清算术运算符行为背后的机制:为何 `/` 永远返回 float、`//` 为何向负无穷取整、`%` 余数为何与除数同号、类型提升的实现、乘方的右结合与模幂的快速幂原理。这些是"算术运算符为何如此"的根基。

### 4.1 `/` 为何永远返回 float:Python 3 的真除法决议

Python 2 时代,`/` 对两个 int 做整数除法(`8 / 2` 得 `4`),对含 float 的做真除。这让同一运算符的行为随操作数类型而变,是经典的"语义重载陷阱"——本想要小数商,写 `7 / 2` 却得 `3`(整数),悄悄丢精度。

Python 3 (PEP 238) 做了决断:**`/` 一律真除,永远返回 float**,把"取整数商"的职责完全交给 `//`。这个改变让 `/` 的语义单一稳定——"我要精确商就用 `/`,要整数商就用 `//`",不再因操作数类型而漂移。代价是迁移:Python 2 代码的整数 `/` 在 Python 3 会变 float,可能破坏依赖整数结果的逻辑(如索引、`isinstance` 检查)。为此 Python 2.2+ 引入了 `from __future__ import division` 让旧代码提前切换,3.x 则强制执行。

理解这条历史,就理解了"`/` 永远 float"不是随意的,而是 Python 为消除语义重载所做的深思熟虑的设计。这也解释了为何 `8 / 2` 是 `4.0` 而非 `4`——一致性优先于"看起来更整洁"。

### 4.2 `//` 向负无穷、`%` 余数与除数同号:地板除的数学一致性

`//` 和 `%` 的行为不是拍脑袋定的,而是遵循一条严格的数学不变量:**对任意 `a, b`(b≠0),恒有 `a == (a // b) * b + (a % b)`,且 `0 <= |a % b| < |b|` 且 `a % b` 与 `b` 同号**。

关键是"与除数同号"这个选择(Voorhees 选择)。数学上有两种合理的取整约定:

- **地板取整(floor)**:`//` 向负无穷取整,余数与**除数**同号。
- **截断取整(trunc)**:向零截断,余数与**被除数**同号(C/Java 的选择)。

以 `-7 / 3 = -2.333...` 为例:

| 约定 | 商 `//` | 余 `%` | 验证 `商*3 + 余` |
|------|--------|--------|------------------|
| 地板(Python) | -3(向负无穷) | 2(与除数3同号) | -3*3+2 = -7 ✓ |
| 截断(C/Java) | -2(向零) | -1(与被除数同号) | -2*3+(-1) = -7 ✓ |

两种约定都满足 `a == 商*b + 余` 等式,区别只在"商往哪取整"。Python 选地板的理由是:**`%` 的结果符号只取决于除数,不取决于被除数**,这让"环形/周期"运算更自然——`i % n`(n>0)的结果恒在 `[0, n)` 范围内,无论 `i` 正负,完美包裹。而 C 的截断约定下 `-1 % 5` 是 `-1`,落在 `[-4, 4]`,做环形索引前还要再加 `n` 修正,啰嗦且易错。

```python
# Python 地板约定的红利:环形索引无需修正
n = 5
for i in [-6, -1, 0, 6]:
    print(i % n, end=' ')   # 4 4 0 1 —— 全落在 [0,5),无需处理负数
```

理解这条原理,就理解了 Python `//`/`%` 看似反直觉的负数行为,实则是为"周期/环形"语义做的优化设计,数学上完全自洽。需要截断语义时用 `math.fmod` 显式切换。

### 4.3 类型提升:数值塔与隐式转换

Python 的数值类型有一条隐式提升链 `bool → int → float → complex`,源于"数值塔"(numeric tower,PEP 3141)概念:较窄类型可无损提升为较宽类型。算术运算时,解释器把两操作数提升到同一类型再运算,结果取较宽类型。

```python
# 提升链体现
print(type(True + 1))      # int —— bool 提升为 int
print(type(1 + 1.0))       # float —— int 提升为 float
print(type(1.0 + 1j))      # complex —— float 提升为 complex
```

实现上,每个数值类型的 C 层实现定义了与"邻居类型"的运算转换。`int` 与 `float` 混算时,`int` 先转 `float` 再做浮点运算;`float` 与 `complex` 混算时,`float` 转成实部为该值的 `complex`。这套机制让 `3 + 0.5` 自然得 `3.5`,无需显式转换。

⚠️ 但提升不是任意双向的:`complex` 不能隐式降回 `float`,`float` 不能隐式当 `int` 用做索引。且 `complex` 不支持 `//`、`%`(因为复数无"大小比较"、无"地板"概念),只能做 `+ - * / **`。这是数值塔"越宽越受限于实数运算能力"的体现。

理解类型提升,就理解了"算术结果何时从 int 变 float"——一旦混入更宽类型,结果跟着变宽,精度特性也随之改变(int 精确 → float 近似)。这是为何"金额混入一个 float 就全盘被污染"的根源。

### 4.4 乘方的右结合与模幂的快速幂原理

`**` 是右结合(`2 ** 3 ** 2` = `2 ** (3 ** 2)`),这与数学中幂塔 `a^b^c` 的约定一致(幂运算是右结合的二元运算)。实现上,解析器把 `a ** b ** c` 构造为 `a ** (b ** c)` 的语法树,而非 `(a ** b) ** c`。原因:`(a ** b) ** c = a ** (b * c)`,右结合形式 `a ** (b ** c)` 才是真正"嵌套的幂",数学上有独立意义。

```python
print(2 ** 3 ** 2)        # 512 = 2**9,右结合
print((2 ** 3) ** 2)      # 64 = 8**2 = 2**6,左结合只是乘法展开
```

**三参数 `pow(a, b, m)` 的快速幂原理**:朴素算 `a ** b % m` 要先把 `a ** b` 算出来——当 `b` 很大(如百万位),`a ** b` 是天文数字,内存与时间都炸。快速幂(modular exponentiation)利用两条数学性质:

1. `a^b mod m = (a^(b//2) mod m)^2 mod m`(b 为偶数,折半)
2. `a^b mod m = (a · a^(b-1) mod m) mod m`(b 为奇数,抽一个 a)

每步都对 `m` 取模,中间值永远小于 `m^2`,复杂度 O(log b)。例如 `pow(2, 10, 1000)`:

```
2^10 % 1000
= (2^5 % 1000)^2 % 1000       # 偶数折半
= (32)^2 % 1000               # 2^5 = 32
= 1024 % 1000 = 24
```

中间最大数是 `32^2 = 1024`,远小于直接算 `2^10 = 1024`(本例差距小,但 `b` 上百万时差距是天文)。密码学 RSA 的核心运算 `m^e mod n`(e 是大整数)全靠快速幂,否则根本算不动。Python 的 `pow(a, b, m)` 在 C 层直接调用 GMP 等大数库的快速幂实现,极致高效。理解此原理,就理解了"大幂取模必须用三参数 pow"的性能依据。

### 4.5 算术运算的对象模型:协议方法与不可变性

Python 的算术运算符不是硬编码的,而是通过**协议方法(dunder)**实现的。每个算术运算符对应一对正/反方法:

| 运算符 | 正向方法 | 反向方法 |
|--------|---------|----------|
| `+` | `__add__` | `__radd__` |
| `-` | `__sub__` | `__rsub__` |
| `*` | `__mul__` | `__rmul__` |
| `/` | `__truediv__` | `__rtruediv__` |
| `//` | `__floordiv__` | `__rfloordiv__` |
| `%` | `__mod__` | `__rmod__` |
| `**` | `__pow__` | `__rpow__` |

`a + b` 执行时,解释器先试 `a.__add__(b)`;若 `a` 不支持(返回 `NotImplemented`)或 `b` 的类型是 `a` 的子类,再试 `b.__radd__(a)`。这套双分派机制让自定义类型能重载算术运算符(如 `Decimal + Decimal`、`numpy 数组 + 标量`),也让 `int + float` 能正确路由(`int.__add__(float)` 不支持,转而用 `float.__radd__(int)`)。

```python
# 自定义类型重载 +
class Price:
    def __init__(self, cents): self.cents = cents
    def __add__(self, other): return Price(self.cents + other.cents)
    def __repr__(self): return f"Price({self.cents}分)"

print(Price(100) + Price(200))   # Price(300分)
```

`int`、`float` 自身的方法由 C 层实现,但走的是同一套协议。这也是为何 `True + True` 能得 `2`、`"a" + "b"` 能拼接——它们各自的类型定义了 `__add__`,赋予 `+` 不同的语义(多态)。

**不可性性的体现**:协议方法返回**新对象**而非修改自身,这是 `int`/`float` 不可变的实现保证。`x + 1` 调 `int.__add__`,创建并返回新 `int`,原 `x` 不动。理解协议方法,就理解了算术运算符本质是"方法调用的语法糖",以及为何它能被各种类型重载、为何结果总是新对象。运算符重载详见《面向对象 OOP 全套》。

## 5. 总结

### 5.1 本文内容回顾

- **算术运算符全表**:`+ - * / // % **` 七个二元运算符加 `+x -x` 两个一元运算符;Python 与 C/Java 三大差异——`/` 永远 float、`//` 向负无穷地板除、`**` 是乘方(`^` 是异或非乘方)。
- **类型提升**:`bool → int → float → complex` 向更宽类型隐式提升,只要运算中有 float 结果即 float(精度特性随之变),有 complex 结果即 complex(complex 不支持 `//`、`%`)。
- **加法/减法/乘法**:`+ - *` 遵循隐式提升,float 上有精度误差;多态重载——`+` 拼接序列/字符串,`*` 重复序列(`[[]] * n` 嵌套引用陷阱)。
- **真除 `/`**(重点):永远返回 float(无论是否整除),不能做索引;除零抛 ZeroDivisionError;Python 3 相对 Python 2 的真除决议(PEP 238)。
- **地板除 `//`**(重点):向负无穷取整(`-7 // 2 = -4`,与 C 的 -3 不同);返回类型"全 int→int,有 float→float";float 上叠加精度误差可偏一格(`0.7 // 0.1 = 6.0`)。
- **取余 `%`**(重点):余数与除数同号,满足 `a == (a//b)*b + a%b`;负数行为与 C 不同(`-7 % 3 = 2`);环形索引/周期取模/时间换算的经典应用;float 精度陷阱(`1.0 % 0.1 ≈ 0.099`);需 C 风格截断余数用 `math.fmod`。
- **乘方 `**`**(重点):`int ** int(非负)`→int,负/float 指数→float,负底数+分数指数→complex;优先级高于一元负号(`-2**2 = -4`);右结合(`2**3**2 = 512`);三参数 `pow(a,b,m)` 做高效模幂;开方 `**0.5` vs `math.sqrt` vs `cmath.sqrt`。
- **一元 `+ -`**:取正取负,不改变类型;`+True` 把 bool 提升 int;`-0.0` 负零(比较与哈希同 0.0)。
- **优先级**:一元/`**` > `* / // %` > `+ -`;`**` 右结合其余左结合;复杂表达式加括号消除歧义。
- **综合实战**:类型提升、除法三兄弟联动、负数 `//`/`%`、乘方陷阱、环形索引、时间换算、float 精度叠加、int 规避精度的完整 demo。
- **最佳实践**:`/` vs `//` 分清、负数取整记忆规则、负底数乘方加括号、float 上 `//`/`%` 慎用、金额不用 float、大数模幂用 `pow(a,b,m)`、算术结果须重新赋值、除零显式处理、`divmod` 取商余、开方选对工具、`^` 不是乘方。
- **原理**:`/` 真除决议(PEP 238)消除语义重载;`//`/`%` 地板约定满足 `a==商*b+余` 并让周期运算自然;类型提升源于数值塔(PEP 3141);`**` 右结合因幂塔数学约定,`pow(a,b,m)` 用快速幂 O(log b);算术运算符是协议方法(`__add__` 等)双分派的语法糖,结果新对象体现不可变性。
