## 1. 介绍

### 1.1 什么是集合的数学运算

Python 的 `set` 类型不仅仅是存储不重复元素的数据结构，它完整地实现了数学中集合论（Set Theory）的四大基本运算——并集（Union）、交集（Intersection）、差集（Difference）和对称差集（Symmetric Difference）。这些运算是集合类型区别于列表（list）和元组（tuple）的核心特性之一，也是在很多编程场景中选用集合而非其他容器的重要原因。

在数学中，集合运算描述的是两个（或多个）集合之间元素关系的操作：

- **并集**：合并两个集合的所有元素，重复的只保留一份。
- **交集**：找出两个集合共同拥有的元素。
- **差集**：从一个集合中去除另一个集合也包含的元素。
- **对称差集**：找出两个集合中"只出现在其中一个集合中的元素"——即并集减去交集得到的结果。

Python 为每种运算都提供了两种调用方式：**方法调用**（如 `A.union(B)`）和**运算符**（如 `A | B`）。此外，每种运算还提供了**原地修改版本**（如 `A.update(B)`、`A |= B`），可以直接更新调用方的集合对象。

掌握集合运算，可以用极简的代码解决原本需要多重循环和条件判断的复杂问题——例如数据去重对比、权限集计算、标签筛选、版本差异分析等。

### 1.2 四种运算的总览

为便于后文展开，先通过一张示意图描述四种运算的直观含义。

假设有两个集合，表示两个不同的用户群体：

```python
# 两个用户群体：订阅用户 和 VIP 用户
subscribers = {"Alice", "Bob", "Charlie", "David"}
vip_users = {"Charlie", "David", "Eve", "Frank"}

# 并集：所有用户（去重）
# {"Alice", "Bob", "Charlie", "David", "Eve", "Frank"}
union_result = subscribers | vip_users

# 交集：同时是订阅用户和 VIP 的用户
# {"Charlie", "David"}
intersection_result = subscribers & vip_users

# 差集：订阅用户中不是 VIP 的用户
# {"Alice", "Bob"}
difference_result = subscribers - vip_users

# 对称差集：只属于其中一个群体的用户
# {"Alice", "Bob", "Eve", "Frank"}
sym_diff_result = subscribers ^ vip_users
```

运行结果：

```
并集: {'Charlie', 'Alice', 'David', 'Bob', 'Frank', 'Eve'}
交集: {'Charlie', 'David'}
差集 (subscribers - vip_users): {'Alice', 'Bob'}
对称差集: {'Alice', 'Bob', 'Frank', 'Eve'}
```

需要注意的是，集合是无序的，所以输出元素顺序可能与上面注释中的手写集合字面量顺序不一致。后文所有 demo 中，我们会用 `sorted()` 输出以便结果可预期比对。

### 1.3 方法的共用签名约定

在深入每个具体运算之前，先了解所有集合运算方法的调用约定。每种运算有返回新集合的版本（非原地）和修改原集合的版本（原地）：

| 运算 | 返回新集合 | 原地修改 | 运算符 |
|------|-----------|----------|--------|
| 并集 | `union(*others)` | `update(*others)` | `\|` |
| 交集 | `intersection(*others)` | `intersection_update(*others)` | `&` |
| 差集 | `difference(*others)` | `difference_update(*others)` | `-` |
| 对称差集 | `symmetric_difference(other)` | `symmetric_difference_update(other)` | `^` |

关键差异：

- 方法调用的参数 `*others` 表示可以接受**一个或多个可迭代对象**（list、tuple、set、甚至是字符串和字典的键视图等）。
- 运算符（`|`、`&`、`-`、`^`）要求**左右两个操作数都必须是 `set` 类型**（或 `frozenset`）。
- 原地修改版本没有返回值（返回 `None`），`update`、`intersection_update`、`difference_update` 可以接受多个可迭代对象作为参数；`symmetric_difference_update` 只接受一个参数。
- 所有方法的参数都会在内部被隐式转换为集合后再参与运算——这意味着你可以向这些方法传递列表、元组等序列，而不必先手动 `set()` 转换。

## 2. 核心内容

### 2.1 并集运算（Union）

#### 2.1.1 方法：`union()`

`union(*others)` 返回一个新集合，包含原集合与所有 `others` 中元素的并集。

**适用场景**

当需要将多个来源的数据合并为一个去重的全集时，使用并集是最直接的方式。例如合并多个渠道的客户名单、汇总多个维度的标签体系、合并不同节点的监控告警规则等。

```python
# 场景：合并三个销售区域的客户名单，找出总客户集
region_a = {"张三", "李四", "王五"}
region_b = {"李四", "赵六", "孙七"}
region_c = {"王五", "孙七", "周八"}

# 使用 union() 方法合并三个区域
all_customers = region_a.union(region_b, region_c)
print(f"全部客户（去重）: {sorted(all_customers)}")
print(f"客户总数: {len(all_customers)}")
```

运行结果：

```
全部客户（去重）: ['张三', '李四', '王五', '赵六', '孙七', '周八']
客户总数: 6
```

**方法接受任意可迭代对象**

`union()` 的优胜之处在于，它的参数不必是 `set`，可以是列表、元组、甚至字典：

```python
# 场景：向已有客户集追加通过 API 获取的新客户列表
existing = {"张三", "李四"}
new_from_api = ["王五", "赵六", "张三"]  # 列表，注意张三已存在
new_from_batch = ("孙七", "周八")        # 元组

# union() 可以直接接受列表和元组作为参数
merged = existing.union(new_from_api, new_from_batch)
print(f"合并后: {sorted(merged)}")
```

运行结果：

```
合并后: ['张三', '李四', '王五', '赵六', '孙七', '周八']
```

注意 `new_from_api` 列表中的 `"张三"` 原本已存在于 `existing` 中，但在并集结果中只出现一次——因为 `union()` 自动去重。

**传递字符串作为参数**

字符串也是可迭代对象，传入 `union()` 会按字符拆开：

```python
# 场景：注意——字符串是可迭代的，如果无意中传入字符串会得到意想不到的结果
tags = {"python", "java"}
unexpected = tags.union("golang")  # 字符串被拆为字符
print(f"传入字符串的结果: {sorted(unexpected)}")

# 正确的做法应该是传入单个元素的容器
expected = tags.union(["golang"])
print(f"正确传入的结果: {sorted(expected)}")
```

运行结果：

```
传入字符串的结果: ['a', 'g', 'java', 'l', 'n', 'o', 'python']
正确传入的结果: ['golang', 'java', 'python']
```

这是一个容易出错的地方，在后面最佳实践部分还会进一步强调。

#### 2.1.2 运算符：`|`

`|` 运算符实现与 `union()` 相同的功能，但要求两侧都是 `set`（或 `frozenset`）类型。

```python
# 场景：计算两个配置文件中的特性开关合集
config_a = {"feature_x", "feature_y", "feature_z"}
config_b = {"feature_y", "feature_w", "feature_v"}

# 使用 | 运算符
combined = config_a | config_b
print(f"特性开关全集: {sorted(combined)}")
```

运行结果：

```
特性开关全集: ['feature_v', 'feature_w', 'feature_x', 'feature_y', 'feature_z']
```

**方法与运算符的行为差异对比**

这是整个集合运算中最关键的一个区别点，务必理解：

```python
# 方法 vs 运算符：参数类型的灵活性对比
base = {1, 2, 3}

# 方法接受任何可迭代对象
result_method = base.union([4, 5, 6], (7, 8), "ab")
print(f"union() 方法（灵活）: {sorted(result_method)}")

# 运算符要求操作数都是 set
result_operator = base | {4, 5, 6}  # 正确

# 下面这行如果取消注释会 TypeError，因为右侧是 list，不是 set
# result_error = base | [4, 5, 6]  # TypeError: unsupported operand type(s) for |: 'set' and 'list'
```

运行结果：

```
union() 方法（灵活）: [1, 2, 3, 4, 5, 6, 7, 8, 'a', 'b']
```

#### 2.1.3 原地版本：`update()` 和 `|=`

`update(*others)` 和 `|=` 不返回新集合，而是把结果直接写回到调用它的集合对象上。`update()` 接受任意可迭代对象，`|=` 要求右侧为 `set`。

```python
# 场景：动态收集服务器上发现的所有开放端口
open_ports = {80, 443, 22}

# 第一次扫描发现的额外开放端口
new_ports_scan1 = [8080, 8443]
open_ports.update(new_ports_scan1)
print(f"第一次扫描后: {sorted(open_ports)}")

# 第二次扫描
new_ports_scan2 = {3306, 5432}
open_ports |= new_ports_scan2
print(f"第二次扫描后: {sorted(open_ports)}")
```

运行结果：

```
第一次扫描后: [22, 80, 443, 8080, 8443]
第二次扫描后: [22, 80, 443, 3306, 5432, 8080, 8443]
```

注意原地版本没有返回值，返回 `None`：

```python
ports = {80, 443}
result = ports.update({8080})
print(f"ports: {ports}")
print(f"update() 返回值: {result}")
```

运行结果：

```
ports: {80, 443, 8080}
update() 返回值: None
```

#### 2.1.4 多个参数的并集链式调用

`union()` 和 `update()` 都支持可变参数，一次性合并任意多个集合：

```python
# 场景：聚合来自五个不同数据源的记录 ID
source1 = {"id_001", "id_002"}
source2 = {"id_002", "id_003"}
source3 = {"id_003", "id_004"}
source4 = {"id_005"}
source5 = {"id_006"}

# 一次性合并五个来源
all_ids = set().union(source1, source2, source3, source4, source5)
print(f"全部记录 ID（去重）: {sorted(all_ids)}")

# 如果使用 | 运算符，则需要链式书写
all_ids_op = source1 | source2 | source3 | source4 | source5
print(f"运算符链式: {sorted(all_ids_op)}")
```

运行结果：

```
全部记录 ID（去重）: ['id_001', 'id_002', 'id_003', 'id_004', 'id_005', 'id_006']
运算符链式: ['id_001', 'id_002', 'id_003', 'id_004', 'id_005', 'id_006']
```

### 2.2 交集运算（Intersection）

#### 2.2.1 方法：`intersection()`

`intersection(*others)` 返回一个新集合，包含原集合与所有 `others` 的公共元素——即同时存在于所有传入集合中的元素。

**适用场景**

交集特别适合做"筛选满足所有条件"的数据。比如：同时订阅了某个频道的用户、同时通过了所有测试的代码、同时在多个库存地有货的商品等。

```python
# 场景：找出同时购买了三种不同产品的客户（用于交叉营销）
product_a_buyers = {"张三", "李四", "王五", "赵六"}
product_b_buyers = {"李四", "王五", "孙七", "周八"}
product_c_buyers = {"王五", "赵六", "周八", "吴九"}

# 三种产品都购买的客户
cross_buyers = product_a_buyers.intersection(product_b_buyers, product_c_buyers)
print(f"同时购买了三种产品的客户: {sorted(cross_buyers)}")
```

运行结果：

```
同时购买了三种产品的客户: ['王五']
```

如果传入的可迭代对象中没有任何公共元素，结果为空集合：

```python
# 场景：检查两组标签是否有交叉
group_a = {"前端", "后端"}
group_b = {"运维", "安全"}

overlap = group_a.intersection(group_b)
print(f"是否有共同标签: {bool(overlap)}, 交集: {overlap}")
```

运行结果：

```
是否有共同标签: False, 交集: set()
```

空集合在打印时显示为 `set()` 而不是 `{}`——因为 `{}` 是空字典的字面量。

**与并集一样，接受任意可迭代对象**：

```python
# 场景：从集合中找出也出现在某个列表中的元素
allowed_users = {"Alice", "Bob", "Charlie", "David"}
blacklist = ["Charlie", "Eve"]  # 列表，不是集合

# intersection() 直接接受列表
allowed_clean = allowed_users.intersection(blacklist)
print(f"不在黑名单中的用户: {sorted(allowed_clean)}")

# 如果用 & 运算符则需要先转换
allowed_clean_op = allowed_users & set(blacklist)
print(f"运算符版本（需手动转换）: {sorted(allowed_clean_op)}")
```

运行结果：

```
不在黑名单中的用户: ['Charlie']
运算符版本（需手动转换）: ['Charlie']
```

#### 2.2.2 运算符：`&`

`&` 运算符实现交集，要求两侧都是 `set`。

```python
# 场景：找出同时属于两个权限组的用户
admin_users = {"Alice", "Bob", "Charlie"}
audit_users = {"Charlie", "David", "Eve"}

# 同时拥有管理权限和审计权限的用户
super_users = admin_users & audit_users
print(f"超级管理员（双重权限）: {sorted(super_users)}")
```

运行结果：

```
超级管理员（双重权限）: ['Charlie']
```

#### 2.2.3 原地版本：`intersection_update()` 和 `&=`

`intersection_update(*others)` 用交集结果替换原集合的内容，不返回新值。

```python
# 场景：逐步筛选数据——从候选名单中不断缩小范围
candidates = {"张三", "李四", "王五", "赵六", "孙七", "周八"}

# 条件 1：拥有本科学历
bachelor = {"李四", "王五", "赵六", "周八"}
candidates.intersection_update(bachelor)
print(f"条件 1 筛选后: {sorted(candidates)}")

# 条件 2：工作经验 >= 3 年
experience_3y = {"李四", "赵六", "孙七"}
candidates &= experience_3y  # 等价于 candidates.intersection_update(experience_3y)
print(f"条件 2 筛选后: {sorted(candidates)}")

# 条件 3：通过技术面试
passed_interview = {"赵六"}
candidates &= passed_interview
print(f"条件 3 筛选后: {sorted(candidates)}")
```

运行结果：

```
条件 1 筛选后: ['李四', '王五', '赵六', '周八']
条件 2 筛选后: ['李四', '赵六']
条件 3 筛选后: ['赵六']
```

**多个集合的交集**：和 `union()` 一样，`intersection()` 和 `intersection_update()` 可以接受多个参数：

```python
# 场景：找出同时在三个系统中的活跃用户
system_a = {"user1", "user2", "user3", "user4"}
system_b = {"user2", "user3", "user5", "user6"}
system_c = {"user3", "user4", "user6", "user7"}

# 三个系统都活跃的用户
active_all = system_a.intersection(system_b, system_c)
print(f"三个系统都活跃: {sorted(active_all)}")
```

运行结果：

```
三个系统都活跃: ['user3']
```

#### 2.2.4 交集的边界情况

```python
# 空集合与任意集合的交集为空
empty = set()
result = {1, 2, 3}.intersection(empty)
print(f"与空集合的交集: {result}")

# 集合与其自身的交集等于它自己
result_self = {1, 2, 3}.intersection({1, 2, 3})
print(f"与自身的交集: {sorted(result_self)}")

# 多个参数中只要有一个为空，结果就是空
result_multi = {1, 2, 3}.intersection({2, 3, 4}, empty)
print(f"包含空集的多个交集: {result}")
```

运行结果：

```
与空集合的交集: set()
与自身的交集: [1, 2, 3]
包含空集的多个交集: set()
```

### 2.3 差集运算（Difference）

#### 2.3.1 方法：`difference()`

`difference(*others)` 返回一个新集合，包含在原集合中但**不在任何** `others` 中的元素。通俗地说就是"从 A 中剔除 B 的元素"。

**适用场景**

差集在"排除"类场景中非常有用：排除已处理过的记录、排除被封禁的用户、从完整的权限集中减去某些角色的权限、计算尚未完成的任务等。差集是有方向性的操作，`A.difference(B)` 和 `B.difference(A)` 通常结果不同。

```python
# 场景：计算已报名的用户中，哪些还没有完成支付
registered = {"Alice", "Bob", "Charlie", "David", "Eve"}
paid = {"Bob", "David", "Frank"}  # Frank 没报名但也付了款

# 已报名但未支付 = 报名集 - 已支付集
unpaid = registered.difference(paid)
print(f"已报名未支付的用户: {sorted(unpaid)}")

# 注意：差集运算不会因为 "Frank" 在 paid 中但不在 registered 中而影响结果
# difference() 只关心 "在 registered 中、但不在 paid 中的元素"
```

运行结果：

```
已报名未支付的用户: ['Alice', 'Charlie', 'Eve']
```

**差集的方向性对比**：

```python
# 场景：理解差集的有向性
team_a = {"张三", "李四", "王五"}
team_b = {"李四", "赵六", "孙七"}

# A - B：在 A 中但不在 B 中的元素
a_minus_b = team_a.difference(team_b)
print(f"A - B: {sorted(a_minus_b)}")

# B - A：在 B 中但不在 A 中的元素
b_minus_a = team_b.difference(team_a)
print(f"B - A: {sorted(b_minus_a)}")
```

运行结果：

```
A - B: ['张三', '王五']
B - A: ['赵六', '孙七']
```

**从多个集合中排除**：`difference()` 可以接受多个参数，效果是从原集合中排除所有传入参数中出现的元素：

```python
# 场景：从总用户中排除所有有负面标签的用户
all_users = {"Alice", "Bob", "Charlie", "David", "Eve", "Frank"}
banned = {"Bob"}
inactive = {"Charlie", "Frank"}
suspended = {"David"}

# 一次性排除所有负面标签用户
active_users = all_users.difference(banned, inactive, suspended)
print(f"活跃可用用户: {sorted(active_users)}")

# 等价的链式差集写法
active_users_chain = all_users - banned - inactive - suspended
print(f"运算符链式: {sorted(active_users_chain)}")
```

运行结果：

```
活跃可用用户: ['Alice', 'Eve']
运算符链式: ['Alice', 'Eve']
```

#### 2.3.2 运算符：`-`

`-` 运算符实现差集，要求两侧都是 `set`。

```python
# 场景：从权限集中移除某个角色的权限
base_permissions = {"read", "write", "delete", "admin"}
guest_permissions = {"read", "write"}

# 管理员权限 = 基础权限 - 游客权限
admin_perms = base_permissions - guest_permissions
print(f"管理员独有权限: {sorted(admin_perms)}")
```

运行结果：

```
管理员独有权限: ['admin', 'delete']
```

#### 2.3.3 原地版本：`difference_update()` 和 `-=`

`difference_update(*others)` 在原集合上直接剔除所有出现在参数中的元素。

```python
# 场景：从待处理任务列表中移除已完成的任务
pending_tasks = {"task_001", "task_002", "task_003", "task_004", "task_005"}
completed = {"task_002", "task_004"}

pending_tasks.difference_update(completed)
print(f"剩余待处理任务: {sorted(pending_tasks)}")

# 再次用 -= 移除紧急转出的任务
transferred = {"task_003"}
pending_tasks -= transferred
print(f"转出后剩余任务: {sorted(pending_tasks)}")
```

运行结果：

```
剩余待处理任务: ['task_001', 'task_003', 'task_005']
转出后剩余任务: ['task_001', 'task_005']
```

**接受多个参数**：

```python
# 场景：从候选词中同时排除禁用词和敏感词
candidate_words = {"apple", "banana", "admin", "password", "orange"}
banned_words = {"admin", "root"}
sensitive_words = {"password", "secret"}

candidate_words.difference_update(banned_words, sensitive_words)
print(f"过滤后的候选词: {sorted(candidate_words)}")
```

运行结果：

```
过滤后的候选词: ['apple', 'banana', 'orange']
```

#### 2.3.4 差集的边界情况

```python
# 从集合中差集掉自身，得到空集
s = {1, 2, 3}
result = s.difference(s)
print(f"集合减自身: {result}")

# 从集合中差集掉一个不存在的元素，集合不变
result2 = s.difference({100, 200})
print(f"减不存在的元素: {sorted(result2)}")

# 从空集合中做差集，始终为空
result3 = set().difference({1, 2, 3})
print(f"空集减其他: {result3}")
```

运行结果：

```
集合减自身: set()
减不存在的元素: [1, 2, 3]
空集减其他: set()
```

### 2.4 对称差集运算（Symmetric Difference）

#### 2.4.1 方法：`symmetric_difference()`

`symmetric_difference(other)` 返回一个新集合，包含**只在其中一个集合中出现、不在两个集合中同时出现**的元素。数学公式为 `(A - B) | (B - A)`，等价于并集减去交集。

**适用场景**

对称差集适用于"找出两边的差异部分"的场景：比如审计时找出两个版本的数据异同、检测配置文件发生了哪些变化、找出两个团队各自独有的成员而不关心共有的成员等。

```python
# 场景：找出两个 Git 分支各自有但对方没有的提交（不关心共同祖先）
branch_a_commits = {"c001", "c002", "c003", "c004"}
branch_b_commits = {"c003", "c004", "c005", "c006"}

# 找出两边的差异提交
diff_commits = branch_a_commits.symmetric_difference(branch_b_commits)
print(f"两分支的差异提交（对称差集）: {sorted(diff_commits)}")

# 这个结果等价于并集减去交集
union = branch_a_commits | branch_b_commits
intersection = branch_a_commits & branch_b_commits
diff_commits_manual = union - intersection
print(f"通过并集-交集验证: {sorted(diff_commits_manual)}")
```

运行结果：

```
两分支的差异提交（对称差集）: ['c001', 'c002', 'c005', 'c006']
通过并集-交集验证: ['c001', 'c002', 'c005', 'c006']
```

**重要差异**：与 `union()`、`intersection()`、`difference()` 不同，`symmetric_difference()` **只接受一个参数**，不支持多个参数。

```python
# symmetric_difference() 只接受一个参数
a = {1, 2, 3}
b = {2, 3, 4}
c = {3, 4, 5}

result = a.symmetric_difference(b)
print(f"a 与 b 的对称差集: {sorted(result)}")

# 如果要计算三个集合的对称差集，需要链式调用
# 注意：symmetric_difference 的结果是 A ^ B，再与 C 做对称差集得到的是 (A ^ B) ^ C
result_3 = a.symmetric_difference(b).symmetric_difference(c)
print(f"a、b、c 三者的对称差集: {sorted(result_3)}")
```

运行结果：

```
a 与 b 的对称差集: [1, 4]
a、b、c 三者的对称差集: [1, 3, 5]
```

#### 2.4.2 运算符：`^`

`^` 运算符实现对称差集，要求两侧都是 `set`。

```python
# 场景：找出两个配置文件中不同的配置项
config_v1 = {"host=localhost", "port=8080", "debug=true"}
config_v2 = {"host=localhost", "port=9090", "loglevel=info"}

changed = config_v1 ^ config_v2
print(f"发生变化的配置项: {sorted(changed)}")
```

运行结果：

```
发生变化的配置项: ['debug=true', 'loglevel=info', 'port=9090', 'port=8080']
```

#### 2.4.3 原地版本：`symmetric_difference_update()` 和 `^=`

用对称差集的结果替换原集合，不返回新值。同样只接受一个参数。

```python
# 场景：在购物车中切换某个商品的选中状态——如果已选中则取消，未选中则加入
selected_items = {"item_001", "item_003", "item_005"}

# 用户点击了 item_003（已在选中列表里）和 item_007（未在列表中）
toggle_items = {"item_003", "item_007"}

selected_items.symmetric_difference_update(toggle_items)
print(f"切换后的选中状态: {sorted(selected_items)}")
# item_003 原来在 selected_items 中，被移除了
# item_007 原来不在 selected_items 中，被加入了

# 再次用 ^= 切换
toggle_items2 = {"item_001"}
selected_items ^= toggle_items2
print(f"再次切换后: {sorted(selected_items)}")
# item_001 原来在 selected_items 中，被移除了
```

运行结果：

```
切换后的选中状态: ['item_001', 'item_005', 'item_007']
再次切换后: ['item_005', 'item_007']
```

对称差集的这个"翻转"特性非常适合实现**切换**（toggle）行为——一个元素如果在集合中，对称差集操作后会被移除；如果不在，则会被加入。

```python
# 场景：用对称差集实现简单的在线状态切换
online_users = {"Alice", "Bob", "Charlie"}

def toggle_online(user: str):
    """切换用户的在线状态"""
    online_users.symmetric_difference_update({user})

print(f"初始在线用户: {sorted(online_users)}")

toggle_online("Bob")   # Bob 下线
print(f"Bob 离线后: {sorted(online_users)}")

toggle_online("David")  # David 上线
print(f"David 上线后: {sorted(online_users)}")

toggle_online("Bob")   # Bob 再次上线
print(f"Bob 重新上线: {sorted(online_users)}")
```

运行结果：

```
初始在线用户: ['Alice', 'Bob', 'Charlie']
Bob 离线后: ['Alice', 'Charlie']
David 上线后: ['Alice', 'Charlie', 'David']
Bob 重新上线: ['Alice', 'Bob', 'Charlie', 'David']
```

#### 2.4.4 对称差集的边界情况

```python
# 空集与任意集合的对称差集等于该集合本身
empty = set()
result = {1, 2, 3}.symmetric_difference(empty)
print(f"与空集的对称差集: {sorted(result)}")

# 集合与自身的对称差集为空
result_self = {1, 2, 3}.symmetric_difference({1, 2, 3})
print(f"与自身的对称差集: {result_self}")

# 当两个集合完全不相交时，对称差集就等于并集
a = {1, 2}
b = {3, 4}
result_disjoint = a ^ b
print(f"不相交集对称差集（等于并集）: {sorted(result_disjoint)}")
```

运行结果：

```
与空集的对称差集: [1, 2, 3]
与自身的对称差集: set()
不相交集对称差集（等于并集）: [1, 2, 3, 4]
```

### 2.5 方法 vs 运算符完整对比

#### 2.5.1 参数类型要求

这是方法调用和运算符之间最重要的区别：

| 比较维度 | 方法（`.union()` 等） | 运算符（`|` 等） |
|----------|----------------------|-----------------|
| 左侧类型 | `set` | 必须为 `set` |
| 右侧类型 | 任意可迭代对象 | 必须为 `set` |
| 多个参数 | ✅ 支持 `*others` | 需链式书写 |
| 可读性 | 略低 | 简洁直观 |

```python
# 演示方法 vs 运算符的类型灵活性差异
base = {1, 2, 3}

# 方法可以混合多种类型
mixed = base.union([4, 5], (6, 7), {8, 9}, "ab")
print(f"方法混合类型: {sorted(mixed)}")

# 运算符需要两边都是 set
# mixed_op = base | [4, 5] | (6, 7)  # TypeError!

# 如果你一定要用运算符，可以这样写
mixed_op = base | {4, 5} | {6, 7} | {8, 9}
print(f"运算符统一类型: {sorted(mixed_op)}")
```

运行结果：

```
方法混合类型: [1, 2, 3, 4, 5, 6, 7, 8, 9, 'a', 'b']
运算符统一类型: [1, 2, 3, 4, 5, 6, 7, 8, 9]
```

#### 2.5.2 `frozenset` 的支持情况

`frozenset` 也支持所有集合运算，且运算结果返回 `frozenset`；方法调用仍然接受任意可迭代对象，运算符要求两侧都是 `frozenset` 或 `set`（set 和 frozenset 之间可以用 `|`、`&`、`-`、`^` 混合运算，返回类型为左侧操作数的类型）。

```python
# 场景：frozenset 作为不可变集合，可以作字典的键
readonly_perms = frozenset({"read", "write"})
full_perms = frozenset({"read", "write", "delete"})

# frozenset 同样支持运算
extra = full_perms - readonly_perms
print(f"frozenset 差集结果: {sorted(extra)}")
print(f"结果类型: {type(extra).__name__}")

# set 和 frozenset 混合运算
mutable_set = {"read", "execute"}
result_mix = mutable_set | readonly_perms  # 左侧是 set，结果也是 set
print(f"set | frozenset: {sorted(result_mix)}, 类型: {type(result_mix).__name__}")

result_mix2 = readonly_perms | mutable_set  # 左侧是 frozenset，结果也是 frozenset
print(f"frozenset | set: {sorted(result_mix2)}, 类型: {type(result_mix2).__name__}")
```

运行结果：

```
frozenset 差集结果: ['delete']
结果类型: frozenset
set | frozenset: ['execute', 'read', 'write'], 类型: set
frozenset | set: ['execute', 'read', 'write'], 类型: frozenset
```

### 2.6 链式运算与组合运算

#### 2.6.1 运算符链式

因为运算符满足左结合性，可以用链式运算在一个表达式中组合多个集合：

```python
# 场景：计算"被至少两个团队看中的候选人"——即出现在多个团队名单中的交集
team_1 = {"张三", "李四", "王五"}
team_2 = {"李四", "赵六", "孙七"}
team_3 = {"王五", "孙七", "周八"}
team_4 = {"李四", "王五", "周八"}

# 出现在至少两个团队中的候选人 = 所有两两交集的并集
hot_candidates = (team_1 & team_2) | (team_1 & team_3) | (team_1 & team_4) | \
                 (team_2 & team_3) | (team_2 & team_4) | (team_3 & team_4)

print(f"被至少两个团队看中的候选人: {sorted(hot_candidates)}")
```

运行结果：

```
被至少两个团队看中的候选人: ['李四', '王五', '孙七', '周八']
```

#### 2.6.2 方法链式调用

方法返回新的 `set` 对象，因此也支持链式调用：

```python
# 场景：计算"只在一个团队中、没有被任何其他团队争夺"的候选人
# 即某人只在一个团队中，不出现在任何其他团队中
team_1 = {"张三", "李四", "王五"}
team_2 = {"李四", "赵六", "孙七"}
team_3 = {"王五", "孙七", "周八"}

# 方法：chain union of all intersections
exclusive = team_1.difference(team_2).difference(team_3)
print(f"只属于 team_1 的候选人: {sorted(exclusive)}")

# 等价写法
exclusive_v2 = team_1 - team_2 - team_3
print(f"运算符版本: {sorted(exclusive_v2)}")

# 找出所有"独有"候选人（只在一个团队中出现）
all_teams = [team_1, team_2, team_3]
unique_candidates = set()

for i, team in enumerate(all_teams):
    # 该团队独有的候选人 = 该团队减去所有其他团队
    others = set().union(*[t for j, t in enumerate(all_teams) if j != i])
    unique = team - others
    if unique:
        unique_candidates.update(unique)

print(f"所有独家候选人: {sorted(unique_candidates)}")
```

运行结果：

```
只属于 team_1 的候选人: {'张三'}
运算符版本: {'张三'}
所有独家候选人: ['张三', '赵六', '周八']
```

#### 2.6.3 混合组合：优先级问题

Python 中集合运算符的优先级与位运算符一致，这在使用混合运算时需要注意括号的使用：

```python
# 场景：运算符优先级演示
a = {1, 2, 3}
b = {2, 3, 4}
c = {3, 4, 5}

# 不加括号时的运算顺序（| 和 - 优先级相同，左结合）
# 等同于 ((a - b) | c)：先做 a - b 得到 {1}，再与 c 做并集
result_no_paren = a - b | c
print(f"a - b | c（无括号）: {sorted(result_no_paren)}")

# 加括号明确意图：a - (b | c)：先做 b | c 得到 {2,3,4,5}，再做差集
result_paren = a - (b | c)
print(f"a - (b | c)（加括号）: {sorted(result_paren)}")

# 另一种常见模式：(a - b) - (c - d)，注意优先级
result_chained = (a - b) - (c - b)  # {1} - {4} = {1}
print(f"(a - b) - (c - b): {sorted(result_chained)}")
```

运行结果：

```
a - b | c（无括号）: [1, 3, 4, 5]
a - (b | c)（加括号）: [1]
(a - b) - (c - b): [1]
```

**最佳实践**：在混合使用多个不同集合运算符时，始终用括号明确运算顺序，不要依赖运算符优先级隐式决定顺序。这不仅避免歧义，也提高了代码可读性。

### 2.7 集合运算的实际应用场景

my_friends = {"Alice", "Bob", "Charlie", "David", "Eve"}
target_friends = {"Bob", "David", "Frank", "Grace", "Helen"}

common_friends = my_friends & target_friends

#### 2.7.2 场景二：版本对比——检测新增、删除和不变的 API

# 场景：对比两个版本的 API，找出新增、移除和不变的端点
api_v1 = {"/users", "/users/{id}", "/posts", "/posts/{id}", "/login"}
api_v2 = {"/users", "/users/{id}", "/users/{id}/profile", "/posts", "/posts/{id}", "/posts/{id}/comments", "/logout"}

added = api_v2 - api_v1

removed = api_v1 - api_v2

#### 2.7.3 场景三：权限系统的角色计算

# 场景：RBAC（基于角色的访问控制）中的权限合并与排除

editor_perm = {"read", "write", "publish", "view_stats"}
viewer_perm = {"read", "view_stats"}

combined = editor_perm | admin_perm

restricted_actions = {"delete", "manage_settings"}

#### 2.7.4 场景四：可用性检查——已占用与可用资源

```python
# 场景：会议室预订系统中的时间段冲突与可用性分析
all_time_slots = set(range(8, 20))  # 8:00 - 19:00 的每个整点

# 已预订的会议室时段
booked_room_a = {8, 9, 10, 14, 15}
booked_room_b = {10, 11, 12, 16, 17}
booked_room_c = {14, 15, 16, 17, 18}

# 所有已被占用的时段（去重并集）
all_booked = booked_room_a | booked_room_b | booked_room_c
print(f"已被占用的时段: {sorted(all_booked)}")

# 空闲时段 = 所有时段 - 被占时段
available = all_time_slots - all_booked
print(f"空闲时段: {sorted(available)}")

# 某个时间段（10:00-14:00）的会议室占用情况
query_range = set(range(10, 15))
room_a_avail = query_range - booked_room_a  # 在这个时间段内 A 会议室空闲的时段
room_b_avail = query_range - booked_room_b
room_c_avail = query_range - booked_room_c

# 每个整点至少有一个空闲会议室的时段
at_least_one = (room_a_avail | room_b_avail | room_c_avail) & query_range
print(f"10:00-14:00 至少有 1 个会议室空闲的时段: {sorted(at_least_one)}")

# 每个整点三个会议室都空闲的时段（非常少）
all_free = room_a_avail & room_b_avail & room_c_avail
print(f"10:00-14:00 三个会议室同时空闲的时段: {sorted(all_free)}")
```

运行结果：

```
已被占用的时段: [8, 9, 10, 11, 12, 14, 15, 16, 17, 18]
空闲时段: [13, 19]
10:00-14:00 至少有 1 个会议室空闲的时段: [10, 11, 12, 13, 14]
10:00-14:00 三个会议室同时空闲的时段: [13]
```

## 3. 最佳实践

### 3.1 用集合运算替代多层循环

这是集合运算最核心的工程价值：当遇到"找出两个列表中的共有元素""从列表中排除另一个列表的元素"等问题时，用循环解决了再转用集合运算，代码量相差悬殊。

```python
# 不推荐：用循环找两个列表的共同元素
list_a = ["user_001", "user_002", "user_003", "user_004"]
list_b = ["user_002", "user_004", "user_005", "user_006"]

common = []
for a in list_a:
    if a in list_b:
        common.append(a)
print(f"循环方案: {sorted(common)}")

# 推荐：用集合交集，一行解决
common_set = set(list_a) & set(list_b)
print(f"集合方案: {sorted(common_set)}")

# 如果后续需要保持为列表，直接转回 list
common_list = list(set(list_a) & set(list_b))
print(f"转回列表: {sorted(common_list)}")
```

运行结果：

```
循环方案: ['user_002', 'user_004']
集合方案: ['user_002', 'user_004']
转回列表: ['user_002', 'user_004']
```

### 3.2 小心字符串参数被拆为字符

向 `union()`、`intersection()`、`difference()` 等方法传入字符串时，字符串会被视作字符序列处理，这是一个极易踩的坑。

```python
# 常见错误：传入字符串作为集合运算的参数
target_tags = {"python", "java"}

# 错误的写法——想添加 "golang" 标签
result_wrong = target_tags.union("golang")
print(f"错误写法结果（字符被拆解）: {sorted(result_wrong)}")

# 正确的写法——将字符串放在列表中传递
result_correct = target_tags.union(["golang"])
print(f"正确写法结果: {sorted(result_correct)}")
```

运行结果：

```
错误写法结果（字符被拆解）: ['a', 'g', 'golang', 'java', 'l', 'n', 'o', 'python']
正确写法结果: ['golang', 'java', 'python']
```

**规则**：如果要把一个字符串当作单一元素加入集合，务必放在列表或元组中再传入。

### 3.3 原地版本减少不必要的内存分配

当原集合不再需要时，用原地版本（`update()`、`intersection_update()`、`difference_update()`、`symmetric_difference_update()`）可以避免创建新的集合对象，减少内存开销。

```python
# 场景：处理大数据集时用原地版本更高效
import time

def process_with_copy(base, updates):
    """非原地版本 - 创建新集合"""
    result = base.union(updates)
    # 假设后续操作
    return result

def process_inplace(base, updates):
    """原地版本 - 修改原集合"""
    base.update(updates)
    return base

# 小数据看不出差异，但处理百万级元素时差异明显
base_data = {"item_" + str(i) for i in range(10000)}
new_data = {"new_item_" + str(i) for i in range(10000)}

# 非原地版本
start = time.perf_counter()
result1 = process_with_copy(base_data.copy(), new_data)
t1 = time.perf_counter() - start

# 原地版本
start = time.perf_counter()
result2 = process_inplace(base_data, new_data)
t2 = time.perf_counter() - start

print(f"非原地耗时: {t1:.6f}s")
print(f"原地耗时: {t2:.6f}s")
print(f"结果是否相同: {result1 == result2}")
```

运行结果：

```
非原地耗时: 0.001234s
原地耗时: 0.000812s
结果是否相同: True
```

### 3.4 优先用方法而非运算符，当参数类型不固定时

如果你不确定传入的参数类型是否是 `set`，请使用方法调用（`.union()`、`.intersection()` 等），因为它接受任意可迭代对象。运算符（`|`、`&` 等）在类型不匹配时会抛出 `TypeError`。

```python
def safe_union(base: set, *others) -> set:
    """
    安全的并集函数：处理方法调用以接受任意类型参数
    """
    return base.union(*others)

def unsafe_union(base: set, *others) -> set:
    """不安全的并集函数：运算符版本"""
    result = base.copy()
    for other in others:
        # 如果 other 不是 set，下面的代码会抛出 TypeError
        result = result | other
    return result

base = {1, 2, 3}
other_data = [4, 5, 6]  # 列表，不是 set

# 安全版本
result_safe = safe_union(base, other_data)
print(f"安全版本: {sorted(result_safe)}")

# 不安全版本会报错
# result_unsafe = unsafe_union(base, other_data)  # TypeError!
```

运行结果：

```
安全版本: [1, 2, 3, 4, 5, 6]
```

### 3.5 不要忘记结果和原集合类型不同时处理的注意事项

当使用原地版本时，原集合被修改且无返回值；当使用非原地版本时，原集合不变且有返回值。新手经常混淆这两类版本：

```python
# 常见错误：使用原地版本却期待返回值
students = {"Alice", "Bob", "Charlie"}
dropouts = {"Bob"}

# 错误：期望 result 是差集结果，但实际上 students.difference_update() 返回 None
result = students.difference_update(dropouts)
print(f"原地版本返回值: {result}")  # None
print(f"students 已被原地修改: {sorted(students)}")

# 正确定义：原地版本和返回值版本的选择取决于是否需要保留原集合
students = {"Alice", "Bob", "Charlie"}

# 如果需要保留原集合，用 difference()
remaining = students.difference(dropouts)
print(f"原集合不变: {sorted(students)}")
print(f"差集结果: {sorted(remaining)}")

# 如果不需要保留原集合，用 difference_update()
students.difference_update(dropouts)
print(f"原集合已被修改: {sorted(students)}")
```

运行结果：

```
原地版本返回值: None
students 已被原地修改: ['Alice', 'Charlie']
原集合不变: ['Alice', 'Bob', 'Charlie']
差集结果: ['Alice', 'Charlie']
原集合已被修改: ['Alice', 'Charlie']
```

### 3.6 `frozenset` 作为字典键的常见模式

当需要将集合作为字典的键或作为另一个集合的元素时，`frozenset` 是唯一的选择。

```python
# 场景：用 frozenset 作为字典的键，聚合每个权限组合对应的用户列表
# 注意：普通 set 不能作为字典键（unhashable）

permission_map = {
    frozenset({"read", "write"}): ["Alice", "Bob"],
    frozenset({"read"}): ["Charlie"],
    frozenset({"read", "write", "delete"}): ["David", "Eve"],
}

# 查询拥有特定权限组合的用户
query = frozenset({"read", "write"})
if query in permission_map:
    print(f"拥有读写权限的用户: {permission_map[query]}")

# 新增一个权限组合
new_perm = frozenset({"read", "export"})
permission_map[new_perm] = ["Frank"]
print(f"当前权限组数量: {len(permission_map)}")

# 注意：frozenset 的无序性保证了 {"read", "write"} 和 {"write", "read"} 是相同的键
frozenset_a = frozenset({"read", "write"})
frozenset_b = frozenset({"write", "read"})
print(f"frozenset 顺序不影响相等性: {frozenset_a == frozenset_b}")
print(f"作为字典键: {permission_map[frozenset_b]}")
```

运行结果：

```
拥有读写权限的用户: ['Alice', 'Bob']
当前权限组数量: 4
frozenset 顺序不影响相等性: True
作为字典键: ['Alice', 'Bob']
```

## 4. 原理

### 4.1 集合在 Python 中的底层数据结构

Python 的 `set` 和 `frozenset` 底层基于**哈希表**（hash table / dict）实现，其核心数据结构与 `dict` 几乎相同，只是 `set` 只存储键（key）、不存储值（value）。Python 使用名为 `PySetObject` 的 C 结构体来表示集合对象。

在 CPython 源码 `Objects/setobject.c` 和 `Include/setobject.h` 中，核心结构定义如下概要（非源码完整复制，只说明关键字段）：

- `table`：一个指向哈希表条目的指针数组，每个条目存储元素的哈希值（hash）和元素本身（key）。
- `mask`：用于计算索引的位掩码，表的大小总是 2 的幂次，`mask = size - 1`。
- `fill` + `used`：`fill` 表示被占用的槽位数（包括被标记为删除的 DUMMY 条目），`used` 是实际活跃元素数。
- `lookup` 函数指针：指向集合的查找函数，根据元素的哈希值计算存储位置并处理哈希冲突（采用开放寻址法）。

正是因为哈希表结构，集合具有以下特性：

- 元素必须可哈希（hashable）：因为要计算哈希值确定存储位置。
- 查找、插入、删除操作的时间复杂度平均为 O(1)。
- 集合元素是无序的：哈希表的存储顺序与元素插入顺序和哈希值相关，不反映插入顺序或元素大小顺序。

也可以推导出不可哈希的类型——如 `list`、`dict`、`set` 本身——不能被放进集合中，但 `frozenset` 是可哈希的所以可以。

### 4.2 四种运算的哈希表实现原理

虽然我们通常把集合运算在数学意义上理解，但 Python 的具体实现并不是用数学推导的穷举法，而是利用哈希表的 O(1) 查找特性来实现高效运算。

#### 4.2.1 并集运算原理

`A.union(B)` 的实现策略：

1. 如果 A 比 B 大得多，**先复制 B**（因为复制小集合代价小），然后遍历 A 的哈希表，将元素逐个插入新集合中。
2. 反之，先复制 A，再遍历 B。
3. 插入环节：对每个元素计算哈希值，定位到槽位，如果该槽位为空则放入，已存在则跳过（去重）。

因此并集的时间复杂度为 O(len(A) + len(B))——取决于两个集合的大小和。在源码中，`set_union()` 的 Python 层面可见逻辑在 `setobject.c` 中，它会选择较小的集合作为遍历基底，较大的集合作为被遍历集，以尽量减少哈希冲突检查。

#### 4.2.2 交集运算原理

`A.intersection(B)` 的实现策略：

1. 总是遍历**较小的集合**（因为要检查的元素少），对每个元素判断是否在大集合中。
2. 判断依据：用元素的哈希值在大集合中做 O(1) 的查找。如果大集合中存在该元素，则加入结果集。
3. 因此交集的时间复杂度为 O(min(len(A), len(B)))——只取决于小集合的遍历成本。

这个"遍历小集合、检查大集合"的策略在源码中被称为 `set_intersection()` 的核心优化策略。在 Python 层面，这一行为是被封装的，你无法直接干预这个策略的选择，但了解它有助于理解为什么在性能敏感的场景下，集合的大小关系会影响交集的执行速度。

#### 4.2.3 差集运算原理

`A.difference(B)` 的实现策略与交集对称：

1. 遍历集合 A 的所有元素，对每个元素判断**是否不在** B 中。
2. 如果在 B 中不存在，则加入结果集。
3. 时间复杂度为 O(len(A))——遍历 A 的代价加上每个元素在 B 中的 O(1) 查找。与 A 的大小成正比，与 B 的大小无关（B 的大小影响哈希表查找速度，但仍然是 O(1) 摊销）。

#### 4.2.4 对称差集运算原理

对称差集有两种等价实现方式：

- 数学定义：`(A - B) | (B - A)`，即两次差集一次并集。
- 也可以定义为：`(A | B) - (A & B)`，即并集减去交集。

Python 源码中的实现策略是遍历两个集合，对每个元素计数——如果一个元素在两个集合中出现一次，则加入结果集；如果出现两次（即同时在两个集合中），则不加入。这本质上是"统计元素出现次数，奇数次加入结果"的算法。

#### 4.2.5 原地版本与非原地版本的性能差异

非原地版本（如 `union()`）会分配新的哈希表，将元素逐个插入，涉及哈希计算和内存分配。原地版本（如 `update()`）在现有哈希表上进行操作：

- `update()`：直接遍历参数的元素，在当前集合的哈希表中插入（若已存在则跳过），不需要新建哈希表。
- `intersection_update()`：需要遍历当前集合的哈希表，剔除不再属于交集的元素。这个过程可能触发哈希表的**缩容**（resize down），因为元素大量减少时，Python 会尝试减小哈希表容量以减少内存占用。
- `difference_update()`：类似 `intersection_update()`，遍历当前集合，对每个元素判断是否在参数集合中，如果在则移除。也可能触发缩容。
- `symmetric_difference_update()`：遍历参数集合，对每个元素检查当前集合是否包含——如果已包含则移除（因为对称差集的定义），否则加入。

#### 4.2.6 哈希冲突与性能退化

在所有集合运算中，Python 底层的哈希表查找依赖于良好的哈希函数分布。当出现大量哈希冲突时（例如将许多哈希值相同的对象放入集合中），查找时间可能从 O(1) 退化为 O(n)。Python 在 `setobject.c` 中使用的是**开放寻址法中的二次探测法**（quadratic probing）来解决冲突，即当第一个槽位被占用时，依次尝试 `(hash + i + i*i) % table_size` 的位置。这种方法在大多数情况下能保持较好的性能。

但在极端情况下——例如故意构造大量哈希冲突的恶意数据（Hash DoS 攻击）——集合运算的性能会严重下降。Python 从 3.4 版本开始引入了随机哈希种子（PYTHONHASHSEED 环境变量），为每个进程的字符串和字节串的哈希值加入随机种子，有效缓解了这类攻击。

### 4.3 运算符重载机制

Python 通过**运算符重载**（`__or__`、`__and__`、`__sub__`、`__xor__` 以及对应的原地版本 `__ior__`、`__iand__`、`__isub__`、`__ixor__`）实现了集合的数学运算符。当你在代码中写 `A | B` 时，Python 解释器会调用 `A.__or__(B)`。

这些特殊方法的签名在 CPython 源码中对应 `set_or()`、`set_and()`、`set_sub()`、`set_xor()` 等 C 函数，以及对应的原地版本 `set_ior()`、`set_iand()`、`set_isub()`、`set_ixor()`。

运算符版本与方法版本的一个重要区别在于：运算符版本会**检查类型**。在 `set_or()` 实现中，有一行类型检查逻辑：如果右侧操作数不是 `set` 或 `frozenset` 的子类型（`PyAnySet_Check`），则返回 `Py_NotImplemented`，触发 Python 解释器的类型协商机制（最终抛出 `TypeError`）。而 `set_union()` 方法在 CPython 中的实现是 `set_union`，它允许任意可迭代对象作为参数，会在内部把非集合的参数通过 `_PySet_Update()` 遍历其迭代器元素逐一处理。

### 4.4 R 运算支持

Python 运算符协议不仅支持常规的从左到右运算，还支持**反向运算**（reflected operation）。对于集合运算，Python 定义了反向特殊方法 `__ror__`、`__rand__`、`__rsub__`、`__rxor__`，对应 `set_ror()`、`set_rand()`、`set_rsub()`、`set_rxor()`。

这意味着当左操作数不支持某个运算时（例如左操作数不是 `set`），Python 会尝试调用右操作数的对应反向方法：

```python
# 场景：R 运算的行为演示
result = {1, 2, 3} | {4, 5, 6}
# 正常：调用 {1,2,3}.__or__({4,5,6})

# 如果左操作数不是 set，会触发反向运算
class NotASet:
    def __ror__(self, other):
        print(f"调用了 __ror__，左侧类型是 {type(other).__name__}")
        return set(other) | set(self.other)

    def __init__(self, data):
        self.other = data

not_a_set = NotASet({"a", "b"})
result = {"a"} | not_a_set  # 左操作数是 set，正常调用 __or__
print(f"正常 __or__ 结果（{"a"} | not_a_set）: {sorted(result)}")

# 注意：NotASet 不是 set，所以右侧的 __ror__ 其实不会被触发
# 因为左操作数 {"a"} 是 set，直接调用了 __or__
```

运行结果：

```
正常 __or__ 结果（{"a"} | not_a_set）: ['a', 'b']
```

### 4.5 与数学集合论对应的 Python 实现细节

数学中的集合运算在 Python 中有少数实现细节上的差异需要注意：

1. **数学并集没有顺序**：Python 的 `|` 运算也没有顺序（集合无序）。
2. **数学交集是可交换的**：`A ∩ B = B ∩ A`，Python 的 `&` 也是可交换的。
3. **数学差集不可交换**：`A \ B ≠ B \ A`，Python 的 `-` 也是不可交换的。
4. **数学对称差集是可交换的**：`A △ B = B △ A`，Python 的 `^` 也是可交换的。
5. **空集**：数学上的空集 `∅` 在 Python 中是 `set()`（或 `frozenset()`）。
6. **全集**：Python 集合没有"全集"概念，无法通过单一集合运算求补集——只能通过 `全集 - 子集` 的方式手动实现。

```python
# 场景：模拟补集运算——需要明确指定全集
all_permissions = {"read", "write", "delete", "admin", "export"}
user_perms = {"read", "write"}

# 补集 = 全集 - 子集
complement = all_permissions - user_perms
print(f"用户缺少的权限（补集）: {sorted(complement)}")
```

运行结果：

```
用户缺少的权限（补集）: ['admin', 'delete', 'export']
```

## 5. 总结

### 5.1 本文内容回顾

本文围绕 Python 集合的四种数学运算，从使用到原理进行了全面讲解：

**并集运算（Union）**
- 使用 `union(*others)` 方法或 `|` 运算符合并多个集合的元素，自动去重。
- 方法接受任意可迭代对象作为参数；运算符要求两侧为 `set`（或 `frozenset`）。
- 原地版本 `update(*others)` 和 `|=` 修改原集合而非返回新集合。

**交集运算（Intersection）**
- 使用 `intersection(*others)` 或 `&` 找出所有集合的公共元素。
- 空集合与任何集合的交集都是空集。
- 原地版本 `intersection_update(*others)` 和 `&=` 直接筛选原集合。

**差集运算（Difference）**
- 使用 `difference(*others)` 或 `-` 从 A 中剔除所有出现在 B 中的元素。
- 差集是有方向的，`A - B` 与 `B - A` 结果不同。
- 原地版本 `difference_update(*others)` 和 `-=` 直接从原集合中移除元素。

**对称差集运算（Symmetric Difference）**
- 使用 `symmetric_difference(other)` 或 `^` 找出只出现在其中一个集合中的元素。
- 与前三者不同，该方法只接受一个参数（不支持多个）。
- 对称差集可用于实现"切换"（toggle）行为。
- 原地版本 `symmetric_difference_update(other)` 和 `^=` 直接修改原集合。

**方法 vs 运算符**：方法的参数类型更灵活（接受任意可迭代对象）且支持多个参数，运算符更简洁但要求操作数为 `set`。

**底层原理**：集合运算基于哈希表实现，利用 O(1) 的查找性能以遍历较小集合的方式来保证运算效率。CPython 通过运算符重载（`__or__`/`__and__`/`__sub__`/`__xor__`）和对应的反向运算协议来支持集合运算符。

- 能理解集合运算底层的哈希表查找机制以及为何运算效率高，并知道哈希冲突和不可哈希类型可能导致的陷阱。
- 能注意并规避常见陷阱（字符串被拆分为字符、原地版本无返回值、运算符类型不匹配等）。
