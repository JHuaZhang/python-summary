# 字典的 setdefault 方法

## 1. 介绍

### 1.1 什么是 setdefault

`setdefault` 是 Python 字典（`dict`）的一个内置方法，它的作用可以用一句话概括：**查找键的值，如果键不存在，就插入一个默认值，然后返回该值。**

听起来很简单，但这个名字容易让人误解。"setdefault" 并不是"设置一个默认值"的意思，而是"set if absent, then get"——**如果键不存在就 set，无论如何都返回值**。理解这一点是掌握该方法的关键。

### 1.2 解决什么问题

在实际开发中，你经常遇到这样的场景：从字典中取一个值，如果键不存在，就给它一个初始值，然后继续操作。不用 `setdefault` 时，代码通常长这样：

```python
# 传统写法：判断 + 初始化 + 操作，三步走
scores = {"张三": 90}
if "李四" not in scores:
    scores["李四"] = 0
score = scores["李四"]
score += 10
scores["李四"] = score
```

用 `setdefault` 后，一行就能完成"判断 + 初始化"：

```python
# setdefault 写法：一行完成判断 + 初始化
scores = {"张三": 90}
scores["李四"] = scores.setdefault("李四", 0) + 10
```

`setdefault` 的核心价值在于：**把"检查-初始化-获取"三步合并为一步**，减少样板代码，让意图更清晰。

### 1.3 最简示例

先看一个最小的例子，感受 `setdefault` 的基本行为：

```python
d = {"name": "Alice"}

# 键存在 → 返回已有值，不修改字典
print(d.setdefault("name", "Bob"))  # 输出：Alice
print(d)  # 输出：{'name': 'Alice'}

# 键不存在 → 插入默认值，返回默认值
print(d.setdefault("age", 20))  # 输出：20
print(d)  # 输出：{'name': 'Alice', 'age': 20}
```

这个例子展示了 `setdefault` 的两条核心规则：

| 情况 | 行为 | 返回值 |
|------|------|--------|
| 键存在 | 不修改字典 | 键已对应的值 |
| 键不存在 | 插入 `key: default` | default 的值 |

## 2. 核心内容

### 2.1 方法签名

`setdefault` 的完整签名如下：

```python
dict.setdefault(key, default=None)
```

| 参数 | 说明 | 是否必需 |
|------|------|---------|
| `key` | 要查找的键 | 必需 |
| `default` | 键不存在时插入的默认值，不传则为 `None` | 可选 |

**返回值**：无论键是否存在，都返回 `key` 对应的值（已存在的值或刚插入的默认值）。

**关键细节**：

- `default` 参数是可选的。如果不传，等价于 `default=None`。
- `default` 可以是任意类型的值，包括可变对象（`list`、`dict`、`set` 等）。
- 即使键已存在（不需要使用 `default`），`default` 表达式仍然会被求值。

### 2.2 键不存在时的行为

当键不存在时，`setdefault` 会做两件事：

1. 将 `key: default` 插入字典
2. 返回 `default`

```python
config = {"host": "localhost", "port": 8080}

# "timeout" 不存在 → 插入并返回
timeout = config.setdefault("timeout", 30)
print(f"返回值: {timeout}")       # 输出：返回值: 30
print(f"字典内容: {config}")      # 输出：字典内容: {'host': 'localhost', 'port': 8080, 'timeout': 30}
```

**运行结果**：

```text
返回值: 30
字典内容: {'host': 'localhost', 'port': 8080, 'timeout': 30}
```

**关键点**：键不存在时，`setdefault` 不仅返回默认值，还**同时修改了字典**。这是它和 `get` 方法最大的区别——`get` 只返回默认值但不修改字典。

### 2.3 键已存在时的行为

当键已存在时，`setdefault` **不会覆盖已有值**，直接返回当前值：

```python
config = {"host": "localhost", "port": 8080}

# "port" 已存在 → 不覆盖，返回已有值
port = config.setdefault("port", 3000)
print(f"返回值: {port}")          # 输出：返回值: 8080
print(f"字典内容: {config}")      # 输出：字典内容: {'host': 'localhost', 'port': 8080}
```

**运行结果**：

```text
返回值: 8080
字典内容: {'host': 'localhost', 'port': 8080}
```

**关键点**：`setdefault` 是"安全"的——它不会意外覆盖已有数据。如果你需要覆盖，应该直接用 `d[key] = value` 赋值，而不是 `setdefault`。

### 2.4 不传 default 参数

如果不传 `default` 参数，默认使用 `None`：

```python
user = {"name": "张三"}

# 不传 default，等价于 default=None
email = user.setdefault("email")
print(f"返回值: {email}")         # 输出：返回值: None
print(f"字典内容: {user}")        # 输出：字典内容: {'name': '张三', 'email': None}
```

**运行结果**：

```text
返回值: None
字典内容: {'name': '张三', 'email': None}
```

**关键点**：不传 `default` 时，键不存在会插入 `None`。这在某些场景下是有用的（比如标记"已查询过但无值"），但在需要具体初始值的场景下，记得显式传 `default`。

### 2.5 default 表达式总是被求值

这是一个容易被忽略的细节：**即使键已存在，`default` 表达式仍然会被求值。**

```python
def create_default():
    print("create_default 被调用了！")
    return []

d = {"items": [1, 2, 3]}

# "items" 已存在，但 create_default() 仍然会执行
result = d.setdefault("items", create_default())
print(f"返回值: {result}")
```

**运行结果**：

```text
create_default 被调用了！
返回值: [1, 2, 3]
```

可以看到，虽然 `"items"` 已存在，`create_default()` 函数仍然被调用了，只是其返回值没有被使用。

**关键点**：

- `setdefault(key, default)` 中的 `default` 是在调用时求值的，不是惰性求值。
- 如果 `default` 是一个开销很大的操作（如创建大对象、调用函数），即使键已存在也会产生开销。
- 这和 `defaultdict` 的行为不同——`defaultdict` 只在键不存在时才调用工厂函数。

### 2.6 setdefault 与 get 的对比

`setdefault` 和 `get` 是字典中最容易被混淆的两个方法。它们都"获取键对应的值"，但在键不存在时的行为截然不同。

**对比表**：

| 维度 | `get(key, default)` | `setdefault(key, default)` |
|------|---------------------|---------------------------|
| 键存在时 | 返回已有值 | 返回已有值 |
| 键不存在时 | 返回 default，**不修改字典** | 返回 default，**插入 key: default** |
| 是否修改字典 | 否 | 是（键不存在时） |
| 典型用途 | 只读查询 | 查询 + 初始化 |
| 返回值类型 | 任意 | 任意 |

用一个例子直观对比：

```python
# get：查完就走，不留痕迹
d1 = {"name": "Alice"}
val1 = d1.get("phone", "未知")
print(f"get: 返回 '{val1}', 字典={d1}")

# setdefault：查完顺手初始化
d2 = {"name": "Alice"}
val2 = d2.setdefault("phone", "未知")
print(f"setdefault: 返回 '{val2}', 字典={d2}")
```

**运行结果**：

```text
get: 返回 '未知', 字典={'name': 'Alice'}
setdefault: 返回 '未知', 字典={'name': 'Alice', 'phone': '未知'}
```

**选择建议**：

- 需要查询但不希望修改字典 → 用 `get`
- 需要查询且希望顺便初始化 → 用 `setdefault`
- 需要频繁初始化默认值 → 考虑用 `collections.defaultdict`

### 2.7 经典模式：用可变对象作为默认值

`setdefault` 最强大的用法是**用可变对象（`list`、`dict`、`set`）作为默认值**，一行代码完成"如果键不存在就创建空容器，然后追加数据"的操作。

#### 2.7.1 用 list 作为默认值——分组模式

这是 `setdefault` 最常见的使用场景：按某个键分组，把值收集到列表中。

```python
# 按城市分组用户
users = [
    ("Alice", "北京"),
    ("Bob", "上海"),
    ("Charlie", "北京"),
    ("Diana", "上海"),
    ("Eve", "广州"),
]

city_groups = {}
for name, city in users:
    city_groups.setdefault(city, []).append(name)

for city, names in city_groups.items():
    print(f"{city}: {names}")
```

**运行结果**：

```text
北京: ['Alice', 'Charlie']
上海: ['Bob', 'Diana']
广州: ['Eve']
```

**关键点**：`city_groups.setdefault(city, [])` 这一行做了三件事：

1. 如果 `city` 不在字典中，插入 `city: []`（空列表）
2. 返回 `city` 对应的列表（已有的或刚创建的）
3. 对返回的列表调用 `.append(name)`

整个过程不需要 `if` 判断，一行代码完成。

#### 2.7.2 用 dict 作为默认值——嵌套字典

需要构建嵌套字典结构时，`setdefault` 同样表现出色：

```python
# 统计每个班级各科最高分
records = [
    ("一班", "数学", 95),
    ("一班", "语文", 88),
    ("二班", "数学", 90),
    ("一班", "数学", 98),  # 同班同科有多次记录，取最高
]

class_scores = {}
for cls, subject, score in records:
    cls_dict = class_scores.setdefault(cls, {})  # 外层：班级 → dict
    current = cls_dict.get(subject, 0)           # 内层：科目 → 最高分
    if score > current:
        cls_dict[subject] = score

for cls, scores in class_scores.items():
    print(f"{cls}: {scores}")
```

**运行结果**：

```text
一班: {'数学': 98, '语文': 88}
二班: {'数学': 90}
```

**关键点**：外层用 `setdefault` 初始化班级字典，内层用 `get` 查询科目分数。两者配合，构建出两级嵌套结构。

#### 2.7.3 用 int 作为默认值——计数器

`setdefault` 配合 `+=` 可以实现计数器：

```python
# 词频统计
words = "the quick brown fox jumps over the lazy dog the fox".split()
word_count = {}
for word in words:
    word_count.setdefault(word, 0)
    word_count[word] += 1

# 按出现次数降序排列
sorted_counts = sorted(word_count.items(), key=lambda x: x[1], reverse=True)
for word, count in sorted_counts:
    print(f"  {word}: {count}")
```

**运行结果**：

```text
  the: 3
  fox: 2
  quick: 1
  brown: 1
  jumps: 1
  over: 1
  lazy: 1
  dog: 1
```

**关键点**：这里需要两行——第一行 `setdefault` 确保 `word` 存在，第二行 `+=` 累加。不能写成 `word_count.setdefault(word, 0) += 1`，因为 `setdefault` 返回的是值而非引用，`+=` 作用于返回值不会修改字典。

### 2.8 可变默认值不会共享

一个常见的担心是：`setdefault(key, [])` 中的 `[]` 会不会被多个键共享？答案是**不会**。

```python
d = {}
d.setdefault("a", []).append(1)
d.setdefault("b", []).append(2)
d.setdefault("a", []).append(3)  # "a" 已存在，新的 [] 被丢弃

print(d)
```

**运行结果**：

```text
{'a': [1, 3], 'b': [2]}
```

**关键点**：

- 每次调用 `setdefault(key, [])` 时，`[]` 都会创建一个新的空列表。
- 但只有键不存在时，这个新列表才会被插入字典。
- 键已存在时，新列表被创建但随即丢弃（被垃圾回收），字典中保留的是原有列表。
- 因此不存在多个键共享同一个列表的问题。

**对比 `dict.fromkeys` 的陷阱**：

需要注意的是，`dict.fromkeys(keys, [])` 这种写法**会共享同一个列表**，因为 `[]` 只创建一次。这是与 `setdefault` 行为不同的地方，使用 `fromkeys` 时要特别小心。

```python
# fromkeys 的陷阱：所有键共享同一个列表
shared = dict.fromkeys(["a", "b", "c"], [])
shared["a"].append(1)
print(shared)  # 输出：{'a': [1], 'b': [1], 'c': [1]}  ← 三个键都变成了 [1]！
```

### 2.9 setdefault 的返回值妙用

`setdefault` 返回值就是键对应的值，这意味着你可以直接对返回值进行操作，而不需要二次访问字典。

**模式 1：链式调用**

```python
# 直接对 setdefault 的返回值调用方法
d = {}
d.setdefault("tags", []).append("Python")
d.setdefault("tags", []).append("教程")
print(d)  # 输出：{'tags': ['Python', '教程']}
```

**模式 2：配合增量操作**

```python
# 计数器：先确保键存在，再增量操作
inventory = {"apple": 5}
inventory.setdefault("banana", 0)  # 初始化
inventory["banana"] += 10           # 增量
print(inventory)  # 输出：{'apple': 5, 'banana': 10}
```

**模式 3：构建缓存**

```python
# 缓存模式：如果没缓存就初始化
cache = {}
def get_user(user_id):
    return cache.setdefault(user_id, fetch_user(user_id))

def fetch_user(user_id):
    # 模拟从数据库获取用户
    return {"id": user_id, "name": f"用户{user_id}"}

user1 = get_user(1)
user1_again = get_user(1)  # 第二次直接从缓存取
print(user1)
print(f"缓存内容: {cache}")
```

**运行结果**：

```text
{'id': 1, 'name': '用户1'}
缓存内容: {1: {'id': 1, 'name': '用户1'}}
```

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

**场景 1：分组收集**

```python
data = [("x", 1), ("y", 2), ("x", 3), ("z", 4)]

# 推荐：setdefault 一行完成
result = {}
for key, val in data:
    result.setdefault(key, []).append(val)

# 不推荐：冗长的 if-else
result = {}
for key, val in data:
    if key not in result:
        result[key] = []
    result[key].append(val)

# 不推荐：先 get 再判断（绕弯路）
result = {}
for key, val in data:
    existing = result.get(key)
    if existing is None:
        result[key] = [val]
    else:
        existing.append(val)
```

| 写法 | 行数 | 可读性 | 问题 |
|------|------|--------|------|
| `setdefault` | 1 行 | 高，意图清晰 | 无 |
| `if-else` | 3 行 | 中，样板代码多 | 冗长但不算错 |
| `get` + 判断 | 4 行 | 低，逻辑绕弯 | 无法区分 `None` 值和键不存在 |

**场景 2：只读查询**

```python
config = {"host": "localhost", "port": 8080}

# 推荐：只查询不修改，用 get
host = config.get("host", "127.0.0.1")

# 不推荐：只查询却用 setdefault（副作用：修改了字典）
host = config.setdefault("host", "127.0.0.1")
```

**原则**：如果不需要修改字典，永远用 `get`，不要用 `setdefault`。`setdefault` 的"副作用"在不需要时是负担。

**场景 3：高频次默认值初始化**

```python
# 推荐：频繁初始化默认值时，用 defaultdict
from collections import defaultdict
word_count = defaultdict(int)
for word in words:
    word_count[word] += 1

# 不推荐：高频次调用 setdefault（default 表达式总是求值）
word_count = {}
for word in words:
    word_count.setdefault(word, 0)
    word_count[word] += 1
```

**原则**：当循环中每次都需要初始化默认值时，`defaultdict` 比 `setdefault` 更合适——`defaultdict` 只在键不存在时才调用工厂函数，而 `setdefault` 的 `default` 参数每次都会求值。

### 3.2 常见错误模式

**错误 1：以为 setdefault 会覆盖已有值**

```python
d = {"count": 5}
d.setdefault("count", 0)  # 期望变成 0？
print(d["count"])  # 输出：5，setdefault 不会覆盖

# 修正：覆盖用直接赋值
d["count"] = 0
```

**错误 2：对 setdefault 返回值做增量操作不会修改字典**

```python
d = {}
# 错误：setdefault 返回的是值的副本（对于不可变类型），+= 不会修改字典
d.setdefault("count", 0) += 1  # SyntaxError！
```

`setdefault` 返回值是一个表达式结果，不能直接对其使用 `+=`。正确写法是两步：

```python
d = {}
d.setdefault("count", 0)
d["count"] += 1
```

**错误 3：用 setdefault 但不需要副作用**

```python
# 错误意图：只是想查一下有没有这个键，不打算修改字典
d = {"name": "Alice"}
phone = d.setdefault("phone", "未知")  # 不小心给字典加了个 "phone" 键
print(len(d))  # 输出：2，字典被修改了

# 修正：只查询用 get
phone = d.get("phone", "未知")
```

**错误 4：用 None 作为可变默认值**

```python
# 错误：想用 setdefault 初始化列表，但传了 None
d = {}
d.setdefault("items", None).append(1)  # AttributeError: 'NoneType' has no attribute 'append'

# 修正：默认值应该是 []，不是 None
d.setdefault("items", []).append(1)
```

### 3.3 setdefault vs defaultdict vs if-else 取舍

当需要"键不存在时初始化默认值"时，有三种主流写法。下面的对比表帮你选择最合适的方案：

| 维度 | `if key not in d` | `setdefault` | `defaultdict` |
|------|-------------------|--------------|---------------|
| 代码量 | 多（3 行） | 少（1 行） | 最少（0 行初始化） |
| 副作用 | 显式，可控 | 隐式（修改字典） | 隐式（修改字典） |
| 默认值类型 | 任意 | 任意 | 需指定工厂函数 |
| 性能（高频初始化） | 好 | 一般（default 每次求值） | 最好（懒求值） |
| 适用范围 | 所有初始化场景 | 简单初始化 | 统一默认值场景 |
| 能否不同键不同默认值 | 是 | 是 | 否（工厂函数统一） |

**选择口诀**：

- 默认值统一、初始化频繁 → `defaultdict`
- 只在个别地方需要初始化、默认值可能不同 → `setdefault`
- 需要完全控制初始化逻辑 → `if-else`

### 3.4 性能注意事项

`setdefault` 在性能方面有两个值得注意的点：

**1. default 参数每次都求值**

```python
# 每次循环都会创建一个新的空列表，即使 "A" 已经存在
d = {"A": [1]}
for i in range(10000):
    d.setdefault("A", []).append(i)
```

上面的代码在每次循环中都创建了 `[]`（10000 次），虽然只有第一次被使用，但创建开销是实实在在的。用 `defaultdict(list)` 可以避免这个问题：

```python
from collections import defaultdict
d = defaultdict(list)
d["A"].append(1)
for i in range(10000):
    d["A"].append(i)  # 没有多余的 [] 创建
```

**2. 两次哈希查找**

`setdefault` 内部需要查找键一次，而后续对 `d[key]` 的操作又需要查找一次。在大字典上，这个开销不可忽略：

```python
# setdefault：内部查找 + 外部再查找 = 2 次哈希
d.setdefault(key, []).append(val)

# 保存引用：只查找 1 次
lst = d.setdefault(key, [])
lst.append(val)  # 后续操作直接用引用
```

不过对于大多数应用场景，这个差异可以忽略。只有在性能敏感的热点路径上才需要关注。

## 4. 原理

### 4.1 setdefault 的等价实现

理解 `setdefault` 最直接的方式是看它的等价实现。以下伪代码展示了 `setdefault` 的内部逻辑：

```python
def setdefault(self, key, default=None):
    if key in self:
        return self[key]       # 键存在：返回已有值，不做任何修改
    else:
        self[key] = default    # 键不存在：插入默认值
        return default         # 返回默认值
```

**执行流程**：

```text
setdefault(key, default) 调用
        │
        ▼
   key 在字典中?
   ┌────┴────┐
   是        否
   │         │
   ▼         ▼
返回 self[key]   插入 key: default
(不修改字典)     返回 default
```

从等价实现可以看出，`setdefault` 本质上是"先查再插"的原子操作。所谓"原子"是指从调用者视角来看，"检查键是否存在"和"插入默认值"这两步不会被其他操作打断。

### 4.2 default 参数为什么不是惰性求值

Python 的函数参数传递机制决定了 `default` 参数在函数调用时就会被求值。这不是 `setdefault` 的特殊设计，而是所有 Python 函数的通用规则：

```python
# 所有 Python 函数的参数都是先求值再传递
def foo(a, b):
    print(f"a={a}, b={b}")
    return a

foo(1, expensive_operation())  # expensive_operation() 总是被调用
```

`setdefault(key, expensive_operation())` 也一样——`expensive_operation()` 在 `setdefault` 被调用时就已经执行了，不管 `key` 是否存在。

与此对比，`defaultdict` 使用工厂函数（可调用对象），只有在键缺失时才调用：

```python
from collections import defaultdict

# defaultdict 只在键不存在时调用工厂函数 int()
d = defaultdict(int)
print(d["count"])  # 此时才调用 int()，返回 0
```

**设计原因**：`setdefault` 是一个普通方法，参数在调用时求值是语言的通用行为。`defaultdict` 是一个特殊类，通过 `__missing__` 魔术方法实现了惰性求值。两者是不同层面的设计。

### 4.3 setdefault 与 __missing__ 机制

Python 字典在通过 `d[key]` 访问键不存在时，会调用 `__missing__` 方法。`defaultdict` 就是通过重写 `__missing__` 来实现自动初始化的：

```text
d[key] 访问流程
      │
      ▼
  key 在字典中?
  ┌────┴────┐
  是        否
  │         │
  ▼         ▼
返回值    调用 d.__missing__(key)
          ┌──────┴──────┐
          │             │
     defaultdict     普通 dict
          │             │
          ▼             ▼
     调用工厂函数    抛出 KeyError
     插入并返回
```

`setdefault` 不依赖 `__missing__`，它是一个"显式"的方法调用——你主动告诉字典"如果键不存在就插入这个值"。而 `defaultdict` 是"隐式"的——你不需要调用任何方法，直接 `d[key]` 就会自动初始化。

两种方式的取舍在于**显式 vs 隐式**：

- `setdefault`：显式，每次都写明默认值，更灵活（不同键可以不同默认值），但代码稍长
- `defaultdict`：隐式，初始化逻辑在创建时定义，代码更简洁，但所有缺失键的默认值由同一个工厂函数决定

---

## 5. 总结

本文围绕字典的 `setdefault` 方法展开，主要介绍了以下内容：

- `setdefault(key, default=None)` 的核心行为：键存在时返回已有值不修改字典，键不存在时插入默认值并返回
- 方法签名的两个参数：`key`（必需）和 `default`（可选，默认 `None`）
- 键不存在与键已存在两种情况的详细行为差异，`default` 表达式总是被求值的特点
- `setdefault` 与 `get` 的对比：`get` 只查询不修改字典，`setdefault` 查询同时初始化
- 经典模式：用 `list`、`dict`、`int` 等可变/不可变对象作为默认值，实现分组收集、嵌套字典、计数器等场景
- 可变默认值不会共享的原因——每次调用创建新对象，只有键缺失时才插入
- 最佳实践：推荐用 `setdefault` 简化分组初始化代码，只读查询用 `get`，高频初始化用 `defaultdict`
- 常见错误模式：不会覆盖已有值、不能对返回值直接 `+=`、不需要副作用时误用
- `setdefault` 的等价实现是"先查再插"的原子操作，`default` 参数非惰性求值是 Python 函数参数传递的通用行为
- `setdefault`（显式）与 `defaultdict`（隐式，基于 `__missing__`）在设计理念上的区别与取舍
