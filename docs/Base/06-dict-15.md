# 字典与运算符

## 1. 介绍

### 1.1 什么是字典的运算符操作

在 Python 中，字典不仅是一个数据容器，还支持多种运算符操作——从最基础的成员判断（`in`）、相等比较（`==`），到身份判断（`is`），再到 Python 3.9 引入的合并运算符（`|`、`|=`）、解包运算符（`**`），以及下标访问（`[]`）和删除操作（`del`）。

这些运算符让你能像操作数字和字符串一样，用简洁的语法对字典进行判断、比较、合并和拆解。掌握了它们，你写出来的字典操作代码会更短、更清晰、更 Pythonic。

### 1.2 解决什么问题

假设你有两份配置字典——一份是默认配置，一份是用户自定义配置，需要合并成最终配置。不用运算符的话，你得这样写：

```python
default = {"host": "localhost", "port": 3306}
user = {"port": 5432, "debug": True}

# 传统方式：copy + update
final = default.copy()
final.update(user)
```

用合并运算符 `|` 一行搞定：

```python
final = default | user
```

或者用解包运算符 `**`：

```python
final = {**default, **user}
```

运算符让代码意图更直接——"合并这两个字典"一眼就能看出来，不需要读到 `copy()` + `update()` 才反应过来。

### 1.3 运算符速览

Python 字典支持的运算符一览：

| 运算符 | 名称 | 作用 | 示例 |
|--------|------|------|------|
| `in` | 成员运算符 | 判断键是否存在 | `"name" in d` |
| `not in` | 成员运算符 | 判断键是否不存在 | `"email" not in d` |
| `==` | 相等比较 | 按内容比较两个字典 | `d1 == d2` |
| `!=` | 不等比较 | 判断内容是否不同 | `d1 != d2` |
| `is` | 身份运算符 | 判断是否同一对象 | `d1 is d2` |
| `is not` | 身份运算符 | 判断是否不同对象 | `d1 is not d2` |
| `\|` | 合并运算符 | 合并字典，创建新对象（Python 3.9+） | `d1 \| d2` |
| `\|=` | 更新合并运算符 | 原地合并字典（Python 3.9+） | `d1 \|= d2` |
| `**` | 解包运算符 | 在字典字面量或函数调用中展开字典 | `{**d1, **d2}` |
| `[]` | 下标运算符 | 按键读取/赋值 | `d["name"]` |
| `del` | 删除操作 | 删除指定键 | `del d["name"]` |

### 1.4 最简示例

先用几个最小的例子快速感受每个运算符的作用：

```python
d = {"name": "张三", "age": 28}

# 成员判断
print("name" in d)       # True
print("email" not in d)  # True

# 相等比较
print(d == {"name": "张三", "age": 28})  # True

# 下标访问
print(d["name"])  # 张三
d["city"] = "杭州"  # 下标赋值

# 合并（Python 3.9+）
base = {"a": 1, "b": 2}
override = {"b": 3, "c": 4}
print(base | override)  # {'a': 1, 'b': 3, 'c': 4}
```

**运行结果**：

```text
True
True
True
张三
{'a': 1, 'b': 3, 'c': 4}
```

## 2. 核心内容

### 2.1 成员运算符 in 和 not in

`in` 运算符用于判断某个键是否存在于字典中，返回 `True` 或 `False`。`not in` 则是 `in` 的反义——判断键是否**不**存在。

**需要注意的核心点**：`in` 检查的是字典的**键**，不是值。这是初学者最常踩的坑。

**示例**

```python
user = {"name": "张三", "age": 28, "city": "杭州"}

# in 判断键是否存在
print("name" in user)      # True
print("email" in user)     # False

# not in 判断键是否不存在
print("email" not in user)  # True
print("name" not in user)  # False
```

**运行结果**：

```text
True
False
True
False
```

#### 2.1.1 in 只检查键，不检查值

```python
scores = {"math": 85, "english": 72, "science": 90}

# in 检查的是键
print(85 in scores)          # False —— 85 是值，不是键
print("math" in scores)      # True
```

**运行结果**：

```text
False
True
```

如果你想检查**值**是否存在，需要用 `.values()` 把值视图取出后再 `in`：

```python
# 检查值是否存在
print(85 in scores.values())  # True
```

**运行结果**：

```text
True
```

如果你想检查**键值对**是否存在，用 `.items()`：

```python
# 检查键值对是否存在
print(("math", 85) in scores.items())   # True
print(("math", 99) in scores.items())    # False
```

**运行结果**：

```text
True
False
```

#### 2.1.2 in 的性能优势

字典的 `in` 操作底层是哈希查找，时间复杂度为 O(1)——无论字典有 10 个键还是 10 万个键，查找速度几乎一样。而列表的 `in` 操作是线性扫描，时间复杂度为 O(n)。

```python
import time

big_dict = {i: f"value_{i}" for i in range(100000)}
big_list = list(range(100000))

# 字典查找
start = time.time()
for _ in range(100000):
    99999 in big_dict
dict_time = time.time() - start

# 列表查找
start = time.time()
for _ in range(100000):
    99999 in big_list
list_time = time.time() - start

print(f"字典 in 查找 100000 次: {dict_time:.4f}s")
print(f"列表 in 查找 100000 次: {list_time:.4f}s")
print(f"速度差异: {list_time / dict_time:.0f}x")
```

**运行结果**（具体数值因环境而异）：

```text
字典 in 查找 100000 次: 0.0032s
列表 in 查找 100000 次: 38.6819s
速度差异: 11939x
```

字典比列表快了上万倍——这就是哈希查找的威力。当你的数据需要频繁做"某元素是否存在"的判断时，应优先用字典或集合，而不是列表。

#### 2.1.3 实际应用：安全访问

`in` 运算符最常见的应用场景是在访问字典前先判断键是否存在，避免 `KeyError`：

```python
config = {"host": "localhost", "port": 3306}

# 用 in 做安全检查后再访问
if "timeout" in config:
    print(f"timeout = {config['timeout']}")
else:
    print("timeout 未配置，使用默认值: 30")
```

**运行结果**：

```text
timeout 未配置，使用默认值: 30
```

#### 2.1.4 嵌套字典的成员判断

`in` 只检查当前层级的键，不会递归检查嵌套字典的键：

```python
company = {
    "name": "蚂蚁集团",
    "address": {"city": "杭州", "district": "西湖区"}
}

# in 只检查顶层键
print("address" in company)          # True
print("city" in company)              # False —— city 是嵌套字典的键
print("city" in company["address"])   # True —— 需要逐层检查
```

**运行结果**：

```text
True
False
True
```

### 2.2 相等比较 == 和 !=

`==` 运算符按**内容**比较两个字典——只要所有键和对应的值都相同，两个字典就相等。`!=` 是 `==` 的反义。

**核心特性**：`==` 比较不关心键的顺序——两个字典键的插入顺序不同，但内容相同，仍然判为相等。

**示例**

```python
d1 = {"name": "张三", "age": 28}
d2 = {"name": "张三", "age": 28}
d3 = {"name": "李四", "age": 28}
d4 = {"age": 28, "name": "张三"}  # 键顺序不同

print(d1 == d2)  # True —— 内容完全相同
print(d1 == d3)  # False —— 值不同
print(d1 == d4)  # True —— 键顺序不影响比较结果
print(d1 != d3)  # True
```

**运行结果**：

```text
True
False
True
True
```

#### 2.2.1 顺序不影响比较

Python 3.7+ 字典保持插入顺序，但 `==` 比较时完全不关心顺序——它只比较"两个字典是否有相同的键和对应的值"：

```python
ordered1 = {"a": 1, "b": 2, "c": 3}
ordered2 = {"c": 3, "a": 1, "b": 2}

print(ordered1 == ordered2)  # True
# 但它们的 keys() 视图顺序不同
print(list(ordered1.keys()))  # ['a', 'b', 'c']
print(list(ordered2.keys()))  # ['c', 'a', 'b']
```

**运行结果**：

```text
True
['a', 'b', 'c']
['c', 'a', 'b']
```

#### 2.2.2 嵌套字典的递归比较

`==` 会递归比较嵌套结构——如果值本身是字典或列表，会进一步比较内部内容：

```python
nested1 = {
    "name": "张三",
    "scores": {"math": 85, "english": 72}
}
nested2 = {
    "name": "张三",
    "scores": {"math": 85, "english": 72}
}
nested3 = {
    "name": "张三",
    "scores": {"math": 85, "english": 99}
}

print(nested1 == nested2)  # True —— 递归比较，内容完全相同
print(nested1 == nested3)  # False —— 嵌套值不同
```

**运行结果**：

```text
True
False
```

#### 2.2.3 值类型对比较的影响

字典的 `==` 比较使用值的 `==` 语义，因此整数 `1` 和浮点数 `1.0` 视为相等，`True` 和 `1` 也视为相等：

```python
# 整数和浮点数比较为相等
print({"value": 1} == {"value": 1.0})  # True —— 1 == 1.0

# True 和 1 比较为相等
print({"flag": True} == {"flag": 1})   # True —— True == 1
```

**运行结果**：

```text
True
True
```

#### 2.2.4 不支持大小比较

Python 3 中字典**不支持**大小比较（`<`、`>`、`<=`、`>=`）——尝试使用会抛出 `TypeError`：

```python
d_a = {"a": 1}
d_b = {"b": 2}

try:
    result = d_a < d_b
except TypeError as e:
    print(f"d_a < d_b 报错: TypeError: {e}")
```

**运行结果**：

```text
d_a < d_b 报错: TypeError: '<' not supported between instances of 'dict' and 'dict'
```

#### 2.2.5 实际应用：配置对比

```python
default_config = {"host": "localhost", "port": 3306, "timeout": 30}
current_config = {"host": "localhost", "port": 5432, "timeout": 30}

if current_config == default_config:
    print("配置与默认值一致")
else:
    print("配置与默认值不同，差异键：")
    all_keys = set(current_config) | set(default_config)
    for key in all_keys:
        if current_config.get(key) != default_config.get(key):
            print(f"  {key}: {current_config.get(key)} ≠ {default_config.get(key)}")
```

**运行结果**：

```text
配置与默认值不同，差异键：
  port: 5432 ≠ 3306
```

### 2.3 身份运算符 is 和 is not

`is` 运算符判断两个变量是否指向内存中的**同一个对象**——不是比较内容，而是比较身份（内存地址）。`is not` 是 `is` 的反义。

`is` 和 `==` 的区别是 Python 中最重要的概念之一：

- `==` 比较**内容**：两个字典的键值是否相同
- `is` 比较**身份**：两个变量是否指向同一个字典对象

**示例**

```python
d1 = {"name": "张三", "age": 28}
d2 = {"name": "张三", "age": 28}  # 内容相同，但不是同一对象
d3 = d1                            # 引用赋值，指向同一对象

print(d1 is d2)   # False —— 不同对象
print(d1 is d3)   # True —— 同一对象
print(d1 == d2)   # True —— 内容相同
```

**运行结果**：

```text
False
True
True
```

可以用 `id()` 验证两个变量的内存地址是否相同：

```python
print(f"id(d1) = {id(d1)}")
print(f"id(d2) = {id(d2)}")
print(f"id(d3) = {id(d3)}")
print(f"d1 和 d3 的 id 相同: {id(d1) == id(d3)}")  # True
```

**运行结果**（地址值因环境而异）：

```text
id(d1) = 4385096512
id(d2) = 4300666432
id(d3) = 4385096512
d1 和 d3 的 id 相同: True
```

#### 2.3.1 修改字典内容不改变身份

字典是可变对象——你往里面增删改键值对，对象的身份（内存地址）不会改变：

```python
d = {"a": 1}
original_id = id(d)

d["b"] = 2
d["a"] = 99

print(f"修改前 id: {original_id}")
print(f"修改后 id: {id(d)}")
print(f"id 不变: {id(d) == original_id}")  # True
```

**运行结果**：

```text
修改前 id: 4385097856
修改后 id: 4385097856
id 不变: True
```

#### 2.3.2 空字典不是同一对象

每次用 `{}` 创建空字典都是一个新的独立对象——字典没有整数/字符串那种缓存机制：

```python
e1 = {}
e2 = {}
print(e1 is e2)   # False —— 不同对象
print(e1 == e2)   # True —— 内容相同（都是空)
```

**运行结果**：

```text
False
True
```

#### 2.3.3 实际应用：避免原地修改副作用

`is` 运算符的一个实用场景是判断传入的参数是否是原始对象，如果是就先拷贝一份再操作，避免副作用：

```python
original_data = {"name": "张三", "age": 28}

def process_data(data):
    """如果 data 是原始对象就拷贝后再操作"""
    if data is original_data:
        data = data.copy()
    data["processed"] = True
    return data

processed = process_data(original_data)

print(f"original_data: {original_data}")  # 不受影响
print(f"processed:     {processed}")
```

**运行结果**：

```text
original_data: {'name': '张三', 'age': 28}
processed:     {'name': '张三', 'age': 28, 'processed': True}
```

#### 2.3.4 is None 判断

`is` 最常见的用途是判断变量是否为 `None`——因为 `None` 是单例对象，整个 Python 中只有一个 `None`，用 `is` 判断比 `==` 更准确、更 Pythonic：

```python
value = None
print(value is None)       # True
print(value is not None)  # False

# 注意：空字典不是 None
empty = {}
print(empty is None)      # False
print(not empty)           # True —— 空字典是 falsy，但不是 None
```

**运行结果**：

```text
True
False
False
True
```

### 2.4 合并运算符 | 和 |=

Python 3.9（PEP 584）引入了字典合并运算符 `|` 和更新合并运算符 `|=`，让字典合并的写法更直观——类似于集合的并集运算符。

| 运算符 | 名称 | 行为 | 是否创建新对象 |
|--------|------|------|---------------|
| `\|` | 合并 | 将两个字典合并为新字典 | 是 |
| `\|=` | 更新合并 | 将右字典合并到左字典中（原地修改） | 否 |

#### 2.4.1 | 合并运算符

`|` 创建一个新字典——把两个字典的键值对合并到一起，遇到同名键时**右边的值优先**：

```python
default_config = {"host": "localhost", "port": 3306, "timeout": 30}
user_config = {"port": 5432, "debug": True}

merged = default_config | user_config

print(f"default_config: {default_config}")  # 不受影响
print(f"user_config:    {user_config}")      # 不受影响
print(f"merged:         {merged}")
```

**运行结果**：

```text
default_config: {'host': 'localhost', 'port': 3306, 'timeout': 30}
user_config:    {'port': 5432, 'debug': True}
merged:         {'host': 'localhost', 'port': 5432, 'timeout': 30, 'debug': True}
```

键覆盖规则：当两个字典有相同的键时，右边的值覆盖左边的值：

```python
base = {"a": 1, "b": 2, "c": 3}
override = {"b": 20, "d": 4}

result = base | override
print(result)  # {'a': 1, 'b': 20, 'c': 3, 'd': 4} —— b 被覆盖
```

**运行结果**：

```text
{'a': 1, 'b': 20, 'c': 3, 'd': 4}
```

#### 2.4.2 |= 更新合并运算符

`|=` 是原地修改——把右边字典的键值对合并到左边字典中，不创建新对象：

```python
config = {"host": "localhost", "port": 3306}
updates = {"port": 5432, "debug": True}

config |= updates

print(f"config: {config}")  # {'host': 'localhost', 'port': 5432, 'debug': True} —— 原地修改
```

**运行结果**：

```text
config: {'host': 'localhost', 'port': 5432, 'debug': True}
```

对比 `|` 和 `|=` 的关键区别：

```python
dict1 = {"a": 1}
dict2 = {"b": 2}

# | 创建新字典
new_dict = dict1 | dict2
print(dict1 is new_dict)  # False —— 新对象

# |= 原地修改
dict1 |= dict2
print(dict1)               # {'a': 1, 'b': 2} —— 原字典被修改
```

**运行结果**：

```text
False
{'a': 1, 'b': 2}
```

#### 2.4.3 | vs update() vs |=

这三种方式都能实现字典合并，区别在于是否创建新对象：

| 方式 | 创建新对象 | 原字典是否修改 | 语法 |
|------|-----------|-------------|------|
| `\|` | 是 | 否 | `result = d1 \| d2` |
| `\|=` | 否 | 是 | `d1 \|= d2` |
| `update()` | 否 | 是 | `d1.update(d2)` |

```python
# 方式一：| 创建新字典（不改原字典）
result1 = {"a": 1, "b": 2} | {"b": 20, "c": 3}

# 方式二：update() 原地修改
base2 = {"a": 1, "b": 2}
base2.update({"b": 20, "c": 3})

# 方式三：|= 原地修改
base3 = {"a": 1, "b": 2}
base3 |= {"b": 20, "c": 3}

print(f"|  创建新字典: {result1}")
print(f"update() 原地修改: {base2}")
print(f"|=     原地修改: {base3}")
```

**运行结果**：

```text
|  创建新字典: {'a': 1, 'b': 20, 'c': 3}
update() 原地修改: {'a': 1, 'b': 20, 'c': 3}
|=     原地修改: {'a': 1, 'b': 20, 'c': 3}
```

#### 2.4.4 链式合并

`|` 运算符支持链式使用——从左到右依次合并，右边的优先级最高：

```python
config1 = {"a": 1}
config2 = {"b": 2}
config3 = {"c": 3}
config4 = {"d": 4}

chained = config1 | config2 | config3 | config4
print(chained)  # {'a': 1, 'b': 2, 'c': 3, 'd': 4}
```

**运行结果**：

```text
{'a': 1, 'b': 2, 'c': 3, 'd': 4}
```

同名键在链式合并中的覆盖——最右边的优先：

```python
left = {"x": "left"}
middle = {"x": "middle"}
right = {"x": "right"}

print(left | middle | right)  # {'x': 'right'} —— 最右边的优先
```

**运行结果**：

```text
{'x': 'right'}
```

#### 2.4.5 实际应用：多级配置覆盖

多级配置覆盖是 `|` 运算符最典型的应用场景——默认配置 < 环境配置 < 用户配置，优先级从低到高依次覆盖：

```python
DEFAULTS = {
    "host": "localhost",
    "port": 3306,
    "timeout": 30,
    "retry": 3,
    "debug": False
}

ENV = {
    "host": "production.db.com",
    "port": 5432
}

USER = {
    "debug": True,
    "timeout": 60
}

# 优先级：USER > ENV > DEFAULTS
final_config = DEFAULTS | ENV | USER

print(f"最终配置: {final_config}")
```

**运行结果**：

```text
最终配置: {'host': 'production.db.com', 'port': 5432, 'timeout': 60, 'retry': 3, 'debug': True}
```

#### 2.4.6 性能对比：| vs update() vs **

三种合并方式的性能差异很小，在大数据量下才有可感知的区别：

```python
import time

big1 = {i: f"val_{i}" for i in range(50000)}
big2 = {i: f"new_{i}" for i in range(25000, 75000)}

# | 运算符合并
start = time.time()
merged_pipe = big1 | big2
pipe_time = time.time() - start

# update() 合并
start = time.time()
merged_update = big1.copy()
merged_update.update(big2)
update_time = time.time() - start

# ** 解包合并
start = time.time()
merged_unpack = {**big1, **big2}
unpack_time = time.time() - start

print(f"|  运算符: {pipe_time:.4f}s")
print(f"update(): {update_time:.4f}s")
print(f"** 解包:  {unpack_time:.4f}s")
print(f"结果相同: {merged_pipe == merged_update == merged_unpack}")
```

**运行结果**（具体数值因环境而异）：

```text
|  运算符: 0.0012s
update(): 0.0009s
** 解包:  0.0008s
结果相同: True
```

三者性能在同一量级，选择哪种主要看可读性和场景需求：

- `|` 语义最清晰——"合并"，且不修改原字典，适合纯函数风格
- `|=` 适合需要原地修改的场景
- `update()` 兼容旧版本 Python，且可以接受非字典的可迭代键值对
- `**` 解包适合在合并的同时添加新键值对

### 2.5 解包运算符 **

`**` 运算符（PEP 448，Python 3.5+）用于将字典"展开"为键值对。它可以在两个场景中使用：字典字面量中合并字典，以及函数调用中传参。

#### 2.5.1 在字典字面量中合并

`**` 将字典展开为键值对，放入新的字典字面量中：

```python
default_config = {"host": "localhost", "port": 3306}
override_config = {"port": 5432, "debug": True}

merged = {**default_config, **override_config}
print(merged)  # {'host': 'localhost', 'port': 5432, 'debug': True}
```

**运行结果**：

```text
{'host': 'localhost', 'port': 5432, 'debug': True}
```

键覆盖规则与 `|` 一致——右边的 `**` 优先：

```python
base = {"a": 1, "b": 2}
override = {"b": 20, "c": 30}
result = {**base, **override}
print(result)  # {'a': 1, 'b': 20, 'c': 30}
```

**运行结果**：

```text
{'a': 1, 'b': 20, 'c': 30}
```

#### 2.5.2 在解包的同时添加键值对

`**` 解包的一个独特优势是可以在展开的同时添加新的键值对——`|` 运算符做不到这一点：

```python
original = {"name": "张三", "age": 28}
extended = {**original, "city": "杭州", "email": "zhang@example.com"}

print(f"original: {original}")  # 不受影响
print(f"extended: {extended}")  # 新增了 city 和 email
```

**运行结果**：

```text
original: {'name': '张三', 'age': 28}
extended: {'name': '张三', 'age': 28, 'city': '杭州', 'email': 'zhang@example.com'}
```

#### 2.5.3 在函数调用中传参

`**` 的另一个重要用途是在函数调用时把字典解包为关键字参数：

```python
def create_user(name, age, city, email):
    return {"name": name, "age": age, "city": city, "email": email}

# 传统方式：逐个传参
user1 = create_user("张三", 28, "杭州", "zhang@example.com")

# ** 解包方式：从字典解包传参
user_data = {"name": "张三", "age": 28, "city": "杭州", "email": "zhang@example.com"}
user2 = create_user(**user_data)

print(f"传统方式: {user1}")
print(f"解包方式: {user2}")
print(f"结果相同: {user1 == user2}")  # True
```

**运行结果**：

```text
传统方式: {'name': '张三', 'age': 28, 'city': '杭州', 'email': 'zhang@example.com'}
解包方式: {'name': '张三', 'age': 28, 'city': '杭州', 'email': 'zhang@example.com'}
结果相同: True
```

#### 2.5.4 ** 与普通参数混用

`**` 解包可以和普通位置参数、关键字参数混用：

```python
def greet(greeting, name, **kwargs):
    """greeting 和 name 是必填参数，kwargs 收集剩余的键值对"""
    message = f"{greeting}, {name}!"
    if "title" in kwargs:
        message = f"{greeting}, {kwargs['title']} {name}!"
    return message

# 部分手动传参，部分用 ** 解包
extra = {"title": "博士", "age": 28}
msg = greet("你好", "张三", **extra)
print(msg)  # 你好，博士 张三！
```

**运行结果**：

```text
你好，博士 张三!
```

#### 2.5.5 多个 ** 连用

可以在一个字典字面量中使用多个 `**` 解包：

```python
d1 = {"a": 1}
d2 = {"b": 2}
d3 = {"c": 3}
d4 = {"d": 4}

multi = {**d1, **d2, **d3, **d4, "e": 5}
print(multi)  # {'a': 1, 'b': 2, 'c': 3, 'd': 4, 'e': 5}
```

**运行结果**：

```text
{'a': 1, 'b': 2, 'c': 3, 'd': 4, 'e': 5}
```

#### 2.5.6 ** vs | 对比

`**` 解包合并和 `|` 运算符合并的结果完全相同，区别在于适用场景和语法灵活性：

| 维度 | `**` 解包 | `\|` 运算符 |
|------|---------|---------|
| 最低 Python 版本 | 3.5+ | 3.9+ |
| 合并时添加新键 | 支持（`{**d, "new": 1}`） | 需额外操作 |
| 函数调用传参 | 支持 | 不支持 |
| 语义清晰度 | "展开" | "合并"（更直观） |
| 链式可读性 | 嵌套 `**` 稍显密集 | 链式 `\|` 更清晰 |

```python
dict1 = {"a": 1, "b": 2}
dict2 = {"b": 3, "c": 4}

# 两种方式结果相同
merged_pipe = dict1 | dict2
merged_unpack = {**dict1, **dict2}

print(merged_pipe == merged_unpack)  # True
```

**运行结果**：

```text
True
```

#### 2.5.7 实际应用：配置模板工厂

```python
BASE_CONFIG = {

def make_config(env_name, **overrides):

dev_config = make_config("dev", log_level="DEBUG", timeout=10)
```


### 2.6 下标运算符 [] 和 del 操作

下标运算符 `[]` 是字典最基本的操作——按键读取和赋值。`del` 操作用于删除指定键。它们虽然不是传统意义上的"运算符"，但构成了字典最核心的交互方式。

#### 2.6.1 下标读取

```python
user = {"name": "张三", "age": 28, "city": "杭州"}

print(user["name"])   # 张三
print(user["age"])    # 28
```

**运行结果**：

```text
张三
28
```

键不存在时报 `KeyError`：

```python
try:
    print(user["email"])
except KeyError as e:
    print(f"user['email'] → KeyError: {e}")
```

**运行结果**：

```text
user['email'] → KeyError: 'email'
```

安全访问用 `.get()`，不存在时返回 `None` 或指定的默认值：

```python
print(user.get("email"))          # None
print(user.get("email", "未填写"))  # 未填写
```

**运行结果**：

```text
None
未填写
```

#### 2.6.2 下标赋值（修改/新增）

`[]` 既可以修改已有键的值，也可以新增键值对：

```python
user = {"name": "张三", "age": 28}

# 修改已有键
user["age"] = 30
print(f"修改后: {user}")

# 新增键
user["city"] = "杭州"
print(f"新增后: {user}")
```

**运行结果**：

```text
修改后: {'name': '张三', 'age': 30}
新增后: {'name': '张三', 'age': 30, 'city': '杭州'}
```

#### 2.6.3 del 删除键值对

`del` 语句用于删除字典中指定键的键值对——如果键不存在会报 `KeyError`：

```python
user = {"name": "张三", "age": 28, "city": "杭州", "email": "z@x.com"}

del user["email"]
print(f"删除 email 后: {user}")

# del 删除不存在的键报 KeyError
try:
    del user["phone"]
except KeyError as e:
    print(f"del user['phone'] → KeyError: {e}")
```

**运行结果**：

```text
删除 email 后: {'name': '张三', 'age': 28, 'city': '杭州'}
del user['phone'] → KeyError: 'phone'
```

#### 2.6.4 del vs pop

`del` 和 `pop()` 都能删除键值对，区别在于 `pop()` 会返回被删除的值，而 `del` 不返回：

```python
config = {"host": "localhost", "port": 3306, "debug": True}

# del：删就删了，不返回值
del config["debug"]
print(f"del 后: {config}")

# pop：删除并返回被删除的值
port = config.pop("port")
print(f"pop('port') 返回: {port}")
print(f"pop 后: {config}")

# pop 可以指定默认值避免 KeyError
removed = config.pop("timeout", None)
print(f"pop('timeout', None) 返回: {removed}")
```

**运行结果**：

```text
del 后: {'host': 'localhost', 'port': 3306}
pop('port') 返回: 3306
pop 后: {'host': 'localhost'}
pop('timeout', None) 返回: None
```

| 操作 | 返回值 | 键不存在时 | 适用场景 |
|------|--------|-----------|---------|
| `del d[key]` | 无 | `KeyError` | 只需要删除，不需要被删除的值 |
| `d.pop(key)` | 被删除的值 | `KeyError` | 需要使用被删除的值 |
| `d.pop(key, default)` | 被删除的值或默认值 | 返回默认值 | 安全删除，避免异常 |

#### 2.6.5 嵌套字典的下标访问

对嵌套字典，可以用链式下标逐层访问：

```python
company = {
    "name": "蚂蚁集团",
    "address": {
        "city": "杭州",
        "district": {
            "name": "西湖区",
            "code": "330106"
        }
    }
}

print(company["address"]["city"])              # 杭州
print(company["address"]["district"]["name"])   # 西湖区
print(company["address"]["district"]["code"])   # 330106
```

**运行结果**：

```text
杭州
西湖区
330106
```

嵌套赋值和删除：

```python
# 嵌套赋值
company["address"]["district"]["code"] = "330100"
print(f"修改后: {company['address']['district']}")

# 嵌套 del
del company["address"]["district"]["code"]
print(f"删除后: {company['address']['district']}")
```

**运行结果**：

```text
修改后: {'name': '西湖区', 'code': '330100'}
删除后: {'name': '西湖区'}
```

#### 2.6.6 安全的逐层访问

当嵌套层级较深且中间层可能不存在时，直接链式下标会抛出 `KeyError`。用 `.get()` 配合空字典默认值可以安全访问：

```python
nested = {"a": {"b": {"c": 1}}}

# 直接链式访问，中间层不存在会 KeyError
try:
    value = nested["x"]["y"]["z"]
except KeyError as e:
    print(f"nested['x']['y']['z'] → KeyError: {e}")

# 安全访问：逐层用 .get() 配合默认空字典
value = nested.get("x", {}).get("y", {}).get("z")
print(f"安全访问: {value}")  # None

value2 = nested.get("a", {}).get("b", {}).get("c")
print(f"安全访问有效路径: {value2}")  # 1
```

**运行结果**：

```text
nested['x']['y']['z'] → KeyError: 'x'
安全访问: None
安全访问有效路径: 1
```

#### 2.6.7 布尔上下文与 len

字典在布尔上下文中：空字典为 `False`（falsy），非空字典为 `True`（truthy）。`len()` 返回键值对的数量。

```python
# 布尔上下文
print(bool({}))           # False —— 空字典为 falsy
print(bool({"a": 1}))     # True —— 非空字典为 truthy

# 用 if 判断字典是否为空
data = {}
if not data:
    print("data 是空字典")

data = {"key": "value"}
if data:
    print("data 非空")
```

**运行结果**：

```text
False
True
data 是空字典
data 非空
```

```python
# len 计算键值对数量
cart = {"apple": 3, "banana": 5, "orange": 2}
print(f"商品种类数: {len(cart)}")  # 3

cart["grape"] = 10
print(f"添加后种类数: {len(cart)}")  # 4

del cart["apple"]
print(f"删除后种类数: {len(cart)}")  # 3
```

**运行结果**：

```text
商品种类数: 3
```

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

| 场景 | 不推荐 | 推荐 | 原因 |
|------|--------|------|------|
| 判断键是否存在 | `if d.get("key") is not None` | `if "key" in d` | `get()` 返回 `None` 可能是值就是 `None`，`in` 语义更准确 |
| 安全访问 | `d["key"]` 捕获 `KeyError` | `d.get("key", default)` | `get()` 更简洁，不需要 try/except |
| 合并字典（不改原字典） | `d.copy(); d.update(other)` | `d \| other`（3.9+）或 `{**d, **other}` | 一行搞定，意图更清晰 |
| 合并字典（原地修改） | `d.update(other)` | `d \|= other`（3.9+） | 更简洁，语义一致 |
| 删除并取值 | `val = d[key]; del d[key]` | `val = d.pop(key)` | 一步到位，原子操作 |
| 判断变量是否为 None | `if d == None` | `if d is None` | `is` 更准确，PEP 8 推荐 |
| 判断字典是否为空 | `if len(d) == 0` | `if not d` | 更 Pythonic，利用 falsy 语义 |

### 3.2 常见错误模式及修正

**错误一：混淆 in 检查键和检查值**

```python
# 不推荐：想检查值是否存在，却用 in 检查键
scores = {"math": 85}
if 85 in scores:       # False —— in 检查的是键
    print("有人考了 85 分")

# 推荐：用 .values() 检查值
if 85 in scores.values():  # True
    print("有人考了 85 分")
```

**错误二：合并字典时不小心修改了原字典**

```python
default = {"host": "localhost", "port": 3306}
user = {"port": 5432}

# 不推荐：update 原地修改了 default
default.update(user)
# default 被污染了！如果其他地方还依赖默认配置就会出 bug

# 推荐：用 | 或 ** 创建新字典
final = default | user  # default 不受影响
```

**错误三：用 == 判断是否同一对象**

```python
d1 = {"a": 1}
d2 = {"a": 1}

# 不推荐：用 == 判断同一对象（内容相同时会误判）
if d1 == d2:
    print("同一对象")  # 会被执行！但它们其实不是同一对象

# 推荐：用 is 判断同一对象
if d1 is d2:
    print("同一对象")  # 不会被执行
```

### 3.3 版本兼容性建议

`|` 和 `|=` 运算符需要 Python 3.9+。如果需要兼容 3.8 或更早版本，使用 `**` 解包或 `update()`：

```python
# Python 3.9+ 方式（推荐，语法最清晰）
merged = default | user

# Python 3.5+ 兼容方式
merged = {**default, **user}

# Python 3.0+ 兼容方式
merged = default.copy()
merged.update(user)
```

| 要求最低版本 | 推荐方式 | 示例 |
|-------------|---------|------|
| Python 3.9+ | `\|` 运算符 | `d1 \| d2` |
| Python 3.5+ | `**` 解包 | `{**d1, **d2}` |
| Python 3.0+ | `copy` + `update` | `d1.copy().update(d2)` |

## 4. 原理

### 4.1 in 运算符的底层机制：哈希查找

字典的 `in` 运算符底层调用的是字典的 `__contains__` 方法，它使用哈希查找——先计算键的哈希值，然后直接定位到哈希表中的槽位，时间复杂度为 O(1)。

```text
in 操作的查找流程：

  "name" in d
       │
       ↓
  计算 hash("name")           → 例如 hash 值为 1234567
       │
       ↓
  取哈希值对表大小取模          → 1234567 % 8 = 7（槽位 7）
       │
       ↓
  检查槽位 7 是否有值
       │
       ├── 有值且键匹配 → True
       ├── 有值但键不匹配（哈希冲突）→ 线性探测下一个槽位
       └── 无值 → False
```

对比列表的 `in` 操作——列表需要从头到尾逐个比较，时间复杂度为 O(n)：

```text
列表 in 操作的查找流程：

  99999 in big_list
       │
       ↓
  遍历列表：list[0] == 99999? → 否
            list[1] == 99999? → 否
            list[2] == 99999? → 否
            ...
            list[99998] == 99999? → 否
            list[99999] == 99999? → 是 → True
            
  最坏情况需要遍历整个列表 → O(n)
```

### 4.2 == 比较的递归机制

字典的 `==` 比较不是简单的内存比较，而是递归比较内容。Python 内部对字典的 `==` 实现逻辑大致如下：

```text
d1 == d2 的比较流程：

  1. 检查两侧是否都是 dict 类型（如果不是，返回 NotImplemented）
  2. 检查 len(d1) == len(d2)，长度不同直接返回 False
  3. 遍历 d1 的每个键值对：
     ├── 键存在于 d2 中？
     │    ├── 不存在 → False
     │    └── 存在 → 比较对应的值：d1[key] == d2[key]
     │         ├── 值相等 → 继续下一个键
     │         └── 值不等 → False
     └── 所有键值对都匹配 → True
```

由于值比较也使用 `==`，如果值本身是字典或列表，会递归进行比较。这就解释了为什么嵌套字典也能正确比较。

### 4.3 | 运算符的实现：__or__ 和 __ror__

`|` 运算符在字典上的行为是通过特殊方法实现的（PEP 584）：

- `dict.__or__(self, other)`：实现 `d1 | d2`，返回新字典
- `dict.__ror__(self, other)`：实现 `other | d1`（右操作数模式，当左操作数不支持 `|` 时调用）
- `dict.__ior__(self, other)`：实现 `d1 |= d2`，原地修改并返回 self

```text
d1 | d2 的调用流程：

  d1.__or__(d2)
       │
       ├── d2 是 dict 类型？
       │    ├── 是 → 创建新 dict，先复制 d1，再合并 d2
       │    │        遇到同名键时用 d2 的值覆盖
       │    │        返回新 dict
       │    └── 否 → 返回 NotImplemented
       │             Python 尝试 d2.__ror__(d1)
       │
       └── 如果都返回 NotImplemented → TypeError
```

`|=` 运算符（`__ior__`）则是对原字典做原地修改——等价于 `dict.update()`，但返回的是修改后的原字典本身（而非 `update()` 返回的 `None`）。

## 5. 总结

本文围绕字典与运算符展开，主要介绍了以下内容：

- **成员运算符 `in` / `not in`**：判断键是否存在于字典中，底层是 O(1) 哈希查找，比列表快数万倍；`in` 只检查键不检查值，检查值需用 `.values()`，检查键值对需用 `.items()`
- **相等比较 `==` / `!=`**：按内容递归比较，不关心键的插入顺序；整数与浮点数 `1 == 1.0` 视为相等，`True == 1` 也视为相等；Python 3 中字典不支持大小比较
- **身份运算符 `is` / `is not`**：比较两个变量是否指向同一个内存对象，与 `==` 比较"内容"不同，`is` 比较"身份"；修改字典内容不改变其身份；`is None` 是判断空值的标准写法
- **合并运算符 `|` / `|=`（Python 3.9+）**：`|` 创建新字典合并两个字典，右边键覆盖左边；`|=` 原地合并；支持链式合并；典型的多级配置覆盖场景：`DEFAULTS | ENV | USER`
- **解包运算符 `**`（Python 3.5+）**：在字典字面量中展开合并，或在函数调用中把字典解包为关键字参数；可在合并时同时添加新键值对，这是 `|` 做不到的
- **下标运算符 `[]` 和 `del`**：按键读取/赋值/删除；键不存在时 `[]` 报 `KeyError`，`.get()` 安全访问返回默认值；`del` 删除不返回值，`pop()` 删除并返回值；嵌套字典可用链式下标逐层访问，安全方式是用 `.get(key, {})` 逐层兜底
- **最佳实践**：判断键用 `in` 不用 `get() is not None`；合并不改原字典用 `|` 或 `**`；判断 `None` 用 `is None` 不用 `== None`；判断空字典用 `if not d` 不用 `len(d) == 0`
- **版本兼容**：`|` 需 Python 3.9+，`**` 需 Python 3.5+，`copy + update` 兼容所有版本
