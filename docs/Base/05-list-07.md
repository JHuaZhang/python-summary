## 1. 介绍

### 1.1 什么是 reverse 与 reversed

`reverse` 与 `reversed` 是 Python 中"反转序列顺序"的两种形态,名字几乎一样,语义却截然不同,是新手极易混淆的一对:

- **`list.reverse()`**:列表的**方法**,**原地修改**调用它的列表,把首尾顺序颠倒,返回 `None`。只作用于 `list`,其他序列没有此方法。
- **`reversed(iterable)`**:内置**函数**,接收任意序列(或实现了 `__reversed__` 的对象),返回一个**惰性迭代器**,逐个**倒序**产出元素,不改原对象。

```python
nums = [1, 2, 3, 4, 5]

# reverse:原地改,返回 None
result = nums.reverse()
print(result)          # None
print(nums)            # [5, 4, 3, 2, 1] —— 原列表已反转

words = ["a", "b", "c"]

# reversed:返回迭代器,原对象不变
rev_it = reversed(words)
print(rev_it)          # <list_reverseiterator object at ...> —— 不是列表!
print(list(rev_it))    # ['c', 'b', 'a'] —— 物化后看到结果
print(words)           # ['a', 'b', 'c'] —— 原列表未变
```

二者的核心区别一句话:**`reverse` 改自己、`reversed` 造一个倒序迭代器**。此外,`reverse` 只能对 `list` 调用,`reversed` 能作用于任何序列(列表、元组、字符串、range 等)及其他可反转对象。

两者都**不涉及排序**——它们只是"把现有顺序首尾颠倒",与 `sort`/`sorted` 的"按大小排序"毫无关系。理解这点,就不会把 `reverse()` 误当成 `sort(reverse=True)`。本篇系统讲解二者的语法、返回值、适用对象、惰性迭代器的特性、与其他反转写法的对照,以及性能选型。

### 1.2 基本语法与最小用法

**`reverse` 的签名**:`list.reverse()` —— 无参数,原地反转,返回 `None`。

```python
lst = [1, 2, 3]
lst.reverse()             # 原地反转
print(lst)                # [3, 2, 1]
```

**`reversed` 的签名**:`reversed(seq)` —— 接收序列,返回倒序迭代器。

```python
# 列表
print(list(reversed([1, 2, 3])))     # [3, 2, 1]

# 元组
print(list(reversed((1, 2, 3))))     # [3, 2, 1]

# 字符串
print(list(reversed("abc")))         # ['c', 'b', 'a']
print("".join(reversed("abc")))      # 'cba' —— 拼回字符串

# range
print(list(reversed(range(5))))      # [4, 3, 2, 1, 0]
```

**速查表**:

| 维度 | `list.reverse()` | `reversed(seq)` | `seq[::-1]` |
|------|------------------|-----------------|-------------|
| 形态 | 列表方法 | 内置函数 | 切片表达式 |
| 作用对象 | 仅 `list` | 任何序列(有 `__reversed__` 或支持随机访问) | 任何支持切片的序列 |
| 是否原地 | 是(改原列表) | 否(返回迭代器) | 否(返回新对象) |
| 返回值 | `None` | 倒序迭代器(惰性) | 反转后的新对象(同切片类型) |
| 原对象是否变 | 变 | 不变 | 不变 |
| 是否立即生成全部 | 是(已反转) | 否(按需产出) | 是(立即) |
| 内存 | O(1) 额外 | O(1) 额外(迭代器) | O(n)(复制) |

三个写法都能"反转",但代价与形态各异:`reverse` 省内存但改原对象、`reversed` 省内存且不改原对象(惰性)、`[::-1]` 不改原对象但要立即复制整份。

### 1.3 为什么 reverse 返回 None,而 reversed 返回迭代器

这是 Python "原地方法返回 None"约定的又一对实例(与 `sort`/`append` 同源):

```python
# ❌ 经典错误:reverse 返回 None,赋值后丢失列表
nums = [1, 2, 3]
nums = nums.reverse()       # nums 变 None!

# ✅ reverse 原地改,无需重新赋值
nums = [1, 2, 3]
nums.reverse()
print(nums)                 # [3, 2, 1]
```

`reverse` 原地修改、返回 None,提醒调用方"我没产生新对象"。而 `reversed` 是纯函数,不碰原对象、返回一个新的迭代器,适合保留原数据、惰性处理的场景:

```python
# reversed 适合函数式 / 惰性
for item in reversed(long_list):     # 不复制整份,逐个倒序产出
    process(item)

# reverse 不行,因为返回 None,且它改原列表
# for item in long_list.reverse():  ❌ None 不可迭代
long_list.reverse()
for item in long_list:
    process(item)                    # 必须先反转再正向遍历,两步
```

记住口诀:**原地方法返回 None、纯函数返回新对象/迭代器**。`reverse` 改自己给 `None`,`reversed` 不改给迭代器,`[::-1]` 不改给新副本——三者各司其职。

### 1.4 reverse / reversed 与 sort / sorted 的对照

`reverse`/`reversed` 与 `sort`/`sorted` 是镜像关系的两对,记忆时可以类同,但本质操作完全不同:

| 维度 | `sort`/`sorted` | `reverse`/`reversed` |
|------|-----------------|----------------------|
| 操作 | 按大小**排序** | 首尾**颠倒**(不比较大小) |
| 原地版 | `list.sort()` 返回 None | `list.reverse()` 返回 None |
| 新对象版 | `sorted(iter)` 返回新列表 | `reversed(seq)` 返回迭代器 |
| 适用对象 | `sort` 仅 list;`sorted` 任意可迭代 | `reverse` 仅 list;`reversed` 序列 |
| 复杂度 | O(n log n) | O(n)(reverse 原地 / reversed 逐个) |

最关键的区别:**`reverse`/`reversed` 不排序**,只把顺序倒过来。`lst.reverse()` 和 `lst.sort()` 长得像,但一个颠倒顺序、一个按大小排,完全不同操作:

```python
a = [3, 1, 4, 1, 5]
a.reverse()             # 颠倒:把 [3,1,4,1,5] 倒成 [5,1,4,1,3]
print(a)                # [5, 1, 4, 1, 3] —— 不是排序!

b = [3, 1, 4, 1, 5]
b.sort(reverse=True)    # 降序排序:按大小从大到小
print(b)                # [5, 4, 3, 1, 1]
```

对已升序的列表,`reverse()` 与 `sort(reverse=True)` 结果恰好相同(因为降序=升序逆转),但对乱序列表两者天差地别。把"反转"和"降序排序"分清,是本篇与上一篇的衔接点。

## 2. 核心内容

本章逐节详解 `reverse` 的原地语义、`reversed` 的惰性迭代器特性、二者适用对象差异、与 `[::-1]` 切片的对照、遍历场景、以及性能。每节遵循"文字详解 → demo → 运行结果说明 → 陷阱"。

### 2.1 `list.reverse()`:原地反转,返回 None

`reverse()` 把调用它的列表首尾颠倒——第 0 个与最后一个交换、第 1 个与倒数第二个交换……直到中间。原地完成,列表 `id` 不变,长度不变,只是元素顺序换了。

```python
nums = [1, 2, 3, 4, 5]
old_id = id(nums)
nums.reverse()
print(nums)                  # [5, 4, 3, 2, 1]
print(id(nums) == old_id)    # True —— 同一个对象,原地改
print(len(nums))             # 5 —— 长度不变
```

**仅 list 有 `reverse` 方法**:

```python
t = (1, 2, 3)
# t.reverse()   ❌ AttributeError: tuple 没有 reverse 方法(不可变,无法原地改)

s = "abc"
# s.reverse()   ❌ AttributeError: str 同样没有
```

元组、字符串等不可变序列无 `reverse` 方法,因为原地修改对它们无意义。它们的反转要用 `reversed` 或 `[::-1]`。

**何时用 `reverse`**:

- 你**不再需要**原顺序,反转结果即结果;
- 想省内存(原地,不复制);
- 数据处理中途需要把列表倒过来。

```python
# 把日志从新到旧处理:原列表是旧→新,反转后新→旧
logs = load_logs()          # [log_old, ..., log_new]
logs.reverse()              # 原地倒成 [log_new, ..., log_old]
for log in logs:
    handle(log)             # 从最新日志开始处理
```

**返回值陷阱**:再次强调,`reverse` 返回 `None`。`nums = nums.reverse()` 会把 `nums` 变 `None`。需要"反转的副本且保留原列表"时,用 `list(reversed(nums))`、`nums[::-1]`,或 `copy = nums[:]; copy.reverse()`。

**reverse 是 O(n) 时间 O(1) 额外空间**:原地交换 n/2 次即完成,无需额外分配。详见 4.1 节。

### 2.2 `reversed(seq)`:返回惰性倒序迭代器

`reversed` 返回的不是列表,而是一个**迭代器对象**(对 list 是 `list_reverseiterator`),它**惰性**产出倒序元素——每次 `next()` 给一个,不预先复制全部。原对象不被修改。

```python
nums = [1, 2, 3, 4, 5]
rev = reversed(nums)        # 迭代器,尚未产出任何元素
print(type(rev))            # <class 'list_reverseiterator'>

# 迭代器是"一次性"的:逐个产出,耗尽即止
print(next(rev))            # 5
print(next(rev))            # 4
print(list(rev))            # [3, 2, 1] —— 剩余的,前面取过的没了

# 原对象未变
print(nums)                 # [1, 2, 3, 4, 5]
```

**迭代器只能遍历一次**:上例先 `next` 两次取走 5、4,再 `list(rev)` 只剩 3、2、1。耗尽后再迭代为空:

```python
rev = reversed([1, 2, 3])
list(rev)                   # [3, 2, 1]
list(rev)                   # [] —— 已耗尽,第二次为空
```

这是迭代器的通性(详见《生成器与迭代器》),`reversed` 返回的迭代器同样"用完即空"。若需多次使用,先 `list(reversed(seq))` 物化成列表。

**用于 for 循环倒序遍历**(最常见的用法):

```python
# 倒序遍历列表,不复制
for item in reversed(tasks):
    print(item)             # 最后一个任务先打印
```

`reversed` 在循环里最自然——`for ... in reversed(seq)` 既倒序又不复制整份数据,省内存。对比传统 `for i in range(len-1, -1, -1)` 索引写法,`reversed` 更清晰:

```python
# ❌ 传统索引倒序:笨重,易 off-by-one
for i in range(len(tasks) - 1, -1, -1):
    print(tasks[i])

# ✅ reversed:直白
for item in reversed(tasks):
    print(item)
```

**物化成需要的类型**:

```python
# 想要反转的列表
new_list = list(reversed([1, 2, 3]))     # [3, 2, 1]

# 想要反转的元组
new_tuple = tuple(reversed((1, 2, 3)))   # (3, 2, 1)

# 想要反转的字符串
new_str = "".join(reversed("abc"))       # 'cba'
```

`reversed` 只给迭代器,要具体容器需自行物化(`list`/`tuple`/`"".join` 等)。

### 2.3 reversed 的适用对象:序列与 __reversed__

`reversed` 能作用于哪些对象?它要求对象是**序列**(有 `__len__` 和 `__getitem__`,能按索引随机访问),或显式实现了 `__reversed__` 方法。

| 对象 | `reversed` 是否可用 | 原因 |
|------|-------------------|------|
| `list` | ✅ | 序列,且实现高效 `__reversed__` |
| `tuple` | ✅ | 序列,通过 `__len__`+`__getitem__` 从尾向前访问 |
| `str` | ✅ | 序列 |
| `range` | ✅ | 实现 `__reversed__`(高效,直接逆推步长) |
| `dict`(3.8+) | ✅ | 实现 `__reversed__`(按键倒序,保插入序的反向) |
| `set` | ❌ | 无序集合,没有"顺序"故无法反转 |
| `生成器`/迭代器 | ❌ | 只能向前流式产出,无法回头 |
| `map`/`filter` 对象 | ❌ | 一次性迭代器,非序列 |

```python
# range:高效倒序
print(list(reversed(range(1, 6))))     # [5, 4, 3, 2, 1]

# dict(3.8+):按键的插入序倒序
d = {"a": 1, "b": 2, "c": 3}
print(list(reversed(d)))               # ['c', 'b', 'a']
print(list(reversed(d.items())))       # [('c',3),('b',2),('a',1)]

# set:不可反转
try:
    reversed({1, 2, 3})
except TypeError as e:
    print(e)                           # 'set' object is not reversible

# 生成器:不可反转
try:
    reversed(x for x in range(3))
except TypeError as e:
    print(e)                           # 'generator' object is not reversible
```

**为什么生成器/迭代器不能 `reversed`?** 它们只支持"向前 `next()`"的流式访问,无法回头取前一个元素,也就无法倒序。要倒序,得先物化成序列(`list(gen)`)再 `reversed`。

**自定义对象实现 `__reversed__`**:你的类若想支持 `reversed`,实现 `__reversed__` 方法返回一个倒序迭代器即可:

```python
class Countdown:
    def __init__(self, start): self.start = start
    def __reversed__(self):
        i = self.start
        while i > 0:
            yield i
            i -= 1

print(list(reversed(Countdown(5))))     # [5, 4, 3, 2, 1]
```

`__reversed__` 应返回一个迭代器(通常用生成器实现)。未实现时,若对象是序列(有 `__len__`+`__getitem__`),`reversed` 仍能通过随机访问从尾向前工作;两者都没有则抛 `TypeError`。

### 2.4 `reversed` vs 切片 `[::-1]`:惰性 vs 立即复制

`seq[::-1]` 切片也能反转,它返回一个**新对象**(立即复制全部),而 `reversed` 返回**惰性迭代器**(不复制)。两者内存与时机不同:

```python
# [::-1]:立即复制,产生新对象(类型与原序列相同)
nums = [1, 2, 3]
rev_copy = nums[::-1]
print(rev_copy)             # [3, 2, 1] —— 新 list
print(nums)                 # [1, 2, 3] —— 原未变
print(rev_copy is nums)     # False

# reversed:惰性迭代器,不复制
rev_iter = reversed(nums)
print(list(rev_iter))       # [3, 2, 1]

# 对元组:[::-1] 返回新元组,reversed 返回迭代器
t = (1, 2, 3)
print(t[::-1])              # (3, 2, 1) —— 新 tuple
print(list(reversed(t)))    # [3, 2, 1] —— list(需物化)

# 对字符串:[::-1] 返回新字符串,这是字符串反转的惯用法
s = "hello"
print(s[::-1])              # 'olleh' —— 直接得到字符串
print("".join(reversed(s))) # 'olleh' —— 也能,但要 join 拼回
```

**字符串反转用 `[::-1]` 更顺手**:因为 `reversed("hello")` 返回字符迭代器,要拼回字符串还得 `"".join(...)`,而 `s[::-1]` 一步到位返回字符串。所以字符串反转的惯用法是 `[::-1]`。

**何时选哪个**:

| 需求 | 推荐 | 理由 |
|------|------|------|
| 倒序 for 循环遍历 | `reversed` | 惰性,不复制 |
| 想要反转后的列表副本 | `seq[::-1]` 或 `list(reversed(seq))` | 立即得到 list |
| 反转字符串 | `s[::-1]` | 直接返回字符串 |
| 大数据、只需逐个处理 | `reversed` | 省 O(n)复制内存 |
| 需要反转对象且类型保持(元组→元组) | `seq[::-1]` | 切片保持类型 |

`[::-1]` 的代价是立即复制 O(n) 内存;`reversed` 的代价是惰性、一次性、要物化才能反复用或按下标访问。按"要不要立即拿到完整副本"决定。

### 2.5 用 reverse / reversed 倒序遍历的几种写法

倒序遍历列表是高频场景,有几种写法,清晰度与代价有别:

```python
data = [10, 20, 30, 40]

# ① reversed:最清晰,惰性
for x in reversed(data):
    print(x)                # 40 30 20 10

# ② [::-1]:也清晰,但复制整份(大列表浪费)
for x in data[::-1]:
    print(x)

# ③ 索引 range:笨重,易错,一般不用
for i in range(len(data) - 1, -1, -1):
    print(data[i])

# ④ while + pop:会消耗原列表,慎用
while data:
    print(data.pop())      # 40 30 20 10,但 data 变空了
```

**推荐 ①**(`reversed`):惰性、不复制、不消耗原列表、语义直白。② 适合"顺便想拿反转副本"的情形;④ 的 `pop()` 会清空原列表,只在确实要"边弹边用"时用(如栈)。

**反向遍历需要索引时**:

```python
# 需要"倒序索引 + 值":enumerate 先转 list 再 reversed
for i, x in reversed(list(enumerate(data))):
    print(i, x)            # 3 40 / 2 30 / 1 20 / 0 10
```

`enumerate` 返回的是迭代器(正向),要先 `list()` 物化成"索引-值"对的列表,再 `reversed`。这是"带索引倒序遍历"的惯用法。详见《流程控制》`enumerate` 章节。

### 2.6 reverse / reversed 不排序:与 sort 的边界再强调

`reverse` 和 `reversed` 与"排序"无关,只颠倒现有顺序。把这点讲透,因为混用是高频 bug 源:

```python
scores = [88, 72, 95, 60, 81]

# ❌ 以为是"从高到低排列"(排序),其实只是颠倒
scores.reverse()
print(scores)             # [81, 60, 95, 72, 88] —— 只是首尾倒置,不是降序!

# ✅ 要"从高到低"应排序
scores.sort(reverse=True)
print(scores)             # [95, 88, 81, 72, 60] —— 真正的降序
```

口诀:**"倒着读"用 reverse/reversed,"从大到小"用 sort(reverse=True)**。当数据本身已升序时,`reverse()` 恰好得到降序,这时二者结果相同,容易让人误以为 `reverse` 等价于降序排序——但只要数据一乱序,区别立刻显现。

**性能差异也是反证**:`reverse` 是 O(n)(单纯颠倒),`sort` 是 O(n log n)(比较排序)。若 `reverse` 真是排序,不可能比排序快——它快正是因为不排序。

### 2.7 性能与内存:原地交换 vs 惰性产出 vs 切片复制

三种反转写法的内存与时间特征对照,对大列表选型有实际意义:

| 写法 | 时间 | 额外内存 | 是否改原对象 | 何时产出结果 |
|------|------|---------|------------|------------|
| `lst.reverse()` | O(n) | O(1) | 是 | 立即(原地反转完) |
| `reversed(lst)` | O(1) 构造 / O(n) 遍历 | O(1) | 否 | 惰性(逐个产出) |
| `lst[::-1]` | O(n) | O(n)(复制) | 否 | 立即(整份复制) |

```python
import timeit

setup = 'lst=list(range(1_000_000))'

# reverse:原地,O(n)
print(timeit.timeit('lst.reverse()', setup=setup, number=10))      # 快

# reversed 构造:O(1),真正消耗在遍历
print(timeit.timeit('reversed(lst)', setup=setup, number=10))      # 极快(未遍历)
print(timeit.timeit('list(reversed(lst))', setup=setup, number=10))# 含物化,O(n)

# 切片:O(n) 复制
print(timeit.timeit('lst[::-1]', setup=setup, number=10))          # 与物化相当
```

**`reversed` 的真正开销在遍历而非构造**:`reversed(lst)` 构造迭代器是 O(1)(只记下引用和位置),后续 `next()` 才逐个访问。所以"只构造不遍历"几乎不花时间,"物化成列表"才 O(n)。这是惰性的精髓:不用的元素不算钱。

**大列表倒序遍历,`reversed` 最省**:既能倒序、又不复制 O(n) 内存,只 O(1) 额外。`[::-1]` 虽然也倒序,但立即复制整份,大列表上内存翻倍。`reverse` 省内存但改原对象,若原顺序还要用就不能选它。详见 4.2 节底层解释。

### 2.8 实战场景:reverse / reversed 的典型用法

把前面几节串起来,看几个贴近真实业务的反转场景,理解何时用哪个。

**场景一:日志/时间序列"最新优先"展示**。数据按时间正序采集(旧→新),展示时往往要"新→旧"。若不需要保留正序,直接 `reverse`;若展示与原始数据并存,用 `reversed`:

```python
events = ["09:00 start", "10:00 build", "11:00 deploy", "12:00 done"]

# 展示最新在前:reverse 原地,省内存,且之后不再用正序
events.reverse()
for e in events:
    print(e)
# 12:00 done / 11:00 deploy / 10:00 build / 09:00 start

# 若正序数据还要用(如稍后写文件),用 reversed 不改原
feed = ["v1", "v2", "v3"]
timeline = list(reversed(feed))   # ['v3','v2','v1'] 供 UI
archive = feed                    # ['v1','v2','v3'] 仍正序归档
```

**场景二:实现撤销/回退——按操作记录倒序回放**。把操作记录正序 push,回退时倒序遍历 `reversed`,惰性且不破坏记录:

```python
history = ["create", "edit", "edit", "resize"]

# 回退:从最近一步往回看,逐一判断是否要撤销
for op in reversed(history):
    print("回退:", op)
    if op == "create":
        break                     # 撤到最早就停
# 回退: resize / 回退: edit / 回退: edit / 回退: create
```

`reversed(history)` 不复制、不改原记录,适合"浏览历史而不消费历史"的回退场景。若用 `while history: history.pop()` 则会真的清空记录,只适合"边撤边丢"。

**场景三:回文判断**。判断字符串是否回文,反转后比较是最直白的写法:

```python
def is_palindrome(s):
    return s == s[::-1]            # [::-1] 直接返回字符串,比较一步到位

print(is_palindrome("radar"))     # True
print(is_palindrome("hello"))     # False

# 进阶:忽略大小写与非字母
import re
def is_palindrome_phrase(s):
    cleaned = re.sub(r"[^a-zA-Z0-9]", "", s).lower()
    return cleaned == cleaned[::-1]

print(is_palindrome_phrase("A man, a plan, a canal: Panama"))   # True
```

字符串反转首选 `[::-1]`:直接返回字符串、与原串比较自然。这里用 `reversed` 反而要 `"".join(reversed(s))`,啰嗦。

**场景四:range 倒序生成**。要生成 `n, n-1, ..., 1` 这样的倒序整数序列,用 `reversed(range(...))` 或直接 `range(n, 0, -1)`:

```python
# 倒序 5..1
print(list(reversed(range(1, 6))))   # [5, 4, 3, 2, 1]
print(list(range(5, 0, -1)))         # [5, 4, 3, 2, 1] —— 直接用 range 步长 -1 更直接

# 倒计时
for i in range(10, 0, -1):
    print(i)
print("发射!")
```

生成倒序整数,`range(start, stop, -1)` 比 `reversed(range(...))` 更直接(一步到位、无需物化)。`reversed(range(...))` 适合"已有 range 想倒着读"的场景,且对 range 走 `__reversed__` 高效逆推、不物化。

**场景五:与 enumerate 配合做"剩余进度"倒计时**。处理任务时想显示"还剩 N 项",用 `reversed(list(enumerate(...)))` 同时拿到倒序索引:

```python
tasks = ["A", "B", "C", "D"]

# 倒序逐项 + 显示剩余编号
for i, t in reversed(list(enumerate(tasks, start=1))):
    print(f"[{i}/{len(tasks)}] 处理 {t}")
# [4/4] 处理 D / [3/4] 处理 C / [2/4] 处理 B / [1/4] 处理 A
```

`enumerate(tasks, start=1)` 给每个任务编号 1..N,`list()` 物化成"编号-任务"对,`reversed` 倒序遍历,得到从最后一个到第一个的处理流。这是"带编号倒序遍历"的惯用法,在进度条、日志回放、撤销栈等场景常用。

这些场景的共同点:**"倒着读"的需求用 `reversed`(惰性、不改),"颠倒入库"用 `reverse`(原地、省内存),"反转字符串/拿副本"用 `[::-1]`(直接、同类型)**。把需求映射到这三类,选型就不再犹豫。

## 3. 最佳实践

### 3.1 倒序遍历用 reversed,不要用 range 索引或 [::-1]

```python
# ✅ 最清晰、惰性、不复制
for item in reversed(data):
    process(item)

# ❌ 索引 range:笨重,易 off-by-one
for i in range(len(data)-1, -1, -1):
    process(data[i])

# ⚠️ [::-1]:也清晰,但复制整份,大列表浪费内存
for item in data[::-1]:
    process(item)
```

`reversed` 是倒序遍历的标准工具:语义直白、惰性省内存、不改原对象。`[::-1]` 适合"恰好要反转副本"的场景;索引 range 写法已过时。

### 3.2 不需要原顺序且省内存,用 reverse;需保留原对象用 reversed/切片

```python
# ✅ 不需要原顺序:reverse 原地,省一份复制
data.reverse()

# ✅ 需要保留原对象:reversed 不改原
for x in reversed(data): ...

# ✅ 或拿反转副本:[::-1] / list(reversed(...))
rev = data[::-1]
```

权衡"还要不要原顺序"。原顺序废了 → `reverse`(省内存);原顺序要留 → `reversed`/`[::-1]`。

### 3.3 不要把 reverse 的 None 返回值赋回变量

```python
# ❌ reverse 返回 None
data = data.reverse()      # data 变 None

# ✅ 原地调用,不接收
data.reverse()
```

`reverse` 与 `sort`/`append` 一样返回 None。需要反转副本用 `data[::-1]` 或 `list(reversed(data))`。

### 3.4 字符串反转用 [::-1],不要 join(reversed(...))

```python
# ✅ 惯用法:直接返回字符串
rev = s[::-1]

# ⚠️ 也能用,但啰嗦
rev = "".join(reversed(s))
```

`reversed("abc")` 返回字符迭代器,要拼回字符串得 `"".join`;`s[::-1]` 一步到位。字符串反转的首选是切片。

### 3.5 reversed 返回的迭代器只能遍历一次,需多次用先物化

```python
rev = reversed([1, 2, 3])
list(rev)                  # [3, 2, 1]
list(rev)                  # [] —— 已耗尽

# 需多次用:先物化
rev_list = list(reversed(data))
# 之后 rev_list 可反复访问、按下标、多次遍历
```

迭代器"用完即空"。若要按下标访问、反复遍历、或传给多处使用,先 `list(reversed(...))` 固化成列表。

### 3.6 倒序遍历同时要索引,先 list(enumerate(...)) 再 reversed

```python
for i, x in reversed(list(enumerate(data))):
    print(i, x)
```

`enumerate` 返回正向迭代器,无法直接 `reversed`;先 `list()` 物化成"索引-值"对列表,再 `reversed` 倒序。这是带索引倒序遍历的惯用法。

### 3.7 反转不可变序列(元组/字符串/range)用 reversed 或 [::-1],没有 .reverse 方法

```python
t = (1, 2, 3)
# t.reverse()  ❌ tuple 没有 reverse

# ✅ reversed 物化,或切片保持类型
rev_t = tuple(reversed(t))   # (3, 2, 1)
rev_t = t[::-1]              # (3, 2, 1)
```

不可变序列无法原地改,故无 `reverse` 方法。记住反转它们的两个出口:`reversed`(转迭代器,要物化)或 `[::-1]`(直接得同类型新对象)。

### 3.8 set / 生成器不能 reversed,先物化成序列再反转

```python
s = {3, 1, 2}
# reversed(s)  ❌ set 无序不可反转
rev = list(reversed(list(s)))   # 先转 list 再反转(顺序基于转 list 后)

gen = (x for x in range(3))
# reversed(gen)  ❌ 生成器不可反转
rev = list(reversed(list(gen))) # 先物化再反转
```

无序的 `set` 和只能向前的迭代器都不支持 `reversed`。需要"它们的倒序",先 `list()` 转成有序序列,再 `reversed`。

### 3.9 别用 reverse 冒充降序排序,要排序用 sort(reverse=True)

```python
scores = [88, 72, 95]
# ❌ 以为是从高到低,实际只是颠倒
scores.reverse()             # [95, 72, 88]?不——是 [95,72,88] 巧合?再看乱序
scores2 = [3,1,2]; scores2.reverse()   # [2,1,3] 不是降序!

# ✅ 真正降序
scores.sort(reverse=True)    # [95, 88, 72]
```

`reverse` 只颠倒顺序。"从大到小"是排序,用 `sort(reverse=True)` 或 `sorted(..., reverse=True)`。详见上一篇。

### 3.10 自定义类支持 reversed 时实现 __reversed__

```python
class Stack:
    def __init__(self): self._items = []
    def push(self, x): self._items.append(x)
    def __reversed__(self):
        return reversed(self._items)   # 返回迭代器

st = Stack(); st.push(1); st.push(2)
print(list(reversed(st)))   # [2, 1] —— 自顶向下浏览栈
```

让你的类支持 `reversed`,实现 `__reversed__` 返回迭代器即可。若类内部本就是序列(有 `__len__`+`__getitem__`),即使不实现 `__reversed__`,`reversed` 也能通过随机访问工作。详见《面向对象OOP全套》协议方法章节。

## 4. 原理

### 4.1 reverse 的原地交换实现:O(n) 时间 O(1) 额外空间

`list.reverse()` 在 CPython 中通过**首尾元素两两交换**完成,无需额外内存分配:

```c
// 简化示意:list_reverse 的核心
void list_reverse(PyListObject *self) {
    PyObject **item = self->ob_item;
    Py_ssize_t n = self->ob_size;
    Py_ssize_t i, j;
    for (i = 0, j = n - 1; i < j; i++, j--) {
        PyObject *tmp = item[i];   // 交换 item[i] 与 item[j]
        item[i] = item[j];
        item[j] = tmp;
    }
    // 无返回值(返回 None)
}
```

关键点:

- **原地操作**:只动 `ob_item` 数组内的指针,交换它们的指向,不新建数组,故 O(1) 额外空间。
- **n/2 次交换**:循环到中间即停,共交换 ⌊n/2⌋ 次,每次 O(1),总计 O(n)。
- **不复制元素对象**:交换的是 `ob_item` 里的引用(指针),不是元素对象本身,所以无论元素多大,交换代价恒定。

这解释了 `reverse` 为何是 O(n) 时间 + O(1) 额外内存——它只搬动指针数组里的指针位置,不分配新数组、不复制元素对象。对比 `[::-1]` 要分配新数组并复制 n 个指针(O(n) 额外空间),`reverse` 在内存上明显更省。

### 4.2 reversed 的惰性迭代器:不复制、按需产出

`reversed(seq)` 返回一个迭代器对象(对 list 是 `list_reverseiterator`),它**不复制**原序列,只记下对原序列的引用和一个"当前倒序位置"指针,每次 `next()` 时按位置取元素:

```c
// 简化示意:list_reverseiterator 的核心
typedef struct {
    PyObject_HEAD
    PyListObject *source;     // 对原列表的引用(弱引用语义,不复制数据)
    Py_ssize_t index;         // 当前倒序位置,从 ob_size-1 开始
} ListReverseIterator;

PyObject *reverseiterator_next(it) {
    if (it->index < 0) return StopIteration;   // 倒到头
    return source->ob_item[it->index--];       // 返回当前位置元素,位置前移
}
```

关键点:

- **构造 O(1)**:`reversed(lst)` 只创建迭代器对象、记下引用和起始位置 `ob_size-1`,不复制任何数据。所以"只构造不遍历"几乎不花时间/内存。
- **逐个产出 O(n)**:真正访问发生在 `next()` 时,每次 O(1) 按位置取元素,遍历到底共 O(n)。这是惰性——不用的元素不算钱。
- **不持有数据副本**:迭代器只引用原序列,不复制。若遍历期间原列表被修改,迭代器看到的是变化后的状态(偏向"实时"),这也是为何迭代遍历时修改列表行为微妙。

**对 list 的优化**:普通序列倒序靠 `__len__`+`__getitem__` 从尾向前随机访问(每次 `next` 算 `index = len-1-k`),略微间接;但 list 实现了专门的 `list_reverseiterator`,直接维护倒序位置指针,避免每次重算索引,更高效。

**为何迭代器一次性**:`next()` 通过 `index--` 前移,一旦 `index < 0` 抛 `StopIteration`,迭代器进入耗尽状态。迭代器没有"重置到起点"的机制(标准迭代器协议不提供 `reset`),故用完即空。要重来必须新建迭代器或物化成列表。

### 4.3 reversed 对不同对象的实现路径

`reversed(obj)` 在 CPython 中按对象能力分两条路径:

```c
// 简化示意
PyObject *builtin_reversed(obj) {
    // 路径一:对象实现了 __reversed__ → 直接调用它,返回其迭代器
    if (hasattr(obj, "__reversed__")) {
        return obj.__reversed__();      // list/range/dict(3.8+) 走这条
    }
    // 路径二:对象是序列(有 __len__ + __getitem__)→ 从尾向前随机访问
    if (hasattr(obj, "__len__") && hasattr(obj, "__getitem__")) {
        return generic_seq_reverseiterator(obj);  // tuple/str 等走这条
    }
    // 都不满足 → 报错
    raise TypeError("object is not reversible");
}
```

两条路径对应不同对象:

- **`list`、`range`、`dict`(3.8+)**:实现 `__reversed__`,走路径一,各自提供最高效的倒序迭代器(list 维护位置指针、range 直接逆推步长 `start + (n-1)*step` 往前、dict 沿内部数组从尾向前)。
- **`tuple`、`str` 等"普通序列"**:`__reversed__`,但提供 `__len__`+`__getitem__`,走路径二,通过 `len` 拿长度、从 `len-1` 向前 `getitem` 逐个取。
- **`set`、生成器、`map`/`filter` 对象**:既无 `__reversed__`、又非序列(无 `__len__`/`__getitem__`),两条路径都不通,抛 `TypeError: object is not reversible`。

这条分路径解释了 2.3 节的速查表:`reversed` 要求"要么对象知道怎么倒序(`__reversed__`)、要么对象能随机访问(序列)",二者皆无则不可反转。生成器之所以不行,正是因为它只能向前流式产出、无法回头,既不能 `__reversed__` 也不是序列。

### 4.4 切片 [::-1] 的实现:立即复制新数组

`seq[::-1]` 走的是切片协议,与 `reversed` 的惰性截然不同——它**立即**构造一个新对象,把原序列的元素按倒序复制进去:

```c
// 简化示意:切片 seq[::-1] 对 list 的核心
PyListObject *list_slice_reversed(src) {
    Py_ssize_t n = src->ob_size;
    PyListObject *result = 新列表(len=n);   // 分配新数组,O(n) 空间
    for (Py_ssize_t i = 0; i < n; i++) {
        result->ob_item[i] = src->ob_item[n - 1 - i];   // 倒序复制指针
    }
    return result;                          // 返回新列表
}
```

关键点:

- **立即复制**:`[::-1]` 在执行时就完成全部复制,返回的已是完整的反转新对象。不像 `reversed` 惰性、要遍历才产出。
- **O(n) 额外空间**:分配了与原序列等大的新数组,复制 n 个指针,内存翻倍。
- **保持类型**:切片返回的对象类型与原序列同(list 切片→list、tuple 切片→tuple、str 切片→str)。这是 `[::-1]` 反转字符串/元组时"直接得到同类型"的原因,也是它比 `reversed`(总返回迭代器,要物化)在某些场景更顺手的原因。

对比三者底层:

- `reverse`:原地交换指针,O(1) 额外,改原对象,O(n) 时间。
- `reversed`:构造迭代器 O(1)、遍历 O(n),O(1) 额外,不改原对象,惰性。
- `[::-1]`:复制新数组 O(n) 额外,不改原对象,立即,O(n) 时间。

三者都能"反转",但内存与时机各异,选型正是基于这些底层差异:省内存且不需原序→reverse、省内存需保留原序且逐个用→reversed、需要立即的完整副本→[::-1]。

### 4.5 为什么 reverse 不排序:操作语义的本质

`reverse`/`reversed` 与 `sort`/`sorted` 都"重排元素",但语义本质不同,源于它们操作的是什么:

- **排序**(`sort`/`sorted`):根据**元素之间的大小关系**重排,需要比较任意两元素,复杂度下界 O(n log n)(比较排序)。结果与原顺序无关,只取决于元素值。
- **反转**(`reverse`/`reversed`):根据**元素的原位置**首尾对称交换,不比较任何元素值,只搬动指针,复杂度 O(n)。结果只取决于原顺序,与元素值无关。

```c
// reverse:只看位置 i 与 n-1-i,交换,不比较值
for (i=0, j=n-1; i<j; i++, j--) swap(item[i], item[j]);

// sort:比较任意两元素值,决定相对顺序
timsort(item, n, compare);
```

正因 `reverse` 不比较值,它:

- 是 O(n) 而非 O(n log n)——没有比较的成本。
- 是稳定的"反转"(对相等概念不敏感,因为根本不看值)。
- 不受元素类型能否比较影响——异类列表也能 `reverse`(只要它是 list),而 `sort` 异类会 `TypeError`。

```python
mixed = [3, "a", 1, "b"]
mixed.reverse()            # OK,反转不比较,['b', 1, 'a', 3]
# mixed.sort()             ❌ TypeError,异类不能比较排序
```

这条"反转不比较"的性质,也解释了为何 `reverse` 能对异类列表工作、为何它快、为何它和"降序排序"只在已升序数据上偶然一致。记住"反转=位置对称交换、排序=按值重排",二者就再不会混。

### 4.6 dict 的 __reversed__:插入序的反向

Python 3.8 起,`dict` 实现 `__reversed__`,按**插入序的反向**迭代键。这得益于 3.7 起 dict 保证插入序(详见《字典深度剖析》):

```python
d = {"a": 1, "b": 2, "c": 3}
# 插入序:a, b, c
# reversed 插入序:c, b, a
print(list(reversed(d)))            # ['c', 'b', 'a']
print(list(reversed(d.keys())))     # ['c', 'b', 'a']
print(list(reversed(d.values())))   # [3, 2, 1]
print(list(reversed(d.items())))    # [('c',3),('b',2),('a',1)]
```

`dict.__reversed__` 沿 dict 内部的稀疏数组装入顺序从尾向前扫描,产出键。`d.keys()`/`values()`/`items()` 这些视图对象也支持 `reversed`(3.8+),分别倒序产出键、值、键值对。

这与 `set` 的对比鲜明:`set` 无序(无插入序保证),没有"顺序"可反转,故不支持 `reversed`;`dict` 有插入序,故能反转。**"能否反转"本质上取决于"是否有可定义的顺序"**,dict 的插入序提供了这个顺序,set 没有提供。

## 5. 总结

### 5.1 本文内容回顾

- **核心区别**:`list.reverse()` 原地修改、返回 `None`、仅作用于 `list`;`reversed(seq)` 返回惰性倒序迭代器、不改原对象、可作用于任何序列(或实现 `__reversed__` 的对象)。选型一句话:"还要不要原顺序 + 要不要立即拿到副本"。

- **原地约定**:`reverse` 返回 None 是 Python 原地方法约定的一部分,提醒无新对象。`nums = nums.reverse()` 会丢列表,需副本用 `[::-1]` 或 `list(reversed(...))`。

- **惰性迭代器**:`reversed` 返回的迭代器不复制数据、构造 O(1)、遍历 O(n)、只能遍历一次(用完即空)。需多次用或按下标访问先 `list(reversed(...))` 物化。

- **适用对象**:序列(list/tuple/str/range)或实现 `__reversed__` 的对象(dict 3.8+、自定义类)可行;set、生成器、迭代器等无序/只能向前的对象不行,抛 `TypeError`。两条实现路径:`__reversed__` 或 `__len__`+`__getitem__`。

- **与切片 [::-1] 对照**:`[::-1]` 立即复制新对象(O(n) 额外、保持类型),`reversed` 惰性迭代器(O(1) 额外、要物化)。字符串反转惯用 `[::-1]`,大列表倒序遍历惯用 `reversed`。

- **不排序**:`reverse`/`reversed` 只颠倒现有顺序,不比较元素值,故 O(n) 而非 O(n log n)、对异类列表也能工作。与 `sort(reverse=True)` 降序排序不同,后者按值排序;二者只在已升序数据上偶然一致。

- **倒序遍历**:`for x in reversed(data)` 是最清晰省内存的写法,优于 `range(len-1,-1,-1)` 索引法和 `[::-1]` 复制法;需带索引时 `reversed(list(enumerate(data)))`。

- **性能/内存**:reverse O(n) 时间 O(1) 额外改原对象;reversed 构造 O(1)/遍历 O(n)、O(1) 额外不改原、惰性;`[::-1]` O(n) 时间 O(n) 额外不改原、立即。

- **原理**:reverse 首尾交换指针 O(1) 额外;reversed 迭代器只记引用+倒序位置按需取、不复制;reversed 对不同对象走 `__reversed__` 或 `__len__`+`__getitem__` 两路径;`[::-1]` 立即复制新数组;reverse 不比较值故快且能处理异类;dict 3.8+ 按插入序反向支持 reversed。

### 5.2 读完本文你应能掌握

- 一句话讲清 `reverse` 与 `reversed` 的区别(原地/迭代器、返回值、适用对象),并据此在"省内存改原序""保留原序惰性""立即副本"间正确选型。

- 避免把 `reverse` 的 `None` 返回值赋回变量导致列表丢失,知道需反转副本用 `[::-1]` 或 `list(reversed(...))`。

- 说明 `reversed` 返回的迭代器是惰性、一次性、不复制数据的,需多次用或按下标访问时先物化。

- 判断哪些对象能 `reversed`(序列/`__reversed__`)、哪些不能(set/生成器),并解释为什么生成器不可反转(只能向前,无法回头)。

- 对比 `reversed` 与 `[::-1]` 在内存(O(1) vs O(n))、时机(惰性 vs 立即)、返回类型(迭代器 vs 同类型新对象)上的差异,并据此选字符串反转用 `[::-1]`、大列表倒序遍历用 `reversed`。

- 解释 `reverse`/`reversed` 为何不排序(只交换位置、不比较值),并据此区分"颠倒顺序"与"降序排序",避免用 `reverse` 冒充 `sort(reverse=True)`。

- 写出倒序遍历的几种写法并择优(`reversed` 优于索引 range 与 `[::-1]`),以及带索引倒序遍历的惯用法 `reversed(list(enumerate(...)))`。

- 阐述 reverse 原地交换 O(1) 额外、reversed 迭代器惰性 O(1) 额外、`[::-1]` 复制 O(n) 额外的底层实现差异,以及 reversed 走 `__reversed__` 或 `__len__`+`__getitem__` 两条路径的机制。
