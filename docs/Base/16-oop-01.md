## 1. 介绍

### 1.1 什么是类与实例

在 Python 中，类（class）是一种自定义数据类型，它把数据（属性）和行为（方法）组织在一起，用来描述某一类事物的共同特征与能力。实例（instance）则是根据类"模板"创建出来的具体对象，每个实例都拥有类定义的属性与方法，同时可以保存自己独立的数据。

可以把类理解成"图纸"，实例理解成按图纸造出来的"产品"。一张图纸可以造出很多件产品，它们结构相同、功能一致，但各自的颜色、编号、内部状态可以不同。这种"图纸—产品"的关系，正是面向对象编程（OOP）的基础。

Python 里一切皆对象，而对象又分两类——类对象（class object）与实例对象（instance object）。我们用 `class` 关键字定义一个类，实际上是在创建一个"类对象"；随后用 `ClassName()` 的形式调用这个类对象，就在创建"实例对象"。理解这两层对象的区别与联系，是掌握 Python 面向对象的起点。

### 1.2 基本语法与最小用法

定义一个类，最基本的形式如下：

```python
class Dog:
    name = "未命名"       # 类属性：写在类体里、方法外的变量

    def bark(self):        # 实例方法
        return f"{self.name}: 汪汪！"
```

上面定义了一个 `Dog` 类，它有一个类属性 `name` 和一个实例方法 `bark`。定义本身不会造出任何具体的狗，它只是"图纸"。

要按这张图纸造出具体的狗，需要"实例化"——即调用类对象：

```python
d = Dog()        # 实例化：调用 Dog，得到一个实例对象
print(d.name)    # 实例可访问类属性
print(d.bark())  # 实例可调用实例方法
# 输出：
# 未命名
# 未命名: 汪汪！
```

这里有几个关键点：

- `Dog` 是类对象，`d` 是实例对象，它们的身份不同，可在内存中分别存在。
- 实例通过"点号"（`.`）访问类的属性和方法，这是 Python 属性查找机制的基本形式。
- 方法定义的第一个参数 `self` 代表"当前实例"，调用 `d.bark()` 时 Python 自动把 `d` 传给 `self`，因此调用时不需要手动传 `self`。

本篇要讲清楚的核心问题正是围绕这个最小示例展开：`class` 关键字到底做了什么、`Dog()` 这个"调用"内部经历了哪些步骤、`__init__` 在其中扮演什么角色、类与实例各自的 `__dict__` 存了什么、类体在什么时候被执行，以及类对象本身为什么也是"一等对象"。

## 2. 核心内容

### 2.1 class 关键字与类体的执行时机

`class` 关键字用来定义一个新类。它的基本语法：

```python
class ClassName(BaseClasses):
    """可选的文档字符串"""
    # 类体：可以包含属性定义、方法定义、嵌套类等
    pass
```

其中：

- `ClassName` 是新类的名字，定义完成后这个名字绑定到一个"类对象"。
- `BaseClasses` 是基类（父类）列表，可省略；省略时等价于隐式继承 `object`（在 Python 3 中所有类最终都继承自 `object`）。
- 类体是一个缩进的代码块，里面可以写变量赋值（类属性）、函数定义（方法）、装饰器、甚至是 `if`、`for` 等普通语句。

**类体执行的时机**：一个容易忽略但非常重要的点是——类体是在 `class` 语句被执行时，就"从头到尾执行一遍"的，并且只在定义时执行一次。也就是说，类体里的赋值语句会在定义类的瞬间把名字绑定到类对象上，成为类属性；方法定义（`def`）也会在这一刻执行，把函数对象绑定到类的命名空间里。

这意味着：当你 `import` 一个含类定义的模块时，类体就已经执行过了；后续每次 `实例化()` 并不会重新执行类体。可以把类体理解成一段"在定义时执行一次、并把结果绑定到类对象"的脚本。

```python
print("① 准备定义类")

class Demo:
    print("② 类体正在被执行！")   # 这条会在定义时立刻执行
    value = 10
    print("③ 类体执行结束")

print("④ 类定义完成")
# 输出：
# ① 准备定义类
# ② 类体正在被执行！
# ③ 类体执行结束
# ④ 类定义完成
```

注意 `②` 和 `③` 在 `Demo` 类定义完成的瞬间就输出了，而不是在 `Demo()` 实例化时。再次强调：实例化不会重新执行类体，类体只在 `class` 语句被执行时跑一次。

**类体中定义的名字去哪了**：类体执行时，Python 会在一个临时的命名空间（可以理解成一个临时字典）里收集所有赋值与定义得到的名字，等类体执行完毕，这个命名空间就被"封"进类对象，成为类的属性。这也是为什么类体里写的 `name = "未命名"` 之后能用 `Dog.name` 访问到——它被存进了类对象的命名空间。

### 2.2 类对象与实例对象

理解 Python 的对象模型，必须分清"类对象"与"实例对象"这两个层次。

**类对象**：用 `class` 定义出来的东西本身就是对象，叫"类对象"。它代表"这一类"的抽象定义，存放所有实例共享的属性和方法。类对象可以像普通对象一样被赋值、传递、作为参数、放进列表——它是一等对象（first-class object）。

**实例对象**：通过"调用类对象"（`ClassName()`）产生的具体对象。每个实例都有自己独立的数据存储，但它们的"结构定义"来自同一个类对象。

```python
class Dog:
    species = "犬科"  # 类属性：所有 Dog 共享

    def bark(self):
        return f"{self.name} 汪汪叫"

# Dog 本身是类对象
print(type(Dog))   # <class 'type'>
print(Dog.species) # 直接通过类对象访问类属性

# 用同一个类造出两只具体的狗
dog_a = Dog()
dog_a.name = "旺财"   # 给实例单独设置属性（写到实例自己的存储里）
dog_b = Dog()
dog_b.name = "富贵"

print(dog_a.bark())   # 旺财 汪汪叫
print(dog_b.bark())   # 富贵 汪汪叫
print(dog_a.species, dog_b.species)  # 都能访问同一个类属性
# 输出：
# <class 'type'>
# 犬科
# 旺财 汪汪叫
# 富贵 汪汪叫
# 犬科 犬科
```

上面例子揭示了几个事实：

- `Dog` 的类型是 `type`，说明"类对象"本身也是某个类型的实例——元类（metaclass）的实例。默认元类就是 `type`，这个细节在第 4 章会展开。
- `dog_a` 与 `dog_b` 是两个独立的实例对象，它们各自保存了 `name`，互不干扰。
- `species` 是类属性，所有实例都能"读到"它，但它们并没有各自"存一份"`species`，而是通过属性查找机制找到类对象里的那份。

**类对象是一等对象**：这一点很重要。类对象和整数、字符串一样，可以被引用、传递、返回：

```python
def get_dog_class():
    return Dog       # 函数返回一个类对象

cls = get_dog_class()
new_dog = cls()      # 用拿到的类对象来实例化
print(new_dog.species)
# 输出：
# 犬科
```

这里 `cls` 拿到了 `Dog` 类对象，之后 `cls()` 就等价于 `Dog()`。这种把类当参数传来传去的能力，在工厂模式、动态注册等场景中非常常见。

### 2.3 __init__ 初始化器

`__init__` 是实例的"初始化器"（initializer）。它的作用是：在实例被创建出来之后，为这个实例设置初始状态——通常就是给实例绑定一批属性。注意它叫"初始化"而不是"构造"，因为真正"构造"空实例对象的工作由 `__new__` 完成，`__init__` 只负责"填内容"。

`__init__` 的签名：

```python
def __init__(self, 形参1, 形参2, ...):
    self.属性1 = 形参1
    self.属性2 = 形参2
    ...
```

关键点：

- 第一个参数 `self` 是刚刚被 `__new__` 创建好的实例对象，Python 自动传入。
- `__init__` 不应写 `return` 返回任何值（默认返回 `None`）。如果在 `__init__` 里返回非 `None` 值会直接报 `TypeError`。
- 调用 `Dog("旺财", 3)` 时，`"旺财"` 和 `3` 这些参数会被传给 `__init__`（精确说，是经过 `__new__` 之后再传给 `__init__`，详情见第 4 章）。

带 `__init__` 的 `Dog` 类：

```python
class Dog:
    species = "犬科"

    def __init__(self, name, age):
        # 为每个新实例绑定自己的属性
        self.name = name
        self.age = age
        self.tricks = []   # 初始化每个实例独立的可变容器

    def bark(self):
        return f"{self.name}（{self.age}岁）: 汪汪！"

    def learn_trick(self, trick):
        self.tricks.append(trick)


dog_a = Dog("旺财", 3)
dog_b = Dog("富贵", 5)

print(dog_a.bark())
print(dog_b.bark())
dog_a.learn_trick("握手")
dog_b.learn_trick("翻滚")
print(dog_a.name, dog_a.tricks)
print(dog_b.name, dog_b.tricks)
# 输出：
# 旺财（3岁）: 汪汪！
# 富贵（5岁）: 汪汪！
# 旺财 ['握手']
# 富贵 ['翻滚']
```

这个 demo 展示了 `__init__` 的典型职责：接收外部参数，把它们存为实例属性，并为每个实例准备独立的内部数据（如 `tricks` 列表）。注意 `tricks` 是在 `__init__` 里挂到 `self` 上的，而不是写成类属性 `tricks = []`——后者会让所有实例共享同一个列表，造成跨实例污染，这是常见坑，第 3 章会专门讲。

**`__init__` 不应返回值**

```python
class Wrong:
    def __init__(self):
        return 1   # 错误！__init__ 只能返回 None

try:
    Wrong()
except TypeError as e:
    print("报错：", e)
# 输出：
# 报错： __init__() should return None, not 'int'
```

Python 会在 `__init__` 返回非 `None` 时主动报错，这是语言层面的约束。

### 2.4 实例化过程 ClassName()

"实例化"就是用 `ClassName(...)` 这种"调用类对象"的形式，产生一个实例对象。对使用者来说，这一步看起来只是简单地"加了个括号"，但内部其实经过了一条固定的调用链。

从使用角度看，实例化时可以传参，也可以不传：

```python
class Animal:
    def __init__(self, kind="未知"):
        self.kind = kind

a1 = Animal()         # 不传参，使用 __init__ 默认值
a2 = Animal("猫")     # 传参，覆盖默认值
print(a1.kind, a2.kind)
# 输出：
# 未知 猫
```

调用 `Animal("猫")` 时发生了什么（简化版）：

1. Python 检测到 `Animal` 是一个类对象，于是把这次"调用"转发给元类 `type` 的 `__call__` 方法处理。
2. `type.__call__` 先调用 `Animal.__new__(Animal, "猫")`，由 `__new__` 负责真正"分配"/"创建"出一个新的空白实例对象。
3. 如果 `__new__` 返回的实例确实是 `Animal` 的实例，`type.__call__` 接着调用 `Animal.__init__(实例, "猫")`，把实例对象交给 `__init__` 做初始化。
4. 最终 `type.__call__` 返回的就是那个已经初始化好的实例对象，把它赋值给 `a2`。

所以 `Animal("猫")` 的返回值并不是 `__init__` 的返回值（`__init__` 返回 `None`），而是 `__new__` 创建、再经 `__init__` 初始化后的那个实例对象。这一点在第 4 章会进一步验证。

**实例化时传参与 `__init__` 必须匹配**

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)     # 传两个参数，对
print(p.x, p.y)

try:
    Point(3)        # 只传一个，__init__ 缺参数
except TypeError as e:
    print("报错：", e)
# 输出：
# 3 4
# 报错： __init__() missing 1 required positional argument: 'y'
```

上面报错信息看似在抱怨 `__init__` 缺参数，实际上体现了"`ClassName(...)` 的参数最终会落到 `__init__`"这个事实。

### 2.5 类与实例各自的 __dict__

每个 Python 对象内部都维护一个"属性字典" `__dict__`，它记录了这个对象自己拥有哪些属性。类对象有类对象的 `__dict__`，实例对象有实例对象的 `__dict__`，二者是分开存储的。分清这两个字典，是理解属性查找、共享与隔离的关键。

对类对象而言，`__dict__` 里存的是这个类定义出来的所有类属性和方法，以及从机制角度附带的一些项（如 `__module__`、`__doc__`、`__dict__` 自身等）。对实例对象而言，`__dict__` 里存的是这个实例"自己单独拥有"的属性，通常是 `__init__` 里通过 `self.xxx = ...` 设置的，或之后动态添加的。

```python
class Dog:
    species = "犬科"
    legs = 4

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        return f"{self.name}: 汪"

d = Dog("旺财", 3)
print("类的 __dict__ 的键：", list(Dog.__dict__.keys()))
print("实例的 __dict__：", d.__dict__)
# 输出：
# 类的 __dict__ 的键： ['__module__', '__firstlineno__', 'species', 'legs', '__init__', 'bark', '__static_attributes__', '__dict__', '__weakref__', '__doc__']
# 实例的 __dict__： {'name': '旺财', 'age': 3}
```

可以看到：

- 类的 `__dict__` 里存放了 `species`、`legs`（类属性）、`__init__`、`bark`（方法）等定义；不同 Python 版本里 `__dict__` 包含的内置项可能略有不同（如上面有 `__firstlineno__` 是 3.13+ 引入的）。
- 实例 `d` 的 `__dict__` 只包含 `name` 与 `age`，因为这两个是 `__init__` 赋给 `self` 的；`species` 和 `legs` 属于类，不在实例的 `__dict__` 里。
- 当你访问 `d.species` 时，Python 先在实例 `__dict__` 找，没找到就沿着类继续找，最终在类的 `__dict__` 里找到。这就是属性查找机制。

**动态添加属性会落到谁的 `__dict__`**

```python
d.color = "黄"        # 给实例 d 动态加属性，存到实例的 __dict__
print(d.__dict__)

Dog.tail = True       # 给类对象动态加属性，存到类的 __dict__
print("tail" in Dog.__dict__)
print(d.tail)         # 实例随后也能"读到"这个类属性
# 输出：
# {'name': '旺财', 'age': 3, 'color': '黄'}
# True
# True
```

这个 demo 直观地展示了：给实例加的属性只在那个实例自己的 `__dict__` 里；给类加的属性进的是类的 `__dict__`，但因为属性查找会"向上查到类"，所有实例随后都能读到这个新属性。

**有些对象没有 `__dict__`**

为了节省内存，使用了 `__slots__` 的类的实例不会有 `__dict__`，只能拥有在 `__slots__` 中声明的属性。这点这里先了解即可，属于进阶用法，超出本篇主线。

### 2.6 __new__ 与 __init__ 的分工

前面已经提到，实例化由两步组成：`__new__` 创建对象，`__init__` 初始化对象。大多数情况下我们只重写 `__init__`，几乎从不重写 `__new__`，因为用默认的 `object.__new__` 就够了。但理解两者的分工，有助于理解实例化的完整过程，也是后续学习单例、不可变类型自定义等进阶话题的基础。

**`__new__` 的职责**：它是一个"静态方法"风格的特殊方法，负责"产生并返回"一个新实例。默认实现（`object.__new__`）会在内存中分配并返回一个空白的实例对象。签名通常写成：

```python
def __new__(cls, *args, **kwargs):
    instance = super().__new__(cls)   # 委托给基类创建实例
    return instance
```

**`__init__` 的职责**：在 `__new__` 返回的实例上做初始化——也就是"填数据"。它不负责创建对象，只负责"装修"。

两者配合的典型情况：

```python
class Ticket:
    def __new__(cls, seat):
        print(f"① __new__ 被调用，准备创建 {cls.__name__} 实例")
        instance = super().__new__(cls)
        return instance

    def __init__(self, seat):
        print(f"② __init__ 被调用，初始化座位 {seat}")
        self.seat = seat

t = Ticket("12A")
print(t.seat)
# 输出：
# ① __new__ 被调用，准备创建 Ticket 实例
# ② __init__ 被调用，初始化座位 12A
# 12A
```

执行顺序固定是"先 `__new__` 后 `__init__`"。如果你只重写了 `__init__` 而不碰 `__new__`，那 `__new__` 用的是从 `object` 继承下来的默认实现，它在幕后默默完成创建对象的工作。

**何时需要自己写 `__new__`**：常见场景有三类——

- 实现单例（Singleton）或限实例数量的类，需要在 `__new__` 里判断是否已有实例，有就直接返回旧实例，跳过新建。
- 子类化不可变类型（如 `int`、`str`、`tuple`），因为不可变对象的值在创建时就必须确定，必须在 `__new__` 里就准备好。
- 从"非本类实例"的东西中创建实例时（例如通过自定义元类/MRO 控制对象生成）。

单例的简化示例：

```python
class Singleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            print("创建了唯一实例")
        return cls._instance

a = Singleton()
b = Singleton()
print(a is b)
# 输出：
# 创建了唯一实例
# True
```

第二次调用时 `__new__` 发现 `_instance` 已存在，直接返回旧实例，于是 `a is b` 成立。注意此时 `__init__` 仍可能被再次调用——这也是为什么单例实现要小心 `__init__` 被重复执行的副作用。

**`__new__` 返回非本类实例时 `__init__` 不会被调用**

```python
class Trick:
    def __new__(cls):
        return "我不想创建实例"   # 返回一个 str，不是 Trick 的实例

t = Trick()
print(type(t))
print(t)
# 输出：
# <class 'str'>
# 我不想创建实例
```

因为 `__new__` 返回的对象并不是 `Trick` 的实例，`type.__call__` 会跳过 `__init__`，直接返回这个字符串。这一点在第 4 章会给出原理性解释。

### 2.7 实例化时的属性初始化

实例属性初始化主要发生在 `__init__` 中。除了最直接的"接收参数并赋值"，还有一些常见的初始化模式和坑需要注意。

**模式一：固定初值**

```python
class Cat:
    def __init__(self, name):
        self.name = name
        self.energy = 100   # 所有猫一出生都是满能量
```

**模式二：基于参数计算**

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height
        self.area = width * height   # 衍生属性
```

**模式三：可变容器必须挂在实例上**

```python
class Dog:
    def __init__(self, name):
        self.name = name
        self.tricks = []   # 列表实例属性，每个实例独立一份
```

如果写成下面的危险写法：

```python
class BadDog:
    tricks = []   # 类属性！所有实例共享同一个列表
    def __init__(self, name):
        self.name = name

a = BadDog("甲")
b = BadDog("乙")
a.tricks.append("握手")
print(b.tricks)   # 本意是看乙的技能，却看到了甲的技能
# 输出：
# ['握手']
```

原因在于 `tricks` 是类属性，`a.tricks` 与 `b.tricks` 查找到的是同一个列表对象，对它的修改会"殃及"所有实例。正确做法是把可变容器放在 `__init__` 里挂到 `self` 上，让每个实例拥有独立副本。

**模式四：延迟赋值也合法**

Python 的实例属性不一定要在 `__init__` 一次性定义完，可在任意时刻动态添加：

```python
class Account:
    def __init__(self, owner):
        self.owner = owner
        # 暂时不设置 balance，后面再加

acc = Account("小明")
acc.balance = 0          # 现在才加 balance 属性
print(acc.__dict__)
# 输出：
# {'owner': '小明', 'balance': 0}
```

这种"随时能加属性"的能力来自实例的 `__dict__` 可写机制，但工程上通常建议在 `__init__` 里声明全部预期属性，避免阅读者难以发现"隐藏属性"。

### 2.8 类作为命名空间

类对象除了用来造实例，本身也是一个"命名空间"：它把一组相关的属性和方法收拢在一起，避免名字污染全局。有时候我们只想把一堆相关的常量或函数组织在一起，并不打算造实例，这时可以把类当作"容器"来用。

```python
class Config:
    """把一组配置项收拢在一起，当作命名空间用。"""
    HOST = "127.0.0.1"
    PORT = 8080
    DEBUG = True

    @staticmethod
    def url():
        return f"http://{Config.HOST}:{Config.PORT}"

print(Config.HOST)
print(Config.url())
# 输出：
# 127.0.0.1
# http://127.0.0.1:8080
```

上面 `Config` 从未被实例化（`Config()`），它纯粹作为"一组名字的容器"存在。这与使用模块、`types.SimpleNamespace`、`dataclass` 都能达到类似效果，取舍在于代码组织风格。

**与模块做对比**：模块也是一种命名空间，适合放跨文件复用的东西；类作为命名空间更适合把"强相关的一小组常量/函数"内聚在一起，或需要配合继承时使用。

### 2.9 空类用 pass

有时候我们只是想先占一个"类坑位"，还没想好里面写什么内容。这时类体不能为空，最简单的填充手段就是 `pass`：

```python
class Placeholder:
    pass

p = Placeholder()
p.anything = 123   # 实例可以任意加属性
print(p.anything)
# 输出：
# 123
```

`pass` 是一个空操作语句，放在类体里仅满足"类体不能为空"的语法要求。除了 `pass`，也可以用文档字符串 `"""..."""` 来填充类体，既占位又留说明：

```python
class TODO:
    """这个类以后用来表示待办事项，当前留空。"""
```

留空类并非毫无意义：它可以作为"统一类型标记"或接收动态属性的"数据包"使用，在原型阶段很常见。

### 2.10 类对象本身是一等对象

前面提到类对象是"一等对象"，这一点值得单独强调，因为它支撑了很多灵活的写法。

一等对象意味着类对象可以：

- 被赋值给变量。
- 作为参数传给函数。
- 作为函数返回值。
- 放进容器（列表、字典）。
- 被 `is`、`==` 判断比较。

```python
class Dog:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "汪"

class Cat:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "喵"

# 把多个类对象放进列表，统一管理
animals = [Dog, Cat]

# 用「类对象」作为参数，根据需要实例化不同类型
def make_animal(cls, name):
    return cls(name)

pets = [make_animal(animals[0], "旺财"),
        make_animal(animals[1], "咪咪")]

for pet in pets:
    print(pet.name, "->", pet.speak())
# 输出：
# 旺财 -> 汪
# 咪咪 -> 喵
```

上面 `make_animal` 不关心传进来的是 `Dog` 还是 `Cat`，只要是"能被调用的类对象"就行。这是一种典型的"把类型当数据用"的模式，在工厂方法、插件系统、策略模式中极为常见。

**把类对象存进字典做"类型注册表"**

```python
registry = {}
registry["dog"] = Dog
registry["cat"] = Cat

def create(kind, name):
    cls = registry.get(kind)
    if cls is None:
        raise ValueError(f"未知类型：{kind}")
    return cls(name)

print(create("dog", "旺财").speak())
# 输出：
# 汪
```

这种"注册表—工厂"的写法在框架中非常普遍，例如 Web 框架按字符串名实例化视图类、序列化库按字段类型名选对应的字段类。

**类对象 vs 实例对象的 `is` 比较**

```python
a1 = Dog("甲")
a2 = Dog("甲")
print(a1 is a2)   # False：两次实例化得到两个不同实例
print(type(a1) is Dog)  # True：两个实例共享同一个类对象
print(type(a1) is type(a2))  # True
# 输出：
# False
# True
# True
```

注意虽然 `a1` 与 `a2` 内容相同，但它们是两次独立实例化产生的新对象，所以 `is` 为 `False`；而它们的类型是同一个类对象 `Dog`，所以 `type(a1) is Dog` 成立。

## 3. 最佳实践

**用 `__init__` 初始化属性，而不是在类体写一大堆实例属性**

类体里写的变量是"类属性"，会被所有实例共享，很多人误把它当成"实例默认值"来用，结果踩了可变对象的坑。正确做法是把需要每个实例独立保存的属性，全部放到 `__init__` 里通过 `self` 设置。

```python
# 不推荐：可变类属性，所有实例共享同一个列表
class BadDog:
    tricks = []
    def add(self, trick):
        self.tricks.append(trick)

# 推荐：每个实例在 __init__ 里拥有独立的列表
class GoodDog:
    def __init__(self, name):
        self.name = name
        self.tricks = []
    def add(self, trick):
        self.tricks.append(trick)
```

**`__init__` 不要做"重活"**

`__init__` 的定位是"把对象准备好"，适合做属性赋值、简单校验。避免在其中执行耗时 I/O、网络请求或复杂业务逻辑。如果一个对象构造时确实需要完成某些重操作，建议拆出专门的 `setup()` 方法显式调用，或用工厂函数封装，让"构造对象"和"执行流程"保持界限清楚。

```python
# 不推荐：构造时就做重操作
class BadFetcher:
    def __init__(self, url):
        self.url = url
        self.data = self._fetch(url)   # 构造即发起请求，隐藏副作用

# 推荐：构造只存配置，用方法触发重操作
class GoodFetcher:
    def __init__(self, url):
        self.url = url
        self.data = None
    def fetch(self):
        self.data = self._fetch(self.url)
```

**参数校验放 `__init__`，失败要早**

如果某些参数非法就根本无法构造出有意义的对象，应该在 `__init__` 里立即校验并抛出异常，避免对象带着"半残"状态流到后续逻辑里。

```python
class Rectangle:
    def __init__(self, width, height):
        if width <= 0 or height <= 0:
            raise ValueError("宽高必须为正数")
        self.width = width
        self.height = height
```

**不要依赖 `__init__` 返回值**

记住 `__init__` 只能返回 `None`，真正被返回的是 `__new__` 创建的实例。如果需要"构造时做条件判断并返回不同对象"，把逻辑放到工厂函数里，而不是试图让 `__init__` 返回东西：

```python
# 推荐：用工厂函数决定返回哪种实例
class Circle:
    def __init__(self, radius):
        self.radius = radius

class Square:
    def __init__(self, side):
        self.side = side

def make_shape(kind, size):
    if kind == "circle":
        return Circle(size)
    elif kind == "square":
        return Square(size)
    raise ValueError(f"未知形状：{kind}")
```

**慎用动态添加实例属性**

Python 允许随时给实例加属性，但滥用会让对象结构难以追踪。工程上建议：所有预期属性都在 `__init__` 中声明；如果需要强制限制属性集合，可以考虑使用 `__slots__`，既节省内存又防止误加属性。

**类作为命名空间时优先考虑 `staticmethod`**

把类当容器装一组工具函数时，方法如果不访问 `self` 也不访问类属性，应标注为 `@staticmethod` 或直接定义为模块级函数，向读者表明"它不依赖实例也不依赖类状态"。

```python
class MathUtil:
    @staticmethod
    def add(a, b):
        return a + b
```

**空类也要留文档字符串**

如果暂时用 `pass` 占位，建议同时写上文档字符串说明用途，避免日后变成"无主代码"。

## 4. 原理

### 4.1 class 是可执行语句：类体的执行与类对象的创建

很多人把 `class` 当成一种"声明"——以为只是告诉编译器"这里有个类"。但在 Python 中，`class` 是一条**可执行语句**，它会在被执行时真正地"跑一遍类体"，并用类体的执行结果创建出一个类对象。这一点和编译型语言（如 Java 的"类编译期就确定"）有本质区别。

具体过程可以拆成以下几步：

1. **执行到 `class` 语句时**，Python 先准备好一个临时命名空间（本质上是一个字典形式的局部作用域），用于收集接下来类体里定义的所有名字。这个命名空间起初可能是空的，或预置一些项（如 `__name__`）。
2. **执行类体**：类体里的每一行语句按顺序执行。赋值语句 `species = "犬科"` 会在临时命名空间里建立 `species`；`def bark(self): ...` 会执行一个函数定义，把函数对象绑定到临时命名空间的 `bark`；`print(...)` 这种普通语句则会直接产出它的副作用。
3. **类体执行完毕后**，Python 会调用元类（默认是 `type`）来"铸造"类对象：`type(name, bases, namespace)`。这里 `name` 是类名字符串（如 `"Dog"`），`bases` 是基类元组，`namespace` 就是刚才类体执行积累下来的命名空间字典。`type(...)` 返回的就是新建的类对象。
4. **绑定类名**：最后 Python 把类对象绑定到当前作用域的类名上（例如模块级别 `class Dog` 会让模块的命名空间里 `Dog` 指向这个新类对象）。

因此，类体中的 `print`、赋值、`if`、`for` 等语句都是会真实执行的：

```python
import random

class Config:
    if random.random() < 0.5:   # 类体里有 if，定义时就会判断
        MODE = "dev"
    else:
        MODE = "prod"
    print("类体被执行，MODE =", MODE)

print("Config.MODE =", Config.MODE)
# 输出（每次运行结果可能不同）：
# 类体被执行，MODE = dev
# Config.MODE = dev
```

上面类体里的 `if` 在定义时就执行过了，所以 `MODE` 的值在类创建那一刻就固定下来。再次强调：类体只在定义时执行一次，后续实例化不会重新跑这段 `if`。

**类对象本身也是 `type` 的实例**

由于类对象是由 `type(name, bases, namespace)` 创建出来的，所以"类"本身也是某个"类型"的实例——那个类型就是元类 `type`。可以验证：

```python
class Dog:
    pass

print(type(Dog))     # <class 'type'>
print(Dog.__class__) # <class 'type'>
print(isinstance(Dog, type))  # True
# 输出：
# <class 'type'>
# <class 'type'>
# True
```

这就形成了一个清晰的层级：普通对象 → 类对象（它的类型）→ `type` 元类。`type` 自己也是自己的实例，这是 Python 对象模型的一个有趣事实。

### 4.2 实例化调用：type.__call__ 驱动 __new__ → __init__

当写 `Dog("旺财", 3)` 时，看起来像是"调用了一个函数"，但这其实是"调用一个类对象"。Python 对"调用类对象"的处理，本质上等价于调用其元类的 `__call__` 方法。由于默认元类是 `type`，所以 `Dog(...)` 实际上分发给 `type.__call__(Dog, ...)`。

`type.__call__` 的行为大致可以用下面这段伪代码描述：

```python
# 伪代码，描述 type.__call__ 的内部流程
def type_call(cls, *args, **kwargs):
    # 第一步：调用 cls.__new__ 创建实例
    instance = cls.__new__(cls, *args, **kwargs)

    # 第二步：判断 __new__ 返回的是不是 cls 的实例
    if isinstance(instance, cls):
        # 是的话，调用 __init__ 做初始化
        cls.__init__(instance, *args, **kwargs)

    # 第三步：返回实例（而不是 __init__ 的返回值）
    return instance
```

从这个伪代码可以解释前文提到的几个"反直觉"现象：

- **为什么 `__init__` 永远返回 `None`，而 `Dog(...)` 却能得到实例**：因为真正被返回的是 `__new__` 创建、再由 `__init__` 加工后的 `instance`，与 `__init__` 的返回值无关。
- **为什么 `__new__` 返回非本类实例时 `__init__` 不被调用**：因为伪代码里的 `isinstance(instance, cls)` 判断为假，跳过了 `__init__`。
- **为什么 `__init__` 写 `return 1` 会报错**：这是 Python 在调用 `__init__` 之后的额外检查——若 `__init__` 返回非 `None`，则抛出 `TypeError`。这个检查并不在 `type.__call__` 的核心流程里，而是 `__init__` 的特殊约束。

可以用代码近似模拟这条调用链，帮助理解：

```python
class Dog:
    def __new__(cls, *args, **kwargs):
        print("→ __new__：创建实例")
        instance = object.__new__(cls)   # 委托 object 完成底层分配
        return instance

    def __init__(self, name, age):
        print("→ __init__：初始化实例")
        self.name = name
        self.age = age

# 手动模拟 type.__call__(Dog, "旺财", 3)
instance = Dog.__new__(Dog, "旺财", 3)
if isinstance(instance, Dog):
    Dog.__init__(instance, "旺财", 3)
dog = instance

print(dog.name, dog.age)
# 输出：
# → __new__：创建实例
# → __init__：初始化实例
# 旺财 3
```

注意上面是"手动拆开"的演示，实际 `Dog("旺财", 3)` 一行就完成了相同流程：`type.__call__` 在 C 层把这一切串起来。

**参数如何从 `Dog(...)` 流到 `__new__` 和 `__init__`**

按默认机制，`Dog("旺财", 3)` 中的参数会同时传给 `__new__` 和 `__init__`。也就是说 `__new__(cls, "旺财", 3)` 与 `__init__(instance, "旺财", 3)` 都会收到这些参数。默认的 `object.__new__` 只接受 `cls`，不接受多余参数——这就是为什么平时我们不重写 `__new__`，直接让 `object.__new__(cls)` 就能用。

但如果子类重写了 `__new__` 且签名不匹配，就容易出现"`__new__` 收到多余参数"的错误：

```python
class Truck:
    def __new__(cls):          # 只接受 cls
        return super().__new__(cls)
    def __init__(self, load):  # 需要 load
        self.load = load

try:
    Truck("5吨")
except TypeError as e:
    print("报错：", e)
# 输出：
# 报错： object.__new__() takes exactly one argument (the type to instantiate)
```

因此在重写 `__new__` 时，通常写成 `def __new__(cls, *args, **kwargs)` 来兼容 `__init__` 的参数，避免因参数不匹配而报错。

### 4.3 类对象的 __dict__ 与实例对象的 __dict__

理解 `__dict__` 的结构，能解释"为什么类属性可以共享、实例属性可以隔离"这个核心问题。

**类对象的 `__dict__`**：它存放类体执行时收集到的全部名字——包括类属性、方法、以及 Python 自动附加的若干项。从实现上看，类的 `__dict__` 通常返回一个 `mappingproxy`（只读视图）而不是普通 `dict`，这是为了防止通过 `Class.__dict__['x'] = ...` 随意修改造成不可控变化。要给类加属性，正确的做法是用赋值语句 `Class.x = ...`。

```python
class Dog:
    species = "犬科"
    def __init__(self, name):
        self.name = name

print(type(Dog.__dict__))   # mappingproxy
print(Dog.__dict__['species'])   # 可以读
# 输出：
# <class 'mappingproxy'>
# 犬科
```

**实例对象的 `__dict__`**：它存放这个实例"自己的"属性，通常是 `__init__` 打在 `self` 上的那些，或之后动态添加的。默认情况下实例的 `__dict__` 是一个普通的 `dict`，可以读写。

```python
d = Dog("旺财")
print(type(d.__dict__))   # dict
d.__dict__['color'] = "黄"   # 这种"直接改 __dict__"的方式虽然可行但不推荐
print(d.color)
# 输出：
# <class 'dict'>
# 黄
```

**属性查找的链路**：当访问 `d.species` 时，Python 的查找顺序大致是：

1. 先看实例的 `__dict__` 里有没有 `species`。
2. 若没有，沿 MRO（方法解析顺序）依次查类的 `__dict__`，以及基类的 `__dict__`。
3. 如果通过常规查找都找不到，才会触发 `__getattr__` 等描述符机制（这里先不展开）。

```python
class Animal:
    species = "动物"

class Dog(Animal):
    def __init__(self, name):
        self.name = name   # 只打实例属性，没给 species

d = Dog("旺财")
print("实例 __dict__：", d.__dict__)
print("类 __dict__ 的 species：", Dog.__dict__.get('species'))
print("基类 __dict__ 的 species：", Animal.__dict__.get('species'))
print("访问 d.species：", d.species)
# 输出：
# 实例 __dict__： {'name': '旺财'}
# 类 __dict__ 的 species： None
# 基类 __dict__ 的 species： 动物
# 访问 d.species： 动物
```

这个 demo 验证了属性查找会"从实例 → 本类 → 基类"逐级上溯，直到找到为止。当实例 `__dict__` 里没有 `species`，本类也没有，最终从基类 `Animal` 的 `__dict__` 里取到 `"动物"`。

**修改类属性等于改"共享数据"**

由于所有实例在访问类属性时都查到同一个类 `__dict__`，修改类属性就是改"所有实例共享的那份"：

```python
class Dog:
    legs = 4

a = Dog()
b = Dog()
print(a.legs, b.legs)
Dog.legs = 3        # 改类属性
print(a.legs, b.legs)
# 输出：
# 4 4
# 3 3
```

`a.legs` 与 `b.legs` 都"跟着变了"，因为它们查到的都是类属性 `Dog.legs`。但如果给某个实例单独赋值同名属性，就会在它的 `__dict__` 里建立自己的副本，从而"遮蔽"类属性：

```python
a.legs = 5           # 给 a 单独赋值，落到 a.__dict__
print(a.legs, b.legs)
print("a.__dict__：", a.__dict__)
print("b.__dict__：", b.__dict__)
# 输出：
# 5 3
# a.__dict__： {'legs': 5}
# b.__dict__： {}
```

`a` 此后有了一份自己的 `legs`，查找时优先命中实例 `__dict__`；而 `b` 依然读到类属性 `3`。这就是"实例属性遮蔽同名类属性"的原理，也是为什么"在 `__init__` 里把每个实例该有的属性都打上去"能保证独立性——它们在实例自己的 `__dict__` 里各存一份。

### 4.4 类体在定义时执行一次：对实例化的影响

第 4.1 节已经讲过类体在定义时执行一次，这里进一步说明它对实例化的影响。

**类属性只初始化一次**：由于类体只在定义时跑一次，类属性 `tricks = []` 也只在那一刻创建一个列表对象。之后所有实例访问 `tricks` 都查到同一个列表对象，对它做 `append` 就是在改"全局共享"对象。这就是"可变类属性坑"的根因。

```python
class BadDog:
    tricks = []   # 只在类体执行那一次创建列表，之后所有实例共享
    def add(self, trick):
        self.tricks.append(trick)

a = BadDog(); a.add("握手")
b = BadDog(); b.add("翻滚")
print(a.tricks)
print(a.tricks is b.tricks)   # 同一个列表对象
# 输出：
# ['握手', '翻滚']
# True
```

**实例方法定义也只执行一次**：类体里的 `def bark(self): ...` 在定义时就执行了 `def` 语句，把函数对象绑到命名空间里。之后多次实例化，`bark` 始终是同一个对象，所有实例共享这一个方法：

```python
class Dog:
    def bark(self):
        return "汪"

print(Dog.bark is Dog.bark)   # 类层面共享同一个方法对象
a = Dog(); b = Dog()
print(a.bark is b.bark)        # True：实例访问的也是同一个函数
# 输出：
# True
# True
```

`a.bark is b.bark` 为真意味着它们访问到的是类 `__dict__` 里的同一个函数对象。只是在通过实例调用 `a.bark()` 时，Python 用描述符机制把 `a` 自动绑定为 `self`，但底层的函数对象是同一个。

**为什么 `__init__` 每次实例化都执行，而类体不重跑**：`__init__` 是一个挂在类上的方法，每次 `type.__call__` 调用 `__new__` 创建新实例后，都会紧接着调用 `__init__(instance, ...)`。所以每个新实例都会经历一次 `__init__`。而类体只在 `class` 语句被执行时跑一次，和实例化无关。两者职责分离：类体负责"定义类的形状"，`__init__` 负责"填充每个新实例的状态"。

## 5. 总结

本文围绕 Python 类与实例的定义，系统讲解了 class 关键字、类对象与实例对象、`__init__` 初始化器、实例化过程、类与实例的 `__dict__`、`__new__` 与 `__init__` 分工、类作为命名空间、空类用 `pass`，以及类对象作为一等对象的使用方式。

要点回顾：

- `class` 是可执行语句，类体在定义时执行一次，留存的命名空间经 `type(...)` 铸成类对象。
- 类对象代表"一类"的抽象定义，实例对象通过 `ClassName()` 产生，各自保存独立数据。
- `__init__` 负责初始化实例状态，不应返回非 `None` 值；真正"构造"空实例的工作由 `__new__` 完成。
- 实例化调用链：`ClassName(...)` → `type.__call__(...)` → `__new__` 创建实例 → 若返回本类实例则调用 `__init__` 初始化 → 返回实例。
- 类对象的 `__dict__` 存类属性与方法，实例对象的 `__dict__` 存实例自己绑定的属性；属性查找按"实例→类→基类"逐级进行。
- 可变容器必须挂到实例上（在 `__init__` 里赋给 `self`），避免作为类属性被所有实例共享。
- 类可以作为命名空间或类型注册表使用；类对象是一等对象，可被赋值、传参、返回、遍历。
- `pass` 或文档字符串可填充空类体，满足"类体不能为空"的语法要求。

- 能区分类对象与实例对象的 `__dict__` 各自存放什么，并用属性查找机制解释"实例访问类属性"和"实例属性遮蔽类属性"的行为。
