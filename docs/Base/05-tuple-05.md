# 元组的拼接与重复

## 1. 介绍

### 1.1 什么是元组的拼接与重复

元组虽然不可变，但 Python 提供了两个序列运算符来"组合"已有元组、生成新元组：**拼接**（`+`）和**重复**（`*`）。它们都不会修改原元组——而是创建一个全新的元组对象。

- **拼接 `+`**：把两个元组首尾相连，合并成一个更长的元组。
- **重复 `*`**：把一个元组复制 n 份首尾相连，生成一个更长的元组。

```python
# 拼接：两段合一
a = (1, 2, 3)
b = (4, 5, 6)
print(a + b)  # (1, 2, 3, 4, 5, 6)

# 重复：复制 n 份
print((0,) * 5)  # (0, 0, 0, 0, 0)
```

理解拼接和重复，核心在于一句话：**它们创建新元组，原元组始终不变**。这和列表的 `+` / `*` 有微妙差异——列表还有 `+=`（就地 extend）和 `*=`（就地重复），而元组的 `+=` / `*=` 也会创建新对象。

### 1.2 运算符速览

| 运算符 | 语法 | 返回类型 | 示例 | 结果 |
|--------|------|---------|------|------|
| 拼接 | `t1 + t2` | tuple | `(1,) + (2,)` | `(1, 2)` |
| 重复 | `t * n` | tuple | `(0,) * 3` | `(0, 0, 0)` |
| 反向重复 | `n * t` | tuple | `3 * (0,)` | `(0, 0, 0)` |
| 增广拼接 | `t += (x,)` | — | `t += (3,)` | `t` 重新绑定到新对象 |
| 增广重复 | `t *= n` | — | `t *= 2` | `t` 重新绑定到新对象 |

### 1.3 核心注意事项

在深入每种运算符之前，有四个关键点需要先记住：

**第一：`+` 两边必须都是元组。** 不能拼接元组和列表，必须先转换。

```python
# 正确
result = (1, 2) + (3, 4)
print(result)  # (1, 2, 3, 4)

# 错误：类型不匹配
# (1, 2) + [3, 4]  # TypeError!

# 修正：先转换
result = (1, 2) + tuple([3, 4])
print(result)  # (1, 2, 3, 4)
```

**第二：`*` 的重复份数 `n` 为 0 或负数时返回空元组。**

```python
print((1, 2, 3) * 0)   # ()
print((1, 2) * -1)     # ()
print((1, 2) * -100)   # ()
```

**第三：`*` 重复可变元素会产生引用共享。** 这是最常见的陷阱。

```python
# 不可变元素：安全
nums = (0,) * 3
print(nums)  # (0, 0, 0)

# 可变元素：引用共享！
lists = ([],) * 3
lists[0].append("X")
print(lists)  # (['X'], ['X'], ['X'])  — 三个都变了！
```

**第四：循环中用 `+=` 拼接元组有性能问题。** 每次拼接都创建新元组并复制全部已有元素，n 次循环的总体复杂度是 O(n^2)。

```python
# 慢：O(n^2) — 每次都复制全部已有元素
result = ()
for i in range(10000):
    result += (i,)

# 快：O(n) — 列表 append 是均摊 O(1)
items = []
for i in range(10000):
    items.append(i)
result = tuple(items)
```

## 2. 核心内容

### 2.1 加法拼接：`+`

`+` 运算符将两个元组合并为一个新元组。原元组不变，结果是一个全新的元组对象。

```python
# 基本拼接
a = (1, 2, 3)
b = (4, 5, 6)
c = a + b
print(f"{a} + {b} = {c}")
print(f"a 不变: {a}, b 不变: {b}")
```

**运行结果**：

```text
(1, 2, 3) + (4, 5, 6) = (1, 2, 3, 4, 5, 6)
a 不变: (1, 2, 3), b 不变: (4, 5, 6)
```

#### 2.1.1 链式拼接

`+` 可以链式使用——从左到右依次合并：

```python
result = (1,) + (2,) + (3,) + (4,)
print(f"链式拼接: {result}")  # (1, 2, 3, 4)
```

**运行结果**：

```text
链式拼接: (1, 2, 3, 4)
```

链式拼接的执行顺序是从左到右：先算 `(1,) + (2,)` 得到 `(1, 2)`，再算 `(1, 2) + (3,)` 得到 `(1, 2, 3)`，最后算 `(1, 2, 3) + (4,)`。每次 `+` 都创建一个新元组，所以 3 次 `+` 创建 3 个中间元组——但只有最后一个被保留，前两个会被垃圾回收。

#### 2.1.2 空元组是拼接的单位元

空元组 `()` 在拼接中扮演"零"的角色——任何元组与空元组拼接，结果都是它自身：

```python
print(f"() + (1,2) = {() + (1, 2)}")  # (1, 2)
print(f"(1,2) + () = {(1, 2) + ()}")  # (1, 2)
```

**运行结果**：

```text
() + (1,2) = (1, 2)
(1,2) + () = (1, 2)
```

数学上，这叫"单位元"（identity element）——`t + ()` 和 `() + t` 都等于 `t`，就像 `x + 0 = x`。但注意，结果是一个新元组对象，不是原对象：

```python
t = (1, 2)
result = t + ()
print(t is result)  # False — 新对象
```

#### 2.1.3 拼接创建新对象

`+` 永远创建一个全新的元组对象，不会修改原元组：

```python
t1 = (1, 2)
t2 = t1 + (3,)
print(f"t1 is t2 → {t1 is t2}")  # False
```

**运行结果**：

```text
t1 is t2 → False
```

这意味着拼接操作是"安全"的——你不需要担心拼接会影响其他引用了原元组的变量。

```python
# 多变量引用同一元组时，拼接不会影响它们
original = (1, 2)
ref = original       # ref 和 original 指向同一对象
new = original + (3,)  # new 指向新对象
print(f"original: {original}")  # (1, 2) — 不变
print(f"ref: {ref}")            # (1, 2) — 不变
print(f"new: {new}")            # (1, 2, 3)
```

#### 2.1.4 类型约束

`+` 运算符要求两边必须是同类型（或至少是可拼接的类型）。元组的 `+` 只接受元组，不接受列表、字符串等其他序列：

```python
# 元组 + 列表 → TypeError
try:
    (1, 2) + [3, 4]
except TypeError as e:
    print(f"TypeError: {e}")

# 解决方案：先转换
from_list = (1, 2) + tuple([3, 4])
print(f"先转再拼: {from_list}")
```

**运行结果**：

```text
TypeError: can only concatenate tuple (not "list") to tuple
先转再拼: (1, 2, 3, 4)
```

如果需要把元组和列表合并，先用 `tuple()` 或 `list()` 统一类型，再拼接。

#### 2.1.5 拼接嵌套元组

拼接嵌套元组时，`+` 只拼接外层——内层元组作为整体保留：

```python
grid_a = ((1, 2), (3, 4))
grid_b = ((5, 6),)
grid = grid_a + grid_b
print(f"嵌套拼接: {grid}")
```

**运行结果**：

```text
嵌套拼接: ((1, 2), (3, 4), (5, 6))
```

结果是 `((1, 2), (3, 4), (5, 6))`——三个内层元组作为外层元素被拼接，内层结构不变。

#### 2.1.6 拼接的实际应用

**场景一：构建表头 + 数据行**

```python
header = ("序号", "姓名", "成绩")
row = (1, "张三", 90.5)
full = header + row
print(f"表头+数据: {full}")
```

**运行结果**：

```text
表头+数据: ('序号', '姓名', '成绩', 1, '张三', 90.5)
```

**场景二：多段坐标拼接成路径**

```python
seg1 = ((0, 0), (1, 1))
seg2 = ((2, 2), (3, 3))
path = seg1 + seg2
print(f"路径拼接: {path}")
```

**运行结果**：

```text
路径拼接: ((0, 0), (1, 1), (2, 2), (3, 3))
```

#### 2.1.7 拼接的性能特征

拼接的时间复杂度是 O(n + m)——需要分配新内存并复制两个元组的所有指针。单次拼接很快，但在循环中反复拼接会导致累积开销：

```python
import time

# 方式一：循环中用 +=（O(n^2)）
start = time.time()
result = ()
for i in range(5000):
    result += (i,)
print(f"循环 += 拼接 5000 次: {time.time() - start:.4f}s, 长度={len(result)}")

# 方式二：用列表收集再转元组（O(n)）
start = time.time()
items = []
for i in range(5000):
    items.append(i)
better = tuple(items)
print(f"列表收集 5000 次: {time.time() - start:.4f}s, 长度={len(better)}")
```

**运行结果**（数值因环境而异）：

```text
循环 += 拼接 5000 次: 0.0177s, 长度=5000
列表收集 5000 次: 0.0002s, 长度=5000
```

列表收集快了近 90 倍。原因：列表 `append` 是均摊 O(1)（只在扩容时复制一次），而元组 `+=` 每次都需要复制全部已有元素。数据量越大，差距越明显。

### 2.2 乘法重复：`*`

`*` 运算符将元组重复 n 次，创建一个包含 n 份副本的新元组。`n` 必须是整数。

#### 2.2.1 基本重复

```python
zeros = (0,) * 5
print(f"(0,) * 5 = {zeros}")

pattern = (1, 2) * 3
print(f"(1, 2) * 3 = {pattern}")
```

**运行结果**：

```text
(0,) * 5 = (0, 0, 0, 0, 0)
(1, 2) * 3 = (1, 2, 1, 2, 1, 2)
```

重复是把整个元组复制 n 份首尾相连——`(1, 2) * 3` 是 `(1, 2)` 重复 3 次，结果是 `(1, 2, 1, 2, 1, 2)`，不是 `(1, 1, 1, 2, 2, 2)`。

#### 2.2.2 n <= 0 时返回空元组

```python
print(f"(1,2,3) * 0 = {(1, 2, 3) * 0}")    # ()
print(f"(1,2) * -1 = {(1, 2) * -1}")        # ()
print(f"(1,2) * -100 = {(1, 2) * -100}")    # ()
```

**运行结果**：

```text
(1,2,3) * 0 = ()
(1,2) * -1 = ()
(1,2) * -100 = ()
```

当 `n <= 0` 时，`*` 返回空元组。而且返回的是全局空元组单例——不会为每次调用分配新对象：

```python
e1 = (1,) * 0
e2 = (2,) * 0
print(f"(1,)*0 is (2,)*0 → {e1 is e2}")  # True — 同一个空元组
```

#### 2.2.3 `t * n` 和 `n * t` 等价

重复运算符的两个操作数顺序不影响结果：

```python
print(f"(1,2) * 3 = {(1, 2) * 3}")  # (1, 2, 1, 2, 1, 2)
print(f"3 * (1,2) = {3 * (1, 2)}")  # (1, 2, 1, 2, 1, 2)
```

**运行结果**：

```text
(1,2) * 3 = (1, 2, 1, 2, 1, 2)
3 * (1,2) = (1, 2, 1, 2, 1, 2)
```

这是因为元组同时实现了 `__mul__`（正向 `t * n`）和 `__rmul__`（反向 `n * t`），两者的行为完全一致。

#### 2.2.4 重复创建新对象

`*` 创建新元组对象。对于非空结果，每次调用都创建独立对象：

```python
t1 = (0,) * 5
t2 = (0,) * 5
print(f"(0,)*5 is (0,)*5 → {t1 is t2}")  # False
```

但有一种特殊情况——在某些 Python 实现中，对小元组的重复结果可能被缓存（如 CPython 3.12+ 的优化）。但这属于实现细节，不应该依赖。

#### 2.2.5 重复的实际应用

**场景一：初始化占位**

```python
padding = (None,) * 4
print(f"占位元组: {padding}")  # (None, None, None, None)
```

**场景二：生成重复模式**

```python
beat = (0, 1) * 4
print(f"节拍模式: {beat}")  # (0, 1, 0, 1, 0, 1, 0, 1)
```

**场景三：生成测试数据**

```python
test_rows = ("test",) * 3
print(f"测试数据: {test_rows}")  # ('test', 'test', 'test')
```

**场景四：构建二维网格行**

```python
grid_row = (0,) * 5
print(f"网格行: {grid_row}")  # (0, 0, 0, 0, 0)
```

#### 2.2.6 重复的内存占用

`*` 重复时只复制指针（引用），不复制元素对象本身。所以内存占用与重复份数成正比：

```python
import sys

for n in [1, 5, 10, 50]:
    t = (0,) * n
    print(f"(0,) * {n:3d} → 长度={len(t):3d}, 占用={sys.getsizeof(t):4d} 字节")
```

**运行结果**：

```text
(0,) *   1 → 长度=  1, 占用=  48 字节
(0,) *   5 → 长度=  5, 占用=  80 字节
(0,) *  10 → 长度= 10, 占用= 120 字节
(0,) *  50 → 长度= 50, 占用= 440 字节
```

每个元素占 8 字节（一个指针），加上对象头的固定开销。因为只复制指针，所以 `(0,) * 1000000` 也只需要几百毫秒：

```python
import time

start = time.time()
t = (0,) * 1000000
elapsed = time.time() - start
print(f"(0,) * 1000000: {elapsed:.4f}s, 长度={len(t)}")

start = time.time()
t = (1, 2, 3) * 1000000
elapsed = time.time() - start
print(f"(1,2,3) * 1000000: {elapsed:.4f}s, 长度={len(t)}")
```

**运行结果**：

```text
(0,) * 1000000: 0.0011s, 长度=1000000
(1,2,3) * 1000000: 0.0039s, 长度=3000000
```

### 2.3 拼接与重复的组合使用

#### 2.3.1 运算优先级

和数值运算一样，`*` 的优先级高于 `+`：

```python
# * 优先于 +
result = (1,) + (2,) * 3
print(f"(1,) + (2,) * 3 = {result}")  # (1, 2, 2, 2)

# 用括号改变优先级
result2 = ((1,) + (2,)) * 3
print(f"((1,) + (2,)) * 3 = {result2}")  # (1, 2, 1, 2, 1, 2)
```

**运行结果**：

```text
(1,) + (2,) * 3 = (1, 2, 2, 2)
((1,) + (2,)) * 3 = (1, 2, 1, 2, 1, 2)
```

`(1,) + (2,) * 3` 先算 `(2,) * 3` 得到 `(2, 2, 2)`，再算 `(1,) + (2, 2, 2)` 得到 `(1, 2, 2, 2)`。

`((1,) + (2,)) * 3` 先算 `(1,) + (2,)` 得到 `(1, 2)`，再算 `(1, 2) * 3` 得到 `(1, 2, 1, 2, 1, 2)`。

#### 2.3.2 先重复再拼接

用 `+` 在重复结果前添加额外元素：

```python
header = ("ID",)
data = ("A", "B", "C")
line = header + data * 2
print(f"header + data * 2 = {line}")
```

**运行结果**：

```text
header + data * 2 = ('ID', 'A', 'B', 'C', 'A', 'B', 'C')
```

#### 2.3.3 先拼接再重复

先拼好一个小单元，再整体重复：

```python
pair = ("left",) + ("right",)
repeated = pair * 3
print(f"pair * 3 = {repeated}")
```

**运行结果**：

```text
pair * 3 = ('left', 'right', 'left', 'right', 'left', 'right')
```

#### 2.3.4 交替模式生成

结合 `+` 和 `*` 可以生成各种有规律的序列：

```python
# 开关交替
on_off = ("ON", "OFF") * 5
print(f"开关模式: {on_off}")

# 带前缀的重复模式
prefix = ("START",)
body = ("tick", "tock") * 3
full = prefix + body
print(f"带前缀: {full}")
```

**运行结果**：

```text
开关模式: ('ON', 'OFF', 'ON', 'OFF', 'ON', 'OFF', 'ON', 'OFF', 'ON', 'OFF')
带前缀: ('START', 'tick', 'tock', 'tick', 'tock', 'tick', 'tock')
```

#### 2.3.5 分组拼接与重复

```python
group1 = (1, 2, 3)
group2 = (4, 5, 6)
group3 = (7, 8, 9)

# 多组拼接
all_groups = group1 + group2 + group3
print(f"三组合并: {all_groups}")

# 重复分组
pairs = (group1 + group2) * 2
print(f"分组重复: {pairs}")
```

**运行结果**：

```text
三组合并: (1, 2, 3, 4, 5, 6, 7, 8, 9)
分组重复: (1, 2, 3, 4, 5, 6, 1, 2, 3, 4, 5, 6)
```

### 2.4 可变元素的引用共享陷阱

这是元组重复中最重要的陷阱。当元组包含可变元素（如列表、字典）时，`*` 重复的是引用——所有副本指向同一个可变对象。

#### 2.4.1 不可变元素：安全

```python
# 数字是不可变的——重复安全
nums = (0,) * 3
print(f"不可变元素: {nums}")  # (0, 0, 0)

# 字符串是不可变的——重复安全
strings = ("hi",) * 3
print(f"字符串重复: {strings}")  # ('hi', 'hi', 'hi')

# 内层元组也是不可变的——重复安全
inner_tuple = ((1, 2),) * 3
print(f"内层元组重复: {inner_tuple}")  # ((1, 2), (1, 2), (1, 2))
```

**运行结果**：

```text
不可变元素: (0, 0, 0)
字符串重复: ('hi', 'hi', 'hi')
内层元组重复: ((1, 2), (1, 2), (1, 2))
```

不可变元素即使被多个引用共享，也无所谓——因为你无法修改它们，不会出现"改一个全变了"的问题。

#### 2.4.2 可变元素：引用共享

```python
# 用 * 重复包含列表的元组
lists = ([],) * 3
print(f"初始: {lists}")

# 修改第一个列表
lists[0].append("X")
print(f"修改后: {lists}")  # 三个都变了！
```

**运行结果**：

```text
初始: ([], [], [])
修改后: (['X'], ['X'], ['X'])
```

原因：`([],) * 3` 在内部只创建了一个列表对象 `[]`，然后让元组的三个槽位都指向它。修改 `lists[0]` 就是修改那个唯一的列表，所以三个位置都看到了变化。

```python
# 验证：三个槽位指向同一个对象
print(f"lists[0] is lists[1] → {lists[0] is lists[1]}")  # True
print(f"lists[0] is lists[2] → {lists[0] is lists[2]}")  # True
```

**运行结果**：

```text
lists[0] is lists[1] → True
lists[0] is lists[2] → True
```

引用共享的内存图解：

```text
([],) * 3 的内部结构：

  元组对象
  ┌─────────────────────────┐
  │ ob_item[0] ──┐           │
  │ ob_item[1] ──┼──→ 同一个 list 对象 []
  │ ob_item[2] ──┘           │
  └─────────────────────────┘

  三个槽位指向同一个 []，修改任何一个，全部都变化。
```

#### 2.4.3 拼接中的引用共享

`+` 本身不会产生引用共享——每段元素来自不同的元组，通常是独立的：

```python
a = ([1],)
b = ([2],)
c = a + b
print(f"c[0] is c[1] → {c[0] is c[1]}")  # False — 不同对象
```

但如果拼接包含相同引用的元组，引用共享依然会出现：

```python
shared = ([],)
d = shared + shared  # 拼接两个相同的元组
print(f"d = {d}")
print(f"d[0] is d[1] → {d[0] is d[1]}")  # True! 引用共享
```

**运行结果**：

```text
d = ([], [])
d[0] is d[1] → True
```

这种情况比较少见，但需要警惕——如果你需要独立的可变元素，拼接后也要检查引用是否独立。

#### 2.4.4 正确做法：推导式创建独立对象

用生成器表达式或列表推导式为每个位置创建独立的可变对象：

```python
# 错误方式
bad = ([],) * 3
bad[0].append(1)
print(f"错误方式: {bad}")  # ([1], [1], [1]) — 全部变了

# 正确方式一：列表推导式
good = tuple([[] for _ in range(3)])
good[0].append(1)
print(f"推导式: {good}")  # ([1], [], []) — 只有第一个变了

# 正确方式二：生成器表达式
good2 = tuple([] for _ in range(3))
good2[0].append(1)
print(f"生成器: {good2}")  # ([1], [], []) — 只有第一个变了
```

**运行结果**：

```text
错误方式: ([1], [1], [1])
推导式: ([1], [], [])
生成器: ([1], [], [])
```

验证引用独立性：

```python
safe = tuple([[] for _ in range(3)])
print(f"safe[0] is safe[1] → {safe[0] is safe[1]}")  # False
print(f"safe[0] is safe[2] → {safe[0] is safe[2]}")  # False
```

**运行结果**：

```text
safe[0] is safe[1] → False
safe[0] is safe[2] → False
```

推导式的内存图解：

```text
tuple([] for _ in range(3)) 的内部结构：

  元组对象
  ┌─────────────────────────┐
  │ ob_item[0] → list对象1 []   │  ← 独立列表 1
  │ ob_item[1] → list对象2 []   │  ← 独立列表 2
  │ ob_item[2] → list对象3 []   │  ← 独立列表 3
  └─────────────────────────┘

  每个槽位指向独立的列表对象，修改互不影响。
```

#### 2.4.5 嵌套可变元素

字典、集合等可变对象同样有引用共享问题：

```python
# 字典重复
configs = ({"name": ""},) * 3
configs[0]["name"] = "Alice"
print(f"字典重复修改后: {configs}")  # 三个都变了！

# 正确做法
safe_configs = tuple({"name": ""} for _ in range(3))
safe_configs[0]["name"] = "Alice"
print(f"安全做法: {safe_configs}")  # 只有第一个变了
```

**运行结果**：

```text
字典重复修改后: ({'name': 'Alice'}, {'name': 'Alice'}, {'name': 'Alice'})
安全做法: ({'name': 'Alice'}, {'name': ''}, {'name': ''})
```

规律很清晰：**只要元素是可变对象，用 `*` 重复就会引用共享**。解决办法统一是用推导式或生成器表达式为每个位置创建独立对象。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

| 场景 | 不推荐 | 推荐 | 原因 |
|------|--------|------|------|
| 逐步构建元组 | `t = (); for x in data: t += (x,)` | `t = tuple(data)` 或 `t = tuple([x for x in data])` | `+=` 每次创建新元组，O(n^2) |
| 生成占位元组 | `t = tuple([0 for _ in range(n)])` | `t = (0,) * n` | `*` 更简洁高效，O(n) |
| 可变元素重复 | `t = ([],) * n` | `t = tuple([] for _ in range(n))` | `*` 导致引用共享 |
| 元组与列表合并 | `(1,2) + tuple([3,4])` | — | 先转类型再拼，没有更简洁的方式 |
| 生成重复模式 | `t = (0,1,0,1,0,1,0,1)` | `t = (0, 1) * 4` | `*` 更简洁，不易出错 |

### 3.2 循环中构建元组的最佳方式

```python
# 不推荐：循环 += 拼接
# 每次 += 都创建新元组，n 次循环的总体复杂度是 O(n^2)
result = ()
for i in range(10000):
    result += (i,)  # 每次复制全部已有元素

# 推荐：列表收集再转元组
# 列表 append 是均摊 O(1)，总体 O(n)
items = []
for i in range(10000):
    items.append(i)
result = tuple(items)

# 更简洁：直接用推导式
result = tuple(i for i in range(10000))

# 最简洁：直接用 tuple()
result = tuple(range(10000))
```

在循环中需要逐步收集元素构建元组时，**先用列表收集，最后再 `tuple()` 转换**。这是 Python 社区的标准做法。

### 3.3 可变元素重复的安全模式

```python
# 不推荐：可变元素用 * 重复
# 会导致引用共享——修改一个全部变化
bad = ([],) * 3
bad[0].append(1)
print(bad)  # ([1], [1], [1])

# 推荐：用推导式或生成器表达式
good = tuple([] for _ in range(3))
good[0].append(1)
print(good)  # ([1], [], [])
```

**判断规则**：如果元组的元素是可变对象（list、dict、set），**不要用 `*` 重复**，改用推导式。如果元素是不可变的（int、str、tuple、frozenset），用 `*` 重复完全安全。

### 3.4 常见错误模式

**错误一：忘记 + 两边的类型必须一致**

```python
# 错误
# result = (1, 2) + [3, 4]  # TypeError

# 修正
result = (1, 2) + tuple([3, 4])  # 先转换
```

**错误二：以为 * 重复的是元素而非整个元组**

```python
# 误解：以为 (1, 2) * 3 会得到 (1, 1, 1, 2, 2, 2)
# 实际：(1, 2) * 3 得到 (1, 2, 1, 2, 1, 2) — 整体重复

# 如果需要按元素重复
result = tuple(x for x in (1, 2) for _ in range(3))
print(result)  # (1, 1, 1, 2, 2, 2)
```

**错误三：用 * 重复可变对象后修改**

```python
# 错误
grids = ([0, 0] for _ in range(3))  # 生成器，不是元组！
# grids[0]  # TypeError: 'generator' object is not subscriptable

# 修正：外面套 tuple()
grids = tuple([0, 0] for _ in range(3))
grids[0][0] = 9
print(grids)  # ([9, 0], [0, 0], [0, 0])
```

## 4. 原理

### 4.1 `+` 运算符的内部机制

元组的 `+` 由 `tuple.__add__` 实现。内部流程：

```text
t1 + t2 的内部流程：

1. 检查 t2 的类型
   ├── t2 不是 tuple → 抛 TypeError
   └── t2 是 tuple → 继续

2. 计算新长度：new_size = len(t1) + len(t2)

3. 分配新 PyTupleObject
   ├── new_size == 0 → 返回全局空元组单例
   └── new_size > 0 → 分配 new_size 个指针槽位

4. 复制元素（C 层 memcpy）
   ├── memcpy(new.ob_item, t1.ob_item, len(t1) * 8)
   └── memcpy(new.ob_item + len(t1), t2.ob_item, len(t2) * 8)

5. 返回新元组
```

时间复杂度 O(n + m)，因为需要分配新内存并复制两个元组的所有指针。空间复杂度也是 O(n + m)。

用 `dis` 模块查看字节码：

```python
import dis

print("=== (1,2) + (3,4) 的字节码 ===")
dis.dis(compile("(1,2) + (3,4)", "<test>", "eval"))
```

**运行结果**：

```text
=== (1,2) + (3,4) 的字节码 ===
  0 LOAD_CONST               0 ((1, 2))
  2 LOAD_CONST               1 ((3, 4))
  4 BINARY_OP                0 (+)        ← + 运算
  6 RETURN_VALUE
```

`BINARY_OP 0 (+)` 会调用 `tuple.__add__`，内部走上述流程。

### 4.2 `*` 运算符的内部机制

元组的 `*` 由 `tuple.__mul__` 和 `tuple.__rmul__` 实现。内部流程：

```text
t * n 的内部流程：

1. 确保 n 是整数（或可 __index__ 转换的对象）

2. 处理 n <= 0 → 返回全局空元组单例

3. 计算新长度：new_size = len(t) * n

4. 分配新 PyTupleObject（new_size 个指针槽位）

5. 循环复制指针（不是对象本身！）
   for i in range(n):
       memcpy(new.ob_item + i * len(t), t.ob_item, len(t) * 8)

6. 返回新元组
```

**关键**：步骤 5 复制的是指针——每个 8 字节的内存地址。元素对象本身不会被复制。这就是引用共享的根源：当 `t = ([],) * 3` 执行时，三个槽位都指向同一个 `[]` 列表对象。

```python
# 验证 * 只复制指针
a = (42,) * 3
print(f"a[0] is a[1] → {a[0] is a[1]}")  # True — 同一个 int 对象
# 但 int 不可变，所以无副作用

b = ([],) * 3
print(f"b[0] is b[1] → {b[0] is b[1]}")  # True — 同一个 list 对象
# list 可变，所以修改 b[0] 会影响 b[1]！
```

**运行结果**：

```text
a[0] is a[1] → True
b[0] is b[1] → True
```

用 `dis` 模块查看字节码：

```python
import dis

print("=== (0,) * 3 的字节码 ===")
dis.dis(compile("(0,) * 3", "<test>", "eval"))
```

**运行结果**：

```text
=== (0,) * 3 的字节码 ===
  0 LOAD_CONST               0 ((0,))
  2 LOAD_CONST               1 (3)
  4 BINARY_OP                5 (*)        ← * 运算
  6 RETURN_VALUE
```

`BINARY_OP 5 (*)` 会调用 `tuple.__mul__`，内部走上述流程。

### 4.3 链式拼接的中间对象开销

链式拼接 `(1,) + (2,) + (3,) + (4,)` 从左到右依次执行，每次 `+` 创建一个中间元组：

```text
链式拼接的执行过程：

步骤 1: temp1 = (1,) + (2,)     → 创建 (1, 2)   [复制 1 个元素 + 1 个元素]
步骤 2: temp2 = temp1 + (3,)    → 创建 (1, 2, 3) [复制 2 个元素 + 1 个元素]
步骤 3: result = temp2 + (4,)   → 创建 (1, 2, 3, 4) [复制 3 个元素 + 1 个元素]

总计复制次数: 1+1 + 2+1 + 3+1 = 9 次
最终结果: (1, 2, 3, 4)
中间对象: temp1, temp2 （会被 GC 回收）
```

对于 n 段拼接，总共复制 O(n^2) 次。这就是为什么循环中用 `+=` 拼接元组是 O(n^2) 的——每次循环都复制越来越多的已有元素。

### 4.4 `+` 和 `*` 的运算符方法对照

| 运算符 | 特殊方法 | 行为 |
|--------|---------|------|
| `t1 + t2` | `__add__(self, other)` | 拼接，创建新元组 |
| `t * n` | `__mul__(self, n)` | 重复，创建新元组 |
| `n * t` | `__rmul__(self, n)` | 反向重复（与 `__mul__` 相同） |
| `t += (x,)` | 无 `__iadd__`，退化为 `__add__` | 创建新元组，重新绑定变量 |
| `t *= n` | 无 `__imul__`，退化为 `__mul__` | 创建新元组，重新绑定变量 |

元组没有定义 `__iadd__` 和 `__imul__`，这是它和列表的关键区别。列表定义了这两个方法来实现就地修改（`list.__iadd__` 就地 extend，`list.__imul__` 就地重复），元组因为不可变所以没有。

### 4.5 `+=` 退化为 `+` 的机制

当 Python 执行 `t += (3,)` 时，内部流程如下：

```text
t += (3,) 的执行流程：

1. 尝试调用 t.__iadd__((3,))
   ├── 元组：没有 __iadd__ → 返回 NotImplemented
   └── 列表：有 __iadd__ → 就地 extend → 返回 self

2. 如果 __iadd__ 返回 NotImplemented
   └── 退化为 t = t.__add__((3,)) → 创建新元组 (1, 2, 3)
   └── 将 t 重新绑定到新对象

3. 原对象不受影响（如果没有其他引用，会被 GC 回收）
```

对比列表的行为：

```python
# 元组 += 创建新对象
t1 = (1, 2)
t2 = t1
t1 += (3,)
print(f"t1 = {t1}, t2 = {t2}")   # t1=(1,2,3), t2=(1,2) — t2 不变
print(f"t1 is t2: {t1 is t2}")   # False

# 列表 += 就地修改
lst1 = [1, 2]
lst2 = lst1
lst1 += [3]
print(f"lst1 = {lst1}, lst2 = {lst2}")  # 都变了
print(f"lst1 is lst2: {lst1 is lst2}")  # True
```

**运行结果**：

```text
t1 = (1, 2, 3), t2 = (1, 2)
t1 is t2: False
lst1 = [1, 2, 3], lst2 = [1, 2, 3]
lst1 is lst2: True
```

### 4.6 空元组单例优化

当 `*` 的 `n <= 0` 时，返回的不是新分配的空元组，而是全局空元组单例：

```python
# 所有通过 * 0 得到的空元组都是同一个对象
e1 = (1,) * 0
e2 = (2,) * 0
e3 = (1, 2, 3) * -1
print(f"e1 is e2: {e1 is e2}")  # True
print(f"e1 is e3: {e1 is e3}")  # True

# 和显式创建的空元组也是同一个对象
e4 = ()
print(f"e1 is e4: {e1 is e4}")  # True
```

**运行结果**：

```text
e1 is e2: True
e1 is e3: True
e1 is e4: True
```

这个优化是安全的——空元组不可变且没有元素，共享一个全局实例不会产生任何副作用。`+` 运算符在 `new_size == 0` 时也会返回这个单例。

### 4.7 内存分配对比

拼接和重复都是"分配新内存 → 复制指针"，但分配策略不同：

```python
import sys

# 拼接：分配恰好 len(t1) + len(t2) 的空间
t1 = tuple(range(10))
t2 = tuple(range(20))
concat = t1 + t2
print(f"拼接结果长度={len(concat)}, 占用={sys.getsizeof(concat)} 字节")

# 重复：分配恰好 len(t) * n 的空间
repeated = t1 * 3
print(f"重复结果长度={len(repeated)}, 占用={sys.getsizeof(repeated)} 字节")
```

**运行结果**（数值因环境而异）：

```text
拼接结果长度=30, 占用=264 字节
重复结果长度=30, 占用=264 字节
```

元组的内存分配是"恰好分配"——`ob_size` 和实际分配的指针数组大小完全一致，不像列表那样预留额外空间。所以拼接和重复的结果占用内存相同（只要长度相同）。

## 5. 总结

本文围绕"元组的拼接与重复"展开，主要介绍了以下内容：

- **加法拼接 `+`**：将两个元组合并为新元组，原元组不变。`+` 两边必须都是元组，否则抛 `TypeError`。空元组是拼接的单位元——`t + ()` 和 `() + t` 都等于 `t`。链式拼接从左到右依次执行，每次创建中间元组。

- **乘法重复 `*`**：将元组重复 n 次创建新元组。`n <= 0` 返回空元组。`t * n` 和 `n * t` 结果相同。`*` 只复制指针不复制对象——不可变元素安全，可变元素导致引用共享。

- **运算优先级**：`*` 优先级高于 `+`，和数值运算一致。用括号可以改变优先级。`header + data * 2` 先重复再拼接，`(header + data) * 2` 先拼接再重复。

- **可变元素引用共享**：`([],) * 3` 的三个槽位指向同一个列表对象——修改一个全部变化。正确做法是用 `tuple([] for _ in range(n))` 创建独立对象。不可变元素（int、str、tuple）用 `*` 重复完全安全。

- **拼接中的引用共享**：`+` 通常不产生引用共享（元素来自不同元组），但如果拼接相同引用的元组（如 `shared + shared`），引用共享依然出现。拼接后含可变元素也需检查引用独立性。

- **性能要点**：循环中用 `+=` 拼接元组是 O(n^2)（每次复制全部已有元素），应改用列表收集再 `tuple()` 转换（O(n)）。单次拼接和重复都是 O(n+m) 或 O(n*m)，很快。`*` 重复只复制指针，百万级重复也只需毫秒。

- **最佳实践**：逐步构建用列表收集再转元组；可变元素重复用推导式；元组与列表合并先转类型；不可变元素用 `*` 重复是安全高效的。

- **底层原理**：`+` 走 `__add__`，分配新元组后 memcpy 两段指针。`*` 走 `__mul__` / `__rmul__`，循环复制指针而非对象（引用共享的根源）。元组没有 `__iadd__` / `__imul__`，所以 `+=` 退化为 `+`（创建新对象），与列表的 `+=`（就地 extend）行为截然不同。空元组是全局单例，`* 0` 返回同一实例。
