## 2. 核心内容

### 2.1 参数类型的完整分类

Python 函数形参一共可以分为六种类型，按它们在形参列表中的出现位置从前往后排列：

| 序号 | 参数类型 | 语法 | 传递方式 | 示例 |
|------|---------|------|---------|------|
| 1 | 普通位置/关键字参数 | `a, b` | 位置或关键字 | `func(1, 2)` 或 `func(a=1, b=2)` |
| 2 | 仅位置分隔符 | `/` | 分隔符 | `/` 之前的参数只能位置传 |
| 3 | 带默认值的位置/关键字参数 | `c=10` | 位置或关键字（可选） | `func(1, 2)` 或 `func(1, 2, c=3)` |
| 4 | 可变位置参数 | `*args` | 收集剩余位置实参 | 元组 |
| 5 | 仅关键字参数 | `*, e, f=3` | 只能关键字 | `func(e=1, f=2)` |
| 6 | 可变关键字参数 | `**kwargs` | 收集剩余关键字实参 | 字典 |

这六种类型的分类可以用决策树来理解：

```text
参数是否必须存在？
  ├── 是 → 参数有几个？
  │       ├── 固定数量 → 普通参数（类型1、3、5）——根据传递方式约束再细分
  │       │                ├── 仅位置：/ 之前的参数
  │       │                ├── 仅关键字：* 之后的参数
  │       │                └── 两者皆可：/ 和 * 之间的自由区参数
  │       └── 不固定   → *args（类型4）或 **kwargs（类型6）
  │                      ├── 位置实参不固定 → *args（收集为元组）
  │                      └── 关键字实参不固定 → **kwargs（收集为字典）
  └── 否 → 有默认值 → 类型3 或 类型5
                ├── 在 / 之前 → 仅位置 + 默认值：func(x=0, /)
                ├── 在 / 和 * 之间 → 位置/关键字 + 默认值：func(x=0)
                └── 在 * 之后 → 仅关键字 + 默认值：func(*, x=0)
```

**每种类型的语法和示例**：

```python
# 类型1: 普通位置/关键字参数（无默认值）
def f1(a, b):          # 调用: f1(1, 2) 或 f1(a=1, b=2)
    pass

# 类型2: / 分隔符
def f2(a, b, /):       # a, b 只能位置传
    pass               # 调用: f2(1, 2) ✅   f2(a=1, b=2) ❌

# 类型3: 带默认值的位置/关键字参数
def f3(a, b=10):       # b 可选
    pass               # 调用: f3(1) 或 f3(1, 2) 或 f3(1, b=2)

# 类型4: *args
def f4(*args):         # 接收任意数量的位置参数
    print(args)        # 调用: f4(1, 2, 3) → (1, 2, 3)

# 类型5: 仅关键字参数
def f5(*, a, b=10):    # a 必选关键字，b 可选关键字
    pass               # 调用: f5(a=1) ✅   f5(1) ❌

# 类型6: **kwargs
def f6(**kwargs):      # 接收任意数量的关键字参数
    print(kwargs)      # 调用: f6(x=1, y=2) → {'x': 1, 'y': 2}
```

### 2.2 形参列表的严格顺序规则

Python 对形参列表中的参数顺序有严格的语法要求。违反任何一条都会直接报 `SyntaxError`。

#### 2.2.1 完整顺序规则

```text
1. 普通位置参数（无默认值）   例: a, b
2. 带默认值的位置参数         例: c=1, d=2
3. / 分隔符（可选）           例: /
4. 普通位置/关键字参数         例: e, f
5. *args 或 * 分隔符          例: *args 或 *
6. 仅关键字参数（无默认值）    例: g
7. 仅关键字参数（有默认值）    例: h=10
8. **kwargs                  例: **kwargs
```

**注意**：第 2 组和第 4 组择一出现——如果使用了 `/`，那么 `/` 之前的参数（第 2 组）可以有默认值，`/` 和 `*` 之间的参数（第 4 组）是另一个区域。

#### 2.2.2 三条最高优先级的规则

**规则一：无默认值的参数不能出现在有默认值的参数之后**

```python
# ❌ 语法错误
# def func(a=1, b):    # SyntaxError
#     pass

# ✅ 正确
def func(a, b=1):
    pass
```

**规则二：`*args` 必须在所有普通位置参数之后**

```python
# ❌ 语法错误
# def func(*args, a):  # SyntaxError
#     pass

# ✅ 正确
def func(a, *args):
    pass
```

**规则三：`**kwargs` 必须位于形参列表末尾——没有例外**

这是 Python 中最严格的位置约束。

```python
# ❌ 语法错误
# def func(**kwargs, a):  # SyntaxError
#     pass

# ✅ 正确
def func(a, **kwargs):
    pass
```

**为什么？** 在调用时，Python 必须先确定每个位置实参的归属，然后才能处理关键字实参和 `**kwargs`。`**kwargs` 收集剩余关键字——如果它后面还有参数，解析顺序会无法确定。这是 Python 语法设计中最深层的约束之一。

这三条规则保证了 Python 在任何调用中都能**无歧义地**确定每个实参的归属。

#### 2.2.3 正确顺序的完整签名

```python
def full(a, b, /, c, d, *args, e, f=10, **kwargs):
    """
    参数分区：
      a, b   → / 之前 → 仅位置参数
      c, d   → / 和 *args 之间 → 位置或关键字
      *args  → 收集剩余位置实参
      e, f   → *args 之后 → 仅关键字参数
      **kwargs → 收集剩余关键字实参
    """
    pass


# e 在 *args 之后自动仅关键字，f=10 有默认值
# **kwargs 在最后——任何时候都是最后一个
```

### 2.3 调用侧的参数匹配规则

当函数被调用时，Python 按固定的优先级将实参匹配到形参。这个过程分为四步：

#### 2.3.1 步骤一：匹配仅位置参数

```text
调用 func(1, 2, c=3) 其中 func(a, b, /, c=10)
  ↓
从位置实参队列取出前 count(仅位置参数) 个：
  1 → a, 2 → b
```

仅位置参数只在位置实参队列中取，不参与关键字匹配。

#### 2.3.2 步骤二：匹配中间区参数

```text
剩余位置实参队列：[]（已空）
关键字实参队列：{c: 3}
  ↓
位置：无剩余 → 中间区参数的默认值保留
关键字：c=3 → 匹配到 c，覆盖默认值 10
```

中间区参数可以同时从位置队列和关键字队列中取值，位置优先。如果同一个参数同时通过位置和关键字传入，Python 会抛出 `TypeError: got multiple values`——参数来源必须唯一。

#### 2.3.3 步骤三：*args 和仅关键字参数

```text
检测到 *args → 但位置队列已空 → args=()
检测到仅关键字参数 → 只有 c 被匹配，其余用默认值或报错
```

#### 2.3.4 步骤四：安全检查

```text
- 每个参数只被赋值一次 ✅
- 所有必选参数都有值 ✅
- 没有位置参数被关键字重复赋值 ✅
```

#### 2.3.5 匹配规则完整示例

```python
def demo(a, b, /, c=10, d=20, *args, e, f=30, **kwargs):
    print(f"a={a}, b={b}, c={c}, d={d}, args={args}, e={e}, f={f}, kwargs={kwargs}")


# 调用1: 只传最少必要参数
demo(1, 2, e=5)
# a=1, b=2, c=10, d=20, args=(), e=5, f=30, kwargs={}

# 调用2: 位置覆盖所有默认值
demo(1, 2, 3, 4, 99, 100, e=5)
# a=1, b=2, c=3, d=4, args=(99, 100), e=5, f=30, kwargs={}

# 调用3: 混合关键字 + kwargs
demo(1, 2, c=3, e=5, f=6, extra="bonus")
# a=1, b=2, c=3, d=20, args=(), e=5, f=6, kwargs={'extra': 'bonus'}
```

每一步的绑定结果都严格遵守参数类型的约束——仅位置参数不接收关键字、仅关键字参数不接收位置、`*args` 收剩余位置、`**kwargs` 收剩余关键字。

### 2.4 参数类型选择原则

#### 2.4.1 选择普通位置/关键字参数

**适用场景**：
- 参数数量少（1-3 个）
- 参数语义明确，顺序不会造成歧义
- 数学/几何类运算中的坐标、长度等

**示例**：`def distance(x1, y1, x2, y2)`——四个坐标值天然排列，用位置参数最自然。

#### 2.4.2 选择仅位置参数（`/` 之前）

**适用场景**：
- 参数名不是 API 的语义组成部分
- 你希望保留改名的自由
- 模仿 C 扩展函数的调用习惯

**示例**：`def push(item, /)`——`item` 是唯一的数据源，名字对调用者来说不重要。Python 内置的 `len(obj, /)` 就是这种设计。

#### 2.4.3 选择仅关键字参数（`*` 之后）

**适用场景**：
- 参数是 bool 类型——调用处 `True`/`False` 无法自解释
- 多个可选配置项排列——调用者可能只想改其中一个
- 需要向后兼容地新增参数

**示例**：`def copy_file(src, dst, /, *, overwrite=False, chunk_size=8192)`——两个 bool 和配置项必须关键字传，防止出现 `copy_file("a", "b", True, 4096)` 这种不知所云的调用。

#### 2.4.4 选择 `*args` / `**kwargs`

**适用场景**：
- 参数数量在调用前无法确定
- 在装饰器中适配任意被装饰函数
- 需要透明转发参数

**示例**：`def log_call(func, *args, **kwargs)`——不关心 `func` 的签名，把参数原样转发。

#### 2.4.5 选择默认参数值

**适用场景**：
- 参数有一个"最适合大多数情况"的值
- 参数是可选配置

**注意**：默认值必须是不可变对象——用 `None` 哨兵模式替代可变默认值。

### 2.5 参数类型覆盖的完整图谱

将前九篇笔记的知识点压入一张图：

```text
Python 函数参数体系
│
├── 核心概念层
│   ├── 形参（定义侧占位符）vs 实参（调用侧实际值）
│   └── 传对象引用（不可变 vs 可变的行为差异）
│
├── 基础传递方式层
│   ├── 位置参数
│   │   └── 顺序决定含义，纯靠位置匹配
│   └── 关键字参数
│       └── 名称决定含义，顺序无关
│
├── 弹性机制层
│   ├── 默认参数值
│   │   ├── 定义时求值一次
│   │   ├── 可变默认值陷阱 → None 哨兵模式
│   │   └── 设计模式：合理默认、覆盖开关、级联默认
│   ├── *args（可变位置参数）
│   │   └── 收集剩余位置实参 → 元组
│   └── **kwargs（可变关键字参数）
│       └── 收集剩余关键字实参 → 字典
│
├── 解包层
│   ├── 调用侧 * ：可迭代对象 → 独立位置实参
│   └── 调用侧 ** ：字典 → 独立关键字实参
│
└── 约束层（Python 3.8+）
    ├── / 分隔符：之前 → 仅位置参数
    └── * 分隔符：之后 → 仅关键字参数
```

每一层建立在前一层之上——位置参数是基础、关键字参数是升级、默认值是简化、`*args`/`**kwargs` 是弹性、解包是互逆操作、约束是主动控制。

### 2.6 定义侧与调用侧的 `*` / `**` 对照

同一个符号在不同位置有完全不同的语义：

同一个符号在不同位置有完全不同的语义：

| 符号 | 定义侧（形参列表） | 调用侧（实参列表） |
|------|-----------------|-----------------|
| `*` | 收集：多个位置实参 → 一个元组 | 解包：一个可迭代对象 → 多个位置实参 |
| `**` | 收集：多个关键字实参 → 一个字典 | 解包：一个字典 → 多个关键字实参 |

```python
# 定义侧：收集
def collect(*args, **kwargs):
    return args, kwargs

# 调用侧：解包（往返验证）
data = [1, 2, 3]
config = {"name": "test"}
result = collect(*data, **config)
# result == ((1, 2, 3), {"name": "test"})  ← 精确往返
```

`*` 和 `**` 还有另外两种用法——赋值侧吸收和字面量展开：

```text
* 的四种身份：
  1. def func(*args)     → 定义侧收集
  2. func(*iterable)     → 调用侧解包
  3. first, *rest = seq  → 赋值侧吸收
  4. [1, *[2, 3], 4]   → 字面量展开（Python 3.5+）

** 的三种身份：
  1. def func(**kwargs)  → 定义侧收集
  2. func(**mapping)     → 调用侧解包
  3. {"a": 1, **{"b": 2}} → 字面量合并（Python 3.5+）
```

### 2.5 参数类型全覆盖的决策框架

设计函数签名时，以下决策框架可以帮你快速确定每个参数应该放在哪里：

```text
参数特征分析
  ↓
┌─────────────────────────────────────────────┐
│ 1. 参数名是否有语义价值？                     │
│    否 → / 之前（仅位置）                      │
│    是 → 继续判断                             │
│    例子：add(x, y) 的 x, y 无额外语义 → / 之前│
│          connect(host) 的 host 有语义 → 自由区│
├─────────────────────────────────────────────┤
│ 2. 参数数量不固定？                          │
│    位置不固定 → *args                        │
│    关键字不固定 → **kwargs                    │
│    固定 → 继续判断                           │
│    例子：sum(*numbers) → *args              │
│          dict(**kwargs) → **kwargs           │
├─────────────────────────────────────────────┤
│ 3. 参数是 bool 类型或有歧义的配置？            │
│    是 → * 之后（仅关键字）                    │
│    否 → 继续判断                             │
│    例子：copy(src, dst, *, overwrite=False)   │
│          中的 overwrite 必须是仅关键字        │
├─────────────────────────────────────────────┤
│ 4. 参数有没有合理的默认值？                   │
│    有 → 设为默认值                           │
│    没有 → 设为必选参数                        │
│    例子：timeout=30 合理，host 默认值不合理    │
├─────────────────────────────────────────────┤
│ 5. 参数的传递方式是否该强制约束？              │
│    是 → 用 / 或 * 约束                       │
│    否 → / 和 * 之间（自由区）                 │
│    例子：len(obj, /)   sorted(iterable, /, *) │
└─────────────────────────────────────────────┘
```

这个决策框架可以进一步用两个经典案例说明。

**案例一：设计文件复制函数**

```python
# 需求：复制文件，源/目标路径必选，是否覆盖可选，块大小可选
# 
# 决策过程：
# 1. source, destination 有意义 → 不在 / 之前（放在自由区）
#    但两者都是路径字符串，位置搞反了不报错 → 考虑仅位置
#    最终方案：/ 之前（仅位置）——两个字符串参数，位置颠倒的风险
#    可以通过仅位置约束让调用处更简洁
# 2. overwrite 是 bool → * 之后（仅关键字）
# 3. chunk_size 有合理默认值 8192 → 默认值
#
# 最终签名：

def copy_file(source, destination, /, *, overwrite=False, chunk_size=8192):
    ...
```

**案例二：设计网络请求函数**

```python
# 需求：发送 HTTP 请求，method/url 必选，headers/timeout 可选
#
# 决策过程：
# 1. method, url 是核心标识，但参数名有意义 → 自由区或仅位置
#    这两个参数不容易搞混（GET/POST vs url 完全不同）→ 自由区即可
# 2. headers, timeout, retries 都是可选配置 → 默认值 + 仅关键字
# 3. 多余的关键字参数（如 query params）→ **kwargs
#
# 最终签名：

def request(method, url, *, headers=None, timeout=30,
            retries=0, **params):
    ...
```

## 3. 实践示例

### 3.1 综合案例：ORM 风格的查询构建器

```python
class QueryBuilder:
    """展示参数全景设计的完整案例"""

    def select(self, table, /, *columns):
        """table 仅位置（语义自明），columns 数量可变"""
        ...

    def where(self, condition, /, **params):
        """condition 仅位置，过滤参数通过 **params"""
        ...

    def order_by(self, *fields):
        """可变数量的排序字段——*args 最佳"""
        ...

    def limit(self, n, /, *, offset=0):
        """n 仅位置，offset 仅关键字（清除歧义）"""
        ...

    def execute(self, *, dry_run=False, explain=False):
        """所有选项必须关键字——bool 不能裸传"""
        ...
```

每个方法的参数类型都根据参数的**语义特征**来选择——这正是参数设计全景的核心要义。这个案例中的设计分析：

| 方法 | 参数类型选择 | 原因 |
|------|------------|------|
| `select(table, /, *columns)` | table 仅位置 + *args | table 是核心数据源，名无额外语义；columns 不固定 |
| `where(condition, /, **params)` | condition 仅位置 + **kwargs | 过滤条件灵活多变 |
| `order_by(*fields)` | *args | 字段数量不固定 |
| `limit(n, /, *, offset=0)` | n 仅位置，offset 仅关键字 | offset 是可选配置，关键字消除歧义 |
| `execute(*, dry_run, explain)` | 全部仅关键字 | bool 不能裸传 |

### 3.2 综合案例：事件系统

```python
class EventBus:
    def on(self, event_type, /, *, priority=0, once=False):
        """event_type 仅位置——事件名是核心标识
           priority 和 once 仅关键字——配置项必须明确"""

    def emit(self, event_type, /, *args, **kwargs):
        """event_type 仅位置——事件名是触发目标
           *args, **kwargs 原样转发给处理器"""
```

`on` 的 `event_type` 是最核心的标识——用仅位置参数最自然。`emit` 通过 `*args, **kwargs` 将所有参数原样转发给每个事件处理器，完全不需要知道处理器的签名。

### 3.3 参数设计速查表

这是在所有笔记基础上总结的设计决策速查表：

| 场景 | 推荐方案 | 原因 |
|------|---------|------|
| 单参数、无歧义 | 普通位置参数 | `add(x, y)` 最自然 |
| 参数 ≥ 4 个 | 考虑 `*` 或 `**kwargs` | 减少位置搞混的风险 |
| bool 参数 | 仅关键字（`*` 之后） | `True`/`False` 无法自解释 |
| 参数名不重要 | 仅位置（`/` 之前） | `pow(2, 10)` 比 `pow(x=2)` 自然 |
| 数量不固定 | `*args` 或 `**kwargs` | `sum(*numbers)` |
| API 向下兼容 | 新参数放 `*` 之后 | 已有调用不受影响 |
| 可变默认值 | None 哨兵模式 | 避免可变默认值陷阱 |
| 装饰器/代理 | `*args, **kwargs` | 适配任意被包装函数 |
| 子类化 | `**kwargs` 链式传递 | `super().__init__(**kwargs)` |
| 配置合并 | 调用侧 `**` 解包 | `func(**merged_config)` |

## 4. 常见误区与边界

**误区一：以为 `/` 和 `*` 分隔符是 Python 很久以前就有的特性**

`/` 是 Python 3.8（2019 年）引入的，在此之前只能用 `*` 和 `*args` 做分割。`*` 分隔符在 Python 3.0 就已存在。

**误区二：用 `*` 分隔符后还在前面放另一个 `*`**

```python
# ❌ 语法错误
# def func(*args, *, a):  # SyntaxError: 不能有两个 * 分隔符
#     pass

# ✅ *args 本身已经起到了 * 分隔符的作用
def func(*args, a):  # a 在 *args 之后自动成为仅关键字
    pass
```

**误区三：忘记了 `/` 和 `*` 左侧参数的默认值规则**

```python
# ⚠️ 微妙情况
def func(a, b=1, /, c=2, d=3):
    # a 和 b 在 / 之前，b 有默认值——这是合法的（Python 3.8+）
    # 但调用时 func(1) 就够了——a=1, b=1(默认), c=2(默认), d=3(默认)
    pass
```

`/` 之前的仅位置参数可以有默认值——注意不要把它和"默认值参数必须在无默认值参数之后"的规则混淆。

**误区四：过度使用 / 和 *——把自由区变成禁区**

```python
# ❌ 过度约束
def calc(*, x, y):       # 加个 x, y 两个坐标还要用关键字传
    ...

# ✅ 合理
def calc(x, y):          # 坐标天然有顺序，位置足够了
    ...
```

**误区五：只有定义自己的函数时才考虑参数签名设计**

实际上你在使用任何 Python 库时都在间接感受参数设计的好坏。阅读 `help(len)`、`help(sorted)` 的输出，学习 Python 标准库如何设计参数签名，是提升设计品味最直接的方法。

**误区六：参数签名设计是一次性的**

好的 API 签名经过多次迭代。随着使用场景的明确，你可能需要用 `*` 来约束新出现的 bool 参数、用 `/` 来保护内部实现细节。参数签名应该是持续演化的。

**误区七：学习完所有参数类型后，认为每个函数都需要用到全部类型**

实际上绝大多数函数的签名只需要其中 2-3 种参数类型。一个典型的 Python 函数签名可能只是：

```python
def process(data, *, verbose=False, timeout=30):
    ...
```

三个参数、一种分隔符——已经覆盖了大部分实际需求。全景图是给你一张"地图"，不是要你每次出行都走遍所有道路。

## 5. 总结

本文作为 Python 函数参数系列的收尾篇，系统梳理了参数类型的全景分类、形参列表的严格顺序规则、调用侧的匹配优先级，以及参数设计的决策框架。以下是本系列笔记的完整知识脉络：

- Python 形参共六种类型，按顺序分为三个区域：仅位置区（`/` 之前）、自由区（`/` 和 `*` 之间）、仅关键字区（`*` 之后），加上 `*args` 和 `**kwargs` 两个弹性收集器
- 形参列表有严格排列顺序：无默认值 → 默认值 → `/` → 普通参数 → `*args`/`*` → 仅关键字 → `**kwargs`。任何违反此顺序的定义都会引发 SyntaxError
- 调用侧匹配分为四步：仅位置参数 → 中间区参数 → `*args`/仅关键字参数 → `**kwargs`。每步都受到参数类型约束的保护，确保参数归属无歧义
- `*` 在 Python 中有四种身份：定义侧收集（`def f(*args)`）、调用侧解包（`f(*iterable)`）、赋值侧吸收（`first, *rest = seq`）、字面量展开（`[1, *[2, 3]]`）；`**` 有对应的三种身份
- 参数设计的核心原则：将核心数据参数放在仅位置或自由区，将 bool 和配置参数放在仅关键字区，将可变数量的参数交给 `*args` 和 `**kwargs`，将"最常见值"设为默认值
- 本系列十篇笔记覆盖了 Python 函数参数的完整体系——从形参与实参的本质（01），到位置参数（02）、关键字参数（03）、默认参数值（04）、可变默认陷阱（05）、`*args`（06）、`**kwargs`（07）、调用侧解包（08），再到 `/` 和 `*` 的参数约束（09），最后回到本篇的全景总结（10），为设计和理解任意复杂度的函数签名打下了坚实基础
- 最重要的收获不是记住每个语法点，而是建立参数设计的思维方式：拿到一个函数需求，能本能地判断每个参数应该放在哪个位置、是否需要默认值、是否需要传递方式约束
