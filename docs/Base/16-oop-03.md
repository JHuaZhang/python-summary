## 1. 介绍

### 1.1 什么是实例属性动态添加

在大多数静态语言（如 Java、C++）里，一个对象能拥有哪些属性，在类定义那一刻就由字段声明钉死了。你写了 `class Person { String name; int age; }`，那么每个 `Person` 实例就只能有 `name` 和 `age`，想在运行时给它临时塞一个 `nickname` 字段，编译器直接报错。

Python 不一样。Python 的类定义里写的 `self.xxx = yyy` 只是"建议"实例拥有哪些属性，并非一份不可逾越的契约。只要实例对象已经创建（即已经调用了 `__init__`、对象在内存中成形），你就可以在代码的任何角落，用赋值语句给这个实例凭空加一个全新的属性：

```python
class Person:
    def __init__(self, name):
        self.name = name

p = Person("张三")
# p 此时只有 name 一个属性

# 运行时凭空加一个属性
p.nickname = "老张"
print(p.nickname)
# 输出：老张
```

这就是"实例属性动态添加"——在对象创建之后，通过 `obj.新属性名 = 值` 的赋值语法，给单个实例对象挂载一个原本在类定义里并不存在的属性。这个属性一旦赋值，就像普通属性一样可以通过 `obj.新属性名` 读取、修改、删除（`del obj.新属性名`）。

需要强调几个关键点，这些也是后续章节展开的线索：

- **动态添加的属性只属于被操作的那个实例，不会"传染"给同类的其他实例**。上面的 `p.nickname = "老张"` 只对 `p` 生效，另建一个 `p2 = Person("李四")`，`p2` 没有 `nickname`，访问会抛 `AttributeError`。
- **实例属性存储在实例自己的 `__dict__` 字典里**。动态添加属性，本质上就是往这个字典里塞了一个键值对。这个字典是普通的 `dict`，可以随意加键。
- **动态属性带来灵活性，也带来风险**：拼写错了不报错（`p.nikname` 写成 `p.nikename` 只会悄悄新建一个属性）、属性集不统一导致可读性下降、大量临时属性增加内存负担。
- **可以用 `__slots__` 关掉动态添加**：在类里定义 `__slots__ = ("name", "age")`，实例就被限定只能拥有这两个属性，再 `obj.xxx = ...` 就会抛 `AttributeError`。
- **动态添加方法不一样**：给实例绑定一个普通函数后，直接 `obj.func()` 调用并不会自动传 `self`，需要用 `types.MethodType` 把函数包装成绑定方法（bound method）才行。

这些就是本文要讲透的内容。

### 1.2 基础语法与最小用法

动态添加实例属性的最小语法就是一句赋值：

```python
obj.新属性名 = 值
```

它的语义极其直白：把"新属性名"这个键和"值"这个对象,写进 `obj` 自己的 `__dict__` 字典。如果这个键已经存在，就是修改；如果不存在，就是新增。

一个完整的最小示例，演示"创建实例 → 动态加属性 → 读取 → 删除"全过程：

```python
class Product:
    def __init__(self, title, price):
        self.title = title
        self.price = price

prod = Product("机械键盘", 399)
# 初始只有 title、price
print(prod.__dict__)
# 输出：{'title': '机械键盘', 'price': 399}

# 动态添加一个属性
prod.stock = 50
print(prod.__dict__)
# 输出：{'title': '机械键盘', 'price': 399, 'stock': 50}

# 读取动态属性，和普通属性没区别
print(prod.stock)
# 输出：50

# 修改动态属性
prod.stock = 30
print(prod.stock)
# 输出：30

# 删除动态属性
del prod.stock
print(prod.__dict__)
# 输出：{'title': '机械键盘', 'price': 399}
```

从这个示例可以看到，动态添加的属性在读写、删除上与 `__init__` 里设置的"常规"属性没有任何语法差异。唯一区别只在于"什么时候、在哪里加的"——`__init__` 里加的属性遵循类定义的约定，而动态添加的属性是代码运行过程中临时挂上去的。

这也是为什么 Python 程序员常说"Python 的对象本质是一个带 `__dict__` 的命名空间"：你对 `obj.x` 的一切操作，底层就是在操作 `obj.__dict__["x"]`。

## 2. 核心内容

### 2.1 给实例动态添加普通属性

**作用与场景**

给实例动态添加属性，最常见的场景是"这个实例在当前业务流程中需要一个临时的、只对它自己有意义的状态字段，但你不希望也不需要把这个字段写进类定义"。

典型情况包括：

- 给某个对象挂一个临时缓存属性，避免重复计算。
- 在处理完一条数据后，给记录对象打个标记（如 `_processed = True`），便于后续筛选。
- 对象从接口/配置反序列化而来，结构里带了些额外字段，你不想为这些边角字段去改类定义。
- 调试时临时把中间结果挂在对象上，方便后续断点查看。

**基本用法**

```python
class Order:
    def __init__(self, order_id, amount):
        self.order_id = order_id
        self.amount = amount

order = Order("A001", 200.0)

# 场景：给这个订单临时挂一个"已优惠金额"
order.discounted = 180.0
print(order.discounted)
# 输出：180.0

# 场景：给单个订单挂一个临时标记，表示这条订单走的是特殊审批通道
order._special_channel = True

if getattr(order, "_special_channel", False):
    print(f"订单 {order.order_id} 走特殊审批")
# 输出：订单 A001 走特殊审批
```

注意第二个场景里的写法：因为不是所有 `Order` 实例都会有 `_special_channel`（只有被动态赋值的那个才有），所以在读取时要用 `getattr(order, "_special_channel", False)` 给个默认值，避免没加过这个属性的实例抛 `AttributeError`。这是动态属性编程中非常常用的防御性写法。

**与初始化时赋值的对比**

很多人第一次接触动态属性会疑惑：`__init__` 里写的 `self.xxx = yyy` 和在外面写的 `obj.xxx = yyy` 有什么本质区别？

答案是：**语法上完全没区别，都是给 `obj.__dict__` 加键值对；区别只在约定和时机**。

```python
class Order:
    def __init__(self, order_id, amount):
        # 这里的 self.xxx = yyy 也是"动态给实例加属性"
        self.order_id = order_id
        self.amount = amount

order = Order("A002", 99.0)
# 这里同样是"动态给实例加属性"，只是发生在对象创建之后
order.coupon = "NEW10"
```

`__init__` 里写的 `self.order_id = ...`，本质也是动态给刚创建的 `order` 对象加属性——Python 没有"字段声明"这一步，类定义里不会预先列出合法属性清单（除非用了 `__slots__`）。`__init__` 只是被 Python 约定为"对象初始化的统一入口"，所以大家都习惯在这里集中加属性，但这不意味着外面加的属性性质有什么不同。

**动态属性不影响 __init__ 的常规属性**

动态添加新属性不会影响实例已有的、在 `__init__` 里设置的属性：

```python
class Order:
    def __init__(self, order_id, amount):
        self.order_id = order_id
        self.amount = amount

order = Order("A003", 100.0)
order.note = "加急"

print(order.order_id, order.amount, order.note)
# 输出：A003 100.0 加急
```

新增的 `note` 和原有的 `order_id`、`amount` 在 `__dict__` 里平等共存：

```python
print(order.__dict__)
# 输出：{'order_id': 'A003', 'amount': 100.0, 'note': '加急'}
```

### 2.2 实例属性存于实例 __dict__

要真正理解动态属性，必须搞懂 `__dict__`。

**__dict__ 是什么**

每个普通类的实例对象，内部都持有一个 `dict`（字典），名字叫 `__dict__`，它就是这个实例所有实例属性的存储仓库。当你写 `self.x = 1` 或 `obj.x = 1`，Python 实际上是在 `obj.__dict__["x"] = 1`；当你读 `obj.x`，Python 先在 `obj.__dict__` 里找 `"x"` 这个键。

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(3, 4)

# 直接查看实例的 __dict__
print(p.__dict__)
# 输出：{'x': 3, 'y': 4}
```

**动态添加 == 往 __dict__ 加键**

既然实例属性就是 `__dict__` 里的键值对，那么"动态添加属性"就只是"往这个字典里加一个新键"：

```python
p.z = 5
print(p.__dict__)
# 输出：{'x': 3, 'y': 4, 'z': 5}

# 甚至可以直接操作 __dict__（不推荐，但能验证原理）
p.__dict__["color"] = "red"
print(p.color)
# 输出：red
print(p.__dict__)
# 输出：{'x': 3, 'y': 4, 'z': 5, 'color': 'red'}
```

上面 `p.__dict__["color"] = "red"` 这种直接操作字典的写法，和 `p.color = "red"` 的效果完全等价（在普通类上）。这进一步说明动态属性的本质就是字典操作。

**__dict__ 是普通字典**

关键的一点：实例的 `__dict__` 不是什么特殊容器，它就是一个标准的 `dict`，你熟悉的字典操作都能用：

```python
class Box:
    pass

b = Box()
b.a = 1
b.b = 2

# 拿到它的类型
print(type(b.__dict__))
# 输出：<class 'dict'>

# 可以用 keys / values / items
print(list(b.__dict__.keys()))
# 输出：['a', 'b']

print(list(b.__dict__.items()))
# 输出：[('a', 1), ('b', 2)]

# 可以用 in 判断是否存在该属性
print("a" in b.__dict__)
# 输出：True

print("c" in b.__dict__)
# 输出：False
```

既然是个普通字典，那当然可以"随意加键"——只要键是合法的字符串。这就是 Python 允许动态加属性的根本原因：存属性这件事没有用一张预先声明的字段表，而是用一个可以随时增删的字典。

**类也有 __dict__，但和实例 __dict__ 是两个东西**

容易混淆的一点：类本身也有 `__dict__`，里面存的是类的方法、类属性等。实例的 `__dict__` 只存这个实例自己的属性，两者是分离的：

```python
class Point:
    default_color = "black"   # 类属性
    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)

# 实例 __dict__：只有实例属性
print(p.__dict__)
# 输出：{'x': 1, 'y': 2}

# 类 __dict__：包含类属性、方法等
print("default_color" in Point.__dict__)
# 输出：True
print("default_color" in p.__dict__)
# 输出：False
```

`default_color` 是类属性，存在 `Point.__dict__` 里，不在 `p.__dict__` 里。当访问 `p.default_color` 时，Python 先找 `p.__dict__` 没有，再去找 `Point.__dict__`，找到了。这就是"实例属性查找优先于类属性"的来源，原理章会详述。

### 2.3 不同实例可有不同属性集

因为动态属性只影响被操作的那个实例，所以**同一个类的不同实例，可以拥有完全不同的属性集合**。这是 Python 和静态语言的一个显著差异。

```python
class Config:
    def __init__(self, env):
        self.env = env

# 实例 A：生产环境，需要加一个 request_timeout 属性
prod = Config("production")
prod.request_timeout = 30
prod.retry_times = 3

# 实例 B：测试环境，加不同的属性
test = Config("test")
test.mock_mode = True

print(prod.__dict__)
# 输出：{'env': 'production', 'request_timeout': 30, 'retry_times': 3}

print(test.__dict__)
# 输出：{'env': 'test', 'mock_mode': True}
```

`prod` 有 `request_timeout`、`retry_times`，`test` 有 `mock_mode`，互不影响。试图在 `test` 上读 `request_timeout` 会报错：

```python
print(test.request_timeout)
# 输出：AttributeError: 'Config' object has no attribute 'request_timeout'
```

**这种"异构实例"带来的两面性**

一方面，这种灵活性很有用。比如你在遍历一堆日志记录对象，只想给其中命中某种条件的记录临时挂一个 `_alert` 标记，没必要为了这一个标记去改类的 `__init__` 让所有实例都带上这个字段。

另一方面，这种灵活性也很危险。如果代码里大量依赖动态属性，就会出现"这个实例有没有这个属性"完全无法从类定义推断的情况，必须追到每一处赋值点才能知道一个实例到底能有哪些属性。可读性、可维护性会迅速下降。

```python
# 反面例子：大量动态属性，别人读代码时根本不知道一个实例有什么
class Record:
    pass

rec = Record()
rec.id = 1
rec.title = "某记录"
rec.status = "open"
rec.assignee = "张三"
rec.created_at = "2026-07-23"
rec.priority = "high"
# 如果数百行代码里散落着这种动态赋值，后来的维护者会很崩溃
```

所以工程实践中，**常规属性一定要写进 `__init__`**，动态属性只用于"确实临时、确实只针对个别实例"的场景。

### 2.4 动态添加方法（types.MethodType）

前面讲的动态添加的都是数据属性。有时候你会想给某个实例动态挂一个"方法"——能通过 `obj.xxx()` 调用、调用时自动把 `obj` 作为第一个参数（`self`）传进去。

**直接赋值普通函数的问题**

先看一个直觉但错误的写法：定义一个普通函数，赋给实例的属性，然后调用。

```python
class Person:
    def __init__(self, name):
        self.name = name

def greet(self, greeting):
    return f"{greeting}, 我是 {self.name}"

p = Person("张三")

# 直接把函数对象赋给实例属性
p.greet = greet

# 调用
print(p.greet("你好"))
# 输出：TypeError: greet() missing 1 required positional argument: 'greeting'
```

为什么报错？因为 `p.greet` 现在只是一个普通的函数对象，通过 `p.greet(...)` 调用时，Python **不会**自动把 `p` 作为 `self` 传进去。所以 `"你好"` 传给了 `self` 参数，`greeting` 参数没人传，于是报"缺少参数"。

换句话说，赋值给实例属性的函数，只是被当成普通的数据属性存起来，并没有被识别为"方法"。

**正确做法：用 types.MethodType 绑定**

要让一个函数挂到实例上后表现得像方法（调用时自动传 `self`），需要用 `types.MethodType` 把函数和实例绑定，制造一个"绑定方法"（bound method）：

```python
import types

class Person:
    def __init__(self, name):
        self.name = name

def greet(self, greeting):
    return f"{greeting}, 我是 {self.name}"

p = Person("张三")

# 用 MethodType 把 greet 函数绑定到 p 这个实例
p.greet = types.MethodType(greet, p)

# 现在调用，self 会自动传成 p
print(p.greet("你好"))
# 输出：你好, 我是 张三
```

`types.MethodType(函数, 实例)` 做的事情是：返回一个绑定方法对象，这个对象记住了"自己是绑定到哪个实例的"。调用它时，它会自动把记住的实例作为第一个参数（也就是 `self`）传给函数。

**只对被绑定的那个实例生效**

和动态属性一样，动态绑定的方法也只对被绑定的那个实例生效：

```python
p2 = Person("李四")

# p2 没有 greet 方法，因为只给 p 绑了
try:
    p2.greet("你好")
except AttributeError as e:
    print(e)
# 输出：'Person' object has no attribute 'greet'
```

如果想给所有实例都加上这个方法，正确做法是把函数定义到类里去（`Person.greet = greet`），而不是一个个 `MethodType` 绑。后面会讲两者的区别。

**类上赋值函数 vs 实例上绑定 MethodType 的区别**

这是一个常被混淆的点，值得展开：

```python
class Person:
    def __init__(self, name):
        self.name = name

def greet(self, greeting):
    return f"{greeting}, 我是 {self.name}"

# 方式 A：把函数挂到类上
Person.greet = greet

# 方式 B：把函数绑到单个实例上
import types
p = Person("张三")
p.greet2 = types.MethodType(greet, p)
```

- **方式 A（挂到类上）**：`greet` 进入 `Person.__dict__`，所有 `Person` 实例访问 `obj.greet` 时，Python 的属性查找机制会发现这是个函数对象，于是自动把它包装成绑定方法（绑定到当前访问的实例）。所以所有实例都能用、都会自动传 `self`。
- **方式 B（绑到实例上）**：`greet` 不进类字典，而是以 `MethodType` 对象的形式存进 `p.__dict__`。只有 `p` 自己有，别的实例没有。访问 `p.greet2` 时直接拿到这个已经绑好的 `MethodType` 对象，调用即自动传 `p`。

这两种方式的本质差异：**类上挂函数是依赖描述符协议在访问时动态包装；实例上绑 MethodType 是预先把函数和实例绑死成一个对象存起来**。原理章会详述。

**给单个实例绑定方法的实际场景**

实际开发中，给单个实例绑方法的场景不算特别常见，但在以下情况会用到：

- 协议/接口适配：某个对象需要临时具备一个方法以满足某个协议（如具备 `close` 方法才能被 `with` 接受），但你不想改类。
- 策略模式：根据运行时条件，给某个实例挂上不同的行为函数作为方法。
- 测试/调试中给某个对象临时补一个桩方法。

```python
# 场景：根据配置给某个 worker 实例绑定不同的处理逻辑
import types

class Worker:
    def __init__(self, name):
        self.name = name

def fast_handle(self, task):
    return f"[{self.name}] 快速处理: {task}"

def slow_handle(self, task):
    return f"[{self.name}] 慢速处理: {task}（带日志）"

worker = Worker("W1")

# 运行时根据配置决定绑哪个
use_fast = True
if use_fast:
    worker.handle = types.MethodType(fast_handle, worker)
else:
    worker.handle = types.MethodType(slow_handle, worker)

print(worker.handle("任务1"))
# 输出：[W1] 快速处理: 任务1
```

### 2.5 与类属性的区别（简提）

实例属性和类属性是两回事，这里简提区别，详细对比放到第 04 篇「类属性与实例属性」。

**存储位置不同**

- 类属性：存在类的 `__dict__` 里（如 `Point.__dict__`），所有实例共享一份。
- 实例属性：存在每个实例自己的 `__dict__` 里，各实例独立。

**动态添加时的作用范围不同**

- `obj.x = v`：只给这一个实例加属性，别的实例没有。
- `Cls.x = v`：给类加属性，所有实例都能通过 `obj.x` 访问到（只要实例自己没有同名属性遮蔽）。

```python
class Dog:
    pass

# 给类加属性
Dog.species = "Canis lupus"

d1 = Dog()
d2 = Dog()

# 所有实例都能读到
print(d1.species, d2.species)
# 输出：Canis lupus Canis lupus

# 给单个实例加属性
d1.name = "旺财"

print(d1.name)
# 输出：旺财

print(d2.name)
# 输出：AttributeError: 'Dog' object has no attribute 'name'
```

**同名时实例属性遮蔽类属性**

当实例自己有同名属性时，`obj.x` 会先找到实例的，类属性被"遮蔽"但不被修改：

```python
class Dog:
    species = "犬科"

d = Dog()
# 通过实例读到的先是类属性
print(d.species)
# 输出：犬科

# 给实例加同名属性
d.species = "哈士奇"
print(d.species)
# 输出：哈士奇
print(Dog.species)
# 输出：犬科  ← 类属性没变，只是被实例属性遮蔽了
```

这部分是理解属性查找链的关键，原理章会详细展开。

### 2.6 用 __slots__ 限制可加属性

**__slots__ 是什么**

如果你不希望实例被随意加动态属性——想让类表现得"规矩一点"，像静态语言那样只允许预定义的属性——可以在类里定义 `__slots__`。

`__slots__` 是一个类属性，通常赋一个字符串元组，列出这个类的实例允许拥有的全部属性名：

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p.x, p.y)
# 输出：1 2

# 试图加一个不在 slots 里的属性
p.color = "red"
# 输出：AttributeError: 'Point' object has no attribute 'color'
```

一旦定义了 `__slots__`，实例就不再有 `__dict__`（默认情况下），也就没法再随手加属性了。所有合法属性都必须在 `__slots__` 里声明。

**__slots__ 的附带好处：省内存**

因为 `__slots__` 让实例不再背一个 `dict`（字典本身是个相对占内存的数据结构），大量实例时能显著省内存：

```python
import sys

class WithDict:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class WithSlots:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y

a = WithDict(1, 2)
b = WithSlots(1, 2)

# 有 __dict__ 的实例可以查看 __dict__
print(a.__dict__)
# 输出：{'x': 1, 'y': 2}

# 有 __slots__ 的实例没有 __dict__
try:
    print(b.__dict__)
except AttributeError as e:
    print(e)
# 输出：'WithSlots' object has no attribute '__dict__'

# 体积对比（近似，具体数值受 Python 版本影响）
print(sys.getsizeof(a))   # 通常较大
print(sys.getsizeof(b))   # 通常较小
# 输出（示例）：
# 152
# 48
```

当实例数量达到百万级（如解析一个大 CSV 得到一百万个记录对象），`__slots__` 带来的内存节省非常可观，这是它除"限制属性"之外被广泛使用的另一原因。

**__slots__ 不能完全阻止动态属性**

需要注意，`__slots__` 并不能 100% 关死"加属性"的口子——如果类里有 `"__dict__"` 这个字符串作为 slots 成员，实例依然会有 `__dict__`，依然能加任意属性：

```python
class Loose:
    __slots__ = ("x", "__dict__")
    def __init__(self, x):
        self.x = x

obj = Loose(1)
obj.anything = 99   # 不报错，因为有 __dict__
print(obj.anything)
# 输出：99
```

这种写法少用，但要知道它的存在，避免"以为加了 __slots__ 就绝对安全"的误解。

**继承时的 __slots__ 行为**

子类如果没有自己定义 `__slots__`，会继承父类的限制吗？不会——子类如果没有自己的 `__slots__`，默认会有 `__dict__`，就能加任意属性：

```python
class Base:
    __slots__ = ("x",)

class Child(Base):
    pass   # 没定义 __slots__

c = Child()
c.x = 1   # 合法
c.y = 2   # 也合法！因为 Child 没有 __slots__，有 __dict__
print(c.y)
# 输出：2
```

要让子类也受限，子类必须自己定义 `__slots__`（即使为空元组）：

```python
class Child2(Base):
    __slots__ = ()   # 显式定义，不新增允许属性

c2 = Child2()
c2.x = 1   # 合法（继承自父类 slots）
try:
    c2.y = 2
except AttributeError as e:
    print(e)
# 输出：'Child2' object has no attribute 'y'
```

**什么时候用 __slots__**

- 大量实例、内存敏感的场景（解析大数据集、游戏里海量实体对象）。
- 希望用类的定义明确"这个类的实例就该有这些属性"，避免团队成员胡乱加属性导致实例结构漂移。
- 不建议在所有类上一律加 `__slots__`，因为它会牺牲一些灵活性（不能用 `__dict__` 做反射、和某些序列化库不兼容、多继承时和描述符协作复杂），只在确有收益时用。

### 2.7 动态属性的适用场景

把前面零散提到的场景汇总一下，并给出更具体的例子。

**场景一：给单个实例加临时缓存属性**

```python
class Query:
    def __init__(self, sql):
        self.sql = sql

    def run(self, db):
        # 假设执行开销较大
        result = db.execute(self.sql)
        # 把结果缓存在实例上，避免重复执行
        self._cached_result = result
        return result

q = Query("SELECT * FROM users")
# 第一次执行
q.run(db)
# 后续直接读缓存
print(q._cached_result)
```

这种用法要注意：缓存属性一般用下划线前缀（`_cached_result`）表示"内部使用、外部别依赖"，并且要在文档或注释里说明，否则后来者看到 `q._cached_result` 会一头雾水。

**场景二：反序列化/动态结构**

```python
class Record:
    def __init__(self, **kwargs):
        # 把传入的键值对都设为实例属性
        for k, v in kwargs.items():
            setattr(self, k, v)

rec = Record(id=1, title="标题", tags=["a", "b"])
print(rec.id, rec.title, rec.tags)
# 输出：1 标题 ['a', 'b']
print(rec.__dict__)
# 输出：{'id': 1, 'title': '标题', 'tags': ['a', 'b']}
```

这里用 `setattr` 动态加属性，适合"字段不固定、来自外部数据"的对象。但要注意这相当于放弃了类型约束，字段名拼错不会报错，只能靠运行时 `getattr` 默认值来兜底。

**场景三：调试/中间状态**

```python
class Pipeline:
    def __init__(self, name):
        self.name = name

    def process(self, data):
        # 调试时把中间结果挂在实例上，方便断点查看
        self._debug_intermediate = data.copy()
        # ... 实际处理 ...
        return result
```

这种用法仅限开发调试，上线前应该删掉，避免遗留临时属性。

**场景四：策略/协议适配（配合 MethodType）**

前面 2.4 已经给过给单个实例绑方法的例子，这里不再重复。

### 2.8 动态属性的坑

动态属性灵活，但坑也不少，重点列出以下几个。

**坑一：拼写错误不报错**

这是动态属性最经典也最隐蔽的坑。你原本想给实例加 `nickname`，手一滑写成了 `nikname`，Python 不会报错——它会乖乖给你新建一个 `nikname` 属性。等你后面去读 `p.nickname` 时，又报 `AttributeError`，但你得花半天才能定位到是赋值时拼错了。

```python
class User:
    def __init__(self, name):
        self.name = name

u = User("张三")
# 想设 nickname，拼错了
u.nikname = "老张"   # 悄悄建了一个错误名字的属性
print(u.__dict__)
# 输出：{'name': '张三', 'nikname': '老张'}

# 后续试图读正确的名字
try:
    print(u.nickname)
except AttributeError as e:
    print(e)
# 输出：'User' object has no attribute 'nickname'
```

规避方式：

- 常规属性都写进 `__init__`，用类定义约束属性名。
- 对属性集要求严格的类用 `__slots__`。
- 读取动态属性时优先用 `getattr(obj, name, default)` 给默认值。
- 配合类型检查工具（如 mypy 用 `dataclass`）在开发期捕获拼写错误。

**坑二：实例属性集不统一，可读性下降**

一旦动态属性被滥用，不同实例拥有的属性集合就不再一致，读代码的人无法从类定义推断"这个实例有什么属性"。这会严重拖累可维护性。

```python
# 反面例子
class Task:
    pass

t1 = Task()
t1.id = 1
t1.title = "任务一"
t1.owner = "张三"

t2 = Task()
t2.id = 2
t2.title = "任务二"
# t2 没有 owner，是故意没有还是忘了？
```

规避方式：**核心、稳定的属性一定要写进 `__init__`**，动态属性只用于确实临时、确实只针对个别实例的情况。

**坑三：内存负担**

每个动态属性都占实例 `__dict__` 里一个键值对的位置。如果一个类有几百万实例，每个实例都额外挂了几个本来可以不要的动态属性，内存浪费可观。

```python
# 反面例子：大量实例 + 不必要的动态属性
class Row:
    pass

rows = []
for i in range(1_000_000):
    r = Row()
    r.id = i
    r.value = i * 2
    r.tag = "x"   # 每个实例都背上 tag
    rows.append(r)
# 这种情况下应该用 __slots__ 或 dataclass(slots=True)，省内存且规范
```

规避方式：大量实例场景用 `__slots__`（或 Python 3.10+ 的 `@dataclass(slots=True)`）。

**坑四：删除动态属性的副作用**

`del obj.x` 删除动态属性后，后续访问会抛 `AttributeError`，如果别处代码依赖这个属性，就会突然崩。要确保删属性前没有其他地方还在用它：

```python
class Holder:
    pass

h = Holder()
h.flag = True

# 某处
def check(h):
    if getattr(h, "flag", False):
        print("flag 开着")

check(h)
# 输出：flag 开着

del h.flag
check(h)
# 没报错但逻辑变了——现在认为 flag 没开
```

**坑五：和类属性同名时遮蔽**

如果类里有一个类属性 `x`，你在实例上 `obj.x = v` 动态加同名属性，不会修改类属性，而是给实例 `__dict__` 加一个键 `x`，从此 `obj.x` 读到的是实例属性，遮蔽了类属性。别的实例读 `x` 还是读类属性。这种"看起来改了、其实只改了自己一个"的行为很容易让人误判：

```python
class C:
    counter = 0

c1 = C()
c2 = C()

c1.counter = 5
print(c1.counter)   # 实例属性遮蔽
# 输出：5
print(c2.counter)   # 还是读类属性
# 输出：0
print(C.counter)    # 类属性没变
# 输出：0
```

想改类属性应该直接 `C.counter = 5`，而不是通过实例去赋值。

**坑六：可变默认值通过动态属性共享?**

其实不共享——动态属性只属于一个实例，不存在多实例共享问题。但有一个相关误区：有人以为把同一个可变对象赋给多个实例的动态属性会"共享"，其实不会，因为每个 `obj.x = [...]` 是独立的赋值。共享只发生在类属性层面：

```python
class C:
    pass

a = C()
b = C()
a.items = [1]   # 只给 a 加，只属于 a
b.items = [2]   # 只给 b 加，只属于 b

a.items.append(99)
print(b.items)
# 输出：[2]   ← 没有受影响
```

但如果你错误地用类属性做默认值，就会真的共享：

```python
class C:
    items = []   # 类属性，可变，所有实例共享

a = C()
b = C()
a.items.append(1)
print(b.items)
# 输出：[1]   ← 这才是经典坑
```

所以"动态实例属性不共享"本身是个优点——它避免了可变默认值共享问题。但前提是你确实是在实例上赋值，而不是误写到类属性上。

## 3. 最佳实践

### 3.1 常规属性写进 __init__，动态属性仅用于临时场景

这是最重要的原则。一个类的"常规、稳定、所有实例都该有"的属性，必须集中写在 `__init__` 里，让类定义本身就是属性清单。动态属性只用于确实临时、确实只针对单个实例的场景：

```python
# 推荐
class Order:
    def __init__(self, order_id, amount):
        self.order_id = order_id
        self.amount = amount
        self.status = "created"      # 常规属性写这里

order = Order("A001", 100)
order._debug_note = "测试单"   # 临时调试属性，用完就删
```

```python
# 不推荐：常规属性散落在各处动态赋值
class Order:
    pass

order = Order()
order.order_id = "A001"
order.amount = 100
order.status = "created"
# 换一个地方创建 Order 实例，又得重新赋一遍，极易漏字段
```

### 3.2 对属性集稳定的类考虑 __slots__

如果一个类的属性集合在设计中是固定的、不会随意扩展，加上 `__slots__` 能同时获得"防止误加属性"和"省内存"两个好处：

```python
class Point:
    __slots__ = ("x", "y")
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

但要注意 `__slots__` 的代价：失去 `__dict__`（无法用 `obj.__dict__` 反射）、和某些依赖 `__dict__` 的库不兼容、多继承场景复杂。所以只在确有收益时使用，不要无脑全加。

Python 3.10+ 推荐用 `dataclass(slots=True)` 一步到位：

```python
from dataclasses import dataclass

@dataclass(slots=True)
class Point:
    x: float
    y: float
```

### 3.3 读取可能不存在的动态属性用 getattr

动态属性的特点就是"可能有也可能没有"，读取时一律用 `getattr(obj, name, default)` 给默认值，避免 `AttributeError` 中断流程：

```python
# 推荐
if getattr(order, "_special_channel", False):
    handle_special(order)

# 不推荐：假设它一定存在
if order._special_channel:   # 没有这个属性直接崩
    handle_special(order)
```

### 3.4 动态属性命名加下划线前缀表示"内部"

临时、内部用的动态属性，命名时加下划线前缀（`_xxx`），表明它是"实现细节、外部代码不应依赖"。这是一种约定，告诉读代码的人"这个属性是临时挂的，别当正式接口用"：

```python
obj._cached_result = compute()
obj._debug_intermediate = data.copy()
obj._internal_flag = True
```

### 3.5 临时属性用完即删

如果动态属性只是某次操作用的临时状态，操作完成后用 `del` 清掉，避免实例长期背着不再需要的属性：

```python
class Task:
    def run(self):
        self._progress = 0
        try:
            self._do_work()
        finally:
            del self._progress   # 用完清掉，避免长期残留
```

### 3.6 动态绑方法优先考虑挂到类上

如果你想让"所有实例"都获得某个方法，把函数挂到类上（`Cls.method = func`），而不是每个实例都用 `MethodType` 绑一遍。`MethodType` 只用于"只给这一个实例加方法"的少数场景。

```python
# 所有实例都要用 → 挂到类
class Person:
    def __init__(self, name):
        self.name = name

def greet(self, greeting):
    return f"{greeting}, 我是 {self.name}"

Person.greet = greet   # 所有实例都能用

p1 = Person("张三")
p2 = Person("李四")
print(p1.greet("你好"))
# 输出：你好, 我是 张三
print(p2.greet("你好"))
# 输出：你好, 我是 李四
```

```python
# 只给单个实例 → MethodType
import types
p3 = Person("王五")
p3.toolbox = types.MethodType(greet, p3)
```

### 3.7 不要用动态属性替代正式的数据模型

如果一个对象的属性集合是业务模型的一部分（如"用户"有"姓名、邮箱、手机号"），用 `dataclass`、`NamedTuple` 或正式的类定义来建模，而不是靠一堆动态赋值。动态属性适合"边角、临时、个别"的状态，不适合承担"领域模型"的职责：

```python
# 推荐：用 dataclass 正式建模
from dataclasses import dataclass

@dataclass
class User:
    name: str
    email: str
    phone: str = ""
```

```python
# 不推荐：用动态属性凑出一个"用户"
class User:
    pass

u = User()
u.name = "张三"
u.email = "z@x.com"
u.phone = "138..."
```

## 4. 原理

### 4.1 实例属性查找优先于类属性

理解动态属性（以及类属性遮蔽、`__slots__` 机制）的前提，是搞清楚 Python 访问 `obj.x` 时的查找顺序。

**查找链（简化版）**

当你写 `obj.x` 时，Python 按大致下面的顺序查找 `x`：

1. **数据描述符**：先看 `type(obj).__class__.__mro__` 里（即类及其父类）是否有名为 `x` 的数据描述符（同时定义了 `__get__` 和 `__set__` 的描述符）。如果有，优先用它。
2. **实例 `__dict__`**：在 `obj.__dict__` 里找 `"x"`。找到就用。
3. **非数据描述符 / 类属性**：在类（及父类）的 `__dict__` 里找 `"x"`。找到就用。
4. **`__getattr__`**：如果以上都没找到，且类定义了 `__getattr__`，调用它兜底。
5. 都没有 → 抛 `AttributeError`。

对于本文关心的场景，最关键的是第 2 步和第 3 步：**实例 `__dict__` 优先于类属性**。

```python
class C:
    x = "class"

obj = C()
# 还没给实例加 x，读到的先是类属性
print(obj.x)
# 输出：class

# 给实例加同名属性
obj.x = "instance"
# 现在实例 __dict__ 里有 x，优先读到实例的
print(obj.x)
# 输出：instance

# 但类属性还在
print(C.x)
# 输出：class

# 删掉实例属性后，又恢复读到类属性
del obj.x
print(obj.x)
# 输出：class
```

**为什么动态加属性"只影响自己一个"**

因为 `obj.x = v` 这条赋值语句的语义是"写进 `obj.__dict__['x']`"——它只动这一个实例的字典，完全不去碰类的字典。所以别的实例的 `__dict__` 没有任何变化，自然不受影响。

```python
class C:
    pass

a = C()
b = C()

a.x = 1
# a.__dict__ 里多了 x，b.__dict__ 没动
print(a.__dict__)
# 输出：{'x': 1}
print(b.__dict__)
# 输出：{}
```

**赋值总是落在实例 __dict__，不会写到类**

一个常见的误区是以为 `obj.x = v` 在"某些情况"下会改类属性。不会——通过实例赋值，永远只写实例自己的 `__dict__`，哪怕类里有同名类属性，也只是"遮蔽"，不会改类属性：

```python
class C:
    counter = 0

c = C()
c.counter = 10
print(C.counter)   # 类属性没变
# 输出：0
print(c.counter)   # 实例属性遮蔽
# 输出：10
```

想改类属性必须通过类名：`C.counter = 10`。

**为什么读 obj.x 有时拿到的是方法**

前面 2.4 说"把函数挂到类上，所有实例访问时会自动包装成绑定方法"。这背后的机制正是查找链：

当 `Person.greet = greet` 后，`greet` 这个函数对象进了 `Person.__dict__`。函数对象实现了描述符协议（`__get__`），但它是一个**非数据描述符**（只有 `__get__`，没有 `__set__`）。所以访问 `p.greet` 时：

1. 实例 `__dict__` 里没有 `greet`（除非你显式给实例加过）。
2. 往上找到 `Person.__dict__`，发现 `greet` 是个非数据描述符，调用它的 `__get__`，把 `greet` 包装成绑定到 `p` 的方法对象返回。

所以你拿到的是"已经绑好 `p` 的方法"，调用时自动传 `p` 作 `self`。

而如果你直接 `p.greet = greet`（不经过 `MethodType`），写进的是 `p.__dict__['greet']`，是个**普通函数对象**（不是 `MethodType`），访问 `p.greet` 时实例字典里直接找到了它，根本走不到描述符那一步，所以就是个普通函数，调用不自动传 `self`。这就是 2.4 里第一个错误示例报错的根本原因。

### 4.2 __dict__ 是普通字典可随意加键

理解了查找链，再回头看"`__dict__` 是普通字典"这件事的原理性含义。

**实例 __dict__ 的来源**

当你定义一个普通类（没有 `__slots__`），Python 在创建这个类的实例时，会自动给实例分配一个 `dict` 作为 `__dict__`。这个 `dict` 不是类的"字段表"，而是实例私有的、和普通 `dict` 一样的可变容器。

**赋值的底层等价**

`obj.x = v` 在普通类上等价于 `obj.__dict__['x'] = v`（暂不计数据描述符拦截的情况）。因为 `__dict__` 是普通字典，这个操作和 `d['x'] = v` 给普通字典加键没有任何本质区别——字典本来就能随时加任意键。

```python
class Box:
    pass

b = Box()

# 两种写法等价（普通类、无描述符场景）
b.a = 1
b.__dict__["b"] = 2

print(b.__dict__)
# 输出：{'a': 1, 'b': 2}
print(b.a, b.b)
# 输出：1 2
```

这也解释了为什么动态属性"几乎没有成本"——加一个属性就是给字典加一个键，字典本来就是为随时增删设计的。

**属性访问 = 字典查找（外加一层描述符协议）**

读 `obj.x` 时，本质是先看 `obj.__dict__['x']` 有没有（再外加类层面的描述符）。字典查找是 O(1) 平均时间，所以属性访问非常快。这也是 Python 对象"什么都能挂属性"的根本原因——对象属性存储就是字典存储，没有任何"字段声明"的限制。

**为什么函数赋给实例不自动变方法**

结合"赋值就是往 `__dict__` 加键"和"只有从类字典里取出的函数才会被描述符包装"这两点，就明白了：

- `Cls.method = func`：`func` 进类字典，访问 `obj.method` 时走描述符，自动包装成绑定方法。
- `obj.method = func`：`func` 进实例字典，访问 `obj.method` 时直接从实例字典拿到 `func`，不走描述符，就是普通函数。
- `obj.method = types.MethodType(func, obj)`：往实例字典里放的是 `MethodType` 对象（已经绑好的方法），访问 `obj.method` 直接拿到它，调用自动传 `obj`。

这三种情况的区分，正是"实例字典优先 + 描述符只在类字典生效"这条查找规则的直接结果。

### 4.3 __slots__ 如何用描述符替代 __dict__ 限制属性

`__slots__` 能限制可加属性，背后的原理是它**用描述符替代了 `__dict__`**。

**__slots__ 做了什么**

当 Python 遇到一个带 `__slots__` 的类，它在创建类对象时，对 `__slots__` 里每一个名字，生成一个特殊的**数据描述符**（具体是 `member_descriptor`），并以这个名字作为键放进类的 `__dict__`。同时，默认情况下**不给实例分配 `__dict__`**（也不分配 `__weakref__`，除非 slots 里显式包含）。

```python
class Point:
    __slots__ = ("x", "y")

# 在类的 __dict__ 里可以看到 member_descriptor
for name in ("x", "y"):
    print(name, type(Point.__dict__[name]))
# 输出：
# x <class 'member_descriptor'>
# y <class 'member_descriptor'>
```

**member_descriptor 是数据描述符**

`member_descriptor` 同时实现了 `__get__` 和 `__set__`（以及 `__delete__`），是个**数据描述符**。回顾查找链第 1 步：数据描述符的优先级高于实例 `__dict__`。这意味着——即使实例有 `__dict__`（比如 slots 里包含了 `"__dict__"`），对 `x` 的赋值也会被描述符的 `__set__` 拦截。

**__set__ 的拦截逻辑**

`member_descriptor.__set__` 的工作是：检查当前要设置的属性名是否在 `__slots__` 声明的集合里。每个 `member_descriptor` 对应一个固定的名字（在 C 层用偏移量记录存储位置），它只负责那一个属性的存取。

当写 `p.x = 1` 时：

1. `type(p)`（即 `Point`）的 MRO 里找 `x`，发现是个数据描述符（`member_descriptor`）。
2. 调用它的 `__set__(p, 1)`，把值写到实例内存里**预先为 `x` 分配的固定槽位**（不是字典）。

当写 `p.color = "red"` 时：

1. `type(p)` 的 MRO 里找不到 `color`（因为 `__slots__` 只声明了 `x`、`y`），没有对应的描述符。
2. 实例又没有 `__dict__`（因为 `__slots__` 没包含 `"__dict__"`），无处可写。
3. 抛 `AttributeError: 'Point' object has no attribute 'color'`。

这就是 `__slots__` 限制属性的根本机制：**它不靠运行时检查"名字是否在白名单"，而是靠"根本没有 `__dict__` 这个字典让你加键" + "每个合法属性都有固定存储槽位"**。没有字典，自然没法随手加属性。

**为什么 __slots__ 省内存**

这也解释了省内存的原因。普通实例背着一个 `dict`，`dict` 本身有哈希表结构、要预留空间，开销不小。`__slots__` 把属性改成固定槽位存储（类似 C 结构体里固定字段的偏移），不再需要 `dict` 这层间接，每个实例省掉了字典本身的内存。

**为什么 slots 里有 "__dict__" 就失效**

如果 `__slots__` 里包含 `"__dict__"`，Python 会照常给实例分配一个 `__dict__`。这时：

- `x`、`y` 仍然走描述符存到固定槽位。
- 其他名字（如 `color`）找不到描述符，但实例有 `__dict__`，于是写进 `__dict__`，不报错。

所以"限制属性"的能力是"没有 `__dict__` 可写"带来的，一旦把 `"__dict__"` 放进 slots，这层限制就破了。

**继承时的行为**

子类创建时，Python 检查子类自己有没有 `__slots__`：

- 没有 → 子类实例会有 `__dict__`（即使父类有 `__slots__`），于是子类实例能加任意属性。
- 有 → 子类实例没有自己的 `__dict__`，但仍继承父类描述符，所以子类实例可用属性 = 子类 slots ∪ 父类 slots。

这就是 2.6 里那个"子类没定义 `__slots__` 就能加任意属性"现象的原理。

### 4.4 动态绑方法需 MethodType 制造 bound method

最后把 `types.MethodType` 的原理讲清楚。

**普通函数 vs 方法的区别**

在 Python 里，函数（`function`）和方法（`method`）是两种不同对象：

- `function`：定义在模块层或类体里的 `def` 产生的是函数对象。调用时不会自动传任何隐式参数。
- `bound method`：方法对象，是"函数 + 绑定的实例"的组合。调用方法对象时，会自动把绑定的实例作为第一个参数传给底层函数。

**类里定义的 def 为什么实例访问时自动变方法**

当你在类体里写 `def greet(self): ...`，`greet` 是个普通 `function`，存进类的 `__dict__`。但函数对象实现了描述符协议的 `__get__`：从类访问 `Cls.greet` 拿到的是函数本身（未绑定），从实例访问 `obj.greet` 触发 `__get__(obj, type(obj))`，返回一个绑定方法对象，把 `obj` 记下来作为 `self`。

```python
class A:
    def f(self):
        return self

a = A()

# 从实例访问，得到绑定方法（bound method）
print(A.f)        # 未绑定，是普通 function
print(a.f)        # 绑定到 a 的方法
# 输出：
# <function A.f at 0x...>
# <bound method A.f of <__main__.A object at 0x...>>
```

**MethodType 做的就是这件事**

`types.MethodType(func, obj)` 做的，正是"手动把 `func` 和 `obj` 绑成绑定方法对象"，效果上相当于模拟了从实例访问类里函数时描述符自动做的包装。

```python
import types

def greet(self, prefix):
    return f"{prefix}, {self.name}"

class Person:
    def __init__(self, name):
        self.name = name

p = Person("张三")

# MethodType(greet, p) 造出一个绑定方法，等价于"如果 greet 是定义在 Person 里，p.greet 拿到的那个东西"
m = types.MethodType(greet, p)
print(m)
# 输出：<bound method greet of <__main__.Person object at 0x...>>

# 调用 m 时，p 自动作为 self 传入
print(m("你好"))
# 输出：你好, 张三
```

**为什么必须用 MethodType 而不是直接赋值**

如果直接 `p.greet = greet`，存进 `p.__dict__['greet']` 的是普通 `function`。访问 `p.greet` 时，实例字典里直接找到了它，**不会触发描述符协议**（描述符只在类字典访问路径上起效，实例字典命中会跳过）。所以 `p.greet` 就是个普通函数，调用时不自动传 `self`。

```python
p.greet = greet
print(p.greet)
# 输出：<function greet at 0x...>   ← 是 function，不是 bound method

print(p.greet("你好"))
# 输出：TypeError: greet() missing 1 required positional argument: 'prefix'
# 因为 "你好" 传给了 self，prefix 没人传
```

而 `MethodType(greet, p)` 把 `greet` 提前绑好了，存的是绑定方法对象，调用时自动补 `self=p`：

```python
p.greet = types.MethodType(greet, p)
print(p.greet)
# 输出：<bound method greet of <__main__.Person object at 0x...>>

print(p.greet("你好"))
# 输出：你好, 张三
```

**bound method 的 __func__ 和 __self__

绑定方法对象有两个关键属性：

- `__func__`：底层的函数对象。
- `__self__`：绑定的实例。

调用 `m(args)` 等价于 `m.__func__(m.__self__, *args)`。这就是"自动传 self"的实现方式。

```python
m = types.MethodType(greet, p)
print(m.__func__ is greet)
# 输出：True
print(m.__self__ is p)
# 输出：True
```

**一句话总结原理**

动态给实例绑方法必须用 `MethodType`，原因是：直接赋值只是把函数当普通数据放进实例字典，访问时实例字典命中、不走描述符、不自动包装，所以调用不传 `self`；而 `MethodType` 提前把"函数 + 实例"封成绑定方法对象，这个对象调用时会自动把记住的实例作为 `self` 传给底层函数，所以表现得像方法。

## 5. 总结

### 5.1 本文内容要点

- **实例属性动态添加**：Python 允许在对象创建后用 `obj.新属性 = 值` 给单个实例加属性，这种属性只属于被操作的那个实例，不影响其他实例。
- **实例属性存储在 `__dict__`**：普通类的实例有一个 `__dict__` 字典，所有实例属性（无论 `__init__` 里加的还是运行时动态加的）都存在这里；动态加属性本质就是往这个字典加键。`__dict__` 是普通字典，可随意增删。
- **不同实例可有不同属性集**：因为动态属性只影响个别实例，同一类的实例属性集合可以不一致，这是灵活性也是隐患。
- **与类属性的区别**：类属性存类的 `__dict__`、所有实例共享；实例属性存实例 `__dict__`、各自独立；同名时实例属性遮蔽类属性但不修改它。详细对比见第 04 篇。
- **动态添加方法需 `types.MethodType`**：直接给实例赋值普通函数不会自动传 `self`，要用 `MethodType(func, obj)` 把函数和实例绑成绑定方法；若想让所有实例都获得该方法，应把函数挂到类上。
- **`__slots__` 限制可加属性**：定义 `__slots__` 后实例不再有 `__dict__`（默认），合法属性只有 `__slots__` 列出的那些，额外加会抛 `AttributeError`；附带好处是省内存。继承时子类需自己定义 `__slots__` 才能保持限制。
- **动态属性的常见坑**：拼写错误不报错、实例属性集不统一降低可读性、大量临时属性增加内存、删除属性导致别处崩溃、与类属性同名时遮蔽而非修改。

### 5.2 读完应能掌握的能力

读完本文你应当能够：

- 解释为什么 `obj.newattr = x` 能给单个实例加一个原本类里没有的属性，并说明它存储在实例的哪个数据结构里。
- 说明实例属性查找优先于类属性的查找链，并据此解释"为什么给实例赋值同名属性只会遮蔽类属性、不会改类属性"。
- 解释 `__dict__` 是普通字典这个事实如何支撑了"动态加属性几乎无成本"和"可随意加任意键"的特性。
- 给单个实例动态绑定一个方法（用 `types.MethodType`），并说明为什么直接赋值普通函数不行、而把函数挂到类上却能让所有实例自动获得方法。
- 用 `__slots__` 限制一个类的实例可加属性，说明 `__slots__` 用描述符替代 `__dict__` 实现限制的原理，以及省内存的来源。
- 说明 `__slots__` 在子类未定义 `__slots__`、slots 中包含 `"__dict__"` 等场景下"限制失效"的原因。
- 列举动态属性的常见坑（拼写错误静默成功、属性集不统一、内存负担、删除副作用、与类属性遮蔽），并给出对应的规避写法。
- 在编码实践中正确取舍：常规属性写进 `__init__`、属性集稳定的类用 `__slots__` 或 `dataclass(slots=True)`、读取可能不存在的动态属性用 `getattr` 默认值、临时属性加下划线前缀并用完即删、给所有实例加方法挂到类上而非逐个 `MethodType`。
