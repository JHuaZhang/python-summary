## 1. 介绍

### 1.1 什么是条件判断

条件判断（Conditional Statement）是编程语言中最基础也是最核心的控制结构之一。它允许程序根据某个条件（Condition）的真假，选择性地执行不同的代码路径。在 Python 中，条件判断通过 `if`、`elif`、`else` 关键字来实现。

几乎所有实际程序都离不开条件判断：用户输入验证、权限检查、数据分类、异常兜底、业务逻辑分支——本质上都是在做"如果怎样，就怎样；否则怎样"的决策。Python 的条件判断语法设计得极为简洁，没有其他语言中常见的 `switch` 或 `case` 关键字（3.10 版本新增了 `match-case`，将在核心内容中介绍），也没有括号包裹条件的强制要求，这极大提升了代码的可读性。

### 1.2 基本语法与最小示例

Python 的条件判断遵循以下基本语法形式：

```python
if condition:
    # 条件为真时执行的代码块
    pass
```

- `condition` 是一个表达式，Python 会对其求值并判断真值（Truthiness）。
- 代码块通过**缩进**（通常为 4 个空格）来标识层级，而不是像 C/Java 那样用花括号。
- `condition` 后面必须加冒号 `:`，这是初学者最容易遗漏的地方。

下面是最小可运行示例：

```python
# 最小可运行的 if 示例
temperature = 30

if temperature > 28:
    print("今天很热，建议开空调。")

# 输出：今天很热，建议开空调。
```

从这个最简单的例子可以看到，Python 条件判断的门槛极低——一个 `if` 关键字、一个布尔表达式、一个冒号、一个缩进的代码块即可完成一次判断。当 `temperature` 为 30 时，`temperature > 28` 的结果为 `True`，因此 `print` 语句被执行。

如果条件不满足：

```python
temperature = 20

if temperature > 28:
    print("今天很热，建议开空调。")

print("这行代码始终会执行。")

# 输出：这行代码始终会执行。
```

当 `temperature` 为 20 时，条件不成立，`if` 块内的 `print` 被跳过，程序直接执行后续代码。

## 2. 核心内容

### 2.1 if 语句：单分支条件判断

`if` 语句是最基本的条件判断形式，仅处理"条件为真时执行"这一种情况，条件为假时什么都不做。

**语法形式**

```python
if boolean_expression:
    # 条件为 True 时执行的代码块
    statement_1
    statement_2
    ...
```

`boolean_expression` 可以是任何返回布尔值的表达式，也可以是 Python 中任何能被判断真值的对象。缩进块内的所有语句在条件为真时按顺序执行。

**完整演示**

```python
# 场景：检查用户是否已成年，以决定是否允许访问成人内容
user_age = 22

if user_age >= 18:
    print("年龄验证通过。")
    print("允许访问成人内容。")
    print("请遵守相关法律法规。")

# 输出：
# 年龄验证通过。
# 允许访问成人内容。
# 请遵守相关法律法规。
```

当 `user_age >= 18` 为 `True` 时，三个 `print` 语句依次执行。注意这三个语句缩进相同，因此它们属于同一个 `if` 代码块。

如果条件表达式为 `False`，整个代码块被跳过：

```python
user_age = 15

if user_age >= 18:
    print("年龄验证通过。")
    print("允许访问成人内容。")

print("程序结束，未经 age 验证。")

# 输出：程序结束，未经 age 验证。
```

这里 `15 >= 18` 为 `False`，因此两个 `print` 被跳过，只输出了最后的"程序结束"。

### 2.2 if-else 语句：双分支条件判断

`if-else` 在 `if` 的基础上增加了"条件为假时做什么"，形成二选一的完整分支结构。

**语法形式**

```python
if condition:
    # 条件为 True 时执行
    true_branch
else:
    # 条件为 False 时执行
    false_branch
```

注意 `else` 也需要冒号，且 `else` 与 `if` 对齐——不在 `if` 代码块内部。`if` 和 `else` 两个分支有且只有一个会被执行。

**完整演示**

```python
# 场景：根据用户输入判断登录状态，给出对应提示
is_logged_in = False

if is_logged_in:
    print("欢迎回来，用户！")
    print("正在加载您的个人主页……")
else:
    print("您尚未登录。")
    print("请前往登录页面进行身份验证。")

# 输出：
# 您尚未登录。
# 请前往登录页面进行身份验证。
```

这里 `is_logged_in` 为 `False`，因此 `if` 分支被跳过，`else` 分支被执行。注意两个分支中缩进块内的语句按顺序执行——只有 `else` 块的两行 `print` 被执行了。

**if-else 的简化写法（非表达式）**

Python 不支持像 C 语言那样在赋值中直接使用 `if-else` 语句，但可以用下面将要讲到的条件表达式来完成类似需求。`if-else` 本身是**语句**，不是**表达式**，因此它没有返回值。

### 2.3 if-elif-else 语句：多分支条件判断

当需要判断的条件超过两个时，使用 `if-elif-else` 结构。`elif` 是 `else if` 的缩写，Python 特有（很多语言没有直接对应的写法）。

**语法形式**

```python
if condition_1:
    # condition_1 为 True 时执行
    branch_1
elif condition_2:
    # condition_1 为 False 且 condition_2 为 True 时执行
    branch_2
elif condition_3:
    # 前两个条件为 False 且 condition_3 为 True 时执行
    branch_3
...
else:
    # 所有条件均为 False 时执行
    fallback_branch
```

- `elif` 可以有任意多个（包括零个）。
- `else` 是可选的（可以有零个或一个）。
- 条件从上到下依次判断，一旦某个条件为 `True`，执行对应分支后立即跳出整个 `if-elif-else` 结构——**不会继续判断后面的条件**。

**完整演示**

```python
# 场景：根据考试成绩评定等级
score = 85

if score >= 90:
    grade = "优秀"
elif score >= 80:
    grade = "良好"
elif score >= 70:
    grade = "中等"
elif score >= 60:
    grade = "及格"
else:
    grade = "不及格"

print(f"成绩等级为：{grade}")
# 输出：成绩等级为：良好
```

运行过程解析：
1. `score >= 90` 为 `False` (85 < 90)，继续。
2. `score >= 80` 为 `True` (85 >= 80)，执行 `grade = "良好"`，然后**立即跳出**整个结构。
3. 即使 `score >= 70`、`score >= 60` 也为 `True`，但不会再被判断。

这是 `elif` 区别于多个独立 `if` 的关键行为——多个独立 `if` 会分别判断每个条件，而 `elif` 保证最多只有一个分支被执行。

**对比：elif 与多个独立 if 的区别**

```python
# 场景：用两种方式判断数字范围，观察行为差异

# 方式一：使用 if-elif-else（正确做法）
number = 75

print("=== 方式一：if-elif-else ===")
if number > 50:
    print("数字大于 50")
elif number > 30:
    print("数字大于 30")
elif number > 10:
    print("数字大于 10")
else:
    print("数字小于等于 10")
# 输出：数字大于 50（只执行第一个匹配的）

print()

# 方式二：使用多个独立 if（通常不符合意图）
print("=== 方式二：多个独立 if ===")
if number > 50:
    print("数字大于 50")
if number > 30:
    print("数字大于 30")
if number > 10:
    print("数字大于 10")
# 输出：
# 数字大于 50
# 数字大于 30
# 数字大于 10
```

多个独立 `if` 会依次判断每个条件，输出所有匹配项；而 `if-elif-else` 只输出第一个匹配项。在实际业务中，前者常用于"筛选/过滤"（如标签分类），后者常用于"互斥分支"（如评分等级、菜单选择）。

**省略 else 的 elif 结构**

`else` 是可选的，省略时如果所有条件都不满足，整个结构不执行任何代码：

```python
# 场景：只在特定时间段给出问候
current_hour = 14

if current_hour < 12:
    print("上午好！")
elif current_hour < 18:
    print("下午好！")

# 当前 hour 为 14，匹配 elif，输出：下午好！
# 如果当前时间为 22（所有条件不匹配），则没有任何输出，程序静默继续
```

### 2.4 条件表达式（三元运算符）

**作用与语法**

Python 的条件表达式（Conditional Expression，常被称为"三元运算符"）允许在一行内完成简单的条件赋值。其语法为：

```python
value_if_true if condition else value_if_false
```

- `condition`：判断条件。
- `value_if_true`：条件为真时表达式的值。
- `value_if_false`：条件为假时表达式的值。

注意：条件表达式**不是语句**，而是**表达式**——它有返回值，可以出现在任何能放表达式的地方（赋值右侧、函数参数、return 语句等）。

**基本用法演示**

```python
# 场景：根据用户年龄决定票价类型
age = 65

# 使用条件表达式
ticket_type = "老人票" if age >= 60 else "普通票"
print(f"票种：{ticket_type}")
# 输出：票种：老人票

# 等价的 if-else 写法
if age >= 60:
    ticket_type = "老人票"
else:
    ticket_type = "普通票"
```

条件表达式的优势是简洁——原本需要 4 行的 `if-else` 结构压缩为 1 行。但这也意味着它**不适合复杂的逻辑**，强行塞入多层嵌套会严重损害可读性。

**条件表达式的嵌套**

条件表达式可以嵌套使用（在 `value_if_true` 或 `value_if_false` 中再放一个条件表达式），但需谨慎：

```python
# 场景：成绩评级，用嵌套条件表达式实现
score = 78

# 嵌套条件表达式——虽然能工作，但可读性急剧下降
rating = "优秀" if score >= 90 else ("良好" if score >= 80 else ("及格" if score >= 60 else "不及格"))
print(f"评分：{rating}")
# 输出：评分：及格

# 更清晰的做法：用 if-elif-else 替代
if score >= 90:
    rating = "优秀"
elif score >= 80:
    rating = "良好"
elif score >= 60:
    rating = "及格"
else:
    rating = "不及格"
```

嵌套条件表达式可读性差，原则上嵌套不超过一层。多层分支请使用普通 `if-elif-else`。

**条件表达式在函数参数和 return 中的使用**

```python
# 场景：计算订单折扣，在函数参数中直接使用条件表达式
def calculate_discount(total_amount, is_vip):
    # 在 return 中使用条件表达式
    return total_amount * 0.2 if is_vip else total_amount * 0.1

# 在 print 参数中使用条件表达式
order_total = 500
is_vip = True

discount = calculate_discount(order_total, is_vip)
print(f"VIP 用户订单金额 {order_total}，折扣 {discount}，实付 {order_total - discount}")

is_vip = False
discount = calculate_discount(order_total, is_vip)
print(f"普通用户订单金额 {order_total}，折扣 {discount}，实付 {order_total - discount}")

# 输出：
# VIP 用户订单金额 500，折扣 100.0，实付 400.0
# 普通用户订单金额 500，折扣 50.0，实付 450.0
```

条件表达式在函数参数和 `return` 语句中特别有用，可以让逻辑在一行内表达完整，避免了临时变量。

**条件表达式与 and/or 模拟的对比**

在条件表达式出现之前（Python 2.4 之前），开发者常利用 `and` 和 `or` 的短路行为来模拟条件判断：

```python
# 场景：获取用户昵称，没有则显示默认名
username = ""

# 传统 and/or 技巧（不推荐，有陷阱）
display_name = username or "匿名用户"
print(f"显示名称：{display_name}")
# 输出：显示名称：匿名用户

# 条件表达式（推荐，更清晰）
display_name = username if username else "匿名用户"
print(f"显示名称：{display_name}")
# 输出：显示名称：匿名用户
```

`username or "匿名用户"` 利用了 `or` 的短路求值：如果 `username` 为真值则返回 `username`，否则返回 `"匿名用户"`。但这种方式在 `username` 为 `0`、`False` 等"假值但合法"的情况下会出错。条件表达式没有这个问题。

### 2.5 真值判断规则（Truthiness）

**什么是真值**

在 Python 中，任何对象都可以被用在需要布尔值的上下文中（如 `if condition` 中的 `condition`）。Python 会隐式地将该对象转换为布尔值（通过 `bool()` 函数），转换规则称为**真值判断**（Truthiness）。

**被视为 False 的值**

以下值在布尔上下文中被视为 `False`：

| 类型 | 被视为 False 的值 | 说明 |
|------|-------------------|------|
| `None` | `None` | 表示"没有值" |
| `bool` | `False` | 布尔假值 |
| 数值类型 | `0`、`0.0`、`0j`、`Decimal(0)`、`Fraction(0,1)` | 各种零值 |
| 字符串 | `""` | 空字符串 |
| 字节串 | `b""` | 空字节串 |
| 列表 | `[]` | 空列表 |
| 元组 | `()` | 空元组 |
| 字典 | `{}` | 空字典 |
| 集合 | `set()` | 空集合 |
| `range` | `range(0)` | 空 range |

所有其他值（非零数值、非空容器、`True` 等）都被视为 `True`。

**演示真值判断**

```python
# 场景：逐一检查各种类型在布尔上下文中的表现
values_to_test = [
    None,       # None 类型
    False,      # bool 假值
    True,       # bool 真值
    0,          # 整数零
    1,          # 非零整数
    0.0,        # 浮点零
    0.5,        # 非零浮点
    "",         # 空字符串
    "hello",    # 非空字符串
    [],         # 空列表
    [1, 2, 3],  # 非空列表
    {},         # 空字典
    {"key": "value"},  # 非空字典
    set(),      # 空集合
    {1, 2},     # 非空集合
    (),         # 空元组
    (1,),       # 非空元组
    range(0),   # 空 range
    range(5),   # 非空 range
]

# 逐个测试真值，并收集结果
print(f"{'值':<20} {'bool() 结果':<15} {'真值判断':<10}")
print("=" * 45)

for value in values_to_test:
    bool_result = bool(value)
    truthiness = "真(True)" if bool_result else "假(False)"
    print(f"{str(value):<20} {str(bool_result):<15} {truthiness}")

# 输出：
# 值                     bool() 结果      真值判断   
# =============================================
# None                   False            假(False)
# False                  False            假(False)
# True                   True             真(True) 
# 0                      0                假(False)
# 1                      True             真(True) 
# 0.0                    False            假(False)
# 0.5                    True             真(True) 
#                        False            假(False)
# hello                  True             真(True) 
# []                     False            假(False)
# [1, 2, 3]              True             真(True) 
# {}                     False            假(False)
# {'key': 'value'}       True             真(True) 
# set()                  False            假(False)
# {1, 2}                 True             真(True) 
# ()                     False            假(False)
# (1,)                   True             真(True) 
# range(0, 0)            False            假(False)
# range(0, 5)            True             真(True)
```

**利用真值简化条件判断**

在 Python 中，直接判断对象本身的真值比显式比较更符合 Python 习惯（Pythonic）：

```python
# 场景：检查用户是否提供了姓名

# 不推荐的做法：显式比较
user_name = "张三"

if len(user_name) > 0:      # 啰嗦，不够 Pythonic
    print(f"欢迎，{user_name}！")

# 推荐的做法：利用真值判断
if user_name:               # 简洁，Pythonic
    print(f"欢迎，{user_name}！")

# 输出：欢迎，张三！
```

但需要注意**边界情况**：当"空"是合法输入时，直接判断真值会有问题：

```python
# 场景：统计购物车中的商品数量，允许数量为 0
item_count = 0

# 问题写法：item_count 为 0 时被视为 False，导致意外行为
if item_count:
    print(f"购物车中有 {item_count} 件商品")
else:
    print("购物车是空的")
# 输出：购物车是空的（虽然确实为空，但实际业务需要区分"空"与"未获取到"）

# 修正写法：显式比较 None
item_count = None

if item_count is not None:
    print(f"购物车中有 {item_count} 件商品")
else:
    print("尚未获取购物车数据")
# 输出：尚未获取购物车数据
```

**自定义对象的真值判断**

如果自定义类实现了 `__bool__` 或 `__len__` 方法，可以控制该类的真值行为：

```python
# 场景：自定义一个任务类，允许通过真值判断任务是否需要处理
class Task:
    """任务类：真值由待处理事项数量决定"""
    
    def __init__(self, title, items=None):
        self.title = title
        self.items = items or []
    
    def __bool__(self):
        # 有待处理事项的任务视为真
        return len(self.items) > 0
    
    def __repr__(self):
        return f"Task({self.title!r}, items={self.items!r})"


# 测试自定义真值行为
empty_task = Task("清理日志", [])
meaningful_task = Task("发布版本", ["更新文档", "运行测试", "打包部署"])

print(f"空任务 {empty_task} 的真值：{bool(empty_task)}")
# 输出：空任务 Task('清理日志', items=[]) 的真值：False

print(f"有效任务 {meaningful_task} 的真值：{bool(meaningful_task)}")
# 输出：有效任务 Task('发布版本', items=['更新文档', '运行测试', '打包部署']) 的真值：True

# 可在 if 中直接使用
if meaningful_task:
    print(f"任务「{meaningful_task.title}」有待处理事项，请处理！")
else:
    print("暂无待处理任务。")

# 输出：任务「发布版本」有待处理事项，请处理！
```

### 2.6 短路求值（Short-Circuit Evaluation）

**什么是短路求值**

短路求值（Short-Circuit Evaluation）是指逻辑运算符 `and` 和 `or` 在求值时，一旦能确定整个表达式的最终结果，就立即停止对后续表达式的求值，不再计算剩余部分。这一特性在 Python 的条件判断中广泛使用。

**and 的短路行为**

`and` 从左到右依次求值，遇到第一个 `False` 值就立即返回该值——因为此时整个 `and` 表达式已经不可能为真了：

```python
# 场景：验证用户输入——用户名非空且密码长度不小于 6 位
def validate_username(name):
    """模拟用户名验证——函数执行时有提示"""
    print(f"  -> 正在验证用户名：{name!r}")
    return len(name) > 0

def validate_password(pwd):
    """模拟密码验证——函数执行时有提示"""
    print(f"  -> 正在验证密码长度：{len(pwd)}")
    return len(pwd) >= 6

print("测试一：用户名和密码均有效")
result = validate_username("alice") and validate_password("abc123")
print(f"最终结果：{result}")
print()

print("测试二：用户名为空，第二次验证不会执行")
result = validate_username("") and validate_password("short")
print(f"最终结果：{result}")

# 输出：
# 测试一：用户名和密码均有效
#   -> 正在验证用户名：'alice'
#   -> 正在验证密码长度：6
# 最终结果：True
# 
# 测试二：用户名为空，第二次验证不会执行
#   -> 正在验证用户名：''
# 最终结果：False（validate_password 未被调用！）
```

测试二中，`validate_username("")` 返回 `False`，整个 `and` 表达式已经不可能为 `True`，所以 `validate_password("short")` 被**跳过**，没有执行。

**or 的短路行为**

`or` 也是从左到右求值，遇到第一个 `True` 值就立即返回该值——因为此时整个 `or` 表达式已经不可能为假了：

```python
# 场景：尝试从多个数据源获取用户配置，使用第一个有效的结果
def get_config_from_cache(user_id):
    """从缓存中读取配置——模拟，返回空字典表示未命中"""
    print(f"  -> 从缓存查询用户 {user_id} 的配置")
    return {}  # 缓存未命中

def get_config_from_db(user_id):
    """从数据库中读取配置——模拟，返回默认配置"""
    print(f"  -> 从数据库查询用户 {user_id} 的配置")
    return {"theme": "dark", "language": "zh-CN"}

def get_config_from_default():
    """返回默认配置"""
    print("  -> 使用默认配置")
    return {"theme": "light", "language": "en"}

user_id = "u1001"

print("查询用户配置（或运算短路）")
config = (
    get_config_from_cache(user_id)
    or get_config_from_db(user_id)
    or get_config_from_default()
)
print(f"最终配置：{config}")

# 输出：
# 查询用户配置（或运算短路）
#   -> 从缓存查询用户 u1001 的配置
#   -> 从数据库查询用户 u1001 的配置
# 最终配置：{'theme': 'dark', 'language': 'zh-CN'}
```

第一个 `or` 左侧（缓存查询）返回空字典（假值），所以继续计算第二个；第二个返回了非空字典（真值），短路发生，第三个（默认配置）被跳过。

**短路求值的实用模式**

短路求值可以用于实现"条件执行"和"默认值"模式：

```python
# 场景一：条件执行——仅在条件为真时执行操作
is_admin = True
user_name = "管理员"

# 利用 and 短路：只有 is_admin 为 True 时才执行后边的 print
is_admin and print(f"欢迎管理员 {user_name}。")
# 输出：欢迎管理员 管理员。
# 如果 is_admin 为 False，print 根本不会执行

# 场景二：默认值——用 or 设定默认值
user_input = ""  # 用户没有输入
name = user_input or "访客"
print(f"当前用户：{name}")
# 输出：当前用户：访客

# 场景三：系列检查——需要所有前置条件都满足
def check_permission(user, resource):
    """检查用户是否有权限访问资源（逐级检查，失败即停止）"""
    return (
        user is not None                   # 用户存在
        and user.get("active", False)      # 用户已激活
        and resource in user.get("permissions", [])  # 有资源权限
    )

# 如果 user 为 None，后续的 .get 调用根本不会发生——避免了 AttributeError
alice = {"active": True, "permissions": ["read", "write"]}
bob = None

print(f"Alice 有权限吗？{check_permission(alice, 'write')}")
# 输出：Alice 有权限吗？True

print(f"Bob 有权限吗？{check_permission(bob, 'write')}")
# 输出：Bob 有权限吗？False（执行到 user is not None 即短路，不会尝试调用 None.get）
```

**注意事项**

短路求值虽然简洁，但也可能隐藏 bug：

```python
# 场景：处理订单时，需要同时更新库存和记录日志
def update_stock(order_id):
    """更新库存——模拟"""
    print(f"  更新库存：订单 {order_id}")
    return True

def record_log(order_id):
    """记录日志——模拟"""
    print(f"  记录日志：订单 {order_id}")
    return True

order_id = "ORD-001"

# 问题写法：如果 update_stock 返回 False，record_log 不会执行
print("问题写法：")
success = update_stock(order_id) and record_log(order_id)
print(f"操作结果：{success}")
print()

# 更安全的写法：两个操作都执行，再统一判断
print("推荐写法：")
stock_ok = update_stock(order_id)
log_ok = record_log(order_id)
success = stock_ok and log_ok
print(f"操作结果：{success}")

# 输出：
# 问题写法：
#   更新库存：订单 ORD-001
#   记录日志：订单 ORD-001
# 操作结果：True
# 
# 推荐写法：
#   更新库存：订单 ORD-001
#   记录日志：订单 ORD-001
# 操作结果：True
```

这个例子中 `update_stock` 和 `record_log` 都返回 `True`，所以看不出区别。但如果 `update_stock` 因某种原因返回 `False`，问题写法中的 `record_log` 就不会被执行，这可能导致日志丢失——而推荐写法不会出现这个问题。

### 2.7 链式比较（Chained Comparison）

**什么是链式比较**

Python 允许将多个比较运算符串联起来，形成一个链式比较表达式。它源于数学中常见的 `a < b < c` 写法，但在大多数编程语言中并不直接支持（需要写成 `a < b && b < c`）。Python 的链式比较自动在内部展开为逻辑与（`and`）的连接。

**语法形式**

```python
a < b <= c > d >= e == f != g
```

等同于：

```python
a < b and b <= c and c > d and d >= e and e == f and f != g
```

但每个操作数只被求值一次。

**基本演示**

```python
# 场景：检查数字是否在某个区间内

# 不使用链式比较（其他语言常见写法）
x = 15
if x > 10 and x < 20:
    print(f"{x} 在 10 到 20 之间")

# 使用链式比较（Python 特有写法）
if 10 < x < 20:
    print(f"{x} 在 10 到 20 之间")

# 输出（两次相同）：
# 15 在 10 到 20 之间
```

链式比较更接近数学表达式的写法，可读性更强。

**链式比较的各种形式**

```python
# 场景：验证各种数值范围检查场景

# 1. 检查年龄是否在合法范围内
age = 25
if 18 <= age <= 60:
    print(f"年龄 {age} 在合法工作年龄范围内（18-60）")
# 输出：年龄 25 在合法工作年龄范围内（18-60）

# 2. 比较浮点数精度范围
measured = 0.501
# 要求测量值在 0.5 ± 0.01 范围内
if 0.49 <= measured <= 0.51:
    print(f"测量值 {measured} 在可接受范围内")
# 输出：测量值 0.501 在可接受范围内

# 3. 不等号混合使用
score = 85
if 0 <= score <= 100:
    print(f"分数 {score} 在有效范围（0-100）内")
# 输出：分数 85 在有效范围（0-100）内

# 4. 三个以上的比较
temperature = 25
if -10 < temperature < 40 and temperature != 0:
    print(f"温度 {temperature}°C 在传感器可正常工作范围内")
# 输出：温度 25°C 在传感器可正常工作范围内

# 5. 使用 == 和 != 的链式比较（检查三个值是否相等）
a, b, c = 5, 5, 5
if a == b == c:
    print("a、b、c 三者相等")
else:
    print("a、b、c 不完全相等")
# 输出：a、b、c 三者相等

# 6. 检查值是否在多个不等关系中
value = 8
result = 1 < value < 10
print(f"1 < {value} < 10 = {result}")
# 输出：1 < 8 < 10 = True
```

**链式比较的特殊行为：任意比较运算符可以出现在同一链中**

Python 对链式比较中使用的运算符没有限制——`<`、`<=`、`>`、`>=`、`==`、`!=`、`is`、`is not`、`in`、`not in` 都可以出现在链中：

```python
# 场景：检查字符串长度同时确保不是空字符串
user_input = "hello"
if 0 < len(user_input) <= 10:
    print(f"输入 \"{user_input}\" 长度合格（1-10 个字符）")
# 输出：输入 "hello" 长度合格（1-10 个字符）

# 注意：0 < len("") <= 10 等价于 0 < 0 and 0 <= 10，结果是 False，不会执行 print

# 练习：使用 is 和 == 混合链式比较
# 注意：虽然语法允许，但混合不同类型运算符会降低可读性，实际中不推荐
```

**链式比较的陷阱**

```python
# 常见陷阱：链式比较不会按预期对列表或集合工作

# 错误直觉：检查 5 是否在列表中
value = 5
my_list = [1, 2, 3, 4, 5]

# 这种写法不会判断"5 是否在列表中"
# 实际上等价于: 1 < [1,2,3,4,5] < 6 → 1 < list ???? → TypeError!
# 下面这行会报错，注释掉以示安全
# if 1 < my_list < 6:  
#     print("value 在 1 到 6 之间")

# 正确的做法：使用 in 运算符
if value in my_list:
    print(f"{value} 在列表中")
# 输出：5 在列表中

# 另一个陷阱：链式比较不支持包含函数调用的复杂比对
def get_value():
    print("get_value 被调用")
    return 5

# 链式比较中每个操作数只求值一次——如果 get_value() 有副作用，这是优势
x = get_value()
if 0 < x < 10:
    print("值在 0 到 10 之间")
# 输出：
# get_value 被调用
# 值在 0 到 10 之间
# 这里 get_value 只被调用了一次
```

### 2.8 多条件组合：and、or、not

在实际的业务逻辑中，条件很少是单一的。Python 提供了三个逻辑运算符来组合多个条件：`and`（与）、`or`（或）、`not`（非）。

**运算符优先级**

逻辑运算符的优先级（从高到低）：

1. `not`（最高优先级）
2. `and`
3. `or`（最低优先级）

但强烈建议在复杂条件中**使用括号来明确优先级**，而不是依赖运算符优先级规则——这能显著提升可读性并减少歧义。

**not 运算符**

`not` 用于取反——将真值变为假，假值变为真：

```python
# 场景：检查用户是否不在禁止列表中
banned_users = {"user001", "user005", "user010"}
current_user = "user003"

if current_user not in banned_users:
    print(f"用户 {current_user} 未被禁言，可以发言。")

# 使用 not 实现同样逻辑：
if not (current_user in banned_users):
    print(f"用户 {current_user} 未被禁言，可以发言。")

# 输出（两次相同）：
# 用户 user003 未被禁言，可以发言。
```

注意 `not` 和 `in` 可以合写为 `not in`——这是 Python 内置的推荐写法，`not in` 整体是一个运算符。

**and 运算符**

`and` 要求所有条件都为真时整体才为真：

```python
# 场景：判断是否可以享受满减优惠
order_amount = 200
is_new_user = True
has_coupon = False

# 满 199 且是新用户即可享受优惠
if order_amount >= 199 and is_new_user:
    print("恭喜！您满足满减条件。")
else:
    print("抱歉，您不满足满减条件。")

# 输出：恭喜！您满足满减条件。

# 有优惠券或满足满减条件
if has_coupon or (order_amount >= 199 and is_new_user):
    print("您可以享受优惠。")
else:
    print("无可用优惠。")

# 输出：您可以享受优惠。
```

**or 运算符**

`or` 要求至少一个条件为真时整体即为真：

```python
# 场景：无条件同意条件——任一条件满足即可参与抽奖
is_vip = False
is_first_order = True
has_invite_code = False

if is_vip or is_first_order or has_invite_code:
    print("您有资格参与抽奖活动！")
else:
    print("您暂无抽奖资格。")

# 输出：您有资格参与抽奖活动！
```

**复杂组合与括号的使用**

```python
# 场景：员工考勤判断——正常出勤的定义
# 规则：正常上班（不迟到、不早退、不旷工），或者（请假且被批准）

attendance_records = {
    "is_late": False,
    "leave_early": False,
    "absent": False,
    "on_leave": True,
    "leave_approved": True,
}

record = attendance_records

# 不推荐：依赖运算符优先级，可读性差
if not record["is_late"] and not record["leave_early"] and not record["absent"] or record["on_leave"] and record["leave_approved"]:
    print("出勤正常")

# 推荐：使用括号明确优先级，一眼就能看出逻辑结构
is_normal = (not record["is_late"] and not record["leave_early"] and not record["absent"])
is_leave_ok = (record["on_leave"] and record["leave_approved"])

if is_normal or is_leave_ok:
    print("出勤正常")

# 输出：出勤正常

# 更复杂的多层条件
def check_order_eligibility(order):
    """检查订单是否可享受最高折扣"""
    # 条件：会员（等级 >= 3）且在促销期内，并且（订单满 200 或首次消费）
    is_vip = order.get("vip_level", 0) >= 3
    in_promotion = order.get("date", "") in ["2026-01-01", "2026-02-01", "2026-03-01"]
    amount_ok = order.get("amount", 0) >= 200
    is_first = order.get("first_order", False)
    
    if is_vip and in_promotion and (amount_ok or is_first):
        return True
    return False


orders = [
    {"vip_level": 4, "date": "2026-01-01", "amount": 150, "first_order": False},
    {"vip_level": 2, "date": "2026-01-01", "amount": 300, "first_order": False},
    {"vip_level": 4, "date": "2026-01-15", "amount": 500, "first_order": False},
    {"vip_level": 5, "date": "2026-02-01", "amount": 50, "first_order": True},
]

for i, order in enumerate(orders, 1):
    eligible = check_order_eligibility(order)
    print(f"订单{i}: {'可享' if eligible else '不可享'}最高折扣")

# 输出：
# 订单1: 不可享最高折扣（金额不足且非首单）
# 订单2: 不可享最高折扣（等级不足）
# 订单3: 不可享最高折扣（不在促销期）
# 订单4: 可享最高折扣（VIP、促销期、首单）
```

**not and or 的优先级演示**

```python
# 场景：通过实际运行展示优先级行为

a, b, c = True, False, True

# 方案一：不加括号（依赖默认优先级）
# 优先级顺序：not > and > or
result1 = not a and b or c
# 等价于：((not a) and b) or c
# 即：((False) and False) or True → False or True → True
print(f"not a and b or c = {result1}")  # True

# 方案二：等价加括号
result2 = ((not a) and b) or c
print(f"((not a) and b) or c = {result2}")  # True

# 方案三：不同的括号位置，完全不同的结果
result3 = not (a and b or c)
# 等价于：not ((a and b) or c) → not (False or True) → not True → False
print(f"not (a and b or c) = {result3}")  # False

# 对比差异
print(f"方案一 vs 方案三：{result1} vs {result3} ——括号位置改变了逻辑")

# 结论：与其记住优先级，不如用括号明确表达意图
# 生产环境推荐写法：
if (not a) and (b or c):
    print("明确优先级，其他人一眼就能看懂")
```

### 2.9 match-case 语句（Python 3.10+）

**概念与定位**

Python 3.10 引入了 `match-case` 语句（全称：结构模式匹配，Structural Pattern Matching）。它并非 `if-elif-else` 的简单替代品，而是一种更强大的模式匹配工具，能够根据值的**结构**而不是仅仅是值本身来进行匹配。

`match-case` 与 `if-elif-else` 的关系：
- `if-elif-else` 适用于布尔条件判断（"是否满足某个条件"）。
- `match-case` 适用于结构匹配（"值是否符合某个模式"）。

**基本语法**

```python
match subject:
    case pattern_1:
        # 匹配 pattern_1 时执行
        ...
    case pattern_2:
        # 匹配 pattern_2 时执行
        ...
    case _:
        # 默认分支（类似 else）
        ...
```

**基本演示**

```python
# 场景：根据 HTTP 状态码给出用户友好的提示

def handle_http_status(status_code):
    """根据 HTTP 状态码返回用户友好的提示信息"""
    match status_code:
        case 200:
            return "请求成功"
        case 301:
            return "资源已永久移动"
        case 302:
            return "资源临时重定向"
        case 400:
            return "请求无效（客户端错误）"
        case 401:
            return "未授权，请先登录"
        case 403:
            return "禁止访问，权限不足"
        case 404:
            return "请求的资源不存在"
        case 500:
            return "服务器内部错误"
        case _:
            return f"未知状态码：{status_code}"


# 测试
for code in [200, 404, 503, 418]:
    print(f"HTTP {code}: {handle_http_status(code)}")

# 输出：
# HTTP 200: 请求成功
# HTTP 404: 请求的资源不存在
# HTTP 503: 未知状态码：503
# HTTP 418: 未知状态码：418
```

注意 `_`（下划线）是通配符，匹配任何值，相当于 `if-elif-else` 中的 `else`。

**用 | 合并多个模式**

```python
# 场景：将数字分类——非整数、整数、小整数、大整数

def classify_number(value):
    """将输入分类为不同类别"""
    match value:
        case 0 | 1 | 2 | 3 | 4 | 5:    # 模式合并：匹配其中任意一个
            return "小整数（0-5）"
        case int():                       # 匹配 int 类型
            return "整数（大于 5）"
        case float():                     # 匹配 float 类型
            return "浮点数"
        case str():                       # 匹配 str 类型
            return "字符串"
        case _:
            return f"其他类型：{type(value).__name__}"


# 测试
test_values = [3, 10, 3.14, "hello", True, None]
for val in test_values:
    print(f"{val!r:<8} -> {classify_number(val)}")

# 输出：
# 3        -> 小整数（0-5）
# 10       -> 整数（大于 5）
# 3.14     -> 浮点数
# 'hello'  -> 字符串
# True     -> 小整数（0-5）  # 注意：bool 是 int 的子类，True == 1
# None     -> 其他类型：NoneType
```

**解包匹配与守卫条件**

```python
# 场景：处理各种形状——通过匹配元组来解包坐标

from math import pi

def describe_shape(shape):
    """描述各种形状的特征"""
    match shape:
        # 解包元组：rectangle(width, height)
        case ("rectangle", w, h):
            area = w * h
            return f"矩形 {w}x{h}，面积 = {area}"
        
        # 解包元组：circle(radius)
        case ("circle", r) if r > 0:    # 守卫条件（额外的 if 条件）
            area = pi * r * r
            return f"圆形 半径={r}，面积 = {area:.2f}"
        
        # 解包元组：triangle(base, height)
        case ("triangle", b, h):
            area = 0.5 * b * h
            return f"三角形 底={b} 高={h}，面积 = {area}"
        
        case _:
            return f"无法识别的形状：{shape}"


# 测试
shapes = [
    ("rectangle", 5, 3),
    ("circle", 10),
    ("triangle", 4, 6),
    ("hexagon", 5),
    ("circle", -5),    # 守卫条件会拦截
]

for shape in shapes:
    print(describe_shape(shape))

# 输出：
# 矩形 5x3，面积 = 15
# 圆形 半径=10，面积 = 314.16
# 三角形 底=4 高=6，面积 = 12.0
# 无法识别的形状：('hexagon', 5)
# 无法识别的形状：('circle', -5)（因为守卫条件 if r > 0 不满足）
```

注意守卫条件 `if r > 0`——它是在匹配模式之后再附加的一个布尔条件，只有模式和守卫同时满足时才算匹配成功。

**match-case 与 if-elif-else 的选择**

```python
# 场景对比：同样的业务逻辑，两种实现方式

# 情况 A：简单值比较——两种都可以，但 match-case 更清晰
def get_season_v1(month):
    """用 if-elif-else 实现"""
    if month in (12, 1, 2):
        return "冬季"
    elif month in (3, 4, 5):
        return "春季"
    elif month in (6, 7, 8):
        return "夏季"
    elif month in (9, 10, 11):
        return "秋季"
    else:
        return "无效月份"


def get_season_v2(month):
    """用 match-case 实现"""
    match month:
        case 12 | 1 | 2:
            return "冬季"
        case 3 | 4 | 5:
            return "春季"
        case 6 | 7 | 8:
            return "夏季"
        case 9 | 10 | 11:
            return "秋季"
        case _:
            return "无效月份"


# 测试两者结果一致
for month in range(1, 14):
    if get_season_v1(month) != get_season_v2(month):
        print(f"不一致：月份 {month}")
    else:
        pass  # 一致

print("两种实现结果完全一致。")

# 情况 B：需要复杂布尔条件时，if-elif-else 仍然是最佳选择
score = 88
# if-elif-else 可以处理范围比较，match-case 做不到（或很难做）
if score >= 90:
    print("优秀")
elif score >= 80:
    print("良好")
elif score >= 70:
    print("中等")
elif score >= 60:
    print("及格")
else:
    print("不及格")

# match-case 处理范围比较需要使用守卫条件，代码更冗长
# 因此这种情况应使用 if-elif-else
```

**使用建议**：`match-case` 适用于解包元组/列表、匹配字典结构、匹配类型等场景；如果仅仅是数值范围比较或布尔表达式组合，`if-elif-else` 仍然是更自然的选择。

### 2.10 嵌套条件判断

**概念**

嵌套条件判断是指在一个 `if`（或 `elif`、`else`）的代码块内部再放置另一个 `if` 语句。当外层条件满足后，内层条件进一步细分逻辑时使用。

**基本演示**

```python
# 场景：根据用户角色和状态决定系统功能菜单
# 外层判断角色，内层判断活动状态

def get_menu_items(user):
    """根据用户角色和状态返回可用的菜单项"""
    role = user.get("role", "guest")
    is_active = user.get("is_active", False)
    
    if role == "admin":
        print("角色：管理员")
        # 嵌套判断：管理员下的细化
        if is_active:
            print("菜单：[用户管理] [系统设置] [内容管理] [数据分析] [日志查看]")
        else:
            print("菜单：[系统设置] [内容管理]（有限功能）")
            print("提示：当前账户未激活，部分功能受限")
    
    elif role == "editor":
        print("角色：编辑")
        # 嵌套判断：编辑下的细化
        if is_active:
            print("菜单：[内容管理] [素材库] [统计概览]")
        else:
            print("菜单：[内容管理]（只读模式）")
            print("提示：当前账户未激活，仅可查看不可编辑")
    
    elif role == "viewer":
        print("角色：访客")
        print("菜单：[内容浏览] [搜索]")
    
    else:
        print("角色：游客")
        print("菜单：[内容浏览]")


# 测试不同组合
users = [
    {"role": "admin", "is_active": True, "name": "Alice"},
    {"role": "admin", "is_active": False, "name": "Bob"},
    {"role": "editor", "is_active": True, "name": "Charlie"},
    {"role": "viewer", "is_active": True, "name": "Diana"},
    {"role": "guest", "is_active": False, "name": "Eve"},
]

for user in users:
    print(f"\n{'='*40}")
    print(f"用户：{user['name']}")
    get_menu_items(user)
```

**嵌套深度的可读性问题**

嵌套本身不是问题，但嵌套层级过深（超过 3 层）会严重影响代码的可读性和维护性：

```python
# 场景：复杂的审批流程——展示了过深的嵌套（不推荐）

def approve_expense_v1(expense):
    """不推荐的深层嵌套写法"""
    if expense["amount"] > 0:
        if expense["category"] in ("travel", "entertainment"):
            if expense["amount"] > 10000:
                if expense["urgent"]:
                    print("需要 CEO 紧急审批")
                else:
                    print("需要 CFO 审批")
            else:
                if expense["has_receipt"]:
                    if expense["amount"] > 5000:
                        print("部门经理审批 + 财务备案")
                    else:
                        print("部门经理直接审批")
                else:
                    print("请补交凭证后再提交")
        else:
            print("常规费用走统一流程")
    else:
        print("金额必须大于 0")

# 写法一对比：使用守卫子句（Guard Clause）减少嵌套
def approve_expense_v2(expense):
    """推荐写法：提前 return 减少嵌套"""
    # 守卫子句 1：金额不合法
    if expense["amount"] <= 0:
        print("金额必须大于 0")
        return
    
    # 守卫子句 2：非差旅/招待费走统一流程
    if expense["category"] not in ("travel", "entertainment"):
        print("常规费用走统一流程")
        return
    
    amount = expense["amount"]
    is_high_value = amount > 10000
    is_mid_value = amount > 5000
    
    # 核心逻辑：高额和普通金额的区别
    if is_high_value:
        if expense["urgent"]:
            print("需要 CEO 紧急审批")
        else:
            print("需要 CFO 审批")
        return
    
    # 核心逻辑：中低额度的审批
    if expense["has_receipt"]:
        if is_mid_value:
            print("部门经理审批 + 财务备案")
        else:
            print("部门经理直接审批")
    else:
        print("请补交凭证后再提交")


# 测试
expenses = [
    {"amount": 15000, "category": "travel", "urgent": True, "has_receipt": True},
    {"amount": 8000, "category": "travel", "urgent": False, "has_receipt": True},
    {"amount": 3000, "category": "travel", "urgent": False, "has_receipt": False},
    {"amount": 500, "category": "office_supplies", "urgent": False, "has_receipt": True},
    {"amount": -100, "category": "travel", "urgent": False, "has_receipt": True},
]

for i, expense in enumerate(expenses, 1):
    print(f"\n--- 报销单 {i} ---")
    approve_expense_v2(expense)
```

**使用 and/or 合并嵌套条件**

有些嵌套条件可以用逻辑运算符合并来减少缩进层级：

```python
# 场景：判断用户是否可以执行某个操作

def can_execute_action_v1(user, resource):
    """深层嵌套写法"""
    if user is not None:
        if user.get("is_active", False):
            if resource.get("requires_admin", False):
                if user.get("is_admin", False):
                    return True
                else:
                    return False
            else:
                return True
        else:
            return False
    else:
        return False


def can_execute_action_v2(user, resource):
    """用 and 合并条件（推荐）"""
    return (
        user is not None
        and user.get("is_active", False)
        and (
            not resource.get("requires_admin", False)
            or user.get("is_admin", False)
        )
    )


# 测试
users = [
    {"name": "Alice", "is_active": True, "is_admin": True},
    {"name": "Bob", "is_active": True, "is_admin": False},
    {"name": "Charlie", "is_active": False, "is_admin": True},
    None,
]

resources = [
    {"name": "普通文档", "requires_admin": False},
    {"name": "系统配置", "requires_admin": True},
]

for user in users:
    for resource in resources:
        user_name = user["name"] if user else "None"
        result_v2 = can_execute_action_v2(user, resource)
        print(f"用户 {user_name:<8} 对「{resource['name']}」: {'允许' if result_v2 else '拒绝'}")

# 输出：
# 用户 Alice    对「普通文档」: 允许
# 用户 Alice    对「系统配置」: 允许
# 用户 Bob      对「普通文档」: 允许
# 用户 Bob      对「系统配置」: 拒绝（非管理员）
# 用户 Charlie  对「普通文档」: 拒绝（未激活）
# 用户 Charlie  对「系统配置」: 拒绝（未激活）
# 用户 None     对「普通文档」: 拒绝（用户为 None）
# 用户 None     对「系统配置」: 拒绝（用户为 None）
```

两种实现的功能完全相同，但 `v2` 的扁平结构更容易追踪逻辑路径。

## 3. 最佳实践

### 3.1 使用 in 替代多个 or 条件

当需要判断一个值是否等于多个可能值之一时，使用 `in` 替代多个 `or`：

```python
# 场景：判断字符是否为元音

# 不推荐：多个 or 条件
def is_vowel_v1(ch):
    if ch == 'a' or ch == 'e' or ch == 'i' or ch == 'o' or ch == 'u':
        return True
    return False

# 推荐：使用 in
def is_vowel_v2(ch):
    return ch in ('a', 'e', 'i', 'o', 'u')

# 测试
test_chars = ['a', 'b', 'e', 'z', 'o']
for ch in test_chars:
    print(f"'{ch}' 是元音？{is_vowel_v2(ch)}")

# 输出：
# 'a' 是元音？True
# 'b' 是元音？False
# 'e' 是元音？True
# 'z' 是元音？False
# 'o' 是元音？True
```

`in` 的可读性远高于多个 `or` 串联，尤其在候选数量较多时。

### 3.2 避免在条件中使用 True/False 的显式比较

```python
# 场景：检查标志位

# 不推荐：显式比较
flag = True
if flag == True:          # 啰嗦，多余
    print("flag 为真")

# 推荐：直接使用对象本身
if flag:                  # 简洁
    print("flag 为真")

# 不推荐：显式比较 None
value = None
if value == None:         # 问题：== 比较值，None 是单例应用用 is
    print("值为空")

# 推荐：使用 is None
if value is None:         # 正确的方式
    print("值为空")

# 输出（两对）：
# flag 为真
# 值为空
# 值为空
```

### 3.3 使用 is 而不是 == 比较 None

`None` 是 Python 中的单例对象，比较时应使用 `is` 而不是 `==`：

```python
# 场景：检查函数返回值是否为 None

def find_user(user_id):
    """模拟查找用户——返回 None 表示未找到"""
    db = {1: "Alice", 2: "Bob"}
    return db.get(user_id)


user = find_user(3)

# 不推荐
if user == None:
    print("用户未找到")

# 推荐
if user is None:
    print("用户未找到")

# 输出（两者相同，但 is 更快且语义更准确）：
# 用户未找到
# 用户未找到
```

`==` 会调用 `__eq__` 方法，而 `is` 直接比较对象内存地址。对于 `None` 这种单例，`is` 是标准做法。

### 3.4 避免误用 = 代替 ==

这是 Python 初学者最容易犯的错误之一——在条件表达式中把 `=`（赋值）误写为 `==`（相等比较）：

```python
# 常见的错误
# 下面这行会报语法错误，因为 Python 不允许在条件中使用赋值表达式
# if score = 100:   # SyntaxError: invalid syntax
#     print("满分！")

# Python 3.8+ 引入了海象运算符（:=）允许在表达式中赋值
# 但不要在 if 条件中滥用
if (score := 100) == 100:  # 合法但可读性差
    print("满分！")

# 更清晰的写法
score = 100
if score == 100:
    print("满分！")

# 输出（两行，确保两种方式都输出）：
# 满分！
# 满分！
```

### 3.5 用字典替代长链 if-elif-else

当条件是对几种固定值的匹配时，可以用字典映射替代 `if-elif-else` 链：

```python
# 场景：根据状态码返回对应消息

# 写法一：if-elif-else 链（可读性一般）
def get_status_message_v1(code):
    if code == 0:
        return "成功"
    elif code == 1:
        return "部分成功"
    elif code == 2:
        return "失败"
    elif code == 3:
        return "超时"
    else:
        return f"未知状态：{code}"


# 写法二：字典映射（推荐，尤其是映射项很多时）
STATUS_MESSAGES = {
    0: "成功",
    1: "部分成功",
    2: "失败",
    3: "超时",
}

def get_status_message_v2(code):
    return STATUS_MESSAGES.get(code, f"未知状态：{code}")


# 测试两种方式是否一致
test_codes = [0, 1, 2, 3, 4, -1]
for code in test_codes:
    msg1 = get_status_message_v1(code)
    msg2 = get_status_message_v2(code)
    print(f"状态码 {code}: {msg1}")
    assert msg1 == msg2, f"不一致：{code}"

# 输出：
# 状态码 0: 成功
# 状态码 1: 部分成功
# 状态码 2: 失败
# 状态码 3: 超时
# 状态码 4: 未知状态：4
# 状态码 -1: 未知状态：-1
```

字典方式不仅代码更短，而且将"映射关系"和"取值逻辑"分离开来——映射关系集中定义，取值逻辑统一通过 `.get()` 完成。

### 3.6 优先使用正条件

在编写条件时，尽量使用肯定的判断而非否定：

```python
# 场景：处理用户登录

# 不推荐：多次取反，增加理解负担
def process_login_v1(user):
    if not user:
        return "用户不存在"
    if not user.get("is_active"):
        return "账号未激活"
    if not user.get("verified"):
        return "邮箱未验证"
    return "登录成功"


# 推荐：正面条件，直接阅读
def process_login_v2(user):
    if user is None:
        return "用户不存在"
    if user.get("is_active") is False:
        return "账号未激活"
    if user.get("verified") is False:
        return "邮箱未验证"
    return "登录成功"


# 测试
test_users = [
    None,
    {"is_active": False, "verified": True},
    {"is_active": True, "verified": False},
    {"is_active": True, "verified": True},
]

for user in test_users:
    print(process_login_v2(user))

# 输出：
# 用户不存在
# 账号未激活
# 邮箱未验证
# 登录成功
```

### 3.7 避免使用双重否定

```python
# 场景：检查是否可访问

# 不推荐：双重否定，难以理解
if not not authorized:
    print("已授权")

# 推荐：直接使用
if authorized:
    print("已授权")

# 不推荐：not 多层嵌套
# if not (not user and not valid):

# 推荐：化简后
```

### 3.8 常见陷阱总结

**陷阱一：== 与 is 的混淆**

```python
# == 比较的是"值"，is 比较的是"身份"（内存地址）

# 对于整数缓存池内的小整数（-5 到 256），两个相等的小整数可能指向同一个对象
a = 256
b = 256
print(f"a is b: {a is b}")      # True（因为小整数缓存）
print(f"a == b: {a == b}")      # True

# 超出缓存范围，即使值相同也可能是不同对象
x = 1000
y = 1000
print(f"x is y: {x is y}")      # False（不同对象）
print(f"x == y: {x == y}")      # True

# 建议：比较数值用 ==，比较 None / 单例用 is
```

**陷阱二：可变对象作为默认参数的真值陷阱**

```python
# 场景：函数使用可变对象作为默认参数
def add_item_v1(item, target_list=[]):
    """常见陷阱：可变默认参数"""
    if not target_list:        # 真值判断：空列表为 False
        print("初始化新列表")
    target_list.append(item)
    return target_list


# 第一次调用
result1 = add_item_v1("苹果")
print(f"第一次结果：{result1}")
# 输出：初始化新列表
# 第一次结果：['苹果']

# 第二次调用——出问题了！
result2 = add_item_v1("香蕉")
print(f"第二次结果：{result2}")
# 输出：（没有打印"初始化新列表"！）
# 第二次结果：['苹果', '香蕉']
# target_list 已经不是空列表了，真值判断为 True，所以没有打印

# 正确的写法：使用 None 作为默认值
def add_item_v2(item, target_list=None):
    """推荐写法"""
    if target_list is None:   # 注意：用 is 比较 None，而不是判断真值
        print("初始化新列表")
        target_list = []
    target_list.append(item)
    return target_list


# 重新测试
result3 = add_item_v2("苹果")
print(f"第一次结果：{result3}")
result4 = add_item_v2("香蕉")
print(f"第二次结果：{result4}")

# 输出：
# 初始化新列表
# 第一次结果：['苹果']
# 初始化新列表
# 第二次结果：['香蕉']
```

**陷阱三：链式比较的意外行为**

```python
# 场景：链式比较中的条件求值

# 错误的直觉
print(f"3 == 3 == True: {3 == 3 == True}")
# 输出：False
# 为什么？因为它是链式比较，等价于 (3 == 3) and (3 == True)
# 3 == 3 为 True
# 3 == True 为 False（True 被视为 1，3 != 1）

# 正确的对比：
print(f"(3 == 3) == True: {(3 == 3) == True}")
# 输出：True
# 因为先计算 (3 == 3) 得到 True，再比较 True == True

# 另一个常见陷阱：链式比较中误用 !=
a, b, c = 1, 2, 3
print(f"a < b != c: {a < b != c}")
# 等价于 a < b and b != c → 1 < 2 and 2 != 3 → True and True → True
```

**陷阱四：空集合类型的真值判断**

```python
# 场景：处理允许空值的集合

# 空字符串在某些场景下是合法的值
username = ""

# 错误写法：将空字符串也当作"未提供"
if not username:
    print("提示用户必须输入用户名")
# 输出：提示用户必须输入用户名（但用户可能"知道自己在做什么"）

# 正确的做法：区分"空"和"未提供"
username = ""  # 用户明确清空了输入

if username is None:  # 只有 None 表示未提供
    print("提示用户必须输入用户名")
else:
    print(f"用户输入：{username!r}")
# 输出：用户输入：''（空字符串被视为有效输入）

# 类似地：购物车数量为 0 是合法状态
cart_count = 0
if cart_count is not None:
    print(f"购物车有 {cart_count} 件商品")
else:
    print("购物车数据加载中……")
# 输出：购物车有 0 件商品
```

## 4. 原理

### 4.1 条件判断语句的本质

Python 条件判断的底层工作流程如下：

1. **表达式求值**：对 `if` 关键字后面的表达式进行求值，得到一个结果对象。
2. **布尔转换**：隐式调用 `bool()` 函数将结果对象转换为布尔值（`True` 或 `False`）。
3. **分支跳转**：根据布尔值决定跳转到哪个代码块执行。

这一过程对应的是 CPython 字节码中的 `JUMP_IF_FALSE_OR_POP`、`JUMP_ABSOLUTE` 等指令。

**从字节码层面理解**

```python
# 演示：通过 dis 模块查看 if 语句生成的字节码
import dis

def simple_if():
    x = 10
    if x > 5:
        print("大于 5")
    else:
        print("小于等于 5")

print("simple_if 的字节码：")
dis.dis(simple_if)

# 输出：
#   2           0 RESUME                   0
# 
#   3           2 LOAD_CONST               1 (10)
#               4 STORE_FAST               0 (x)
# 
#   4           6 LOAD_FAST                0 (x)
#               8 LOAD_CONST               2 (5)
#              10 COMPARE_OP               4 (>)
#              12 POP_JUMP_IF_FALSE       22 (to 44)
# 
#   5          14 LOAD_GLOBAL              1 (NULL + print)
#              26 LOAD_CONST               3 ('大于 5')
#              28 CALL                     1
#              36 POP_TOP
#              38 LOAD_CONST               0 (None)
#              40 RETURN_VALUE
# 
#   7     >>   42 LOAD_GLOBAL              1 (NULL + print)
#              54 LOAD_CONST               4 ('小于等于 5')
#              56 CALL                     1
#              64 POP_TOP
#              66 LOAD_CONST               0 (None)
#              68 RETURN_VALUE
```

关键字节码指令的含义：
- `LOAD_CONST` / `LOAD_FAST`：将变量或常量加载到栈上。
- `COMPARE_OP`：执行比较操作，将结果推入栈。
- `POP_JUMP_IF_FALSE`：弹出栈顶值，如果为 `False` 则跳转到指定偏移量（这里是 22，对应 `else` 分支的起始位置）。
- 如果栈顶值为 `True`，则继续执行 `if` 分支的代码。

### 4.2 bool() 函数的底层行为

`bool()` 函数本质上调用对象的 `__bool__()` 方法。如果对象没有实现 `__bool__()`，则退而调用 `__len__()`；如果两者都没有实现，则默认返回 `True`。

```python
# 展示 bool() 的底层调用链
class DemoNoMethods:
    """没有实现 __bool__ 和 __len__——默认真"""
    pass

class DemoWithLen:
    """只实现了 __len__——通过长度判断真值"""
    def __len__(self):
        return 0

class DemoWithBool:
    """实现了 __bool__——优先使用 __bool__"""
    def __bool__(self):
        return True

    def __len__(self):
        return 0  # 即使长度为 0，也使用 __bool__ 的结果

# 测试三个类
print(f"DemoNoMethods: bool() = {bool(DemoNoMethods())}")
# 输出：DemoNoMethods: bool() = True

print(f"DemoWithLen: bool() = {bool(DemoWithLen())}")
# 输出：DemoWithLen: bool() = False（因为 __len__ 返回 0）

print(f"DemoWithBool: bool() = {bool(DemoWithBool())}")
# 输出：DemoWithBool: bool() = True（使用了 __bool__）

# 验证调用优先级
print(f"bool([]): {bool([])}")      # False，因为 __len__ 返回 0
print(f"bool([1]): {bool([1])}")    # True，因为 __len__ 返回 1
```

### 4.3 短路求值的字节码实现

```python
# 通过字节码观察 and 和 or 的短路行为
import dis

def demo_short_circuit_and():
    a = 0
    b = 1
    return a and b  # 短路——b 不会被求值

def demo_short_circuit_or():
    a = 1
    b = 2
    return a or b  # 短路——b 不会被求值


print("and 短路的字节码：")
dis.dis(demo_short_circuit_and)

print("\nor 短路的字节码：")
dis.dis(demo_short_circuit_or)
```

`and` 和 `or` 的实现使用了类似的机制——计算出左侧操作数后，根据结果直接决定是否继续求值右侧操作数，如果不需求值则直接跳转。

### 4.4 链式比较的底层实现

链式比较在语法解析阶段被展开为 `and` 连接，但有一个关键区别：**每个操作数只被求值一次**。

```python
# 展示链式比较的单次求值特性
counter = [0]

def get_value():
    """调用一次就让计数加 1"""
    counter[0] += 1
    return 3

counter[0] = 0
result = 1 < get_value() < 10
print(f"get_value 被调用次数：{counter[0]}，结果：{result}")
# 输出：get_value 被调用次数：1，结果：True

# 对比手动展开和不短路的写法
counter[0] = 0
result_manual = 1 < get_value() and get_value() < 10
print(f"手动展开后 get_value 被调用次数：{counter[0]}，结果：{result_manual}")
# 输出：手动展开后 get_value 被调用次数：2，结果：True
# 第二种写法中 get_value 被调用了两次！
```

链式比较在这个细节上优于手动展开的 `and` 写法。

### 4.5 match-case 语句的底层原理（简要）

`match-case` 语句（Python 3.10+）在底层实现上比 `if-elif-else` 复杂得多。它并不是简单的语法糖，而是引入了新的字节码指令（如 `MATCH_KEYS`、`MATCH_CLASS`、`MATCH_MAPPING`、`MATCH_SEQUENCE` 等）来支持模式匹配。

每个 `case` 分支在字节码层面被编译为一系列匹配指令，逐个尝试直到命中一个模式。由于增加了解包和类型检查的指令开销，在极短路径上 `match-case` 可能比 `if-elif-else` 稍慢，但实际影响可以忽略不计。

## 5. 总结

本文全面讲解了 Python 中条件判断相关的所有核心内容，从最基本的 `if` 语句到 Python 3.10 的 `match-case` 结构模式匹配。

- **`if` 语句**：单分支，条件为真时执行代码块。
- **`if-else` 语句**：双分支，二选一的分支结构。
- **`if-elif-else` 语句**：多分支，从上到下依次判断，最多执行一个分支。
- **条件表达式（三元运算符）**：`x if cond else y`，在表达式中完成条件判断。
- **真值判断**：`None`、`0`、空容器等在布尔上下文中被视为 `False`，其余为 `True`。
- **短路求值**：`and` 和 `or` 在确定结果后停止后续求值。
- **链式比较**：`a < b < c` 等价于 `a < b and b < c`，但每个操作数只求值一次。
- **多条件组合**：`and`、`or`、`not` 的优先级与使用，建议用括号明确定义。
- **`match-case` 语句**：Python 3.10+ 的结构模式匹配，适用于解包和结构匹配场景。
- **嵌套条件**：减少嵌套层数、使用守卫子句是提升可读性的关键实践。
- **常见陷阱**：`==` vs `is`、误用 `=` 代替 `==`、默认参数的可变对象真值。
