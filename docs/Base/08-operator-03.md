# 赋值与复合赋值运算符

## 1. 介绍

### 1.1 什么是赋值与复合赋值运算符

赋值，是把一个值绑定到一个名字（变量）上的操作；复合赋值，是"先做一次运算，再把结果赋回原变量"的简写。`score = 88` 是普通赋值，`total += 50` 是复合赋值——后者等价于 `total = total + 50`，但写起来更短、意图更清晰。

在 Python 里，赋值运算符的覆盖面比看起来更广：除了最常见的 `=` 和一整套算术复合赋值（`+=` `-=` `*=` `/=` `//=` `%=` `**=`），还有位运算复合赋值（`&=` `|=` `^=` `<<=` `>>=`、外加矩阵乘 `@=`），再加上多重赋值、元组解包、星号解包这些"一次给多个变量"的写法。算下来，赋值家族的成员并不少。

### 1.2 解决什么问题

赋值解决的是"把计算结果存起来，之后还能用"的问题：没有赋值，每算出一个值就只能当场打印或丢弃；有了赋值，值可以绑到名字上反复使用。复合赋值解决的是"在原值基础上更新"的简写需求——计数器累加、库存扣减、权限位翻转、缓冲区追加，这些"读旧值、算新值、写回"的模式用复合赋值一行就能表达，少打几个字、也少一次把变量名写两遍的出错机会。

### 1.3 最简示例

先用一个最小例子，把普通赋值和复合赋值对照看一眼：

```python
total = 100        # 普通赋值：把 100 绑定到 total
total += 50        # 复合赋值：等价于 total = total + 50
print(total)
```

运行结果：

```text
150
```

`total += 50` 这一行，读作"给 total 加上 50 再写回 total"。复合赋值让"自更新"这个高频动作变得紧凑。下面逐类拆开讲。

### 1.4 运算符总览表

```text
赋值运算符家族
├── 普通赋值        =          → 绑定值到变量
├── 算术复合赋值
│     +=  -=  *=  /=  //=  %=  **=
├── 位运算复合赋值
│     &=  |=  ^=  <<=  >>=  @=（矩阵乘复合）
├── 多重/链式赋值   a = b = c = 0   → 多名同值
├── 解包赋值
│     元组解包   a, b = 1, 2
│     星号解包   a, *rest = seq
│     交换       a, b = b, a
└── 赋值表达式（海象运算符） :=     → 赋值同时返回值
```

复合赋值有一个共同的规律：`X op= Y` 在语义上约等于 `X = X op Y`，但底层会优先尝试"就地修改"（in-place），这对可变类型会产生力和语义上的差别，是原理章节的重点。先把这张总览表记住，后面逐个展开。

## 2. 核心内容

### 2.1 普通赋值 `=`

普通赋值把右侧表达式求值的结果，绑定到左侧的名字上。如果这个名字已存在，就让它指向新对象（重新绑定）；如果不存在，就新建。

**行为**：`name = 表达式`——先求右侧，再把结果绑定给左侧名字。Python 的赋值是"绑定引用"而非"拷贝值"，名字指向对象本身。

**示例**

```python
score = 88             # 新建名字 score，指向 88
name = "Ada"           # 新建名字 name，指向字符串对象
score = 95             # 重新绑定 score，指向 95
print(f"score={score}, name={name}")
```

**运行结果**：

```text
score=95, name=Ada
```

**关键点**：赋值是"让名字指向对象"，不是"把对象复制进名字占的盒子"。这意味着多个名字可以指向同一个对象——这是后面多重赋值和解包会产生"别名陷阱"的根源。还要记住一条：`=` 是**语句**，没有返回值，不能当作表达式用在 `print(x = 5)` 这种位置；想"赋值同时拿到值"要用 2.8 节的海象运算符。

### 2.2 算术复合赋值 `+=` `-=` `*=` `/=` `//=` `%=` `**=`

算术复合赋值把七种算术运算各对应一个"自更新"版本：读旧值、做运算、写回。它们让计数、累加、扣减、均摊、整除取余、幂次自乘等操作一行写完。

**签名与等价关系**：`X op= Y` 约等于 `X = X op Y`，但底层优先就地修改（见原理章）。下面逐个看：

```python
total = 100
total += 50          # 加法复合：total = total + 50
print(f"100 += 50 -> {total}")

stock = 50
stock -= 17          # 减法复合：库存扣减
print(f"50 -= 17 -> {stock}")

price = 19.9
price *= 3           # 乘法复合：单价涨 3 倍
print(f"19.9 *= 3 -> {price}")

avg = 90
avg /= 3             # 真除法复合：三人平均
print(f"90 /= 3 -> {avg}（结果 float）")

pages = 23
pages //= 5          # 整除复合
print(f"23 //= 5 -> {pages}")

second = 7384
second %= 60         # 取余复合：取秒数余数
print(f"7384 %= 60 -> {second}")

base = 2
base **= 10          # 幂复合：求 2 的 10 次方
print(f"2 **= 10 -> {base}")
```

**运行结果**：

```text
100 += 50 -> 150
50 -= 17 -> 33
19.9 *= 3 -> 59.699999999999996
90 /= 3 -> 30.0（结果 float）
23 //= 5 -> 4
7384 %= 60 -> 4
2 **= 10 -> 1024
```

**关键点**：复合赋值的语义和"运算后再赋值"一致，但要注意三件事。其一，`/=` 永远产生 `float`（因为 `/` 是真除法），即使能整除也是 `90 /= 3 → 30.0`，需要整数结果用 `//=`。其二，浮点复合赋值同样有精度尾巴，`19.9 *= 3` 得到 `59.699999999999996`，处理金额要避免用 `float` 复合赋值累积误差。其三，也是最重要的一点——对可变类型（如列表），`+=` 是**就地修改**而非重新绑定，会副作用到所有引用同一对象的别名，这条放在原理章详细展开。

### 2.3 位运算复合赋值 `&=` `|=` `^=` `<<=` `>>=`

位运算复合赋值把五种位运算各自配一个自更新形式，外加矩阵乘复合 `@=`。它们最常用于位标志（权限位、状态位）的置位、清除、翻转和移位。

**示例**

用权限位模拟"置位、清除、翻转、移位"四类操作：

```python
# &= 按位与：用掩码保留/清除指定位
flags = 0b1010
flags &= 0b1110      # 掩码清掉最低位（最低位本来是 0，保持 0）
print(f"0b1010 &= 0b1110 -> {bin(flags)}")

# |= 按位或：给最低位置 1（添加权限）
flags = 0b1010
flags |= 0b0001
print(f"0b1010 |= 0b0001 -> {bin(flags)}")

# ^= 按位异或：翻转低两位
flags = 0b1010
flags ^= 0b0011
print(f"0b1010 ^= 0b0011 -> {bin(flags)}")

# <<= 左移：数值翻倍（低位补 0）
val = 1
val <<= 4           # 等价于 *2**4
print(f"1 <<= 4 -> {val}")

# >>= 右移：数值减半（高位补符号位）
val = 256
val >>= 3           # 等价于 //2**3
print(f"256 >>= 3 -> {val}")
```

**运行结果**：

```text
0b1010 &= 0b1110 -> 0b1010
0b1010 |= 0b0001 -> 0b1011
0b1010 ^= 0b0011 -> 0b1001
1 <<= 4 -> 16
256 >>= 3 -> 32
```

**关键点**：位运算复合赋值都是对整数就地运算后重新绑定（int 不可变，所以是产生新 int 再绑定）。`@=` 是矩阵乘复合赋值，需要类型实现 `__imatmul__`，主要用于 `numpy` 等数值库，标准库场景很少用到，了解即可。位运算本身的工作细节（补码、掩码设计）属于位运算主题，这里聚焦的是"复合赋值"那一层：`flags |= 0b0001` 就是"在原值上按位或、再写回 flags"的简写。

### 2.4 多重赋值与链式赋值

多重赋值（也叫链式赋值）用一行给多个名字绑定同一个值：`a = b = c = 0`。它的求值顺序是"先算最右侧，再依次绑定给左边的名字"。

**示例**

```python
a = b = c = 0
print(f"a={a}, b={b}, c={c}")

a = 10
print(f"a 改 10 后：a={a}, b={b}, c={c}    # int 不可变，互不影响")
```

**运行结果**：

```text
a=0, b=0, c=0
a 改 10 后：a=10, b=0, c=0    # int 不可变，互不影响
```

**关键点**：对不可变类型（int、str、tuple），链式赋值很安全——任何一个名字被重新赋值，只是让它指向新对象，其余名字仍指向旧对象，互不影响。但可变类型是另一回事：

```python
list_a = list_b = []        # 同一个列表对象，两个名字
list_a.append(1)           # 通过一个名字就地改
print(f"list_a 追加后：list_a={list_a}, list_b={list_b}")
print(f"是同一对象？{list_a is list_b}")
```

运行结果：

```text
list_a 追加后：list_a=[1], list_b=[1]
是同一对象？True
```

`list_a` 和 `list_b` 指向同一个空列表，通过任意一个名字追加，另一个名字看到的列表也变了——它们本就是同一个对象。想要两个独立的列表，必须各自构造：

```python
safe_a = []
safe_b = []
safe_a.append(1)
print(f"独立构造：safe_a={safe_a}, safe_b={safe_b}")
```

运行结果：

```text
独立构造：safe_a=[1], safe_b=[]
```

这条"链式赋值给可变类型会共享对象"的坑，是多重赋值最需要记住的一点。

### 2.5 元组解包赋值

元组解包赋值把右侧一个序列按位置"拆"给左侧多个名字，是一行给多个变量赋不同值的标准写法。它最常用于接收函数的多返回值。

**示例**

```python
name, age = "Ada", 30
print(f"name={name}, age={age}")

def min_max(nums):
    return min(nums), max(nums)

lo, hi = min_max([3, 7, 1, 9])
print(f"最小={lo}, 最大={hi}")
```

**运行结果**：

```text
name=Ada, age=30
最小=1, 最大=9
```

**关键点**：解包的本质是"右侧序列的元素按位置对应左侧名字"。数量必须一致，否则报错：

```python
# a, b = [1, 2, 3]   # ValueError: too many values to unpack
# a, b, c = [1, 2]   # ValueError: not enough values to unpack
```

解包还能用于不需要临时变量的交换——这是 Python 的招牌写法：

```python
x, y = 1, 2
x, y = y, x
print(f"交换后 x={x}, y={y}")
```

运行结果：

```text
交换后 x=2, y=1
```

`x, y = y, x` 之所以安全，是因为右侧 `y, x` 先被打包成一个元组求值，再一次性解包给左侧，不存在"先改 x 导致 y 读错"的中间状态。这在很多语言里要靠临时变量三步走才能实现。

### 2.6 星号解包赋值

星号解包用 `*名字` 收集"剩余的多个元素"到一个列表里，让解包不必精确数个数。它在取首尾、切片语义、读取可变长参数时特别有用。

**示例**

```python
first, *middle, last = [1, 2, 3, 4, 5]
print(f"first={first}, middle={middle}, last={last}")

head, *_, tail = "abcdef"
print(f"head={head}, tail={tail}")
```

**运行结果**：

```text
first=1, middle=[2, 3, 4], last=5
head=a, tail=f
```

**关键点**：带 `*` 的名字收集到的一定是 `list`，无论原序列是元组、字符串还是 range；而且一条语句里 `*名字` 只能出现一次（Python 3 扩展解包规则）。`*_` 是一个常见惯用法——用下划线表示"这些我不要，丢弃"，只关心头和尾。解包嵌套结构时也支持匹配：

```python
(x1, y1), (x2, y2) = (1, 2), (3, 4)
print(f"两点坐标：({x1},{y1}) 与 ({x2},{y2})")
```

运行结果：

```text
两点坐标：(1,2) 与 (3,4)
```

对字典解包默认拿到的是键，要显式拿值用 `.values()`、拿键值对用 `.items()`：

```python
d = {"a": 1, "b": 2}
k1, k2 = d
print(f"键：{k1}, {k2}")
v1, v2 = d.values()
print(f"值：{v1}, {v2}")
```

运行结果：

```text
键：a, b
值：1, 2
```

### 2.7 交换赋值

交换赋值本质上就是元组解包的一个特例——把右侧变量打包成元组、再解包给左侧，顺序自然就交换了。它值得单独拎出来讲，是因为它是一个"既方便又容易写错"的高频写法。

**示例**

```python
# 两个变量交换
x, y = 1, 2
x, y = y, x
print(f"x={x}, y={y}")

# 三个变量循环交换：a→b→c→a
a, b, c = 1, 2, 3
a, b, c = c, a, b
print(f"a={a}, b={b}, c={c}")
```

运行结果：

```text
x=2, y=1
a=3, b=1, c=2
```

**关键点**：`a, b, c = c, a, b` 这种"环形交换"用临时变量要写好几步，解包写法一行搞定，且右侧整体先求值再赋值，不会出现中间状态污染。要注意的是"右侧先打包"这一前提——交换的是名字指向的对象引用，不是值拷贝；如果交换后两个名字本就指向可变对象，通过任一名字的就地修改仍会互相影响。

### 2.8 海象运算符 `:=`（表达式式赋值）

海象运算符 `:=` 是赋值家族里一个特殊成员：它和 `=` 的核心区别在于，`:=` 是**表达式**，在赋值的同时会"返回被赋的值"，可以嵌进别的表达式里使用；而 `=` 是语句，没有返回值。

**示例**

最常见的用法是"在条件里赋值，循环体里直接用"——避免把读取表达式写两遍：

```python
text = "hello"
if (n = len(text)) > 3:     # 仅示意：= 是语句，这样写会报错
    print(n)
```

上面这个写法用的是 `=`，会直接报语法错误，因为 `=` 不能用在表达式位置。正确写法是用 `:=`：

```python
text = "hello"
if (n := len(text)) > 3:
    print(f"长度 {n} 超过 3")
```

**运行结果**：

```text
长度 5 超过 3
```

**关键点**：`:=` 读作"walrus"（双目形似海象的眼睛和牙），它让"读值—判断—再用值"三步合一。`(n := len(text))` 这个括号很关键——`:=` 的优先级极低，不加括号会被解析成 `if n := (len(text) > 3)`，含义完全不同。海象运算符的实战场景（while 读取循环、列表推导里复用值、模式匹配等）较丰富，这里只点明它"是赋值家族里唯一有返回值的成员"这个定位，理解它和 `=` 的语法边界即可。

## 3. 最佳实践

### 3.1 推荐写法 vs 不推荐写法

| 场景 | 不推荐 | 推荐 | 原因 |
|------|--------|------|------|
| 计数器自增 | `i = i + 1` | `i += 1` | 复合赋值更短、意图"自更新"更明确 |
| 给可变类型多个别名 | `a = b = []` | `a, b = [], []` | 链式赋值共享同一对象，易踩联动修改坑 |
| 接收多返回值 | `r = f(); x=r[0]; y=r[1]` | `x, y = f()` | 解包一行表达，不需手动取下标 |
| 交换两变量 | `tmp=x; x=y; y=tmp` | `x, y = y, x` | 解包交换无中间状态，更不易错 |
| 条件里复用计算结果 | `n=len(x); if n>3: use(n)` | `if (n:=len(x))>3: use(n)` | 海象避免重复计算，且作用域更集中 |
| 金额累加 | `total += 19.9` | 用 `Decimal` 累加 | 浮点复合赋值累积误差 |

先看"给可变类型多个别名"那条——链式赋值给可变对象的坑很隐蔽：

```python
# 不推荐：两个列表共享同一对象
rows = cols = []
rows.append(1)
print(cols)        # [1]，cols 也被改了
```

运行结果：

```text
[1]
```

```python
# 推荐：各自构造
rows, cols = [], []
rows.append(1)
print(rows, cols)   # [1] []
```

运行结果：

```text
[1] []
```

再看海象那条——避免重复求值的价值，在读文件、读输入场景最明显：

```python
# 不推荐：len(data) 算了两次
data = "some input"
if len(data) > 3:
    process = len(data) * 2
    print(process)
```

运行结果：

```text
10
```

```python
# 推荐：只算一次，赋值同时用
data = "some input"
if (n := len(data)) > 3:
    print(n * 2)
```

运行结果：

```text
10
```

### 3.2 常见错误模式及修正

**错误一：解包数量不匹配**

```python
# a, b = [1, 2, 3]   # ValueError: too many values to unpack
```

修正：用星号解包吸收多余元素：

```python
a, *b = [1, 2, 3]
print(f"a={a}, b={b}")    # a=1, b=[2, 3]
```

运行结果：

```text
a=1, b=[2, 3]
```

**错误二：误以为 `+=` 对所有类型都产生新对象**

```python
nums = [1, 2]
ref = nums
nums += [3]
print(ref is nums, ref)   # True [1,2,3]  ref 也变了
```

运行结果：

```text
True [1, 2, 3]
```

修正：当不想影响别名时，用 `+` 或显式返回新对象，而不用 `+=`：

```python
nums = [1, 2]
ref = nums
nums = nums + [3]      # + 创建新列表，nums 重新绑定
print(ref is nums, ref, nums)   # False [1,2] [1,2,3]
```

运行结果：

```text
False [1, 2] [1, 2, 3]
```

**错误三：函数内对参数 `+=` 副作用外溢**

```python
def grow(lst):
    lst += [99]        # 就地修改，影响调用方

data = [1, 2]
grow(data)
print(data)           # [1, 2, 99] 实参被改了
```

运行结果：

```text
[1, 2, 99]
```

修正：函数若不该改实参，要么用 `+` 返回新列表，要么约定"返回结果、不改入参"：

```python
def grow_safe(lst):
    return lst + [99]  # 不动入参，返回新列表

data2 = [1, 2]
data2 = grow_safe(data2)
print(data2)          # [1, 2, 99]
```

运行结果：

```text
[1, 2, 99]
```

### 3.3 可读性取舍

复合赋值能省字，但不是越多越好。一个原则：**当"自更新"是同类型同量纲的累加/扣减时首选复合赋值**；当左右混了不同语义（如 `total = total - penalty * rate`）时，写成复合 `total -= penalty * rate` 仍清晰，可以放心用；但若一个表达式复杂到要看半天才能还原出"原值参与的是哪种运算"，宁可拆开写或加括号。变量交换、多返回值解包这类"惯用法"，则应毫无犹豫地用解包写法——临时变量反而更绕。

性能上，对可变类型 `+=` 比 `x = x + y` 略快（就地修改省了创建新对象的成本）；对不可变类型两者基本等价（都产生新对象再绑定）。但日常写得清最重要，除非是大循环里反复累加，否则不必为这点差异改写法。

## 4. 原理

### 4.1 赋值是"绑定引用"而非"拷贝值"

Python 的变量不是装值的盒子，而是贴在对象上的标签。`a = 5` 做的是：创建（或复用）整数对象 `5`，把名字 `a` 这个标签贴到它上面。`b = a` 再贴一个标签 `b` 到同一对象。这也是为什么 `a = b = []` 会让 `a`、`b` 指向同一个列表——只有一个对象、两个标签，而不是两个空列表。

理解这点，就能解释 2.4 节可变类型链式赋值的陷阱：通过任一标签就地修改对象，其他标签看到的自然也变，因为它们看的是同一个对象。要两个独立列表，得让右侧产生两个不同对象（`a, b = [], []` 各构造一次）。

### 4.2 复合赋值的就地修改 vs 重新绑定

这是复合赋值最容易踩坑、也最需要理解的一条原理：`X op= Y` 不一定等于 `X = X op Y`。

底层上，复合赋值会优先调用类型的"就地"方法（如 `__iadd__`、`__imul__`），找不到才回退到"普通运算后重新绑定"（调用 `__add__` 等）。对不可变类型（int、str、tuple），它们没有就地方法，于是复合赋值走"算新对象、重新绑定"路径，结果和 `X = X op Y` 一致；对可变类型（list、dict 的某些运算），就地方法会**修改原对象**而不是创建新对象，于是同一个对象被改了，所有别名都受影响。

```python
# 不可变：int 的 += 重新绑定
n = 100
m = n
n += 1                  # int 不可变 → 产生新 101 → n 重新绑定
print(f"n={n}, m={m}, 同一对象? {n is m}")

# 可变：list 的 += 就地修改
nums = [1, 2]
ref = nums
nums += [3]             # list.__iadd__ 原地扩展
print(f"nums={nums}, ref={ref}, 同一对象? {nums is ref}")
```

**运行结果**：

```text
n=101, m=100, 同一对象? False
nums=[1, 2, 3], ref=[1, 2, 3], 同一对象? True
```

对比"非复合"的 `+` 对列表——它总是创建新对象：

```python
nums2 = [1, 2]
ref2 = nums2
nums2 = nums2 + [3]     # + 创建新列表 → nums2 重新绑定
print(f"nums2={nums2}, ref2={ref2}, 同一对象? {nums2 is ref2}")
```

**运行结果**：

```text
nums2=[1, 2, 3], ref2=[1, 2], 同一对象? False
```

`+=` 对列表是就地修改、`+` 对列表是产生新列表——两者对"是否影响别名"的行为完全不同。记住这条决策树：想要"就地改、所有别名可见"用 `+=`；想要"不影响别名、只要新结果"用 `+` 再赋值。函数内部尤其要当心：对入参做 `+=` 会改动调用方传入的可变对象，这是"副作用外溢"的高发地。

### 4.3 赋值是语句、海象是表达式

`=` 和 `:=` 的分工背后是 Python 的语法分类：`=` 属于语句（statement），执行"绑定"这个动作但不产生值；`:=` 属于表达式（expression），既绑定又返回被绑定的值。这解释了两条边界：

```python
# ./= 不能用在表达式位置
# print(x = 5)        # 报错：= 是语句，没有值

# := 可以用在表达式位置
print(y := 5)         # 合法：赋值同时返回 5 给 print
```

运行结果：

```text
5
```

设计上，Python 故意让 `=` 和 `:=` 长得像但归属不同：`=` 用于"语句层把结果存起来"，`:=` 弥补"想在表达式内部赋值"这个缺口（比如条件里复用计算结果）。混用了会报语法错，这是语言帮你拦住误用的一道护栏。

### 4.4 解包赋值的求值顺序

元组解包能安全交换、能接收多返回值，靠的是它的求值顺序：**右侧整体先打包求值，再一次性解包赋给左侧**。以 `x, y = y, x` 为例，先算右侧 `y, x` 打成元组 `(y原值, x原值)`，然后一次性按位置给左边 `x` 和 `y`——不存在"先给 x 赋值、再去读 y"的中间状态，所以交换是安全的。

这条顺序也解释了"为什么右侧表达式读到的是赋值前的旧值"：

```python
a = [1, 2]
i = 0
i, a[i] = 1, 99        # 右侧 (1, 99) 先打包求值，再解包
print(a)               # a[0]? 不——先赋 i=1 还是先赋 a[i]？
```

运行结果：

```text
[1, 99]
```

实际执行：右侧 `(1, 99)` 先求值成元组；解包时按从左到右依次赋值，先 `i = 1`，再 `a[i] = 99`——此时 `i` 已是 1，所以改的是 `a[1]`，结果 `[1, 99]`（原本 `a[1]` 是 2，被 99 覆盖）。这类"左值依赖左侧已赋值变量"的写法虽然能跑，但极易误读，生产代码里建议拆开写、避免依赖求值顺序的微妙之处。

## 5. 总结

本文围绕 Python 的赋值与复合赋值运算符展开，主要介绍了以下内容：

- 普通赋值 `=` 把右侧值绑定到左侧名字，赋值是"绑定引用"而非"拷贝值"，多个名字可指向同一对象
- 算术复合赋值（`+=` `-=` `*=` `/=` `//=` `%=` `**=`）是"读旧值—做运算—写回"的简写，注意 `/=` 恒得 float、浮点复合赋值有精度尾巴
- 位运算复合赋值（`&=` `|=` `^=` `<<=` `>>=`、外加 `@=`）用于权限位的置位、清除、翻转、移位等自更新
- 多重/链式赋值 `a = b = c = 0` 对不可变类型安全，对可变类型会让多个名字共享同一对象、踩联动修改的坑
- 元组解包与星号解包是一行给多变量赋值、接收多返回值、交换变量的标准写法，交换靠"右侧先打包求值再解包"保证安全
- 海象运算符 `:=` 是赋值家族里唯一有返回值的成员，可在表达式里赋值并用值，优先级极低需加括号
- 复合赋值对可变类型优先就地修改（`__iadd__` 等）、对不可变类型重新绑定，于是 `+=` 和 `= ... + ...` 对列表等可变类型行为不同，函数内对入参 `+=` 会副作用外溢
- `=` 是语句无返回值、`:=` 是表达式有返回值，混用会被语法错拦住；解包时右侧先打包求值再解包，是交换和多返回值安全的基础
