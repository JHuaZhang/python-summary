## 1. 介绍

### 1.1 什么是 property 的 setter 与 deleter

在 `@property` 的基础用法中，我们用 `@property` 装饰一个方法，使之成为一个只读的"属性"——外部可以用 `obj.x` 读取，但它对应的 getter 方法在定义时并没有提供写入和删除的能力。如果尝试 `obj.x = 10`，Python 会抛出 `AttributeError: can't set attribute`；如果尝试 `del obj.x`，同样会被拒绝。

然而，在很多真实业务场景中，我们既希望用属性语法（`obj.x = value`、`del obj.x`）来访问对象状态，又希望在赋值或删除时插入额外的逻辑——比如做范围校验、类型转换、同步内部存储、让缓存失效、释放底层资源等。直接用公开变量做不到这些，因为普通的属性赋值只是把引用换掉，没有任何中间环节。把变量改成方法（`obj.set_x(value)`）又能做到，但调用写法从优雅的 `obj.x = value` 变成了啰嗦的方法调用，失去 property 的意义。

`@x.setter` 和 `@x.deleter` 正是为解决这个矛盾而生的。它们是 `@property` 的配套装饰器：

- `@x.setter`：紧跟在 `@property` 定义的 getter 之后，装饰一个**同名方法**，使该属性变为可写。每次执行 `obj.x = value` 时，Python 不再直接替换属性，而是调用你在这个装饰器下写的方法，把 `value` 传进去，由你决定怎么存、存不存。
- `@x.deleter`：同样装饰一个**同名方法**，使该属性支持 `del obj.x`。执行 `del` 时调用你写的方法，你可以在其中做资源释放、状态清理。

把 getter、setter、deleter 三者合在一起，就构成了一个"完整 property"——对外是一个普通的属性 `x`，对内则由三个方法分别处理读、写、删，且三个方法都在你的代码掌控之下。这就是 property 区别于普通实例变量的核心价值：**属性语法保留，行为可控**。

### 1.2 基础语法与最小用法

一个包含 getter + setter 的最小 property 长这样：

```python
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius          # 内部存储用带下划线的名字

    @property
    def celsius(self):                    # getter：读取 obj.celsius 时调用
        return self._celsius

    @celsius.setter
    def celsius(self, value):             # setter：执行 obj.celsius = value 时调用
        if value < -273.15:
            raise ValueError(f"温度不能低于绝对零度：{value}")
        self._celsius = value
```

读写都走属性语法：

```python
t = Temperature(25)
print(t.celsius)       # 读 → 调 getter
# 输出：25

t.celsius = 100        # 写 → 调 setter，校验通过
print(t.celsius)
# 输出：100

t.celsius = -300       # 写 → 调 setter，校验失败
# 输出：ValueError: 温度不能低于绝对零度：-300
```

加上 deleter 后，三件套完整成形：

```python
class Temperature:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError(f"温度不能低于绝对零度：{value}")
        self._celsius = value

    @celsius.deleter
    def celsius(self):                    # deleter：执行 del obj.celsius 时调用
        print(f"清理温度状态：{self._celsius}°C")
        self._celsius = None               # 释放/清理内部存储
```

```python
t = Temperature(37)
del t.celsius            # → 调 deleter
# 输出：清理温度状态：37°C

print(t.celsius)         # getter 仍可调，读到内部已被置为 None
# 输出：None
```

注意三个关键点，它们贯穿全文：

1. `@celsius.setter`、`@celsius.deleter` 修饰的方法**必须与 getter 同名**（这里都叫 `celsius`）。
2. setter 内部要写 `self._celsius = value`，**不能写 `self.celsius = value`**，否则会再次触发 setter 形成无限递归（原因在第 4 章详述）。
3. deleter 执行后属性本身并没有从对象上消失，只是 deleter 方法里你写的清理逻辑被调用了；后续再读 `obj.celsius` 仍走 getter，返回什么取决于你在 deleter 里把内部存储置成了什么。

## 2. 核心内容

### 2.1 @x.setter：让只读属性可写

**作用**：在 `@property` 定义的 getter 基础上，追加一个写方法，使得 `obj.x = value` 不再报 `AttributeError`，而是调用你写的方法。

**签名**：`@<getter 返回的 property 对象>.setter`，装饰一个与 getter 同名的方法，方法签名为 `def x(self, value):`（只接收 `value` 一个参数）。

**何时用**：当你需要对赋值做拦截时——校验范围、限制类型、转换格式、触发副作用、同步相关字段、让缓存失效。只要"赋值时不能照单全收"，就该用 setter。

**与无 setter 的差异**：

- 无 setter：`obj.x = v` 抛 `AttributeError: can't set attribute`，属性只读。
- 有 setter：`obj.x = v` 走 setter 方法，存与不存、怎么存由方法逻辑决定。

**场景一：Temperature.celsius setter 校验范围**

温度不能低于绝对零度（-273.15°C）。用 setter 把这条物理约束固化在赋值入口：

```python
class Temperature:
    def __init__(self, celsius=0.0):
        self._celsius = None
        self.celsius = celsius        # 走 setter，保证构造时也校验

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if not isinstance(value, (int, float)):
            raise TypeError(f"温度必须是数值，收到 {type(value).__name__}")
        if value < -273.15:
            raise ValueError(f"温度不能低于绝对零度：{value}")
        self._celsius = float(value)   # 顺便做类型统一：存成 float
```

```python
t = Temperature(25)
t.celsius = 36.5
print(t.celsius)
# 输出：36.5

t.celsius = "36"          # 类型校验拦截
# 输出：TypeError: 温度必须是数值，收到 str

t.celsius = -300          # 范围校验拦截
# 输出：ValueError: 温度不能低于绝对零度：-300

t2 = Temperature(-273)    # 构造时也走 setter，边界值放行
print(t2.celsius)
# 输出：-273.0
```

这个例子体现了 setter 的三件事：**范围校验**（不低于绝对零度）、**类型校验**（必须是数值）、**类型转换**（统一存 `float`）。这些都在赋值入口一次性完成，外部调用方完全感知不到 `self._celsius` 的存在，只管用 `t.celsius = 数字`。

**场景二：Account.balance setter 拒绝负数**

账户余额不能为负——典型的业务约束。用 setter 把"拒绝非法状态"的规则固化：

```python
class Account:
    def __init__(self, owner, balance=0.0):
        self.owner = owner
        self._balance = 0.0
        self.balance = balance          # 构造时也走 setter 校验

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError(f"余额不能为负：{value}")
        self._balance = round(value, 2)  # 顺带规整为两位小数，避免浮点误差
```

```python
acc = Account("小明", 1000)
acc.balance = 800        # 正常赋值
print(acc.balance)
# 输出：800.0

acc.balance = -50        # 业务规则拦截
# 输出：ValueError: 余额不能为负：-50

acc.balance = 800.123    # 会被规整为两位小数
print(acc.balance)
# 输出：800.12
```

注意这里 setter 额外做了 `round(value, 2)`——这是 setter 的另一项典型用途：**赋值时顺带做格式规整**，保证读出来的永远是干净数据。

**场景三：Rectangle 的联动 setter**

一个矩形的 `width`、`height` 和 `area` 有关联。有时我们希望修改 `width` 时自动按比例调整 `height`，保持面积不变。这种"联动副作用"是 setter 的拿手好戏：

```python
class Rectangle:
    def __init__(self, width, height):
        self._width = 1.0
        self._height = 1.0
        self.width = width           # 走 setter
        self.height = height         # 走 setter

    @property
    def width(self):
        return self._width

    @width.setter
    def width(self, value):
        if value <= 0:
            raise ValueError("宽必须为正")
        self._width = float(value)

    @property
    def height(self):
        return self._height

    @height.setter
    def height(self, value):
        if value <= 0:
            raise ValueError("高必须为正")
        self._height = float(value)

    @property
    def area(self):                  # area 是只读的派生属性，无 setter
        return self._width * self._height
```

```python
r = Rectangle(4, 5)
print(r.width, r.height, r.area)
# 输出：4.0 5.0 20.0

r.width = 10
print(r.area)          # area 随之变化，无需手动同步
# 输出：50.0

r.area = 100           # area 无 setter，只读
# 输出：AttributeError: can't set attribute
```

`area` 只定义了 getter，没有 `@area.setter`，因此它是只读的派生属性——这正是 property 的常用模式：**可变的源字段配上只读的派生字段**，源字段写入受控，派生字段自动跟着变。

### 2.2 @x.deleter：让属性支持 del

**作用**：为 property 追加一个删除方法，使得 `del obj.x` 不报错，而是调用你写的方法。

**签名**：`@<property 对象>.deleter`，装饰与 getter 同名的方法，方法签名为 `def x(self):`（不接收额外参数）。

**何时用**：当你需要在"删除属性"时执行清理逻辑——释放底层资源（文件句柄、数据库连接、外部句柄）、清理相关状态标记、把内部存储置空、让对象进入某种"已清理"状态。如果删除属性时没有任何清理工作要做，那就**不需要**写 deleter。

**与无 deleter 的差异**：

- 无 deleter：`del obj.x` 抛 `AttributeError: can't delete attribute`。
- 有 deleter：`del obj.x` 调用 deleter 方法，做什么由你决定。

**场景：Cache.value deleter 清理底层资源**

缓存对象内部用一个字典保存数据，当外部执行 `del cache.value` 时，我们希望清空整个字典、释放占用，并打一条日志。deleter 正好做这件事：

```python
class Cache:
    def __init__(self):
        self._data = {"id": 1, "name": "demo", "token": "abc123"}

    @property
    def value(self):
        return self._data

    @value.deleter
    def value(self):
        print(f"清理缓存，释放 {len(self._data)} 个条目")
        self._data.clear()       # 清空底层数据结构
```

```python
cache = Cache()
print(cache.value)
# 输出：{'id': 1, 'name': 'demo', 'token': 'abc123'}

del cache.value                 # → 调 deleter，清理底层资源
# 输出：清理缓存，释放 3 个条目

print(cache.value)              # 再读，得到空字典（getter 还在）
# 输出：{}
```

这里要理解一个微妙之处：`del obj.x` **不会把 property 本身从类上删掉**。property 是类级别的描述符，`del obj.x` 触发的是描述符的 `__delete__` 方法，它转而调用你写的 deleter。deleter 执行完毕后，属性 `x` 仍然存在——后续读取 `obj.x` 仍走 getter，返回什么取决于你在 deleter 里把内部存储置成了什么。上例中 `self._data.clear()` 把字典清空但没删除引用，所以 `cache.value` 还能读到空字典；如果改成 `self._data = None`，那么再读会得到 `None`。

**deleter 不止是"清空"**

deleter 不一定要把数据清掉，也可以用来触发某种"失效"语义。下面的例子用一个 `valid` 标志位来表达"属性是否已失效"：

```python
class Session:
    def __init__(self, token):
        self._token = token
        self._valid = True

    @property
    def token(self):
        if not self._valid:
            raise RuntimeError("token 已失效，无法读取")
        return self._token

    @token.deleter
    def token(self):
        self._valid = False        # 标记为失效
        self._token = None         # 抹掉敏感数据
        print("token 已注销")
```

```python
s = Session("secret-xyz")
print(s.token)
# 输出：secret-xyz

del s.token                 # → 调 deleter，抹掉并标记失效
# 输出：token 已注销

print(s.token)              # 再读，getter 拦截
# 输出：RuntimeError: token 已失效，无法读取
```

这里 deleter 和 getter 配合：deleter 负责"注销"动作，getter 在注销后拒绝再读。这种"删除即失效"的设计在管理敏感凭证（密码、token、会话密钥）时很常见。

### 2.3 property 的显式三参构造：property(fget, fset, fdel)

除了用三个装饰器，还可以用 `property` 的显式构造形式一次性传入三个函数：

```python
property(fget=None, fset=None, fdel=None, doc=None)
```

- `fget`：getter 函数，签名 `fget(self)`。
- `fset`：setter 函数，签名 `fset(self, value)`。
- `fdel`：deleter 函数，签名 `fdel(self)`。
- `doc`：可选的文档字符串。

上面 Temperature 的三件套用显式构造写出来是这样：

```python
class Temperature:
    def __init__(self, celsius=0.0):
        self._celsius = None
        self.celsius = celsius

    def _get_celsius(self):
        return self._celsius

    def _set_celsius(self, value):
        if value < -273.15:
            raise ValueError(f"温度不能低于绝对零度：{value}")
        self._celsius = float(value)

    def _del_celsius(self):
        print(f"清理温度状态：{self._celsius}")
        self._celsius = None

    celsius = property(_get_celsius, _set_celsius, _del_celsius, "摄氏温度")
```

```python
t = Temperature(25)
print(t.celsius)
# 输出：25

t.celsius = 60
print(t.celsius)
# 输出：60.0

del t.celsius
# 输出：清理温度状态：60.0

print(Temperature.celsius.__doc__)   # 读 property 的 doc
# 输出：摄氏温度
```

**装饰器写法 vs 显式构造写法的对比**：

| 维度 | `@property` + `@x.setter` + `@x.deleter` | `property(fget, fset, fdel)` |
|------|------------------------------------------|------------------------------|
| 方法命名 | 三个方法同名（都叫 `x`） | 三个方法各自起名（如 `_get_x`） |
| 可读性 | 一眼看出这是同一个 property 的三面 | 需要看到底部 `property(...)` 才知归属 |
| 顺序灵活 | 必须先 `@property` 再 `.setter`/`.deleter` | 一次性传全，无顺序依赖 |
| 适用场景 | 绝大多数现代写法 | 需要用已有方法构造 property、元编程动态生成 |

日常编码推荐装饰器写法：它把 getter/setter/deleter 在视觉上聚拢成一个块，可读性最好，也是社区主流写法。显式构造则在元编程（动态拼装 property）、或把已有方法直接复用为 property 时更方便。

**只传 fget 的"只读 property"**

只传 `fget`、不传 `fset`/`fdel`，就得到一个只读 property——这正是 `@property` 单独使用时的等价形式：

```python
class Circle:
    def __init__(self, radius):
        self._radius = radius

    def _get_area(self):
        import math
        return math.pi * self._radius ** 2

    area = property(_get_area)      # 只传 fget
```

```python
c = Circle(3)
print(c.area)
# 输出：28.274333882308138

c.area = 100
# 输出：AttributeError: can't set attribute

del c.area
# 输出：AttributeError: can't delete attribute
```

可见"只读"不是因为有什么特殊标记，而是因为 `fset`/`fdel` 为 `None`，描述符的 `__set__`/`__delete__` 会抛 `AttributeError`。第 4 章会详述这条调用链。

### 2.4 getter/setter/deleter 的协作关系

property 的三个方法并不是孤立的，它们围绕同一个内部存储协作。理清这条协作链是用好 property 的关键。

```python
class Product:
    def __init__(self, name, price):
        self._name = name
        self._price = None
        self.price = price          # 构造时走 setter，触发校验

    @property
    def price(self):
        return self._price          # getter：从内部存储读

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError(f"价格不能为负：{value}")
        self._price = float(value)  # setter：写内部存储，校验+转换

    @price.deleter
    def price(self):
        self._price = None          # deleter：清空内部存储
        print("价格已清空")
```

```python
p = Product("笔记本", 5999)
print(p.price)          # ① 读 → getter
# 输出：5999.0

p.price = 4999          # ② 写 → setter，校验通过
print(p.price)
# 输出：4999.0

p.price = -1            # ③ 写 → setter，校验拦截
# 输出：ValueError: 价格不能为负：-1

del p.price             # ④ 删 → deleter，清空存储
# 输出：价格已清空

print(p.price)          # ⑤ 再读 → getter 返回 None
# 输出：None
```

协作链可归纳为：

1. **读**经 getter：从内部存储 `_price` 读出来。
2. **写**经 setter：校验、转换后写入内部存储 `_price`。
3. **删**经 deleter：清空内部存储 `_price`（但 property 本身仍在类上）。
4. 三个方法共享同一个内部存储名（`_price`），外部对 `p.price` 的所有操作都由这三个方法拦截，内部存储名 `_price` 不对外暴露。

这条协作链是 property 的"骨架"，第 4 章会把骨架背后的描述符机制讲透。

### 2.5 setter 与 __init__ 的配合

构造函数里要不要走 setter？这是初学 property 时常见的疑问。答案是：**通常要**。如果 `__init__` 里直接写 `self._price = value`，构造时就绕开了校验，那构造出的对象可能状态非法。正确做法是 `self.price = value`，让构造值也过一遍 setter：

```python
class Product:
    def __init__(self, price):
        # ❌ 错误写法：绕过 setter，构造时无校验
        # self._price = price

        # ✅ 正确写法：走 setter，构造时同样校验
        self.price = price

    @property
    def price(self):
        return self._price

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError(f"价格不能为负：{value}")
        self._price = float(value)
```

```python
Product(-10)
# 输出：ValueError: 价格不能为负：-10
```

**例外情况**：在 setter 还没准备好（比如 setter 依赖另一个还未初始化的字段）或性能极敏感的内部初始化路径中，可以在 `__init__` 里直接写 `self._x`，但这是刻意为之的内部写法，不是默认。

### 2.6 用 property 动态替换 setter/deleter

每个 `@x.setter`、`@x.deleter` 装饰器执行后，都会返回一个**新的 property 对象**，它替换了类命名空间中原来的 property。这意味着你可以拿到一个 property 对象后，在类外动态补上 setter 或 deleter：

```python
class Demo:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):
        return self._v

# 类外补 setter：拿到原来的 property，调 .setter 生成新 property，再赋回类
def _set_v(self, value):
    print(f"设置 v = {value}")
    self._v = value

Demo.v = Demo.v.setter(_set_v)
```

```python
d = Demo(1)
d.v = 2
# 输出：设置 v = 2

print(d.v)
# 输出：2
```

这种写法在元编程、混入（mixin）场景里有用：基类定义只读 property，子类或混入动态补上 setter。日常编码很少这么写，但理解它有助于把"setter/deleter 本质是生成新 property"这件事看透（第 4 章会从源码层面展开）。

## 3. 最佳实践

**setter 内部必须写 `self._内部名`，绝不能写 `self.属性名`**

这是 property 使用中最高频、后果最严重的错误。setter 里如果写 `self.celsius = value`，等于又触发了一次 setter，setter 再次执行 `self.celsius = value`，又触发……无限递归，直到 Python 栈溢出抛 `RecursionError`。

```python
class Bad:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):
        return self._v

    @v.setter
    def v(self, value):
        self.v = value         # ❌ 写的是 self.v，不是 self._v → 无限递归
```

```python
b = Bad(1)
b.v = 2
# 输出：RecursionError: maximum recursion depth exceeded
```

正确做法是 setter 内部直接写带下划线的内部存储名：

```python
class Good:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):
        return self._v

    @v.setter
    def v(self, value):
        self._v = value        # ✅ 写内部名，不触发 setter
```

这个陷阱的根因在第 4 章会从描述符 `__set__` 调用链层面完全说清。

**`@x.setter` / `@x.deleter` 的方法名必须与 getter 同名**

装饰器 `x.setter` 里的 `x` 是 getter 返回的 property 对象变量名。为了让三者绑定到同一个 property，被装饰的方法名必须与 getter 一致；否则会出现"同名 property 被 setter 破坏"或"setter 没挂上去"的怪现象。

```python
class Wrong:
    @property
    def x(self):
        return self._x

    @x.setter
    def set_x(self, value):     # ❌ 方法名 set_x ≠ x
        self._x = value
```

上面这段代码执行后，`Wrong.x` 会被替换成一个带 fset 的 property，但 `Wrong.set_x` 会变成另一个独立的 property（只读），造成类属性污染。正确写法是 `def x(self, value):`。

**只读属性就别写 setter，让 AttributeError 帮你挡住误改**

派生属性（如 `area`、`perimeter`、`total`）天然只读——它们由其他字段计算得出，外部不应该赋值。这类 property 只定义 getter 即可，让"无 setter 时赋值报 `AttributeError`"成为第一道防线：

```python
class Circle:
    def __init__(self, r):
        self._r = r

    @property
    def radius(self):
        return self._r

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("半径必须为正")
        self._r = float(value)

    @property
    def area(self):            # 只读派生属性，无 setter
        import math
        return math.pi * self._r ** 2
```

```python
c = Circle(2)
c.area = 10
# 输出：AttributeError: can't set attribute
```

**deleter 不是必选项**

很多 property 用不到 deleter。只在需要清理外部资源、或需要把对象标记为"已失效"时才写。滥加 deleter 只会增加无谓的代码，并让外部误以为 `del` 这个属性是安全的常规操作。

**setter 校验要彻底，别只校验一半**

如果 setter 只校验了范围却没校验类型，调用方传个字符串进来，setter 里的 `<` 比较会抛 `TypeError`，错误信息很不好读。推荐在范围校验前先做类型校验：

```python
@price.setter
def price(self, value):
    if not isinstance(value, (int, float)):
        raise TypeError(f"价格必须是数值，收到 {type(value).__name__}")
    if value < 0:
        raise ValueError(f"价格不能为负：{value}")
    self._price = float(value)
```

这样错误信息清晰、可定位，对调试友好。

**避免在 setter 里做耗时操作**

setter 走的是属性赋值语法 `obj.x = v`，调用方心理预期是"快"。如果在 setter 里做网络请求、数据库写入、大文件 IO，会破坏这种预期——调用方看不出一行简单的赋值背后藏着重型操作。需要重型操作时，建议显式定义方法（`obj.update_x(v)`）而非 setter，让成本在调用点上可见。

**用 doc 说明 property 的语义**

property 可以通过 getter 的 docstring 或 `property(..., doc=...)` 提供文档。对带 setter/deleter 的 property 尤其重要，因为它对外看起来像普通字段，但赋值/删除有副作用。在 doc 里写明"赋值会校验范围""删除会清空缓存"。

```python
class Temperature:
    @property
    def celsius(self):
        """摄氏温度，赋值时校验不低于绝对零度，删除会清空。"""
        return self._celsius
```

`help(Temperature)` 时这段 doc 会显示出来，是 API 自文档化的好习惯。

## 4. 原理

### 4.1 property 是数据描述符

要理解 `@x.setter` 和 `@x.deleter` 为什么能生效，必须先理解 property 的本质：它是一个**数据描述符（data descriptor）**。

描述符是实现了描述符协议的对象。协议包含三个方法：

- `__get__(self, obj, objtype=None)`：读取属性时调用。
- `__set__(self, obj, value)`：赋值属性时调用。
- `__delete__(self, obj)`：删除属性时调用。

实现了 `__get__` 的叫非数据描述符（如普通函数）；同时实现 `__get__` 和 `__set__` 的叫数据描述符。property 同时实现了三者，是数据描述符。

当你写：

```python
class C:
    @property
    def x(self):
        return self._x
```

`x` 在类 `C` 的命名空间里是一个 `property` 实例，它持有你写的 getter 方法作为 `fget`。property 的 `__get__` 会调用 `fget`，`__set__` 会调用 `fset`，`__delete__` 会调用 `fdel`。

### 4.2 属性查找顺序与描述符的拦截

Python 中 `obj.x` 的查找并非"先看实例字典再看类"。真实顺序是：

1. **数据描述符优先**：先在类（及基类）的 `__dict__` 中查找 `x`，若找到且是数据描述符（实现了 `__get__` 和 `__set__`），直接调用其 `__get__`。
2. 实例字典 `obj.__dict__['x']`。
3. 非数据描述符或类属性。
4. 抛 `AttributeError`。

因为 property 是数据描述符，它的 `__get__` 优先于实例字典，这正是 property 能拦截 `obj.x` 读取的原因。同样，赋值 `obj.x = v` 走的是数据描述符的 `__set__`，删除 `del obj.x` 走的是 `__delete__`——这就是 property 能全面拦截读、写、删的底层机制。

### 4.3 @property 干了什么

`@property` 装饰器本质是：把被装饰的函数 `f` 传给 `property(fget=f)`，生成一个 property 对象，再把这个对象赋给被装饰函数同名的类变量。

```python
@police
def x(self):
    return self._x
# 等价于
x = property(fget=x)
```

此时 property 对象的 `fset`、`fdel` 都是 `None`。所以"只读"的真相是：**`fset`/`fdel` 为 `None`，导致描述符的 `__set__`/`__delete__` 找不到回调函数，直接抛 `AttributeError`**。

### 4.4 @x.setter 生成了新 property

`@x.setter` 的精妙之处在于：它不是"修改原 property"，而是"生成一个新 property"。

`property` 类提供了 `setter`、`deleter`、`getter` 三个方法，它们的实现逻辑一致——以自身为模板，替换对应字段，复制其余字段，生成一个新 property 对象：

```python
# 语义等价的伪代码
def setter(self, fset):
    return type(self)(self.fget, fset, self.fdel, self.__doc__)
```

所以当你写：

```python
@celsius.setter
def celsius(self, value):
    ...
```

发生的事情是：

1. `def celsius(self, value)` 定义一个新函数 `celsius`（注意它覆盖了类命名空间里的名字 `celsius`）。
2. `celsius.setter` 里的 `celsius` 在装饰器求值时仍是**原来的 property 对象**（因为左值 `celsius` 直到赋值发生前，还指向原 property）。
3. `原property.setter(新函数)` 返回一个**新 property 对象**，其 `fget` 继承自原 property，`fset` 被设为新函数，`fdel` 仍为 `None`。
4. 这个新 property 被赋给类命名空间里的 `celsius`，**替换了原来的 property**。

结果是：类变量 `celsius` 现在指向一个同时带 `fget` 和 `fset` 的新 property。原 property 对象被替换掉，但它的 `fget` 被继承过来——所以 getter 不会丢。

`@x.deleter` 的逻辑完全一致，只是替换的字段从 `fset` 变成 `fdel`。

理解这点很重要：

- **装饰器顺序必须先 `@property` 后 `.setter`/`.deleter`**。因为 `.setter` 是在原 property 对象上调用的，原 property 要先由 `@property` 创建出来。
- **每个 `.setter`/`.deleter` 调用都会生成新 property**。如果你连续写 `@x.setter` 两次，第二次会基于第一次的新 property 再生成一个，最终生效的是最后一次。
- **方法名必须同名**，否则被装饰的函数名会变成一个新的类变量，和原 property 绑定不上。

### 4.5 赋值 obj.x = v 的完整调用链

结合上面的原理，赋值 `obj.x = v` 在带 setter 的 property 上完整经过：

1. Python 发现 `obj.x = v` 是属性赋值语句。
2. 查找 `type(obj)` 的 `__dict__['x']`，发现是 property（数据描述符）。
3. 调用 property 的 `__set__(obj, v)`。
4. property 的 `__set__` 内部检查 `self.fset`：
   - 若为 `None` → 抛 `AttributeError: can't set attribute`。
   - 若存在 → 调用 `self.fset(obj, v)`，即执行你写的 setter 方法。
5. setter 方法内的 `self._x = v` 把值存进实例字典的 `_x` 键。

注意第 5 步：`self._x = v` 不触发任何 property，因为 `_x` 不是 property，是普通实例属性，直接写入 `obj.__dict__['_x']`。这就是为什么 setter 内部必须用 `_x` 而不能写 `self.x = v`——后者会回到第 1 步，触发整个调用链，再次进 setter，再写 `self.x = v`……无限递归，直到 `RecursionError`。

```
obj.x = v
  → type(obj).__dict__['x'].__set__(obj, v)
    → property.__set__ 调用 self.fset(obj, v)
      → 执行你写的 setter 方法
        如果是 self._x = v   → 写入 obj.__dict__['_x']，结束  ✅
        如果是 self.x = v    → 回到 obj.x = v，再次 __set__ ...  ❌ 无限递归
```

### 4.6 del obj.x 的完整调用链

`del obj.x` 经过的是 `__delete__`：

1. Python 发现 `del obj.x` 是属性删除语句。
2. 查找 `type(obj)` 的 `__dict__['x']`，发现是 property。
3. 调用 property 的 `__delete__(obj)`。
4. property 的 `__delete__` 内部检查 `self.fdel`：
   - 若为 `None` → 抛 `AttributeError: can't delete attribute`。
   - 若存在 → 调用 `self.fdel(obj)`，即执行你写的 deleter 方法。
5. deleter 方法做你安排的清理工作（把 `_x` 置空、清字典、释放资源等）。

关键点：`del obj.x` **删的不是 property 本身**，property 还在类上。被调用的是它的 `__delete__`，转而执行你写的清理逻辑。所以 deleter 执行完，`obj.x` 读取仍然走 getter——读到的值取决于 deleter 把内部存储置成了什么。

### 4.7 setter 递归陷阱的根因与修复

把 4.5 节的递归路径放到具体代码上看：

```python
class Bad:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):                   # property v，fget = 此方法
        return self._v

    @v.setter
    def v(self, value):            # property v 被替换为带 fset 的新对象
        self.v = value             # ❌ 触发 __set__，递归
```

执行 `b.v = 2`：

1. `b.v = 2` → property `v` 的 `__set__(b, 2)` → 调 `fset(b, 2)` → 进 setter。
2. setter 里 `self.v = 2` 又是属性赋值 → `__set__(b, 2)` → 又调 `fset` → 又进 setter。
3. setter 里再次 `self.v = 2` → ……

每多一层，Python 的调用栈多一帧。Python 默认递归深度上限约 1000（`sys.getrecursionlimit()`），超出即抛 `RecursionError`。

**根因**：setter 内部写的是 `self.v`（property 名）而非 `self._v`（内部存储名），导致赋值又被描述符拦截，回到 setter 自己。

**修复**：setter 内部一律写带下划线的内部存储名。

```python
class Good:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):
        return self._v

    @v.setter
    def v(self, value):
        self._v = value           # ✅ 写内部存储，不触发 __set__
```

`self._v = value` 中的 `_v` 不是 property，是普通实例属性。赋值时直接写入 `obj.__dict__['_v']`，不经过任何描述符，调用链到此终止。

**修复后验证**：

```python
g = Good(1)
g.v = 2
print(g.v)
# 输出：2

import sys
print(sys.getrecursionlimit())    # 看一眼默认上限
# 输出：1000
```

下面给一个能直观看到递归现象的复现，用计数器在栈溢出前抓住规律：

```python
import sys

class RecursionDemo:
    def __init__(self):
        self._v = 0
        self._count = 0

    @property
    def v(self):
        return self._v

    @v.setter
    def v(self, value):
        self._count += 1
        print(f"第 {self._count} 次进 setter")
        if self._count > 5:
            print("... 显然会一直递归下去，主动停止")
            return
        self.v = value      # ❌ 故意触发递归，用于演示

try:
    r = RecursionDemo()
    r.v = 1
except RecursionError:
    print("若不主动停止，最终会抛 RecursionError")
# 输出：
# 第 1 次进 setter
# 第 2 次进 setter
# 第 3 次进 setter
# 第 4 次进 setter
# 第 5 次进 setter
# 第 6 次进 setter
# ... 显然会一直递归下去，主动停止
```

可见 `self.v = value` 会把 setter 自己又调一遍，栈一层层堆上去。修复方法只有一个：**改写内部存储名**。

### 4.8 三件套的等价性

`@property` + `@x.setter` + `@x.deleter` 与 `property(fget, fset, fdel)` 在最终效果上完全等价。两种写法最后在类命名空间里留下的都是一个 property 对象，其 `fget`/`fset`/`fdel` 三个槽位被填上对应的函数。

装饰器写法可以理解为"分三次填槽"，第一次由 `@property` 填 `fget`，第二次由 `@x.setter` 用新 property 替换并填上 `fset`，第三次由 `@x.deleter` 再替换并填上 `fdel`。显式构造则是"一次性填三个槽"。殊途同归。

可以用 `property` 对象的 `fget`、`fset`、`fdel` 属性验证这一点：

```python
class A:
    @property
    def x(self):
        return self._x

    @x.setter
    def x(self, value):
        self._x = value

    @x.deleter
    def x(self):
        del self._x

class B:
    def _get(self):
        return self._x

    def _set(self, value):
        self._x = value

    def _del(self):
        del self._x

    x = property(_get, _set, _del)
```

```python
print(A.x.fget, A.x.fset, A.x.fdel)
# 输出：<function A.x ...> <function A.x ...> <function A.x ...>

print(B.x.fget, B.x.fset, B.x.fdel)
# 输出：<function B._get ...> <function B._set ...> <function B._del ...>
```

两者结构同构，都是带满 `fget`/`fset`/`fdel` 的 property。

### 4.9 子类继承与 property 覆写

子类想给继承来的只读 property 补上 setter，或修改 setter 行为，可以在子类里重新定义整套 property。注意：不能只写 `@x.setter`——必须先在子类里用 `@property` 重新定义 getter，再挂 setter，因为装饰器依赖当前类命名空间中的 property 对象。

```python
class Base:
    def __init__(self, v):
        self._v = v

    @property
    def v(self):
        return self._v

class Child(Base):
    @property
    def v(self):                 # 子类重新定义 getter
        return self._v

    @v.setter
    def v(self, value):          # 子类补上 setter
        if value < 0:
            raise ValueError("不能为负")
        self._v = value
```

```python
c = Child(1)
c.v = 5
print(c.v)
# 输出：5

c.v = -1
# 输出：ValueError: 不能为负
```

如果在子类里只写 `@v.setter` 而不重定义 getter，Python 在装饰器求值时会找不到子类命名空间里的 `v`（因为 `v` 是从基类继承的，不在子类 `__dict__` 里），导致行为不符合预期或报错。重定义 getter 是最稳的写法。

## 5. 总结

### 5.1 本文内容要点

- `@x.setter` 装饰与 getter 同名的方法，使 property 变为可写；赋值时调你写的方法，可在其中做范围校验、类型校验、类型转换、联动副作用、缓存失效等。
- `@x.deleter` 装饰与 getter 同名的方法，使 property 支持 `del obj.x`；删除时调你写的方法，可在其中释放资源、清空内部存储、把对象标记为失效。
- 只读 property（只有 getter、无 setter）赋值会抛 `AttributeError: can't set attribute`；无 deleter 时 `del` 会抛 `can't delete attribute`，这是由 `fset`/`fdel` 为 `None` 导致的。
- 完整 property 的三件套：`@property`（填 fget）+ `@x.setter`（填 fset）+ `@x.deleter`（填 fdel），也可用 `property(fget, fset, fdel, doc)` 显式一次构造。
- setter 内部必须写 `self._内部名`，不能写 `self.属性名`，否则会再次触发 `__set__` 形成无限递归，最终 `RecursionError`。
- `@x.setter`/`@x.deleter` 的机制是：以原 property 为模板生成一个新 property，替换类命名空间中的原对象，相应的 `fset`/`fdel` 槽位被填上。
- property 是数据描述符，property 的 `__get__`/`__set__`/`__delete__` 优先于实例字典，因此读、写、删三类操作都能被拦截。
- deleter 执行后 property 本身不消失，后续读取仍走 getter，返回值取决于 deleter 把内部存储置成了什么。

### 5.2 读完后你应能掌握

- 能写出带 getter + setter + deleter 的完整 property，并说明三者各自何时被调用。
- 能用 setter 做赋值时的范围/类型校验、类型转换、派生字段联动，并用 deleter 做资源清理和状态失效。
- 能解释为什么 setter 内部写 `self.x = v` 会无限递归，并用 `self._x = v` 修复。
- 能说明 `@x.setter` 生成新 property 的原理，以及为什么方法名必须与 getter 同名。
- 能解释 `obj.x = v` 和 `del obj.x` 经描述符 `__set__`/`__delete__` 调用 `fset`/`fdel` 的完整调用链。
- 能在装饰器写法和 `property(fget, fset, fdel)` 显式构造写法之间根据场景选择，并在子类中正确覆写带 setter 的 property。
