# 循环结构概述与基本概念

## 1. 介绍

### 1.1 什么是循环结构

写程序时经常遇到这样的情况：同一个动作要做很多遍——给 40 个学生逐个打招呼、把 100 条成绩逐个加进总分、把一段文字里每个字符逐个检查一遍。如果每一遍都亲手写一遍代码，程序会又长又难维护。**循环结构（loop）** 就是 Python 为"重复"准备的解决方案：它让你**只描述一次"要做的是什么"，再告诉 Python 重复多少次或什么时候停，剩下的重复交给语言本身去完成**。

更正式地说，循环结构是程序三大控制结构之一：它控制一段代码**被反复执行**，直到某个条件不再成立、或某个数据被取完为止。它和顺序结构（从上到下逐行执行）、选择结构（按条件挑一条路走）并列，共同构成一切程序逻辑的骨架。

**类比**：把循环想象成音乐播放器的"单曲循环"模式——你只按一次播放键（写一次代码），歌就会被反复播放（代码被反复执行），直到你喊停（终止条件成立）。没有循环的世界里，想听十遍就得亲手按十次播放键：每听一遍都得重新点一次——这正是"复制粘贴式编程"的困境。

在 Python 中，循环结构属于"控制流"（control flow）——它管的不是"数据是什么"，而是"程序以什么节奏、什么方式跑"。

### 1.2 为什么需要循环结构

空说不足为凭，直接看一个没有循环的世界。假设班里五个学生，需要向每个人打招呼：

```python
students = ["小明", "小红", "小刚", "小丽", "小强"]

print(f"你好，{students[0]}！欢迎来到 Python 课堂。")
print(f"你好，{students[1]}！欢迎来到 Python 课堂。")
print(f"你好，{students[2]}！欢迎来到 Python 课堂。")
print(f"你好，{students[3]}！欢迎来到 Python 课堂。")
print(f"你好，{students[4]}！欢迎来到 Python 课堂。")
```

运行结果：

```text
你好，小明！欢迎来到 Python 课堂。
你好，小红！欢迎来到 Python 课堂。
你好，小刚！欢迎来到 Python 课堂。
你好，小丽！欢迎来到 Python 课堂。
你好，小强！欢迎来到 Python 课堂。
```

五个人，五行代码，看起来咬咬牙也能接受。但重复代码有三宗罪：

| 问题 | 具体表现 |
|------|---------|
| 写得慢 | 人数翻倍，代码行数就翻倍；100 个人就要写 100 行 |
| 改得疼 | 欢迎语从"欢迎来到 Python 课堂"改成"欢迎加入晨读小组"，要改 5 处（100 人就改 100 处），漏一处就不一致 |
| 错得隐蔽 | 下标写歪一个（比如手滑写成 `students[1]` 两次），两行重复打招呼、有一个人被漏掉，肉眼很难发现 |

本质问题在于：**这些代码每一行做的都是同一件事，但你被迫把"做一件事"写成了"很多件事"**。当一份代码里出现大量形状雷同的行，就是在提醒你——该用循环了。

用循环重写这五行的重复部分：

```python
students = ["小明", "小红", "小刚", "小丽", "小强"]

for name in students:
    print(f"你好，{name}！欢迎来到 Python 课堂。")
```

运行结果与手写版完全一致，但重复代码从 5 行缩到 2 行。更关键的收益不在"变短"，而在**变化来临时不用改代码**：

- 学生从 5 人增加到 40 人？往列表里加名字就行，`for` 这一行一个字都不用动。
- 欢迎语要改？只有一处 `print` 需要改，改完对所有人生效。
- 会漏掉谁吗？不会——循环"挨个来"的机制保证了每个元素都会被处理到。

这就是循环的核心价值：**把"重复的量"从代码里挪到数据里，让代码只描述"规则"本身**。数据负责说"有多少"，代码只负责说"做什么"。

### 1.3 最简示例

先见一见两种循环长什么样。

for 的最简示例——把一串名字逐个处理：

```python
for name in ["小明", "小红", "小刚"]:
    print(f"你好，{name}！")
```

运行结果：

```text
你好，小明！
你好，小红！
你好，小刚！
```

读法：`for name in ...` 的意思是"从后面的数据里依次取元素，每取到一个就存进变量 `name`，然后执行一遍缩进的代码"。数据取空，循环结束。三个要素一眼可见——`for` 开头、`in` 后面挂着被处理的数据、缩进部分是循环重复做的事。

while 的最简示例——盯住一个条件重复：

```python
countdown = 3
while countdown > 0:
    print(f"倒计时：{countdown}")
    countdown -= 1
print("发射！")
```

运行结果：

```text
倒计时：3
倒计时：2
倒计时：1
发射！
```

读法：`while countdown > 0` 的意思是"只要 `countdown > 0` 成立，就重复执行缩进部分"。每执行一轮，`countdown` 被减 1，减到 0 时条件不再成立，循环结束，程序落到 `print("发射！")`。

两个例子都已经能跑了。本篇的任务不是抠每一种写法的细节，而是回答三个更根本的问题：**循环在整个程序逻辑里处在什么位置？它由哪些不可少的骨架构成？它执行的时候内部到底是怎么走的？** 把这三件事想通，后面遇到再复杂、再长的循环写法，拆开看也逃不出这套骨架。

## 2. 核心内容

### 2.1 程序的三种控制结构：顺序、选择、循环

循环不是凭空出现的孤岛，理解它的第一步，是把它放进"控制结构"这个大框架。一段程序无论多复杂，代码执行的**组织方式**只有三种：

| 控制结构 | 核心动作 | 典型语法 | 解决什么问题 |
|---------|---------|---------|------------|
| 顺序结构 | 从上到下逐行执行 | 普通语句 | 按步骤把事做完 |
| 选择结构 | 按条件挑一条路走 | `if` / `if-else` / `if-elif-else` | 分情况处理 |
| 循环结构 | 让一段代码反复执行 | `for` / `while` | 批量、重复地做事 |

用一张图看三者的骨架差异（竖线代表一行代码的执行轨迹）：

```text
顺序结构              选择结构                    循环结构
   |                     |                          |
   |  语句1              |  语句1                    |  语句1
   |                     |      \                   |     \
   |  语句2              |  条件   \                 |  条件成立? --不成立--> 结束
   |                     |   |     \                |    |
   |  语句3              | 成立     不成立           | 成立(执行循环体)
   |                     |   |        |             |    |
   |                     | 语句2     语句3          | 回到条件，再检查一轮
   ↓                     |   |        |             |
   结束                  ↓   ↓        ↓             ↓
                       (两条路最终汇合)         (某一轮条件不成立，退出)
```

顺序结构是一条直线，选择结构是岔路口，而循环结构是一条**会回头的路**——执行到循环体底部，不往下走，而是跳回循环的起点再检查一次。这个"回头"正是循环与另外两者的本质区别。

真实的程序是三者组合出来的。比如一件日常任务："检查全班成绩单，给每个不及格的学生发一条提醒"——外层是循环（把 40 个学生逐个过一遍），循环体内是选择（及格跳过、不及格发提醒），而"先加载名单、再处理、最后保存"的大流程是顺序。三种结构各管一层，谁也替代不了谁。

循环在这个框架里的职责可以一句话概括：**顺序管"按什么次序"，选择管"走哪条路"，循环管"做多少遍"**。当你要解决的问题里出现"每一条""逐个""全部""反复""直到"这样的字眼，基本就是循环结构出场的信号。

### 2.2 循环的两大形态：for 与 while

Python 里表达"重复"的语句有两条路，它们思路完全不同，但功能上有重叠。

**for：遍历派——"把一串东西挨个处理"**

```python
for fruit in ["苹果", "香蕉", "橘子"]:
    print(f"今天吃：{fruit}")
```

运行结果：

```text
今天吃：苹果
今天吃：香蕉
今天吃：橘子
```

`for` 的注意力在**数据**上：`in` 后面放着一批元素，`for` 负责一个接一个把元素取出来交给循环体，取完为止。它天生适合"我手里有一堆东西，每个都要处理一下"的场景——一堆学生、一堆成绩、一堆文件名，甚至一个字符串里的每个字符。

**while：条件派——"只要条件成立就一直做"**

```python
battery = 3
while battery > 0:
    print(f"剩余电量：{battery} 格")
    battery -= 1
print("电量耗尽")
```

运行结果：

```text
剩余电量：3 格
剩余电量：2 格
剩余电量：1 格
电量耗尽
```

`while` 的注意力在**条件**上：它不关心有什么数据，只盯住"条件还成立吗"，成立就再执行一轮循环体，不成立就放行。它天生适合"什么时候停我说了算，中间做几轮数不清"的场景——比如游戏里"只要玩家还活着就一直运行"、程序里"输入不合法就一直要求重新输入"。

同一段倒计时，两条路都能走。for 的版本：

```python
# for 版：对着 [3, 2, 1] 这串数字逐个过
for n in [3, 2, 1]:
    print(f"倒计时：{n}")
print("发射！")
```

运行结果：

```text
倒计时：3
倒计时：2
倒计时：1
发射！
```

while 的版本：

```python
# while 版：盯住 countdown > 0 这个条件
countdown = 3
while countdown > 0:
    print(f"倒计时：{countdown}")
    countdown -= 1
print("发射！")
```

运行结果与 for 版完全相同。两条路各自的优势场景不同：

| 维度 | for | while |
|------|-----|-------|
| 关注点 | 在乎"in 后面那批数据" | 在乎"循环开头那个条件" |
| 次数由谁定 | 数据有几个就循环几次，事前可数 | 条件满足多久就循环多久，事前可能数不清 |
| 经典类比 | 发牌员：手里牌一张张发，发完收工 | 跑步者：天没黑就再跑一圈，天黑了才回家 |
| 典型场景 | 遍历名单、逐条处理数据 | 等待某个条件被满足、事件轮询 |
| 出错方式 | 数据太大/太小时轮数出乎意料 | 条件设计不当，一轮也进不去、或永久停不下来 |

两条路怎么选？经验法则很朴素：**"手里有明显的一批数据要逐个处理"优先 for；"要等某个条件被打破，事先数不清几轮"优先 while**。Python 社区的整体品味更偏好 for——凡是能写成 for 的场景，for 通常更短也更不容易出错；while 常见于"轮数由运行时情况决定"的场合。

### 2.3 循环的三要素：初始、推进、终止

把 while 倒计时展开，逐部件拆开看：

```python
countdown = 3             # ① 初始：从什么状态出发
while countdown > 0:      # ③ 终止条件：什么时候停
    print(f"倒计时：{countdown}")
    countdown -= 1        # ② 推进：每一轮向终止靠近一步
```

这三个部件合称循环三要素，缺一不可——这不是教材规定的教条，而是循环能正常结束的必然要求：

| 要素 | 作用 | 缺失后果 |
|------|------|---------|
| ① 初始 | 给循环一个明确的起点（`countdown = 3`） | 还没出发就出问题：变量未定义直接报 `NameError`，或从错误的位置出发 |
| ② 推进 | 每一轮让"离终止"更近一步（`countdown -= 1`） | 条件永远成立 → **死循环**（程序卡死，永不结束） |
| ③ 终止条件 | 每轮开头重新判断，决定继续还是结束（`countdown > 0`） | 没有判断就没有退出机制，同样是死循环 |

把三要素的运转画成流程图（while 循环内部每轮的真实动线）：

```text
        ┌────────────┐
        │ ①  初始化    │  countdown = 3
        └──────┬─────┘
               ↓
        ┌────────────┐
   ┌───→│ ③ 检查条件   │  countdown > 0 ?
   │    └──────┬─────┘
   │      成立 ↓        不成立 ──→ 退出循环，执行后面代码
   │    ┌────────────┐
   │    │  循环体      │  print(...)
   │    └──────┬─────┘
   │           ↓
   │    ┌────────────┐
   └────┤ ②  推进      │  countdown -= 1
        └────────────┘
```

逐轮跟着走一遍 `countdown` 的取值变化，看③②③②怎么交替：

| 轮次 | 检查③（条件） | 循环体 | 推进②（之后 countdown 的值） |
|------|------------------|-------------|------------------|
| 第 1 轮 | 3 > 0 成立 → 进 | 打印 3 | 3 − 1 = 2 |
| 第 2 轮 | 2 > 0 成立 → 进 | 打印 2 | 2 − 1 = 1 |
| 第 3 轮 | 1 > 0 成立 → 进 | 打印 1 | 1 − 1 = 0 |
| 第 4 轮 | 0 > 0 不成立 → 不进循环体 | — | 循环结束（放行） |

三要素里最容易被忽略的是②"推进"。写代码时验证它的办法特别简单：**每次写完 while，找到条件里那个变量，看看循环体里是不是有语句在动它**。完全没人动的变量配上一个"当前成立"的条件，基本就是一只死循环。用一个安全的演示看看"缺推进"是什么样子（在条件里加了保险装置，只让它跑三轮就放行，避免演示时真的把程序卡住）：

```python
countdown = 3
safety = 0                      # 保险计数：防止演示程序失控
while countdown > 0 and safety < 3:
    safety += 1
    print(f"第 {safety} 轮了，countdown 依旧是 {countdown}，条件永远成立……")
    # 这里漏掉了 countdown -= 1
print("印够三轮了，靠保险条件才停下来——正常情况下这就是一只死循环")
```

运行结果：

```text
第 1 轮了，countdown 依旧是 3，条件永远成立……
第 2 轮了，countdown 依旧是 3，条件永远成立……
第 3 轮了，countdown 依旧是 3，条件永远成立……
印够三轮了，靠保险条件才停下来——正常情况下这就是一只死循环
```

`countdown` 从头到尾停在 3 上纹丝不动，"倒计时"变成"原地转圈"。真遇到这种程序，现象就是：无输出刷屏或界面假死，只能手动中断。排查思路反过来用三要素即可：**卡死 → 查②推进（变量动了没）；一轮没进 → 查①③（起点和条件是否矛盾）**。

现在用三要素视角回头看 for，会发现一个有价值的事实：

```python
flowers = ["玫瑰", "百合", "康乃馨"]

for flower in flowers:
    print(f"这束里有：{flower}")
```

"初始、推进、终止"三件事在 for 里一件都没少，只是**从"你亲自管理"改成了"语言替你托管"**：初始和推进（"取下一个元素"）由 for 自动完成，终止条件（"取不到下一个了"）也由 for 自动判断。这正是 for 用起来省心的根源——三要素集中托管，出错面积就小。而 while 把三件事全权交给你，自由度更大，代价是每一件都得自己负责。for 与 while 的分工，某种意义上就是"托管式重复"和"自治式重复"的分工。

### 2.4 循环的执行流程图解

写循环时"读"得明白的关键，是把循环执行时的**内部动线**脑补出来：程序在循环里是怎么"走了回头路"的。先看 for，再看 while，最后看一个容易让人意外的边界情况。

**for 循环的内部动线**

`for fruit in ["苹果", "香蕉", "橘子"]:` 真实执行时的每一步动作：

```text
   ┌──────────────────────────┐
   │ 从列表取下一个元素          │ ←──┐
   └────────────┬─────────────┘    │
                ↓                  │
        ┌───────────────┐          │
        │  取到了吗？    │          │
        └───┬───────┬───┘          │
          取到↓       取不到        │
   ┌──────────┐      │            │
   │ 交给 fruit │      │            │
   └─────┬────┘      │            │
         ↓           ↓             │
 ┌─────────────┐  ┌──────┐         │
 │ 执行循环体   │  │ 结束  │         │
 └─────┬───────┘  └──────┘         │
       └──────── 回到取元素 ────────┘
```

看图能发现 for 循环的身体里其实还藏着一个"检查点"：每一轮开始前，它都先问一次"还有下一个元素吗"，**取不到才结束**。用一份逐轮记录看得更直观：

| 轮次内部节点 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 第 4 轮（未发生） |
|--------------|---------|---------|---------|------------------|
| 取到的元素 | "苹果" | "香蕉" | "橘子" | （已取空） |
| fruit 的值 | 苹果 | 香蕉 | 橘子 | 不再进入循环体 |
| 循环体动作 | 打印"今天吃：苹果" | 打印"今天吃：香蕉" | 打印"今天吃：橘子" | — |

三个元素，循环体恰好执行三轮；第 4 次"取元素"扑了个空，循环干净地结束。由此能立刻得到一个实用结论：**for 的循环体执行次数 = 数据源里元素的个数**。

**while 循环的内部动线**

while 把"检查"摆在明面上，直接写在语句结构里（`while 条件:`），动线反而好懂。一段按轮次打印余量的代码：

```python
money = 3
while money > 0:
    print(f"口袋还有 {money} 元")
    money -= 1
```

运行结果：

```text
口袋还有 3 元
口袋还有 2 元
口袋还有 1 元
```

逐轮追踪它的"检查 → 执行 → 推进、回头"三部曲：

| 轮次 | 检查 money > 0 | 循环体 | 推进后 |
|------|----------------|-------------------|--------|
| 第 1 轮 | 3 > 0 成立 → 进 | 打印"还有 3 元" | 3 − 1 = 2 |
| 第 2 轮 | 2 > 0 成立 → 进 | 打印"还有 2 元" | 2 − 1 = 1 |
| 第 3 轮 | 1 > 0 成立 → 进 | 打印"还有 1 元" | 1 − 1 = 0 |
| 第 4 轮 | 0 > 0 不成立 → 直接结束 | （进不去） | — |

要注意 while 的检查发生在**每轮循环体开始之前**，不是"先做一遍再回头看"。这个时序直接决定下面的边界行为。

**边界情况：一次都不执行的循环**

很容易想当然地认为"循环体至少会执行一次"。实际上两类循环都在每轮**开头做检查**，条件不成立就根本不进循环体。先看 for 遇到空列表：

```python
empty = []
for item in empty:
    print("这一行永远不会被打印")
print("列表是空的：一个元素都取不到，循环体一次都没执行")
```

运行结果：

```text
列表是空的：一个元素都取不到，循环体一次都没执行
```

再看 while 条件首轮就不成立的情形：

```python
money = 0
while money > 0:
    print("兜里有钱才轮得到这行")
print("money 一开始就是 0，条件首轮就不成立，这行直接被打出来")
```

运行结果：

```text
money 一开始就是 0，条件首轮就不成立，这行直接被打出来
```

记住这个结论：**循环不是"先做一遍再看"，而是"先检查再做"**。这一条能帮你避开一大类"循环怎么一行都没跑"的困惑。

### 2.5 可迭代对象初识

for 的 `in` 后面能放什么？答案是 Python 里一个庞大的家族：**可迭代对象（iterable）——凡是能被 for 逐个取值的东西都算**。先认识家族的主要成员，把 for 与数据源的"接口"看清楚。

| 可迭代对象 | 每轮取出的"一个元素" | 示例 |
|-----------|-------------------|------|
| 列表 | 列表里的一个值 | `[86, 92, 78]` → 先 86、再 92、后 78 |
| 元组 | 元组里的一个值 | `(3, 5, 7)` → 先 3、再 5、后 7 |
| 字符串 | 单个字符 | `"Py"` → 先 P、再 y |
| 字典 | 字典的一个键 | `{"语文": 88}` → 取到键 "语文" |
| 集合 | 集合里的一个值 | `{1, 2, 3}` → 依次取到 1、2、3（次序不保证） |
| range | 一串连续整数 | `range(3)` → 先 0、再 1、后 2 |

先试最常用的一种——字符串也是可迭代对象，一轮取一个字符：

```python
for ch in "Python":
    print(f"字符：{ch}")
```

运行结果：

```text
字符：P
字符：y
字符：t
字符：h
字符：o
字符：n
```

for 切分字符串时严格按字符进行，一个不多一个不少——"Python" 有六个字符，循环体就恰好执行六轮。再看字典的遍历细节：

```python
courses = {"语文": 88, "数学": 95}
for subject in courses:          # 直接遍历字典 → 每轮取到一个键
    print(f"{subject}：{courses[subject]} 分")
```

运行结果：

```text
语文：88 分
数学：95 分
```

这段代码有个关键认识：for 的循环体里**可以直接使用"取到的元素"**，也能拿着元素再去查别的数据（上面拿键去查分数）。

在此基础上，最重要的是建立一个读 for 语句的习惯：**先看 in 后面的数据源，再看循环变量叫什么**。因为数据源的"元素长什么样"，决定了循环变量每一轮会接到什么。同一条 for 语句还有几种"接收端"的形态值得先见一面，理解它们的关键就一句话——**接收端按"元素的形状"去接**。

（1）元素本身是"两个值组成的序列"时，接收端可以一次接住两个：

```python
pairs = [("语文", 88), ("数学", 95)]
for subject, score in pairs:     # 元素是("语文", 88)这样的对 → 拆成两个变量接住
    print(f"{subject}：{score} 分")
```

运行结果：

```text
语文：88 分
数学：95 分
```

（2）元素是一个完整的"键值对"时，也可以先整体接住、再看它的形状：

```python
scores_map = {"学员A": 20, "学员B": 22}
for pair in scores_map.items():  # 每轮 pair 是 ("学员A", 20) 这样的一对
    print(f"取到一对：{pair}")
```

运行结果：

```text
取到一对：('学员A', 20)
取到一对：('学员B', 22)
```

第一种写法把"一对"拆开成两个变量分别接，第二种写法用一个变量把整对接住——**数据源的元素是什么形状，接收端就按什么形状接（整体接、或拆开接）**。这是通用的拆解原则，循环家族里所有"长度可观的接收写法"，底层基线都是这一条。

### 2.6 循环能做什么：四类典型用途

循环的用途千姿百态，但绝大多数都逃不出以下四类。每类配一段小示例，建立一个"用途地图"。

**用途一：遍历处理——把每个元素过一遍，各做各的处理**

```python
fruits = ["apple", "banana", "cherry"]
for fruit in fruits:
    print(fruit.upper())          # 每个元素都套用同一个动作：转大写
```

运行结果：

```text
APPLE
BANANA
CHERRY
```

适合场景：批量格式转换、逐个打印、逐条校验、逐条写入——凡是"对每条数据做同一件事"。

**用途二：累计统计——一轮轮攒出一个总量**

```python
scores = [86, 92, 78]
total = 0                        # 累加器：先给个空起点
for score in scores:
    total += score                # 每轮把当前值叠进总量
print(f"总分：{total}")
```

运行结果：

```text
总分：256
```

这是循环最实用的模式之一，**累加器模式（accumulator pattern）**：循环开始前先立一个"账本"变量（这里 `total = 0`），循环体每轮往账本里记一笔。求和、计数、拼接字符串、收集结果清单，全是这个模式的变体：

| 变体 | 账本起点 | 每轮记账动作 | 产出 |
|------|---------|--------------|------|
| 求和 | `total = 0` | `total += score` | 总分 |
| 计数 | `count = 0` | 命中则 `count += 1` | 满足条件的有几个 |
| 拼接 | `text = ""` | `text += word` | 串成长句 |
| 收集 | `result = []` | `result.append(x)` | 攒成清单 |

**用途三：查找判定——在重复中筛出目标**

```python
scores = [86, 45, 92, 78]
for score in scores:
    if score < 60:                # 条件命中才动手
        print(f"发现不及格：{score} 分")
```

运行结果：

```text
发现不及格：45 分
```

查找判定的骨架是"循环 + 条件"：循环提供"逐个到场"的元素，条件决定"这一个要不要动手"。

**用途四：批量制造——按规则生产一批新数据**

```python
table = []
for n in [1, 2, 3]:
    row = n * n                  # 对每个原料套用同一个加工程序
    table.append(row)
print(table)                     # 产出一份新数据
```

运行结果：

```text
[1, 4, 9]
```

适合场景：生成平方数表、生成随机样本、把一批原始数据加工成新格式——"进一批原料，出一批成品"。它与累加器模式的区别在于：累加器把结果**攒成一个总量**，批量制造把结果**攒成一份新清单**。

四类用途背后是同一个认知：循环 = **"每轮取到一个新元素" + "每轮对它做一次相应的动作"**。变的是动作，不变的是骨架。

## 3. 实践示例

### 3.1 从五遍复制粘贴到一行规则的改造过程

第一个实践，把本篇开头"五遍打招呼"的手写版做个完整改造，体会"发现重复 → 提炼规则 → 循环复原"的思路。改造前先看清重复的样子：手写版五行其实是同一句话 `print(f"你好，{某同学}！欢迎来到 Python 课堂。")` 的五次复制品，逐行变化的只有方括号里的下标。所谓改造，就是把"某同学"变成一个轮换的身份：每一轮由循环提供一个新的名字。第一步，摆出其中三行，拆出"会变"与"不变"这两个部分：

```python
students = ["小明", "小红", "小刚", "小丽", "小强"]

print(f"你好，{students[0]}！欢迎来到 Python 课堂。")
print(f"你好，{students[1]}！欢迎来到 Python 课堂。")
print(f"你好，{students[2]}！欢迎来到 Python 课堂。")
```

观察定位到两个部分：

- 会轮换的部分：`students[0]`、`students[1]`、`students[2]`……每行不同；
- 不变的部分：`print(f"你好，{...}！欢迎来到 Python 课堂。")` 这身骨架每行一样。

第二步，把"会轮换的部分"用变量 `name` 顶上，把整行退化为一份模板：

```python
# 模板：把会变的部分挖成变量坑位
print(f"你好，{name}！欢迎来到 Python 课堂。")
```

第三步，用循环把"名字来源 + 模板"合体：

```python
students = ["小明", "小红", "小刚", "小丽", "小强"]

for name in students:
    print(f"你好，{name}！欢迎来到 Python 课堂。")
```

运行结果：

```text
你好，小明！欢迎来到 Python 课堂。
你好，小红！欢迎来到 Python 课堂。
你好，小刚！欢迎来到 Python 课堂。
你好，小丽！欢迎来到 Python 课堂。
你好，小强！欢迎来到 Python 课堂。
```

改造完成。回头检验，当初的三宗罪都痊愈了吗？

- 五个人变四十个人：只改 `students` 列表本身，for 一行不动；
- 欢迎语调整：改一处 print，全班同步生效；
- 漏掉某个人：循环机制保证逐个到访，不会偏心。

这套"找重复 → 分离变与不变 → 循环复原"的三步改造法，是从手写代码走向循环思维的通用钥匙。往后在写代码时一旦发现自己正在按 Ctrl+V，就当场练习把它改造成循环。

### 3.2 用循环统计一份成绩单

第二个实践把前面的知识点串成一件完整的事：给你一份成绩单，统计出"逐个判定、总分、平均分、最高分、不及格名单"。任务使用的源数据如下：

```python
scores = [92, 78, 55, 88, 61, 100, 73]
```

第一步，逐个过一遍，逐条判定，同时把总分用累加器攒起来：

```python
total = 0
for score in scores:
    verdict = "及格" if score >= 60 else "不及格"
    print(f"成绩 {score} 分：{verdict}")
    total += score
```

运行结果：

```text
成绩 92 分：及格
成绩 78 分：及格
成绩 55 分：不及格
成绩 88 分：及格
成绩 61 分：及格
成绩 100 分：及格
成绩 73 分：及格
```

这里的 `total += score` 正是累加器模式；而 `"及格" if score >= 60 else "不及格"` 这一小行则是条件表达式的典型用法——按分数是否达到 60 在两个文案里二选一。顺带这个样例还验证了循环体可以包含多个动作：一轮之内先判定、再打印、再记账，三条语句按顺序依次执行。

第二步，用攒好的总分计算平均分：

```python
average = total / len(scores)
print(f"共 {len(scores)} 人，总分 {total} 分，平均 {average} 分")
```

运行结果：

```text
共 7 人，总分 547 分，平均 78.142857142857146 分
```

第三步，找最高分。这里用**打擂台法**：先让第一份成绩站上擂台当擂主，循环往后每一份都来挑战——比擂主高就取而代之，不如就原地保持；循环结束时站在台上的就是最高分：

```python
highest = scores[0]              # 先让第一份成绩当擂主
for score in scores:
    if score > highest:          # 挑战者更高 → 换擂主
        highest = score
print(f"全班最高分：{highest} 分")
```

运行结果：

```text
全班最高分：100 分
```

打擂台法本质上仍是累加器模式——只是把"记账动作"从"加进总量"换成了"遇到更大的就更新记录"。账本从 `0` 换成了 `scores[0]`，记账规则从 `total += x` 换成了"挑战成功才更新"。

第四步，统计不及格的人数，并把具体名单收集起来：

```python
failed_count = 0
failed_scores = []
for score in scores:
    if score < 60:
        failed_count += 1
        failed_scores.append(score)
print(f"不及格人数：{failed_count} 人，分别是 {failed_scores}")
```

运行结果：

```text
不及格人数：1 人，分别是 [55]
```

这四步合在一起看结构：**同一份 `scores` 被四条 for 循环各自过了一遍，每条循环承载一个独立的小任务**。真实项目里这几条循环常会合并为一条大循环（逐轮同时更新总分、最高分与不及格名单）；但学习阶段保持"一条循环只做一件事"，每个模式看得更清楚。读懂单个循环，是读懂一切长循环的第一步。

## 4. 常见误区与边界

### 4.1 误区一：循环和遍历是一回事

初学者常把"循环"与"遍历"混着说，比如一句"我写了一个遍历，把成绩加起来"，听起来自然，但概念上必须掰清两个词。

它们的分工是：**循环是"重复执行"这种控制结构本身，遍历是"把一批数据逐个过一遍"这种具体行为**。循环是机制，遍历是这个机制最常见的用法之一。

拿 while 来看，下面这个循环就完全没有"一批数据"可谈：

```python
water_in_cup = 0
while water_in_cup < 3:
    water_in_cup += 1            # 一勺一勺舀水
print(f"舀满 {water_in_cup} 勺，条件达成")
```

运行结果：

```text
舀满 3 勺，条件达成
```

这个 while 纯粹靠"条件 + 推进"在重复，手边没有任何被"遍历"的数据。可见：**遍历必用循环，而循环不止用于遍历**。二者是"能力"与"典型用法"的关系。

### 4.2 误区二：循环体至少会执行一次

很多人潜意识里默认"进了循环，好歹跑一轮"。实际上 for 和 while 都是**先检查、后执行**——首轮检查通不过，循环体一次都不会进。先看 for 遇到空数据：

```python
salaries = []
for salary in salaries:
    print(f"处理薪资：{salary}")
print("上面一行都没打印——列表是空的，元素取不到")
```

运行结果：

```text
上面一行都没打印——列表是空的，元素取不到
```

更隐蔽的是 while 首轮条件不成立的情形，问题常出在起点值与条件的方向互相矛盾：

```python
position = 10
while position < 0:               # 起点 10，条件要求小于 0 → 首轮就不成立
    print("这行永远不会执行")
print("position 从 10 出发，条件 position < 0 首轮就不成立，循环体直接被跳过")
```

运行结果：

```text
position 从 10 出发，条件 position < 0 首轮就不成立，循环体直接被跳过
```

掌握"先检查后执行"这条时序，就能解释一大类"循环怎么一行没跑"的 bug。出现这种 bug 时排查顺序：先看 for 的数据源是不是空的；再看 while 的起点值是不是让条件首轮就不成立。

### 4.3 误区三：缩进偏移会让代码意外进出循环体

Python 不靠 begin/end 之类的关键词画循环体边界，只靠**缩进**——与 for/while 语句行同列的代码在循环体外，多缩进一层的代码在循环体内。差一个空格，代码身份不同。两类事故分别看一下。

**事故一：少缩进一层，语句掉出了循环体。** 下面的"（本项完成）"本应每处理完一项就报一次，实际却少了缩进、与 for 同列——掉到循环体外，落得只在全部结束后执行一次：

```python
steps = ["洗菜", "切菜", "炒菜"]
for step in steps:
    print(f"正在处理：{step}")
print("（本项完成）")          # 少缩进一层，与 for 同列 → 不在循环体内
```

运行结果：

```text
正在处理：洗菜
正在处理：切菜
正在处理：炒菜
（本项完成）
```
"（本项完成）"只在最后出现一次——它想报告的是"每一项的完成"，但身份掉出循环体后，就只在循环结束的那一刻执行一回。

**事故二：多缩进一层，语句被卷进了循环体。** 这次的"三项全部完成"本意是全程结束后收个尾，却多缩进了一层，被卷进循环里，每轮都跟着跑：

```python
steps = ["洗菜", "切菜", "炒菜"]
for step in steps:
    print(f"正在处理：{step}")
    print("三项全部完成")      # 多缩进一层 → 进了循环体 → 每轮都执行
```

运行结果：

```text
正在处理：洗菜
三项全部完成
正在处理：切菜
三项全部完成
正在处理：炒菜
三项全部完成
```

"三项全部完成"出现三次——它被缩进卷进循环，成了循环体的一部分。快速判定规则就一条：**一条语句属于循环体，当且仅当它比 for/while 语句行多缩进一层**。写循环时第一件事就是划好缩进边界——哪些语句要跟着循环逐轮跑（多缩进一层），哪些是循环结束后的收尾（与 for/while 同列），从写第一行起就分清楚，比事后修对齐容易得多。

### 4.4 误区四：循环结束后循环变量就消失了

另一个常见误会：以为循环结束，循环产生的中间变量会被 Python 清理掉。实测 for：

```python
for score in [86, 92, 78]:
    print(f"处理中：{score}")
print(f"循环结束后再访问：{score}")    # 没有任何清理，变量还在
```

运行结果：

```text
处理中：86
处理中：92
处理中：78
循环结束后再访问：78
```

`score` 在循环结束后依然有效，值停在最后一轮接到的元素（78）。while 同理，控制它推进的那个变量也原地保留（倒计时例子结束后的 `countdown` 是 0）。

这个行为有两个实际影响：

- **便利**：循环扫完一批数据后，能直接在循环外的代码里继续用这些变量做"收尾加工"（例如打印最后处理的那一份）；
- **风险**：几个循环先后运行时，一个循环别误用更早循环遗留的同名变量当起点，尤其 while 的初始值如果"忘了写"，可能正好捡到历史残留的值、运行到一半才暴露问题。

稳妥习惯是"自己的循环自己初始化"——在 for/while 开始之前明确地立起所有要用的变量，不依赖上下文里的历史值。

### 4.5 循环结构的能力边界

循环不是万金油。有几种情况，更应当让出舞台。

**数据已经现成，不需要"逐轮发明"**。求和、找最值这类整批操作，Python 内置了直接下手的现成函数；若目的只是"拿到结果"，直接用 `sum([86, 92, 78])` 就不必手写一轮一轮的累加器。手写循环的真正价值在于**动作需要自定义**时——每一轮要做的事现成函数插不上手，循环才当主角。例如"每个成绩先乘权重再求和""跳过所有缺考项"这类带自定义规则的批量处理，就是循环的用武之地。

**重复次数实际上是一次的"假循环"**。有时会看到一个循环体只跑一轮，多是因为数据源里只放了一个元素。这种"形似循环、其实没有重复需求"的代码，不如直接写成顺序语句更清晰：

```python
# 列表里只放了一个名字，循环只会跑一轮，形同顺序执行
for name in ["张三"]:
    print(f"你好，{name}")
```

这种写法能跑，但读者会误以为"这个位置将来应有一批数据"。如果没有此意图，直接 `print(f"你好，张三")` 更能把"只做一次"的真实意图摆在脸上。

**规则简单到一行可解的批量生成**。Python 里有专门为"批量转换一批数据"准备的更紧凑写法（推导式）：当"每一轮做的事"能凝缩成一个简单的表达式、且没有复杂的多步逻辑时，它比 for 大段循环更轻。

边界记诵一句足矣：**循环的价值在于表达"重复的规则"——规则越复杂，循环越是恰当的主角；没有规则、或规则已被现成工具覆盖时，别硬上循环**。

## 5. 总结

本文围绕循环结构的概念地基展开，主要介绍了以下内容：

- 循环结构是"让一段代码反复执行"的控制结构，核心收益是把"重复的量"从代码挪到数据里——代码只描述规则本身；
- 程序三大控制结构（顺序、选择、循环）中，循环管"做多少遍"，特征是执行动线上"会回头"；
- 循环的两大形态：for 是遍历派（对着数据逐个取，三要素由语言托管），while 是条件派（盯住条件反复执行，三要素自主管理），选型口诀是"批量数据优先 for，等条件被破选 while"；
- 循环三要素（初始、推进、终止）缺一不可，缺推进是死循环的头号成因；检查三要素是排查"循环卡死"与"循环不执行"的通用手法；
- for/while 都是"先检查后执行"：数据为空或条件首轮不成立时，循环体一次都不会进；
- for 的数据源是"可迭代对象"家族（列表、元组、字符串、字典、集合、range 等）；读 for 语句先看数据源里元素的形状，循环变量就按什么形状接收（整体接或拆开接）；
- 循环的四大用途（遍历处理、累计统计、查找判定、批量制造）共享同一种骨架，累加器模式是其中最常用的记账套路；
- 实践演练了"找重复 → 分离变与不变 → 循环复原"的三步改造法，以及成绩单统计的完整流程；
- 四个高频误区（循环不等于遍历、循环体可能零次执行、缩进划界、循环变量事后保留）与能力边界（现成工具能覆盖时不必硬写循环），是写出正确循环的护栏。
