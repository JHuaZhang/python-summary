# 字典的 pop 与 popitem 方法

## 1. 介绍

### 1.1 什么是 pop 与 popitem

在 Python 字典中，`pop` 和 `popitem` 是两个用于**删除并返回**元素的内置方法。它们的共同点是"删除的同时把被删除的东西交给你"，区别在于删除的方式不同：

- `pop(key)` —— 你指定一个键，方法删除该键值对并返回对应的值。就像你从抽屉里指定拿走某一件东西。
- `popitem()` —— 你不指定任何东西，方法自动删除**最后插入的**键值对并返回 `(key, value)` 元组。就像你从栈顶取走最上面那个。

这两个方法在实际开发中非常常用。当你需要从字典中"取出并移除"某个配置项时，`pop` 是首选；当你需要按"后进先出"的顺序处理字典数据时，`popitem` 最合适。

### 1.2 解决什么问题

先看一个最常见的场景——从请求参数中提取特殊参数。假设你有一个包含请求配置的字典，其中 `timeout` 需要单独处理，其余参数直接传给请求函数：

```python
def make_request(params):
    # 从 params 中取出 timeout，取完后 params 中不再包含它
    timeout = params.pop("timeout", 30)
    # 剩余的 params 直接传给请求函数
    print(f"timeout: {timeout}")
    print(f"剩余参数: {params}")

request_params = {"url": "/api/data", "method": "GET", "timeout": 10}
make_request(request_params)
```

**运行结果**：

```text
timeout: 10
剩余参数: {'url': '/api/data', 'method': 'GET'}
```

如果不用 `pop`，你需要先用 `params["timeout"]` 取值，再 `del params["timeout"]` 删除，两步操作。`pop` 把这两步合一，代码更简洁。

### 1.3 最简示例

先用最小例子感受两个方法的核心行为：

```python
# pop：指定键，删除并返回值
d = {"a": 1, "b": 2, "c": 3}
val = d.pop("b")
print(f"pop 返回: {val}")
print(f"pop 后: {d}")
```

**运行结果**：

```text
pop 返回: 2
pop 后: {'a': 1, 'c': 3}
```

```python
# popitem：不指定键，删除并返回最后一个键值对
d = {"a": 1, "b": 2, "c": 3}
item = d.popitem()
print(f"popitem 返回: {item}")
print(f"popitem 后: {d}")
```

**运行结果**：

```text
popitem 返回: ('c', 3)
popitem 后: {'a': 1, 'b': 2}
```

这个例子揭示了两个方法的核心区别：**`pop` 由你指定删除哪个，`popitem` 自动删除最后一个。** 理解这个区别是正确选择使用哪个方法的第一步。

## 2. 核心内容

### 2.1 pop 方法签名

`pop` 是字典的内置方法，用于通过键删除并返回对应的值。它的完整签名：

```python
dict.pop(key, [default])
```

| 参数 | 说明 | 是否必需 |
|------|------|---------|
| `key` | 要删除的键 | 必需 |
| `default` | 键不存在时返回的默认值 | 可选 |

**返回值**：

- 键存在时：返回该键对应的值，同时从字典中删除该键值对。
- 键不存在且提供了 `default`：返回 `default`，不修改字典。
- 键不存在且未提供 `default`：抛出 `KeyError`。
- 不传任何参数：抛出 `TypeError`。

### 2.2 pop 基本用法：删除并返回值

最基本的用法是传入一个键，`pop` 会删除该键值对并返回值：

```python
# 场景：用户注销时从在线列表移除
online_users = {
    "user_001": "Alice",
    "user_002": "Bob",
    "user_003": "Charlie",
}

# pop 返回被删除的值，同时从字典中移除该键
removed_user = online_users.pop("user_002")
print(f"被移除的用户: {removed_user}")
print(f"剩余在线用户: {online_users}")
```

**运行结果**：

```text
被移除的用户: Bob
剩余在线用户: {'user_001': 'Alice', 'user_003': 'Charlie'}
```

**关键点**：

- `pop` 和 `del` 都能删除键值对，但 `del` 只删除不返回值，`pop` 删除的同时返回值。当你需要"取出并移除"时，`pop` 是正确选择。
- `pop` 返回的是值，不是键值对元组。如果你只需要值，直接用返回值即可。

#### 2.2.1 键不存在时的行为

当键不存在于字典中时，`pop` 的行为取决于是否提供了默认值参数：

**不提供默认值——抛出 KeyError**：

```python
config = {"host": "localhost", "port": 8080}
try:
    config.pop("timeout")
except KeyError as e:
    print(f"KeyError: {e}")
```

**运行结果**：

```text
KeyError: 'timeout'
```

如果你确定键一定存在，不传默认值是合理的——如果键意外不存在，`KeyError` 会立刻暴露问题，属于"快速失败"策略。

#### 2.2.2 不传参数时的行为

`pop` 要求至少传一个参数（`key`）。不传任何参数会抛出 `TypeError`：

```python
d = {"a": 1}
try:
    d.pop()
except TypeError as e:
    print(f"TypeError: {e}")
```

**运行结果**：

```text
TypeError: pop expected at least 1 argument, got 0
```

这与列表的 `list.pop()` 不同——列表的 `pop` 可以不传参数（默认删除最后一个元素），但字典的 `pop` 必须指定键。这是因为字典的"最后一个"在不同 Python 版本中语义不同（Python 3.7 前不保证顺序），所以 `pop` 不提供默认删除行为。

#### 2.2.3 pop 与 del 的对比

`pop` 和 `del` 都能删除字典中的键值对，但适用场景不同：

```python
d = {"a": 1, "b": 2}

# del：只删除，不返回值
del d["a"]
# val = del d["b"]  ← 语法错误，del 不返回值

# pop：删除并返回值
d2 = {"x": 10, "y": 20}
val = d2.pop("x")
print(f"取出的值: {val}")
```

**运行结果**：

```text
取出的值: 10
```

| 维度 | `del d[key]` | `d.pop(key)` | `d.pop(key, default)` |
|------|-------------|-------------|----------------------|
| 返回值 | 无 | 被删除的值 | 被删除的值或默认值 |
| 键不存在时 | `KeyError` | `KeyError` | 返回默认值 |
| 适用场景 | 纯删除 | 删除同时取值 | 安全删除 |
| 链式使用 | 不支持 | 不支持 | 不支持 |

**选择建议**：

- 纯删除、不需要返回值 → `del`（语义最直接）
- 需要取出值并移除 → `pop`
- 不确定键是否存在、需要安全删除 → `pop(key, default)`

### 2.3 pop 的默认值参数

`pop` 的第二个参数 `default` 是一个强大的特性——它让删除操作变得"安全"，不再因为键不存在而抛出异常。

**行为规则**：

- 键存在时：删除并返回值（与不带默认值完全一样，`default` 被忽略）
- 键不存在时：返回 `default`，不修改字典，不抛异常

```python
# 场景：从配置中取出并移除某个键，不存在时用默认值
config = {
    "host": "localhost",
    "port": 8080,
    "debug": False,
}

# 键存在：返回真实值并删除
timeout = config.pop("timeout", 30)
print(f"timeout: {timeout}")
print(f"config: {config}")

# 键不存在：返回默认值，不报错
retries = config.pop("retries", 3)
print(f"retries: {retries}")
print(f"config: {config}")
```

**运行结果**：

```text
timeout: 30
config: {'host': 'localhost', 'port': 8080, 'debug': False}
retries: 3
config: {'host': 'localhost', 'port': 8080, 'debug': False}
```

注意 `timeout` 在 `config` 中不存在，所以返回了默认值 `30`，字典本身没有被修改。`retries` 同理，返回了默认值 `3`。

**关键点**：

- 当你不确定键是否存在时，传默认值比用 `try/except` 更简洁。
- 默认值的作用是"键不存在时的替代返回值"，不是"键存在时的替换值"。

#### 2.3.1 默认值可以是任意类型

`default` 不限于数字或字符串——它可以是任何 Python 对象：

```python
params = {"name": "Alice", "age": 30}

# 默认值为列表
tags = params.pop("tags", ["default"])
print(f"tags: {tags}")

# 默认值为字典
metadata = params.pop("metadata", {"source": "unknown"})
print(f"metadata: {metadata}")

# 默认值为 None
avatar = params.pop("avatar", None)
print(f"avatar: {avatar}")
```

**运行结果**：

```text
tags: ['default']
metadata: {'source': 'unknown'}
avatar: None
```

**注意**：当默认值是可变对象（如列表、字典）时，每次调用 `pop` 且键不存在时返回的都是你传入的**同一个对象**。如果你在循环中多次 `pop` 同一个不存在的键，每次返回的是同一个可变对象引用。这一点在大多数场景下不是问题，但如果你修改了返回的默认值对象，后续 `pop` 返回的还是被修改后的对象。

#### 2.3.2 用 pop 实现一次性配置提取

`pop` 最经典的实战场景是"一次性配置提取"——从参数字典中取出某些特殊参数，取完后字典中不再包含它们，剩余参数直接传给下游：

```python
# 场景：从请求参数中提取特殊参数，其余透传
request_params = {
    "url": "https://api.example.com",
    "method": "GET",
    "timeout": 30,
    "headers": {"Content-Type": "application/json"},
    "auth_token": "secret_xxx",
}

# auth_token 需要单独处理，不传给下游
auth_token = request_params.pop("auth_token", None)
print(f"提取的 auth_token: {auth_token}")
print(f"传递给下游的参数: {request_params}")

# 如果没有 auth_token，则返回 None，不报错
safe_params = {"url": "https://api.example.com"}
token = safe_params.pop("auth_token", None)
print(f"无 auth_token 时: {token}")
```

**运行结果**：

```text
提取的 auth_token: secret_xxx
传递给下游的参数: {'url': 'https://api.example.com', 'method': 'GET', 'timeout': 30, 'headers': {'Content-Type': 'application/json'}}
无 auth_token 时: None
```

**关键点**：

- `pop("auth_token", None)` 完美实现了"有就取出来、没有就返回 None"的逻辑，不需要 `if "auth_token" in params` 判断。
- 取出后 `auth_token` 不在 `request_params` 中了，可以直接把剩余参数传递给下游函数，不用担心敏感信息泄露。

#### 2.3.3 用 pop 实现计数消耗

当字典的值是计数器时，`pop` 可以配合计数逻辑实现"消耗完即移除"：

```python
# 场景：API 调用配额管理
api_quota = {
    "user_001": 5,    # 剩余 5 次调用
    "user_002": 3,
    "user_003": 10,
}

def consume_quota(user_id):
    remaining = api_quota.get(user_id, 0)
    if remaining <= 0:
        print(f"{user_id} 配额不足")
        return False
    api_quota[user_id] -= 1
    print(f"{user_id} 消耗一次，剩余 {api_quota[user_id]}")
    # 配额用完时移除该用户
    if api_quota[user_id] == 0:
        api_quota.pop(user_id, None)
        print(f"{user_id} 配额已用完，自动移除")
    return True

consume_quota("user_001")
consume_quota("user_001")
consume_quota("user_002")
print(f"剩余配额: {api_quota}")
```

**运行结果**：

```text
user_001 消耗一次，剩余 4
user_001 消耗一次，剩余 3
user_002 消耗一次，剩余 2
剩余配额: {'user_001': 3, 'user_002': 2, 'user_003': 10}
```

这里用 `pop(user_id, None)` 而不是 `del api_quota[user_id]`，是因为即使因为并发等原因键已经被删除，`pop` 也不会报错。

### 2.4 popitem 方法签名

`popitem` 是字典的另一个删除方法，但它不需要你指定键——它自动删除**最后插入的**键值对。完整签名：

```python
dict.popitem()
```

| 参数 | 说明 | 是否必需 |
|------|------|---------|
| 无 | `popitem` 不接受任何参数 | — |

**返回值**：

- 字典非空时：返回 `(key, value)` 元组，同时从字典中删除该键值对。
- 字典为空时：抛出 `KeyError`。

**关键特性**：Python 3.7+ 保证 `popitem` 按照 **LIFO（后进先出）** 顺序删除——最后插入的键值对最先被弹出。在 Python 3.6 及之前，`popitem` 删除的是**任意**键值对（不保证顺序），因为早期字典不维护插入顺序。

### 2.5 popitem 基本用法

`popitem` 返回一个 `(key, value)` 元组，不需要任何参数：

```python
# 场景：任务队列，后进先出处理
tasks = {}
tasks["task_001"] = "数据清洗"
tasks["task_002"] = "模型训练"
tasks["task_003"] = "结果分析"

# popitem 删除最后插入的键值对，返回元组 (key, value)
last_task = tasks.popitem()
print(f"取出的任务: {last_task}")
print(f"类型: {type(last_task)}")
print(f"剩余任务: {tasks}")
```

**运行结果**：

```text
取出的任务: ('task_003', '结果分析')
类型: <class 'tuple'>
剩余任务: {'task_001': '数据清洗', 'task_002': '模型训练'}
```

**关键点**：

- `popitem` 返回的是**元组** `(key, value)`，不是单独的值。这和 `pop` 返回值不同。
- 删除的是最后插入的键值对（LIFO 顺序），不是第一个或随机一个。
- 元组支持解包，可以同时获取键和值：`key, value = d.popitem()`。

#### 2.5.1 连续 popitem 清空字典

`popitem` 非常适合用 `while` 循环逐个弹出所有元素：

```python
# 用 popitem 循环取出所有任务（LIFO 顺序）
queue = {"a": 1, "b": 2, "c": 3}
print(f"初始队列: {queue}")

while queue:
    key, value = queue.popitem()
    print(f"  取出: ({key}, {value}), 剩余: {queue}")
```

**运行结果**：

```text
初始队列: {'a': 1, 'b': 2, 'c': 3}
  取出: (c, 3), 剩余: {'a': 1, 'b': 2}
  取出: (b, 2), 剩余: {'a': 1}
  取出: (a, 1), 剩余: {}
```

`while queue` 在字典非空时为 `True`，空字典为 `False`。这个模式简洁高效，不需要知道字典有多少个元素。

**关键点**：

- `while queue` 利用了空字典在布尔上下文中为 `False` 的特性，避免了先检查 `len(queue) > 0` 的冗余写法。
- 弹出顺序是 LIFO——`c` 最后插入，最先弹出；`a` 最先插入，最后弹出。

#### 2.5.2 空字典调用 popitem

对空字典调用 `popitem` 会抛出 `KeyError`：

```python
empty = {}
try:
    empty.popitem()
except KeyError as e:
    print(f"KeyError: {e}")
```

**运行结果**：

```text
KeyError: 'popitem(): dictionary is empty'
```

注意错误信息是 `popitem(): dictionary is empty`，比普通 `KeyError` 的信息更明确。在用 `while queue` 循环时不会遇到这个问题，因为循环条件已经保证了字典非空。

#### 2.5.3 popitem 的返回值解包

`popitem` 返回元组这一特性使它非常适合配合解包使用：

```python
# 场景：遍历处理并清空缓存
cache = {
    "page_1": "<html>...",
    "page_2": "<html>...",
    "page_3": "<html>...",
}

# popitem 返回元组，可以同时解包获取 key 和 value
while cache:
    page_key, page_content = cache.popitem()
    print(f"处理缓存: key={page_key}, content_len={len(page_content)}")
    print(f"  剩余缓存数: {len(cache)}")
```

**运行结果**：

```text
处理缓存: key=page_3, content_len=9
  剩余缓存数: 2
处理缓存: key=page_2, content_len=9
  剩余缓存数: 1
处理缓存: key=page_1, content_len=9
  剩余缓存数: 0
```

如果你只需要值不需要键，可以写成 `_, value = d.popitem()`。如果只需要键，可以 `key, _ = d.popitem()`。但从可读性角度，同时解包两个变量更清晰。

#### 2.5.4 popitem 的 LIFO 顺序验证

Python 3.7+ 保证字典保持插入顺序，`popitem` 删除的始终是最后插入的键值对。验证这一点：

```python
# Python 3.7+ 字典保持插入顺序，popitem 删除最后插入的
ordered = {}
ordered["first"] = 1
ordered["second"] = 2
ordered["third"] = 3
ordered["fourth"] = 4

print(f"字典内容: {ordered}")
print("popitem 顺序（LIFO）：")
while ordered:
    print(f"  {ordered.popitem()}")
```

**运行结果**：

```text
字典内容: {'first': 1, 'second': 2, 'third': 3, 'fourth': 4}
popitem 顺序（LIFO）：
  ('fourth', 4)
  ('third', 3)
  ('second', 2)
  ('first', 1)
```

弹出顺序恰好是插入顺序的逆序——`fourth` 最后插入、最先弹出，`first` 最先插入、最后弹出。

**中间插入后再 popitem**：

```python
d = {"a": 1, "b": 2}
d["c"] = 3     # c 最后插入
print(f"popitem: {d.popitem()}")  # 返回 ('c', 3)

d["d"] = 4     # d 现在最后
print(f"popitem: {d.popitem()}")  # 返回 ('d', 4)
```

**运行结果**：

```text
popitem: ('c', 3)
popitem: ('d', 4)
```

每次 `popitem` 后，如果又插入了新键值对，新插入的成为"最后插入的"，下次 `popitem` 会弹出它。

### 2.6 pop 与 popitem 对比

`pop` 和 `popitem` 都是"删除并返回"的方法，但在使用方式、返回值和适用场景上有明确区别：

| 维度 | `d.pop(key)` | `d.pop(key, default)` | `d.popitem()` |
|------|-------------|----------------------|---------------|
| 需要知道键名 | 是 | 是 | 否 |
| 删除哪个元素 | 指定的键 | 指定的键 | 最后插入的（LIFO） |
| 返回值 | 值 | 值或默认值 | `(key, value)` 元组 |
| 键/字典为空时 | `KeyError` | 返回默认值 | `KeyError` |
| 接受参数 | 1 个（key） | 2 个（key, default） | 0 个 |
| Python 3.7 前行为 | 同 | 同 | 删除**任意**键值对 |

**选择建议**：

- **知道要删除哪个键** → `pop(key)` 或 `pop(key, default)`
- **不需要知道键名，只需取一个** → `popitem()`
- **需要安全删除（键可能不存在）** → `pop(key, default)`
- **需要 LIFO 顺序处理** → `popitem()` + `while` 循环

### 2.7 popitem 模拟 LIFO 栈

`popitem` 的 LIFO 特性使它天然适合模拟栈结构。栈的核心操作是"压入"和"弹出"，`dict[key] = value` 对应压入，`popitem()` 对应弹出：

```python
# 场景：撤销操作栈，后进先出
undo_stack = {}

def push_action(action_id, description):
    undo_stack[action_id] = description
    print(f"  压入: {action_id} = {description}")

def undo_last():
    if not undo_stack:
        print("  没有可撤销的操作")
        return None
    action_id, description = undo_stack.popitem()
    print(f"  撤销: {action_id} = {description}")
    return action_id

push_action("act_001", "插入段落")
push_action("act_002", "修改格式")
push_action("act_003", "删除图片")

print("  --- 开始撤销 ---")
undo_last()
undo_last()
undo_last()
undo_last()  # 没有可撤销的
```

**运行结果**：

```text
  压入: act_001 = 插入段落
  压入: act_002 = 修改格式
  压入: act_003 = 删除图片
  --- 开始撤销 ---
  撤销: act_003 = 删除图片
  撤销: act_002 = 修改格式
  撤销: act_001 = 插入段落
  没有可撤销的操作
```

**关键点**：

- 最后压入的 `act_003` 最先被撤销，这正是 LIFO 栈的行为。
- 用字典模拟栈的好处是可以用有意义的键名标识每个操作，而列表栈只能用索引。
- `if not undo_stack` 检查栈是否为空，防止 `popitem` 抛出 `KeyError`。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

**场景 1：安全删除键**

```python
data = {"name": "Alice", "age": 30}

# 推荐：pop 带默认值，键不存在也不报错
email = data.pop("email", "")
print(f"email: {email!r}")

# 不推荐：先判断再删除，代码冗长
if "email" in data:
    email = data.pop("email")
else:
    email = ""

# 不推荐：try/except 处理键不存在
try:
    email = data.pop("email")
except KeyError:
    email = ""
```

| 写法 | 行数 | 可读性 | 安全性 |
|------|------|--------|--------|
| `data.pop("email", "")` | 1 行 | 高 | 安全 |
| `if "email" in data: ... else: ...` | 3 行 | 中 | 安全 |
| `try: ... except KeyError: ...` | 3 行 | 低 | 安全 |

**原则**：`pop(key, default)` 是处理"可能不存在的键"最简洁、最 Pythonic 的方式。

**场景 2：取出并移除值**

```python
config = {"host": "localhost", "port": 8080, "timeout": 30}

# 推荐：pop 一步完成取值和删除
timeout = config.pop("timeout")
print(f"timeout: {timeout}, config: {config}")

# 不推荐：先取值再 del，两步操作
timeout = config["timeout"]
del config["timeout"]
print(f"timeout: {timeout}, config: {config}")
```

**原则**：当需要同时取值和删除时，`pop` 一步搞定，比 `取值 + del` 更简洁。

**场景 3：遍历并清空字典**

```python
queue = {"a": 1, "b": 2, "c": 3}

# 推荐：while + popitem，简洁且不需要知道键名
while queue:
    key, value = queue.popitem()
    print(f"处理: {key}={value}")

# 不推荐：先取 keys 再逐个 pop，需要额外列表
keys = list(queue.keys())
for key in keys:
    value = queue.pop(key)
    print(f"处理: {key}={value}")
```

**原则**：当需要遍历清空字典时，`while + popitem` 是最简洁的方式，不需要先提取键列表。

### 3.2 常见错误模式

**错误 1：pop 不带默认值导致 KeyError**

```python
config = {"host": "localhost", "port": 8080}

# 错误：不确定键是否存在时不带默认值
try:
    timeout = config.pop("timeout")
except KeyError as e:
    print(f"KeyError: {e}")

# 修正：不确定键是否存在时带默认值
timeout = config.pop("timeout", 30)
print(f"timeout: {timeout}")
```

**原则**：如果你不确定键是否存在，一定要传默认值。只有在确定键一定存在时才省略默认值。

**错误 2：以为 popitem 返回值而不是元组**

```python
d = {"a": 1, "b": 2}

# 错误：以为 popitem 返回单个值
# val = d.popitem()  # val 是 ('b', 2)，不是 2
# print(val + 1)     # TypeError: can only concatenate tuple (not "int") to tuple

# 修正：popitem 返回元组，需要解包或索引
key, value = d.popitem()
print(f"key={key}, value={value}")

# 或直接索引
item = d.popitem()
print(f"value={item[1]}")
```

**原则**：记住 `pop` 返回值，`popitem` 返回 `(key, value)` 元组。混淆返回值类型是最常见的错误。

**错误 3：对空字典调用 popitem**

```python
empty = {}

# 错误：没有检查字典是否为空就调用 popitem
try:
    empty.popitem()
except KeyError as e:
    print(f"KeyError: {e}")

# 修正：用 while 循环自动检查，或先判断
d = {"a": 1}
while d:
    print(d.popitem())
```

**原则**：在使用 `popitem` 前检查字典是否为空，或用 `while d:` 循环让条件检查自动完成。

**错误 4：pop 用可变对象做默认值**

```python
# 潜在问题：可变默认值被共享
def get_tags(params):
    # 每次调用 pop("tags", []) 时，如果 "tags" 不存在，
    # 返回的是同一个列表对象
    return params.pop("tags", [])

params1 = {"name": "Alice"}
tags1 = get_tags(params1)
tags1.append("python")

params2 = {"name": "Bob"}
tags2 = get_tags(params2)
print(f"tags2: {tags2}")  # 可能包含 "python"！
```

**修正**：用 `None` 做默认值，在函数内部创建新可变对象：

```python
def get_tags(params):
    tags = params.pop("tags", None)
    if tags is None:
        tags = []
    return tags

params1 = {"name": "Alice"}
tags1 = get_tags(params1)
tags1.append("python")

params2 = {"name": "Bob"}
tags2 = get_tags(params2)
print(f"tags2: {tags2}")  # 干净的空列表
```

**原则**：当默认值是可变对象（列表、字典、集合）时，用 `None` 做默认值并在使用时创建新对象，避免共享引用。

**错误 5：在遍历字典时用 pop 修改字典**

```python
d = {"a": 1, "b": 2, "c": 3, "d": 4}

# 错误：遍历字典的同时用 pop 删除元素
# for key in d:          # RuntimeError: dictionary changed size during iteration
#     if d[key] % 2 == 0:
#         d.pop(key)

# 修正：先收集要删除的键，再统一删除
keys_to_remove = [k for k, v in d.items() if v % 2 == 0]
for key in keys_to_remove:
    d.pop(key)
print(f"过滤后: {d}")

# 修正：用字典推导式创建新字典
d2 = {"a": 1, "b": 2, "c": 3, "d": 4}
d2 = {k: v for k, v in d2.items() if v % 2 != 0}
print(f"推导式过滤: {d2}")
```

**原则**：不要在遍历字典时用 `pop` 修改字典大小，会抛出 `RuntimeError`。先收集键再删除，或用字典推导式创建新字典。

### 3.3 安全删除 vs 不安全删除

`pop` 的带默认值和不带默认值两种形式体现了两种不同的错误处理策略：

```python
data = {"name": "Alice", "age": 30}

# --- 不安全：不带默认值，键不存在抛异常 ---
print("不安全删除（可能抛异常）：")
try:
    data.pop("email")  # email 不存在
except KeyError as e:
    print(f"  KeyError: {e}")

# --- 安全：带默认值，键不存在返回默认值 ---
data = {"name": "Alice", "age": 30}
print("安全删除（带默认值）：")
email = data.pop("email", "")
print(f"  email={email!r}, data={data}")
phone = data.pop("phone", "")
print(f"  phone={phone!r}, data={data}")
```

**运行结果**：

```text
不安全删除（可能抛异常）：
  KeyError: 'email'
安全删除（带默认值）：
  email='', data={'name': 'Alice', 'age': 30}
  phone='', data={'name': 'Alice', 'age': 30}
```

**策略选择**：

| 策略 | 写法 | 适用场景 |
|------|------|---------|
| 快速失败 | `d.pop(key)` | 键应该存在，不存在说明程序有 bug |
| 安全降级 | `d.pop(key, default)` | 键可能不存在，不存在时用默认值即可 |

**原则**：当你希望"键不存在"是一个需要暴露的错误时，用 `pop(key)`；当你希望"键不存在"是一种正常的、需要优雅处理的场景时，用 `pop(key, default)`。

### 3.4 pop vs popitem 选择指南

在实际编码中，什么时候用 `pop`，什么时候用 `popitem`？核心判断依据是**你是否知道要删除哪个键**：

```python
# --- pop：知道要删哪个键 ---
settings = {"volume": 80, "brightness": 60, "contrast": 50}
# 需要移除 brightness（知道键名）
brightness = settings.pop("brightness")
print(f"pop 删除已知键 'brightness': {brightness}")
print(f"剩余: {settings}")

# --- popitem：不需要知道键名，取最后插入的 ---
processed = {"item_1": "done", "item_2": "done", "item_3": "done"}
# 只需要取一个（最后插入的），不需要知道键名
key, value = processed.popitem()
print(f"popitem 取出最后一个: ({key}, {value})")
print(f"剩余: {processed}")
```

**决策流程**：

```text
需要删除字典元素
        │
        ▼
  知道要删哪个键?
   ┌────┴────┐
   是        否
   │         │
   ▼         ▼
  pop      popitem
   │         │
   ▼         │
键可能不存在?   │
┌──┴──┐      │
是     否     │
│     │      │
▼     ▼      ▼
pop(key,  pop(key)  popitem()
default)
```

| 场景 | 推荐方法 | 原因 |
|------|---------|------|
| 提取已知键的值并删除 | `pop(key)` | 知道键名，一步完成 |
| 安全提取可能不存在的键 | `pop(key, default)` | 避免 KeyError |
| LIFO 顺序处理全部元素 | `popitem()` + `while` | 不需要知道键名 |
| 模拟栈的弹出操作 | `popitem()` | LIFO 行为天然匹配 |
| 删除并获取单个元素 | `popitem()` | 不关心具体是哪个 |
| 条件过滤删除多个元素 | 先收集键再 `pop` | 避免遍历时修改字典 |

## 4. 原理

### 4.1 pop 与 popitem 的内部机制

字典在 Python 内部是用哈希表实现的。`pop` 和 `popitem` 都涉及哈希表元素的删除，但机制有所不同。

**pop 的执行流程**：

1. 对 `key` 计算哈希值，定位到哈希表中的槽位。
2. 检查槽位是否存在该键（处理哈希冲突链）。
3. 如果找到：取出值，将该槽位标记为"已删除"（dummy entry），返回值。
4. 如果未找到且有 `default`：返回 `default`。
5. 如果未找到且无 `default`：抛出 `KeyError`。

```text
pop("timeout", 30)
        │
        ▼
  计算 hash("timeout")
  定位哈希表槽位
        │
        ▼
   槽位有该键?
   ┌────┴────┐
   是        否
   │         │
   ▼         ▼
 取出值      有 default?
 删除槽位   ┌──┴──┐
 返回值     是     否
            │      │
            ▼      ▼
        返回    raise KeyError
        default
```

**popitem 的执行流程**：

1. 直接访问字典内部维护的"最后插入位置"。
2. 取出该位置的键值对。
3. 从哈希表和插入顺序链表中删除该条目。
4. 返回 `(key, value)` 元组。
5. 如果字典为空：抛出 `KeyError`。

```text
popitem()
    │
    ▼
 字典为空?
 ┌──┴──┐
 是    否
 │     │
 ▼     ▼
raise  访问最后插入位置
KeyError    │
            ▼
      取出 (key, value)
      删除该条目
      返回元组
```

**关键差异**：

| 维度 | `pop` | `popitem` |
|------|-------|-----------|
| 是否需要计算哈希 | 是，需要用哈希定位键 | 否，直接访问最后位置 |
| 时间复杂度 | O(1) 平均（哈希查找） | O(1)（直接访问） |
| 删除后是否触发缩容 | 可能（连续删除后哈希表负载过低） | 同 |

### 4.2 为什么 popitem 是 LIFO 顺序

Python 3.7 起字典保证插入顺序，这一保证的实现依赖内部维护的插入顺序链表。`popitem` 删除"最后插入的"键值对，实际上是访问这个链表的尾部。

```python
# Python 3.7+ 字典内部结构（简化示意）
d = {"a": 1, "b": 2, "c": 3}

# 内部维护的插入顺序链表：a → b → c
# popitem 访问链表尾部 → c
# 删除后链表变为：a → b
```

```text
插入顺序链表：
  head → [a:1] → [b:2] → [c:3] ← tail
                              │
                              ▼
                         popitem()
                         删除 [c:3]
                              │
                              ▼
  head → [a:1] → [b:2] ← tail
```

**Python 3.6 及之前**：字典不保证插入顺序，`popitem` 删除的是哈希表中的**任意**一个元素（取决于哈希表内部排列），不可预测。如果你的代码需要在旧版本运行，不能依赖 `popitem` 的 LIFO 行为。

### 4.3 3.7 前后 popitem 行为差异

`popitem` 的行为在 Python 3.7 是一个重要分界线：

| Python 版本 | 字典是否有序 | `popitem` 删除的元素 |
|------------|------------|-------------------|
| 3.6 及之前 | 不保证顺序 | 任意键值对（不可预测） |
| 3.7+ | 保证插入顺序 | 最后插入的键值对（LIFO） |

```python
# Python 3.7+ 行为（确定性的 LIFO）
d = {"a": 1, "b": 2, "c": 3}
print(d.popitem())  # 确定输出：('c', 3)

# Python 3.6 及之前（不可预测）
# d = {"a": 1, "b": 2, "c": 3}
# print(d.popitem())  # 可能是 ('a', 1)、('b', 2) 或 ('c', 3)
```

**实践建议**：

- 如果你的代码运行在 Python 3.7+，可以放心使用 `popitem` 的 LIFO 特性。
- 如果需要兼容 Python 3.6 及之前，不要依赖 `popitem` 的顺序，改用 `collections.OrderedDict`。

### 4.4 删除操作与哈希表缩容

当你频繁使用 `pop` 或 `popitem` 删除大量键值对后，哈希表中会出现很多"已删除"标记（dummy entries）。这些标记虽然不再保存有效数据，但仍然占用内存空间。

```python
# 大量删除后哈希表状态
d = {i: i * 2 for i in range(1000)}

# 删除 800 个键
for i in range(800):
    d.pop(i, None)

# 此时哈希表容量仍为 1000+，但有效元素只有 200
# 800 个 dummy entries 占据空间
print(f"剩余元素: {len(d)}")
print(f"哈希表容量远大于 {len(d)}（内部有空位）")
```

Python 字典在删除元素后不会立即缩容——只有在下一次插入时如果发现负载因子过低，才会触发重建哈希表。这是为了避免频繁删除-插入导致的反复重建开销。

**实践影响**：

- 在正常使用中，你不需要关心这个细节——Python 的字典实现已经很好地处理了性能问题。
- 如果你一次性删除了字典中绝大多数元素，并且后续不再添加新元素，可以考虑创建一个新字典来节省内存：`d = dict(d)`。

## 5. 总结

本文围绕字典的 `pop` 和 `popitem` 方法展开，主要介绍了以下内容：

- `pop(key)` 通过指定键删除并返回对应的值，键不存在时抛出 `KeyError`；`pop(key, default)` 在键不存在时安全返回默认值，不抛异常
- `pop` 不接受零参数——与列表的 `pop()` 不同，字典的 `pop` 必须指定键，因为字典在 Python 3.7 前不保证顺序
- `pop` 的默认值可以是任意类型（数字、字符串、列表、字典、`None`），当默认值是可变对象时需注意共享引用问题
- `pop` 的经典实战场景包括一次性配置提取（取出特殊参数后剩余透传）、计数消耗（用完后自动移除）、安全删除（不确定键是否存在时优雅降级）
- `popitem()` 不需要参数，自动删除并返回最后插入的键值对 `(key, value)` 元组，空字典调用时抛出 `KeyError`
- Python 3.7+ 保证 `popitem` 按 LIFO（后进先出）顺序删除；Python 3.6 及之前删除的是任意键值对
- `popitem` 适合用于 `while` 循环遍历清空字典、模拟 LIFO 栈结构等不需要知道具体键名的场景
- `pop` 与 `popitem` 的核心区别：`pop` 需要指定键并返回值，`popitem` 不需要指定键并返回元组
- 最佳实践：安全删除用 `pop(key, default)`，取值并删除用 `pop(key)`，遍历清空用 `while + popitem()`，不要在遍历字典时用 `pop` 修改字典大小
- 常见错误：不带默认值导致 `KeyError`、以为 `popitem` 返回值而非元组、对空字典调用 `popitem`、用可变对象做默认值导致共享引用、遍历时用 `pop` 修改字典
- 原理层面：`pop` 通过哈希查找定位键（O(1)），`popitem` 直接访问插入顺序链表尾部（O(1)）；Python 3.7+ 的字典有序性保证由内部插入顺序链表实现，`popitem` 的 LIFO 行为依赖此链表
