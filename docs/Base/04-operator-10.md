## 1. 介绍

### 1.1 什么是运算符优先级

运算符优先级(operator precedence)是 Python 在一个含多种运算符的表达式里,决定**哪个运算符先算、哪个后算**的规则。它就像数学里"先乘除后加减"——`2 + 3 * 4` 等于 14(先乘 3*4=12,再加 2)而不是 20(先加 2+3=5,再乘 4),就是因为 `*` 优先级高于 `+`。优先级是表达式求值顺序的根基,理解它才能正确预判(和书写)复杂表达式的结果。

```python
print(2 + 3 * 4)          # 14 —— * 优先于 +,先算 3*4
print((2 + 3) * 4)        # 20 —— 括号强制先算 2+3
print(2 ** 3 ** 2)        # 512 —— ** 右结合,2**(3**2)=2**9=512
print(not True or False)  # False —— not 高于 or,(not True) or False
print(5 > 3 and 2 > 1)    # True —— 比较高于 and,(5>3) and (2>1)
```

优先级解决的核心问题是"省去括号"——如果每个表达式都全加括号,优先级就无意义;但全加括号极其啰嗦。Python(及多数语言)用一套优先级规则让"自然写法"正确解析:`2 + 3 * 4` 不写括号也能得 14。但这套规则有几十个运算符的层级,复杂表达式仍可能让人误判,所以**复杂场景仍推荐加括号**——优先级是"让简单表达式自然",不是"让复杂表达式裸奔"。

理解优先级,要抓住两个概念:

- **优先级(precedence)**:不同运算符之间的"谁先算"。高优先级先算,低优先级后算。
- **结合性(associativity)**:同优先级运算符的"从哪边算"。多数是左结合(从左到右),但 `**`(乘方)、赋值类、三元等是右结合(从右到左)。

```python
# 优先级:* 高于 +
print(1 + 2 * 3)          # 7(先 *)
# 结合性:- 左结合(左到右)
print(10 - 3 - 2)         # 5 —— (10-3)-2=7-2,不是 10-(3-2)=9
# ** 右结合(右到左)
print(2 ** 3 ** 2)        # 512 —— 2**(3**2),不是 (2**3)**2=64
```

Python 优先级与 C/Java 的几个显著差异(也是本篇重点):

- **比较运算符可链式,且同级无结合性**:`a < b < c` 是 `a<b and b<c`(链式),不是 C 的 `(a<b)<c`。Python 比较运算符被特殊解析为链式,打破常规结合性(详见《链式比较》)。
- **`**` 右结合,且优先级高于一元负号**:`-2 ** 2` 是 `-4`(`-(2**2)`),不是 `4`(`(-2)**2`)。这与数学符号直觉冲突,是高频陷阱。
- **位运算优先级高于比较**:`5 > 3 & 2` 是 `5 > (3&2)`,不是 `(5>3) & 2`。这与逻辑运算符(低于比较)相反,C 程序员易错。
- **海象 `:=` 与三元 `x if c else y` 优先级极低**:仅高于 lambda,在复合表达式里几乎必须加括号。

```python
# 四处差异直观对比
print(1 < 2 < 3)          # True —— 链式(1<2 且 2<3),C 是 (1<2)<3
print(-2 ** 2)            # -4 —— ** 高于一元 -,即 -(2**2),不是 (-2)**2
print(5 > 3 & 2)          # False? 3&2=2,5>2=True? 实际 5 > (3&2)=5>2 比较为 True
print(True)               # 上式 5 > (3&2) = 5>2 = True(注意链式?不,单比较)
# 海象/三元低优先级
print((n := 5) > 3)       # True —— 必须括号,否则 n := (5>3) 错
```

本篇是「运算符与表达式」大章节的收尾篇,要把前 9 篇涉及的运算符(算术、赋值、比较、逻辑、位、成员、三元、海象等)的优先级**总成一张完整表**,并讲透优先级规则、结合性、链式比较的特殊解析、括号的使用策略、常见陷阱,以及求值原理。它是前 9 篇的"索引页",让你在任何复杂表达式前都能快速查到运算顺序、判断是否需加括号。

### 1.2 优先级 vs 结合性

先把优先级和结合性这两个概念彻底分清,这是理解一切优先级问题的基础。

**优先级(precedence)**:不同运算符之间的运算顺序。高优先级先算。

```python
print(2 + 3 * 4)          # 14 —— *(高) 先于 +(低)
print(2 * 3 + 4)          # 10 —— * 先于 +
print(2 + 3 == 5)         # True —— +(高) 先于 ==(低),(2+3)==5
```

**结合性(associativity)**:同优先级运算符的运算方向。左结合(从左到右)或右结合(从右到左)。

```python
# 左结合(多数二元运算符):从左到右
print(10 - 3 - 2)         # 5 —— (10-3)-2,左到右
print(20 / 4 / 2)         # 2.5 —— (20/4)/2,左到右
print(12 // 3 // 2)       # 2 —— (12//3)//2

# 右结合(**、赋值、三元、海象):从右到左
print(2 ** 3 ** 2)        # 512 —— 2**(3**2),右到左
x = y = 5                 # 右结合:x=(y=5),先 y=5 再 x=5
print(x, y)               # 5 5
```

⚠️ **比较运算符特殊:同级但无结合性(链式)**。Python 的比较运算符(`< > <= >= == != is in`)同级,但不走左/右结合,而是**链式**:`a < b < c` 解析为 `a < b and b < c`,不是 `(a < b) < c`。这是 Python 独有的特殊解析,详见 §1.4、§4.1、《链式比较》。

```python
print(1 < 2 < 3)          # True —— 链式:1<2 且 2<3(不是 (1<2)<3 = True<3)
# 对比 C:1 < 2 < 3 → (1<2)<3 → 1<3 → 1(True 当 1) —— 完全不同语义
```

理解优先级(谁先)+ 结合性(同级的方向)+ 链式特殊(比较同级不走结合),就掌握了表达式求值顺序的全部规则。

### 1.3 运算符优先级完整表

下面是本篇的核心——Python 运算符优先级完整表,**从高到低**排列。同行的运算符优先级相同。这张表是后续所有讨论的基础,值得反复查阅。

| 优先级 | 运算符 | 名称 | 结合性 | 备注 |
|--------|--------|------|--------|------|
| 1(最高) | `(expressions...)`, `[...]`, `{...}`, `{k:v}` | 括号/列表/字典/集合字面量 | — | 括号强制提升优先级 |
| 2 | `x[index]`, `x[index:index]`, `x(args...)`, `x.attribute` | 索引/切片/调用/属性 | — | 成员访问,左到右 |
| 3 | `await x` | await | — | 异步 |
| 4 | `**` | 乘方 | **右结合** | 高于一元符号!`-2**2=-4` |
| 5 | `+x`, `-x`, `~x` | 一元正/负/取反 | — | 一元 |
| 6 | `*`, `@`, `/`, `//`, `%` | 乘/矩阵乘/除/整除/取余 | 左结合 | 算术 |
| 7 | `+`, `-` | 加/减 | 左结合 | 算术 |
| 8 | `<<`, `>>` | 左移/右移 | 左结合 | 位移 |
| 9 | `&` | 按位与 | 左结合 | 位运算 |
| 10 | `^` | 按位异或 | 左结合 | 位运算 |
| 11 | `\|` | 按位或 | 左结合 | 位运算 |
| 12 | `in`, `not in`, `is`, `is not`, `<`, `<=`, `>`, `>=`, `!=`, `==` | 比较/成员/身份 | **链式**(非结合) | 同级链式解析 |
| 13 | `not x` | 逻辑非 | — | 一元 |
| 14 | `and` | 逻辑与 | 左结合 | 短路 |
| 15 | `or` | 逻辑或 | 左结合 | 短路 |
| 16 | `if ... else` | 条件表达式(三元) | 右结合 | `x if c else y` |
| 17 | `lambda` | lambda 表达式 | — | 匿名函数 |
| 18 | `:=` | 海象运算符 | — | 赋值表达式,3.8+ |
| 19(最低) | `=`,`+=`,`-=`,... | 赋值/增强赋值 | 右结合 | 语句,非表达式 |

**记忆要点(从高到低的粗粒度分组)**:

```
括号/成员访问 > ** > 一元符号 > 算术(* / 先于 + -)> 位移 > 位运算(& ^ |)> 
比较/成员/身份(链式)> not > and > or > 三元 > lambda > 海象 > 赋值
```

几个**最该记住**的优先级关系(高频陷阱):

1. **`**` 高于一元 `-`**:`-2 ** 2 = -4`(是 `-(2**2)`,非 `(-2)**2`)。
2. **算术高于比较**:`a + b == c` 是 `(a+b) == c`,比较最后算。
3. **位运算(`& ^ | << >>`)高于比较**:`a & b == c` 是 `a & (b==c)`?需查——实际比较低于位运算,故 `a & b == c` 是 `(a & b) == c`?见 §1.5 澄清。
4. **比较高于 `not` > `and` > `or`**:`a < b and c > d` 是 `(a<b) and (c>d)`,不用括号。
5. **赋值/三元/海象优先级最低**,复合表达式里几乎要全加括号。

这张表后续每节会按分组展开,讲清各组的优先级关系与陷阱。

### 1.4 链式比较:打破常规结合性

Python 的比较运算符(优先级 12)有一个特殊性:它们同级,但**不走左/右结合**,而是被解析为**链式**(`a < b < c` = `a < b and b < c`)。这是 Python 相对所有语言最独特的优先级规则,值得单独强调。

常规二元运算符(如 `+`、`*`)按结合性解析:`a + b + c` 左结合为 `(a + b) + c`。若比较运算符也这样,`a < b < c` 会变成 `(a < b) < c`——先得布尔 `a < b`(0/1),再和 `c` 比,这是 C 的"伪链式",语义错误。

Python 解析器对比较运算符做**特殊规则**:`a OP1 b OP2 c ...` 被解析为链式 `a OP1 b and b OP2 c and ...`,而非左结合。这让 `1 < x < 10` 真正表示"x 在 (1,10) 区间",而非 `(1 < x) < 10`。

```python
x = 5
print(1 < x < 10)        # True —— 链式:1<x 且 x<10(不是 (1<x)<10)
print(0 < x < 10 < 100)  # True —— 三段链式:0<x 且 x<10 且 10<100
print(1 < x > 0)         # True —— 混合链式:1<x 且 x>0(合法但难读)
# 对比 C:1 < x < 10 → (1<x)<10 → (0或1)<10 → 恒真(语义错)
```

链式还让**混合比较运算符**有特殊语义:`a < b == c` 是 `a < b and b == c`(链式),不是 `a < (b == c)`(按优先级拆)。这是链式打破常规优先级的体现——比较链是一体的,不按运算符优先级拆段。详见《链式比较》。

```python
print(1 < 5 == 5)        # True —— 链式:(1<5) 且 (5==5)
print(1 < (5 == 5))      # False —— 非链式:1 < True = 1 < 1 = False
# 两者不同!链式不按优先级拆,是一体"且"
```

理解链式比较的特殊解析(同级无结合性、一体"且"),就理解了为何比较运算符优先级表里标注"链式(非结合)"而非"左/右结合"。这是 Python 优先级体系里唯一打破常规结合性的地方。

### 1.5 位运算与比较的优先级:易错重灾区

位运算符(`& ^ | << >>`,优先级 8-11)与比较运算符(`< > ==`等,优先级 12)的优先级关系,是 Python 表达式里**最易出错**的地方,因为它们与逻辑运算符(低于比较)相反,且 C 程序员直觉相悖。

**位运算优先级高于比较**(比较是 12,位运算 8-11 更高):

```python
# & 高于 ==
print(3 & 4 == 0)        # 解析:3 & (4 == 0) = 3 & False = 3 & 0 = 0(False)
# 因 == 低于 &,先算?不对——等下澄清,需实测
```

⚠️ 这里有个常见误解需要澄清:**比较运算符(12)优先级低于位运算(8-11)**,所以 `a & b == c` 解析为... 让我实测确认:

```python
print(3 & 4)             # 0(011 & 100 = 000)
print(3 & 4 == 0)        # ?
# 若 (3 & 4) == 0 → 0 == 0 → True
# 若 3 & (4 == 0) → 3 & False → 3 & 0 → 0 → False
# 实测看结果
```

实测 `3 & 4 == 0` 得 `True`(在 Python 3.x)——说明解析为 `(3 & 4) == 0`?那意味着 `&` 高于 `==`(`&` 先算)。等下,这与"比较低于位运算"一致:`&`(9)高于 `==`(12),先 `3 & 4 = 0`,再 `0 == 0 = True`。

但**官方文档和实际行为**:实际上 Python 中 `==` 与 `&` 的优先级——`&`(9)高于比较(12),故 `a & b == c` 是 `(a & b) == c`。下面用更多实测确认:

```python
print((3 & 4) == 0)      # True —— 显式括号:3&4=0,0==0=True
print(3 & 4 == 0)        # True —— 无括号同上,说明 &(9) 高于 ==(12),先 & 再 ==
print(3 & (4 == 0))      # 0 —— 反向括号:3 & False = 3 & 0 = 0
```

确认:`&`(优先级 9)**高于** `==`(优先级 12),`3 & 4 == 0` = `(3 & 4) == 0` = True。但**强烈不推荐依赖这个**——`a & b == c` 到底先算 `&` 还是 `==`,即便查表也容易记错,且读者难以一眼判断。**位运算与比较混用,一律加括号**:

```python
# 推荐:加括号
if (perm & READ) != 0: ...        # 明确:先 &,再 !=
if (flags & MASK) == MASK: ...    # 明确
if (x << 2) > threshold: ...      # 移位后比较

# 不推荐:依赖优先级
# if perm & READ != 0: ...        // 虽对但难读,易误判
```

位运算-vs-比较的优先级陷阱,加上"逻辑运算符(低于比较)与位运算相反",让 C 程序员极易把 `&` 当 `and` 用且优先级错乱(详见《位运算符》《逻辑运算符与短路求值》)。**原则:位运算、比较、逻辑三者混用,一律括号明示**,不依赖记忆与直觉。

## 2. 核心内容

本章按优先级分组详解各运算符的优先级与结合性,每节遵循"规则 → demo → 陷阱 → 场景"展开。重点是 `**`/一元符号、算术、位运算vs比较、逻辑、三元/海象/赋值最低优先级。

### 2.1 括号与成员访问(最高优先级)

括号 `()` 和成员访问(`[]` 索引、`()` 调用、`.` 属性)是最高优先级,它们"强制"或"确定"运算顺序。

**括号 `()`**:强制改变优先级,括号内先算。

```python
print(2 + 3 * 4)          # 14(* 先)
print((2 + 3) * 4)        # 20(括号强制 + 先)
print(2 ** (3 + 1))       # 16(括号先 3+1=4,2**4)
# 括号可嵌套,内层先算
print(((1 + 2) * 3) - 1)  # 8(1+2=3,3*3=9,9-1=8)
```

括号是"覆盖优先级"的工具——无论默认优先级如何,括号内总先算。生产代码复杂表达式靠括号明示意图,而非依赖优先级记忆。

**成员访问 `[]`/`()`/`.`**:索引、切片、调用、属性访问,优先级仅次于括号。

```python
lst = [1, 2, 3]
print(lst[0] + 1)         # 2 —— lst[0] 先(成员访问),再 + 1
print(len([1,2,3]) + 1)   # 4 —— len(...) 调用先,再 +1
print("hello".upper()[0]) # 'H' —— .upper() 调用,再 [0] 索引(左到右链式访问)
# 成员访问左到右链式:obj.attr.method()[0]
```

成员访问"紧贴"对象,优先级极高,几乎总是先算。`obj.attr.method()[0]` 从左到右:`.attr` → `.method()` → `[0]`。这让"方法链 + 索引"自然:无需括号,`a.b().c[0]` 从左到右执行。

⚠️ **函数调用 `f()` 与乘法 `f * g` 的优先级**:`f(a, b)` 是调用(`f` 后跟 `(args)`),`f * (a, b)` 是 `f` 乘元组。调用 `()` 优先级极高,故 `f(a, b)` 一定是调用,不会被误解为 `f * (a,b)`。但 `f (a, b)`(f 后空格)仍被解析为调用 `f(a,b)`——故函数名与括号间别加空格(易误读)。

### 2.2 乘方 `**`:右结合,高于一元符号(重点)

`**`(乘方)优先级 4,有两个易错特性:**右结合**和**优先级高于一元符号**。

**`**` 右结合**:`a ** b ** c` 是 `a ** (b ** c)`(从右到左),不是 `(a ** b) ** c`。

```python
print(2 ** 3 ** 2)        # 512 —— 2 ** (3**2) = 2**9 = 512(右结合)
print((2 ** 3) ** 2)      # 64 —— 显式左括号:8**2 = 64
# 幂塔右结合源自数学约定 a^b^c 默认右结合
```

`**` 右结合源于数学中幂运算的约定(幂塔右结合)。`2 ** 3 ** 2 = 512` 而非 64,这是新手最常误判的——很多人直觉左结合算成 64。

**`**` 优先级高于一元 `-`**:`-2 ** 2` 是 `-(2 ** 2) = -4`,不是 `(-2) ** 2 = 4`。

```python
print(-2 ** 2)            # -4 —— ** 高于一元 -,(2**2)=4,再取负 -4
print((-2) ** 2)          # 4 —— 括号先 -2,再 **2 = 4
print(-2 ** 3)            # -8 —— -(2**3) = -8
print(2 ** -2)            # 0.25 —— 一元 - 在指数,2 ** (-2) = 1/4
```

`-2 ** 2 = -4` 是最高频陷阱:数学里"负 2 的平方"可能直觉为 4,但 Python 解析为"2 的平方取负 = -4"(因 `**` 优先级高于一元 `-`)。要"负 2 的平方"必须写 `(-2) ** 2`。在把数学公式转代码时,凡"负底的幂"一律加括号。

**`**` 与其他算术**:`**` 高于 `* / // %`,更高于 `+ -`。

```python
print(2 * 3 ** 2)         # 18 —— ** 先,3**2=9,2*9=18
print(2 ** 2 * 3)         # 12 —— ** 先,2**2=4,4*3=12
print(2 + 3 ** 2)         # 11 —— ** 先,9,2+9=11
```

`**` 在所有算术里最高,故 `2 * 3 ** 2 = 18`(先乘方)。理解 `**` 右结合 + 高于一元符号,就避开了乘方表达式两个最大的坑。

### 2.3 一元运算符 `+` `-` `~`

一元正 `+x`、一元负 `-x`、按位取反 `~x`(优先级 5),优先级低于 `**` 但高于算术二元运算。

```python
print(-5)                 # -5(一元负)
print(+5)                 # 5(一元正,基本无效果)
print(~5)                 # -6(取反 ~5 = -6)
# 一元符号高于 * / + -
print(-3 * 2)             # -6 —— (-3) * 2,一元 - 先
print(-3 + 2)             # -1 —— (-3) + 2
print(~5 & 0xFF)          # 250 —— (~5) & 0xFF,~ 先于 &
```

⚠️ **一元符号低于 `**`**(§2.2 已强调):`-2 ** 2 = -4`,一元 `-` 在 `**` 之后才作用。这是一元符号最该记的优先级关系。

**多个一元符号叠加**:

```python
print(--5)                # 5 —— -(-5) = 5(两次负号)—— 但 Python 无 --,这是 -(-5)
print(- -5)               # 5 —— -(-5),空格分开两个一元 -
print(~~5)                # 5 —— ~(~5) = ~(-6) = 5(两次取反还原)
print(not not 5)          # True —— 两次 not(not 5 = False,not False = True)
```

`--5` 在 Python 是 `-(-5) = 5`(两次一元负),不是 C 的自减(Python 无 `--`)。`~~5 = 5`(两次取反还原)。`not not x` 是"转 bool"的技巧(等价 `bool(x)`)。

### 2.4 算术运算符 `* / // %` 先于 `+ -`(重点)

算术运算符分两组:`* / // %`(乘除类,优先级 6)高于 `+ -`(加减类,优先级 7)。这是"先乘除后加减"的 Python 版。

**`* / // %` 同级,左结合**:

```python
print(2 * 3 / 4)          # 1.5 —— (2*3)/4 = 6/4,左到右
print(10 % 3 * 2)         # 2 —— (10%3)*2 = 1*2,左到右(% 和 * 同级)
print(20 // 3 // 2)       # 3 —— (20//3)//2 = 6//2,左结合
print(7 / 2 // 1)         # 3.0 —— (7/2)//1 = 3.5//1 = 3.0
```

`* / // %` 同级左结合,从左到右算。`10 % 3 * 2` 是 `(10%3)*2`(`%` 和 `*` 同级,左到右,先 `%`)。

**`+ -` 同级,左结合,低于 `* / // %`**:

```python
print(2 + 3 - 1)          # 4 —— (2+3)-1,左结合
print(10 - 3 + 2)         # 9 —— (10-3)+2
print(2 * 3 + 4)          # 10 —— * 先,(2*3)+4
print(2 + 3 * 4)          # 14 —— * 先,2+(3*4)
print(10 - 2 * 3)         # 4 —— * 先,10-(2*3)
```

加减低于乘除,故 `2 + 3 * 4 = 14`(先乘)。加减同级左结合。

**矩阵乘 `@`**:优先级与 `* / // %` 同级(6),用于 numpy 等矩阵乘法,日常少用。

⚠️ **算术与比较/逻辑混用**:算术高于比较,比较高于逻辑,故 `a + b == c and d > 0` 自然解析:

```python
print(2 + 3 == 5 and 10 > 0)   # True —— ((2+3)==5) and (10>0)
# 算术(+)→ 比较(==)→ 逻辑(and),层层降低,不用括号
```

`2 + 3 == 5 and 10 > 0` 因优先级层层降低(算术 > 比较 > 逻辑),自然解析为 `((2+3)==5) and (10>0)`,无需括号。这就是优先级"让自然写法正确"的价值。

### 2.5 位移 `<<` `>>`

位移 `<<`(左移)、`>>`(右移)优先级 8,低于算术(`+ -`),高于位逻辑(`& ^ |`)。

```python
print(1 << 2 + 1)         # 8 —— + 高于 <<,(2+1)=3,1<<3=8
print(1 + 1 << 2)         # 8 —— + 高于 <<,(1+1)=2,2<<2=8
print(0b1010 << 2)        # 40 —— 0b101000 = 40
print(0b1010 >> 1)        # 5 —— 0b101 = 5
# 位移高于 &
print(0b1 << 2 & 0b111)   # 4 —— (1<<2) & 7 = 4 & 7 = 4
```

⚠️ **位移低于算术**:`1 << 2 + 1` 是 `1 << (2+1)`(`+` 高于 `<<`),不是 `(1<<2)+1`。这与"位运算通常低"的直觉不同——位移在算术之下,但在位逻辑之上。位移与算术混用加括号:`(1 << 2) + 1` 或 `1 << (2 + 1)` 明示。详见《位运算符》。

### 2.6 位逻辑 `&` `^` `|`(优先级递减)

位逻辑三个运算符优先级递减:`&`(9) > `^`(10) > `|`(11),都左结合。

```python
print(0b1100 & 0b1010)    # 8 —— &(9)
print(0b1100 | 0b1010)    # 14 —— |(11)
print(0b1100 ^ 0b1010)    # 6 —— ^(10)
# & 高于 ^ 高于 |
print(0b1100 & 0b1010 | 0b0001)  # 9 —— (& 先)0b1000 | 0b0001 = 0b1001 = 9
print(0b1100 | 0b1010 & 0b0001)  # 12 —— (& 先)0b1010 & 0b0001=0,0b1100|0=0b1100=12
```

`& > ^ > |` 的优先级递减意味着 `a & b | c` 是 `(a & b) | c`(`&` 先),`a | b & c` 是 `a | (b & c)`。这让"先与后或"自然(类似"先乘后加"),但可读性仍差,**位逻辑混用建议加括号**:`(a & b) | c` 明示。

⚠️ **`^` 是异或不是乘方**(§1.1 已提):`2 ^ 10 = 8`(异或),不是 1024(乘方是 `**`)。从其他语言/数学迁来常误用。详见《位运算符》《算术运算符》。

```python
print(2 ** 10)            # 1024(乘方 **)
print(2 ^ 10)             # 8(异或 ^)—— 别混淆!
```

### 2.7 比较/成员/身份(链式,重点)

比较(`< > <= >= == !=`)、成员(`in not in`)、身份(`is is not`)优先级 12,**同级且链式**(不走结合)。它们高于逻辑(`not and or`),低于位运算。

```python
# 比较高于逻辑
print(5 > 3 and 2 > 1)    # True —— (5>3) and (2>1),不用括号
print(1 < 2 or 3 > 5)     # True —— (1<2) or (3>5)
# 成员/身份同级
print("a" in "abc" and 1 is 1)   # True —— (in) and (is) 同级链式?不,被 and 分隔
# 实际:("a" in "abc") and (1 is 1)
```

**比较同级链式**:`a < b < c` 是链式 `a<b and b<c`,不是结合。详见 §1.4、《链式比较》。这是这组运算符最特殊的优先级规则。

```python
print(1 < 2 < 3)          # True —— 链式
print(1 < 3 > 2)          # True —— 混合链式:1<3 且 3>2
print(1 == 1 == 1)        # True —— 三者相等
print(1 != 2 != 1)        # True —— 相邻不等(注意非"互异",见《链式比较》)
```

⚠️ **比较组成员/身份混合链式的可读性陷阱**:`a < b in c` 是 `a<b and b in c`(链式),虽合法但极难读:

```python
# 合法但难读
# x < y in lst   →  (x < y) and (y in lst)
# 不推荐,展开:
if (x < y) and (y in lst): ...
```

混合比较/成员/身份的链式虽合法,但读者难以一眼看懂"中间项同时参与两段",应展开为显式 `and`。**链式仅在"单一运算符递进"(如范围 `a < x < b`)时清晰**,混合运算符链式展开。

### 2.8 逻辑运算符 `not` > `and` > `or`(重点)

逻辑运算符优先级:`not`(13) > `and`(14) > `or`(15),`and`/`or` 左结合,`not` 一元。

```python
# not 高于 and 高于 or
print(not True or False)         # False —— (not True) or False = False or False
print(not True and False)        # False —— (not True) and False
print(True or False and False)   # True —— True or (False and False)=True or False
print(not 5 > 3)                 # False —— not (5>3) = not True(比较高于 not)
```

**三者优先级 `not > and > or`** 让 `a or b and c` 是 `a or (b and c)`("与"比"或"紧,类似乘比加),`not a and b` 是 `(not a) and b`(`not` 先作用于 a)。这匹配布尔代数惯例。

**比较运算符高于逻辑**:`5 > 3 and 2 > 1` 是 `(5>3) and (2>1)`,不用括号。这让"比较 + 逻辑"自然书写。

**`not` 低于比较**:`not 5 > 3` 是 `not (5 > 3)` = `not True` = `False`(`not` 在比较之后)。要"非整个比较结果"直接 `not (a > b)`,但要"非 a 再比较"(`(not a) > b`)则需括号(通常无意义)。

⚠️ **`not` 优先级陷阱**:`not a and b` 是 `(not a) and b`,不是 `not (a and b)`:

```python
print(not True and False)   # False —— (not True) and False = False and False
print(not (True and False)) # True —— not False = True
# 两者不同!not 只作用于紧跟的 a,要作用于整个 and 加括号
```

`not a and b` 默认 `(not a) and b`(`not` 优先级高于 `and`)。要 `not (a and b)` 必须加括号。这是 `not` 最易错的优先级点。详见《逻辑运算符与短路求值》。

### 2.9 三元、lambda、海象:极低优先级(重点)

三元 `x if c else y`(16)、lambda(17)、海象 `:=`(18)优先级**极低**(仅高于赋值),在复合表达式里几乎必须加括号。

**三元 `x if c else y` 优先级低**:

```python
# 三元优先级低于算术
x = 5
print(x + 1 if x > 0 else 0)   # 6 —— 解析为 (x+1) if (x>0) else 0
print((x + 1) if x > 0 else 0) # 6 —— 显式,与上行同
print(x + (1 if x > 0 else 0)) # 6 —— 不同解析:x + (1 if..else 0),x=5 时也 6
```

⚠️ **关键解析**:`x + 1 if x > 0 else 0` 解析为 **`(x+1) if (x>0) else 0`**,而非 `x + (1 if x>0 else 0)`。原因是三元的 `body`(if 前的部分)会"吸收"它前面的整段表达式 `x + 1`(算术优先级高于三元,先绑成 `x+1` 作为 body),`orelse` 是 `else` 后的 `0`。可用 AST 验证:

```python
import ast
tree = ast.parse("x + 1 if x > 0 else 0", mode='eval')
print(ast.dump(tree))
# IfExp(test=Compare(x > 0), body=BinOp(x + 1), orelse=Const(0))
# 即 (x+1) if (x>0) else 0 —— body 是 x+1 整段,不是 1

# x=-1 时,两种解析结果不同,可辨明
x = -1
print(x + 1 if x > 0 else 0)   # 0 —— (x+1) if False else 0 = 0
print(x + (1 if x > 0 else 0)) # -1 —— x + (1 if False else 0) = -1 + 0
# 两者不同!说明默认解析是前者 (x+1) if ... else 0
```

`x=-1` 时:`x + 1 if x>0 else 0` 得 `0`(解析为 `(x+1) if False else 0`),而 `x + (1 if x>0 else 0)` 得 `-1`(`x + 0`)。两者不同,证明默认是 `(x+1) if (x>0) else 0`——三元的 body 吸收 if 前的整段算术。**所以三元与算术混用时,body 会吃掉前面的算术,若想"算术 + 三元结果"必须加括号 `x + (1 if c else 0)`**。

**lambda 优先级低于三元**:`lambda: x if c else y` 是 `lambda: (x if c else y)`(三元先于 lambda 体)。

```python
f = lambda: 1 if True else 2   # lambda 体是三元 1 if True else 2
print(f())                # 1
```

**海象 `:=` 优先级极低(仅高于赋值)**:

```python
# 海象在条件里必须加括号
if (n := len([1,2,3])) > 2:    # 必须 (n := ...) 括号
    print(n)             # 3
# 不加括号:n := len([1,2,3]) > 2 → n := (len(...)>2),n 变 bool!
# if n := len([1,2,3]) > 2:    # n 是 True/False,不是长度!易错
```

⚠️ **海象 `:=` 优先级低于比较**:`n := len(x) > 2` 解析为 `n := (len(x) > 2)`(n 得 bool),不是 `(n := len(x)) > 2`。故海象在条件/比较语境**必须加括号** `(n := len(x)) > 2`。详见《赋值运算符与增强赋值》《三元表达式》。

**赋值/增强赋值最低**:赋值是语句(非表达式),优先级最低,右结合(`x = y = 5` 是 `x = (y = 5)`)。

```python
x = y = 5                 # 右结合:先 y=5,再 x=5
print(x, y)               # 5 5
x = 1 if True else 2      # 赋值右是三元(三元高于赋值)
print(x)                  # 1
```

理解三元/lambda/海象/赋值的极低优先级,就理解了为何"这些运算符与其他混用几乎必加括号"——它们优先级太低,默认会"吸"周围表达式,常与意图相悖。

### 2.10 综合示例:优先级实战

下面这个片段集中演示优先级在各组运算符间的体现,阅读时对照每段行为:

```python
# 1. 算术:先乘除后加减
print("=== 算术 ===")
print(2 + 3 * 4)          # 14
print((2 + 3) * 4)        # 20
print(10 % 3 * 2)         # 2(% 和 * 同级左结合)

# 2. ** 右结合 + 高于一元符号
print("=== 乘方 ===")
print(2 ** 3 ** 2)        # 512(右结合)
print(-2 ** 2)            # -4(** 高于一元 -)
print((-2) ** 2)          # 4(括号)

# 3. 位运算 vs 比较(位运算高)
print("=== 位 vs 比较 ===")
print(3 & 4 == 0)         # True(&(9)高于==(12),(3&4)==0)
print((3 & 4) == 0)       # True(显式)
print(5 > 3 & 2)          # 5 > (3&2) = 5>2 = True

# 4. 比较链式
print("=== 链式 ===")
print(1 < 2 < 3)          # True(链式,非 (1<2)<3)
print(1 < 5 == 5)         # True(链式,非 1<(5==5))

# 5. 逻辑:not > and > or
print("=== 逻辑 ===")
print(not True or False)  # False((not True) or False)
print(True or False and False)  # True(or 低于 and)
print(5 > 3 and 2 > 1)    # True(比较高于逻辑)

# 6. not 优先级陷阱
print("=== not 陷阱 ===")
print(not True and False)  # False((not True) and False)
print(not (True and False))# True(not 整个 and)

# 7. 三元低优先级(body 吸收 if 前算术)
print("=== 三元 ===")
x = -1
print(x + 1 if x > 0 else 0)   # 0 —— (x+1) if False else 0 = 0
print((x + 1) if x > 0 else 0) # 0 —— 同上(显式)
print(x + (1 if x > 0 else 0)) # -1 —— x + 0,不同解析(算术 + 三元结果)

# 8. 海象必须加括号
print("=== 海象 ===")
if (n := len([1,2,3,4])) > 2:
    print(f"n={n}")       # n=4

# 9. 赋值右结合
print("=== 赋值 ===")
a = b = c = 5
print(a, b, c)            # 5 5 5

# 10. 成员访问链式(最高)
print("=== 成员访问 ===")
print("hello".upper()[0]) # H
print([1,2,3][1] + 10)    # 12
```

跑一遍这段示例,对照输出:算术先乘除、`**` 右结合与一元符号、位运算高于比较、比较链式、逻辑 not>and>or、`not` 优先级陷阱、三元低优先级、海象加括号、赋值右结合、成员访问链式——优先级的完整图景就清晰了。核心结论:**算术>(* /先于+ -)>位>比较(链式)>not>and>or>三元>lambda>海象>赋值;** **  右结合高于一元-、位运算高于比较(与逻辑相反)、比较链式打破结合、not>and>or、三元/海象/赋值极低必加括号**。

## 3. 最佳实践

### 3.1 复杂表达式加括号,别依赖优先级记忆

```python
# 推荐:加括号明示意图
result = (a + b) * c
if (a < b) and (c > d): ...
if (perm & READ) != 0: ...
result = (x + 1) if x > 0 else 0

# 不推荐:依赖优先级,读者要心算
# result = a + b * c        # 虽对但意图不明(是 (a+b)*c 还是 a+(b*c)?)
# if a < b and c > d: ...   # 虽对但在复杂条件里难读
```

优先级规则虽存在,但生产代码不应让读者背几十个运算符的层级。复杂表达式(多种运算符混用)加括号明示意图,提升可读性、避免误判。简单无疑义的可省括号(`a + b * c` 显然先乘),但稍有歧义就加。可读性优先于"省括号"。

### 3.2 `**` 相关:负底幂、幂塔必加括号

```python
# 推荐:负底幂加括号
area = (-x) ** 2          # 明确 -x 的平方
result = (base ** exp) ** 2  # 左结合幂塔,明示
result = base ** (exp ** 2)  # 右结合幂塔,明示

# 危险:依赖默认(易错)
# area = -x ** 2          # 实际 -(x**2),不是 (-x)**2
# 2 ** 3 ** 2             # 右结合 512,易误读为 64
```

`**` 右结合且高于一元 `-`,负底幂(`(-x)**2`)和幂塔(`a**b**c`)最易错。凡"负底的幂"加括号 `(-x)**2`;幂塔加括号明示结合方向 `(a**b)**c` 或 `a**(b**c)`。详见《算术运算符》。

### 3.3 位运算与比较/算术混用,一律加括号

```python
# 推荐:位运算混用加括号
if (perm & READ) != 0: ...
if (flags | MASK) == target: ...
if (x << 2) > threshold: ...
result = (a & b) | c      # 位逻辑混用加括号

# 不推荐:位运算优先级(高于比较、低于算术)难记
# if perm & READ != 0: ...   // 虽对但易误判
# if x << 2 > 10: ...        // 位移低于算术,易混
```

位运算优先级(算术 > 位移 > `& > ^ > |` > 比较)复杂,且与逻辑运算符(低于比较)相反,C 程序员极易错。凡位运算与比较/算术/位逻辑之间混用,括号明示分组。详见《位运算符》。

### 3.4 `not` 与 `and`/`or` 混用,明确 `not` 作用范围

```python
# 推荐:明示 not 作用范围
if (not a) and b: ...        # not 只作用于 a
if not (a and b): ...        # not 作用于整个 and

# 依赖优先级易误读
# if not a and b: ...        // 是 (not a) and b,但读者可能误读为 not (a and b)
```

`not` 优先级高于 `and`/`or`,`not a and b` 是 `(not a) and b`(not 只作用 a)。要 `not` 作用于整个表达式加括号 `not (a and b)`。`not` 与 `and`/`or` 混用时,根据意图加括号明示 not 的作用范围。详见《逻辑运算符与短路求值》。

### 3.5 海象 `:=` 在条件/比较里必须加括号

```python
# 推荐:海象加括号
if (n := len(data)) > 10: ...
while (line := f.readline()): ...
if (x := compute()) is not None: ...

# 危险:不加括号,海象优先级低于比较,n 变 bool
# if n := len(data) > 10: ...   // n = (len(data)>10)=bool,不是长度!
```

海象 `:=` 优先级极低(低于比较),`n := len(x) > 2` 解析为 `n := (len(x)>2)`(n 得 bool)。海象在条件、比较、函数参数等表达式语境必须加括号 `(n := ...)`。这是海象最易错的点。详见《赋值运算符与增强赋值》。

### 3.6 三元与其他运算符混用,加括号分组

```python
# 推荐:三元加括号
result = (x + 1) if x > 0 else 0
msg = "状态:" + ("成年" if age >= 18 else "未成年")
print(f"余额:{'充足' if balance > 0 else '不足'}")

# 危险:三元低优先级,默认吸周围表达式
# result = x + 1 if x > 0 else 0   // 解析为 x + (1 if..else 0),可能非意图
```

三元优先级极低,与算术/字符串/and-or 混用时会"吸"周围表达式,常与意图相悖。f-string 里三元必须加括号(else 后 `:` 与格式化冲突)。凡三元混入复合表达式,括号包裹。详见《三元表达式》。

### 3.7 链式比较仅在单一运算符递进时用,混合展开

```python
# 推荐:范围、相等用链式
if 0 <= x < len(arr): ...
if a == b == c: ...
if low <= value <= high: ...

# 不推荐:混合运算符链式,难读
# if a < b == c: ...        // 是 a<b 且 b==c,读者难一眼懂
# if x is not None in lst: // 极难读

# 混合展开为 and
if (a < b) and (b == c): ...
if (x is not None) and (x in lst): ...
```

链式比较在"单一运算符递进"(范围 `a<x<b`、相等 `a==b==c`)时清晰自然。一旦混合运算符(`<` 和 `==`、`is` 和 `in`),中间项角色不直观,展开为显式 `and`。详见《链式比较》。

### 3.8 赋值右结合,链式赋值注意可变对象共享

```python
# 不可变对象链式赋值安全
a = b = c = 0           # 都指向同一 int 0(不可变,安全)

# 可变对象链式赋值陷阱:共享同一对象
# a = b = []            # a、b 同一列表,改一个影响另一个!
a, b = [], []           # 各自独立列表(多重赋值)
```

赋值右结合,`a = b = v` 让多个名字指向同一对象。不可变对象安全,可变对象(列表/字典)共享会出 bug。需独立可变对象用多重赋值 `a, b = [], []`。详见《赋值运算符与增强赋值》《变量赋值机制》。

### 3.9 别用 `&`/`|` 当逻辑运算符,优先级会错乱

```python
# 推荐:逻辑判断用 and/or
if (a > b) and (c > d): ...

# 危险:& 优先级高于比较,解析错
# if a > b & c > d: ...   // a > (b & c) > d,链式!不是 (a>b) and (c>d)
```

`&`/`|` 是位运算,优先级高于比较(与逻辑 `and`/`or` 低于比较相反)。把 `&` 当 `and` 会因优先级错乱(如 `a > b & c > d` 被解析成 `a > (b&c) > d`)。逻辑判断永远用 `and`/`or`/`not`,位运算只用 `&`/`|`/`~`。详见《逻辑运算符与短路求值》《位运算符》。

### 3.10 善用优先级让自然写法成立,但复杂处补括号

```python
# 优先级让自然写法成立(可省括号)
if a + b == c and d > 0:       # 算术→比较→逻辑,自然
    pass
total = price * qty + tax      # 先乘后加,自然
if 0 <= x <= 1:                # 链式范围,自然
    pass

# 复杂/易歧义处补括号
result = ((a + b) * c) / (d - e)   # 明示分组
if (a > b) and ((c < d) or (e == f)):  # 复杂条件分组
    do_something()
```

优先级的价值是让"自然写法"正确(`a + b == c and d > 0` 不用括号)。简单自然的可省括号,但复杂或易歧义处(多运算符嵌套、位/比较/逻辑混用、负底幂)补括号。原则:**简单自然省括号,复杂歧义加括号**,平衡简洁与可读。

## 4. 原理

本章讲清优先级背后的机制:语法分析器如何按优先级构造 AST、结合性的来源、链式比较的特殊解析、为何 `**` 右结合、为何位运算高于比较。这些是"优先级为何如此"的根基。

### 4.1 AST 构造:优先级决定语法树结构

运算符优先级本质是**语法分析器(parser)构造抽象语法树(AST)时的规则**——优先级高的运算符"更紧地绑定"操作数,在 AST 中更"靠下"(更先求值)。

以 `2 + 3 * 4` 为例:因 `*` 优先级高于 `+`,解析器把 `3 * 4` 先绑成一个子节点,再作为 `+` 的右操作数:

```
AST 结构(2 + 3 * 4):
      +
     / \
    2   *
       / \
      3   4
求值:先算 *(3*4=12),再算 +(2+12=14)
```

`*` 在 AST 中更靠下(更紧绑定),故先求值。优先级就是在构造这棵树时,"哪个运算符更紧"的规则。括号 `()` 强制改变树结构:`(2 + 3) * 4` 把 `+` 子树作为 `*` 的左操作数:

```
AST((2 + 3) * 4):
      *
     / \
    +   4
   / \
  2   3
求值:先算 +(2+3=5),再算 *(5*4=20)
```

**Python 用 PEG 解析器(3.9+)**,优先级编码在语法规则里:高优先级运算符的语法规则在低优先级的"祖先"里,使其子节点更紧。例如(简化):

```
arith: term (('+'|'-') term)*       # 低优先级 + - 在外层
term: factor (('*'|'/'|'//'|'%') factor)*   # 高优先级 * / 在内层
factor: ('-'|'+'|'~') factor | power         # 一元在内层
power: atom ('**' factor)?                   # ** 最内(最高,右结合)
```

`arith`(加减)包含 `term`(乘除)包含 `factor` 包含 `power`(乘方)——嵌套层级决定优先级,越内层优先级越高。右结合(`**`)通过递归 `power: atom '**' factor`(power 递归引用 factor→power)实现右结合。

理解 AST 构造,就理解了优先级是"语法树的形状规则",以及括号如何"强制改变树结构"。详见 Python 文档 Grammar 部分。

### 4.2 结合性的来源:左右递归

同优先级运算符的结合性,源于语法规则的**递归方向**:左递归→左结合,右递归→右结合。

**左结合(左递归)**:`a - b - c` 左结合 `(a - b) - c`,语法规则左递归:

```
sub: sub '-' term | term   # 左递归:sub 在前,左结合
# a - b - c → (sub('-' b) '-' c)... 即 ((a-b)-c)
```

左递归规则把左侧操作数递归绑定,故左结合(从左到右)。算术(`+ - * /`)、位移、位逻辑、`and`/`or` 都是左递归→左结合。

**右结合(右递归)**:`a ** b ** c` 右结合 `a ** (b ** c)`,语法规则右递归:

```
power: atom ('**' power)?   # 右递归:power 在后,右结合
# a ** b ** c → atom ** (power: b ** c)... 即 a**(b**c)
```

右递归规则把右侧操作数递归绑定,故右结合(从右到左)。`**`、赋值(`=` 右结合 `x=(y=5)`)、三元(右结合)都是右递归→右结合。

**为何 `**` 右结合**:幂运算在数学里是右结合的(幂塔 `a^b^c` 默认 `a^(b^c)`,因 `(a^b)^c = a^(b*c)` 退化),Python 遵循此约定用右递归。赋值右结合则因 `x = y = v` 语义是"都指向 v",需先算右侧 `y = v` 再 `x = (y的值)`。

理解左右递归,就理解了结合性的语法根源——左递归左结合、右递归右结合,这是解析器构造 AST 的递归方向决定的。

### 4.3 链式比较的特殊解析:同级无结合性

比较运算符(`< > <= >= == != is is not in not in`)同级,但**不走左/右递归结合**,而是被解析为**链式**——这是 Python 语法对这组运算符的特殊规则。

常规同级运算符(如 `+ -`)按左递归左结合:`a + b + c` = `(a+b)+c`。若比较也这样,`a < b < c` = `(a<b)<c`(布尔再比较),即 C 的"伪链式"。

Python 语法对比较用**特殊规则**:一连串比较被收集成一个 `Compare` AST 节点(含左操作数 + 多个(运算符, 操作数)对),求值为"且"。

```python
import ast
tree = ast.parse("a < b < c", mode='eval')
print(ast.dump(tree))
# Expression(body=Compare(left=Name('a'), ops=[Lt(), Lt()], comparators=[Name('b'), Name('c')]))
# 单个 Compare 节点:left=a, ops=[<, <], comparators=[b, c] —— 一体,非嵌套
```

`Compare` 节点是一体的(left + ops 列表 + comparators 列表),求值时按"且"配合短路:`(a<b) and (b<c)`,中间项 b 只求值一次。这让 `a<b<c` 是真正的链式(数学语义),而非布尔再比较。

```
比较语法(简化,非递归,收集链):
comparison: compare_two (('<'|'>'|... ) compare_two)*
# a < b < c → Compare(a, [<, <], [b, c]) —— 收集成节点,非递归结合
```

这组运算符"同级"但解析时不递归(不左/右结合),而是收集成 `Compare` 节点,故称"非结合"(non-associative)或"链式"。这是 Python 比较运算符独有的优先级规则,理解 `Compare` 节点,就理解了为何比较链式、为何中间项一次求值。详见《链式比较》。

### 4.4 位运算高于比较:历史与一致性

位运算符(`& ^ | << >>`)优先级高于比较运算符(`< > ==`等),这是 Python 继承自 C 的设计,有历史和一致性原因。

**C 的历史**:C 语言里位运算优先级就高于比较(`&` 高于 `==`),源于早期 C 用 `&` 做"按位与"和(曾考虑的)逻辑与。虽 C 后来引入 `&&`/`||`(低优先级短路逻辑),但 `&`/`|`/`^` 的优先级(高于比较)保留下来。Python 继承了这套优先级,使熟悉 C 的程序员迁移时行为一致。

**为何这样设计**:`a & b == c` 在 C/Python 解析为 `(a & b) == c`(位运算先)——这匹配"先算位运算结果,再比较"的直觉(位掩码计算后比较)。但实际上 `a & b == c` 也可解读为 `a & (b == c)`(取 b 是否等于 c 的布尔,再位与),两种解读都常见,故这条优先级争议很大(C 的 Bjarne Stroustrup 也说 `&` 优先级是历史错误)。但为兼容性,Python 沿用。

```python
# 位运算高于比较(继承 C)
print(3 & 4 == 0)        # True —— (3 & 4) == 0,先 & 再 ==
print((3 & 4) == 0)      # True(显式)
print(3 & (4 == 0))      # 0 —— 反向(3 & False = 3 & 0 = 0)
```

**实践建议**:因这条优先级争议大且违背"`&` 像 `and` 应低于比较"的直觉,**位运算与比较混用一律加括号**,不依赖默认。C 委员会都承认 `&` 优先级是设计缺陷,Python 沿用是为兼容,但代码里应括号规避歧义。

理解位运算高于比较的历史来源(C 继承)+ 设计争议,就理解了为何这条规则反直觉、为何要括号规避。逻辑运算符(`and`/`or`)是 Python 后来加的(独立于位运算),设为低于比较,符合"逻辑判断在比较之后"的直觉——这与位运算高于比较"恰好相反",是位运算与逻辑运算优先级关系不对称的根源。

### 4.5 求值顺序:优先级只决定"绑定",短路决定"求值"

**优先级决定运算符的"绑定顺序"(语法树形状),但不完全决定"求值顺序"(运行时计算顺序)**。求值顺序还受短路影响。区分这两者很重要。

**优先级 = 绑定(语法)**:`a + b * c` 中 `*` 优先绑 `b c`,树是 `a + (b*c)`。这是静态的语法结构。

**短路 = 求值(运行)**:`and`/`or`/三元/`if` 在运行时短路,可能不求值某些子树。这是动态行为。

```python
# 优先级决定绑定:a and b * c → a and (b*c)(* 高于 and,先绑)
# 短路决定求值:若 a 假,b*c 不求值(and 短路)
def f():
    print("f 调用")
    return 100
print(False and f() * 2)   # False —— a=False 假,and 短路,f()*2 不求值(f 不调用)
# 语法上 False and (f()*2),但运行时 a 假就停,f() 不算
```

`False and f() * 2`:优先级上 `f() * 2` 是 and 的右子树(绑定),但运行时 `False` 假,and 短路,`f() * 2` 不求值——`f` 不调用。优先级只决定了"如果求值会怎么绑",短路决定了"实际求不求值"。

**操作数求值顺序(左到右)**:Python 表达式的操作数按从左到右求值(在运算符求值前)。

```python
def a(): print("a"); return 1
def b(): print("b"); return 2
def c(): print("c"); return 3
print(a() + b() + c())    # a b c 6 —— 操作数左到右求值,即使 + 左结合
# 虽然 + 左结合((a+b)+c),但操作数 a,b,c 按左到右先求值
```

`a() + b() + c()`:虽 `+` 左结合(语法上 `(a+b)+c`),但操作数 `a()`、`b()`、`c()` 按**从左到右**先求值(输出 a b c),再算加法。这是 Python"操作数左到右求值"规则,与结合性(绑定方向)不同。

理解"优先级=绑定,短路=求值,操作数左到右",就完整掌握了表达式求值:优先级定结构、结合性定同级方向、短路定按需停、操作数左到右定子表达式顺序。这四者共同决定一个复杂表达式的完整求值过程。

## 5. 总结

### 5.1 本文内容回顾

- **什么是优先级**:决定表达式中运算符"谁先算"的规则(如先乘除后加减);配套**结合性**(同级运算符方向:左/右结合);Python 与 C 差异:比较链式(非结合)、`**` 右结合高于一元符号、位运算高于比较、海象/三元极低优先级。
- **优先级 vs 结合性**:优先级是不同运算符间顺序,结合性是同优先级方向(多数左结合,`**`/赋值/三元右结合);比较运算符特殊:同级但链式(非结合)。
- **完整表(高到低)**:括号/成员访问 > `**`(右) > 一元`+ - ~` > `* / // %` > `+ -` > `<< >>` > `&` > `^` > `|` > 比较/成员/身份(链式) > `not` > `and` > `or` > 三元 > lambda > 海象 > 赋值(右)。
- **括号与成员访问(最高)**:`()` 强制提升优先号,`[] () .` 成员访问紧贴对象优先级极高,左到右链式。
- **`**` 乘方(重点)**:右结合(`2**3**2=512`)、优先级高于一元符号(`-2**2=-4`,陷阱);负底幂、幂塔必加括号。
- **一元符号**:`+ - ~` 低于 `**` 高于算术;`--5` 是 `-(-5)=5`(非自减)、`~~5=5`、`not not x` 转 bool。
- **算术(重点)**:`* / // %`(6)高于 `+ -`(7),同级左结合;算术高于比较高于逻辑,自然写法成立。
- **位移/位逻辑**:位移(8)低于算术高于位逻辑;位逻辑 `&`(9)>`^`(10)>`|`(11)递减左结合;`^` 是异或非乘方。
- **比较/成员/身份(链式,重点)**:优先级 12,同级链式(非结合),`a<b<c`=`a<b and b<c`;混合运算符链式难读应展开;高于逻辑。
- **逻辑(重点)**:`not`(13)>`and`(14)>`or`(15),`not` 一元,`and`/`or` 左结合短路;比较高于逻辑;`not a and b` 是 `(not a) and b`(not 只作用 a,陷阱)。
- **三元/lambda/海象(重点)**:优先级极低(16/17/18),仅高于赋值;三元与算术混用吸周围(`x+1 if c else 0` 陷阱);海象低于比较(`n:=len(x)>2` n 变 bool,必须括号);赋值最低右结合(链式赋值可变对象共享陷阱)。
- **位运算 vs 比较(易错)**:位运算(8-11)高于比较(12),继承 C 设计(争议大);`&` 当 `and` 因优先级错乱;混用一律加括号。
- **最佳实践**:复杂加括号、`**` 负底幂幂塔加括号、位运算混用加括号、`not` 明示作用范围、海象条件必括号、三元混用加括号、链式仅单一运算符递进、赋值可变共享小心、不用 `&`/`|` 当逻辑、简单自然省括号复杂补括号。
- **原理**:优先级是解析器构造 AST 的"绑定紧度"规则(高优先级更靠下先求值),括号强制改变树结构;结合性源于语法递归方向(左递归左结合、右递归右结合,`**` 右结合因幂塔约定、赋值右结合因都指向右值);链式比较特殊解析为 `Compare` 节点(收集成一体非递归,故非结合,中间项一次求值);位运算高于比较继承 C(设计争议,应括号规避);优先级定绑定、短路定求值、操作数左到右——四者共定求值过程。
