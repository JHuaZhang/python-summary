# if-else 二分支结构

程序里的大量决策本质上是二选一：验证通过还是失败、余额充足还是不足、订单已支付还是未支付、用户名存在还是不存在。`if-else` 二分支结构就是 Python 为这类"非此即彼"决策提供的最直接语法：条件为真走一条路，条件为假走另一条路，两条路互斥，且每次必走其一。本篇把二分支的执行语义、缩进规则、`else` 的全部语法约束、空分支处理、紧凑写法、表达式形态以及底层实现一次讲透。

## 1. 介绍

### 1.1 什么是二分支结构

`if` 语句可以单独工作：条件为真就执行一段代码，为假就绕过去。但相当多的业务问题不是"做或不做"，而是"做甲还是做乙"——登录要么成功要么失败，整数要么是偶数要么是奇数，预订要么有效要么过期。这类问题的共同点是：两个结果互斥，且必然有一种成立。

给二分支找个生活类比：写字楼的闸机。员工卡有效，闸门打开、放行；员工卡无效，蜂鸣报警、拦下。机器不会出现"既放行又报警"，也不会出现"什么都不做"——两种结果覆盖了全部可能。`if-else` 写在代码里，就是把这个闸机逻辑原样搬进程序。

先对比一下"单独的 if"和"二分支"在意图上的区别：

| 维度 | 单独的 `if` | `if-else` 二分支 |
|------|------------|------------------|
| 路径数量 | 一条（执行或跳过） | 两条（真、假各一条） |
| 表达的语义 | 条件成立时"做点什么" | 条件成立做甲，不成立做乙 |
| 不满足时的行为 | 静默跳过，调用方可能毫无感知 | `else` 保证另一侧一定有响应 |
| 适用场景 | 越界保护、命中缓存提前返回、可选配置 | 登录成功/失败、扣款成功/不足、奇数/偶数 |

可以看到，两者的关键差异在"不满足时干什么"：单独的 `if` 对不满足的情况保持沉默，二分支则强制你为另一半可能给出明确的处理。这也是很多健壮性问题的分水岭——系统里最难排查的 bug，往往不是处理错了，而是某个失败分支被静默跳过了。

如果一次决策的档位超过两档（比如成绩 A/B/C/D/F 五档），就需要在"真分支"与"假分支"之间再插入中间档位，那属于多分支结构的范畴。本篇专注于把两档的骨架搭稳：两分支写对了，多分支无非是在中间多插几个检查点。

### 1.2 最简示例

下面这个温度提醒是能想到的最小二分支：

```python
temperature = 33

if temperature >= 30:
    print("今天很热，注意防暑")
else:
    print("今天不算热，正常着装")
```

**运行结果**：

```text
今天很热，注意防暑
```

语法成分各就各位：

1. `if temperature >= 30:` ——`if` 关键字 + 条件表达式 + 冒号，冒号宣告"下面是一个代码块"
2. `print("今天很热，注意防暑")` ——缩进 4 格，属于真分支，条件为真时执行
3. `else:` ——`else` 关键字 + 冒号，与 `if` 首字符对齐，不带任何条件
4. `print("今天不算热……")` ——缩进 4 格，属于假分支

变量 `temperature` 改成 22 再运行，输出就变成第二句。判断逻辑没变，变的是数据，二分支自动选对路径。

### 1.3 语法骨架总览

把上面的示例抽象出来，二分支的完整语法骨架长这样：

```text
┌────────────────────────────────────────────────────┐
│  if 条件表达式:                                     │
│      真分支语句块        ← 至少一条缩进语句          │
│  else:                                              │
│      假分支语句块        ← 至少一条缩进语句          │
└────────────────────────────────────────────────────┘
```

逐个部件拆开看：

| 部件 | 写法 | 是否必填 | 作用与约束 |
|------|------|---------|-----------|
| `if` 关键字 | `if` | 必填 | 开启二分支，后面必须跟条件表达式 |
| 条件表达式 | 任意一个表达式 | 必填 | 求值后按真值测试解释为真或假 |
| 第一个冒号 | `:` | 必填 | 宣告真分支块开始 |
| 真分支块 | 缩进的语句 | 必填 | 条件为真时执行；至少一条语句（空块用 `pass`） |
| `else` 关键字 | `else` | 必填 | 开启假分支；后面**不写条件**，直接冒号 |
| 第二个冒号 | `:` | 必填 | 宣告假分支块开始 |
| 假分支块 | 缩进的语句 | 必填 | 条件为假时执行；至少一条语句 |
| `else` 行的对齐 | 与 `if` 同列 | 必填 | 缩进决定配对关系，错位即报错 |

这张表里最容易违反的两条约束——"`else` 后不写条件"和"`else` 与 `if` 对齐"——将在核心内容里逐一用真实报错验证。

## 2. 核心内容

### 2.1 基本形态：互斥的两个分支

二分支的执行语义由三个词概括：**互斥、必走其一、最终汇合**。先看最基本的形态，判断奇偶：

```python
def check_parity(number):
    if number % 2 == 0:
        return f"{number} 是偶数"
    else:
        return f"{number} 是奇数"


print(check_parity(8))
print(check_parity(31))
```

**运行结果**：

```text
8 是偶数
31 是奇数
```

任何整数除以 2 的余数只有 0 和非 0 两种可能，奇偶判断因此是天然的二分支问题。接着在两个分支里都放上追踪打印，观察互斥性：

```python
def trace_flow(score):
    print(f"--- 开始判断 score = {score} ---")
    if score >= 60:
        print("① 条件 score >= 60 为真")
        print("② 本轮只执行了真分支")
    else:
        print("① 条件 score >= 60 为假")
        print("② 本轮只执行了假分支")
    print("③ 两个分支在这里汇合")


trace_flow(75)
trace_flow(52)
```

**运行结果**：

```text
--- 开始判断 score = 75 ---
① 条件 score >= 60 为真
② 本轮只执行了真分支
③ 两个分支在这里汇合
--- 开始判断 score = 52 ---
① 条件 score >= 60 为假
② 本轮只执行了假分支
③ 两个分支在这里汇合
```

**关键点**：

- 两轮调用，没有任何一轮出现"两段都执行"或"两段都不执行"——这就是互斥加全覆盖
- 条件先求值，再选路径；顺序永远是"先判断后执行"
- ③ 号打印的缩进与 `if` 对齐、位于二分支整体之后：两轮调用它都执行了——分支结束后程序照常继续

### 2.2 执行流程：从求值到汇合

把 2.1 的观察画成流程图：

```text
            ┌────────────────┐
            │   进入 if 语句  │
            └───────┬────────┘
                    ▼
            ┌────────────────┐
            │ 对条件表达式求值 │
            └───────┬────────┘
                    ▼
            ┌────────────────┐
            │    真值测试     │
            └───┬────────┬───┘
            真  │        │  假
        ┌───────▼──┐ ┌───▼────────┐
        │ 执行真分支 │ │ 执行假分支  │
        │  语句块   │ │   语句块    │
        └───────┬──┘ └───┬────────┘
                │        │
                └───┬────┘
                    ▼
            ┌────────────────┐
            │ 汇合：继续执行  │
            │ if-else 之后的  │
            │     代码        │
            └────────────────┘
```

三个值得记住的细节：

- **求值时机**：条件只在进入二分支时求值一次，两个分支都不会让它重新计算
- **汇合点**：真假分支执行完，都在 `if-else` 整体结束后汇合，继续顺序执行其后的代码
- **变量作用域**：分支里赋值的变量，汇合后照样可以访问（Python 没有块级作用域）

用一个"扣款"例子验证汇合点与变量可见性：

```python
balance = 300.0

if balance >= 100:
    balance = balance - 100
    print("已扣款 100 元")
else:
    print("余额不足，未扣款")

print(f"无论走哪个分支都会到达这里，balance = {balance}")
```

**运行结果**：

```text
已扣款 100 元
无论走哪个分支都会到达这里，balance = 200.0
```

**关键点**：真分支里修改了 `balance`，最后一行读到的就是修改后的值。分支只是"代替你选择性执行某些语句"，不会引入新的命名空间。这个特性既是便利（不用提前声明变量），也是隐患（只在某分支赋值的变量，若另一分支修改了语义，汇合点的代码就要面对两种状态）。

### 2.3 条件表达式：任意对象都能当条件

`if` 后面不要求必须是布尔值。Python 对条件做**真值测试**：先调用 `bool()` 把条件对象转成真或假，再决定走哪个分支。各类型的"假值"只有固定的一小撮，其余全是真值：

| 类型 | 该类型的假值 | 真值举例 |
|------|------------|---------|
| 布尔 | `False` | `True` |
| 整数/浮点/复数 | `0`、`0.0`、`0j` | `1`、`-3.5`、`2+3j` |
| 字符串 | `''`（空串） | `'py'` |
| 列表 | `[]` | `[1, 2]` |
| 元组 | `()` | `(0,)` |
| 字典 | `{}` | `{'k': 1}` |
| 集合 | `set()` | `{1}` |
| `None` | 本身就是假值 | —— |

**示例**：

```python
cart = []

if cart:
    print("开始结算购物车")
else:
    print("购物车为空，先去挑选商品")
```

**运行结果**：

```text
购物车为空，先去挑选商品
```

**关键点**：

- `if cart:` 是"列表非空则……"的地道写法，等价于但优于 `if len(cart) > 0:`
- 空容器、零值数字、空字符串、`None` 走 `else`；元素非空或数值非零就走真分支
- 想显式比较时只能用 `==` 或 `is`，不要写 `if cart == True:` 这类比较，原因在最佳实践部分展开

### 2.4 分支体：多少条语句都行，归属全看缩进

真分支和假分支都不是"只能放一行 print"的摆设，它们是普通的语句块，想放几条语句就放几条：

```python
def settle_order(is_vip):
    unit_price = 100
    if is_vip:
        price = unit_price * 0.8
        note = "VIP 八折"
        # 上面两行与下面两行都在 if 块内：要么全执行，要么全不执行
        print(f"结算价：{price:.0f} 元（{note}）")
        print("已赠送 10 积分")
    else:
        price = unit_price
        print(f"结算价：{price:.0f} 元（普通价）")


settle_order(True)
settle_order(False)
```

**运行结果**：

```text
结算价：80 元（VIP 八折）
已赠送 10 积分
结算价：100 元（普通价）
```

缩进不仅决定"哪些语句属于分支"，也决定"哪些语句在分支之外"。对照 2.2 的流程图：缩进回到与 `if` 同级的那一行，就离开了二分支的块，落到汇合点上：

```python
total = 45
if total >= 30:
    freight = 0
    print("订单满 30 元，免运费")
else:
    freight = 8
    print("订单不满 30 元，收取运费 8 元")
# 这一行缩进与 if 对齐：不属于任何分支，两个分支执行完都会执行它
print(f"最终运费按变量 freight 计算：{freight} 元")
```

**运行结果**：

```text
订单满 30 元，免运费
最终运费按变量 freight 计算：0 元
```

**关键点**：

- 分支块的边界完全由缩进划定：往里缩一级即进入块，退回原级即离开块
- 块内语句"一组绑定"：`settle_order` 的真分支里，漏写任何一条都会让整个 VIP 分支表现异常，调试时要整体检查
- Python 官方风格（PEP 8）规定一级缩进为 4 个空格，保持全文一致即可

#### 2.4.1 两种最常见的缩进错误

缩进是语法，写错不会"风格告警"，而是直接拒绝运行。最常见的两类：

**第一类：同一块内缩进量不一致**

```python
# 非法示例（不要运行）——第二行比第一行少缩进 2 格：
# if True:
#     print("第一行")
#   print("第二行")
```

**报错信息**：

```text
IndentationError: unindent does not match any outer indentation level
```

解读：解析器发现回退的缩进量跟任何一个外层块都对不上，不知道这行属于哪一层，直接报错。

**第二类：冒号后没有缩进语句块**

```python
# 非法示例（不要运行）——if 头的下一行没有缩进：
# flag = True
# if flag:
# print("少了缩进")
```

**报错信息**：

```text
IndentationError: expected an indented block after 'if' statement on line 3
```

解读：冒号宣告"后面是一个块"，结果什么块都没出现，报错信息还贴心地指出问题发生在第几行。

还有一个隐形炸弹：**Tab 与空格混用**。源码里有的行用 Tab 缩进、有的行用 4 空格缩进，视觉上完全对齐，解析器却认为是两个缩进单位，运行时抛出 `TabError: inconsistent use of tabs and spaces in indentation`，或者表现为与本小节相同的 `unindent does not match` 错误。解决方案只有一条：编辑器统一配置为"Tab 键输出 4 空格"。

### 2.5 else 分支的完整规则

`else` 看似只是"另一种情况"，但它的语法约束比 `if` 更严格。这一小节把四条规则全部给出，并用真实报错验证。

#### 2.5.1 else 后面不写条件

先记住正确的形态：

```python
score = 55
if score >= 60:
    print("及格")
else:
    print("不及格")
```

**运行结果**：

```text
不及格
```

`else` 的语义是"if 条件为假的补集"，这个补集由解释器根据代码位置自动划定，**不由你写**。在 `else` 后面画蛇添足写上条件，是语法错误：

```python
# 非法示例（不要运行）——else 后面加了条件：
# if score >= 60:
#     print("及格")
# else (score < 60):
#     print("不及格")
```

**报错信息**：

```text
SyntaxError: expected ':'
```

解读：解析器读到 `else` 之后，只接受紧跟的冒号；它看到 `(score < 60)` 时仍然在等那个冒号，最终在 else 所在行报错。两层含义值得咀嚼：

1. **语法层面就拒绝**，不是"多余但合法"——`else` 分支本来就只在条件为假时执行，再写条件等于怀疑自己刚算完的条件
2. 如果确实想让条件更直白（比如反过来写"不及格"一侧），正确做法是**调整 `if` 侧的条件**，例如把 `if` 的条件换成 `score < 60`，让两侧语义对调

#### 2.5.2 else 必须与配对 if 同级对齐

`else` 通过缩进与某个 `if` 配对：两者的 `if`/`else` 关键字必须在**同一缩进列**。缩进比 `if` 深一级（好像 `else` 属于 if 块的话），直接是语法错误：

```python
# 非法示例（不要运行）——else 缩进太深，看起来像属于 if 块：
# score = 55
# if score >= 60:
#     print("及格")
#     else:
#         print("不及格")
```

**报错信息**：

```text
SyntaxError: invalid syntax
```

解读：解析器把深入一级的 `else` 当作 if 块内的一条语句来解析，可 `else` 根本不能作为普通语句出现，于是报 `invalid syntax`。"else 必须与 if 对齐"因此不是风格建议，而是硬性语法。

#### 2.5.3 孤立的 else 是语法错误

`else` 是从属关键字，必须依附一个 `if` 而存在，唯独不能**凭空出现**：

```python
# 非法示例（不要运行）——其上没有任何与之配对的 if：
# score = 55
# else:
#     print("悬空的 else")
```

**报错信息**：

```text
SyntaxError: invalid syntax
```

解读：`else` 的作用是"接住 if 跳转失败的那一侧"，没有 `if` 就没有跳转，`else` 自然无处安放。理解 `else` 要始终带着这层从属关系。

#### 2.5.4 嵌套时的配对规则：就近配对

二分支内部还可以再写二分支。嵌套时 `else` 跟谁配对？规则一句话：**与缩进列相同、位置最近的、尚未被配对的 `if` 配对**。

```python
a, b = 10, 20
if a > 5:
    if b > 100:
        print("a>5 并且 b>100")
    else:
        # 缩进与内层 if 对齐：只属于内层 if
        print("a>5，但 b 不大于 100")
```

**运行结果**：

```text
a>5，但 b 不大于 100
```

配对关系用图看得更清楚：

```text
if a > 5:              ← 外层 if（缩进列 0）
    if b > 100:        ← 内层 if（缩进列 4）
        print("...")
    else:              ← 缩进列 4：与内层 if 配对
        print("...")
                       ← 外层没有 else：内层块结束后走过外层 if 块的收尾
```

**关键点**：

- 想给外层也配一个 `else`，把它写到缩进列 0 的位置即可，两个 `else` 各归各的 `if`
- 感觉到两层缩进开始"叠罗汉"时，就是该重构成并列判断或提前返回的信号（方案在最佳实践部分展开）

顺带一提，C、Java 这类花括号语言存在著名的"悬空 else"歧义：`else` 默认跟最近的 `if` 配对，与书写缩进无关，靠缩进表达意图就会埋雷：

```c
/* C 语言的悬空 else：else 看起来属于外层 if，实际配最近的一个 */
if (a > 5)
    if (b > 100)
        printf("both\n");
else
    printf("a <= 5?\n");   /* 实际与内层 if 配对，与缩进提示相反 */
```

Python 用缩进本身作为语法，`else` 属于谁由缩进列一眼可见，歧义在语言层面被消除。

### 2.6 分支暂时为空：pass

有时分支的逻辑还没想好，或者明明知道"这个分支什么都不做"。但空块不是合法选项：

```python
# 非法示例（不要运行）——if 块一个语句都没有：
# amount = 88
# if amount > 0:
# else:
#     print("无需退款")
```

**报错信息**：

```text
SyntaxError: expected an indented block after 'if' statement on line 3
```

`else` 同样不允许空块，报错信息是 `SyntaxError: expected an indented block after 'else' statement on line 5`。

`pass` 是唯一的正解——它是一条"什么都不做"的语句，专门用来占住块的位置：

```python
def decide_refund(amount):
    if amount > 0:
        pass          # 退款规则还在讨论中，先占住分支位置
    else:
        print("金额为 0，无需退款")


print("程序可以正常运行：")
decide_refund(88)
decide_refund(0)
```

**运行结果**：

```text
程序可以正常运行：
金额为 0，无需退款
```

**关键点**：区分两种"空"：

- **阶段的空**：逻辑还没写完，用 `pass` 占位，先跑通整体结构，这是 `pass` 的本职工作
- **刻意的空**：上线逻辑里明确知道"这一支不需要动作"，写 `pass` 等于留下"我想过，确定不做"的痕迹；不写 `else` 则读起来更接近"作者没想到"。运行效果等价，可读性含义不同

### 2.7 单行分支体的紧凑写法

分支体只有一条简单语句时，可以直接写在冒号后面，省掉换行缩进：

```python
temperature = 33

if temperature >= 30: print("高温预警")
else: print("体感正常")
```

**运行结果**：

```text
高温预警
```

`temperature` 为 33，条件为真，单行的真分支照常执行、假分支照常被跳过——互斥性与多行形态完全一致。这个写法有三个边界：

1. **冒号后只能放简单语句**——表达式、赋值、`pass`、`return` 都可以；想再嵌套 `if`、`for`、`def` 这类复合语句，必须换行缩进
2. **`else` 必须另起一行**——把 `if` 和 `else` 挤在同一行（`if cond: a = 1 else: a = 2`）直接报 `SyntaxError: invalid syntax`，解析器在 `else` 处就断了
3. **可读性优先**——行内分支体省了两行，却破坏了"块"的视觉结构，代码评审大多不待见它。保留给"一句废话都没有的短逻辑"，例如兜底赋值；其余场景老老实实换行

### 2.8 条件表达式：表达式版本的二分支

二分支还有一副"表达式"面孔——条件表达式，语法形态是：

```text
A if 条件 else B
```

求值顺序：先算条件；为真取 `A` 的值，为假取 `B` 的值。它最擅长"赋值二选一"：

```python
age = 16
status = "成年" if age >= 18 else "未成年"
print(status)
```

**运行结果**：

```text
未成年
```

"必须产出一个值"的场景还能顺手做防御：

```python
values = []
result = values[0] if values else "空列表占位"
print(result)
```

**运行结果**：

```text
空列表占位
```

列表为空，条件为假，`else` 一侧的占位字符串被选中——真分支里的 `values[0]` 根本没被求值，自然不会触发越界。这验证了条件表达式**两支只求值一支**的特性。

语句版与表达式版的取舍：

| 维度 | 语句版 `if-else` | 表达式版 `A if cond else B` |
|------|------------------|-------------------------------|
| 本质 | 语句，用于组织控制流 | 表达式，求值后必须产出一个值 |
| 分支体 | 任意多语句、可嵌套 | 各只能是**一个**表达式 |
| 适合场景 | 有副作用（打印、修改状态）、逻辑复杂 | 纯取值：赋值、参数、返回值 |
| 嵌套 | 支持但要注意缩进 | 可以嵌套但极难读，应当避免 |
| 求值 | 只执行选中的一支 | 只求值选中的一支 |

**关键点**：赋值二选一是条件表达式的主场；一旦两个分支要"做事"（打印、改状态、调函数），就回到语句版。判断口诀："产出值用三元，执行动作用二分支。"

### 2.9 典型应用场景

把本篇所有要素串进五个真实场景。

**场景 1：登录校验**

`and` 把"账号对"与"密码对"合并成一个复合条件，整个判断仍然是非此即彼：

```python
def login(account, password):
    if account == "admin" and password == "py123456":
        print(f"[{account}] 登录成功，即将进入主页")
    else:
        print("登录失败，请检查账号或密码")


login("admin", "py123456")
login("admin", "wrong-pwd")
```

**运行结果**：

```text
[admin] 登录成功，即将进入主页
登录失败，请检查账号或密码
```

失败提示刻意写得模糊——"账号或密码"——不暴露到底哪个字段错了：二分支只回答"过没过"，不负责给攻击者递线索。

**场景 2：两数取较大值**

比较后二选一返回，最能看出 `>=` 与 `>` 的细节差异：

```python
def max_of_two(first, second):
    if first >= second:
        return first
    else:
        return second


print(f"max_of_two(7, 3) = {max_of_two(7, 3)}")
print(f"max_of_two(2.5, 9.8) = {max_of_two(2.5, 9.8)}")
```

**运行结果**：

```text
max_of_two(7, 3) = 7
max_of_two(2.5, 9.8) = 9.8
```

用 `>=` 而不是 `>`，两值相等时确定走真分支返回 `first`——"相等时返回谁"从此不再含糊。

**场景 3：余额扣款**

分支内修改状态、汇合点继续使用，正是 2.2 末尾那个特性的完整应用：

```python
balance = 300.0
order_amount = 120.0

if balance >= order_amount:
    balance = balance - order_amount
    print(f"扣款成功，剩余余额 {balance:.1f} 元")
else:
    print(f"余额 {balance:.1f} 元不足以支付 {order_amount:.1f} 元")
print(f"随后可继续使用的余额：{balance:.1f} 元")
```

**运行结果**：

```text
扣款成功，剩余余额 180.0 元
随后可继续使用的余额：180.0 元
```

**场景 4：嵌套二分支（先过第一关，再过第二关）**

酒店入住：先看有没有预订，再看是否在保留时间内。后一个判断只在"有预订"时才有意义，天然适合嵌套：

```python
def check_in(is_reserved, is_before_deadline):
    if is_reserved:
        if is_before_deadline:
            print("欢迎入住，已为您保留至截止时间")
        else:
            print("预订已过期，房间已释放，请重新登记")
    else:
        print("未查询到预订，请选择现场开房")


check_in(True, True)
check_in(True, False)
check_in(False, True)
```

**运行结果**：

```text
欢迎入住，已为您保留至截止时间
预订已过期，房间已释放，请重新登记
未查询到预订，请选择现场开房
```

三种输入各返回一条路径——注意嵌套只有两层，每个 `else` 的归属都一目了然。

**场景 5：密码强度二分**

只区分"能用"与"太短"两档：

```python
def check_password_strength(password):
    if len(password) >= 8:
        print("密码强度达标，可以提交")
    else:
        print(f"密码太短（当前 {len(password)} 位），至少需要 8 位")


check_password_strength("py123456")
check_password_strength("abc12")
```

**运行结果**：

```text
密码强度达标，可以提交
密码太短（当前 5 位），至少需要 8 位
```

失败分支把 `len(password)` 的实测值回显出来——报错时携带上下文，是最有价值的失败反馈。

## 3. 最佳实践

### 3.1 互斥场景必须用 else，而不是两个独立 if

互斥逻辑最危险的写法是两个条件互补的独立 `if`：

```python
# ❌ 不推荐：两个独立 if 表达互斥
score = 55
if score >= 60:
    print("及格")
if score < 60:
    print("不及格")
```

```python
# ✅ 推荐：if-else 一次表达两态
score = 55
if score >= 60:
    print("及格")
else:
    print("不及格")
```

两者当下行为一致，差别在**演化**：需求改成"及格线 65"时，推荐写法只改一处；不推荐写法要记得同时改两个条件，漏改一边就出现"两次都打印"或"一次都不打印"的裂缝。二分支由语法保证互斥，不需要靠条件书写的自觉性。

### 3.2 else 分支不要静默吞掉失败

失败分支空着（或干脆不写 else），等于把问题留给未来的自己：

```python
# ❌ 不推荐：未达门槛时什么都不发生
def apply_discount(cart_total):
    if cart_total >= 200:
        return cart_total * 0.9
    if cart_total < 200:
        pass
```

```python
# ✅ 推荐：失败分支给出可观察的反馈
def apply_discount(cart_total):
    if cart_total >= 200:
        print(f"已按 9 折结算，原价 {cart_total} 元")
        return cart_total * 0.9
    else:
        print(f"未达门槛（{cart_total} 元），按原价结算")
        return cart_total
```

用户看不到"为什么不打折"，排查问题的人也定位不到逻辑走向——静默是二分支里最昂贵的错觉。就算暂时只想处理成功路径，`else` 里也写上一行日志级提示，成本极低。

### 3.3 分支体保持短，复杂逻辑抽函数

分支体膨胀到十几行时，二分支的"两选一"骨架就被淹没了：

```python
# ❌ 不推荐：分支体塞满细节，扫一眼看不出决策结构
def settle(order):
    if order["vip"]:
        price = order["total"] * 0.8
        price = max(price, order["total"] - 50)
        print(f"VIP 结算：{price}")
        order["price"] = price
        order["gift_points"] = 50
        notify_vip_benefit(order["user"])    # notify_vip_benefit 是已定义的通知函数
    else:
        price = order["total"]
        print(f"普通结算：{price}")
        order["price"] = price
        order["gift_points"] = 0
```

```python
# ✅ 推荐：二分支只保留"判断 + 派发"，细节交给函数
def settle(order):
    if order["vip"]:
        order["price"] = settle_vip(order)
    else:
        order["price"] = settle_normal(order)


def settle_vip(order):
    price = max(order["total"] * 0.8, order["total"] - 50)
    print(f"VIP 结算：{price}")
    order["gift_points"] = 50
    notify_vip_benefit(order["user"])
    return price


def settle_normal(order):
    print(f"普通结算：{order['total']}")
    order["gift_points"] = 0
    return order["total"]
```

重构后 `settle` 只剩五行，二分支的形状重新浮现：判断什么、两条路各去哪。细节改动只发生在 `settle_vip`/`settle_normal` 内部，不碰决策骨架。

### 3.4 用命名布尔变量替代长条件

复合条件直接写在 `if` 里，读代码的人要现场翻译一遍语义：

```python
# ❌ 不推荐：条件本身没有名字，翻译成本转嫁给读者
if user["login_days"] >= 30 and not user["banned"] and user["age"] >= 18:
    grant_badge(user)
else:
    reject(user)
```

```python
# ✅ 推荐：先把语义算成变量，二分支只负责选路
is_eligible = user["login_days"] >= 30 and not user["banned"] and user["age"] >= 18

if is_eligible:
    grant_badge(user)
else:
    reject(user)
```

`is_eligible` 这个名字让 `if` 行变成一句陈述。排查 `else` 为什么被触发时，还可以把 `is_eligible` 直接打印出来，并逐个子条件拆开检查。顺带一提：判断布尔变量时直接写 `if is_eligible:`，不要写 `if is_eligible == True:`——后者多两个字符，还可能在变量并非严格布尔值时意外变味。

### 3.5 常见错误模式速查表

| 错误写法 | 后果（实测报错信息） | 修正 |
|---------|------------------------|------|
| `else (x < 0):` | `SyntaxError: expected ':'` | `else:` 后直接冒号，条件交给 `if` |
| `if x > 0` （漏冒号） | `SyntaxError: expected ':'` | 补上冒号 |
| `else` 缩进比 `if` 深 | `SyntaxError: invalid syntax` | `else` 与 `if` 首字符同列对齐 |
| 无 `if` 的孤立 `else` | `SyntaxError: invalid syntax` | 删除，或给它一个配对的 `if` |
| 分支体空白 | `SyntaxError: expected an indented block after 'if'/'else' statement` | 块内放 `pass` 占位 |
| `if x = 5:` | `SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?` | 比较用 `==`，赋值不要出现在条件位置 |
| Tab 与空格混用 | `TabError: inconsistent use of tabs and spaces in indentation` 等缩进报错 | 编辑器统一"Tab 转 4 空格" |
| 两个独立 `if` 表互斥 | 无报错，条件漂移后出现逻辑裂缝 | 互斥语义一律 `if-else` |
| `if cond: a = 1 else: a = 2` 挤一行 | `SyntaxError: invalid syntax` | `else` 换行；或改用条件表达式 |

这张表覆盖了二分支九成的新手报错。排查口诀：报 `expected ':'` 看冒号，报 `invalid syntax` 看 `else` 位置，报 `expected an indented block` 看缩进块是否存在，报 `unindent does not match` 看块内缩进是否一致。

## 4. 原理

二分支的规则看似是若干条独立约定，其实可以统一在"条件跳转 + 缩进划分块"两套底层机制上。理解原理后，规则不再是需要背诵的条文，而是推导结果。

### 4.1 字节码视角：一次条件跳转

`dis` 模块能把函数翻译成 CPython 字节码。定义一个最小的二分支函数并反汇编：

```python
import dis


def pick(x):
    if x >= 0:
        return "非负数"
    else:
        return "负数"


dis.dis(pick)
```

**运行结果**（CPython 3.12）：

```text
  4           0 RESUME                   0

  5           2 LOAD_FAST                0 (x)
              4 LOAD_CONST               1 (0)
              6 COMPARE_OP              92 (>=)
             10 POP_JUMP_IF_FALSE        1 (to 14)

  6          12 RETURN_CONST             2 ('非负数')

  8     >>   14 RETURN_CONST             3 ('负数')
```

从上到下逐条读：

1. 最左侧数字是源码行号：第 4 行是 `def`，入口指令 `RESUME 0` 是 3.11 起的调试探针，与控制流无关
2. 第 5 行对应四条指令：取 `x`、取常量 `0`、做 `>=` 比较（`COMPARE_OP` 的 `92` 是操作符的内部编号），然后 `POP_JUMP_IF_FALSE` 拿出比较结果——**为假就跳到偏移 14**
3. 不跳转则落到偏移 12：第 6 行的 `RETURN_CONST '非负数'`，对应真分支
4. `>> 14` 标记出跳转目标：第 8 行的 `RETURN_CONST '负数'`，对应 else 分支

控制流画出来：

```text
偏移 2-6:    求值 x >= 0
                  │
偏移 10:     POP_JUMP_IF_FALSE
                  │
      假  ──────┴──────  真
      │                    │
      ▼                    ▼
偏移 14:             偏移 12:
RETURN_CONST         RETURN_CONST
'负数'               '非负数'
（else 分支）         （真分支）
      │                    │
      └────────┬───────────┘
               ▼
           函数返回
```

这解释了二分支的三个行为特征：

- **互斥的底层保证**：两条返回指令位于偏移 12 和 14 两个**不相交的区间**，一次执行流只会流经其中一段，语法层面想"都执行"都做不到
- **"必走其一"不是口号**：求值后要么在偏移 10 跳走、要么不跳，两种可能都被指令编进了计划，不存在第三条通路
- 侧记一条版本差异：3.9 及更早版本用 `POP_JUMP_IF_FALSE` 配 `JUMP_ABSOLUTE` 表达同样的两段式跳转；不同版本指令名有出入，"条件跳转撕开两条路径"的骨架始终一致

### 4.2 为什么 else 不需要条件

有了字节码视角，这条规则可以推导出来。运行期根本不存在"再判断一次 else 的条件"这回事：`POP_JUMP_IF_FALSE` 只有一个跳转目标，条件为假时控制权被**直接送往** else 块的入口地址。换句话说：

```text
else 块入口 = 条件为假时的跳转目标
```

else 的"条件"就是 if 条件的补集，这个补集在**编译期**由控制流位置锁定，运行期无需任何判断。所以在 `else` 后面写条件不仅在语法上被拒绝，在语义上也是冗余的——解释器已经把"条件为假的全部可能"划给了这个块。同理，"孤立 `else`"报 `invalid syntax` 的原因也清楚了：没有 `if` 的跳转，就没有"条件为假的落点"，`else` 无处依附。

### 4.3 缩进如何被编译器理解

Python 解析器在词法阶段为每一行的行首空白生成两个特殊记号：进入更深一级时产生 `INDENT`，退出一级时产生 `DEDENT`。二分支的"块"结构就是从这串记号里涌现的：

```text
if 条件:              → 解析器期待一个缩进块
    语句              → 行首空白加深，INDENT，真分支块开始
    语句
else:                 → 行首回到原级，DEDENT，真分支块结束
    语句              → else 与 if 同列 → 配对成功；再次 INDENT，假分支块开始
if-else 之后的代码    → DEDENT，假分支块结束
```

（图中的 `INDENT`/`DEDENT` 是概念示意，帮助你理解机制，非逐字记号。）

由此可以推导出本篇所有缩进规则的来历：

- 缩进量不一致报 `IndentationError`——回退量与所有未闭合层级都不匹配，词法层无法产出合法的 `DEDENT`
- `else` 必须与 `if` 同列——配对是**编译期**按缩进列完成的，错列了配不上对
- Tab 与空格混用出 `TabError`——两种字符宽度不同，"同一级"的判断失去统一单位
- 分支不能为空——块的定义就是"至少一条语句"，`pass` 正是为了在"逻辑为空"时兜住这条定义

PEP 8 推荐 4 空格不是语法强制，而是全社区统一的**缩进单位**约定——单位统一了，`INDENT`/`DEDENT` 的计算才永不歧义。

### 4.4 条件的真值从哪来

2.3 说过任意对象都能当条件。机制是：CPython 求条件真假时按固定次序查找三种途径——

1. 类型定义了 `__bool__` → 调用它，返回值即真假
2. 没有 `__bool__` 但定义了 `__len__` → 调用它，返回 0 即假、非 0 即真
3. 两者都没有 → 默认为真

标准类型们走的多是第二条路：空容器 `__len__` 返回 0，所以"空容器为假"。自定义一个重载 `__bool__` 的类验证：

```python
class Account:
    def __init__(self, level):
        self.level = level

    def __bool__(self):
        return self.level > 0


level_0 = Account(0)
level_3 = Account(3)

if level_0:
    print("有效")
else:
    print("无效")

if level_3:
    print("有效")
else:
    print("无效")
```

**运行结果**：

```text
无效
有效
```

两个对象都"存在"，但走进二分支的结果由 `__bool__` 决定。这也提醒我们：**把对象放进条件时要清楚它的真值定义**——自建类型若忘了定义 `__bool__`/`__len__`，永远为真，这可能不是你想要的语义；反过来，谨慎地定义 `__bool__`，能让"对象是否有效"直接参与条件判断，代码更自然。

## 5. 总结

本文围绕 `if-else` 二分支结构展开，主要介绍了以下内容：

- 二分支解决"非此即彼"问题：条件为真走真分支，为假走假分支，互斥、必走其一、最终汇合
- 语法骨架：`if` + 条件表达式 + 冒号 + 缩进块、`else:`（不带条件）+ 缩进块
- 条件可为任意对象，经真值测试解释；空容器、零值、空串、`None` 为假
- 分支体是普通语句块，可放多条语句；块的边界由缩进划定，块外的语句在两个分支执行完都执行
- 缩进错误有两类典型：块内缩进不一致（`unindent does not match`）与空块（`expected an indented block`）；Tab 与空格混用是隐形炸弹
- `else` 三大硬约束：后面不写条件、与配对 `if` 同列对齐、不能孤立出现；嵌套时按"就近配对"，歧义在 Python 中被缩进规则消除
- 空分支必须写 `pass` 占块；"阶段的空"与"刻意的空"含义不同
- 单行分支体仅限一条简单语句，`else` 必须另起一行
- 条件表达式 `A if cond else B` 是表达式版二分支，两支只求值一支，适合纯取值场景
- 最佳实践：互斥交给 `else`、失败分支给反馈、分支体抽函数、长条件命名布尔变量
- 底层是两段互不相交的指令区间加一次条件跳转；`else` 落点是编译期定好的"条件为假的跳转目标"；缩进由 `INDENT`/`DEDENT` 记号折算成块结构
