## 1. 介绍

### 1.1 三种方法从哪儿来

在 Python 的类体里，用 `def` 写出来的函数默认是**实例方法**（instance method）。如果给它加上 `@classmethod` 装饰器，它就变成**类方法**；加上 `@staticmethod`，它就变成**静态方法**。这三者看起来都是"类里面的函数"，但它们的第一参数、能访问的状态、以及典型用途完全不同。

本篇是面向对象方法篇的"决策篇"：前面三篇分别讲了实例方法（05）、类方法（06）、静态方法（07）各自的定义和用法，本篇不再重复定义，而是把三者并排放在一起，回答一个工程上最常被问到的问题——"我这个函数到底该写成实例方法、类方法还是静态方法？"

### 1.2 三者一眼对比

先把最关键的差异列出来，后面的章节会逐条展开：

| 维度 | 实例方法 | 类方法 `@classmethod` | 静态方法 `@staticmethod` |
|---|---|---|---|
| 第一参数 | `self`（实例） | `cls`（类） | 无隐式参数 |
| 能访问实例属性 | 是 | 否（没有 `self`） | 否 |
| 能访问类属性 | 是（经 `self.__class__` 或类名） | 是（直接经 `cls`） | 否（只能硬编码类名） |
| 典型调用 | `obj.method()` | `Cls.method()` / `obj.method()` | `Cls.method()` / `obj.method()` |
| 典型用途 | 操作实例状态 | 操作类状态、替代构造器、多态工厂 | 纯工具函数，只是逻辑上归属类 |

一个最小的三合一示例，先建立直觉：

```python
class Demo:
    cls_attr = "我是类属性"

    def __init__(self, val):
        self.val = val

    # 实例方法：拿到 self，既能用实例状态也能用类状态
    def show_instance(self):
        return f"instance: val={self.val}, cls={self.cls_attr}"

    # 类方法：拿到 cls，只能用类状态
    @classmethod
    def show_class(cls):
        return f"class: cls_attr={cls.cls_attr}"

    # 静态方法：什么隐式参数都没有
    @staticmethod
    def show_static():
        # 只能硬编码类名访问类属性，拿不到 self/cls
        return f"static: cls_attr={Demo.cls_attr}"


d = Demo(10)
print(d.show_instance())   # 通过实例调用实例方法
print(Demo.show_class())   # 通过类调用类方法
print(Demo.show_static())  # 通过类调用静态方法
# 输出：
# instance: val=10, cls=我是类属性
# class: cls_attr=我是类属性
# static: cls_attr=我是类属性
```

三种方法都能用"实例.方法()"的形式调用，也都能用"类.方法()"的形式调用，区别只在于调用时解释器会自动往方法里塞什么第一参数。这个"塞什么"的差异，正是第 4 章原理部分要讲的描述符绑定差异。

### 1.3 为什么需要三种

只有实例方法行不行？理论上绝大多数业务逻辑都可以塞进实例方法。但有两类需求实例方法覆盖不好：

1. **不依赖实例、只依赖类的逻辑**：比如根据"2024-01-01"这样的字符串创建一个 `Date` 实例。这个函数在创建实例之前还没有 `self` 可言，但它显然属于 `Date` 这个类。把它写成 `@classmethod` 的 `from_string`，调用形如 `Date.from_string("2024-01-01")`，既归属清晰，又能在被 `ChineseDate` 子类继承时自动创建子类实例（这就是 `cls` 的多态价值）。

2. **既不依赖实例、也不依赖类的纯工具函数**：比如判断某年是否闰年，输入只是一个年份整数，输出一个布尔值，跟具体的 `Date` 实例或 `Date` 类本身都没关系。但它逻辑上属于"日期"这个概念域，放在 `Date` 里比放在全局更合理。这种就写成 `@staticmethod`。

实例方法负责"实例自己的事"，类方法负责"类层面的事（尤其涉及多态创建）"，静态方法负责"和类概念相关但谁都不依赖的工具"。三者各司其职，这就是本篇要讲的选型逻辑。

## 2. 核心内容

### 2.1 实例方法：需要实例状态时选它

实例方法是默认形态，第一参数 `self` 在调用时被解释器绑定为调用它的那个实例。只要一个函数需要读或写实例属性（`self.xxx`），它就应该是实例方法。

**典型场景**：

- 读取/修改实例自身的属性。
- 依赖实例内部状态做计算（如 `is_weekend` 需要知道"自己是哪一天"）。
- 调用同一实例的其他实例方法。

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    # 实例方法：必须知道"自己是哪一天"才能判断
    def is_weekend(self):
        import datetime
        d = datetime.date(self.year, self.month, self.day)
        return d.weekday() >= 5  # 5=周六, 6=周日


d = Date(2024, 6, 15)   # 2024-06-15 是周六
print(d.is_weekend())
# 输出：True
```

`is_weekend` 依赖 `self.year/month/day`，没有实例就没有这些值，所以它天然只能是实例方法。

**注意**：不要把"用不到 `self`"的函数写成实例方法。这是最常见的误用之一，第 3 章会专门讲。

### 2.2 类方法：需要类状态或希望子类多态时选它

`@classmethod` 把方法的第一个参数绑定为"调用它的那个类"（不是实例）。`cls` 不是关键字，只是约定俗成的参数名，就像 `self` 一样。

**典型场景一：替代构造器（工厂方法）**

Python 一个类的正经构造器只有 `__init__`，且参数固定。当需要"从别的格式构造实例"时，惯例写一个 `from_xxx` 类方法：

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    @classmethod
    def from_iso(cls, iso_string):
        # cls 是当前调用方所在类，下面 new 的是 cls 而非硬编码 Date
        y, m, d = iso_string.split("-")
        return cls(int(y), int(m), int(d))


d = Date.from_iso("2024-06-15")
print(d.year, d.month, d.day)
# 输出：2024 6 15


class ChineseDate(Date):
    """子类：日期用中文格式打印"""
    def __str__(self):
        return f"{self.year}年{self.month}月{self.day}日"


# 子类继承父类的 from_iso，但因为 cls 是子类，创建的是 ChineseDate
c = ChineseDate.from_iso("2024-06-15")
print(c)
print(type(c).__name__)
# 输出：
# 2024年6月15日
# ChineseDate
```

关键点在 `return cls(...)`：如果这里写成 `return Date(...)`，那 `ChineseDate.from_iso` 创建出来的就还是 `Date`，子类多态就被丢了。这就是 `cls` 相对"硬编码类名"的工程价值——**类方法天然支持子类多态工厂**。

**典型场景二：类级配置与实例计数**

当需要读改类属性（比如全局配置、实例计数器）时，用类方法比用 `ClassName.attr` 硬编码更灵活，同样因为子类继承时 `cls` 会指向子类。

```python
class Connection:
    _pool = []          # 类属性：连接池
    _created = 0        # 类属性：已创建实例数

    def __init__(self, name):
        self.name = name
        Connection._created += 1   # 计数最简单的方式是直接用类名

    @classmethod
    def total_created(cls):
        return cls._created

    @classmethod
    def from_config(cls, config_dict):
        """根据配置字典构造连接，子类继承时自动创建子类实例"""
        return cls(config_dict["name"])


c1 = Connection("main")
c2 = Connection("cache")
print(Connection.total_created())
# 输出：2
```

**典型场景三：多态工厂（多个类方法互为入口）**

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    @classmethod
    def from_iso(cls, s):
        y, m, d = s.split("-")
        return cls(int(y), int(m), int(d))

    @classmethod
    def from_tuple(cls, t):
        return cls(*t)

    @classmethod
    def from_timestamp(cls, ts):
        import datetime
        d = datetime.date.fromtimestamp(ts)
        return cls(d.year, d.month, d.day)


d1 = Date.from_iso("2024-06-15")
d2 = Date.from_tuple((2024, 6, 15))
d3 = Date.from_timestamp(1718409600)
print(d1.year, d2.year, d3.year)
# 输出：2024 2024 2024
```

三个 `from_xxx` 各自是一个清晰的构造入口，且都被子类无成本继承——这是实例方法和静态方法都做不到的。

### 2.3 静态方法：谁都不依赖、只是归类时选它

`@staticmethod` 不注入任何隐式第一参数。它本质上是"刚好放在类的命名空间里的普通函数"。

**典型场景**：

- 纯工具函数，输入只来自参数，输出只来自 `return`。
- 逻辑上属于这个类的概念域，但既不需要实例状态也不需要类状态。
- 给一组相关函数一个命名空间归属（比单独放全局更内聚）。

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    @staticmethod
    def is_leap_year(year):
        """判断某年是否闰年：输入只是一个 int，与实例/类都无关"""
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)


print(Date.is_leap_year(2024))
print(Date.is_leap_year(2023))
# 输出：
# True
# False
```

`is_leap_year` 只需要一个年份整数。它不关心"是哪个 `Date` 实例在问"，也不关心"是哪个 `Date` 子类在问"。这种情况下用 `@staticmethod` 最贴切。

也可以通过实例调用静态方法，但不会用到实例状态：

```python
d = Date(2024, 6, 15)
print(d.is_leap_year(d.year))   # 合法，但 self 不会被注入，year 仍来自显式参数
# 输出：True
```

**静态方法 vs 写在模块顶层的普通函数**

`is_leap_year` 完全可以写成模块级函数：

```python
def is_leap_year(year):
    return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)
```

什么时候选择放进类里当静态方法？标准是**内聚性**：如果这个函数的逻辑和这个类高度相关，使用者会天然去这个类里找它，那就放进去；如果它是个通用工具（比如字符串清洗、数值格式化），谁都能用，没有明确的归属类，那就放模块顶层或专门的 `utils` 模块。

### 2.4 一个 Date 类的三者合理分工

把三者放在同一个 `Date` 类里，看它们如何各司其职、互不越界：

```python
import datetime


class Date:
    """综合示例：实例方法 / 类方法 / 静态方法的合理分工"""

    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    # ---------- 实例方法：依赖 self（自己这个日期）----------
    def is_weekend(self):
        """依赖 self.year/month/day，只能用实例"""
        d = datetime.date(self.year, self.month, self.day)
        return d.weekday() >= 5

    def days_since_epoch(self):
        """依赖 self，只能用实例"""
        d = datetime.date(self.year, self.month, self.day)
        return (d - datetime.date(1970, 1, 1)).days

    # ---------- 类方法：依赖 cls（类/子类），工厂入口 ----------
    @classmethod
    def from_iso(cls, iso_string):
        """替代构造器：从 "YYYY-MM-DD" 创建"""
        y, m, d = iso_string.split("-")
        return cls(int(y), int(m), int(d))

    @classmethod
    def today(cls):
        """替代构造器：创建今天的日期，子类继承自动得到子类实例"""
        t = datetime.date.today()
        return cls(t.year, t.month, t.day)

    # ---------- 静态方法：纯工具，谁都不依赖 ----------
    @staticmethod
    def is_leap_year(year):
        """判断闰年：只看 year 这一个 int"""
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

    @staticmethod
    def days_in_month(year, month):
        """某年某月有多少天：纯计算，与实例/类无关"""
        if month == 2:
            return 29 if Date.is_leap_year(year) else 28
        if month in (4, 6, 9, 11):
            return 30
        return 31


# 子类，验证 cls 多态
class ChineseDate(Date):
    def __str__(self):
        return f"{self.year}年{self.month}月{self.day}日"


# --- 实例方法：必须先有实例 ---
d = Date.from_iso("2024-06-15")
print(d.is_weekend())          # True，依赖 self
print(d.days_since_epoch())    # 19919，依赖 self

# --- 类方法：工厂入口，子类自动受益 ---
c = ChineseDate.from_iso("2024-06-15")
print(c)
print(type(c).__name__)        # ChineseDate，cls 多态生效
print(ChineseDate.today())     # 今天，且是 ChineseDate 实例

# --- 静态方法：纯工具 ---
print(Date.is_leap_year(2024))     # True
print(Date.days_in_month(2024, 2)) # 29
# 输出：
# True
# 19919
# 2024年6月15日
# ChineseDate
# 2026年7月23日
# True
# 29
```

这个 `Date` 类把三者用在了各自该用的地方：

- `is_weekend` / `days_since_epoch` 必须知道"是哪个日期"，用实例方法。
- `from_iso` / `today` 是创建实例的入口且希望子类多态，用类方法（`cls` 而非 `Date`）。
- `is_leap_year` / `days_in_month` 只做纯计算，用静态方法。

如果把 `is_leap_year` 写成实例方法，调用就得 `d.is_leap_year()`，但实际上它根本不关心 `self`，白拿了一个 `self` 没用；如果把 `from_iso` 写成静态方法，里面只能 `return Date(...)`，`ChineseDate.from_iso` 创建出来的就不再是 `ChineseDate`，多态工厂失效。第 3 章会具体讲这些误用。

### 2.5 三者签名与调用对比表

把签名、调用形式、绑定行为做一张更细的对比表，便于速查：

| 对比项 | 实例方法 | `@classmethod` | `@staticmethod` |
|---|---|---|---|
| 定义 | `def f(self, ...)` | `@classmethod`<br>`def f(cls, ...)` | `@staticmethod`<br>`def f(...)` |
| 第一参数 | `self`（实例对象） | `cls`（类对象） | 无隐式参数 |
| 经实例调用 `obj.f()` | `self=obj`，正常 | `cls=type(obj)`，正常 | 不绑定，按普通函数调用 |
| 经类调用 `Cls.f()` | 报错（缺 `self`），除非传实例 | `cls=Cls`，正常 | 正常 |
| 能读实例属性 | 是 | 否 | 否 |
| 能读类属性 | 是（`self.xxx` 会回退到类） | 是（`cls.xxx`） | 否（硬编码类名才行） |
| 能改实例属性 | 是 | 否 | 否 |
| 能改类属性 | 是（经 `type(self)` 或类名） | 是（经 `cls`） | 否（硬编码类名） |
| 继承时行为 | 子类实例调到子类自己的 `self` | `cls` 指向子类 | 和写死类名的普通函数一样 |
| 适合做工厂 | 否（没有实例可创建实例） | 是（`cls(...)` 多态） | 勉强（需硬编码类名，丢多态） |
| 能否访问 `self` | 是 | 否 | 否 |
| 能否访问 `cls` | 否（但可 `type(self)`） | 是 | 否（但可硬编码类名） |

**几种调用形式都试一遍**

```python
class C:
    x = "cls_attr"

    def __init__(self):
        self.x = "inst_attr"

    def im(self):
        return f"im: self.x={self.x}"

    @classmethod
    def cm(cls):
        return f"cm: cls.x={cls.x}"

    @staticmethod
    def sm():
        return f"sm: C.x={C.x}"


obj = C()

# 实例方法
print(obj.im())        # 经实例：self=obj
# print(C.im())        # 经类：TypeError，缺少 self
print(C.im(obj))       # 经类但手动传实例：等价于 obj.im()

# 类方法
print(C.cm())          # 经类：cls=C
print(obj.cm())        # 经实例：cls=type(obj) 仍是 C

# 静态方法
print(C.sm())          # 经类
print(obj.sm())        # 经实例：不会绑定，和 C.sm() 一样
# 输出：
# im: self.x=inst_attr
# im: self.x=inst_attr
# cm: cls.x=cls_attr
# cm: cls.x=cls_attr
# sm: C.x=cls_attr
# sm: C.x=cls_attr
```

几个值得注意的细节：

- `C.im(obj)` 是合法的——实例方法本质上就是个普通函数，`obj.im()` 只是语法糖。
- `obj.cm()` 里 `cls` 仍然是类 `C` 而不是实例，类方法永远拿不到实例。
- `obj.sm()` 也能调用静态方法，但不会注入任何东西，`sm` 内部拿不到 `obj`。

### 2.6 三者与继承的协作

把继承场景单独拉出来看，因为这是三者差异最明显的地方。

```python
class Animal:
    legs = 4

    def __init__(self, name):
        self.name = name

    def describe(self):              # 实例方法
        return f"{self.name} has {self.legs} legs"

    @classmethod
    def create(cls, name):           # 类方法工厂
        return cls(name)

    @staticmethod
    def kingdom():
        return "Animalia"


class Spider(Animal):
    legs = 8


# 实例方法：子类继承父类方法，self 是 Spider 实例，self.legs 回退到 Spider.legs=8
s = Spider("Webby")
print(s.describe())
# 输出：Webby has 8 legs

# 类方法：cls 是 Spider，创建的是 Spider 实例
s2 = Spider.create("Ari")
print(type(s2).__name__, s2.name)
# 输出：Spider Ari

# 静态方法：直接继承，和普通函数没区别
print(Spider.kingdom())
# 输出：Animalia
```

可以看到：

- **实例方法**通过 `self` 自动获得子类的实例属性与（回退的）类属性，无需任何额外代码。
- **类方法**通过 `cls` 自动指向子类，是最适合做"多态工厂"的形态。
- **静态方法**只是被继承过来，它内部如果不硬编码类名，就无法感知自己处于哪个子类。

这就是"替代构造器优先用类方法而非静态方法"的根本原因——只有 `cls` 才能在被继承时创建出正确子类的实例。

## 3. 最佳实践

### 3.1 选型决策树

把第 2 章的内容凝练成一张可直接照做的决策表。写代码时，遇到"要在类里加一个函数"的瞬间，按这个顺序问自己：

| 顺序 | 问题 | 回答 | 选择 |
|---|---|---|---|
| 1 | 这个函数需要读/写实例属性（`self.xxx`）吗？ | 是 | 实例方法 |
| 2 | 这个函数需要读/改类属性，或者希望它作为被继承的多态工厂吗？ | 是 | 类方法 |
| 3 | 这个函数逻辑上属于这个类，但既不依赖实例也不依赖类吗？ | 是 | 静态方法 |
| 4 | 既不依赖实例/类，也没有明确的类归属？ | 是 | 模块级函数，别塞进类里 |

一句话口诀：**要实例 → 实例方法；要类或多态 → 类方法；都不要只是归类 → 静态方法；连类都不沾 → 模块函数。**

### 3.2 推荐写法 vs 不推荐写法

**误用一：把能用静态方法的写成实例方法（白拿 `self`）**

不推荐：

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    def is_leap_year(self):
        # 方法体里根本没用 self，只是想借用 d.year
        y = self.year
        return y % 4 == 0 and (y % 100 != 0 or y % 400 == 0)
```

这样写的问题：

- 调用必须先有实例：`Date(2024,1,1).is_leap_year()`，但其实你想问的只是"2024 年是不是闰年"，根本不需要构造一个具体日期。
- 无法脱离实例使用，丧失了"纯工具"的便利性。
- 语义错位：`is_leap_year` 是关于"年"的判断，不是关于"某个日期实例"的操作。

推荐：

```python
class Date:
    @staticmethod
    def is_leap_year(year):
        return year % 4 == 0 and (year % 100 != 0 or year % 400 == 0)

# 直接用，无需任何实例
print(Date.is_leap_year(2024))
```

**误用二：把工厂写成静态方法（丢失 `cls` 多态）**

不推荐：

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    @staticmethod
    def from_iso(s):
        y, m, d = s.split("-")
        return Date(int(y), int(m), int(d))   # 硬编码 Date


class ChineseDate(Date):
    pass

c = ChineseDate.from_iso("2024-06-15")
print(type(c).__name__)
# 输出：Date   ← 期望 ChineseDate，实际得到 Date，多态丢失
```

问题在于 `from_iso` 内部写死了 `Date(...)`，子类调用时创建不出子类实例。

推荐：

```python
class Date:
    @classmethod
    def from_iso(cls, s):
        y, m, d = s.split("-")
        return cls(int(y), int(m), int(d))    # cls 自动指向调用方类

c = ChineseDate.from_iso("2024-06-15")
print(type(c).__name__)
# 输出：ChineseDate
```

**误用三：把该用实例方法的写成静态方法（拿不到状态）**

不推荐：

```python
class Date:
    def __init__(self, year, month, day):
        self.year, self.month, self.day = year, month, day

    @staticmethod
    def is_weekend(year, month, day):
        import datetime
        return datetime.date(year, month, day).weekday() >= 5
```

这样写虽然能跑，但调用形如 `Date.is_weekend(d.year, d.month, d.day)`——明明 `d` 自己就持有这些值，却要外部拆开再传回去，既啰嗦又容易传错。

推荐：

```python
class Date:
    def is_weekend(self):   # 实例方法，直接用 self
        import datetime
        return datetime.date(self.year, self.month, self.day).weekday() >= 5

d = Date(2024, 6, 15)
print(d.is_weekend())   # 干净
```

**误用四：把不依赖实例/类的纯通用工具硬塞进类里**

不推荐：

```python
class Order:
    @staticmethod
    def format_price(p):
        return f"￥{p:.2f}"

    @staticmethod
    def trim_whitespace(s):
        return s.strip()
```

`format_price`/`trim_whitespace` 是通用字符串处理，跟 `Order` 没有概念上的强归属，放进类只是徒增调用路径（`Order.format_price(x)`）。这种应该放模块级 `utils.py` 或就近的 `formatting` 模块。是否放进类，标准是"使用者会不会天然到这个类里找它"。

### 3.3 类方法做替代构造器的命名惯例

Python 社区对类方法工厂有稳定的命名约定，遵循它能让代码自解释：

- `from_xxx`：从某种数据格式构造，如 `from_string`、`from_dict`、`from_tuple`、`from_json`、`from_iso`。
- `create_xxx` / `make_xxx`：带额外处理或副作用的构造，如 `create_from_config`。
- `today` / `now` / `utcnow`：取"当前"值的快捷构造（参照 `datetime.date.today`）。

`datetime` 标准库本身就是这套惯例的范本：`datetime.date.today()`、`datetime.datetime.fromisoformat()`、`datetime.datetime.fromtimestamp()` 全是类方法。写自己的类时照这个惯例来，别人一看就懂。

### 3.4 类属性访问：`cls` vs 硬编码类名

在类方法和静态方法里，访问类属性有两种写法：

```python
class Counter:
    _count = 0

    @classmethod
    def increment(cls):
        cls._count += 1     # 推荐：经 cls，子类继承时计数分开

    @staticmethod
    def reset():
        Counter._count = 0  # 静态方法只能硬编码类名
```

在涉及继承时，`cls` 和硬编码类名会产生不同行为：

```python
class SubCounter(Counter):
    _count = 0

Counter.increment()      # 改的是 Counter._count
SubCounter.increment()   # 改的是 SubCounter._count，因为 cls=SubCounter
print(Counter._count, SubCounter._count)
# 输出：1 1
```

如果你希望"每个子类有自己独立的计数"，就用类方法 + `cls`；如果就是想改基类的计数，才硬编码类名。这是 `cls` 多态价值的又一处体现。

### 3.5 调用形式的可读性建议

- 实例方法：始终用 `obj.method()`，别用 `Cls.method(obj)`——后者虽然合法但可读性差，只在元编程或测试里偶尔用。
- 类方法：优先 `Cls.method()`，即使能用 `obj.method()` 也优先用类名，因为类方法的语义是"类层面的操作"，用类名调用更体现意图。
- 静态方法：同样优先 `Cls.method()`，用类名调用能强调"这不依赖任何实例"。

### 3.6 当不确定时，默认用实例方法

如果你对着决策树还是拿不准，记住一个安全的退化策略：**默认用实例方法**。实例方法是覆盖面最广的形态，绝大多数业务逻辑都依赖实例状态。只有在明确出现"构造前的工厂""纯工具函数"这两种信号时，才主动升级到类方法或降级到静态方法。宁可多写几个实例方法，也不要 为了"看起来高级"而滥用 `@classmethod`/`@staticmethod`。

### 3.7 不要用静态方法拼凑"命名空间"

如果一整个类里全是 `@staticmethod`、没有任何实例方法或类方法，那这个类其实不是类，只是一个被大括号包起来的命名空间。Python 不需要用类来 grouping 函数，模块本身就是命名空间。写成：

```python
# 不推荐：用类当命名空间
class DateUtils:
    @staticmethod
    def is_leap_year(year): ...
    @staticmethod
    def days_in_month(year, month): ...
```

不如直接写成模块级函数：

```python
# date_utils.py
def is_leap_year(year): ...
def days_in_month(year, month): ...
```

只有当这些工具函数确实和某个有状态的类强绑定时，才把它们作为静态方法放进类里。

## 4. 原理

### 4.1 三者都是描述符，区别在绑定行为

`@classmethod` 和 `@staticmethod` 在 CPython 里都是用描述符协议实现的。函数对象本身也是一个描述符（实现了 `__get__`）。三者差异的本质，是 `__get__` 被触发时返回的东西不同。

**函数（实例方法）作为描述符**

普通函数对象实现了 `__get__`。当你写 `obj.method` 时，Python 执行 `Function.__get__(method, obj, type(obj))`，它返回一个**绑定方法对象（bound method）**，这个对象把 `obj` 预先塞进了第一参数位。于是调用 `obj.method(a)` 等价于调用 `method(obj, a)`。

```python
class C:
    def f(self, x):
        return x + 1

c = C()
bm = c.f            # 触发 Function.__get__，返回绑定方法
print(bm)
print(bm.__self__ is c)   # 绑定方法记住了实例
print(bm(10))             # 等价于 C.f(c, 10)
# 输出：
# <bound method C.f of <__main__.C object at ...>>
# True
# 11
```

而 `C.f`（经类访问）触发的是 `Function.__get__(method, None, C)`，此时返回的是**函数本身**（未绑定），所以 `C.f()` 缺 `self` 会报错，必须 `C.f(c)` 手动传实例。

**classmethod 作为描述符**

`classmethod` 是一个独立的描述符类型。它的 `__get__` 总是把"调用者所在类"绑进去，无论是经类还是经实例访问：

```python
class C:
    @classmethod
    def f(cls, x):
        return (cls, x)

c = C()
print(C.f(10))     # 经类：cls=C
print(c.f(10))     # 经实例：cls 仍是 type(c)=C
# 输出：
# (<class '__main__.C'>, 10)
# (<class '__main__.C'>, 10)
```

`classmethod.__get__` 大致等价于"返回一个把 `cls` 绑好的绑定方法"。所以类方法永远拿到的是类，不是实例——即使你用 `obj.method()` 调用。

**staticmethod 作为描述符**

`staticmethod` 的 `__get__` 最简单：它直接返回被它包裹的那个原始函数，不做任何绑定。

```python
class C:
    @staticmethod
    def f(x):
        return x

c = C()
print(C.f is C.f)   # 经类取多次，返回的就是同一个原始函数
print(c.f is C.f)   # 经实例取，也是同一个原始函数，没有绑定方法
# 输出：
# True
# True
```

这就是为什么静态方法内部既拿不到 `self` 也拿不到 `cls`——`__get__` 压根没往里绑任何东西。

**三者 `__get__` 行为对比**

| 描述符类型 | 经实例 `obj.f` 的 `__get__` 返回 | 经类 `Cls.f` 的 `__get__` 返回 | 调用时第一参数来自哪里 |
|---|---|---|---|
| 普通函数（实例方法） | 绑定方法（`self=obj`） | 原始函数（未绑定） | `obj` 被绑进第一参数位 |
| `classmethod` | 绑定方法（`cls=type(obj)`） | 绑定方法（`cls=Cls`） | 类被绑进第一参数位 |
| `staticmethod` | 原始函数 | 原始函数 | 无隐式参数 |

这张表是本篇原理的核心。第一参数的差异、能访问什么的差异、调用形式能否成立的差异，全都源自 `__get__` 返回了什么。

### 4.2 为什么类方法经实例调用拿到的是类而不是实例

一个常见的疑惑：`obj.cm()` 里 `cls` 为什么不是 `obj`？

因为 `classmethod.__get__` 的实现里，拿到的是 `type(obj)` 而不是 `obj` 本身。设计上，类方法的语义就是"类层面的操作"，实例只是"借道"提供一个查找入口，描述符在绑定时把实例转成了它的类。这保证了无论你怎么调用，类方法永远在类层面工作，不会意外拿到实例状态。

可以验证：

```python
class C:
    @classmethod
    def cm(cls):
        return cls

c = C()
print(c.cm() is C)   # True，cls 是类，不是实例 c
print(type(c) is C)  # True，正是 type(c)
# 输出：
# True
# True
```

### 4.3 cls 多态机制的工程价值

`cls` 在被继承时指向子类，这是类方法相对静态方法的根本优势。把这个机制拆开看：

1. 子类没有重写父类的类方法时，`SubCls.from_xxx()` 实际调用的仍是父类的实现。
2. 但 `classmethod.__get__` 在绑定时用的 `cls` 是"调用方的类"，即 `SubCls`。
3. 父类实现里写 `return cls(...)`，创建的就是 `SubCls` 实例。

这套机制让"工厂方法可被无成本继承"成为可能。对比静态方法：静态方法内部只能 `return BaseCls(...)`（硬编码），继承后创建的永远是基类实例，除非子类把整个静态方法重写一遍。这就是替代构造器优先用类方法的原理依据。

```python
class Base:
    @classmethod
    def make(cls):
        return cls()    # cls 决定了创建什么

    @staticmethod
    def make_static():
        return Base()   # 硬编码，子类继承不变


class Sub(Base):
    pass

print(type(Sub.make()).__name__)         # Sub，cls 多态
print(type(Sub.make_static()).__name__)  # Base，静态方法丢多态
# 输出：
# Sub
# Base
```

### 4.4 实例方法为何经类调用会报错

因为普通函数经类访问时，`__get__` 返回的是未绑定的原始函数，第一参数 `self` 没有被自动填入。于是 `Cls.method()` 缺少 `self` 实参，Python 抛 `TypeError`。

```python
class C:
    def f(self):
        return "ok"

# C.f()   # TypeError: f() missing 1 required positional argument: 'self'
C.f(C())  # 手动传实例，合法
```

这也是"实例方法必须经实例调用"的原理根源——不是语法规定，而是描述符绑定行为使然。

### 4.5 绑定方法对象的小开销

`obj.method` 每次访问都会新建一个绑定方法对象（轻量，但非零成本）。在性能敏感的热循环里，把绑定方法缓存到局部变量会更稳：

```python
class Counter:
    def __init__(self):
        self.n = 0

    def tick(self):
        self.n += 1
        return self.n


c = Counter()
tick = c.tick     # 缓存绑定方法，避免循环里反复构造
for _ in range(3):
    print(tick())
# 输出：
# 1
# 2
# 3
```

类方法和静态方法同理：类方法每次访问也会构造绑定方法，静态方法不会（直接返回原函数）。这点开销在日常代码里可以忽略，只在密集循环或底层库里需要留意。

## 5. 总结

### 5.1 本文内容要点

- 一个类里的函数有三种形态：实例方法（默认，第一参数 `self`）、类方法（`@classmethod`，第一参数 `cls`）、静态方法（`@staticmethod`，无隐式参数）。
- 实例方法依赖实例状态，用于操作 `self` 持有的数据；典型如 `is_weekend`。
- 类方法依赖类状态或承担多态工厂职责，`cls` 在被继承时自动指向子类，使替代构造器（`from_xxx`）能被无成本继承；典型如 `from_iso`、`today`。
- 静态方法是不依赖实例也不依赖类的纯工具函数，只是逻辑上归属这个类；典型如 `is_leap_year`。
- 选型决策树：需要实例状态 → 实例方法；需要类状态或希望子类多态 → 类方法；都不需要只是归类 → 静态方法；连类都不沾 → 模块级函数。
- 常见误用：把能用静态方法的写成实例方法（白拿 `self`、无法脱离实例使用）、把工厂写成静态方法（丢 `cls` 多态，子类创建出基类实例）、把该用实例方法的写成静态方法（拿不到状态，调用啰嗦）。
- 三者的差异根源在描述符 `__get__` 的绑定行为：实例方法绑实例、类方法绑类、静态方法不绑，这决定了各自第一参数与能否经类/实例调用。
- `cls` 多态的工程价值：让工厂方法可被子类无成本继承并创建子类实例，是"替代构造器优先用类方法"的原理依据。

### 5.2 读完本文你应能掌握

- 能说出三者的第一参数分别是什么、能访问什么状态，不假思索地选出正确形态。
- 能看一段"类里的函数"代码，判断它是否误用了形态（白拿 `self`、丢失多态、拿不到状态）并给出修正。
- 能为自定义类编写符合 Python 社区惯例的替代构造器（`from_xxx` / `today` 等），并解释为什么用 `@classmethod` 而不是 `@staticmethod`。
- 能在不依赖实例的场景下，把纯工具函数正确地写成 `@staticmethod` 或模块级函数，并说明取舍理由。
- 能用描述符 `__get__` 的绑定行为解释：为何实例方法经类调用会报错、为何类方法经实例调用拿到的仍是类、为何静态方法内部拿不到 `self`/`cls`。
- 能在出现继承时，预测三者各自的绑定结果，并据此选择"多态工厂用类方法、纯工具用静态方法"的写法。
