## 1. 介绍

### 1.1 什么是 zip

`zip` 是 Python 内置函数，用于将多个可迭代对象中对应位置的元素"聚合"成元组，实现并行遍历。它的名字来源于物理世界的拉链（zipper）——将两侧的齿牙一对一地啮合在一起。

在实际编程中，你时常会遇到"两个列表中的元素在位置上存在对应关系"的场景。最典型的例子是学生名单和成绩单：列表 `names` 中的第 `i` 个学生，对应列表 `scores` 中的第 `i` 个成绩。如果没有 zip，你需要通过下标索引来手动配对，代码冗长且易错；有了 zip，一行代码就能将"对应位置"的关系清晰地表达出来。

zip 的核心价值在于：

- **消除下标访问**：不再需要 `for i in range(len(list1))` 这种笨拙的写法，直接配对元素本身。
- **提升可读性**：代码的意图是"并行遍历这些集合"，对阅读者一目了然。
- **惰性求值**：zip 在 Python 3 中返回的是迭代器，不一次性生成全部配对结果，对大数据的处理非常友好。

Python 2 中的 `zip` 返回的是列表，Python 3 改为返回迭代器（`zip` 对象），这是向后兼容时需要注意的重大区别。

### 1.2 基本语法与最小示例

`zip` 的基本语法形式如下：

```python
zip(*iterables)
```

其中 `*iterables` 表示可以传入零个、一个或多个可迭代对象。每个可迭代对象可以是列表、元组、字符串、range、字典、集合、文件对象、生成器等任何实现了迭代协议的对象。

先看一个最直观的最小示例——将两个列表按位置配对：

```python
# 将两个列表并行配对
names = ["Alice", "Bob", "Charlie"]
scores = [88, 95, 73]

# 将两个列表中相同位置的元素配对为元组
paired = zip(names, scores)
print(paired)           # 输出：<zip object at 0x...>
print(list(paired))     # 输出：[('Alice', 88), ('Bob', 95), ('Charlie', 73)]
```

运行结果说明：
- 直接打印 `zip` 对象看到的是 `zip object` 的描述信息，说明它是迭代器而非具体列表。
- 通过 `list()` 消费该迭代器后，得到三个元组，每个元组包含两个列表中对应位置的元素。
- 这种配对是"垂直"的——第一个元组来自所有可迭代对象的第一个元素，第二个元组来自所有可迭代对象的第二个元素，以此类推。

如果需要将一个 zip 对象用于后续操作（如遍历），可以直接在 `for` 循环中使用它，无需先转换成列表：

```python
names = ["Alice", "Bob", "Charlie"]
scores = [88, 95, 73]

# 在 for 循环中直接使用 zip 迭代器
for name, score in zip(names, scores):
    print(f"{name}: {score}")
# 输出：
# Alice: 88
# Bob: 95
# Charlie: 73
```

解包赋值是 zip 最常见的搭配：`for name, score in zip(names, scores)` 中的 `name, score` 会将每个元组分拆到两个变量中，既简洁又清晰。

## 2. 核心内容

### 2.1 zip 基础用法：两个可迭代对象的并行遍历

两个可迭代对象的配对是最常用的形式。你只需要将两个可迭代对象作为位置参数传入，zip 就会逐个取出它们第 0 个、第 1 个、第 2 个……元素组成元组。

```python
# 基本形式：zip(iterable1, iterable2)
# 将两个列表对应位置的元素配对
students = ["Alice", "Bob", "Charlie", "David"]
grades = ["A", "B+", "A-", "B"]

# 逐个打印配对结果
for student, grade in zip(students, grades):
    print(f"{student}: {grade}")
# 输出：
# Alice: A
# Bob: B+
# Charlie: A-
# David: B
```

值得注意的是，zip 不要求两个可迭代对象是同一类型——列表、元组、字符串等可以混合使用，只要它们都是可迭代对象：

```python
# 混合不同类型的可迭代对象
ids = [101, 102, 103]           # 列表
names = ("Alice", "Bob", "Charlie")  # 元组
initials = "ABC"                # 字符串（迭代每个字符）

for id_num, name, initial in zip(ids, names, initials):
    print(f"ID={id_num}, Name={name}, Initial={initial}")
# 输出：
# ID=101, Name=Alice, Initial=A
# ID=102, Name=Bob, Initial=B
# ID=103, Name=Charlie, Initial=C
```

zip 也支持将 range 对象作为输入，这在处理序列编号时非常有用：

```python
# 用 range 生成序号，与数据列表配对
datapoints = [23.5, 24.1, 22.8, 23.9, 24.3]

for index, value in zip(range(len(datapoints)), datapoints):
    print(f"第 {index + 1} 个数据点: {value}")
# 输出：
# 第 1 个数据点: 23.5
# 第 2 个数据点: 24.1
# 第 3 个数据点: 22.8
# 第 4 个数据点: 23.9
# 第 5 个数据点: 24.3
```

不过上面这种写法在 Python 中并非最佳实践——使用 `enumerate` 会更简洁。但理解这个模式仍然有价值，因为它体现了 zip 的灵活性。

### 2.2 zip 传入三个及以上的可迭代对象

zip 可以接收任意数量的可迭代对象（理论上限由系统内存决定，但调用时直接作为位置参数传入即可）。传入三个对象时，每次生成的元组包含三个元素：

```python
# 三个列表并行遍历
subjects = ["Math", "English", "Science", "History"]
teachers = ["Mr. Wang", "Ms. Li", "Dr. Chen", "Prof. Zhao"]
classrooms = ["A101", "B203", "C105", "A208"]

print("=== 课表信息 ===")
for subject, teacher, room in zip(subjects, teachers, classrooms):
    print(f"{subject} | 授课教师: {teacher} | 教室: {room}")
# 输出：
# === 课表信息 ===
# Math | 授课教师: Mr. Wang | 教室: A101
# English | 授课教师: Ms. Li | 教室: B203
# Science | 授课教师: Dr. Chen | 教室: C105
# History | 授课教师: Prof. Zhao | 教室: A208
```

传入四个对象的情况在实际中也时有出现。例如处理一个表格的每一列数据，将它们按行对齐：

```python
# 四列数据按行对齐 —— 模拟 CSV 表格的列式读取
order_ids = [1001, 1002, 1003, 1004]
products = ["Laptop", "Mouse", "Keyboard", "Monitor"]
quantities = [1, 3, 2, 1]
prices = [5999.0, 129.0, 399.0, 1899.0]

print("订单号 | 商品 | 数量 | 单价")
print("-" * 35)
for oid, prod, qty, price in zip(order_ids, products, quantities, prices):
    print(f"{oid} | {prod} | {qty} | ¥{price:.2f}")
# 输出：
# 订单号 | 商品 | 数量 | 单价
# -----------------------------------
# 1001 | Laptop | 1 | ¥5999.00
# 1002 | Mouse | 3 | ¥129.00
# 1003 | Keyboard | 2 | ¥399.00
# 1004 | Monitor | 1 | ¥1899.00
```

如果传入的可迭代对象数量很大（比如超过 10 个），代码的可读性会显著下降。此时应该考虑使用 `zip(*list_of_iterables)` 的形式，从列表解包传入：

```python
# 通过 * 解包传入大量可迭代对象
columns = [
    ["Jan", "Feb", "Mar", "Apr"],          # 月份
    [12000, 13500, 11000, 14800],          # 销售额
    [8000, 9200, 7500, 10100],             # 成本
]

print("月份 | 销售额 | 成本")
for row in zip(*columns):
    month, revenue, cost = row
    profit = revenue - cost
    print(f"{month} | ¥{revenue} | ¥{cost} | 利润: ¥{profit}")
# 输出：
# 月份 | 销售额 | 成本
# Jan | ¥12000 | ¥8000 | 利润: ¥4000
# Feb | ¥13500 | ¥9200 | 利润: ¥4300
# Mar | ¥11000 | ¥7500 | 利润: ¥3500
# Apr | ¥14800 | ¥10100 | 利润: ¥4700
```

### 2.3 zip 的截断行为

zip 的一个关键行为是：**以输入中最短的可迭代对象为准，当最短的那个耗尽时就停止，更长对象中多余的元素被丢弃**。这个行为是默认的，且没有警告。

```python
# 截断行为的直观演示：三个列表长度不同
names = ["Alice", "Bob", "Charlie", "David", "Eve"]  # 5 个元素
scores = [88, 95, 73]                                  # 3 个元素
ranks = [1, 2, 3, 4]                                   # 4 个元素

result = list(zip(names, scores, ranks))
print(f"配对结果共 {len(result)} 组:")
for item in result:
    print(item)
# 输出：
# 配对结果共 3 组:
# ('Alice', 88, 1)
# ('Bob', 95, 2)
# ('Charlie', 73, 3)
```

运行结果说明：三个列表中 `scores` 最短（仅 3 个元素），因此 zip 只产生了 3 个元组。`names` 中的 "David" 和 "Eve"、`ranks` 中的 4 都被丢弃了，没有警告或报错。

这种截断行为在某些场景下正是你想要的（例如你确定较长的序列是多出的、不关心的尾部数据），但在另一些场景下可能是 bug 的源头。

**什么时候截断行为是安全的？**

当你确信序列等长或你只关心"对齐到最前部"时，截断是无害的。例如：

```python
# 安全截断：日期和股价数据，只取到有完整记录的日期
dates = ["2024-01-01", "2024-01-02", "2024-01-03", "2024-01-04"]
closing_prices = [178.0, 179.5, 177.8]   # 最新数据还没出全

# 只取出两者都有的记录
for date, price in zip(dates, closing_prices):
    print(f"{date}: ${price}")
# 输出：
# 2024-01-01: $178.0
# 2024-01-02: $179.5
# 2024-01-03: $177.8
# 2024-01-04 没有对应的股价数据，被自动排除
```

**什么时候截断行为是危险的？**

当数据本应等长但因 bug（如数据漏采集）导致不等长时，截断会默默地掩盖问题：

```python
# 危险场景：数据本来应该等长，但录入时少录了一条
employees = ["Alice", "Bob", "Charlie", "David"]
salaries = [8000, 9500, 7300]  # 本该有 4 条，漏了一条

# zip 不会报错，会直接跳过 David！
print("工资表（可能有遗漏）：")
for emp, sal in zip(employees, salaries):
    print(f"{emp}: ¥{sal}")
# 输出：
# Alice: ¥8000
# Bob: ¥9500
# Charlie: ¥7300
# 注意：David 没有被输出 —— 数据丢失了且没有任何提示
```

如果你希望在这种情况下被提醒，可以在 zip 之前手动检查长度是否相等：

```python
employees = ["Alice", "Bob", "Charlie", "David"]
salaries = [8000, 9500, 7300]

# 主动校验长度，防止数据静默丢失
if len(employees) != len(salaries):
    print(f"警告：员工数({len(employees)})与工资数({len(salaries)})不一致！")
else:
    for emp, sal in zip(employees, salaries):
        print(f"{emp}: ¥{sal}")
# 输出：
# 警告：员工数(4)与工资数(3)不一致！
```

### 2.4 对比：itertools.zip_longest——以最长的为准

如果 zip 默认的"取最短"行为不符合需求，标准库 `itertools.zip_longest` 提供了相反的策略：以最长的可迭代对象为准，短的用 `fillvalue` 填补空缺。

`itertools.zip_longest` 的函数签名：

```python
itertools.zip_longest(*iterables, fillvalue=None)
```

其中 `fillvalue` 参数指定用于填补缺失位置的默认值，默认为 `None`。

```python
import itertools

# zip 默认：取最短
names = ["Alice", "Bob", "Charlie"]
scores = [88, 95]
print("zip 默认截断:", list(zip(names, scores)))
# 输出：zip 默认截断: [('Alice', 88), ('Bob', 95)]

# zip_longest：取最长，短的用 fillvalue 补齐
print("zip_longest 补齐:", list(itertools.zip_longest(names, scores)))
# 输出：zip_longest 补齐: [('Alice', 88), ('Bob', 95), ('Charlie', None)]

# zip_longest 指定 fillvalue
print("zip_longest 指定填补:", list(itertools.zip_longest(names, scores, fillvalue="N/A")))
# 输出：zip_longest 指定填补: [('Alice', 88), ('Bob', 95), ('Charlie', 'N/A')]
```

当数据有缺失、需要显式标注"此处缺值"时，`zip_longest` 比 zip 更合适：

```python
import itertools

# 实际案例：多批次的考试成绩，部分批次缺考
batch_a = [88, 92, 76, 85]           # A 组 4 人
batch_b = [79, 94, 81]               # B 组 3 人（第 4 人缺考）
student_names = ["Alice", "Bob", "Charlie", "David"]

# 用 zip_longest 确保每个学生都有记录，缺考标记为 "-"
print("考试结果（缺考标记为 -）：")
for name, score_a, score_b in itertools.zip_longest(
    student_names, batch_a, batch_b, fillvalue="-"
):
    print(f"{name}: A={score_a}, B={score_b}")
# 输出：
# Alice: A=88, B=79
# Bob: A=92, B=94
# Charlie: A=76, B=81
# David: A=85, B=-
```

`zip_longest` 的 `fillvalue` 可以传入任意类型，包括自定义对象、字符串、数字，甚至可调用对象（不过传入的是值，不是工厂函数）：

```python
import itertools

# fillvalue 使用不同数据类型
keys = ["x", "y", "z"]
values = [10, 20]  # 缺一个

# 字符串填补
print(list(itertools.zip_longest(keys, values, fillvalue="missing")))
# 输出：[('x', 10), ('y', 20), ('z', 'missing')]

# 数字填补
print(list(itertools.zip_longest(keys, values, fillvalue=0)))
# 输出：[('x', 10), ('y', 20), ('z', 0)]

# 列表填补
print(list(itertools.zip_longest(keys, values, fillvalue=[])))
# 输出：[('x', 10), ('y', 20), ('z', [])]
```

**性能对比**：zip 是内置函数，C 语言实现，速度极快；`zip_longest` 是 Python 标准库函数，性能比 zip 略差。在性能敏感的循环中，如果确实需要"以最短为准"，应该优先使用 zip 而不是 `zip_longest` 加手动丢弃。

### 2.5 zip 返回迭代器对象（Python 3 vs Python 2）

这是从 Python 2 迁移到 Python 3 时影响最广的变更之一。

**Python 2 行为**：
- `zip()` 返回一个**列表**，包含所有配对的元组。
- 如果输入可迭代对象非常大，会消耗大量内存。
- 在 Python 2 中，如果想惰性配对，需要使用 `itertools.izip()`。

**Python 3 行为**：
- `zip()` 返回一个**迭代器**（`zip` 对象），仅在迭代到每个元素时才逐一生成元组。
- 内存占用固定，不随输入大小增长。
- `itertools.izip()` 被移除，直接使用 `zip()` 即可。

```python
# 验证 zip 对象类型
data_a = [1, 2, 3]
data_b = [4, 5, 6]

zipped = zip(data_a, data_b)

print(f"type(zipped) = {type(zipped)}")
# 输出：type(zipped) = <class 'zip'>

print(f"是否可直接迭代: {hasattr(zipped, '__next__')}")
# 输出：是否可直接迭代: True

print(f"是否有长度: ", end="")
try:
    print(len(zipped))
except TypeError as e:
    print(f"不支持 len() — {e}")
# 输出：不支持 len() — TypeError: object of type 'zip' has no len()
```

迭代器的重要特征之一是"一次性消费"——遍历后不能再次遍历：

```python
grades = [88, 92, 76]
ranks = [1, 2, 3]

zipped = zip(grades, ranks)

# 第一次遍历：正常输出
print("第一次遍历：")
for g, r in zipped:
    print(f"  grade={g}, rank={r}")
# 输出：
#   grade=88, rank=1
#   grade=92, rank=2
#   grade=76, rank=3

# 第二次遍历：没有输出了，因为迭代器已耗尽
print("第二次遍历：")
for g, r in zipped:
    print(f"  grade={g}, rank={r}")
# 输出：
# 第二次遍历：
# （没有任何输出）
```

这一特性在实际使用中容易踩坑。如果你需要多次使用 zip 的结果，应该先用 `list()` 将其转换为列表：

```python
grades = [88, 92, 76]
ranks = [1, 2, 3]

# 先转换成列表，可以多次遍历
zipped_list = list(zip(grades, ranks))
print(f"列表长度: {len(zipped_list)}")               # 输出：列表长度: 3
print(f"第一个元组: {zipped_list[0]}")                # 输出：第一个元组: (88, 1)
print(f"支持下标访问: {zipped_list[-1]}")              # 输出：支持下标访问: (76, 3)
print(f"支持切片: {zipped_list[1:]}")                  # 输出：支持切片: [(92, 1), (76, 3)]
```

### 2.6 消费 zip 对象的多种方式

zip 对象作为迭代器，可以用多种方式消费其内容：

**方式一：for 循环解包**

```python
cities = ["Beijing", "Shanghai", "Guangzhou"]
populations = [2154, 2487, 1868]  # 单位：万人

for city, pop in zip(cities, populations):
    print(f"{city}: {pop} 万人")
# 输出：
# Beijing: 2154 万人
# Shanghai: 2487 万人
# Guangzhou: 1868 万人
```

**方式二：list() 一次性转换为列表**

```python
letters = ["A", "B", "C", "D"]
numbers = [1, 2, 3, 4]

pairs = list(zip(letters, numbers))
print(pairs)
# 输出：[('A', 1), ('B', 2), ('C', 3), ('D', 4)]
```

**方式三：tuple() 转换为元组列表**

```python
keys = ["name", "age", "city"]
values = ["Alice", 25, "Beijing"]

pairs_tuple = tuple(zip(keys, values))
print(pairs_tuple)
# 输出：(('name', 'Alice'), ('age', 25), ('city', 'Beijing'))
```

**方式四：dict() 直接构建字典**

```python
keys = ["name", "age", "city"]
values = ["Alice", 25, "Beijing"]

info_dict = dict(zip(keys, values))
print(info_dict)
# 输出：{'name': 'Alice', 'age': 25, 'city': 'Beijing'}
```

**方式五：集合推导式 / 列表推导式**

```python
names = ["Alice", "Bob", "Charlie"]
ages = [25, 30, 22]

# 用列表推导式加工 zip 结果
info_list = [f"{name}（{age}岁）" for name, age in zip(names, ages)]
print(info_list)
# 输出：['Alice（25岁）', 'Bob（30岁）', 'Charlie（22岁）']

# 用集合推导式去重
score_a = [85, 92, 78, 92]
score_b = [90, 85, 78, 85]
unique_pairs = {pair for pair in zip(score_a, score_b)}
print(sorted(unique_pairs))
# 输出：[(78, 78), (85, 90), (92, 85)]
```

**方式六：* 解包赋值给多个变量**

```python
# 将 zip 结果解包到多个变量 —— 一行代码拆分多列
headers = ["Name", "Age", "Score"]
alice = ["Alice", 25, 88]
bob = ["Bob", 30, 95]

# 转置：将每人的字段列表转成每个字段的元组
name_col, age_col, score_col = zip(alice, bob)
print(f"名字列: {name_col}")    # 输出：名字列: ('Alice', 'Bob')
print(f"年龄列: {age_col}")     # 输出：年龄列: (25, 30)
print(f"分数列: {score_col}")   # 输出：分数列: (88, 95)
```

**方式七：next() 手动迭代**

```python
s1 = [1, 2, 3]
s2 = [10, 20, 30]

z = zip(s1, s2)
print(next(z))   # 输出：(1, 10)
print(next(z))   # 输出：(2, 20)
print(next(z))   # 输出：(3, 30)

# 再调一次会触发 StopIteration
try:
    next(z)
except StopIteration:
    print("迭代器已耗尽")
# 输出：迭代器已耗尽
```

### 2.7 zip(*iterable) —— 解压与转置

`zip` 的逆操作：将"配对后的列表"恢复成"多个独立的序列"。这个操作常被称为"unzip"。

语法上，通过在 zip 参数前加 `*` 实现解包：`zip(*list_of_tuples)`。

**基础原理：**

```python
# 假设我们有三个配对好的元组
pairs = [("Alice", 88), ("Bob", 95), ("Charlie", 73)]

# *pairs 相当于将三个元组作为三个独立参数传入
names, scores = zip(*pairs)

print(names)   # 输出：('Alice', 'Bob', 'Charlie')
print(scores)  # 输出：(88, 95, 73)
```

运行结果说明：`zip(*pairs)` 等价于 `zip(("Alice", 88), ("Bob", 95), ("Charlie", 73))`。zip 会将每个元组的第 0 个元素（Alice、Bob、Charlie）聚合成一个新的元组，将每个元组的第 1 个元素（88、95、73）聚合成另一个新元组——这就是"解压"的过程。

**转置矩阵——最经典的应用：**

```python
# 将矩阵的行列互换
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9],
]

# 转置：行变列，列变行
transposed = list(zip(*matrix))
print("转置结果:")
for row in transposed:
    print(row)
# 输出：
# (1, 4, 7)
# (2, 5, 8)
# (3, 6, 9)
```

运行结果说明：原始矩阵是 3x3，第一行是 [1,2,3]，第二行是 [4,5,6]，第三行是 [7,8,9]。`zip(*matrix)` 将三个行向量作为参数传入 zip，zip 取各行的第 0 个元素组成 (1,4,7)，取第 1 个元素组成 (2,5,8)，取第 2 个元素组成 (3,6,9)——完成了矩阵转置。

**非方阵的转置（zip 的截断行为再次体现）：**

```python
# 非方阵的转置
original = [
    [1, 2, 3],
    [4, 5, 6],
]
# 2 行 3 列的矩阵

transposed = list(zip(*original))
print("2x3 转置为 3x2:")
for row in transposed:
    print(row)
# 输出：
# (1, 4)
# (2, 5)
# (3, 6)
```

运行结果说明：原矩阵 2 行 3 列，转置后变为 3 行 2 列。注意结果中的元素是元组而非列表——这是 zip 的默认行为。

**解压后回收到原样：**

```python
pairs = [("Alice", 88), ("Bob", 95), ("Charlie", 73)]

# 解压
names, scores = zip(*pairs)

# 重新 zip 回去 —— 应该恢复原样
restored = list(zip(names, scores))
print(f"恢复后: {restored}")
print(f"与原样相同: {restored == pairs}")
# 输出：
# 恢复后: [('Alice', 88), ('Bob', 95), ('Charlie', 73)]
# 与原样相同: True
```

**解包到多余变量时需注意数量匹配：**

```python
data = [(1, 10, 100), (2, 20, 200), (3, 30, 300)]

# 解包时变量数量必须与每个元组的元素数一致
a, b, c = zip(*data)
print(a)  # 输出：(1, 2, 3)
print(b)  # 输出：(10, 20, 30)
print(c)  # 输出：(100, 200, 300)

# 变量数量过少会报错
try:
    a, b = zip(*data)
except ValueError as e:
    print(f"解包错误: {e}")
# 输出：解包错误: too many values to unpack (expected 2)
```

**foreach 循环中用 zip(*...) 实现列式处理：**

```python
# 将多行数据转成列，然后逐列处理
students_data = [
    ("Alice", 88, "A"),
    ("Bob", 95, "A+"),
    ("Charlie", 73, "B"),
    ("David", 67, "C+"),
]

# 解压获得三个独立的列
names, scores, grades = zip(*students_data)

print(f"平均分: {sum(scores) / len(scores):.1f}")
# 输出：平均分: 80.8
print(f"最高分: {max(scores)}")   # 输出：最高分: 95
print(f"最低分: {min(scores)}")   # 输出：最低分: 67
```

### 2.8 用 zip 创建字典

`dict(zip(keys, values))` 是从两个列表构建字典的最地道、最 Pythonic 的方式之一。

**基本用法：**

```python
# 最标准的键值对构造
fields = ["name", "age", "city", "job"]
values = ["Alice", 25, "Beijing", "Engineer"]

user = dict(zip(fields, values))
print(user)
# 输出：{'name': 'Alice', 'age': 25, 'city': 'Beijing', 'job': 'Engineer'}
```

**截断行为的影响：**

```python
# 键多值少时：多余键被丢弃
keys = ["a", "b", "c", "d"]
vals = [1, 2]
print(dict(zip(keys, vals)))
# 输出：{'a': 1, 'b': 2}
# "c" 和 "d" 被静默丢弃

# 值多键少时：多余值被丢弃
keys2 = ["x", "y"]
vals2 = [10, 20, 30, 40]
print(dict(zip(keys2, vals2)))
# 输出：{'x': 10, 'y': 20}
# 30 和 40 被静默丢弃
```

**配合 zip_longest 处理不等长键值：**

```python
from itertools import zip_longest

# 键多值少时，缺值的设为 None
keys = ["a", "b", "c", "d"]
vals = [1, 2]
print(dict(zip_longest(keys, vals)))
# 输出：{'a': 1, 'b': 2, 'c': None, 'd': None}

# 指定默认值
print(dict(zip_longest(keys, vals, fillvalue=0)))
# 输出：{'a': 1, 'b': 2, 'c': 0, 'd': 0}
```

**利用切片从多列数据构建多个字典：**

```python
# CSV 风格的数据：标题行 + 数据行
headers = ["name", "age", "city"]
row1 = ["Alice", 25, "Beijing"]
row2 = ["Bob", 30, "Shanghai"]
row3 = ["Charlie", 22, "Guangzhou"]

# 用 zip 和字典推导式构造列表
user_list = [dict(zip(headers, row)) for row in [row1, row2, row3]]
for user in user_list:
    print(user)
# 输出：
# {'name': 'Alice', 'age': 25, 'city': 'Beijing'}
# {'name': 'Bob', 'age': 30, 'city': 'Shanghai'}
# {'name': 'Charlie', 'age': 22, 'city': 'Guangzhou'}
```

**用 zip 反向构造字典 —— 交换键值：**

```python
original = {"Alice": 88, "Bob": 95, "Charlie": 73}

# 交换键值（需要值是可哈希的）
reversed_dict = dict(zip(original.values(), original.keys()))
print(reversed_dict)
# 输出：{88: 'Alice', 95: 'Bob', 73: 'Charlie'}
```

### 2.10 zip 与 enumerate 嵌套使用

`enumerate` 为序列元素添加序号，`zip` 将多个序列配对——两者结合使用可以同时获得"索引"和"多列数据"。

**基础嵌套模式：**

```python
# 同时获取序号和多列数据
names = ["Alice", "Bob", "Charlie"]
scores = [88, 95, 73]

print("排名榜：")
for rank, (name, score) in enumerate(zip(names, scores), start=1):
    print(f"  第{rank}名: {name} —— {score}分")
# 输出：
# 排名榜：
#   第1名: Alice —— 88分
#   第2名: Bob —— 95分
#   第3名: Charlie —— 73分
```

关键细节：`enumerate(zip(names, scores))` 中，外层是 enumerate，内层是 zip。这样 enumerate 返回的每个元素是 `(index, (name, score))` 形式的嵌套元组，因此需要用 `for rank, (name, score)` 的解包写法。

**另一种同等效果的写法：**

```python
names = ["Alice", "Bob", "Charlie"]
scores = [88, 95, 73]

# 也可以先处理 zip 再包 enumerate
for rank, pair in enumerate(zip(names, scores), start=1):
    name, score = pair  # 额外解包一行
    print(f"  第{rank}名: {name} —— {score}分")
```

**配合 sorted 实现按分数排序输出：**

```python
# 按分数降序排列并输出排名
names = ["Alice", "Bob", "Charlie", "David"]
scores = [88, 95, 73, 88]

# 先配对，再按分数排序
sorted_pairs = sorted(zip(names, scores), key=lambda x: x[1], reverse=True)

print("按分数排序：")
for rank, (name, score) in enumerate(sorted_pairs, start=1):
    print(f"  第{rank}名: {name} —— {score}分")
# 输出：
# 按分数排序：
#   第1名: Bob —— 95分
#   第2名: Alice —— 88分
#   第3名: David —— 88分
#   第4名: Charlie —— 73分
```

**复杂一点的三列数据加序号：**

```python
students = ["Alice", "Bob", "Charlie"]
subjects = ["Math", "English", "Science"]
grades = ["A", "B+", "A-"]

#   1. Alice | Math | A
```

### 2.11 不等长序列的处理策略

在实际数据处理中，序列等长是理想情况，不等长才是常态。下面系统地总结几种处理策略。

**策略一：使用 zip 默认截断（接受较短序列）**

适用于：你明确知道较长的序列尾部是无效的、无关的数据。

```python
# 场景：两个传感器不同步，只取二者都有读数的时间片段
sensor_a = [23.5, 24.1, 22.8, 23.9]           # 4 个读数
sensor_b = [120, 115, 118]                     # 3 个读数（最后一个故障缺失）

for a, b in zip(sensor_a, sensor_b):
    print(f"A={a}, B={b}")
# 输出：
# A=23.5, B=120
# A=24.1, B=115
# A=22.8, B=118
# sensor_a 的第 4 个读数 23.9 被丢弃
```

**策略二：使用 zip_longest 补全（接受缺值）**

适用于：需要保留所有记录，缺失值显式标注。

```python
from itertools import zip_longest

a = [1, 2, 3]
b = [10, 20]

# 默认补 None
for x, y in zip_longest(a, b):
    print(f"({x}, {y})")
# 输出：
# (1, 10)
# (2, 20)
# (3, None)

# 指定 fillvalue
for x, y in zip_longest(a, b, fillvalue=0):
    print(f"({x}, {y})")
# 输出：
# (1, 10)
# (2, 20)
# (3, 0)
```

**策略三：使用切片手动截断（对齐到较长序列中的指定范围）**

适用于：需要对齐到特定范围而不是简单取最短或最长。

```python
dates = ["2024-01-01", "2024-01-02", "2024-01-03", "2024-01-04", "2024-01-05"]
prices = [100, 102, 101]

# 只取最近 3 天的价格（取 dates 的后三个）
recent_dates = dates[-len(prices):]
print(list(zip(recent_dates, prices)))
# 输出：[('2024-01-03', 100), ('2024-01-04', 102), ('2024-01-05', 101)]
```

**策略四：使用 itertools.cycle 循环补齐短序列**

适用于：需要让短序列循环重复以匹配长序列的长度。

```python
from itertools import cycle

# 3 个工人轮班值守 7 天
workers = ["Alice", "Bob", "Charlie"]
days = ["周一", "周二", "周三", "周四", "周五", "周六", "周日"]

# cycle 会不断重复 workers 序列
roster = list(zip(days, cycle(workers)))
for day, worker in roster:
    print(f"{day}: {worker}")
# 输出：
# 周一: Alice
# 周二: Bob
# 周三: Charlie
# 周四: Alice
# 周五: Bob
# 周六: Charlie
# 周日: Alice
```

**策略五：自定义填充策略**

适用于：需要区分"因索引越界而缺失"和"实际值就是 None"的场景。

```python
from itertools import zip_longest

class Sentinel:
    """哨兵值，用于标识缺失数据"""
    def __repr__(self):
        return "<MISSING>"

MISSING = Sentinel()

list_a = [1, 2, 3]
list_b = [10]

# 使用自定义对象作为 fillvalue，避免与真实数据混淆
result = list(zip_longest(list_a, list_b, fillvalue=MISSING))
print(result)
# 输出：[(1, 10), (2, <MISSING>), (3, <MISSING>)]

# 可以安全地判断缺失
for x, y in result:
    if y is MISSING:
        print(f"{x} 没有对应的匹配值")
    else:
        print(f"{x} 匹配 {y}")
# 输出：
# 1 匹配 10
# 2 没有对应的匹配值
# 3 没有对应的匹配值
```

### 2.12 空序列的 zip 行为

zip 在遇到空序列时的行为有一些细节需要明确。

**传入一个空列表：**

```python
# 传入一个空列表
result = list(zip([]))
print(f"zip([]) = {result}")
# 输出：zip([]) = []
# 结果是一个空列表，因为空列表没有元素可以配对
```

**传入多个可迭代对象，其中一个是空的：**

```python
# 传入的空序列会导致立即停止
letters = ["A", "B", "C"]
empty_list = []
numbers = [1, 2, 3]

result = list(zip(letters, empty_list, numbers))
print(f"含空序列的 zip = {result}")
# 输出：含空序列的 zip = []
# 因为 empty_list 的第一轮就取完了，所以立即停止
```

**传入零个参数：**

```python
# 不传入任何可迭代对象
result = list(zip())
print(f"zip() = {result}")
# 输出：zip() = []
# 空 zip 返回一个空的迭代器
```

**zip_longest 与空序列：**

```python
from itertools import zip_longest

a = ["A", "B"]
b = []

result = list(zip_longest(a, b, fillvalue="<NONE>"))
print(f"zip_longest 含空序列: {result}")
# 输出：zip_longest 含空序列: [('A', '<NONE>'), ('B', '<NONE>')]
# zip_longest 会保留所有非空序列的元素，空序列的每个位置都用 fillvalue 填补
```

**空序列在 unzip 中的影响：**

```python
# 空列表解包
result = list(zip(*[]))
print(f"zip(*[]) = {result}")
# 输出：zip(*[]) = []
# 传入空列表被解包相当于没有参数，结果为空

# 包含空元组的列表
result = list(zip(*[()]))
print(f"zip(*[()]) = {result}")
# 输出：zip(*[()]) = []
# 所有元组都为空，解包后没有元素可取
```

### 2.13 zip 与不同类型可迭代对象的组合

zip 不仅仅适用于列表和元组，可以处理任何可迭代对象。

**与字符串搭配：**

```python
# 字符串也是可迭代对象，zip 会逐个迭代字符
names = ["Alice", "Bob", "Charlie"]
initials = "ABC"

for name, initial in zip(names, initials):
    print(f"{name} 的首字母是 {initial}")
# 输出：
# Alice 的首字母是 A
# Bob 的首字母是 B
# Charlie 的首字母是 C
```

**与 range 搭配：**

```python
# range 对象作为序号生成器
fruits = ["apple", "banana", "cherry", "date"]

# 从 1 开始编号
numbered = list(zip(range(1, len(fruits) + 1), fruits))
print(numbered)
# 输出：[(1, 'apple'), (2, 'banana'), (3, 'cherry'), (4, 'date')]
```

**与生成器表达式搭配：**

```python
# 生成器是惰性的，zip 同样能处理
def fibonacci(n):
    """生成斐波那契数列的前 n 项"""
    a, b = 0, 1
    for _ in range(n):
        yield a
        a, b = b, a + b

# 将自然数与斐波那契数配对
natural = range(1, 11)
fib = fibonacci(10)

for idx, fib_num in zip(natural, fib):
    print(f"第 {idx} 个斐波那契数: {fib_num}")
# 输出：
# 第 1 个斐波那契数: 0
# 第 2 个斐波那契数: 1
# 第 3 个斐波那契数: 1
# 第 4 个斐波那契数: 2
# 第 5 个斐波那契数: 3
# 第 6 个斐波那契数: 5
# 第 7 个斐波那契数: 8
# 第 8 个斐波那契数: 13
# 第 9 个斐波那契数: 21
# 第 10 个斐波那契数: 34
```

**与字典搭配（迭代键）：**

```python
# zip 字典时，默认迭代键
names_dict = {1: "Alice", 2: "Bob", 3: "Charlie"}
scores_dict = {1: 88, 2: 95, 3: 73}

# 默认取键
pairs = list(zip(names_dict, scores_dict))
print(f"zip(dict, dict) = {pairs}")
# 输出：zip(dict, dict) = [(1, 1), (2, 2), (3, 3)]

# 用 .values() 迭代值
pairs = list(zip(names_dict.values(), scores_dict.values()))
print(f"zip(values, values) = {pairs}")
# 输出：zip(values, values) = [('Alice', 88), ('Bob', 95), ('Charlie', 73)]

# 用 .items() 迭代键值对
pairs = list(zip(names_dict.items(), scores_dict.items()))
print(f"zip(items, items) = {pairs}")
# 输出：zip(items, items) = [((1, 'Alice'), (1, 88)), ((2, 'Bob'), (2, 95)), ((3, 'Charlie'), (3, 73))]
```

### 2.14 zip 的惰性求值与内存效率

Python 3 的 zip 返回的是迭代器，这是其内存效率的核心来源。

**惰性配对的工作原理：**

```python
# zip 不会一次性生成所有配对，而是逐个生成
import sys

large_a = range(10_000_000)  # 1000 万个数字
large_b = range(10_000_000)

# zip 对象占用的内存非常小
zipped = zip(large_a, large_b)
print(f"zip 对象大小: {sys.getsizeof(zipped)} 字节")
# 输出：zip 对象大小: 56 字节（具体数值可能因 Python 版本而异）
# 56 字节 vs 包含 1000 万元素的列表 —— 内存差异巨大

# 对比：如果强行转换成列表
try:
    big_list = list(zip(range(10_000_000), range(10_000_000)))
    print(f"列表大小: {sys.getsizeof(big_list)} 字节")
except MemoryError:
    print("内存不足！这就是惰性求值的意义。")
# 输出可能会有 MemoryError，或者占用数百 MB 内存
```

**为什么 zip 的内存效率高？**

zip 的内部实现类似以下逻辑（简化示意，实际是 C 语言实现）：

```python
def zip_simulated(*iterables):
    """模拟 zip 的内部惰性求值行为"""
    if not iterables:
        return

    # 将每个可迭代对象转成迭代器
    iterators = [iter(it) for it in iterables]

    try:
        while True:
            # 每次从每个迭代器取一个元素，组成元组
            # 任意一个耗尽则停止
            yield tuple(next(it) for it in iterators)
    except StopIteration:
        # 任一迭代器耗尽，就结束
        return
```

关键点：
- 每次调用 `next()` 只产生一个元组。
- 上次生成的元组在被引用时存在的内存中；不被引用时，可以被垃圾回收。
- 如果只需要前几个元组，后面的元素永远不会被计算或存储——这就是惰性求值的优势。

**for 循环中直接使用 zip 的内存优势：**

```python
# 推荐：直接 for 循环迭代 zip，内存效率高
ids = range(100_000)
names = (f"user_{i}" for i in range(100_000))  # 生成器

count = 0
for id_, name in zip(ids, names):
    # 每次只在内存中保留一个 id_name 元组
    count += 1
    if count >= 5:
        break
    print(f"ID: {id_}, Name: {name}")
# 输出：
# ID: 0, Name: user_0
# ID: 1, Name: user_1
# ID: 2, Name: user_2
# ID: 3, Name: user_3
# ID: 4, Name: user_4
# 只读取了前 5 个元素，后面近 10 万个元素从未生成
```

**不推荐：过早将 zip 的迭代器转成列表：**

```python
# 不推荐：将大量数据用 list() 消费
# 如果只配对少量数据或者必须多次遍历才需要转列表
large_a = range(1_000_000)
large_b = range(1_000_000)

# 这一行会生成 100 万个元组，占用大量内存

# 推荐：只在需要遍历的地方使用 zip
for a, b in zip(large_a, large_b):
    # 处理每一对
    pass  # 内存占用恒定
```

**哪些场景下必须消费为列表？**

```python

items_a = ["A1", "A2", "A3"]
items_b = ["B1", "B2", "B3"]
pairs_list = list(zip(items_a, items_b))

# 第一次遍历
for a, b in pairs_list:
    print(f"第一轮: {a}-{b}")
# 第二次遍历
for a, b in pairs_list:
    print(f"第二轮: {a}-{b}")

# 2. 需要随机访问

print(pairs_list[-1]) # ('A3', 'B3')
```

## 4. 原理

### 4.1 zip 的 C 语言实现机制

zip 是 Python 的内置函数，由 C 语言实现（位于 `Python/bltinmodule.c`）。其核心思路是：

1. 将传入的每个可迭代对象转换为独立的迭代器（`PyObject_GetIter`）。
2. 在一个无限循环中，每次从每个迭代器调用 `__next__` 获取一个元素。
3. 将获取到的元素组装成一个元组并 `yield` 出去。
4. 如果任意一个迭代器抛出 `StopIteration`，则整个 zip 停止。

核心伪代码（近似实现逻辑）：

```c
/* 这不是真实代码，而是简化示意 */
PyObject *zip_next(zipobject *lz) {
    Py_ssize_t tuplesize = lz->tuplesize;
    PyObject *result = PyTuple_New(tuplesize);

    for (i = 0; i < tuplesize; i++) {
        PyObject *item = PyIter_Next(lz->itervalues[i]);
        if (item == NULL) {
            Py_DECREF(result);
            return NULL;  /* 任意迭代器耗尽，停止 */
        }
        PyTuple_SET_ITEM(result, i, item);
    }
    return result;
}
```

关键点：
- 每次只生成一个元组，所有元组的大小在 zip 创建时就确定了（等于传入的可迭代对象数量）。
- 每个迭代器是独立推进的，意味着即使某个可迭代对象已经被消费完，其他迭代器仍然可能还在运行——但 zip 会立即停止。
- 迭代器本身不会自动倒回，所以 zip 对象一旦消费完就不能重用了。

### 4.2 zip 的迭代器协议

zip 对象实现了迭代器协议，即包含 `__iter__` 和 `__next__` 方法：

```python
z = zip([1, 2, 3], ['a', 'b', 'c'])

# __iter__ 返回自身（符合迭代器协议）
print(z is iter(z))            # 输出：True

# __next__ 返回下一个元素
print(z.__next__())            # 输出：(1, 'a')
print(z.__next__())            # 输出：(2, 'b')

# 兼容 next() 内置函数
print(next(z))                 # 输出：(3, 'c')

# 耗尽后抛出 StopIteration
try:
    next(z)
except StopIteration:
    print("迭代器已耗尽")
# 输出：迭代器已耗尽
```

这个协议是 Python 迭代器架构的基础——凡是实现了这两个方法的对象都可以用于 `for` 循环。
`zip` 的迭代器协议实现是线程安全的吗？并非完全线程安全。在多个线程中同时迭代同一个 zip 对象是未定义行为，需要外部同步。

### 4.3 惰性求值与内存模型

理解 zip 的惰性求值，关键在于区分"迭代器"和"可迭代对象"。

**迭代器 vs 可迭代对象**：

```python
# 可迭代对象：可以是列表、元组、字符串等
numbers = [1, 2, 3, 4, 5]  # 这是一个可迭代对象，不是迭代器

# zip 创建时不会从可迭代对象中取出任何元素
z = zip(numbers, "abcde")

# 只有当迭代发生时，zip 才从 numbers 和 "abcde" 中逐一取出元素
first = next(z)  # 此时才从 numbers 取 1，从 "abcde" 取 'a'
print(first)     # 输出：(1, 'a')
```

**内存占用示意图**：

```
zip([1,2,3,4,5], "abcde")
  ├── 创建时：存储两个迭代器引用，不存储数据
  │   └── 内存占用：约 56 字节（与数据量无关）
  ├── 第一次 next：生成元组 (1, 'a')，占用约 56 字节
  ├── 第二次 next：生成元组 (2, 'b')，前一个元组可被回收
  └── ...以此类推
```

这就意味着，在遍历 1000 万对元素时，zip 在任何时刻的内存占用都是 `O(1)` 级别（固定开销 + 一个正在处理的元组），而转换成列表后的内存占用是 `O(n)` 级别。

**为何 Python 3 改为返回迭代器？**

Python 2 中 zip 返回列表，大部分使用场景只需要遍历一次，返回列表会无端消耗大量内存。以下是 Python 2 时代的经验：

```python
# Python 2 中的糟糕体验
# data_a 和 data_b 各有 1000 万个元素
# pairs = zip(data_a, data_b)  # 立即生成 1000 万元素元组列表，占用数百 MB 内存
```

因此 Python 3 把 zip 改为惰性的，同时移除了 `itertools.izip()`，将所有 zip 使用统一为惰性版本。如果需要完整列表，用户调用 `list(zip(...))` 显式消费。

### 4.4 zip_longest 与 fillvalue 的实现原理

`zip_longest` 与 zip 的核心区别在于：zip 在遇到任意迭代器耗尽时立即停止，而 `zip_longest` 在遇到所有迭代器都耗尽时才停止。

```python
from itertools import zip_longest

# zip_longest 的内部逻辑（简化示意）
def zip_longest_simulated(*args, fillvalue=None):
    iterators = [iter(it) for it in args]
    active = len(iterators)

    if active == 0:
        return

    while True:
        values = []
        for it in iterators:
            try:
                values.append(next(it))
            except StopIteration:
                # 该迭代器已耗尽，用 fillvalue 替代
                values.append(fillvalue)
                # 但需要继续跟踪：是否所有迭代器都耗尽了？
                # 实际实现通过 "哨兵" 机制更复杂

        # 真正判断是否该结束，要检查是否所有迭代器都已耗尽
        # 且当前轮次的所有元素都来自 fillvalue
        yield tuple(values)
```

### 4.5 zip(*x) 转置的数学本质

`zip(*matrix)` 完成的是矩阵转置操作，其本质是线性代数中的行列互换。从实现角度：

1. `*matrix` 将矩阵的各行解包为独立参数。
2. zip 接受这些参数后，将每行的第 i 个元素聚合成第 i 行。

以数学语言描述：

- 输入矩阵 M，M[i][j] 表示第 i 行第 j 列的元素。
- `zip(*M)` 生成的元组序列中，第 i 个元组的第 j 个元素是 M[j][i]。
- 即新矩阵 T 中，T[i][j] = M[j][i]。

这就是标准的矩阵转置定义。由于 zip 以最短行为准，当矩阵各行长度不一致时，结果会截断到最短行的长度。

本文系统性地介绍了 Python 内置函数 `zip` 的全部用法与相关概念。以下是核心要点：

**基础用法**
- `zip(iterable1, iterable2)` 将两个可迭代对象中对应位置的元素配对为元组。
- `zip(iterable1, iterable2, iterable3)` 支持任意多个可迭代对象，生成的元组元素数等于输入参数个数。
- zip 以输入中最短的可迭代对象为准，超出部分自动截断丢弃。

**重要特性**
- Python 3 中 zip 返回的是迭代器（`zip` 对象），不是在 Python 2 中的列表——这是最重要的不兼容变更。
- 迭代器是**惰性求值**的，只在迭代时才逐一生成元组，内存效率极高。
- 迭代器是**一次性消费**的，遍历后不能再次使用，需要多次使用时要先调用 `list()` 转换为列表。
- 可以通过 `list()`、`tuple()`、`dict()`、`set()`、`next()`、`for` 循环等多种方式消费 zip 对象。

**进阶用法**
- `zip(*iterable)` 实现解压/转置，将"配对后的元组列表"还原为"多个独立的元组"。
- `dict(zip(keys, values))` 是从两个列表构建字典的最 Pythonic 的方式。
- 配合 `enumerate` 实现"索引 + 多列数据"的同时遍历：`enumerate(zip(a, b))`。
- `for (idx, (a, b))` 这种嵌套解包是标准写法。

**不等长序列处理**
- 默认截断：使用 zip 自身的截断行为，适用于接受较短序列的场景。
- 补齐缺失：使用 `itertools.zip_longest(*iterables, fillvalue=None)`，以最长的为准。
- 循环补充：使用 `itertools.cycle` 配合 zip 实现周期性补齐。
- 自定义填充：使用哨兵对象作为 fillvalue，区分"缺失"与"值为 None"。

**最佳实践要点**
- 优先使用 zip 而非下标索引（`range(len(...))`）访问对应位置元素。
- 使用 `enumerate(zip(...))` 而非手动维护计数器。
- 数据本应等长时，应在 zip 之前校验长度，防止静默丢失数据。
- 不需要早消费 zip 对象，只在需要多次遍历或随机访问时才转列表。
- 解包变量数量必须与元组元素数一致，否则会抛出 ValueError。

**读完本文你应能掌握**
- 熟练使用 `zip()` 对任意多个可迭代对象进行并行遍历。
- 明确区分 zip 的截断行为与 `zip_longest` 的补齐行为，并能根据业务场景正确选用。
- 能够用 `dict(zip(keys, values))` 一行代码构建字典。
- 能够用 `zip(*data)` 实现数据的解压和矩阵转置。
- 理解 zip 返回迭代器的内存优势与"一次性消费"的局限，并正确处理。
- 在实际编码中，能够在需要"多序列按位置对齐"时自然而然地选择 zip，而非手动管理下标。
