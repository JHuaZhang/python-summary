# 运算符与表达式概述与基本概念

## 1. 介绍

### 1.1 什么是运算符与表达式

如果你写过哪怕一行 Python 代码，几乎可以肯定你已经用过运算符和表达式了。`3 + 5` 里的 `+` 是运算符，整个 `3 + 5` 是一个表达式，它会被求值成 `8`。这组概念就像写文章时的"动词"和"短语"——运算符是决定"做什么动作"的符号，表达式是由操作数和运算符组合成、能算出一个值的代码片段。

在 Python 中，运算符和表达式处于"语法层"：它们不是某个具体的函数或类，而是一套贯穿所有数据类型的书写规则。理解运算符和表达式，本质上是理解 Python 是如何把一段"看起来像数学公式"的文字转换成一个具体结果的。

### 1.2 最简示例

先用一个最小的例子，让你一眼看到运算符和表达式"长什么样"：

```python
price = 19.9
quantity = 3
total = price * quantity
print(total)
```

运行结果：

```text
59.7
```

这里的 `*` 是运算符，`price` 和 `quantity` 是操作数，`price * quantity` 是一个表达式，它求值成 `59.7`，再通过 `=` 赋值给 `total`。短短一行代码，运算符、操作数、表达式、赋值四个概念全都登场了。

---

## 2. 核心内容

### 2.1 运算符：决定"怎么算"的符号

运算符（operator）是一种特殊的符号或关键字，它告诉 Python 对操作数执行什么操作。你可以把它理解成"动词"：它本身不持有一个值，而是规定了"拿这些操作数来做什么"。

**类比**：运算符就像厨房里的各种刀具。同样一块食材（操作数），交给菜刀会切成丝，交给刨子会削成片，交给压蒜器会压成蒜泥。决定"加工成什么形态"的不是食材，而是你选用的那把工具——运算符就是这套工具。

Python 的运算符大致有两类外观：

- **符号型运算符**：用标点符号表示，比如 `+`、`-`、`*`、`==`、`in`、`&`、`<<`。
- **关键字型运算符**：用英文单词表示，比如 `and`、`or`、`not`、`is`、`in`。

两者没有本质区别，只是写法不同。下面这段代码用两种外观做了同样的事——逻辑判断：

```python
# 符号视角对比：and / or / not 是关键字型运算符
print(3 > 2 and 5 > 1)
print(not False)
```

运行结果：

```text
True
True
```

需要特别说明：Python 里像 `if`、`for`、`def` 这类**关键字是控制结构的引导词，不是运算符**。区别在于：运算符会"算出一个值"（表达式有值），而 `if`/`for` 只是组织代码流程的语句骨架，本身不产出一个值。

### 2.2 表达式：可以求值的代码片段

表达式（expression）是 Python 中"能算出一个值"的代码片段。它由操作数和运算符组合而成，最终会被解释器求值成一个具体的结果。

**类比**：表达式就像数学里的算式。`2 + 3` 是一个算式，它"等于"5；`x * y` 也是一个算式，当 `x` 和 `y` 有具体值时，它也等于某个确定的数。表达式最重要的特征就是"有值"——任何能出现在赋值号右边、或能被 `print` 直接打印的东西，通常都是表达式。

下面这些都是合法的表达式：

```python
42              # 单个字面量也是表达式，求值为它自身
price           # 单个变量也是表达式，求值为它指向的值
3 + 5           # 算术表达式，求值为 8
a > b           # 比较表达式，求值为 True 或 False
"a" + "b"       # 字符串表达式，求值为 "ab"
len("hello")    # 函数调用也是表达式，求值为函数的返回值
```

表达式可以嵌套——内层表达式先求值，结果再作为外层表达式的操作数：

```python
result = (3 + 5) * 2
# 先算 3+5 得 8，再把 8 作为外层操作数，算 8*2 得 16
print(result)
```

运行结果：

```text
16
```

**表达式 vs 语句的区别**：表达式"有值"，语句"做事但本身没有值"。`x = 10` 是赋值语句，它把 10 绑定到名字 `x`，但整个赋值动作本身在 Python 中没有返回值。而 `x + 10` 是表达式，它有值。判断方法很简单：能不能把它塞进 `print()` 里而不报错？能的就是表达式。

```python
# 表达式可以直接打印
print(10 + 5)      # 输出 15

# 赋值语句不能当表达式用
# print(x = 10)    # 报错：x = 10 是语句，没有值
```

### 2.3 运算符与表达式的关系

运算符是表达式的"零件"，表达式是运算符的"成品"。两者是"积木"和"搭好的造型"的关系：运算符单独没有意义，必须配合操作数组成表达式才能运行；而表达式至少要由操作数构成，运算符则可有可无（单个字面量也是表达式）。

它们之间的组成关系可以这样表示：

```text
表达式(Expression)
  ├── 操作数(Operand)
  │     ├── 字面量：42、"hi"、True
  │     ├── 变量：price、name
  │     └── 子表达式：(3 + 5)
  └── 运算符(Operator)  ← 决定操作数如何被处理
        例如：+、-、*、and、in
```

一个完整的"算出结果"的过程，就是：解释器读取表达式 → 找出里面的运算符 → 按规则对操作数执行运算 → 产出一个值。运算符是这套生产线的"工序指令"，表达式是"待加工的整体"。

用一句话总结它们的关系：**运算符是动词，操作数是名词，表达式是"名词+动词"组成的短语，而求值过程就是把这个短语翻译成一个具体的词**。

### 2.4 操作数与目数（arity）

#### 2.4.1 什么是操作数

操作数（operand）是参与运算的值或变量。在 `3 + 5` 中，`3` 和 `5` 就是操作数；在 `price * quantity` 中，`price` 和 `quantity` 是操作数。操作数可以是字面量、变量，也可以是另一个嵌套的表达式——因为子表达式求值后也是一个值，自然可以充当操作数。

#### 2.4.2 目数：运算符吃几个操作数

运算符看"吃几个操作数"分成单目、双目、三目三种，这就是目数（arity）的概念，也是理解运算符形态的基础。

| 目数 | 别名 | 操作数个数 | 典型运算符 | 示例 |
|------|------|-----------|-----------|------|
| 单目 | 一元 | 1 个 | `-`、`~`、`not` | `-5`、`~6`、`not True` |
| 双目 | 二元 | 2 个 | `+`、`*`、`==`、`and`、`in` | `a + b`、`x in y` |
| 三目 | 三元 | 3 个 | 条件表达式 `值A if 条件 else 值B` | `大` if x>0 else 小` |

绝大多数运算符是双目的，这也是为什么你直觉上总觉得"运算符夹在两个东西中间"。单目运算符要么"前置"（写在操作数前面，如 `-5`），要么"后置"。Python 里的三目运算符只有一个，就是条件表达式，它用 `if`/`else` 关键字把三个操作数串起来。

```python
# 单目：1 个操作数
n = 5
print(-n)        # -5，负号
print(not True)  # False，逻辑非

# 双目：2 个操作数
print(10 + 3)    # 13
print(5 in [1, 3, 5])  # True，成员判断

# 三目：3 个操作数（条件表达式）
age = 20
label = "成年" if age >= 18 else "未成年"
print(label)     # 成年
```

运行结果：

```text
-5
False
13
True
成年
```

### 2.5 Python 运算符的七大类总览

Python 把运算符按"做什么样的事"分成了七大类，加上条件表达式和海象运算符这两个较特殊的写法。这一节给你一个全景，建立"有哪些运算符"的整体认知。每一类的完整规则都有专门主题展开，这里你只需要记住"分类的依据和每类的大致职责"。

七大类的分类层级关系如下：

```text
Python 运算符
├── 算术运算符        → 数值计算（+、-、*、/、//、%、**）
├── 赋值运算符        → 把值绑定给变量（=、+=、-= …）
├── 比较运算符        → 比较两个值的大小/相等（==、!=、<、> …）
├── 逻辑运算符        → 布尔逻辑运算（and、or、not）
├── 位运算符          → 按二进制位操作（&、|、^、~、<<、>>）
├── 成员运算符        → 判断元素是否属于容器（in、not in）
└── 身份运算符        → 判断两个对象是否是同一个（is、is not）

特殊写法：
├── 条件表达式（三元）→ 值A if 条件 else 值B
└── 海象运算符        → := 赋值并返回，用在表达式里
```

下面这张表把每一类的"职责、典型运算符、产出的值类型"集中对比：

| 类别 | 解决什么问题 | 典型运算符 | 结果类型 |
|------|------------|-----------|---------|
| 算术运算符 | 做数值计算 | `+` `-` `*` `/` `//` `%` `**` | 数字（int/float） |
| 赋值运算符 | 把计算结果绑定到变量 | `=` `+=` `-=` `*=` … | 无返回值（语句） |
| 比较运算符 | 判断两个值的关系 | `==` `!=` `<` `>` `<=` `>=` | bool |
| 逻辑运算符 | 组合多个条件 | `and` `or` `not` | bool（或操作数本身） |
| 位运算符 | 按二进制位运算 | `&` `\|` `^` `~` `<<` `>>` | int |
| 成员运算符 | 判断元素是否在容器里 | `in` `not in` | bool |
| 身份运算符 | 判断两个对象是否同一 | `is` `is not` | bool |

需要留意赋值运算符这一行：它是七大类里唯一"结果没有返回值"的——其余六类都产出值（是表达式），而赋值是语句。这点会直接影响 2.6 节里"什么能当表达式用"的判断。

最简示例，每类各看一眼：

```python
# 算术
print(7 / 3, 7 // 3, 7 % 3)        # 2.333 2 1

# 赋值（复合赋值）
x = 10
x += 5
print(x)                            # 15

# 比较
print(3 == 3.0, "a" < "b")          # True True

# 逻辑（短路）
print(0 or "default")               # default

# 位运算
print(12 & 10, 12 | 10, 1 << 4)     # 8 14 16

# 成员
print(20 in [10, 20, 30])           # True

# 身份
a = [1, 2]
b = a
print(a is b, a is [1, 2])          # True False
```

运行结果：

```text
2.3333333333333335 2 1
15
True True
default
8 14 16
True
True False
```

### 2.6 表达式的求值：优先级与结合性

当一行表达式里出现多个运算符时，Python 必须决定"先算谁、后算谁"。这套规则由两个概念决定：**优先级**回答"不同运算符谁先算"，**结合性**回答"相同优先级的运算符从哪边往哪边算"。

#### 2.6.1 优先级：先算谁

优先级（precedence）类似数学里"先乘除、后加减"的规则。在 `2 + 3 * 4` 中，`*` 优先级高于 `+`，所以先算 `3*4=12`，再算 `2+12=14`。

```python
print(2 + 3 * 4)      # 14，先乘后加
print((2 + 3) * 4)    # 20，括号强制先算 2+3
```

运行结果：

```text
14
20
```

括号是改变优先级最直接的手段——不管原优先级多低，括号里的内容一定先算。所以写复杂表达式时，如果担心优先级记不清，直接加括号既安全又提升可读性。

下面是常见运算符的优先级，从高到低排列（高优先级先算）：

| 优先级 | 运算符类别 | 说明 |
|--------|-----------|------|
| 高 | `**`（幂） | 幂运算优先级很高 |
| ↓ | `+x` `-x` `~x`（单目正负、取反） | 单目运算符 |
| ↓ | `*` `/` `//` `%` | 乘除、取整除、取余 |
| ↓ | `+` `-` | 加减 |
| ↓ | `<<` `>>` | 位移 |
| ↓ | `&` `^` `\|` | 位运算 |
| ↓ | `==` `!=` `<` `>` `<=` `>=` `is` `in` | 比较与身份、成员 |
| ↓ | `not` `and` `or` | 逻辑 |
| 低 | `=` `+=` …（赋值） | 赋值优先级最低 |

记忆不必死记整张表，记住几条关键规律就够用：**幂运算最高、赋值最低、算术高于比较、比较高于逻辑**。吃不准的时候加括号。

#### 2.6.2 结合性：同优先级往哪边算

当一行里出现多个同优先级的运算符时，结合性（associativity）决定方向。Python 绝大多数运算符是**从左到右**结合的，只有幂运算 `**` 是**从右到左**结合。

```python
# 从左到右：先算 20-5=15，再算 15-3=12
print(20 - 5 - 3)      # 12

# 幂运算从右到左：先算 3**2=9，再算 2**9=512
print(2 ** 3 ** 2)     # 512
```

运行结果：

```text
12
512
```

理解结合性很重要，因为它影响结果。`20 - 5 - 3` 如果从右到左算就会变成 `20 - (5-3) = 18`，和正确结果 `12` 完全不同。所以遇到同优先级连写时，要记得默认是从左到右，幂运算是唯一的例外。

#### 2.6.3 链式比较：Python 的特色写法

Python 允许把比较运算符"链"起来写，这在其他很多语言里是不允许的。`60 <= score <= 100` 会被 Python 自动理解为 `60 <= score and score <= 100`，而且 `score` 只会被求值一次。

```python
score = 75
print(60 <= score <= 100)   # True，等价于 60 <= 75 and 75 <= 100
```

运行结果：

```text
True
```

这种写法更接近数学直觉，也避免了 `score` 被重复计算，是 Python 在表达式语法上的一道便利。

### 2.7 运算符重载：同一符号的多面性

运算符重载（operator overloading）指的是：同一个运算符作用在不同类型的对象上，会表现出不同的行为。这是 Python 运算符体系里非常关键的一个特性——运算符不是写死的"数学动作"，而是"按对象类型调度的通用接口"。

**类比**：运算符重载就像"双关动词"。`run` 这个词，对运动员是"跑步"，对程序是"执行"，对水是"流淌"。`+` 这个符号，对数字是"加法"，对字符串是"拼接"，对列表是"合并"——同一个符号，含义随操作对象的类型而变。

```python
# + 对 int：加法
print(3 + 5)              # 8

# + 对 str：拼接
print("Py" + "thon")      # Python

# + 对 list：合并
print([1, 2] + [3, 4])    # [1, 2, 3, 4]

# * 对 int：乘法
print(3 * 4)              # 12

# * 对 str/list：重复
print("ab" * 3)           # ababab
print([0] * 3)            # [0, 0, 0]
```

运行结果：

```text
8
Python
[1, 2, 3, 4]
12
ababab
[0, 0, 0]
```

底层原理是：每个运算符背后都对应一类"魔术方法"（以双下划线命名的方法，如 `__add__`、`__mul__`、`__eq__`）。当你写 `a + b` 时，Python 实际上是在调用 `a.__add__(b)`。内置类型已经实现了这些方法，所以 `+` 对数字和字符串行为不同；自定义类也可以实现这些方法，让运算符支持自己的对象。

```python
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    # 重载 +：让两个向量相加
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    # 重载 ==：按坐标比较
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1 = Vector(1, 2)
v2 = Vector(3, 4)
print(v1 + v2)                 # Vector(4, 6)  + 被重载为向量加法
print(v1 + v2 == Vector(4, 6)) # True          == 被重载为坐标比较
```

运行结果：

```text
Vector(4, 6)
True
```

这里要先把"重载"和"带方法名的函数"分清：运算符重载走的是 `__add__` 这类魔术方法，由类型自己决定行为；而不是你可以随意给某个符号换规则。对普通使用者而言，记住一句话即可——**运算符的行为由操作对象的类型决定，`+` 不是天生加法，是"对象让它做什么它就做什么"**。

理解了重载，你也就理解了为什么 `==` 和 `is` 会在第 4 章产生那些区别：`==` 调用对象的 `__eq__` 比较"值"，`is` 不调用任何方法、直接比较"两个引用是否指向同一对象"。

### 2.8 一个核心区分：表达式有值，赋值语句无值

在进入实践示例前，有必要把"赋值不是表达式"这一点拎出来强调，因为它是初学者最常踩的坑之一。

判断一段代码是不是表达式，最简单的标准是"它有没有一个值"。赋值在 Python 中是语句，它没有值；算术、比较、函数调用这些都是表达式，它们有值。

```python
# 表达式有值，可以放进 print
print(10 + 5)               # 15
print(len("hello"))          # 5

# 赋值是语句，没有值，不能放进 print 当表达式
x = 10
# print(x = 10)              # 报错：赋值没有值
print(x)                     # 10，打印的是变量指向的值，这一行里 print(x) 是表达式语境
```

这条规则也解释了为什么复合赋值（`+=`、`-=`）要先算右侧表达式再赋值：右侧是表达式（有值），左侧是赋值目标，先求值右侧，再赋给左侧。

## 3. 实践示例

### 3.1 用一个购物结算场景串起各类运算符

光看概念容易浮在表面，用一个贴近现实的场景把各类运算符"串"起来，你会看到它们在真实代码里是如何协作的。设想一个购物车结算：算总价、打折扣、判断是否包邮、决定会员等级标签。

```python
# 购物车商品单价与数量
prices = [29.9, 45.0, 12.5]
quantities = [2, 1, 3]

# 1. 算术运算符：逐项算小计，再求总和
subtotal = sum(p * q for p, q in zip(prices, quantities))  # p*q 是表达式
print("小计:", subtotal)

# 2. 赋值 + 复合赋值：根据总额打折
discount = 0.0
if subtotal > 100:
    discount += 0.1          # 复合赋值，等价于 discount = discount + 0.1
total = subtotal * (1 - discount)
print("折扣后:", total)

# 3. 比较运算符：判断是否包邮
free_shipping = total >= 50
print("是否包邮:", free_shipping)

# 4. 逻辑运算符：会员且满额才送额外券
is_member = True
has_coupon = is_member and total > 100
print("是否送券:", has_coupon)

# 5. 成员运算符：某商品是否在购物车里
target = 45.0
in_cart = target in prices
print(f"商品 {target} 是否在购物车: {in_cart}")

# 6. 身份运算符：两个折扣配置是否同一对象
cfg_a = {"rate": 0.1}
cfg_b = cfg_a              # 指向同一对象
print("配置一致(身份):", cfg_a is cfg_b)

# 7. 三目运算符：根据会员级别打标签
level = "VIP" if is_member else "普通"
print("会员标签:", level)
```

这一段代码几乎用齐了七大类运算符中的关键成员。你看，每一类运算符都在"算一个具体的值"或"做一个判断"，最后整段程序就是把多个表达式按顺序求值、组合的结果。

### 3.2 从表达式到结果：手工拆解求值过程

理解表达式最好的办法，是手工拆解一行复杂表达式"怎么被一步步算出来的"。以判断"减掉 30 元后是否还没到满减门槛，且总额又没超过 200"为例：

```python
cart_total = 159.3
min_price = 130
need_more = (cart_total - 30) < min_price and not (cart_total >= 200)
print("是否需要凑单:", need_more)
```

运行结果：

```text
是否需要凑单: True
```

按优先级和结合性，这行表达式的求值过程拆解如下：

```text
原表达式：
  (cart_total - 30) < min_price and not (cart_total >= 200)

求值步骤：
  ① 先算括号里的子表达式：cart_total - 30 = 159.3 - 30 = 129.3
     → 129.3 < min_price and not (cart_total >= 200)
  ② 比较运算（优先级高于逻辑）：129.3 < min_price 即 129.3 < 130 → True
     → True and not (cart_total >= 200)
  ③ 继续算括号内：cart_total >= 200 即 159.3 >= 200 → False
     → True and not False
  ④ 逻辑非 not 优先于 and：not False → True
     → True and True
  ⑤ 逻辑与：True and True → True
  ⑥ 把求值结果 True 赋值给 need_more
  最终：need_more = True，与运行输出一致
```

从拆解过程能看出几个关键点：括号强制子表达式先算，决定了 `129.3` 这个中间值；比较运算符优先级高于逻辑运算符，所以两处比较在 `and` 之前就完成了；`not` 优先于 `and`，因此先算出 `not False`，再和左侧的 `True` 做与运算。每一步都遵循"先算谁"的优先级规则和"同优先级从左到右"的结合性规则。

一个实用经验是：**写复杂表达式时，自己手算一遍求值过程，再用真实运行验证一遍，两者对得上才算真正理解**。优先级、结合性、短路求值这些规则，记在脑子里是一回事，能用它们正确预测运行结果是另一回事。

再看一个对比写法，换一个会让结果为 `False` 的条件，体会"语义"如何影响最终判断：

```python
cart_total = 159.3
threshold = 100
need_more = (cart_total - 30) < threshold and not (cart_total >= 200)
print("是否需要凑单:", need_more)
```

运行结果：

```text
是否需要凑单: False
```

```text
对比拆解：
  ① cart_total - 30 = 159.3 - 30 = 129.3
  ② 129.3 < threshold 即 129.3 < 100 → False
  ③ cart_total >= 200 即 159.3 >= 200 → False
  ④ not False → True
  ⑤ False and True → False（and 两边需同时为真，左边是 False，整体即 False）
  最终：need_more = False
```

同样的表达式骨架，只是把 `min_price = 130` 换成 `threshold = 100`，结果就从 `True` 翻成 `False`。差别全在第②步的比较结果上：一次得到 `True`，另一次得到 `False`，随后 `and` 的判断也随之反转。这正说明"求值过程"才是理解表达式的正确视角——不必死记任何结果，只要能逐步走通求值，任何表达式都能预测出来。

## 4. 常见误区与边界

### 4.1 误区：`==` 和 `is` 是一回事

`==` 和 `is` 都会返回布尔值，看起来都像"判断相等"，但它们判断的东西完全不同：`==` 比较的是"值是否相等"（调用 `__eq__`），`is` 比较的是"两个引用是否指向同一个对象"（不调用任何方法）。

```python
a = [1, 2]
b = [1, 2]       # 值相等，但是不同的对象
print(a == b)    # True  值相等
print(a is b)    # False 是不同的对象

c = a            # c 和 a 指向同一个列表
print(a is c)    # True  同一对象
```

运行结果：

```text
True
False
True
```

**实用建议**：判断"两个东西内容是否一样"用 `==`，判断"两个变量是否是同一个对象"用 `is`。绝大多数业务判断用的是 `==`；`is` 常用于和单例对象做比较，比如 `x is None`。

### 4.2 误区：运算符总是产生新对象

不少人以为 `x += 1` 或 `list1 + list2` 一定产生新对象，但事实更微妙：对不可变类型（int、str、tuple），运算确实会创建新对象；对可变类型（如列表的 `+=`），则是在原对象上就地修改，不一定产生新对象。

```python
# 不可变类型：int 运算产生新对象
n = 100
m = n           # m 和 n 指向同一个 100
n += 1          # int 不可变，n 被重新绑定到新的 101
print(n is m)   # False，n 已指向新对象

# 可变类型：列表 += 就地修改
nums = [1, 2]
ref = nums
nums += [3]     # 列表 += 调用 __iadd__，就地扩展
print(nums is ref)   # True  仍是同一个对象
print(ref)            # [1, 2, 3]  ref 也"跟着变了"
```

运行结果：

```text
False
True
[1, 2, 3]
```

这个区别解释了为什么多个人同时引用一个列表时，有人"顺手 +="会让其他人手里的列表也变化——他们引用的是同一个对象，不是副本。

### 4.3 误区：所有符号都是运算符

并不是代码里出现的符号都叫运算符。下面这些"长得很像运算符"的符号，其实各自有别的身份：

| 符号 | 真实身份 | 说明 |
|------|---------|------|
| `=` | 赋值语句 | 是语句不是运算符，没有值 |
| `:` | 语句引导符 | 用于切片、字典、注解、代码块，不是运算符 |
| `->` | 函数返回注解 | 标注返回类型，不执行运算 |
| `@` | 装饰符 | 用在函数/类的装饰，matrix mult 运算符也用 @，看语境 |

```python
# = 是赋值语句
x = 5          # 这叫"赋值语句"，不叫"赋值运算表达式"

# : 在切片里是分隔符，不是运算符
nums = [0, 1, 2, 3, 4]
print(nums[1:3])   # [1, 2]，冒号分隔起止

# -> 是返回类型注解
def add(a: int, b: int) -> int:
    return a + b
print(add(2, 3))   # 5，-> int 只是标注，不参与运算
```

运行结果：

```text
[1, 2]
5
```

区分这些的意义在于：只有运算符才参与"求值"，才知道优先级和结合性；语句引导符不参与这套规则，强行按运算符去理解会走偏。

## 5. 总结

本文围绕运算符与表达式展开，主要介绍了以下内容：

- 运算符是决定操作数"怎么算"的符号或关键字，表达式是由操作数和运算符组成、能求出一个值的代码片段
- 运算符与表达式是"动词与短语"的关系：运算符单独无意义，必须配合操作数组成表达式才能运行
- 操作数有目数之分：单目（1 个）、双目（2 个）、三目（3 个，即条件表达式）
- Python 运算符分为七大类：算术、赋值、比较、逻辑、位、成员、身份，外加条件表达式和海象运算符两个特殊写法
- 表达式的求值由优先级和结合性决定，优先级回答"先算谁"，结合性回答"同优先级往哪边算"；赋值是语句而非表达式，没有返回值
- 运算符重载让同一符号对不同类型表现不同行为，底层依赖 `__add__`、`__eq__` 等魔术方法
- `==` 比较值、`is` 比较身份，不可变类型运算产新对象而可变类型可能就地修改，这些是初学时最易混淆的边界
