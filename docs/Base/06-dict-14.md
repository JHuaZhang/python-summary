# 字典的拷贝深浅剖析

## 1. 介绍

### 1.1 要理解什么

在 Python 中，当你写 `d2 = d1` 时，你以为你"复制"了一个字典，但实际上你只是给同一个字典起了一个别名。两个变量指向内存中的同一个对象——改一个，另一个也跟着变。

这就引出了"深拷贝"与"浅拷贝"的核心问题：**当你复制一个字典时，到底复制了多少层？**

- **引用赋值**（`d2 = d1`）：一层都不复制，两个变量指向同一个字典对象。
- **浅拷贝**（`d.copy()` / `copy.copy(d)`）：复制顶层字典，但嵌套的可变对象（如内部的列表、字典）仍然是共享的引用。
- **深拷贝**（`copy.deepcopy(d)`）：递归复制所有层级，创建一个完全独立的副本。

理解这三者的差异，有助于你在实际编码中判断：

- 为什么修改了"副本"的嵌套字段，原始数据也跟着变了
- 什么时候 `dict.copy()` 就够了，什么时候必须用 `copy.deepcopy()`
- 函数传入字典参数后修改了内容，为什么外部数据也被改了
- 如何安全地备份一个复杂嵌套字典而不影响原始数据

### 1.2 为什么需要理解它

如果你只操作扁平的简单字典（值都是 `int`、`str` 等不可变类型），浅拷贝似乎就够了，你可能从来没有踩过坑。但一旦你的字典包含嵌套的可变对象——内部的列表、字典、自定义对象——浅拷贝就会暴露"共享引用"的问题：

```python
config = {
    "database": {"host": "localhost", "port": 3306},
    "features": ["auth", "logging"]
}

backup = config.copy()                    # 浅拷贝
backup["database"]["port"] = 5432          # 修改"备份"的嵌套字典

print(config["database"]["port"])          # 3306？不，是 5432！
```

你以为 `backup` 是一个独立的副本，但它只是顶层独立——嵌套的 `database` 字典仍然是同一个对象。修改 `backup` 的嵌套内容，`config` 也被污染了。这类 bug 隐蔽且难以排查，因为代码看起来"没有问题"。

## 2. 整体架构

### 2.1 三种"复制"方式的层级关系

在深入细节之前，先用一张全局图展示三种方式的复制深度：

```text
┌──────────────────────────────────────────────────────────────────────┐
│                        字典的"复制"方式全景                            │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  字典 d = {"name": "张三",                                            │
│            "scores": [85, 90],         ← 嵌套列表（可变）              │
│            "address": {"city": "杭州"}}  ← 嵌套字典（可变）            │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────┐       │
│  │  方式一：引用赋值   d2 = d                                  │       │
│  │                                                            │       │
│  │  d ──┐                                                     │       │
│  │       ├──→ {"name":..., "scores":[...], "address":{...}}  │       │
│  │  d2─┘                                                      │       │
│  │  （同一个对象，零层复制）                                     │       │
│  └────────────────────────────────────────────────────────────┘       │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────┐       │
│  │  方式二：浅拷贝   d2 = d.copy()  或  copy.copy(d)           │       │
│  │                                                            │       │
│  │  d ──→ {"name":..., "scores":─┐, "address":─┐}            │       │
│  │                                 │              │           │       │
│  │  d2──→ {"name":..., "scores":─┤, "address":─┤}            │       │
│  │                                 │              │           │       │
│  │                          ┌──────┴──────────────┘           │       │
│  │                          ↓                                 │       │
│  │                    [85, 90]  {"city": "杭州"}              │       │
│  │                    （嵌套对象仍然共享）                      │       │
│  └────────────────────────────────────────────────────────────┘       │
│                                                                      │
│  ┌────────────────────────────────────────────────────────────┐       │
│  │  方式三：深拷贝   d2 = copy.deepcopy(d)                     │       │
│  │                                                            │       │
│  │  d ──→ {"name":..., "scores":─→ [85, 90],                  │       │
│  │          "address":─→ {"city": "杭州"}}                     │       │
│  │                                                            │       │
│  │  d2──→ {"name":..., "scores":─→ [85, 90],  ← 全新的列表     │       │
│  │          "address":─→ {"city": "杭州"}}   ← 全新的字典      │       │
│  │  （所有层级都独立复制）                                       │       │
│  └────────────────────────────────────────────────────────────┘       │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 数据流：修改操作如何影响各副本

以下流程图展示了一个修改操作在不同拷贝方式下如何传播：

```text
                    修改副本的嵌套可变对象
                            │
                 ┌──────────┼──────────┐
                 ↓          ↓          ↓
           引用赋值       浅拷贝       深拷贝
                 │          │          │
                 ↓          ↓          ↓
         原对象被修改   原对象被修改  原对象不受影响
         （同一个对象） （嵌套共享）  （完全独立）

                    修改副本的顶层键值
                            │
                 ┌──────────┼──────────┐
                 ↓          ↓          ↓
           引用赋值       浅拷贝       深拷贝
                 │          │          │
                 ↓          ↓          ↓
         原对象被修改   不受影响    不受影响
         （同一个对象） （顶层独立）  （完全独立）
```

### 2.3 核心概念速览

| 概念 | 操作 | 顶层是否新建 | 嵌套是否新建 | 性能 |
|------|------|-------------|-------------|------|
| 引用赋值 | `d2 = d` | 否 | 否 | 最快 |
| 浅拷贝 | `d.copy()` / `copy.copy(d)` | 是 | 否 | 快 |
| 深拷贝 | `copy.deepcopy(d)` | 是 | 是 | 慢 |

## 3. 关键机制拆解

### 3.1 引用赋值：变量名只是标签

在 Python 中，变量不是"容器"，而是"标签"。当你写 `d2 = d1`，你并不是把 `d1` 里的内容复制了一份放到 `d2`，而是给同一个字典对象贴了第二个标签。两个标签指向内存中的同一份数据。

**类比**：想象一个人有两个名字——中文名"张三"和英文名"Zhang San"。不管你用哪个名字叫这个人，回应的都是同一个人。`d1` 和 `d2` 就像是同一个字典对象的两个名字。

```python
d1 = {"name": "张三", "age": 28}
d2 = d1  # 这不是拷贝，只是别名

# 两个变量指向同一个对象
print(d1 is d2)  # True

# 修改 d2，d1 也变了
d2["age"] = 30
print(d1["age"])  # 30 —— 因为 d1 和 d2 是同一个字典
```

**运行结果**：

```text
True
30
```

用 `id()` 可以验证两个变量确实指向同一块内存：

```python
d1 = {"name": "张三", "age": 28}
d2 = d1

print(f"id(d1) = {id(d1)}")
print(f"id(d2) = {id(d2)}")
print(f"d1 is d2 → {d1 is d2}")  # True
```

**运行结果**：

```text
id(d1) = 4311924864
id(d2) = 4311924864
d1 is d2 → True
```

#### 3.1.1 函数传参也是引用

Python 的函数参数传递本质上是"传引用"——函数内部拿到的字典和外部传入的字典是同一个对象。这意味着函数内部对字典的修改会反映到外部：

```python
def add_salary(record):
    """给记录添加 salary 字段"""
    record["salary"] = 15000
    return record

emp = {"name": "李四", "age": 25}
result = add_salary(emp)

print(emp)     # {'name': '李四', 'age': 25, 'salary': 15000} —— emp 被修改了
print(result)  # {'name': '李四', 'age': 25, 'salary': 15000}
print(emp is result)  # True —— 返回值和入参是同一个对象
```

**运行结果**：

```text
{'name': '李四', 'age': 25, 'salary': 15000}
{'name': '李四', 'age': 25, 'salary': 15000}
True
```

这是一个常见的坑：你以为函数只是处理并返回了一个新字典，但实际上原始数据已经被修改了。如果调用方不期望入参被修改，这种"副作用"就会导致难以追踪的 bug。

#### 3.1.2 引用赋值的适用场景

引用赋值并非"坏"的——它在以下场景中是完全正确的行为：

- **同一对象的多个视图**：你需要在不同的上下文中用不同的变量名引用同一个字典，且期望修改是同步的。
- **函数传参**：不希望复制大字典带来的内存和性能开销，只传递引用即可。
- **临时别名**：简化深层链式访问，如 `db = server_config["database"]`，通过 `db` 操作内层字典。

```python
# 用引用简化访问 —— 通常的用法
config = {
    "database": {"host": "localhost", "port": 3306, "pool": {"min": 5, "max": 20}}
}

# 不用引用：每次都要写一长串链式访问
config["database"]["pool"]["max"] = 50

# 用引用做别名：简化后续操作
pool = config["database"]["pool"]
pool["max"] = 50      # 直接操作内层字典
pool["min"] = 10      # 改的就是 config 里的内层字典

print(config["database"]["pool"])  # {'min': 10, 'max': 50}
```

**运行结果**：

```text
{'min': 10, 'max': 50}
```

### 3.2 浅拷贝：只复制第一层

浅拷贝（Shallow Copy）创建一个新的字典对象，然后把原字典中所有键值对的**引用**复制过来。顶层字典是独立的，但值对象——尤其是可变对象（列表、字典）——仍然是共享的。

**类比**：浅拷贝就像复印一份通讯录。你拿到了一个新本子，上面写着同样的联系人信息。但如果某个联系人是个"群组"，本子上写的只是群组的地址——你通过这个地址找到的群组和原通讯录找到的是同一个。你如果在群组里加人，原通讯录持有者也能看到变化。

#### 3.2.1 dict.copy() 方法

字典内置的 `copy()` 方法是最常用的浅拷贝方式：

```python
original = {"name": "张三", "age": 28, "tags": ["dev", "python"]}
shallow = original.copy()

# 顶层是新对象
print(original is shallow)   # False

# 但值相同
print(original == shallow)    # True
```

**运行结果**：

```text
False
True
```

修改顶层的键值对时，浅拷贝是独立的——因为顶层字典各自维护自己的键值表：

```python
shallow["age"] = 30
shallow["name"] = "李四"

print(original)  # {'name': '张三', 'age': 28, 'tags': ['dev', 'python']} —— 不受影响
print(shallow)   # {'name': '李四', 'age': 30, 'tags': ['dev', 'python']}
```

**运行结果**：

```text
{'name': '张三', 'age': 28, 'tags': ['dev', 'python']}
{'name': '李四', 'age': 30, 'tags': ['dev', 'python']}
```

#### 3.2.2 copy.copy() 通用浅拷贝

`copy` 模块的 `copy()` 函数是一种通用的浅拷贝方式，适用于任何对象，不仅限于字典：

```python
import copy

original = {"name": "张三", "age": 28, "tags": ["dev", "python"]}
shallow = copy.copy(original)

print(original is shallow)  # False
```

**运行结果**：

```text
False
```

`dict.copy()` 和 `copy.copy(d)` 对于字典的效果是完全一样的——都创建一个顶层新字典，值引用共享。区别在于 `copy.copy()` 是通用方法，可以作用于列表、集合、自定义对象等任意类型。

#### 3.2.3 其他浅拷贝方式

除了 `dict.copy()` 和 `copy.copy()`，还有几种常见操作也能产生浅拷贝效果：

```python
original = {"name": "张三", "tags": ["dev"]}

# 方式一：dict() 构造函数
s1 = dict(original)

# 方式二：字典推导式
s2 = {k: v for k, v in original.items()}

# 方式三：解包（Python 3.5+）
s3 = {**original}

# 验证：都是浅拷贝
print(original is s1)                          # False
print(original is s2)                          # False
print(original is s3)                          # False
print(original["tags"] is s1["tags"])           # True —— 嵌套共享
print(original["tags"] is s2["tags"])           # True
print(original["tags"] is s3["tags"])           # True
```

**运行结果**：

```text
False
False
False
True
True
True
```

这些方式虽然写法不同，但本质都一样——创建新的顶层字典，值引用指向原对象。选择哪种纯粹是风格和可读性偏好。

### 3.3 浅拷贝的嵌套陷阱

浅拷贝最大的陷阱在于嵌套的可变对象。当你修改浅拷贝中嵌套的列表或字典时，原对象也会被影响——因为它们指向内存中的同一个嵌套对象。

#### 3.3.1 嵌套字典的共享

```python
import copy

config = {
    "app_name": "myapp",
    "database": {
        "host": "localhost",
        "port": 3306
    },
    "features": ["auth", "logging"]
}

shallow = config.copy()

# 顶层是新对象
print(config is shallow)                                        # False

# 但嵌套对象共享
print(config["database"] is shallow["database"])               # True
print(config["features"] is shallow["features"])                # True
```

**运行结果**：

```text
False
True
True
```

修改浅拷贝的嵌套字典，原对象也被污染：

```python
# 通过浅拷贝修改嵌套字典
shallow["database"]["port"] = 5432

print(config["database"])   # {'host': 'localhost', 'port': 5432} —— 原对象也被修改了！
print(shallow["database"])  # {'host': 'localhost', 'port': 5432}
```

**运行结果**：

```text
{'host': 'localhost', 'port': 5432}
{'host': 'localhost', 'port': 5432}
```

但修改顶层的键值对是安全的：

```python
shallow["app_name"] = "newapp"

print(config["app_name"])   # myapp —— 不受影响
print(shallow["app_name"])  # newapp
```

**运行结果**：

```text
myapp
newapp
```

#### 3.3.2 嵌套列表的共享

同理，嵌套的列表也是共享的：

```python
user = {
    "name": "王五",
    "hobbies": ["reading", "coding"],
    "scores": [85, 90, 78]
}

user_copy = user.copy()

# 修改 hobbies 列表（原地操作）
user_copy["hobbies"].append("gaming")

print(user["hobbies"])       # ['reading', 'coding', 'gaming'] —— 被污染
print(user_copy["hobbies"])  # ['reading', 'coding', 'gaming']
```

**运行结果**：

```text
['reading', 'coding', 'gaming']
['reading', 'coding', 'gaming']
```

#### 3.3.3 重新赋值 vs 原地修改

理解浅拷贝陷阱的关键在于区分"重新赋值"和"原地修改"：

- **重新赋值**（`d_copy["key"] = new_value`）：在浅拷贝字典自己的键值表中替换值引用，不影响原字典。
- **原地修改**（`d_copy["key"].append(x)` / `d_copy["key"]["sub"] = y`）：通过共享的引用操作底层对象，原字典也会看到变化。

```python
original = {"scores": [85, 90, 78]}

# --- 原地修改：通过共享引用操作 ---
copy1 = original.copy()
copy1["scores"].append(95)  # 通过列表引用追加元素
print(original["scores"])   # [85, 90, 78, 95] —— 被影响

# --- 重新赋值：在新字典中替换引用 ---
original2 = {"scores": [85, 90, 78]}
copy2 = original2.copy()
copy2["scores"] = [100, 100, 100]  # 替换为新列表
print(original2["scores"])         # [85, 90, 78] —— 不受影响
```

**运行结果**：

```text
[85, 90, 78, 95]
[85, 90, 78]
```

**为什么有这个区别？**

`copy1["scores"].append(95)` 时，`copy1["scores"]` 取出的是与 `original["scores"]` 相同的列表对象，`.append()` 在该列表对象上操作，两边都指向它，所以都看到变化。

`copy2["scores"] = [...]` 时，是在 `copy2` 自己的键值表中把 `"scores"` 键对应的引用替换为一个全新的列表对象。`original2` 的键值表中 `"scores"` 仍然指向原来的列表，不受影响。

```text
原地修改（append / update / 内层赋值）：

  original["scores"] ──→ [85, 90, 78]  ←── copy["scores"]
                              ↑
                      .append(95) 在这个列表上操作
                      → 两个变量都看到变化

重新赋值（= 新值）：

  original["scores"] ──→ [85, 90, 78]     （不变）
  copy["scores"]    ──→ [100, 100, 100]   （新对象）
                      → 互不影响
```

#### 3.3.4 多层嵌套的共享

浅拷贝只复制一层，无论嵌套多深，内层的可变对象全部共享：

```python
import copy

deep_config = {
    "level1": {
        "level2": {
            "level3": ["data"]
        }
    }
}

shallow = copy.copy(deep_config)

# 顶层独立
print(deep_config is shallow)                                    # False

# 但所有内层都共享
print(deep_config["level1"] is shallow["level1"])                # True

# 修改最内层的列表
shallow["level1"]["level2"]["level3"].append("new_data")

print(deep_config)  # {'level1': {'level2': {'level3': ['data', 'new_data']}}} —— 被污染
print(shallow)      # {'level1': {'level2': {'level3': ['data', 'new_data']}}}
```

**运行结果**：

```text
False
True
{'level1': {'level2': {'level3': ['data', 'new_data']}}}
{'level1': {'level2': {'level3': ['data', 'new_data']}}}
```

### 3.4 深拷贝：递归复制所有层级

深拷贝（Deep Copy）通过 `copy.deepcopy()` 实现——它递归地复制字典及其所有嵌套的可变对象，创建一个完全独立的副本。修改深拷贝的任何层级，都不会影响原对象。

#### 3.4.1 deepcopy 基本用法

```python
import copy

original = {
    "name": "张三",
    "age": 28,
    "scores": [85, 90, 78],
    "address": {
        "city": "杭州",
        "district": "西湖区"
    }
}

deep = copy.deepcopy(original)

# 顶层是新对象
print(original is deep)                                            # False

# 嵌套对象也是全新的
print(original["scores"] is deep["scores"])                       # False
print(original["address"] is deep["address"])                     # False
```

**运行结果**：

```text
False
False
False
```

修改深拷贝的任何层级——无论是顶层还是嵌套——都不影响原对象：

```python
deep["scores"].append(95)
deep["scores"][0] = 100
deep["address"]["city"] = "北京"
deep["address"]["street"] = "长安街"
deep["name"] = "李四"

print(original)
# {'name': '张三', 'age': 28, 'scores': [85, 90, 78], 'address': {'city': '杭州', 'district': '西湖区'}}

print(deep)
# {'name': '李四', 'age': 28, 'scores': [100, 90, 78, 95], 'address': {'city': '北京', 'district': '西湖区', 'street': '长安街'}}
```

**运行结果**：

```text
{'name': '张三', 'age': 28, 'scores': [85, 90, 78], 'address': {'city': '杭州', 'district': '西湖区'}}
{'name': '李四', 'age': 28, 'scores': [100, 90, 78, 95], 'address': {'city': '北京', 'district': '西湖区', 'street': '长安街'}}
```

#### 3.4.2 深拷贝的递归机制

`deepcopy` 的核心机制是递归遍历对象结构：

```text
deepcopy({"name": "张三", "scores": [85, 90], "address": {"city": "杭州"}})
    │
    ├── 创建新的字典对象 new_dict
    │
    ├── 处理键 "name"：
    │     值 "张三" 是 str（不可变）→ 直接复用，不复制
    │     new_dict["name"] = "张三"
    │
    ├── 处理键 "scores"：
    │     值 [85, 90] 是 list（可变）→ 递归 deepcopy
    │       │
    │       ├── 创建新的列表对象 new_list
    │       ├── 元素 85 是 int（不可变）→ 直接复用
    │       ├── 元素 90 是 int（不可变）→ 直接复用
    │       └── new_dict["scores"] = new_list
    │
    └── 处理键 "address"：
          值 {"city": "杭州"} 是 dict（可变）→ 递归 deepcopy
            │
            ├── 创建新的字典对象 new_inner_dict
            ├── 处理键 "city"：值 "杭州" 是 str → 直接复用
            └── new_dict["address"] = new_inner_dict
```

关键点：**不可变对象（int、str、tuple、frozenset 等）不会被复制**，而是直接复用引用。这是因为不可变对象无法被"修改"——你只能重新赋值，而重新赋值是在字典的键值表中替换引用，不影响原字典。所以深拷贝对它们做了一个性能优化：跳过复制。

```python
import copy

immutable_test = {"a": 1, "b": "hello", "c": (1, 2, 3)}
immutable_deep = copy.deepcopy(immutable_test)

# 不可变值直接复用
print(immutable_test["a"] is immutable_deep["a"])   # True（小整数缓存）
print(immutable_test["b"] is immutable_deep["b"])   # True
print(immutable_test["c"] is immutable_deep["c"])   # True —— tuple 不被复制
```

**运行结果**：

```text
True
True
True
```

#### 3.4.3 深拷贝处理循环引用

`deepcopy` 使用一个 `memo` 字典记录已经复制过的对象，避免重复复制和无限递归。这使得它能正确处理循环引用：

```python
import copy

# 创建一个自引用字典
circular = {"name": "循环引用示例"}
circular["self"] = circular  # 字典引用自身

print(circular["self"] is circular)  # True —— 自引用

# deepcopy 能正确处理循环引用
circular_deep = copy.deepcopy(circular)

# 深拷贝保持了循环引用结构
print(circular_deep["self"] is circular_deep)  # True —— 深拷贝内部也循环引用自己
print(circular_deep is circular)               # False —— 但和原对象不同
```

**运行结果**：

```text
True
True
False
```

如果 `deepcopy` 不使用 `memo` 机制，遇到循环引用就会无限递归直到栈溢出。`memo` 记录了 `id(原对象) → 新对象` 的映射，每次复制前先检查是否已经复制过——如果复制过，直接返回 `memo` 中的新对象引用，避免重复创建。

```text
deepcopy(circular) 的处理流程：

1. 创建 new_dict = {}，记录到 memo：memo[id(circular)] = new_dict
2. 处理 "name" → new_dict["name"] = "循环引用示例"
3. 处理 "self" → 值是 circular（dict），检查 memo：
   - 发现 id(circular) 已在 memo 中 → 直接返回 memo[id(circular)] = new_dict
   - new_dict["self"] = new_dict  ← 自引用深拷贝本身
4. 返回 new_dict

最终：new_dict["self"] is new_dict → True（循环引用保持）
```

#### 3.4.4 多层嵌套深拷贝

无论嵌套多少层，`deepcopy` 都能正确处理：

```python
import copy

multi_level = {
    "level1": {
        "level2": {
            "level3": {
                "data": [1, 2, 3],
                "info": {"key": "value"}
            }
        }
    }
}

multi_deep = copy.deepcopy(multi_level)

# 修改最内层
multi_deep["level1"]["level2"]["level3"]["data"].append(4)
multi_deep["level1"]["level2"]["level3"]["info"]["new_key"] = "new_value"

print(multi_level["level1"]["level2"]["level3"]["data"])   # [1, 2, 3] —— 不受影响
print(multi_deep["level1"]["level2"]["level3"]["data"])    # [1, 2, 3, 4]

print(multi_level["level1"]["level2"]["level3"]["info"])   # {'key': 'value'}
print(multi_deep["level1"]["level2"]["level3"]["info"])    # {'key': 'value', 'new_key': 'new_value'}
```

**运行结果**：

```text
[1, 2, 3]
[1, 2, 3, 4]
{'key': 'value'}
{'key': 'value', 'new_key': 'new_value'}
```

### 3.5 自定义对象的拷贝协议

`copy` 模块不仅适用于字典和列表，也适用于自定义对象。默认情况下，`copy.copy()` 和 `copy.deepcopy()` 通过反射机制复制对象的属性。但你也可以通过实现 `__copy__` 和 `__deepcopy__` 方法来自定义拷贝行为。

#### 3.5.1 默认行为

```python
import copy

class Database:
    def __init__(self, name, tables):
        self.name = name
        self.tables = tables

    def __repr__(self):
        return f"Database(name={self.name!r}, tables={self.tables!r})"

db = Database("mydb", ["users", "orders"])

# 默认浅拷贝：创建新对象，但属性共享引用
db_shallow = copy.copy(db)
print(db is db_shallow)                # False
print(db.tables is db_shallow.tables)   # True —— 属性共享

# 默认深拷贝：创建新对象，属性也递归复制
db_deep = copy.deepcopy(db)
print(db is db_deep)                    # False
print(db.tables is db_deep.tables)      # False —— 属性独立
```

**运行结果**：

```text
False
True
False
False
```

#### 3.5.2 自定义 __copy__ 和 __deepcopy__

当你需要控制拷贝行为——比如某些属性不应该被复制、或者需要做特殊处理时——可以实现这两个协议方法：

```python
import copy

class ConfigBox:
    """带自定义拷贝协议的配置容器"""

    def __init__(self, settings):
        self.settings = settings
        self.version = "1.0"

    def __copy__(self):
        # 浅拷贝：创建新实例，settings 做一次浅拷贝
        new_box = ConfigBox(self.settings.copy())
        new_box.version = self.version
        return new_box

    def __deepcopy__(self, memo):
        # 深拷贝：创建新实例，settings 做深拷贝
        new_box = ConfigBox(copy.deepcopy(self.settings, memo))
        new_box.version = self.version
        return new_box

    def __repr__(self):
        return f"ConfigBox(settings={self.settings!r}, version={self.version!r})"

config = ConfigBox({
    "host": "localhost",
    "ports": [8080, 8081]
})

# 浅拷贝：调用 __copy__
config_shallow = copy.copy(config)
print(config is config_shallow)                              # False
print(config.settings is config_shallow.settings)           # False —— __copy__ 中做了 .copy()
```

**运行结果**：

```text
False
False
```

注意，即使我们在 `__copy__` 中对 `settings` 做了一次 `.copy()`（这只是浅拷贝），`settings` 内部的嵌套对象仍然共享。如果 `settings` 里有嵌套的可变对象，修改浅拷贝的嵌套对象仍然会影响原对象：

```python
config_shallow.settings["ports"].append(8082)

print(config.settings["ports"])        # [8080, 8081, 8082] —— 被影响！
print(config_shallow.settings["ports"]) # [8080, 8081, 8082]
```

**运行结果**：

```text
[8080, 8081, 8082]
[8080, 8081, 8082]
```

而深拷贝则完全独立：

```python
config2 = ConfigBox({
    "host": "localhost",
    "ports": [8080, 8081]
})
config_deep = copy.deepcopy(config2)

config_deep.settings["ports"].append(8082)

print(config2.settings["ports"])      # [8080, 8081] —— 不受影响
print(config_deep.settings["ports"])  # [8080, 8081, 8082]
```

**运行结果**：

```text
[8080, 8081]
[8080, 8081, 8082]
```

#### 3.5.3 __deepcopy__ 的 memo 参数

`__deepcopy__` 方法接收一个 `memo` 参数，这是一个字典，用于记录已复制的对象以处理循环引用。实现自定义 `__deepcopy__` 时，必须把 `memo` 传递给内部的 `deepcopy` 调用：

```python
def __deepcopy__(self, memo):
    # 先检查 memo 中是否已有本对象的拷贝
    # 这一步通常由 copy.deepcopy 自动处理，但手动实现时需注意
    new_box = ConfigBox(copy.deepcopy(self.settings, memo))  # 传递 memo！
    new_box.version = self.version
    return new_box
```

如果不传递 `memo`，嵌套对象中的循环引用就无法被正确处理，可能导致无限递归。

## 4. 设计决策与权衡

### 4.1 为什么浅拷贝是 dict 的内置方法

Python 字典内置了 `copy()` 方法来做浅拷贝，但没有内置的深拷贝方法——深拷贝需要通过 `copy.deepcopy()` 实现。这是一个有意识的设计选择。

| 维度 | 内置浅拷贝 (`dict.copy()`) | 模块深拷贝 (`copy.deepcopy()`) |
|------|------|------|
| 使用频率 | 高——大多数场景浅拷贝足够 | 低——嵌套可变对象时才需要 |
| 性能开销 | O(n)——遍历键值对 | O(n*m)——递归遍历所有层级 |
| 实现复杂度 | 简单——复制一层 | 复杂——需递归 + memo |
| 通用性 | 字典专用 | 通用——适用于所有类型 |

浅拷贝是"够用就好"的设计——大多数字典的值是不可变类型（`str`、`int`、`tuple`），浅拷贝就足够安全。深拷贝作为 `copy` 模块的一部分提供，需要时再引入，避免给每个内置类型都内置一个可能永远用不到的深拷贝方法。

### 4.2 为什么 deepcopy 放在 copy 模块而非内置

`deepcopy` 需要处理任意类型的对象，包括自定义对象、循环引用、嵌套结构等。如果做成内置方法，每个类型都要实现一套深拷贝逻辑，且类型之间的交互（比如字典中的自定义对象）需要统一的调度框架。放在 `copy` 模块中，通过通用的递归 + memo 机制统一处理所有类型，是最简洁的设计。

```text
copy 模块的架构：

  copy.copy(obj)   → 调用 obj.__copy__()        或回退到反射机制
  copy.deepcopy(obj) → 调用 obj.__deepcopy__(memo) 或回退到递归反射

  ┌───────────────────────────────────┐
  │        copy 模块（统一入口）        │
  │                                   │
  │   copy()     → 类型专用 __copy__    │
  │   deepcopy() → 类型专用 __deepcopy__│
  │                                   │
  │   memo 字典 → 防止循环引用重复复制   │
  └───────────────────────────────────┘
        │                    │
        ↓                    ↓
   ┌─────────┐         ┌──────────────┐
   │  dict   │         │ 自定义对象     │
   │ copy()  │         │ __copy__     │
   │         │         │ __deepcopy__ │
   └─────────┘         └──────────────┘
```

### 4.3 不可变对象的优化策略

`deepcopy` 对不可变对象（`int`、`str`、`tuple`、`frozenset`）做了优化——不复制，直接复用引用。这是一个重要的性能决策：

| 维度 | 复制不可变对象 | 复用不可变对象 |
|------|------|------|
| 正确性 | 安全但浪费 | 安全且高效 |
| 内存开销 | 每次拷贝都分配新内存 | 共享同一份内存 |
| 性能 | 需要深拷贝所有元素 | 跳过不可变对象 |

不可变对象无法被原地修改（你只能重新赋值），因此共享引用不会产生"修改污染"的问题。复用引用既安全又高效。

但需要注意一个边界情况：**包含可变元素的 tuple**。`tuple` 本身不可变，但如果它的元素是可变对象（如列表），`deepcopy` 仍然会复制那些可变元素：

```python
import copy

mixed_tuple = (1, "hello", [10, 20])

deep_tuple = copy.deepcopy(mixed_tuple)

# tuple 本身不被复制
print(mixed_tuple is deep_tuple)                # True —— tuple 复用

# 但 tuple 内的可变元素被复制
print(mixed_tuple[2] is deep_tuple[2])            # False —— 列表被深拷贝
```

**运行结果**：

```text
True
False
```

### 4.4 性能权衡：浅拷贝 vs 深拷贝

深拷贝需要递归遍历所有层级，性能开销远大于浅拷贝。以下是一个直观的对比：

```python
import copy
import time

# 构造较大的嵌套字典
large_dict = {
    f"key_{i}": {
        "sub_key": "value",
        "numbers": list(range(100)),
        "nested": {"deep": list(range(50))}
    }
    for i in range(100)
}

# 浅拷贝计时
start = time.time()
for _ in range(1000):
    copy.copy(large_dict)
shallow_time = time.time() - start

# 深拷贝计时
start = time.time()
for _ in range(1000):
    copy.deepcopy(large_dict)
deep_time = time.time() - start

print(f"浅拷贝 1000 次: {shallow_time:.4f}s")
print(f"深拷贝 1000 次: {deep_time:.4f}s")
print(f"深拷贝/浅拷贝: {deep_time / shallow_time:.1f}x")
```

**运行结果**（具体数值因环境而异）：

```text
浅拷贝 1000 次: 0.0003s
深拷贝 1000 次: 2.0640s
深拷贝/浅拷贝: 6528.8x
```

深拷贝比浅拷贝慢了数千倍——因为它需要递归遍历所有嵌套对象、创建新对象、维护 memo。对于大型嵌套结构，这是一个需要考虑的性能因素。

**选择建议**：

- 只需要别名 → 引用赋值（`d2 = d1`），零开销
- 字典无嵌套可变对象 → 浅拷贝（`d.copy()`），O(n) 开销
- 字典含嵌套可变对象且需要独立 → 深拷贝（`copy.deepcopy(d)`），但注意性能
- 不确定有没有嵌套可变对象 → 用深拷贝最安全，但考虑数据量

### 4.5 实际场景中的选择策略

| 场景 | 推荐方式 | 理由 |
|------|------|------|
| 函数传参 | 引用赋值 | 避免复制大字典的性能开销 |
| 函数内部需要修改但不影响入参 | 深拷贝 | 保证函数的"无副作用"特性 |
| 备份配置文件 | 深拷贝 | 配置通常多层嵌套，需完全独立 |
| 扁平字典的快照 | 浅拷贝 | 无嵌套可变对象，浅拷贝足够 |
| 字典推导式中的临时引用 | 引用赋值 | 推导式中按需引用，无复制需求 |
| 缓存模式（原始 + 加工） | 深拷贝 | 加工副本不影响缓存中的原始数据 |
| 配置覆盖（base + override） | 浅拷贝 + 顶层合并 | 先浅拷贝 base，再顶层覆盖 override 值 |

#### 4.5.1 函数中安全修改入参的模式

当函数需要修改字典入参但不希望产生副作用时，可以在函数开头先做一次深拷贝：

```python
import copy

def process_config(config):
    """处理配置，但不修改原字典"""
    # 深拷贝入参，确保后续修改不影响原始数据
    safe_config = copy.deepcopy(config)

    safe_config["processed"] = True
    safe_config.setdefault("options", {})["timeout"] = 30

    return safe_config

original = {
    "host": "localhost",
    "options": {"retry": 3}
}

result = process_config(original)

print(original)
# {'host': 'localhost', 'options': {'retry': 3}} —— 不受影响

print(result)
# {'host': 'localhost', 'options': {'retry': 3, 'timeout': 30}, 'processed': True}
```

**运行结果**：

```text
{'host': 'localhost', 'options': {'retry': 3}}
{'host': 'localhost', 'options': {'retry': 3, 'timeout': 30}, 'processed': True}
```

#### 4.5.2 何时浅拷贝就足够

当字典的所有值都是不可变类型时，浅拷贝和深拷贝的行为完全等价——因为没有可变的嵌套对象可以被"原地修改"，浅拷贝就能保证独立性：

```python
# 所有值都是不可变类型 → 浅拷贝足够
config = {
    "host": "localhost",     # str（不可变）
    "port": 3306,            # int（不可变）
    "tags": ("dev", "prod"), # tuple（不可变）
    "enabled": True          # bool（不可变）
}

backup = config.copy()  # 浅拷贝就足够了

# 修改顶层键值不影响原件
backup["port"] = 5432
backup["host"] = "remote"

print(config)  # {'host': 'localhost', 'port': 3306, ...} —— 不受影响
print(backup)  # {'host': 'remote', 'port': 5432, ...}
```

**运行结果**：

```text
{'host': 'localhost', 'port': 3306, 'tags': ('dev', 'prod'), 'enabled': True}
{'host': 'remote', 'port': 5432, 'tags': ('dev', 'prod'), 'enabled': True}
```

只要字典中不包含嵌套的列表、字典、集合等可变对象，`dict.copy()` 就是安全且高效的选择。

本文深入剖析了 Python 字典拷贝的三种方式及其内存行为，主要介绍了以下内容：

- **引用赋值**（`d2 = d1`）：不创建新对象，两个变量指向同一个字典，修改一个另一个也跟着变；函数传参也是引用传递，修改入参会影响外部数据
- **浅拷贝**（`d.copy()` / `copy.copy(d)`）：创建新的顶层字典对象，但嵌套的可变对象（列表、字典等）仍然共享引用——修改浅拷贝的嵌套内容会污染原对象
- **原地修改 vs 重新赋值**：通过嵌套引用做原地修改（`.append()` / 内层 `["key"] =`）会共享传播，而在字典顶层重新赋值（`d["key"] = new_value`）只影响该字典自身
- **深拷贝**（`copy.deepcopy(d)`）：递归复制所有层级的可变对象，创建完全独立的副本；不可变对象直接复用以优化性能
- **循环引用处理**：`deepcopy` 通过 `memo` 字典记录已复制对象，正确处理自引用和循环引用结构
- **自定义拷贝协议**：通过实现 `__copy__` 和 `__deepcopy__` 方法可以控制自定义对象的拷贝行为，`__deepcopy__` 必须传递 `memo` 参数
- **性能权衡**：深拷贝需要递归遍历所有嵌套对象，性能开销远大于浅拷贝（可达数千倍）；当字典值全为不可变类型时，浅拷贝就足以保证独立性
- **选择策略**：无嵌套可变对象用浅拷贝，有嵌套可变对象需独立性时用深拷贝，函数内部安全修改入参时先深拷贝
