# 集合概述与基本概念

## 1. 介绍

### 1.1 什么是集合

集合（Set）是 Python 中一种用于存储**不重复元素**的无序容器类型。它的核心能力可以一句话概括：**自动去重 + 快速成员判断**。

如果你有两个列表 `[1, 2, 3]` 和 `[1, 2, 3]`，它们即使内容一样也是两个独立的列表对象；但如果你把它们合并成一个集合 `{1, 2, 3}`，重复的元素会被自动消除。这就是集合最直观的价值——它天然地帮你维护"唯一性"。

在 Python 的内置类型体系中，集合属于**容器类型**，与列表（list）、元组（tuple）、字典（dict）并列。但集合的设计目标与它们不同：

- 列表/元组：关心**顺序和重复**，适合按位置存取数据
- 字典：关心**键值映射**，适合通过键快速查找值
- 集合：关心**存在与否**，适合判断"某个元素在不在里面"和"两个群体之间有什么关系"

**类比**：集合就像你电脑里的"标签系统"。同一张照片不会被同一个标签打两次（去重），你只需要快速判断"某张照片有没有'旅行'这个标签"（成员判断），你还可以看"旅行标签"和"美食标签"的交集（集合运算）。

### 1.2 最简示例

用一个最小的例子来认识集合长什么样：

```python
# 创建一个集合
fruits = {"apple", "banana", "orange", "apple"}
print(fruits)
```

运行结果：

```text
{'orange', 'banana', 'apple'}
```

注意两个细节：第一，重复的 `"apple"` 只保留了一个；第二，元素的输出顺序和定义顺序不同——这是集合"无序"和"去重"特性的直接体现。

再看一个成员判断的例子：

```python
fruits = {"apple", "banana", "orange"}
print("apple" in fruits)
print("grape" in fruits)
```

运行结果：

```text
True
False
```

`in` 操作在集合上的速度极快——无论集合有 10 个元素还是 10 万个元素，判断一个元素在不在里面，耗时几乎相同。这是列表做不到的。

### 1.3 集合在 Python 中的定位

Python 的内置类型可以按"关心什么"来分类：

```text
Python 内置容器类型
├── 序列类型（关心顺序和位置）
│   ├── list    —— 可变，有序，可重复
│   ├── tuple   —— 不可变，有序，可重复
│   └── str     —— 不可变，有序，字符序列
├── 映射类型（关心键值映射）
│   └── dict    —— 键唯一，可变，键无序（3.7+ 保持插入顺序）
└── 集合类型（关心存在性）
    ├── set         —— 可变，无序，元素不重复
    └── frozenset   —— 不可变，无序，元素不重复
```

集合在这个体系中的定位非常清晰：当你需要的是"一批东西有没有"，而不是"一批东西按什么顺序排"时，就该用集合。

## 2. 核心内容

### 2.1 集合的定义与本质

要理解集合，需要从两个层面来看：

**数学层面**：集合的直接灵感来源是数学中的集合论。数学教材中，集合是由某些确定的、互不相同的对象聚集在一起的整体。Python 的集合几乎完全继承了这一概念——确定性（一个元素要么在集合里要么不在）、互异性（元素不重复）、以及集合之间的运算（并集、交集、差集）。

**数据结构层面**：Python 的集合底层是**哈希表**（Hash Table）。哈希表是一种通过"哈希函数"将元素映射到存储位置的数据结构。这种结构天然支持两件事：快速查找（判断元素存不存在）和自动去重（相同哈希值的元素会被视为同一个）。当你把一个元素放进集合时，Python 先算出它的哈希值，再把哈希值对应到内存中的一个位置——如果那个位置已经有等价的元素了，就不再存储。

**类比**：集合就像酒店寄存行李。你递给前台一个包（元素），前台不会按顺序把包排在架子上，而是给每个包分配一个编号（哈希值），放到对应位置的格子中。下次你想来取包，前台根据编号直接走到对应的格子——不需要从头到尾扫描所有格子。如果你寄存了两个一模一样的包，前台只收一个。

### 2.2 集合的三大核心特征

集合的行为由三个核心特征决定：**无序性、确定性、互异性**。这三个特征直接来自数学集合论，也是集合区别于列表、元组的关键。

#### 2.2.1 无序性

集合中的元素**没有固定的排列顺序**。你定义集合时写 `{"a", "b", "c"}`，实际存储和输出的顺序可能是 `{"c", "a", "b"}`，也可能每次运行都不同。

```python
s = {"python", "java", "c++", "go", "rust"}
print(s)
```

多次运行可能得到：

```text
{'rust', 'python', 'c++', 'java', 'go'}
{'java', 'go', 'c++', 'rust', 'python'}
{'python', 'java', 'go', 'rust', 'c++'}
```

**为什么无序？** 因为集合用哈希表存储，元素的位置由哈希值决定，而不是由插入顺序决定。哈希值看起来是"乱"的，所以输出也"乱"。

**无序性的影响**：

| 行为 | 列表 | 集合 |
|------|------|------|
| 按索引取值 `s[0]` | 支持 | 不支持，报 TypeError |
| 切片 `s[1:3]` | 支持 | 不支持 |
| 遍历 `for x in s` | 按顺序 | 顺序不可预期 |

```python
s = {10, 20, 30}
# 以下操作会报错
# print(s[0])  # TypeError: 'set' object is not subscriptable
```

无序性意味着你**不能用索引访问集合元素**，也不能依赖遍历顺序。如果你需要有序 + 去重，可以先用集合去重再转成列表排序。

#### 2.2.2 确定性

确定性指的是：对于任意一个元素，它是否属于某个集合是**明确可判断**的——要么在，要么不在，没有模棱两可。

这听起来理所当然，但在实际编码中有重要含义：集合的成员判断 `x in s` 是一个 O(1) 操作，速度极快且结果确定。这和列表的线性查找 `x in lst`（O(n)）形成鲜明对比。

```python
# 集合：O(1) 成员判断
big_set = set(range(100000))
print(99999 in big_set)   # 几乎瞬间完成

# 列表：O(n) 成员判断
big_list = list(range(100000))
print(99999 in big_list)  # 需要从头扫描到末尾
```

**类比**：在电话簿（有序列表）里找一个名字，你要从第一页翻到最后一页（列表查找）；在手机通讯录（哈希表/集合）里找一个名字，输入第一个字母就定位到了（哈希查找）。

#### 2.2.3 互异性

互异性指的是：集合中的元素**不能重复**。当你试图把一个已存在的元素加入集合时，集合不会报错，但也不会产生重复——它只保持一份。

```python
s = {1, 2, 3}
s.add(2)     # 2 已经在里面了
print(s)     # 还是 {1, 2, 3}
```

这个特性是集合最大的实用价值之一。去重只需要一行代码：

```python
# 列表去重：一行搞定
data = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]
unique_data = list(set(data))
print(unique_data)
```

运行结果：

```text
[1, 2, 3, 4]
```

**注意**：`set(data)` 去重后顺序会丢失。如果需要保持原始顺序去重，可以用 `dict.fromkeys()`：

```python
data = [3, 1, 4, 1, 5, 9, 2, 6, 5]
# 保持顺序去重
unique_ordered = list(dict.fromkeys(data))
print(unique_ordered)
```

运行结果：

```text
[3, 1, 4, 5, 9, 2, 6]
```

不过 `dict.fromkeys()` 利用的不是集合，而是字典键的唯一性——这是一种旁敲侧击的去重技巧，原因在于 Python 3.7+ 字典保持插入顺序，而集合不保持。

### 2.3 集合的三大特征对比

把这个三个特征放在一起对比，可以更清晰地理解集合的全貌：

| 特征 | 含义 | 实际影响 | 对应数学概念 |
|------|------|---------|-------------|
| 无序性 | 元素没有固定顺序 | 不能用索引访问，遍历顺序不可预期 | 集合元素无先后 |
| 确定性 | 元素在不在集合里可明确判断 | `in` 操作 O(1) 极快 | 属于关系 ∈ |
| 互异性 | 元素不重复 | 自动去重，add 重复元素无效 | 集合元素互不相同 |

这三个特征是集合一切行为的基础：无序性来源于哈希表的存储方式；确定性来源于哈希表的查找机制；互异性来源于哈希表对相同元素的去重逻辑。

### 2.4 集合的分类：set 与 frozenset

Python 提供了两种集合类型，分别对应可变和不可变两种需求：

#### 2.4.1 可变集合 set

`set` 是最常用的集合类型。你可以动态地添加、删除元素：

```python
s = {1, 2, 3}
s.add(4)
s.discard(1)
print(s)
```

运行结果：

```text
{2, 3, 4}
```

`set` 是可变对象，意味着它的内容可以在原地修改。但这也意味着它**不可哈希**——不能作为字典的键，也不能作为另一个集合的元素。

```python
s = {1, 2, 3}
# 把 set 当作字典的键会报错
# d = {s: "value"}  # TypeError: unhashable type: 'set'
```

#### 2.4.2 不可变集合 frozenset

`frozenset` 是 `set` 的不可变版本。一旦创建，内容不可修改——不能添加、不能删除。但它**可哈希**，可以作为字典的键或集合的元素。

```python
fs = frozenset([1, 2, 3])
print(fs)
print(type(fs))

# frozenset 可以作为字典的键
d = {frozenset([1, 2]): "一对数字"}
print(d[frozenset([1, 2])])

# frozenset 可以作为集合的元素
nested = {frozenset([1, 2]), frozenset([3, 4])}
print(nested)
```

运行结果：

```text
frozenset({1, 2, 3})
<class 'frozenset'>
一对数字
{frozenset({1, 2}), frozenset({3, 4})}
```

#### 2.4.3 set 与 frozenset 对比

| 维度 | set | frozenset |
|------|-----|-----------|
| 可变性 | 可变（可增删） | 不可变（创建后不可改） |
| 可哈希性 | 不可哈希 | 可哈希 |
| 能否做字典键 | 不能 | 能 |
| 能否做集合元素 | 不能 | 能 |
| 创建方式 | `{...}` 或 `set()` | `frozenset(...)` |
| 典型场景 | 日常去重、成员判断、集合运算 | 需要不可变集合的场景、做字典键、嵌套集合 |

**类比**：`set` 是一个可以随时往里加东西、往外拿东西的篮子；`frozenset` 是一个密封的展示盒——东西放进去后封死，不能再动，但可以安全地放在任何地方（做字典键、做集合元素），因为别人可以信任它不会变。

### 2.5 集合在 Python 类型体系中的位置

集合不是凭空存在的，它在 Python 的类型体系中有清晰的归属关系：

```text
Python 对象
└── 容器类型（可以包含多个元素）
    ├── 序列类型
    │   ├── list / tuple / str / range / bytes
    │   └── 特征：有序、可索引、可重复
    ├── 映射类型
    │   ├── dict
    │   └── 特征：键值对、键唯一
    └── 集合类型
        ├── set / frozenset
        └── 特征：无序、不重复、基于哈希表
```

从这个层级关系可以看出：

1. 集合和序列、映射是并列的三大容器类型，各有侧重点
2. 集合和字典在底层都依赖**哈希表**——字典可以看作"有值的集合"（键的集合 + 每个键绑一个值）
3. 集合是可迭代对象（支持 `for x in s`），但不是序列（不能用索引访问）

**集合与字典的亲密关系**：在 Python 的 CPython 实现中，集合和字典共用很多底层机制。字典的键本质上就是一个集合——唯一、无序、基于哈希。集合可以理解为"只有键、没有值"的字典。这也解释了为什么删重复元素可以用 `dict.fromkeys()`：它的本质是"用字典键的唯一性来做去重"。

### 2.6 集合与数学概念的关系

集合的概念直接来自离散数学中的集合论。Python 的集合几乎完整地实现了基础集合论的运算：

| 数学运算 | 数学符号 | Python 操作符 | Python 方法 | 含义 |
|---------|---------|-------------|------------|------|
| 并集 | A ∪ B | `A | B` | `A.union(B)` | 在 A 或 B 中的所有元素 |
| 交集 | A ∩ B | `A & B` | `A.intersection(B)` | 同时在 A 和 B 中的元素 |
| 差集 | A - B | `A - B` | `A.difference(B)` | 在 A 中但不在 B 中的元素 |
| 对称差集 | A △ B | `A ^ B` | `A.symmetric_difference(B)` | 只在 A 或只在 B 中的元素 |
| 子集 | A ⊆ B | `A <= B` | `A.issubset(B)` | A 的所有元素都在 B 中 |
| 超集 | A ⊇ B | `A >= B` | `A.issuperset(B)` | B 的所有元素都在 A 中 |

```python
A = {1, 2, 3, 4}
B = {3, 4, 5, 6}

print("并集:", A | B)
print("交集:", A & B)
print("差集:", A - B)
print("对称差集:", A ^ B)
```

运行结果：

```text
并集: {1, 2, 3, 4, 5, 6}
交集: {3, 4}
差集: {1, 2}
对称差集: {1, 2, 5, 6}
```

这套运算和数学课上学的一模一样。这意味着如果你有离散数学或概率论的基础，Python 集合的行为完全符合直觉。反过来，学习 Python 集合也能帮你巩固数学中的集合概念。

**类比**：数学课上用 Venn 图（韦恩图）画两个圆的交叠，Python 集合用 `&` 算出两个圆的重叠部分——思维模型完全一致。

### 2.7 集合元素的要求：可哈希性

集合不是什么都能装的。一个元素能放进集合，前提条件是它**可哈希**（hashable）。

#### 2.7.1 什么是可哈希

一个对象可哈希，意味着它实现了 `__hash__()` 方法，并且满足两个条件：

1. **在其生命周期内哈希值不变**——如果对象内容变了，哈希值变了，集合就找不到它了
2. **可比较**——实现了 `__eq__()` 方法，用于判断两个元素是否"相等"

在 Python 中，**不可变类型默认可哈希**，**可变类型默认不可哈希**：

| 类型 | 可哈希？ | 能否放入集合？ |
|------|---------|-------------|
| int, float, bool, complex | 可哈希 | 能 |
| str, tuple（元素均不可变） | 可哈希 | 能 |
| frozenset | 可哈希 | 能 |
| list | 不可哈希 | 不能 |
| dict | 不可哈希 | 不能 |
| set | 不可哈希 | 不能 |
| 自定义类实例 | 默认可哈希（按 id） | 能 |

#### 2.7.2 为什么有这个限制

集合用哈希表存储元素，需要通过哈希值来确定元素的存储位置。如果元素是可变的——比如一个列表，你往集合里放了 `[1, 2]`，之后改成了 `[1, 2, 3]`——哈希值就变了，集合就找不到它了，这个元素就会从集合中"丢失"。

```python
# 尝试把列表放入集合——报错
# s = {[1, 2], [3, 4]}  # TypeError: unhashable type: 'list'

# 元组可以
s = {(1, 2), (3, 4)}
print(s)
```

运行结果：

```text
{(1, 2), (3, 4)}
```

**注意**：元组虽然本身不可变，但如果元组里包含可变元素（如 `(1, [2, 3])`），它仍然不可哈希——哈希函数会递归检查每个元素。

```python
# 包含可变元素的元组也不可哈希
# s = {(1, [2, 3])}  # TypeError: unhashable type: 'list'
```

#### 2.7.3 自定义类对象与可哈希性

自定义类的实例默认是可哈希的，哈希值基于对象的 `id()`（内存地址）。这意味着两个内容相同但不同实例的对象，在集合中会被视为**两个不同元素**：

```python
class Person:
    def __init__(self, name):
        self.name = name

p1 = Person("Alice")
p2 = Person("Alice")

s = {p1, p2}
print(len(s))  # 2，因为 p1 和 p2 是不同对象
```

如果你想让内容相同的对象在集合中被去重，需要同时实现 `__eq__` 和 `__hash__`：

```python
class Person:
    def __init__(self, name):
        self.name = name

    def __eq__(self, other):
        return isinstance(other, Person) and self.name == other.name

    def __hash__(self):
        return hash(self.name)

p1 = Person("Alice")
p2 = Person("Alice")

s = {p1, p2}
print(len(s))  # 1，因为内容相同被视为同一个元素
```

运行结果：

```text
2
1
```

**类比**：集合的"可哈希"要求就像档案室的规则——只接受装订好的、不可修改的档案（不可变类型）。活页夹（可变类型）随时可以增删页面，存进去后如果编号变了，档案室就找不到它了。

## 3. 实践示例

### 3.1 集合的创建与基本观察

```python
# 方式一：字面量语法（推荐，简洁）
colors = {"red", "green", "blue"}
print("字面量创建:", colors, type(colors))

# 方式二：set() 构造器，从可迭代对象创建
from_list = set([1, 2, 2, 3, 3, 3])
print("从列表创建（去重）:", from_list)

from_string = set("hello")
print("从字符串创建:", from_string)

# 方式三：集合推导式
squares = {x * x for x in range(5)}
print("集合推导式:", squares)
```

运行结果：

```text
字面量创建: {'red', 'blue', 'green'} <class 'set'>
从列表创建（去重）: {1, 2, 3}
从字符串创建: {'o', 'e', 'h', 'l'}
从集合推导式: {0, 1, 4, 9, 16}
```

**空集合的创建**有一个容易踩的坑：

```python
# 错误：{} 创建的是空字典，不是空集合
empty_wrong = {}
print(type(empty_wrong))  # <class 'dict'>

# 正确：用 set() 创建空集合
empty_right = set()
print(type(empty_right))  # <class 'set'>
```

运行结果：

```text
<class 'dict'>
<class 'set'>
```

`{}` 在 Python 中被分配给了字典的字面量语法。这既是历史原因（字典比集合更早出现），也提醒你：创建空集合时必须显式调用 `set()`。

### 3.2 去重场景演示

去重是集合最常见的实际用途。以下是一个模拟数据处理中的去重场景：

```python
# 模拟一批用户访问记录，其中有重复用户
visit_records = [
    "user_001", "user_002", "user_003",
    "user_001", "user_004", "user_002",
    "user_005", "user_001", "user_006"
]

# 需求：统计有多少个不同的用户访问过
unique_users = set(visit_records)
print(f"总访问记录数: {len(visit_records)}")
print(f"不同用户数: {len(unique_users)}")
print(f"去重后的用户: {unique_users}")
```

运行结果：

```text
总访问记录数: 9
不同用户数: 6
去重后的用户: {'user_003', 'user_001', 'user_006', 'user_004', 'user_002', 'user_005'}
```

### 3.3 集合运算实战：找出两个群体的差异

集合运算在实际开发中经常用于"分析两个群体之间有什么不同"。以下是一个模拟场景：

```python
# 两门课程的选课名单
python_students = {"Alice", "Bob", "Charlie", "Diana", "Eve"}
java_students = {"Bob", "Charlie", "Frank", "Grace"}

# 两门课都选了的同学
both = python_students & java_students
print(f"两门课都选了: {both}")

# 只选了 Python 的同学
only_python = python_students - java_students
print(f"只选了 Python: {only_python}")

# 只选了其中一门课的同学（对称差集）
either_but_not_both = python_students ^ java_students
print(f"只选了一门课: {either_but_not_both}")

# 至少选了一门课的同学
at_least_one = python_students | java_students
print(f"至少选了一门课: {at_least_one}")
```

运行结果：

```text
两门课都选了: {'Charlie', 'Bob'}
只选了 Python: {'Alice', 'Diana', 'Eve'}
只选了一门课: {'Alice', 'Diana', 'Frank', 'Grace', 'Eve'}
至少选了一门课: {'Alice', 'Diana', 'Frank', 'Eve', 'Grace', 'Charlie', 'Bob'}
```

这个例子展示了集合运算的语义表达力：用 `&`、`-`、`^`、`|` 四个符号，分别表达了"两都"、"只在A不在B"、"只居其一"、"至少一个"四种逻辑关系——如果用列表来写，每种都需要嵌套循环或列表推导式，而且性能更差。

### 3.4 成员判断性能对比

下面通过一个实验来直观感受集合在成员判断上的性能优势：

```python
import time

# 构造一个大列表和大集合
big_list = list(range(1000000))
big_set = set(range(1000000))

# 测试列表查找
start = time.time()
for _ in range(1000):
    _ = 999999 in big_list
list_time = time.time() - start
print(f"列表查找 1000 次: {list_time:.4f} 秒")

# 测试集合查找
start = time.time()
for _ in range(1000):
    _ = 999999 in big_set
set_time = time.time() - start
print(f"集合查找 1000 次: {set_time:.4f} 秒")

print(f"集合比列表快约 {list_time / set_time:.0f} 倍")
```

运行结果（具体数值取决于机器性能）：

```text
列表查找 1000 次: 2.8734 秒
集合查找 1000 次: 0.0001 秒
集合比列表快约 28000 倍
```

列表要从头扫描到第 100 万个位置才能找到 `999999`，每次查找都做 100 万次比较，1000 次就是 10 亿次比较；集合通过哈希值直接定位，每次查找只需要 1~2 次比较，1000 次也只是两千多次比较。

**这个对比说明**：当你的代码里出现了 `if x in big_list` 且 `big_list` 很大时，转换为 `if x in big_set` 可能是最大的性能优化手段。

## 4. 常见误区与边界

### 4.1 误区一：集合是有序的

有人观察到在一个简单的测试中集合的输出顺序看起来"固定不变"，就误以为集合是有序的。这是一个错觉。

```python
# 小整数集合，在某些 Python 版本下输出看似稳定
s = {1, 2, 3, 4, 5}
print(s)  # 可能稳定输出 {1, 2, 3, 4, 5}
```

这并不是 Python 保证有序，而是小整数的哈希值碰巧等于自身（`hash(1) == 1`），导致连续小整数在哈希表中的存储位置恰好是递增的。这不是语言规范，属于实现细节——如果你依赖这个"看似有序"的行为，在不同 Python 版本、不同操作系统上可能得到不同结果。

**修正**：如果需要有序去重，用 `sorted(set(data))` 或 `list(dict.fromkeys(data))`，不要依赖集合的遍历顺序。

### 4.2 误区二：集合可以存储任意类型

有人尝试把列表或字典放进集合，然后遇到 `TypeError`：

```python
# 常见错误：尝试把列表放入集合
# s = {[1, 2], [3, 4]}  # TypeError: unhashable type: 'list'
```

**修正**：如果需要存储"一组数据项"且每项不重复，先将数据项转为元组。元组是不可变的，可以作为集合元素：

```python
# 正确：用元组代替列表
s = {(1, 2), (3, 4), (1, 2)}
print(s)  # {(1, 2), (3, 4)}，重复的 (1, 2) 被去重
```

### 4.3 误区三：用 {} 创建空集合

```python
# 常见错误
empty = {}
print(type(empty))  # <class 'dict'>，不是集合！

# 正确做法
empty_set = set()
print(type(empty_set))  # <class 'set'>
```

`{}` 语法属于字典。Python 没有为空集合设计单独的字面量语法，这是初学者最容易犯的错误之一。

### 4.4 误区四：集合遍历时有固定顺序

开发者有时写出依赖集合遍历顺序的代码：

```python
s = {"b", "a", "c"}
# 理想中希望得到 "a, b, c"
result = ",".join(s)
print(result)
# 实际输出可能是 "b,c,a" 或任何顺序
```

**修正**：需要有序输出时要显式排序：

```python
s = {"b", "a", "c"}
result = ",".join(sorted(s))
print(result)  # "a,b,c"
```

### 4.5 集合的边界

集合虽然强大，但也有适用边界：

| 场景 | 是否适合用集合 | 原因 |
|------|-------------|------|
| 去重 | 适合 | 集合天然去重 |
| 成员判断（大列表） | 适合 | O(1) 查找 |
| 保序去重 | 不适合（需转换） | 集合无序，需配合排序或 dict |
| 需要按索引访问 | 不适合 | 集合不支持索引 |
| 记录重复次数 | 不适合 | 集合丢弃重复信息 |
| 存储键值对 | 不适合（应使用字典） | 集合只有元素，无值 |
| 存储可变对象 | 不适合 | 可变对象不可哈希 |
| 嵌套集合 | 需用 frozenset | set 不可哈希，不能嵌套 |

**最重要的判断标准**：如果你的核心需求是"某个东西在不在里面"，用集合；如果是"一堆东西按什么顺序排"，用列表；如果是"一个键对应一个值"，用字典。选错容器会同时牺牲性能和代码可读性。

## 5. 总结

本文围绕 Python 集合的概述与基本概念展开，主要介绍了以下内容：

- 集合是一种存储不重复元素的无序容器类型，核心能力是自动去重和快速成员判断
- 集合的三大核心特征：无序性（不支持索引访问）、确定性（`in` 判断为 O(1)）、互异性（自动去重）
- Python 提供两种集合：`set`（可变，不可哈希）和 `frozenset`（不可变，可哈希，可嵌套）
- 集合在 Python 类型体系中与序列、映射并列，底层依赖哈希表，与字典共享核心机制
- 集合继承了数学集合论的运算体系，支持并集、交集、差集、对称差集、子集/超集判断
- 集合元素必须是可哈希对象，不可变类型默认可哈希，可变类型不可哈希——这是哈希表存储方式的必然要求
- 常见误区包括：误认为集合有序、用 `{}` 创建空集合、依赖遍历顺序、尝试存储可变对象等
