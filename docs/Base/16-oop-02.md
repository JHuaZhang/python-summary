## 1. 介绍

### 1.1 什么是 self

在 Python 面向对象编程中，`self` 是一个频繁出现却又容易被误解的概念。当你定义一个类并在其中书写实例方法时，方法的第一个参数几乎总是 `self`；当你调用 `obj.method(x)` 时，你并没有显式传入 `self`，但方法内部却能通过 `self` 访问到 `obj` 本身。这背后的机制，正是本篇要讲清楚的「self 的本质」。

一句话定义：**`self` 就是当前正在被操作的实例对象的引用**。它不是关键字，不是一个特殊变量，它只是一个普通的形参名——只不过 Python 在调用实例方法时，会自动把调用该方法的对象作为第一个参数传入，而这个第一个参数按约定写作 `self`。

理解 `self` 的关键在于把它和「实例方法」「类」「对象」三者放到一起看：

- **类（Class）** 是一张蓝图，定义了属性和方法的模板。
- **对象（Object）** 是根据蓝图创建的具体实例，拥有自己的属性数据。
- **实例方法（Instance Method）** 是定义在类中的函数，它通过 `self` 与某个具体对象建立联系，从而能够读写该对象的属性。

当你写下：

```python
class Dog:
    def bark(self):
        print(f"{self.name} says: Woof!")

dog = Dog()
dog.name = "Rex"
dog.bark()
# 输出：Rex says: Woof!
```

这里的 `dog.bark()` 看似只传了零个参数，实际上 Python 做了等价于 `Dog.bark(dog)` 的调用：把 `dog` 这个对象作为 `self` 传进了 `bark` 方法。所以方法体里的 `self.name` 其实就是 `dog.name`，也就是 `"Rex"`。

**为什么需要 self**

很多从 Java、C++ 转过来的初学者会问：为什么 Python 要把 `self` 显式写在参数列表里，而不是像 Java 那样用一个隐式的 `this`？这是 Python 的设计哲学决定的——Python 奉行「显式优于隐式」（Explicit is better than implicit）。把 `self` 写出来，意味着你在方法定义的签名处就能一眼看清：这个方法操作的是实例本身，它接收哪些参数，第一个参数代表谁。没有魔法，没有隐藏的上下文，一切都是可见的。

### 1.2 基本语法与最小用法

实例方法定义的最基本形式：

```python
class 类名:
    def 方法名(self, 其他参数...):
        方法体
```

- `self` 必须是第一个形参（位置上），这个名字是约定但强烈建议遵守。
- 调用方式：`实例对象.方法名(其他参数...)`，Python 自动把实例对象绑定为 `self`。
- 在方法体内部，通过 `self.属性名` 访问/修改实例属性，通过 `self.方法名()` 调用其他实例方法。

最小可运行示例：

```python
class Counter:
    def __init__(self, start=0):
        self.count = start          # 通过 self 写实例属性

    def increment(self, step=1):
        self.count += step          # 通过 self 改实例属性

    def show(self):
        print(f"current count = {self.count}")

c = Counter(10)
c.increment(3)
c.show()
# 输出：current count = 13
```

在这个例子中，`c.increment(3)` 等价于 `Counter.increment(c, 3)`。`self` 就是 `c`，所以 `self.count += step` 实际修改的是 `c.count`。方法执行完毕后，`c.count` 从 `10` 变成了 `13`。

**两种等价的调用形式**

理解 `self` 的一个重要直观感受是：下面两种调用完全等价。

```python
class Greeter:
    def greet(self, name):
        print(f"Hello, {name}! I am {self.who}.")

g = Greeter()
g.who = "Alice"

# 形式一：通过实例调用（Python 自动传 self）
g.greet("Bob")
# 输出：Hello, Bob! I am Alice.

# 形式二：通过类调用，手动传 self
Greeter.greet(g, "Bob")
# 输出：Hello, Bob! I am Alice.
```

两种形式输出完全一致。形式一是日常写法，简洁且符合直觉；形式二揭示了底层真相——实例方法本质上是定义在类上的普通函数，第一个参数就是要操作的对象。`obj.method(x)` 这种语法只是把 `obj`「绑定」到了 `method` 上，省去你手动写第一个参数的麻烦。

本篇接下来会从「self 作为实例引用」「自动绑定机制」「self vs cls」「命名约定」「显式哲学」等多个角度展开，最后在原理章深入到描述符协议与字节码层面，把 `self` 的来龙去脉彻底讲透。

## 2. 核心内容

### 2.1 self 是当前实例对象的引用

`self` 最根本的身份，就是「当前这次方法调用所操作的那个实例对象」的引用。所谓"引用"，意味着 `self` 并不是对象的副本，而是指向堆上那同一个对象的同一份内存——通过 `self` 修改属性，修改的就是对象本身的属性；通过 `self` 读取属性，读到的就是对象当前的属性值。

为了体会"引用同一份对象"，看这个例子：

```python
class Account:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount     # 通过 self 修改实例属性
        return self.balance

    def whoami(self):
        # self 就是那个对象本身，id 相同
        print(f"owner={self.owner}, balance={self.balance}")
        print(f"id(self) = {id(self)}")

acc = Account("Bob", 100)
print(f"id(acc) = {id(acc)}")
# 输出：id(acc) = <某个地址>

acc.deposit(50)
acc.whoami()
# 输出：owner=Bob, balance=150
# 输出：id(self) = <与 id(acc) 完全相同的地址>
```

关键观察：

1. `deposit` 方法里 `self.balance += amount` 执行后，外面 `acc.balance` 也变成了 `150`——因为 `self` 和 `acc` 指向同一个对象，没有拷贝发生。
2. `whoami` 里打印 `id(self)`，和外面打印 `id(acc)` 得到的数值完全相同——`self` 就是 `acc`，不是 `acc` 的影子或副本。

这意味着 `self` 是方法与实例数据之间的唯一桥梁。方法体里所有对实例属性的访问，都必须经过 `self`。如果你在方法体里写一个不带 `self` 的变量名，Python 会按 LEGB 规则去局部、 enclosing、全局、内置查找，它不会自动指向实例属性。这一点和 Java/C++ 完全不同，后面会专门讲。

**一个更具场景感的例子：BankAccount 存取款**

```python
class BankAccount:
    def __init__(self, owner, initial_balance=0):
        self.owner = owner
        self.balance = initial_balance
        self.history = []          # 每个账户独立维护一份交易历史

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit amount must be positive")
        self.balance += amount
        self.history.append(("deposit", amount, self.balance))
        return self.balance

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("withdraw amount must be positive")
        if amount > self.balance:
            raise ValueError("insufficient funds")
        self.balance -= amount
        self.history.append(("withdraw", amount, self.balance))
        return self.balance

    def statement(self):
        print(f"--- {self.owner}'s account ---")
        print(f"balance: {self.balance}")
        for op, amt, bal in self.history:
            print(f"  {op:8s} {amt:>8.2f}  ->  {bal:>8.2f}")

alice = BankAccount("Alice", 1000)
bob = BankAccount("Bob", 500)

alice.deposit(200)
alice.withdraw(150)
bob.deposit(50)

alice.statement()
# 输出：
# --- Alice's account ---
# balance: 1050
#   deposit    200.00  ->   1200.00
#   withdraw   150.00  ->   1050.00

bob.statement()
# 输出：
# --- Bob's account ---
# balance: 550
#   deposit     50.00  ->    550.00
```

这个例子完整展示了 `self` 的核心作用：

- `self.balance`、`self.history` 是**每个实例各自独立**的。`alice` 和 `bob` 是两个不同的对象，当调用 `alice.deposit(200)` 时，`self` 就是 `alice`，因此只修改 `alice` 的余额和历史；调用 `bob.deposit(50)` 时，`self` 就是 `bob`，只动 `bob` 的数据。两者互不干扰。
- 方法内部对实例属性的读写必须通过 `self`：`self.balance += amount`、`self.history.append(...)`。如果不写 `self.`，写成 `balance += amount`，Python 会把 `balance` 当作一个未定义的局部变量，抛出 `UnboundLocalError` 或 `NameError`，它绝对不会去访问实例属性。
- 方法可以返回 `self.balance` 这样的实例属性值，也可以返回 `self` 本身（用于链式调用，后面会讲）。

### 2.2 调用 obj.method(x) 时 Python 自动把 obj 作为 self 传入

这是 `self` 机制最关键的一点：**自动绑定**。当你用 `obj.method(x)` 这种形式调用实例方法时，Python 会在背后把它转换成 `Class.method(obj, x)`——把 `obj` 自动填到第一个参数位置（也就是形参 `self`），再把 `x` 作为第二个参数传入。你不需要、也不应该自己写 `obj.method(obj, x)`，那会导致 `self` 被重复传入。

用代码验证这种等价性：

```python
class Calculator:
    def add(self, a, b):
        return a + b

calc = Calculator()

# 日常写法：Python 自动把 calc 作为 self 传入
r1 = calc.add(3, 4)
print(r1)
# 输出：7

# 等价写法：通过类直接调用，手动把 calc 作为第一个参数传入
r2 = Calculator.add(calc, 3, 4)
print(r2)
# 输出：7

# 甚至可以用别的对象，只要它"像"第一个参数所需那样被使用
# 这里直接传 None，只要方法体不访问 self 属性就能跑
r3 = Calculator.add(None, 3, 4)
print(r3)
# 输出：7
```

最后一行 `Calculator.add(None, 3, 4)` 能正常运行并返回 `7`，是因为 `add` 方法体里根本没有用到 `self`。这进一步说明：`self` 在语法层面就是个普通参数，它和 `a`、`b` 没有本质区别，只是按惯例放在第一个位置、按惯例起名叫 `self` 而已。Python 解释器并不会因为参数名叫 `self` 就做任何特殊处理——特殊处理发生在「绑定」阶段，与参数名字无关。

**自动绑定只发生在通过实例访问方法时**

```python
class Speaker:
    def say(self, msg):
        print(f"[{id(self)}] {msg}")

s = Speaker()

# 通过实例访问：自动绑定，self = s
s.say("hi via instance")
# 输出：[<s 的 id>] hi via instance

# 通过类访问：不绑定，得到原始函数，必须手动传 self
raw = Speaker.say
print(type(raw))
# 输出：<class 'function'>

raw(s, "hi via class")
# 输出：[<s 的 id>] hi via class
```

可以看到：

- `s.say` 得到的是一个「绑定方法（bound method）」对象，`self` 已经被预填为 `s`，调用时只需传剩下的参数。
- `Speaker.say` 得到的是原始的「函数（function）」对象，`self` 未被预填，调用时必须手动传入第一个参数。

这两种访问方式的差别，本质上涉及描述符协议，原理章会详细展开。这里先记住一个结论：**`self` 的自动传入，是「通过实例访问方法」这一动作触发的，不是方法定义本身触发的**。

### 2.3 self vs cls：实例方法与类方法的区别

除了实例方法的第一个参数 `self`，你还会遇到类方法的第一个参数 `cls`。两者容易混淆，需要明确区分。

- **实例方法**：`def method(self, ...)`，第一个参数是 `self`，指向**实例对象**。通过实例调用时自动传入实例。这是最常见的方法类型。
- **类方法**：用 `@classmethod` 装饰，`def method(cls, ...)`，第一个参数是 `cls`，指向**类本身**（不是实例）。无论通过实例还是类调用，都传入类对象。
- **静态方法**：用 `@staticmethod` 装饰，没有 `self` 也没有 `cls`，就是个定义在类命名空间里的普通函数，不会自动传入任何隐式参数。

对比示例：

```python
class Temperature:
    _unit = "celsius"          # 类属性

    def __init__(self, value):
        self.value = value     # 实例属性

    # 实例方法：操作实例，self 指向实例
    def read(self):
        return f"{self.value}° in {self._unit}"

    # 类方法：操作类，cls 指向类
    @classmethod
    def set_unit(cls, unit):
        cls._unit = unit

    # 工厂方法：常见的类方法用法，用 cls 创建实例
    @classmethod
    def from_fahrenheit(cls, f):
        c = (f - 32) * 5 / 9
        return cls(c)          # cls 是类本身，等价于 Temperature(c)

    # 静态方法：不依赖实例也不依赖类
    @staticmethod
    def to_fahrenheit(celsius):
        return celsius * 9 / 5 + 32

t = Temperature(36.5)
print(t.read())
# 输出：36.5° in celsius

Temperature.set_unit("kelvin")
print(t.read())
# 输出：36.5° in kelvin

t2 = Temperature.from_fahrenheit(98.6)
print(t2.value)
# 输出：37.0

print(Temperature.to_fahrenheit(100))
# 输出：212.0
```

关键点：

1. `self` 与 `cls` 指向的对象层次不同。`self` 是 `Temperature` 的某个实例（如 `t`），`cls` 是 `Temperature` 这个类本身。
2. 实例方法内既能访问实例属性（`self.value`），也能访问类属性（`self._unit` 或 `Temperature._unit`）。类方法内通常操作类属性（`cls._unit`），不能直接访问某个具体实例的属性，因为它根本没有拿到实例。
3. 类方法常用作工厂方法（`from_fahrenheit`），因为 `cls` 让子类调用时能自动创建子类实例——这是 `self`/`cls` 区分的一大用途。
4. 静态方法没有 `self`/`cls`，适合放与类相关但不需要访问实例或类数据的工具函数。

**self 和 cls 各自的"身份"验证**

```python
class Foo:
    @classmethod
    def show_cls(cls):
        print(f"cls is Foo? {cls is Foo}")
        print(f"id(cls) = {id(cls)}, id(Foo) = {id(Foo)}")

    def show_self(self):
        print(f"self is instance? {isinstance(self, Foo)}")
        print(f"id(self) = {id(self)}")

f = Foo()
Foo.show_cls()
# 输出：cls is Foo? True
# 输出：id(cls) = <x>, id(Foo) = <相同的 x>

f.show_cls()        # 即使通过实例调用类方法，cls 依然是类，不是实例
# 输出：cls is Foo? True

f.show_self()
# 输出：self is instance? True
# 输出：id(self) = <f 的 id>
```

注意 `f.show_cls()` 这一行：即使通过实例 `f` 调用类方法，Python 传入的 `cls` 依然是类 `Foo` 而不是实例 `f`。这是因为 `@classmethod` 装饰器改变了绑定行为——它绑定的是「类」，而非「实例」。这正是 `cls` 和 `self` 的核心区别所在。

### 2.4 self 名字只是约定，可改但不建议改

Python 语言层面并没有规定实例方法的第一个参数必须叫 `self`。`self` 只是一个约定俗成的名字（PEP 8 明确推荐使用）。从语法角度看，你可以把它叫成任何合法的标识符，只要保证调用时第一个参数位置对应即可。

```python
class WeirdName:
    # 第一个参数叫 me 而不是 self，完全合法
    def greet(me, name):
        print(f"{me.identity} greets {name}")

w = WeirdName()
w.identity = "Zaphod"
w.greet("Trillian")
# 输出：Zaphod greets Trillian
```

这段代码能正常运行。`me` 在这里扮演的就是 `self` 的角色——它是第一个形参，调用 `w.greet("Trillian")` 时 Python 自动把 `w` 绑定到 `me` 上。功能上与叫 `self` 没有任何区别。

**为什么不建议改名**

尽管可以改名，几乎所有 Python 项目、标准库、第三方库都严格遵守 `self` 这个名字。原因有三：

1. **可读性**：`self` 是全社区的共同约定。任何 Python 程序员看到 `self` 立刻明白它指代实例自身；换成 `me`、`this`、`obj` 反而需要读者停顿思考"这个参数是什么"。
2. **工具与 IDE 支持**：大部分 IDE、linter、文档生成工具都默认第一个参数叫 `self`。改名可能导致工具提示异常、检查规则误报。
3. **与类方法/静态方法的命名一致性**：`self`（实例）、`cls`（类）这套命名已经是 Python 面向对象代码的"方言"，保持一致能让代码库整体风格统一。

PEP 8 原话："Always use `self` for the first argument to instance methods."——这是"总是使用"，不是"建议使用"。所以实际编码中，请始终使用 `self`，不要为了标新立异而改名。

**特殊场景下的非 self 命名**

在极少数情况下，你可能会看到 `self` 被替换为别的名字，这些通常有特定理由：

- 一些元编程或描述符内部实现，为了区分"被绑定的对象"和"方法内部的其他对象"，偶尔用更语义化的名字。
- 某些协议方法（如 `__init_subclass__` 用 `cls`，`__new__` 用 `cls`）本身就是类级别，第一个参数按规则叫 `cls` 而不是 `self`。
- 极个别老式代码或个人风格，但这是反模式，不应效仿。

日常编写的实例方法，第一个参数永远是 `self`。

### 2.5 self 让方法访问和修改实例属性

`self` 的核心用途，是让方法能够访问和修改实例的属性。没有 `self`，方法就是一座孤岛，无法与对象的数据建立任何联系。这一节详细讲几种典型的属性操作模式。

**模式一：在 `__init__` 中初始化实例属性**

```python
class Person:
    def __init__(self, name, age):
        # self 在创建实例时就被传入，用于把传入的数据保存为实例属性
        self.name = name
        self.age = age

p = Person("Alice", 30)
print(p.name, p.age)
# 输出：Alice 30
```

`__init__` 是实例方法的一种特殊形式。当你执行 `Person("Alice", 30)` 时，Python 先创建一个空对象，再调用 `Person.__init__(新对象, "Alice", 30)`，把新对象作为 `self` 传入。方法体里 `self.name = name` 就把这个名字数据挂到了这个对象上。调用结束后外部就能通过 `p.name` 访问到。

**模式二：方法读取实例属性进行计算**

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        # 通过 self 读取实例属性
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

r = Rectangle(3, 4)
print(r.area())
# 输出：12
print(r.perimeter())
# 输出：14
```

`area` 和 `perimeter` 方法本身不接收额外参数，但它们能算出结果，靠的就是通过 `self` 读到 `width` 和 `height`。方法的"状态"全部存在于实例属性里，`self` 是访问这些状态的唯一入口。

**模式三：方法修改实例属性（带状态变化）**

```python
class LightSwitch:
    def __init__(self):
        self.is_on = False

    def toggle(self):
        # 通过 self 修改实例属性
        self.is_on = not self.is_on
        print("click! now", "ON" if self.is_on else "OFF")

switch = LightSwitch()
switch.toggle()
# 输出：click! now ON
switch.toggle()
# 输出：click! now OFF
```

每次调用 `toggle`，`self.is_on` 都被翻转。`self` 让方法能持久地改变对象的状态，下次再调用时读到的就是新值。这就是"有状态对象"的基础。

**模式四：通过 self 调用同一实例的其他方法**

```python
class Workflow:
    def __init__(self, name):
        self.name = name
        self.steps_done = 0

    def step_one(self):
        print(f"[{self.name}] step one")
        self.steps_done += 1

    def step_two(self):
        print(f"[{self.name}] step two")
        self.steps_done += 1

    def run(self):
        # 通过 self 调用本实例的其他方法
        self.step_one()
        self.step_two()
        print(f"[{self.name}] done, steps={self.steps_done}")

wf = Workflow("build")
wf.run()
# 输出：
# [build] step one
# [build] step two
# [build] done, steps=2
```

`self.step_one()` 这种写法等价于 `Workflow.step_one(self)`——通过 `self` 调用其他实例方法时，`self` 会被再次作为第一个参数传入被调用的方法，保证整个调用链操作的是同一个对象。这是面向对象代码组织的基本手段。

**模式五：返回 self 实现链式调用**

```python
class QueryBuilder:
    def __init__(self):
        self.conditions = []

    def where(self, condition):
        self.conditions.append(condition)
        return self          # 返回 self，让调用方继续链式调用

    def build(self):
        return "SELECT * FROM t WHERE " + " AND ".join(self.conditions) if self.conditions else "SELECT * FROM t"

q = QueryBuilder().where("age > 18").where("city = 'NYC'").build()
print(q)
# 输出：SELECT * FROM t WHERE age > 18 AND city = 'NYC'
```

返回 `self` 是实现流式 API（fluent interface）的常见手法。每次方法调用都返回同一个对象，因此可以连续调用多个方法。这里 `self` 既是"被操作的对象"，也是"被返回的句柄"。

### 2.6 显式 self 是 Python 的显式哲学

Python 有一条著名的设计原则（PEP 20，The Zen of Python）：「Explicit is better than implicit」（显式优于隐式）。`self` 的显式存在，正是这一哲学在面向对象层面的直接体现。

对比 Java：

```java
// Java：this 是隐式的，可以省略
class Person {
    String name;
    int age;
    void greet() {
        System.out.println(name);        // 隐式 this.name
        System.out.println(this.name);   // 显式 this.name，两者等价
    }
}
```

```python
# Python：self 必须显式写出，没有省略形式
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def greet(self):
        print(self.name)     # 必须 self.，否则报错
```

在 Java 里，方法体可以直接写 `name`，编译器会自动在 `this` 上查找。这看起来方便，但代价是：你看到 `name` 这个词时，它可能是局部变量、参数、也可能隐式地是 `this.name`——需要阅读上下文才能判断。Python 选择把这条隐式通路堵死：方法体里写 `name` 就是按 LEGB 查找的普通变量，绝不会自动指向实例属性；要访问实例属性，必须写 `self.name`。一眼可辨，没有歧义。

这种显式带来的好处：

1. **作用域清晰**：`self.name` 一定是实例属性，`name` 一定是局部/全局变量，不混淆。
2. **方法签名透明**：看方法定义的参数列表，立刻知道这个方法需要操作实例（有 `self`）还是不需要（无 `self`，如静态方法）。
3. **降低魔法**：没有隐式上下文，新手读到方法体不必猜测某个名字从哪来。

代价是书写上多了一个 `self.` 前缀和参数列表里的一个 `self`。多数 Python 程序员认为这个代价值得付。

### 2.7 类内直接写 attr 不带 self 不会成为实例属性

这是一个极其常见的初学者陷阱：在方法体里直接写一个不带 `self` 的赋值，期望它成为实例属性。实际上它只是一个局部变量，方法结束就消失，对实例没有任何影响。

**错误示范**

```python
class BadCounter:
    def __init__(self, start):
        count = start          # 错！这只是局部变量，不是实例属性
        self._count = start    # 这才是实例属性

    def increment(self):
        count += 1             # 错！操作的是局部变量，且未定义会报错
        self._count += 1       # 这才是修改实例属性

    def show(self):
        print(count)           # 错！NameError，count 不在这个作用域
        print(self._count)     # 对，访问实例属性

c = BadCounter(0)
c.increment()
# 输出：(假设上面 increment 只保留 self._count += 1 那行)
c.show()
# 输出：1
```

如果完全不带 `self`：

```python
class Broken:
    def set_value(self, v):
        value = v          # 局部变量，方法结束就没了

    def get_value(self):
        return value       # NameError，value 在这个作用域根本不存在

b = Broken()
b.set_value(42)
print(b.get_value())
# 输出：NameError: name 'value' is not defined
```

**为什么这样设计**

Python 的作用域规则决定了：函数内部出现的赋值语句会让该名字成为局部变量（除非另有 `global`/`nonlocal` 声明）。方法本质上是定义在类命名空间的函数，方法体内的赋值遵循同样的规则——`name = x` 定义局部变量 `name`，不会"穿透"到实例属性。要写到实例上，必须显式 `self.name = x`。

这与 Java/C++ 截然不同。C++ 的成员函数内可以直接写 `count = start`，编译器知道 `count` 是成员变量，会自动绑定 `this->count`。Python 不做这种推断，一切必须显式。

**类属性 vs 实例属性：不带 self 的另一种含义**

注意，在 `class` 主体中（不在方法内）直接写的赋值，是类属性，不是实例属性：

```python
class Config:
    timeout = 30            # 类属性，所有实例共享
    retries = 3

    def __init__(self, name):
        self.name = name    # 实例属性，每个实例独立

a = Config("a")
b = Config("b")

print(a.timeout, b.timeout)
# 输出：30 30

a.timeout = 60              # 给 a 创建实例属性 timeout，遮蔽类属性
print(a.timeout, b.timeout, Config.timeout)
# 输出：60 30 30
```

类属性 `timeout` 定义在 `class` 主体里，不在任何方法内，不带 `self`。它是属于类的，所有实例通过 `self.timeout`（或 `a.timeout`）能读到同一个值。注意它能被读取，但直接在实例上赋值 `a.timeout = 60` 会创建一个同名的实例属性，遮蔽类属性，不会修改类属性本身。这是另一套机制，关键还是那句话：**方法体内不带 `self` 的赋值不会成为实例属性，而是局部变量**。

### 2.8 未绑定方法：手动传 self

前面提到，通过类访问方法得到的是「未绑定」的原始函数，必须手动传 `self`。这一节深入讲这种「未绑定方法」的使用场景和注意点。

在 Python 3 中，通过类访问实例方法得到的就是一个普通的 `function` 对象（Python 2 中叫「未绑定方法 unbound method」，3 里取消了这一类型，合并为普通函数）。调用它时第一个参数必须是要操作的对象。

```python
class Echo:
    def echo(self, msg):
        return f"<{self.tag}> {msg}"

e = Echo()
e.tag = "INFO"

# 绑定方式：通过实例，自动传 self
print(e.echo("hello"))
# 输出：<INFO> hello

# 未绑定方式：通过类，手动传 self（也就是 e）
print(Echo.echo(e, "hello"))
# 输出：<INFO> hello
```

**什么时候会用到未绑定方式**

日常编码几乎总是用绑定方式（`obj.method(...)`），更简洁直观。未绑定方式在以下场景出现：

1. **显式调用父类方法**：`super().method(...)` 内部其实就是在用未绑定形式调用父类的方法并传入当前实例。手写类似 `Parent.method(self, ...)` 也是合法的（虽然推荐用 `super()`）。

```python
class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        Animal.__init__(self, name)   # 手动传 self 调用父类初始化
        self.breed = breed

d = Dog("Rex", "Lab")
print(d.name, d.breed)
# 输出：Rex Lab
```

2. **把方法当函数传递**：需要把某个实例方法当成普通函数传给回调时，可以传 `ClassName.method` 并保证调用时第一个参数是对象。更常见的是直接传 `obj.method`（已绑定），但理解未绑定形式有助于排查问题。

3. **理解机制**：从教学角度，未绑定形式揭示了「self 只是第一个参数」这一本质。

**忘记传 self 的常见错误**

```python
class Printer:
    def print_msg(self, msg):
        print(msg)

p = Printer()

# 错误：通过类调用但忘了传 self
try:
    Printer.print_msg("hello")
except TypeError as ex:
    print(f"Error: {ex}")
# 输出：Error: print_msg() missing 1 required positional argument: 'msg'
```

这个错误信息提示"缺少 `msg` 参数"，原因是 `Printer.print_msg("hello")` 把 `"hello"` 当成了 `self`，于是真正需要的 `msg` 缺失。新手常常被这种错误信息迷惑，以为是 `msg` 没传，其实是 `self` 没传。识别要点：当你通过类直接调用方法时，永远要记得多传一个对象作为第一个参数。

## 3. 最佳实践

### 3.1 始终使用 self 这个名字

**推荐**：实例方法的第一个参数永远叫 `self`。

```python
class Good:
    def method(self, x):
        self.process(x)
```

**不推荐**：改成 `this`、`me`、`obj` 等名字。

```python
class Bad:
    def method(this, x):       # 能跑，但违反社区约定
        this.process(x)
```

**原因**：PEP 8 明确要求使用 `self`。所有 Python 标准库、主流第三方库、IDE 模板都用 `self`。改名只会让代码与其他代码格格不入，增加阅读和理解负担，没有任何收益。

### 3.2 方法体内不要省略 self 前缀

**推荐**：访问实例属性一律带 `self.`。

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

    def double(self):
        self.balance *= 2     # 清晰：实例属性
```

**不推荐**：期望省略 `self` 自动访问实例属性（Python 不支持这种行为）。

```python
class Account:
    def __init__(self, balance):
        self.balance = balance

    def double(self):
        balance *= 2          # 错：这是局部变量，与实例属性无关
```

**原因**：Python 不像 Java/C++ 那样在方法体内隐式查找成员变量。`self.` 是访问实例属性的唯一通道，省略会直接得到局部变量或 NameError。

### 3.3 在 __init__ 中初始化所有实例属性

**推荐**：在 `__init__` 里集中声明并初始化实例会拥有的全部属性，即使初值为 `None`。

```python
class User:
    def __init__(self, name):
        self.name = name
        self.email = None       # 先占位，后续由 set_email 赋值
        self.login_count = 0

    def set_email(self, email):
        self.email = email
```

**不推荐**：在多个方法里零散地"动态"添加实例属性。

```python
class User:
    def __init__(self, name):
        self.name = name        # 只有 name，其他属性在哪是个谜

    def set_email(self, email):
        self.email = email      # 读代码的人不知道 User 还有 email 属性

    def login(self):
        self.login_count = 0    # 第一次 login 时才创建，隐蔽
        self.login_count += 1
```

**原因**：在 `__init__` 集中初始化能让读者一眼看清"这个类的实例有哪些属性"，也方便 IDE 的自动补全和类型检查工具分析。动态添加属性会让对象的结构难以追踪，是面向对象代码的坏味道。

### 3.4 区分实例属性和类属性的使用场景

**推荐**：实例自己的可变状态用 `self.x` 存；所有实例共享的不可变配置用类属性存。

```python
class GameConfig:
    max_players = 4             # 类属性：所有游戏共享的常量

    def __init__(self, room_id):
        self.room_id = room_id  # 实例属性：每个房间独有
        self.players = []       # 实例属性：可变状态
```

**不推荐**：把每个实例独立的数据放在类属性里。

```python
class GameConfig:
    players = []                # 错：类属性，所有实例共享同一个 list！
```

这种写法的陷阱是：`GameConfig.players` 是一个类级别的 list，所有实例对它的 `append` 都会作用在同一个 list 上，导致数据串台：

```python
class BadGame:
    players = []                # 类属性

g1 = BadGame()
g2 = BadGame()
g1.players.append("Alice")
print(g2.players)
# 输出：['Alice']    # g2 看到了 g1 添加的玩家，因为共享同一个 list
```

**原因**：可变默认值放在类属性上会被所有实例共享，是经典的 Python 陷阱。实例独立的可变数据必须通过 `self.x = []` 在 `__init__` 中初始化为实例属性。

### 3.5 避免在静态方法里偷偷访问实例

**推荐**：静态方法不要依赖任何实例或类的状态，纯粹作为工具函数。

```python
class Formatter:
    @staticmethod
    def format_price(amount):
        return f"${amount:,.2f}"

print(Formatter.format_price(1234567.89))
# 输出：$1,234,567.89
```

**不推荐**：把静态方法当作实例方法来用，试图通过别的方式拿到实例。

```python
class Formatter:
    @staticmethod
    def format_price(amount):
        # 静态方法没有 self，无法访问实例属性
        # 如果硬要访问，只能通过全局变量或参数传入，破坏封装
        return f"{currency_symbol}{amount}"   # currency_symbol 从哪来？
```

**原因**：静态方法设计上就是与实例无关的。如果方法需要访问实例数据，请用实例方法并使用 `self`，不要绕路。

### 3.6 链式调用要返回 self，但要谨慎

**推荐**：实现 fluent interface 时每个变更方法返回 `self`。

```python
class StringBuilder:
    def __init__(self):
        self.parts = []

    def append(self, s):
        self.parts.append(s)
        return self

    def build(self):
        return "".join(self.parts)

result = StringBuilder().append("Hello").append(", ").append("World").build()
print(result)
# 输出：Hello, World
```

**注意点**：返回 `self` 的方法意味着调用者可以继续在同一对象上链式操作。但要明确：链式调用修改的是同一个对象（而非产生新对象），如果希望不可变风格（每次返回新实例），就不应返回 `self` 而应返回新对象。两者不要混淆。

```python
# 可变风格（返回 self）：修改原对象
class MutableList:
    def __init__(self, items=None):
        self.items = list(items) if items else []

    def add(self, x):
        self.items.append(x)
        return self

# 不可变风格（返回新实例）：不改原对象
class ImmutableList:
    def __init__(self, items=None):
        self.items = tuple(items) if items else ()

    def add(self, x):
        return ImmutableList(self.items + (x,))   # 返回新对象，不是 self
```

**原因**：链式调用风格本身没有问题，但调用者会依据"返回的是不是 self"判断是否修改了原对象。混淆这两种风格会导致难以排查的副作用 bug。

### 3.7 不要在 self 上存放不该存在的东西

**推荐**：实例属性应该是对象状态的合理组成部分。

```python
class HttpRequest:
    def __init__(self, url, method="GET"):
        self.url = url
        self.method = method
        self.headers = {}
```

**不推荐**：把全局配置、临时缓存、跨实例的共享数据塞到 `self` 上。

```python
class HttpRequest:
    _cache = {}                 # 类属性：用作跨实例缓存，放在类上合理

    def __init__(self, url):
        self.url = url
        self.global_counter = 0  # 错：这是"全局"概念，不该每个实例各存一份
```

**原因**：`self` 是实例状态的载体，应该只存放"属于这个实例"的数据。跨实例共享的计数器、缓存、配置应该放在类属性或模块级变量，避免每个实例冗余存储，也避免数据不一致。

## 4. 原理

### 4.1 实例方法本质是定义在类 __dict__ 的普通函数

要真正理解 `self`，必须先理解"实例方法到底是什么"。一个反直觉但关键的事实：**在 Python 中，实例方法在类定义执行时，就是被存进类的 `__dict__` 里的普通函数对象**，和你在模块顶层写的函数没有任何类型上的区别。

验证这一点：

```python
class Demo:
    def method(self, x):
        return x * 2

# 查看 Demo.__dict__ 里的 method 是什么类型
print(type(Demo.__dict__["method"]))
# 输出：<class 'function'>

# 和顶层函数对比
def top_func(x):
    return x * 2

print(type(top_func))
# 输出：<class 'function'>

# 它们是同一种对象
print(Demo.__dict__["method"] is Demo.method if False else "见下文")
```

`Demo.method` 在通过类访问时，由于函数对象本身就是描述符，触发描述符协议后返回的也是同一个 function（在 Python 3 里通过类访问与通过 `__dict__` 取原始对象得到的表现一致或近似）。关键结论：**方法定义体在类里，本质上就是把一个普通函数对象放进类的命名空间**。它之所以能"自动绑定"，不是因为它是一种特殊的方法类型，而是因为「函数对象实现了描述符协议」。

```python
class Demo:
    def method(self, x):
        return x * 2

# 函数对象实现了 __get__，是描述符
print(hasattr(Demo.method, "__get__"))
# 输出：True

# 直接从 __dict__ 取出原始函数
raw = Demo.__dict__["method"]
print(raw)
# 输出：<function Demo.method at 0x...>
```

所以，「实例方法 = 定义在类 `__dict__` 里的普通函数」。这个普通函数之所以能表现出"自动传 self"的行为，是因为它实现了描述符协议，在「通过实例访问」时会被绑定。

### 4.2 描述符协议：绑定机制的核心

描述符协议是 Python 属性访问的底层机制。一个对象如果定义了 `__get__`、`__set__`、`__delete__` 中的任意一个方法，它就是一个描述符。函数对象默认定义了 `__get__`，因此函数是描述符。

当你执行 `obj.method` 时，Python 内部发生的事情（简化版）：

1. 在 `obj` 的类型（也就是类 `Demo`）的 `__dict__` 里查找 `method`。
2. 找到的对象（函数）是一个"数据描述符"或"非数据描述符"。函数只实现了 `__get__`，是非数据描述符。
3. Python 调用该描述符的 `__get__(obj, type(obj))` 方法。
4. 函数的 `__get__` 返回一个「绑定方法（bound method）」对象，把 `obj` 预先绑定进去。

当你执行 `Demo.method`（通过类访问）时：

1. 在 `Demo.__dict__` 里查找 `method`，得到函数对象。
2. 因为是通过类访问，描述符的 `__get__` 被调用为 `__get__(None, Demo)`。
3. 函数的 `__get__` 在第一参数为 `None` 时返回函数自身（不绑定），所以得到原始函数。

用代码观察绑定方法对象：

```python
class Demo:
    def method(self, x):
        return x * 2

d = Demo()

# 通过实例访问：得到绑定方法
bound = d.method
print(type(bound))
# 输出：<class 'bound method' 或 'method'>

print(bound)
# 输出：<bound method Demo.method of <__main__.Demo object at 0x...>>

# 绑定方法记住了它绑定的对象
print(bound.__self__ is d)
# 输出：True

print(bound.__func__ is Demo.__dict__["method"] or "近似相等")
# 输出：近似相等   （绑定的底层函数与类里定义的函数是同一个）
```

绑定方法对象有两个关键属性：

- `__self__`：被绑定的实例（这里是 `d`）。
- `__func__`：底层原始函数（类 `__dict__` 里的那个函数）。

当你调用 `bound(x)` 时，Python 实际执行的是 `bound.__func__(bound.__self__, x)`——也就是把 `__self__` 作为第一个参数传进原始函数。这就是"自动传 self"的真相：**绑定方法在创建时就把实例预填到了第一个参数位置，调用时只是把后续参数追加进去**。

手动模拟这个绑定过程：

```python
class Demo:
    def method(self, x):
        return self, x

d = Demo()

# 手动调用函数的 __get__
bound = Demo.__dict__["method"].__get__(d, Demo)
print(type(bound))
# 输出：<class 'method'>

# 调用绑定方法
print(bound(42))
# 输出：(<Demo object>, 42)

# 等价于直接调用原始函数并传入 d
raw = Demo.__dict__["method"]
print(raw(d, 42))
# 输出：(<Demo object>, 42)
```

可以看到，`bound(42)` 与 `raw(d, 42)` 结果完全一致。绑定方法只是把 `d` 提前"包"了进去。

### 4.3 Python 不是"自动 self"，而是在绑定阶段传入

有一个常见的误解：「Python 调用实例方法时自动给 self 赋值」。更准确的描述是：**Python 在「通过实例访问方法」这一步就完成了 self 的预填，调用方法时并没有额外的"自动传参"动作**。

分两步看：

- **访问阶段** `obj.method`：触发描述符 `__get__`，产生绑定方法对象，`__self__` 被设为 `obj`。这一步已经把"self 是谁"确定下来了。
- **调用阶段** `bound(x)`：把 `x` 追加到 `__self__` 之后，调用底层函数 `func(__self__, x)`。这一步没有再"自动"什么，参数列表早在访问阶段就固定了。

换句话说，`self` 的"自动"发生在访问阶段，不发生在调用阶段。验证：

```python
class Demo:
    def method(self, x):
        return x

d = Demo()

# 访问阶段就产生绑定方法，self 已固定为 d
m = d.method
print(m.__self__ is d)
# 输出：True

# 即使后面 d 被重新赋值（变量 d 指向别处），m 绑定的仍是原对象
d = Demo()
print(m.__self__ is d)
# 输出：False   （m 绑定的是最初的那个对象，不是新的 d）
```

`m` 在 `d.method` 这一步就"捕获"了当时的对象。之后变量 `d` 指向新对象并不影响 `m` 已绑定的 `__self__`。这证明绑定发生在访问阶段，调用 `m(42)` 时 self 早已确定。

### 4.4 与 Java 的隐式 this 对比

Java 的方法调用机制和 Python 表面上相似，但底层有很大差别。理解这种差别能加深对 `self` 的认识。

**Java 的机制**

在 Java 里，每个实例方法在编译后就隐含一个 `this` 参数，指向当前对象。方法体内直接写 `name` 时，编译器先在局部变量表找，找不到就自动转成 `this.name`。这个 `this` 是隐式的，参数列表里看不到它，方法体里也可以省略 `this.` 前缀。

```java
class Person {
    String name;
    void greet(String msg) {
        // 编译器把 name 解析为 this.name
        System.out.println(name + ": " + msg);
    }
}
```

编译后 `greet` 的字节码等价于 `greet(Person this, String msg)`，`this` 是隐式第一参数。调用 `p.greet("hi")` 时 JVM 把 `p` 作为 `this` 传入。这点和 Python 概念上类似，差别在于：

- Java 在**编译期**就确定 `name` 是成员访问，绑死在 `this` 上。
- Java 的方法不是一等对象，没有"绑定方法"这种独立的运行时对象；绑定发生在调用指令层面。
- Java 不允许把方法像函数一样取出传递（虽然有方法引用 `::` 语法糖）。

**Python 的机制**

Python 在**运行期**通过描述符协议动态绑定。函数对象和实例对象是分离的，访问 `obj.method` 时才把它们组合成一个绑定方法对象。方法体内写 `name` 绝不会自动指向 `self.name`，必须显式写 `self.name`。

```python
class Person:
    def __init__(self, name):
        self.name = name

    def greet(self, msg):
        # name 不会自动指向 self.name，必须显式
        print(f"{self.name}: {msg}")
```

两者对比：

| 方面 | Java | Python |
|---|---|---|
| 隐式/显式 | `this` 隐式，可省略前缀 | `self` 显式，不可省略 |
| 绑定时机 | 编译期确定成员访问 | 运行期描述符 `__get__` 绑定 |
| 方法对象 | 不是一等对象 | 绑定方法是一等对象，可传递 |
| 省略前缀 | 允许，编译器自动加 `this.` | 不允许，必须 `self.` |
| 参数列表体现 | 看不到 `this` | 看得到 `self` |

这种差别本质上是两种语言的设计取向：Java 偏向编译期确定、隐式便利；Python 偏向运行期动态、显式清晰。

### 4.5 字节码视角：LOAD_METHOD / CALL_METHOD 的绑定优化

Python 3.7 引入了一对专门的字节码指令 `LOAD_METHOD` 和 `CALL_METHOD`，用来优化 `obj.method(args)` 这种最常见的调用形式，避免每次都创建绑定方法对象。

用 `dis` 模块看看 `obj.method(x)` 编译成什么样的字节码：

```python
import dis

class Demo:
    def method(self, x):
        return x

def caller(obj, x):
    return obj.method(x)

dis.dis(caller)
# 输出（简化示意，具体字节码随版本有差异）：
#   LOAD_FAST    obj
#   LOAD_METHOD  method
#   LOAD_FAST    x
#   CALL_METHOD  1
#   RETURN_VALUE
```

**`LOAD_METHOD` 做了什么**

`LOAD_METHOD` 是 `LOAD_ATTR` 的方法专用变体。它在栈上放两样东西：底层函数和（如果是绑定方法的话）实例对象。具体逻辑：

1. 在对象类型里查找 `method`，得到类 `__dict__` 中的函数。
2. 如果该函数是普通函数（会触发描述符绑定），`LOAD_METHOD` 不创建绑定方法对象，而是直接把"函数 + 实例"两样压入栈。
3. 如果不是函数（比如是类方法、静态方法，或其他描述符），回退到普通的 `LOAD_ATTR` 行为，创建绑定方法对象。

**`CALL_METHOD` 做了什么**

`CALL_METHOD n` 把栈上的"函数 + 实例 + n 个参数"组合起来调用：相当于 `func(self, arg1, ..., argn)`，但全程没有创建 bound method 这一中间对象。

**为什么这是优化**

在旧机制（Python 3.7 之前）里，`obj.method(x)` 会：

1. `LOAD_ATTR method` → 调用函数的 `__get__`，创建一个绑定方法对象（包含 `__self__` 和 `__func__`）。
2. `CALL_FUNCTION 1` → 调用绑定方法，内部再调 `func(self, x)`。

每次调用都要创建一个临时绑定方法对象，调用结束后丢弃，造成不必要的内存分配和 GC 压力。`LOAD_METHOD`/`CALL_METHOD` 跳过了绑定方法对象的创建，直接把 `self` 作为第一参数传给底层函数。对于 `obj.method(x)` 这种高频模式，节省了大量临时对象。

**验证优化效果**

```python
class Demo:
    def method(self, x):
        return x

d = Demo()

# 单独访问 d.method 仍会创建绑定方法对象
m = d.method
print(type(m))
# 输出：<class 'method'>  （绑定方法对象）

# 但在 d.method(x) 这种"立即调用"的形式下，CPython 走优化路径
# 不创建绑定方法对象（这一优化对用户透明，行为一致）
result = d.method(42)
print(result)
# 输出：42
```

对使用者来说，`d.method(42)` 和 `m = d.method; m(42)` 行为完全一致，只是前者在 CPython 内部走了更快的路径。这也是为什么在性能敏感场景推荐直接写 `obj.method(x)` 而不是先取出方法再调用。

**这个优化与 self 的关系**

`LOAD_METHOD`/`CALL_METHOD` 的存在进一步印证了一个事实：**「自动传 self」不是调用时发生的魔法，而是访问机制的一部分**。优化后的字节码里，`self` 是 `LOAD_METHOD` 阶段就和函数一起被放到栈上的，`CALL_METHOD` 只是按位置传参。整个过程中 `self` 始终是一个普通的参数位置，没有任何特殊对待。这从底层证明了本篇的核心论点：`self` 不是关键字，不是隐式注入，它就是实例方法的第一个参数，由访问/绑定机制负责填入。

### 4.6 描述符协议的完整视角：函数作为非数据描述符

把前面的描述符细节再补完整。Python 的属性访问顺序大致如下：

对于 `obj.attr`：

1. 在 `type(obj)` 的 MRO 中查找 `attr`，如果找到的是**数据描述符**（同时定义了 `__get__` 和 `__set__`/`__delete__`），调用其 `__get__`，返回结果。
2. 在 `obj.__dict__` 中查找 `attr`，如果找到，返回它。
3. 在 `type(obj)` 的 MRO 中查找 `attr`，如果找到的是**非数据描述符**（只定义了 `__get__`）或普通值，非数据描述符调用 `__get__`，普通值直接返回。
4. 都没找到，抛 `AttributeError`（或触发 `__getattr__`）。

函数只定义了 `__get__`，是**非数据描述符**。这意味着：如果实例自己的 `__dict__` 里也有同名属性，实例属性会遮蔽方法（因为非数据描述符优先级低于实例 `__dict__`）。

```python
class Demo:
    def method(self):
        return "from method"

d = Demo()
print(d.method())
# 输出：from method

# 在实例 __dict__ 里塞一个同名属性，遮蔽方法
d.method = lambda: "from instance __dict__"
print(d.method())
# 输出：from instance __dict__

# 但通过类访问仍能拿到原始函数
print(Demo.method)
# 输出：<function Demo.method at 0x...>
```

这个细节解释了为什么实例可以"覆盖"方法名：因为函数是非数据描述符，优先级低于实例 `__dict__`。反之，像 `property` 这种数据描述符（同时实现了 `__get__` 和 `__set__`）会优先于实例 `__dict__`，所以 property 不会被实例同名属性遮蔽。

对于 `self` 机制而言，关键结论是：**实例方法的"自动绑定"是函数作为非数据描述符的 `__get__` 行为**。掌握了这一点，你就能理解 `obj.method` 与 `Class.method` 的所有差异，也能解释各种"奇怪"现象（比如实例属性遮蔽方法、方法赋值给实例变量后不再自动绑定等）。

### 4.7 绑定方法的细节：__self__ 与 __func__

绑定方法对象是 `types.MethodType` 的实例，它内部由两部分组成：

```python
import types

class Demo:
    def method(self, x):
        return x

d = Demo()
m = d.method

print(isinstance(m, types.MethodType))
# 输出：True

print(m.__self__ is d)
# 输出：True

print(m.__func__ is Demo.__dict__["method"])
# 输出：True   （底层函数就是类里定义的那个函数对象）
```

当你调用 `m(42)`，Python 执行的等价操作是：

```python
# m(42) 等价于
m.__func__(m.__self__, 42)
```

`__func__` 是底层函数，`__self__` 是绑定的实例。这个模型非常简单：绑定方法就是个「预填了第一参数的函数包装」。理解了它，前面讲的"自动传 self"就再没有魔法可言。

类方法（`@classmethod`）的绑定方法略有不同：`__self__` 是类本身而非实例：

```python
class Demo:
    @classmethod
    def cls_method(cls):
        return cls

m = Demo.cls_method
print(m.__self__ is Demo)
# 输出：True
print(m.__func__)
# 输出：<function Demo.cls_method at 0x...>
```

这也是为什么类方法无论通过类还是实例调用，`cls` 都是类——它的绑定方法对象在创建时就把 `__self__` 设成了类。

## 5. 总结

### 5.1 本文内容要点

- `self` 是当前正在被操作的实例对象的引用，是实例方法的第一个形参。它不是关键字，只是按约定使用的参数名。
- 调用 `obj.method(x)` 时，Python 自动把 `obj` 作为 `self` 传入，等价于 `Class.method(obj, x)`。这种"自动"实质是描述符协议在访问阶段产生的绑定，不是调用时的魔法注入。
- `self` 与 `cls` 的区别：`self` 指向实例（实例方法），`cls` 指向类（类方法）。静态方法两者都没有。
- `self` 名字只是约定，可改但不建议。PEP 8 要求实例方法第一个参数始终叫 `self`。
- `self` 是方法访问/修改实例属性的唯一通道：`self.attr` 读实例属性，`self.attr = v` 写实例属性。方法体内不带 `self` 的赋值只是局部变量，不会成为实例属性。
- 显式 `self` 体现了 Python「显式优于隐式」的哲学，与 Java 隐式 `this` 形成对比。
- 实例方法本质是定义在类 `__dict__` 里的普通函数对象；函数实现了 `__get__`，是非数据描述符，访问 `obj.method` 时触发绑定，产生绑定方法对象（`__self__` + `__func__`）。
- Python 3.7 引入 `LOAD_METHOD`/`CALL_METHOD` 字节码，对 `obj.method(x)` 这种立即调用做优化，跳过绑定方法对象的创建，直接把 `self` 作为第一参数传给底层函数。

### 5.2 读完应能掌握

- 能说明为什么 `obj.method(x)` 与 `Class.method(obj, x)` 完全等价，并能用代码验证。
- 能解释 `self` 是普通参数而非关键字，并说明为什么实际编码中仍必须使用 `self` 这个名字。
- 能区分实例方法、类方法、静态方法三者的第一参数（`self`/`cls`/无）及各自绑定的对象。
- 能识别"方法体内不带 `self` 的赋值是局部变量"这一陷阱，并写出正确的实例属性初始化代码。
- 能复述描述符协议在 `obj.method` 访问中的作用：函数的 `__get__` 返回绑定方法对象，把 `obj` 设为 `__self__`，调用时执行 `__func__(__self__, ...)`。
- 能说明 Java 的隐式 `this` 与 Python 显式 `self` 的三点以上核心差异。
- 能说出 `LOAD_METHOD`/`CALL_METHOD` 优化的目的：避免在立即调用场景创建临时绑定方法对象，把 `self` 直接作为第一参数传给函数。
- 能在阅读面向对象代码时，准确判断每个 `self.xxx` 指向的是实例属性还是（通过实例访问的）类属性，并理解非数据描述符优先级低于实例 `__dict__` 带来的遮蔽行为。
