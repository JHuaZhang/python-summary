# 比较运算符在条件中的应用

## 1. 介绍

### 1.1 什么是比较运算符

条件判断的核心是"根据某个情况决定做不做某事"。但"情况"通常不是一个现成的 `True`/`False`——它往往是两个值之间的关系："年龄够不够 18"、"密码对不对"、"温度高不高 37.3"。要把这些"两个值的关系"翻译成 `if` 能用的布尔结果，就需要**比较运算符**。

比较运算符是一组用来比较两个值关系的符号，它们接收两个操作数，返回一个布尔值：关系成立返回 `True`，不成立返回 `False`。Python 提供了六个比较运算符：`==`（等于）、`!=`（不等于）、`<`（小于）、`>`（大于）、`<=`（小于等于）、`>=`（大于等于）。它们是条件分支里最基础、最高频的"判断原料"——`if`、`elif` 后面写的条件，绝大多数都是用比较运算符拼出来的。

**一句话定位**：比较运算符把"两个值之间的关系"转成 `True`/`False`，是给 `if` 条件喂布尔结果的最常用工具。

### 1.2 最简示例

先用一个最小例子看清比较运算符在条件里怎么用：判断年龄是否成年。

```python
age = 20

if age >= 18:            # >= 比较，20 >= 18 成立 → True → 执行这一支
    print("已成年")
else:
    print("未成年")
```

**运行结果**：

```text
已成年
```

`age >= 18` 就是一个比较表达式：拿 `age`（20）和 18 用 `>=` 比较。20 大于等于 18，关系成立，表达式求值为 `True`，于是 `if` 命中，打印"已成年"。如果把 `age` 改成 15，`15 >= 18` 不成立，表达式变成 `False`，`if` 不命中，走 `else` 打印"未成年"。比较运算符做的就是这个"把关系转成布尔"的活儿。

### 1.3 六个运算符速览

Python 的六个比较运算符整体如下，先建个总印象，后面逐个展开：

| 运算符 | 含义 | 成立时返回 | 典型场景 |
|--------|------|-----------|---------|
| `==` | 等于 | 两边值相等 → `True` | 判断密码对不对、键在不在 |
| `!=` | 不等于 | 两边值不等 → `True` | 判断两个值不同、数据有变化 |
| `<` | 小于 | 左 < 右 → `True` | 严格小于的区间判断 |
| `>` | 大于 | 左 > 右 → `True` | 严格大于的阈值判断 |
| `<=` | 小于等于 | 左 ≤ 右 → `True` | 含边界的区间下限 |
| `>=` | 大于等于 | 左 ≥ 右 → `True` | 含边界的区间上限 |

几个要点先记在心里，后面逐一展开：

- 六个运算符**都返回 `True` 或 `False`**，可直接放进 `if` 条件里。
- `==` 比较的是"值是否相等"，不是"是不是同一个对象"——判断对象同一性另有 `is`。
- `<` `>` 这组大小比较，要求两边类型兼容，跨类型可能报 `TypeError`。
- 比较运算符可以**链式**连写，如 `9 <= hour <= 18`，等价于先比左边再比右边。
- 比较结果是货真价实的 `bool` 类型，可以存进变量、参与逻辑运算。

## 2. 核心内容

### 2.1 相等性比较：== 与 !=

`==` 判断两个值是否相等，`!=` 判断是否不相等。它们是条件里出现频率最高的两个——判断"对不对"、"在不在"、"有没有变化"都靠它们。

**数字相等性**：

```python
print(3 == 3)        # True，整数自等
print(3 != 4)        # True，3 不等于 4
print(3 == 3.0)      # True，int 与 float 数值相等即为 True
print(0 == False)    # True，False 在数值上等价于 0
```

**运行结果**：

```text
True
True
True
True
```

注意第三个：`3 == 3.0` 为 `True`，因为 `==` 比较的是**数值是否相等**，不关心一个是 `int` 一个是 `float`。第四个体现了布尔值在比较时被当作数字——`False` 等价于 0，`True` 等价于 1。

**字符串相等性（大小写敏感）**：

```python
print("abc" == "abc")    # True，内容完全一致
print("abc" == "ABC")    # False，大小写不同
print("abc" != "abcd")   # True，长度不同自然不等
```

**运行结果**：

```text
True
False
True
```

字符串的 `==` 是逐字符比的，连大小写都要一致才算相等。`"abc"` 和 `"ABC"` 虽然字母相同，但大小写不同，`==` 判定为不等。这一点在做用户输入校验时要特别留心——用户敲了 `"Yes"`，你拿 `"yes"` 去比，会得到 `False`。

**容器相等性：按内容逐元素比较**：

```python
print([1, 2, 3] == [1, 2, 3])   # True，元素和顺序都一致
print([1, 2, 3] == [3, 2, 1])   # False，顺序不同
print((1, 2) == [1, 2])         # False，类型不同（tuple vs list）
```

**运行结果**：

```text
True
False
False
```

容器的 `==` 比的是**内容**：把两边元素按位置逐个比，全部相等且顺序一致才算相等。但类型不同的容器即使内容一样也不等——元组 `(1, 2)` 和列表 `[1, 2]` 是不同类型，`==` 返回 `False`。

### 2.2 大小比较：< > <= >=

`<` `>` `<=` `>=` 用于判断大小关系，最常用于数值的区间判断和阈值判断。

**数字大小比较**：

```python
print(3 < 5)     # True
print(5 > 3)     # True
print(5 <= 5)    # True，等于时 <= 也成立
print(5 >= 5)    # True
print(5 < 5)     # False，< 是严格小于，等于时不成立
```

**运行结果**：

```text
True
True
True
True
False
```

`<=` 和 `<` 的区别在于边界：当两边相等时，`<=` 返回 `True`（"小于或等于"），`<` 返回 `False`（"严格小于"）。做区间判断时，如果边界值要算进区间内，就用 `<=` `>=`；如果要排除边界，就用 `<` `>`。这是最容易记混的一个点。

**字符串的字典序比较**：

```python
print("apple" < "banana")   # True，a 在 b 前
print("python" < "java")    # False，p 在 j 后
print("abc" < "abcd")       # True，前缀相同，短的是前缀较小
```

**运行结果**：

```text
True
False
True
```

字符串也能用 `<` 比大小，规则是**字典序**（按 Unicode 码点逐字符比）：从左到右逐个字符比较，第一次出现不同字符时，码点小的那个字符串较小；如果一直相同，短的字符串较小。`"apple" < "banana"` 成立，因为首字符 `'a'` 的码点小于 `'b'`。

### 2.3 比较结果的本质：返回 bool，直接当条件

比较运算符求值后得到的是一个 `bool` 类型的值——不是 1/0，不是"成立/不成立"这种模糊描述，而是货真价实的 `True` 或 `False`。这意味着比较结果可以直接放进 `if` 条件，也可以先存进变量再用。

**直接当条件**：

```python
age = 20
if age >= 18:
    print("已成年")
```

**运行结果**：

```text
已成年
```

`age >= 18` 求值为 `True`，`if` 命中。

**先存变量再判断**：比较结果可以赋值给变量，这个变量就是一个 `bool`，之后可以反复使用。

```python
score = 85
is_passed = score >= 60     # 比较结果存进变量，is_passed 是 True
print(is_passed)            # True
print(type(is_passed))      # <class 'bool'>

if is_passed:               # bool 变量直接当条件
    print("通过")
```

**运行结果**：

```text
True
<class 'bool'>
通过
```

`is_passed = score >= 60` 这一行把比较结果 `True` 存进变量，之后 `is_passed` 就是一个 `bool`，既能 `print` 出来，也能直接当 `if` 条件。这种"先算比较、存结果、再用"的写法在需要复用判断结果时很常见。

### 2.4 数字之间的比较

数字之间的大大小小比较最直观，但有几个细节值得拎出来讲清楚。

**整数与浮点数可以互相比较**：

```python
print(3 < 3.5)      # True，int 和 float 直接比数值
print(3 == 3.0)     # True，数值相等
print(2.5 > 2.0)    # True
```

**运行结果**：

```text
True
True
True
```

`int` 和 `float` 之间比较不需要类型转换，Python 直接按数值比。`3 == 3.0` 为 `True` 正是这个原因。

**浮点数比较的精度陷阱**：

```python
b = 0.1 + 0.2
print(b)             # 0.30000000000000004
print(b == 0.3)      # False！精度误差导致不等
```

**运行结果**：

```text
0.30000000000000004
False
```

这是浮点数比较里最经典的坑：`0.1 + 0.2` 在二进制浮点表示下无法精确，结果是一个略大于 0.3 的值，所以 `== 0.3` 判定为 `False`。**比较浮点数是否相等时，不能直接用 `==`**，要用"容差比较"——判断两数之差的绝对值是否足够小。这一点在最佳实践里会详细讲。

### 2.5 字符串的字典序比较

字符串的大小比较按**字典序**进行，规则可以归纳成三句话：从头逐字符比码点，第一次分出大小就定了，全相同则短的更小。

**字母顺序与码点**：

```python
print("a" < "b")    # True，'a' 码点 97 < 'b' 码点 98
print("A" < "a")    # True，大写 'A' 码点 65 < 小写 'a' 码点 97
print("1" < "a")    # True，数字字符码点 48~57 < 字母码点
```

**运行结果**：

```text
True
True
True
```

注意 `"A" < "a"` 为 `True`——大写字母的 Unicode 码点（65~90）比小写字母（97~122）小，所以大写字母在字典序里"排前面"。这意味着按 `<` 排序时，`"Apple"` 会排在 `"apple"` 前面。如果想忽略大小写比较，要先把两边统一成同一大小写（如 `.lower()`）再比。

**多字符字符串的逐字符比较**：

```python
print("abc" < "abd")     # True，前两字符相同，第三字符 'c' < 'd'
print("abc" < "abcd")    # True，前 3 个字符相同，"abc" 更短 → 更小
print("ab" < "ac")       # True，第二字符 'b' < 'c'
```

**运行结果**：

```text
True
True
True
```

比较 `"abc"` 和 `"abd"` 时，前两个字符 `'a'`、`'b'` 都相同，比到第三字符 `'c'` 与 `'d'`，`'c'` 码点小，所以 `"abc"` 较小。比较 `"abc"` 和 `"abcd"` 时，前三个字符全相同，但 `"abc"` 是 `"abcd"` 的前缀，更短的较小。这就是字典序的完整规则：先逐字符比码点，分不出胜负就比长度。

### 2.6 不同类型之间的比较规则

比较运算符对不同类型有不同的"脾气"：`==` `!=` 很包容，跨类型比较永远不报错，顶多返回 `False`；而 `<` `>` 这组大小比较就挑剔得多，类型不兼容时直接抛 `TypeError`。

**相等性 `==` 跨类型：永远不报错**：

```python
print(1 == "1")          # False，数字和字符串内容不同
print(1.0 == True)       # True，True 等价于 1
print([1, 2] == (1, 2))  # False，list 和 tuple 类型不同
```

**运行结果**：

```text
False
True
False
```

`==` 遇到类型不同的两个对象时，能比就比、比不了就返回 `False`，但**不会报错**。这让它非常适合" safely 探测两个值是否相等"，不必担心类型不匹配会崩溃。

**大小比较 `<` 跨类型：可能 `TypeError`**：

```python
print(3 < 3.5)           # True，int 和 float 可互相比较
print(1 < True)          # False，bool 被当成数字（True=1）

try:
    1 < "1"              # ❌ 数字和字符串无法比大小
except TypeError as e:
    print(f"TypeError: {e}")
```

**运行结果**：

```text
True
False
TypeError: '<' not supported between instances of 'int' and 'str'
```

数字和字符串做 `<` 比较直接抛 `TypeError`——Python 不知道"1 比 '1' 大还是小"，于是拒绝比较。`2 > True` 能跑是因为布尔值被当作数字（`True` 等价于 1）。**想跨数字和字符串比大小，必须先显式做类型转换**，比如 `int("1") < 2` 或 `str(1) < "2"`。

把规则整理成一张表方便记忆：

| 比较种类 | 跨类型表现 | 是否报错 |
|---------|-----------|---------|
| `==` `!=` | 能比就比，比不了返回 `False` | 不报错 |
| `<` `>` `<=` `>=`（数字之间 int/float/bool） | 直接按数值比 | 不报错 |
| `<` `>` 等（数字 vs 字符串等不兼容类型） | 无法比较 | `TypeError` |
| `<` `>` 等（同类型，如字符串 vs 字符串） | 按各自规则比 | 不报错 |

### 2.7 布尔值参与比较

布尔值在比较运算里会被当作数字：`True` 等价于 `1`，`False` 等价于 `0`。这一点既能带来便利，也容易埋下陷阱。

```python
print(True == 1)        # True
print(False == 0)       # True
print(True + True)      # 2，布尔能当数字参与算术
print(True < 2)         # True，True 当成 1，1<2 成立
```

**运行结果**：

```text
True
True
2
True
True
```

因为 `True == 1`，所以 `if x == True:` 在 `x` 为 1 时也会命中——这通常是无意为之的 bug。更推荐直接写 `if x:`（当 `x` 本身是布尔时），或者用更精确的比较。把布尔当数字用虽然能跑，但会降低可读性，最好把"判断真值"和"比数值大小"这两件事分开做。

### 2.8 容器的逐元素比较

列表、元组等序列容器之间用 `<` `>` 比大小时，Python 采用**逐元素比较**（lexicographic）：从左到右逐个比对应位置的元素，第一次分出大小就定了整个比较结果。

```python
print([1, 2, 3] < [1, 2, 4])   # True，前两个相等，第三元素 3<4
print([1, 2] < [1, 2, 3])      # True，前缀相同，短的更小
print([1, 2, 3] < [1, 2, 3])   # False，完全相等
print([1, 9] < [1, 10])        # True？9<10 成立
```

**运行结果**：

```text
True
True
False
True
```

这里的规则和字符串字典序完全一致：逐位比，分出胜负即止；都相同则短的较小。注意 `[1, 9] < [1, 10]` 比的是第二元素 `9` 与 `10`——**是按数值比，不是按字符比**，所以 `9 < 10` 成立，结果是 `True`（如果是字符串 `"9"` 和 `"10"` 比，反而 `"9" > "10"`，因为 `'9'` 码点大于 `'1'`）。这是容器比较和字符串比较的一个关键区别：容器里存的是数字就按数字比，存的是字符串才按字符串比。

### 2.9 链式比较写法

Python 允许把多个比较连着写，比如 `9 <= hour <= 18`，这种写法叫**链式比较**。它比拆成 `9 <= hour and hour <= 18` 更简洁，也更接近数学里的区间写法。

```python
hour = 14

if 9 <= hour <= 18:          # 链式比较，等价于 9<=hour and hour<=18
    print("工作时间")
else:
    print("非工作时间")
```

**运行结果**：

```text
工作时间
```

链式比较的求值顺序是从左到右：先算 `9 <= hour`（`True`），再算 `hour <= 18`（`True`），两边都为真整体才为真。它和 `and` 拼接的写法语义等价，但 `hour` 只被求值一次——如果 `hour` 是个有副作用的函数调用，链式写法更安全。链式比较也可以 mix 运算符，如 `0 < x < 1` 表示 `x` 在 0 到 1 之间。

### 2.10 典型应用场景

比较运算符在条件里的应用模式可以照搬到很多业务场景。

#### 2.10.1 范围判断

判断一个值落在哪个区间，是比较运算符最常见的用法。按严格度从高到低排好顺序，用 `elif` 串成互斥链：

```python
def temperature_advice(temp):
    if temp <= 0:
        return "冰点以下，防冻"
    elif temp < 15:
        return "寒冷，保暖"
    elif temp < 28:
        return "舒适"
    elif temp < 40:
        return "高温，防暑"
    else:
        return "极端高温"

for t in [-2, 8, 22, 35, 45]:
    print(f"  {t}°C → {temperature_advice(t)}")
```

**运行结果**：

```text
  -2°C → 冰点以下，防冻
  8°C → 寒冷，保暖
  22°C → 舒适
  35°C → 高温，防暑
  45°C → 极端高温
```

区间判断的关键是**把含边界的条件交给 `<=` `>=`，排除边界的用 `<` `>`**，然后按严格度排好顺序，靠 `elif` 的命中即停隐式获得下界。

#### 2.10.2 判断重复与去重

判断两个值是否相同、检测数据是否变化，都靠 `==`：

```python
old_password = "abc123"
new_password = "abc123"

if new_password == old_password:
    print("新密码不能与旧密码相同")
else:
    print("密码已更新")
```

**运行结果**：

```text
新密码不能与旧密码相同
```

#### 2.10.3 数值边界校验

校验输入是否在合法范围内，是 `>=` `<=` 的强项，常配合链式比较一次表达上下界：

```python
def validate_score(score):
    if 0 <= score <= 100:        # 链式比较一次验证上下界
        return "成绩合法"
    return "成绩必须在 0~100 之间"

for s in [85, -5, 120, 0, 100]:
    print(f"  {s} → {validate_score(s)}")
```

**运行结果**：

```text
  85 → 成绩合法
  -5 → 成绩必须在 0~100 之间
  120 → 成绩必须在 0~100 之间
  0 → 成绩合法
  100 → 成绩合法
```

`0 <= score <= 100` 一行就表达了"成绩在 0 到 100 之间（含边界）"，比写 `score >= 0 and score <= 100` 更简洁直观，也更不容易写错边界。

## 3. 最佳实践

### 3.1 = 与 == 千万别混

这是 Python 新手最经典的错误：把赋值 `=` 当成比较 `==` 用。`=` 是赋值运算符，`==` 才是比较运算符，两者天差地别。

```python
x = 5

# ❌ 不推荐（而且会报错）：在条件里用 = 赋值
# if x = 5:
#     print("x 是 5")    # SyntaxError: 赋值不能放进条件里

# ✅ 推荐：用 == 比较
if x == 5:
    print("x 是 5")
```

**运行结果**：

```text
x 是 5
```

Python 在这里做得比很多语言更好——它直接拒绝 `if x = 5:` 这种写法，抛 `SyntaxError`，让你立刻发现错误，而不是像 C/Java 那样把赋值结果悄悄塞进条件。记住口诀：**判断相等用 `==`（两个等号），赋值用 `=`（一个等号）**。

### 3.2 浮点数比较用容差而非 ==

浮点数在二进制下无法精确表示很多十进制小数，直接用 `==` 比较会因为微小误差得到 `False`。正确做法是用"容差比较"——判断两数之差的绝对值是否小于一个可接受的误差范围。

```python
b = 0.1 + 0.2

# ❌ 不推荐：直接用 == 比较浮点数
if b == 0.3:
    print("相等（直接比较）")
else:
    print("不相等（直接比较）")   # 实际会走这里，因为有精度误差
```

**运行结果**：

```text
不相等（直接比较）
```

```python
b = 0.1 + 0.2

# ✅ 推荐：用容差比较，差值足够小就认为相等
def almost_equal(a, b, tol=1e-9):
    return abs(a - b) < tol

if almost_equal(b, 0.3):
    print("相等（容差比较）")
```

**运行结果**：

```text
相等（容差比较）
```

容差 `tol` 取多小取决于业务精度需求，常用 `1e-9`。如果是金额计算，可能要更严格的容差；如果是传感器数据，可以放宽。核心思想是：**浮点数不存在"精确相等"，只存在"在允许误差内相等"**。

### 3.3 比较结果直接当条件，别再 == True

比较运算符返回的就是 `bool`，直接放进 `if` 即可。把布尔结果再和 `True`/`False` 比一次，是画蛇添足，还可能埋下 `1 == True` 这种意外命中的坑。

```python
temperature = 38
is_fever = temperature > 37.3

# ❌ 不推荐：把布尔结果再 == True 一次
if is_fever == True:
    print("发热（冗余写法）")

# ✅ 推荐：bool 直接当条件
if is_fever:
    print("发热（直接判断）")
```

**运行结果**：

```text
发热（冗余写法）
发热（直接判断）
```

`if is_fever == True:` 不但啰嗦，还因为 `1 == True` 为 `True`，万一 `is_fever` 意外是个数字 1，也会被当成"真"命中。直接写 `if is_fever:` 既简洁又安全。判断"布尔为假"则用 `if not is_fever:`，而不是 `if is_fever == False:`。

### 3.4 字符串比较注意大小写与空白

字符串的 `==` 是大小写敏感、连空白都要严格匹配的。用户输入常带多余空格或大小写不一致，直接 `==` 容易误判。处理前先 `strip()` 去空白、用 `lower()`/`upper()` 统一大小写。

```python
user_input = "  Yes  "

# ❌ 不推荐：直接比较，空白和大小写都会导致不等
if user_input == "yes":
    print("确认")
else:
    print("不匹配")
```

**运行结果**：

```text
不匹配
```

```python
user_input = "  Yes  "

# ✅ 推荐：先 strip 去空白，再统一大小写
if user_input.strip().lower() == "yes":
    print("确认")
```

**运行结果**：

```text
确认
```

这种"清洗后再比较"的套路在处理表单输入、命令行参数、配置值时极其常见。养成习惯：**拿用户输入做相等比较前，先想清楚是否要清洗**。

### 3.5 跨类型大小比较先想清楚类型

`==` 跨类型永远安全（最多返回 `False`），但 `<` `>` 跨不兼容类型会直接 `TypeError`。在做大小比较前，要确认两边类型兼容，必要时先做类型转换。

```python
age_str = "20"

# ❌ 不推荐：数字和字符串直接比大小会 TypeError
# if age_str >= 18:
#     print("成年")

# ✅ 推荐：先转成同类型再比
if int(age_str) >= 18:
    print("成年")
```

**运行结果**：

```text
成年
```

从外部（用户输入、文件、网络）拿到的数据经常是字符串，拿它们和数字比大小前必须先 `int()`/`float()` 转换。相等比较虽然不报错，但要留意 `1 == "1"` 是 `False`——别以为"内容看着一样"就相等，类型不同直接判 `False`。

### 3.6 常见错误模式速查表

把比较运算符里高频踩的坑汇总成一张速查表，写代码时可以对照检查：

| 错误模式 | 错误示例 | 后果 | 正确做法 |
|---------|---------|------|---------|
| `=` 当 `==` 用 | `if x = 5:` | `SyntaxError` | 比较用 `==`，赋值用 `=` |
| 浮点直接 `==` | `0.1 + 0.2 == 0.3` | 因精度误差得 `False` | 用容差比较 `abs(a-b) < tol` |
| 布尔再 `== True` | `if flag == True:` | 冗余，且 `1==True` 意外命中 | 直接 `if flag:` |
| 字符串带空白直接比 | `" yes" == "yes"` | 误判为不等 | 先 `strip()` 再比 |
| 字符串大小写不一致 | `"Yes" == "yes"` | 误判为不等 | 先 `lower()` 统一再比 |
| 数字与字符串比大小 | `1 < "2"` | `TypeError` | 先 `int()`/`str()` 转同类型 |
| `<` 当 `<=` 用 | 边界值漏掉 | 边界值未被算进区间 | 含边界用 `<=` `>=` |
| 容器 `==` 忽略顺序 | `[1,2]==[2,1]` 期望 `True` | 实际 `False` | 容器 `==` 要求顺序一致 |
| 以为 `==` 比对象同一性 | 用 `==` 判断是否同一对象 | 只比值相等不代表同一对象 | 判同一性用 `is` |

## 4. 原理

### 4.1 比较运算符的返回值类型

比较运算符求值后得到的不是 1/0 这种整数，而是 Python 的 `bool` 类型。`bool` 是 `int` 的子类——`True` 实际上就是 1，`False` 就是 0，所以 `True + 1` 能等于 2。但作为比较结果，它们就是纯粹的 `True`/`False`。

```python
result = 3 < 5
print(result)            # True
print(type(result))      # <class 'bool'>
print(isinstance(result, int))   # True，bool 是 int 的子类
print(True + True)       # 2，布尔能当数字参与运算
```

**运行结果**：

```text
True
<class 'bool'>
True
2
```

理解 `bool` 是 `int` 子类这一点，能解释很多现象：为什么 `True == 1` 成立、为什么 `True + True == 2`、为什么 `if 1:` 也能命中（1 被真值测试判为真）。也正因为如此，把布尔结果直接当条件、别再 `== True`，才能避免 `1 == True` 这种意外命中。

### 4.2 比较如何分派到魔术方法

比较运算符不是"内置魔法"，它背后对应着一组**双下划线方法**（魔术方法）。当写下 `a == b` 时，Python 实际上尝试调用 `a.__eq__(b)`；写 `a < b` 时调用 `a.__lt__(b)`。内置类型（数字、字符串、列表等）都实现了这些方法，所以能直接比较；自定义对象如果没实现，比较时就会退回到默认行为。

```python
print((3).__eq__(5))          # False，int 实现了 __eq__
print("apple".__lt__("banana"))  # True，str 实现了 __lt__
print([1, 2].__eq__([1, 2]))  # True，list 实现了 __eq__
```

**运行结果**：

```text
False
True
True
```

每个比较运算符对应一个魔术方法：

| 运算符 | 魔术方法 | 含义 |
|--------|---------|------|
| `==` | `__eq__` | 相等 |
| `!=` | `__ne__` | 不相等（默认基于 `__eq__` 取反） |
| `<` | `__lt__` | 小于 |
| `>` | `__gt__` | 大于 |
| `<=` | `__le__` | 小于等于 |
| `>=` | `__ge__` | 大于等于 |

这也解释了为什么跨类型大小比较会报 `TypeError`：数字没实现"和字符串比大小"的 `__lt__`，两边都拿不出比较方法，Python 就抛错。而 `==` 即使类型不同也只会返回 `False` 而非报错，是因为 `__eq__` 有个兜底逻辑——比不了就返回 `NotImplemented`，最终退化成"不等"。自定义类想让自己的对象能比较大小，实现对应的魔术方法即可。

### 4.3 字符串为什么能比较大小

字符串能直接用 `<` `>` 比大小，是因为 `str` 类型实现了 `__lt__` 等方法，比较规则是按**Unicode 码点**逐字符进行。每个字符在计算机里都对应一个数字（码点），比较时就是比这些数字。

```python
print(ord("a"))    # 97，'a' 的码点
print(ord("b"))    # 98，'b' 的码点
print(ord("A"))    # 65，'A' 的码点（小于 'a'）
```

**运行结果**：

```text
97
98
65
```

`"a" < "b"` 成立，本质就是 `97 < 98`。`"A" < "a"` 成立，是因为大写字母码点（65~90）整体小于小写字母（97~122）。用 `ord()` 函数可以查任意字符的码点，反过来 `chr(97)` 能把码点转回字符。理解了码点，字符串字典序的规则就一目了然：逐字符比码点大小，分出胜负即止，都相同则短的更小。这也解释了为什么按 `<` 排序时大写字母会排在小写前面——它们的码点本来就小。

## 5. 总结

本文围绕比较运算符在条件中的应用展开，主要介绍了以下内容：

- 比较运算符是什么：把"两个值之间的关系"转成 `True`/`False` 的六个符号，是给 `if` 条件喂布尔结果最常用的工具
- 六个运算符速览：`==` 等于、`!=` 不等于、`<` 小于、`>` 大于、`<=` 小于等于、`>=` 大于等于，都返回 `bool`
- 相等性比较：`==` `!=` 比的是值是否相等，大小写敏感、容器按内容逐元素比、类型不同直接判 `False`
- 大小比较：`<` `>` `<=` `>=` 按大小关系判断，`<=` 含边界而 `<` 不含，字符串按字典序比码点
- 比较结果本质：返回的是货真价实的 `bool` 类型，可直接当条件，也可存变量复用
- 数字比较：int 与 float 互相可比、浮点数有精度陷阱不能直接 `==`
- 字符串字典序：逐字符比 Unicode 码点，大写码点小于小写，前缀相同则短的更小
- 跨类型规则：`==` 跨类型永远安全不报错，`<` `>` 跨不兼容类型会 `TypeError`
- 布尔参与比较：`True` 等价 1、`False` 等价 0，`bool` 是 `int` 子类
- 容器逐元素比较：从左到右逐位比，分出胜负即止，数字按数值比而非按字符比
- 链式比较：`9 <= x <= 18` 等价 `9<=x and x<=18`，更简洁且 `x` 只求值一次
- 典型场景：范围判断、判断重复、数值边界校验，都有可照搬的写法
- 最佳实践：`=` 与 `==` 别混、浮点用容差比较、布尔别再 `== True`、字符串比前先清洗、跨类型大小先转类型
- 原理：比较结果返回 `bool`（`int` 子类）；每个运算符对应 `__eq__`/`__lt__` 等魔术方法，自定义对象可实现它们来支持比较；字符串能比大小是因为 `str` 按码点实现了比较方法，用 `ord()` 可查码点
