# 条件分支概述与基本概念

## 1. 介绍

### 1.1 什么是条件分支

你写过哪怕一段稍有逻辑的 Python 代码，几乎就一定用过条件分支。判断"分数是否及格""用户是否登录""文件是否存在"——这些"根据情况做不同处理"的需求，背后都是条件分支（conditional branch）。

条件分支是程序的一种控制结构：它让程序在执行时**先判断一个条件是否成立，再决定要不要执行某段代码、或从多条路径中选一条走**。换句话说，条件分支给了程序"做选择"的能力。

**类比**：想象一条路走到黑的高速公路，所有车都必须从起点开到终点，中途没有任何岔路——这是没有分支的顺序执行。而条件分支就像在路口放了一个指示牌："如果目的地方向在东，走左边出口；否则直行"。于是车辆到了路口会**根据自己的情况**走不同车道，不再是一条路走到底。条件分支就是给代码加上的"岔路口"。

在 Python 中，条件分支属于"控制流"（control flow）这一层——它和循环结构一起，决定了代码**以什么顺序、以什么条件**被执行，而不是某个具体的数据类型或函数。换句话说，条件分支管的是"程序往哪走"，而不是"数据是什么"。

### 1.2 为什么需要条件分支

要理解条件分支的价值，先看一个没有分支的世界。假设你写一段"根据天气给出穿衣建议"的程序：

```python
print("天气偏冷，建议带上外套")
print("天气温暖，穿单衣即可")
print("天气炎热，注意防晒")
```

不管今天温度是 5 度还是 35 度，这三行都会**全部打印**——因为代码只会从上到下逐行执行（这叫顺序结构）。可现实是，冷天不该穿单衣，热天不该带外套。没有分支时，程序就丧失了"区分情况"的能力。

引入条件分支后，同样的逻辑可以这样写：

```python
temperature = 5

if temperature < 18:
    print("天气偏冷，建议带上外套")
```

运行结果：

```text
天气偏冷，建议带上外套
```

现在只有温度低于 18 度时才会提醒带外套。把 `temperature` 改成 25，这行就**不会出现**。这就是条件分支带来的根本变化——**程序可以根据条件决定哪些代码被执行、哪些被跳过**。

真实程序几乎处处是"分情况处理"的需求：用户登录成功走一套流程、失败走另一套；分数不同给不同等级；文件存在就读取、不存在就提示。没有条件分支，这些"因地制宜"的逻辑都无从表达。可以说，**条件分支是让程序从"只会机械地按顺序做事"变成"会根据情况做事"的关键能力**。

### 1.3 最简示例

用一个最小的例子，让你一眼看到条件分支"长什么样"：

```python
score = 75

if score >= 60:
    print("及格")
```

运行结果：

```text
及格
```

这里 `if score >= 60:` 就是条件分支，`score >= 60` 是要判断的条件，`:` 后面缩进的 `print("及格")` 是条件成立时才执行的代码。把 `score` 改成 50，运行结果会变成空——什么也不打印，因为条件没成立，那行代码被跳过了。

短短两行，条件分支的核心要素全都在了：`if` 引导判断、一个条件表达式、一个冒号、一段缩进代码块。本篇要讲的就是这套机制背后的"是什么、有哪些、怎么协作"。

## 2. 核心内容

### 2.1 程序的三种控制结构：顺序、选择、循环

条件分支不是孤立存在的，它是程序三种基本控制结构之一。理解条件分支，先要把它放进"控制结构"这个更大的框架里看。

程序代码的执行顺序，归根结底只有三种组织方式：

| 控制结构 | 核心动作 | 典型语法 | 解决什么问题 |
|---------|---------|---------|------------|
| 顺序结构 | 从上到下逐行执行 | 普通语句 | 按步骤把事情做完 |
| 选择结构 | 根据条件选择执行路径 | `if` / `if-else` / `if-elif-else` | 根据情况做不同处理 |
| 循环结构 | 重复执行某段代码 | `for` / `while` | 批量、重复地做事 |

任何复杂程序，拆到底都是这三种结构的不同组合。比如"先登录，再循环读取 100 条数据，每条根据类型做不同处理"——这就是顺序（先登录后读数据）+ 循环（读 100 条）+ 选择（按类型处理）的串联。

**类比**：把三种结构比作做饭。顺序结构是"按菜谱一行行做"——洗菜、切菜、下锅，按步骤来。选择结构是"看食材决定怎么做"——如果是牛肉就红烧、如果是鱼就清蒸。循环结构是"把同样动作重复做"——饺子一个一个包，直到包完。真实做一顿饭，三种动作是穿插进行的。

三者在控制流中的关系可以这样表示：

```text
程序控制流
├── 顺序结构   → 从上到下逐行执行（默认行为）
├── 选择结构   → 条件成立才执行 / 多路择一        ← 本篇主题
└── 循环结构   → 重复执行某段代码
```

本篇聚焦其中的"选择结构"，也就是条件分支。理解了它，你就掌握了让程序"会做选择"的那一半能力。

### 2.2 条件分支的本质：判断驱动的执行

有了框架认知，再深入看条件分支的本质。一句话概括：**条件分支是"判断驱动的执行"——先算出一个判断结果，再根据结果决定走哪条路**。

这里有两个关键动作：**判断**和**执行**。判断产生一个"是或否"的结果（成立 / 不成立，真 / 假），执行则是根据这个结果决定要不要运行某段代码。可以把条件分支抽象成一个最基本的工作流程：

```text
         ┌──────────────┐
输入 →   │  计算条件     │  →  得到一个判断结果（真 / 假）
         └──────────────┘
                │
        ┌───────┴───────┐
        │               │
     为真              为假
        │               │
        ▼               ▼
   执行代码块 A     不执行（或执行备选块）
```

**类比**：条件分支就像地铁闸机。你刷卡（计算条件），闸机读取余额（判断结果）。余额充足（为真）→ 闸机开门放行（执行 A）；余额不足（为假）→ 闸机不开（不执行 A）。同样的入口，每个人的结果可能不同，于是有人通过、有人被拦。条件分支就是代码世界的"闸机"。

需要强调的是：**判断结果是"算"出来的**。`if` 后面跟的一定是一个能被求值为真或假的东西——它可以是一个比较表达式（`score >= 60`）、一个逻辑组合（`is_login and has_permission`），甚至是一个直接的对象（如一个非空字符串）。无论形式如何，Python 都会把它算成一个真值或假值，再据此决定走哪条路。弄清"条件到底是什么、怎么被判为真或假"，就是理解条件分支的钥匙。

### 2.3 三种分支结构概览：单分支、二分支、多分支

条件分支按"岔路口有几条路"分成三种基本结构。这一节给你一个全景，先记住分类和职责，具体语法细节属于更专门的主题。

分类层级关系如下：

```text
条件分支（if 语句家族）
├── 单分支  （if）             → 条件成立才执行的代码
├── 二分支  （if-else）        → 成立走一条，不成立走另一条
└── 多分支  （if-elif-else）   → 在多种互斥情况里择一执行
```

三种结构的对比：

| 结构 | 关键字 | 分叉条数 | 是否一定有代码被执行 | 适用场景 |
|------|--------|---------|-------------------|---------|
| 单分支 | `if` | 1 条 | 否（条件不成立时跳过） | 只关心"成立时做什么" |
| 二分支 | `if` `else` | 2 条 | 是（两条必走其一） | 非此即彼的二选一 |
| 多分支 | `if` `elif` `else` | 3+ 条 | 是（最多一条被执行） | 多种互斥情况择一 |

下面用一个"穿衣建议"场景，把三种结构并排写一遍，让你直观感受差异：

```python
# 场景一：单分支——只关心冷天，暖和时不做任何提醒
temperature = 5
if temperature < 18:
    print("冷天建议带外套")
# 当 temperature >= 18 时，没有任何输出
```

```python
# 场景二：二分支——冷热各走一条
temperature = 5
if temperature < 18:
    print("冷天建议带外套")
else:
    print("暖和，穿单衣即可")
# 两条路一定会走其中一条
```

```python
# 场景三：多分支——按温度区间分多种情况
temperature = 25
if temperature < 10:
    print("寒冷，穿冬装")
elif temperature < 22:
    print("凉爽，穿秋装")
elif temperature < 30:
    print("温暖，穿单衣")
else:
    print("炎热，注意防晒")
# 从上往下依次判断，命中一个就停止，只走一条
```

运行场景三的代码会打印：

```text
温暖，穿单衣
```

注意多分支的一个关键特性：**互斥择一**。`elif` 是 "else if" 的缩写，含义是"否则如果"。从上往下逐个判断，一旦某个条件命中，就执行对应代码块，**其后所有 `elif`/`else` 都不再检查**。所以 `temperature=25` 命中第三个条件（22 < 25 < 30）后，得到"温暖，穿单衣"，最后那条炎热提醒就不会再判断。这和把每个条件都写成独立 `if`（每个都要单独判断）是本质区别。

### 2.4 条件：真值测试（条件是什么）

前面一直说"判断条件是否成立"，那"条件"到底是什么？在 Python 里，`if` 后面跟的东西不一定是显而易见的 `True`/`False`。Python 有一套"真值测试"（truth value testing）机制：**任何对象都能被判定为"真"或"假"**，`if` 会用这套机制来决定走哪条路。

最常见的情况是写一个会产生布尔值的表达式——比较运算或逻辑运算的结果：

```python
age = 20
if age >= 18:
    print("成年")
```

运行结果：

```text
成年
```

这里 `age >= 18` 会被求值为 `True`，条件成立。但 Python 不要求条件必须是布尔值，它接受任何对象，并按真值测试规则判定。以下这些值在真值测试中会被判定为**假**（其余都是真）：

| 类型 | 判定为假的值 | 说明 |
|------|------------|------|
| 布尔 | `False` | 真假的另一个就是假 |
| None | `None` | "没有值"被判为假 |
| 数字 | `0`、`0.0` | 数值为零即假 |
| 序列/容器 | `""`、`[]`、`()`、`{}` | 任何空容器即假 |

```python
# 这些条件都不成立——对象都被判为假
if 0:
    print("不会执行")
if "":
    print("不会执行")
if []:
    print("不会执行")
if None:
    print("不会执行")

# 而这些都被判为真
if 3:
    print("非零数字为真")
if "hello":
    print("非空字符串为真")
if [0]:
    print("非空列表为真，哪怕只含一个 0")
```

运行结果：

```text
非零数字为真
非空字符串为真
非空列表为真，哪怕只含一个 0
```

最后一条特别值得留意：`[0]` 是一个**非空列表**，所以被判为真——哪怕它里面装的是 0。"空与非空"看的是容器的长度，不看里面的元素是否为假。如果你需要"列表里有真值元素"这种判断，要用 `any([0])`，那是另一套逻辑。

真值测试的存在让条件分支非常灵活：你不必总是写 `if len(name) > 0:`，直接 `if name:` 就够了——Python 知道空字符串代表"没东西"。但灵活也意味着要小心：把一个本意是数字相等的判断误写成 `if user_score:`（想表达"分数非零"），得到的结果是对的，可如果分数本身可能是合法的 0，就会把正常的 0 当成"假"而走错分支。真值测试的细节属于专门主题，本篇只需建立"条件可以是任意对象、Python 会自动做真假判定"这个认知。

### 2.5 条件分支的执行流程

把概念放在一起，条件分支一次完整的执行流程是这样走的：

```text
程序运行到 if 行
        │
        ▼
   计算条件表达式
        │
   得到真值 / 假值
        │
   ┌────┴────┐
   为真      为假
   │         │
   ▼         ▼
执行 if 块   检查是否有 elif
            │
   ┌────────┴────────┐
 有 elif              无 elif 只剩 else
   │                    │
   ▼                    ▼
 计算该 elif 条件     执行 else 块
   │                    │
 ┌─┴─┐                  │
 为真 为假              │
 │    │                 │
 ▼    └─→继续看下一个 elif / else
 执行该 elif 块
        │
        ▼
   分支选择结束，程序继续往后执行
```

这个流程图揭示了几个关键点：

1. **条件总是从上往下依次判断**——先算第一个 `if`，不成立才看下一个 `elif`。
2. **命中即停**——只要有一个条件成立并执行了对应代码块，其后的分支全部跳过，不再判断。
3. **最多执行一块**——无论有多少个 `elif`，一次执行中最多只有一个代码块会被运行。
4. `else` 是兜底——所有条件都不成立时，`else` 块才执行；没有 `else` 又全不成立，则什么都不执行。

用一段带跟踪打印的代码，把"哪条路真的被走了"显示出来：

```python
hour = 14

if hour < 6:
    print("走了：凌晨分支")
elif hour < 12:
    print("走了：上午分支")
elif hour < 18:
    print("走了：下午分支")
else:
    print("走了：晚上分支")
print("流程到达终点")
```

运行结果：

```text
走了：下午分支
流程到达终点
```

`14` 不满足 `hour < 6`（跳过）、不满足 `hour < 12`（跳过）、满足 `hour < 18`（命中），于是执行"下午分支"并停止后续判断，最后跳出整个 if 结构到达终点。把 `hour` 改成 3、9、21，会分别走到凌晨、上午、晚上分支——一次执行永远只走一条。

### 2.6 Python 中的条件分支工具一览

`if` 语句家族是条件分支的主力，但不是全部。Python 提供了好几种"根据条件做选择"的写法，适用场景各不相同。先建立一个全景认知，知道"有哪些工具"，再在各自专门主题里深入。

| 工具 | 形态 | 产不产生值 | 典型用途 |
|------|------|-----------|---------|
| `if` / `if-else` / `if-elif-else` | 语句 | 否（控制执行流程） | 根据条件执行一段代码块 |
| 条件表达式（三元） | `值A if 条件 else 值B` | 是（是一个值） | 在赋值/表达式里做二选一 |
| `match-case` | 语句 | 否 | 按结构化模式做多路匹配（Python 3.10+） |

需要先把"语句"和"表达式"区分清楚：**`if` 语句不产生值**，它只是控制"要不要执行某段代码"；而**条件表达式会产生一个值**，可以塞进赋值号右边或函数参数里。这是两种工具最本质的区别。

```python
# if 语句：控制执行流程，本身没有值
age = 20
if age >= 18:
    label = "成年"
else:
    label = "未成年"
print(label)
```

运行结果：

```text
成年
```

```python
# 条件表达式：直接是一个值，可以塞进赋值里，更紧凑
age = 20
label = "成年" if age >= 18 else "未成年"
print(label)
```

运行结果：

```text
成年
```

两种写法结果一样，但条件表达式把"二选一"压缩成了一行，适合简单、纯粹的"挑一个值回来"的场景。一旦每个分支里要做的事不止一个（比如还要打印日志、调用函数），就不适合塞进条件表达式，应该回到完整的 `if` 语句。

`match-case` 是 Python 3.10 引入的更强大的多路分支工具，擅长按"数据的结构"来匹配，而不仅仅是布尔条件。一个直观例子：

```python
command = "quit"

match command:
    case "start":
        print("启动")
    case "stop":
        print("停止")
    case "quit":
        print("退出")
    case _:
        print("未知命令")
```

运行结果：

```text
退出
```

这里的 `case _` 是"匹配任意值"的兜底，相当于 `if-elif-else` 里的 `else`。`match-case` 的强项不只是匹配相等值，还能对数据的结构（如列表长度、字典字段、类型）做模式匹配，写出来的多路分支比一连串 `if-elif` 更清晰。它的完整能力属于专门主题，本篇只需知道"还存在一种更强大的多路匹配工具"即可。

### 2.7 缩进与代码块：Python 分支的语法特点

讲条件分支绕不开一个 Python 特有的语法特点：**用缩进（而不是花括号）来划分代码块**。很多语言用 `{ }` 把一个分支的代码包起来，Python 用的是行首的空格缩进。

```python
score = 75

if score >= 60:
    print("及格")
    print("恭喜你")   # 这两行都属于 if 块，都缩进了
print("流程结束")     # 这行不缩进，属于 if 块之外，一定会执行
```

运行结果：

```text
及格
恭喜你
流程结束
```

把 `score` 改成 50，前两行不打印，最后一行"流程结束"依然出现——因为缩进已经说明它不受 `if` 管辖。**缩进决定了哪些行属于同一个块**，这直接影响条件分支的作用范围。

**类比**：缩进就像文章里的段落缩进，告诉你"这几句话属于同一段"。如果一行没有缩进，就相当于另起了一段，不再从属于上面的条件。Python 用这种"看得见的层级"来界定代码块，省去了花括号，让代码结构在视觉上一目了然。

关于缩进有几个要点：

- **同一块内的缩进必须一致**——不能有的行缩进 4 个空格、有的行缩进 2 个空格，否则会报 `IndentationError`。
- **约定缩进 4 个空格**——官方 PEP 8 风格指南推荐用 4 个空格，而不是 Tab。
- **缩进表"从属关系"**——缩进越深，表示越是从属于上面的条件语句。

```python
# 嵌套分支：外层走通后才能进入内层
is_login = True
role = "admin"

if is_login:
    # 下面缩进的代码只有 is_login 为真才会执行
    if role == "admin":
        print("管理员权限")     # 双重缩进，属于内层 if
    else:
        print("普通用户权限")
else:
    print("未登录")
```

运行结果：

```text
管理员权限
```

这里有两层缩进：第一层表示从属于外层 `if is_login`，第二层表示从属于内层 `if role == "admin"`。嵌套分支就是"分支里再套分支"，用来表达"先满足 A，再在 A 成立的前提下判断 B"这种有层级关系的条件。缩进让这种层级关系在代码上清晰可见——但层级太深也会让代码难读，如何优化属于专门的主题。

## 3. 实践示例

### 3.1 用成绩等级判定场景串起三种分支结构

概念光看容易浮在表面，用一个贴近现实的小场景把单分支、二分支、多分支串起来用一遍，你会看到它们在真实代码里如何协作。场景：根据分数判定等级，再根据是否补考给出最终结论。

```python
# 学生数据：分数、是否补考
students = [
    {"name": "小明", "score": 85, "resit": False},
    {"name": "小红", "score": 58, "resit": True},
    {"name": "小刚", "score": 58, "resit": False},
]

for student in students:
    name = student["name"]
    score = student["score"]
    resit = student["resit"]

    # 第一步：单分支——做输入合法性校验，不合法直接跳过
    if score < 0 or score > 100:
        print(f"{name} 分数异常，跳过")
        continue

    # 第二步：多分支——把分数映射到等级
    if score >= 90:
        grade = "优秀"
    elif score >= 80:
        grade = "良好"
    elif score >= 60:
        grade = "及格"
    else:
        grade = "不及格"
    print(f"{name} 等级：{grade}")

    # 第三步：二分支——是否补考决定最终结论
    if resit:
        result = "重修" if grade == "不及格" else "补考通过"
    else:
        result = "需补考" if grade == "不及格" else "一次通过"
    print(f"  最终结论：{result}")
```

运行结果：

```text
小明 等级：良好
  最终结论：一次通过
小红 等级：不及格
  最终结论：重修
小刚 等级：不及格
  最终结论：需补考
```

这段代码几乎用齐了三种结构：用**单分支**做"不合法就跳过"的前置校验；用**多分支**做"分数到等级"的多路映射；用**二分支**做"补考与否"的非此即彼。每一种结构都用在了它最合适的场景——这正是条件分支在实际编程中的典型用法组合。

### 3.2 手工拆解一次完整的分支判断过程

理解条件分支最好的办法，是手工把一次判断"怎么一步步走过去"拆解清楚。以判断"成绩 85 在上面多分支里会怎么走"为例：

```python
score = 85

if score >= 90:
    grade = "优秀"
elif score >= 80:
    grade = "良好"
elif score >= 60:
    grade = "及格"
else:
    grade = "不及格"
print(grade)
```

运行结果：

```text
良好
```

把这次判断的走向逐步拆解如下：

```text
进入分支判断
  ① score >= 90 → 85 >= 90 → False → 不命中，看下一个
  ② score >= 80 → 85 >= 80 → True  → 命中！执行 grade = "良好"
  ③ 命中即停，后面的 elif score >= 60 和 else 都跳过
跳出整个 if 结构
最终 grade = "良好"，与运行结果一致
```

从拆解过程能看出多分支的关键特性：**它是"短路"的**——一旦某个条件命中，紧接着的判断就全部跳过。所以 85 虽然也满足 `score >= 60`，但因为已经在第②步命中了 `score >= 80`，第三个条件根本不会被检查。这也是为什么分支顺序很重要：把 `score >= 60` 放在第一个，85 会立刻命中并得到"及格"，反而和预期不符。

再看一个会走到 `else` 兜底的情况，体会"全不命中才兜底"：

```python
score = 45

if score >= 90:
    grade = "优秀"
elif score >= 80:
    grade = "良好"
elif score >= 60:
    grade = "及格"
else:
    grade = "不及格"
print(grade)
```

运行结果：

```text
不及格
```

拆解走向：

```text
进入分支判断
  ① 45 >= 90 → False
  ② 45 >= 80 → False
  ③ 45 >= 60 → False
  ④ 所有 elif 都不成立 → 执行 else 兜底 → grade = "不及格"
跳出整个 if 结构
最终 grade = "不及格"
```

45 不满足任何前序条件，于是 `else` 这条"兜底之路"接管了它。`else` 不需要写条件，因为它表达的就是"前面的全都不成立时的默认情况"。一个实用经验是：**写多分支时，先想清楚各种互斥情况，再决定把哪种情况做兜底**。把异常或最常见的默认情况放在 `else`，是种常见且清晰的写法。

## 4. 常见误区与边界

### 4.1 误区：条件分支只能判断布尔值

不少初学者以为 `if` 后面只能写 `True`/`False` 或比较运算，于是把代码写成"每次都加一道比较"：

```python
name = "小明"

# 多此一举：把真值结果再和 True 比较
if bool(name) == True:        # 等价于 if name:，但更啰嗦
    print("有名字")
```

运行结果：

```text
有名字
```

实际上 `if name:` 已经够了——Python 会对 `name` 直接做真值测试，非空字符串就是真。强行再加 `== True` 反而有两个坏处：一是让代码变啰嗦；二是可能踩坑，比如 `if name == True:` 在 `name` 是非空字符串时反而会判定为 `False`（因为字符串和布尔值用 `==` 比较不相等）。

正确认知是：**条件可以是任何对象，Python 会用真值测试规则自动判断真假**。想表达"非空"就直接写原对象，想表达"数值非零"也直接写变量名，不必绕一圈去和 `True` 比较。

### 4.2 误区：把 `=` 写成 `==`（或反过来）

这是一个经典且隐蔽的错误：把"赋值"和"比较"写混。`=` 是赋值（把值绑定给变量），`==` 是比较（判断两个值是否相等）。在条件里，本意是"判断相等"却写成赋值，会引发问题。

```python
score = 75

# 本意：判断 score 是否等于 100
# 错误写法：if score = 100:   # SyntaxError，Python 不允许在条件里赋值
# 正确写法：
if score == 100:
    print("满分")
else:
    print("非满分")
```

运行结果：

```text
非满分
```

这里 Python 实际上帮了你一个忙：`if score = 100:` 会直接报语法错误（`SyntaxError`），因为 Python 不允许在 `if` 条件里用赋值。但在另一些语言里这种写法不会报错、却会改变变量值，导致难以排查的 bug。要记牢：**条件里用 `==` 做比较，用 `=` 做赋值，两者不可混用**。

一个相关的注意点是：判断"是否为 `None`"时，习惯用 `is` 而非 `==`（如 `if x is None:`）。这属于身份比较的细节，把它理解为"`None` 是单例，`is` 判断的是'同一个对象'"即可。

### 4.3 误区：分支越多越好

有些初学者一遇到复杂逻辑，就堆砌大量 `elif`，把一个分支写到十几个条件。分支多本身不是错，但当条件之间有清晰的结构时，往往有更清晰的写法。

```python
# 方式一：一连串 elif，能跑但有点啰嗦
http_status = 404

if http_status == 200:
    desc = "OK"
elif http_status == 201:
    desc = "Created"
elif http_status == 404:
    desc = "Not Found"
elif http_status == 500:
    desc = "Server Error"
else:
    desc = "Unknown"
print(desc)
```

运行结果：

```text
Not Found
```

```python
# 方式二：用字典做"值→含义"的映射，更紧凑
http_status = 404
status_map = {
    200: "OK",
    201: "Created",
    404: "Not Found",
    500: "Server Error",
}
desc = status_map.get(http_status, "Unknown")
print(desc)
```

运行结果：

```text
Not Found
```

两种写法结果一样。当条件是"对一个固定值做相等匹配、且分支很多"时，字典映射往往比一长串 `elif` 更清晰、更易扩展。这并不是说分支多就一定不好——当每个分支里要执行的逻辑很复杂、或判断条件不是简单相等匹配时，`if-elif-else` 仍是首选。关键是有意识地选择更合适的结构，而不是无脑堆 `elif`。

## 5. 总结

本文围绕条件分支展开，主要介绍了以下内容：

- 条件分支是程序三种基本控制结构之一（顺序、选择、循环），它让程序能"先判断条件、再决定执行哪段代码"，从只会顺序执行变成会根据情况做选择
- 条件分支的本质是"判断驱动的执行"：先算出条件真假，再据此决定走哪条路；条件可以是任何对象，Python 会用真值测试自动判定其真假
- 条件分支按叉路条数分为三种结构：单分支（`if`，成立才执行）、二分支（`if-else`，两条必走其一）、多分支（`if-elif-else`，互斥择一，命中即停）
- 多分支是从上往下依次判断、命中即停、其后分支全部跳过的"短路"机制；`else` 是所有条件都不成立时的兜底
- Python 提供几种"按条件选择"的工具：`if` 家族控制执行流程（不产生值）、条件表达式在赋值里做二选一（产生值）、`match-case` 做结构化模式匹配（Python 3.10+）
- Python 用缩进而非花括号划分代码块，缩进决定了哪些行从属于哪个条件，层级关系在视觉上一目了然
- 常见误区包括：以为条件只能是布尔值（其实任意对象都能真值测试）、把 `=` 和 `==` 写混、无脑堆砌 `elif`（有时字典映射更清晰）
