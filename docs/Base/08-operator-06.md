# 位运算符

## 1. 介绍

### 1.1 什么是位运算符

位运算符是一类直接对整数二进制位（bit）进行操作的运算符。它把数字看成由 0 和 1 组成的一串比特，然后逐位地做"与""或""异或""取反""移位"等动作。和加减乘除作用于"数值"不同，位运算作用在"数值的二进制结构"上。

它的价值在于两点：一是**性能**，位运算是 CPU 最底层的操作，单条指令就能完成，常用于对速度敏感的底层代码；二是**紧凑表达组合状态**，一个整数有几十个比特位，每个比特位都可以独立表示一个开关或标志，用一个数就能装下多组布尔信息，省内存又便于传递。

位运算符一共六个，分成两类：

| 类别 | 运算符 | 含义 |
|------|--------|------|
| 位逻辑运算 | `&` | 按位与 |
| | `\|` | 按位或 |
| | `^` | 按位异或 |
| | `~` | 按位取反（一元） |
| 移位运算 | `<<` | 左移 |
| | `>>` | 右移 |

需要特别说明的是：**位运算只适用于整数**。把浮点数、字符串拿来做位运算会直接报 `TypeError`，这一规则也和"位"这个概念本身一致——只有整数才有确定的二进制表示。

### 1.2 在运算符体系中的定位

位运算符属于 Python 运算符体系中"按位操作"这一层。它和算术运算符、逻辑运算符并列，但定位很特别：算术运算符把数当"数"算（关心数值大小），逻辑运算符把值当"真假"算（关心真值），而位运算符把数当"一串 bit"算（关心每一位的状态）。理解这种视角的切换，是掌握位运算的关键。

### 1.3 最简示例

先用一个最小的例子感受位运算到底在做什么：

```python
a = 0b1100   # 二进制 1100，十进制 12
b = 0b1010   # 二进制 1010，十进制 10

print(a & b)   # 按位与：8
print(a | b)   # 按位或：14
print(a ^ b)   # 按位异或：6
```

运行结果是：

```text
8
14
6
```

`0b1100` 这种写法是 Python 的二进制字面量（`0b` 前缀）。把两个数的二进制位上下对齐看，`&` 是"两位都为 1 才得 1"，`|` 是"有 1 就得 1"，`^` 是"不同才得 1"。下面会逐个讲透每个运算符的规则和用途。

## 2. 核心内容

本章先讲一个绕不开的前置知识——补码，因为位运算处理负数时，结果完全由补码规则决定；然后逐个讲解每个位运算符的用法。

### 2.1 前置基础：二进制与补码

理解位运算之前，必须先理解两件事：整数在计算机里怎么用二进制表示，以及负数用补码怎么表示。否则看到 `~5` 得到 `-6` 这种结果会一头雾水。

**整数的二进制表示**

一个非负整数可以写成 2 的幂次求和。比如十进制 13：

```text
13 = 8 + 4 + 1
   = 1×2³ + 1×2² + 0×2¹ + 1×2⁰
   = 0b1101
```

Python 里看二进制表示有两个常用工具。`bin()` 返回带 `0b` 前缀的字符串；`format(n, 'b')` 返回不带前缀的纯二进制串，还可以指定位宽补零：

```python
print(bin(13))           # 0b1101
print(format(13, 'b'))   # 1101
print(format(13, '04b')) # 1101，位宽 4
print(format(13, '08b')) # 00001101，位宽 8 高位补零
```

运行结果：

```text
0b1101
1101
1101
00001101
```

**负数用补码表示**

计算机里没有真正的"负号"，负数靠**补码**来表示。补码的规则是：正数原样不变，负数按"取反加一"得到。以 4 位（仅用于演示）为例，能表示的范围是 `[-8, 7]`：

```text
 十进制       4 位补码
  7   ->   0111
  6   ->   0110
  ...
  1   ->   0001
  0   ->   0000
 -1   ->   1111   （1 取反加一：0001 → 1110 → 1111）
 -8   ->   1000
```

关键规律：补码的最高位是**符号位**，0 表示正、1 表示负；0 只有一种表示（全 0），这是补码相比"原码"的优势（原码里 +0 和 -0 是两种表示）。

**Python 的特殊之处：无限精度整数**

Python 的整数没有固定位宽（不像 C 的 `int` 是 32 位）。在补码视角下，正数高位补无限个 0，负数高位补无限个 1。所以 `~5`（按位取反）会把 5 的所有位都翻转，包括那些无限延伸的高位 0，全部变成 1——结果是一个负数，表现为 `-6`。这就是为什么位运算里负数看起来"反直觉"。

用固定位数截断后观察会更直观：

```python
n = 5
print(f"~{n} = {~n}")                       # -6
print(f"8 位视角 -> ~{n} & 0xFF = {~n & 0xFF}")   # 250
print(f"16 位视角 -> ~{n} & 0xFFFF = {~n & 0xFFFF}") # 65530
```

运行结果：

```text
~5 = -6
8 位视角 -> ~5 & 0xFF = 250
16 位视角 -> ~5 & 0xFFFF = 65530
```

把 `~5` 限制在 8 位里看是 `250`（二进制 `11111010`），正是 5 的二进制 `00000101` 逐位翻转的结果。但在 Python 默认的无限精度下，那些翻转后的高位 1 让它成了负数 `-6`。理解了这一点，后面 `~` 和 `>>` 处理负数时的行为就都有了依据。

### 2.2 按位与运算符 `&`

`&` 是二元运算符，规则是**逐位比较，两位都为 1 才得 1，否则得 0**。它本质是"两个条件同时成立"在比特层面的表达。

对齐来看 `12 & 10`：

```text
  1 1 0 0   <- a = 12
& 1 0 1 0   <- b = 10
---------
  1 0 0 0   <- a & b = 8
```

**示例**

```python
# 1. 基础按位与
a, b = 0b1100, 0b1010
print(f"{a} & {b} = {a & b}")   # 8

# 2. 用 & 取低位掩码：只保留低 4 位，高位清零
n = 0b10110101
print(f"n & 0b1111 = {n & 0b1111}")   # 5，只剩低 4 位

# 3. 用 & 判断奇偶：最低位为 0 即偶数
for x in [10, 15, 0, 7]:
    print(f"{x} -> {'偶数' if x & 1 == 0 else '奇数'}")
```

运行结果：

```text
12 & 10 = 8
n & 0b1111 = 5
10 -> 偶数
15 -> 奇数
0 -> 偶数
7 -> 奇数
```

**关键点**

`&` 最典型的两个用途都是靠"掩码"实现的：

- **取指定位**：和一个全 1 掩码做 `&`，就能把这些位原样保留、其余位清零。比如 `n & 0xFF` 取低 8 位、`n & 1` 取最低位。
- **清零某位**：和一个只有目标位为 0 的掩码做 `&`，就能把那一位清零。配合取反写法是 `flags & ~mask`，意思是"保留掩码以外的位、清掉掩码标记的那些位"。

判断奇偶用 `x & 1` 比 `x % 2` 更贴合位运算的思路，但意义相同，按可读性选用即可。

### 2.3 按位或运算符 `|`

`|` 是二元运算符，规则是**逐位比较，只要有一位为 1 就得 1，两位都为 0 才得 0**。它对应"至少一个条件成立"的比特表达。

对齐看 `12 | 3`：

```text
  1 1 0 0   <- a = 12
| 0 0 1 1   <- b = 3
---------
  1 1 1 1   <- a | b = 15
```

**示例**

```python
# 1. 基础按位或
a, b = 0b1100, 0b0011
print(f"{a} | {b} = {a | b}")   # 15

# 2. 设置某一位为 1（置位）：flags | mask
flags = 0b1001
mask = 0b0010
print(f"置第2位为1 -> {flags | mask} ({flags | mask:04b})")   # 11 (1011)

# 3. 叠加权限标志（读=1 写=2 执行=4，按位或得到组合权限）
READ, WRITE, EXEC = 1, 2, 4
print(f"读|写|执行 = {READ | WRITE | EXEC}")  # 7

# 4. RGB 三分量合成一个颜色值
red, green, blue = 200, 100, 50
color = (red << 16) | (green << 8) | blue
print(f"颜色值 = {color} (0x{color:06X})")   # 13132850 (0xC86432)
```

运行结果：

```text
12 | 3 = 15
置第2位为1 -> 11 (1011)
读|写|执行 = 7
颜色值 = 13132850 (0xC86432)
```

**关键点**

`|` 的核心用途是**置位**和**组合标志**：

- **置位**：把某个比特位强制变 1，而不影响其他位，写法是 `flags | mask`，其中 `mask` 只有目标位是 1。
- **组合标志**：多个独立的"开关"用互不重叠的比特位表示（通常取 1、2、4、8……即 2 的幂），用 `|` 叠加成一个整数。权限系统、配置标志位都是这个套路。

`|` 和 `&` 是一对：`&` 用来"读取/清零"位，`|` 用来"设置"位。两者配合能完成所有位状态的管理。

### 2.4 按位异或运算符 `^`

`^` 是二元运算符，规则是**逐位比较，两位相同时为 0，不同时为 1**。它对应"两者不相同"的比特表达。

对齐看 `12 ^ 10`：

```text
  1 1 0 0   <- a = 12
^ 1 0 1 0   <- b = 10
---------
  0 1 1 0   <- a ^ b = 6
```

异或有几条非常关键的性质，理解了它们，日常使用就不绕：

```text
a ^ a = 0          # 任何数异或自己 = 0
a ^ 0 = a          # 任何数异或 0 = 自己
(a ^ b) ^ b = a    # 异或同一个数两次会还原（可逆）
```

**示例**

```python
# 1. 基础按位异或
a, b = 0b1100, 0b1010
print(f"{a} ^ {b} = {a ^ b}")   # 6

# 2. 不用临时变量交换两个数（异或三步法）
x, y = 15, 28
x ^= y
y ^= x
x ^= y
print(f"交换后 x={x}, y={y}")   # x=28, y=15

# 3. 翻转特定位（toggle）：flags ^ mask
flags = 0b1100
print(f"翻转第1位 -> {flags ^ 1} ({(flags ^ 1):04b})")   # 13 (1101)
print(f"再翻转一次 -> {(flags ^ 1) ^ 1} ({((flags ^ 1) ^ 1):04b})")  # 12 (1100) 还原

# 4. 简单加解密：明文 ^ 密钥 = 密文，密文 ^ 密钥 = 明文
plaintext, key = 2023, 0x55AA
cipher = plaintext ^ key
print(f"密文={cipher}，解密={cipher ^ key}")   # 解密=2023

# 5. 数组里找只出现一次的数（其余都成对出现）
nums = [4, 1, 2, 1, 2]
result = 0
for n in nums:
    result ^= n
print(f"只出现一次的是 {result}")   # 4
```

运行结果：

```text
12 ^ 10 = 6
交换后 x=28, y=15
翻转第1位 -> 13 (1101)
再翻转一次 -> 12 (1100) 还原
密文=21069，解密=2023
只出现一次的是 4
```

**关键点**

异或的特性让它特别适合三类场景：

- **翻转特定位**：和只有目标位为 1 的掩码做 `^`，会把那一位 0/1 互换，再 `^` 一次就还原，常用于状态切换。
- **可逆运算**：`^` 一个相同的数两次会还原，这是加密、校验、消重（找唯一数）的理论基础。
- **交换两数**：`x ^= y; y ^= x; x ^= y` 能不用临时变量完成交换，是一道经典位运算技巧，但实际工程中不如直接 `x, y = y, x` 清晰可读。

### 2.5 按位取反运算符 `~`

`~` 是唯一的一元位运算符，规则是**每一位取反：0 变 1，1 变 0**。因为补码的存在，它对正数操作的结果一定是负数。

记住这条公式就不会算错：

```text
~n  ==  -(n + 1)
```

比如 `~5 = -6`、`~0 = -1`。原因是 5 在补码视角的高位是无限个 0，全部翻转成无限个 1，就成了负数。

**示例**

```python
# 1. 基础取反 + 公式验证
for n in [0, 1, 5, 10]:
    print(f"~{n} = {~n}, 公式 -(n+1) = {-(n + 1)}")

# 2. 固定位数视角观察取反结果
for n in [0, 5, 255]:
    print(f"~{n} & 0xFF = {~n & 0xFF} ({(~n & 0xFF):08b})")

# 3. 用 ~n + 1 求相反数（补码思路：-n 的补码 = 取反加一）
for n in [3, 5, 20]:
    print(f"n={n}, ~n+1={~n + 1}, -n={-n}, 相等？{~n + 1 == -n}")

# 4. 切片里的小技巧：~0 == -1，即倒数第一个
s = "abcdefg"
print(f"s[~0] = {s[~0]}")   # g
```

运行结果：

```text
~0 = -1, 公式 -(n+1) = -1
~1 = -2, 公式 -(n+1) = -2
~5 = -6, 公式 -(n+1) = -6
~10 = -11, 公式 -(n+1) = -11
~0 & 0xFF = 255 (11111111)
~5 & 0xFF = 250 (11111010)
~255 & 0xFF = 0 (00000000)
n=3, ~n+1=-3, -n=-3, 相等？True
n=5, ~n+1=-5, -n=-5, 相等？True
n=20, ~n+1=-20, -n=-20, 相等？True
s[~0] = g
```

**关键点**

`~` 单独用得不多，但它经常和其他位运算配合，完成"清零某几位"的写法：

- **位清除的标准写法** `flags & ~mask`：先用 `~` 把要清的位变成 0、其余变 1，再 `&`，就保留别的位、清掉目标位。比如 `flags & ~3` 清除低 2 位。
- **补码定义**：`-n` 在补码层面就是 `~n + 1`，这条规律是理解所有"负数位运算"的钥匙。

### 2.6 左移 `<<` 与右移 `>>`

移位运算符把整数的二进制位整体平移，是做"乘除 2 的幂"最高效的方式。

**左移 `<<`**

格式 `n << k`：把 `n` 的二进制位向左移动 `k` 位，低位补 0，高位溢出的位丢弃（Python 里因为整数不固定位宽，所以是高位无限扩展，不存在溢出）。左移在数值上等价于**乘以 2 的 k 次方**。

```text
n = 1（...0001）
1 << 1  ->  ...0010   = 2   （×2¹）
1 << 3  ->  ...1000   = 8   （×2³）
1 << 10 ->           1024   （×2¹⁰）
```

**右移 `>>`**

`n >> k`：把 `n` 的二进制位向右移动 `k` 位，低位丢弃。高位怎么补是关键——这是**算术右移**：正数高位补 0，负数高位补 1（保留符号）。右移在数值上等价于**除以 2 的 k 次方并向下取整**。

```text
正数：  20 >> 2  = 5    （20 // 4）
负数：  -7 >> 1  = -4   （-7 // 2 = -4，向负无穷取整）
```

注意负数右移是"向负无穷取整"，而不是"向 0 取整"——所以 `-7 >> 1` 得 `-4` 而不是 `-3`，这和 `//` 的行为一致，但和很多语言里"负数直接截断"不同。

**示例**

```python
# 1. 左移 ≈ 乘 2 的幂
for n in [1, 3, 5]:
    print(f"{n} << 1 = {n << 1}（×2）,  {n} << 3 = {n << 3}（×8）")
print(f"1 << 10 = {1 << 10}")   # 1024

# 2. 右移 ≈ 除 2 的幂（向下取整）
for n in [10, 11, 100]:
    print(f"{n} >> 1 = {n >> 1},  {n} >> 2 = {n >> 2}")
print(f"-7 >> 1 = {-7 >> 1}   # -7 // 2 = -4，向负无穷取整")

# 3. 移位 vs 真除法的区别：移位永远返回 int
print(f"20 / 4 = {20 / 4}（float）, 20 >> 2 = {20 >> 2}（int）")

# 4. 用 1 << k 构造掩码：只有第 k 位为 1
for k in range(4):
    print(f"1 << {k} = {1 << k} ({(1 << k):04b})")
# 用 (1 << k) - 1 构造低 k 位全 1 的掩码
for k in range(1, 5):
    print(f"(1 << {k}) - 1 = {(1 << k) - 1} ({(1 << k) - 1:04b})  低{k}位全1")
```

运行结果：

```text
1 << 1 = 2（×2）,  1 << 3 = 8（×8）
3 << 1 = 6（×2）,  3 << 3 = 24（×8）
5 << 1 = 10（×2）,  5 << 3 = 40（×8）
1 << 10 = 1024
10 >> 1 = 5,  10 >> 2 = 2
11 >> 1 = 5,  11 >> 2 = 2
100 >> 1 = 50,  100 >> 2 = 25
-7 >> 1 = -4   # -7 // 2 = -4，向负无穷取整
20 / 4 = 5.0（float）, 20 >> 2 = 5（int）
1 << 0 = 1 (0001)
1 << 1 = 2 (0010)
1 << 2 = 4 (0100)
1 << 3 = 8 (1000)
(1 << 1) - 1 = 1 (0001)  低1位全1
(1 << 2) - 1 = 3 (0011)  低2位全1
(1 << 3) - 1 = 7 (0111)  低3位全1
(1 << 4) - 1 = 15 (1111)  低4位全1
```

**关键点**

移位运算记住几条就很顺手：

- **等价关系**：`n << k` ≈ `n * 2**k`，`n >> k` ≈ `n // 2**k`。现代编译器/解释器对乘除 2 的幂都有优化，所以写 `* 2` 还是 `<< 1` 在 Python 里性能差异极小，**可读性优先，不要为了"显得高级"硬用移位**。
- **类型差异**：右移永远返回 `int`，而 `/` 返回 `float`。需要整数结果时，`>>` 或 `//` 比 `/` 更合适。
- **构造掩码的两大套路**：`1 << k` 造"只有第 k 位是 1"的掩码；`(1 << k) - 1` 造"低 k 位全是 1"的掩码。这两个写法在位操作里反复出现。
- **Python 无溢出**：`1 << 100` 不会溢出，Python 整数自动扩展位数，结果是真正意义上的 2 的 100 次方，这和 C/C++ 截断溢出的行为完全不同。

### 2.7 运算符优先级与结合性

把六个位运算符放在一起用时，优先级很容易记错。Python 里的相对优先级（从高到低）大致是：

```text
~（取反，一元，最高）
<<  >>（移位）
&（按位与）
^（按位异或）
|（按位或）
```

也就是说 `~` 最先算，移位次之，然后 `&`、`^`、`|` 依次降低。和算术、比较运算相比，位运算的优先级都偏低，所以**位运算混用算术或比较时一定要加括号**。

**常见混淆点**

```python
a, b, c = 12, 10, 5

# 1. 以为 a & b | c 是 (a & b) | c？是对的，但容易看错
print(a & b | c)          # (12 & 10) | 5 = 8 | 5 = 13

# 2. 以为 a | b & c 是 (a | b) & c？错了！& 比 | 高
print(a | b & c)           # a | (b & c) = 12 | (10 & 5) = 12 | 0 = 12
print((a | b) & c)         # 加括号反过来 = (12 | 10) & 5 = 14 & 5 = 4

# 3. 比较 vs 位运算：== 比 & 高，要先 & 再比较必须加括号
flags = 6
print(flags & 5 == 4)      # 实际算 flags & (5 == 4) = flags & False = flags & 0 = 0，不是你以为的
print((flags & 5) == 4)    # 这才是"判断第2位是否为1"
```

运行结果：

```text
13
12
4
False
True
```

最后那个 `flags & 5 == 4` 是最经典的坑：`==` 优先级比 `&` 高，所以先算 `5 == 4` 得 `False`，再 `flags & False`，`False` 当成 0，结果就错得离谱。**养成习惯：位运算和比较混用，一律加括号**。

## 3. 最佳实践

### 3.1 可读性优先，不为炫技用位运算

位运算的很多技巧（无临时变量交换、`n & (n-1)` 判 2 的幂）在面试和底层代码里很经典，但在普通业务代码里，如果一行位运算让人要看半分钟才能懂，就得不偿失了。

把位运算用在真正"用位来承载状态"或"对性能敏感"的场景；普通数值计算，用加减乘除和普通判断更清晰。

**推荐 vs 不推荐**

| 场景 | 推荐写法 | 不推荐写法 | 原因 |
|------|---------|-----------|------|
| 乘 2 | `n * 2` | `n << 1` | 可读性差，Python 里没有性能优势 |
| 判断奇偶 | `n % 2 == 0` 或 `n & 1 == 0` | `n & 1` 后不说明 | 两者都行，但判断逻辑要写清楚 |
| 交换两数 | `x, y = y, x` | `x ^= y; y ^= x; x ^= y` | 异或交换难懂，且 Python 中元组解包更快 |
| 组合标志位 | `READ \| WRITE` | `1 \| 2` 然后到处用魔数 | 魔数 1、2 要定义成命名常量 |
| 判某位是否为1 | `(flags & MASK) != 0` | `flags & MASK == 0` | 后者因优先级会先算 `MASK == 0`，是经典坑 |
| 清除某几位 | `flags & ~MASK` | 手算几个 1 的掩码再 `&` | `~MASK` 写法意图清晰、不易算错 |

### 3.2 用命名常量代替魔数

位标志最怕的就是满屏 `& 0x04`、`| 0x08` 这样的魔数。一定要把每个权限位定义成有意义的常量：

```python
# 推荐：权限位定义为常量，自解释
PERM_READ = 1 << 0    # 1
PERM_WRITE = 1 << 1   # 2
PERM_EXEC = 1 << 2    # 4
PERM_DELETE = 1 << 3  # 8

perm = PERM_READ | PERM_WRITE
can_write = (perm & PERM_WRITE) != 0
perm &= ~PERM_WRITE        # 移除写权限
perm |= PERM_DELETE       # 增加删除权限
```

这样代码读起来就是在描述业务，而不是在解一道位运算谜题。

### 3.3 处理负数时的注意事项

由于补码和无限精度，位运算遇到负数要格外留心：

```python
# 1. 右移负数是向负无穷取整，不是向 0
print(-7 >> 1)   # -4，而 int(-7 / 2) = -3，两者不同！
print(-7 // 2)   # -4，和 >> 一致

# 2. 用 & 截断到固定位数时，负数要先 & 掩码再解释
val = -1
print(val & 0xFF)        # 255，-1 的低 8 位全 1
# 想当成有符号字节看，要手动转换
print(((val & 0xFF) ^ 0x80) - 0x80)   # 把无符号字节转回有符号：-1
```

做底层协议解析、字节拼装时，常需要把负数"按固定位数"重新解释，记住 `& mask` 截断后再按有符号规则还原这一套流程。

### 3.4 常见错误模式

**错误一：以为 `&` `|` 是逻辑运算**

```python
# 想判断 x 在 0 到 10 之间
x = 5
# 错：& 是按位与，0 < x & x < 10 会先算 x & x = x，变成 0 < x < 10，这里碰巧对但逻辑是错的
if 0 < x & x < 10:
    print("ok")
# 对：用 and
if 0 < x and x < 10:
    print("ok")
```

布尔逻辑判断用 `and`/`or`，位运算只用在位上，不要混为一谈。

**错误二：取反后忘记是负数**

```python
n = 5
mask = ~0b100   # 你以为是 0b011 = 3，实际 ~0b100 = -5
print(mask)     # -5
print(n & ~0b100)  # 想清第3位，写 ~x 配合 & 是对的，结果 1（5 & -5 = 1）
```

单独写 `~某个正数` 得到的是负数，不要直接把 `~0b100` 当成 `0b011` 用。正确做法是 `& ~mask` 配着用，让取反只作为"清除"的一部分。

## 4. 原理：补码与 Python 无限精度整数

位运算的"反直觉"几乎都来自补码和 Python 整数的无限精度。这一节把它讲透，前面那些结论就有了根据。

### 4.1 补码：负数为什么这么表示

补码的设计目标只有一个：**让加减法用同一套电路完成**。正数的补码就是它本身，负数的补码是"按位取反后加一"。

以 8 位为例，`-5` 的补码推导过程：

```text
5 的二进制     : 0000 0101
按位取反        : 1111 1010
加一            : 1111 1011   <- -5 的补码
```

关键性质是 `n + (~n + 1) = 0`，即一个数和它的负数相加正好溢出成 0。这就是 `-n == ~n + 1` 的来源，也是 `~n == -(n + 1)` 的来源。

用最小可验证代码确认：

```python
for n in [5, 100, -7]:
    print(f"n={n:>4}, ~n+1={~n + 1:>5}, -n={-n:>4}, 相等？{~n + 1 == -n}")
```

运行结果：

```text
n=   5, ~n+1=   -5, -n=  -5, 相等？True
n= 100, ~n+1= -100, -n= -100, 相等？True
n=  -7, ~n+1=    7, -n=   7, 相等？True
```

这解释了为什么 `~5` 是 `-6`：取反后少加了一，所以从 `-(n+1)` 反推回去就是 `~5 = -(5+1) = -6`。

### 4.2 Python 整数无固定位宽意味着什么

在 C 语言里，一个 `int` 通常是 32 位，最高位是符号位，超出范围就溢出。比如 C 中 `1 << 31` 会得到负数（因为符号位被置 1 了）。

Python 的整数是**无限精度**的——需要多少位就分配多少位，永远不会溢出。这带来几个和 C 截然不同的行为：

```python
# 1. 大数左移不溢出
print(1 << 100)   # 真的得到 2 的 100 次方，而不是溢出

# 2. 负数的补码是"无限个 1 打头"
# -1 在补码视角是 ...1111 1111（高位全是 1）
print(-1 & 0xFF)      # 255，低 8 位全 1
print(-1 & 0xFFFF)    # 65535，低 16 位全 1

# 3. 负数 >> 高位补 1，所以负数右移永远还是负数
print(-16 >> 2)       # -4
print(-256 >> 4)       # -16
```

运行结果：

```text
1267650600228229401496703205376
255
65535
-4
-16
```

这意味着：在 Python 里想模拟固定宽度（比如 8 位、32 位）的位运算，必须手动用掩码截断——`& 0xFF` 取低 8 位、`& 0xFFFFFFFF` 取低 32 位。截断后的结果是个非负数，需要还原成有符号数时再按"超过中点减去总宽度"的规则转换：

```python
def to_signed_8(v):
    v &= 0xFF
    return v - 0x100 if v & 0x80 else v

for v in [200, 0b11110111, 5]:
    print(f"{v} -> 有符号8位: {to_signed_8(v)}")
```

运行结果：

```text
200 -> 有符号8位: -56
247 -> 有符号8位: -9
5 -> 有符号8位: 5
```

这里 `200` 的 8 位补码是 `11001000`，最高位是 1 即负数，还原成有符号数是 `-56`。这种"截断 + 还原"的转换在解析二进制协议、处理固定宽度字段时非常常用。

### 4.3 移位与乘除的真实关系

`<<` 和乘 2 的幂等价，这点直白。`>>` 和除 2 的幂的关系有个细节值得确认：右移是**算术右移**，对负数高位补 1，所以负数右移的结果和"地板除"一致，而不是"向零截断"。

```python
import math
for n in [-7, -8, -9, -1]:
    print(f"{n} >> 1 = {n >> 1}, {n} // 2 = {n // 2}, int({n}/2) = {int(n / 2)}, math.floor = {math.floor(n / 2)}")
```

运行结果：

```text
-7 >> 1 = -4, -7 // 2 = -4, int(-7/2) = -3, math.floor = -4
-8 >> 1 = -4, -8 // 2 = -4, int(-8/2) = -4, math.floor = -4
-9 >> 1 = -5, -9 // 2 = -5, int(-9/2) = -4, math.floor = -5
-1 >> 1 = -1, -1 // 2 = -1, int(-1/2) = 0, math.floor = -1
```

可以清楚看到：`>>` 行为和 `//`、`math.floor` 一致（向负无穷取整），而 `int(x/2)` 是向零截断，两者在负数时不同。所以**用 `>>` 做除法时，要意识到它对负数是地板除**，如果你的预期是向零取整，应该用 `int(n / 2)` 而不是 `n >> 1`。

## 5. 总结

本文围绕位运算符展开，主要介绍了以下内容：

- 位运算符是把整数当成二进制位串来操作的一类运算符，共六个：`&`、`|`、`^`、`~`、`<<`、`>>`，只适用于整数
- 补码是理解位运算负数行为的基础：负数按"取反加一"表示，`~n == -(n+1)`，`-n == ~n + 1`
- `&` 用于取位、清位（`flags & ~mask`），`|` 用于置位、组合标志，`^` 用于翻位和可逆运算，`~` 用于位清除，`<<`/`>>` 用于高效乘除 2 的幂
- 优先级：`~` 最高，移位次之，依次 `& > ^ > |`；位运算与比较混用时务必加括号，否则 `==` 会先于 `&` 计算导致经典错误
- Python 整数无限精度，左移不溢出、负数高位补无限个 1，模拟固定位宽要用掩码截断并手动还原有符号数
- 负数右移是算术右移，等价于地板除而非向零截断
- 最佳实践：可读性优先，魔数换成命名常量，把位运算用在组合标志和性能敏感场景，而非普通数值计算
