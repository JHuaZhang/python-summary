## 1. 介绍

### 1.1 从浅拷贝到深拷贝:本篇要解决的问题

上一篇《列表拷贝》讲清了"赋值不是拷贝"和"浅拷贝只复制外壳、共享内层"。浅拷贝对一维列表够用,但只要拓扑里出现**嵌套的可变对象**(列表的列表、字典的列表、互相引用的对象),浅拷贝就会留下共享的尾巴——通过一个名字原地改了内层,另一个名字也跟着变:

```python
import copy

a = [[1, 2], [3, 4]]

# 浅拷贝:内层共享
sh = copy.copy(a)
sh[0].append(99)
print(a)                 # [[1, 2, 99], [3, 4]] —— a 的内层被波及

# 深拷贝:连内层都独立
dp = copy.deepcopy(a)
dp[0].append(99)
print(a)                 # [[1, 2], [3, 4]] —— a 完全不受影响
```

本篇承接那条线索,系统讲透**深拷贝(deep copy)**:`copy.deepcopy` 如何递归地把整棵对象树都复制成独立的副本、如何处理**循环引用**而不会无限递归、不可变对象在深拷贝里的特殊处理、自定义对象的 `__copy__`/`__deepcopy__` 钩子,以及在真实场景里如何在"浅 / 深 / 不拷贝"之间做选择。

### 1.2 二者最简对照

```python
import copy

original = [[1, 2], {"k": [3, 4]}]

shallow = copy.copy(original)      # 浅拷贝
deep    = copy.deepcopy(original)  # 深拷贝

# 外层都独立
print(shallow is original)         # False
print(deep    is original)         # False

# 内层:浅拷贝共享,深拷贝独立
print(shallow[0]       is original[0])      # True  —— 共享
print(deep[0]          is original[0])      # False —— 独立
print(shallow[1]["k"]  is original[1]["k"]) # True  —— 共享
print(deep[1]["k"]     is original[1]["k"]) # False —— 独立
```

深拷贝与浅拷贝唯一的差别就是**递归深度**:浅拷贝只复制最外层、内层沿用原引用;深拷贝对每个可变元素**再次拷贝**,层层下探,直到把所有可变对象都换成新副本(不可变对象通常直接共享,见 1.4)。

**速查表**:

| 维度 | 赋值 `=` | 浅拷贝 `copy.copy` | 深拷贝 `copy.deepcopy` |
|------|---------|--------------------|------------------------|
| 外层独立 | ❌ 单一对象 | ✅ | ✅ |
| 内层独立 | ❌ | ❌(共享内层引用) | ✅(递归复制整个拓扑) |
| 循环引用 | —— | 不处理(继承原结构) | ✅(用备忘录打破环) |
| 代价 | O(1) | O(n)(一层) | O(全部可变节点) |
| 典型用途 | 别名/传引用 | 元素不可变或只替换外层 | 嵌套可变对象需彻底独立 |

### 1.3 浅拷贝回顾:为什么不够

上一篇已建立的心智:浅拷贝(`a.copy()` / `a[:]` / `list(a)` / `copy.copy(a)`)分配新外壳,但外壳每个槽位放的是**与原列表相同引用**。对不可变元素无碍;对可变嵌套元素,`b[i].append(...)` 会改到被共享的内层对象,使 a 也变:

```python
a = [[1, 2], [3, 4]]
b = a.copy()          # 浅拷贝

b[0].append(99)       # 原地改 b[0](共享的内层列表)
print(a)              # [[1, 2, 99], [3, 4]] —— a 跟着变
print(a[0] is b[0])   # True
```

浅拷贝只能挡住"替换外层引用"(`b[i] = x`),挡不住"原地改内层对象"。当需求是"对副本的任何修改都不波及原对象"——包括改内层——浅拷贝就不够,必须深拷贝。

### 1.4 深拷贝的关键性质:递归 + 不可变对象优化 + 循环引用安全

在展开细节前,先记住深拷贝的三条核心性质,后面每节都是在讲其中一条:

1. **递归复制可变对象**:`deepcopy` 遇到 list/dict/set 就新建并递归复制其元素,层层下探,直到把整棵可变对象树都换成新副本。结果是副本与原对象在可变结构上**完全不共享**。

2. **不可变对象常被直接共享**:对 `int`/`str`/`frozenset`/`None`/`bool` 等,深拷贝往往不新建,直接复用原对象(因为它们改不动,共享即等于拷贝,省分配)。**全不可变的元组**(如 `(1, 2, 3)`)也整体复用;**含可变元素的元组**则因有元素被复制、副本与原不同,外壳会被新建(见 2.2 节)。

3. **用"备忘录(memo)"打破循环引用**:`deepcopy` 在内部维护一张"原对象→副本对象"的映射表,每复制一个对象就登记。再遇到同一对象时直接取已造好的副本,既避免无限递归,又保证"原对象里多次引用同一子对象"时副本保持同一性。

```python
import copy

# 性质一:递归复制
a = [[1, 2], [3, 4]]
d = copy.deepcopy(a)
d[0].append(99)
print(a[0], d[0])           # [1, 2] [1, 2, 99] —— 内层彻底独立
print(a[0] is d[0])         # False

# 性质二:不可变对象常共享
t = (1, 2, 3)
dt = copy.deepcopy(t)
print(dt is t)              # True —— 全不可变元组直接复用

# 性质三:同一子对象被多次引用,副本保持同一性
shared = [9]
a = [shared, shared]        # 同一个列表出现两次
d = copy.deepcopy(a)
print(d[0] is d[1])         # True —— 副本里仍是同一对象(不是两个 [9])
print(d[0] is shared)       # False —— 但与原对象不同
```

理解这三条性质,深拷贝的"古怪行为"就都有了答案:为什么有时 `deepcopy(x) is x` 为真(性质二)、为什么循环引用不爆栈(性质三)、为什么多处引用同一子对象副本不分裂(性质三)。

## 2. 核心内容

本章逐节详解:`deepcopy` 的递归行为、不可变对象的处理、同一子对象多次引用的同一性保持、循环引用的安全复制、自定义 `__copy__`/`__deepcopy__`、性能与代价、以及真实场景选型。每节遵循"文字详解 → demo → 运行结果说明 → 陷阱"。

### 2.1 `deepcopy` 逐层复制可变对象树

`copy.deepcopy(x)` 从 x 出发,遇到每个**可变容器**就新建一个空副本,再**逐个元素递归复制**填进去。最终的副本与原图在可变节点上两两独立:

```python
import copy

# 三层嵌套:列表→字典→列表
data = [{"nums": [1, 2]}, {"nums": [3, 4]}]
dp = copy.deepcopy(data)

# 改副本的最内层,完全不波及原对象
dp[0]["nums"].append(99)
print(data[0]["nums"])         # [1, 2] —— 原对象纹丝不动
print(dp[0]["nums"])           # [1, 2, 99]
print(data[0]["nums"] is dp[0]["nums"])   # False —— 最内层也独立
```

深拷贝会无差别地复制每一层可变对象,所以无论嵌多深,副本都和原对象彻底解耦。这也是它**代价高**的原因——整棵可变树都要遍历、分配、填充。

**陷阱:浅拷贝"假装够用"的二维结构**。二维列表浅拷贝后外层独立、内层共享,新手常误以为"二维列表拷贝了就独立了":

```python
a = [[0] * 3 for _ in range(2)]   # [[0,0,0],[0,0,0]]
b = a.copy()                       # 浅拷贝
b[0][0] = 9
print(a)                          # [[9,0,0],[0,0,0]] —— a[0][0] 被改!

dp = copy.deepcopy(a)
dp[0][0] = 9
print(a)                          # [[0,0,0],[0,0,0]] —— deepcopy 才安全
```

凡是"列表的列表/字典的列表"且会原地改内层,浅拷贝都不够。记住这条:**嵌套可变结构 + 需要完全独立副本 = `deepcopy`**。

### 2.2 不可变对象在深拷贝里的处理

深拷贝对**不可变对象**会判断"是否需要复制"。对 `int`/`str`/`bytes`/`frozenset`/内容全不可变的 `tuple`,通常**直接复用原对象**(共享),因为它们改不动:

```python
import copy

print(copy.deepcopy(42)      is 42)         # True —— int
print(copy.deepcopy("abc")   is "abc")      # True —— str(驻留情况下)
print(copy.deepcopy((1,2,3)) is (1,2,3))    # True —— 全不可变元组

fs = frozenset({1, 2})
print(copy.deepcopy(fs) is fs)              # True —— frozenset
```

> 小贴士:字符串是否 `is` 返回原对象受解释器驻留(interning)影响,上面某些 `is` 结果在不同版本/值上可能不同;重点是"深拷贝不会为不可变对象额外分配副本",行为上等价于共享。

**含可变元素的元组**则不同:元组外壳虽不可变,但元素可变。CPython 的深拷贝对元组采取"逐个深拷贝元素;只有当**没有任何元素被改变**(全部仍 `is` 原元素)时才整体复用外壳,否则新建一个元组、装填复制后的元素"。既然其中有可变元素被复制成了新对象,`is` 不再相等,外壳也会被新建:

```python
import copy

t = ([1, 2], [3, 4])          # 元组里装了可变 list
dt = copy.deepcopy(t)

print(dt is t)                # False —— 有元素被复制,外壳也新建
print(dt[0] is t[0])          # False —— 内层 list 被递归复制成新的
dt[0].append(99)
print(t[0])                   # [1, 2] —— 内层改动不波及原元组
print(dt[0])                  # [1, 2, 99]
```

对照验证"全部不变才复用外壳"——纯不可变元素的元组,深拷贝直接返回原对象:

```python
print(copy.deepcopy((1, 2, 3)) is (1, 2, 3))   # True —— 无元素被改变,整体复用
```

这正是 08 篇 4.5 节留的尾巴:不可变外壳 + 可变内层的元组,浅拷贝会整体返回原对象(于是内层 list 被共享,改内层会波及原元组);而**深拷贝会复制可变内层、并因此新建外壳**,使内层彻底独立。区分"全不可变元组(整体复用)"与"含可变元组(新建外壳、内层复制)",是深拷贝对不可变对象行为的要点。

### 2.3 同一子对象被多次引用:副本保持同一性

原对象里如果**多次引用同一个子对象**(比如两个槽位指向同一个内层列表),深拷贝后副本里**仍保持"指向同一个副本"**,而不是分裂成两份。这靠"备忘录"实现(见 4.3 节):

```python
import copy

shared = [1, 2]
a = [shared, shared, {"ref": shared}]   # 三处都引用同一个 shared
print(a[0] is a[1], a[0] is a[2]["ref"])  # True True

d = copy.deepcopy(a)
# 副本里三处仍指向"同一个副本",而不是三个独立的 [1,2]
print(d[0] is d[1], d[0] is d[2]["ref"])  # True True
# 但与原对象不同
print(d[0] is shared)                    # False

# 改副本的任一处,其它两处也跟着变(因为它们是同一副本)
d[0].append(9)
print(d[1], d[2]["ref"])                 # [1, 2, 9] [1, 2, 9]
print(shared)                            # [1, 2] —— 原对象不变
```

这个性质很重要:深拷贝**保持原图的引用拓扑结构**,只是把每个节点换成新副本。如果它把每个引用都复制成独立对象,就会破坏"原本是同一个对象"的语义。备忘录让"复制图"忠实于"原图"。

**陷阱:误以为深拷贝会"拆分"重复引用**。有人期望 `deepcopy` 把 `a = [s, s]` 变成两个独立内层,但实际仍是同一副本。这是特性而非 bug——保持同一性才符合"忠实复制拓扑"。

### 2.4 循环引用:deepcopy 不会无限递归

对象互相引用(甚至自引用)形成环时,朴素的递归复制会无限下钻、最终栈溢出。`deepcopy` 用备忘录打破环:**遇到已复制的对象就返回其副本,不再下探**:

```python
import copy

# 自引用:a 里有一个指向自己的引用
a = [1, 2]
a.append(a)            # a = [1, 2, a] —— 自己引用自己

d = copy.deepcopy(a)
print(d is a)          # False —— 是新对象
print(d[2] is d)       # True  —— 副本也是自引用(保持拓扑!)
d[0] = 99
print(d)               # [99, 2, [...]] —— 改副本不影响原对象
print(a)               # [1, 2, [...]]
```

```python
import copy

# 互相引用:a 引用 b,b 引用 a
a = {"name": "a"}
b = {"name": "b", "link": a}
a["link"] = b          # a ⇄ b 互引用成环

d = copy.deepcopy(a)
# 副本保持环结构:a' ⇄ b',且与原对象解耦
print(d["link"]["link"] is d)   # True —— 副本环连通
print(d is a)                    # False —— 但是独立的新图
d["name"] = "A"
print(a["name"])                 # "a" —— 原对象不受影响
```

要点:**`deepcopy` 既能复制环、又能打破环导致的无限递归,还保持副本的拓扑与原图一致**。这正是浅拷贝做不到的——浅拷贝只复制一层,内层的环引用照原样继承,改动会互相穿透;`deepcopy` 把整张图(含环)独立翻一份。

> 对比:CPython 用 `Py_ReprEnter`/递归深度限制给 `repr` 防爆栈,但单纯 repr 不复制对象。`deepcopy` 用的是"备忘录登记 + 复用到已建副本"的主动策略,既能复制又能防环,机制更完整(见 4.3 节)。

### 2.5 自定义对象的拷贝:`__copy__` 与 `__deepcopy__`

自定义类默认按通用规则拷贝:`copy.copy` 走"创建同型实例 + 复制 `__dict__`"的浅路径;`copy.deepcopy` 递归复制实例字典。若想自定义拷贝行为(例如某些字段不复制、或拷贝时重建连接),实现 `__copy__` 和 `__deepcopy__` 钩子:

```python
import copy

class Connection:
    def __init__(self, host, pool=None):
        self.host = host
        self.pool = pool             # 假设 pool 是共享/单例,不该被深拷贝

    # 浅拷贝钩子:返回新实例,字段共享
    def __copy__(self):
        cls = self.__class__
        new = cls.__new__(cls)
        new.__dict__.update(self.__dict__)
        return new

    # 深拷贝钩子:深拷贝自己,但 pool 用备忘录拿原对象(不复制 pool)
    def __deepcopy__(self, memo):
        cls = self.__class__
        new = cls.__new__(cls)
        memo[id(self)] = new         # 先登记自己,防止环导致无限递归
        for k, v in self.__dict__.items():
            if k == "pool":
                setattr(new, k, v)   # pool 不深拷贝,保留原单例
            else:
                setattr(new, k, copy.deepcopy(v, memo))
        return new

c = Connection("db.example.com", pool=GLOBAL_POOL)
sh = copy.copy(c)
dp = copy.deepcopy(c)

print(sh is c)               # False
print(dp is c)               # False
print(dp.pool is c.pool)     # True —— pool 被保留,未深拷贝
print(dp.host is c.host)     # True —— str 不可变,共享无妨
```

`__deepcopy__(self, memo)` 的要点:

- **签名必须收 `memo`**:这是 deepcopy 传进来的备忘录字典,自定义实现里对子对象要调 `copy.deepcopy(v, memo)` 把同一备忘录传下去,否则会丢失环/同一性保护。
- **先把自己登记进 memo**:`memo[id(self)] = new`,再深拷贝字段。这样若有环引用回到自身,会命中 memo 返回已建的 `new`,避免无限递归。
- **选择性跳过**:像连接池、缓存、文件句柄这类"不该复制"的字段,直接赋原引用即可,实现"深拷贝但局部共享"的精细控制。

**陷阱:忘了传 memo**。自定义 `__deepcopy__` 里若用 `copy.deepcopy(v)`(不带 memo)复制子对象,会丢失备忘录,导致同一子对象被复制成多份、且无法处理环。始终 `copy.deepcopy(v, memo)`。

### 2.6 性能与代价:deepcopy 不便宜

`deepcopy` 要遍历整棵可变对象树、对每个可变节点分配+填充、维护备忘录,代价远高于浅拷贝。对大嵌套结构,这是实打实的 CPU 和内存开销:

```python
import copy, timeit

# 大型嵌套结构:1000 个字典,每个含一个 100 元素列表
big = [{"nums": list(range(100))} for _ in range(1000)]

print(timeit.timeit('copy.copy(big)',     globals=globals(), number=100))   # 快:只复制外层
print(timeit.timeit('copy.deepcopy(big)', globals=globals(), number=100))   # 慢得多:递归全复制
```

`deepcopy` 通常比 `copy.copy` 慢一个数量级以上,因为:

- 浅拷贝是 O(n)(一层),深拷贝是 O(全部可变节点)(整棵树)。
- deepcopy 用 Python 层调度 + memo 字典查找,无法像浅拷贝那样走 C 层一次性 `list_copy` 快路径。
- 每个可变对象要单独分配、逐元素填、登记 memo。

**选型原则**:**能用浅拷贝就别用深拷贝**。只有当"嵌套可变结构 + 需要原地改内层且完全独立"时才上 `deepcopy`。若只是只读使用,连浅拷贝都不必;若是元素不可变的一维列表,浅拷贝足够。把 `deepcopy` 当"重型工具",按需取用。

### 2.7 实战场景:何时浅、何时深、何时不拷贝

把前面的知识串到真实场景,看选型如何落地。

**场景一:配置对象的"可编辑副本"**。系统读入一份嵌套配置(字典套列表套字典),某个模块需要拿一份能自由改又不影响全局配置的副本——这里必须深拷贝:

```python
import copy

GLOBAL_CONFIG = {
    "db": {"hosts": ["h1", "h2"], "timeout": 30},
    "cache": {"size": 100},
}

# 某进程想临时加一个 host,且不影响 GLOBAL_CONFIG
local = copy.deepcopy(GLOBAL_CONFIG)
local["db"]["hosts"].append("local")
print(GLOBAL_CONFIG["db"]["hosts"])   # ['h1', 'h2'] —— 全局未变
print(local["db"]["hosts"])           # ['h1', 'h2', 'local']
```

若是浅拷贝,`local["db"]["hosts"].append(...)` 会改到全局共享的内层列表。嵌套可改配置→深拷贝。

**场景二:并发/隔离的任务数据**。把同一份嵌套数据分发给多个 worker 处理,要求 worker 之间互不干扰:

```python
import copy

template = [{"x": [0]}, {"x": [0]}]

# 每个 worker 拿独立副本
worker_a = copy.deepcopy(template)
worker_b = copy.deepcopy(template)

worker_a[0]["x"].append(1)
print(worker_b[0]["x"])    # [0] —— b 不受 a 影响
```

若是浅拷贝,worker_a 改内层会污染 worker_b(共享内层)。并发隔离→深拷贝。

**场景三:单层结构/元素不可变——浅拷贝即可**。一维列表、或元素都是不可变对象时,深拷贝没有额外收益,浅拷贝更快:

```python
import copy

names = ["alice", "bob"]                # 一维,元素 str 不可变
sh = names.copy()                        # 浅拷贝足够
# dp = copy.deepcopy(names)             # 多余:没有嵌套可变对象要复制

points = [(1, 2), (3, 4), (5, 6)]        # 元素是元组(不可变)
sh2 = copy.copy(points)                  # 浅拷贝足够;deepcopy 会直接复用这些元组
```

**场景四:只读使用——不拷贝**。只是读一份数据来计算,完全不用拷贝,直接传引用:

```python
def total(values):
    return sum(values)        # 只读,不改 values,无需拷贝

data = [1, 2, 3, 4]
print(total(data))           # 10 —— 直接用原引用,O(0) 额外开销
```

**场景五:缓存返回值时防御性浅拷贝**。一个缓存内部存了列表,对外返回时不希望调用方改到缓存:

```python
_cache = {"v1": [1, 2, 3]}

def get(key):
    # 返回浅拷贝:调用方 append/排序不污染缓存
    # 若值是嵌套结构且可能被人改内层,这里要 deepcopy
    return _cache[key].copy()

out = get("v1")
out.append(4)
print(_cache["v1"])   # [1, 2, 3] —— 缓存未被污染
```

选型一句话总结:**"要不要拷贝"看是否有独立修改需求;"浅还是深"看嵌套可变结构是否存在且会改内层**。三层判断:不拷贝(只读)→ 浅拷贝(一层/不可变元素)→ 深拷贝(嵌套可变、彻底独立)。

## 3. 最佳实践

### 3.1 嵌套可变结构要彻底独立,用 `copy.deepcopy`

```python
import copy

a = [[1, 2], {"k": [3, 4]}]
# ❌ 浅拷贝:内层共享,b[0].append / b[1]["k"].append 会波及 a
b = a.copy()
# ✅ 深拷贝:整棵可变树独立
b = copy.deepcopy(a)
```

只要拓扑含 list/dict/set 的嵌套且需原地改内层,浅拷贝就不够。这是深拷贝的标准用武之地。

### 3.2 元素不可变或只换外层引用,浅拷贝足够,别上 deepcopy

```python
names = ["a", "b", "c"]       # 一维,不可变元素
b = names.copy()               # ✅ 浅拷贝足够

# ❌ 多余且更慢
# b = copy.deepcopy(names)
```

`deepcopy` 对没有嵌套可变对象的结构没有额外收益,却带来 O(全树) 代价。能用浅就别用深。

### 3.3 只读使用不要拷贝,省 O(n) 内存

```python
# ❌ 只读却拷贝,浪费
for x in data.copy():
    consume(x)

# ✅ 直接遍历引用
for x in data:
    consume(x)
```

没有"独立修改"需求,直接用引用。大数据场景尤其要克制拷贝。

### 3.4 处理循环引用数据放心用 deepcopy,它会自动防环

```python
import copy

node = {"v": 1}
node["self"] = node            # 自引用成环

# ✅ deepcopy 用 memo 安全复制环,不爆栈
d = copy.deepcopy(node)
print(d["self"] is d)          # True —— 副本保持自引用拓扑
```

手写递归复制遇到环会栈溢出;`deepcopy` 内置备忘录,放心用于含自引用/互引用的结构(如链表、树父子互引、图)。

### 3.5 自定义 `__copy__`/`__deepcopy__` 控制"该复制什么、共享什么"

```python
import copy

class Conn:
    def __init__(self, host, pool): self.host, self.pool = host, pool
    def __deepcopy__(self, memo):
        new = self.__class__.__new__(self.__class__)
        memo[id(self)] = new                       # 先登记防环
        new.host = copy.deepcopy(self.host, memo)  # 普通字段深拷贝
        new.pool = self.pool                       # 单例/连接池不复制
        return new
```

实现 `__deepcopy__(self, memo)` 时:必须接受并传递 `memo`、先登记自身再深拷贝字段、对不该复制的字段(单例/句柄/缓存)直接赋原引用。这给你"深拷贝但局部共享"的精细控制。

### 3.6 判断拷贝深度用 `is` 检验各层,别只看外层

```python
import copy
a = [[1, 2]]
sh = copy.copy(a); dp = copy.deepcopy(a)

print(sh is a, dp is a)         # 外层都 False(都拷了)
print(sh[0] is a[0])            # True  —— 浅拷贝内层共享
print(dp[0] is a[0])            # False —— 深拷贝内层独立
```

验"浅还是深"不能只看外层(都独立),要逐层 `is` 检验内层是否共享。这是回归测试"拷贝是否真正独立"的正确姿势。

### 3.7 deepcopy 慢且重,热路径/大数据慎用或换方案

```python
import copy
big = [{"nums": list(range(100))} for _ in range(1000)]

# 热路径里对 big 反复 deepcopy 是性能杀手
# 考虑:① 设计成不可变结构,直接共享不拷贝;
#       ② 只复制即将修改的那条路径(结构性共享);
#       ③ 用更轻的自定义拷贝只复制必要字段。
```

`deepcopy` 在循环/热路径上对大嵌套结构反复调用代价极高。若确有性能问题,优先从"避免拷贝"入手(只读共享、不可变结构),其次用结构性共享或自定义拷贝只复制必要部分,而非无脑 `deepcopy`。

## 4. 原理

### 4.1 浅拷贝回顾:一层复制,内层共享

从 08 篇已建立的机制出发:浅拷贝分配新外壳、复制 n 个引用(O(n)),每法对 list 落到同一条 `list_copy` 快路径:

```c
// 简化示意:list 浅拷贝
PyListObject *list_copy(src) {
    Py_ssize_t n = src->ob_size;
    PyListObject *dst = 新建长度 n 的列表;
    for (i = 0; i < n; i++) {
        dst->ob_item[i] = src->ob_item[i];   // 复制指针,指向同一内层对象
        Py_INCREF(dst->ob_item[i]);
    }
    return dst;
}
```

`dst` 的每个槽位与 `src` 对应槽位指向**同一内层对象**,所以 `b[i].append(...)` 改的是被共享的内层,a 跟着变。深拷贝要在这一基础上"对每个内层对象也再拷一遍"。

### 4.2 deepcopy 的递归骨架:遇容器则新建并递归

`copy.deepcopy` 在 CPython 的 `copy` 模块(Python 实现,非内置 C 快路径)里大致是"递归 + 备忘录"的结构。简化示意:

```c
// 简化示意:deepcopy 的核心递归(Python 层逻辑用 C 风格表达)
PyObject *deepcopy(PyObject *x, Memo *memo) {
    // ① 不可变对象:直接复用(详见 4.4)
    if (is_immutable_no_need_copy(x)) return x;

    // ② 命中备忘录:返回已建副本(防环 + 保同一性)
    if (memo_has(memo, x)) return memo_get(memo, x);

    // ③ 按类型新建空副本,登记进备忘录,再逐元素递归复制
    PyObject *y = new_empty_same_type(x);     // 新 list/dict/set 空壳
    memo_set(memo, x, y);                     // 先登记!再递归,才能防环
    for (item : elements(x)) {
        append_or_set(y, deepcopy(item, memo));   // 对每个元素递归
    }
    return y;
}
```

关键点:

- **先登记后递归**:`memo_set(memo, x, y)` 必须在递归子元素**之前**完成。这样若子元素引用回 x(成环),递归到 x 时会命中 `memo_has` 返回已建的 y,打破无限递归。
- **逐元素递归**:对 list 的每个元素、dict 的每个值(可选键)都 `deepcopy`,层层下探,直到全是不可变对象直接复用为止。这就是"深"——深到底。
- **Python 层调度**:不同于浅拷贝走 C 快路径,deepcopy 主要在 Python 层用类型分派 + 递归实现,这是它慢于浅拷贝的根本原因(见 2.6)。

### 4.3 备忘录 memo:防环与保持同一性

`memo` 是一个 `{id(原对象): 副本}` 的字典,贯穿整次深拷贝。它有两个作用:

```c
// 简化示意:memo 的两个作用
PyObject *deepcopy(x, memo):
    // 作用一:防环
    //   自引用 a=[...]; a.append(a) 时,递归到 a 的元素 a,
    //   若没有 memo 会无限递归。命中 memo 直接返回已建副本,止住。
    if (memo_has(memo, x)) return memo_get(memo, x);

    y = new_empty_same_type(x);
    memo_set(memo, x, y);          // 作用二:保同一性
    //   后续若同一 x 再被引用,都取同一个 y。
    //   所以 [s, s] 深拷贝后副本仍是 [s', s'](同一副本),而非两个 [s']。
    fill_with_deepcopied_elements(y, x, memo);
    return y;
```

- **防环**:成环时递归会回到已处理对象,memo 让它"折返"返回副本而非继续下钻。这是 `deepcopy` 能安全处理自引用/互引用的关键。
- **保持同一性**:原图里"同一子对象被多处引用"的拓扑,在副本里忠实保留——多处都指向"该子对象的同一副本"。这让深拷贝结果在结构上与原图同构(只是节点都是新的)。

这条机制解释了 2.3、2.4 节的所有现象:多次引用同一对象不分裂(同一性)、循环引用不爆栈(防环)。

### 4.4 不可变对象的判定:为何有的 deepcopy 返回原对象

`deepcopy` 对不可变对象常直接复用原对象,这是性能优化,也基于"不可变=共享即等于拷贝"的等价性。简化示意其判定:

```c
// 简化示意:deepcopy 对不可变类型快返回
PyObject *deepcopy(x, memo):
    // int/str/bytes/frozenset/None/bool 等基本不可变类型:直接复用
    if (PyLong_Check(x) || PyUnicode_Check(x) || PyBytes_Check(x)
        || PyFrozenSet_Check(x) || x == None || x == True/False)
        return x;

    // tuple:逐个深拷贝元素,得到一组"可能复用、可能新建"的元素
    if (PyTuple_Check(x)) {
        new_items = [deepcopy(e, memo) for e in x];
        // 关键判定:只有当"没有任何元素被改变"(全部仍 is 原元素)时整体复用外壳
        if (all(new_items[i] is x[i] for i in range(len(x)))) {
            return x;                        // 全部未变 → 复用原元组
        }
        return tuple(new_items);             // 否则新建一个元组,装填复制后的元素
    }

    // 可变容器:list/dict/set → 新建 + memo + 递归(见 4.2)
    ...
```

要点:

- **基本不可变对象复用**:`int`/`str`/`bytes`/`frozenset`/`None`/`bool` 改不动,深拷贝直接返回原对象,省分配。
- **全不可变元组整体复用**:`(1, 2, 3)` 各元素深拷贝后仍 `is` 原元素(都没变),于是整体 `return x`。
- **含可变元组新建外壳**:元组里有 `list` 被复制成新对象(不再 `is` 原 list),"有元素被改变"成立,于是**新建一个元组**装填复制后的元素——`dt is t` 为假(外壳新建)、`dt[0] is t[0]` 也为假(内层复制)。

这解释了 2.2 节的对照与行为差异。深拷贝并非"无脑全部新建",而是"可变的才复制、不可变的复用";对元组则进一步"仅当全体元素都未变时才复用外壳,否则连外壳一起新建",在保证行为等价(完全独立)的前提下尽量省分配。

### 4.5 `__deepcopy__` 钩子的派发与 memo 透传

`deepcopy` 在新建自定义类实例前,会先查对象是否实现了 `__deepcopy__`,有则调用它,把 memo 传进去:

```c
// 简化示意:deepcopy 对自定义类型的派发
PyObject *deepcopy(x, memo):
    if (hasattr(x, "__deepcopy__")) {
        return x.__deepcopy__(memo);   // 自定义优先,并传入 memo
    }
    // 否则走通用路径:新建实例 + 递归复制 __dict__
    y = cls.__new__(cls);
    memo_set(memo, x, y);
    for (k, v in x.__dict__.items())
        y.__dict__[k] = deepcopy(v, memo);
    return y;
```

要点:

- **自定义优先**:实现 `__deepcopy__(self, memo)` 后,完全由你决定复制逻辑。这是实现"深拷贝但保留单例/句柄"的官方入口。
- **memo 必须透传**:钩子里对子对象要 `copy.deepcopy(v, memo)` 而非 `copy.deepcopy(v)`,把同一个 memo 传下去,否则防环和同一性都失效。
- **先登记自身**:钩子开头 `memo[id(self)] = new` 再处理字段,与通用路径一致,防环可达。

这正是 2.5 节自定义拷贝的底层依据。

### 4.6 浅 vs 深:代价与适用边界的本质对照

把三档(赋值/浅/深)放到同一框架对照,选型的因果就清晰了:

```c
// 赋值:只复制引用,O(1)
b = a;                 // b、a 同一对象,改一处处处变

// 浅拷贝:复制一层外壳,O(n)
b = list_copy(a);      // 外壳独立,内层共享;改 b[i] 安全,改 b[i].mut() 会穿透

// 深拷贝:递归复制整棵可变树,O(全部可变节点)+ memo 维护
b = deepcopy(a, memo); // 整树独立,任何改动都不波及原对象;能防环、保同一性
```

| 维度 | 赋值 | 浅拷贝 | 深拷贝 |
|------|------|--------|--------|
| 复制范围 | 引用 | 一层外壳 | 整棵可变树 |
| 时间 | O(1) | O(n) | O(全树) |
| 额外内存 | 0 | O(n) | O(全树副本) |
| 内层独立 | 否 | 否 | 是 |
| 防环 | —— | 否(继承原结构) | 是(memo) |
| 实现 | 解释器内联 | C 快路径 | Python 层递归 + memo |

这条递进的本质是"切断共享的层级":赋值不切、浅拷贝切到第 1 层、深拷贝切到底。代价随切断层级升高而升高。所以"选哪一档"等价于"需要切断到第几层共享":

- 只读 / 不改 → 不切(赋值/直接引用)。
- 改外层引用、元素不可变 → 切第一层(浅拷贝)。
- 改嵌套可变内层且要彻底独立 → 切到底(深拷贝)。

把这条与本篇的备忘录/不可变优化/自定义钩子合起来,浅拷贝与深拷贝的"实战"就完整了:知道何时深、知道深为何慢、知道深如何防环保同一性、知道如何用 `__deepcopy__` 精细控制。

## 5. 总结

### 5.1 本文内容回顾

- **从浅到深**:浅拷贝只复制外壳、内层共享,对嵌套可变结构不够;`copy.deepcopy` 递归复制整棵可变对象树,使副本与原图在可变结构上完全独立。

- **三条核心性质**:① 递归复制可变对象深到底;② 基本不可变对象(int/str/bytes/frozenset/None/bool)、全不可变元组常直接复用;含可变元素的元组则在有元素被复制时连同外壳一起新建(详见 4.4 的"全体未变才复用"判定);③ 用备忘录 memo 打破循环引用、保持"同一子对象多次引用"在副本里仍是同一副本。

- **循环引用安全**:`deepcopy` 在递归前把对象登记进 memo,遇到环时命中 memo 返回已建副本,既不爆栈又保持副本拓扑(自引用/互引用)与原图一致。这是浅拷贝做不到的。

- **同一性保持**:`a = [s, s]` 深拷贝后副本仍是 `[s', s']`(同一副本),而非拆成两份。备忘录让"复制图忠实于原图"。

- **自定义拷贝**:实现 `__copy__`/`__deepcopy__(self, memo)` 钩子可精细控制复制行为;钩子里必须接受并透传 memo、先登记自身防环、对不该复制的字段(单例/句柄)直接赋原引用。

- **性能**:`deepcopy` 走 Python 层递归 + memo 维护,远慢于走 C 快路径的浅拷贝;热路径/大嵌套结构慎用,优先考虑只读共享、不可变结构或结构性共享。

- **选型三档**:不拷贝(只读)→ 浅拷贝(一层/元素不可变/只换外层引用)→ 深拷贝(嵌套可变结构 + 需原地改内层彻底独立)。本质是"切断共享的层级"。

- **检验**:判断深浅用 `is` 逐层检验内层是否共享,不止看外层;外层都独立,差别在内层共享与否。

- 一句话讲清浅拷贝与深拷贝的差别(复制一层外壳 vs 递归复制整棵可变树),并说明为何嵌套可变结构必须用深拷贝。

- 说明 `deepcopy` 的三条核心性质(递归可变、不可变复用、memo 防环保同一性),并据此解释"全不可变元组 `deepcopy(x) is x` 为真""含可变元组则 `deepcopy(x) is x` 为假且内层被复制"等现象,清楚"全体元素都未变才复用元组外壳"的判定规则。
