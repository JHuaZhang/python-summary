# 字典的嵌套与深度操作

## 1. 介绍

### 1.1 什么是嵌套字典

嵌套字典（Nested Dictionary）是指字典的值本身也是一个字典，形成多层嵌套结构。 Python 中，字典的值可以是任意类型——整数、字符串、列表，当然也可以是另一个字典。当字典的值是字典时，就构成了嵌套字典。

你可以把它理解为"字典套字典"——就像俄罗斯套娃一样，打开一层里面还有一层。最外层的字典包含若干键，其中一些键对应的值又是一个字典，这个内层字典的值还可以继续是字典，层层嵌套下去。

```python
# 一个典型的嵌套字典：学生信息
student = {
    "name": "张三",
    "scores": {
        "math": 85,
        "english": 72,
        "science": {
            "physics": 90,
            "chemistry": 78
        }
    }
}
```

在这个例子中，`student` 是外层字典，`scores` 是内层字典，`science` 是更内层的字典。三层嵌套结构清晰地表达了"学生 → 科目 → 子科目"的层级关系。

### 1.2 解决什么问题

嵌套字典主要解决**层级数据的表示问题**。现实世界中的数据往往是有层次的——一个学校有多个年级，每个年级有多个班级，每个班级有多个学生。用扁平的字典无法表达这种层级关系，而嵌套字典可以自然地映射这种结构。

| 问题场景 | 扁平字典的困境 | 嵌套字典的解决方案 |
|---------|--------------|-------------------|
| 组织架构 | 键名需要拼接前缀（如"tech_head"），查询不便 | 按部门分组，逐层访问 |
| 配置管理 | 所有配置项平铺，难以按模块分类 | 按模块嵌套，结构清晰 |
| JSON 数据 | API 返回的 JSON 天然嵌套，扁平字典无法直接对应 | 嵌套字典与 JSON 结构一一对应 |
| 多维统计 | 部门×职级×性别的三维统计无法用单层字典表达 | 三层嵌套，每层一个维度 |

### 1.3 最简示例

先用一个最简单的例子建立感性认识：

```python
# 两层嵌套字典
company = {
    "name": "蚂蚁集团",
    "address": {
        "city": "杭州",
        "district": "西湖区"
    }
}

# 链式访问：逐层取值
print(company["name"])                # 蚂蚁集团
print(company["address"]["city"])     # 杭州
```

读法：`company["address"]` 先取出内层字典 `{"city": "杭州", "district": "西湖区"}`，然后 `["city"]` 从内层字典中取出值 `"杭州"`。链式访问就是从外到内逐层取下标。

## 2. 核心内容

### 2.1 嵌套字典的创建方式

#### 2.1.1 直接定义

最直观的方式是直接书写嵌套结构，适合结构固定、数据量小的场景：

```python
school = {
    "name": "希望小学",
    "address": {
        "city": "北京",
        "district": "海淀区",
        "street": "中关村南大街5号"
    },
    "students": {
        "grade1": {"count": 120, "teacher": "王老师"},
        "grade2": {"count": 135, "teacher": "李老师"},
        "grade3": {"count": 110, "teacher": "赵老师"}
    }
}
```

这个结构有三层：`school` → `students` → `grade1`，每一层都是字典。直接定义的好处是结构一目了然，缺点是数据量大时手写繁琐。

#### 2.1.2 用 dict() 构造

等价于直接定义，但用 `dict()` 构造每一层。适合从函数参数构建字典的场景：

```python
school2 = dict(
    name="希望小学",
    address=dict(
        city="北京",
        district="海淀区"
    ),
    students=dict(
        grade1=dict(count=120, teacher="王老师"),
        grade2=dict(count=135, teacher="李老师")
    )
)
```

两种写法产出的字典完全相同，选择哪种取决于个人偏好和上下文。

#### 2.1.3 推导式创建同构嵌套

当多个键需要相同的嵌套结构时，字典推导式是最佳选择。但要注意 `fromkeys` 的可变默认值陷阱：

```python
grades = ["grade1", "grade2", "grade3"]

# 错误写法：fromkeys 的可变值会被所有键共享
wrong_dict = dict.fromkeys(grades, {"count": 0, "teacher": ""})
wrong_dict["grade1"]["count"] = 100
print(wrong_dict["grade2"]["count"])  # 100，不是 0！
```

**运行结果**：

```text
100
```

原因：`fromkeys` 的第二个参数是一个对象，所有键指向同一个字典。修改 `grade1` 的 `count` 实际上修改的是那个共享对象，`grade2` 自然也变了。

正确做法是用字典推导式，每个键独立创建：

```python
correct_dict = {g: {"count": 0, "teacher": ""} for g in grades}
correct_dict["grade1"]["count"] = 100
print(correct_dict["grade2"]["count"])  # 0，不受影响
```

**运行结果**：

```text
0
```

推导式每轮迭代都会执行 `{"count": 0, "teacher": ""}` 创建新字典，所以每个键拥有独立的内层字典。

#### 2.1.4 推导式生成异构嵌套

更实用的场景是外层和内层都用推导式生成。比如生成九九乘法表字典：

```python
multiplication = {
    i: {j: i * j for j in range(1, i + 1)}
    for i in range(1, 10)
}
print(multiplication[3][3])   # 9
print(multiplication[9][9])   # 81
```

**运行结果**：

```text
9
81
```

外层推导式 `for i in range(1, 10)` 生成键 1~9，内层推导式 `for j in range(1, i + 1)` 为每个 i 生成 `{1: i, 2: 2i, ..., i: i*i}`。

#### 2.1.5 逐步构建

数据是动态添加时，用逐步构建法。场景：统计每个部门每个职级的人数：

```python
records = [
    ("技术部", "初级", 15),
    ("技术部", "中级", 10),
    ("技术部", "高级", 5),
    ("市场部", "初级", 8),
    ("市场部", "中级", 6),
]

# 方式1：手动判断键是否存在
dept_stats = {}
for dept, level, count in records:
    if dept not in dept_stats:
        dept_stats[dept] = {}          # 先建内层字典
    dept_stats[dept][level] = count     # 再往内层写入

# 方式2：用 setdefault 更简洁
dept_stats2 = {}
for dept, level, count in records:
    dept_stats2.setdefault(dept, {})[level] = count
```

**运行结果**：

```text
部门统计: {'技术部': {'初级': 15, '中级': 10, '高级': 5}, '市场部': {'初级': 8, '中级': 6}}
技术部高级人数: 5
```

`setdefault(dept, {})` 的作用是：如果 `dept` 不存在，就设为 `{}` 并返回；如果已存在，直接返回已有的字典。这样一行代码就完成了"确保内层字典存在 + 写入值"两个操作。

### 2.2 链式访问多层值

#### 2.2.1 基本链式访问

嵌套字典的访问方式是逐层取下标，从外到内：

```python
company = {
    "name": "蚂蚁集团",
    "headquarters": {
        "city": "杭州",
        "address": {
            "district": "西湖区",
            "street": "西溪路1号",
            "building": "Z空间"
        }
    },
    "departments": {
        "tech": {"head": "张三", "size": 500},
        "hr": {"head": "李四", "size": 30}
    }
}

# 三层嵌套：外层 → 中层 → 内层
district = company["headquarters"]["address"]["district"]
print(f"所在区: {district}")           # 西湖区

# 两层嵌套
tech_head = company["departments"]["tech"]["head"]
print(f"技术负责人: {tech_head}")     # 张三
```

**运行结果**：

```text
所在区: 西湖区
技术负责人: 张三
```

#### 2.2.2 链式访问的执行顺序

链式访问从左到右逐层执行，每一步返回一个中间结果：

```text
company["headquarters"]          →  {"city": "杭州", "address": {...}}
    └→ ["address"]               →  {"district": "西湖区", ...}
        └→ ["district"]           →  "西湖区"  （最终值）
```

理解这个过程很重要——你不是一次性取出"三层深的值"，而是分三步，每步取一层。中间任何一步如果键不存在，就会抛出 `KeyError`。

#### 2.2.3 混合嵌套：字典 + 列表

实际场景中，JSON API 返回的数据通常是字典和列表的混合嵌套：

```python
api_response = {
    "status": "ok",
    "data": {
        "users": [
            {"id": 1, "name": "张三", "profile": {"age": 25, "city": "北京"}},
            {"id": 2, "name": "李四", "profile": {"age": 30, "city": "上海"}}
        ],
        "total": 2
    }
}

# 字典 → 字典 → 列表 → 索引 → 字典 → 键
first_user_city = api_response["data"]["users"][0]["profile"]["city"]
print(f"第一个用户的城市: {first_user_city}")   # 北京

# 遍历列表中的字典
for user in api_response["data"]["users"]:
    print(f"  用户{user['id']}: {user['name']}, {user['profile']['age']}岁, {user['profile']['city']}")
```

**运行结果**：

```text
第一个用户的城市: 北京
  用户1: 张三, 25岁, 北京
  用户2: 李四, 30岁, 上海
```

这种混合嵌套是处理 JSON 数据时的常态，链式访问的原理不变——从左到右逐层取，遇到字典用 `["键"]`，遇到列表用 `[索引]`。

#### 2.2.4 中间层类型不一致的报错

如果中间层不是字典而是其他类型，继续用 `["键"]` 访问会报 `TypeError`：

```python
data = {
    "info": {
        "phone": "13800000000",
        "tags": ["vip", "active"]    # tags 是列表，不是字典
    }
}

# 正确：phone 是字符串，直接用
print(data["info"]["phone"])         # 13800000000

# 正确：tags 是列表，取索引
print(data["info"]["tags"][0])       # vip

# 错误：对字符串用键访问 → TypeError
# data["info"]["phone"]["xxx"]       # TypeError: string indices must be integers
```

遇到 `TypeError: ... indices must be integers` 或 `TypeError: ... object is not subscriptable` 时，先检查中间层返回的类型是否符合预期。

### 2.3 链式修改与增删

#### 2.3.1 修改已有值

与访问同理，只是最后一步改为赋值：

```python
student = {
    "name": "张三",
    "scores": {
        "math": 85,
        "english": 72,
        "science": {
            "physics": 90,
            "chemistry": 78
        }
    }
}

# 修改两层嵌套的值
student["scores"]["math"] = 95
print(student["scores"]["math"])           # 95

# 修改三层嵌套的值
student["scores"]["science"]["physics"] = 100
print(student["scores"]["science"]["physics"])  # 100
```

#### 2.3.2 添加新键

如果路径存在但最后一层不存在该键，直接赋值即可添加：

```python
# scores 存在，chinese 不存在 → 新增
student["scores"]["chinese"] = 88
print(student["scores"]["chinese"])       # 88

# 在 science 下新增 biology
student["scores"]["science"]["biology"] = 85
print(student["scores"]["science"]["biology"])  # 85
```

也可以在已有键上挂一个全新的嵌套字典：

```python
student["contact"] = {
    "phone": "13800000000",
    "address": {
        "city": "北京",
        "district": "海淀区"
    }
}
print(student["contact"]["address"]["city"])  # 北京
```

#### 2.3.3 删除嵌套键

用 `del` 删除嵌套中的某个键：

```python
del student["scores"]["chinese"]
print("chinese" in student["scores"])    # False

# 删除更深层
del student["scores"]["science"]["chemistry"]
print(student["scores"]["science"])     # {'physics': 100, 'biology': 85}
```

用 `pop` 删除并返回被删除的值：

```python
removed_math = student["scores"].pop("math")
print(f"pop返回: {removed_math}")       # 95
print(f"pop后: {student['scores']}")   # {'english': 72, 'science': {...}}
```

#### 2.3.4 批量修改嵌套数据

遍历修改值是允许的——Python 允许在遍历字典时修改值（只是不能增删键）：

```python
scores = {"math": 85, "english": 72, "physics": 90, "chemistry": 78}

# 给所有科目加5分
for subject in scores:
    scores[subject] += 5

print(scores)   # {'math': 90, 'english': 77, 'physics': 95, 'chemistry': 83}
```

#### 2.3.5 修改的副作用风险

如果多个变量引用同一个嵌套字典，修改一处会影响所有引用：

```python
config_a = {"db": {"host": "localhost", "port": 3306}}
config_b = config_a                       # 同一个对象
config_b["db"]["port"] = 5432

print(config_a["db"]["port"])              # 5432，被影响了！
print(config_a is config_b)                # True
```

这是因为 `config_b = config_a` 只是创建了新引用，两个变量指向同一个字典对象。要避免这个问题，需要用到拷贝机制（详见 2.5 节）。

### 2.4 安全访问嵌套值

#### 2.4.1 直接访问的风险

嵌套字典直接用链式下标访问，任一层缺失都会 `KeyError`：

```python
user = {
    "name": "张三",
    "profile": {"age": 25, "city": "北京"}
}

# 正常访问
print(user["profile"]["city"])             # 北京

# profile 下没有 email 键
# user["profile"]["email"]                 # KeyError!
```

在处理不确定性数据（如 API 返回、用户输入）时，直接访问是不安全的。

#### 2.4.2 get 链式安全访问

`get(key, default)` 在键不存在时返回默认值而非报错。逐层用 `get`，每层传一个空字典 `{}` 作为默认值：

```python
# 两层 get
email = user.get("profile", {}).get("email", "未填写")
print(email)                               # 未填写

# 外层就缺失
phone = user.get("contact", {}).get("phone", "无联系方式")
print(phone)                               # 无联系方式

# 三层 get
country = user.get("profile", {}).get("location", {}).get("country", "中国")
print(country)                             # 中国
```

**运行结果**：

```text
未填写
无联系方式
中国
```

原理：`get("profile", {})` 如果 `profile` 不存在就返回 `{}`，然后 `{}.get("email", "未填写")` 自然返回 `"未填写"`。链条中任一环节断裂，都会优雅地降级到默认值。

#### 2.4.3 get 链的陷阱

`get` 链有一个陷阱：如果中间层存在但不是字典（比如是字符串），对它调 `get` 会 `AttributeError`：

```python
mixed_data = {"info": "这是一个字符串，不是字典"}

# info 存在且是字符串，get("info", {}) 返回字符串
# 然后对字符串调 get → AttributeError
# mixed_data.get("info", {}).get("x")   # AttributeError: 'str' object has no attribute 'get'
```

解决方法：用 `try-except` 或自定义安全取值函数。

#### 2.4.4 try-except 方式

另一种安全访问方式是直接访问 + 捕获异常，适合"大概率键存在，偶尔缺失"的场景：

```python
try:
    deep_value = user["profile"]["address"]["street"]
    print(f"深层值: {deep_value}")
except KeyError as e:
    print(f"键不存在: {e}")               # 'address'
```

**运行结果**：

```text
键不存在: 'address'
```

#### 2.4.5 get 链 vs try-except 对比

| 维度 | get 链 | try-except |
|------|--------|------------|
| 可读性 | 层级多时冗长 | 简洁 |
| 性能 | 每层都调用 get | 正常路径零开销 |
| 异常类型 | 只处理 KeyError | 可区分 KeyError / TypeError |
| 默认值 | 每层可设不同默认值 | 统一处理 |
| 适用场景 | 层级浅、不确定性强 | 层级深、大概率存在 |

```python
# get 链——每层都安全，但要写很多 get
theme1 = api_response.get("data", {}).get("users", [{}])[0].get("profile", {}).get("city", "未知")

# try-except——简洁
try:
    theme2 = api_response["data"]["users"][0]["profile"]["city"]
except (KeyError, IndexError, TypeError):
    theme2 = "未知"
```

#### 2.4.6 自定义安全访问函数

封装一个通用的安全取值函数，兼顾简洁和安全：

```python
def safe_get(d, *keys, default=None):
    """逐层安全取值，任一层缺失或类型不匹配返回 default"""
    current = d
    for key in keys:
        if isinstance(current, dict):
            current = current.get(key, default)
        else:
            return default
    return current

# 使用示例
user = {"name": "张三", "profile": {"age": 25, "city": "北京"}}

name = safe_get(user, "profile", "name", default="匿名")
print(name)                               # 匿名（profile下没有name）

age = safe_get(user, "profile", "age", default=0)
print(age)                                 # 25

# 深层缺失
admin = safe_get(user, "profile", "permissions", "admin", default=False)
print(admin)                               # False

# 中间层不是字典
mixed = {"info": "字符串"}
result = safe_get(mixed, "info", "x", default="N/A")
print(result)                              # N/A
```

**运行结果**：

```text
匿名
25
False
N/A
```

`safe_get` 的核心逻辑：逐层判断当前值是否为字典，是则继续取键，不是则直接返回默认值。这样既处理了 `KeyError`（键缺失），也处理了 `TypeError`（中间层非字典）。

### 2.5 浅拷贝与深拷贝

#### 2.5.1 赋值不是拷贝

直接赋值只是创建了一个新的引用，指向同一个字典对象：

```python
import copy

original = {"name": "张三", "scores": {"math": 85, "english": 72}}
reference = original
reference["name"] = "李四"

print(original["name"])                    # 李四（被影响了）
print(original is reference)              # True
```

#### 2.5.2 浅拷贝

浅拷贝（`copy.copy` 或 `dict.copy`）创建新的外层字典，但内层嵌套对象仍然共享：

```python
shallow = copy.copy(original)
# 也可以用 original.copy()，效果一样

# 外层独立
print(original is shallow)                        # False

# 内层共享！
print(original["scores"] is shallow["scores"])    # True
```

修改外层互不影响，但修改内层会互相影响——这是浅拷贝的核心陷阱：

```python
# 修改外层：互不影响
shallow["name"] = "王五"
print(original["name"])                    # 李四（不受影响）

# 修改内层：互相影响！
shallow["scores"]["math"] = 100
print(original["scores"]["math"])          # 100！被影响了
```

**运行结果**：

```text
李四
100
```

原因可以用下图理解：

```text
浅拷贝后的内存关系：

  original ──→ { "name": ..., "scores": ──┐ }
                                            ↓
  shallow  ──→ { "name": ..., "scores": ──┐ }
                                            ↓
                                   同一个 scores 字典
                                   {"math": 85, ...}
```

外层字典是两个独立对象，但 `scores` 键指向同一个内层字典。修改任一方的 `scores` 内部，另一方都能看到。

#### 2.5.3 深拷贝

深拷贝（`copy.deepcopy`）递归复制所有层级，内外层都完全独立：

```python
original2 = {
    "name": "张三",
    "info": {
        "address": {
            "city": "北京",
            "district": "海淀区"
        }
    }
}

deep = copy.deepcopy(original2)

# 外层不同
print(original2 is deep)                                    # False
# 中间层不同
print(original2["info"] is deep["info"])                    # False
# 最内层也不同
print(original2["info"]["address"] is deep["info"]["address"])  # False
```

修改任意层都不影响原字典：

```python
deep["info"]["address"]["city"] = "上海"
print(original2["info"]["address"]["city"])  # 北京（不受影响）
print(deep["info"]["address"]["city"])       # 上海
```

#### 2.5.4 浅拷贝 vs 深拷贝对比

用一个三层嵌套字典做全面对比：

```python
data = {
    "level1": "value1",
    "level2": {
        "level3": {
            "level4": "deep_value"
        }
    }
}

sh = copy.copy(data)
dp = copy.deepcopy(data)

# 对比每一层是否为同一对象
print(f"{'层级':<20} {'浅拷贝(同一对象?)':<20} {'深拷贝(同一对象?)'}")
print(f"{'外层dict':<20} {data is sh:<20} {data is dp}")
print(f"{'data[\"level2\"]':<20} {data['level2'] is sh['level2']:<20} {data['level2'] is dp['level2']}")
print(f"{'data[l2][l3]':<20} {data['level2']['level3'] is sh['level2']['level3']:<20} {data['level2']['level3'] is dp['level2']['level3']}")
```

**运行结果**：

```text
层级                   浅拷贝(同一对象?)           深拷贝(同一对象?)
外层dict               False                False
data["level2"]         True                 False
data[l2][l3]           True                 False
```

| 维度 | 浅拷贝 (copy.copy) | 深拷贝 (copy.deepcopy) |
|------|-------------------|----------------------|
| 外层字典 | 独立 | 独立 |
| 内层嵌套 | 共享 | 独立 |
| 修改外层影响原字典 | 否 | 否 |
| 修改内层影响原字典 | **是** | 否 |
| 性能 | 快 | 较慢（递归复制） |
| 适用场景 | 扁平字典 | 嵌套字典 |

#### 2.5.5 嵌套列表的拷贝

字典内部嵌套列表时，浅拷贝同样共享内层列表：

```python
config = {
    "name": "test",
    "tags": ["python", "dict", "nested"],
    "nested_list": [[1, 2], [3, 4]]
}

shallow_config = copy.copy(config)
deep_config = copy.deepcopy(config)

# 浅拷贝：tags 列表共享
shallow_config["tags"].append("shared")
print(config["tags"])                      # ['python', 'dict', 'nested', 'shared']

# 深拷贝：tags 列表独立
deep_config["tags"].append("independent")
print(config["tags"])                      # ['python', 'dict', 'nested', 'shared']（不受影响）

# 嵌套列表中的列表也要深拷贝才能独立
deep_config["nested_list"][0].append(99)
print(config["nested_list"][0])            # [1, 2]（不受影响）
print(deep_config["nested_list"][0])      # [1, 2, 99]
```

#### 2.5.6 拷贝选择建议

| 场景 | 推荐方案 |
|------|---------|
| 纯扁平字典（无嵌套） | `copy.copy` 或 `dict.copy` |
| 有嵌套字典/列表 | `copy.deepcopy` |
| 需要完全隔离 | `copy.deepcopy` 是唯一可靠方案 |

```python
# 扁平字典：浅拷贝就够
flat = {"a": 1, "b": 2}
flat_copy = flat.copy()
flat_copy["a"] = 99
print(flat["a"])                           # 1，安全

# 嵌套字典：必须深拷贝
nested = {"inner": {"x": 1}}
nested_deep = copy.deepcopy(nested)
nested_deep["inner"]["x"] = 99
print(nested["inner"]["x"])               # 1，安全
```

### 2.6 递归遍历嵌套字典

#### 2.6.1 递归遍历所有键值对

递归思路：遇到字典就继续深入，遇到非字典（叶子节点）就处理当前值：

```python
def traverse(d, path=""):
    """递归遍历嵌套字典，打印所有叶子节点的路径和值"""
    if isinstance(d, dict):
        for key, value in d.items():
            current_path = f"{path}.{key}" if path else key
            traverse(value, current_path)
    else:
        print(f"  {path} = {d}")

company = {
    "name": "蚂蚁集团",
    "hq": {
        "city": "杭州",
        "address": {"district": "西湖区", "street": "西溪路"}
    },
    "dept": {"tech": {"head": "张三", "count": 500}}
}

traverse(company)
```

**运行结果**：

```text
  name = 蚂蚁集团
  hq.city = 杭州
  hq.address.district = 西湖区
  hq.address.street = 西溪路
  dept.tech.head = 张三
  dept.tech.count = 500
```

递归的执行过程可以用下图理解：

```text
traverse(company, "")
├→ key="name", value="蚂蚁集团"  → 非dict → 打印 name = 蚂蚁集团
├→ key="hq", value={...}        → 是dict → traverse(value, "hq")
│   ├→ key="city", value="杭州" → 非dict → 打印 hq.city = 杭州
│   └→ key="address", value={...} → 是dict → traverse(value, "hq.address")
│       ├→ key="district" → 非dict → 打印 hq.address.district = 西湖区
│       └→ key="street"   → 非dict → 打印 hq.address.street = 西溪路
└→ key="dept", value={...}      → 是dict → traverse(value, "dept")
    └→ key="tech", value={...}   → 是dict → traverse(value, "dept.tech")
        ├→ key="head"  → 非dict → 打印 dept.tech.head = 张三
        └→ key="count" → 非dict → 打印 dept.tech.count = 500
```

#### 2.6.2 收集所有键值对到列表

有时候不只是打印，还需要收集结果做进一步处理：

```python
def collect_pairs(d, path="", pairs=None):
    """收集所有叶子节点的 (路径, 值) 到列表"""
    if pairs is None:
        pairs = []
    if isinstance(d, dict):
        for key, value in d.items():
            current_path = f"{path}.{key}" if path else key
            collect_pairs(value, current_path, pairs)
    else:
        pairs.append((path, d))
    return pairs

all_pairs = collect_pairs(company)
for path, value in all_pairs:
    print(f"  {path} → {value}")
```

**运行结果**：

```text
  name → 蚂蚁集团
  hq.city → 杭州
  hq.address.district → 西湖区
  hq.address.street → 西溪路
  dept.tech.head → 张三
  dept.tech.count → 500
```

注意 `pairs=None` 的写法——不能直接用 `pairs=[]` 作为默认参数，因为 Python 的默认参数在函数定义时只创建一次，多次调用会共享同一个列表。

#### 2.6.3 按深度遍历

记录每个键值对所在层级深度：

```python
def traverse_by_depth(d, depth=0, results=None):
    """按深度遍历，记录每个键值对所在层级"""
    if results is None:
        results = []
    if isinstance(d, dict):
        for key, value in d.items():
            results.append((depth, key, value))
            if isinstance(value, dict):
                traverse_by_depth(value, depth + 1, results)
    return results

depth_results = traverse_by_depth(company)
for depth, key, value in depth_results:
    indent = "  " * depth
    type_name = type(value).__name__ if not isinstance(value, dict) else "dict"
    print(f"  [深度{depth}] {indent}{key} ({type_name})")
```

**运行结果**：

```text

  [深度0] hq (dict)
  [深度1]   city (str)
  [深度1]   address (dict)
  [深度2]     district (str)
  [深度2]     street (str)
```

#### 2.6.4 查找特定键

在嵌套字典中查找指定键名，返回所有匹配的路径：

```python
def find_key(d, target_key, path=""):
    """在嵌套字典中查找指定键，返回所有匹配的路径"""
    results = []
    if isinstance(d, dict):
        for key, value in d.items():
            current_path = f"{path}.{key}" if path else key
            if key == target_key:
                results.append((current_path, value))
            if isinstance(value, dict):
                results.extend(find_key(value, target_key, current_path))
    return results

# 含有重复键的嵌套字典
data = {
    "name": "root",
    "config": {"name": "config_name", "value": 1},
    "info": {"name": "info_name", "sub": {"name": "sub_name"}}
}

found = find_key(data, "name")
for path, value in found:
    print(f"  {path} = {value}")
```

**运行结果**：

```text
  name = root
  config.name = config_name
  info.name = info_name
  info.sub.name = sub_name
```

这种查找在处理 JSON 配置时很有用——比如你想知道配置中有哪些地方设置了 `"timeout"` 键，递归查找可以一次找到所有。

```python
search_data = {"a": 1, "b": {"c": 1, "d": 2}, "e": {"f": {"g": 1, "h": 3}}}
```

#### 2.6.6 递归计算最大深度

```python
def max_depth(d):
    """计算嵌套字典的最大深度"""
    if not isinstance(d, dict) or not d:
        return 0
    return 1 + max(max_depth(v) for v in d.values())

deep_dict = {"a": {"b": {"c": {"d": "到底了"}}}, "x": {"y": 1}}

print(f"最大深度: {max_depth(deep_dict)}")      # 4
print(f"空字典深度: {max_depth({})}")             # 0
print(f"扁平字典深度: {max_depth({'a': 1})}")     # 1
```

`max_depth` 的逻辑：如果当前不是字典或是空字典，深度为 0；否则深度为 1 + 所有子值中最大的深度。递归到叶子节点时返回 0，逐层加 1 累计。

### 2.7 扁平化与还原

#### 2.7.1 扁平化：嵌套字典转扁平字典

将多层嵌套的字典展平为单层，键用点号连接：

```python
def flatten(d, parent_key="", sep="."):
    """将嵌套字典扁平化为单层字典，键用 sep 连接"""
    items = []
    for key, value in d.items():
        new_key = f"{parent_key}{sep}{key}" if parent_key else key
        if isinstance(value, dict):
            items.extend(flatten(value, new_key, sep).items())
        else:
            items.append((new_key, value))
    return dict(items)

config = {
    "app": {
        "name": "myapp",
        "version": "1.0",
        "database": {"host": "localhost", "port": 3306, "name": "testdb"}
    },
    "log": {"level": "INFO", "file": "/var/log/app.log"}
}

flattened = flatten(config)
for key, value in flattened.items():
    print(f"  {key} = {value}")
```

**运行结果**：

```text
  app.name = myapp
  app.version = 1.0
  app.database.host = localhost
  app.database.port = 3306
  app.database.name = testdb
  log.level = INFO
  log.file = /var/log/app.log
```

#### 2.7.2 自定义分隔符

`sep` 参数支持不同的分隔符——下划线、斜杠等：

```python

for key, value in flat_underscore.items():
    print(f"  {key} = {value}")
```

**运行结果**：

#### 2.7.3 还原：扁平字典转嵌套字典

```python
def unflatten(flat_dict, sep="."):
    """将扁平字典还原为嵌套字典"""
    result = {}
    for key, value in flat_dict.items():
        parts = key.split(sep)
        current = result
        for part in parts[:-1]:
            if part not in current or not isinstance(current[part], dict):
                current[part] = {}
            current = current[part]
        current[parts[-1]] = value
    return result

restored = unflatten(flattened)
print(restored["app"]["name"])                 # myapp
print(restored["app"]["database"]["host"])      # localhost
print(restored["log"]["level"])                 # INFO
```

还原逻辑：对每个扁平键按 `sep` 拆分，逐层创建嵌套字典，最后在叶子层赋值。

#### 2.7.4 往返验证

扁平化再还原，结果应该和原字典一致：

```python
round_trip = unflatten(flatten(config))
print(f"往返验证一致: {round_trip == config}")  # True
```

#### 2.7.6 含列表值的扁平化

当嵌套字典中有列表时，可以选择按索引展开：

```python
def flatten_with_lists(d, parent_key="", sep="."):
    """扁平化时处理列表：将列表元素按索引展开"""
    items = []
    for key, value in d.items():
        new_key = f"{parent_key}{sep}{key}" if parent_key else key
        if isinstance(value, dict):
            items.extend(flatten_with_lists(value, new_key, sep).items())
        elif isinstance(value, list):
            for i, item in enumerate(value):
                indexed_key = f"{new_key}{sep}{i}"
                if isinstance(item, dict):
                    items.extend(flatten_with_lists(item, indexed_key, sep).items())
                else:
                    items.append((indexed_key, item))
        else:
            items.append((new_key, value))
    return dict(items)

data_with_list = {
    "users": [
        {"name": "张三", "age": 25},
        {"name": "李四", "age": 30}
    ],
    "total": 2
}

flat_list = flatten_with_lists(data_with_list)
for key, value in flat_list.items():
    print(f"  {key} = {value}")
```

**运行结果**：

```text

  users.0.age = 25
  users.1.name = 李四
  users.1.age = 30
  total = 2
```

## 3. 最佳实践

### 3.1 嵌套层级控制：推荐 vs 不推荐

**推荐**：层级不超过 3~4 层，超过时考虑用数据类或对象替代。

```python
# 推荐：3层嵌套，结构清晰
user = {
    "name": "张三",
    "profile": {"age": 25, "city": "北京"},
    "settings": {"theme": "dark", "lang": "zh"}
}

# 不推荐：5层嵌套，链式访问太长，可读性差
deep = {
    "a": {"b": {"c": {"d": {"e": "太难访问了"}}}}
}
print(deep["a"]["b"]["c"]["d"]["e"])   # 链太长，容易出错
```

**推荐**：用有意义的键名，避免歧义。

```python
# 推荐
order = {
    "customer": {"name": "张三", "address": {"city": "北京"}},
    "product": {"name": "手机", "price": 5999}
}

# 不推荐：key 太抽象，看不出层级关系
data = {
    "a": {"b": {"c": "北京"}},
    "d": {"e": "手机"}
}
```

### 3.2 安全访问：推荐 vs 不推荐

**推荐**：不确定数据完整性时用 `get` 链或 `safe_get`。

```python
# 推荐：用 get 链安全访问
city = user.get("profile", {}).get("address", {}).get("city", "未知")

# 推荐：封装 safe_get 函数
city = safe_get(user, "profile", "address", "city", default="未知")

# 不推荐：直接访问，任一层缺失就崩溃
city = user["profile"]["address"]["city"]   # 可能 KeyError
```

**推荐**：确定数据完整时用直接访问，简洁高效。

```python
# 数据来源可靠，结构确定时直接访问没问题
config = load_config()   # 自己加载的配置，结构确定
host = config["database"]["host"]   # 直接访问，简洁
```

### 3.3 拷贝选择：推荐 vs 不推荐

**推荐**：嵌套字典用 `deepcopy`，扁平字典用 `copy`。

```python
# 推荐：嵌套字典用 deepcopy
import copy
new_config = copy.deepcopy(config)

# 推荐：扁平字典用 copy
flat_copy = flat_dict.copy()

# 不推荐：嵌套字典用浅拷贝，内层会共享
new_config = copy.copy(config)   # 内层还是共享的！
```

### 3.4 常见错误模式与修正

| 错误模式 | 问题 | 修正方式 |
|---------|------|---------|
| `dict.fromkeys(keys, {})` | 所有键共享同一个字典 | 用推导式 `{k: {} for k in keys}` |
| 浅拷贝后改内层 | 原字典被修改 | 改用 `deepcopy` |
| `get` 链遇到非字典中间层 | `AttributeError` | 用 `safe_get` 或 `try-except` |
| 多层直接访问不确定数据 | `KeyError` | 用 `get` 链或 `try-except` |
| 递归函数默认参数用 `[]` | 多次调用共享列表 | 用 `None` + 函数内初始化 |

### 3.5 递归函数的注意事项

**推荐**：用 `None` 作为可变默认参数的占位符。

```python
# 推荐
def collect(d, pairs=None):
    if pairs is None:
        pairs = []
    # ...
    return pairs

# 不推荐：默认参数在函数定义时只创建一次
def collect(d, pairs=[]):   # 多次调用共享同一个列表！
    # ...
    return pairs
```

**推荐**：递归函数加类型检查，避免非字典输入导致无限递归。

```python
# 推荐：先检查类型再递归
def safe_traverse(d):
    if not isinstance(d, dict):
        return
    for key, value in d.items():
        if isinstance(value, dict):
            safe_traverse(value)
        else:
            print(f"{key} = {value}")
```

## 4. 原理：嵌套字典的内存模型与拷贝机制

### 4.1 字典的引用语义

Python 中字典是引用类型——变量存储的不是字典本身，而是指向字典对象的引用。理解这一点是理解嵌套字典拷贝行为的基础。

```python
a = {"x": 1}
b = a
```

这段代码执行后，`a` 和 `b` 指向内存中同一个字典对象：

```text
栈帧（变量引用）          堆（对象）
  a ──────────────→  {"x": 1}
  b ──────────────→  ↑ 同一个对象
```

用 `id()` 可以验证：

```python
print(id(a) == id(b))    # True
print(a is b)            # True
```

### 4.2 嵌套字典的内存结构

嵌套字典的外层和内层是独立的对象，通过引用连接：

```python
d = {"outer": {"inner": 42}}
```

内存结构：

```text
  d ──→ 外层字典 {"outer": ──┐}
                              ↓
                    内层字典 {"inner": 42}
```

外层字典存储的 `"outer"` 键对应的值是一个引用，指向内层字典对象。这意味着：

- 浅拷贝外层字典时，只复制了外层字典，内层字典的引用被原样复制——两个外层字典的 `"outer"` 指向同一个内层字典。
- 深拷贝时，递归地复制每一层——内层字典也被复制，两个外层字典的 `"outer"` 指向各自独立的内层字典。

### 4.3 copy.copy 的实现机制

`copy.copy` 对字典的实现等价于创建一个新字典，把原字典的所有键值对复制过去：

```python
# copy.copy(d) 等价于：
new_dict = {}
for key, value in d.items():
    new_dict[key] = value    # 值是引用，直接复制引用
return new_dict
```

因为值是引用，所以 `new_dict` 中的值和原字典中的值指向同一个内层对象。这就是浅拷贝只复制外层的原因。

### 4.4 copy.deepcopy 的实现机制

`copy.deepcopy` 递归地复制每一个可变对象：

```python
# copy.deepcopy(d) 的简化逻辑：
def deep_copy(obj):
    if isinstance(obj, dict):
        new_dict = {}
        for key, value in obj.items():
            new_dict[deep_copy(key)] = deep_copy(value)  # 递归复制值
        return new_dict
    elif isinstance(obj, list):
        return [deep_copy(item) for item in obj]
    else:
        return obj    # 不可变对象直接返回
```

深拷贝还维护了一个 `memo` 字典来处理循环引用——如果对象 A 引用了自身，`memo` 会记录已复制的对象，避免无限递归：

```python
# 循环引用的例子
a = {}
a["self"] = a    # a 引用自身

# deepcopy 能正确处理
import copy
b = copy.deepcopy(a)
print(b["self"] is b)    # True，b 也引用自身
print(b is a)            # False，但 b 和 a 是不同对象
```

### 4.5 不可变对象不需要拷贝

整数、字符串、元组等不可变对象不需要拷贝——因为无法修改它们，共享引用不会有副作用：

```python
a = "hello"
b = a           # 共享同一个字符串对象
b = "world"      # 只是让 b 指向新对象，不影响 a
print(a)         # hello
```

这就是为什么浅拷贝对扁平字典是安全的——扁平字典的值通常是不可变对象（整数、字符串），共享引用没有副作用。只有当值是可变对象（字典、列表）时，浅拷贝才不安全。
