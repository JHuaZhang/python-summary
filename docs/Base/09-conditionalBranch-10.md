# 链式比较

## 1. 介绍

### 1.1 什么是链式比较

判断一个值在不在某个区间里，是条件分支里极高频的需求：成绩在不在 0 到 100、年龄在不在 18 到 60、温度在不在舒适区间。用比较运算符单独写，这两种思路都能做到——写 `x >= 0 and x <= 100` 用 `and` 把两个比较拼起来，或者写成 `0 <= x <= 100` 一次性表达。后一种"把多个比较连着写"的语法，就叫**链式比较**（chained comparison）。

链式比较是 Python 的一个语法便利：它允许把 `a < b and b < c` 简写成 `a < b < c`，让区间判断读起来几乎和数学里的不等式一模一样——`0 <= x <= 100` 一眼就能看出"x 在 0 到 100 之间（含端点）"，不必在脑子里把 `and` 拆成两半再拼。它不止能连 `<` `<=`，还能连 `>` `>=` `==` `!=`，方向也可以任意搭配，比如 `a < b > c` 这种"拐弯"写法。

链式比较和用 `and` 拼接不等价的地方有两点：一是可读性更好（像数学不等式），二是**中间操作数只求值一次**——`a < f() < c` 里 `f()` 只算一次，而 `a < f() and f() < c` 会把 `f()` 调两次。理解这两点，才能既用得顺、又不踩坑。

**一句话定位**：链式比较把 `a < b and b < c` 简写成 `a < b < c`，像数学不等式一样直观地表达"区间/范围"判断，且中间值只求值一次。

### 1.2 最简示例

先用一个最小例子看清链式比较的样子：判断一个数在不在 0 到 10 之间。

```python
x = 5

if 0 < x < 10:           # 链式比较：0 < x 且 x < 10
    print(f"{x} 在 0~10 之间")
else:
    print(f"{x} 不在 0~10 之间")
```

**运行结果**：

```text
5 在 0~10 之间
```

`0 < x < 10` 就是一条链式比较：它等价于 `0 < x and x < 10`，要求两个比较都成立整体才为真。`x` 为 5 时，`0 < 5` 和 `5 < 10` 都成立，整体 `True`，命中 `if`。把 `x` 改成 `-1`，`0 < -1` 不成立，整体直接 `False`——这正是后续会讲到的"短路"行为：左边失败了，右边那段不必再看。

### 1.3 速览

链式比较的关键用法整体如下，先建个总印象，后面逐个展开：

| 写法 | 含义 | 等价 and 拼接 | 典型场景 |
|------|------|-------------|---------|
| `a < b < c` | a<b 且 b<c | `a < b and b < c` | 严格区间 |
| `a <= b <= c` | a≤b 且 b≤c | `a <= b and b <= c` | 含端点闭区间 |
| `0 <= x <= 100` | 闭区间判断 | `0 <= x and x <= 100` | 边界校验 |
| `a < b > c` | a<b 且 b>c（任意方向） | `a < b and b > c` | "b 在 a、c 之间且都比它们大" |
| `a == b == c` | a==b 且 b==c | `a == b and b == c` | 多值相等 |

几个要点先记在心里，后面逐一展开：

- 链式比较**等价于**把每相邻两个操作数用 `and` 拼起来，全部成立才为真。
- 中间操作数**只求值一次**：`a < f() < c` 调 `f()` 一次，`a < f() and f() < c` 调两次。
- 链式比较有**短路**：左边比较失败时，右侧不再求值。
- 方向可以任意搭配（`<` `>` `<=` `>=` `==` `!=` 混着连），但**混用时语义是"a 比中、中比右"，逐段判断**。
- `a == b == c` 不是"三者同时相等的结果"，而是"a==b 且 b==c"——别误读。

## 2. 核心内容

### 2.1 基本语法：a < b < c 等价 a < b and b < c

链式比较的基本形态是把三个或更多操作数用比较运算符连成一串，整体语义是"每相邻两侧的比较都成立"。最经典的三段式 `a < b < c`，等价于 `a < b and b < c`。

**基本对比**：

```python
x = 5
print(0 < x < 10)            # True，链式比较
print(0 < x and x < 10)      # True，等价的 and 拼接
```

**运行结果**：

```text
True
True
```

两种写法结果完全一致。区别在于：链式写法 `0 < x < 10` 像数学不等式，一眼读懂"x 在 0 到 10 之间"；`and` 拼接要把 `0 < x` 和 `x < 10` 两个比较拆开再在心里拼回去，多一道转译。对区间判断这种"范围"语义，链式比较天然更贴切。

**两端都成立才为真**：

```python
for v in [-1, 5, 15]:
    print(0 < v < 10)
```

**运行结果**：

```text
False
True
False
```

`-1` 让左比较 `0 < -1` 失败，`15` 让右比较 `15 < 10` 失败，二者整体都 `False`；只有 `5` 两段都成立才 `True`。链式比较要求"全段通过"，这一行为和 `and` 拼接一致。

### 2.2 范围判断：闭区间 0 <= x <= 100

范围判断是链式比较最常用、也最能体现优势的场景。闭区间用 `<=` `>=`，半开区间混用 `<=` 和 `<`，边界是否含端点完全由运算符决定。

**闭区间（含两端边界）**：

```python
for score in [85, -5, 0, 100, 120]:
    print(0 <= score <= 100)
```

**运行结果**：

```text
True
False
True
True
False
```

`0 <= score <= 100` 一行表达"成绩在 0 到 100 之间，含两端"。注意边界值 0 和 100 都判定为 `True`（合法），而 `-5` 和 120 判定 `False`（越界）——这正是 `<=` 把端点算进区间的体现。

**半开区间（左闭右开）**：Python 的切片索引场景里，合法索引范围是 `0 <= idx < len`，左闭右开，正好用 `<=` 和 `<` 混写：

```python
data = [10, 20, 30]
idx = 1
print(0 <= idx < len(data))     # True，idx 是合法索引
```

**运行结果**：

```text
True
True
```

**边界是否含端点**：用 `<=` 还是 `<` 决定端点算不算在内，这一点最容易记混，用具体值验证最清楚：

```python
x = 10
print(0 <= x <= 10)      # True，用 <= 边界算在内
print(0 <= x < 10)       # False，用 < 边界排除在外
```

**运行结果**：

```text
True
False
```

`x = 10` 时，`0 <= x <= 10` 为 `True`（右端 `<= 10` 含 10），而 `0 <= x < 10` 为 `False`（右端 `< 10` 排除 10）。**口诀：含边界用 `<=` `>=`，不含边界用 `<` `>`**，半开区间就把两种混起来写。

**校验成绩合法性**——范围判断的标准用法，一行判断一个值合法不合法：

```python
for s in [60, 0, 100, -1, 101]:
    if 0 <= s <= 100:
        print(f"{s:>4} 合法")
    else:
        print(f"{s:>4} 非法")
```

**运行结果**：

```text
  60 合法
   0 合法
 100 合法
  -1 非法
 101 非法
```

### 2.3 任意方向：a < b > c

链式比较不要求方向一致——可以把 `<` `>` `<` `>` 任意混着连，语义是"逐段判断相邻两侧的关系都成立"。最典型的"拐弯"写法 `a < b > c`，意思是"a<b 且 b>c"，常用来表达"b 比 a 和 c 都大"。

```python
a, b, c = 1, 5, 3
print(a < b > c)        # True，1<5 且 5>3
print(a > b < c)        # False，1>5 不成立
```

**运行结果**：

```text
True
False
```

`a < b > c` 读作"a 小于 b，且 b 大于 c"——逐段拆开理解就行，方向不一致也完全合法。`a > b < c` 同理：先判 `a > b`（1>5 失败），失败后整体直接 `False`。

任意方向写法虽然能跑，但**方向杂乱会牺牲可读性**，比如 `a < b > c < b` 这种四段拐弯，读者要逐段跟着拐，很容易看错。**实际写代码时，优先选择方向一致的同向链式（全 `<` 或全 `>`），或在拐弯处加注释说明意图**。

### 2.4 中间操作数只求值一次

这是链式比较和 `and` 拼接最本质的区别：**链式比较里的中间操作数只求值一次**，而写成 `a < f() and f() < c` 会让 `f()` 被调用两次。当中间值是带副作用的函数调用、或计算开销较大时，这个差异很重要。

用调用计数"亲眼"看到差异：

```python
call_count = 0

def f():
    global call_count
    call_count += 1
    return 5

# 链式比较：中间值 f() 只求一次
call_count = 0
result = 0 < f() < 10
print(f"0 < f() < 10 → {result}，f 共调用 {call_count} 次")

# and 拼接直接写 f() 两次：f 调两次
call_count = 0
result = 0 < f() and f() < 10
print(f"0 < f() and f() < 10 → {result}，f 共调用 {call_count} 次")

# and 拼接先存变量：f 只调一次
call_count = 0
v = f()
result = 0 < v and v < 10
print(f"0 < v and v < 10 → {result}，f 共调用 {call_count} 次")
```

**运行结果**：

```text
0 < f() < 10 → True，f 共调用 1 次
0 < f() and f() < 10 → True，f 共调用 2 次
0 < v and v < 10 → True，f 共调用 1 次
```

三种写法结果都为 `True`，但 `f()` 的调用次数差别明显：链式比较只调 1 次，`and` 直接拼两次会调 2 次，先存变量再拼也是 1 次。所以"链式比较中间值只求一次"的好处，等价于"`and` 拼接先存变量"的效果，但写法更简洁——不用显式声明中间变量。

**短路特性**：链式比较也有短路——左边比较失败时，右侧不再求值。这一点和 `and` 拼接一致：

```python
call_count = 0
result = 100 < f() < 1000      # 100 < 5 为假，整体直接 False
print(f"100 < f() < 1000 → {result}，f 共调用 {call_count} 次")
```

**运行结果**：

```text
100 < f() < 1000 → False，f 共调用 1 次
```

`100 < f()`（`100 < 5`）为假，链式比较短路返回 `False`，右侧的 `1000` 根本没参与比较。而 `f()` 作为中间操作数已经被求值了一次（它是左侧比较的一部分），所以计 1 次。短路与"只求一次"互不冲突：中间值永远只求一次，右侧值在短路时跳过。

### 2.5 不同运算符混合

链式比较里的运算符不必相同——`<` `>` `<=` `>=` `==` `!=` 可以混着连。混用时语义依然是"逐段判断相邻两侧的关系都成立"，但要注意混 `==` 容易让人误读。

**混用 `==` 和 `<`**：

```python
print(3 == 3 < 10)        # True，3==3 且 3<10
print(0 < 3 == 3)         # True，0<3 且 3==3
```

**运行结果**：

```text
True
True
```

`3 == 3 < 10` 读作"3 等于 3，且 3 小于 10"，逐段都成立所以为 `True`。`0 < 3 == 3` 同理："0 小于 3，且 3 等于 3"。混用运算符时记住一条规则：**永远是"左操作数 与 中操作数 比、中操作数 与 右操作数 比"，不是"整个比较的结果再做什么"**。

**`a == b == c` 的语义**：这是最容易误读的一处——`a == b == c` 表示"a==b 且 b==c"，不是"三者同时相等的结果"，也不是"`(a==b) == (b==c)`":

```python
print(3 == 3 == 3)        # True，3==3 且 3==3
print(1 == 2 == 2)        # False，1==2 失败，整体 False
```

**运行结果**：

```text
True
False
```

`3 == 3 == 3` 两段都成立所以 `True`；`1 == 2 == 2` 第一段 `1 == 2` 失败，整体 `False`，并不会因为"2==2"相等的部分而变真。理解为"a==b 且 b==c"就不会错：要求相邻两段都成立。

### 2.6 多段比较链

链式比较不止三段，可以连成任意多段：`a < b < c < d` 要求"每相邻一段都成立"。多段链式在"层层递进的范围判断"里偶尔有用，但段数多了要小心可读性。

```python
print(0 < 3 < 5 < 10)     # True，四段逐段成立
print(0 < 3 < 5 < 4)      # False，5<4 不成立，整体 False
```

**运行结果**：

```text
True
False
```

`0 < 3 < 5 < 10` 四段全成立：0<3、3<5、5<10，整体 `True`。`0 < 3 < 5 < 4` 三段成立但第四段 `5 < 4` 失败，整体变 `False`——链式比较要求"全程绿灯"，任何一段断了都整体为假。多段链式本质上和 `and` 拼接等价（`0<3 and 3<5 and 5<10`），但在段数较多时，链式写法的可读性优势更明显。

### 2.7 典型应用场景

链式比较的应用模式可以照搬到很多业务场景，几乎都围绕"区间/范围判断"展开。

#### 2.7.1 闭区间判断

判断一个值在不在闭区间内，是链式比较最自然的用法：

```python
def is_normal_temp(t):
    return 36 <= t <= 37.5       # 体温正常区间（含端点）

for t in [36.5, 36.0, 37.5, 38.0]:
    print(f"{t}°C 正常？{is_normal_temp(t)}")
```

**运行结果**：

```text
36.5°C 正常？True
36.0°C 正常？True
37.5°C 正常？True
38.0°C 正常？False
```

#### 2.7.2 半开区间判断

切片索引、分页页码等场景常用左闭右开区间，正好用 `<=` 和 `<` 混写：

```python
def valid_index(idx, length):
    return 0 <= idx < length      # 合法索引：0 到 length-1

print(valid_index(2, 5))      # True
print(valid_index(5, 5))      # False，长度 5 的合法索引是 0~4
print(valid_index(-1, 5))     # False
```

**运行结果**：

```text
True
False
False
```

#### 2.7.3 成绩等级校验

把分数切成几档，每档用一个链式比较表达，是链式比较最常见的复合用法：

```python
def grade_of(score):
    if 90 <= score <= 100:
        return "A"
    elif 80 <= score < 90:
        return "B"
    elif 60 <= score < 80:
        return "C"
    elif 0 <= score < 60:
        return "D"
    else:
        return "非法"

for s in [95, 85, 70, 30, 120]:
    print(f"{s:>4} → {grade_of(s)}")
```

**运行结果**：

```text
  95 → A
  85 → B
  70 → C
  30 → D
 120 → 非法
```

注意这里用了一个混合写法的细节：A 档是闭区间 `90 <= score <= 100`（含 100），其余档是左闭右开 `80 <= score < 90`——靠 `<=` 和 `<` 的搭配精确表达"上界归哪一档"，避免边界值被重复归属。

#### 2.7.4 BMI 分类

把连续数值切成几段，每段一类，用链式比较写最直观：

```python
def bmi_category(w, h):
    bmi = w / (h ** 2)
    if bmi < 18.5:
        cat = "偏瘦"
    elif 18.5 <= bmi < 24:
        cat = "正常"
    elif 24 <= bmi < 28:
        cat = "偏胖"
    else:
        cat = "肥胖"
    return round(bmi, 1), cat

for w, h in [(50, 1.7), (65, 1.7), (78, 1.7), (95, 1.7)]:
    b, c = bmi_category(w, h)
    print(f"体重 {w}kg / 身高 {h}m → BMI={b}，{c}")
```

**运行结果**：

```text
体重 50kg / 身高 1.7m → BMI=17.3，偏瘦
体重 65kg / 身高 1.7m → BMI=22.5，正常
体重 65kg / 身高 1.7m → BMI=27.0，偏胖
体重 95kg / 身高 1.7m → BMI=32.9，肥胖
```

`18.5 <= bmi < 24` 这种用链式比较表达"左闭右开区间"的写法，在分段分类里非常顺手——左边界归本档（含 18.5），右边界归下一档（不含 24），和 `elif` 的命中即停配合，边界归属清晰不重叠。

## 3. 最佳实践

### 3.1 范围判断优先用链式比较而非 and 拼接

区间判断是链式比较的主场，能用链式就不要写成 `and` 拼接——可读性和"中间值只求一次"两个好处都能拿到。

```python
score = 85

# ❌ 不推荐：and 拼接，读起来要拆成两半再拼回去，且 score 写两次
if 0 <= score and score <= 100:
    print("合法")

# ✅ 推荐：链式比较，像数学不等式，一眼读懂
if 0 <= score <= 100:
    print("合法")
```

**运行结果**：

```text
合法
合法
```

两种写法结果一致，但 `0 <= score <= 100` 直接对应数学表达式"0 ≤ score ≤ 100"，阅读无需转译；`and` 拼接要把 `0 <= score` 和 `score <= 100` 两个比较各自的含义再合起来理解。**只要判断的是"范围/区间"，默认用链式比较**。

### 3.2 复杂链式可读性权衡

链式比较的方向和段数可以任意搭配，但"能跑"不等于"好读"。方向杂乱或段数过多时，可读性会下降，需要权衡是不是该拆开或加注释。

```python
# ❌ 不推荐：方向拐来拐去，读者要跟着拐弯
a, b, c = 1, 5, 3
if a < b > c < b:
    print("命中")        # 1<5 且 5>3 且 3<5，能跑但读起来绕

# ✅ 推荐：表达"b 最大且 b>a、b>c"，拆成清晰的两段或加注释
if a < b and c < b:       # 或 max(a, b, c) == b
    print("b 最大")
```

**运行结果**：

```text
命中
b 最大
```

方向杂乱的链式虽然合法，但读者要逐段跟着拐弯，反而比拆成 `and` 更难懂。**当链式比较要让读者"拐超过一次弯"时，就考虑拆开或换更直白的写法**——链式的优势在于"区间"这种天然单向、单意图的表达，不在炫技。

### 3.3 注意混用 == 的语义

链式比较里混用 `==` 时，语义是"逐段相等/大小判断"，不是"整体比较结果"。最容易误读的是 `a == b == c`，它表示"a==b 且 b==c"，而非"三者相等"或"`(a==b)==(b==c)`"。

```python
# ❌ 不推荐：误以为 a == b == c 是"三者同时相等的结果变量"
a, b, c = 3, 3, 4
if a == b == c:           # 期望三者相等，但 3==3==4 是 3==3 且 3==4 → False
    print("全等")

# ✅ 推荐：要判三者相等，用三个 == 的 and 拼接更直白
if a == b and b == c:
    print("全等")
else:
    print("不全等")
```

**运行结果**：

```text
不全等
```

`a == b == c` 表达"链式相等"语义正确（a==b 且 b==c），但它和"a、b、c 三个值都一样"在直觉上关系不直接。判断"多值是否都相同"时，用 `a == b and b == c` 显式拼接，意图比 `a == b == c` 更清楚，不易误读。

### 3.4 跨类型比较要先转换

链式比较如果两侧类型不兼容，会让中间和右侧的跨类型比较抛 `TypeError`。链式比较遇到字符串和数字这类不兼容类型时，要先做类型转换再放进去。

```python
age_str = "20"

# ❌ 不推荐：字符串和数字直接比大小，跨类型 TypeError
# if 0 <= age_str <= 100:
#     print("合法")

# ✅ 推荐：先转成同类型再放进链式比较
age = int(age_str)
if 0 <= age <= 100:
    print("合法年龄")
```

**运行结果**：

```text
合法年龄
```

`0 <= age_str <= 100` 会因为字符串和 `<= 100` 的跨类型比较而报 `TypeError`。从外部拿到的字符串值，比大小前先 `int()`/`float()` 转成数字，再放进链式比较——这一步转换该在比较之前显式做，而不是依赖比较自己处理类型。

### 3.5 常见错误模式速查表

把链式比较里高频踩的坑汇总成一张速查表，写代码时可以对照检查：

| 错误模式 | 错误示例 | 后果 | 正确做法 |
|---------|---------|------|---------|
| 区间用 `and` 拼接不用链式 | `0 <= x and x <= 100` | 可读性差、中值求两次 | 用 `0 <= x <= 100` |
| 忘了边界用 `<` 还是 `<=` | `0 <= x < 100` 想含 100 | 边界丢失 | 含端点用 `<=`、不含用 `<` |
| 误读 `a == b == c` | 以为"三值相等结果" | 语义错（是 a==b 且 b==c） | 判全等用 `a==b and b==c` |
| 方向杂乱当成炫技 | `a < b > c < b` | 难读 | 单意图同向、或拆 `and` |
| `a < f() and f() < c` 忘存变量 | `f()` 调两次 | 性能/副作用问题 | 用链式 `a < f() < c` 或存变量 |
| 跨类型直接链式比较 | `0 <= "5" <= 100` | `TypeError` | 先 `int()`/`float()` 转换 |
| 把多档区间边界写重叠 | `>=80`、`>80` 混用 | 边界归属不清 | 用左闭右开统一规则 |

## 4. 原理

### 4.1 链式比较的等价翻译

链式比较到底怎么求值？规则可以归纳成一句话：**把每相邻两个操作数用 `and` 拼起来，逐段求值、全部成立才为真**。`a < b < c` 翻译成 `a < b and b < c`，`a < b <= c >= d` 翻译成 `a < b and b <= c and c >= d`。

用 `a < b < c` 为例拆解求值顺序：

```text
1. 求值 a
2. 求值 b（中间操作数，只这一次）
3. 判断 a < b 是否成立
4. 不成立 → 短路，整体 False（不再求值 c、不再判断 b < c）
5. 成立 → 求值 c，判断 b < c 是否成立
6. 第 5 步成立 → 整体 True；否则 → 整体 False
```

关键在"中间操作数 `b` 只在第 2 步求值一次，第 5 步判断 `b < c` 时用的是同一个 `b`，不会重新求值"。这就是 `a < f() < c` 里 `f()` 只调一次的根源——翻译虽是 `a < f() and f() < c`，但实际执行时中间的 `f()` 只算一次，而不是字面上的两次调用。所以别把"等价翻译"理解成"等价执行"：语义等价不等于求值次数相同。

### 4.2 中间操作数只求值一次的字节码

用 `dis` 模块看 `a < f() < c` 的字节码，就能确认中间值 `f()` 只求一次。

```python
import dis

def demo(a, c, f):
    return a < f() < c

dis.dis(demo)
```

**运行结果**（节选关键指令）：

```text
  3           0 RESUME 0
  4           2 LOAD_FAST 0 (a)
              4 LOAD_GLOBAL 1 (f)
              6 CALL
              8 COPY 1                  # 把 f() 的结果复制一份，供两段比较复用
             10 COMPARE_OP 2 (<)        # 判断 a < f()
             14 POP_JUMP_IF_FALSE ...     # 不成立短路
             16 LOAD_FAST 0 (c)          # 注意：这里没有再调一次 f()！
             18 COMPARE_OP 2 (<)        # 判断 f() < c（用的是上面复制的结果）
             22 RETURN_VALUE
```

字节码里 `f()` 被调用一次后，用 `COPY` 指令把结果复制一份保留，第二段比较 `f() < c` 直接复用这份复制值，**没有第二次 `CALL f`**。这正是"中间操作数只求值一次"在底层的确切体现。对比 `a < f() and f() < c` 的字节码会有两次完整的 `LOAD_GLOBAL f` + `CALL`，差别一目了然。

这也解释了链式比较为什么不能简单视为 `and` 拼接的语法糖：它不仅仅是"写成一行"，而是**执行层面复用了中间结果**，在求值次数上有真实差异。当 `f()` 是有副作用（打印、计数、改全局）的函数时，链式比较比 `and` 拼接少调一次，行为可能完全不同。

### 4.3 为什么 Python 支持链式比较

很多语言（C、Java、JavaScript）并不支持链式比较的"区间"语义——`a < b < c` 在那些语言里会被解析成 `(a < b) < c`：先算 `a < b` 得到 0 或 1，再和 `c` 比较，几乎从来不是你想要的含义，是个典型的 bug 源。Python 专门支持链式比较，把它解释成 `a < b and b < c`，有几方面的设计考量。

**对齐数学表达**：数学里 `0 ≤ x ≤ 100` 就是"区间"，编程里却要拆成 `0 <= x and x <= 100`，是个翻译断层。Python 让代码能直接写成 `0 <= x <= 100`，消除这层断层，读代码像读公式一样自然。

**避免 `(a < b) < c` 这类隐蔽 bug**：在没有链式比较的语言里，`a < b < c` 不报错但语义错——`(a < b)` 得到布尔，再和 `c` 比大小容易得到非预期结果。Python 把它解释成区间语义，既消除了这类隐患，又给了一个表达区间的高效语法。

**收益与代价权衡**：代价是 `a < b < c` 不再是"`a < b` 的结果再和 `c` 比"——和其它语言习惯不同，初学者可能误解。但 Python 选择把这个"误解"变成有用的"区间"语义，并用严格的中间值求值规则保证行为可控，整体利大于弊。理解了 Python 这套等价翻译和"只求一次"的规则，就能在可读性和正确性上都拿到收益。

## 5. 总结

本文围绕链式比较展开，主要介绍了以下内容：

- 链式比较是什么：把 `a < b and b < c` 简写成 `a < b < c`，像数学不等式一样直观表达区间/范围判断，且中间值只求值一次
- 基本语法：`a < b < c` 等价 `a < b and b < c`，逐段判断相邻两侧都成立才为真
- 范围判断：闭区间用 `0 <= x <= 100`，半开区间混用 `<=` 和 `<`，边界是否含端点由运算符决定（`<=` 含、`<` 不含）
- 任意方向：`a < b > c` 这类拐弯写法合法，语义是逐段判断相邻两侧关系；但方向杂乱会牺牲可读性
- 中间操作数只求值一次：链式 `a < f() < c` 调 `f()` 一次，`a < f() and f() < c` 调两次，先存变量再拼才等价；链式有短路，左比较失败时右侧不求值
- 不同运算符混合：`<` `>` `<=` `>=` `==` `!=` 可混连，语义是"左比中、中比右"逐段成立；`a == b == c` 是"a==b 且 b==c"，不是"三者相等的结果"
- 多段链：`0 < 3 < 5 < 10` 任意多段，要求全程绿灯，一段断了整体为假
- 典型场景：闭区间判断、半开区间判断、成绩等级校验、BMI 分类，几乎都围绕区间/范围判断
- 最佳实践：范围判断优先用链式而非 `and` 拼接、复杂链式可读性权衡、混用 `==` 注意语义、跨类型先转换、不用纯炫技拐弯写法
- 原理：链式比较等价翻译为相邻段 `and` 拼接，但中间操作数只求值一次（字节码用 `COPY` 复用结果）；Python 支持它既是为对齐数学表达、避免 `(a < b) < c` 这类隐蔽 bug，也用严格求值规则保证行为可控
