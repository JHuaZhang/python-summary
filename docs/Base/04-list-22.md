# 列表与 JSON 序列化

## 1. 介绍

### 1.1 什么是 JSON 序列化

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式。它以文本形式表示结构化数据，易于人阅读和编写，也易于机器解析和生成。虽然 JSON 起源于 JavaScript，但它已经是一种语言无关的标准格式——几乎所有编程语言都有对 JSON 的支持。

"序列化"（Serialization）是指把内存中的数据结构转换成可存储或可传输的格式（如文本字符串）的过程。反过来，"反序列化"（Deserialization）就是把文本恢复成内存中的数据结构。

在 Python 中，`json` 模块提供了完整的 JSON 序列化与反序列化能力。`list` 和 `dict` 是 Python 中与 JSON 交互最频繁的类型——JSON 数组对应 Python 列表，JSON 对象对应 Python 字典。

```text
序列化（编码）：Python 对象 → JSON 字符串
    [1, 2, 3]  →  "[1, 2, 3]"
    {"name": "张三"}  →  '{"name": "张三"}'

反序列化（解码）：JSON 字符串 → Python 对象
    "[1, 2, 3]"  →  [1, 2, 3]
    '{"name": "张三"}'  →  {"name": "张三"}
```

### 1.2 为什么列表需要 JSON 序列化

列表是 Python 中最常用的数据容器，而 JSON 是跨语言、跨平台传输数据的标准格式。列表与 JSON 的结合场景无处不在：

- **Web API**：后端返回 JSON 格式的列表数据，前端解析后渲染页面
- **配置文件**：用 JSON 文件存储列表配置（如白名单、任务队列）
- **数据持久化**：把列表数据写入文件，程序重启后读取恢复
- **跨语言通信**：Python 程序把列表序列化成 JSON 传给 Java/Go/JavaScript 程序

一个简单的例子——把学生列表保存为 JSON 文件再读回来：

```python
import json

students = [
    {"name": "张三", "age": 20, "city": "北京"},
    {"name": "李四", "age": 22, "city": "上海"},
]

# 写入 JSON 文件
with open("students.json", "w", encoding="utf-8") as f:
    json.dump(students, f, ensure_ascii=False, indent=2)

# 读取 JSON 文件
with open("students.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(f"读取到 {len(loaded)} 条记录")
```

### 1.3 Python 与 JSON 的类型映射

理解序列化的核心是搞清楚 Python 类型与 JSON 类型的对应关系：

| Python 类型 | JSON 类型 | 示例（Python → JSON） |
|------------|----------|----------------------|
| `dict` | object | `{"a": 1}` → `{"a": 1}` |
| `list` / `tuple` | array | `[1, 2, 3]` → `[1, 2, 3]` |
| `str` | string | `"hello"` → `"hello"` |
| `int` | number | `42` → `42` |
| `float` | number | `3.14` → `3.14` |
| `bool` | boolean | `True` → `true` |
| `None` | null | `None` → `null` |

注意几个关键差异：
- JSON 的布尔值是小写的 `true` / `false`，Python 是大写的 `True` / `False`
- JSON 的空值是 `null`，Python 是 `None`
- JSON 没有"元组"类型，Python 的 `tuple` 序列化后变成 JSON 数组（和 list 一样）
- JSON 只有 number 类型，不区分整数和浮点数——但 Python 反序列化时会根据是否有小数点还原成 `int` 或 `float`

## 2. 核心内容

### 2.1 json.dumps：Python 对象序列化为 JSON 字符串

`json.dumps()` 是最核心的序列化函数——"dumps" = "dump string"，把 Python 对象转成 JSON 格式的字符串。

#### 2.1.1 基本用法

```python
import json

# 列表 → JSON 数组字符串
lst = [10, 20, 30, 40, 50]
json_str = json.dumps(lst)
print(f"列表 → JSON: {json_str}")
print(f"类型: {type(json_str)}")
```

**运行结果**：

```text
列表 → JSON: [10, 20, 30, 40, 50]
类型: <class 'str'>
```

`dumps` 返回的是一个**字符串**——内容是 JSON 格式的文本。这个字符串可以发送到网络、写入文件、传递给其他程序。

```python
# 字典 → JSON 对象字符串
person = {"name": "张三", "age": 25, "city": "北京"}
json_str = json.dumps(person)
print(f"字典 → JSON: {json_str}")
```

**运行结果**：

```text
字典 → JSON: {"name": "\u5f20\u4e09", "age": 25, "city": "\u5317\u4eac"}
```

注意：默认情况下中文字符被转义成了 `\uXXXX` 形式。这是因为 `dumps` 默认 `ensure_ascii=True`，把非 ASCII 字符转义以保证生成的 JSON 是纯 ASCII 文本。使用 `ensure_ascii=False` 即可保留原始中文字符。

#### 2.1.2 嵌套结构

列表和字典可以任意嵌套，`dumps` 会递归处理：

```python
students = [
    {"name": "张三", "age": 20, "scores": [85, 90, 78]},
    {"name": "李四", "age": 22, "scores": [92, 88, 95]},
]

json_str = json.dumps(students, ensure_ascii=False)
print(f"嵌套结构 → JSON: {json_str}")
```

**运行结果**：

```text
嵌套结构 → JSON: [{"name": "张三", "age": 20, "scores": [85, 90, 78]}, {"name": "李四", "age": 22, "scores": [92, 88, 95]}]
```

列表中有字典，字典中有列表——`dumps` 能正确处理任意深度的嵌套。

#### 2.1.3 dumps 的完整参数速查

`json.dumps()` 的完整签名如下：

```python
json.dumps(obj, *, skipkeys=False, ensure_ascii=True, check_circular=True,
           allow_nan=True, cls=None, indent=None, separators=None,
           default=None, sort_keys=False, **kw)
```

常用参数速查表：

| 参数 | 默认值 | 作用 |
|------|--------|------|
| `ensure_ascii` | `True` | `False` 时保留中文字符，不转义为 `\uXXXX` |
| `indent` | `None` | 设为数字（如 2）时格式化缩进，美化输出 |
| `sort_keys` | `False` | `True` 时按 key 字母序排序字典 |
| `separators` | `(', ', ': ')` | 自定义元素间和键值间的分隔符 |
| `default` | `None` | 自定义不可序列化对象的转换函数 |
| `skipkeys` | `False` | `True` 时跳过非字符串类型的字典 key |
| `allow_nan` | `True` | `False` 时 `float('nan')`/`float('inf')` 会报错而非输出 `NaN`/`Infinity` |

接下来逐个讲解最常用的参数。

### 2.2 ensure_ascii：中文编码控制

这是处理中文数据时最重要的参数。

```python
import json

data = {"name": "张三", "city": "北京"}

# 默认 ensure_ascii=True：中文被转义
json_str = json.dumps(data)
print(f"ensure_ascii=True: {json_str}")
```

**运行结果**：

```text
ensure_ascii=True: {"name": "\u5f20\u4e09", "city": "\u5317\u4eac"}
```

`\u5f20` 是"张"的 Unicode 编码。这种转义保证了生成的 JSON 字符串是纯 ASCII，任何系统都能安全传输。但人类阅读不方便。

```python
# ensure_ascii=False：保留原始中文
json_str = json.dumps(data, ensure_ascii=False)
print(f"ensure_ascii=False: {json_str}")
```

**运行结果**：

```text
ensure_ascii=False: {"name": "张三", "city": "北京"}
```

**选择建议**：
- 需要跨系统安全传输、不确定接收端编码 → `ensure_ascii=True`（默认）
- 本地存储、配置文件、调试输出、确定双方都用 UTF-8 → `ensure_ascii=False`

实际开发中，大部分场景都用 `ensure_ascii=False`，因为现代系统基本都支持 UTF-8。

### 2.3 indent：格式化缩进

默认 `dumps` 输出的 JSON 是紧凑的一行，适合机器解析但不适合人眼阅读。`indent` 参数添加缩进和换行：

```python
import json

data = {"name": "张三", "age": 25, "city": "北京", "scores": [85, 90, 78]}

# indent=2：每级缩进 2 个空格
json_str = json.dumps(data, ensure_ascii=False, indent=2)
print(json_str)
```

**运行结果**：

```text
{
  "name": "张三",
  "age": 25,
  "city": "北京",
  "scores": [
    85,
    90,
    78
  ]
}
```

```python
# indent=4：更宽的缩进
json_str = json.dumps(data, ensure_ascii=False, indent=4)
print(json_str)
```

**运行结果**：

```text
{
    "name": "张三",
    "age": 25,
    "city": "北京",
    "scores": [
        85,
        90,
        78
    ]
}
```

`indent` 的值就是每级缩进的空格数。格式化后的 JSON 带换行和缩进，层次清晰，适合写入配置文件供人查看。

**注意**：`indent` 会增大 JSON 体积（多了空格和换行），网络传输时通常不用。典型搭配是——存储和调试用 `indent=2`，传输用默认紧凑模式。

### 2.4 sort_keys：按键排序

默认 `dumps` 保留字典的原始插入顺序（Python 3.7+ `dict` 保序）。`sort_keys=True` 会按 key 的字母序排序：

```python
import json

data = {"name": "张三", "age": 25, "city": "北京", "scores": [85, 90, 78]}

# 不排序（保留原始顺序）
json_str = json.dumps(data, ensure_ascii=False)
print(f"不排序: {json_str}")

# 排序
json_str = json.dumps(data, ensure_ascii=False, sort_keys=True)
print(f"排序后: {json_str}")
```

**运行结果**：

```text
不排序: {"name": "张三", "age": 25, "city": "北京", "scores": [85, 90, 78]}
排序后: {"age": 25, "city": "北京", "name": "张三", "scores": [85, 90, 78]}
```

排序后 key 按字母序排列：age → city → name → scores。

**使用场景**：
- 生成稳定的 JSON 用于哈希校验（确保每次输出的字典顺序一致）
- 调试时方便对比两个 JSON 是否结构相同
- 生成配置文件时按字母序排列便于查找

### 2.5 separators：分隔符控制

`separators` 参数控制两个分隔符：元素之间的分隔符和键值之间的分隔符。

```python
import json

data = {"name": "张三", "age": 25, "city": "北京"}

# 默认分隔符：', '（逗号+空格）和 ': '（冒号+空格）
default_json = json.dumps(data, ensure_ascii=False)
print(f"默认: {default_json}")

# 紧凑模式：去掉额外空格
compact_json = json.dumps(data, ensure_ascii=False, separators=(',', ':'))
print(f"紧凑: {compact_json}")
```

**运行结果**：

```text
默认: {"name": "张三", "age": 25, "city": "北京"}
紧凑: {"name":"张三","age":25,"city":"北京"}
```

紧凑模式去掉了逗号后的空格和冒号后的空格，能减小 JSON 体积。对于传输大量数据时，累积节省的字节很可观：

```python
import sys

normal_size = len(json.dumps(data, ensure_ascii=False))
compact_size = len(json.dumps(data, ensure_ascii=False, separators=(',', ':')))
print(f"正常长度: {normal_size}, 紧凑长度: {compact_size}")
```

**运行结果**：

```text
正常长度: 43, 紧凑长度: 36}
```

**使用场景**：网络传输大量 JSON 数据时，用 `separators=(',', ':')` 减小体积，节省带宽。

### 2.6 json.loads：JSON 字符串反序列化为 Python 对象

`json.loads()` 是 `dumps` 的逆操作——"loads" = "load string"，把 JSON 字符串转成 Python 对象。

#### 2.6.1 基本用法

```python
import json

# JSON 数组 → 列表
json_str = '[10, 20, 30, 40, 50]'
data = json.loads(json_str)
print(f"JSON → 列表: {data}")
print(f"类型: {type(data)}, 元素类型: {type(data[0])}")
```

**运行结果**：

```text
JSON → 列表: [10, 20, 30, 40, 50]
类型: <class 'list'>, 元素类型: <class 'int'>
```

```python
# JSON 对象 → 字典
json_str = '{"name": "张三", "age": 25}'
data = json.loads(json_str)
print(f"JSON → 字典: {data}")
print(f"name 值: {data['name']}, 类型: {type(data['name'])}")
```

**运行结果**：

```text
JSON → 字典: {'name': '张三', 'age': 25}
name 值: 张三, 类型: <class 'str'>
```

#### 2.6.2 嵌套 JSON 的反序列化

```python
json_str = '[{"name": "张三", "scores": [85, 90]}, {"name": "李四", "scores": [92, 88]}]'
data = json.loads(json_str)
print(f"JSON → 嵌套列表: {data}")
print(f"第一个学生名字: {data[0]['name']}")
print(f"第一个学生分数: {data[0]['scores']}")
```

**运行结果**：

```text
JSON → 嵌套列表: [{'name': '张三', 'scores': [85, 90]}, {'name': '李四', 'scores': [92, 88]}]
第一个学生名字: 张三
第一个学生分数: [85, 90]
```

`loads` 同样会递归处理嵌套结构——JSON 数组变成列表，JSON 对象变成字典，层层嵌套都正确还原。

#### 2.6.3 往返转换一致性

"dumps 再 loads"应该得到与原始数据相等的结果（往返一致）：

```python
original = {"name": "张三", "age": 25, "tags": ["dev", "python"], "active": True}
round_tripped = json.loads(json.dumps(original))
print(f"往返转换后相等: {original == round_tripped}")
print(f"往返后类型: {type(round_tripped)}")
```

**运行结果**：

```text
往返转换后相等: True
往返后类型: <class 'dict'>
```

往返转换是类型安全的——只要数据只包含 JSON 原生类型（dict/list/str/int/float/bool/None），`dumps → loads` 后得到的数据和原始数据相等。

#### 2.6.4 JSON 数据类型映射验证

`loads` 把 JSON 类型映射回 Python 类型时，有几点需要注意：

```python
mixed = {
    "int": 42,
    "float": 3.14,
    "str": "hello",
    "bool": True,
    "null": None,
    "list": [1, 2, 3],
    "nested": {"a": 1, "b": 2},
}
json_str = json.dumps(mixed, ensure_ascii=False)
restored = json.loads(json_str)

print(f"int 类型: {type(restored['int'])}")     # int
print(f"float 类型: {type(restored['float'])}") # float
print(f"bool 类型: {type(restored['bool'])}")   # bool
print(f"null 类型: {type(restored['null'])}")   # NoneType
print(f"list 类型: {type(restored['list'])}")   # list
```

**运行结果**：

```text
int 类型: <class 'int'>
float 类型: <class 'float'>
bool 类型: <class 'bool'>
null 类型: <class 'NoneType'>
list 类型: <class 'list'>
```

JSON 的 `true`/`false` → Python 的 `True`/`False`，JSON 的 `null` → Python 的 `None`。这些都是自动完成的。

### 2.7 json.dump 和 json.load：文件级序列化

`json.dump()` 和 `json.load()` 直接操作文件，不需要手动读写字符串。记住"没有 s"就是操作文件。

#### 2.7.1 写入 JSON 文件

```python
import json

data = [
    {"name": "张三", "age": 20, "city": "北京"},
    {"name": "李四", "age": 22, "city": "上海"},
    {"name": "王五", "age": 25, "city": "深圳"},
]

# dump 直接写入文件（注意是 dump 不是 dumps）
with open("students.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

print("已写入 students.json")
```

**运行结果**：

```text
已写入 students.json
```

写入的文件内容如下：

```json
[
  {
    "name": "张三",
    "age": 20,
    "city": "北京"
  },
  {
    "name": "李四",
    "age": 22,
    "city": "上海"
  },
  {
    "name": "王五",
    "age": 25,
    "city": "深圳"
  }
]
```

`dump` 的参数和 `dumps` 完全一样，只是第一个参数变成了文件对象。`dump` 不会返回字符串——它直接把 JSON 写到文件里。

#### 2.7.2 读取 JSON 文件

```python
import json

# load 直接从文件读取（注意是 load 不是 loads）
with open("students.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(f"读取到 {len(loaded)} 条记录:")
for student in loaded:
    print(f"  {student['name']}, {student['age']}岁, {student['city']}")
```

**运行结果**：

```text
读取到 3 条记录:
  张三, 20岁, 北京
  李四, 22岁, 上海
  王五, 25岁, 深圳
```

`load` 从文件对象中读取 JSON 文本并解析为 Python 对象。同样，`load` 的参数和 `loads` 类似，只是输入源是文件而非字符串。

#### 2.7.3 dump vs dumps 的区别

| 函数 | 输入 | 输出 | 使用场景 |
|------|------|------|---------|
| `json.dumps(obj)` | Python 对象 | JSON 字符串 | 网络传输、内存操作 |
| `json.dump(obj, f)` | Python 对象 | 写入文件 | 文件存储 |
| `json.loads(s)` | JSON 字符串 | Python 对象 | 解析网络数据、解析字符串 |
| `json.load(f)` | 文件 | Python 对象 | 读取文件 |

记忆口诀：**有 s 操作字符串，无 s 操作文件**。

#### 2.7.4 追加模式：读取-修改-写回

JSON 文件不能直接"追加"数据——因为整个文件是一个完整的 JSON 值，往末尾加内容会破坏结构。正确做法是读取→修改→写回：

```python
import json

# 先读取现有数据
with open("students.json", "r", encoding="utf-8") as f:
    students = json.load(f)

# 修改数据
students.append({"name": "赵六", "age": 23, "city": "杭州"})

# 写回文件
with open("students.json", "w", encoding="utf-8") as f:
    json.dump(students, f, ensure_ascii=False, indent=2)

print(f"追加后 {len(students)} 条记录")
```

**运行结果**：

```text
追加后 4 条记录
```

如果数据量很大，频繁全量读写可能影响性能。此时应考虑换用数据库（如 SQLite）或专门的 JSON 数据库（如 MongoDB）。

### 2.8 不可直接序列化的类型与自定义编码

JSON 只支持 6 种数据类型（object/array/string/number/boolean/null），Python 中很多类型不在其中。

#### 2.8.1 哪些类型不能直接序列化

```python
import json
from datetime import datetime
from decimal import Decimal

# datetime 不能直接序列化
dt = datetime(2024, 1, 15, 10, 30, 0)
try:
    json.dumps({"created_at": dt})
except TypeError as e:
    print(f"datetime 序列化失败: {e}")

# set 不能直接序列化
try:
    json.dumps({"tags": {"python", "json", "web"}})
except TypeError as e:
    print(f"set 序列化失败: {e}")

# Decimal 不能直接序列化
try:
    json.dumps({"price": Decimal("19.99")})
except TypeError as e:
    print(f"Decimal 序列化失败: {e}")
```

**运行结果**：

```text
datetime 序列化失败: Object of type datetime is not JSON serializable
set 序列化失败: Object of type set is not JSON serializable
Decimal 序列化失败: Object of type decimal.Decimal is not JSON serializable
```

`datetime`、`set`、`Decimal`、自定义类等都不在 JSON 的原生类型中，`dumps` 遇到它们直接报 `TypeError`。

#### 2.8.2 使用 default 参数自定义序列化

`dumps` 的 `default` 参数接受一个函数，当遇到无法序列化的对象时调用该函数做转换：

```python
import json
from datetime import datetime
from decimal import Decimal

def json_encoder(obj):
    """处理 JSON 不支持的类型"""
    if isinstance(obj, datetime):
        return obj.isoformat()  # ISO 8601 格式字符串
    elif isinstance(obj, set):
        return sorted(list(obj))  # 转成有序列表
    elif isinstance(obj, Decimal):
        return str(obj)  # 转成字符串避免精度丢失
    raise TypeError(f"无法序列化类型: {type(obj)}")

data = {
    "created_at": datetime(2024, 1, 15, 10, 30, 0),
    "tags": {"python", "json", "web"},
    "price": Decimal("19.99"),
    "name": "测试商品",
}

json_str = json.dumps(data, ensure_ascii=False, default=json_encoder)
print(f"自定义编码: {json_str}")
```

**运行结果**：

```text
自定义编码: {"created_at": "2024-01-15T10:30:00", "tags": ["json", "python", "web"], "price": "19.99", "name": "测试商品"}
```

`default` 函数的工作流程：

```text
dumps 遇到对象 obj
    ↓
obj 是 JSON 原生类型？
    → 是：直接序列化
    → 否：调用 default(obj)
            ↓
          default 返回值是原生类型？
            → 是：序列化返回值
            → 否：抛出 TypeError
```

`default` 函数只需要处理你关心的类型，其他类型抛出 `TypeError` 即可——`dumps` 会把这个错误传播给调用者。

#### 2.8.3 使用 object_hook 自定义反序列化

`loads` 的 `object_hook` 参数接受一个函数，在解析每一个 JSON 对象时调用。可以用来恢复特殊类型：

```python
import json
from datetime import datetime

def json_decoder(obj):
    """反序列化时恢复 datetime"""
    if "created_at" in obj:
        obj["created_at"] = datetime.fromisoformat(obj["created_at"])
    return obj

# 使用上面序列化的 json_str
restored = json.loads(json_str, object_hook=json_decoder)
print(f"反序列化后 created_at 类型: {type(restored['created_at'])}")
print(f"反序列化后 created_at 值: {restored['created_at']}")
```

**运行结果**：

```text
反序列化后 created_at 类型: <class 'datetime.datetime'>
反序列化后 created_at 值: 2024-01-15 10:30:00
```

`object_hook` 对每个 JSON 对象（`{...}`）调用一次，传入已解析的字典，函数返回修改后的字典。利用这个机制可以在反序列化时恢复 `datetime` 等特殊类型。

#### 2.8.4 自定义类的序列化

自定义类不能直接序列化为 JSON。常见做法是通过 `to_dict()` / `from_dict()` 方法手动转换：

```python
import json

class Student:
    def __init__(self, name, age, scores):
        self.name = name
        self.age = age
        self.scores = scores

    def to_dict(self):
        return {"name": self.name, "age": self.age, "scores": self.scores}

    @classmethod
    def from_dict(cls, data):
        return cls(data["name"], data["age"], data["scores"])

    def __repr__(self):
        return f"Student({self.name}, {self.age}, {self.scores})"

# 序列化：自定义对象 → dict → JSON
student = Student("张三", 20, [85, 90, 78])
json_str = json.dumps(student.to_dict(), ensure_ascii=False)
print(f"自定义类 → JSON: {json_str}")

# 反序列化：JSON → dict → 自定义对象
restored = json.loads(json_str)
student_restored = Student.from_dict(restored)
print(f"JSON → 自定义类: {student_restored}")
```

**运行结果**：

```text
自定义类 → JSON: {"name": "张三", "age": 20, "scores": [85, 90, 78]}
JSON → 自定义类: Student(张三, 20, [85, 90, 78])
```

这种模式的流程：

```text
序列化:   自定义对象  →  to_dict()  →  dict  →  json.dumps  →  JSON 字符串
反序列化: JSON 字符串  →  json.loads  →  dict  →  from_dict()  →  自定义对象
```

`to_dict()` 负责把对象属性提取为字典，`from_dict()` 负责从字典重建对象。这是最通用的模式，适用于任何自定义类。

### 2.9 错误处理与调试

#### 2.9.1 JSONDecodeError

`json.loads()` 解析非法 JSON 时抛出 `json.JSONDecodeError`，包含详细的错误位置信息：

```python
import json

# 常见错误1：单引号（JSON 标准要求双引号）
bad_json = "{'name': '张三'}"
try:
    json.loads(bad_json)
except json.JSONDecodeError as e:
    print(f"JSON 解析错误: {e}")
    print(f"错误位置: 行 {e.lineno}, 列 {e.colno}")
```

**运行结果**：

```text
JSON 解析错误: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)
错误位置: 行 1, 列 2
```

`JSONDecodeError` 提供了 `lineno`（行号）、`colno`（列号）、`pos`（字符偏移）三个属性，方便定位错误。

```python
# 常见错误2：尾逗号
bad_json2 = '[1, 2, 3,]'
try:
    json.loads(bad_json2)
except json.JSONDecodeError as e:
    print(f"尾逗号错误: {e}")
```

**运行结果**：

```text
尾逗号错误: Expecting value: line 1 column 9 (char 8)
```

JSON 标准不允许最后一个元素后面有逗号，但 Python 列表允许。这是一个常见的从 Python 到 JSON 的坑。

#### 2.9.2 文件读取错误处理

```python
import json

# 文件不存在
try:
    with open("not_exist.json", "r") as f:
        json.load(f)
except FileNotFoundError as e:
    print(f"文件不存在: {e}")

# 文件内容不是有效 JSON
with open("bad.json", "w") as f:
    f.write("not a json")

try:
    with open("bad.json", "r") as f:
        json.load(f)
except json.JSONDecodeError as e:
    print(f"JSON 解析错误: {e}")
```

**运行结果**：

```text
文件不存在: [Errno 2] No such file or directory: 'not_exist.json'
JSON 解析错误: Expecting value: line 1 column 1 (char 0)
```

读取 JSON 文件时需要处理两类错误：`FileNotFoundError`（文件找不到）和 `json.JSONDecodeError`（内容格式错误）。

### 2.10 整数与浮点数的精度问题

#### 2.10.1 int 和 float 的区分

JSON 标准只有"number"类型，不区分整数和小数。Python 的 `loads` 会根据是否有小数点来还原类型：

```python
import json

data = {"int_val": 42, "float_val": 42.0}
json_str = json.dumps(data)
restored = json.loads(json_str)
print(f"整数 42 → JSON → Python: {type(restored['int_val'])}")
print(f"浮点 42.0 → JSON → Python: {type(restored['float_val'])}")
```

**运行结果**：

```text
整数 42 → JSON → Python: <class 'int'>
浮点 42.0 → JSON → Python: <class 'float'>
```

`42` 没有小数点，还原为 `int`；`42.0` 有小数点，还原为 `float`。这是因为 JSON 文本中 `42` 和 `42.0` 的写法不同，Python 解析时根据写法判断类型。

#### 2.10.2 大整数不溢出

```python
big_int = 10 ** 40
json_str = json.dumps({"value": big_int})
restored = json.loads(json_str)
print(f"大整数 10^40 往返: {restored['value'] == big_int}")
```

**运行结果**：

```text
大整数 10^40 往返: True
```

很多语言的 JSON 库把大整数解析为 `double`（浮点数），导致精度丢失。Python 的 `json` 模块正确处理任意大小的整数，因为 Python 的 `int` 本身就是任意精度的。

#### 2.10.3 浮点精度

```python
float_val = 0.1 + 0.2  # 0.30000000000000004
json_str = json.dumps({"value": float_val})
restored = json.loads(json_str)
print(f"0.1+0.2 往返: {restored['value'] == float_val}")
```

**运行结果**：

```text
0.1+0.2 往返: True
```

`dumps` 用 `repr()` 生成的浮点数字符串保留了足够的精度，`loads` 再解析回来能精确还原原值。但要注意——如果 JSON 来自其他语言（如 JavaScript），浮点数可能被截断到 `double` 精度，此时可能与 Python 的浮点数不完全一致。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法

| 场景 | 不推荐 | 推荐 | 原因 |
|------|--------|------|------|
| 处理中文 | `json.dumps(data)` | `json.dumps(data, ensure_ascii=False)` | 保留中文可读性 |
| 写配置文件 | `json.dumps(data)` + `f.write()` | `json.dump(data, f, indent=2)` | 一步到位，格式美观 |
| 读 JSON 文件 | `f.read()` + `json.loads()` | `json.load(f)` | 少一步中间操作 |
| 紧凑传输 | `json.dumps(data, ensure_ascii=False)` | `json.dumps(data, ensure_ascii=False, separators=(',', ':'))` | 去空格省体积 |
| 自定义类型 | 手动 `str(obj)` 代替序列化 | `default=json_encoder` | 可控的、可逆的转换 |
| 异常处理 | 裸 `json.loads(user_input)` | `try...except json.JSONDecodeError` | 给用户友好错误提示 |

### 3.2 编码注意事项

**统一使用 UTF-8**：读写 JSON 文件时始终指定 `encoding="utf-8"`，避免在不同操作系统下出现编码问题：

```python
# 推荐：显式指定编码
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False)

with open("data.json", "r", encoding="utf-8") as f:
    data = json.load(f)
```

不指定 `encoding` 时，Python 使用系统默认编码（Windows 上可能是 GBK），导致中文 JSON 在不同系统间传输时乱码。

### 3.3 性能注意事项

**大文件的流式处理**：`json.load(f)` 一次性读取整个文件到内存。如果 JSON 文件很大（几百 MB），应该用 `ijson` 库做流式解析：

```python
# 大文件不推荐：一次性加载
with open("huge.json", "r") as f:
    data = json.load(f)  # 全部加载到内存

# 大文件推荐：流式解析（需要安装 ijson）
# import ijson
# with open("huge.json", "r") as f:
#     for item in ijson.items(f, "item"):
#         process(item)
```

**紧凑模式减小网络开销**：API 返回大量 JSON 数据时用 `separators=(',', ':')` 减小体积：

```python
# 推荐：紧凑模式用于网络传输
response = json.dumps(data, ensure_ascii=False, separators=(',', ':'))
```

## 4. 常见误区与边界

### 4.1 以为 tuple 序列化后还是 tuple

JSON 没有元组类型。Python 的 `tuple` 序列化后变成 JSON 数组，反序列化回来是 `list` 不是 `tuple`：

```python
import json

tup = (1, 2, 3)
json_str = json.dumps(tup)
print(f"tuple → JSON: {json_str}")

restored = json.loads(json_str)
print(f"JSON → Python: {restored}")
print(f"类型: {type(restored)}")  # list，不是 tuple
```

**运行结果**：

```text
tuple → JSON: [1, 2, 3]
JSON → Python: [1, 2, 3]
类型: <class 'list'>
```

如果你依赖 `tuple` 的不可变性，需要在反序列化后手动转换：`tuple(restored)`。

### 4.2 以为 set 可以直接序列化

`set` 不是 JSON 原生类型，直接 `dumps` 会报错：

```python
import json

try:
    json.dumps({"tags": {1, 2, 3}})
except TypeError as e:
    print(f"set 序列化失败: {e}")
```

**运行结果**：

```text
set 序列化失败: Object of type set is not JSON serializable
```

正确做法：先转成 `list`，或用 `default` 函数自动转换：

```python
# 方式1：手动转 list
data = {"tags": list({1, 2, 3})}
print(json.dumps(data))

# 方式2：用 default 自动转
def handle_set(obj):
    if isinstance(obj, set):
        return sorted(list(obj))
    raise TypeError(f"不支持: {type(obj)}")

data = {"tags": {1, 2, 3}}
print(json.dumps(data, default=handle_set))
```

**运行结果**：

```text
{"tags": [1, 2, 3]}
{"tags": [1, 2, 3]}
```

### 4.3 以为 JSON 允许尾逗号

Python 列表和字典允许最后一个元素后面有逗号，JSON 不允许：

```python
import json

# Python 允许
lst = [1, 2, 3,]
dct = {"a": 1, "b": 2,}
print(f"Python 允许尾逗号: {lst}, {dct}")

# JSON 不允许
bad_json = '[1, 2, 3,]'
try:
    json.loads(bad_json)
except json.JSONDecodeError as e:
    print(f"JSON 不允许尾逗号: {e}")
```

**运行结果**：

```text
Python 允许尾逗号: [1, 2, 3], {'a': 1, 'b': 2}
JSON 不允许尾逗号: Expecting value: line 1 column 9 (char 8)
```

手工拼 JSON 字符串时容易犯这个错——用 `dumps` 生成 JSON 就不会有这个问题。

### 4.4 以为 JSON 的 key 可以是数字

JSON 规范要求 object 的 key 必须是字符串。Python 字典支持数字 key，但 `dumps` 会自动转成字符串：

```python
import json

# Python 字典用数字 key
d = {1: "one", 2: "two", 3: "three"}
json_str = json.dumps(d)
print(f"数字 key → JSON: {json_str}")

# 反序列化后 key 变成字符串
restored = json.loads(json_str)
print(f"JSON → Python: {restored}")
print(f"key 类型: {type(list(restored.keys())[0])}")  # str，不是 int
```

**运行结果**：

```text
数字 key → JSON: {"1": "one", "2": "two", "3": "three"}
JSON → Python: {'1': 'one', '2': 'two', '3': 'three'}
key 类型: <class 'str'>
```

数字 key `1` 序列化后变成字符串 `"1"`，反序列化回来还是字符串 `"1"`——这个往返不一致需要注意。如果必须用数字 key，需要在反序列化后手动转换。

### 4.5 以为 JSON 可以包含注释

标准 JSON 不支持注释。`//` 和 `/* */` 都会导致解析错误：

```python
import json

json_with_comment = '{"name": "张三", /* 用户名 */ "age": 25}'
try:
    json.loads(json_with_comment)
except json.JSONDecodeError as e:
    print(f"JSON 不支持注释: {e}")
```

**运行结果**：

```text
JSON 不支持注释: Expecting property name enclosed in double quotes: line 1 column 17 (char 16)
```

如果需要注释，可以改用 JSONC（JSON with Comments）或 YAML 格式。或者在 JSON 中用特殊字段如 `"_comment"` 来存储注释信息：

```python
import json

# 用 "_comment" 字段存储注释
config = {
    "_comment": "这是配置文件的说明",
    "name": "张三",
    "age": 25,
}
json_str = json.dumps(config, ensure_ascii=False, indent=2)
print(json_str)
```

### 4.6 忽略 NaN 和 Infinity 的兼容性

Python 的 `json` 模块默认允许 `float('nan')`、`float('inf')` 和 `float('-inf')`：

```python
import json

data = {"nan": float('nan'), "inf": float('inf')}
json_str = json.dumps(data)
print(f"NaN/Inf → JSON: {json_str}")
```

**运行结果**：

```text
NaN/Inf → JSON: {"nan": NaN, "inf": Infinity}
```

但 `NaN`、`Infinity` 不是标准 JSON 类型——很多其他语言的 JSON 库无法解析它们。如果要确保严格兼容：

```python
json_str = json.dumps(data, allow_nan=False)
# 报错 ValueError: Out of range float values are not JSON compliant
```

**运行结果**：

```text
ValueError: Out of range float values are not JSON compliant
```

`allow_nan=False` 会在遇到 NaN/Inf 时抛出 `ValueError` 而非生成非标准 JSON。

## 5. 总结

本文围绕列表与 JSON 序列化展开，主要介绍了以下内容：

- JSON 是轻量级数据交换格式，Python 通过 `json` 模块实现序列化（编码）和反序列化（解码）
- Python 与 JSON 的类型映射：`dict`↔object、`list`/`tuple`↔array、`str`↔string、`int`/`float`↔number、`bool`↔boolean、`None`↔null
- `json.dumps()` 把 Python 对象序列化为 JSON 字符串，`json.loads()` 把 JSON 字符串反序列化为 Python 对象
- `json.dump()` / `json.load()` 直接操作文件，记忆口诀是"有 s 操作字符串，无 s 操作文件"
- `ensure_ascii=False` 保留中文可读性，`indent` 格式化缩进，`sort_keys` 按键排序，`separators` 控制紧凑模式
- `default` 参数自定义不可序列化类型的转换函数，`object_hook` 参数自定义反序列化恢复特殊类型
- `tuple` 序列化后变成 JSON 数组，反序列化回来是 `list` 而非 `tuple`
- JSON 不允许尾逗号、不支持注释、key 必须是字符串——与 Python 语法有关键差异
- `JSONDecodeError` 提供行号列号信息，方便定位解析错误
- 大文件用流式解析（如 `ijson` 库），网络传输用紧凑模式 `separators=(',', ':')` 减小体积
