# 字典的 update 与合并

## 1. 介绍

### 1.1 什么是字典合并

在 Python 中，"字典合并"指的是将两个或多个字典的内容整合到一起，形成一个包含所有键值对的字典。合并的核心规则只有一条：**如果多个字典有相同的键，后者的值覆盖前者的值。**

字典合并在实际开发中无处不在。配置管理需要合并默认配置与用户配置；HTTP 请求需要合并公共参数与请求参数；数据处理需要合并多个来源的字段……几乎每个 Python 项目都会遇到字典合并的场景。

Python 提供了多种合并字典的方式，从传统的 `update` 方法到 Python 3.9 引入的 `|` 运算符，再到 `**` 解包语法和 `collections.ChainMap`。每种方式有自己的适用场景和性能特点，你需要理解它们的区别才能做出正确选择。

### 1.2 解决什么问题

先看一个最常见的场景——多层配置合并。假设你有默认配置、环境配置和用户配置三层，优先级从低到高，需要合并成一个最终配置：

```python
# 三层配置，需要按优先级合并：用户 > 环境 > 默认
defaults = {"host": "localhost", "port": 8080, "timeout": 30, "debug": False}
env_config = {"port": 3000, "debug": True}
user_config = {"timeout": 60, "retries": 3}

# 方式一：逐层 update
config = defaults.copy()
config.update(env_config)
config.update(user_config)

# 方式二：Python 3.9+ 合并运算符
config = defaults | env_config | user_config

# 方式三：** 解包
config = {**defaults, **env_config, **user_config}
```

三种方式都能得到 `{'host': 'localhost', 'port': 3000, 'timeout': 60, 'debug': True, 'retries': 3}`，但在语义清晰度、是否修改原字典等方面各有差异。这篇笔记会逐一拆解每种方式。

### 1.3 最简示例

先用一个最小例子感受字典合并的核心行为——相同的键被覆盖，不同的键被保留：

```python
d1 = {"a": 1, "b": 2}
d2 = {"b": 3, "c": 4}

# update：原地合并，d2 覆盖 d1
d1.update(d2)
print(d1)  # 输出：{'a': 1, 'b': 3, 'c': 4}
```

```text
{'a': 1, 'b': 3, 'c': 4}
```

```python
# | 运算符：非原地合并，产生新字典
d1 = {"a": 1, "b": 2}
d2 = {"b": 3, "c": 4}
merged = d1 | d2
print(merged)  # 输出：{'a': 1, 'b': 3, 'c': 4}
print(d1)      # 输出：{'a': 1, 'b': 2}  ← 原字典不变
```

```text
{'a': 1, 'b': 3, 'c': 4}
{'a': 1, 'b': 2}
```

这个例子揭示了两种合并方式最核心的区别：**update 修改原字典，`|` 产生新字典。** 理解这个区别是选择正确合并方式的第一步。

## 2. 核心内容

### 2.1 update 方法签名

`update` 是字典的内置方法，用于将另一个字典或可迭代对象的内容合并到当前字典中。它的完整签名：

```python
dict.update([other], **kwargs)
```

| 参数 | 说明 | 是否必需 |
|------|------|---------|
| `other` | 字典或产生 `(key, value)` 二元组的可迭代对象 | 可选（至少传一个位置参数或关键字参数） |
| `**kwargs` | 以关键字参数形式传入的键值对 | 可选 |

**返回值**：`None`。`update` 是原地修改方法，不返回新字典。

`update` 接受三种形式的参数：

1. **一个字典**：`d.update(other_dict)`
2. **一个可迭代对象**（产生 `(key, value)` 二元组）：`d.update([(k1, v1), (k2, v2)])`
3. **关键字参数**：`d.update(k1=v1, k2=v2)`

三种形式可以混合使用（一个位置参数 + 关键字参数），但不能传两个位置参数。

### 2.2 update 接受字典参数

这是最基本也是最常用的形式。传入一个字典，将其所有键值对合并到当前字典中：

```python
# 场景：合并用户个人信息的两个来源
base_profile = {
    "name": "张三",
    "age": 28,
    "city": "北京",
}

update_profile = {
    "age": 29,           # 覆盖：年龄更新
    "email": "z3@test.com",  # 新增：补充邮箱
    "phone": "13800000000",  # 新增：补充手机号
}

result = base_profile.update(update_profile)
print(f"返回值: {result}")           # 输出：返回值: None
print(f"合并后: {base_profile}")
```

**运行结果**：

```text
返回值: None
合并后: {'name': '张三', 'age': 29, 'city': '北京', 'email': 'z3@test.com', 'phone': '13800000000'}
```

**关键点**：

- `update` 返回 `None`，不是返回修改后的字典。这是 Python 中原地修改方法的统一约定（和 `list.append`、`list.sort` 一样），链式调用 `d.update(x).update(y)` 会抛出 `AttributeError`。
- 相同键被新值覆盖，不同键被新增。合并是"后者覆盖前者"的单向操作。
- 源字典（`update_profile`）不会被修改，只有目标字典（`base_profile`）被修改。

### 2.3 update 接受键值对序列

`update` 不局限于字典——任何产生 `(key, value)` 二元组的可迭代对象都可以传入。这比只接受字典灵活得多：

```python
# 场景 1：从配置覆盖列表更新
config = {"host": "localhost", "port": 8080}
overrides = [("port", 3000), ("debug", True), ("timeout", 60)]

config.update(overrides)
print(f"从列表更新: {config}")
```

**运行结果**：

```text
从列表更新: {'host': 'localhost', 'port': 3000, 'debug': True, 'timeout': 60}
```

```python
# 场景 2：从生成器产生的键值对更新
def parse_kv_lines(lines):
    """逐行解析 'key=value' 格式，产生 (key, value) 元组"""
    for line in lines:
        key, val = line.strip().split("=")
        yield key, int(val) if val.isdigit() else val

raw_lines = ["name=Alice", "age=30", "city=北京"]

profile = {"name": "unknown"}
profile.update(parse_kv_lines(raw_lines))
print(f"从生成器更新: {profile}")
```

**运行结果**：

```text
从生成器更新: {'name': 'Alice', 'age': 30, 'city': '北京'}
```

```python
# 场景 3：从 zip 产生的键值对构建
keys = ["数学", "语文", "英语"]
values = [95, 88, 92]

scores = {}
scores.update(zip(keys, values))
print(f"从 zip 构建: {scores}")
```

**运行结果**：

```text
从 zip 构建: {'数学': 95, '语文': 88, '英语': 92}
```

**关键点**：

- `update` 只要求可迭代对象的每个元素是一个两元素序列（如元组、列表），第一项作为键，第二项作为值。
- 元素不是二元组时会抛出 `ValueError`：`d.update([1, 2, 3])` 会报 `not enough values to unpack`。
- 利用生成器可以流式合并大量数据，不需要先构建完整列表。

### 2.4 update 接受关键字参数

`update` 还可以接受关键字参数，适合键是字符串且数量不多的情况：

```python
# 基本用法
config = {"host": "localhost", "port": 8080}
config.update(timeout=60, debug=True, retries=3)
print(f"关键字参数更新: {config}")
```

**运行结果**：

```text
关键字参数更新: {'host': 'localhost', 'port': 8080, 'timeout': 60, 'debug': True, 'retries': 3}
```

```python
# 字典参数与关键字参数可以混用
config = {"host": "localhost"}
config.update({"port": 8080}, timeout=60, debug=True)
print(f"混合参数更新: {config}")
```

**运行结果**：

```text
混合参数更新: {'host': 'localhost', 'port': 8080, 'timeout': 60, 'debug': True}
```

**限制**：关键字参数的键必须是合法的 Python 标识符——不能含空格、不能以数字开头、不能含特殊字符：

```python
config = {}
# config.update("key with space"=1)  # SyntaxError！
# 必须用字典形式传递非标识符键
config.update({"key with space": 1, "123": 2})
print(f"非标识符键只能用字典: {config}")
```

**运行结果**：

```text
非标识符键只能用字典: {'key with space': 1, '123': 2}
```

**关键点**：关键字参数形式简洁但有局限性。当键来自变量或动态数据时，用字典形式更合适；当键是固定字符串且数量少时，关键字参数写法更干净。

### 2.5 | 合并运算符

Python 3.9（PEP 584）引入了字典合并运算符 `|` 和 `|=`，为字典合并提供了更直观、更具表现力的语法。

#### 2.5.1 | 运算符：创建新字典

`|` 运算符将两个字典合并为一个新字典，不修改任何一个原字典：

```python
base = {"a": 1, "b": 2}
extra = {"b": 3, "c": 4}

merged = base | extra
print(f"base: {base}")
print(f"extra: {extra}")
print(f"base | extra: {merged}")
print(f"原 base 未变: {base}")
```

**运行结果**：

```text
base: {'a': 1, 'b': 2}
extra: {'b': 3, 'c': 4}
base | extra: {'a': 1, 'b': 3, 'c': 4}
原 base 未变: {'a': 1, 'b': 2}
```

**关键点**：

- `|` 产生新字典，原字典不变。这和 `update` 的原地修改行为完全不同。
- 右操作数的值覆盖左操作数的同名键。合并方向：右覆盖左。
- `|` 只接受字典类型作为操作数，不能接受键值对序列或关键字参数。

#### 2.5.2 |= 运算符：原地更新

`|=` 运算符是原地更新操作，功能等价于 `update` 方法：

```python
config = {"host": "localhost", "port": 8080}
config |= {"port": 3000, "retries": 3}
print(f"config |= 后: {config}")
```

**运行结果**：

```text
config |= 后: {'host': 'localhost', 'port': 3000, 'retries': 3}
```

`|=` 还能接受键值对序列（和 `update` 一样）：

```python
d = {"a": 1}
d |= [("b", 2), ("c", 3)]
print(f"d |= 序列: {d}")
```

**运行结果**：

```text
d |= 序列: {'a': 1, 'b': 2, 'c': 3}
```

#### 2.5.3 多个字典连续合并

`|` 运算符可以链式调用，连续合并多个字典，形成优先级链：

```python
defaults = {"a": 1, "b": 2}
env_config = {"b": 20, "c": 30}
user_config = {"c": 200, "d": 400}

# 后面的覆盖前面的，形成优先级链
final = defaults | env_config | user_config
print(f"三层合并: {final}")
```

**运行结果**：

```text
三层合并: {'a': 1, 'b': 20, 'c': 200, 'd': 400}
```

#### 2.5.4 合并的方向性

`|` 运算不满足交换律——`d1 | d2` 和 `d2 | d1` 的结果不同：

```python
d1 = {"x": 1}
d2 = {"x": 2, "y": 3}

print(f"d1 | d2: {d1 | d2}")  # d2 覆盖 d1
print(f"d2 | d1: {d2 | d1}")  # d1 覆盖 d2
```

**运行结果**：

```text
d1 | d2: {'x': 2, 'y': 3}
d2 | d1: {'x': 1, 'y': 3}
```

**关键点**：`x` 的值取决于谁在右边——右边的覆盖左边的。在多层配置合并中，应将优先级低的放左边、优先级高的放右边：`defaults | env | user`。

### 2.6 ** 解包合并

在 Python 3.9 的 `|` 运算符出现之前，`**` 解包是合并字典最常用的方式。它的语法是在字典字面量内用 `**` 展开多个字典：

```python
base = {"a": 1, "b": 2}
extra = {"b": 3, "c": 4}

merged = {**base, **extra}
print(f"{{**base, **extra}}: {merged}")
```

**运行结果**：

```text
{**base, **extra}: {'a': 1, 'b': 3, 'c': 4}
```

**结果与 `base | extra` 完全相同**。但 `**` 解包有一个独特优势——可以在解包之间插入新的键值对：

```python
# 在解包之间插入新键值对
defaults = {"host": "localhost", "port": 8080}
env = {"port": 3000}

config = {**defaults, "debug": True, **env, "retries": 3}
print(f"解包间插新键: {config}")
```

**运行结果**：

```text
解包间插新键: {'host': 'localhost', 'port': 3000, 'debug': True, 'retries': 3}
```

**运行流程**：`**` 解包会按从左到右的顺序逐个展开字典，同时处理显式写的键值对。每一步中，后面的同名键覆盖前面的，最终形成一个新字典。

```text
{**defaults, "debug": True, **env, "retries": 3}
      │              │              │              │
      ▼              ▼              ▼              ▼
   展开 defaults  插入 debug    展开 env     插入 retries
  host=localhost  debug=True   port=3000    retries=3
  port=8080                    (覆盖 port)
      │              │              │              │
      └──────────────┴──────────────┴──────────────┘
                         │
                         ▼
                 最终合并结果:
  {host, port(被env覆盖), debug, retries}
```

**多字典解包**：

```python
d1 = {"a": 1}
d2 = {"b": 2}
d3 = {"a": 10, "c": 3}
result = {**d1, **d2, **d3}  # 后面的覆盖前面的
print(f"三字典解包: {result}")
```

**运行结果**：

```text
三字典解包: {'a': 10, 'b': 2, 'c': 3}
```

**关键点**：

- `**` 解包始终创建新字典，不修改原字典。
- `**` 解包只能在字典字面量 `{}` 内使用，不能在赋值语句右侧单独使用 `merged = **base`（语法错误）。
- 可以混合使用 `**` 和显式键值对，灵活性比 `|` 运算符更高。

### 2.7 三种合并方式对比

`update`、`|`、`**` 解包是最常见的三种字典合并方式。下表从多个维度进行对比：

| 维度 | `d.update(other)` | `d1 \| d2` | `{**d1, **d2}` |
|------|-------------------|------------|-----------------|
| 是否修改原字典 | 是（原地修改） | 否（产生新字典） | 否（产生新字典） |
| 返回值 | `None` | 新字典 | 新字典 |
| 接受可迭代对象 | 是 | 否（仅字典） | 否（仅字典） |
| 接受关键字参数 | 是 | 否 | 否（但可插入显式键值对） |
| 最低 Python 版本 | 所有版本 | 3.9+ | 3.5+ |
| 链式合并多字典 | 需多次调用 | `d1\|d2\|d3\|...` | `{**d1, **d2, **d3, ...}` |
| 插入额外键值对 | 不支持 | 不支持 | 支持 |
| 可读性 | 中等 | 高，语义直观 | 高，但写法稍长 |

**选择建议**：

- **需要原地修改、修改后继续使用原变量** → `update` 或 `|=`
- **Python 3.9+，且不需要插入额外键** → `|` 运算符，语义最清晰
- **需要在新字典中插入额外键值对** → `**` 解包
- **Python 3.5~3.8** → `**` 解包是最佳选择（不支持 `|`）
- **接受动态数据源（非字典的可迭代对象）** → `update`（`|` 和 `**` 只接受字典）

### 2.8 ChainMap：逻辑合并视图

前面三种方式都会创建新字典（或原地修改），而 `collections.ChainMap` 提供了一种完全不同的合并方式——**不创建新字典，只是把多个字典"逻辑"串联成一个视图。**

#### 2.8.1 基本用法

```python
from collections import ChainMap

defaults = {"host": "localhost", "port": 8080, "timeout": 30}
env_config = {"port": 3000, "debug": True}
user_config = {"timeout": 60}

# ChainMap 中第一个字典优先级最高
config = ChainMap(user_config, env_config, defaults)

print(f"config['host']: {config['host']}")       # 来自 defaults
print(f"config['port']: {config['port']}")        # 来自 env_config
print(f"config['timeout']: {config['timeout']}")  # 来自 user_config
print(f"config['debug']: {config['debug']}")      # 来自 env_config
```

**运行结果**：

```text
config['host']: localhost
config['port']: 3000
config['timeout']: 60
config['debug']: True
```

**关键点**：`ChainMap` 不复制数据，只是把多个字典按顺序串联。查询时从第一个字典开始往后找，找到就返回。第一个字典的优先级最高。

#### 2.8.2 查找流程

```text
config = ChainMap(user_config, env_config, defaults)
                         │              │              │
                         ▼              ▼              ▼
                    优先级 1        优先级 2       优先级 3

    查询 config['port']
         │
         ▼
    user_config 有 'port'? ──否──→ env_config 有 'port'? ──否──→ defaults 有 'port'?
         │                           │                           │
         是                          是                          是
         │                           │                           │
         ▼                           ▼                           ▼
    返回 60                      返回 3000                   返回 8080
    (没找到就继续往后                (找到了，返回 3000)
     找下一个字典)
```

查到 `config['port']` 时，`user_config` 没有 `port` 键，于是继续查找 `env_config`，在其中找到了 `port: 3000`，直接返回。

#### 2.8.3 修改操作只影响第一个字典

```python
config["retries"] = 5  # 写入 user_config
print(f"user_config: {user_config}")
print(f"env_config: {env_config}")
print(f"defaults: {defaults}")
```

**运行结果**：

```text
user_config: {'timeout': 60, 'retries': 5}
env_config: {'port': 3000, 'debug': True}
defaults: {'host': 'localhost', 'port': 8080, 'timeout': 30}
```

**关键点**：写入操作（赋值、删除）只作用于 `ChainMap` 的第一个字典。这个行为对配置管理非常有用——修改只会落在优先级最高（通常是用户级）的字典上，不会污染默认配置。

#### 2.8.4 new_child 与 parents

`ChainMap` 提供了两个有用的方法：

```python
# new_child() 在链头插入新字典，创建新的 ChainMap
overrides = {"port": 9999, "extra": "new"}
new_config = config.new_child(overrides)
print(f"new config['port']: {new_config['port']}")  # 9999，来自 overrides
print(f"原 config['port']: {config['port']}")       # 3000，不受影响

# parents 去掉第一个字典
print(f"当前链条: {list(config.maps)}")
parents = config.parents
print(f"parents: {list(parents.maps)}")
```

**运行结果**：

```text
new config['port']: 9999
原 config['port']: 3000
当前链条: [{'timeout': 60, 'retries': 5}, {'port': 3000, 'debug': True}, {'host': 'localhost', 'port': 8080, 'timeout': 30}]
parents: [{'port': 3000, 'debug': True}, {'host': 'localhost', 'port': 8080, 'timeout': 30}]
```

**关键点**：

- `new_child()` 不修改原 `ChainMap`，而是创建一个新的 `ChainMap`，在最前面插入一个新字典。这在"临时覆盖某些配置但不影响原始配置"的场景中非常有用。
- `parents` 返回去掉了第一个字典的新 `ChainMap`，用于向上查找。

#### 2.8.5 ChainMap vs update 的核心区别

`ChainMap` 和 `update` 都能实现"多层配置合并"的效果，但机制完全不同：

```python
d1 = {"a": 1, "b": 2}
d2 = {"b": 3, "c": 4}

# update：创建新字典，复制数据
merged_update = d1.copy()
merged_update.update(d2)

# ChainMap：不复制，只是视图
merged_chain = ChainMap(d1, d2)

# 修改原字典，ChainMap 立刻反映变化
d2["c"] = 100
print(f"修改 d2 后 ChainMap['c']: {merged_chain['c']}")  # 100，实时反映
print(f"修改 d2 后 update['c']: {merged_update['c']}")   # 4，不变
```

**运行结果**：

```text
修改 d2 后 ChainMap['c']: 100
修改 d2 后 update['c']: 4
```

**对比表**：

| 维度 | `update` / `|` | `ChainMap` |
|------|----------------|------------|
| 是否复制数据 | 是 | 否，只是视图 |
| 内存消耗 | 与字典总大小成正比 | 常数级（仅存引用） |
| 原字典修改是否反映 | 否（合并不再反映源变化） | 是（实时反映） |
| 写入操作 | 直接修改合并后的字典 | 只影响第一个字典 |
| 查找性能 | O(1)，直接哈希查找 | O(k)，k 为字典数量，最坏需遍历所有 |
| 适用场景 | 合并后独立使用 | 多层配置的动态视图 |

**选择建议**：

- 合并后需要独立使用、不再关心源字典变化 → `update` / `|` / `**`
- 需要实时反映源字典变化、需要分层管理配置 → `ChainMap`
- 字典数量多、频繁合并 → `ChainMap` 省内存
- 只读查询且只查一两次 → `ChainMap` 无需合并开销

### 2.9 copy + update 模式

当你需要"保留原字典，同时得到一个合并后的副本"时，标准做法是 `copy` + `update`：

```python
defaults = {"host": "localhost", "port": 8080, "timeout": 30}
env_config = {"port": 3000, "debug": True}

# 先复制默认配置，再用环境配置更新副本
config = defaults.copy()
config.update(env_config)

print(f"最终配置: {config}")
print(f"原 defaults 未变: {defaults}")
```

**运行结果**：

```text
最终配置: {'host': 'localhost', 'port': 3000, 'timeout': 30, 'debug': True}
原 defaults 未变: {'host': 'localhost', 'port': 8080, 'timeout': 30}
```

**关键点**：

- `dict.copy()` 创建的是**浅拷贝**——字典结构是新的，但值如果是可变对象（如列表、字典），修改值会影响原字典。
- 如果值都是不可变对象（字符串、数字、元组），浅拷贝足够。
- 如果值包含可变对象，需要用 `copy.deepcopy` 进行深拷贝。

**浅拷贝 vs 深拷贝的陷阱**：

```python
import copy

# 浅拷贝：可变值被共享
d1 = {"items": [1, 2, 3]}
d2 = d1.copy()
d2["items"].append(4)
print(f"浅拷贝后 d1: {d1}")  # d1 也被改了！
print(f"浅拷贝后 d2: {d2}")

# 深拷贝：可变值也被复制
d3 = copy.deepcopy(d1)
d3["items"].append(5)
print(f"深拷贝后 d1: {d1}")  # d1 不受影响
print(f"深拷贝后 d3: {d3}")
```

**运行结果**：

```text
浅拷贝后 d1: {'items': [1, 2, 3, 4]}
浅拷贝后 d2: {'items': [1, 2, 3, 4]}
深拷贝后 d1: {'items': [1, 2, 3, 4]}
深拷贝后 d3: {'items': [1, 2, 3, 4, 5]}
```

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

**场景 1：保留原字典的合并**

```python
defaults = {"host": "localhost", "port": 8080}
user = {"port": 3000}

# 推荐：| 运算符，语义清晰，不修改原字典
config = defaults | user

# 推荐：** 解包，兼容 Python 3.5+
config = {**defaults, **user}

# 不推荐：copy + update，写法冗长
config = defaults.copy()
config.update(user)

# 不推荐：直接 update（会修改 defaults！）
config = defaults
config.update(user)  # defaults 被修改了！
```

| 写法 | 修改原字典 | 可读性 | Python 版本 | 问题 |
|------|-----------|--------|------------|------|
| `defaults \| user` | 否 | 高，语义直观 | 3.9+ | 无 |
| `{**defaults, **user}` | 否 | 高 | 3.5+ | 无 |
| `copy` + `update` | 否 | 低，写法冗长 | 所有 | 无，但啰嗦 |
| 直接 `update` | **是** | 高 | 所有 | defaults 被意外修改 |

**原则**：如果你不想修改原字典，用 `|` 或 `**`。只有当你确实想原地修改时才用 `update` 或 `|=`。

**场景 2：多层配置合并**

```python
# 推荐：| 链式合并，优先级一目了然
config = defaults | env_config | user_config

# 推荐：** 解包链式合并
config = {**defaults, **env_config, **user_config}

# 不推荐：多次 update，容易遗漏 copy
config = defaults.copy()
config.update(env_config)
config.update(user_config)
```

**原则**：多层合并用 `|` 或 `**` 链式写法，一行完成，避免多次 `update` 造成的遗漏和可读性下降。

**场景 3：需要插入额外键的合并**

```python
# 推荐：** 解包，可以在中间插入新键
config = {**defaults, "debug": True, **env, "retries": 3}

# 不推荐：先 merge 再逐个加
config = defaults | env
config["debug"] = True
config["retries"] = 3
```

**原则**：当你需要在合并的同时插入额外键值对，`**` 解包是唯一能一步完成的写法。`|` 不支持插入额外键。

### 3.2 常见错误模式

**错误 1：忘记 copy 导致原字典被修改**

```python
defaults = {"a": 1, "b": 2}
config = defaults
config.update({"b": 3, "c": 4})
print(f"defaults: {defaults}")
# 输出: defaults: {'a': 1, 'b': 3, 'c': 4}  ← defaults 被修改了！

# 修正：用 | 或先 copy 再 update
config = defaults | {"b": 3, "c": 4}  # 推荐
# 或
config = defaults.copy()
config.update({"b": 3, "c": 4})
```

**错误 2：以为 update 返回新字典**

```python
d = {"a": 1}
result = d.update({"b": 2})
print(result)          # 输出: None
print(result["b"])     # TypeError: 'NoneType' is not subscriptable

# 修正：update 返回 None，不要链式调用
# 如果需要返回值，用 |
result = d | {"b": 2}
```

**错误 3：浅拷贝导致的可变值共享**

```python
defaults = {"tags": ["python"]}
config = defaults.copy()
config["tags"].append("3.12")
print(f"defaults: {defaults}")
# 输出: defaults: {'tags': ['python', '3.12']}  ← defaults 也被改了！

# 修正：值含可变对象时用 deepcopy
import copy
config = copy.deepcopy(defaults)
config["tags"].append("3.12")
print(f"defaults: {defaults}")  # 不受影响
```

**错误 4：| 运算符与非字典类型混用**

```python
d = {"a": 1}
# d | [("b", 2)]  # TypeError: unsupported operand type(s) for |: 'dict' and 'list'

# 修正：| 只接受字典。键值对序列用 update 或 |=
d |= [("b", 2)]   # |= 支持键值对序列
# 或
d.update([("b", 2)])
```

**错误 5：合并方向搞反**

```python
defaults = {"port": 8080}
user = {"port": 3000}

# 错误意图：用户配置覆盖默认配置
config = user | defaults  # 实际上 defaults 覆盖了 user！
print(config["port"])     # 输出: 8080 ← 变成了默认值

# 修正：优先级低的放左边，优先级高的放右边
config = defaults | user  # 正确：user 覆盖 defaults
print(config["port"])    # 输出: 3000
```

### 3.3 合并方式的性能对比

在性能敏感场景（如高频请求中的参数合并），选择合适的合并方式有实际意义：

```python
import timeit

setup = """
d1 = {'a': 1, 'b': 2, 'c': 3}
d2 = {'b': 4, 'd': 5, 'e': 6}
"""

# update（原地修改）
t1 = timeit.timeit("d1.update(d2)", setup=setup, number=1000000)
# | 运算符（创建新字典）
t2 = timeit.timeit("d1 | d2", setup=setup, number=1000000)
# ** 解包（创建新字典）
t3 = timeit.timeit("{**d1, **d2}", setup=setup, number=1000000)
# copy + update
t4 = timeit.timeit("d1.copy(); d1.copy().update(d2)", setup=setup, number=1000000)

print(f"update:     {t1:.3f}s")
print(f"| 运算符:    {t2:.3f}s")
print(f"** 解包:    {t3:.3f}s")
print(f"copy+update:{t4:.3f}s")
```

**性能排序（快→慢）**：

| 方式 | 是否创建新字典 | 相对速度 |
|------|--------------|---------|
| `update` | 否（原地修改） | 最快 |
| `|` | 是 | 快 |
| `**` 解包 | 是 | 稍慢于 `|` |
| `copy` + `update` | 是 | 最慢（两步操作） |

**关键点**：

- 原地修改的 `update` 总是最快，因为不需要分配新内存。
- `|` 和 `**` 解包都需要创建新字典，但 `|` 稍快一些（底层实现更直接）。
- `copy` + `update` 是两步操作，最慢。
- 实际项目中，除非合并操作在热路径上被频繁执行（如每秒上万次），否则性能差异可以忽略。**可读性优先于微优化。**

### 3.4 何时用哪种合并方式

根据实际场景选择最合适的合并方式：

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 合并多层配置，不修改原字典 | `defaults \| env \| user` | 语义清晰，优先级链一目了然 |
| 合并多层配置，需要在中间插入新键 | `{**d1, "k": v, **d2}` | `**` 解包支持中间插键 |
| 原地修改当前字典 | `d.update(other)` 或 `d \|= other` | 省内存，不需要创建新字典 |
| 从非字典的可迭代对象合并 | `d.update(iterable)` | `|` 和 `**` 不支持非字典 |
| 多层配置的动态视图 | `ChainMap` | 不复制数据，实时反映变化 |
| Python 3.8 及以下 | `{**d1, **d2}` | 不支持 `|` 运算符 |
| 大字典合并、内存敏感 | `ChainMap` 或 `update` | 避免 `|` / `**` 的复制开销 |
| 配置链可能频繁变化 | `ChainMap` | 增删字典只需操作 `maps` 列表 |

## 4. 原理

### 4.1 update 的等价实现

`update` 方法的行为可以用以下等价代码理解：

```python
def update(self, other=None, **kwargs):
    if other is not None:
        if isinstance(other, dict):
            # 字典参数：逐键覆盖
            for key, value in other.items():
                self[key] = value
        else:
            # 可迭代对象：逐个解包为 (key, value)
            for key, value in other:
                self[key] = value
    # 关键字参数：逐键覆盖
    for key, value in kwargs.items():
        self[key] = value
```

**执行流程**：

```text
update(other, **kwargs)
        │
        ▼
  other 是字典?
  ┌───┴───┐
  是      否
  │       │
  │       ▼
  │   other 是可迭代对象?
  │   逐个解包为 (key, value)
  │       │
  ▼       ▼
遍历 other.items()     逐个 (key, value)
  │                    │
  └────────┬───────────┘
           │
           ▼
     逐键 self[key] = value
     （相同键覆盖，新键添加）
           │
           ▼
     处理 **kwargs
     （逐键 self[key] = value）
```

### 4.2 | 运算符的底层实现

Python 3.9 的 `|` 运算符通过 `dict.__or__` 和 `dict.__ror__` 魔术方法实现：

```python
# __or__ 实现 d1 | d2
def __or__(self, other):
    if not isinstance(other, dict):
        return NotImplemented
    new = dict(self)      # 先复制左边字典
    new.update(other)     # 再用右边字典更新
    return new

# __ror__ 实现 other | d（当 other 没有 __or__ 时）
def __ror__(self, other):
    if not isinstance(other, dict):
        return NotImplemented
    new = dict(other)
    new.update(self)
    return new

# __ior__ 实现 d1 |= d2（原地更新）
def __ior__(self, other):
    self.update(other)
    return self
```

**关键点**：

- `|` 的底层就是 `dict(self)` + `update(other)`，本质和 `copy` + `update` 一样，但封装成了运算符，语义更清晰。
- `|=` 的底层就是 `update`，只是返回 `self` 以支持链式赋值。
- `|` 只接受 `dict` 类型——这正是为什么 `d | [list]` 会报 `TypeError`。`__or__` 检查参数类型，不匹配时返回 `NotImplemented`，Python 解释器随即抛出 `TypeError`。

### 4.3 | 运算符为什么只接受字典

`update` 方法很灵活，可以接受字典、键值对序列和关键字参数。但 `|` 运算符故意只接受字典，这是 PEP 584 的设计决策：

```python
# update 接受多种类型
d.update({"a": 1})       # OK
d.update([("a", 1)])     # OK
d.update(a=1)             # OK

# | 只接受字典
d | {"a": 1}              # OK
# d | [("a", 1)]          # TypeError
```

**设计原因**：

1. **语义清晰**：`|` 是合并运算符，语义是"将两个字典合并"。如果接受键值对序列，读者需要判断 `d | x` 中的 `x` 是字典还是列表，增加认知负担。
2. **避免歧义**：`d | [(1, 2), (3, 4)]` 中，`[(1,2),(3,4)]` 到底是键值对序列还是值恰好是元组的列表？类型标注无法区分。只接受字典避免了这种歧义。
3. **运算符重载一致性**：Python 中 `|` 运算符在集合（`set`）上表示并集，双方都是同类类型。字典合并也遵循这个原则——双方都是 `dict`。
4. **需要非字典类型时用 `update`**：`update` 和 `|=` 都已经支持可迭代对象，需要灵活参数时用它们即可。`|` 保持简单。

### 4.4 ChainMap 的查找机制

`ChainMap` 的核心机制是在内部维护一个 `maps` 列表，查询时从前往后依次在各字典中查找：

```python
# ChainMap 的简化等价实现
class ChainMap:
    def __init__(self, *maps):
        self.maps = list(maps) or [{}]  # 至少一个空字典

    def __getitem__(self, key):
        for mapping in self.maps:
            if key in mapping:
                return mapping[key]
        raise KeyError(key)

    def __setitem__(self, key, value):
        self.maps[0][key] = value  # 只写入第一个字典

    def __delitem__(self, key):
        # 只从第一个字典删除
        del self.maps[0][key]
```

```text
ChainMap(['user_config', 'env_config', 'defaults'])
     │
     │  查询 config['port']
     ▼
┌─────────────────────┐
│ user_config         │ ── 'port' 不在 ──→ 继续
└─────────────────────┘
     │
     ▼
┌─────────────────────┐
│ env_config         │ ── 'port' 在！返回 3000
└─────────────────────┘
     │
     ▼
┌─────────────────────┐
│ defaults            │ (不会到达)
└─────────────────────┘
```

**性能特点**：

- 查找时间复杂度为 O(k)（k 为字典数量），而非普通字典的 O(1)。但实际中 k 通常很小（2~5 层），实际差异可忽略。
- 写入和删除都是 O(1)，只作用于第一个字典。
- 不复制任何数据，内存开销为常数级（仅存储字典引用列表）。

**与 update 的关键区别**：`update` 合并后是独立的字典，源字典的变化不再反映。`ChainMap` 是引用视图，源字典的任何增删改都会实时反映在查询结果中。这就是 ChainMap 被称为"动态视图"的原因。

## 5. 总结

本文围绕字典的 `update` 方法与多种字典合并方式展开，主要介绍了以下内容：

- `update` 方法接受三种参数形式：字典、产生 `(key, value)` 二元组的可迭代对象、关键字参数，原地修改目标字典，返回 `None`
- `|` 运算符（Python 3.9+）创建新字典进行合并，`|=` 运算符等价于 `update` 进行原地更新，两者只接受字典类型作为操作数
- `**` 解包语法在字典字面量中展开多个字典并产生新字典，独特优势是可以在解包之间插入额外键值对
- 三种合并方式的对比：`update` 原地修改、`|` 和 `**` 产生新字典，在是否修改原字典、参数灵活性、Python 版本要求上的差异
- `ChainMap` 提供逻辑合并视图，不复制数据、实时反映源字典变化、写入只影响第一个字典
- `copy` + `update` 模式用于保留原字典的合并，注意浅拷贝和深拷贝的区别——值含可变对象时需用 `deepcopy`
- 最佳实践：保留原字典用 `|` 或 `**`，原地修改用 `update` 或 `|=`，多层配置动态视图用 `ChainMap`，合并方向为右覆盖左
- 常见错误模式：忘记 copy 导致原字典修改、以为 update 返回新字典、浅拷贝导致可变值共享、`|` 运算符与非字典混用、合并方向搞反
- 性能对比：`update` 最快（原地修改），`|` 稍快于 `**`（新字典创建），`copy` + `update` 最慢（两步操作）
- 原理层面：`|` 的底层实现是 `dict(self)` + `update(other)`，`|` 只接受字典是 PEP 584 为保持语义清晰的设计决策，`ChainMap` 通过 `maps` 列表实现 O(k) 查找的动态视图机制
