# for 循环基础与迭代协议

## 1. 介绍

### 1.1 什么是 for 循环

for 循环是 Python 中"由数据驱动"的循环语句：**从一串数据（可迭代对象）里依次取出元素，每取到一个，就执行一遍循环体；元素取完，循环自然结束**。它天生面向"手里有一批东西，每个都要处理"的场景。

与 while 立个分水岭把两者摆正：while 盯的是**条件**（条件成立就继续，事前数不清轮数），for 盯的是**数据**（有几个元素就跑几轮，数据说了算）。用 while 写遍历要自己管理下标、边界、推进三件事；用 for 写遍历，这三件事全部交给语言托管——**你只负责说清楚"每一轮拿元素干什么"**。

**类比**：for 像流水线的传送带——货物（元素）挨个送到工位（循环体），工人对每件做同样的加工，传送带送完最后一件，流水线自己停下来。注意工人从不操心"还有几件货"——货没送到手，流水线不停；货送完了，停是自动的。而 while 更像门口的门卫，每一轮都重新问一遍"条件还成立吗"。两条路线的分工感从此就能建立起来。

顺带把"迭代（iterate）"这个词也认领了：**迭代 = 逐个取用可迭代对象里的元素并把每个都过一遍**。for 循环的正式学名就叫"迭代循环"，读了下文你会看到这个学名一点不虚——for 的内部真的就是靠一套"迭代协议"运转的。

### 1.2 for 循环解决什么问题

for 的应用场景可以归成三类，每一类都是把"一批"变成"逐个"：

| 场景类型 | 典型例子 | for 承担的角色 |
|---------|---------|---------------|
| 遍历处理 | 给每个学生发一条通知、核对购物清单每项 | 把一批数据逐个送进处理逻辑 |
| 逐元素加工 | 统计字符串里字母数字各几个、给每个分数判等级 | 挨个检视、挨个记录 |
| 批量生产 | 由一列原料生成一列产品（如平方数表） | 按同一套规则逐个加工并收集结果 |

共同点一眼可见：**"一批数据 + 每个都做同一件事" = for 的主场**。反过来，当"什么时候停"取决于某个运行时状态而不是数据规模（比如"一直重试直到连接成功"），那就该把舞台让给 while。

### 1.3 最简示例

五行代码看全 for 的样子：

```python
fruits = ["苹果", "香蕉", "橘子"]

for fruit in fruits:
    print(f"今天吃：{fruit}")
```

运行结果：

```text
今天吃：苹果
今天吃：香蕉
今天吃：橘子
```

部件指认：`for` 是关键字，负责"开loop"；`fruit` 是循环变量，每轮接住一个元素；`in fruits` 指明数据源是 `fruits` 这个列表；冒号和缩进圈出循环体的范围。三个元素，循环体恰好执行三轮；第四轮"f伸手取元素"扑了个空，循环自动画上句号。

往列表里加两个水果，代码一个字不用改——**数据的规模由数据自己负责，代码只描述规则**，这是 for 带来的核心红利。

本篇的任务分两层：第一层把 for 的每个部件、每种用法装进工具箱（数据源放什么、循环变量怎么接、循环体能干什么）；第二层拆开 for 的引擎盖，看清它背后那套**迭代协议**——理解了这套协议，你就明白为什么列表、字符串、字典、集合、文件行……形形色色的数据源，for 都能一视同仁地遍历。

## 2. 核心内容

### 2.1 for 语句的完整语法骨架

for 语句由四个部件构成：

| 部件 | 角色 | 说明 |
|------|------|------|
| `for` 关键字 | 引导语句 | 告诉 Python"这是数据驱动的迭代循环" |
| 循环变量 | 每轮元素的接收端 | 写一个变量名；一轮接到一个元素；名字由你定 |
| `in 数据源` | 元素的来源 | `in` 后面放任何可迭代对象：列表、元组、字符串、字典、集合、range 等 |
| `:` 冒号 + 缩进循环体 | 每轮执行的代码 | 缩进一层；一到多条语句；轮内从上到下执行 |

骨架展开：

```python
for 变量 in 数据源:
    语句1
    语句2        # 循环体：缩进部分，一轮内完整执行
    ...
# 缩进复位后：循环结束才执行的收尾代码
```

**示例**

各部件在成绩遍历里各就各位：

```python
scores = [86, 92, 78]

for score in scores:          # for + 循环变量 score + in 数据源 scores
    print(f"处理中：{score}")   # 循环体：每轮执行一遍
print("全部处理完毕")           # 与 for 同列 → 循环结束后执行一次
```

**运行结果**：

```text
处理中：86
处理中：92
处理中：78
全部处理完毕
```

**关键点**：用循环三要素（初始、推进、终止）的视角审视 for，会发现三件事全部被语言托管——初始（从第一个元素取起）、推进（自动取下一个）、终止（取不到下一个了）都不需要你写一行。这正是 for 比 while 少操心、少出错的根源：**while 把三要素全权交给你，for 把三要素全部收走**。你唯一必须写清楚的是循环体——"每一轮拿这个元素干什么"。

### 2.2 循环变量：每轮到岗的"接收端"

循环变量是 for 与循环体之间的**交接岗**：每轮开始，for 把这一轮取到的元素赋值给它，循环体里就能直接用这个名字办事。它有四条性质需要一次认清，后面写代码才不迷糊。

**性质一：每轮换一个新值，上一轮的值直接被覆盖。**

```python
for score in [86, 92, 78]:
    print(f"本轮 score 接到：{score}")
```

**运行结果**：

```text
本轮 score 接到：86
本轮 score 接到：92
本轮 score 接到：78
```

**性质二：接收端按"元素的形状"接。** 数据源元素是什么样，循环变量就按什么样接住——一个值就用一个名字；元素本身是"两个值组成的对"，可以写两个名字拆开接：

```python
for subject, score in [("语文", 88), ("数学", 95)]:
    print(f"{subject}：{score} 分")
```

**运行结果**：

```text
语文：88 分
数学：95 分
```

**关键点**：拆开接的前提是元素形状真的对得上——元素是二元组就拆两个名字，三元组拆三个，不匹配会直接报错。读写任何 for 语句都从这一步入手：**先看数据源的元素长什么样，再决定接收端怎么写**。

**性质三：循环结束后，循环变量不消失，停留在最后一个元素上。**

```python
scores = [86, 92, 78]
for score in scores:
    pass                    # 先让循环空跑一遍
print(f"循环结束，score 仍然是：{score}")
```

**运行结果**：

```text
循环结束，score 仍然是：78
```

**性质四：循环体内给循环变量重新赋值，只在本轮内有效。** 你改它，改的是"这一轮的复印件"；下一轮 for 照样取来新元素覆盖它，数据源毫发无损：

```python
for score in [86, 92, 78]:
    score += 100            # 本轮内 score 变成了别的数
    print(f"循环体内看到的 score：{score}")
print("但这个改动既回不到数据源，也活不到下一轮")
```

**运行结果**：

```text
循环体内看到的 score：186
循环体内看到的 score：192
循环体内看到的 score：178
但这个改动既回不到数据源，也活不到下一轮
```

**关键点**：循环变量是"交接岗"，不是"仓库"——想改数据源，得绕过它直接对数据源下手，这一手法在 2.6 节展开。

除这四条性质之外，循环变量的命名有讲究：**名字跟着元素的业务含义走**——遍历成绩用 `score`、遍历单词用 `word`、遍厉学生用 `student`。名字起了 80% 的注释作用，`for x in xs:` 这种写法等于把解释权扔了。

### 2.3 遍历三种序列：列表、元组、字符串

序列类（列表、元组、字符串）是 for 数据源里最常见的一族。三者共用同一条 for 语句，差别只在"每轮取到的元素是什么"：

| 数据源 | 每轮取到的元素 | 典型场景 |
|--------|--------------|---------|
| 列表 | 列表里的一个值（按存放顺序） | 核对清单、逐个处理业务对象 |
| 元组 | 元组里的一个值（按存放顺序） | 与列表遍历行为完全一致 |
| 字符串 | 单个字符（按从左到右顺序） | 逐字符检查、统计、清洗文本 |

**遍历列表：核对购物清单**

```python
shopping = ["牛奶", "鸡蛋", "面包"]
for item in shopping:
    print(f"核对清单：{item}")
```

**运行结果**：

```text
核对清单：牛奶
核对清单：鸡蛋
核对清单：面包
```

**遍历元组：坐标点过检查站**——语法与列表零差别：

```python
checkpoints = [(0, 0), (3, 4), (5, 12)]
for point in checkpoints:
    print(f"坐标 {point} 通过检查")
```

**运行结果**：

```text
坐标 (0, 0) 通过检查
坐标 (3, 4) 通过检查
坐标 (5, 12) 通过检查
```

注意元素本身是元组——接收端写一个 `point` 整体接、或写 `x, y` 拆开接，两种都合法（性质二）。

**遍历字符串：逐字符分类统计**

```python
text = "Py3thon"
letters = 0
digits = 0
for ch in text:
    if ch.isalpha():
        letters += 1
    elif ch.isdigit():
        digits += 1
print(f"“{text}” 中字母 {letters} 个，数字 {digits} 个")
```

**运行结果**：

```text
“Py3thon” 中字母 6 个，数字 1 个
```

**关键点**：字符串遍历严格按单个字符切开，一个不多一个不少——七个字符的字符串，循环体就执行七轮（P、y、3、t、h、o、n）。这里顺演示了"累加器 + 条件"和 for 的标准组合：循环负责送元素，条件负责筛记账，这是日常代码里最高频的搭配之一。

### 2.4 遍历字典的三种姿势与集合

字典在 for 里是个特例：它同时住着键和值，于是"每轮取到什么"有了三种选择，全靠接收端怎么配合。

**姿势一：直接遍历字典 → 每轮取到一个键**（拿到键后随手用 `字典[键]` 查值）：

```python
courses = {"语文": 88, "数学": 95, "英语": 91}
for subject in courses:
    print(f"课程名：{subject}（courses[subject] = {courses[subject]}）")
```

**运行结果**：

```text
课程名：语文（courses[subject] = 88）
课程名：数学（courses[subject] = 95）
课程名：英语（courses[subject] = 91）
```

**姿势二：遍历 `.values()` → 每轮只取一个值**（只关心分数、不关心课程名时）：

```python
for score in courses.values():
    print(f"分数：{score}")
```

**运行结果**：

```text
分数：88
分数：95
分数：91
```

**姿势三：遍历 `.items()` → 键值成对到手**（元素是 `(键, 值)` 元组，配合拆开接收正合适）：

```python
for subject, score in courses.items():
    print(f"{subject}：{score} 分")
```

**运行结果**：

```text
语文：88 分
数学：95 分
英语：91 分
```

**关键点**：三种姿势对应"你要什么"——只要键、只要值、键值都要。`.items()` 的元素形状是二元组，正好印证接收端规则：**元素是两个值的对，接收端就写两个名字**。这也是"长 for 写法"家族里最常出场的一支：`(键, 值)` 的形状决定 `k, v` 的接收姿势。

**遍历集合：无重复、无次序保证**：

```python
tags = {"新手", "进阶", "新手", "入门", "入门"}
for tag in tags:
    print(f"标签：{tag}")
print(f"集合里实际只有 {len(tags)} 个元素（重复的不计）")
```

**运行结果**：

```text
标签：入门
标签：新手
标签：进阶
集合里实际只有 3 个元素（重复的不计）
```

**关键点**：集合的两个特性格在这段代码里都现了形——**重复元素入库时自动去重**（五个标签只剩三个）；**遍历顺序不做保证**（不同环境下打印次序可能不同，不能依赖"先放的先遍历"）。凡是"标签""参与名单"这类天生不重复、又不在乎次序的数据，集合是最贴身的容器。

### 2.5 for 与 range 的最小配合

有一类任务**没有现成数据可遍历**——"做五次重复的固定动作""把 1 到 100 每个数都过一遍"。硬造一个 `[1, 2, 3, ..., 100]` 的列表显然笨重；这件事 range 对象专职承包：

```python
for n in range(5):          # range(5) 依次产出 0、1、2、3、4
    print(f"第 {n + 1} 次抽奖")
```

**运行结果**：

```text
第 1 次抽奖
第 2 次抽奖
第 3 次抽奖
第 4 次抽奖
第 5 次抽奖
```

range 的最小用法两条就够起步：

| 写法 | 产出的整数序列 | 规则 |
|------|--------------|------|
| `range(5)` | 0, 1, 2, 3, 4 | 从 0 出发，**不含**终点 5 |
| `range(10, 15)` | 10, 11, 12, 13, 14 | 从 10 出发，**不含**终点 15 |

**含头不含尾**是 range 的端点铁律——写 `range(1, 101)`，产出的正是"1 到 100 整一百个数"。把计数交给 for + range，对照手写 while 计数（初始、条件、推进三件全要自己招呼），for + range 一行把三件事全托管了：

```python
# 计算存款翻倍多少轮后超过 1000（纯数轮次的任务也能交给 for）
amount = 100
for rounds in range(1, 11):      # 最多试 10 轮
    amount *= 2
    print(f"第 {rounds} 轮后金额：{amount}")
```

**运行结果**：

```text
第 1 轮后金额：200
第 2 轮后金额：400
第 3 轮后金额：800
第 4 轮后金额：1600
...
```

（输出共 10 行，金额按轮翻倍：200、400、800、1600、3200、6400、12800、25600、51200、102400。）

**关键点**：range 还支持第三参数"步长"（如 `range(0, 10, 2)` 产出 0、2、4、6、8）与倒序写法，同理"含头不含尾"。它作为专用主题有自己的一整套用法，本篇先把"给 for 当计数数据源"这条主干用法拿稳即可。

### 2.6 循环变量与元素的关系：复印件还是原件

2.2 节性质四埋了引线："改循环变量改不动数据源"，本节把这个话题收圆。核心只有一句话：**循环变量接到的，是不可变元素的"值复印件"，却是可变元素的"原件别名"**——两种行为要用两个例子分别看清。

**情形一：元素是不可变值（数字、字符串等）——改循环变量白改。**

```python
scores = [86, 92, 78]
for score in scores:
    score += 5              # 改的只是本轮的循环变量
print(f"循环后原数据：{scores}——一个都没变")
```

**运行结果**：

```text
循环后原数据：[86, 92, 78]——一个都没变
```

**修正：想改数据源，绕开循环变量、按下标回到数据源定位再改。**

```python
scores = [86, 92, 78]
for i in range(len(scores)):      # 用下标逐个定位
    if scores[i] < 90:
        scores[i] += 5            # 对数据源本尊动手
print(f"补分后的数据：{scores}——低于 90 的被改了")
```

**运行结果**：

```text
补分后的数据：[91, 92, 83]——低于 90 的被改了
```

**情形二：元素是可变对象（列表、字典等）——循环变量是它的原件别名，通过这个别名用方法修改，改的是真身。**

```python
teams = [["小明", "小红"], ["小刚"], ["小丽", "小军", "小芳"]]
for team in teams:          # team 接到的是内层列表这个对象本身
    team.append("替补")      # 对它调用方法，直接改在了原数据上
print(f"每组都多了一名替补：{teams}")
```

**运行结果**：

```text
每组都多了一名替补：[['小明', '小红', '替补'], ['小刚', '替补'], ['小丽', '小军', '小芳', '替补']]
```

**关键点**：这背后是值的引用语义——不可变值（数字、字符串、元组）交接时给的是"值本身"，改它等于另立门户；可变值（列表、字典、集合）交接时给的是"同一个对象的引用"，别名 `team` 与原数据里的那格是**同一个对象**，一动俱动。记住 结论版口诀：**想改数据源，对不可变元素按下标回炉；对可变元素直接通过循环变量调方法**。

## 3. 最佳实践

### 3.1 推荐写法与不推荐写法对照

写 for 的常见决策点，推荐姿势与踩坑姿势对照如下：

| # | 场景 | 不推荐写法 | 推荐写法 | 原因 |
|---|------|-----------|---------|------|
| 1 | 遍历已知序列 | 下标手动挡三件套 | `for x in seq:` | 自己管初始/边界/推进，多一处出错面 |
| 2 | 循环变量命名 | `for x in xs:` | `for score in scores:` | 名字即注释，业务含义一行点透 |
| 3 | 字典按需取用 | 一律 `for k, v in d.items()` | 只要值就 `.values()`，只要键就直接遍历 | 索取与需求对齐，代码更短、意图更直 |
| 4 | 修改数据源 | 给循环变量赋值想改原数据 | 不可变元素按下标回炉；可变元素通过别名调方法 | 循环变量是复印件（值）或别名（对象），赋值改不到数据源 |
| 5 | 循环体内用与元素无关的常量 | 每轮重复计算 | 循环开始前先算好存进变量 | 同一个值算 n 遍是浪费，先算一次处处可用 |

第 1 条展开对照一眼看清差距。不推荐的手动挡：

```python
names = ["张三", "李四", "王五"]
i = 0
while i < len(names):
    print(f"你好，{names[i]}")
    i += 1
```

推荐的直接遍历：

```python
for name in names:
    print(f"你好，{name}")
```

同一段输出，for 版把三要素（初始、条件、推进）全部托管给语言，既短又稳。**判据复习一遍：数据在手、逐个处理，必选 for**。

### 3.2 常见错误模式及修正

**错误模式一：边遍历边删除——迭代器被"抄了后路"**

任务是从 `[1, 2, 2, 3]` 里删光所有的 2：

```python
nums = [1, 2, 2, 3]
for n in nums:
    if n == 2:
        nums.remove(n)       # 一边遍历、一边对同一列表动刀
print(f"删除后：{nums}")
```

**运行结果**：

```text
删除后：[1, 2, 3]
```

预期是 `[1, 3]`，实际残留了一个 2。原因藏在遍历机制里：**循环按"当前位置"取元素，remove 把后面的元素整体左移一格，紧跟被删元素的下一个值就滑进了"当前位置"，下一轮直接跳到它后面**——被跳过的正是第二个 2。修正姿势一：遍历副本、对原件动刀：

```python
nums = [1, 2, 2, 3]
for n in nums[:]:             # nums[:] 造一个同内容的副本供遍历
    if n == 2:
        nums.remove(n)        # 删的是原列表，遍历的是副本，互不干扰
print(f"删除后：{nums}")
```

**运行结果**：

```text
删除后：[1, 3]
```

修正姿势二：不删原件、筛选重构（保留谁就收集谁）：

```python
nums = [1, 2, 2, 3]
kept = []
for n in nums:
    if n != 2:
        kept.append(n)
print(f"删除后：{kept}")
```

**运行结果**：

```text
删除后：[1, 3]
```

**关键点**：**循环进行期间，别改变数据源自身的规模**——删除会让元素滑位、新增会让循环计划变卦，两者都会让"每个元素恰好过一遍"的约定失效。要么遍历副本、要么整个重构一遍，让遍历与修改彻底分家。

**错误模式二：循环变量遮蔽外层同名变量**

外层已经有一个 `count` 另有他用，再顺手用它当循环变量，一轮遍历下来原值被洗掉：

```python
count = 100                       # 外层业务变量
for count in [1, 2, 3]:           # 无意间同名——循环会覆盖它
    pass
print(f"count 现在是：{count}")
```

**运行结果**：

```text
count 现在是：3
```

100 无声无息地变成了 3。修正是**给循环变量挑一个专属名字**，同名即隐患：循环变量每轮必然被赋值，同名的外层变量迟早被覆盖。

**错误模式三：字典姿势错位——要值却绕远路**

需要打印每门课的分数（不需要课程名），却绕道键去查值：

```python
courses = {"语文": 88, "数学": 95}
for subject in courses:
    score = courses[subject]      # 拿到键，再折回字典查一次值
    print(f"分数：{score}")
```

功能正确，但**索取应与需求对齐**——只关心值时直接 `.values()` 一步到位：

```python
for score in courses.values():
    print(f"分数：{score}")
```

两段输出相同，后者少一重拐弯、意图更直。姿势选择的心法很简单：**要什么，就遍历什么**。

### 3.3 for 与 while 的场景分工速查

| 特征 | 优先选 for | 优先选 while |
|------|-----------|-------------|
| 手里的数据 | 有一批已知元素 | 没有现成数据，只有状态与条件 |
| 循环次数 | 事前数得清（元素个数/轮次上限） | 事前数不清 |
| 停止方式 | 元素取完自然停 | 条件被打破才停 |
| 三要素 | 语言托管，零负担 | 自己管理，全责自负 |
| 典型场景 | 遍历序列、逐字符处理、配合 range 计数 | 等待达标、消耗库存、重试到成功 |

一句话判据：**for 问"还有没有下一个"，while 问"条件还成立吗"**；写循环前自问这一句，选型基本不会错。

## 4. 原理：迭代协议——for 背后的真实运转

### 4.1 iter() 与 next()：两步走的标准流程

for 最让人好奇的一点：列表、字符串、字典、集合……数据源五花八门，for 凭什么一视同仁地遍历？答案是一套**迭代协议（iteration protocol）**——所有能进 for 的对象都遵守同一条契约，for 也只认这一条契约。契约由两步构成：

| 步骤 | 谁来做 | 做什么 |
|------|--------|--------|
| 第一步 | `iter(数据源)` | 向数据源要一个"迭代器"（iterator）——真正负责逐个吐元素的工作台 |
| 第二步 | `next(迭代器)` | 每轮找迭代器吐下一个元素；吐完了（耗尽）给出结束信号 |

for 语句启动时先执行第一步拿到迭代器，之后每轮执行第二步取元素，直到收到"取完了"的信号，循环安静退出。全流程画成图：

```text
   ┌──────────────────────┐
   │ for 开始：it = iter(数据源)│
   └──────────┬───────────┘
              ↓
   ┌──────────────────────┐
   │ item = next(it)       │ ←─────────┐
   └──────────┬───────────┘           │
              ↓                       │
        还有元素吗？                    │
      元素 ↙      ↘ 取完了(StopIteration)
   ┌──────────────┐      ┌──────────┐  │
   │ 执行循环体    │      │ for 退出 │  │
   └──────┬───────┘      └──────────┘  │
          └──────── 回去取下一个 ──────┘
```

**手动走一遍协议**，把 for 托管的两步亲手做一次：

```python
letters = ["A", "B", "C"]
it = iter(letters)                 # 第一步：向数据源要迭代器
print(f"取一个：{next(it)}")       # 第二步：找迭代器要下一个元素
print(f"取一个：{next(it)}")
print(f"取一个：{next(it)}")
print(f"再取 → {next(it, '（取完了，返回默认值）')}")   # 双参数形态：耗尽不报错
```

**运行结果**：

```text
取一个：A
取一个：B
取一个：C
再取 → （取完了，返回默认值）
```

**关键点**：`next(迭代器)` 单参数形态在耗尽时会抛出 `StopIteration`——这不是程序坏了，而是协议约定的**结束哨兵**；for 的内部正是靠"听到哨兵就收工"来断定循环结束的。日常手动验证行为时推荐用双参数形态 `next(it, 默认值)`：耗尽不再抛哨兵、改为安静返回默认值，省去异常处理的麻烦。

### 4.2 用 while 手动模拟一次 for

既然迭代协议的全部动作就两步，把 for 正在做的事用 while 翻译出来，就等于亲眼看见了 for 的源代码。哨兵选一个独一无二的值（比如 `object()` 造的独门对象），用"取出的是不是哨兵"来判定是否耗尽：

```python
letters = ["甲", "乙", "丙"]
it = iter(letters)                 # for 语句启动时背后的第一步
SENTINEL = object()                # 一个独一无二的"取完了"信号
item = next(it, SENTINEL)          # 先取一个在手里
while item is not SENTINEL:        # 手里是哨兵 = 数据源到头了
    print(f"处理元素：{item}")
    item = next(it, SENTINEL)      # 处理完再取下一个
print("循环结束")
```

**运行结果**：

```text
处理元素：甲
处理元素：乙
处理元素：丙
循环结束
```

**关键点**：逐行对照——`it = iter(...)` 对应 for 的启动动作；`next(it, SENTINEL)` 对应每轮开始前"自动取下一个"的推进；`item is not SENTINEL` 对应"还有下一个吗"的终止判断；中间的 print 对应循环体。while 版要你亲手钉好每一个零件，for 版把这三件事打成一个整包语句。**for 不是魔法，是迭代协议的语法糖**——这句大白话就是本篇的原理总纲。

### 4.3 可迭代对象 vs 迭代器：一字之差的分工

协议里有两个角色最容易混淆：**可迭代对象（iterable）**与**迭代器（iterator）**。它们的分工像仓库与工位：

| 维度 | 可迭代对象（iterable） | 迭代器（iterator） |
|------|----------------------|-------------------|
| 身份 | "家底殷实"的数据源：能把元素**逐个交出去** | "一线工位"：接受指令后逐个**吐出**元素 |
| 核心能力 | 支持 `iter(x)`——被要时能交出一个迭代器 | 支持 `next(x)`——每次吐下一个，吐完报耗尽 |
| 典型代表 | 列表、元组、字符串、字典、集合、range | `iter(某个可迭代对象)` 的返回结果 |
| 自己能被 for 直接遍历吗 | 能（for 第一步就是向它 iter） | 也能（迭代器自身也遵守协议） |
| 可重复遍历吗 | 能——每次 iter 都发一个**全新**工位 | 不能——一个工位吐完即废止（下节展开） |

身份可以现场检验。从标准库 `collections.abc` 借两个"身份检查器"（`Iterable` 问"能不能被 for"、`Iterator` 问"是不是一线工位"），配合已知的 `isinstance` 用法：

```python
from collections.abc import Iterable, Iterator

letters = ["A", "B", "C"]
it = iter(letters)

print(f"列表是可迭代对象吗：{isinstance(letters, Iterable)}")     # 家底：能
print(f"列表自己是迭代器吗：{isinstance(letters, Iterator)}")     # 但不是一线工位
print(f"iter() 返回的是迭代器吗：{isinstance(it, Iterator)}")     # 它才是吐元素的
```

**运行结果**：

```text
列表是可迭代对象吗：True
列表自己是迭代器吗：False
iter() 返回的是迭代器吗：True
```

**关键点**：列表本身"家底殷实"但它不亲自吐元素——`iter(letters)` 交出的 `it` 才是一线工位。**for 要的是可迭代对象（能被 iter 的），真正干活的是迭代器（能被 next 的）**。这个分工记牢，接下来"迭代器一次性"的怪脾气就顺理成章。

### 4.4 迭代器的一次性：耗尽即止

迭代器有一条铁律：**一个工位只吐一轮元素，耗尽即废止**。亲手验证——同一个迭代器喂给 for 两次。第一遍正常喝干：

```python
it = iter(["一", "二", "三"])
for item in it:                    # 第一遍：把工位的元素取干
    print(f"第一遍取到：{item}")
```

**运行结果**：

```text
第一遍取到：一
第一遍取到：二
第一遍取到：三
```

紧接着对**同一个** `it` 再 for 一遍，并数一数这回取到了几个：

```python
count = 0
for item in it:                    # 第二遍：同一个工位已经吐空了
    count += 1
    print(f"第二遍取到：{item}")
print(f"实测：同一个迭代器第二次只取到 {count} 个元素")
```

**运行结果**：

```text
实测：同一个迭代器第二次只取到 0 个元素
```

**对照实验**：列表本身就可以反反复复遍历，原因在 4.3 的表格里——**每次 `for x in 列表`，第一步都是向列表重新领一个全新的迭代器**，上一轮用废的工位与这一轮无关：

```python
letters = ["甲", "乙", "丙"]
for item in letters:
    print(f"第一遍：{item}")
for item in letters:
    print(f"第二遍：{item}")       # 列表毫发无损，两遍都完整
```

**运行结果**：

```text
第一遍：甲
第一遍：乙
第一遍：丙
第二遍：甲
第二遍：乙
第二遍：丙
```

**关键点**：把两所以并成一句话——**谁握着"可迭代对象"（家底），谁就能反复遍历；谁只握着裸"迭代器"（工位），谁就得省着用**。日后凡是碰到"只能遍历一次"的对象（某些惰性产出的序列、一次性的流式数据），怪脾气都出于此：它们把家底直接做成了工位，吐完即空，想再来一遍只能重新造一个。

### 4.5 这套协议解决了什么

回头俯瞰，迭代协议的设计价值可以归纳成两条：

**其一：给 for 一个统一接口。** for 不需要知道数据源是列表还是字符串、是字典还是 range——它只按协议行事："你能被 iter、吐出的工位能被 next，我就带你遍历。"容器家族里每一个成员都各自实现了"交元素"的具体方式，而 for 侧的代码一行都不用改。这解释了本章开头的疑问：**五花八门的数据源，for 为什么一视同仁——不是 for 博爱，是大家都签了同一份契约**。

**其二：把"怎么取"的权利下放给数据源自己。** 字典最懂自己的键值结构、字符串最懂自己的字符序列、range 更是根本不存元素、要谁现造谁——每种数据源按自己的家情设计取元素的方式，for 只负责流水线调度。这套分工的妙处在于**开放扩展**：协议对自定义类型同样开放——凡实现"交出迭代器、逐个吐元素"这两个约定动作的对象，无论多特殊，都能直接进入 for 的世界。理解了契约本身，新容器上手时你只需要问一句"它的元素按什么序吐出来"，遍历姿势自动就位。

## 5. 总结

本文围绕 for 循环的用法与背后的迭代协议展开，主要介绍了以下内容：

- for 是数据驱动的循环：依次取元素、每轮执行一遍循环体、取完自然停；三要素（初始、推进、终止）全部由语言托管，你只描述"每轮拿元素干什么"；
- 语法骨架四部件（for 关键字、循环变量、in 数据源、冒号+缩进循环体）；循环变量每轮接一个元素、结束后停在最后一个值上、同轮内改它只在当轮有效；
- 接收端按"元素的形状"接：单值单名收、二元组拆两个名收——读任何 for 先看数据源元素长什么样；
- 三种序列（列表、元组、字符串）遍历行为一致，差别只在每轮元素的形态；字符串严格按单字符切分；
- 字典遍历三种姿势（直接遍历取键、`.values()` 取值、`.items()` 键值成对）——要什么就遍历什么；集合去重且顺序不做保证；
- range 是"无现成数据时"的计数数据源：`range(5)` 产 0~4、`range(10, 15)` 产 10~14，含头不含尾；
- 循环变量与元素的关系：不可变元素是"值复印件"（改循环变量改不到数据源，修数据要按下标回炉），可变元素是"原件别名"（通过循环变量调方法改的是真身）；
- 最佳实践五组对照与三类错误模式：边遍历边删（迭代器被抄后路，遍历副本或筛选重构）、循环变量遮蔽外层同名变量、字典姿势错位绕远路；
- 迭代协议原理：for = iter() 拿迭代器 + 每轮 next() 取元素 + StopIteration 收工的两步契约；可迭代对象（家底）与迭代器（工位）一字分工；迭代器耗尽即废止、可迭代对象每次 for 都领新工位；
- 协议的设计价值：统一接口让形形色色的数据源一视同仁，"怎么取"的权利下放给数据源自己，并天然开放给更多对象加入。
