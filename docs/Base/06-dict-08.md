# 字典的 get 方法与默认值

## 1. 介绍

### 1.1 什么是 get 方法

`dict.get(key)` 是 Python 字典提供的一个安全访问方法。当你用中括号语法 `dict[key]` 访问一个不存在的键时，Python 会抛出 `KeyError` 异常导致程序崩溃；而 `get` 方法在键不存在时安静地返回 `None`（或你指定的默认值），不会报错。

一句话概括：**`get` 是字典的"温柔版"访问方式——有就给你值，没有就给你默认值，绝不崩溃。**

### 1.2 最简示例

```python
scores = {"张三": 90, "李四": 85}

# 中括号访问：键不存在 → KeyError 崩溃
# scores["王五"]  # KeyError: '王五'

# get 方法访问：键不存在 → 返回 None，不报错
result = scores.get("王五")
print(result)
```

运行结果：

```text
None
```

如果想自定义键不存在时的返回值，传入第二个参数 `default`：

```python
scores = {"张三": 90, "李四": 85}

result = scores.get("王五", 0)
print(result)
```

运行结果：

```text
0
```

### 1.3 get 方法的签名

```python
dict.get(key, default=None)
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `key` | 任意可哈希对象 | 要查找的键 |
| `default` | 任意类型 | 键不存在时返回的默认值，默认为 `None` |

**返回值**：

- 键存在 → 返回键对应的值
- 键不存在 → 返回 `default`（未传 `default` 时返回 `None`）

**关键特性**：`get` 是纯读取操作，不会在字典中创建或修改任何键值对。即使你传了 `default`，字典本身也不会多出这个键。

## 2. 核心内容

### 2.1 get 与中括号访问的本质区别

中括号 `dict[key]` 和 `get` 方法都能从字典中取值，但它们对"键不存在"这一情况的处理方式截然不同。

**中括号访问：暴力失败**

```python
config = {"host": "localhost", "port": 8080}

# 键存在：正常返回值
print(config["host"])

# 键不存在：直接抛出 KeyError
# print(config["debug"])  # KeyError: 'debug'
```

**get 方法：安静处理**

```python
config = {"host": "localhost", "port": 8080}

# 键存在：正常返回值
print(config.get("host"))

# 键不存在：返回 None，程序继续运行
print(config.get("debug"))
```

运行结果：

```text
localhost
None
```

两者对比如下：

| 维度 | `dict[key]` | `dict.get(key)` |
|------|-------------|-----------------|
| 键存在时 | 返回值 | 返回值 |
| 键不存在时 | 抛出 `KeyError` | 返回 `None` |
| 是否可指定默认值 | 不可以 | 可以（`default` 参数） |
| 是否修改字典 | 否 | 否 |
| 适用场景 | 确定键一定存在 | 键可能不存在，需要优雅处理 |
| 代码健壮性 | 低（需 try-except 保护） | 高（天然防 KeyError） |

**选择原则**：如果你100%确定键存在（比如刚创建的字典、循环中已确认的键），用中括号更直接；如果键可能不存在（比如用户输入、配置项、API 响应），用 `get` 更安全。

### 2.2 default 参数详解

`default` 是 `get` 方法的第二个参数，用于指定键不存在时的返回值。这个参数让 `get` 从"安静地返回 None"升级为"安静地返回你想要的值"。

#### 2.2.1 default 的基本行为

```python
product = {"name": "键盘", "price": 199}

# 键存在：default 被忽略
print(product.get("name", "未知商品"))

# 键不存在：返回 default
print(product.get("brand", "无品牌"))
print(product.get("stock", 0))
print(product.get("in_stock", True))
```

运行结果：

```text
键盘
无品牌
0
True
```

#### 2.2.2 default 可以是任意类型

`default` 不限于字符串或数字，可以是任意 Python 对象：

```python
user = {"name": "张三", "age": 28}

# 字符串默认值
print(user.get("email", "未填写"))

# 数字默认值
print(user.get("score", 0))

# 布尔默认值
print(user.get("is_vip", False))

# 列表默认值 —— 适合后续做追加操作
tags = user.get("tags", [])
print(tags)

# 字典默认值 —— 适合后续做嵌套取值
meta = user.get("metadata", {})
print(meta)

# None 作为默认值（与不传 default 等效，但语义更明确）
print(user.get("phone", None))
```

运行结果：

```text
未填写
0
False
[]
{}
None
```

#### 2.2.3 default 不会被写入字典

这是 `get` 方法的一个重要特性——`default` 只影响返回值，不会把键值对写入字典。

```python
product = {"name": "键盘"}

# 用 get 查询不存在的键，传入 default
brand = product.get("brand", "罗技")
print("返回值:", brand)

# 字典本身没有变化——brand 没有被写入
print("字典内容:", product)
print("brand 在字典中吗:", "brand" in product)
```

运行结果：

```text
返回值: 罗技
字典内容: {'name': '键盘'}
brand 在字典中吗: False
```

这与 `setdefault` 方法形成鲜明对比——`setdefault` 在键不存在时会把 default 写入字典。两者的区别会在后文详细对比。

#### 2.2.4 default 为可变对象的注意事项

当 `default` 是列表、字典等可变对象时，需要注意一个细节：每次调用 `get` 时传入的字面量都会创建一个新对象。

```python
data = {"a": 1}

# 每次传入的是不同的字面量 → 不同的对象
list1 = data.get("items", [])
list2 = data.get("items", [])
print("同一个对象吗:", list1 is list2)
```

运行结果：

```text
同一个对象吗: False
```

但如果你把同一个可变对象存到变量中，反复传入 `get`，那么多次调用会共享同一个引用：

```python
data = {"a": 1}
shared = []

list1 = data.get("items", shared)
list2 = data.get("items", shared)
print("传入同一引用:", list1 is list2)
```

运行结果：

```text
传入同一引用: True
```

实际编码中，直接传字面量（如 `[]`、`{}`）是最安全的做法，不会有共享引用的副作用。

### 2.3 get 方法在嵌套字典中的链式安全访问

实际开发中，你经常遇到多层嵌套的字典结构（如 API 响应、JSON 配置）。如果用中括号逐层访问，任何一层缺失都会导致 `KeyError`。用 `get` 配合空字典作为 `default`，可以构建一条安全的访问链。

#### 2.3.1 逐层 get 的基本模式

```python
# 模拟 API 响应：三层嵌套
response = {
    "status": "success",
    "data": {
        "user": {
            "name": "张三",
            "profile": {
                "age": 28,
                "city": "上海"
            }
        }
    }
}

# 危险写法：中间任何一层缺失都会 KeyError
# age = response["data"]["user"]["profile"]["age"]

# 安全写法：每层用 get 兜底，default 给空字典 {}
age = response.get("data", {}).get("user", {}).get("profile", {}).get("age")
print("用户年龄:", age)
```

运行结果：

```text
用户年龄: 28
```

**原理解析**：每一层 `get(key, {})` 的含义是"如果这一层不存在，就返回一个空字典，让后续的 `.get()` 调用可以继续执行而不会报错"。空字典上调用 `get` 方法返回 `None`，从而实现整个链路的"安全降级"。

用一个流程图来展示这条安全链的工作方式：

```text
response.get("data", {})
     │
     ├── data 存在 → 返回 data 字典
     │                │
     │                └── .get("user", {})
     │                       │
     │                       ├── user 存在 → 返回 user 字典
     │                       │                  │
     │                       │                  └── .get("profile", {})
     │                       │                                        │
     │                       │                                        ├── profile 存在 → 返回 profile 字典
     │                       │                                        │                         │
     │                       │                                        │                         └── .get("age") → 28
     │                       │                                        │
     │                       │                                        └── profile 不存在 → {} → .get("age") → None
     │                       │
     │                       └── user 不存在 → {} → .get("profile", {}) → {} → .get("age") → None
     │
     └── data 不存在 → {} → .get("user", {}) → {} → .get("profile", {}) → {} → .get("age") → None
```

#### 2.3.2 错误响应也能安全处理

```python
# 模拟一个缺失了 data 字段的错误响应
bad_response = {"status": "error", "message": "invalid token"}

# 即使 data 层完全缺失，整条链也不会报错
user_name = bad_response.get("data", {}).get("user", {}).get("name", "未知用户")
print("用户名:", user_name)
```

运行结果：

```text
用户名: 未知用户
```

#### 2.3.3 None 值的陷阱

链式 `get` 有一个陷阱：如果中间层的值不是字典而是 `None`，你无法在 `None` 上调用 `.get()`。

```python
raw = {"shipping": None}

# shipping 的值是 None，不能调用 None.get("address")
# None 没有 get 方法，会抛出 AttributeError
# address = raw.get("shipping", {}).get("address", "未填写")  # AttributeError!
```

正确处理方式是先判断中间值是否为 `None`：

```python
raw = {"shipping": None}

shipping = raw.get("shipping")
if shipping is None:
    address = "未填写收货地址"
else:
    address = shipping.get("address", "未填写收货地址")

print("收货地址:", address)
```

运行结果：

```text
收货地址: 未填写收货地址
```

或者封装一个通用的安全取值函数：

```python
def safe_get(data, *keys, default=None):
    """沿路径安全取值，任意一层不存在或为 None 就返回 default"""
    current = data
    for key in keys:
        if isinstance(current, dict):
            current = current.get(key)
        else:
            return default
        if current is None:
            return default
    return current if current is not None else default

# 使用
config = {"server": {"host": "0.0.0.0", "port": 3000}}
print(safe_get(config, "server", "host"))
print(safe_get(config, "server", "pool", "max_size", default=10))
print(safe_get(config, "cache", "host", default="localhost"))
```

运行结果：

```text
0.0.0.0
10
localhost
```

### 2.4 get 方法实战场景

#### 2.4.1 场景：配置读取与默认值兜底

在应用开发中，配置通常分为"默认配置"和"用户配置"两部分。用户配置覆盖默认值，未覆盖的使用默认值。`get` 方法非常适合这个场景。

```python
DEFAULT_CONFIG = {
    "host": "127.0.0.1",
    "port": 8080,
    "debug": False,
    "max_connections": 100,
    "timeout": 30,
}

# 用户只覆盖了部分字段
user_config = {
    "host": "0.0.0.0",
    "port": 3000,
    "debug": True,
}

# 合并配置：用户配置存在就取用户的，否则取默认值
final_config = {
    key: user_config.get(key, DEFAULT_CONFIG[key])
    for key in DEFAULT_CONFIG
}

for k, v in final_config.items():
    print(f"  {k}: {v}")
```

运行结果：

```text
  host: 0.0.0.0
  port: 3000
  debug: True
  max_connections: 100
  timeout: 30
```

**解读**：`user_config.get(key, DEFAULT_CONFIG[key])` 的含义是——在用户配置中查找 `key`，找到就用用户的值，找不到就用默认值。这种写法一行搞定配置合并，比 `if-else` 判断简洁得多。

#### 2.4.2 场景：词频统计（计数）

统计列表中每个元素出现的次数，是 `get` 方法最经典的用法之一。

传统写法需要 `if-else` 判断：

```python
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]

count = {}
for word in words:
    if word in count:
        count[word] += 1
    else:
        count[word] = 1

print(count)
```

运行结果：

```text
{'apple': 3, 'banana': 2, 'cherry': 1}
```

用 `get` 简化后：

```python
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]

count = {}
for word in words:
    count[word] = count.get(word, 0) + 1

print(count)
```

运行结果：

```text
{'apple': 3, 'banana': 2, 'cherry': 1}
```

**关键点**：`count.get(word, 0) + 1` 这一行做了两件事——如果 `word` 不在字典中，`get` 返回 `0`，加 `1` 后赋值进去，完成初始化；如果 `word` 已在字典中，`get` 返回已有计数，加 `1` 后更新。一行代码替代了原来的 `if-else` 四行逻辑。

#### 2.4.3 场景：分组聚合

将一批数据按某个字段分组，也是 `get` 方法的拿手好戏。

```python
students = [
    {"name": "张三", "grade": "一班"},
    {"name": "李四", "grade": "二班"},
    {"name": "王五", "grade": "一班"},
    {"name": "赵六", "grade": "三班"},
]

groups = {}
for s in students:
    grade = s["grade"]
    groups[grade] = groups.get(grade, [])
    groups[grade].append(s["name"])

for grade, names in groups.items():
    print(f"  {grade}: {names}")
```

运行结果：

```text
  一班: ['张三', '王五']
  二班: ['李四']
  三班: ['赵六']
```

**解读**：`groups.get(grade, [])` 确保即使遇到新的班级名，也能拿到一个空列表来 `append`。注意这里需要先把 `get` 的结果赋值回字典，因为 `get` 不会自动写入。

#### 2.4.4 场景：缓存查找

在缓存系统中，`get` 方法可以优雅地处理缓存未命中的情况。

```python
cache = {
    "user:1001": {"name": "张三", "age": 28},
    "user:1002": {"name": "李四", "age": 32},
}

def get_user(user_id):
    cache_key = f"user:{user_id}"
    # 缓存未命中时返回默认结构，而非 None
    return cache.get(cache_key, {"name": "unknown", "age": 0})

# 缓存命中
print(get_user(1001))
# 缓存未命中 —— 返回默认结构，调用方可以直接使用
print(get_user(9999))
```

运行结果：

```text
{'name': '张三', 'age': 28}
{'name': 'unknown', 'age': 0}
```

**关键点**：这里把 `default` 设为一个字典而非 `None`，这样调用方拿到结果后可以直接访问 `result["name"]` 和 `result["age"]`，不需要额外做 `None` 判断。

#### 2.4.5 场景：环境变量读取

读取环境变量时，通常要为未设置的变量提供默认值。`os.environ` 是一个类字典对象，同样支持 `get` 方法。

```python
# 模拟 os.environ（实际开发中用 os.environ）
env = {
    "APP_NAME": "myapp",
    "APP_PORT": "8080",
    "APP_DEBUG": "true",
}

APP_NAME = env.get("APP_NAME", "default_app")
APP_PORT = int(env.get("APP_PORT", "3000"))
APP_DEBUG = env.get("APP_DEBUG", "false").lower() == "true"
APP_HOST = env.get("APP_HOST", "localhost")

print(f"应用名: {APP_NAME}")
print(f"端口: {APP_PORT}")
print(f"调试模式: {APP_DEBUG}")
print(f"主机: {APP_HOST}")
```

运行结果：

```text
应用名: myapp
端口: 8080
调试模式: True
主机: localhost
```

### 2.5 get 与 setdefault 的对比

`get` 和 `setdefault` 都能在键不存在时返回默认值，但核心区别在于：`get` 只读不改，`setdefault` 既读又写。

#### 2.5.1 行为对比

```python
user = {"name": "张三", "age": 28}

# --- get 方式：只读 ---
email_get = user.get("email", "未填写")
print("get 返回:", email_get)
print("get 后字典:", user)
print("email 是否已写入:", "email" in user)

print("-" * 30)

# --- setdefault 方式：读写 ---
user2 = {"name": "张三", "age": 28}
email_sd = user2.setdefault("email", "未填写")
print("setdefault 返回:", email_sd)
print("setdefault 后字典:", user2)
print("email 是否已写入:", "email" in user2)
```

运行结果：

```text
get 返回: 未填写
get 后字典: {'name': '张三', 'age': 28}
email 是否已写入: False
------------------------------
setdefault 返回: 未填写
setdefault 后字典: {'name': '张三', 'age': 28, 'email': '未填写'}
email 是否已写入: True
```

**核心差异表**：

| 维度 | `dict.get(key, default)` | `dict.setdefault(key, default)` |
|------|--------------------------|--------------------------------|
| 键存在时 | 返回值（不修改字典） | 返回值（不修改字典） |
| 键不存在时 | 返回 default（不修改字典） | 返回 default **并写入字典** |
| 是否修改字典 | 否 | 是（仅在键不存在时写入） |
| 返回值含义 | 键的值或默认值 | 键的值或默认值 |
| 字典状态 | 不变 | 可能新增键值对 |

#### 2.5.2 计数场景对比

```python
words = ["apple", "banana", "apple", "cherry", "banana", "apple"]

# 方式一：用 get 计数
count_get = {}
for word in words:
    count_get[word] = count_get.get(word, 0) + 1

# 方式二：用 setdefault 计数
count_sd = {}
for word in words:
    count_sd[word] = count_sd.setdefault(word, 0) + 1

print("get 结果:", count_get)
print("setdefault 结果:", count_sd)
```

运行结果：

```text
get 结果: {'apple': 3, 'banana': 2, 'cherry': 1}
setdefault 结果: {'apple': 3, 'banana': 2, 'cherry': 1}
```

两种方式结果一样。但在计数场景中，`setdefault` 略有性能优势——`get` 方式做了两次字典查找（`get` 一次 + 赋值一次），而 `setdefault` 只做一次查找（`setdefault` 一次 + 赋值一次，但写入操作发生在 `setdefault` 内部）。

#### 2.5.3 分组场景对比

```python
students = [
    {"name": "张三", "grade": "一班"},
    {"name": "李四", "grade": "二班"},
    {"name": "王五", "grade": "一班"},
]

# 方式一：用 get 分组（需要两行）
groups_get = {}
for s in students:
    grade = s["grade"]
    groups_get[grade] = groups_get.get(grade, [])
    groups_get[grade].append(s["name"])

# 方式二：用 setdefault 分组（一行搞定）
groups_sd = {}
for s in students:
    grade = s["grade"]
    groups_sd.setdefault(grade, []).append(s["name"])
```

在这个场景中 `setdefault` 更简洁——一行代码完成"获取列表或初始化空列表 + 追加元素"。

#### 2.5.4 什么时候该用哪个

**用 `get` 的场景**：

- 只需要读取，不希望修改字典
- 需要给调用方返回默认值，但不想改变字典状态
- 嵌套字典的链式安全访问（`{}.get(key, {}).get(key2)`）

**用 `setdefault` 的场景**：

- 需要在键不存在时自动初始化并保留
- 计数、分组等需要写入字典的场景
- 确保后续访问同一个键时不需要再初始化

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法

**推荐：用 get 代替 try-except 处理 KeyError**

```python
# 不推荐：用 try-except 包裹中括号访问
config = {"host": "localhost"}
try:
    port = config["port"]
except KeyError:
    port = 8080

# 推荐：用 get 一行搞定
port = config.get("port", 8080)
```

**推荐：default 值要匹配业务语义**

```python
# 不推荐：默认值 None，调用方还需要判断 None
score = student.get("score", None)
if score is not None:
    grade = calculate_grade(score)
else:
    grade = "未参加考试"

# 推荐：默认值直接给业务合理的值
score = student.get("score", 0)
grade = calculate_grade(score)
```

**推荐：嵌套字典用空字典 default 链式访问**

```python
# 不推荐：多层 if 判断
data = {"user": {"name": "张三"}}
if "user" in data:
    if "name" in data["user"]:
        name = data["user"]["name"]
    else:
        name = "未知"
else:
    name = "未知"

# 推荐：链式 get
name = data.get("user", {}).get("name", "未知")
```

**推荐：计数和分组场景选择合适的工具**

```python
# 不推荐：计数用 collections.defaultdict 大材小用（简单场景）
from collections import defaultdict
count = defaultdict(int)
for word in words:
    count[word] += 1

# 推荐：简单场景用 get 一行解决
count = {}
for word in words:
    count[word] = count.get(word, 0) + 1

# 但如果逻辑复杂，defaultdict 确实更优雅
# 选择取决于团队风格和代码可读性偏好
```

### 3.2 常见错误模式

**错误一：忘记 get 只读不改**

```python
# 误以为 get 会把默认值写入字典
config = {"host": "localhost"}
config.get("port", 8080)
# 以为 config 现在有 port 了 → 实际上没有
print("port" in config)  # False

# 修正：需要写入就用 setdefault 或直接赋值
config["port"] = config.get("port", 8080)  # 显式赋值
```

**错误二：在 None 上调用 get**

```python
data = {"shipping": None}

# 错误：shipping 的值是 None，不能调用 None.get()
# address = data.get("shipping", {}).get("address")
# AttributeError: 'NoneType' object has no attribute 'get'

# 修正：先判断是否为 None
shipping = data.get("shipping")
if shipping is not None:
    address = shipping.get("address", "未填写")
else:
    address = "未填写"
```

**错误三：用 get 做存在性判断**

```python
# 不推荐：用 get 判断键是否存在（当值本身可能是 None 时有歧义）
d = {"key": None}
if d.get("key"):  # None 是 falsy，但这不代表键不存在
    print("键存在")

# 推荐：用 in 判断键是否存在
if "key" in d:
    print("键确实存在")  # 正确输出

# 如果需要同时判断"键存在且值非 None"
if d.get("key") is not None:
    print("键存在且值不为 None")
```

### 3.3 性能考量

`get` 方法在性能上与中括号访问几乎相当，因为底层都是哈希查找。在有默认值的场景下，`get` 比中括号 + `try-except` 更快，因为异常处理本身有开销。

对于计数场景的微基准测试：

```python
import timeit

def use_get():
    d = {}
    for i in range(100):
        d[f"key_{i}"] = d.get(f"key_{i}", 0) + 1

def use_in():
    d = {}
    for i in range(100):
        key = f"key_{i}"
        if key in d:
            d[key] += 1
        else:
            d[key] = 1

def use_setdefault():
    d = {}
    for i in range(100):
        key = f"key_{i}"
        d[key] = d.setdefault(key, 0) + 1

print(f"get:        {timeit.timeit(use_get, number=10000):.4f}s")
print(f"if-in:      {timeit.timeit(use_in, number=10000):.4f}s")
print(f"setdefault: {timeit.timeit(use_setdefault, number=10000):.4f}s")
```

典型运行结果：

```text
get:        0.1687s
if-in:      0.0948s
setdefault: 0.1031s
```

`get` 方式略慢于 `if-in` 和 `setdefault`，因为 `get` 做了两次字典查找（`get` 查找一次 + 赋值时再查找一次）。但差异在微秒级别，在绝大多数场景中可以忽略。选择写法时应优先考虑可读性，而非这点微小的性能差异。

## 4. 原理

### 4.1 为什么需要 get 方法

字典的核心能力是通过键快速查找值，底层使用哈希表实现。当你用 `dict[key]` 访问时，Python 的哈希查找逻辑是：

1. 计算 `key` 的哈希值
2. 根据哈希值定位到哈希表中的槽位
3. 如果槽位为空或键不匹配 → 抛出 `KeyError`
4. 如果键匹配 → 返回对应的值

`get` 方法在步骤 3 做了不同处理：槽位为空或键不匹配时，不抛异常，而是返回 `default` 参数的值（默认 `None`）。

用流程图表示两种路径的差异：

```text
dict[key] 的查找路径:
    计算 key 的哈希值
        ↓
    定位哈希表槽位
        ↓
    槽位匹配吗?
        ├── 是 → 返回值
        └── 否 → 抛出 KeyError ← 程序中断

dict.get(key, default) 的查找路径:
    计算 key 的哈希值
        ↓
    定位哈希表槽位
        ↓
    槽位匹配吗?
        ├── 是 → 返回值
        └── 否 → 返回 default ← 程序继续
```

### 4.2 get 的只读特性

`get` 是一个纯读取操作——它只查找哈希表，不会修改哈希表的结构。这意味着：

- 不会新增键值对
- 不会修改已有键的值
- 不会触发字典的扩容（resize）操作

这与 `setdefault` 不同。`setdefault` 在键不存在时需要进行写入操作（在哈希表中插入新的键值对），可能触发哈希表扩容。因此，当你只需要读取时，`get` 是更轻量的选择。

### 4.3 CPython 中的实现

在 CPython 源码中，`dict.get` 的实现核心逻辑（简化版 C 伪代码）如下：

```python
# 伪代码，展示核心逻辑
def dict_get(self, key, default=None):
    # 1. 计算哈希值
    hash_value = hash(key)
    # 2. 在哈希表中查找
    entry = self._lookup(key, hash_value)
    # 3. 找到了就返回值，找不到就返回 default
    if entry is FOUND:
        return entry.value
    else:
        return default
```

注意 `setdefault` 的实现则多了一步：

```python
# 伪代码
def dict_setdefault(self, key, default=None):
    hash_value = hash(key)
    entry = self._lookup(key, hash_value)
    if entry is FOUND:
        return entry.value
    else:
        # 额外步骤：把 default 写入哈希表
        self._insert(key, hash_value, default)
        return default
```

`_insert` 操作可能触发哈希表扩容（当装填因子超过阈值 2/3 时），这是 `setdefault` 在某些场景下比 `get` 稍慢的原因之一。

## 5. 总结

本文围绕字典的 `get` 方法与默认值机制展开，主要介绍了以下内容：

- `get` 方法是字典的安全访问方式，键不存在时返回 `None` 或指定的 `default`，不抛出 `KeyError`
- `default` 参数可以是任意类型，但不会被写入字典——`get` 是纯读取操作
- 嵌套字典场景下，用 `get(key, {})` 链式调用可以安全地逐层访问，避免任何一层缺失导致的异常
- `get` 在实战中有广泛应用：配置合并、词频统计、分组聚合、缓存查找、环境变量读取
- `get` 与 `setdefault` 的核心区别：`get` 只读不改，`setdefault` 读写一体——根据是否需要写入字典来选择
- 在性能层面，`get` 与中括号访问的哈希查找开销相当，`if-in` 方式在计数场景略快，但差异在微秒级，可读性应优先于微优化
- `get` 的底层实现是哈希查找 + 默认值返回，不涉及写入操作，因此比 `setdefault` 更轻量
