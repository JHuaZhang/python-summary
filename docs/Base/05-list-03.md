## 1. 介绍

### 1.1 什么是 append 与 extend

`append` 和 `extend` 是列表(`list`)最常用的两个"追加元素"方法,都用于在列表**末尾**添加内容,但二者处理的"单位"完全不同:

- **`append(x)`**:把 `x` **作为一个整体**追加到列表末尾。无论 `x` 是数字、字符串、元组还是另一个列表,它都只占**一个位置**。
- **`extend(iterable)`**:把可迭代对象 `iterable` 里的**每一个元素**逐一追加到列表末尾,每个元素各占**一个位置**。

```python
# 同样是往空列表里加 [4, 5, 6]
a = [1, 2, 3]
a.append([4, 5, 6])
print(a)            # [1, 2, 3, [4, 5, 6]]   —— 列表变成了 4 个元素,最后一项是嵌套列表

b = [1, 2, 3]
b.extend([4, 5, 6])
print(b)            # [1, 2, 3, 4, 5, 6]     —— 列表变成了 6 个元素,逐个展开
```

这是初学者最容易混淆的点:`append` "加一个东西",`extend` "加一堆东西进去并摊平"。搞错一个,列表的多维结构就会出现意料外的嵌套或扁平。

两个方法都**原地修改**原列表,返回值都是 `None`(不返回新列表)。这也是与 `+`、切片等"产生新对象"操作的本质区别。本篇系统讲解 `append` 与 `extend` 的语义、参数要求、返回值、性能差异、常见误用与陷阱,并在末尾给出完整的选型指南。

### 1.2 基本语法与最小用法

**`append` 的签名**:`list.append(x)` —— 接收**任意单个对象** `x`,把它整体塞到末尾。

```python
nums = [1, 2, 3]
nums.append(4)
print(nums)         # [1, 2, 3, 4]

# 返回值是 None,不是新列表
result = nums.append(5)
print(result)       # None
print(nums)         # [1, 2, 3, 4, 5]
```

**`extend` 的签名**:`list.extend(iterable)` —— 接收**可迭代对象**,逐个取出元素追加。

```python
nums = [1, 2, 3]
nums.extend([4, 5])
print(nums)         # [1, 2, 3, 4, 5]

# 右侧可以是任意可迭代对象,不限于列表
nums.extend((6, 7))
print(nums)         # [1, 2, 3, 4, 5, 6, 7]

nums.extend("ab")
print(nums)         # [1, 2, 3, 4, 5, 6, 7, 'a', 'b'] —— 字符串被拆成字符
```

注意 `extend("ab")` 把字符串当成字符序列展平,这是 `extend` "可迭代协议"的直接体现,也是常见误用点(本篇 2.3 节详述)。

**一句话区分**:

| 方法 | 参数类型 | 追加方式 | 返回值 | 原列表长度变化 |
|------|---------|---------|--------|--------------|
| `append` | 任意对象(单个) | 作为一个元素 | `None` | +1 |
| `extend` | 可迭代对象 | 逐个元素摊平 | `None` | +len(iterable) |

### 1.3 为什么 `append` 和 `extend` 都返回 None

很多人第一次写 `nums = nums.append(4)` 后,发现 `nums` 变成了 `None`,大呼踩坑。这不是 bug,而是 Python 对**可变对象原地操作**的一致约定:

```python
# ❌ 经典错误:append 返回 None,赋值后丢失列表
nums = [1, 2, 3]
nums = nums.append(4)
print(nums)         # None

# ✅ 正确:append 原地改 nums,无需重新赋值
nums = [1, 2, 3]
nums.append(4)
print(nums)         # [1, 2, 3, 4]
```

设计哲学是:**原地修改的方法不返回被修改的对象**,以避免误导调用者以为产生了新对象。这样你就无法把"原地改"和"产生新对象"两种风格混用而浑然不觉。Python 标准库里很多可变对象方法(`list.append`、`list.sort`、`dict.update`、`set.add`)都遵循此约定。

对比产生新对象的操作:

```python
# + 产生新列表,可以重新赋值
a = [1, 2]
b = a + [3, 4]      # b 是新列表,a 不变
print(a, b)         # [1, 2] [1, 2, 3, 4]

# extend 原地改,无新对象
a = [1, 2]
a.extend([3, 4])    # a 被原地修改
print(a)            # [1, 2, 3, 4]
```

记住口诀:**返回 `None` 的方法是原地改,产生新对象的方法有返回值**。看到 `list`/`dict`/`set` 的增删方法返回 `None`,就知道它在改自己。

### 1.4 append 与 extend 在工程中的地位

`append` 是列表"逐个累积"的标准动作——从空列表起步,循环里 `append` 收集结果,是 Python 代码最高频的模式之一。`extend` 则用于"批量并入"——合并两个列表、把一段数据集中追加,是批量场景的高效写法。

```python
# 经典模式:循环里用 append 逐个收集
squares = []
for x in range(5):
    squares.append(x * x)           # 逐个累积
print(squares)                      # [0, 1, 4, 9, 16]

# 经典模式:用 extend 批量并入
existing = load_user_ids()           # 已有的用户 id
new_batch = fetch_new_batch()        # 新一批
existing.extend(new_batch)           # 一次性并入,而非循环 append
```

选错方法会导致两类问题:用 `append` 加一个列表会产生意外的嵌套结构;用 `extend` 加一个不可迭代对象会抛 `TypeError`。本篇后续逐一展开这些边界与陷阱。

## 2. 核心内容

本章逐个详解 `append`、`extend` 的参数语义、与等价操作(`+=`、`+`)的关系、边界行为、性能,并给出完整的选型对照。每节遵循"文字详解 → demo → 运行结果说明 → 陷阱"。

### 2.1 `append(x)`:把任意对象整体追加

`append` 的参数 `x` 没有"可迭代"要求——它接收任意类型的单个对象,把这个对象的引用写到列表末尾的新槽位。列表长度恒定增加 1。

```python
lst = [1, 2, 3]

# 追加各种类型的单个对象
lst.append(4)               # 整数
lst.append("hello")         # 字符串(整个字符串是一个元素)
lst.append((5, 6))          # 元组(整个元组是一个元素)
lst.append([7, 8])          # 列表(整个列表作为一个元素)
lst.append({"x": 1})        # 字典作为一个元素
lst.append(None)            # None 也是一个元素
print(lst)
# [1, 2, 3, 4, 'hello', (5, 6), [7, 8], {'x': 1}, None]
print(len(lst))             # 9 —— 每次 append 长度 +1
```

关键观察:即便 `x` 本身是列表 `[7, 8]`,`append` 也把它当作**一个整体元素**塞进去,列表内部多出一个嵌套层级。这与 `extend` 摊平列表的行为形成鲜明对比。

**用 `append` 构建嵌套结构**:

```python
# 构建二维矩阵:每行作为整体 append
matrix = []
matrix.append([1, 2, 3])
matrix.append([4, 5, 6])
matrix.append([7, 8, 9])
print(matrix)              # [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
```

这里**必须**用 `append`,因为你想让每一行作为一个子列表存在,形成二维结构。若误用 `extend`,所有数字会被摊平成 `[1,2,3,4,5,6,7,8,9]`,矩阵就被压扁了。

**`append` 追加的是引用,不是拷贝**:若 `x` 是可变对象,追加后列表里持有的是指向该对象的引用,后续修改 `x` 会影响列表:

```python
row = [0, 0]
matrix2 = []
matrix2.append(row)        # 追加的是 row 的引用
row[0] = 99                # 改 row,列表内的元素也变
print(matrix2)             # [[99, 0]]

# 仍是同一个对象
print(matrix2[0] is row)   # True
```

要避免这种"一改全改",追加前先拷贝:`matrix2.append(row.copy())` 或 `matrix2.append(row[:])`。这是可变对象引用导致的经典陷阱,详见《浅拷贝与深拷贝实战》。

### 2.2 `extend(iterable)`:把可迭代对象逐个摊平追加

`extend` 要求参数是**可迭代对象**,它会调用 `iter(iterable)` 取出每个元素,依次追加到列表末尾。长度增加 `len(iterable)`(对有长度的可迭代对象)。

```python
lst = [1, 2, 3]

# 右侧是列表:逐个并入
lst.extend([4, 5])          # 长度 +2
print(lst)                  # [1, 2, 3, 4, 5]

# 右侧是元组:同样摊平
lst.extend((6, 7))
print(lst)                  # [1, 2, 3, 4, 5, 6, 7]

# 右侧是集合:顺序不保证
lst.extend({9, 8})
print(lst)                  # [1, 2, 3, 4, 5, 6, 7, 8, 9](顺序可能为 9,8)

# 右侧是 range
lst.extend(range(10, 12))
print(lst)                  # [..., 10, 11]

# 右侧是生成器表达式:惰性计算后展开为元素
lst.extend(x * 10 for x in [1, 2])
print(lst)                  # [..., 10, 20]
```

`extend` 的灵活性来自可迭代协议——任何实现 `__iter__` 的对象都能作参数。这也是它比"只能接收列表"的方法更通用的原因。

**用 `extend` 合并列表**:

```python
base = [1, 2, 3]
incoming = [4, 5, 6]
base.extend(incoming)
print(base)                 # [1, 2, 3, 4, 5, 6]
print(incoming)             # [4, 5, 6] —— incoming 不变,extend 读取它
```

`extend` 只**读取**右侧可迭代对象,不会修改它。合并后 `incoming` 仍是原来的样子——它是被"摊平复制"进 `base`,而非被"移走"。

**`extend` 是原地修改,无新对象**:

```python
a = [1, 2]
old_id = id(a)
a.extend([3, 4])
print(id(a) == old_id)      # True —— 仍是同一个列表对象
```

这与 `a = a + [3, 4]`(产生新对象、`id` 变化)不同,是省内存的关键。

### 2.3 `extend` 的可迭代协议陷阱:字符串与字典

`extend` 对**可迭代对象**逐个取出元素。但"可迭代"对某些类型意味着与直觉不同的拆分方式,最容易踩坑的是字符串和字典。

**字符串被拆成字符**:

```python
# 看似想把 "abc" 作为一个整体追加
accounts = ["alice"]
accounts.extend("bob")
print(accounts)             # ['alice', 'b', 'o', 'b'] —— 不是 ['alice', 'bob']!
```

`"bob"` 是可迭代对象,`extend` 把它拆成 `'b'`、`'o'`、`'b'` 三个字符依次追加。如果想把 `"bob"` 作为一个元素,应该用 `append`:

```python
accounts = ["alice"]
accounts.append("bob")      # ['alice', 'bob']
```

**判断标准**:你要的是"把整个对象当作一个元素" → `append`;你要的是"把对象内部元素逐个摊平" → `extend`。对字符串,绝大多数情况下你想加的是一个完整字符串,那就用 `append`。

**字典被拆成键**:

```python
data = [1, 2]
data.extend({"a": 10, "b": 20})
print(data)                 # [1, 2, 'a', 'b'] —— 摊平的是键,不是键值对
```

`extend(dict)` 等价于 `extend(dict.keys())`,只追加键。要追加键值对,需显式用 `dict.items()`:

```python
data = [1, 2]
data.extend({"a": 10, "b": 20}.items())
print(data)                 # [1, 2, ('a', 10), ('b', 20)]
```

**不可迭代对象会抛 `TypeError`**:

```python
lst = [1, 2]
try:
    lst.extend(5)           # 5 是 int,不可迭代
except TypeError as e:
    print(e)                # 'int' object is not iterable
```

`extend` 的参数必须可迭代。一个整数、一个 `None`、一个自定义不可迭代的对象,都不能直接 `extend`。这是 `extend` 与 `append`(可接收任意对象)的参数约束差异。

### 2.4 `extend` 与 `+=`、`+` 的等价关系

理解 `extend` 的一个好办法是把它与 `+`、`+=` 对比。三者都涉及"列表拼接",但语义有别:

```python
# + :产生新列表,不修改原列表
a = [1, 2]
b = a + [3, 4]              # b 是新列表
print(a, b)                 # [1, 2] [1, 2, 3, 4]

# += :对可变类型相当于 extend,原地修改
a = [1, 2]
a += [3, 4]                 # 原地扩展,等价于 a.extend([3,4])
print(a)                    # [1, 2, 3, 4]

# extend :原地修改,显式调用
a = [1, 2]
a.extend([3, 4])
print(a)                    # [1, 2, 3, 4]
```

**`+=` 与 `extend` 的微妙差异**:`list` 的 `+=` 底层走 `__iadd__`,对列表而言等价于 `extend`(原地扩展,接收任意可迭代对象)。但若类型不支持原地操作,`+=` 会回退到 `+`(产生新对象)。对列表,两者效果一致:

```python
a = [1, 2]
old = id(a)
a += [3]
print(id(a) == old)         # True —— 原地
print(a)                    # [1, 2, 3]

# 与 extend 完全等价
a = [1, 2]
a.extend([3])
print(a)                    # [1, 2, 3]
```

但 `a += [3]` 写法在循环里不如 `a.append(3)` 直观,且 `+=` 把"原地改"和隐式赋值混在一起,不如 `extend` 显式。社区习惯上:**批量追加用 `extend`,单个用 `append`,`+` 用于产生新列表**。

**`+` 要求两侧都是列表**:

```python
a = [1, 2]
a + [3]                     # OK
a + (3, 4)                  # TypeError: can only concatenate list (not "tuple") to list
```

`+` 严格要求两侧类型一致(都是 `list`),而 `extend`/`+=` 接收任意可迭代对象,更宽松。所以"把元组并进列表"必须用 `extend` 或 `+=`,不能用 `+`。

### 2.5 `append` 与 `extend` 的边界行为

**空列表的场景**:

```python
# extend 空可迭代对象:无操作,列表不变
a = [1, 2]
a.extend([])                # 什么都不加
print(a)                    # [1, 2]
print(len(a))               # 2

# append 空列表:加一个空列表元素
b = [1, 2]
b.append([])
print(b)                    # [1, 2, []]
print(len(b))               # 3
```

`extend([])` 是幂等的空操作,`append([])` 则真的多出一个空列表元素。当右侧来源可能为空时,`extend` 的"空操作"语义更安全——不会意外塞入多余元素。

**`extend` 与长度未知的可迭代对象**:`extend` 对没有 `__len__` 的可迭代对象(如生成器)也能工作,内部边迭代边追加:

```python
def gen():
    yield 1
    yield 2
    yield 3

lst = [0]
lst.extend(gen())
print(lst)                  # [0, 1, 2, 3]
```

对生成器,`extend` 会消耗它(迭代到 `StopIteration`)。生成器只能遍历一次,`extend` 后生成器即耗尽,再次使用为空。

**`append` 追加生成器对象本身**:

```python
lst = [0]
lst.append(gen)            # 追加的是函数对象,不是调用结果
print(lst)                  # [0, <function gen>]

lst.append(gen())          # 追加的是生成器对象本身(未展开)
print(lst)                  # [0, <function gen>, <generator>]
```

若想把生成器的**结果**摊平进列表,用 `extend(gen())`;若想把生成器对象本身存起来以后再说,用 `append`。这是 `append`/`extend` 在迭代器场景的核心选择。

### 2.6 性能对比:摊还 O(1) 与批量追加

`append` 和 `extend` 都是**原地修改**,底层都借助列表的"过度分配"容量(`allocated > ob_size`)实现高效追回。但二者的性能特征有细节差异。

**`append` 的摊还 O(1)**:

```python
import timeit

# 单次 append 很快
print(timeit.timeit('lst.append(1)', setup='lst=[]', number=1_000_000))
# 约 0.08 秒(在合理机器上),即约 80ns/次

# 即使容量偶尔翻倍,均摊下来仍接近 O(1)
lst = []
for i in range(1_000_000):
    lst.append(i)           # 总体快,偶尔触发扩容但不显著
```

每次 `append` 平摊到 O(1),因为只写一个槽位,容量不够时才扩容(扩容次数随总数对数级增长)。

**`extend` 的批量优势**:当要一次性追加很多元素时,`extend` 比循环 `append` 快得多,因为:

1. `extend` 一次性预估需要扩容的总量(若可迭代对象有 `__len__`),减少多次扩容。
2. 内部循环在 C 层完成,省去 Python 层 `append` 方法查找与调用的开销。

```python
import timeit

setup = 'lst=list(range(1000)); batch=list(range(1000))'

# extend 一次性追加 1000 个
print(timeit.timeit('lst.extend(batch)', setup=setup, number=10_000))
# 约 0.4 秒

# 循环 append 1000 个
code = '''
for x in batch:
    lst.append(x)
'''
print(timeit.timeit(code, setup=setup, number=10_000))
# 约 2.5 秒 —— 慢约 6 倍
```

结论:**批量追加用 `extend`,单个追加用 `append`**。循环里逐个 `append` 一个已知集合,应改写成一次 `extend`,性能提升数倍。

**无长度可迭代对象的 `extend` 退化为 append 般的多次扩容**:若右侧是生成器(无 `__len__`),`extend` 无法预估总量,只能边迭代边按需扩容,此时性能优势不如对 `list`/`tuple` 那样大,但仍比"先 list() 再 extend"两步走省一次分配:

```python
# 右侧有 len:可预估,一次扩容到位
lst.extend(other_list)

# 右侧无 len:边迭代边扩容,类似连续 append
lst.extend(gen_expr)
```

### 2.7 append 与 extend 选型全表

把前几节的关键差异集中对照,便于实战选型:

| 维度 | `append` | `extend` |
|------|---------|---------|
| 参数类型 | 任意单个对象 | 可迭代对象 |
| 参数约束 | 无(任何对象都行) | 必须可迭代,否则 `TypeError` |
| 追加结果 | +1 个元素(可能创建嵌套) | +len(iter) 个元素(摊平) |
| 返回值 | `None` | `None` |
| 是否原地 | 是 | 是 |
| 长度变化 | 恒 +1 | +len(iterable) |
| 空参数行为 | `append([])` 多一个空元素 | `extend([])` 空操作 |
| 字符串处理 | `"ab"` 作为整体元素 | `"ab"` 拆成 `'a'`、`'b'` |
| 典型用途 | 逐个累积、构建嵌套 | 批量并入、合并列表 |
| 性能(批量) | 循环 append 较慢 | 一次 extend 快数倍 |

**决策口诀**:

- 要"加一个东西"当整体 → `append`
- 要"加一堆东西"并摊平 → `extend`
- 不确定参数可不可迭代,或就是想存原始对象 → `append`
- 合并两个列表、把一段结果集并入 → `extend`

### 2.8 append/extend 与其他增删方法的协作

`append` 和 `extend` 只管"在末尾加"。列表还有其他位置的增删方法,理解各自定位有助于整体把握:

```python
lst = [1, 2, 3]

# 末尾加一个
lst.append(4)               # [1, 2, 3, 4]

# 指定位置插一个
lst.insert(0, 0)            # [0, 1, 2, 3, 4],insert 是 O(n)

# 末尾批量加
lst.extend([5, 6])          # [0, 1, 2, 3, 4, 5, 6]

# 末尾弹出一个(并返回它)
last = lst.pop()            # 6,lst 变 [0,1,2,3,4,5]
```

- `append` / `extend` 只操作**末尾**,复杂度最优(摊还 O(1))。
- `insert` 操作**任意位置**,需要搬移后续元素,是 O(n),慎用(尤其循环里 `insert(0, ...)`)。
- `pop()` 默认弹末尾,O(1);`pop(0)` 弹头部,O(n),频繁弹头应换 `collections.deque`。

详见《insert_pop_remove》《append与extend区别》(本篇)。

## 3. 最佳实践

### 3.1 记住 append 和 extend 的"单位"区别,避免意外嵌套/摊平

```python
# ❌ 错误:本想摊平,却用 append 产生嵌套
matrix = [1, 2]
matrix.append([3, 4])       # 结果 [1, 2, [3, 4]] —— 可能不是你要的

# ✅ 要摊平用 extend
matrix.extend([3, 4])       # [1, 2, 3, 4]
```

写代码前先问自己一句:"我要的是这一个对象作为一个元素,还是把它内部的元素散开?"——这一问就能挡住绝大多数 append/extend 误用。

### 3.2 不要把原地方法的返回值赋回变量

```python
# ❌ append 返回 None,这样写等于丢掉列表
items = [1, 2]
items = items.append(3)     # items = None

# ✅ 直接调用,不接收返回值
items = [1, 2]
items.append(3)             # items = [1, 2, 3]
```

同样适用于 `extend`、`insert`、`sort`、`reverse` 等"返回 None 的原地方法"。养成习惯:看到返回 `None` 的方法,绝不 `x = x.method()`。

### 3.3 批量追加用 extend,而非循环 append

```python
# ❌ 慢:循环里逐个 append
result = [0]
for x in source:
    result.append(x)        # 每次都走 Python 层方法调用

# ✅ 快:一次 extend
result = [0]
result.extend(source)       # C 层批量,快数倍
```

如果 `source` 已经是可迭代对象,`extend` 几乎总是更好的选择。只有当每个元素需要先经过复杂的 Python 层计算才能产生时,才退回 `append`(或者更推荐列表推导式)。

### 3.4 字符串、字典作整体追加时用 append,别误用 extend

```python
# ❌ 误用 extend:字符串被拆成字符
names = ["alice"]
names.extend("bob")         # ['alice', 'b', 'o', 'b']

# ✅ 加完整字符串用 append
names.append("bob")         # ['alice', 'bob']
```

字典同理——`extend(dict)` 只摊平键。想要完整键值对你得显式 `.items()`,想要字典作为整体元素你得 `append`。在"可迭代但直觉不符"的参数上,先想清楚可迭代协议会怎么拆。详见 2.3 节。

### 3.5 合并列表优先 extend 或 `+=`,不要用 `+` 反复产生新列表

```python
a = [1, 2]

# ❌ + 每次产生新列表,循环里累积是 O(n²)
for chunk in many_chunks:
    a = a + chunk           # 每次都复制整个 a,效率很差

# ✅ extend 原地扩展,累积是 O(n)
for chunk in many_chunks:
    a.extend(chunk)         # 只追加,不复制已有部分
```

`+` 适合"一次性合并两个产生新值"的场景;累积合并时反复用 `+` 会因反复复制而退化为平方复杂度。`extend` (`+=`) 原地操作,是累积合并的正解。

### 3.6 追加可变对象前考虑是否需要拷贝

```python
# ⚠️ 追加的是引用,后续修改会影响列表
row = [0, 0]
matrix = [row]              # matrix[0] is row
row[0] = 1
print(matrix)               # [[1, 0]]

# ✅ 需要独立副本,追加前拷贝
matrix = [row.copy()]       # 或 row[:]
row[0] = 1
print(matrix)               # [[0, 0]] —— 不受影响
```

`append` / `extend` 都不深拷贝元素,只复制引用。当来源是可变对象且后续会改动,而你又想让列表里的快照独立,就追加前先 `.copy()` / `[:]`(浅)或 `copy.deepcopy`(嵌套可变)。

### 3.7 处理"可能为空"的可迭代来源时,extend 更安全

```python
# extend 对空来源是空操作,不会多出元素
queue.extend(maybe_empty_list)     # maybe_empty_list 为 [] 时,queue 不变
```

如果改用 `append`,会把空列表本身作为一个元素塞进去(`append([])` → 长度 +1)。当来源由数据库查询、API 响应等动态产生、可能为空时,`extend` 的"空则不动"语义更符合"有就并入、没有就拉倒"的预期。

### 3.8 用列表推导式替代"循环里 append"的纯计算场景

```python
# ❌ 冗长:循环里 append 做纯转换
squares = []
for x in range(10):
    squares.append(x * x)

# ✅ 推导式:更 Pythonic,也更快
squares = [x * x for x in range(10)]
```

当循环体是"对每个元素计算一个值并 append",列表推导式几乎总是比 `append` 循环更清晰且更快。`append` 循环适合有副作用(I/O、复杂分支)或结果大小难预估的场景。详见《列表推导式》。

### 3.9 别用 `list.insert(0, x)` 模拟队列头插,改用 deque

```python
from collections import deque

# ❌ 列表头部插入/弹出是 O(n),大列表下严重退化
queue = []
for item in stream:
    queue.insert(0, item)   # 每次都搬移整个列表

# ✅ deque 双端 O(1)
queue = deque()
for item in stream:
    queue.appendleft(item)  # 头部 O(1)
```

`append`/`extend` 善长末尾操作;一旦频繁改头部,列表的结构(连续数组+搬移)就不再合适,应换 `collections.deque`。这是性能方面的关键取舍。

### 3.10 extend 迭代器后会耗尽它,重复使用要重新构造

```python
gen = (x for x in range(3))

lst = []
lst.extend(gen)             # [0, 1, 2],gen 被耗尽
print(list(gen))            # [] —— 已经空了

# 需要重复使用,定义成可重复构造的来源(列表/函数)
def make_gen():
    return (x for x in range(3))

lst.extend(make_gen())      # 第一份
lst.extend(make_gen())      # 第二份,各自独立
```

`extend` 对生成器是一次性消费。迭代器"只能走一遍"的特性在 `extend` 上表现得尤为明显:用完即空。若要多次使用同一序列来源,用 `list`/`tuple` 缓存,或用工厂函数重新构造。

## 4. 原理

### 4.1 列表的过度分配:为什么 append 是摊还 O(1)

回顾列表的内存结构:每个列表是一个 `PyListObject`,内部持有指向 `PyObject*` 数组的指针 `ob_item`,以及当前容量 `allocated` 和当前长度 `ob_size`。关键在于 `allocated >= ob_size`,且通常 `allocated` 大于 `ob_size`——这就是"过度分配"。

```c
// 简化示意
typedef struct {
    PyObject_VAR_HEAD
    PyObject **ob_item;     // 实际存放引用的数组
    Py_ssize_t allocated;   // 数组容量(槽位数)
} PyListObject;
// 约束:ob_size <= allocated,且通常 allocated > ob_size
```

`append` 时:

```c
void list_append(lst, x) {
    if (lst->ob_size < lst->allocated) {
        // 容量还够,直接写入新槽位
        lst->ob_item[lst->ob_size] = x;
        lst->ob_size++;
    } else {
        // 容量不够,扩容(按约 1.125 倍线性增长 + 一些常数项)
        new_cap = lst->allocated + (lst->allocated >> 3) + 3;
        realloc_ob_item_to(new_cap);
        lst->ob_item[lst->ob_size] = x;
        lst->ob_size++;
    }
}
```

绝大多数 `append` 走"容量够"分支,只做一次数组写入,O(1)。偶发的扩容走 `realloc`,把整个 `ob_item` 搬到更大的内存,这是 O(n),但发生频率随总数对数级递减。把扩容成本均摊到所有 `append` 上,每次仍是 O(1)——这就是"摊还 O(1)"。

过度分配是 `append`/`extend` 高效的根本:它用"预占一点空间"换取"追加时不频繁搬移",与 `list` 作为"动态数组"的定位一致。

### 4.2 extend 如何利用容量预估实现批量加速

`extend(iterable)` 追加多个元素时,若能提前知道要加多少个,就可以**一次性扩容到位**,避免追加过程中反复触发扩容:

```c
void list_extend(lst, iterable) {
    // 1. 尝试拿到长度(若 iterable 实现了 __len__)
    n = PyObject_Length(iterable);   // 对 list/tuple/range 可得具体值

    // 2. 预留容量:确保 allocated >= ob_size + n
    if (lst->allocated < lst->ob_size + n)
        realloc_to_fit(lst->ob_size + n);

    // 3. 逐个取出并写入,期间不再扩容
    it = iter(iterable);
    while ((item = next(it)) != 停止)
        lst->ob_item[lst->ob_size++] = item;
}
```

对有 `__len__` 的可迭代对象(`list`、`tuple`、`range`、`set`、`dict` 等),`extend` 能一次性分配好容量,内部循环在 C 层完成,没有 Python 层方法查找开销——这正是 `extend` 比循环 `append` 快数倍的两大原因:一次扩容 + C 层循环。

若无 `__len__`(如生成器),`extend` 无法预估,只能边迭代边按需扩容,退化为类似连续 `append` 的扩容模式,此时性能优势主要来自"仍在 C 层循环"。

### 4.3 为什么 append/extend 返回 None:原地操作的设计约定

CPython 中,`append` 和 `extend` 的 C 实现都返回 `Py_None`:

```c
// 简化示意
static PyObject *
list_append(PyListObject *self, PyObject *obj) {
    // 原地修改 self
    ...
    Py_RETURN_NONE;          // 返回 None,不返回 self
}
```

这不是性能或实现限制,而是明确的设计约定。Python 之禅(Peper 20)里"显式优于隐式"的体现:**原地修改的方法返回 `None`,让调用方无法把它和"返回新对象"的方法混用**。如果你写 `lst = lst.append(x)`,`lst` 就变 `None`,这个"惩罚"迫使你注意到 `append` 是原地操作。

对比返回新对象的方法:

```python
sorted(lst)        # 返回新列表,不原地改
lst + [1]          # 返回新列表
"abc".upper()      # 返回新字符串(字符串不可变,只能返回新的)
```

而原地改的:

```python
lst.append(1)      # 返回 None,原地改
lst.sort()         # 返回 None,原地改
lst.reverse()      # 返回 None,原地改
```

记住这条规则,就能一眼判断某个 `list` 方法是原地改(`返回 None`)还是产生新对象(`返回 list`)。`append`/`extend`/`insert`/`remove`/`pop`/`sort`/`reverse`/`clear`/`update` 都是前者。

### 4.4 `+=` 与 `extend` 的同一实现:`__iadd__`

`list` 的 `+=` 运算符由 `__iadd__` 实现,在内置 `list` 上,**`__iadd__` 与 `extend` 走的是同一段 C 代码**:

```c
// 简化示意
static PyObject *
list_inplace_concat(PyListObject *self, PyObject *other) {
    // 等价于 list_extend(self, other)
    list_extend(self, other);   // 原地扩展,接收任意可迭代对象
    Py_INCREF(self);
    return self;                // 返回原对象(id 不变)
}
```

所以 `a += [3, 4]` 和 `a.extend([3, 4])` 在 `list` 上完全等价:都是原地扩展、都接收任意可迭代对象、都保持 `id` 不变。这也解释了为什么 `a += (3, 4)`(元组)能工作——因为底层是 `extend`,接收任意可迭代对象,而 `a + (3, 4)` 会报错——因为 `+`(`__add__`)要求另一侧类型是 `list`。

```python
a = [1, 2]
a += (3, 4)                 # OK,等价 extend((3,4))
print(a)                    # [1, 2, 3, 4]

a + (5, 6)                  # ❌ TypeError,只能 list + list
```

字节码层面可验证 `+=` 原地性:

```python
import dis
dis.dis('a += [1]')
# INPLACE_ADD —— 对 list 走 __iadd__,原地
```

`INPLACE_ADD` 对可变类型调用 `__iadd__`(原地),对不可变类型(如 `int`、`tuple`)则回退到 `__add__`(产生新对象)。这就是为什么 `t = (1, 2); t += (3,)` 看似原地实则产生新元组,而 `[1, 2] += [3]` 真的原地。

### 4.5 extend 与可迭代协议的协作

`extend` 能接收任意可迭代对象,本质是依赖**可迭代协议**:对参数调用 `iter()` 拿到迭代器,循环调用 `next()` 直到收到 `StopIteration`。

```python
# extend 的概念性伪实现
def list_extend(self, iterable):
    iterator = iter(iterable)          # 调用 iterable.__iter__()
    while True:
        try:
            item = next(iterator)      # 调用 iterator.__next__()
            # 走 append 的 C 路径(预留容量后逐个写)
            self._append_one(item)
        except StopIteration:
            break                      # 迭代器耗尽,结束
```

任何实现了 `__iter__`(或旧式 `__getitem__`)的对象,都能被 `extend` 接收。这就是为什么:

- `list`、`tuple`、`range`、`set`、`frozenset`、`dict.keys()`、`dict.values()`、`dict.items()` 都行。
- 字符串、字节串也行(被按"字符/字节"维度拆开)。
- 生成器、迭代器、`map`/`filter` 对象等惰性序列也行(被逐个消耗)。
- `int`、`None`、自定义且无 `__iter__` 的对象不行,抛 `TypeError`。

理解了可迭代协议,就能预判 `extend` 对任何参数会怎么拆——拆开到"迭代器 `next()` 拿到的每一项"那一层。字符串的"项"是字符、字典的"项"是键,这些都由各类型的 `__iter__` 决定,而非 `extend` 自己挑。详见《列表创建方式》原理章对可迭代协议的介绍。

### 4.6 append 与 extend 的内存影响对比

两者都原地修改,但新元素如何安置有区别,影响内存增长模式:

- **`append(x)`**:增加 1 个槽位(若触发扩容则批量增加)。槽位里存的是 `x` 的引用,无论 `x` 本身多大,列表只多一个指针大小的开销。
- **`extend(iter)`**:增加 `len(iter)` 个槽位。每个槽位存对应元素的引用。

```python
# append 一个大数据结构:列表只多一个指针
big = [0] * 1_000_000          # 100 万个元素的大列表
container = []
container.append(big)          # container 长度 1,内部持有 big 的引用
# container 本身占 1 个槽位,大列表仍是 big 那一份

# extend 一个大数据结构:列表要复制全部引用
container2 = []
container2.extend(big)         # container2 长度 100 万,持有 100 万个引用
# container2 多出 100 万个槽位,但元素仍是共享的(浅)
```

内存上 `append` "轻"、`extend` "重"——前者只加一个引用,后者按元素数加引用数组。但两者都是**浅**的:元素对象本身不被复制,只存引用。因此用 `extend` 合并大列表时,内存增长的是"引用数组"那部分,而非元素对象本身。

这也是 `extend` 比先 `list(other)` 再 `+` 更省内存的原因:`extend` 直接扩容原列表的引用数组,`+` 则要新建一个列表并复制两侧全部引用。原地 vs 新对象,内存代价差异明显。

## 5. 总结

### 5.1 本文内容回顾

- **核心区别**:`append(x)` 把 `x` 作为一个整体元素追加,长度 +1;`extend(iterable)` 把可迭代对象内的元素逐个摊平追加,长度 +len(iter)。这是二者最根本、也最常被混淆的语义差异。

- **返回值与原地性**:两者都返回 `None`,都原地修改原列表(`id` 不变),不产生新对象。这是 Python"原地方法返回 None"约定的一部分,也提醒不要写 `lst = lst.append(...)`。

- **参数约束**:`append` 接收任意对象;`extend` 要求可迭代对象,否则 `TypeError`。字符串会被 `extend` 拆成字符、字典只摊平键,这两类是常见误用点;不可迭代对象(如 `int`、`None`)不能 `extend`。

- **与 `+` / `+=` 的关系**:`+` 产生新列表、要求两侧都是 `list`;`+=` 对 `list` 等价于 `extend`(原地、接收任意可迭代);`extend` 原地且不返回。累积合并优先 `extend`/`+=`,避免反复 `+` 退化为 O(n²)。

- **边界行为**:`extend([])` 是空操作、`append([])` 多一个空元素;`extend` 消耗生成器(一次性)、`append` 可存放生成器对象本身;`extend` 对无 `__len__` 的可迭代无法预估容量。

- **性能**:`append` 摊还 O(1)(依赖过度分配);批量追加 `extend` 比循环 `append` 快数倍(一次预估扩容 + C 层循环)。举单个用 `append`、批量用 `extend`。

- **内存**:两者都是浅的(只复制引用,不复制元素对象);`append` 加一个引用,`extend` 加 len 个引用。追加可变对象前需先拷贝才能保证独立。

- **原理**:过度分配(`allocated > ob_size`)让 `append`/`extend` 摊还高效;`extend` 借 `__len__` 一次扩容到位;`__iadd__` 与 `extend` 同实现;`extend` 依赖可迭代协议决定如何拆解参数;返回 None 是设计约定而非实现限制。

### 5.2 读完本文你应能掌握

- 一句话讲清 `append` 与 `extend` 的区别,并能根据"加一个整体还是摊平一堆"正确选用。

- 解释为什么 `append([3,4])` 产生嵌套而 `extend([3,4])` 产生扁平结果,并能修复因此导致的列表结构错误。

- 说明 `append`/`extend` 返回 `None` 的设计原因,并避免 `lst = lst.append(...)` 这类丢失列表的错误。

- 预判 `extend` 对字符串、字典、生成器、`int` 等不同参数的行为,识别哪些会"拆得不符合直觉"、哪些会抛 `TypeError`。

- 对比 `extend`、`+=`、`+` 三者在原地性、参数类型约束、内存上的差异,并在累积合并场景选用 `extend`/`+=` 而非反复 `+`。

- 说明 `append` 摊还 O(1) 与 `extend` 批量加速的底层原因(过度分配、容量预估、C 层循环),并用 `timeit` 验证批量场景下 `extend` 明显更快。

- 解释可迭代协议如何决定 `extend` 的拆解行为,据此推断对任意可迭代对象的展开结果。

- 识别追加可变对象的引用陷阱,知道何时需在追加前 `.copy()` / `deepcopy`。
