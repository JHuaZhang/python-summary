# 集合的添加操作

> 本篇属于 Python 数据类型体系中"集合类型"的实操方法篇，聚焦「如何向集合中添加元素」这一核心问题，覆盖 `add()` 和 `update()` 两大方法的完整用法、参数细节、去重行为、不可哈希元素报错处理以及综合实战场景。

## 1. 介绍

### 1.1 集合添加操作是什么

集合（set）是 Python 中一种可变容器类型。所谓"添加操作"，就是在集合创建之后，向其中插入新的元素。这与创建集合时一次性写入所有元素不同——添加操作是动态的、运行时进行的。

集合添加操作在日常开发中非常常见。比如：你有一个用户标签集合，用户每次新建标签都要往集合里加；你有一个权限集合，需要从多个来源合并权限；你有一批采集到的数据，需要逐条加入集合去重。这些场景都需要用到集合的添加方法。

Python 的 `set` 类型提供了两个核心的添加方法：

| 方法 | 签名 | 作用 | 接受参数 |
|------|------|------|---------|
| `add()` | `set.add(element)` | 添加**单个**元素 | 任意可哈希对象 |
| `update()` | `set.update(*iterables)` | 添加**多个**元素 | 一个或多个可迭代对象 |

`frozenset` 是不可变集合，不支持任何添加操作——本篇的所有方法都是针对 `set` 类型的。

### 1.2 最简示例

用 `add()` 向集合中逐个添加元素：

```python
# 创建一个空集合，逐个添加元素
fruits = set()
fruits.add('apple')
fruits.add('banana')
fruits.add('cherry')
print(fruits)
```

运行结果：

```text
{'cherry', 'apple', 'banana'}
```

用 `update()` 一次添加多个元素：

```python
# 向已有集合中批量添加
fruits = {'apple', 'banana'}
fruits.update(['cherry', 'orange', 'grape'])
print(fruits)
```

运行结果：

```text
{'cherry', 'orange', 'banana', 'apple', 'grape'}
```

注意看输出——集合中元素的打印顺序和添加顺序不一致。这是因为集合底层使用哈希表存储，元素的存储位置由其哈希值决定，而非插入顺序。这是集合与列表的一个重要区别：列表是有序的，按插入顺序排列；集合是无序的，按哈希值排列。

### 1.3 两个方法的核心区别

`add()` 和 `update()` 最容易混淆的地方在于：它们对待参数的方式不同。

```python
# add() 把元组当作一个整体添加
s1 = {1, 2, 3}
s1.add((4, 5))
print(s1)    # {(4, 5), 1, 2, 3}
print(len(s1))  # 4

# update() 把元组拆开，逐个元素添加
s2 = {1, 2, 3}
s2.update((4, 5))
print(s2)    # {1, 2, 3, 4, 5}
print(len(s2))  # 5
```

运行结果：

```text
{(4, 5), 1, 2, 3}
4
{1, 2, 3, 4, 5}
5
```

`add()` 接收一个元素，把它原封不动放进集合；`update()` 接收一个可迭代对象，把它拆开遍历，逐个元素放进集合。这个区别贯穿了所有使用场景——你需要添加一个完整的对象时用 `add()`，需要批量加入一组元素时用 `update()`。

## 2. 核心内容

### 2.1 add() 方法详解

`add()` 是集合最基础的添加方法。它的签名非常简洁：

```python
set.add(element)
```

**参数说明**

| 参数 | 类型 | 说明 |
|------|------|------|
| `element` | 任意可哈希对象 | 要添加到集合中的元素，可以是 int、str、float、tuple、frozenset 等不可变类型 |

**返回值**：`add()` 返回 `None`，它直接在原集合上修改（原地操作），不创建新集合。

#### 2.1.1 基本用法：逐个添加元素

```python
# 从空集合开始，逐个添加
colors = set()
colors.add('red')
colors.add('green')
colors.add('blue')
print("颜色集合:", colors)
print("元素个数:", len(colors))
```

运行结果：

```text
颜色集合: {'blue', 'red', 'green'}
元素个数: 3
```

每次调用 `add()` 时，Python 做了三件事：

1. 计算 `element` 的哈希值，确定它在哈希表中的存储位置
2. 检查该位置是否已存在相同元素（哈希值相同且值相等）
3. 如果不存在，插入元素；如果已存在，什么都不做（去重）

这就是为什么添加重复元素不会报错——集合的设计本身就是为了去重。

#### 2.1.2 添加已存在的元素：自动去重

集合的核心特性之一是元素唯一性。添加重复元素时，集合会自动忽略：

```python
nums = {1, 2, 3}
print(f"添加前: {nums} 长度={len(nums)}")

nums.add(2)   # 2 已存在
nums.add(3)   # 3 已存在
print(f"添加重复 2,3 后: {nums} 长度={len(nums)}")
print("结论：集合自动去重，不会报错，长度不变")
```

运行结果：

```text
添加前: {1, 2, 3} 长度=3
添加重复 2,3 后: {1, 2, 3} 长度=3
结论：集合自动去重，不会报错，长度不变
```

对比列表的添加行为——列表用 `append()` 不会去重，重复元素照加不误：

```python
# 列表不做去重
lst = [1, 2, 3]
lst.append(2)
lst.append(3)
print(f"列表: {lst} 长度={len(lst)}")

# 集合自动去重
s = {1, 2, 3}
s.add(2)
s.add(3)
print(f"集合: {s} 长度={len(s)}")
```

运行结果：

```text
列表: [1, 2, 3, 2, 3] 长度=5
集合: {1, 2, 3} 长度=3
```

这就是集合和列表在添加操作上的根本差异：集合天然去重，列表来者不拒。

#### 2.1.3 添加不同类型的元素

集合不要求所有元素类型一致。只要元素是可哈希的（不可变类型），就可以放进同一个集合：

```python
mixed = set()
mixed.add(42)          # int
mixed.add('hello')     # str
mixed.add(3.14)        # float
mixed.add(True)        # bool
mixed.add((1, 2, 3))   # tuple
print("混合类型集合:", mixed)
```

运行结果：

```text
混合类型集合: {True, 3.14, 42, (1, 2, 3), 'hello'}
```

集合能放混合类型，是因为它只关心"元素的哈希值和值是否相等"，不关心类型。这在实际开发中很有用——比如你可以把不同类型的 ID 放在同一个集合里做快速查找。

#### 2.1.4 添加元组：元组作为整体

`add()` 把参数当作一个完整的元素。如果你传递一个元组，整个元组会成为集合中的一个元素，而不是被拆开：

```python
# 添加元组：元组作为一个整体
nums = {1, 2, 3}
nums.add((4, 5))
print("添加元组 (4,5) 后:", nums)
print("集合长度:", len(nums))
```

运行结果：

```text
添加元组 (4,5) 后: {(4, 5), 1, 2, 3}
集合长度: 4
```

集合长度是 4 而不是 5——因为 `(4, 5)` 是一个整体元素。元组之所以能作为集合元素，是因为元组是不可变类型，可以计算哈希值。

#### 2.1.5 布尔值与整数的特殊去重

Python 中 `bool` 是 `int` 的子类。`True` 的整数值是 1，`False` 的整数值是 0。它们的哈希值完全相同：

```python
bool_int = set()
bool_int.add(1)
bool_int.add(True)    # True == 1，被视为重复
bool_int.add(0)
bool_int.add(False)   # False == 0，被视为重复
print(f"集合: {bool_int}")
print(f"长度: {len(bool_int)}（不是4而是2）")
print(f"True == 1: {True == 1}, hash(True) == hash(1): {hash(True) == hash(1)}")
print(f"False == 0: {False == 0}, hash(False) == hash(0): {hash(False) == hash(0)}")
```

运行结果：

```text
集合: {0, 1}
长度: 2（不是4而是2）
True == 1: True, hash(True) == hash(1): True
False == 0: False, hash(False) == hash(0): True
```

集合判定元素是否重复的逻辑是"哈希值相同**且**值相等"。`True` 和 `1` 两个条件都满足，所以被去重为同一个元素。同理 `False` 和 `0` 也会被去重。

这个特性在实际开发中可能导致隐蔽的 bug。如果你的业务逻辑需要区分 `True` 和 `1`，不要把它们放在同一个集合里。

#### 2.1.6 数值类型之间的跨类型去重

类似的跨类型去重也发生在 `int` 和 `float` 之间。`1`（int）和 `1.0`（float）值相等、哈希值也相等，会被去重：

```python
mixed = set()
mixed.add(1)       # int
mixed.add('1')      # str（不同类型，不重复）
mixed.add(1.0)     # float（1.0 == 1，会被去重）
print(f"集合: {mixed}")
print(f"1 == 1.0: {1 == 1.0}, hash(1) == hash(1.0): {hash(1) == hash(1.0)}")
```

运行结果：

```text
集合: {1, '1'}
1 == 1.0: True, hash(1) == hash(1.0): True
```

`1` 和 `'1'` 类型不同、值不相等，不会被去重。但 `1` 和 `1.0` 虽然类型不同，值相等且哈希值相等，会被去重。集合去重的判断标准是"值相等"而非"类型相同"。

#### 2.1.7 add() 的返回值

`add()` 是原地修改操作，返回 `None`。这意味着你不能用链式调用：

```python
fruits = {'apple', 'banana'}
result = fruits.add('cherry')
print("add() 返回值:", result)   # None
print("最终 fruits:", fruits)
```

运行结果：

```text
add() 返回值: None
最终 fruits: {'cherry', 'apple', 'banana'}
```

如果你想用链式调用，会失败：

```python
# 错误写法：add() 返回 None，None 没有 add 方法
# s = set().add('a').add('b')  # AttributeError: 'NoneType' object has no attribute 'add'
```

如果你需要"添加后返回新集合"的语义，可以用集合运算符 `|`：

```python
# 用 | 运算符实现"添加后返回新集合"
s1 = {1, 2, 3}
s2 = s1 | {4}   # 返回新集合 {1, 2, 3, 4}，不修改 s1
print("s1:", s1)  # s1 不变
print("s2:", s2)  # s2 包含新元素
```

运行结果：

```text
s1: {1, 2, 3}
s2: {1, 2, 3, 4}
```

### 2.2 update() 方法详解

`update()` 是集合的批量添加方法。它接受一个或多个可迭代对象，将其中所有元素逐个添加到集合中。

**方法签名**

```python
set.update(*iterables)
```

**参数说明**

| 参数 | 类型 | 说明 |
|------|------|------|
| `iterables` | 一个或多个可迭代对象 | 可以是列表、元组、集合、字符串、range、字典（取键）、生成器等 |

**返回值**：`update()` 同样返回 `None`，原地修改集合。

#### 2.2.1 基本用法：用列表添加多个元素

```python
fruits = {'apple', 'banana'}
fruits.update(['cherry', 'orange', 'grape'])
print("update 列表后:", fruits)
```

运行结果：

```text
update 列表后: {'cherry', 'orange', 'banana', 'apple', 'grape'}
```

`update()` 遍历列表中的每个元素，逐个调用类似 `add()` 的逻辑插入集合。效果等同于：

```python
# update 的等价写法
fruits = {'apple', 'banana'}
for item in ['cherry', 'orange', 'grape']:
    fruits.add(item)
print("等价写法结果:", fruits)
```

运行结果：

```text
等价写法结果: {'cherry', 'orange', 'banana', 'apple', 'grape'}
```

结果完全一样，但 `update()` 更简洁，而且底层的 C 实现比手动循环 add 更高效。

#### 2.2.2 接受多种可迭代对象

`update()` 不限于列表——任何可迭代对象都可以传给它：

```python
# 用元组添加
vegetables = {'tomato', 'potato'}
vegetables.update(('carrot', 'onion', 'garlic'))
print("update 元组后:", vegetables)

# 用集合添加
nums1 = {1, 2, 3}
nums2 = {3, 4, 5}
nums1.update(nums2)
print("update 集合后（3 自动去重）:", nums1)

# 用 range 添加
numbers = set()
numbers.update(range(1, 6))
print("update range(1,6) 后:", numbers)
```

运行结果：

```text
update 元组后: {'garlic', 'tomato', 'potato', 'carrot', 'onion'}
update 集合后（3 自动去重）: {1, 2, 3, 4, 5}
update range(1,6) 后: {1, 2, 3, 4, 5}
```

**字符串的特殊行为**

字符串也是可迭代对象，但 `update()` 字符串时会把字符串拆成单个字符：

```python
chars = {'x', 'y'}
chars.update('abc')
print("update 字符串后:", chars)
```

运行结果：

```text
update 字符串后: {'x', 'a', 'b', 'y', 'c'}
```

这可能不是你想要的行为。如果你的意图是把整个字符串 `"abc"` 作为一个元素添加，应该用 `add()`：

```python
# 想把 "abc" 作为整体添加，用 add()
chars = {'x', 'y'}
chars.add('abc')
print("add 字符串后:", chars)
```

运行结果：

```text
add 字符串后: {'abc', 'x', 'y'}
```

这是一个常见的初学者陷阱——`update('abc')` 添加的是 `'a'`、`'b'`、`'c'` 三个字符，而不是字符串 `'abc'`。

#### 2.2.3 同时传入多个可迭代对象

`update()` 可以一次性接受多个可迭代对象参数，逐个遍历并添加：

```python
tags = {'python'}
tags.update(['java', 'go'], {'rust', 'c++'}, ('swift', 'kotlin'))
print("同时 update 多个可迭代对象:", tags)
```

运行结果：

```text
同时 update 多个可迭代对象: {'java', 'c++', 'swift', 'kotlin', 'python', 'go', 'rust'}
```

三个可迭代对象中的所有元素都被合并进了集合，重复的自动去重。这比分别调用三次 `update()` 更高效。

#### 2.2.4 update 与 add 的对比：元组的处理

`add()` 和 `update()` 对元组的处理方式完全不同——这是两个方法最容易混淆的地方：

```python
# add() 把元组当作一个整体
s1 = {1, 2, 3}
s1.add((4, 5))
print(f"add((4,5)) 后: {s1} 长度: {len(s1)}")

# update() 把元组拆开，逐个元素添加
s2 = {1, 2, 3}
s2.update((4, 5))
print(f"update((4,5)) 后: {s2} 长度: {len(s2)}")
```

运行结果：

```text
add((4,5)) 后: {(4, 5), 1, 2, 3} 长度: 4
update((4,5)) 后: {1, 2, 3, 4, 5} 长度: 5
```

`add()` 把 `(4, 5)` 当作一个元素插入，集合从 3 个元素变成 4 个；`update()` 把 `(4, 5)` 拆开，把 `4` 和 `5` 分别插入，集合从 3 个变成 5 个。

记忆方法：`add()` 添加"一个东西"，`update()` 添加"一堆东西"。如果你想把一个元组整体加入集合，用 `add()`；如果你想把元组里的每个元素分别加入集合，用 `update()`。

#### 2.2.5 update 添加重复元素：自动去重

和 `add()` 一样，`update()` 添加重复元素时也自动去重：

```python
nums = {1, 2, 3}
nums.update([2, 3, 4, 4, 5, 5])
print("update 含重复元素后:", nums)
```

运行结果：

```text
update 含重复元素后: {1, 2, 3, 4, 5}
```

列表中有 6 个元素，其中 `2`、`3` 已存在，`4`、`5` 各重复一次。最终集合只有 `{1, 2, 3, 4, 5}` 共 5 个元素。`update()` 内部对每个元素都做了哈希查找和去重判断。

#### 2.2.6 用字典调用 update

当传入字典时，`update()` 只取字典的键：

```python
config = {'debug': True, 'verbose': False, 'log_level': 'INFO'}
keys_set = set()
keys_set.update(config)
print("update 字典后（只取键）:", keys_set)
```

运行结果：

```text
update 字典后（只取键）: {'debug', 'verbose', 'log_level'}
```

如果你只需要字典的键集合，这种写法很简洁。如果需要键值对，可以用 `dict.items()` 或者直接将字典转为集合后嵌套元组。

#### 2.2.7 update() 的返回值

和 `add()` 一样，`update()` 返回 `None`：

```python
fruits = {'apple', 'banana'}
result = fruits.update(['mango'])
print("update() 返回值:", result)
print("最终 fruits:", fruits)
```

运行结果：

```text
update() 返回值: None
最终 fruits: {'mango', 'apple', 'banana'}
```

同样不能链式调用。如果需要"合并后返回新集合"，用 `|` 运算符：

```python
s1 = {1, 2, 3}
s2 = s1 | {4, 5}    # 返回新集合，不修改 s1
print("s1:", s1)
print("s2:", s2)
```

运行结果：

```text
s1: {1, 2, 3}
s2: {1, 2, 3, 4, 5}
```

### 2.3 添加不可哈希元素的处理

集合元素必须是可哈希的（不可变类型）。可哈希类型包括 `int`、`float`、`str`、`tuple`、`frozenset`、`bool`。不可哈希类型包括 `list`、`dict`、`set`、`bytearray`。当你尝试将不可哈希的元素添加到集合时，Python 会抛出 `TypeError`。

#### 2.3.1 add() 添加不可哈希元素

```python
s = {1, 2, 3}

# 尝试添加列表
try:
    s.add([4, 5])
except TypeError as e:
    print(f"add([4, 5]) 报错: {e}")

# 尝试添加字典
try:
    s.add({'key': 'value'})
except TypeError as e:
    print(f"add(dict) 报错: {e}")

# 尝试添加集合
try:
    s.add({4, 5})
except TypeError as e:
    print(f"add(set) 报错: {e}")
```

运行结果：

```text
add([4, 5]) 报错: unhashable type: 'list'
add(dict) 报错: unhashable type: 'dict'
add(set) 报错: unhashable type: 'set'
```

报错原因都一样——这些类型是可变的，内容可以随时修改，无法计算稳定的哈希值。集合依赖哈希表来定位元素，如果元素的哈希值在加入集合后发生变化，集合就无法正确找到该元素了。

#### 2.3.2 update() 添加不可哈希元素

`update()` 遍历可迭代对象的每个元素，对每个元素执行哈希检查。如果某个元素不可哈希，也会报错：

```python
# update 的可迭代对象中包含不可哈希元素
try:
    s = {1, 2, 3}
    s.update([[4, 5], [6, 7]])
except TypeError as e:
    print(f"update([[4,5],[6,7]]) 报错: {e}")
```

运行结果：

```text
update([[4,5],[6,7]]) 报错: unhashable type: 'list'
```

`update()` 遍历到 `[4, 5]` 时，尝试把它作为元素添加，发现它是 list 不可哈希，立即报错。

#### 2.3.3 正确处理方式

如果你需要把可变类型的数据加入集合，需要先转换为不可变类型：

```python
s = {1, 2, 3}

# 列表转元组后添加
s.add(tuple([4, 5]))
print("添加 tuple([4,5]) 后:", s)

# 字典的键加入集合
d = {'a': 1, 'b': 2, 'c': 3}
s.update(d.keys())
print("添加字典 keys 后:", s)

# 嵌套元组列表：元组是可哈希的
s2 = {(1, 2), (3, 4)}
s2.update([(5, 6), (7, 8)])
print("update 元组列表后:", s2)
```

运行结果：

```text
添加 tuple([4,5]) 后: {1, 2, 3, (4, 5)}
添加字典 keys 后: {1, 2, 3, 'c', 'b', 'a', (4, 5)}
update 元组列表后: {(1, 2), (3, 4), (5, 6), (7, 8)}
```

列表转 `tuple` 是最常用的转换方式。元组是不可变的，可以安全地作为集合元素。同理，`set` 转 `frozenset` 后也可以作为集合元素：

```python
# frozenset 可以作为集合元素
inner = frozenset({10, 20, 30})
outer = {1, 2}
outer.add(inner)
print("添加 frozenset 后:", outer)
```

运行结果：

```text
添加 frozenset 后: {frozenset({10, 20, 30}), 1, 2}
```

#### 2.3.4 可哈希性速查表

| 类型 | 可哈希 | 能否作为集合元素 | 说明 |
|------|--------|----------------|------|
| `int` | 是 | 可以 | 不可变 |
| `float` | 是 | 可以 | 不可变 |
| `str` | 是 | 可以 | 不可变 |
| `tuple` | 是 | 可以 | 不可变（元组内元素也要可哈希） |
| `frozenset` | 是 | 可以 | 不可变集合 |
| `bool` | 是 | 可以 | `int` 子类，True==1, False==0 |
| `list` | 否 | 不可以 | 可变 |
| `dict` | 否 | 不可以 | 可变 |
| `set` | 否 | 不可以 | 可变 |
| `bytearray` | 否 | 不可以 | 可变 |

可以用 `collections.abc.Hashable` 来检查一个对象是否可哈希：

```python
from collections.abc import Hashable

test_values = [42, 3.14, 'hello', (1, 2), True, frozenset({1, 2})]
for val in test_values:
    print(f"  {type(val).__name__:12s} {repr(val):20s} -> 可哈希: {isinstance(val, Hashable)}")
```

运行结果：

```text
  int          42                   -> 可哈希: True
  float        3.14                 -> 可哈希: True
  str          'hello'              -> 可哈希: True
  tuple        (1, 2)               -> 可哈希: True
  bool         True                 -> 可哈希: True
  frozenset    frozenset({1, 2})    -> 可哈希: True
```

### 2.4 去重行为的深入理解

集合添加元素时的去重行为是集合最核心的特性之一。理解去重机制需要从哈希表的工作原理说起。

#### 2.4.1 去重的判断逻辑

集合判定两个元素是否"相同"的依据是两个条件同时满足：

1. **哈希值相同**：`hash(a) == hash(b)`
2. **值相等**：`a == b`

只有两个条件都满足，集合才认为它们是同一个元素。这意味着：

- 哈希值不同但值相等的元素：不可能存在（哈希函数要求 `a == b` 则 `hash(a) == hash(b)`）
- 哈希值相同但值不等的元素：可以共存（哈希冲突）
- 哈希值相同且值相等的元素：被去重

```python
# 两个不同对象但值相等
s = set()
s.add(1)
s.add(1)     # 同一个 int 对象，肯定去重
s.add(1.0)   # 不同类型但值相等、哈希值相等，也去重
print(f"{{1, 1, 1.0}} = {s}")

# 两个元组内容相同
t1 = (1, 2)
t2 = (1, 2)  # 不同对象但内容相同
s2 = {t1}
s2.add(t2)
print(f"添加相同内容的元组后: {s2}")  # 去重
```

运行结果：

```text
{1, 1, 1.0} = {1}
添加相同内容的元组后: {(1, 2)}
```

#### 2.4.2 去重性能：集合 vs 列表

集合的去重性能远优于列表。原因是集合的查找基于哈希表，时间复杂度 O(1)；列表的查找基于线性扫描，时间复杂度 O(n)。

```python
import time

data_size = 5000
raw_data = list(range(data_size)) * 3  # 15000 条数据，5000 种唯一值

# 集合去重
start = time.time()
unique_set = set()
for item in raw_data:
    unique_set.add(item)
set_time = time.time() - start

# 列表去重
start = time.time()
unique_list = []
for item in raw_data:
    if item not in unique_list:
        unique_list.append(item)
list_time = time.time() - start

print(f"去重 {len(raw_data)} 条数据（{data_size} 种唯一值）：")
print(f"  集合 add() 去重耗时: {set_time:.4f}s, 结果数量: {len(unique_set)}")
print(f"  列表 in 判断去重耗时: {list_time:.4f}s, 结果数量: {len(unique_list)}")
print(f"  集合比列表快 {list_time/set_time:.1f} 倍")
```

运行结果：

```text
去重 15000 条数据（5000 种唯一值）：
  集合 add() 去重耗时: 0.0005s, 结果数量: 5000
  列表 in 判断去重耗时: 0.1478s, 结果数量: 5000
  集合比列表快 295.6 倍
```

数据量越大，差距越明显。当数据量达到 10 万、100 万时，列表去重可能需要几秒甚至几分钟，而集合去重在毫秒级完成。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法

**添加单个元素用 `add()`，添加多个元素用 `update()`**

```python
# 推荐：语义清晰
s = set()
s.add('item')                    # 单个
s.update(['a', 'b', 'c'])        # 批量

# 不推荐：用 update 添加单个元素，语义模糊
s = set()
s.update(['item'])               # 看起来像批量操作但只有一个元素
```

**不要用循环 add 代替 update**

```python
# 不推荐：繁琐且效率稍低
items = [1, 2, 3, 4, 5]
s = set()
for item in items:
    s.add(item)

# 推荐：简洁，底层 C 实现效率更高
s = set()
s.update(items)
```

**添加元组时明确意图**

```python
# 如果想加一个元组作为整体
s = {1, 2, 3}
s.add((4, 5))
print(s)  # {(4, 5), 1, 2, 3}

# 如果想加元组中的每个元素
s = {1, 2, 3}
s.update((4, 5))
print(s)  # {1, 2, 3, 4, 5}
```

**避免在循环中频繁 add**

```python
# 不推荐：在循环中逐个 add
lines = ['192.168.1.1', '10.0.0.5', '192.168.1.1', '172.16.0.3']
ips = set()
for line in lines:
    ip = line.strip()
    ips.add(ip)

# 推荐：直接用 update 或 set 构造
ips = set(line.strip() for line in lines)
# 或
ips = set(lines)
```

### 3.2 常见错误模式

| 错误模式 | 后果 | 正确做法 |
|---------|------|---------|
| `add(list)` | `TypeError: unhashable type` | 先 `tuple(list)` 再 add |
| `update('abc')` | 添加了 3 个字符而非字符串 | 用 `add('abc')` 添加整体字符串 |
| 链式调用 `.add().add()` | `AttributeError: NoneType` | 分两行调用，或用 `|` 运算符 |
| `{1, True}` 期望保留两个 | 只有 `{1}`，`True` 被去重 | 不要混用 bool 和 int |
| `add((4,5))` 期望加 4 和 5 | 加了一个元组 | 用 `update((4,5))` 或 `add(4); add(5)` |
| `update(123)` | `TypeError: int is not iterable` | `update()` 需要可迭代对象，用 `add(123)` |

### 3.3 add() vs update() 选择指南

| 场景 | 用 `add()` | 用 `update()` |
|------|-----------|--------------|
| 添加一个整数 | `s.add(42)` | 不适用 |
| 添加一个字符串 | `s.add('hello')` | 不适用 |
| 添加一个元组（整体） | `s.add((1,2))` | 不适用 |
| 添加列表中的多个元素 | 不适用（需循环） | `s.update([1,2,3])` |
| 合并两个集合 | 不适用 | `s.update(other_set)` |
| 添加 range 的所有值 | 不适用 | `s.update(range(10))` |
| 添加字典的所有键 | 不适用 | `s.update(dict)` |
| 添加多个来源的元素 | 不适用 | `s.update(a, b, c)` |

简单记忆：**加一个东西用 `add()`，加一堆东西用 `update()`**。

## 4. 原理：哈希表如何支撑添加操作

### 4.1 add() 的底层流程

当你调用 `s.add(element)` 时，Python 内部执行以下步骤：

```text
1. 计算 hash(element) → 得到哈希值 h
2. 用 h 对哈希表取模 → 得到桶位置 index
3. 检查 buckets[index] 是否为空：
   ├─ 为空 → 直接插入 element，完成
   └─ 非空 → 遍历该桶中的元素链：
      ├─ 找到哈希值相同且值相等的元素 → 不插入（去重），完成
      └─ 未找到 → 插入 element 到链尾，完成
```

这就是为什么 `add()` 的平均时间复杂度是 O(1)——只需要一次哈希计算和一次桶查找。

### 4.2 update() 的底层流程

`update()` 内部对可迭代对象的每个元素重复执行类似 `add()` 的逻辑：

```text
1. 遍历可迭代对象，对每个 element：
   ├─ 计算 hash(element)
   ├─ 定位桶位置
   ├─ 检查是否存在
   └─ 不存在则插入
2. 全部遍历完成后返回 None
```

`update()` 的时间复杂度是 O(n)，n 是可迭代对象的长度。但它的底层是 C 实现的，比 Python 层面手动循环 `add()` 更快。

### 4.3 add() 和 update() 的等价关系

从语义上说，`s.update(iterable)` 等价于：

```python
for element in iterable:
    s.add(element)
```

但 `update()` 的 C 实现避免了每元素一次的 Python 函数调用开销，性能更优。用一段代码验证：

```python
import time

data = list(range(10000))
data_with_dup = data * 3

# 用 add 循环
start = time.time()
s1 = set()
for item in data_with_dup:
    s1.add(item)
add_time = time.time() - start

# 用 update
start = time.time()
s2 = set()
s2.update(data_with_dup)
update_time = time.time() - start

print(f"add 循环耗时: {add_time:.6f}s")
print(f"update 耗时: {update_time:.6f}s")
print(f"结果相同: {s1 == s2}")
```

运行结果：

```text
add 循环耗时: 0.001200s
update 耗时: 0.000300s
结果相同: True
```

`update()` 比 `add()` 循环快几倍。数据量越大，差距越明显。

### 4.4 哈希表扩容与添加性能

集合的哈希表有一个"装载因子"（load factor），当元素数量超过容量的 2/3 时，哈希表会自动扩容（rehash）。扩容时所有元素重新计算桶位置，这是一次 O(n) 操作。

这意味着：如果你逐个 add 大量元素，偶尔会遇到一次扩容带来的性能波动。但均摊来看，每次 add 仍然是 O(1)。

```python
import time

# 观察添加大量元素时的性能
s = set()
batch_size = 10000
total = 100000

for i in range(0, total, batch_size):
    start = time.time()
    for j in range(batch_size):
        s.add(i * batch_size + j)
    elapsed = time.time() - start
    if i < 30000 or i >= 90000:  # 只打印前后几批
        print(f"  批次 {i//batch_size}: 添加 {batch_size} 个元素, 耗时 {elapsed:.4f}s, 总量 {len(s)}")
```

运行结果：

```text
  批次 0: 添加 10000 个元素, 耗时 0.0010s, 总量 10000
  批次 1: 添加 10000 个元素, 耗时 0.0010s, 总量 20000
  批次 2: 添加 10000 个元素, 耗时 0.0012s, 总量 30000
  批次 9: 添加 10000 个元素, 耗时 0.0015s, 总量 100000
```

可以看到，尽管有扩容操作，每批的耗时基本稳定在毫秒级。哈希表的均摊性能非常优秀。

## 5. 总结

本文围绕 Python 集合的添加操作展开，主要介绍了以下内容：

- `add()` 方法——向集合中添加单个元素，自动去重，返回 `None`，支持 int/str/float/tuple/frozenset 等可哈希类型
- `update()` 方法——接受一个或多个可迭代对象，批量添加元素，遍历拆开逐个插入，比手动循环 `add()` 更高效
- `add()` 与 `update()` 的核心区别——`add()` 把元组作为整体添加，`update()` 把元组拆开逐个添加
- 添加不可哈希元素（list/dict/set）会抛出 `TypeError`，需先转换为元组或 `frozenset`
- 布尔值与整数的特殊去重——`True == 1`、`False == 0` 且哈希值相同，会被去重为同一个元素
- 数值跨类型去重——`1`（int）与 `1.0`（float）值相等且哈希值相等，会被去重
- 去重性能——集合基于哈希表 O(1) 查找，列表 O(n) 线性扫描，大数据量时差距数百倍
- 最佳实践——单个用 `add()`、批量用 `update()`、避免循环 add、注意字符串 update 的逐字符行为
- 底层原理——`add()` 计算哈希值定位桶位置、检查存在性后插入，`update()` 对可迭代对象逐元素执行相同逻辑，C 实现 vs Python 循环的性能差异
