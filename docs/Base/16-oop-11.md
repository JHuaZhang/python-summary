## 1. 介绍

### 1.1 什么是 property

在面向对象编程中，"封装"是一个被反复强调的原则：对象的内部状态应该被保护起来，外部代码通过受控的接口来访问和修改这些状态。很多语言（如 Java、C++）通过 `private` 字段加 `getXxx()`/`setXxx()` 方法来实现这一点，于是你会写出 `obj.getWidth()` 和 `obj.setWidth(10)` 这样的调用。

Python 没有真正的 `private` 关键字，它用一种更优雅的机制来处理"受控的属性访问"——`property`。`property` 的核心能力是：**把一个"方法调用"伪装成"属性访问"**。也就是说，你在类里定义一个方法，经过 `property` 包装后，外部代码用 `obj.x` 来读取它会自动调用这个方法拿到返回值，而不是用 `obj.x()` 这种带括号的调用形式。

这层"伪装"带来了几个立竿见影的好处：

- 调用方代码更简洁：`circle.area` 比 `circle.get_area()` 读起来更自然，面积本来就是一个"属性"而非一个"动作"。
- 内部实现可以平滑演进：一开始你直接用 `self.area = 3.14` 存储面积，后来发现应该每次实时计算，于是把 `area` 改成 `property`，调用方的 `circle.area` 写法完全不用动。这种"接口稳定、内部可变"是 property 最重要的工程价值。
- 可以做到只读：只定义 getter 不定义 setter 的 property，外部赋值会直接抛 `AttributeError`，从机制层面阻止误改。

从实现角度看，`property` 是 Python 内置的一个类型，它的实例是一种"描述符"（descriptor），会劫持对属性的访问。理解这一点需要先了解描述符协议，本篇第 4 章会详细展开。你暂时只需要记住：`property` 让"属性访问"和"方法调用"在描述符层面统一起来，使你既能享受属性语法的简洁，又能保留方法体内的计算逻辑。

### 1.2 @property 装饰器的基本语法

定义一个只读 property 最常见的形式是使用 `@property` 装饰器。`@property` 装饰的是一个**无参方法**（除 `self` 外不再接受参数），方法名就是你希望对外暴露的属性名。装饰后，这个方法不再是普通方法，而变成了一个 `property` 对象，通过 `obj.方法名` 访问时会自动调用该方法并返回其返回值。

最小示例：

```python
class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def diameter(self):
        """直径：半径的两倍，每次访问即时计算"""
        return self.radius * 2


c = Circle(5)
# 注意：这里不带括号，像访问属性一样
print(c.diameter)

c.radius = 10
print(c.diameter)

# 试图对只读 property 赋值会报错
try:
    c.diameter = 30
except AttributeError as e:
    print(f"赋值失败：{e}")
```

```python
# 输出：
# 10
# 20
# 赋值失败：can't set attribute
```

注意几个关键点：

- `c.diameter` 没有括号。如果你写成 `c.diameter()`，实际上是先拿到 `property` 的返回值（一个整数），再对整数加 `()`，会报 `'int' object is not callable`。这是初学者最常犯的错误之一。
- 第二次访问 `c.diameter` 时，因为 `radius` 已经改成 10，返回值变成了 20。这说明 property 不是"存一个值"，而是"每次访问都执行方法体"，这正是"计算属性"的特征。
- `c.diameter = 30` 抛 `AttributeError: can't set attribute`，因为只定义了 getter 没有 setter。这个报错是 property 机制本身给出的，不需要你手写校验逻辑。

### 1.3 property 的三参形式简述

除了 `@property` 装饰器，`property` 还可以作为一个函数直接调用，完整签名是：

```
property(fget=None, fset=None, fdel=None, doc=None)
```

其中 `fget` 是 getter 函数，`fset` 是 setter 函数，`fdel` 是 deleter 函数，`doc` 是该属性的文档字符串。四个参数都是可选的，但通常至少要传 `fget`，否则这个 property 读出来什么也拿不到。

`@property` 装饰器其实是三参形式的一种语法糖：`@property` 等价于把被装饰的方法作为 `fget` 传给 `property()`，得到一个只读的 property 对象。要把 setter 和 deleter 也挂上，可以用 `@x.setter` 和 `@x.deleter`，这些会在本系列第 12 篇（property setter/deleter）详细展开。

本篇聚焦于 getter 封装， setter 和 deleter 只在需要对比时简要提及。三参形式的一个简单示例如下，帮助你建立完整印象：

```python
class Person:
    def __init__(self, name):
        self._name = name

    def get_name(self):
        return self._name

    # 用三参形式直接构造一个只读 property
    name = property(get_name)


p = Person("张三")
print(p.name)  # 像属性一样访问，触发 get_name
# 输出：张三
```

这个写法和下面的 `@property` 形式完全等价：

```python
class Person:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        return self._name


p = Person("张三")
print(p.name)
# 输出：张三
```

在类体内，`@property` 把 `name` 方法包装成 `property` 对象后，存入类的 `__dict__`。所以你在 `Person.__dict__` 里看到的 `name` 不再是一个函数，而是一个 `property` 实例。这个细节对理解第 4 章的原理很关键，先记下。

## 2. 核心内容

### 2.1 计算属性：每次访问即时计算

计算属性是 property getter 最经典的用途。所谓计算属性，指的是这个"属性"的值不是预先存储好的，而是在每次访问时根据对象当前的其它状态实时算出来。它的好处是：永远不会出现"存了一份旧值、和真实状态不一致"的同步问题。

考虑一个 `Circle` 类，它有 `radius`（半径）。圆的面积、周长、直径这些量都可以由半径推出来。如果把这些量当作普通属性存储，每次 `radius` 改变后你都要记得同步更新它们，一旦漏改就会出现数据不一致。用 property 把它们变成计算属性，问题就消失了。

```python
import math


class Circle:
    """圆：用半径作为唯一真实状态，面积/周长/直径均为计算属性"""

    def __init__(self, radius):
        self.radius = radius  # 唯一需要存储的真实状态

    @property
    def diameter(self):
        """直径"""
        return self.radius * 2

    @property
    def circumference(self):
        """周长 = 2πr"""
        return 2 * math.pi * self.radius

    @property
    def area(self):
        """面积 = πr²"""
        return math.pi * self.radius ** 2


c = Circle(3)
print(f"半径 {c.radius} -> 直径 {c.diameter}, 周长 {c.circumference:.2f}, 面积 {c.area:.2f}")
# 输出：半径 3 -> 直径 6, 周长 18.85, 面积 28.27

c.radius = 5
print(f"半径 {c.radius} -> 直径 {c.diameter}, 周长 {c.circumference:.2f}, 面积 {c.area:.2f}")
# 输出：半径 5 -> 直径 10, 周长 31.42, 面积 78.54
```

这个例子体现了计算属性的精髓：`radius` 一改，`diameter`、`circumference`、`area` 全部立刻跟着变，因为它们根本不存值，每次访问都是现场算的。

**何时用计算属性**

当属性的值满足以下任一条件时，适合做成计算属性：

- 完全由其它属性派生，没有独立的存储意义（如直径之于半径）。
- 派生计算成本不高，且访问频率不高，没必要缓存。
- 你希望避免"存储多份相关数据，改了 A 忘了改 B"的同步负担。

**计算成本 vs 缓存**

需要注意，计算属性每次访问都重算。如果计算很重（比如要遍历一个大列表），而你又频繁访问，会有性能问题。这种情况下不要用朴素的 `@property`，可以考虑两种替代：

- 在 setter 里更新缓存（把派生值存一份，每次源属性变化时重算并存储），这需要定义 setter，属于第 12 篇的内容。
- 用 `functools.cached_property`，它在首次访问时计算并缓存，之后直接返回缓存值。但要注意 `cached_property` 要求类没有定义 `__dict__` 干扰，且属性本身必须是可哈希场景下才合适。

简言之：轻计算用 `@property`，重计算用缓存策略，不要无脑 `@property`。

### 2.2 只读属性：暴露但不允许外部改

property getter 的另一个核心用途是构造只读属性。只读 property 的定义方式很简单：只定义 getter，不定义 setter。此时 property 会在 `__set__` 里抛 `AttributeError`，外部代码读得到但写不进去。

典型场景是：对象的某个状态对外需要暴露（方便读取），但不允许外部随意修改（只能通过对象自己提供的方法变更）。比如一个 `Account` 的 `balance`（余额），外部可以查询，但只能通过 `deposit`/`withdraw` 方法改动，不能 `account.balance = 999999` 这样直接篡改。

```python
class Account:
    """账户：余额对外只读，只能通过 deposit/withdraw 修改"""

    def __init__(self, owner, initial_balance=0):
        self._owner = owner
        self._balance = initial_balance  # 内部存储，下划线表示"内部用"

    @property
    def owner(self):
        """开户人：只读"""
        return self._owner

    @property
    def balance(self):
        """余额：只读，改动只能走 deposit/withdraw"""
        return self._balance

    def deposit(self, amount):
        """存款：唯一让余额增加的途径"""
        if amount <= 0:
            raise ValueError("存款金额必须为正")
        self._balance += amount
        return self._balance

    def withdraw(self, amount):
        """取款：唯一让余额减少的途径，内含余额校验"""
        if amount <= 0:
            raise ValueError("取款金额必须为正")
        if amount > self._balance:
            raise ValueError("余额不足")
        self._balance -= amount
        return self._balance


acc = Account("张三", 1000)
print(f"{acc.owner} 当前余额：{acc.balance}")
# 输出：张三 当前余额：1000

acc.deposit(500)
print(f"存款后余额：{acc.balance}")
# 输出：存款后余额：1500

acc.withdraw(200)
print(f"取款后余额：{acc.balance}")
# 输出：取款后余额：1300

# 试图直接改只读属性
try:
    acc.balance = 1000000
except AttributeError as e:
    print(f"直接改余额失败：{e}")
# 输出：直接改余额失败：can't set attribute

try:
    acc.owner = "李四"
except AttributeError as e:
    print(f"直接改户主失败：{e}")
# 输出：直接改户主失败：can't set attribute
```

这里有一个设计要点：`_balance` 和 `_owner` 用下划线开头，表示"这是内部存储，外部别直接碰"；对外暴露的 `balance` 和 `owner` 是只读 property，提供受控的读取入口。这就是 Python 式封装的标准套路——"下划线内部存储 + property 对外暴露"。

**只读不是绝对安全**

需要说明，Python 的只读 property 是"君子协定 + 机制拦截"，并非真正的访问控制。外部代码只要愿意，仍可以通过 `acc._balance = 999999` 直接改内部存储（下划线只是约定），甚至可以通过绕过 property 直接操作类字典来强行赋值。property 阻止的是"通过 `acc.balance = ...` 这种规范路径的误改"，挡不住"明知故犯的恶意操作"。这在 Python 中是普遍现象——它把"该不该做"交给开发者自觉，但把"容易误做"的路径用机制隔开。

### 2.3 内外分离：_x 内部存储、x 对外 property

上一节已经出现了 `_balance` 内部、`balance` 对外的写法。这一节把它作为一个独立模式讲透，因为它是 property getter 最常见、最值得固化的用法。

模式是这样的：

1. 用一个带下划线前缀的属性（如 `self._name`）作为真正的数据存储，写在 `__init__` 或其它方法里。
2. 定义一个同名去下划线的 property（如 `name`），getter 里返回 `self._name`。
3. 外部代码统一通过 `obj.name` 访问，永远不直接碰 `obj._name`。

这样做的好处是解耦"存储形式"和"访问接口"。内部存储形式随时可以变（换字段名、换数据结构、换成数据库查询），只要 getter 的返回值含义不变，外部调用方完全无感。

```python
class Product:
    """商品：内部用 _price 存储，对外用 price 暴露"""

    def __init__(self, name, price):
        self.name = name
        self._price = price  # 内部存储

    @property
    def price(self):
        """对外价格：以元为单位的字符串，保留两位小数"""
        return f"￥{self._price:.2f}"


p = Product("Python 编程", 59.0)
print(p.price)
# 输出：￥59.00

# 内部存储仍是 float，方便做运算
p._price = 49.5
print(p.price)
# 输出：￥49.50
```

注意上面 `price` 这个 property 返回的是格式化字符串，而内部 `_price` 是 float。外部看到的是 `￥59.00` 这种展示形式，内部参与运算时用的是 `_price` 这个数字。实现了"展示"和"存储"的分离。

**接口稳定，内部实现可变**

这个模式最大的工程价值在于"演进"。来看一个典型的演进路径：

阶段一：你最初设计 `Product` 时，直接用普通属性存储价格，外部 `p.price` 直接读写。

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price  # 直接公开属性
```

阶段二：需求变化了——价格现在要带货币符号展示，且不允许设置为负数。如果在 Java 里，你得把 `price` 字段改成 `private`，再加 `getPrice()`/`setPrice()`，所有调用 `p.price` 的地方都要改成 `p.getPrice()`，调用方大量改动。

在 Python 里，你只需要：

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self._price = price  # 改成内部存储

    @property
    def price(self):
        return f"￥{self._price:.2f}"
```

调用方的 `p.price` 一行都不用改——它本来用的就是属性语法，现在 `price` 变成了 property，属性语法依然有效。这就是"property 让接口稳定、内部实现可变"的真正含义。反过来说，如果你一开始就用 `get_price()`/`set_price()` 式的方法，演进时要保持接口不变就麻烦得多。

这种"先简单属性、必要时升级为 property"的演进策略，是 Python 社区广泛推荐的做法：不要一上来就给所有字段都套 property（那是过度设计），但在需要加逻辑时能无痛升级。

### 2.4 内部存储单位的隐藏：Temperature 转换

只读 property 还有一个特别能体现"内外分离"价值的场景：内部用一种单位/格式存储，对外用另一种单位/格式暴露，中间靠 getter 做转换。外部调用方完全感觉不到内部存储是什么形式，只和"对外接口"打交道。

考虑温度。科学计算内部用开尔文（Kelvin）最干净（无负数、和热力学直接对应），但用户面对的是摄氏度（Celsius）。我们可以让 `Temperature` 内部存开尔文，对外的 `celsius` property 自动做转换。

```python
class Temperature:
    """温度：内部以开尔文存储，对外暴露摄氏度"""

    def __init__(self, celsius=0.0):
        # 构造时接收摄氏度，内部转成开尔文存储
        self._kelvin = celsius + 273.15

    @property
    def celsius(self):
        """对外摄氏度 = 内部开尔文 - 273.15"""
        return self._kelvin - 273.15

    @property
    def kelvin(self):
        """对外开尔文（只读）"""
        return self._kelvin

    @property
    def fahrenheit(self):
        """对外华氏度 = C * 9/5 + 32"""
        return self.celsius * 9 / 5 + 32


# 外部用摄氏度构造，完全不知道内部存的是开尔文
room = Temperature(celsius=25.0)
print(f"摄氏 {room.celsius}°C = 华氏 {room.fahrenheit}°F = 开尔文 {room.kelvin}K")
# 输出：摄氏 25.0°C = 华氏 77.0°F = 开尔文 298.15K

# 只读：不能直接改 celsius
try:
    room.celsius = 30
except AttributeError as e:
    print(f"改 celsius 失败：{e}")
# 输出：改 celsius 失败：can't set attribute
```

这个例子里，外部世界看到的是 `celsius`、`fahrenheit`、`kelvin` 三个"只读属性"，它们都是根据内部 `_kelvin` 现场换算的。调用方不需要知道内部存的是哪种单位，也不需要手动调用 `to_celsius()` 方法——属性语法让这一切像读一个普通字段一样自然。

在本例中 `fahrenheit` 还展示了计算属性的链式派生：它依赖 `self.celsius`（本身是一个 property），而 `celsius` 又依赖 `self._kelvin`。property 链完全可以层层调用，只要最终落到某个真实存储上即可。这种"派生属性再派生属性"的设计在建模物理量、金融量时非常常见。

需要提醒：本例为了聚焦 getter，三个 property 都是只读的。实际中你多半会希望 `t.celsius = 30` 能生效（自动转成开尔文存进 `_kelvin`），这就需要 setter，属于第 12 篇的内容。届时你会看到 setter 写一条 `self._kelvin = value + 273.15`，getter 和 setter 在 `_kelvin` 这个内部存储上汇合，对外形成"摄氏度可读可写"的完整假象——这正是 property 完整封装的威力。

### 2.5 @property 与 property() 三参形式的对照

`@property` 装饰器和 `property(fget, fset, fdel, doc)` 三参形式在功能上等价，区别只是写法。理解两者的关系有助于你看懂不同风格的代码。

**装饰器形式（推荐日常使用）**

```python
class Square:
    def __init__(self, side):
        self._side = side

    @property
    def side(self):
        return self._side

    @property
    def area(self):
        return self._side ** 2


s = Square(4)
print(s.side, s.area)
# 输出：4 16
```

`@property` 形式把 getter 方法直接以"目标属性名"命名，语义清晰，读起来就是"这个属性是这样取的"。

**三参形式**

```python
class Square:
    def __init__(self, side):
        self._side = side

    def _get_side(self):
        return self._side

    def _get_area(self):
        return self._side ** 2

    # 把函数对象传给 property，得到的 property 对象赋值给类属性
    side = property(_get_side)
    area = property(_get_area)


s = Square(4)
print(s.side, s.area)
# 输出：4 16
```

三参形式把"取值函数"和"对外属性名"显式分开，函数名可以叫 `_get_side` 这种带动词前缀的名字，属性名仍叫 `side`。这种写法在需要把同一个函数用在多个 property 上、或者需要动态构造 property 时更灵活。

**等价性说明**

`@property` 本质上就是：

```python
@property
def side(self):
    return self._side

# 等价于
side = property(side)
```

被 `@property` 装饰后，`side` 不再是函数，而是 `property(fget=原side函数)` 的返回值——一个只读 property 对象。

**完整签名的参数说明**

`property(fget=None, fset=None, fdel=None, doc=None)` 的四个参数：

| 参数 | 作用 | 不传时的行为 |
|------|------|-------------|
| `fget` | 取值函数，`obj.x` 时调用 | `obj.x` 抛 `AttributeError: unreadable attribute` |
| `fset` | 赋值函数，`obj.x = v` 时调用 | `obj.x = v` 抛 `AttributeError: can't set attribute`（只读） |
| `fdel` | 删除函数，`del obj.x` 时调用 | `del obj.x` 抛 `AttributeError: can't delete attribute` |
| `doc` | 该属性的文档字符串 | 取 `fget` 的 `__doc__` |

本篇锁定 getter，所以重点关注 `fget` 和 `doc`。只读的机制就是"不传 `fset`"，此时 property 的 `__set__` 会抛 `AttributeError`，这个机制第 4 章会从描述符角度展开。

### 2.6 property 的 __doc__ 与帮助信息

`property` 可以携带文档字符串，这点容易被忽略。用 `@property` 时，文档字符串直接写在被装饰的方法里；用三参形式时，通过 `doc=` 参数传。

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        """矩形面积 = 宽 × 高（只读计算属性）"""
        return self.width * self.height


r = Rectangle(3, 4)
print(r.area)
print(Rectangle.area.__doc__)
# 输出：
# 12
# 矩形面积 = 宽 × 高（只读计算属性）
```

`help(Rectangle)` 时，`area` 这个 property 的文档字符串也会被展示出来。这对库的 API 友好性很重要——只读属性也是 API 的一部分，应当有文档。

### 2.7 只读 property 与普通属性混用

一个类里往往不是所有属性都做成 property，通常是"需要逻辑的用 property、不需要的直接属性"。混用是常态，不必强行统一。

```python
class Book:
    def __init__(self, title, author, price):
        self.title = title        # 普通属性：直接读写
        self.author = author      # 普通属性
        self._price = price       # 内部存储

    @property
    def price(self):
        """价格：对外展示带单位"""
        return f"￥{self._price:.2f}"


b = Book("Python 学习", "某作者", 39.0)
print(b.title)      # 普通属性直接读
# 输出：Python 学习

b.title = "新版"    # 普通属性直接改
print(b.title)
# 输出：新版

print(b.price)      # property 读
# 输出：￥39.00
```

这里 `title`/`author` 是普通属性，`price` 是 property。他们的访问形式完全一样（都是 `obj.名字`），调用方感受不到区别。这正是 property 的设计意图：让你在"需要加逻辑的地方"加逻辑，而不用为了加逻辑而改变调用接口。

### 2.8 常见错误用法

**错误一：getter 里带参数**

`@property` 装饰的 getter 方法除 `self` 外不能有参数。下面这样写是错的：

```python
class Wrong:
    @property
    def value(self, scale):  # 错：getter 不能有额外参数
        return self._value * scale
```

`property` 在调用 `fget` 时只传 `obj` 本身，多出来的 `scale` 没人给，用的时候会报参数缺失。需要参数的逻辑做成普通方法（`def value(self, scale)`），别挂 property。

**错误二：调用时带括号**

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


c = Circle(2)
print(c.area)   # 对：12.56
print(c.area()) # 错：'float' object is not callable
```

`c.area` 已经是算好的值（float），再 `()` 就是把 float 当函数调用。记住：property 就是属性语法，不带括号。

**错误三：property 同名遮蔽实例属性**

```python
class Bad:
    def __init__(self):
        self.x = 1      # 想存一个 x

    @property
    def x(self):        # 类属性 x 是 property，会遮蔽实例属性
        return 2


b = Bad()  # 报错：AttributeError: can't set attribute
```

`__init__` 里 `self.x = 1` 会触发 property 的 `__set__`，而 `x` 是只读 property，于是赋值失败。property 是类属性（描述符），优先级高于实例属性，同名时实例属性赋值会被 property 拦截。这正是要用 `_x` + `x` 这种"下划线内部存储"模式的原因——避免同名冲突。

## 3. 最佳实践

### 3.1 内部存储与对外属性命名分离

固定用"下划线内部名 + property 对外名"的双层结构：内部 `self._name`，对外 `@property def name`。不要让 property 和它要操作的存储同名，否则会触发上面 2.8 的遮蔽错误。

推荐写法：

```python
class User:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        return self._name
```

不推荐写法（会报错或行为诡异）：

```python
class User:
    def __init__(self, name):
        self.name = name   # 被 property 拦截，只读时直接报错

    @property
    def name(self):
        return self.name   # 还会无限递归
```

### 3.2 不要为所有字段无脑加 property

property 是"需要时才加"的工具，不是"每个字段都套一层"的仪式。如果一个属性就是简单的数据存取、没有校验/计算/转换需求，直接用普通属性即可。过度使用 property 会让代码啰嗦、可读性下降，也增加维护负担。

推荐写法（无需逻辑时）：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

需要加逻辑时再升级为 property，调用方代码无需改动。这正是 Python 鼓励的"渐进式封装"。

### 3.3 getter 应尽量轻、无副作用

property getter 在语义上应接近"读取一个属性"，所以它应当是轻量的、幂等的、无副作用的。避免在 getter 里做这些事：

- 修改对象状态（`self._counter += 1` 之类），这会让"读取"产生副作用，违反最小惊讶原则。
- 抛出非预期的异常（偶尔的 ValueError 可以，但别让它变成主要逻辑路径）。
- 执行重型 I/O 或长计算（把每次 `obj.x` 都变成一次数据库查询是性能灾难，调用方会以为这只是个属性访问）。

如果确实需要重逻辑，要么改为显式方法（`obj.compute_x()`），要么用缓存（`cached_property`）并在文档里说清楚首次访问的成本。

### 3.4 计算属性记得标注不可缓存/可缓存

计算属性的"每次都算"特性在文档里写清楚，尤其当一个 property 看起来像存储属性时。否则调用方可能误以为它存了一份不变的值，在循环里反复访问导致重复计算。

推荐写法（在 docstring 里点明）：

```python
class Polygon:
    def __init__(self, points):
        self.points = points

    @property
    def perimeter(self):
        """周长：每次访问重新计算，点数多时注意性能"""
        total = 0.0
        for i in range(len(self.points)):
            x1, y1 = self.points[i]
            x2, y2 = self.points[(i + 1) % len(self.points)]
            total += ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5
        return total
```

### 3.5 只读 property 的"只读"应明示

只读 property 在文档里写明"只读"，避免调用方尝试赋值后踩 `AttributeError`。

```python
class Session:
    def __init__(self, token):
        self._token = token

    @property
    def token(self):
        """会话令牌（只读，不可外部修改）"""
        return self._token
```

### 3.6 演进策略：从普通属性起步

设计类时，先用最简单的普通属性。等以下任一情况出现，再把该属性升级为 property：

- 需要在读取时做计算或转换。
- 需要禁止外部赋值（只读）。
- 需要在赋值时加校验（此时需要 setter，跨到第 12 篇）。
- 需要对外保持接口稳定、内部想换存储形式。

由于 `obj.x` 这种调用形式对"普通属性"和"property"都成立，升级时调用方代码零改动，所以"先简单、再升级"是低风险的演进策略。

### 3.7 property 不要用于控制流

不要用 property 替代本应是方法的操作，尤其是有副作用或语义上是"动作"的。判断标准：如果它读起来像名词（`area`、`price`、`balance`），适合 property；如果读起来像动词（`save`、`send`、`compute_report`），适合方法。把 `save` 写成 `@property` 会让 `obj.save` 触发保存操作，语义错位且容易埋 bug。

## 4. 原理

### 4.1 property 是描述符

要理解 property 的工作原理，必须先了解 Python 的"描述符协议"（descriptor protocol）。简单说，描述符是一个实现了 `__get__`、`__set__`、`__delete__` 中某些方法的类，它的实例作为"类属性"存在时，Python 会对它的访问做特殊处理——不再是普通的属性查找，而是转去调用对应的协议方法。

`property` 就是 Python 内置的一种描述符。`property` 类（用 C 实现，但等价的 Python 伪代码可以写出来）大致长这样：

```python
class property:
    def __init__(self, fget=None, fset=None, fdel=None, doc=None):
        self.fget = fget
        self.fset = fset
        self.fdel = fdel
        self.__doc__ = doc

    def __get__(self, obj, objtype=None):
        if obj is None:           # 通过类访问（如 Circle.area）时返回 property 自己
            return self
        if self.fget is None:
            raise AttributeError("unreadable attribute")
        return self.fget(obj)     # 关键：调用 getter 函数，传入实例

    def __set__(self, obj, value):
        if self.fset is None:
            raise AttributeError("can't set attribute")  # 只读的关键
        self.fset(obj, value)

    def __delete__(self, obj):
        if self.fdel is None:
            raise AttributeError("can't delete attribute")
        self.fdel(obj)
```

这段伪代码揭示了 property 的全部行为：

- `__get__`：访问 `obj.x` 时被调用。如果是 `obj.x`（实例访问），`obj` 是实例，调用 `fget(obj)` 返回值；如果是 `Cls.x`（类访问），`obj` 是 `None`，返回 property 自己。
- `__set__`：`obj.x = v` 时被调用。没有 `fset` 就抛 `AttributeError: can't set attribute`，这就是"只读"的实现。
- `__delete__`：`del obj.x` 时被调用。没有 `fdel` 就抛 `AttributeError: can't delete attribute`。

所以 property 把"方法的调用"包装成"描述符协议方法的调用"，再让协议方法在"属性访问语法"下被 Python 自动触发，从而实现了"方法伪装成属性"。

### 4.2 @property 在类体里做了什么

当你在类体里写：

```python
class Circle:
    @property
    def area(self):
        return 3.14 * self.r ** 2
```

执行过程是这样的：

1. Python 先定义普通函数 `area`（和定义任何方法一样）。
2. `@property` 装饰器对 `area` 调用 `property(area)`，即 `property(fget=area)`，得到一个 `property` 实例。
3. 这个 `property` 实例被赋值给类名字空间里的 `area`。也就是说，`Circle.__dict__['area']` 现在不是一个函数，而是一个 `property` 对象。

可以验证：

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


print(type(Circle.__dict__['area']))
# 输出：<class 'property'>

print(isinstance(Circle.__dict__['area'], property))
# 输出：True
```

注意，普通方法在类的 `__dict__` 里就是普通函数，而 `area` 是 `property` 实例——这是 `@property` 改变了它的存放形态。

### 4.3 访问 obj.x 触发 __get__ 的完整链路

当外部代码写 `c.area` 时，Python 的属性查找过程（简化版）是这样的：

1. 先看 `type(c).__dict__`（即类 `Circle` 的字典）里有没有 `area`。有，而且它是个"数据描述符"（实现了 `__set__`，property 实现了 `__set__` 所以算数据描述符）。
2. 数据描述符的优先级高于实例 `__dict__`，所以 Python 直接调用描述符的 `__get__(c, Circle)`。
3. `property.__get__` 里，`obj` 是 `c`（非 None），于是调用 `self.fget(c)`，也就是你写的那段 `return 3.14 * self.r ** 2`，其中 `self` 是 `c`。
4. 方法体执行完，返回值就是 `c.area` 表达式的值。

关键点：描述符的 `__get__` 调用你的 getter，getter 的 `self` 就是触发访问的那个实例。这一切对你和调用方都透明——调用方只写了 `c.area`，Python 在背后完成了"找到描述符 → 调 `__get__` → 调 `fget(c)` → 返回"。

可以手动模拟这个过程来验证理解：

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


c = Circle(3)

# 普通访问
print(c.area)
# 输出：28.26

# 手动取出 property 描述符，手动调 __get__
prop = Circle.__dict__['area']
print(prop.__get__(c, Circle))
# 输出：28.26

# 通过类访问：obj 为 None，返回 property 自己
print(Circle.area)
# 输出：<property object at 0x...>
```

`c.area` 和 `prop.__get__(c, Circle)` 输出一致，证明 `c.area` 确实就是走了描述符的 `__get__`。

### 4.4 只读的实现：__set__ 抛 AttributeError

只读 property 之所以"只读"，是因为它没传 `fset`，于是 `property.__set__` 在被触发时直接抛 `AttributeError`。来看执行链路：

`c.area = 100` 这条赋值语句执行时：

1. Python 查 `type(c).__dict__['area']`，发现是数据描述符（有 `__set__`）。
2. 调用描述符的 `__set__(c, 100)`。
3. `property.__set__` 检查 `self.fset is None`（因为你只定义了 getter），是，于是 `raise AttributeError("can't set attribute")`。
4. 这个异常冒泡上去，`c.area = 100` 这一行就报了 `AttributeError`。

验证：

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


c = Circle(3)
prop = Circle.__dict__['area']

try:
    prop.__set__(c, 100)
except AttributeError as e:
    print(f"__set__ 抛出：{e}")
# 输出：__set__ 抛出：can't set attribute
```

可以看到，"只读"完全是描述符机制在 `__set__` 里主动抛异常实现的，和访问控制关键字无关。这也解释了为什么 property 能在赋值时给出标准 `AttributeError`——它是协议方法主动 raise 的。

**注意描述符优先级**

property 是"数据描述符"（实现了 `__set__`），数据描述符的优先级高于实例 `__dict__`。所以即使你在实例 `__dict__` 里塞一个同名 key，访问时仍会走 property：

```python
class C:
    @property
    def x(self):
        return "from property"


c = C()
# 试图在实例 __dict__ 里塞 x
c.__dict__['x'] = "from instance dict"
print(c.x)
# 输出：from property
```

`c.x` 还是返回 property 的结果，数据描述符优先级压过了实例字典。

### 4.5 property 统一了"属性访问"与"方法调用"

把前面几节串起来看，property 的本质是：在描述符层面，把"一段逻辑（方法）"挂到"属性访问语法"的触发链路上。

- 普通方法 `obj.foo()`：`foo` 在类 `__dict__` 里是函数，`obj.foo` 取出绑定方法，`()` 触发调用。
- property `obj.foo`：`foo` 在类 `__dict__` 里是 property（数据描述符），`obj.foo` 直接触发 `property.__get__`，里面调 `fget(obj)`，返回值就成了 `obj.foo` 的值。

两者在"最终都要调用一段 Python 逻辑"上是一样的，但 property 把"调用"这一步藏进了描述符协议，让外部看起来像在访问字段。这种统一的价值在于：你可以把"字段"和"计算逻辑"放在同一种访问语法下，从而在不改变调用接口的前提下，自由地在"直接存值"和"动态计算"之间切换。

换句话说，property 让 Python 的"属性"不再只是"一块存值的格子"，而可以是一个"会执行一段逻辑的入口"。这个入口对外是属性语法，对内是一段你可以随便写的方法体。封装的"内外解耦"由此达成。

### 4.6 通过类访问 property：返回 property 自己

一个细节：`Circle.area`（通过类访问，不是实例）不会触发 getter，而是返回 property 对象本身。这是因为描述符的 `__get__(self, obj, objtype)` 在 `obj is None` 时（类访问场景）按约定返回描述符自己。

```python
class Circle:
    def __init__(self, r):
        self.r = r

    @property
    def area(self):
        return 3.14 * self.r ** 2


print(Circle.area)
# 输出：<property object at 0x...>

# 拿到 property 后可以查它的 fget
print(Circle.area.fget)
# 输出：<function Circle.area at 0x...>
```

这个特性在你想用反射/getter 函数对象时有用（比如要给某个只读 property 后补 setter 时，可以通过 ` Circle.area.fget` 找回原 getter）。日常使用不太会碰到，但了解后能避免"`Circle.area` 为什么不是值"的困惑。

### 4.7 property 与继承

子类继承父类时，父类的 property 会被继承，描述符协议照常工作。子类可以通过重新定义同名 property 来覆盖父类的 getter（或者补上 setter/deleter）。

```python
class Shape:
    def __init__(self):
        pass

    @property
    def description(self):
        return "一个形状"


class Circle(Shape):
    @property
    def description(self):
        return "一个圆"


s = Shape()
c = Circle()
print(s.description)
print(c.description)
# 输出：
# 一个形状
# 一个圆
```

子类的 `description` 在 `Circle.__dict__` 里是一个新的 property，查找时优先于父类的，所以覆盖生效。这一行为和普通方法继承覆盖一致——property 在这件事上和普通属性/方法没有特殊之处。

### 4.8 完整调用链对照表

把 property 的几条关键路径汇总成一张表，便于复习：

| 外部写法 | 内部触发 | 结果 |
|---------|---------|------|
| `obj.x` | `type(obj).__dict__['x'].__get__(obj, type(obj))` | 调 `fget(obj)` 的返回值 |
| `Cls.x` | `Cls.__dict__['x'].__get__(None, Cls)` | property 对象本身（`obj is None` 分支） |
| `obj.x = v` | `type(obj).__dict__['x']__set__(obj, v)` | 有 `fset` 调 `fset(obj, v)`；无 `fset` 抛 `AttributeError: can't set attribute` |
| `del obj.x` | `type(obj).__dict__['x'].__delete__(obj)` | 有 `fdel` 调 `fdel(obj)`；无 `fdel` 抛 `AttributeError: can't delete attribute` |

这张表是本篇原理章的浓缩：property 的全部行为就是"描述符协议方法 + fget/fset/fdel 三段逻辑"的组合。

## 5. 总结

### 5.1 本文内容要点

- `property` 把方法调用伪装成属性访问，使 `obj.x` 自动触发一段 getter 逻辑，返回值即为属性值；调用方无需写 `obj.x()`。
- `@property` 装饰器装饰一个无参方法（除 `self`），方法名成为对外属性名，得到一个只读 property 对象存入类 `__dict__`。
- 计算属性：每次访问即时计算，适合完全由其它状态派生、计算不重的量，如 `Circle.area`/`Circle.circumference`。
- 只读属性：只定义 getter 不定义 setter 的 property 在赋值时抛 `AttributeError: can't set attribute`，从机制上阻止误改，如 `Account.balance`。
- 内外分离：用 `self._x` 做内部存储，用 `@property def x` 对外暴露，内部存储形式可变而对外接口稳定；典型如 `Temperature` 内部存开尔文、对外暴露摄氏/华氏。
- property 完整签名 `property(fget=None, fset=None, fdel=None, doc=None)`，`@property` 是只传 `fget` 的语法糖；setter/deleter 由第 12 篇展开。
- property 是描述符：实现了 `__get__`/`__set__`/`__delete__`，访问 `obj.x` 触发 `__get__` 调 `fget`，赋值触发 `__set__` 在无 `fset` 时抛 `AttributeError`，由此实现只读。
- property 在描述符层统一了"属性访问"与"方法调用"，使类设计者能在不改变调用接口的前提下，在"直接存值"和"动态计算/受控访问"之间平滑切换。

### 5.2 读完本文你应能掌握

- 能用 `@property` 正确定义只读 property，并说明 `obj.x` 不带括号、`obj.x()` 会报错的原因。
- 能判断什么场景该用计算属性（派生量、轻计算）、什么场景不该用（重计算需缓存），并写出如 `Circle.area` 这样的计算属性 demo。
- 能用"下划线内部存储 + property 对外暴露"模式实现只读封装（如 `Account.balance`），并解释这只读是"机制拦截 + 君子协定"，挡不住恶意绕过。
- 能用 property 做内部存储与对外接口的单位/格式转换（如 `Temperature` 内部开尔文、对外摄氏度），并说出这种解耦的工程价值。
- 能说明 `@property` 与 `property(fget, ...)` 三参形式的等价关系，能读、能写两种形式。
- 能从描述符协议角度讲清 `obj.x` 触发 `property.__get__` → 调 `fget(obj)` → 返回值，以及 `obj.x = v` 在无 `fset` 时由 `__set__` 抛 `AttributeError` 实现只读的完整链路。
- 能规避常见错误：getter 带参数、调用带括号、property 同名遮蔽实例属性、为无逻辑字段过度加 property、在 getter 里写副作用。
- 能陈述"先普通属性、必要时升级为 property"的渐进式封装策略，并解释为何升级时调用方代码零改动。
