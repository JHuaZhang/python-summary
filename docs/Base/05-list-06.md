## 1. 介绍

### 1.1 什么是 sort 与 sorted

`sort` 和 `sorted` 都用于对序列排序,但形态与语义截然不同,是 Python 列表排序的两面:

- **`list.sort(*, key=None, reverse=False)`**:列表的**方法**,**原地修改**调用它的列表,返回 `None`。排序后原列表内容被改变,不产生新列表。
- **`sorted(iterable, *, key=None, reverse=False)`**:内置**函数**,接收任意可迭代对象,**返回一个排好序的新列表**,不改原对象。

```python
nums = [3, 1, 4, 1, 5, 9, 2, 6]

# sort:原地改,返回 None
result = nums.sort()
print(result)          # None
print(nums)            # [1, 1, 2, 3, 4, 5, 6, 9] —— 原列表已变

names = ["banana", "apple", "cherry"]

# sorted:返回新列表,原对象不变
ordered = sorted(names)
print(ordered)         # ['apple', 'banana', 'cherry']
print(names)           # ['banana', 'apple', 'cherry'] —— 原列表未变
```

二者的核心区别总结为一句话:**`sort` 改自己、`sorted` 造新的**。这个区别决定了它们的适用场景、内存代价、以及能否用在元组/字符串等不可变序列上(只有 `sorted` 能)。

两者都**按升序**为默认,通过 `reverse=True` 改为降序;都用 `key` 参数指定"按什么排序"的映射函数;底层都用 **Timsort** 算法,稳定、O(n log n)。理解 `key`/`reverse` 的用法以及 Timsort 的稳定排序特性,是本篇的重点。

### 1.2 基本语法与最小用法

**`sort`** 是列表方法,无返回值:

```python
lst = [3, 1, 2]
lst.sort()             # 升序,原地
print(lst)             # [1, 2, 3]

lst.sort(reverse=True) # 降序,原地
print(lst)             # [3, 2, 1]
```

**`sorted`** 是内置函数,返回新列表:

```python
lst = [3, 1, 2]
new = sorted(lst)          # 升序,新列表
print(new, lst)            # [1, 2, 3] [3, 1, 2]

new_desc = sorted(lst, reverse=True)
print(new_desc)            # [3, 2, 1]

# sorted 还能接收任意可迭代对象,不只列表
print(sorted((3, 1, 2)))   # [1, 2, 3] —— 元组也行,返回列表
print(sorted("bca"))       # ['a', 'b', 'c'] —— 字符串拆成字符排序
print(sorted({3, 1, 2}))   # [1, 2, 3] —— 集合排序(顺序变确定)
```

**速查表**:

| 维度 | `list.sort()` | `sorted(iter)` |
|------|---------------|----------------|
| 形态 | 列表方法 | 内置函数 |
| 作用对象 | 只能是 `list` | 任意可迭代对象 |
| 是否原地 | 是(改原列表) | 否(产新列表) |
| 返回值 | `None` | 新 `list`(已排序) |
| 原对象是否变 | 变 | 不变 |
| 参数 | `key`, `reverse`(仅关键字) | `key`, `reverse`(仅关键字) |
| 典型用途 | 不需要原顺序、省内存 | 需保留原对象、处理元组/字符串 |

两者参数完全一致(`key=None, reverse=False`),区别只在"原地 vs 新建"和"能接收什么"。所以要先决定"要不要保留原对象":要保留 → `sorted`,不需要 → `sort`(省一次内存分配)。

### 1.3 为什么 sort 返回 None,而 sorted 返回列表

这是 Python "原地方法返回 None"约定的又一个实例(与 `append`/`extend`/`reverse` 同源):

```python
# ❌ 经典错误:sort 返回 None,赋值后丢失列表
nums = [3, 1, 2]
nums = nums.sort()        # nums 变 None!

# ✅ sort 原地改,无需重新赋值
nums = [3, 1, 2]
nums.sort()
print(nums)               # [1, 2, 3]
```

设计意图:**原地修改的方法返回 None,明确提醒调用方"我没有产生新对象"**,避免把"原地改"和"产生新对象"两种风格混用而浑然不觉。`sorted` 则是"纯函数"——不碰原对象、返回新值,适合函数式风格的链式表达。

```python
# sorted 适合链式 / 函数式
top3 = sorted(scores, reverse=True)[:3]   # 取前 3 高分

# sort 不行,因为返回 None
# scores.sort()[:3]   ❌ None 没法切片
scores.sort()
top3 = scores[-3:]                        # 必须分两步
```

记住口诀:**原地方法返回 None、纯函数返回新对象**。看到 `sort`/`reverse`/`append` 返回 `None`,就知道它在改自己;要用返回值做链式,选 `sorted`/`reversed`/`+`。

### 1.4 排序的稳定性与 Timsort 初识

Python 的 `sort`/`sorted` 底层用 **Timsort** 算法,它有两个对实战至关重要的特性:

- **稳定排序(stable)**:当两个元素"比较相等"时,它们的**相对顺序保持不变**(原列表中靠前的,排序后仍靠前)。
- **O(n log n) 最坏复杂度**,且对"已经部分有序"的数据接近 O(n)(因为 Timsort 善于识别已排好的段)。

稳定性是 `key` 函数能实现"多级排序"的关键——按第二关键字排一次、再按第一关键字排一次,最终结果按第一关键字为主、第二关键字为辅,且不依赖复杂的比较函数。本篇 2.5 节会展开。

```python
# 稳定性示例:按长度排序,长度相同的保持原顺序
words = ["apple", "pie", "kiwi", "fig", "pear"]
# 长度: 5       3     4     3     4
# 长度为3的有 pie,fig(原序 pie在前);长度为4的有 kiwi,pear(原序 kiwi在前)
result = sorted(words, key=len)
print(result)            # ['pie', 'fig', 'kiwi', 'pear', 'apple']
#                         长度3,原序保留     长度4,原序保留   长度5
```

`pie` 在 `fig` 之前(原列表中 `pie` 在前)、`kiwi` 在 `pear` 之前(原列表中 `kiwi` 在前)——稳定性保证了相同 key 元素不被打乱。若 Timsort 不稳定,这些同长度元素的相对顺序就可能颠倒。

## 2. 核心内容

本章逐节详解 `sort`/`sorted` 的原地与新对象语义、`key` 函数、`reverse`、多级排序(稳定性)、不同类型排序、`reverse` 与 `reversed` 区别、以及性能。每节遵循"文字详解 → demo → 运行结果说明 → 陷阱"。

### 2.1 sort:原地排序,返回 None

`list.sort()` 直接对调用它的列表进行排序,排序结果**覆盖**原列表内容,列表对象的 `id` 不变(仍是同一个 list 对象),长度不变,只是元素顺序变了。

```python
nums = [5, 2, 8, 1, 9]
old_id = id(nums)
nums.sort()
print(nums)                  # [1, 2, 5, 8, 9]
print(id(nums) == old_id)    # True —— 同一个对象,原地改

# 降序
nums.sort(reverse=True)
print(nums)                  # [9, 8, 5, 2, 1]
```

**仅 list 有 `sort` 方法**:

```python
t = (3, 1, 2)
# t.sort()   ❌ AttributeError: tuple 没有 sort 方法(不可变,不能原地改)
```

元组、字符串、`frozenset` 等不可变序列没有 `sort` 方法,因为原地修改对它们无意义。要排它们,只能用 `sorted`(返回新列表)。

**何时用 `sort`**:

- 你**不再需要**原顺序,排序结果就是要的结果;
- 数据量大、想省一次新列表的内存分配;
- 在数据处理的中途步骤,只想把当前列表理顺。

```python
# 读取一批成绩,排序后逐个处理
scores = read_scores()
scores.sort()                # 原地理顺,不再需要原始顺序
for s in scores:
    process(s)
```

**返回值陷阱**:再次强调,`sort` 返回 `None`,任何 `lst = lst.sort()` 都会把 `lst` 变 `None`。需要拿"排好序的副本且保留原列表"时,用 `sorted(lst)` 或 `lst[:]` 拷贝后再 `sort`。

### 2.2 sorted:返回新列表,适用任意可迭代对象

`sorted(iterable)` 接收任意可迭代对象,返回一个**新的、排好序的 list**。原对象不被触碰。这是它与 `sort` 最实质的差异,也使它适用范围更广。

```python
# 列表:保留原列表
nums = [3, 1, 2]
ordered = sorted(nums)
print(ordered, nums)         # [1, 2, 3] [3, 1, 2]

# 元组:返回列表(元组不可变,无法 sort)
t = (3, 1, 2)
print(sorted(t))             # [1, 2, 3]

# 字符串:拆成字符排序
print(sorted("python"))      # ['h', 'n', 'o', 'p', 't', 'y']

# 集合:排序后顺序确定(集合本身无序)
print(sorted({3, 1, 2}))     # [1, 2, 3]

# 字典:默认对键排序
d = {"b": 2, "a": 1, "c": 3}
print(sorted(d))                      # ['a', 'b', 'c']
print(sorted(d.items()))              # [('a',1),('b',2),('c',3)] —— 按 key 排键值对

# 生成器:消耗并排序
gen = (3, 1, 2)
print(sorted(gen))            # [1, 2, 3]
```

`sorted` 总是返回 `list`(即使输入是元组、字符串、生成器)——这是它的"归一化"输出。要得到排好序的元组,`tuple(sorted(t))`;要得到字符串,`"".join(sorted(s))`。

**何时用 `sorted`**:

- 需要**保留原对象**不变(函数式风格、纯函数、不想有副作用);
- 对象是元组/字符串/集合等**非 list** 可迭代对象;
- 想用返回值做链式表达(`sorted(x)[:3]`)。

```python
# 用户列表显示:不想改原始数据,只想要一份排好序的副本
users = load_users()
display(sorted(users, key=attrgetter("name")))   # 原数据不动
```

### 2.3 key 函数:按"映射值"排序

`key` 是 `sort`/`sorted` 最强大的参数。它接收一个**函数**,对每个元素调用一次,得到一个"排序键";排序时比较的是这些键,而非元素本身。元素本身的位置据键的顺序排列。

**基本用法**:

```python
words = ["banana", "apple", "cherry", "fig"]

# 按字典序(默认,等价于 key=identity)
print(sorted(words))                 # ['apple', 'banana', 'cherry', 'fig']

# 按长度排序
print(sorted(words, key=len))        # ['fig', 'apple', 'banana', 'cherry']
#                                     长度3  长度5    长度6     长度6
```

`key=len` 让每个词先过 `len()` 得到长度(3,5,6,6),再按长度排,长度相同的(原列表中靠前的)保持原序——稳定性。

**对复杂对象按属性排序**:

```python
students = [
    {"name": "Alice", "age": 30, "gpa": 3.8},
    {"name": "Bob", "age": 25, "gpa": 3.5},
    {"name": "Carol", "age": 28, "gpa": 3.9},
]

# 按年龄升序
by_age = sorted(students, key=lambda s: s["age"])
print([s["name"] for s in by_age])   # ['Bob', 'Carol', 'Alice']

# 按 GPA 降序
by_gpa = sorted(students, key=lambda s: s["gpa"], reverse=True)
print([s["name"] for s in by_gpa])   # ['Carol', 'Alice', 'Bob']
```

`lambda s: s["age"]` 是把每个字典映射到其 `age` 值,排序时比较年龄。`key` 只负责"算键",不负责比较逻辑——比较由 Timsort 内部按键的自然顺序进行。

**用 `operator` 模块替代 lambda**(更快、更可读):

```python
from operator import itemgetter, attrgetter

# 字典列表:itemgetter 取指定键
by_age = sorted(students, key=itemgetter("age"))

# 对象列表:attrgetter 取属性
class Student:
    def __init__(self, name, gpa): self.name, self.gpa = name, gpa
objs = [Student("Alice", 3.8), Student("Bob", 3.5)]
by_gpa = sorted(objs, key=attrgetter("gpa"))
```

`itemgetter("age")` 等价于 `lambda s: s["age"]`,但在 C 层实现,比 Python 层 lambda 略快,且表达"取某键/属性"更直白。

**key 是"每元素调一次",不是"对整个列表调一次"**:

```python
# key 函数签名:接收单个元素,返回单个键
sorted(words, key=len)          # len 对每个词调一次,不是 len(words)
```

这点常被新手误解。`key` 的函数是 `T -> K`(元素到键),不是 `[T] -> K`(整个列表到键)。

### 2.4 reverse:降序,且不影响稳定性

`reverse=False`(默认)升序,`reverse=True` 降序。`reverse` 的实现并非"排好序后整个颠倒",而是 Timsort 在比较时反转方向——这意味着**稳定性依旧保持**:相等元素的原相对顺序不变。

```python
data = [("A", 1), ("B", 1), ("C", 2), ("D", 2)]

# 升序:按第二个元素
asc = sorted(data, key=lambda x: x[1])
print(asc)    # [('A',1),('B',1),('C',2),('D',2)] —— A,B 原序保留;C,D 原序保留

# 降序:按第二个元素
desc = sorted(data, key=lambda x: x[1], reverse=True)
print(desc)   # [('C',2),('D',2),('A',1),('B',1)] —— C,D 原序仍保留!不是 D,C
```

注意降序结果中 `C` 仍在 `D` 前(原列表中 `C` 在前),`A` 仍在 `B` 前——`reverse` 反转的是"键的大小顺序",**不反转**相等键元素的相对顺序。这是稳定排序的关键性质,也是新手常误以为"降序会把相等元素也倒过来"的纠正点。

若你确实想让相等元素也**反序**(如完全按输入逆序),那是另一回事:可以先 `reverse` 列表再排,或用自定义 `cmp`(Python 3 已移除 `cmp` 参数,改用 `functools.cmp_to_key`),但绝大多数场景稳定性正是想要的。

**用负 key 模拟降序(仅数值型)**:

```python
nums = [3, 1, 4, 1, 5]
# 降序:用 reverse=True
print(sorted(nums, reverse=True))     # [5, 4, 3, 1, 1]

# 也可用负 key(仅限数值)
print(sorted(nums, key=lambda x: -x)) # [5, 4, 3, 1, 1]
```

负 key 与 `reverse=True` 对纯数值等价,但 `reverse=True` 更通用(任意可比较类型都行)、更可读。负 key 只在对 key 做更复杂变换时偶尔有用(如"按某个字段降序、其他字段升序"的多级排序,见 2.5)。

### 2.5 多级排序:利用稳定性,逐级 sort

当要按多个关键字排序(如先按年龄、年龄相同再按 GPA),用稳定排序可以"从低优先级到高优先级"连续排多次,**最后一次排的是主关键字**。这是稳定排序最经典的实用技巧。

```python
students = [
    {"name": "Alice", "age": 25, "gpa": 3.5},
    {"name": "Bob",   "age": 25, "gpa": 3.9},
    {"name": "Carol", "age": 30, "gpa": 3.5},
    {"name": "Dave",  "age": 25, "gpa": 3.5},
]

# 目标:先按 age 升序,age 相同再按 gpa 降序

# 方法一:连续 sort(稳定排序的威力)
# 先排次要关键字 gpa(降序)
students_sorted = sorted(students, key=lambda s: s["gpa"], reverse=True)
# 再排主关键字 age(升序)——age 相同的,gpa 的相对顺序被保留
students_sorted = sorted(students_sorted, key=lambda s: s["age"])
print([(s["name"], s["age"], s["gpa"]) for s in students_sorted])
# [('Alice',25,3.5),('Dave',25,3.5),('Bob',25,3.9),('Carol',30,3.5)]
# age=25 的三个里:gpa 仍按 3.5,3.5,3.9 的降序排列(因为先排了 gpa 降序)
```

**为什么能这样?** 最后一次排序按 `age` 升序,`age` 相同的元素之间,Timsort 因稳定而保持它们"上一轮排好的 gpa 顺序"。所以多级排序的口诀是:**先排次要的,再排主要的**。

**方法二:返回元组作为 key(更简洁)**:

```python
# 元组比较是从左到右逐项比较
# (age, -gpa):age 升序,gpa 因取负而降序
students_sorted = sorted(students, key=lambda s: (s["age"], -s["gpa"]))
print([(s["name"], s["age"], s["gpa"]) for s in students_sorted])
# [('Alice',25,3.5),('Dave',25,3.5),('Bob',25,3.9),('Carol',30,3.5)]
```

元组 `key` 是更常用的写法:元组的比较规则是"逐项比较,第一项决定则停,否则看下一项",天然表达"多级排序"。但要**混用升降序**(如 age 升、gpa 降)时,得对降序字段做变换(取负适用于数值;字符串等非数值要另想办法,如把字符串反转或用 `ord` 映射)。

**混用升降序的非数值处理**:当降序字段是不可"取负"的类型(如字符串),元组 key 难以直接表达降序,这时回到"连续 sort"法更稳妥:

```python
# 按部门升序,部门相同按姓名降序
emps = [("Eng","Alice"),("Eng","Bob"),("Eng","Carol"),("Sales","Dave")]
by_name_desc = sorted(emps, key=lambda e: e[1], reverse=True)  # 姓名降序
final = sorted(by_name_desc, key=lambda e: e[0])              # 部门升序(主)
print(final)   # [('Eng','Carol'),('Eng','Bob'),('Eng','Alice'),('Sales','Dave')]
```

姓名降序因先排且稳定,在部门分组内被保留。详见《列表推导式》和标准库 `operator`、`functools.cmp_to_key` 章节。

### 2.6 不同类型元素的排序限制

Python 3 中,**不同类型之间默认不能比较**——`int` 与 `str` 比较、`str` 与 `None` 比较都会抛 `TypeError`。这比 Python 2(有隐式跨类型排序规则)更严格。

```python
mixed = [3, "1", 2, "2"]

try:
    sorted(mixed)          # int 与 str 混排 → TypeError
except TypeError as e:
    print(e)               # '<' not supported between instances of 'str' and 'int'
```

Python 2 会按"类型名"做隐式排序,Python 3 直接禁止,逼你显式处理。处理方式是用 `key` 把异类元素统一成可比较的形式:

```python
mixed = [3, "1", 2, "2", None]

# 统一转成字符串后排序
print(sorted(mixed, key=str))    # [None, 2, 3, '1', '2'](None 的 str 是 "None")
# 注意:str(None)='None',所以结果里 None 被当作 'None' 排到中间

# 或按"先类型名、再值"的元组排序,让同类聚一起
print(sorted(mixed, key=lambda x: (type(x).__name__, x) if x is not None else ("NoneType", "")))
# 先按类型名分组,组内按值
```

**含 None 的数值列表**:常见于数据库查询结果,`None` 与 `int` 不能直接比。用 `key` 把 `None` 映射成"极值":

```python
nums = [3, None, 1, 5, None, 2]
# 把 None 视为最大(排到末尾)
print(sorted(nums, key=lambda x: float("inf") if x is None else x))
# [1, 2, 3, 5, None, None]
```

异类/含 None 数据的排序,核心是"用 `key` 把元素归一化到同一可比类型",而不是依赖默认比较。

### 2.7 sort/reverse=True 与 reversed、list.reverse 的区别

排序相关的几个操作容易混淆,这里统一厘清:

| 操作 | 作用 | 是否排序 | 原地/新对象 | 返回值 |
|------|------|---------|-----------|--------|
| `lst.sort()` | 按大小排序 | 是(升序/降序) | 原地 | `None` |
| `sorted(lst)` | 按大小排序 | 是 | 新 list | 新 list |
| `lst.sort(reverse=True)` | 按大小**降序**排序 | 是 | 原地 | `None` |
| `lst.reverse()` | **反转**当前顺序(不排序) | 否 | 原地 | `None` |
| `reversed(lst)` | 反转(迭代器) | 否 | 新迭代器 | 迭代器 |
| `lst[::-1]` | 反转(切片) | 否 | 新 list | 新 list |

**`sort(reverse=True)` 与 `reverse()` 完全不同**:

```python
nums = [3, 1, 4, 1, 5]

nums.sort(reverse=True)   # 降序排序:按大小从大到小
print(nums)               # [5, 4, 3, 1, 1]

nums.reverse()            # 反转当前顺序(不排序):把列表首尾颠倒
print(nums)               # [1, 1, 3, 4, 5] —— 只是把上面结果倒过来
```

`reverse()` 只是把列表"首尾颠倒",不比较大小;`sort(reverse=True)` 是按值从大到小排。对已是升序的列表,`sort(reverse=True)` 和 `reverse()` 结果相同(因为降序=升序反转),但对乱序列表二者天差地别。

**`reversed` 返回迭代器,不返回列表**:

```python
nums = [3, 1, 2]
r = reversed(nums)        # 迭代器,惰性
print(list(r))            # [2, 1, 3]
print(nums)               # [3, 1, 2] —— 原列表不变
```

`reversed` 区别于 `sorted`:它反转顺序但不排序、返回惰性迭代器(省内存)、且要求对象是序列(有 `__reversed__` 或支持 `__len__`+`__getitem__`)。详见《reverse原地反转与reversed迭代器》。

### 2.8 性能:Timsort 与时间/空间复杂度

`sort`/`sorted` 底层都是 **Timsort**(Tim Peters 为 Python 设计,Java/Android/V8 等也采用),性能特征:

- **最坏 O(n log n)**,平均 O(n log n),**最好接近 O(n)**(对已部分有序的数据)。
- **稳定排序**(用归并策略处理相等元素)。
- **空间 O(n)**:Timsort 需要临时空间(归并段),`sorted` 还要额外分配结果列表。

**对已排好序的数据,Timsort 几乎是 O(n)**:

```python
import timeit

# 乱序数据
import random
random_data = list(range(100000)); random.shuffle(random_data)
print(timeit.timeit(lambda: sorted(random_data), number=10))   # 较慢

# 已升序数据:Timsort 识别出有序段,接近 O(n)
sorted_data = list(range(100000))
print(timeit.timeit(lambda: sorted(sorted_data), number=10))   # 快很多
```

所以"先排序、后续多次查询"的预排序成本,在最坏情况下是 O(n log n) 一次性投入。

**`sort` 比 `sorted` 省内存**:`sort` 原地修改,只需 Timsort 的临时空间;`sorted` 要新建结果列表(额外 n 个引用)+ 临时空间。对大列表且不需保留原序时,`sort` 更省。

**key 函数的调用开销**:`key` 对每个元素调一次,n 个元素就 n 氃调用。若 `key` 是 Python 层 lambda,这 n 次调用有开销;Timsort 优化为**对每个元素只调一次 `key`**(称为 decorate-sort-undecorate / Schwartzian 变换),结果缓存起来用于后续比较,所以 key 不会在每次比较时重复调用——这是 `key` 比"自定义比较函数"快的关键。

```python
# key=len:对 n 个词各调一次 len,而非每次比较都调
sorted(words, key=len)     # n 次 len 调用,总共 O(n) 次 key 计算
```

对比 Python 2 时代的 `cmp` 参数(每次比较都调 cmp,可能 O(n log n) 次调用),`key` 把 key 计算摊到 O(n) 次,显著更快。这也是 Python 3 移除 `cmp` 的原因——`key` 在大多数场景更优,复杂比较可用 `functools.cmp_to_key` 转换。

### 2.9 key 的进阶用法

**多字段元组 key**:

```python
# 同时按年龄、姓名排序(都升序)
people = [("Bob",25),("Alice",25),("Carol",30)]
print(sorted(people, key=lambda p: (p[1], p[0])))
# [('Alice',25),('Bob',25),('Carol',30)]
```

**`itemgetter` 取多字段**(等价于元组 lambda):

```python
from operator import itemgetter
print(sorted(people, key=itemgetter(1, 0)))   # 同上
```

`itemgetter(1, 0)` 返回 `(p[1], p[0])`,与 lambda 等价但更快。

**方法作 key**:

```python
# 按字符串的小写形式排序(忽略大小写)
names = ["Bob", "alice", "Carol", "dave"]
print(sorted(names, key=str.lower))
# ['alice', 'Bob', 'Carol', 'dave'] —— 大小写不敏感,稳定保持原相对顺序
```

`str.lower` 作为 key 函数,等价于 `lambda s: s.lower()`。这是"函数即对象"的体现——方法本身可以作为 `key` 传入。

**`functools.cmp_to_key` 处理复杂比较**(当 `key` 难以表达比较逻辑时):

```python
from functools import cmp_to_key

# 自定义比较:按"约数个数"排序(无法简单映射成 key)
def count_divisors(n):
    return sum(1 for i in range(1, n+1) if n % i == 0)

nums = [12, 7, 6, 28]
# 比较函数:旧式 cmp(a,b) 返回负/零/正
def cmp_divisors(a, b):
    return count_divisors(a) - count_divisors(b)

print(sorted(nums, key=cmp_to_key(cmp_divisors)))   # [7, 6, 12, 28]
```

`cmp_to_key` 把旧式比较函数包装成 `key` 对象,适合比较逻辑无法简化为"映射值"的场景。但常规排序应优先用 `key`+元组,`cmp_to_key` 是兜底方案。

## 3. 最佳实践

### 3.1 需保留原对象用 sorted,不需要用 sort

```python
# ✅ 不需要原序、省内存:sort
nums.sort()

# ✅ 需保留原对象 / 处理非 list:sorted
ordered = sorted(nums)
```

选型一句话:**"还要不要原始顺序?"** 要 → `sorted`,不要 → `sort`。函数式、纯函数代码倾向 `sorted`;数据处理中段倾向 `sort`(省内存)。

### 3.2 不要把 sort/reverse 的返回值赋回变量

```python
# ❌ sort 返回 None
nums = nums.sort()

# ❌ reverse 返回 None
nums = nums.reverse()

# ✅ 原地调用,不接收
nums.sort()
```

`sort`、`reverse`、`append` 等原地方法都返回 `None`。需要"排好序的副本"用 `sorted`;需要"反转的副本"用 `lst[::-1]` 或 `list(reversed(lst))`。

### 3.3 排序用 key,不要用 cmp(已移除)

```python
# ✅ key 函数:每个元素算一次键
sorted(students, key=lambda s: s["age"])

# ❌ cmp 参数在 Python 3 已移除
# sorted(students, cmp=lambda a,b: a["age"]-b["age"])   SyntaxError/TypeError

# 复杂比较兜底用 cmp_to_key
from functools import cmp_to_key
sorted(nums, key=cmp_to_key(my_cmp))
```

`key` 比 `cmp` 快(key 算 O(n) 次,cmp 算 O(n log n) 次)、更易读。Python 3 强制 `key`,旧 cmp 代码用 `cmp_to_key` 迁移,但新代码应直接写 `key`。

### 3.4 多级排序优先用元组 key,混升降序用连续稳定 sort

```python
# ✅ 纯升序/纯降序多级:元组 key 一行搞定
sorted(rows, key=lambda r: (r["dept"], r["name"]))

# ✅ 混升降序:数值降序字段取负
sorted(rows, key=lambda r: (r["dept"], -r["salary"]))   # 部门升,薪水降

# ✅ 混升降序非数值:连续稳定 sort(先次要、再主要)
tmp = sorted(rows, key=lambda r: r["name"], reverse=True)   # 姓名降
final = sorted(tmp, key=lambda r: r["dept"])                # 部门升(主)
```

元组 key 简洁但"降序"依赖能取负(限数值);连续 sort 通用但需两步。按字段类型选。

### 3.5 异类/含 None 数据:用 key 归一化,别依赖默认比较

```python
# 含 None 的数值:把 None 映射成极值
sorted(values, key=lambda v: float("inf") if v is None else v)

# 异类混合:转字符串统一
sorted(mixed, key=str)
```

Python 3 严格,跨类型直接排会 `TypeError`。用 `key` 把元素映射到可比类型,排序才稳。

### 3.6 处理大列表排序省内存用 sort;需要副本时 sorted 多一次分配要心中有数

```python
# 大列表、不需原序:sort 原地,省一份 n 引用的内存
big.sort()

# 需要副本:sorted 多分配一份结果列表
ordered = sorted(big)   # 内存约为 big 的两倍(原 + 新)
```

`sorted` 对极大列表可能接近 2 倍内存(原对象 + 新列表)。内存敏感场景优先 `sort`。

### 3.7 只取前 N 名用 sort + 切片,但超大数据可考虑 heapq

```python
# 小数据:直接排序取前 N
top10 = sorted(scores, reverse=True)[:10]

# 超大数据、只需前 N:heapq.nlargest 更省(O(n log k))
import heapq
top10 = heapq.nlargest(10, scores)
```

`sorted` 是 O(n log n) 全排;`heapq.nlargest` / `nsmallest` 是 O(n log k)(k 为取的数量),n 远大于 k 时更快、内存更省。详见《标准库精讲》`heapq`。

### 3.8 字典排序:明确排键、排值还是排键值对

```python
d = {"b": 2, "a": 3, "c": 1}

# 排键
print(sorted(d))                          # ['a','b','c']

# 按值排序(返回键)
print(sorted(d, key=d.get))               # ['c','b','a']

# 按值排序的键值对
print(sorted(d.items(), key=lambda kv: kv[1]))   # [('c',1),('b',2),('a',3)]
```

字典默认 `sorted` 排键;排值需用 `key=d.get`;要保留对应关系排 `d.items()`。常被搞混,意图要明确。详见《字典深度剖析》。

### 3.9 key 函数不要有副作用或依赖外部可变状态

```python
# ⚠️ key 依赖可变外部状态,排序结果不确定
counter = {"Alice": 0}
sorted(names, key=lambda n: counter[n] if n in counter else 0)   # 若 counter 被并发改,结果飘

# ✅ key 应是纯函数:给定元素,确定返回键
sorted(names, key=lambda n: len(n))
```

`key` 在排序期间被调用,应是无副作用的纯映射。依赖外部可变状态会让排序结果不可预期,尤其多线程下。

### 3.10 对不可变序列排序用 sorted,不要试图转 list 再 sort

```python
# ✅ 元组排序:sorted 直接返回新列表
t = (3, 1, 2)
ordered = sorted(t)            # [1, 2, 3]

# ❌ 绕弯:转 list、sort、再转回
tmp = list(t); tmp.sort(); ordered = tuple(tmp)   # 啰嗦
ordered = tuple(sorted(t))     # 想要元组结果时这样写即可
```

`sorted` 对任意可迭代都返回 `list`,要元组/字符串结果再包一层 `tuple(...)` / `"".join(...)`。不需要绕道 `list.sort`。

## 4. 原理

### 4.1 Timsort 概览:归并 + 插入的混合稳定排序

Timsort 是 Tim Peters 在 2002 年为 Python 设计的排序算法,核心思想是**识别并利用数据中已存在的有序段(run)**,再把这些 run 归并起来。它结合了归并排序(稳定、O(n log n))和插入排序(对小段高效)的优点。

**算法骨架**(简化):

1. **扫描并提取 run**:从左到右扫描数据,识别连续的升序或降序段(run)。降序段被原地反转为升序。
2. **run 太短则用插入排序补长**:若 run 短于某个阈值(minrun,通常 32~64),用插入排序把后续元素并入,凑成一个 minrun 长度的 run。
3. **归并**:把 run 压入栈,维护栈上 run 的长度不变式(类似"维持归并树平衡"),当满足归并条件时归并相邻 run。
4. **收尾**:数据扫完后,把栈上剩余 run 逐对归并,得到最终有序结果。

关键性质:

- **稳定**:归并时对相等元素保持原相对顺序(归并段内已有序,归并取左段优先)。
- **对已有序数据接近 O(n)**:若数据已升序,Timsort 只识别出几个大 run,几乎只做扫描不做归并;若已降序,识别后反转,也接近 O(n)。
- **最坏 O(n log n)**:归并的复杂度上界。
- **空间 O(n)**:归并需要临时缓冲区,但比朴素归并更省(只对归并的两段中较短者分配缓冲)。

这就是 `sort`/`sorted` 在"几乎有序"数据上飞快、在最坏数据上仍可靠的根源。

### 4.2 稳定性如何实现:归并时"左优先"

Timsort 的稳定性来自归并步骤的约定:当归并两个 run(左 run L、右 run R)时,若 `L[i] == R[j]`,**优先取左 run 的元素**。这样原列表中靠前的相等元素仍排在靠前位置。

```python
# 归并稳定性的概念示意
def merge_stable(L, R):
    result = []
    i = j = 0
    while i < len(L) and j < len(R):
        if L[i] <= R[j]:       # ⚠️ 注意是 <=,相等时取左 → 稳定
            result.append(L[i]); i += 1
        else:
            result.append(R[j]); j += 1
    result.extend(L[i:]); result.extend(R[j:])
    return result
```

`<=`(而非 `<`)是稳定的关键:相等时让左 run 先出。若用 `<`,相等时取右 run,就会破坏稳定性。Timsort 内部的归并严格遵循"左优先",保证排序结果中相等元素保持原序。

这条性质是多级排序(2.5 节)能成立的基础:**先排次要键、再排主键,主键相等的元素里,次要键的相对顺序被稳定地保留**。

### 4.3 Schwartzian 变换:为什么 key 比 cmp 快

`key` 参数的实现采用 **Schwartzian 变换**(decorate-sort-undecorate),把"对每个元素算键"与"比较排序"解耦:

```python
# 概念实现
def sorted_with_key(iterable, key):
    # 1. decorate:对每个元素算一次键,得到 (key, 原元素) 列表
    decorated = [(key(x), x) for x in iterable]   # key 调用 n 次

    # 2. sort:对 decorated 按键排序(比较的是已算好的键,不再调 key)
    decorated.sort(key=lambda pair: pair[0])

    # 3. undecorate:取出原元素
    return [x for (_, x) in decorated]
```

关键:**`key` 函数总共只调用 n 次**(每个元素一次),后续 O(n log n) 次比较都直接比较已算好的键,不再回调 `key`。

对比旧式 `cmp` 参数:

```python
# cmp 的概念实现(已废弃)
def sorted_with_cmp(iterable, cmp):
    # 每次比较都调 cmp,O(n log n) 次回调
    ...bubble/merge using cmp(a, b)...   # cmp 被调用 O(n log n) 次
```

`cmp` 在每次比较时调用比较函数,共 O(n log n) 次回调;`key` 只有 n 次。当 `key`/`cmp` 函数本身较重(如解析字符串、查表)时,`n` 与 `n log n` 的差距巨大。这就是 Python 3 移除 `cmp`、主推 `key` 的性能原因,也是"能用 key 就别用 cmp"的最佳实践依据。

### 4.4 reverse 如何在保持稳定性的前提下降序

`reverse=True` 不是"排完再整体翻转列表"(那会破坏稳定性),而是 Timsort 在归并比较时**反转比较方向**:本应"`L[i] <= R[j]` 取左"变成"`R[j] <= L[i]` 取右"的镜像。

```c
// 简化:reverse 影响比较方向,但不改变相等元素的取法
compare(a, b, reverse):
    c = a < b ? -1 : (a > b ? 1 : 0)
    return reverse ? -c : c   // reverse 时取反
// 归并时:相等(c==0)无论 reverse 与否,都"取左"(稳定)
```

关键:对**相等**元素(c==0),`reverse` 不改变取法(仍取左 run),所以相等元素的相对顺序不被反转;`reverse` 只反转"键的大小判断",让大的排前。这就是为什么 2.4 节中降序结果里相等键元素仍保持原序。

若用"排完再 `list.reverse()`"实现降序,则相等元素顺序会被整体翻转,破坏稳定性——所以 Python 用"比较方向反转"而非"结果翻转"来实现 reverse,正是为了保住稳定性这条关键性质。

### 4.5 sort 原地与 sorted 新建的实现差异

`list.sort()` 和 `sorted()` 共享同一套 Timsort 核心代码,差异在"数据从哪来、结果放哪去":

```c
// list.sort:数据来自 self,结果写回 self
list_sort(self, key, reverse) {
    // 直接在 self->ob_item 上跑 Timsort
    timsort(self->ob_item, self->ob_size, key, reverse);
    // 结果已在 self 中,返回 None
    Py_RETURN_NONE;
}

// sorted:数据来自任意 iterable,结果放新 list
sorted(iterable, key, reverse) {
    // 1. 把 iterable 物化为新 list(遍历收集)
    result = list_from_iterable(iterable);   // O(n) 分配 + 复制
    // 2. 在新 list 上跑 Timsort
    timsort(result->ob_item, result->ob_size, key, reverse);
    // 3. 返回新 list
    return result;
}
```

因此:

- **`sort` 省一次分配**:不新建列表,只在原 `ob_item` 数组上排序,内存只有 Timsort 的临时缓冲。
- **`sorted` 多一次分配**:先 `list(iterable)` 物化成新 list(O(n) 复制),再排序。对极大列表,这是额外一份 n 引用的内存。
- **`sorted` 能接收任意可迭代**:因为它先物化,元组/字符串/生成器都能进;`sort` 只能对已有的 list 调用,故只 list 有此方法。

这也解释了 `sort` 为何返回 `None`(原地,无新对象可返)、`sorted` 为何返回 list(新建,自然返回它):两个设计的差异在实现上一脉相承。

### 4.6 元组 key 的比较规则:逐项短路

元组作为 `key` 能表达多级排序,源于元组的**逐项比较**规则:从左到右逐项比较,第一对"不相等"的项决定整个元组的比较结果,后面的项不再看(短路);全部相等则两元组相等。

```python
# 元组比较的等价逻辑
def tuple_cmp(a, b):
    for x, y in zip(a, b):
        if x != y:
            return -1 if x < y else 1   # 第一处不等决定结果,短路
    # 所有对应项都相等(或长度不同)
    return 0 if len(a) == len(b) else (-1 if len(a) < len(b) else 1)
```

```python
print((1, "b") < (1, "a"))     # False —— 第一项都1相等,比第二项 'b' vs 'a'
print((1, 2) < (2, 1))         # True  —— 第一项 1<2,直接决定,不看第二项
print((1, 2, 3) < (1, 2))      # False —— 前两项相等,但前者更长
```

这条规则让 `key=lambda r: (r["dept"], r["name"])` 自然实现"先按 dept、dept 相同按 name":元组比较先看 dept 项,dept 相等再看 name 项。混升降序之所以要"取负"或"连续 sort",是因为元组比较每项都用同一方向(都升序),无法在元组内对某项单独反向——这是元组 key 的固有限制,也是连续稳定 sort 仍有用武之地的原因。

## 5. 总结

### 5.1 本文内容回顾

- **核心区别**:`list.sort()` 原地修改、返回 `None`、只能作用于 `list`;`sorted(iterable)` 返回新 `list`、不改原对象、可接收任意可迭代对象。选型一句话:"还要不要原序"——要 → `sorted`,不要 → `sort`。

- **原地约定**:`sort` 返回 `None` 是 Python 原地方法约定的一部分,提醒"没产生新对象"。需链式/纯函数用 `sorted`。

- **key 函数**:`key` 接收一个函数,对每个元素算键,排序比较的是键而非元素。元组 key 表达多级排序,`itemgetter`/`attrgetter` 比 lambda 更快更直白。Schwartzian 变换使 `key` 只调 n 次,比旧 `cmp`(O(n log n) 次)快得多,故 Python 3 移除 `cmp`、主推 `key`。

- **reverse**:`reverse=True` 降序,通过反转比较方向实现,**不破坏稳定性**——相等元素的相对顺序仍保持。负 key 仅对数值等效于降序,通用场景用 `reverse=True`。

- **稳定性与多级排序**:Timsort 是稳定排序,相等元素保持原相对顺序。多级排序:纯升/纯降用元组 key;混升降序用"先排次要、再排主要"的连续稳定 sort。

- **类型限制**:Python 3 禁止异类默认比较(int≠str 抛 `TypeError`),含 None 数据无法直接排,均需用 `key` 归一化到可比类型。

- **易混操作**:`sort(reverse=True)`(降序排序)≠ `reverse()`(只反转不排序);`reversed` 返回惰性迭代器、`sorted` 返回新列表、`lst[::-1]` 返回反转新列表。

- **性能**:Timsort 最坏 O(n log n)、对已有序数据接近 O(n)、稳定、空间 O(n)。`sort` 比 `sorted` 省一份结果列表内存。大列表取前 N 可用 `heapq.nlargest/nsmallest` 降到 O(n log k)。

- **原理**:Timsort 识别 run + 归并,稳定性靠归并"左优先",Schwartzian 变换令 key 只算 n 次,reverse 靠反转比较方向而非翻转结果,sort/sorted 共享核心但 sorted 多一次物化,元组 key 靠逐项短路比较实现多级。
