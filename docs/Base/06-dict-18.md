# 有序字典 OrderedDict

## 1. 介绍

### 1.1 什么是 OrderedDict

`OrderedDict` 是 Python 标准库 `collections` 模块提供的一个字典子类，它在普通字典功能的基础上，**额外维护了键值对的插入顺序**。你可以把它理解为：一个"记住了你什么时候放进去"的字典。

普通字典（`dict`）从 Python 3.7 开始也保持插入顺序，但 `OrderedDict` 仍然是 `collections` 模块中的重要工具。两者之间有几个关键区别：

| 维度 | `OrderedDict` | `dict`（Python 3.7+） |
|------|--------------|----------------------|
| 插入顺序 | 保持 | 保持 |
| `move_to_end()` | 有 | 无 |
| `popitem(last=False)` | 支持 | 不支持（`dict.popitem()` 无参数） |
| 相等性比较 | 顺序敏感 | 顺序不敏感 |
| 内存占用 | 较大（维护双向链表） | 较小 |
| 设计意图 | 明确表达"顺序很重要" | 顺序是实现细节，不是承诺 |

即使普通字典在 Python 3.7+ 也保持顺序，`OrderedDict` 的特有方法和顺序敏感的相等性比较，使它在很多场景下仍然不可替代。

### 1.2 最简示例

用 `OrderedDict` 创建一个有序字典，然后观察遍历顺序：

```python
from collections import OrderedDict

od = OrderedDict()
od['apple'] = 5
od['banana'] = 3
od['cherry'] = 8

# 遍历时按插入顺序输出
for key, value in od.items():
    print(f"{key}: {value}")
```

运行结果：

```text
apple: 5
banana: 3
cherry: 8
```

可以看到，遍历顺序与插入顺序完全一致：先插入的 `apple` 排在最前面，最后插入的 `cherry` 排在最后面。这就是 `OrderedDict` 最核心的特征。

### 1.3 在 Python 字典体系中的定位

`OrderedDict` 位于 `collections` 模块中，是 `dict` 的子类。在整个 Python 字典体系中，它的定位如下：

```text
dict（普通字典）
  │
  ├── collections.OrderedDict    ← 有序字典，维护插入顺序，提供 move_to_end / popitem(last)
  ├── collections.defaultdict    ← 带默认值的字典
  ├── collections.Counter         ← 计数字典
  └── collections.ChainMap        ← 链式字典（多个字典的视图合并）
```

`OrderedDict` 继承了 `dict` 的全部接口，所有普通字典支持的操作（`[]` 访问、`del` 删除、`in` 判断、`len()` 等）都能直接使用。在此基础上，它增加了顺序管理能力。

## 2. 核心内容

### 2.1 创建 OrderedDict

`OrderedDict` 支持多种创建方式，与普通字典的创建方式基本一致，但额外保证插入顺序。

#### 2.1.1 逐个赋值创建

最基础的方式是先创建空的 `OrderedDict`，然后逐个添加键值对：

```python
from collections import OrderedDict

od = OrderedDict()
od['apple'] = 5
od['banana'] = 3
od['cherry'] = 8

print(list(od.items()))
```

运行结果：

```text
[('apple', 5), ('banana', 3), ('cherry', 8)]
```

插入顺序就是后续遍历的顺序。如果先插入 `apple`，再插入 `banana`，遍历时 `apple` 一定排在 `banana` 前面。

#### 2.1.2 从键值对列表创建

`OrderedDict` 可以直接接收一个 `(key, value)` 元组列表来初始化：

```python
from collections import OrderedDict

od = OrderedDict([('cat', 1), ('dog', 2), ('bird', 3)])
print(list(od.items()))
```

运行结果：

```text
[('cat', 1), ('dog', 2), ('bird', 3)]
```

列表中元素的先后顺序决定了 `OrderedDict` 中键的排列顺序。

#### 2.1.3 从普通 dict 创建

也可以用一个已有的普通字典来初始化 `OrderedDict`：

```python
from collections import OrderedDict

# Python 3.7+ 普通 dict 也保持插入顺序，所以转换后顺序不变
od = OrderedDict({'red': '#FF0000', 'green': '#00FF00', 'blue': '#0000FF'})
print(list(od.items()))
```

运行结果：

```text
[('red', '#FF0000'), ('green', '#00FF00'), ('blue', '#0000FF')]
```

需要注意的是，在 Python 3.7 之前，普通字典不保证顺序，因此传入 `OrderedDict` 的顺序是不可预测的。从 Python 3.7 开始，普通字典保持插入顺序，这种转换是安全的。

#### 2.1.4 关键字参数创建

与普通字典一样，`OrderedDict` 也支持关键字参数方式创建：

```python
from collections import OrderedDict

od = OrderedDict(name='Alice', age=30, city='Beijing')
print(list(od.items()))
```

运行结果：

```text
[('name', 'Alice'), ('age', 30), ('city', 'Beijing')]
```

关键字参数的传入顺序就是字典的排列顺序。但需要注意，关键字参数只能是合法的 Python 标识符（不能以数字开头、不能含空格等）。

#### 2.1.5 从生成器创建

`OrderedDict` 还可以接收任何可迭代的 `(key, value)` 序列，包括生成器表达式：

```python
from collections import OrderedDict

# 用生成器创建平方数表
od = OrderedDict((str(i), i * i) for i in range(1, 5))
print(list(od.items()))
```

运行结果：

```text
[('1', 1), ('2', 4), ('3', 9), ('4', 16)]
```

生成器逐个产出键值对，`OrderedDict` 按产出顺序插入。这种方式在需要动态生成大量键值对时非常方便。

**创建方式速查表**：

| 创建方式 | 代码示例 | 特点 |
|---------|---------|------|
| 逐个赋值 | `od = OrderedDict(); od['a'] = 1` | 灵活，适合动态构建 |
| 列表初始化 | `OrderedDict([('a', 1), ('b', 2)])` | 一次性创建，顺序明确 |
| dict 初始化 | `OrderedDict({'a': 1, 'b': 2})` | 从已有字典转换 |
| 关键字参数 | `OrderedDict(a=1, b=2)` | 简洁，但键名有限制 |
| 生成器 | `OrderedDict((k, v) for k, v in ...)` | 动态生成，适合大批量 |

### 2.2 有序性的本质

#### 2.2.1 插入顺序保证

`OrderedDict` 最核心的特性是：**键的遍历顺序始终与它们的插入顺序一致**。无论你对字典做了什么操作，这个保证都成立。

来看一个完整的验证：

```python
from collections import OrderedDict

od = OrderedDict()
od['first'] = 1
od['second'] = 2
od['third'] = 3

print("插入顺序遍历:")
for key in od:
    print(f"  {key}: {od[key]}")
```

运行结果：

```text
插入顺序遍历:
  first: 1
  second: 2
  third: 3
```

#### 2.2.2 删除后重新插入：排到末尾

这是 `OrderedDict` 的一个关键行为——当你删除一个键然后重新插入它时，该键会被排到**末尾**，而不是回到原来的位置：

```python
from collections import OrderedDict

od = OrderedDict()
od['first'] = 1
od['second'] = 2
od['third'] = 3

# 删除 second
del od['second']
print("删除 second 后:", list(od.keys()))

# 重新插入 second
od['second'] = 2
print("重新插入 second 后:", list(od.keys()))
```

运行结果：

```text
删除 second 后: ['first', 'third']
重新插入 second 后: ['first', 'third', 'second']
```

`second` 被删除后再插入，它会排在最后面，而不是回到 `first` 和 `third` 之间。这个行为对 `OrderedDict` 和 Python 3.7+ 的普通字典都是一致的。

#### 2.2.3 更新已存在的键：位置不变

如果你对一个已存在的键重新赋值（不是删除再添加），它的位置不会改变，只有值会更新：

```python
from collections import OrderedDict

od = OrderedDict([('x', 1), ('y', 2), ('z', 3)])

# 对已存在的键 x 重新赋值
od['x'] = 999
print("更新 x 的值后:")
for key, value in od.items():
    print(f"  {key}: {value}")
```

运行结果：

```text
更新 x 的值后:
  x: 999
  y: 2
  z: 3
```

`x` 的值从 1 变成了 999，但它仍然排在第一位，位置没有移动。

**顺序行为总结**：

| 操作 | 键的位置变化 |
|------|------------|
| 新增键 | 排到末尾 |
| 更新已存在的键的值 | 位置不变 |
| 删除键后重新添加 | 排到末尾 |
| `move_to_end(key)` | 移到末尾（或头部） |

### 2.3 move_to_end 方法

`move_to_end` 是 `OrderedDict` 最有特色的专有方法，普通字典没有这个方法。它可以将指定的键移动到字典的头部或尾部。

#### 2.3.1 方法签名

```python
OrderedDict.move_to_end(key, last=True)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `key` | 任意不可变类型 | 必填 | 要移动的键，必须已存在于字典中 |
| `last` | `bool` | `True` | `True` 移到末尾，`False` 移到头部 |

如果 `key` 不存在，会抛出 `KeyError`。

#### 2.3.2 移到末尾（last=True）

默认行为是将键移到字典末尾，相当于"标记为最近使用"：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3), ('d', 4)])
print("初始状态:", list(od.keys()))

# 将 b 移到末尾
od.move_to_end('b')
print("b 移到末尾后:", list(od.keys()))
```

运行结果：

```text
初始状态: ['a', 'b', 'c', 'd']
b 移到末尾后: ['a', 'c', 'd', 'b']
```

`b` 从第二位移动到了最后一位，其他键的相对顺序保持不变。

#### 2.3.3 移到头部（last=False）

传入 `last=False` 可以将键移到字典头部，相当于"标记为最早使用"：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3), ('d', 4)])
print("初始状态:", list(od.keys()))

# 将 d 移到头部
od.move_to_end('d', last=False)
print("d 移到头部后:", list(od.keys()))
```

运行结果：

```text
初始状态: ['a', 'b', 'c', 'd']
d 移到头部后: ['d', 'a', 'b', 'c']
```

`d` 从最后一位移动到了第一位。

#### 2.3.4 实际应用：标记最近访问

`move_to_end` 最典型的应用场景是 LRU 缓存——每次访问一个元素时，把它移到末尾表示"最近使用过"，这样头部就是"最久未使用"的元素，可以优先淘汰。

```python
from collections import OrderedDict

# 模拟一个简单的访问记录追踪器
access_log = OrderedDict()
access_log['page_a'] = '首页'
access_log['page_b'] = '关于'
access_log['page_c'] = '联系'

# 用户访问了 page_a，将其移到末尾（最近访问）
access_log.move_to_end('page_a')
print("最近访问顺序:", list(access_log.keys()))

# 最久未访问的是头部第一个
oldest = next(iter(access_log))
print(f"最久未访问: {oldest}")
```

运行结果：

```text
最近访问顺序: ['page_b', 'page_c', 'page_a']
最久未访问: page_b
```

### 2.4 popitem 方法

`popitem` 是另一个 `OrderedDict` 增强过的方法。普通字典的 `dict.popitem()` 随机弹出一个键值对（Python 3.7+ 弹出最后一个），而 `OrderedDict.popitem()` 可以精确地从头部或尾部弹出。

#### 2.4.1 方法签名

```python
OrderedDict.popitem(last=True)
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `last` | `bool` | `True` | `True` 弹出末尾（最后插入的），`False` 弹出头部（最先插入的） |

返回值是被弹出的 `(key, value)` 元组。如果字典为空，抛出 `KeyError`。

#### 2.4.2 弹出末尾（last=True）

默认从末尾弹出，行为类似栈（LIFO）：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3), ('d', 4)])
print("初始:", list(od.keys()))

last_item = od.popitem()
print(f"弹出末尾: {last_item}")
print(f"剩余: {list(od.keys())}")
```

运行结果：

```text
初始: ['a', 'b', 'c', 'd']
弹出末尾: ('d', 4)
剩余: ['a', 'b', 'c']
```

#### 2.4.3 弹出头部（last=False）

传入 `last=False` 可以从头部弹出，行为类似队列（FIFO）：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3), ('d', 4)])
print("初始:", list(od.keys()))

first_item = od.popitem(last=False)
print(f"弹出头部: {first_item}")
print(f"剩余: {list(od.keys())}")
```

运行结果：

```text
初始: ['a', 'b', 'c', 'd']
弹出头部: ('a', 1)
剩余: ['b', 'c', 'd']
```

#### 2.4.4 用 popitem(last=False) 实现 FIFO 队列

`popitem(last=False)` 特别适合实现先进先出（FIFO）队列——先入队的先出队：

```python
from collections import OrderedDict

fifo = OrderedDict()
for i in range(5):
    fifo[f'task_{i}'] = f'任务内容{i}'

print("入队后:", list(fifo.keys()))

# 逐个出队（先进先出）
while fifo:
    key, value = fifo.popitem(last=False)
    print(f"  出队: {key} -> {value}")
```

运行结果：

```text
入队后: ['task_0', 'task_1', 'task_2', 'task_3', 'task_4']
  出队: task_0 -> 任务内容0
  出队: task_1 -> 任务内容1
  出队: task_2 -> 任务内容2
  出队: task_3 -> 任务内容3
  出队: task_4 -> 任务内容4
```

#### 2.4.5 popitem 在 dict 与 OrderedDict 中的区别

| 对比维度 | `dict.popitem()` | `OrderedDict.popitem()` |
|---------|-------------------|------------------------|
| 参数 | 无参数 | 支持 `last` 参数 |
| 弹出位置 | 弹出最后一个（Python 3.7+） | 可选头部或尾部 |
| 返回值 | `(key, value)` 元组 | `(key, value)` 元组 |
| 空字典行为 | `KeyError` | `KeyError` |

普通字典的 `popitem()` 不接受任何参数，你无法控制从哪一端弹出。`OrderedDict` 的 `popitem(last=False)` 让你能够精确地从头部弹出，这是实现 FIFO 队列和 LRU 缓存的关键能力。

### 2.5 相等性比较：顺序敏感

`OrderedDict` 的相等性比较（`==`）是**顺序敏感**的，这是它与普通字典的一个重要区别。

#### 2.5.1 OrderedDict 之间的比较

两个 `OrderedDict` 只有在**内容相同且顺序也相同**时才算相等：

```python
from collections import OrderedDict

od1 = OrderedDict([('a', 1), ('b', 2), ('c', 3)])
od2 = OrderedDict([('a', 1), ('b', 2), ('c', 3)])
od3 = OrderedDict([('c', 3), ('b', 2), ('a', 1)])  # 内容相同，顺序不同

print("od1 == od2 (同序):", od1 == od2)
print("od1 == od3 (异序):", od1 == od3)
```

运行结果：

```text
od1 == od2 (同序): True
od1 == od3 (异序): False
```

`od1` 和 `od3` 的键值对完全相同，但因为顺序不同，`==` 返回 `False`。

#### 2.5.2 OrderedDict 与普通 dict 的比较

当 `OrderedDict` 与普通 `dict` 比较时，**顺序不再敏感**——只比较内容是否一致：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3)])
d1 = {'a': 1, 'b': 2, 'c': 3}
d2 = {'c': 3, 'b': 2, 'a': 1}  # 顺序不同

print("OrderedDict vs dict (同序):", od == d1)
print("OrderedDict vs dict (异序):", od == d2)
```

运行结果：

```text
OrderedDict vs dict (同序): True
OrderedDict vs dict (异序): True
```

这是因为 `dict.__eq__` 不关心顺序，而 Python 的 `==` 运算会先尝试左侧对象的 `__eq__`，如果返回 `NotImplemented`，再尝试右侧对象的 `__eq__`。`OrderedDict.__eq__` 只在两侧都是 `OrderedDict` 时才进行顺序敏感比较，否则回退到普通字典的比较逻辑。

#### 2.5.3 普通字典之间的比较

普通字典之间的比较一直是顺序不敏感的：

```python
d1 = {'a': 1, 'b': 2, 'c': 3}
d2 = {'c': 3, 'b': 2, 'a': 1}
print("dict vs dict (异序):", d1 == d2)
```

运行结果：

```text
dict vs dict (异序): True
```

**相等性比较总结**：

| 比较场景 | 顺序敏感？ | 说明 |
|---------|-----------|------|
| `OrderedDict == OrderedDict` | 是 | 内容和顺序都相同才相等 |
| `OrderedDict == dict` | 否 | 只比较内容 |
| `dict == OrderedDict` | 否 | 只比较内容 |
| `dict == dict` | 否 | 只比较内容 |

### 2.6 其他常用操作

`OrderedDict` 继承了 `dict` 的全部接口，以下操作与普通字典完全一致。

#### 2.6.1 字典推导式

`OrderedDict` 支持字典推导式，但需要注意的是，直接使用 `{k: v for ...}` 语法生成的是普通 `dict`，不是 `OrderedDict`。要生成 `OrderedDict`，需要显式构造：

```python
from collections import OrderedDict

# 用生成器表达式构造 OrderedDict
od = OrderedDict((k, v) for k, v in [('a', 1), ('b', 2), ('c', 3)] if v > 1)
print(type(od).__name__, list(od.items()))
```

运行结果：

```text
OrderedDict [('b', 2), ('c', 3)]
```

#### 2.6.2 reversed 反向遍历

从 Python 3.8 开始，`OrderedDict` 支持 `reversed()` 反向遍历，普通字典也支持：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3)])

print("正向遍历:", list(od.keys()))
print("反向遍历:", list(reversed(od)))
```

运行结果：

```text
正向遍历: ['a', 'b', 'c']
反向遍历: ['c', 'b', 'a']
```

#### 2.6.3 copy 方法

`OrderedDict` 的 `copy()` 方法返回一个浅拷贝，保持原有顺序：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3)])
od_copy = od.copy()

print("原始:", list(od.items()))
print("拷贝:", list(od_copy.items()))
print("类型:", type(od_copy).__name__)
```

运行结果：

```text
原始: [('a', 1), ('b', 2), ('c', 3)]
拷贝: [('a', 1), ('b', 2), ('c', 3)]
类型: OrderedDict
```

#### 2.6.4 setdefault 方法

`setdefault` 方法与普通字典一致，如果键不存在则插入并返回默认值：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2)])

# 键已存在，返回已有值
val1 = od.setdefault('a', 999)
print(f"a 的值: {val1}, 字典: {list(od.items())}")

# 键不存在，插入新键值对（排到末尾）
val2 = od.setdefault('c', 3)
print(f"c 的值: {val2}, 字典: {list(od.items())}")
```

运行结果：

```text
a 的值: 1, 字典: [('a', 1), ('b', 2)]
c 的值: 3, 字典: [('a', 1), ('b', 2), ('c', 3)]
```

#### 2.6.5 clear 方法

`clear()` 清空字典，与普通字典一致：

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2), ('c', 3)])
print("清空前:", list(od.items()))

od.clear()
print("清空后:", list(od.items()))
print("长度:", len(od))
```

运行结果：

```text
清空前: [('a', 1), ('b', 2), ('c', 3)]
清空后: []
长度: 0
```

### 2.7 OrderedDict vs dict：如何选择

Python 3.7 以后，普通字典也开始保持插入顺序，这让很多人疑惑 `OrderedDict` 是否还有存在价值。答案是肯定的——`OrderedDict` 在以下方面仍然是更好的选择。

#### 2.7.1 功能差异对比

| 功能 | `OrderedDict` | `dict` |
|------|--------------|--------|
| 保持插入顺序 | 是 | 是（Python 3.7+，3.6 为实现细节） |
| `move_to_end(key)` | 有 | 无 |
| `popitem(last=False)` | 支持 | 不支持 |
| 顺序敏感的 `==` 比较 | 是 | 否 |
| `reversed()` 支持 | Python 3.8+ | Python 3.8+ |
| 内存占用 | 较大（额外维护双向链表） | 较小 |
| 语义表达 | 明确表示"顺序很重要" | 顺序是实现细节 |

#### 2.7.2 内存占用对比

`OrderedDict` 内部使用双向链表维护顺序，内存占用比普通字典大：

```python
import sys
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2)])
d = {'a': 1, 'b': 2}

print(f"OrderedDict 内存: {sys.getsizeof(od)} bytes")
print(f"dict 内存: {sys.getsizeof(d)} bytes")
```

运行结果（具体数值因 Python 版本和平台而异）：

```text
OrderedDict 内存: 376 bytes
dict 内存: 184 bytes
```

`OrderedDict` 的内存占用大约是普通字典的两倍，这是因为每个键值对除了存储在哈希表中，还需要在双向链表中维护前后指针。

#### 2.7.3 什么时候用 OrderedDict

**推荐使用 `OrderedDict` 的场景**：

- 需要 `move_to_end()` 方法来调整顺序（如 LRU 缓存）
- 需要 `popitem(last=False)` 从头部弹出（如 FIFO 队列）
- 需要顺序敏感的相等性比较（如测试中验证数据顺序）
- 代码中顺序是核心逻辑而非偶然，需要用类型明确表达这一意图
- 需要兼容 Python 3.7 以下版本（虽然现在很少见了）

**普通 dict 就够用的场景**：

- 只是需要按插入顺序遍历（Python 3.7+）
- 不需要调整顺序或从头部弹出
- 对内存占用敏感
- 顺序只是"顺便"保持，不是核心逻辑

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法

**场景一：实现 LRU 缓存**

推荐写法——直接使用 `OrderedDict` 的 `move_to_end` 和 `popitem`：

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = OrderedDict()

    def get(self, key):
        if key not in self.cache:
            return -1
        self.cache.move_to_end(key)  # 标记为最近使用
        return self.cache[key]

    def put(self, key, value):
        if key in self.cache:
            self.cache.move_to_end(key)
        self.cache[key] = value
        if len(self.cache) > self.capacity:
            self.cache.popitem(last=False)  # 淘汰最久未使用
```

不推荐写法——用普通字典手动维护顺序，代码复杂且容易出错：

```python
# 不推荐：用普通 dict 模拟 LRU，需要手动维护顺序列表
class BadLRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = {}
        self.order = []  # 手动维护顺序

    def get(self, key):
        if key not in self.cache:
            return -1
        self.order.remove(key)     # O(n) 操作
        self.order.append(key)
        return self.cache[key]

    def put(self, key, value):
        if key in self.cache:
            self.order.remove(key)
        self.cache[key] = value
        self.order.append(key)
        if len(self.cache) > self.capacity:
            oldest = self.order.pop(0)  # O(n) 操作
            del self.cache[oldest]
```

普通字典方案的 `order.remove()` 和 `order.pop(0)` 都是 O(n) 操作，而 `OrderedDict` 的 `move_to_end` 和 `popitem` 是 O(1) 操作。性能差异在大规模数据下非常明显。

**场景二：需要顺序敏感的比较**

推荐写法——用 `OrderedDict` 明确表达"顺序重要"的意图：

```python
from collections import OrderedDict

# 测试中验证配置项的顺序是否正确
expected = OrderedDict([('host', 'localhost'), ('port', 8080), ('debug', True)])
actual = OrderedDict([('host', 'localhost'), ('port', 8080), ('debug', True)])

assert actual == expected  # 只有内容和顺序都对才通过
```

不推荐写法——用普通字典无法检测顺序错误：

```python
# 不推荐：普通 dict 的 == 不检测顺序，以下断言会通过（可能是 bug）
expected = {'host': 'localhost', 'port': 8080, 'debug': True}
actual = {'debug': True, 'port': 8080, 'host': 'localhost'}

assert actual == expected  # 永远通过，无法发现顺序问题
```

**场景三：简单顺序遍历**

推荐写法——Python 3.7+ 直接用普通字典即可：

```python
# 推荐：简单遍历用普通 dict 足够
config = {'host': 'localhost', 'port': 8080, 'debug': True}
for key, value in config.items():
    print(f"{key}: {value}")
```

不推荐写法——不需要顺序操作时强行用 `OrderedDict` 增加内存开销：

```python
# 不推荐：不需要 move_to_end / popitem 时用 OrderedDict 浪费内存
from collections import OrderedDict
config = OrderedDict([('host', 'localhost'), ('port', 8080), ('debug', True)])
for key, value in config.items():
    print(f"{key}: {value}")
```

### 3.2 常见错误

#### 3.2.1 move_to_end 传入不存在的键

```python
from collections import OrderedDict

od = OrderedDict([('a', 1), ('b', 2)])
od.move_to_end('c')  # KeyError: 'c'
```

`move_to_end` 要求键必须已存在。如果不确定键是否存在，应该先检查：

```python
if 'c' in od:
    od.move_to_end('c')
```

#### 3.2.2 忘记 OrderedDict 已被普通字典取代顺序保证的部分

有些开发者看到 Python 3.7+ 字典有序后，就认为 `OrderedDict` 完全没用了。但实际上普通字典没有 `move_to_end` 和 `popitem(last=False)`，也不能做顺序敏感比较。需要根据实际需求选择，不能一概而论。

### 3.3 性能考量

| 操作 | `OrderedDict` | `dict` |
|------|--------------|--------|
| 查找 `od[key]` | O(1) | O(1) |
| 插入 `od[key] = v` | O(1) | O(1) |
| 删除 `del od[key]` | O(1) | O(1) |
| `move_to_end()` | O(1) | 不支持 |
| `popitem(last=False)` | O(1) | 不支持 |
| `popitem()` | O(1) | O(1) |
| 遍历 | O(n) | O(n) |
| 内存（每元素） | 较大（链表指针） | 较小 |

`OrderedDict` 的核心操作时间复杂度与普通字典一致，都是 O(1)。额外的开销主要在内存层面——每个键值对需要维护双向链表的前驱和后继指针。

## 4. 原理

### 4.1 OrderedDict 的内部结构

`OrderedDict` 能够在 O(1) 时间内完成 `move_to_end` 和 `popitem(last=False)` 的秘密在于其内部数据结构：**哈希表 + 双向链表**。

```text
OrderedDict 内部结构示意：

  哈希表（dict）                      双向链表（维护顺序）
  ┌──────────────────┐
  │ "a" → Node(a,1)  │◄───────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ "b" → Node(b,2)  │◄─────┐     │    │ Node(a)  │◄──►│ Node(b)  │◄──►│ Node(c)  │
  │ "c" → Node(c,3)  │◄──┐  │     │    │ key="a"  │    │ key="b"  │    │ key="c"  │
  └──────────────────┘   │  │     │    │ val=1    │    │ val=2    │    │ val=3    │
                         │  │     │    │ prev=None│    │ prev=a   │    │ prev=b   │
                         └──┘     │    │ next=b   │    │ next=c   │    │ next=None│
                                  │    └──────────┘    └──────────┘    └──────────┘
                                  │         ▲                               ▲
                              head ─────────┘                               │
                              tail ─────────────────────────────────────────┘
```

- **哈希表**：负责 O(1) 的键查找，与普通字典一样
- **双向链表**：负责维护插入顺序，每个节点记录前驱（prev）和后继（next）指针

哈希表中存储的不是直接的值，而是指向链表节点的引用。通过哈希表找到节点后，可以通过链表指针在 O(1) 时间内调整其位置。

### 4.2 move_to_end 为什么是 O(1)

普通字典如果要"把某个键移到末尾"，需要先删除再重新插入，虽然也是 O(1)，但需要重新计算哈希。而 `OrderedDict` 的 `move_to_end` 直接操作链表指针：

```text
move_to_end('b') 的过程：

  操作前:  head → [a] ↔ [b] ↔ [c] ← tail

  步骤1: 从链表中摘除 b（修改 a.next 和 c.prev）
         head → [a] ↔ [c] ← tail     [b]（游离）

  步骤2: 将 b 插入到链表尾部（修改 c.next 和 tail）
         head → [a] ↔ [c] ↔ [b] ← tail

  操作后:  head → [a] ↔ [c] ↔ [b] ← tail
```

整个过程只修改了 4 个指针（`a.next`、`c.prev`、`c.next`、`b.prev`），不涉及哈希计算，时间复杂度为 O(1)。

### 4.3 popitem(last=False) 为什么是 O(1)

普通字典的 `popitem()` 只能弹出最后一个元素。如果要从头部弹出，需要遍历到第一个键，时间复杂度至少 O(1)（Python 3.7+ 维护了头部指针），但普通字典没有暴露这个接口。

`OrderedDict` 通过维护 `head` 指针，可以直接定位到链表头部的节点：

```text
popitem(last=False) 的过程：

  操作前:  head → [a] ↔ [b] ↔ [c] ← tail

  步骤1: 通过 head 指针找到第一个节点 a
  步骤2: 从链表中摘除 a（修改 head 指向 b，b.prev 置为 None）
  步骤3: 从哈希表中删除 a 的条目
  步骤4: 返回 (a.key, a.value)

  操作后:  head → [b] ↔ [c] ← tail
```

整个过程也是 O(1)，因为 `head` 指针直接指向第一个节点，不需要遍历。

### 4.4 为什么 OrderedDict 的 == 是顺序敏感的

普通字典的 `__eq__` 方法只比较键值对是否一致，不关心顺序：

```text
{'a': 1, 'b': 2} == {'b': 2, 'a': 1}  →  True
```

`OrderedDict` 重写了 `__eq__` 方法，在比较两个 `OrderedDict` 时，不仅检查键值对是否一致，还逐一检查顺序是否相同：

```text
OrderedDict([('a',1),('b',2)]) == OrderedDict([('a',1),('b',2)])  →  True
OrderedDict([('a',1),('b',2)]) == OrderedDict([('b',2),('a',1)])  →  False
```

但如果比较的一方不是 `OrderedDict`，`OrderedDict.__eq__` 会返回 `NotImplemented`，让 Python 回退到 `dict.__eq__`，此时就变成了顺序不敏感的比较。

### 4.5 Python 3.7+ 普通 dict 为什么也有序

Python 3.6 的 CPython 实现引入了"紧凑字典"（compact dict），将键值对存储在两个连续数组中，插入顺序天然就是数组顺序。Python 3.7 将此行为正式写入语言规范，所有 Python 实现都必须保证字典保持插入顺序。

但普通字典的有序性只是"存储顺序"，它没有 `OrderedDict` 那样的双向链表，因此无法提供 O(1) 的 `move_to_end` 和从头弹出的能力。普通字典要"移到末尾"需要先 `del` 再赋值，虽然也是 O(1)，但语义不如 `move_to_end` 清晰，且无法移到头部。

## 5. 总结

本文围绕 `OrderedDict` 展开，主要介绍了以下内容：

- `OrderedDict` 是 `collections` 模块提供的字典子类，在普通字典功能基础上维护键的插入顺序
- 支持五种创建方式：逐个赋值、列表初始化、dict 初始化、关键字参数、生成器
- 有序性的核心行为：新增键排到末尾，更新已存在键位置不变，删除后重新插入排到末尾
- `move_to_end(key, last=True)` 是 `OrderedDict` 的专有方法，可在 O(1) 时间内将键移到头部或尾部
- `popitem(last=True)` 支持从头部或尾部弹出，适合实现 FIFO 队列和 LRU 缓存
- `OrderedDict` 之间的 `==` 比较是顺序敏感的，与普通字典比较时退化为顺序不敏感
- 内部通过"哈希表 + 双向链表"实现 O(1) 的顺序操作，内存占用比普通字典大
- Python 3.7+ 普通字典也保持插入顺序，但缺少 `move_to_end` 和 `popitem(last=False)`，且相等性比较不敏感于顺序
- 典型应用场景包括 LRU 缓存、FIFO 队列、顺序敏感的配置比较
