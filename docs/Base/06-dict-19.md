# 字典与 JSON 互转

## 1. 介绍

### 1.1 什么是 JSON

JSON（JavaScript Object Notation）是一种轻量级的数据交换格式。它用文本表示结构化数据，语法上与 Python 字典非常相似——键值对用大括号 `{}` 包裹，用逗号分隔。由于其简洁、易读、跨语言通用，JSON 几乎无处不在：Web API 返回的数据是 JSON 格式，配置文件常用 JSON，前端与后端之间用 JSON 通信。

一个典型的 JSON 字符串看起来是这样：

```text
{"name": "张三", "age": 30, "married": false, "salary": 9999.99}
```

你可以把它想象成"一段纯文本格式的字典"——存储和传输靠 JSON，处理和操作靠 Python 字典。两者之间需要往返转换。

### 1.2 为什么需要互转

Python 程序在运行时操作的是内存中的字典对象，但数据要写入文件、通过网络发送给别的程序时，需要转成纯文本格式；反过来，文件里或网络收到的数据是一串文本，要变成 Python 能操作的字典才能用。

```text
Python 字典 (内存对象)
    ↓  序列化 (dumps / dump)
JSON 字符串 (纯文本)
    ↑  反序列化 (loads / load)
```

序列化（Python 对象 → JSON 文本）和反序列化（JSON 文本 → Python 对象）是日常开发中最常见的操作之一。

### 1.3 最简示例

下面这段代码让你一眼看到全貌：字典变成 JSON 字符串，再从 JSON 字符串还原成字典。

```python
import json

person = {"name": "张三", "age": 30, "married": False, "salary": 9999.99}

# 序列化：dict → JSON 字符串
json_str = json.dumps(person)
print(json_str)
# 输出：{"name": "\u5f20\u4e09", "age": 30, "married": false, "salary": 9999.99}

# 反序列化：JSON 字符串 → dict
restored = json.loads(json_str)
print(restored)
# 输出：{'name': '张三', 'age': 30, 'married': False, 'salary': 9999.99}
```

注意一个细节：JSON 中布尔值 `false`（小写）对应 Python 的 `False`（首字母大写），JSON 中没有双引号包裹的数字和小数都表示数值型，中文默认会被转义为 `\uXXXX` 序列。这些差异背后的规则在本章稍后详细展开。

### 1.4 json 模块核心 API 速查

| 函数 | 方向 | 输入 / 输出 | 用途 |
|------|------|------------|------|
| `json.dumps(obj)` | 序列化 | Python 对象 → str | 把字典/列表转成 JSON 字符串 |
| `json.loads(s)` | 反序列化 | str → Python 对象 | 把 JSON 字符串解析成字典/列表 |
| `json.dump(obj, fp)` | 序列化 | Python 对象 → 文件 | 把对象直接写入文件 |
| `json.load(fp)` | 反序列化 | 文件 → Python 对象 | 从文件读取并解析成对象 |

ms、ds、ad、al 是四个函数名末尾字母的口诀：
- `s` 结尾（dumps/loads）操作**字符串**（string）
- 不带 `s`（dump/load）操作**文件**（file）

> 你可以这样记："**带 s 转 string，不带 s 转 file**"。其他函数（如 custom encoder、JSONDecoder 类等）在日常开发中用得少，但下面会逐步提到。

### 1.5 JSON 数据类型与 Python 类型映射

JSON 自己只有六种数据类型，而 Python 的类型体系丰富得多。互转时的核心规则就是这张映射表：

| JSON 类型 | Python 类型（反序列化后得到） | Python 类型（可序列化） |
|---------|----------------------------|----------------------|
| object `{}` | dict | dict |
| array `[]` | list | list、tuple（转成 array） |
| string | str | str |
| number（整数部分） | int | int |
| number（带小数） | float | float |
| `true` / `false` | True / False | True / False |
| `null` | None | None |

**记忆要点**：JSON 里小写 `true / false / null`，对应 Python 里首字母大写 `True / False / None`；JSON 不区分整数和浮点数，都属于 `number` 类型。

```python
import json

# 正反方向的类型映射演示
print(json.dumps("hello"))
# 输出："hello"
print(json.dumps(42))
# 输出：42
print(json.dumps(3.14))
# 输出：3.14
print(json.dumps(True), json.dumps(False))
# 输出：true false
print(json.dumps(None))
# 输出：null
print(json.dumps([1, 2, 3]))
# 输出：[1, 2, 3]
print(json.dumps({"a": 1}))
# 输出：{"a": 1}

# tuple 会被转成 JSON array（注意不是 tuple）
print(json.dumps((1, 2, 3)))
# 输出：[1, 2, 3]
```

值得强调的是 tuple 在 JSON 中没有对应类型，会被转成 array（list）。反过来，JSON 的 array 在 `loads` 后返回的永远是 list，不会变回 tuple——这是反序列化时的有损转换，需要在设计中注意。

## 2. 核心内容

### 2.1 序列化：dict → JSON 字符串

序列化的核心函数是 `json.dumps`（dump + s = dump string）。它将 Python 对象转成 JSON 格式的字符串。

#### 2.1.1 函数签名

```text
json.dumps(obj, *, skipkeys=False, ensure_ascii=True, check_circular=True,
           allow_nan=True, cls=None, indent=None, separators=None,
           default=None, sort_keys=False, **kw)
```

不必一次记住所有参数，下面分小节解释常用参数的含义和用法。

#### 2.1.2 最基础的 dumps

```python
import json

person = {"name": "张三", "age": 30, "married": False, "salary": 9999.99}
json_str = json.dumps(person)
print(json_str)
print(type(json_str))
```

```text
{"name": "\u5f20\u4e09", "age": 30, "married": false, "salary": 9999.99}
<class 'str'>
```

返回值是一个 `str` 对象。注意：
- Python 字典用单引号显示键和字符串值，JSON 严格使用双引号。
- 中文被转成 `\uXXXX`（Unicode 转义序列）。这是 `ensure_ascii=True`（默认值）的行为。
- `False` 输出为小写 `false`，`True` 输出为 `true`，`None` 输出为 `null`。
- 数字保持原样。

#### 2.1.3 ensure_ascii 参数

```python
import json

person = {"name": "张三", "age": 30, "city": "北京"}

# 默认：中文被转义
print(json.dumps(person))
# 输出：{"name": "\u5f20\u4e09", "age": 30, "city": "\u5317\u4eac"}

# 设为 False：保留中文原文
print(json.dumps(person, ensure_ascii=False))
# 输出：{"name": "张三", "age": 30, "city": "北京"}
```

**对比说明**：

| ensure_ascii | 效果 | 适用场景 |
|-------------|------|---------|
| `True`（默认） | 非 ASCII 字符转 `\uXXXX` 序列 | 兼容老系统、纯 ASCII 环境 |
| `False` | 保留原始字符（如中文） | 配置文件、日志、可读性优先的场景 |

日常开发中，推荐显式写 `ensure_ascii=False`，可读性更好。注意写文件时要同时指定 `encoding="utf-8"`，否则在 Windows 系统上可能因为默认编码是 GBK 而写入乱码。

#### 2.1.4 indent 参数：美化输出

```python
import json

data = {"name": "李四", "age": 25, "hobbies": ["读书", "编程", "旅行"]}

# 紧凑模式（默认）：一行写完
print(json.dumps(data, ensure_ascii=False))
# 输出：{"name": "李四", "age": 25, "hobbies": ["读书", "编程", "旅行"]}

# 缩进 2 空格
print(json.dumps(data, indent=2, ensure_ascii=False))
```

```text
{
  "name": "李四",
  "age": 25,
  "hobbies": [
    "读书",
    "编程",
    "旅行"
  ]
}
```

| indent 值 | 效果 | 用途 |
|----------|------|------|
| `None`（默认） | 紧凑一行 | 网络传输、节省空间 |
| `0` | 每个元素一行，无额外缩进 | 特殊场景 |
| `2` | 2 空格缩进（常用） | 配置文件、人类阅读 |
| `4` | 4 空格缩进 | 代码风格统一的场景 |
| 字符串（如 `"\t"`） | 用 tab 缩进 | 特殊风格需求 |

注意 `indent=0` 行为有点特殊：它会在元素间换行但不额外加缩进空格，效果介于紧凑和多空格缩进之间。

#### 2.1.5 sort_keys 参数

```python
import json

unordered = {"zebra": 3, "apple": 1, "mango": 2, "banana": 4}

# 默认保持字典定义时的顺序
print(json.dumps(unordered, ensure_ascii=False))
# 输出：{"zebra": 3, "apple": 1, "mango": 2, "banana": 4}

# 按 key 字母排序
print(json.dumps(unordered, ensure_ascii=False, sort_keys=True))
# 输出：{"apple": 1, "banana": 4, "mango": 2, "zebra": 3}
```

Python 3.7+ 字典保证插入顺序，`sort_keys=True` 会强行按 key 排序输出。**适合对输出确定性有要求的场景**：比如用于生成哈希摘要、做单元测试比对、对文件做版本对比时，排序输出能避免顺序差异造成的虚假"变更"。

#### 2.1.6 separators 参数

控制元素间的分隔符。默认值是 `(', ', ': ')`——逗号后有空格，冒号后有占两个空格。

```python
import json

data = {"name": "李四", "age": 25, "city": "北京"}

# 默认 separators=(', ', ': ')
print(json.dumps(data, ensure_ascii=False))
# 输出：{"name": "李四", "age": 25, "city": "北京"}

# 紧凑模式：去掉多余空格
print(json.dumps(data, ensure_ascii=False, separators=(',', ':')))
# 输出：{"name":"李四","age":25,"city":"北京"}
```

**经典搭配**：`separators=(',', ':')` + `indent=None` 是最紧凑的形式，能减小传输体积，适合对网络包大小敏感的场景。

#### 2.1.7 skipkeys 参数

当字典的 key 不是字符串类型时，默认行为是抛出 `TypeError`。设 `skipkeys=True` 会跳过这些键，方便数据清洗。

```python
import json

# 键含非字符串类型（int）
data = {1: "one", "name": "张三"}

# 默认行为：抛 TypeError
try:
    print(json.dumps(data))
except TypeError as e:
    print(f"报错: {e}")
    # 输出：报错: keys must be str, int, float, bool or None, not int

# skipkeys=True：跳过非字符串键
print(json.dumps(data, skipkeys=True, ensure_ascii=False))
# 输出：{"name": "张三"}
```

注意 JSON 规范要求 object 的 key 必须是字符串。Python 偶尔会有 int 键（比如 `{1: "a"}`），但 JSON 无法表达，这时候要么 `skipkeys=True` 丢弃，要么手动转字符串。

#### 2.1.8 check_circular 和 allow_nan 参数

```python
import json

# check_circular：循环引用检测
a = {}
b = {"ref": a}
a["back"] = b  # 循环引用

try:
    print(json.dumps(a))
except ValueError as e:
    print(f"循环引用检测: {e}")
    # 输出：Circular reference detected
```

`check_circular`（默认 True）用于检测循环引用。关闭它（设 False）主要用于性能优化——当你明确数据没有循环引用时跳过检测。但关闭后如果真的有循环引用会导致无限递归。

```python
import json
import math

# allow_nan：是否允许 NaN / Infinity
print(json.dumps({"x": float('nan'), "y": float('inf')}))
# 输出：{"x": NaN, "y": Infinity}

# 标准的 JSON 不支持 NaN/Infinity
# 严格模式可以用 allow_nan=False 强制拒绝
try:
    print(json.dumps({"x": float('nan')}, allow_nan=False))
except ValueError as e:
    print(f"拒绝 NaN: {e}")
    # 输出：Out of range float values are not JSON compliant
```

`allow_nan`（默认 True）控制是否允许序列化 `NaN`、`Infinity`、`-Infinity`。一些严格的 JSON 解析器会拒绝这些值。

### 2.2 反序列化：JSON 字符串 → dict

反序列化的函数是 `json.loads`（load + s = load string）：从字符串解析出 Python 对象。

#### 2.2.1 函数签名

```text
json.loads(s, *, cls=None, object_hook=None, parse_float=None,
           parse_int=None, parse_constant=None, object_pairs_hook=None, **kw)
```

#### 2.2.2 基础的 loads

```python
import json

json_str = '{"name": "张三", "age": 30, "married": false, "salary": 9999.99}'
person = json.loads(json_str)

print(person)
# 输出：{'name': '张三', 'age': 30, 'married': False, 'salary': 9999.99}
print(type(person))
# 输出：<class 'dict'>
print(person['married'], type(person['married']))
# 输出：False <class 'bool'>
```

JSON 中的 `false` 在 Python 中变成 `False`，并且被打印为单引号（Python 字典的默认 repr）。JSON 中没有显式区分整数和浮点数，Python 会根据是否有小数点决定返回 `int` 还是 `float`。

#### 2.2.3 object_hook：批量处理每个对象字典

```python
import json

# 反序列化时把所有 key 从 snake_case 转 camelCase
def snake_to_camel(obj):
    result = {}
    for k, v in obj.items():
        parts = k.split('_')
        new_key = parts[0] + ''.join(p.title() for p in parts[1:])
        result[new_key] = v
    return result

json_str = '{"user_name": "张三", "user_age": 30}'
data = json.loads(json_str, object_hook=snake_to_camel)
print(data)
# 输出：{'userName': '张三', 'userAge': 30}
```

`object_hook` 会在每个 JSON object 解析成 dict 之前执行，函数接收一个 dict，返回处理后（或原样）的 dict，然后用返回值替代原始字典。**嵌套对象也会被逐个调用**，常用于统一改字段名、注入类型标记、校验字段等场景。

#### 2.2.4 parse_float / parse_int / parse_constant：自定义数值解析

```python
import json
from decimal import Decimal

json_str = '{"price": 19.99, "count": 42, "flag": NaN}'

# 默认：float、int、float('nan')
data = json.loads(json_str)
print(type(data['price']), type(data['count']), type(data['flag']))
# 输出：<class 'float'> <class 'int'> <class 'float'>

# parse_float 改为 Decimal，避免浮点精度丢失
data = json.loads(json_str, parse_float=Decimal)
print(type(data['price']))
# 输出：<class 'decimal.Decimal'>
print(data['price'])  # Decimal('19.99')，不会丢失精度
```

**金融场景的必备技巧**：金额计算必须用 Decimal，float 的 IEEE 754 浮点表示会引入精度误差（`0.1 + 0.2 = 0.30000000000000004`）。用 `parse_float=Decimal` 让 JSON 解析时直接生成 Decimal，省去后续转换的坑。

```python
import json

# parse_int：把所有整数解析为字符串（比如超出 JS 安全整数范围）
json_str = '{"big": 999999999999999999999}'
data = json.loads(json_str, parse_int=str)
print(type(data['big']))
# 输出：<class 'str'>
```

```python
import json

# parse_constant：处理 NaN / Infinity / -Infinity
def reject_special(obj):
    raise ValueError(f"不支持特殊数值: {obj}")

json_str = '{"flag": NaN}'
try:
    json.loads(json_str, parse_constant=reject_special)
except ValueError as e:
    print(e)
    # 输出：不支持特殊数值: NaN
```

### 2.3 文件读写：dump 与 load

`dump` 和 `load` 是直接操作文件对象的版本，省去了你手动 `write / read` 的步骤。

#### 2.3.1 json.dump 写入文件

```python
import json

config = {
    "app_name": "MyApp",
    "version": "1.0.0",
    "database": {"host": "localhost", "port": 5432},
    "features": ["logging", "cache", "auth"],
    "max_connections": 100,
    "debug_mode": False
}

with open("config.json", "w", encoding="utf-8") as f:
    json.dump(config, f, indent=2, ensure_ascii=False)
```

`json.dump` 接收一个已打开的文件对象 `f`，把序列化结果直接写入。`indent=2` 美化缩进，`ensure_ascii=False` 保留中文。

> **注意**：`dump` 内部不会自动管理文件的打开和关闭，你需要自己用 `with open(...)` 包裹。同时打开文件时要指定 `encoding="utf-8"`，否则在某些系统默认编码环境下会写错字符。

#### 2.3.2 json.load 读取文件

```python
import json

with open("config.json", "r", encoding="utf-8") as f:
    config = json.load(f)

print(config['app_name'])
print(config['database']['host'])
print(config['features'])
# 输出：
# MyApp
# localhost
# ['logging', 'cache', 'auth']
```

`json.load` 接收已打开的文件对象，内部读取并解析。同样的，指定 `encoding="utf-8"` 读取是安全的做法。

#### 2.3.3 dump 与 dumps 的关系

```python
import json

# 这两段代码完全等价：
obj = {"a": 1}

# 方式 1：dump 直接写文件
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(obj, f)

# 方式 2：dumps 转 str 再 write
with open("out.json", "w", encoding="utf-8") as f:
    f.write(json.dumps(obj))
```

`dump` 本质上就是 `dumps + file.write` 的封装。load 与 loads 也是同样的关系：
```python
# load 等价于 loads + file.read
# json.load(f)  ≡  json.loads(f.read())
```

#### 2.3.4 完整示例：读写配置文件

一个更现实的例子：写一个 JSON 配置文件读写流程——读默认配置、保存到文件、修改后再读取。

```python
import json

config = {
    "app_name": "MyApp",
    "version": "1.0.0",
    "debug": True,
    "database": {"host": "localhost", "port": 5432},
    "allowed_ips": ["127.0.0.1"]
}

# 保存
with open("app_config.json", "w", encoding="utf-8") as f:
    json.dump(config, f, indent=2, ensure_ascii=False)

# 读取
with open("app_config.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

# 修改后再次保存
loaded["version"] = "1.1.0"
loaded["debug"] = False
loaded["allowed_ips"].append("10.0.0.0/8")

with open("app_config.json", "w", encoding="utf-8") as f:
    json.dump(loaded, f, indent=2, ensure_ascii=False)
print("配置已更新")
```

```text
配置已更新
```

最终的 JSON 文件内容看起来是这样：

```json
{
  "app_name": "MyApp",
  "version": "1.1.0",
  "debug": false,
  "database": {
    "host": "localhost",
    "port": 5432
  },
  "allowed_ips": [
    "127.0.0.1",
    "10.0.0.0/8"
  ]
}
```

### 2.4 嵌套结构的处理

JSON 与 Python 字典都能自然表达嵌套。复杂 API 响应往往有多层嵌套：外层是 meta + data，data 里又是 list，每个 list 元素内又有 object。

#### 2.4.1 嵌套 dict 和 list

```python
import json

api_response = {
    "status": "success",
    "code": 200,
    "data": {
        "users": [
            {"id": 1, "name": "王五", "roles": ["admin", "editor"]},
            {"id": 2, "name": "赵六", "roles": ["viewer"]}
        ],
        "pagination": {"page": 1, "total": 2}
    }
}

# 序列化嵌套结构
json_str = json.dumps(api_response, indent=2, ensure_ascii=False)
print(json_str)
```

```text
{
  "status": "success",
  "code": 200,
  "data": {
    "users": [
      {
        "id": 1,
        "name": "王五",
        "roles": [
          "admin",
          "editor"
        ]
      },
      {
        "id": 2,
        "name": "赵六",
        "roles": [
          "viewer"
        ]
      }
    ],
    "pagination": {
      "page": 1,
      "total": 2
    }
  }
}
```

`dumps` 会递归处理所有嵌套层级，你只需要传一个根对象即可。

#### 2.4.2 反序列化后访问嵌套数据

```python
import json

restored = json.loads(json_str)
print(f"状态: {restored['status']}")
print(f"第一个用户名: {restored['data']['users'][0]['name']}")

# 注意：JSON 里返回的永远是 dict / list，不要误以为是 object
user_list = restored['data']['users']
print(f"第一个用户的第一个角色: {user_list[0]['roles'][0]}")
```

```text
状态: success
第一个用户名: 王五
第一个用户的第一个角色: admin
```

Python 字典用 `[]` 下标逐层访问嵌套数据，用法没有任何变化。新手容易把 JSON 的 object 误认成某种"对象"，然后用 `.name` 的方式访问字段，这是不对的——反序列化后是 dict，访问得用 `["name"]`。

#### 2.4.3 sort_keys 对嵌套结构的作用

`sort_keys=True` 会递归地排序**所有层级的 key**。排序后的 JSON 在做版本对比时更友好。

```python
import json

print(json.dumps(api_response, indent=2, ensure_ascii=False, sort_keys=True))
```

第一层是 `code / data / status`，第二层是 `users / pagination`，第三层嵌套也按字母顺序，特点是不影响数据内容，只改变输出形式。

### 2.5 自定义对象的序列化

Python 字典和基本类型以外，许多对象（自定义类、datetime、Decimal、set 等）默认无法直接序列化，需要额外处理。

#### 2.5.1 默认行为的报错

```python
import json

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

user = User("张三", 30)

try:
    json.dumps(user)
except TypeError as e:
    print(f"报错: {e}")
    # 输出：报错: Object of type User is not JSON serializable
```

默认的序列化器只认字典、列表、字符串、数字、布尔、None。其他类型一律报 `is not JSON serializable`。

#### 2.5.2 方案一：default 参数

```python
import json

def user_to_dict(obj):
    if isinstance(obj, User):
        return {"name": obj.name, "age": obj.age, "type": "User"}
    raise TypeError(f"无法序列化类型: {type(obj)}")

user_json = json.dumps(user, default=user_to_dict, ensure_ascii=False)
print(user_json)
# 输出：{"name": "张三", "age": 30, "type": "User"}
```

`default(obj)` 会在遇到未知类型时被调用，返回一个 dict 或基础类型作为替换。函数内部可以按类型分发处理多种类。

```python
import json
from datetime import datetime
from decimal import Decimal

def smart_default(obj):
    if hasattr(obj, 'isoformat'):
        return obj.isoformat()  # datetime -> ISO 字符串
    if isinstance(obj, Decimal):
        return float(obj)
    if isinstance(obj, set):
        return list(obj)
    if hasattr(obj, '__dict__'):
        return obj.__dict__
    raise TypeError(f"无法序列化: {type(obj)}")

data = {
    "event": "order",
    "ts": datetime(2024, 6, 15, 14, 30, 0),
    "amount": Decimal("19.99"),
    "tags": {"vip", "new"}
}
print(json.dumps(data, default=smart_default, ensure_ascii=False))
# 输出：{"event": "order", "ts": "2024-06-15T14:30:00", "amount": 19.99, "tags": ["vip", "new"]}
```

这是一个非常实用的通用 `default` 函数，可以处理 datetime、Decimal、set 和普通 Python 对象。把 `__dict__` 作为回退方式能简单覆盖大多数自定义类。

#### 2.5.3 方案二：自定义 to_dict 方法

对自定义类而言，更清晰的写法是让类自己提供 `to_dict()` 方法，外部调用时手动转换。

```python
import json

class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def to_dict(self):
        return {"name": self.name, "price": float(self.price)}

p = Product("笔记本", 5999.0)
print(json.dumps(p.to_dict(), ensure_ascii=False))
# 输出：{"name": "笔记本", "price": 5999.0}
```

**对比 default 参数 vs to_dict 方法**：

| 维度 | default 参数 | to_dict 方法 |
|------|-------------|--------------|
| 调用方式 | 自动递归触发 | 需要显式转换 |
| 对已有类无侵入 | 可以 | 需要 |
| 跨模块适用 | 注册一次即可 | 各模块都要实现 |
| 不修改类代码 | 适合 | 不适合 |
| 多类型混合 | 集中处理 | 各自实现 |

实践中两套方案经常组合使用：在 `default` 函数里调用 `obj.to_dict()`，既保留显式控制，又支持递归序列化。

#### 2.5.4 datetime 和 Decimal 序列化

这两个是 Python 中最常见的不可 JSON 序列化类型，处理方式需要单独说明。

**datetime**：标准的转换方式是 ISO 8601 字符串。

```python
import json
from datetime import datetime

now = datetime(2024, 6, 15, 14, 30, 0)
ts_json = json.dumps({"ts": now}, default=lambda o: o.isoformat(), ensure_ascii=False)
# 输出：{"ts": "2024-06-15T14:30:00"}
```

反序列化时，返回的是字符串需要手动用 `datetime.fromisoformat(...)` 转回，否则保留为 str。

```python
restored = json.loads(ts_json)
dt = datetime.fromisoformat(restored["ts"])
print(dt, type(dt).__name__)
# 输出：2024-06-15 14:30:00 datetime
```

> 如果时间需要跨时区，建议在序列化前统一转 UTC（`dt.astimezone(timezone.utc)`），并保留时区信息。接收方再做时区转换，避免歧义。

**Decimal**：金额计算的常见坑。

```python
import json
from decimal import Decimal

price = Decimal("19.99")

# 直接转 float 会丢失精度
print(json.dumps({"price": float(price)}))
# 输出：{"price": 19.99}
# 但在计算中 0.1 + 0.2 != 0.3

# 保留精度的做法：把 Decimal 当字符串存
print(json.dumps({"price": str(price)}))
# 输出：{"price": "19.99"}
# 读取时再 Decimal("19.99") 还原
```

| 方式 | 序列化结果 | 反序列化后类型 | 适用场景 |
|------|---------|--------------|---------|
| `float(price)` | `19.99`（number） | float | 对精度不敏感的场景 |
| `str(price)` | `"19.99"`（string） | str（需手动转 Decimal） | 金融场景，需保留精度 |
| `default=lambda o: str(o)` | 自动处理 Decimal | str | 批量处理 |

### 2.6 错误处理

实际项目中，反序列化失败是高频问题。理解错误类型和定位方式能帮你快速排错。

#### 2.6.1 JSONDecodeError 的常见原因

```python
import json

bad_jsons = [
    '{"name": "张三", "age": 30,}',     # 尾部多余逗号
    "{'name': '李四'}",                 # 单引号（JSON 要求双引号）
    '{"name": "王五"',                  # 缺少右大括号
    '{"name": "赵六" "age": 25}',       # 键值对间缺逗号
]

for bad in bad_jsons:
    try:
        json.loads(bad)
    except json.JSONDecodeError as e:
        print(f"输入: {bad}")
        print(f"  错误: {e.msg}")
        print(f"  位置: 第 {e.lineno} 行, 第 {e.colno} 列")
        print()
```

```text
输入: {"name": "张三", "age": 30,}
  错误: Expecting property name enclosed in double quotes
  位置: 第 1 行, 第 26 列

输入: {'name': '李四'}
  错误: Expecting property name enclosed in double quotes
  位置: 第 1 行, 第 2 列

输入: {"name": "王五"
  错误: Expecting ',' delimiter
  位置: 第 1 行, 第 14 列

输入: {"name": "赵六" "age": 25}
  错误: Expecting ',' delimiter
  位置: 第 1 行, 第 15 列
```

JSON 规范严格，常见的违规有：
- 使用单引号（JSON 只接受双引号）
- 写了尾随逗号
- 键值对之间少了逗号
- 引号未闭合

#### 2.6.2 错误定位的三个属性

`JSONDecodeError` 提供三个有用的属性用于精确定位错误位置：

```python
import json

bad = '{"a": 1, "b": [2, 3,}'
try:
    json.loads(bad)
except json.JSONDecodeError as e:
    print(f"消息: {e.msg}")
    print(f"行号: {e.lineno}（从 1 开始）")
    print(f"列号: {e.colno}（从 1 开始）")
    print(f"字符位置: {e.pos}（从 0 开始）")

    # 视觉化定位
    print(bad)
    print(" " * e.pos + "^")
```

```text
消息: Expecting value
行号: 1（从 1 开始）
列号: 21（从 1 开始）
字符位置: 20（从 0 开始）
{"a": 1, "b": [2, 3,}
                    ^
```

| 属性 | 含义 | 起点 |
|------|------|------|
| `e.msg` | 错误描述（英文） |  |
| `e.lineno` | 行号 | 从 1 开始 |
| `e.colno` | 列号 | 从 1 开始 |
| `e.pos` | 字符位置 | 从 0 开始 |

写日志或用 UI 展示错误时，用 `e.pos` 配合 `" " * e.pos + "^"` 直接在控制台画一个箭头，能非常清楚地指出问题位置。

**Python 3.10 之前**的版本，`JSONDecodeError` 没有 `colno` 和 `pos`，只有 `lineno` 和 `offset`，需要在兼容旧版本时注意。

#### 2.6.3 文件编码问题

下面是文件读取时的常见编码问题。

```python
import json

# 写：始终指定 encoding="utf-8"
with open("data.json", "w", encoding="utf-8") as f:
    json.dump({"name": "张三"}, f, ensure_ascii=False)

# 读：同样要指定 encoding="utf-8"
with open("data.json", "r", encoding="utf-8") as f:
    data = json.load(f)
print(data)
# 输出：{'name': '张三'}
```

**常见坑**：

| 现象 | 原因 | 解决 |
|------|------|------|
| 读出乱码 | 写文件用 utf-8、读文件用了 GBK | 读写双方都显式指定 `encoding="utf-8"` |
| UnicodeDecodeError | 文件含非 ASCII 字符，但用 ASCII 模式打开 | 改用 `encoding="utf-8"` |
| Windows 上中文乱码 | Windows 默认编码是 GBK | 必须显式指定编码，不能依赖系统默认 |

**最佳实践**：任何涉及到非 ASCII 字符的文件读写，都显式指定 `encoding="utf-8"`。这是跨平台开发的基础习惯。

#### 2.6.4 安全反序列化注意事项

Python 的 `json` 模块比 `pickle` 模块安全许多——只能解析纯文本数据结构，不会执行任意代码。但仍要注意两点：

1. **不要信任外部输入的数据**：解析时用 `parse_float`、`parse_int`、`parse_constant` 限制可接受类型。
2. **避免数值溢出**：极端大的整数在 Python 里没问题，但传递到 JavaScript 等语言会变成 `Infinity` 或溢出。

```python
import json
from decimal import Decimal

# 严格模式：拒绝 NaN 和 Infinity
def strict_constant(s):
    raise ValueError(f"拒绝特殊常量: {s}")

try:
    json.loads('{"v": NaN}', parse_constant=strict_constant)
except ValueError as e:
    print(e)
    # 输出：拒绝特殊常量: NaN
```

### 2.7 进阶：自定义编码器与解码器

如果你的项目涉及大量自定义类型的 JSON 互转，每个地方都写 `default` 回调会很啰嗦。这时可以使用 `JSONEncoder` / `JSONDecoder` 的子类，统一处理。

#### 2.7.1 JSONEncoder 子类

```python
import json
from datetime import datetime
from decimal import Decimal

class MyEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        if isinstance(obj, Decimal):
            return str(obj)
        if isinstance(obj, set):
            return sorted(obj)
        return super().default(obj)

data = {
    "ts": datetime(2024, 6, 15, 14, 30, 0),
    "amount": Decimal("19.99"),
    "tags": {"vip", "new"}
}

print(json.dumps(data, cls=MyEncoder, ensure_ascii=False))
# 输出：{"ts": "2024-06-15T14:30:00", "amount": "19.99", "tags": ["new", "vip"]}
```

通过 `cls=MyEncoder` 把一个自定义编码器传给 `dumps`，所有未知类型都会走 `default` 方法。

#### 2.7.2 JSONDecoder 子类

```python
import json
from datetime import datetime

class MyDecoder(json.JSONDecoder):
    def __init__(self, *args, **kwargs):
        # 注册一个 object_hook，对每个 dict 做后处理
        super().__init__(object_hook=self._hook, *args, **kwargs)

    def _hook(self, obj):
        # 自动识别 ISO 8601 字符串转回 datetime
        for k, v in obj.items():
            if isinstance(v, str) and len(v) >= 20 and 'T' in v:
                try:
                    obj[k] = datetime.fromisoformat(v)
                except ValueError:
                    pass
        return obj

raw = '{"ts": "2024-06-15T14:30:00", "name": "张三"}'
data = json.loads(raw, cls=MyDecoder)
print(data)
# 输出：{'ts': datetime.datetime(2024, 6, 15, 14, 30), 'name': '张三'}
print(type(data['ts']))
# 输出：<class 'datetime.datetime'>
```

自定义 Decoder 让反序列化与序列化保持对称，是个常见的工程模式。注意启发式还原（比如猜字符串是不是时间戳）有一定误差，标明字段是最稳妥的方式——例如约定字段名以 `_at` 结尾的必然是时间，或加一个 `"_type": "datetime"` 的元字段。

#### 2.7.3 Encoder / Decoder 使用建议

**何时用 default 参数，何时用 JSONEncoder 子类？**

| 场景 | 推荐方式 |
|------|---------|
| 只有一两个特殊类型 | `default=func` |
| 多个模块有相同的序列化需求 | 抽出 `JSONEncoder` 子类，全局复用 |
| 需要双向对称处理 | Encoder + Decoder 子类成对使用 |
| 一次性脚本 | `default` 函数，简单直接 |

## 3. 最佳实践

### 3.1 推荐 vs 不推荐的写法

#### 3.1.1 序列化字典时显式指定 ensure_ascii

**不推荐**：用默认参数，非 ASCII 字符全部转义，可读性差。

```python
# 不推荐
json_str = json.dumps({"name": "张三"})
# 结果：{"name": "\u5f20\u4e09"}
```

**推荐**：显式设置 `ensure_ascii=False`，保留原文。

```python
# 推荐
json_str = json.dumps({"name": "张三"}, ensure_ascii=False)
# 结果：{"name": "张三"}
```

#### 3.1.2 文件读写时显式指定编码

**不推荐**：依赖系统默认编码，跨平台会出问题。

```python
# 不推荐
with open("data.json", "w") as f:
    json.dump(data, f)
with open("data.json", "r") as f:
    data = json.load(f)
```

**推荐**：始终指定 `encoding="utf-8"`。

```python
# 推荐
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
with open("data.json", "r", encoding="utf-8") as f:
    data = json.load(f)
```

#### 3.1.3 序列化自定义对象统一用 default

**不推荐**：每个调用点都重复写转换逻辑。

```python
# 不推荐
json.dumps({"user": {"name": u.name, "age": u.age}})
json.dumps({"product": {"name": p.name, "price": float(p.price)}})
```

**推荐**：统一注册 `default` 函数或自定义 Encoder，集中处理。

```python
# 推荐
def smart_default(obj):
    if isinstance(obj, User):
        return {"name": obj.name, "age": obj.age}
    if isinstance(obj, Product):
        return {"name": obj.name, "price": float(obj.price)}
    raise TypeError(...)

json.dumps({"user": user}, default=smart_default)
```

#### 3.1.4 反序列化用 try/except 显式处理异常

**不推荐**：不加 try/except，出错时定位困难。

```python
# 不推荐
data = json.loads(user_input)
```

**推荐**：用 `try/except json.JSONDecodeError` 并记录错误位置。

```python
# 推荐
try:
    data = json.loads(user_input)
except json.JSONDecodeError as e:
    print(f"解析失败：{e.msg}（行 {e.lineno}，列 {e.colno}）")
    data = {}
```

### 3.2 JSON 在不同场景下的推荐参数组合

| 场景 | 推荐参数 | 原因 |
|------|---------|------|
| API 响应 | `ensure_ascii=False`, `separators=(',', ':')` | 紧凑可读 |
| 配置文件 | `ensure_ascii=False`, `indent=2` | 易于人工编辑 |
| 日志输出 | `ensure_ascii=False`, `indent=2`, `sort_keys=True` | 字段顺序稳定 |
| 跨语言签名（参与哈希） | `sort_keys=True`, `separators=(',', ':')` | 输出完全确定 |
| 极小化网络传输 | `separators=(',', ':')`, `ensure_ascii=True` | 字节最少 |

**这里有一个"签名稳定"技巧值得一提**：

```python
import json
import hashlib

data = {"b": 1, "a": 2, "c": 3}
# 不排序：不同顺序产出不同签名
hash1 = hashlib.md5(json.dumps(data).encode()).hexdigest()
hash2 = hashlib.md5(json.dumps({"a": 2, "b": 1, "c": 3}).encode()).hexdigest()
print(f"未排序匹配: {hash1 == hash2}")  # 可能是 False

# 排序后：内容相同则签名相同
hash3 = hashlib.md5(json.dumps(data, sort_keys=True).encode()).hexdigest()
hash4 = hashlib.md5(json.dumps({"a": 2, "b": 1, "c": 3}, sort_keys=True).encode()).hexdigest()
print(f"排序后匹配: {hash3 == hash4}")  # True
```

这种用法在 webhook 签名校验中很常见：先按一致的规则序列化再计算 MAC 或签名，避免顺序差异导致的校验失败。

### 3.3 性能要点

对大对象的 `dumps`/`loads` 是有开销的，几个影响性能的关键：

1. `ensure_ascii=False` 比 `True` 略快——不会做字符编码转换。
2. `separators=(',', ':')` 能减小输出体积，网络传输更快。
3. `indent` 为正数时会增加输出体积，不应在性能敏感场景使用。
4. 读 JSON 文件不要先 `f.read()` 再 `loads`：直接用 `json.load(f)` 更省内存。

```python
# 不推荐：先 read 再 loads，多一次内存拷贝
content = f.read()  # 一次性读入整个文件
data = json.loads(content)
```

```python
# 推荐：直接 load，更省内存
data = json.load(f)  # 解析器流式读取
```

`loads` 和 `load` 内部都是同一套解析器，但 `load` 走的是流式接口，在处理 GB 级别 JSON 文件时差异比较明显。

**更极端的大文件场景**：标准库的 `json` 模块是纯 Python 实现（C 加速器可选），对于上百 MB 的 JSON 文件可以用第三方的 `orjson` 或 `ujson` 替代，性能能提升 2~10 倍：

```python
# 标准库
import json
json.dumps(data)  # ~1

# orjson（需要 pip install orjson）
import orjson
orjson.dumps(data)  # 通常快 3~10 倍
```

## 4. 原理：json 模块的内部实现

理解 `json` 模块的实现方式有助于理解性能表现、扩展方式，以及遇到怪异问题时的诊断思路。这里讲到实现层面，便于日常使用和排查问题。

### 4.1 模块结构

Python 标准库的 `json` 采用**编码器/解码器分层**的设计：

```text
json.dumps / loads / dump / load     ← 用户 API 层（方便）
        ↓
    JSONEncoder / JSONDecoder         ← 基于类的扩展（面向 OOP）
        ↓
    C 优化实现（_json）/ 纯 Python   ← 底层实现（性能）
```

`json` 模块同时提供两个实现：
- **纯 Python 实现**：`json.encoder` 和 `json.decoder`，跨平台兼容。
- **C 加速实现**：`_json` 模块，CPython 启动时会优先加载。`dumps / loads` 都会尝试用 C 实现，性能更高。

通过 `json.decoder` 的 `py_decode` 和 `json.encoder` 的 `py_encode_basestring` 能看到纯 Python 版本的实现逻辑，方便学习理解。

### 4.2 dumps 的内部调用链

```text
json.dumps(obj, **kwargs)
  → JSONEncoder(**kwargs).encode(obj)
    → 对每个对象调用 default()（如果有未知类型）
    → 调用 c_make_encoder 或 py_make_encoder 进行序列化
      → 逐个处理类型：dict、list、str、int、float、bool、None
      → 递归处理嵌套
  → 返回序列化后的字符串
```

**默认的 default 实现只抛 TypeError**。你给 `default` 参数传入的函数会替换默认实现，遇到未知类型时被调用。

### 4.3 loads 的内部解析器

`loads` 的实现比 `dumps` 复杂——因为没有结构化指示，需要通过扫描器识别 token。

```text
json.loads(s, **kwargs)
  → JSONDecoder(**kwargs).decode(s)
    → 调用扫描器（scanstring、scanner）
    → 递归下降解析 object、array、value
    → 遇到 object → 构建 dict
    → 遇到 array → 构建 list
    → 遇到 string → 构建为 str（同时处理转义）
    → 遇到 number → 构建 int 或 float
    → 遇到 true/false/null → 构建 True/False/None
    → 每个对象构建完后调用 object_hook / object_pairs_hook
    → 返回顶层对象
```

`object_hook` 是**对每个解析出的 dict 做后处理**，而 `object_pairs_hook` 是更底层的钩子（接收键值对列表），默认走 `dict(pairs)`，你可以替换为 `OrderedDict` 或其他类。

### 4.4 类型映射的底层逻辑

Python 的 `True` 在 JSON 中变成 `true`，是因为 `json` 的编码器对 `bool` 做了特殊处理：

```python
# 简化的编码逻辑
def encode_value(obj):
    if obj is True:
        return "true"
    if obj is False:
        return "false"
    if obj is None:
        return "null"
    if isinstance(obj, str):
        return encode_string(obj)
    if isinstance(obj, (int, float)):
        return repr(obj)  # 数字转字符串
    if isinstance(obj, (list, tuple)):
        return encode_array(obj)
    if isinstance(obj, dict):
        return encode_object(obj)
    raise TypeError(f"无法序列化: {type(obj)}")
```

`bool` 在 Python 中实际是 `int` 的子类（True=1，False=0）。编码器必须先检查 `is True/False`，否则 `True` 会被当成整数 1 处理，输出就不是 `true` 而是 `1` 了。这也是为什么扩展 default 时要记得：用 `isinstance(obj, bool)` 判断时要放在 `isinstance(obj, int)` 之前。

```python
# 反例：bool 会被 int 分支拦截
def bad_default(obj):
    if isinstance(obj, int):
        return obj
    if isinstance(obj, bool):
        return {"_bool": obj}  # 永远到不了这里
    ...

# 正例：bool 判断放前面
def good_default(obj):
    if isinstance(obj, bool):
        return {"_bool": obj}
    if isinstance(obj, int):
        return obj
    ...
```

### 4.5 循环引用检测的实现

`check_circular` 默认开启，内部用一个 set 记录已经处理过的对象 id：

```text
dumps 对 dict 调用 encode_object:
  → obj_id = id(obj)
  → if obj_id in seen_set: raise ValueError("Circular reference detected")
  → seen_set.add(obj_id)
  → 递归编码子元素
  → seen_set.discard(obj_id)（编码完后移除）
```

这个机制能检测任意层级的循环引用，对深嵌套数据有少量开销。当数据量大且确信无循环时，可以显式关闭 `check_circular=False` 获得性能提升，但代价是危险——真有循环引用会无限递归导致栈溢出。

### 4.6 Encoder / Decoder 子类的扩展机制

```python
class MyEncoder(json.JSONEncoder):
    def default(self, obj):
        # 在这里扩展处理自定义类型
        ...
```

`JSONEncoder.default` 默认抛 `TypeError`。子类重写它后，`dumps` 在遇到未知类型时调用 `self.default(obj)`。这个简单的虚函数机制是 json 的核心扩展点，无需注册全局 handler 就能让每个项目定义自己的序列化规则。

`JSONDecoder` 的扩展更底层：
- `object_hook`：处理 dict 后能改写
- `object_pairs_hook`：处理键值对列表（在构建 dict 之前）
- `parse_float / parse_int / parse_constant`：精确控制数值和特殊常量的解析

灵活组合这些钩子可以实现完全自定义的解码行为。例如：保留键值对的原始顺序用 `OrderedDict`、使用 `dataclass` 自动重建对象等。
