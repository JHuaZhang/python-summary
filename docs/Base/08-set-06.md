## 1. 介绍

### 1.1 什么是集合去重

去重（deduplication）是编程中极其常见的需求——从一批数据中剔除重复项，只保留唯一值。Python 的「集合」（`set`）是处理去重最直接、最高效的工具。它的核心能力很纯粹：**同一个集合中，不会出现两个相等的元素**。当你向集合中添加一个元素时，如果该元素的值与集合中已有元素相等，这个新元素会被静默忽略。

```python
# 集合自动去重：重复元素只保留一个
unique_numbers = {1, 2, 2, 3, 3, 3}
print(unique_numbers)  # 输出：{1, 2, 3}
```

这看起来很简单，但背后隐藏着计算机科学中最精巧的数据结构之一——**哈希表（hash table）**。集合的几乎所有核心能力（O(1) 的添加、删除、成员判断、自动去重）都源自哈希表。理解集合去重的原理，本质上就是理解哈希表在集合场景下是如何工作的。

与列表去重相比，集合的优势是数量级的差异：

```python
# 列表去重：O(n^2) —— 每插一个元素都要扫描整个列表
def dedup_with_list(items):
    result = []
    for item in items:
        if item not in result:     # not in 是 O(n) 操作
            result.append(item)
    return result

# 集合去重：O(n) —— 哈希表定位，每个元素 O(1)
def dedup_with_set(items):
    return list(set(items))        # set() 构造过程中自动去重

# 用包含 10 万个大字符串的列表测试
import time, random, string
large_list = [''.join(random.choices(string.ascii_letters, k=20)) for _ in range(100000)]
# 再插入约一半重复，模拟真实去重场景
large_list = large_list + [random.choice(large_list) for _ in range(50000)]

start = time.perf_counter()
result_list = dedup_with_list(large_list[:5000])    # 列表法只能测小数据量
list_time = time.perf_counter() - start
print(f"列表去重 5000 条: {list_time:.4f}s")         # 输出示例：1.8s

start = time.perf_counter()
result_set = dedup_with_set(large_list)              # 集合法测试 15 万条
set_time = time.perf_counter() - start
print(f"集合去重 150000 条: {set_time:.4f}s")         # 输出示例：0.08s
```

列表去重的时间随数据量平方增长，集合去重近似线性增长。当数据量达到数万级别时，列表去重将变得不可用，而集合去重仍能在毫秒级完成。

### 1.2 集合的本质：只有键的哈希表

理解集合去重，首先要理解集合的底层结构。在 CPython 中，**集合本质上是一个简化的字典——只有键（元素），没有值**。字典的哈希表存储的是 `(hash, key, value)` 三元组，集合的哈希表则只存储元素本身。所有哈希表的核心机制——哈希函数、冲突处理、负载因子、扩容——在集合中完全适用。

```python
# 从数据结构的角度看，集合和字典共享同一套底层设施
# 集合：{elem1, elem2, elem3}  →  哈希表：存元素
# 字典：{k1: v1, k2: v2, k3}  →  哈希表：存 (key, value) 对

# 一个直观的类比：可以把集合看成"值永远为 None 的字典"
# set_demo = {'a', 'b', 'c'}
# dict_demo = {'a': None, 'b': None, 'c': None}  # 逻辑上等价
```

因为底层共享哈希表实现，集合和字典使用相同的哈希与判等约定：
- 元素必须**可哈希**（`hashable`），即实现了 `__hash__()` 方法且哈希值稳定不变
- 元素之间靠 `__eq__()` 判断是否相等，相等即视为"重复"
- 如果 `a == b`，则必须 `hash(a) == hash(b)`（反方向不要求）

这套规则是集合去重的全部基础——后续所有内容都围绕它展开。

### 1.3 集合去重的基本用法

Python 提供了多种使用集合去重的方式：

```python
# 方式一：用 {} 字面量直接创建集合并去重
nums = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5}
print(nums)  # 输出：{1, 2, 3, 4, 5, 6, 9}  ← 元素被去重，剩余的元素自动排序？

# 注意：{} 不是空集合，而是空字典！
# empty_set = {}      # TypeError？不，这是 dict
# print(type({}))     # <class 'dict'>

# 方式二：用 set() 构造函数从可迭代对象构建
chars = set("hello world")       # 字符串也是可迭代对象
print(chars)                     # 输出：{'r', 'd', ' ', 'o', 'w', 'e', 'h', 'l'}  ← 重复的 'l' 只保留一个

# 方式三：列表去重——最常用的场景
user_ids = [101, 102, 103, 101, 104, 102, 105]
unique_ids = list(set(user_ids))
print(unique_ids)                # 输出：[101, 102, 103, 104, 105]  ← 注意：顺序不一定保持

# 方式四：保留顺序的去重（利用 dict fromkeys 技巧）
# Python 3.7+ 的 dict 天然有序，利用 dict.fromkeys 去重同时保留首次出现顺序
ordered_unique = list(dict.fromkeys(user_ids))
print(ordered_unique)            # 输出：[101, 102, 103, 104, 105]  ← 保持了首次出现的顺序
```

**重要说明**：上述 demo 中的 `print(nums)` 输出显示的是排序后的形态，但**集合不保证排序，也不保证顺序**。这里的"排序"只是 CPython 小整数哈希值恰好等于自身带来的副作用，不能依赖。如果需要有序集合，使用 `OrderedDict.fromkeys()` 或第三方库。

### 1.4 集合 vs 列表去重的时间复杂度对比

先以一个数据量测试直观感受集合与列表的去重性能差距，再从原理层面说明"为什么"。

```python
import time

# 构造测试数据：50% 重复率
test_sizes = [100, 1000, 10000, 100000]
print(f"{'数据量':>8} {'列表去重耗时(s)':>18} {'集合去重耗时(s)':>18} {'加速比':>10}")
print("-" * 56)

for size in test_sizes:
    # 构造包含重复的数据
    half = size // 2
    data = list(range(half)) + list(range(half))  # 前一半和后一半完全重复
    
    # 列表去重
    start = time.perf_counter()
    result = []
    for item in data:
        if item not in result:
            result.append(item)
    list_time = time.perf_counter() - start
    
    # 集合去重
    start = time.perf_counter()
    unique = list(set(data))
    set_time = time.perf_counter() - start
    
    speedup = list_time / set_time if set_time > 0 else 0
    print(f"{size:>8} {list_time:>18.6f} {set_time:>18.6f} {speedup:>10.1f}x")
```

输出示例：
```
  数据量      列表去重耗时(s)       集合去重耗时(s)       加速比
--------------------------------------------------------
     100            0.000082            0.000003         27.3x
    1000            0.004582            0.000026        176.2x
   10000            0.298572            0.000319        936.0x
  100000           27.834201            0.003821       7284.3x
```

列表去重随数据量平方增长（O(n^2)），集合去重呈线性增长（O(n)）。数据量越大，差距越悬殊。这正是哈希表带来的质变。

### 1.5 哈希表前置知识：哈希值与可哈希性

在深入集合的哈希机制之前，先明确三个核心概念。

**哈希值（hash value）**：`hash(obj)` 返回一个整数，代表对象的"数字指纹"。关键性质：
- 同一进程内，同一个对象 `hash()` 返回值始终相同（稳定性）
- 如果 `a == b`，则 `hash(a) == hash(b)`（一致性）
- 不同对象可以有相同哈希值——这叫哈希冲突，是正常的

```python
# 不同类型对象的哈希值
print(hash("apple"))        # 输出：某个整数，如 -3700617445664685442
print(hash(42))             # 输出：42  ← 小整数的哈希值就是自身
print(hash(3.14))           # 输出：322818021289917443
print(hash((1, 2, 3)))      # 输出：529344067295497451

# 相等对象的哈希值也相等
print(hash(1.0) == hash(1))  # 输出：True  ← 1.0 == 1，所以哈希必须相等

# 同一对象多次 hash 结果一致
s = "hello"
print(hash(s) == hash(s))    # 输出：True
```

**可哈希性（hashability）**：一个对象能加入集合的前提是"可哈希"——即实现了 `__hash__()` 方法，且该方法返回的值在对象生命周期内恒定不变。不可变类型天然可哈希，可变类型天然不可哈希。

```python
# 可哈希类型：不可变对象
print(hash("hello"))          # 输出：整数
print(hash(42))               # 输出：整数
print(hash((1, 2)))           # 输出：整数
print(hash(frozenset({1, 2})))  # 输出：整数

# 不可哈希类型：可变对象
# print(hash([1, 2, 3]))     # TypeError: unhashable type: 'list'
# print(hash({1, 2}))         # TypeError: unhashable type: 'set'
# print(hash({"a": 1}))       # TypeError: unhashable type: 'dict'

# 判断对象是否可哈希
from collections.abc import Hashable
print(isinstance("hello", Hashable))       # 输出：True
print(isinstance([1, 2], Hashable))        # 输出：False
print(isinstance((1, [2]), Hashable))      # 输出：False ← 含可变元素的元组不可哈希
```

**同一性原则**："可哈希"不只看是否实现了 `__hash__`，还看哈希值是否**稳定**。如果一个对象实现了 `__hash__` 但哈希值随状态变化，它就"理论上不可哈希"——Python 虽然不会在语法层面阻止，但这种对象放入集合后会导致不可预期的行为（元素丢不掉、查找不到）。

```python
# "虚假的可哈希"——极危险的写法
class BadHash:
    def __init__(self, value):
        self.value = value
    
    def __hash__(self):
        return hash(self.value)   # 哈希值依赖于 value，而 value 是可变的！
    
    def __eq__(self, other):
        return isinstance(other, BadHash) and self.value == other.value
    
    def __repr__(self):
        return f"BadHash({self.value})"

# 先加入集合
bad_set = set()
obj = BadHash(10)
bad_set.add(obj)
print(bad_set)               # 输出：{BadHash(10)}
print(10 in bad_set)          # 输出：False（类型不同，不影响这里）
print(BadHash(10) in bad_set) # 输出：True（相同值可找到）

# 修改对象的值
obj.value = 20                # 哈希值变了！
print(BadHash(10) in bad_set) # 输出：False ← 对象还在集合中，但已经找不到了！
print(obj in bad_set)         # 输出：False ← 当前对象自身的哈希也变了，同样找不到

# 现在这个元素永远留在集合里了——集合既无法通过新哈希找到它，
# 也不允许重复添加（因为 obj 已在集合中）
bad_set.add(obj)              # 不报错也不生效——obj 已经在集合里了
print(bad_set)                # 输出：{BadHash(20)}  ← 原来那个找不到了，也无法删除
```

这个例子展示了**哈希稳定性为什么是集合去重的前提条件**——如果对象的哈希值会变，集合的整个定位系统就会失效。

## 2. 核心内容

### 2.1 集合去重的完整流程：hash() + __eq__() 协作

当向集合添加元素时，CPython 执行的是一套经过精确定义的流程，**不是简单地调用一次 hash() 就完事了**。理解这个流程，你才能真正理解"集合为什么能去重"。

**添加一个元素的完整步骤**：

```
step 1: 计算哈希值          h = hash(element)
step 2: 按掩码定位索引       idx = h & (table_size - 1)
step 3: 检查索引槽位状态     
         - 槽位为空 (EMPTY) → 直接放入，去重成功（无重复）
         - 槽位有元素：
           a) 先比哈希值     槽位条目的哈希 == h ?
              - 不等 → 冲突，按探测公式找下一槽位，回到 step 3
              - 相等 → 进入步骤 b)
           b) 再比 __eq__    槽位条目 == element ?
              - 相等 → 发现重复，静默放弃（不添加也不报错）
              - 不等 → 哈希冲突（碰撞），按探测公式找下一槽位，回到 step 3
step 4: 空闲时检查负载因子    若 usable 降到 0，触发 resize
```

```python
# 模拟集合添加元素的完整去重流程
class SimSet:
    """模拟集合的去重流程"""
    EMPTY = object()
    DUMMY = object()
    
    def __init__(self, size=8):
        self.size = size
        self.mask = size - 1
        self.table = [self.EMPTY] * size  # 槽位数组，只存元素（不存 hash-key-value）
        self.used = 0
        self.usable = size * 2 // 3
    
    def _probe(self, element):
        """探测，返回 (插入位置, 是否为重复)"""
        h = hash(element)
        idx = h & self.mask
        perturb = h
        
        while self.table[idx] is not self.EMPTY:
            existing = self.table[idx]
            if existing is self.DUMMY:
                # DUMMY 可复用，但不能停下——需要确认元素是否在后面
                idx = (idx + 1) & self.mask
                continue
            
            # 先比哈希值（性能优化：哈希值不等直接跳过）
            # 在真正的 CPython 中，槽位会缓存哈希值；这里简化了
            if hash(existing) == h and existing == element:
                return idx, True   # 找到重复！
            
            # 哈希冲突：哈希相等但 __eq__ 不等，或哈希不等
            # 继续探测
            perturb >>= 5
            idx = (idx * 5 + 1 + perturb) & self.mask
        
        return idx, False
    
    def add(self, element):
        idx, found = self._probe(element)
        if found:
            return  # 重复，静默忽略
        
        if self.usable <= 0:
            self._resize()
            idx, _ = self._probe(element)  # resize 后重新定位
        
        self.table[idx] = element
        self.used += 1
        self.usable -= 1
    
    def _resize(self):
        """扩容"""
        new_size = max(8, self.used * 2)
        sz = 8
        while sz < new_size:
            sz <<= 1
        
        old_table = [e for e in self.table if e is not self.EMPTY and e is not self.DUMMY]
        
        self.size = sz
        self.mask = sz - 1
        self.table = [self.EMPTY] * sz
        self.used = 0
        self.usable = sz * 2 // 3
        
        for elem in old_table:
            idx, _ = self._probe(elem)
            self.table[idx] = elem
            self.used += 1
            self.usable -= 1

# 测试模拟集合的去重效果
ss = SimSet()
ss.add("apple")
ss.add("banana")
ss.add("apple")        # 重复，应该被忽略
ss.add("cherry")

# 查看内部状态
print(f"有效元素数: {ss.used}")       # 输出：3  ← 只添加了 3 个不同元素
print(f"内部数组: {[e if e is not SimSet.EMPTY else 'EMPTY' for e in ss.table]}")
```

这个流程揭示了两个关键事实：

1. **哈希值是先导**：先比哈希可以快速排除绝大多数槽位。因为哈希值是整数，比较一次整数运算比调用 `__eq__`（可能涉及复杂的属性对比）快得多。
2. **`__eq__` 充当最终裁决**：哈希值相等只代表"可能在同一个槽"，是否真重复要看 `__eq__`。两个不同的元素可以有相同的哈希值（哈希碰撞），这时 `__eq__` 会防止它们被错误地当作重复。

```python
# 演示 __eq__ 的最终裁决作用
class SimilarString:
    """模拟两个值不同但哈希可能相同的对象"""
    def __init__(self, content):
        self.content = content
    
    def __hash__(self):
        return 42   # 强制所有实例哈希相同
    
    def __eq__(self, other):
        if not isinstance(other, SimilarString):
            return NotImplemented
        return self.content == other.content
    
    def __repr__(self):
        return f"SS({self.content!r})"

s1 = SimilarString("Hello")
s2 = SimilarString("World")   # s1 和 s2 哈希相同（都是 42）
s3 = SimilarString("Hello")   # s3 和 s1 __eq__ 相等

test_set = {s1, s2}           # s1 和 s2 哈希相同但 __eq__ 不等，都可以加入
print(len(test_set))          # 输出：2  ← 哈希冲突但值不同，两个元素共存

test_set.add(s3)              # s3 虽然哈希也是 42，但 s3 == s1，所以是重复
print(len(test_set))          # 输出：2  ← s3 被视为 s1 的重复，被忽略
```

这个例子的核心价值在于显示：**哈希值相同不意味着被去重**，只有 `__eq__` 判定相等才算重复。哈希冲突（hash collision）和值重复（value duplicate）是两个不同的概念。

### 2.2 hash() 函数详解：各类型的实现行为

`hash()` 是集合去重的"第一关"。不同类型的对象有各自的哈希算法，但它们都遵循相同的契约。理解这些行为，对于预测集合何时会去重、何时不会，至关重要。

```python
# 整数类型的哈希
# int: 小整数（64 位平台为 -2^61 到 2^61-1 范围）的哈希值就是自身
# -1 被特殊处理为 -2（因为 -1 在 CPython 内部用作错误标记）
print(hash(0))       # 输出：0
print(hash(1))       # 输出：1
print(hash(42))      # 输出：42
print(hash(-1))      # 输出：-2  ← 特殊处理
print(hash(10**30))  # 输出：某个整数（大整数截断）

# 关键：数值相等的整数哈希相等
print(hash(1) == hash(1))      # 输出：True
print(hash(True) == hash(1))   # 输出：True  ← True == 1，所以哈希相等
```

```python
# 浮点数的哈希
# 基于 IEEE 754 二进制表示，但关键约束是：a == b ⇒ hash(a) == hash(b)
print(hash(1.0))           # 输出：1  ← hash(1.0) == hash(1)，因为 1.0 == 1
print(hash(3.14))          # 输出：某个整数
print(hash(float('nan')))  # 输出：0  ← NaN 特殊处理

# 0.0 和 -0.0 是相等的
print(0.0 == -0.0)         # 输出：True
print(hash(0.0) == hash(-0.0))  # 输出：True

# 浮点数精度问题对集合去重的影响
s = {0.1 + 0.2, 0.3}
print(s)                   # 输出：{0.3, 0.30000000000000004}  ← 两个元素！
print(0.1 + 0.2)           # 输出：0.30000000000000004
print(0.1 + 0.2 == 0.3)   # 输出：False

# 所以：用浮点数在集合中做去重要格外小心
prices = [0.1, 0.2, 0.3, 0.1 + 0.2, 0.4, 0.3]
unique_prices = list(set(prices))
print(unique_prices)       # 输出：可能是 [0.1, 0.2, 0.3, 0.30000000000000004, 0.4]
# 0.3 和 0.1+0.2 被认为是不同的值，虽然数学上相等
```

```python
# 字符串的哈希
# Python 3.4+ 使用 SipHash 算法
# 受 PYTHONHASHSEED 影响——同一字符串不同进程哈希值不同
print(hash("hello"))       # 输出：每次运行不同
print(hash("hello") == hash("hello"))  # 输出：True ← 同一进程内相同

# 字符串去重示例
words = ["the", "quick", "brown", "fox", "jumps", "over", "the", "lazy", "dog", "the"]
unique_words = set(words)
print(unique_words)        # 输出：{'the', 'over', 'lazy', 'brown', 'jumps', 'quick', 'dog', 'fox'}
# "the" 出现了三次，集合中只保留一次
```

```python
# 元组的哈希
# 基于元素哈希值的混合，公式大致为：h = h ^ (hash(elem) * mult) 循环
print(hash((1, 2, 3)))     # 输出：529344067295497451
print(hash((3, 2, 1)))     # 输出：不同的值 ← 顺序重要

# 元素顺序影响哈希值！
print(hash((1, 2, 3)) == hash((3, 2, 1)))  # 输出：False

# 含可变元素的元组不可哈希
# print(hash((1, [2])))    # TypeError

# 嵌套元组可哈希（因为元组是不可变的）
print(hash(((1, 2), (3, 4))))   # 输出：整数

# 元组集合去重示例：用元组表示坐标，在集合中去重
coordinates = [(1, 2), (3, 4), (1, 2), (5, 6), (3, 4), (7, 8)]
unique_coords = set(coordinates)
print(unique_coords)       # 输出：{(3, 4), (5, 6), (1, 2), (7, 8)}
```

```python
# frozenset（冻结集合）的哈希
# 基于所有元素的哈希值 XOR 组合——因为集合无序，XOR 交换律适合表达无序性
fs1 = frozenset([1, 2, 3])
fs2 = frozenset([3, 1, 2])   # 相同元素，不同顺序
print(hash(fs1) == hash(fs2))   # 输出：True  ← 因为 XOR 交换律

# frozenset 可哈希，因此可以放入 set 中
fs3 = frozenset([4, 5, 6])
set_of_frozensets = {fs1, fs3, frozenset([1, 2, 3])}  # fs1 和最后一个重复
print(len(set_of_frozensets))    # 输出：2  ← 两个 frozenset，因为 [1,2,3] 重复

# frozenset 作为集合元素的场景：分组去重
# 例如：对一组无序的标签分组去重
tag_groups = [
    frozenset(["python", "data"]),
    frozenset(["data", "python"]),   # 与上一组相同
    frozenset(["java", "web"]),
    frozenset(["python", "ml"]),
]
unique_groups = set(tag_groups)
print(len(unique_groups))   # 输出：3  ← 前两组被视为重复
```

### 2.3 为什么可变对象不能放入集合

集合要求元素可哈希，而可哈希的核心是**哈希值稳定**。可变对象（list、dict、set）的哈希值随内容变化，如果将它们放入集合，会导致致命的问题。

```python
# 清单：哪些类型不能放入集合
# 列表
# s = set()
# s.add([1, 2, 3])       # TypeError: unhashable type: 'list'

# 字典
# s.add({"a": 1})        # TypeError: unhashable type: 'dict'

# 集合（自身）
# s.add({1, 2})          # TypeError: unhashable type: 'set'
```

为什么 Python 要这样设计？用一个思维实验说明：

```python
# 如果列表能放入集合，会发生什么？
# Python 没有允许这个，但我们可以模拟"破坏性"的行为：

class MutableInSet:
    """模拟如果可变对象能放入集合会怎样"""
    def __init__(self, items):
        self.items = items
    
    def __hash__(self):
        # 危险的设计：哈希值依赖于可变的 items
        # 如果 items 变化，哈希值也变化
        return hash(tuple(self.items))
    
    def __eq__(self, other):
        return isinstance(other, MutableInSet) and self.items == other.items
    
    def __repr__(self):
        return f"MIS({self.items!r})"

# step 1: 创建对象并放入集合
obj = MutableInSet([1, 2, 3])
s = {obj}
print(f"初始状态: {s}")
print(f"obj in s: {obj in s}")         # 输出：True

# step 2: 修改对象内容——哈希值随之改变
obj.items.append(4)                    # 哈希值变了！
print(f"\n修改后: {obj}")
print(f"obj in s: {obj in s}")         # 输出：False ← 找不到 obj 了！
print(f"s 的长度: {len(s)}")           # 输出：1  ← obj 还在集合里

# step 3: 再创建一个"新"对象，尝试删除原来的
# 此时无法通过任何方式移除原来的 obj
# s.remove(MutableInSet([1, 2, 3, 4])) # 这个对象的哈希值路径不同
# s.discard(obj)                       # obj 的哈希已变，discard 也定位不到

# 结论：obj 成了"幽灵元素"——占用内存、永远无法访问或删除
```

这解释了 Python 的语言设计决策：**与其让程序员承担这种调试噩梦，不如在语法层面直接禁止可变类型**。当你试图把列表加入集合时，Python 在 `hash()` 这一步就抛出异常，堵死所有可能的错误路径。

```python
# 例外情况：自定义类的实例虽然内部状态可变，但默认是"可哈希"的
# 这是因为默认的 __hash__ 基于 id()，而 id() 在对象生命周期内不变
class MutablePoint:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    
    # 没有定义 __hash__ 和 __eq__
    # 默认：__hash__ 基于 id，__eq__ 基于身份（is）
    
p1 = MutablePoint(3, 4)
p2 = MutablePoint(3, 4)   # 内容相同但 id 不同

s = {p1}
print(p1 in s)             # 输出：True
print(p2 in s)             # 输出：False  ← 内容相同但 id 不同

# 虽然可以这么做，但通常不是你想要的行为
# 如果要按"值"去重，必须显式实现 __hash__ 和 __eq__
```

### 2.4 不可哈希的元组：含有可变元素的嵌套元组

元组本身是不可变的，但如果元组的元素中有可变对象，这个元组也**不可哈希**——因为它的哈希值依赖于可变元素的哈希值，而可变元素没有稳定的哈希。

```python
# 全是不可变元素的元组 → 可哈希
t1 = (1, 2, 3)
t2 = ("hello", 42, (1, 2))
print(hash(t1))   # 输出：整数
print(hash(t2))   # 输出：整数

# 含可变元素的元组 → 不可哈希
# t3 = (1, [2, 3])         # 这里虽然不报错
# print(hash(t3))          # TypeError: unhashable type: 'list'

# 含字典的元组
# t4 = ({"a": 1}, 2)      
# print(hash(t4))          # TypeError: unhashable type: 'dict'

# 含集合的元组
# t5 = ({1, 2}, 3)        
# print(hash(t5))          # TypeError: unhashable type: 'set'

# 这对集合去重的实际影响
data_items = [
    (1, 2, 3),
    (4, 5, 6),
    (1, 2, 3),               # 重复
    # (1, [2, 3]),           # 这个元素会导致 set() 构造失败
]

unique_tuples = set(data_items)
print(unique_tuples)         # 输出：{(4, 5, 6), (1, 2, 3)}

# 实战场景：对包含元组的列表去重，但元组中不能有可变对象
records = [
    ("Alice", 30, "Engineer"),
    ("Bob", 25, "Designer"),
    ("Alice", 30, "Engineer"),   # 重复
    ("Charlie", 35, "Manager"),
]

# 输出：[('Charlie', 35, 'Manager'), ('Alice', 30, 'Engineer'), ('Bob', 25, 'Designer')]
```

### 2.5 哈希冲突与探测：集合如何让不同元素共存

哈希冲突（hash collision）是指两个不同的元素计算出的哈希值相同（或经过掩码后映射到同一个槽位）。集合必须能够处理这种情况——让多个哈希冲突的元素共存。

```python
# 演示哈希冲突场景
# 人为构造一组哈希值相同的元素
class HashCollider:
    def __init__(self, value, tag=""):
        self.value = value
        self.tag = tag
    
    def __hash__(self):
        # 强制所有实例哈希值一样
        # 用固定值制造极端冲突条件
        return 42
    
    def __eq__(self, other):
        if not isinstance(other, HashCollider):
            return NotImplemented
        return self.value == other.value
    
    def __repr__(self):
        return f"HC({self.value})"

# 添加 20 个哈希相同的元素
collision_set = set()
for i in range(20):
    collision_set.add(HashCollider(i))

print(f"集合大小: {len(collision_set)}")       # 输出：20（每个 value 不同）
# 所有元素哈希都是 42，但因为 __eq__ 区分它们，所以 20 个都可以共存
# 但查找性能会大幅下降——因为所有元素在同一个探测链上

import time

# 正常集合：均匀分布
normal_set = set(range(1000))
start = time.perf_counter()
for _ in range(10000):
    _ = 500 in normal_set
normal_time = time.perf_counter() - start

# 冲突集合：全部哈希相同
class IntCollider:
    def __init__(self, val):
        self.val = val
    def __hash__(self):
        return 42
    def __eq__(self, other):
        return isinstance(other, IntCollider) and self.val == other.val
    def __repr__(self):
        return f"IC({self.val})"

collided_set = set(IntCollider(i) for i in range(1000))
start = time.perf_counter()
target = IntCollider(500)
for _ in range(10000):
    _ = target in collided_set
collided_time = time.perf_counter() - start

print(f"正常集合查找耗时: {normal_time:.6f}s")     # 输出：约 0.0002s（近乎常数）
print(f"冲突集合查找耗时: {collided_time:.6f}s")    # 输出：约 0.03s（退化明显）
```

### 2.6 Python 集合的两种冲突策略：链地址法 vs 开放寻址

哈希冲突的处理策略主要有两大类。Python 的字典和集合早期版本使用不同的策略，而现在它们都基于**开放寻址法（open addressing）**。

**链地址法（chaining）**：每个槽位是一个链表（或桶），冲突的元素挂在同一个槽位的链表上。查找时，先定位到槽位，再在链表中线性查找。

```
链地址法示意：
  槽位 0 → [(hash, key1), (hash, key2)]    ← 冲突的元素在同一链表
  槽位 1 → EMPTY
  槽位 2 → [(hash, key3)]
  ...
```

**开放寻址法（open addressing）**：没有链表结构。当槽位被占时，按探测序列找下一个空位。查找时走同样的探测序列。

```
开放寻址法示意：
  槽位 0 → key1     ← 哈希到槽 0
  槽位 1 → key2     ← 和 key1 同哈希，探测到槽 1
  槽位 2 → key3     ← 又冲突，再探测到槽 2
  槽位 3 → EMPTY
  ...
```

```python
# 两种策略的对比实现

# 链地址法实现（简化版，仅演示思想）
class ChainingSet:
    def __init__(self, size=8):
        self.size = size
        self.table = [[] for _ in range(size)]  # 每个槽位是一个列表
    
    def _bucket(self, element):
        return hash(element) % self.size
    
    def add(self, element):
        bucket = self._bucket(element)
        if element not in self.table[bucket]:   # 在链表中线性查找
            self.table[bucket].append(element)
    
    def __contains__(self, element):
        bucket = self._bucket(element)
        return element in self.table[bucket]    # 线性查找

# 开放寻址法实现（简化版，线性探测）
class OpenAddrSet:
    EMPTY = object()
    
    def __init__(self, size=8):
        self.size = size
        self.table = [self.EMPTY] * size
    
    def add(self, element):
        idx = hash(element) % self.size
        while self.table[idx] is not self.EMPTY:
            if self.table[idx] == element:
                return              # 重复
            idx = (idx + 1) % self.size  # 线性探测下一槽
        self.table[idx] = element
    
    def __contains__(self, element):
        idx = hash(element) % self.size
        while self.table[idx] is not self.EMPTY:
            if self.table[idx] == element:
                return True
            idx = (idx + 1) % self.size
        return False

# 测试两种实现
print("=== 链地址法 ===")
cs = ChainingSet(4)
chars = "hello world"
for c in chars:
    cs.add(c)
print(f"'h' in set: {'h' in cs}")    # 输出：True
print(f"'l' in set: {'l' in cs}")    # 输出：True
print(f"内部结构: {cs.table}")
# 输出示例：{..., ['h', 'e', 'w', 'r', 'd'], ['l', 'o', ' ']}

print("\n=== 开放寻址法 ===")
os = OpenAddrSet(8)
for c in chars:
    os.add(c)
print(f"'h' in set: {'h' in os}")    # 输出：True
print(f"内部结构: {[e if e is not OpenAddrSet.EMPTY else 'EMPTY' for e in os.table]}")
```

CPython 选择开放寻址而不是链地址法，主要有以下考量：

1. **缓存友好**：链地址法中的链表节点分散在内存中，CPU 缓存命中率低。开放寻址法的数组是连续内存块，缓存更友好。
2. **无额外指针开销**：链表的每个节点需要额外指针存储，开放寻址法只需一个数组。
3. **可预测的内存访问**：线性探测的访问模式是顺序的，对 CPU 预取更友好。

但开放寻址也有代价：删除时需要 DUMMY 标记（防止探测链断裂），当负载因子高时冲突率上升快于链地址法。

### 2.7 集合的负载因子与扩容机制

与字典类似，集合也有负载因子和扩容机制。但集合的负载因子阈值与字典不同。

```python
import sys

# 观察集合的元素增长时的扩容行为
s = set()
prev_size = sys.getsizeof(s)
resize_points = [(0, prev_size)]

for i in range(1, 100):
    s.add(i)
    cur_size = sys.getsizeof(s)
    if cur_size != prev_size:
        resize_points.append((len(s) - 1, cur_size))
        prev_size = cur_size

print("集合扩容记录（元素数 → 内存）：")
for count, mem in resize_points[1:]:  # 跳过初始状态
    print(f"  元素数={count:<5} → 内存={mem:>6} bytes")
```

输出示例：
```
  元素数=5     →    内存=728 bytes
  元素数=10    →    内存=728 bytes
  元素数=19    →    内存=2264 bytes
  元素数=38    →    内存=7288 bytes
  元素数=76    →    内存=22856 bytes
```

集合的负载因子阈值约为 **2/3**，即当元素数量达到槽位数的约 2/3 时触发扩容。这个阈值与字典相同。但集合的扩容行为略有不同——**集合的初始大小是 8，扩容时新大小为当前元素数量的 4 倍（而非字典的 2 倍）**，然后向上取 2 的幂。

```python
# 模拟集合的扩容计算逻辑
def set_next_size(current_used):
    """根据当前元素数计算集合扩容后的大小"""
    if current_used == 0:
        return 8
    # 集合扩容策略：new_size = used * 4（向上取 2 的幂）
    new_estimate = current_used * 4
    size = 8
    while size < new_estimate:
        size <<= 1
    return size

# 在各种数据量下，集合的扩容行为
test_sizes = [0, 1, 5, 10, 50, 100, 1000]
for used in test_sizes:
    next_size = set_next_size(used)
    usable = next_size * 2 // 3  # 按 2/3 计算可装元素数
    print(f"当前元素={used:<5} → 下次扩容大小={next_size:<6} → 可容纳 ≈ {next_size * 2 // 3}")
```

扩容时，集合会分配一个新的大数组，将所有现有元素重新哈希后插入新数组。这个操作是 O(n) 的，但因为每次扩容后新数组足够大，下次扩容需要较长时间，**均摊到每次插入仍然是 O(1)**。

```python
# 测试集合的均摊性能：测量大量插入的平均耗时
import time

def measure_insert_avg(n):
    s = set()
    start = time.perf_counter()
    for i in range(n):
        s.add(i)
    elapsed = time.perf_counter() - start
    return elapsed / n  # 平均每次插入时间

# 不同数据量下的均摊时间
for n in [1000, 10000, 100000, 1000000]:
    avg = measure_insert_avg(n)
    print(f"插入 {n:>7} 个元素，平均每个: {avg*1e6:.2f}μs")  # 微秒
```

运行结果将显示，随着 n 增长，均摊时间趋近于一个常数——这就是 O(1) 均摊的含义。

### 2.8 集合去重中的 `__hash__` 与 `__eq__` 调用时机详解

在集合添加元素的探测过程中，`__hash__` 和 `__eq__` 的调用次数是不同的：

- **`__hash__` 调用 1 次**：在探测开始时计算目标元素的哈希值（除非哈希值已被缓存）。
- **`__eq__` 调用 0 到 N 次**：在探测路径上，只有哈希值匹配的槽位才需要调用 `__eq__` 来最终确认是否重复。哈希值不匹配的槽位直接跳过，不调用 `__eq__`。

```python
# 追踪 __hash__ 和 __eq__ 的调用次数
class TracedString:
    def __init__(self, content):
        self.content = content
    
    def __hash__(self):
        result = hash(self.content)
        print(f"  [hash] {self.content!r} → {result}")
        return result
    
    def __eq__(self, other):
        result = self.content == other.content
        print(f"  [eq]   {self.content!r} == {other.content!r} → {result}")
        return result
    
    def __repr__(self):
        return f"T({self.content!r})"

print("=== 向空集合添加元素 ===")
s = set()
s.add(TracedString("apple"))
print()

print("=== 向有元素的集合添加重复元素 ===")
s.add(TracedString("apple"))    # 重复：hash 匹配 + eq 匹配 → 去重
print()

print("=== 向有元素的集合添加不同元素（无冲突） ===")
s.add(TracedString("banana"))   # 不同：hash 可能不同，也可能冲突
print()

print("=== 查询存在的元素 ===")
_ = TracedString("apple") in s
print()

print("=== 查询不存在的元素 ===")
_ = TracedString("grape") in s
```

输出会显示：
- 每次 `in` 或 `add` 开始时调用一次 `__hash__`
- 只有落入同一槽位（哈希值匹配）的元素才会触发 `__eq__` 比较
- `__eq__` 的调用次数等于探测路径上哈希匹配的槽位数

这意味着：**如果你的 `__hash__` 分布均匀，`__eq__` 几乎不会被调用**——每个槽位大概率只有一个元素，一次 `__hash__` 定位就足够。性能优化的关键在 `__hash__` 的均匀性，不在 `__eq__` 的速度。

### 2.9 自定义对象放入集合：实现 `__hash__` 和 `__eq__`

自定义类的实例默认可以放入集合（因为基于 `id()` 的 `__hash__` 存在），但这导致的是"按身份去重"而非"按值去重"。要正确按值去重，必须同时实现 `__hash__` 和 `__eq__`。

```python
# 不实现 __hash__ 和 __eq__：按身份去重
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

p1 = Person("Alice", 30)
p2 = Person("Alice", 30)        # 内容相同
p3 = Person("Bob", 25)

people = {p1, p2, p3}
print(f"默认行为: {len(people)}")  # 输出：3  ← 三个不同对象，即使 p1 和 p2 内容相同

# 原因：默认 __hash__ 基于 id()，p1 和 p2 id 不同，所以哈希不同
print(f"p1 hash: {hash(p1)}, p2 hash: {hash(p2)}")  # 两个不同的整数
```

```python
# 正确实现 __hash__ 和 __eq__：按值去重
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def __repr__(self):
        return f"Person({self.name!r}, {self.age})"
    
    def __eq__(self, other):
        if not isinstance(other, Person):
            return NotImplemented
        return self.name == other.name and self.age == other.age
    
    def __hash__(self):
        # 最佳实践：委托给不可变元组的哈希
        return hash((self.name, self.age))

p1 = Person("Alice", 30)
p2 = Person("Alice", 30)        # 内容相同
p3 = Person("Bob", 25)

people = {p1, p2, p3}
print(f"按值去重后: {len(people)}")  # 输出：2  ← p2 被识别为 p1 的重复
print(people)
# 输出：{Person('Alice', 30), Person('Bob', 25)}
```

**实现 `__hash__` 的最佳实践**：

```python
# 推荐方案 1：委托给 tuple 的 hash
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __hash__(self):
        return hash((self.x, self.y))   # 简单、可靠

# 推荐方案 2：使用 XOR 组合（适用于无序属性）
class Color:
    def __init__(self, r, g, b):
        self.r, self.g, self.b = r, g, b
    def __hash__(self):
        return hash((self.r, self.g, self.b))  # 建议仍用 tuple 而不是 XOR

# 不推荐：手动混合（容易不均匀）
class BadHashDemo:
    def __init__(self, a, b):
        self.a, self.b = a, b
    def __hash__(self):
        # return hash(self.a) ^ hash(self.b)  # XOR 可能导致不同组合得到相同哈希
        return hash(self.a) + hash(self.b)     # 加法也不够好
    # 始终用 hash((a, b)) 最安全
```

**关键规则**：实现 `__hash__` 时，必须保证**只依赖不可变属性**。如果一个属性在对象创建后会被修改，就不能用于计算哈希。

```python
# 错误示范：__hash__ 依赖可变属性
class BadPerson:
    def __init__(self, name, age):
        self.name = name
        self.age = age
    
    def __hash__(self):
        return hash((self.name, self.age))   # 如果 name 或 age 可变，就出问题
    
    def __eq__(self, other):
        return isinstance(other, BadPerson) and self.name == other.name and self.age == other.age

# 实际使用
bp = BadPerson("Alice", 30)
s = {bp}
print(bp in s)           # 输出：True

bp.age = 31              # 修改了属性，哈希值变了！
print(bp in s)           # 输出：False ← 找不到 bp 了！

# 解决：要么将对象设计为不可变，要么基于不可变标识计算哈希
class ImmutablePerson:
    def __init__(self, name, age):
        self._name = name
        self._age = age
    
    @property
    def name(self):
        return self._name
    
    @property
    def age(self):
        return self._age
    
    def __hash__(self):
        return hash((self._name, self._age))
    
    def __eq__(self, other):
        return isinstance(other, ImmutablePerson) and self._name == other._name and self._age == other._age
```

### 2.10 集合的去重应用场景

集合去重在实际编码中有多种常见模式，下面列出最常用的几种。

```python
# 场景 1：列表去重
logins = ["alice", "bob", "alice", "charlie", "bob", "dave"]
unique_logins = list(set(logins))
print(unique_logins)    # 输出：['dave', 'charlie', 'alice', 'bob']

# 场景 2：保留顺序的去重（Python 3.7+）
ordered = list(dict.fromkeys(logins))
print(ordered)          # 输出：['alice', 'bob', 'charlie', 'dave']

# 场景 3：列表的列表去重（需要转为可哈希类型）
data = [[1, 2], [3, 4], [1, 2], [5, 6]]
# 将内部列表转为元组
unique = list(set(tuple(sub) for sub in data))
print(unique)           # 输出：[(1, 2), (5, 6), (3, 4)]

# 场景 4：字典列表去重（借助 frozenset 或排序后的元组）
records = [
    {"id": 1, "name": "Alice"},
    {"id": 2, "name": "Bob"},
    {"id": 1, "name": "Alice"},
]
# 方法：将字典转为 frozenset 的 items 元组（假设结构一致）
def dict_to_key(d):
    return frozenset(d.items())

unique_records = list({dict_to_key(d): d for d in records}.values())
print(unique_records)
# 输出：[{'id': 1, 'name': 'Alice'}, {'id': 2, 'name': 'Bob'}]

# 场景 5：按照对象的某个属性去重
class Product:
    def __init__(self, sku, name):
        self.sku = sku
        self.name = name
    def __repr__(self):
        return f"Product({self.sku}, {self.name!r})"

products = [
    Product("P001", "苹果"),
    Product("P002", "香蕉"),
    Product("P001", "苹果"),      # 重复的 sku
]

# 按照 sku 去重
seen = set()
unique_products = []
for p in products:
    if p.sku not in seen:
        seen.add(p.sku)
        unique_products.append(p)
print(unique_products)   # 输出：[Product(P001, '苹果'), Product(P002, '香蕉')]

# 场景 6：文本去重（忽略空行和空白）
raw_text = """hello world
python is great
hello world
data science
python is great"""

lines = raw_text.splitlines()
unique_lines = list(dict.fromkeys(line.strip() for line in lines if line.strip()))
print(unique_lines)     # 输出：['hello world', 'python is great', 'data science']
```

### 2.11 集合去重的"副作用"：元素顺序不保证

使用集合去重时最容易踩的坑是**顺序不保证**。集合没有顺序概念，去重后元素的排列顺序是哈希表内部布局的产物，不可预测、不可依赖。

```python
# 同一集合在不同运行环境、不同 Python 版本甚至不同数据量下顺序不同
nums1 = {3, 1, 4, 1, 5, 9}
nums2 = {9, 5, 4, 3, 1, 0, 8}   # 不同数据量

# 外观上看起来元素像是"排序"的，但这只是小整数哈希等于自身的产物
print(nums1)  # 输出：{1, 3, 4, 5, 9}
print(nums2)  # 输出：{0, 1, 3, 4, 5, 8, 9}
# 注意：大整数或字符串的集合就不会有这样的"排序"外观

# 字符串集合没有排序外观
words = set(["apple", "banana", "cherry", "date", "elderberry"])
print(words)  # 输出：{'banana', 'date', 'apple', 'cherry', 'elderberry'}

# 实战教训：不要依赖集合去重后的顺序
def process_tags(raw_tags):
    """不正确的去重：后续逻辑依赖顺序会出错"""
    tags = raw_tags.split(",")
    return list(set(tags))

def process_tags_ordered(raw_tags):
    """正确的去重：保留顺序"""
    tags = raw_tags.split(",")
    return list(dict.fromkeys(tag.strip() for tag in tags))

user_tags = "python,data,ml,python,web,data"
print(f"无序: {process_tags(user_tags)}")
print(f"有序: {process_tags_ordered(user_tags)}")
```

如果需要保留顺序且去重，除了 `dict.fromkeys` 方法，也可在需要显式理解的场景下使用以下写法：

```python
def dedup_ordered(items):
    """保留首次出现顺序的去重"""
    seen = set()
    result = []
    for item in items:
        if item not in seen:
            seen.add(item)
            result.append(item)
    return result

# 这种方式的好处：清晰、可控、可扩展（可以按条件去重）
items = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5]
print(dedup_ordered(items))  # 输出：[3, 1, 4, 5, 9, 2, 6]
```

## 3. 最佳实践

### 3.1 保留顺序的去重优先用 `dict.fromkeys`

集合去重虽然快，但不保证顺序。当你需要**既去重又保留首次出现顺序**时，用 `dict.fromkeys` 是 Python 3.7+ 最简便的方式。

```python
# 推荐：dict.fromkeys 保留顺序
config_keys = ["host", "port", "host", "debug", "port", "timeout", "debug"]
unique = list(dict.fromkeys(config_keys))
print(unique)   # 输出：['host', 'port', 'debug', 'timeout']

# 不推荐：set() + 排序（你不知道原始顺序）
# 如果原始数据有业务含义的顺序，set() 后排序可能丢失信息
# 除非你确定顺序不重要
```

`dict.fromkeys` 的内部原理也很简单——字典的键是唯一的（去重），且 Python 3.7+ 字典保留插入顺序。所以 `dict.fromkeys(iterable)` 天然就是一个"顺序保留去重器"。

### 3.2 海量数据的去重：不要直接 set(iterable)

当数据量极大（数百万条）时，一次性 `set(massive_data)` 会占用大量内存。如果你只需要判断某个元素是否存在而非完整保存所有元素，考虑其他数据结构。

```python
# 场景：有一个 1000 万条数据的日志文件，想快速判断某 IP 是否出现过
# 坏做法：一次性全部读入集合
# 全部读入可能占用数 GB 内存

# 好做法 1：分批处理 + 提前返回
def check_ip_in_logs(target_ip, log_file):
    """流式处理：边读边查，不必读完全部数据"""
    seen = set()
    with open(log_file, "r") as f:
        for line in f:
            ip = line.strip().split(",")[0]  # 假设 CSV 格式
            if ip == target_ip:
                return True
    return False
```

对于"需要完全去重且数据极大"的场景，可以考虑使用外部排序 + 去重（如 `sort -u`）或数据库。Python 的集合在百万级别是高效的，但上亿级别就需要考虑内存管理了。

### 3.3 不要用可变类型、不要搞乱哈希

这是最基础但也最常犯的错误。

```python
# 规则 1：不要把可变类型放入集合
# ❌ data = {[1, 2], [3, 4]}  # TypeError: unhashable type: 'list'

# ✅ 用 frozenset 或 tuple 替代
data_valid = {(1, 2), (3, 4)}    # 元组

# 规则 2：自定义对象的哈希值必须稳定
# ❌ 哈希值依赖可变属性
# class Bad:
#     def __init__(self, data):
#         self.data = data
#     def __hash__(self):
#         return hash(self.data)  # 如果 data 可变就完了

# ✅ 用不可变标识计算哈希
class Good:
    def __init__(self, id_, data):
        self._id = id_        # 不可变的唯一标识
        self.data = data
    def __hash__(self):
        return hash(self._id)  # 基于不可变 id
    def __eq__(self, other):
        return isinstance(other, Good) and self._id == other._id
```

**`__hash__` 和 `__eq__` 必须一起实现**。如果你重写了 `__eq__` 但没有重写 `__hash__`，Python 会自动将 `__hash__` 设为 `None`，使对象不可哈希。

```python
class OnlyEq:
    def __init__(self, value):
        self.value = value
    def __eq__(self, other):
        return isinstance(other, OnlyEq) and self.value == other.value

# 只有 __eq__ 没有 __hash__ → 对象不可哈希
oe1 = OnlyEq(10)
# s = {oe1}   # TypeError: unhashable type: 'OnlyEq'
```

### 3.4 理解去重的"等价"判定规则

集合去重的"重复"由 `__eq__` 判定，但 `__eq__` 是可重写的，这导致了一些微妙的边界情况。

```python
# 浮点数的 +0.0 和 -0.0
s = {0.0, -0.0}
print(len(s))     # 输出：1  ← 0.0 == -0.0 为 True，所以被去重

# 浮点数的 NaN
s = {float('nan'), float('nan')}
print(len(s))     # 输出：2  ← 因为 NaN != NaN，两个 NaN 被认为"不相等"

# 整数和浮点数
s = {1, 1.0}
print(len(s))     # 输出：1  ← 1 == 1.0，去重

# Decimal 和 float
from decimal import Decimal
s = {Decimal('1.0'), 1.0}
print(len(s))     # 输出：1  ← Decimal('1.0') == 1.0 为 True

# True 和 1
s = {True, 1}
print(len(s))     # 输出：1  ← True == 1 为 True

# 自定义类型的 __eq__ 覆盖
class CaseInsensitive:
    def __init__(self, text):
        self.text = text
    def __hash__(self):
        return hash(self.text.lower())   # 大小写不敏感哈希
    def __eq__(self, other):
        if not isinstance(other, CaseInsensitive):
            return NotImplemented
        return self.text.lower() == other.text.lower()
    def __repr__(self):
        return f"CI({self.text!r})"

# 大小写不同的字符串被视为重复
ci_set = {CaseInsensitive("Hello"), CaseInsensitive("HELLO"), CaseInsensitive("hello")}
print(ci_set)     # 输出：{CI('Hello')}  ← 大小写不同但内容相同，只保留一个
```

### 3.5 效率选择：何时用集合去重，何时用其他方法

不是所有去重场景都适合集合。选择取决于数据量、是否需要顺序、是否需要统计元素数量等。

```python
# 场景决策表
# ┌──────────────────────┬──────────────────────┬──────────────────────┐
# │ 场景                 │ 推荐方案              │ 原因                 │
# ├──────────────────────┼──────────────────────┼──────────────────────┤
# │ 小数据去重（<1万）    │ set()                │ 简单、高效            │
# │ 大数据去重            │ set() 分批或数据库    │ 内存需控制            │
# │ 保留顺序去重           │ dict.fromkeys        │ O(n) 保留顺序         │
# │ 统计元素出现次数       │ collections.Counter   │ 内置计数功能          │
# │ 需要去重后排序         │ sorted(set(data))     │ 先集后排序            │
# │ 大数据统计去重         │ collections.Counter    │ 内存优化好            │
# │ 流式数据去重           │ set + 分批 discard    │ 控制内存              │
# │ 复杂对象按属性去重      │ seen set + loop       │ 灵活选择去重键        │
# └──────────────────────┴──────────────────────┴──────────────────────┘

from collections import Counter

# 场景：统计数据去重前先统计出现次数
data = ["apple", "banana", "apple", "cherry", "banana", "apple", "date"]
counter = Counter(data)

# 只保留出现次数 > 1 的元素，同时去重
frequent = {item for item, count in counter.items() if count > 1}
print(frequent)   # 输出：{'apple', 'banana'}
```

### 3.6 集合去重与内存管理

集合底层使用哈希表，内存占用与元素数量成正比。理解内存特性可以帮助你写出更高效的代码。

```python
import sys

# 空集合的内存
s = set()
print(f"空集合: {sys.getsizeof(s)} bytes")        # 输出：216 bytes（集合本身）

# 添加元素后的内存增长
for i in range(1, 100000, 1000):
    s.add(i)
    print(f"元素数={len(s):<8} 内存={sys.getsizeof(s):>8} bytes")
```

**共享键（shared keys）** 是 CPython 对字典的优化，但集合没有这个优化——因为集合的元素可以是不同类型，不像对象属性名那样可共享。但集合的哈希表同样使用了紧凑设计（Python 3.6+），索引数组与条目数组分离以节省内存。

```python
# 集合的紧凑存储示例：查看不同类型集合的内存
# 相同的元素数量，不同类型的元素占用内存不同
import sys

small_ints = set(range(100))
print(f"整数集合 100 个: {sys.getsizeof(small_ints)} bytes")

strings = set(f"str-{i}" for i in range(100))
print(f"字符串集合 100 个: {sys.getsizeof(strings)} bytes")

# 元组集合
tuples = set((i, i+1) for i in range(100))
print(f"元组集合 100 个: {sys.getsizeof(tuples)} bytes")
```

**注意**：`sys.getsizeof` 只返回集合对象本身占用的内存，不包括元素对象占用的内存。元素对象本身的管理由内存分配器负责。

## 4. 原理

### 4.1 集合的底层结构：PySetObject

在 CPython 中，集合的实现在 `Objects/setobject.c` 中。核心数据结构是 `PySetObject`：

```
PySetObject 结构体（简化）：
├── ob_base          ← 基础对象头（引用计数 + 类型）
├── fill             ← 已使用 + DUMMY 的槽位总数
├── used             ← 有效元素数（不含 DUMMY）
├── mask             ← table_size - 1（位掩码）
├── table            ← 哈希表数组（指向 setentry 的指针）
└── hash             ← frozenset 的缓存哈希值（set 无此字段）
```

每个槽位存储的是 `setentry` 结构体：

```
setentry 结构体：
├── hash             ← 缓存元素的哈希值（避免重复计算）
└── key              ← 指向实际元素的指针（PyObject*）
```

```python
# 用 Python 模拟 CPython 的集合内部结构
import ctypes

# 集合条目的模拟
class SetEntry:
    __slots__ = ('hash_val', 'key')
    def __init__(self, hash_val, key):
        self.hash_val = hash_val
        self.key = key
    
    def __repr__(self):
        return f"Entry(hash={self.hash_val}, key={self.key!r})"

# 集合对象的模拟
class SimCPythonSet:
    """模拟 CPython 集合内部结构"""
    EMPTY = -1
    DUMMY = -2
    
    def __init__(self):
        # 初始大小
        self.fill = 0         # 已使用槽位数（含 DUMMY）
        self.used = 0         # 有效元素数
        self.mask = 7         # 初始 table_size=8，mask=7
        self.table = [None] * 8  # setentry 数组
    
    def _setentry(self, entry):
        """返回槽位的 (hash, key) 或特殊标记"""
        if entry is None:
            return self.EMPTY, None
        h, k = entry.hash_val, entry.key
        if k is None:
            return self.DUMMY, None
        return h, k
    
    def add(self, element):
        """模拟集合添加元素的 CPython 内部流程"""
        h = hash(element)
        idx = h & self.mask
        perturb = h
        first_dummy = -1
        
        while True:
            entry = self.table[idx]
            if entry is None:   # EMPTY
                insert_idx = first_dummy if first_dummy != -1 else idx
                break
            h2, k2 = entry.hash_val, entry.key
            if k2 is None:      # DUMMY
                if first_dummy == -1:
                    first_dummy = idx
            elif h2 == h and k2 == element:   # 先比哈希，再比 equality
                return   # 重复，忽略
            perturb >>= 5
            idx = (idx * 5 + 1 + perturb) & self.mask
        
        # 将元素放入找到的位置
        new_entry = SetEntry(h, element)
        self.table[insert_idx] = new_entry
        if first_dummy != -1:
            pass  # fill 不变（复用了 DUMMY 槽位）
        else:
            self.fill += 1
        self.used += 1
        
        # 检查是否需要 resize（fill 达到 2/3 mask）
        if self.fill > self.mask * 2 // 3:  # 简化判断
            self._resize()
    
    def _resize(self):
        """扩容——重新分配哈希表"""
        new_size = max(8, self.used * 4)  # 集合的扩容策略
        sz = 8
        while sz < new_size:
            sz <<= 1
        
        old_entries = []
        for e in self.table:
            if e is not None and e.key is not None:
                old_entries.append((e.hash_val, e.key))
        
        self.table = [None] * sz
        self.mask = sz - 1
        self.fill = 0
        self.used = 0
        
        for h, k in old_entries:
            self.add(k)  # 重新哈希插入
    
    def __contains__(self, element):
        h = hash(element)
        idx = h & self.mask
        perturb = h
        
        while True:
            entry = self.table[idx]
            if entry is None:
                return False   # 遇到空槽，确定不存在
            h2, k2 = entry.hash_val, entry.key
            if k2 is None:
                pass           # DUMMY，继续
            elif h2 == h and k2 == element:
                return True     # 找到！
            perturb >>= 5
            idx = (idx * 5 + 1 + perturb) & self.mask

# 测试模拟集合
ss = SimCPythonSet()
ss.add("apple")
ss.add("banana")
ss.add("apple")         # 重复
ss.add("cherry")
print(f"有效元素: {ss.used}")    # 输出：3
print(f"'apple' in set: {'apple' in ss}")   # 输出：True
print(f"'grape' in set: {'grape' in ss}")   # 输出：False
```

### 4.2 集合的哈希函数：SipHash

Python 3.4+ 使用 **SipHash** 作为字符串和字节串的哈希算法。SipHash 是一种专为哈希表设计的键控哈希函数（keyed hash function），它具有以下特性：

1. **快速**：对短输入（如字符串键）非常高效
2. **抗碰撞**：即使攻击者知道算法，没有密钥也无法预计算哈希值
3. **安全**：带密钥的伪随机函数（PRF），防御哈希冲突攻击

```python
# 演示字符串哈希的随机性（不同进程）
# 虽然在同一个脚本中运行，但每次执行结果不同
import sys

# 字符串哈希每次启动不同
print(f"hash('python') = {hash('python')}")

# 检查哈希随机化是否启用
print(f"PYTHONHASHSEED: {sys.flags.hash_randomization}")
# 输出：1（启用）

# 整数哈希是确定的
print(f"hash(42) = {hash(42)}")   # 输出：42
```

但不是所有类型都使用 SipHash。只有 `str`、`bytes` 和 `datetime` 使用了随机化哈希。整数、浮点数、元组的哈希算法不依赖随机种子——它们是确定的。

```python
# 各类型哈希值的性质对比
print(f"hash(42) 在所有进程中都相同: {hash(42) == 42}")
print(f"hash('hello') 在不同进程可能不同")
print(f"hash((1, 2, 3)) 在不同进程相同（基于元素值）")
```

### 4.3 集合的探测序列

集合使用的探测算法与字典相同：线性探测的变体，通过扰动变量（perturb）混合高位信息。但与字典不同的是，**集合的负载因子阈值更低**（约为 2/3 的 fill / mask 比例），这是为了在只有键（没有值）的结构中保持更低的冲突概率。

```python
# 集合探测算法的模拟
def set_probe_sequence(hash_val, mask):
    """生成集合的探测序列——与字典相同"""
    perturb = hash_val
    idx = hash_val & mask
    
    for step in range(10):
        yield idx
        perturb >>= 5
        idx = (idx * 5 + 1 + perturb) & mask

# 演示不同键的探测序列分布
hash_a = hash("aaa")
hash_b = hash("bbb")
mask = 15  # 16 槽位

seq_a = list(set_probe_sequence(hash_a, mask))
seq_b = list(set_probe_sequence(hash_b, mask))

print(f"键 'aaa' 探测路径: {seq_a}")
print(f"键 'bbb' 探测路径: {seq_b}")

# 即使初始槽相同，后续路径也会分叉
same_initial = seq_a[0] == seq_b[0]
print(f"初始槽相同: {same_initial}")
if same_initial:
    divergence_step = 1
    while divergence_step < len(seq_a) and seq_a[divergence_step] == seq_b[divergence_step]:
        divergence_step += 1
    print(f"在第 {divergence_step} 步分叉")
```

### 4.4 集合的扩容策略

与字典不同，集合的扩容策略是**新大小 = used * 4**（而非字典的 used * 2），然后向上取 2 的幂。这是因为集合只有键没有值，同样的槽位数量下，集合可容纳的元素密度更低才能保持性能。

```python
# 集合扩容策略的详细分析
import sys

def set_capacity(used):
    """计算集合应该有的容量"""
    if used == 0:
        return 8
    # 集合：新大小 = used * 4，向上取 2 的幂
    new = used * 4
    sz = 8
    while sz < new:
        sz <<= 1
    return sz

# 对比集合和字典的扩容策略
results = []
for used in [5, 10, 50, 100, 500, 1000, 50000]:
    set_sz = set_capacity(used)
    # 字典：used * 2 向上取 2 的幂
    dict_sz = 8
    dict_need = used * 2
    while dict_sz < dict_need:
        dict_sz <<= 1
    results.append((used, set_sz, dict_sz))

print(f"{'元素数':>8} {'集合容量':>10} {'字典容量':>10} {'集合/字典':>10}")
print("-" * 42)
for used, set_sz, dict_sz in results:
    ratio = set_sz / dict_sz if dict_sz > 0 else 0
    print(f"{used:>8} {set_sz:>10} {dict_sz:>10} {ratio:>10.1f}x")
```

输出示例：
```
  元素数    集合容量    字典容量   集合/字典
------------------------------------------
      5         16         16          1.0x
     10         64         32          2.0x
     50        256        128          2.0x
    100        512        256          2.0x
    500       2048       1024          2.0x
   1000       4096       2048          2.0x
  50000     262144     131072          2.0x
```

集合的扩容倍数更大（4 倍 vs 2 倍），为的是在"只有键没有值"的结构中保持更低的冲突率。

### 4.5 frozenset 的哈希机制

`frozenset` 是可哈希的，它的哈希值由所有元素的哈希值经过 XOR 运算得到。因为 XOR 满足交换律，所以 `frozenset` 的哈希值与元素的插入顺序无关。

```python
# frozenset 的哈希计算过程（CPython 简化模拟）

def frozenset_hash(elements):
    """模拟 CPython 中 frozenset 的哈希计算方法"""
    h = 0
    for elem in elements:
        h ^= hash(elem)          # XOR 混合每个元素的哈希
    return h

# 不同顺序的 frozenset 哈希相同
fs1 = frozenset([1, 2, 3])
fs2 = frozenset([3, 1, 2])       # 相同元素不同顺序

print(f"fs1 hash: {hash(fs1)}")
print(f"fs2 hash: {hash(fs2)}")
print(f"哈希相等: {hash(fs1) == hash(fs2)}")     # 输出：True

# 模拟计算
print(f"\n模拟哈希:")
print(f"  hash(1) ^ hash(2) ^ hash(3) = {hash(1) ^ hash(2) ^ hash(3)}")
print(f"  hash(3) ^ hash(1) ^ hash(2) = {hash(3) ^ hash(1) ^ hash(2)}")
```

**重要特性**：因为 XOR 是可逆的（`a ^ b ^ a == b`），所以 `frozenset` 的哈希具有以下性质：
- 删除一个元素再添加相同的元素，哈希值不变（如果该元素是唯一出现的）
- 但这也意味着 `frozenset` 的哈希对于包含相同元素的集合是一致的

### 4.7 哈希碰撞与性能退化

前面提到过，不同的对象可以有相同的哈希值——这称为哈希碰撞（hash collision）。当碰撞严重时，原来 O(1) 的操作会退化为 O(n) 的线性探测。

```python
# 演示哈希碰撞对集合插入时间的影响
import time

class GoodHash:
    """均匀分布的哈希"""
    def __init__(self, val):
        self.val = val
    def __hash__(self):
        return hash(self.val)    # 使用 Python 内置的高质量哈希
    def __eq__(self, other):
        return isinstance(other, GoodHash) and self.val == other.val

class BadHash:
    """所有元素哈希相同——最差的碰撞"""
    def __init__(self, val):
        self.val = val
    def __hash__(self):
        return 0       # 全部哈希为 0，所有元素冲突
    def __eq__(self, other):
        return isinstance(other, BadHash) and self.val == other.val

# 测试不同碰撞率下的插入性能
test_data = range(1000)

# 均匀分布
good_set = set()
start = time.perf_counter()
for v in test_data:
    good_set.add(GoodHash(v))
good_time = time.perf_counter() - start

# 极端碰撞
bad_set = set()
start = time.perf_counter()
for v in test_data:
    bad_set.add(BadHash(v))
bad_time = time.perf_counter() - start

print(f"均匀哈希 1000 次插入: {good_time*1e6:.2f}μs")
print(f"极端碰撞 1000 次插入: {bad_time*1e6:.2f}μs")
print(f"退化倍率: {bad_time / good_time:.1f}x")

# 更大数据量极端碰撞的退化
import time

for n in [100, 500, 1000, 2000, 5000]:
    bad_set = set()
    start = time.perf_counter()
    for i in range(n):
        bad_set.add(BadHash(i))
    t = time.perf_counter() - start
    print(f"碰撞集 n={n:>5} 耗时: {t*1e6:>10.2f}μs")
```

**关键发现**：极端碰撞下，插入的复杂度确实从 O(1) 退化为 O(n)，意味着插入 n 个元素的总耗时从 O(n) 退化为 O(n^2)。

### 4.8 Python 3.6+ 紧凑集合

Python 3.6 引入的紧凑字典（compact dict）架构同样影响了集合的实现。集合也采用了类似的"索引数组 + 条目数组"分离设计。

```
旧版集合（Python 3.5 及以前）：
  槽位 0: (hash, key)          ← 一个大的稀疏数组
  槽位 1: (hash, key)
  槽位 2: EMPTY
  槽位 3: (hash, key)
  ...

新版紧凑集合（Python 3.6+）：
  索引数组: [2, EMPTY, 0, 3, 1]   ← 更小的元素，存条目下标
  条目数组: [(hash, key), ...]     ← 紧凑排列，无空位
```

这种分离设计的优势：
1. **索引数组元素尺寸小**：根据集合大小，可以用 1 字节、2 字节、4 字节来存储索引
2. **条目数组无空位**：遍历集合时直接按条目数组顺序输出
3. **内存节省**：对于中等大小的集合，内存节省可达 30-50%

```python
# 紧凑集合的内存使用分析
import sys

# 观察不同大小集合的内存
for size in [10, 100, 1000, 10000]:
    s = set(range(size))
    mem = sys.getsizeof(s)
    # 估算每个元素的平均额外开销
    entry_size = mem / size if size > 0 else 0
    print(f"size={size:<6} getsizeof={mem:>8} bytes  每个元素 ~{entry_size:.1f} bytes")
```

### 4.9 集合的线程安全问题

Python 的集合不是线程安全的。多线程环境中对集合进行并发添加和删除可能会导致数据损坏或异常。

```python
import threading

# 演示多线程下的集合竞争
results = []
def worker(shared_set, thread_id):
    try:
        for i in range(1000):
            shared_set.add(f"thread-{thread_id}-item-{i}")
        for i in range(500):
            # 尝试删除部分元素
            shared_set.discard(f"thread-{thread_id}-item-{i}")
        # 遍历集合
        for _ in shared_set.copy():  # 拷贝避免迭代时修改
            pass
        results.append(f"线程 {thread_id} 完成")
    except Exception as e:
        results.append(f"线程 {thread_id} 异常: {e}")

def run_thread_unsafe_test(num_threads=10):
    shared_set = set()
    threads = [threading.Thread(target=worker, args=(shared_set, i)) for i in range(num_threads)]
    
    for t in threads:
        t.start()
    for t in threads:
        t.join()
    
    return results

# 运行测试
output = run_thread_unsafe_test(10)
for line in output:
    print(line)
```

**解决方案**：使用 `threading.Lock` 保护集合操作，或使用 `concurrent.futures.ThreadPoolExecutor` 等更高级的并发工具。

```python
import threading

class ThreadSafeSet:
    """线程安全的集合封装"""
    def __init__(self):
        self._set = set()
        self._lock = threading.Lock()
    
    def add(self, element):
        with self._lock:
            self._set.add(element)
    
    def remove(self, element):
        with self._lock:
            self._set.remove(element)
    
    def __contains__(self, element):
        with self._lock:
            return element in self._set
    
    def __len__(self):
        with self._lock:
            return len(self._set)

# 使用线程安全集合
safe_set = ThreadSafeSet()

def safe_worker(thread_id):
    for i in range(1000):
        safe_set.add(f"item-{i}")
    
    # 查询
    if f"item-500" in safe_set:
        pass

threads = []
for i in range(10):
    t = threading.Thread(target=safe_worker, args=(i,))
    threads.append(t)

for t in threads:
    t.start()

for t in threads:
    t.join()

print(f"最终集合大小: {len(safe_set)}")  # 输出：1000（元素被去重）
```

### 4.10 集合去重的均摊时间复杂度证明

集合的 add 操作是均摊 O(1) 的，以下是直观证明。

```python
# 均摊成本演示
import time

def amortized_analysis(n_trials=100000):
    """测量不同阶段插入的耗时"""
    s = set()
    
    # 初始阶段（无扩容）
    start = time.perf_counter()
    for i in range(10):
        s.add(i)
    initial_time = time.perf_counter() - start
    
    # 中期阶段（经历多次扩容）
    s = set()
    start = time.perf_counter()
    for i in range(n_trials):
        s.add(i)
    bulk_time = time.perf_counter() - start
    
    avg_time_per_insert = bulk_time / n_trials
    
    print(f"前10个插入: {initial_time*1e6:.2f}μs")
    print(f"总{n_trials}个插入: {bulk_time*1e6:.2f}μs")
    print(f"平均每个插入: {avg_time_per_insert*1e6:.2f}μs")
    
    # 证明：即使包含了 resize 的成本，平均成本仍是常数级别
    print(f"\n结论：即使在 {n_trials} 次插入（含多次 resize）后，")
    print(f"平均每次插入时间 ≈ {avg_time_per_insert*1e6:.2f}μs，趋于常数。")

amortized_analysis()
```

**均摊分析的原理**：
- 每次插入 O(1)（不考虑 resize）
- 每次 resize O(n)，但 resize 发生的频率为：每次插入时 resize 概率 ≈ 1/n
- 所以每次插入的期望成本 = O(1) + (1/n) * O(n) = O(1) + O(1) = O(1)

## 5. 总结

### 5.1 集合去重核心机制速查

```
去重流程：
  add(elem):
    1. h = hash(elem)                  # 计算哈希
    2. idx = h & mask                  # 定位槽位
    3. 探测 path:
       - 空槽 → 放入（无重复）
       - 匹配 hash → 比 __eq__:
         - == True → 重复，忽略
         - == False → 继续探测（哈希碰撞）
       - DUMMY → 继续探测

核心组件：
  - 哈希函数      hash(elem) — 必须稳定、均匀
  - 哈希表        稀疏数组，元素为 setentry (hash, key)
  - 掩码          table_size - 1，用 & 替代 % 加速

关键约束：
  - 元素必须可哈希（实现 __hash__）
  - a == b ⇒ hash(a) == hash(b)
  - 哈希值在生命周期内不变

扩容策略：
  - 初始大小      8
  - 负载因子      约 2/3（fill > mask * 2/3 时触发）
  - 新大小        used * 4 向上取 2 的幂
  - 缩容          不自动缩容

性能特征：
  - 添加：        O(1) 平均，O(n) 最坏（极端碰撞）
  - 查找：        O(1) 平均，O(n) 最坏
  - 删除：        O(1) 平均，O(n) 最坏
```

### 5.2 核心要点回顾

- 集合去重的本质是哈希表：通过元素的哈希值快速定位，避免逐个比较。
- `hash()` + `__eq__()` 协同工作：哈希值决定"可能的位置"，`__eq__` 最终裁决是否重复。
- 只有不可变对象才能加入集合——因为只有它们的哈希值在生命周期内不变。
- 可变对象（list、dict、set）不可哈希，Python 在 `hash()` 调用时直接抛 TypeError。
- 哈希冲突是正常的，集合通过开放寻址法处理——探测序列由扰动公式决定。
- 自定义对象要按值去重，必须同时实现 `__hash__` 和 `__eq__`，且遵守"相等→同哈希"的约定。
- 集合的负载因子约 2/3，扩容策略为 used * 4 向上取 2 的幂，比字典更激进。
- 集合不保证元素顺序，需要保留顺序的去重用 `dict.fromkeys`。
- Python 3.6+ 的紧凑集合将索引数组与条目数组分离，节省内存。

### 5.4 常见面试问题

**问题一：集合去重的底层原理是什么？**

集合底层是哈希表。当添加元素时，首先调用 `hash()` 计算元素的哈希值，通过位掩码定位到具体的槽位。如果槽位为空，直接放入；如果槽位已被占用，先比较哈希值，哈希不等继续探测，哈希相等则调用 `__eq__` 最终判断是否重复。重复则忽略，不重复则按探测序列继续找下一个空位。整个过程不依赖集合中已有元素的数量，因此平均时间复杂度为 O(1)。

**问题二：`__hash__` 和 `__eq__` 在集合去重中的调用顺序？**

`__hash__` 先调用（每个元素一次，用于定位），`__eq__` 后调用（只对哈希值匹配的槽位调用，用于最终确认）。一个好的哈希分布可以让 `__eq__` 几乎不被调用——因为每个槽位大概率只有一个元素，一次哈希定位就命中了。

**问题三：为什么列表不能放入集合，而元组可以？**

列表是可变类型，其内容可以随时变化。如果允许列表放入集合，那么列表哈希值的稳定性就得不到保证——修改列表内容后哈希值改变，集合再也找不到这个元素。元组是不可变类型，内容不能修改，哈希值稳定，所以可以放入集合。这也是 Python 语言的安全设计——从语法层面阻止一类极其难调试的 bug。

**问题四：哈希冲突和值重复有什么区别？**

哈希冲突（hash collision）是两个不同元素有相同的哈希值——它们经过掩码后定位到同一个初始槽位，需要通过探测序列找到各自的位置。值重复是两个元素 `__eq__` 判定相等——它们是"同一个值"，集合只保留其中一个。哈希冲突是哈希表机制的内部处理，值重复是集合的去重逻辑。

**问题五：如何设计一个可以被正确放入集合的自定义类？**

需要同时满足三个条件：
1. 实现 `__hash__` 方法，返回基于不可变属性的整数哈希值
2. 实现 `__eq__` 方法，定义值相等的逻辑
3. 保证 `a == b ⇒ hash(a) == hash(b)`

实现 `__hash__` 最安全的方式是委托给元组：`hash((self.attr1, self.attr2, ...))`。

**问题六：集合扩容后为什么性能会短暂下降？**

扩容是集合性能中的一个分水岭。扩容本身是 O(n) 的（所有元素重新哈希），触发扩容的那次插入会明显慢于正常插入。但扩容后数组变大、冲突率大幅下降，后续操作的性能提升。这就是"均摊 O(1)"的含义：扩容的高成本被后续的大量低成本操作摊平。

### 5.5 实战串讲：从零实现一个迷你集合

将全文的核心概念——哈希、探测、去重、冲突处理、扩容——串成一个可运行的迷你集合。

```python
from typing import Any, Optional, List, Tuple


class MiniSet:
    """从零实现的迷你集合，展示哈希去重的全部核心机制"""
    
    # 槽位状态标记
    _EMPTY: int = 0
    _DUMMY: int = 1
    _OCCUPIED: int = 2
    
    class _Slot:
        """哈希表槽位"""
        __slots__ = ('state', 'hash_val', 'key')
        
        def __init__(self):
            self.state = MiniSet._EMPTY
            self.hash_val = 0
            self.key = None
        
        def __repr__(self):
            if self.state == MiniSet._EMPTY:
                return "EMPTY"
            elif self.state == MiniSet._DUMMY:
                return "DUMMY"
            return f"KEY({self.key!r})"
    
    def __init__(self, initial_capacity: int = 8):
        self._slots: List[MiniSet._Slot] = [self._Slot() for _ in range(initial_capacity)]
        self._mask: int = initial_capacity - 1
        self._used: int = 0           # 有效元素数量
        self._dummy_count: int = 0   # DUMMY 槽位数量
        self._fill: int = 0          # 已填充槽位（used + dummy）
        # 负载因子阈值近似 2/3：fill > mask * 2/3 时扩容
    
    def __len__(self) -> int:
        return self._used
    
    def __repr__(self) -> str:
        elements = [s.key for s in self._slots 
                    if s.state == self._OCCUPIED and s.key is not None]
        return "{" + ", ".join(repr(e) for e in elements) + "}"
    
    def _lookup(self, key: Any, for_insert: bool = False):
        """核心查找算法
        
        参数:
            key: 要查找的元素
            for_insert: 是否用于插入（插入时需要找空位，查找不需要）
        
        返回:
            (slot_index, found, first_dummy_index)
            - slot_index: 找到的槽位（found=True时是匹配槽，found=False时是可插入槽）
            - found: 是否找到匹配元素
            - first_dummy_index: 探测过程中遇到的第一个 DUMMY 槽位（插入时复用）
        """
        h = hash(key)
        idx = h & self._mask
        perturb = h
        first_dummy = -1
        
        while True:
            slot = self._slots[idx]
            
            if slot.state == self._EMPTY:
                # 遇到空槽：如果是查找，确定不存在；如果是插入，返回空位
                break
            
            if slot.state == self._DUMMY:
                # 遇到 DUMMY：不能停下，继续探测，但记录第一个 DUMMY 位置
                if first_dummy == -1:
                    first_dummy = idx
            else:
                # 有效元素：先比哈希，再比 __eq__
                if slot.hash_val == h and slot.key == key:
                    return idx, True, first_dummy    # 找到了！
            
            # 继续探测
            perturb >>= 5
            idx = (idx * 5 + 1 + perturb) & self._mask
        
        # 没找到：返回可插入的位置
        if for_insert and first_dummy != -1:
            return first_dummy, False, -1
        return idx, False, first_dummy
    
    def _should_resize(self) -> bool:
        """判断是否需要扩容"""
        # 阈值：fill > mask * 2/3（约等于 2/3 负载）
        threshold = (self._mask + 1) * 2 // 3
        return self._fill > threshold
    
    def _resize(self) -> None:
        """扩容操作"""
        # 新大小：used * 4 向上取 2 的幂
        new_size = max(8, self._used * 4)
        sz = 8
        while sz < new_size:
            sz <<= 1
        
        # 保存旧表
        old_occupied = []
        for slot in self._slots:
            if slot.state == self._OCCUPIED:
                old_occupied.append((slot.hash_val, slot.key))
        
        # 创建新表
        self._slots = [self._Slot() for _ in range(sz)]
        self._mask = sz - 1
        self._used = 0
        self._dummy_count = 0
        self._fill = 0
        
        # 重新 all occupied 元素插入新表
        for h, k in old_occupied:
            self.add(k)  # 复用 add 的插入逻辑
    
    def add(self, key: Any) -> bool:
        """添加元素。如果元素已存在，返回 False；否则返回 True。"""
        # 检查是否需要扩容（放在查找之前，确保有空间）
        if self._should_resize():
            self._resize()
        
        h = hash(key)
        idx, found, first_dummy = self._lookup(key, for_insert=True)
        
        if found:
            return False   # 重复，忽略
        
        # 确定实际插入位置
        insert_idx = first_dummy if first_dummy != -1 else idx
        slot = self._slots[insert_idx]
        
        if slot.state == self._EMPTY:
            self._fill += 1
        elif slot.state == self._DUMMY:
            self._dummy_count -= 1
            # fill 不变（复用已占用的槽位）
        
        slot.state = self._OCCUPIED
        slot.hash_val = h
        slot.key = key
        self._used += 1
        
        return True
    
    def __contains__(self, key: Any) -> bool:
        """成员检查"""
        _, found, _ = self._lookup(key, for_insert=False)
        return found
    
    def discard(self, key: Any) -> bool:
        """删除元素。元素不存在时返回 False。"""
        idx, found, _ = self._lookup(key, for_insert=False)
        if not found:
            return False
        
        slot = self._slots[idx]
        slot.state = self._DUMMY     # 标记为 DUMMY（墓碑）
        slot.hash_val = 0
        slot.key = None
        self._used -= 1
        self._dummy_count += 1
        
        return True
    
    def remove(self, key: Any) -> None:
        """删除元素。元素不存在时抛出 KeyError。"""
        if not self.discard(key):
            raise KeyError(key)
    
    def clear(self) -> None:
        """清空集合"""
        self._slots = [self._Slot() for _ in range(8)]  # 重置为初始大小
        self._mask = 7
        self._used = 0
        self._dummy_count = 0
        self._fill = 0
```

### 5.6 延伸

集合的去重原理与字典的键唯一性原理同源——它们共享同一套哈希表实现。理解集合的哈希机制后，你会发现：

- **字典的键去重**和**集合的元素去重**是同一件事的不同表现形式
- `frozenset` 可哈希的本质是它的内容不可变，哈希值基于元素 XOR 组合
- **"可哈希"本质要求**在 Python 的 `hashable` 协议中定义清晰：实现 `__hash__()` 且哈希值稳定

如果你对 CPython 源码感兴趣，入口文件是 `Objects/setobject.c`。建议从 `set_add_key` 和 `set_lookkey` 函数读起——它们是集合添加和查找的核心实现，与本文的 MiniSet 一一对应。

回到本系列的起点：集合不是 Python 中"唯一的去重工具"，但它是**最高效的去重工具**。当你理解它"为什么"能去重时，你就能在任何复杂的去重场景中做出正确的设计决策——而不仅仅是"调一个 set() 看看"。
