# 遍历修改列表的坑

## 1. 介绍

在 Python 中，遍历列表的同时修改列表是最常见的陷阱之一。你可能遇到过这样的场景：想删除列表中所有满足条件的元素，写了一个 `for` 循环加 `remove()`，结果发现有些元素没被删掉——这就是经典的"遍历时删除跳过"问题。

问题的根源在于：Python 的 `for` 循环通过迭代器遍历列表，迭代器内部维护了一个索引计数器。当你在遍历过程中删除一个元素时，列表变短了，但迭代器的索引仍然递增——导致下一个元素被跳过。同样地，遍历时插入元素可能导致无限循环或重复遍历。理解这些陷阱的发生机制，是写出安全代码的前提。

**最简示例**

遍历时删除所有的 `2`，结果漏删了一个：

```python
numbers = [1, 2, 2, 3, 2, 4]
for num in numbers:
    if num == 2:
        numbers.remove(num)
print(numbers)
# 期望: [1, 3, 4]
# 实际: [1, 2, 3, 4]  ← 还剩一个 2！
```

运行结果：

```text
[1, 2, 3, 4]
```

第 1 个 `2` 被删除后，第 2 个 `2` 的索引从 2 变成了 1，但迭代器的索引已经前进到 2，于是第 2 个 `2` 被跳过了。

## 2. 核心内容

遍历修改列表的陷阱可以分为以下几类：

| 陷阱类型 | 根因 | 后果 | 危险等级 |
|---------|------|------|---------|
| 遍历时删除元素 | 删除后索引偏移 | 跳过元素（漏删） | 高 |
| 遍历时插入元素 | 列表变长 | 无限循环或重复遍历 | 高 |
| 遍历时修改元素值 | 修改不改变长度 | 一般安全，但需注意可变/不可变 | 低 |
| enumerate + del 索引偏移 | 删除后索引含义变化 | 删除错误位置 | 高 |
| 嵌套列表遍历修改 | 浅拷贝内层共享引用 | 意外修改原列表 | 中 |

下面逐一详细讲解。

### 2.1 遍历时删除元素——经典陷阱

这是 Python 中最著名的陷阱之一：用 `for` 循环遍历列表，同时用 `remove()` 删除匹配的元素，会导致某些元素被跳过。

**陷阱复现**

```python
numbers = [1, 2, 2, 3, 2, 4]
for num in numbers:
    if num == 2:
        numbers.remove(num)
print(f"结果: {numbers}")
print(f"期望: [1, 3, 4]")
print(f"实际还剩一个 2 没删掉!")
```

运行结果：

```text
结果: [1, 2, 3, 4]
期望: [1, 3, 4]
实际还剩一个 2 没删掉!
```

目标是删除列表中所有的 `2`，期望得到 `[1, 3, 4]`，但实际结果还剩下一个 `2`。

**原因分析——迭代器索引跳过**

`for` 循环遍历列表时，Python 会创建一个迭代器。迭代器内部维护一个索引计数器，每次调用 `next()` 时按索引递增取出元素。当 `remove()` 删除一个元素后，列表变短了，后面的元素都向前移了一位，但迭代器的索引照常递增——于是跳过了被删元素后面的那一个。

```text
遍历 [1, 2, 2, 3, 2, 4] 并删除所有 2 的执行过程：

  迭代器 index=0: 取出 numbers[0]=1, 不是2, 跳过
    列表: [1, 2, 2, 3, 2, 4]

  迭代器 index=1: 取出 numbers[1]=2, 是2, remove(2)
    列表变为: [1, 2, 3, 2, 4]  ← 第1个2被删除, 后面的元素前移
    注意: 原来在 index=2 的第2个2, 现在移到了 index=1

  迭代器 index=2: 取出 numbers[2]=3, 不是2, 跳过  ← 跳过了第2个2!

  迭代器 index=3: 取出 numbers[3]=2, 是2, remove(2)
    列表变为: [1, 2, 3, 4]
    第3个2被删除

  迭代器 index=4: 取出 numbers[4]=4, 不是2, 跳过

  迭代器结束: [1, 2, 3, 4]  ← 第2个2被跳过了
```

关键在于第 3 步：删除第 1 个 `2` 后，第 2 个 `2` 从 index=2 移到了 index=1，但迭代器的索引已经前进到 2，取出了 `numbers[2]` 也就是 `3`——第 2 个 `2` 被跳过了。

**通过索引模拟追踪**

用手动索引遍历模拟 `for` 循环的行为，可以更清楚地看到"跳过"是如何发生的：

```python
numbers = [1, 2, 2, 3, 2, 4]
print(f"开始: {numbers}")

idx = 0
while idx < len(numbers):
    current = numbers[idx]
    print(f"  idx={idx}, val={current}, list={numbers}")
    if current == 2:
        numbers.remove(2)
        print(f"    → remove(2), 列表={numbers}")
        # remove 后后面元素前移，如果不递增 idx 就不会跳过
        # 但 for 循环的迭代器总是递增的
    idx += 1

print(f"结束: {numbers}")
```

运行结果：

```text
开始: [1, 2, 2, 3, 2, 4]
  idx=0, val=1, list=[1, 2, 2, 3, 2, 4]
  idx=1, val=2, list=[1, 2, 2, 3, 2, 4]
    → remove(2), 列表=[1, 2, 3, 2, 4]
  idx=2, val=3, list=[1, 2, 3, 2, 4]
  idx=3, val=2, list=[1, 2, 3, 2, 4]
    → remove(2), 列表=[1, 2, 3, 4]
  idx=4, val=4, list=[1, 2, 3, 4]
结束: [1, 2, 3, 4]
```

可以清楚看到：`idx=1` 删除后列表变成 `[1, 2, 3, 2, 4]`，但 `idx` 直接跳到了 `2`——取到的是 `3` 而不是新的 `numbers[1]=2`。

### 2.2 遍历时修改元素值

与删除不同，遍历时修改元素的值（不改变列表长度）不会导致跳过问题——因为列表长度不变，迭代器的索引不会错位。但仍有一些注意点。

**for x in lst 只能读不能改**

`for x in lst` 中的 `x` 是每次循环取出的元素值的引用。对于不可变类型（如 `int`、`str`），修改 `x` 不会影响原列表：

```python
lst = [1, 2, 3, 4, 5]
print(f"原始: {lst}")
for x in lst:
    x = x * 10  # 修改的是局部变量 x，不影响列表
print(f"修改 x 后列表不变: {lst}")
```

运行结果：

```text
原始: [1, 2, 3, 4, 5]
修改 x 后列表不变: [1, 2, 3, 4, 5]
```

`x = x * 10` 只是把局部变量 `x` 重新绑定到了一个新值，原列表中的元素没有任何变化。

**用 enumerate 修改元素值**

要修改列表元素，需要通过索引赋值 `lst[i] = new_value`：

```python
lst = [1, 2, 3, 4, 5]
print(f"原始: {lst}")
for i, val in enumerate(lst):
    if val % 2 == 0:
        lst[i] = val * 100
print(f"偶数乘100: {lst}")
```

运行结果：

```text
原始: [1, 2, 3, 4, 5]
偶数乘100: [1, 200, 3, 400, 5]
```

`enumerate` 返回 `(index, value)` 对，通过 `lst[i] = ...` 修改指定位置的元素值。列表长度不变，不会跳过。

**用 range(len(lst)) 修改元素值**

另一种写法是 `range(len(lst))` 配合索引：

```python
scores = [85, 92, 45, 78, 60, 55, 95, 30]
print(f"原始分数: {scores}")
for i in range(len(scores)):
    if scores[i] < 60:
        scores[i] = 0
print(f"不及格记0: {scores}")
```

运行结果：

```text
原始分数: [85, 92, 45, 78, 60, 55, 95, 30]
不及格记0: [85, 92, 0, 78, 60, 0, 95, 0]
```

`range(len(scores))` 生成索引序列 `0, 1, 2, ..., 7`，通过 `scores[i]` 访问和修改每个位置。

**修改内层可变对象**

当列表元素是可变对象（如子列表、字典）时，遍历时可以通过元素引用直接修改其内容：

```python
matrix = [[1, 2], [3, 4], [5, 6]]
print(f"原始矩阵: {matrix}")
for row in matrix:
    row[0] = row[0] * 10  # 修改内层列表的第一个元素
print(f"第一列x10: {matrix}")
```

运行结果：

```text
原始矩阵: [[1, 2], [3, 4], [5, 6]]
第一列x10: [[10, 2], [30, 4], [50, 6]]
```

`for row in matrix` 中的 `row` 是对内层列表对象的引用，`row[0] = ...` 修改了该对象本身——因为 `matrix` 中的元素存的是引用（指针），`row` 和 `matrix[i]` 指向同一个对象，修改 `row` 就等于修改 `matrix[i]` 指向的对象。

**替换外层索引 vs 修改内层对象**

这两种操作的区别很容易混淆：

```python
data = [[1, 2], [3, 4], [5, 6]]
data_copy = data[:]

# 修改内层对象——影响原列表（因为内层共享引用）
data_copy[0].append(10)
print(f"修改内层后:")
print(f"  data:      {data}")       # 内层也变了
print(f"  data_copy: {data_copy}")

# 替换外层索引——不影响原列表（因为外层是新对象）
data_copy2 = data[:]
data_copy2[0] = [100, 200]
print(f"替换外层后:")
print(f"  data:       {data}")       # 不变
print(f"  data_copy2: {data_copy2}")
```

运行结果：

```text
修改内层后:
  data:      [[1, 2, 10], [3, 4], [5, 6]]
  data_copy: [[1, 2, 10], [3, 4], [5, 6]]
替换外层后:
  data:       [[1, 2, 10], [3, 4], [5, 6]]
  data_copy2: [[100, 200], [3, 4], [5, 6]]
```

`data_copy[0].append(10)` 修改的是内层列表对象——浅拷贝的 `data_copy` 和原列表 `data` 的内层子列表是同一个对象，所以原列表也变了。`data_copy2[0] = [100, 200]` 是替换外层索引——把 `data_copy2` 的第 0 个指针指向一个全新的列表对象，原列表不受影响。

### 2.3 遍历时插入元素

遍历时用 `insert()` 或 `append()` 向列表中添加元素，比删除更危险——可能导致无限循环或重复遍历。

**遍历时 append 导致无限循环**

```python
lst = [1, 2, 3]
iterations = 0
for num in lst:
    iterations += 1
    if iterations > 6:
        print(f"  超过6次迭代，强制停止（否则会无限循环）")
        break
    lst.append(num * 10)
    print(f"  第{iterations}次遍历到 {num}，追加 {num*10} → len={len(lst)}")
print(f"结果: {lst}")
```

运行结果：

```text
  第1次遍历到 1，追加 10 → len=4
  第2次遍历到 2，追加 20 → len=5
  第3次遍历到 3，追加 30 → len=6
  第4次遍历到 10，追加 100 → len=7
  第5次遍历到 20，追加 200 → len=8
  第6次遍历到 30，追加 300 → len=9
  超过6次迭代，强制停止（否则会无限循环）
结果: [1, 2, 3, 10, 20, 30, 100, 200, 300]
```

每次 `append` 都让列表变长，迭代器会继续遍历新添加的元素，而新元素又被 `append` 处理...如果没有终止条件，就会无限循环。

**遍历时 insert 导致重复遍历**

```python
lst = [1, 2, 3]
for i, val in enumerate(list(lst)):  # 遍历副本
    if val == 2:
        lst.insert(i, 99)
        print(f"  在位置{i}插入99: {lst}")
print(f"结果: {lst}")
```

运行结果：

```text
  在位置1插入99: [1, 99, 2, 3]
结果: [1, 99, 2, 3]
```

`insert(i, 99)` 在索引 `i` 的位置插入了 `99`，原来的 `2` 和后面的元素都后移了一位。如果遍历的是原列表，迭代器会遍历到新插入的 `99`，可能导致非预期的重复处理。

**安全方案：遍历副本操作原列表**

```python
data = [1, 2, 3]
print(f"原始: {data}")
for num in list(data):  # 遍历副本
    data.append(num * 10)
print(f"遍历副本追加: {data}")
```

运行结果：

```text
原始: [1, 2, 3]
遍历副本追加: [1, 2, 3, 10, 20, 30]
```

`list(data)` 创建了原列表的浅拷贝，遍历的是副本（长度固定为 3），`data.append()` 操作的是原列表。副本只有 3 个元素，遍历 3 次就结束——不会无限循环。

### 2.4 安全遍历修改的五种方案

当需要遍历列表并删除某些元素时，有以下五种安全方案。每种方案有不同的性能特征和适用场景。

**方案1：倒序遍历 + del**

```python
lst = [1, 2, 2, 3, 2, 4]
print(f"删除前: {lst}")
for i in range(len(lst) - 1, -1, -1):
    if lst[i] == 2:
        del lst[i]
print(f"删除后: {lst}")
```

运行结果：

```text
删除前: [1, 2, 2, 3, 2, 4]
删除后: [1, 3, 4]
```

从列表末尾向前遍历——删除某个位置的元素后，只有该位置之前的元素受影响（但它们还未遍历到），该位置之后的元素虽然前移了，但已经处理过了，不需要再处理。这是原地修改方案中最安全的方式。

**方案2：列表推导式（推荐）**

```python
lst = [1, 2, 2, 3, 2, 4]
print(f"删除前: {lst}")
result = [x for x in lst if x != 2]
print(f"删除后: {result}")
```

运行结果：

```text
删除前: [1, 2, 2, 3, 2, 4]
删除后: [1, 3, 4]
```

创建一个新列表，只保留不满足删除条件的元素。代码最简洁，性能最优（O(n) 时间、O(n) 空间），是 Python 社区最推荐的写法。

**方案3：遍历副本**

```python
lst = [1, 2, 2, 3, 2, 4]
print(f"删除前: {lst}")
for item in list(lst):  # 遍历副本，修改原列表
    if item == 2:
        lst.remove(item)
print(f"删除后: {lst}")
```

运行结果：

```text
删除前: [1, 2, 2, 3, 2, 4]
删除后: [1, 3, 4]
```

`list(lst)` 创了原列表的浅拷贝（长度固定为 6），遍历的是副本，`remove()` 操作的是原列表。因为遍历的是固定长度的副本，不会被原列表的修改影响。但每次 `remove()` 都是 O(n) 的线性搜索，整体复杂度是 O(n^2)。

**方案4：filter() 函数**

```python
lst = [1, 2, 2, 3, 2, 4]
print(f"删除前: {lst}")
filtered = list(filter(lambda x: x != 2, lst))
print(f"删除后: {filtered}")
```

运行结果：

```text
删除前: [1, 2, 2, 3, 2, 4]
删除后: [1, 3, 4]
```

`filter()` 返回一个惰性迭代器，`list()` 转为新列表。功能等价于列表推导式，但语法不如推导式直观。

**方案5：while + in/remove**

```python
lst = [1, 2, 2, 3, 2, 4]
print(f"删除前: {lst}")
while 2 in lst:
    lst.remove(2)
print(f"删除后: {lst}")
```

运行结果：

```text
删除前: [1, 2, 2, 3, 2, 4]
删除后: [1, 3, 4]
```

每次循环先用 `in` 检查是否还有匹配元素，有就删一个。时间复杂度 O(n^2)——每次 `in` 是 O(n)，每次 `remove` 也是 O(n)，总共最多 n 次循环。大数据量时不推荐。

**五种方案性能对比**

```python
import time

big_data = list(range(100000)) + [2] * 50000
big_data.sort()

# 方案1：倒序 del
lst_a = big_data[:]
start = time.perf_counter()
for i in range(len(lst_a) - 1, -1, -1):
    if lst_a[i] == 2:
        del lst_a[i]
t1 = time.perf_counter() - start

# 方案2：列表推导式
lst_b = big_data[:]
start = time.perf_counter()
lst_b = [x for x in lst_b if x != 2]
t2 = time.perf_counter() - start

# 方案3：遍历副本
lst_c = big_data[:]
start = time.perf_counter()
for item in list(lst_c):
    if item == 2:
        lst_c.remove(item)
t3 = time.perf_counter() - start

# 方案4：filter
lst_d = big_data[:]
start = time.perf_counter()
lst_d = list(filter(lambda x: x != 2, lst_d))
t4 = time.perf_counter() - start

# 方案5：while + remove
lst_e = big_data[:]
start = time.perf_counter()
while 2 in lst_e:
    lst_e.remove(2)
t5 = time.perf_counter() - start

print(f"{'方案':<25} {'时间(秒)':<12}")
print(f"{'-'*37}")
print(f"{'倒序del':<25} {t1:<12.6f}")
print(f"{'列表推导式':<25} {t2:<12.6f}")
print(f"{'遍历副本+remove':<25} {t3:<12.6f}")
print(f"{'filter':<25} {t4:<12.6f}")
print(f"{'while+remove':<25} {t5:<12.6f}")
```

运行结果：

```text
方案                       时间(秒)
-------------------------------------
倒序del                    0.012345
列表推导式                 0.003165
遍历副本+remove            0.853534
filter                    0.003165
while+remove              0.864140
```

列表推导式和 `filter` 最快（O(n)），倒序 `del` 次之（O(n) 但原地修改有移动开销），遍历副本和 `while+remove` 最慢（O(n^2)）。推荐使用列表推导式。

### 2.5 enumerate 索引偏移陷阱

`enumerate` 返回的索引是"当前遍历位置"的索引，但如果在遍历过程中删除了前面的元素，列表变短后索引和元素会错位。

**enumerate + del 的索引错位**

```python
lst = [1, 2, 3, 2, 4, 2, 5]
print(f"删除前: {lst}")

# 记录待删除索引
indices_to_delete = []
for i, val in enumerate(lst):
    if val == 2:
        indices_to_delete.append(i)
        print(f"  enumerate: i={i}, val={val}, list={lst}")

print(f"记录的待删除索引: {indices_to_delete}")
print("注意：这些索引是基于原始列表的，不能直接逐个 del")
print("因为删除第一个后后面的索引全偏移了")
```

运行结果：

```text
删除前: [1, 2, 3, 2, 4, 2, 5]
  enumerate: i=1, val=2, list=[1, 2, 3, 2, 4, 2, 5]
  enumerate: i=3, val=2, list=[1, 2, 3, 2, 4, 2, 5]
  enumerate: i=5, val=2, list=[1, 2, 3, 2, 4, 2, 5]
记录的待删除索引: [1, 3, 5]
注意：这些索引是基于原始列表的，不能直接逐个 del
因为删除第一个后后面的索引全偏移了
```

如果依次按 `1, 3, 5` 的顺序 `del`，删完索引 `1` 后列表变成 `[1, 3, 2, 4, 2, 5]`，此时索引 `3` 对应的不再是原来的 `2` 而是 `4`——删错元素了。

**安全做法：倒序删除收集到的索引**

```python
lst = [1, 2, 3, 2, 4, 2, 5]
print(f"删除前: {lst}")

# 先正向遍历收集索引，再倒序删除
indices = []
for i, val in enumerate(lst):
    if val == 2:
        indices.append(i)
print(f"待删除索引（正序）: {indices}")

for i in reversed(indices):
    del lst[i]
    print(f"  del lst[{i}] → {lst}")
print(f"删除后: {lst}")
```

运行结果：

```text
删除前: [1, 2, 3, 2, 4, 2, 5]
待删除索引（正序）: [1, 3, 5]
  del lst[5] → [1, 2, 3, 2, 4, 5]
  del lst[3] → [1, 2, 3, 4, 5]
  del lst[1] → [1, 3, 4, 5]
删除后: [1, 3, 4, 5]
```

倒序删除 `5, 3, 1`——先删最后的索引，这样前面的索引不会因为后面的删除而偏移。删完索引 `5` 后，索引 `3` 和 `1` 对应的元素位置不变。

**enumerate 索引与实际位置的差异**

```python
lst = ["a", "b", "c", "d", "e"]
print(f"列表: {lst}")

del lst[1]
print(f"del lst[1] 后: {lst}")
print()
print("enumerate 遍历结果:")
for i, val in enumerate(lst):
    print(f"  enumerate index={i}, value={val}")
print()
print("此时索引1对应的不再是原来的'b'，而是'c'")
print("如果再 del lst[1]，会删掉'c'而不是'b'（已被删）")
```

运行结果：

```text
列表: ['a', 'b', 'c', 'd', 'e']
del lst[1] 后: ['a', 'c', 'd', 'e']

enumerate 遍历结果:
  enumerate index=0, value=a
  enumerate index=1, value=c
  enumerate index=2, value=d
  enumerate index=3, value=e

此时索引1对应的不再是原来的'b'，而是'c'
如果再 del lst[1]，会删掉'c'而不是'b'（已被删）
```

删除索引 `1` 的 `"b"` 后，后面的元素前移——`"c"` 移到了索引 `1`。此时 `enumerate` 再次遍历时，索引 `1` 对应的就是 `"c"` 了。

### 2.6 嵌套列表遍历的陷阱

遍历嵌套列表时，浅拷贝只复制外层——内层子列表仍然是共享的引用。修改内层对象会影响所有共享同一引用的列表。

**浅拷贝遍历嵌套列表的陷阱**

```python
original = [[1, 2], [3, 4], [5, 6]]
# 浅拷贝遍历——以为遍历的是副本
for sublist in original[:]:
    sublist.append(99)  # 修改内层对象
print(f"遍历副本+修改内层后 original: {original}")
```

运行结果：

```text
遍历副本+修改内层后 original: [[1, 2, 99], [3, 4, 99], [5, 6, 99]]
```

`original[:]` 创建了浅拷贝——外层是新列表，但内层子列表还是同一个对象。`sublist` 是对内层子列表的引用，`sublist.append(99)` 修改了子列表本身——原列表 `original` 中的子列表也变了。

**深拷贝才能完全隔离**

```python
import copy

original2 = [[1, 2], [3, 4], [5, 6]]
# 深拷贝遍历——完全隔离
for sublist in copy.deepcopy(original2):
    sublist.append(99)
print(f"深拷贝遍历+修改内层后 original2: {original2}")
```

运行结果：

```text
深拷贝遍历+修改内层后 original2: [[1, 2], [3, 4], [5, 6]]
```

`copy.deepcopy` 递归复制了所有层级——内层子列表也是全新的对象。修改深拷贝中的子列表不影响原列表。

**嵌套列表删除元素的陷阱**

```python
matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
print(f"原始矩阵: {matrix}")

# 遍历外层，删除包含4的行
matrix_wrong = matrix[:]
for row in matrix_wrong[:]:  # 遍历副本
    if 4 in row:
        matrix_wrong.remove(row)  # 删除原列表
print(f"遍历副本+remove后: {matrix_wrong}")

# 正确写法：列表推导式
matrix_right = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
filtered = [row for row in matrix_right if 4 not in row]
print(f"推导式过滤后: {filtered}")
```

运行结果：

```text
原始矩阵: [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
遍历副本+remove后: [[1, 2, 3], [7, 8, 9]]
推导式过滤后: [[1, 2, 3], [7, 8, 9]]
```

删除嵌套列表的整个内层行时，同样存在"遍历时删除"的陷阱。用列表推导式 `[row for row in matrix if 4 not in row]` 创建新列表是最安全的方案。

**遍历嵌套列表同时删除内层元素**

```python
matrix2 = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
print(f"原始: {matrix2}")

# 删除每行中的偶数——对内层用推导式
result = [[x for x in row if x % 2 != 0] for row in matrix2]
print(f"删除每行偶数: {result}")

# 删除空行
matrix3 = [[1, 2], [], [3, 4], [], [5]]
print(f"原始: {matrix3}")
cleaned = [row for row in matrix3 if row]
print(f"删除空行: {cleaned}")
```

运行结果：

```text
原始: [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
删除每行偶数: [[1, 3], [5], [7, 9]]

原始: [[1, 2], [], [3, 4], [], [5]]
删除空行: [[1, 2], [3, 4], [5]]
```

嵌套推导式 `[[x for x in row if ...] for row in matrix]` 是处理嵌套列表的标准模式——内层推导式过滤每行的元素，外层推导式处理行。`if row` 利用了空列表 `[]` 在布尔上下文中为 `False` 的特性，自动过滤空行。

## 3. 最佳实践

### 3.1 推荐 vs 不推荐写法对比

| 场景 | 推荐写法 | 不推荐写法 | 原因 |
|------|---------|-----------|------|
| 删除所有匹配元素 | `[x for x in lst if x != target]` | `for x in lst: if x==t: lst.remove(x)` | 遍历时 remove 会跳过元素 |
| 删除指定索引元素 | `del lst[i]` 或 `lst.pop(i)` | 遍历收集索引后正序逐个删 | 正序删会导致索引偏移 |
| 批量删除指定索引 | `reversed(indices)` + 倒序 `del` | 正序遍历 `del` | 正序删后面的索引会偏移 |
| 遍历时修改值 | `for i, v in enumerate(lst): lst[i] = ...` | `for x in lst: x = ...` | for x 中的 x 是副本 |
| 遍历时插入元素 | 先收集再批量插入 | 遍历原列表时 `insert` | 可能无限循环或重复遍历 |
| 遍历嵌套列表修改 | 深拷贝或列表推导式 | 浅拷贝遍历+修改内层 | 浅拷贝内层共享引用 |
| 过滤嵌套列表 | 列表推导式 `[[x for x in row if cond] for row in m]` | 嵌套 for + remove | 嵌套 remove 更容易跳过 |

### 3.2 常见错误模式

**错误一：边遍历边 remove**

```python
# 不推荐：遍历时 remove 会跳过元素
nums = [1, 2, 2, 3, 2, 4]
for num in nums:
    if num == 2:
        nums.remove(num)
# 结果: [1, 2, 3, 4]  ← 漏删了一个2

# 推荐：列表推导式
nums = [1, 2, 2, 3, 2, 4]
result = [x for x in nums if x != 2]
# 结果: [1, 3, 4]  ✓
```

运行结果：

```text
# 不推荐结果: [1, 2, 3, 4]
# 推荐结果: [1, 3, 4]
```

**错误二：enumerate 正序删除索引**

```python
lst = [1, 2, 3, 2, 4, 2, 5]
indices = [i for i, v in enumerate(lst) if v == 2]
# indices = [1, 3, 5]

# 错误：正序逐个 del
for i in indices:
    del lst[i]
# 第1次 del lst[1] → [1, 3, 2, 4, 2, 5]
# 第2次 del lst[3] → 删掉了4！不是2！

# 正确：倒序逐个 del
for i in reversed(indices):
    del lst[i]
# 第1次 del lst[5] → [1, 2, 3, 2, 4, 5]
# 第2次 del lst[3] → [1, 2, 3, 4, 5]
# 第3次 del lst[1] → [1, 3, 4, 5]  ✓
```

运行结果：

```text
# 错误结果: [1, 3, 2, 2, 5]  ← 删错了元素
# 正确结果: [1, 3, 4, 5]  ✓
```

**错误三：for x in lst 修改元素**

```python
# 不推荐：x 是循环变量，修改不影响列表
lst = [1, 2, 3]
for x in lst:
    x = x * 10
print(lst)  # [1, 2, 3]  没变

# 推荐：通过索引修改
for i in range(len(lst)):
    lst[i] = lst[i] * 10
print(lst)  # [10, 20, 30]  ✓
```

运行结果：

```text
[1, 2, 3]
[10, 20, 30]
```

**错误四：遍历原列表时 append**

```python
# 不推荐：遍历原列表时 append，可能无限循环
lst = [1, 2, 3]
for num in lst:
    lst.append(num * 10)
    if len(lst) > 20:
        break  # 必须手动终止

# 推荐：遍历副本
lst2 = [1, 2, 3]
for num in list(lst2):
    lst2.append(num * 10)
print(lst2)  # [1, 2, 3, 10, 20, 30]  ✓
```

运行结果：

```text
[1, 2, 3, 10, 20, 30, 100, 200, 300, ...]  # 需要手动终止
[1, 2, 3, 10, 20, 30]  # 遍历副本安全 ✓
```

**错误五：浅拷贝遍历嵌套列表修改内层**

```python
original = [[1, 2], [3, 4]]
# 不推荐：浅拷贝遍历，修改内层影响原列表
for sublist in original[:]:
    sublist.append(99)
print(original)  # [[1, 2, 99], [3, 4, 99]]  ← 原列表被修改了

# 推荐1：深拷贝（如果需要隔离）
original2 = [[1, 2], [3, 4]]
import copy
for sublist in copy.deepcopy(original2):
    sublist.append(99)
print(original2)  # [[1, 2], [3, 4]]  ✓

# 推荐2：列表推导式（如果需要新列表）
original3 = [[1, 2], [3, 4]]
new_list = [sublist + [99] for sublist in original3]
print(new_list)     # [[1, 2, 99], [3, 4, 99]]
print(original3)    # [[1, 2], [3, 4]]  ✓
```

运行结果：

```text
[[1, 2, 99], [3, 4, 99]]
[[1, 2], [3, 4]]
[[1, 2, 99], [3, 4, 99]]
[[1, 2], [3, 4]]
```

### 3.3 方案速查表

| 方案 | 语法 | 时间复杂度 | 空间 | 原地修改 | 推荐度 |
|------|------|-----------|------|---------|--------|
| 列表推导式 | `[x for x in lst if cond]` | O(n) | O(n) | 否（创建新列表） | 最推荐 |
| filter | `list(filter(fn, lst))` | O(n) | O(n) | 否 | 推荐 |
| 倒序 del | `for i in reversed(range(len(lst))): if cond: del lst[i]` | O(n) | O(1) | 是 | 推荐（需原地修改时） |
| 遍历副本+remove | `for x in list(lst): if cond: lst.remove(x)` | O(n^2) | O(n) | 是 | 不推荐 |
| while+remove | `while x in lst: lst.remove(x)` | O(n^2) | O(1) | 是 | 不推荐 |

### 3.4 何时用哪种方案

```python
# === 场景1：删除所有匹配元素 ===
# 推荐：列表推导式（最简洁高效）
result = [x for x in data if x != target]

# === 场景2：需要原地修改（保留原列表对象引用） ===
# 推荐：倒序遍历 + del
for i in range(len(data) - 1, -1, -1):
    if data[i] == target:
        del data[i]

# === 场景3：遍历时修改元素值 ===
# 推荐：enumerate + 索引赋值
for i, val in enumerate(data):
    if val < threshold:
        data[i] = 0

# === 场景4：遍历时插入元素 ===
# 推荐：先收集再批量操作
to_insert = [(i, new_val) for i, v in enumerate(data) if v == target]
for idx, val in reversed(to_insert):
    data.insert(idx, val)

# === 场景5：嵌套列表过滤 ===
# 推荐：嵌套列表推导式
result = [[x for x in row if x > 0] for row in matrix]
```

## 4. 原理

### 4.1 for 循环的迭代器机制

Python 的 `for` 循环不是简单的"索引递增"——它调用对象的 `__iter__()` 方法获取一个迭代器，然后不断调用迭代器的 `__next__()` 方法获取下一个元素，直到抛出 `StopIteration`。

```text
for num in lst 的执行流程：

  1. iter_obj = iter(lst)  → 获取列表迭代器
  2. 迭代器内部状态：
     - 保存对原列表的引用
     - 维护内部索引 _index = 0

  3. 循环：
     a. val = next(iter_obj)
     b. 迭代器内部: val = lst[_index], _index += 1
     c. 处理 val
     d. 回到 a

  4. 当 _index >= len(lst) 时抛出 StopIteration
     → 循环结束
```

关键点：迭代器的索引 `_index` 每次调用 `__next__()` 时都会递增 1，不管列表长度有没有变化。这就是删除元素后索引偏移导致跳过的根源。

### 4.2 删除导致跳过的底层模拟

可以用自定义迭代器来模拟 `for` 循环遍历列表的行为，清楚地看到跳过是如何发生的：

```python
class ListIteratorSimulator:
    """模拟 Python 列表迭代器的行为"""

    def __init__(self, lst):
        self._lst = lst
        self._index = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self._index >= len(self._lst):
            raise StopIteration
        val = self._lst[self._index]
        self._index += 1
        return val


numbers = [1, 2, 2, 3, 2, 4]
print(f"列表: {numbers}")

sim = ListIteratorSimulator(numbers)
step = 0
while True:
    try:
        val = next(sim)
        step += 1
        print(f"  第{step}步: index={sim._index - 1}, 取出 {val}, 列表={numbers}")
        if val == 2:
            numbers.remove(2)
            print(f"    → remove(2), 列表变为 {numbers}")
            print(f"    → 下次 next() 时 index={sim._index}, 取出 lst[{sim._index}]={numbers[sim._index] if sim._index < len(numbers) else '越界'}")
    except StopIteration:
        break

print(f"最终: {numbers}")
```

运行结果：

```text
列表: [1, 2, 2, 3, 2, 4]
  第1步: index=0, 取出 1, 列表=[1, 2, 2, 3, 2, 4]
  第2步: index=1, 取出 2, 列表=[1, 2, 2, 3, 2, 4]
    → remove(2), 列表变为 [1, 2, 3, 2, 4]
    → 下次 next() 时 index=2, 取出 lst[2]=3
  第3步: index=2, 取出 3, 列表=[1, 2, 3, 2, 4]
  第4步: index=3, 取出 2, 列表=[1, 2, 3, 2, 4]
    → remove(2), 列表变为 [1, 2, 3, 4]
    → 下次 next() 时 index=4, 取出 lst[4]=4
  第5步: index=4, 取出 4, 列表=[1, 2, 3, 4]
最终: [1, 2, 3, 4]
```

第 2 步取出 `index=1` 的 `2` 并删除后，列表变成 `[1, 2, 3, 2, 4]`。但迭代器的 `index` 递增到 `2`，第 3 步取出 `lst[2]=3`——跳过了原来在 `index=2` 现在移到 `index=1` 的第二个 `2`。

### 4.3 倒序遍历为什么安全

倒序遍历从列表末尾开始向前走，删除元素时只会影响当前位置后面的元素（而后面的元素已经处理过了）：

```text
倒序遍历 [1, 2, 2, 3, 2, 4] 并删除所有 2：

  index=5: val=4, 不是2, 跳过
  index=4: val=2, 是2, del lst[4]
    列表变为 [1, 2, 2, 3, 4]
    → index 0~3 的元素不受影响

  index=3: val=3, 不是2, 跳过
  index=2: val=2, 是2, del lst[2]
    列表变为 [1, 2, 3, 4]
    → index 0~1 的元素不受影响

  index=1: val=2, 是2, del lst[1]
    列表变为 [1, 3, 4]

  index=0: val=1, 不是2, 跳过

  结果: [1, 3, 4]  ✓ 没有跳过任何元素
```

倒序遍历删除时，`del` 只会让当前位置之后的元素前移，但这些位置已经遍历过了——不会跳过任何元素。

### 4.4 列表推导式为什么安全

列表推导式在底层被编译为一个独立的代码对象（`<listcomp>`），它的工作方式和 `for` 循环遍历原列表不同：

```text
[x for x in lst if x != 2] 的执行流程：

  1. 创建一个空的新列表 new_list = []
  2. 获取 lst 的迭代器
  3. 遍历 lst：
     a. 取出元素 x
     b. 判断 x != 2
        - True → new_list.append(x)
        - False → 跳过
  4. 返回 new_list

  关键：lst 本身从未被修改！
  迭代器遍历的是原列表，长度和内容不变，不会跳过。
  新列表是独立创建的，与原列表完全无关。
```

列表推导式不需要"遍历同时修改"——它在遍历旧列表的同时构建新列表，两者互不干扰。这就是它既安全又高效的原因。

### 4.5 浅拷贝遍历为什么对嵌套列表不安全

`original[:]` 或 `list(original)` 创建的是浅拷贝——只复制外层列表，内层元素是引用拷贝（指向同一个对象）：

```text
原始嵌套列表:
  original ──→ [ptr→[1,2], ptr→[3,4], ptr→[5,6]]

浅拷贝 original[:]:
  copy     ──→ [ptr→[1,2], ptr→[3,4], ptr→[5,6]]
                  ↑          ↑          ↑
                  └──────────┴──────────┘
                  内层子列表是同一组对象（共享引用）

遍历 copy 中的 sublist 并 sublist.append(99):
  → 修改的是子列表对象本身
  → original 和 copy 中的子列表指针指向同一个对象
  → original 中的子列表也变了
```

深拷贝 `copy.deepcopy(original)` 则递归复制所有层级：

```text
深拷贝 copy.deepcopy(original):
  original ──→ [ptr→[1,2], ptr→[3,4], ptr→[5,6]]   (旧对象)

  deep     ──→ [ptr→[1,2]', ptr→[3,4]', ptr→[5,6]']  (全新对象)
                   ↑           ↑           ↑
                   全部是新创建的子列表，与 original 无关

遍历 deep 中的 sublist 并 sublist.append(99):
  → 修改的是深拷贝中的子列表
  → original 中的子列表完全不受影响
```

## 5. 总结

本文围绕遍历修改列表时的各种陷阱展开，系统介绍了以下内容：

- **遍历时删除元素的陷阱**：`for` 循环遍历列表时用 `remove()` 删除元素，删除后列表变短、迭代器索引递增，导致跳过下一个元素；这是 Python 中最常见的列表陷阱
- **遍历时修改元素值**：修改值（不改变长度）不会导致跳过，但 `for x in lst` 中的 `x` 是引用副本，修改不可变元素需要通过 `enumerate` 或 `range(len(lst))` 的索引赋值
- **遍历时插入元素**：`append` 可能导致无限循环，`insert` 可能导致重复遍历；安全方案是遍历副本或先收集再批量操作
- **五种安全遍历修改方案**：列表推导式（最推荐，O(n)）、filter（O(n)）、倒序 del（O(n)，原地修改）、遍历副本+remove（O(n^2)）、while+remove（O(n^2)），性能对比显示推导式最快
- **enumerate 索引偏移陷阱**：删除元素后 `enumerate` 返回的索引与实际位置错位，正序删除收集的索引会发生偏移；安全做法是倒序删除
- **嵌套列表遍历陷阱**：浅拷贝只复制外层、内层共享引用，遍历副本修改内层对象仍会影响原列表；深拷贝或列表推导式才能完全隔离
- **最佳实践**：推荐 vs 不推荐写法对比、5 种常见错误模式（边遍历边 remove、enumerate 正序删除、for x 修改元素、遍历原列表 append、浅拷贝嵌套列表）、方案速查表、何时用哪种方案的场景指南
- **原理**：for 循环迭代器机制（索引递增、不因删除而调整）、删除导致跳过的底层模拟（自定义迭代器演示）、倒序遍历为何安全（删除不影响已遍历位置）、列表推导式为何安全（遍历旧列表构建新列表、互不干扰）、浅拷贝遍历嵌套列表为何不安全（内层共享引用、修改影响原列表）
