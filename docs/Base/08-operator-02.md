# 算术运算符

## 1. 介绍

### 1.1 什么是算术运算符

算术运算符是 Python 中用于数值计算的一类运算符，覆盖加、减、乘、除、整除、取余、幂七种基本运算，再加上一元正负号。它们是所有编程语言里最接近"数学课本"的一组运算符——你写出的 `3 + 5`、`price * quantity`，几乎就是在直接写算式。

但 Python 的算术运算符并不只是把数学符号搬过来。它在几个关键点上比许多语言更"讲究"：真除法 `/` 永远返回浮点数、整除 `//` 朝负无穷方向取整、取余 `%` 的符号跟随除数、幂运算 `**` 优先级高且右结合。这些细节决定了你写出来的表达式是不是真按预期求值。

### 1.2 解决什么问题

算术运算符解决的是"对数值进行计算并得到一个值"的问题。它适用于计算总价、折扣、面积、进度百分比、分页页数、时间换算、复利等几乎所有涉及数值的场景。理解每个运算符的边界行为（尤其是负数整除、除法返回类型、浮点精度），能帮你避免一类隐蔽的 bug：算出来不对，却找不到错在哪。

### 1.3 最简示例

先用一个最小的例子，把七个算术运算符一次性看个全貌：

```python
print(7 + 3)     # 加法
print(7 - 3)     # 减法
print(7 * 3)     # 乘法
print(7 / 3)     # 真除法（返回 float）
print(7 // 3)    # 整除
print(7 % 3)     # 取余
print(2 ** 3)    # 幂运算
```

运行结果：

```text
10
4
21
2.3333333333333335
2
1
8
```

七个运算符，七种结果。下面逐个拆开讲。

### 1.4 运算符总览表

在进入逐个讲解前，先用一张表建立全貌，记住每个运算符的"做什么、返回什么类型、典型场景"：

| 运算符 | 名称 | 作用 | 结果类型 | 典型场景 |
|--------|------|------|---------|---------|
| `+` | 加法 | 两数相加 | int/float | 求和、拼接 |
| `-` | 减法 | 两数相减 | int/float | 差值、扣减 |
| `*` | 乘法 | 两数相乘 | int/float | 总价、倍数 |
| `/` | 真除法 | 除得精确结果 | float（恒定） | 比例、均值 |
| `//` | 整除 | 商向下取整 | int 或 float | 分页、分组 |
| `%` | 取余 | 求除法余数 | int 或 float | 周期、奇偶 |
| `**` | 幂运算 | 求幂 | int 或 float | 平方、开方 |
| `+x` | 一元正号 | 原值 | 数值 | 强调符号 |
| `-x` | 一元负号 | 取相反数 | 数值 | 取负 |

注意 `/` 那一行——它是唯一一个"结果类型固定"的运算符：无论操作数是什么、能否整除，`/` 永远返回 `float`。这个设计是后面要重点讲的内容。

## 2. 核心内容

### 2.1 加法运算符 `+`

加法把两个操作数相加，返回它们的和。操作数可以是整数、浮点数，或者支持重载的其他类型（如字符串、列表）。

**签名与行为**：`a + b` → 返回 `a` 与 `b` 的和。当两个 int 相加得 int，混入 float 则结果提升为 float。

**示例**

用一笔购物账模拟加法的常见用法——单价加运费得总支出：

```python
price = 88          # 单价
freight = 12        # 运费
total = price + freight
print(f"总支出：{total}")

# int + float → 类型提升为 float
mixed = 10 + 0.5
print(f"{mixed}，类型 {type(mixed).__name__}")
```

**运行结果**：

```text
总支出：100
10.5，类型 float
```

**关键点**：当加法里混入 `float`，结果会自动提升成 `float`；两个 `int` 相加则仍是 `int`，不会自动变浮点。这一点决定了你后续做整数索引或需要精确整数时，要小心别被混入的 `float` 破坏类型预期。

加法对字符串和列表是"拼接"而不是数值加法，这属于运算符重载，会在原理章节再点明。这里先放一个直观印象：

```python
print("Hello" + " " + "Python")   # 字符串拼接
print([1, 2] + [3, 4])            # 列表合并
```

运行结果：

```text
Hello Python
[1, 2, 3, 4]
```

### 2.2 减法运算符 `-`

减法用第一个操作数减去第二个，返回差值。它的行为和加法对称，类型提升规则也一样。

**示例**

模拟库存扣减：库存减去售出量得剩余量。

```python
stock = 50          # 库存
sold = 17           # 售出
remain = stock - sold
print(f"剩余库存：{remain}")

# 负数参与减法
delta = 10 - 25
print(f"10 - 25 = {delta}")
```

**运行结果**：

```text
剩余库存：33
10 - 25 = -15
```

**关键点**：减法结果可以是负数，不必担心"不够减"会报错——Python 的整数没有溢出，结果是精确的负数。要注意的是 `float` 减法可能出现精度尾巴，如 `0.3 - 0.1` 不一定正好等于 `0.2`，这是浮点表示的固有限制，留到最佳实践和原理章节展开。

```python
print(0.3 - 0.1)
# 0.19999999999999998
```

运行结果：

```text
0.19999999999999998
```

### 2.3 乘法运算符 `*`

乘法把两个操作数相乘，返回积。它的语义在数值上是"倍数"，在序列类型上则是"重复"。

**示例**

模拟最常见的小计计算：单价乘以数量。

```python
unit_price = 19.9
qty = 3
subtotal = unit_price * qty
print(f"小计：{subtotal}")
```

**运行结果**：

```text
小计：59.699999999999996
```

**关键点**：注意这次运行结果不是干净的 `59.7`，而是 `59.699999999999996`。这是 `19.9 * 3` 在二进制浮点表示下的精度表现——`19.9` 在计算机里本就不是一个能精确表示的值。这是浮点运算最常见的"惊喜"，处理金额时通常要用 `round()` 或 `Decimal` 规整，细节留到最佳实践章节给出。

乘法对序列的"重复"行为同样属于重载示意：

```python
print("ab" * 3)      # 字符串重复
print([0] * 3)       # 列表重复
```

运行结果：

```text
ababab
[0, 0, 0]
```

### 2.4 真除法 `/`

真除法返回两个数相除的精确结果，**结果始终是 `float`**，这是 Python 算术运算符中最容易被忽略、却最关键的一条规则。

**示例**

```python
print(f"10 / 2 = {10 / 2}        # 能整除也是 float")
print(f"10 / 3 = {10 / 3:.4f}    # 不能整除得到近似小数")
print(f"99 / 3 = {99 / 3}, 类型 = {type(99 / 3).__name__}")
```

**运行结果**：

```text
10 / 2 = 5.0        # 能整除也是 float
10 / 3 = 3.3333    # 不能整除得到近似小数
99 / 3 = 33.0, 类型 = float
```

**关键点**：`10 / 2` 的数学结果是 `5`，但 Python 返回 `5.0`（float），而不是 `5`（int）。这个设计的好处是：你一眼就能知道"这里是除法，结果可能带小数"，不会把整数除整数误当成"只取整数部分"。但它也带来一个坑——如果你把 `/` 的结果直接当作列表索引或需要精确 `int` 的地方使用，会因为类型是 `float` 而报错或行为异常。

```python
# 索引场景：float 不能做下标
# nums[10 / 2]   # 报错：TypeError，列表索引必须是 int
```

当你确定需要整数结果时，要用 `int()` 转换或直接使用整除 `//`。

### 2.5 整除 `//`

整除（floor division）返回商的"整数部分"，但取整方向是**朝负无穷（floor）**，而不是朝零截断。这一条是初学者最容易踩的坑。

**示例**

先看正数，行为直觉正常：

```python
print(f"17 // 5 = {17 // 5}    # 17/5=3.4 → floor → 3")
print(f"16 // 4 = {16 // 4}     # 整除得 4")
```

**运行结果**：

```text
17 // 5 = 3    # 17/5=3.4 → floor → 3
16 // 4 = 4     # 整除得 4
```

再看负数，差异就出现了：

```python
print(f"-17 // 5 = {-17 // 5}   # -17/5=-3.4 → 朝负无穷 → -4")
print(f"17 // -5 = {17 // -5}   # 17/-5=-3.4 → 朝负无穷 → -4")
print(f"-17 // -5 = {-17 // -5}  # -17/-5=3.4 → 朝负无穷 → 3")
```

**运行结果**：

```text
-17 // 5 = -4   # -17/5=-3.4 → 朝负无穷 → -4
17 // -5 = -4   # 17/-5=-3.4 → 朝负无穷 → -4
-17 // -5 = 3  # -17/-5=3.4 → 朝负无穷 → 3
```

**关键点**：`-17 / 5` 的数学商是 `-3.4`。很多人凭直觉以为"整除就是把小数部分砍掉"得 `-3`，但 Python 朝负无穷取整得 `-4`。区别在于 `floor` 找的是"不大于商的最大整数"——不大于 `-3.4` 的最大整数是 `-4`，不是 `-3`。如果需要"朝零截断"的行为（即得 `-3`），要用 `int(a / b)` 或 `math.trunc`，但不能直接用 `//`。

另一个常被忽略的细节：只要有一个操作数是 `float`，`//` 的结果就是 `float`。

```python
print(f"10 // 4.0 = {10 // 4.0}, 类型 {type(10 // 4.0).__name__}")
```

运行结果：

```text
10 // 4.0 = 2.0, 类型 float
```

**典型场景**：分页计算。共 23 条数据、每页 5 条，求总页数时，"向上取整"是个常用技巧：

```python
total, per_page = 23, 5
pages = (total + per_page - 1) // per_page   # 向上取整
last = total % per_page
print(f"共 {pages} 页，最后一页 {last} 条")
```

运行结果：

```text
共 5 页，最后一页 3 条
```

### 2.6 取余 `%`

取余（modulo）返回除法后的余数。它的核心规律是：**余数的符号与除数（右操作数）一致**，并且始终满足恒等式 `(a // b) * b + a % b == a`。

**示例**

```python
print(f"17 % 5 = {17 % 5}      # 除数 5 为正，余数正")
print(f"-17 % 5 = {-17 % 5}    # 除数 5 为正，余数正：3")
print(f"17 % -5 = {17 % -5}    # 除数 -5 为负，余数负：-3")
print(f"-17 % -5 = {-17 % -5}  # 除数 -5 为负，余数负：-2")
```

**运行结果**：

```text
17 % 5 = 2      # 除数 5 为正，余数正
-17 % 5 = 3    # 除数 5 为正，余数正：3
17 % -5 = -3    # 除数 -5 为负，余数负：-3
-17 % -5 = -2  # 除数 -5 为负，余数负：-2
```

用恒等式验证，确保理解无误：

```python
a, b = -17, 5
print((a // b) * b + a % b == a)   # True
print(f"({a}//{b})*{b} + {a}%{b} = {(a // b) * b + a % b} == {a}")
```

运行结果：

```text
True
(-17//5)*5 + -17%5 = -17 == -17
```

**关键点**：`-17 % 5` 得 `3` 而不是 `-2`，这是 Python 和某些语言（如 C/Java 的 `%` 朝零截断）最大的区别。Python 的取余之所以这样设计，是为了让"周期性"场景天然成立——比如用 `% 5` 把任何整数映射到 `0..4` 区间，无论它是正是负：

```python
for x in [-3, -8, 2, 7, 13]:
    print(f"{x} 映射到 {x % 5}")
```

运行结果：

```text
-3 映射到 2
-8 映射到 2
2 映射到 2
7 映射到 2
13 映射到 3
```

**典型场景**：判断奇偶、判断闰年、计算钟表刻度。判断奇偶是最常见的：

```python
nums = [7, 10, 15, 22]
for x in nums:
    kind = "偶数" if x % 2 == 0 else "奇数"
    print(f"{x} 是 {kind}")
```

运行结果：

```text
7 是 奇数
10 是 偶数
15 是 奇数
22 是 偶数
```

### 2.7 幂运算 `**`

幂运算求"底数的指数次方"。它在三方面有特别之处：优先级最高（仅次于括号）、右结合、对负数和分数指数有专门处理。

**示例**

正整数幂是最直观的：

```python
print(f"2 ** 10 = {2 ** 10}        # 2 的 10 次方")
print(f"5 ** 3 = {5 ** 3}          # 5 的 3 次方")
```

**运行结果**：

```text
2 ** 10 = 1024        # 2 的 10 次方
5 ** 3 = 125          # 5 的 3 次方
```

右结合——多个 `**` 连写时，从右往左算：

```python
print(f"2 ** 3 ** 2 = {2 ** 3 ** 2}    # 先算 3**2=9，再算 2**9=512")
```

**运行结果**：

```text
2 ** 3 ** 2 = 512    # 先算 3**2=9，再算 2**9=512
```

**关键点**：右结合带来的结果和"从左到右"完全不同。`2 ** 3 ** 2` 如果从左到右算会是 `(2**3)**2 = 64`，但实际是 `2**(3**2) = 512`。这是 Python 里唯一一个"从右往左"的双目算术运算符，记不住时直接加括号。

负指数等于取倒数：

```python
print(f"2 ** -1 = {2 ** -1}        # 等于 1/2")
print(f"4 ** -2 = {4 ** -2}        # 等于 1/(4**2)")
```

运行结果：

```text
2 ** -1 = 0.5        # 等于 1/2
4 ** -2 = 0.0625        # 等于 1/(4**2)
```

分数指数可以开 N 次方：

```python
print(f"9 ** 0.5 = {9 ** 0.5}      # 平方根")
print(f"8 ** (1/3) = {8 ** (1/3):.6f}  # 立方根")
```

运行结果：

```text
9 ** 0.5 = 3.0      # 平方根
8 ** (1/3) = 2.000000  # 立方根
```

负底数开偶次方会得到复数——这是 Python 3 的行为，不再报错，而是返回 `complex`：

```python
print(f"(-9) ** 0.5 = {(-9) ** 0.5}    # 负数开平方 → 复数")
```

运行结果：

```text
(-9) ** 0.5 = (1.8369701987210297e-16+3j)    # 负数开平方 → 复数
```

**关键点**：幂运算的优先级比一元负号还高，所以 `-2 ** 2` 是 `-4` 而不是 `4`——先算 `2**2=4`，再应用负号；想要负数的平方必须加括号 `(-2) ** 2`。

```python
print(f"-2 ** 2 = {-2 ** 2}       # 先 2**2=4，再加负号 = -4")
print(f"(-2) ** 2 = {(-2) ** 2}    # 括号先算 = 4")
```

运行结果：

```text
-2 ** 2 = -4       # 先 2**2=4，再加负号 = -4
(-2) ** 2 = 4    # 括号先算 = 4
```

**典型场景**：面积/体积公式用 `**` 算平方和立方，复利公式用 `(1+r)**n` 算增长。

### 2.8 一元正负号 `+x` 与 `-x`

一元正负号是单目运算符，写在操作数前面。`+x` 基本原样返回数值（并显式触发类型的 `__pos__` 方法），`-x` 取相反数。

**示例**

```python
n = 5
print(f"+{n} = {+n}, 类型 {type(+n).__name__}")
print(f"-{n} = {-n}")
print(f"-(-{n}) = {-(-n)}        # 负负得正")
```

**运行结果**：

```text
+5 = 5, 类型 int
-5 = -5
-(-5) = 5        # 负负得正
```

**关键点**：`+x` 对普通数字几乎是"无操作"，它在源码里的真实价值是表达"我故意强调这是个正数"，或者在自定义类上触发 `__pos__`。相比之下 `-x` 才是真正改变值的运算符，常用于"取一个数的相反数"。要小心 `-x` 和幂运算的优先级配合：`-2 ** 2` 是 `-4` 而不是 `4`，这在 2.7 节已经演示过。

## 3. 最佳实践

### 3.1 推荐写法 vs 不推荐写法

| 场景 | 不推荐 | 推荐 | 原因 |
|------|--------|------|------|
| 需要整数结果 | `int(a / b)` | `a // b` | `//` 语义明确，且避免一次多余的浮点除法 |
| 向上取整分页 | `a // b + (1 if a % b else 0)` | `(a + b - 1) // b` | 后者一行表达，不易写错 |
| 金额计算 | `19.9 * 3` | `Decimal("19.9") * 3` | 浮点有精度尾巴，金额必须用 `Decimal` |
| 判断奇偶 | `x % 2 == 1` | `x % 2 != 0` | 负奇数 `% 2` 是 `-1`，`== 1` 会漏判负数 |
| 平方/立方 | `x * x` 和 `x * x * x` 可读性 OK | 复杂乘方用 `**` | 简单平方可用 `x*x`，但多幂次用 `**` 更清晰 |
| 浮点比较相等 | `0.1 + 0.2 == 0.3` | `abs(a-b) < 1e-9` | 浮点无法精确相等，要用容差 |

先看金额那条：用 `float` 直接算账会有精度问题，推荐做法：

```python
# 不推荐：浮点精度问题
total = 19.9 * 3
print(total)   # 59.699999999999996

# 推荐：用 Decimal 处理金额
from decimal import Decimal
total_ok = Decimal("19.9") * 3
print(total_ok)   # 59.7
```

运行结果：

```text
59.699999999999996
59.7
```

注意 `Decimal("19.9")` 必须传字符串，如果传 `Decimal(19.9)` 会先把 `19.9` 转成不精确的 `float` 再包装，精度问题原地保留。

再看奇偶判断那条——这是一个真实的隐蔽 bug：

```python
# 不推荐：负奇数会被误判成“不是奇数”
def is_odd_wrong(x):
    return x % 2 == 1      # -3 % 2 = 1? 实际是 1，但 -7 % 2 = 1 仍对...
# 看似没问题，但一些语言里!=0更稳

# 推荐：用 != 0，兼容负数
def is_odd(x):
    return x % 2 != 0
print(is_odd(-7))   # True
```

运行结果：

```text
True
```

虽然 Python 的 `%` 朝负无穷取整，负奇数 `% 2` 实际是 `1`（因为 `-7 = -4*2 + 1`），但写成 `!= 0` 在语义上更安全、更跨语言通用。

### 3.2 常见错误模式及修正

**错误一：拿 `/` 的结果当索引**

```python
# 错误
# value = data[10 / 2]   # TypeError: list indices must be integers

# 修正：用 // 得到 int 索引
value_idx = 10 // 2
print(f"索引 {value_idx}，类型 {type(value_idx).__name__}")
```

运行结果：

```text
索引 5，类型 int
```

**错误二：以为 `//` 是"截断小数"**

```python
# 误以为 -17 // 5 = -3
print(-17 // 5)   # 实际是 -4
```

运行结果：

```text
-4
```

修正方式：需要朝零截断用 `int(a / b)` 或 `math.trunc`：

```python
import math
print(int(-17 / 5))          # -3 朝零截断
print(math.trunc(-17 / 5))   # -3 显式截断
```

运行结果：

```text
-3
-3
```

**错误三：浮点相等比较**

```python
print(0.1 + 0.2 == 0.3)   # False！
```

运行结果：

```text
False
```

修正：用容差比较，或用 `Decimal`、`math.isclose`：

```python
import math
print(math.isclose(0.1 + 0.2, 0.3))   # True
```

运行结果：

```text
True
```

### 3.3 可读性取舍

写表达式时，优先级容易让人犹豫。一个好习惯是：**当表达混合了算术和比较、或含 `**` 与一元负号时，主动加括号**——即便不写括号结果也对，括号也能让读代码的人一眼明白你的意图。

```python
# 不加括号，要靠记忆判断优先级
price = base + extra * 1.2
# 加括号，意图清晰
price = base + (extra * 1.2)
```

性能上，`//` 比 `int(a / b)` 略快，因为它省了一次浮点除法转换；但日常业务里这点差异基本可以忽略，可读性更重要。

## 4. 原理

### 4.1 为什么 `/` 永远返回 float

Python 3 故意把 `/` 设计成"永远返回浮点数"，`//` 才是"整数除法"。这个设计是为了消除一个历史坑：在 Python 2 里，`/` 的行为依赖操作数——两个 int 相除得 int（截断），混入 float 得 float。结果同一行 `total / count`，有时是整数有时是小数，非常容易出 bug。

Python 3 的取舍是：让 `/` 始终意味着"精确除法"，把"取整数部分"的需要显式交给 `//`。代价是想要整数商时多打两个字符，换来的是**语义稳定**——你一眼看到 `/`，就知道结果可能带小数，绝不会把整数除结果误用。

### 4.2 `//` 为什么朝负无穷取整

`//` 的取整方向叫 floor——找"不大于真实商的最大整数"。对于正数这和"截断小数"没有区别，但对负数不同：`-3.4` 朝负无穷 floor 得 `-4`，朝零截断得 `-3`。

Python 选 floor 而不是截断，是为了和 `%` 保持自洽：让恒等式 `(a // b) * b + a % b == a` 在正负数下都成立，并且余数符号跟随除数。这样"周期映射"天然成立——任何整数 `% 5` 都落在 `0..4`，无论正负。代价是负数整除结果和一些人直觉相反，需要单独记住。

如果你确实需要"朝零截断"，用 `int(a / b)` 或 `math.trunc(a / b)`，这是语言提供的另一条出路，两者各司其职。

### 4.3 算术运算符的重载

算术运算符的"对不同类型不同行为"由类型自己的魔术方法决定。每个算术运算符背后都对应一个双下划线方法，你写 `a + b` 时，Python 实际是尝试 `a.__add__(b)`：

| 运算符 | 魔术方法 | 含义 |
|--------|---------|------|
| `+` | `__add__` | 加 / 拼接 |
| `-` | `__sub__` | 减 |
| `*` | `__mul__` | 乘 / 重复 |
| `/` | `__truediv__` | 真除法 |
| `//` | `__floordiv__` | 整除 |
| `%` | `__mod__` | 取余 |
| `**` | `__pow__` | 幂 |
| `+x` | `__pos__` | 一元正号 |
| `-x` | `__neg__` | 一元负号 |

内置的 `int`、`float` 都在 C 层实现了这些方法，所以 `3 + 5` 是加法；`str` 实现了 `__add__` 让 `+` 变成拼接，实现了 `__mul__` 让 `*` 变成重复。理解这一点，你就能预测：一个自定义类只要实现了 `__add__`，它的对象就能用 `+`，行为完全由你来定义。

```python
class Money:
    def __init__(self, yuan, fen=0):
        self.cents = yuan * 100 + fen      # 统一用“分”存放，避免浮点

    def __add__(self, other):
        return Money(0, self.cents + other.cents)

    def __repr__(self):
        return f"Money({self.cents / 100:.2f}元)"

a = Money(19, 90)        # 19.90 元
b = Money(3, 50)        # 3.50 元
print(a + b)             # Money(23.40元)，+ 被重载
```

运行结果：

```text
Money(23.40元)，+ 被重载
```

这个小例子也顺带示范了处理金额的正确思路：内部用整数"分"存储、对外显示时再换算，从根上避开浮点精度问题。

### 4.4 浮点精度从何而来

为什么 `19.9 * 3` 不是干净的 `59.7`？因为 `float` 在底层是 IEEE 754 双精度二进制浮点数。很多十进制小数（如 `0.1`、`19.9`）在二进制下是无限循环小数，存进有限位数后就会产生截断误差，再参与运算误差就暴露出来。

这不是 Python 的 bug，而是几乎所有语言 `float` 的共同特征。面对钱的场景用 `Decimal`（十进制存储，精确表示小数），面对需要精确整数商的场景用 `//`，面对浮点比较用容差或 `math.isclose`——这三条对应了 3.1 节推荐写法表里的三行。

## 5. 总结

本文围绕 Python 的算术运算符展开，主要介绍了以下内容：

- 算术运算符包括 `+`、`-`、`*`、`/`、`//`、`%`、`**` 七种双目运算符，以及 `+x`、`-x` 两个一元正负号
- 真除法 `/` 永远返回 `float`，这是 Python 3 为了语义稳定做的设计；需要整数商要显式用 `//`
- 整除 `//` 朝负无穷（floor）取整，负数的整除结果常和直觉相反，需要朝零截断时用 `int(a/b)` 或 `math.trunc`
- 取余 `%` 的符号跟随除数，且满足恒等式 `(a//b)*b + a%b == a`，让周期映射和奇偶判断天然成立
- 幂运算 `**` 优先级最高、右结合，`-2**2` 是 `-4` 而非 `4`，混合优先级时建议加括号
- 浮点数存在精度尾巴，金额计算要用 `Decimal`、浮点比较要用容差或 `math.isclose`
- 算术运算符对不同类型的不同行为由类型的魔术方法（如 `__add__`、`__mul__`）决定，自定义类可实现这些方法让运算符支持自己的对象
