# while 循环基础

## 1. 介绍

### 1.1 什么是 while 循环

while 循环是 Python 中"由条件驱动"的循环语句：**只要某个条件成立，就反复执行一段代码；条件一旦不成立，循环结束**。它不关心循环多少轮，只关心"此刻条件还满足吗"。

把它和已知的 for 摆在一起看分工：for 面向"手里有一批已知数据，逐个处理"（数据驱动），while 面向"什么时候停由一个条件说了算，事先数不清几轮"（条件驱动）。两种循环解决的重复问题不同侧面——for 像发牌员按名单发牌，while 像门口的门卫，**每一轮放你进门前都重新问一遍"条件还成立吗"**，问到不成立那一刻就关门。

**类比**：把 while 想象成自动售货机的出货循环——"只要投入的金额还够买一瓶（条件成立），就继续出货（执行循环体）；金额一但不够（条件不成立），立即停止"。它从不去数"我要出多少瓶"，只盯着金额这件事本身。

### 1.2 while 循环解决什么问题

while 的用武之地，是那些"重复次数没法提前数清"的场景。看三类典型情况：

| 场景类型 | 例子 | 为什么用 while |
|---------|------|---------------|
| 等待条件达成 | 持续加热直到水温超过 100 度 | 几轮后达标没人说得准 |
| 事件自适应轮数 | 密码输错就再试一次，直到正确 | 用户可能第一次就对，也可能一直错 |
| 数据消耗 | 购物车有货就一直结算，车空为止 | 剩多少件取决于运行时数据 |

用一个最小的消耗场景把"条件驱动"展示出来：

```python
cart = ["苹果", "香蕉", "酸奶", "面包", "薯片"]

while cart:                     # 购物车还有货这一条件驱动着循环
    item = cart.pop()           # 每轮从车尾拿走一件
    print(f"已结算：{item}")
print("购物车空了")
```

运行结果：

```text
已结算：薯片
已结算：面包
已结算：酸奶
已结算：香蕉
已结算：苹果
购物车空了
```

这段循环从头到尾没有出现"轮数"，也不需要知道车里有几件商品——**"车空没空"本身就是条件**，物品消耗殆尽的那一刻循环自动终止。这类"把复杂度交给条件"的写法正是 while 的招牌能力，for 要表达同样逻辑则需要先数清楚件数，反而别扭。

### 1.3 最简示例

一个最小的 while 循环，只有三行：

```python
seconds = 3
while seconds > 0:
    print(f"还剩 {seconds} 秒")
    seconds -= 1
print("完成！")
```

运行结果：

```text
还剩 3 秒
还剩 2 秒
还剩 1 秒
完成！
```

指认各个部件：`seconds = 3` 是**初始**（从什么状态出发）；`while seconds > 0:` 里的 `seconds > 0` 是**终止条件**（什么时候停）；循环体里的 `seconds -= 1` 是**推进**（每轮向终点靠近一步）。三要素在 while 里全部由你亲手管理——这正是它与 for 最大的差异：for 把这三件事托管给了语言，while 把自由度留给你，也把责任留给你。

本篇要做的就是把这副骨架的每个部件逐一拆开讲透：条件怎么设计、循环体怎么安排、推进放哪里，以及哪些写法是陷阱。

## 2. 核心内容

### 2.1 while 语句的完整语法骨架

while 语句由四个部件构成，一个都不能少：

| 部件 | 角色 | 说明 |
|------|------|------|
| `while` 关键字 | 引导语句 | 告诉 Python"这是条件循环" |
| 条件表达式 | 每轮的判定依据 | 常见是比较式、真值测试或两者组合，末尾**不加括号** |
| `:` 冒号 | 开启代码块 | 与 if、for 的冒号同待遇 |
| 缩进的循环体 | 每轮执行的代码 | 缩进一层；包含一到多条语句；**通常含推进语句** |

写成骨架结构：

```python
初始准备
while 条件表达式:
    语句1
    语句2        # 循环体：缩进部分，一轮内从上到下执行
    推进语句      # 通常放循环体末尾，让条件有朝一日不成立
```

**示例**

各部件在最简倒计时里各就各位：

```python
countdown = 3                    # 初始：写在 while 外面
while countdown > 0:              # 条件 + 冒号
    print(f"准备中……{countdown}")   # 循环体第一条
    countdown -= 1               # 循环体最后一条：推进
print("点火！")                    # 缩进复位 → 循环结束后的收尾代码
```

**运行结果**：

```text
准备中……3
准备中……2
准备中……1
点火！
```

**关键点**：初始语句必须出现在 while 之前（否则条件里的变量没定义，直接报 `NameError`）；推进语句通常放在循环体的**最后一行**——先做完本轮正事，再向终点挪一步，这与"检查 → 干活 → 靠近终点"的顺序直觉一致。最后一条 `print("点火！")` 与 `while` 同列，不属于循环体，循环结束后才执行一次。

### 2.2 循环条件：每轮重新判定的"裁判"

条件是 while 的灵魂。三个关键认识必须先立起来，再谈条件的三种常见写法。

**认识一：条件每轮开始前重新求值一次。** 它不是在循环开始时判一次就定终身——每轮进门都要重新体检。看钱包购物的例子：

```python
money = 5
price = 2
while money >= price:
    print(f"兜里 {money} 元，还买得起")
    money -= price
print(f"兜里 {money} 元，条件不再成立，循环结束")
```

**运行结果**：

```text
兜里 5 元，还买得起
兜里 3 元，还买得起
兜里 1 元，条件不再成立，循环结束
```

第 3 轮开始前 `money` 已经只剩 1 元，`money >= price` （1 >= 2）不再成立，循环体直接被跳过。条件的"重新体检"救了程序一命。

**认识二：条件可以是任何对象，按真值测试判定。** 不是只有写明比较式才能当条件——任何对象扔进条件位，Python 会自动做真值测试。空容器（空列表、空字典、空字符串）、数字 0、None 都算"假"：

```python
inbox = ["报表", "邀请函", "垃圾邮件"]
while inbox:                     # 空列表为假 → 收件箱一空条件自动失效
    message = inbox.pop()
    print(f"处理邮件：{message}")
print("收件箱清空")
```

**运行结果**：

```text
处理邮件：垃圾邮件
处理邮件：邀请函
处理邮件：报表
收件箱清空
```

**关键点**：`while inbox:` 是 `while len(inbox) > 0:` 的地道简写——真值测试判断的是容器里"还有没有东西"。凡是"不空就继续"的场景，直接把容器写在条件位即可。

**认识三：条件可以由 and / or 组合成复合条件。** 一行条件里可以同时押几道关卡，全部通过（用 and）或至少一道通过（用 or）才算成立：

```python
countdown = 3
safety = 0
while countdown > 0 and safety < 3:   # 两道关卡同时成立才继续
    safety += 1
    print(f"第 {safety} 轮（countdown = {countdown}）")
    countdown -= 1
```

**运行结果**：

```text
第 1 轮（countdown = 3）
第 2 轮（countdown = 2）
第 3 轮（countdown = 1）
```

**关键点**：`and` 连接出的复合条件是"多道保险"——任何一道不成立整个条件就崩塌。演示或排查危险逻辑时加一个 `safety < 上限` 的闸门，是防御性编程的常见手段。反过来用 or 组合时，任何一道成立就由它递补导致循环继续，使用时要格外想清楚各自含义。

### 2.3 循环体：一轮要做的全部事

循环体是每轮**完整执行一遍**的代码块。它可以从一条语句到几十条语句，一轮之内严格按从上到下顺序跑完，再回到条件处报到。看一个一轮干三件事的例子：打印进度、处理正文、推进计数：

```python
reviewed = 0
total_docs = 3
while reviewed < total_docs:
    print(f"开始审核第 {reviewed + 1} 份合同")     # 事前：报个进度
    reviewed += 1                                  # 推进：处理完才计数
    print(f"  ……已审核完成，累计 {reviewed} 份")      # 事后：汇报结果
```

**运行结果**：

```text
开始审核第 1 份合同
  ……已审核完成，累计 1 份
开始审核第 2 份合同
  ……已审核完成，累计 2 份
开始审核第 3 份合同
  ……已审核完成，累计 3 份
```

一行行核对输出能验证时序：每轮三行整齐地成组出现——循环体作为整体被重复，而不是某个语句被单独重复。**记住这条边界规则：缩进对齐到循环体的语句每轮都跑；缩进退回与 while 同列的语句只在循环结束后跑一次**。

推进语句放在循环体的什么位置有讲究。多数场景放**最后一行**（先干活、再挪步）；有些场景放在**第一行**（先挪步、再干活），两种位置输出可能不同：

```python
# 推进放末尾："干活前"打印的仍是旧值，第一轮看到起点值
n = 0
while n < 3:
    print(f"末尾推进：本轮打印 {n}")
    n += 1
```

**运行结果**：

```text
末尾推进：本轮打印 0
末尾推进：本轮打印 1
末尾推进：本轮打印 2
```

```python
# 推进放开头：先走一步再干活，第一轮看到的就是递增后的值
n = 0
while n < 3:
    n += 1
    print(f"开头推进：本轮打印 {n}")
```

**运行结果**：

```text
开头推进：本轮打印 1
开头推进：本轮打印 2
开头推进：本轮打印 3
```

**关键点**：两段循环都合法、都恰好跑三轮，但打印的数值序列不同——推进位置决定了循环体"看到"的是递增前还是递增后的值。写 while 时要带着这个问题审视推进语句的位置：**这一轮的业务逻辑，应该发生在"挪步之前"还是"挪步之后"**。没有定论，只有意图。

### 2.4 最典型用法一：计数循环

计数循环是 while 最经典的形态：拿一个变量当计数器，条件写成"还没数到终点"，循环体里推进计数器。**计数方向三类都要熟**：递增、递减、自定义步长。

**递增计数：从 0 数到大目标**

```python
pushups = 0
while pushups < 5:
    pushups += 1
    print(f"做完第 {pushups} 个俯卧撑")
print(f"训练完成，共 {pushups} 个")
```

**运行结果**：

```text
做完第 1 个俯卧撑
做完第 2 个俯卧撑
做完第 3 个俯卧撑
做完第 4 个俯卧撑
做完第 5 个俯卧撑
训练完成，共 5 个
```

**倒计时：从大往小数**

```python
countdown = 5
while countdown > 0:
    print(f"倒计时 {countdown}")
    countdown -= 1
print("点火！")
```

**运行结果**：

```text
倒计时 5
倒计时 4
倒计时 3
倒计时 2
倒计时 1
点火！
```

**自定义步长：推进不只有 ±1**

推进语句的本质是"每轮向终点靠近一步"，这一步可大可小、可加可乘：

```python
step = 0
while step < 17:
    step += 3                          # 加法步长：一次上 3 级台阶
    print(f"站在第 {step} 级台阶")

balance = 100
while balance < 800:
    balance *= 2                       # 乘法步长：余额每轮翻倍
    print(f"余额变为 {balance}")
```

**运行结果**：

```text
站在第 3 级台阶
站在第 6 级台阶
站在第 9 级台阶
站在第 12 级台阶
站在第 15 级台阶
站在第 18 级台阶
余额变为 200
余额变为 400
余额变为 800
```

**关键点**：台阶循环最后一轮站上的是 18 级而非恰好 17 级——步长 3 的栅格对不齐 17 这个终点时，循环**从终点上方迈过去**再停（17 不满足时 18 也已越线）。翻倍循环停在 800 是因为按步长栅格恰好踩中。用自定义步长时要预判"最后一个落点会停在哪"，规则是：**条件首次不成立时立刻停在被检的当前值上，绝不回退**。

### 2.5 最典型用法二：消耗循环

计数循环靠"数进度"驱动；消耗循环不数进度，**直接拿"数据还剩不剩"当条件**——容器不空就继续、一空自动折返。这是 while 条件真值测试（2.2 节）的招牌应用场景：

```python
ports = [8080, 8081, 8082]        # 待尝试的候选端口
while ports:
    port = ports.pop(0)            # 从头部取一个：消耗数据本身
    print(f"尝试连接端口 {port} ……成功")
print("候选端口全部试完，循环结束")
```

**运行结果**：

```text
尝试连接端口 8080 ……成功
尝试连接端口 8081 ……成功
尝试连接端口 8082 ……成功
候选端口全部试完，循环结束
```

**关键点**：整个循环没有计数器、没有终点值——`while ports:` 只认"列表里还有东西吗"。每轮 `pop` 会**真地把数据拿出一个**（列表随之变短），消耗行为本身在改变条件，到列表清空那一刻条件自动熄火。这正是消耗循环的省心之处：**条件不需要你维护，它自己随数据枯竭而终止**。

取的方向也有讲究：`pop()` 默认从**尾部**拿（后进先出），`pop(0)` 从**头部**拿（先进先出）。拿端口试连这种"按排列顺序试"的场景用 `pop(0)`；购物车那种"从最后加的开始结"的场景用 `pop()`。方向的选择取决于业务语义，但**消耗循环每次循环体必须真的消耗至少一个元素**，否则列表永远不空，又是一次条件恒真的死循环。防御口诀：**条件靠什么瓦解，循环体就必须在动什么**。

### 2.6 最典型用法三：标志位驱动

有一类循环的"继续与否"既不是数出来的（计数）、也不是数据剩不剩（消耗），而是一个**业务状态**：自检通过没有、用户确认没有、游戏结束没有。这类状态用**标志位（flag）**表达——起一个布尔变量当"开关"，条件写成 `while not 开关已拨` 的形式：

```python
ready = False                 # 标志位 False = 还没就绪，还得继续
attempts = 0
while not ready:              # 只看开关状态，不看具体轮数
    attempts += 1
    passed = attempts >= 3    # 模拟：前两轮自检失败、第三轮通过
    print(f"第 {attempts} 次自检执行，通过={passed}")
    if passed:
        ready = True          # 拨动开关 → 下一轮条件顺势瓦解
print(f"自检完成，共尝试 {attempts} 次")
```

**运行结果**：

```text
第 1 次自检执行，通过=False
第 2 次自检执行，通过=False
第 3 次自检执行，通过=True
自检完成，共尝试 3 次
```

**关键点**：标志位的运转分两步看——条件位写 `while not ready`（只要开关没拨就继续），循环体内某处在达成条件时 `ready = True` 拨开关。它把"什么时候停"的复杂判断从条件行挪进了循环体：条件行只管盯开关，**至于该不该拨开关、什么时候拨，是循环体里 if 的职责**。当停止的时机涉及多重业务判断时，标志位能把条件行保持得极简，是把复杂度从条件表达式转移进循环体的标准手法。

### 2.7 下标遍历序列：while 的"手动挡"

数据已就位，就能拿 while 顺着**位置**把它们逐个访问一遍：起一个下标变量 `i` 从 0 出发，条件写 `i < len(数据)`，循环体里用 `数据[i]` 取元素、`i += 1` 前进：

```python
fruits = ["苹果", "香蕉", "橙子", "葡萄"]
i = 0                          # 初始：从下标 0 出发
while i < len(fruits):         # 终止：下标越界前停下
    print(f"第 {i + 1} 个水果是：{fruits[i]}")
    i += 1                     # 推进：下标前移
print(f"循环结束时 i = {i}，恰好等于列表长度 {len(fruits)}")
```

**运行结果**：

```text
第 1 个水果是：苹果
第 2 个水果是：香蕉
第 3 个水果是：橙子
第 4 个水果是：葡萄
循环结束时 i = 4，恰好等于列表长度 4
```

**关键点**：这套"初始 → 条件 → 用 i 取值 → 推进"四件事，恰好是 for 循环一行替你全部托管的内容。for 版对照：

```python
for fruit in fruits:
    print(f"今天吃：{fruit}")
```

`for fruit in fruits:` 一个语句行完成了"i 从 0 起、不越界、取当前、往后挪"的全部工作。所以**能用 for 的遍历场景优先 for**——手动挡留着给"非用位置不可"的场景，比如输出中要报位置、按位置跳过、按位置修改等：

```python
playlist = ["晴天", "后来", "探窗", "后来"]
i = 0
while i < len(playlist):
    print(f"曲目 {i + 1}：{playlist[i]}（下标 {i}）")
    i += 1
```

**运行结果**：

```text
曲目 1：晴天（下标 0）
曲目 2：后来（下标 1）
曲目 3：探窗（下标 2）
曲目 4：后来（下标 3）
```

两首"后来"靠下标区分开了身份——这种"位置本身就是信息"的场合，是下标循环的一席之地。另外留意边界：条件必须写 `i < len(...)` 而不是 `i <= len(...)`，下标从 0 编号，长度为 4 的列表最大合法下标是 3；`<= length` 会让最后一轮取 `fruits[4]` 直接抛出 `IndexError`。

## 3. 最佳实践

### 3.1 推荐写法与不推荐写法对比

写 while 的常见决策点，推荐姿势与踩坑姿势对照如下：

| # | 场景 | 不推荐写法 | 推荐写法 | 原因 |
|---|------|-----------|---------|------|
| 1 | 遍历已知序列 | `i = 0` + `while i < len(seq)` + `i += 1` | `for x in seq:` | 三行手动挡做 for 一行托管的事，三要素全自己担责，多一个出错机会 |
| 2 | 推进语句位置 | 散落在 if 分支深处，甚至漏写 | 紧跟业务语句放循环体末尾，一望便知 | 推进藏在分支里容易某条路径漏推进 → 死循环 |
| 3 | 复杂停止条件 | 一行塞五个 `and`/`or` 的超长条件 | 标志位 + 循环体内拨开关 | 超长条件读不懂也排不对；flag 把判断搬进循环体，一行一意 |
| 4 | 浮点计数 | `while x != 1.0:` | 计数用整数；阈值用 `<`/`>` | 浮点存在精度误差，等值比较可能永不成立 |
| 5 | 边界条件 | 信手写 `<` 或 `<=` | 先明确"要包含最后一个吗" | off-by-one：差一个符号少算一轮 |

其中第 1 条展开看个正反对照。不推荐的手动挡遍历：

```python
names = ["张三", "李四", "王五"]
i = 0
while i < len(names):
    print(f"你好，{names[i]}")
    i += 1
```

等价的 for 版本：

```python
for name in names:
    print(f"你好，{name}")
```

两段输出相同，但 while 版自己管理三要素（初始 `i = 0`、条件 `i < len`、推进 `i += 1`），任何一处写歪都出 bug；for 版把这些托管给语言，行数更短、心智负担更低。**判据不变：数据在手且顺序固定就用 for；只有位置本身是信息时才请下标出马**。

### 3.2 常见错误模式及修正

**错误模式一：off-by-one——"少了一轮"的边界错**

任务是打印 1 到 5，代码却只到 4，因为条件边界选错：

```python
n = 1
while n < 5:                # 目标是 1~5，写成 < 5 少打一轮
    print(f"< 5 版本轮：{n}")
    n += 1
print(f"循环停在 {n}，5 没被打印")

n = 1
while n <= 5:               # 边界修正：包含端点的任务用 <=
    print(f"<= 5 版本轮：{n}")
    n += 1
print(f"循环停在 {n}，5 已被打印")
```

**运行结果**：

```text
< 5 版本轮：1
< 5 版本轮：2
< 5 版本轮：3
< 5 版本轮：4
循环停在 5，5 没被打印
<= 5 版本轮：1
<= 5 版本轮：2
<= 5 版本轮：3
<= 5 版本轮：4
<= 5 版本轮：5
循环停在 6，5 已被打印
```

修正技巧：写条件前先自问一句"**最后一个值要不要做**"。要——用 `<=`（或调终点值）；不要——用 `<`。边界是把"意图"翻译成符号的地方，翻译误差一轮就现形。

**错误模式二：浮点计数——永远差一点点的精确陷阱**

想让 0.1 的累加停在那精确的 1.0 上，用等值比较作条件：

```python
x = 0.0
times = 0
while x != 1.0 and times < 15:      # 保险装置只是便于观察，非业务逻辑
    x += 0.1
    times += 1
print(f"加了 {times} 次后 x = {x}")
```

**运行结果**：

```text
加了 15 次后 x = 1.5000000000000002
```

`x` 加满保险允许的 15 次也没有精确停在 1.0 上——0.1 在二进制中是无限循环小数，每次累加都带一点误差，加满 10 次的真实结果是 0.9999999999999999，继续往上加也只是在 1.0 附近漂浮，等值条件永远等不到精确落点。修正姿势：**浮点循环用不等式做阈值，不做等值**：

```python
x = 0.0
steps = 0
while x < 1.0:
    x += 0.1
    steps += 1
print(f"用 x < 1.0 作条件：走 {steps} 轮稳定结束")
```

**运行结果**：

```text
用 x < 1.0 作条件：走了 11 轮稳定结束
```

注意轮数是 11 不是 10——第 10 次累加后 x = 0.9999999999999999，仍然小于 1.0，门卫继续放行；第 11 次累加后 x = 1.0999999999999999 才越过阈值。这恰好展示了阈值条件的价值：**它不承诺精确的轮数与落点，只承诺"不越过阈值就不停"**——浮点误差让它多走一轮也照样稳定收场。更彻底的修正是把计数交给整数（`while times < 10:`），只在业务需要处做浮点计算——整数的边界判断永远可靠。

**错误模式三：条件位写赋值——一处必报的语法错**

初学者偶尔从其他语言迁移习惯，把"判断 x 是否为 5"错写成赋值：

```text
while x = 5:
    ...
```

Python 直接拒绝这种写法，报 `SyntaxError: invalid syntax`——**条件位只接受表达式**（能求值出真假的式子），赋值语句没有真值，没有资格站岗。判定成立应写 `while x == 5:`（双等号比较），判空应写 `while x != None:` 或更地道的 `while x is not None:`。

**错误模式四：`while True` 没有出口意识**

```python
while True:
    print("警告：这是一段演示用的永动循环文本……")
```

条件位写死 `True`，循环**没有任何自行终止的可能**——除非循环体内存在能改变这一局面的手段，否则程序会永远轮转下去，只能靠手动中断（终端里按 Ctrl+C 强行打断）才停得下来。在尚未掌握"从循环内部中途退出的专门手法"之前，请对自己写下的每一个 `while True` 保持戒心：它在语义上是"永不熄火的循环"，要么别写，要么明确知道它靠什么手段收场。

### 3.3 while 与 for 的场景分工

两大循环的选型判据合并成一张速查表：

| 特征 | 优先选 for | 优先选 while |
|------|-----------|-------------|
| 手里的数据 | 有一批已知元素 | 没有现成数据，只有状态 |
| 循环次数 | 事前数得清 | 事前数不清 |
| 停止方式 | 元素取完自然停 | 条件被打破才停 |
| 典型场景 | 遍历名单、逐条处理、逐字符扫描 | 等待达标、消耗库存、重试到成功、下标手动遍历 |
| 三要素 | 语言托管，零负担 | 自己管理，全责自负 |

一句话定调：**for 问"还有没有下一个"，while 问"条件还成立吗"**。写循环前先想这一句，选型基本不会错。

## 4. 原理：条件门卫与跳回机制

### 4.1 while 的微观运转：判一次、跑一轮、跳回来

把 while 放到放大镜下，它每轮的运转只有四步：

```text
        ┌──────────────────────┐
        │ 求值条件表达式        │ ←──────┐
        └──────────┬───────────┘        │
                   ↓                    │
             结果为 True？               │
           True ↙        ↘ False        │
   ┌──────────────┐      ┌──────────┐  │
   │ 从上到下执行   │      │ 放行：执行 │  │
   │ 整个循环体     │      │ 循环后代码 │  │
   └──────┬───────┘      └──────────┘  │
          ↓                            │
   ┌──────────────┐                    │
   │ 跳回条件处     │ ───────────────────┘
   └──────────────┘
```

这张图解释了 while 的两条根本时序：**其一，条件求值永远发生在"进入循环体之前"**——首轮条件就不成立时，循环体一行都不会执行（零轮循环）；**其二，循环体跑完的终点不是"下一条语句"，而是"跳回条件处"**——所谓"循环"，物理上就是这条回跳路径。

由此也能看清"每轮重判"的含义：条件表达式里写的是"变量此刻的值"，不是某一瞬间的快照。`while money >= price` 每一轮都拿**当前**的 `money` 与 `price` 相比，money 在循环里被逐次扣减，判断结果就随之逐次变化。条件不是一条"一次性裁决"，而是一位**逐轮重新上岗的门卫**。

### 4.2 变量变化何时被感知：本轮内不审，下一轮再审

顺着门卫模型推一个容易踩的细节：**在循环体执行过程中改变了条件变量，这个变化不会中途打断本轮，但要等本轮跑完、跳回条件处，下一轮判定时才生效**。验证它：

```python
money = 6
price = 2
while money >= price:
    money -= price            # 本轮开头就扣了钱
    print(f"扣款后剩 {money} 元——本轮仍会继续执行完")
    print(f"但 {money} >= {price} 是否成立，要下一轮门卫重新判定")
```

**运行结果**：

```text
扣款后剩 4 元——本轮仍会继续执行完
但 4 >= 2 是否成立，要下一轮门卫重新判定
扣款后剩 2 元——本轮仍会继续执行完
但 2 >= 2 是否成立，要下一轮门卫重新判定
扣款后剩 0 元——本轮仍会继续执行完
但 0 >= 2 是否成立，要下一轮门卫重新判定
```

第三轮开始时 `money` 是 2，门卫放行（2 >= 2 成立）；轮内扣成 0 后，**本轮剩余行照常执行完毕**，没有任何"中途刹车"；0 的现状要等跳回条件处、由下一轮的判定才被确认不成立。一句话归拢：**while 的刹车踩在两轮之间的条件处，不在循环体中间**。理解这条，"为什么循环体改了变量还在继续跑"就不再是谜团，而是设计使然。

## 5. 总结

本文围绕 while 循环的基础用法展开，主要介绍了以下内容：

- while 是条件驱动的循环：条件成立就重复执行循环体，不成立即停；三要素（初始、推进、终止）全部由自己管理；
- 语法骨架四部件（`while` 关键字、条件表达式、冒号、缩进循环体），初始必须先于 while 出现，推进通常放循环体末尾；
- 条件是逐轮重新上岗的门卫：三种常见形态（比较表达式、真值测试、and/or 复合条件），空容器为假值可直接作条件；
- 循环体是每轮从上到下完整执行的整体；推进语句放末尾还是开头，决定循环体"看到"的是旧值还是新值；
- 四类典型用法：计数循环（递增/倒计时/自定义步长）、消耗循环（数据枯竭自动停）、标志位驱动（flag 开关控制业务状态）、下标遍历序列（需要位置信息时的手动挡）；
- 最佳实践五组对照与四种错误模式：已知序列优先 for、推进贴近条件变量、复杂条件拆成标志位、浮点别做等值条件、边界先想"最后一个值要不要做"；off-by-one、浮点精度、条件位写赋值、`while True` 无出口意识各有对应修正姿势；
- 原理层面：条件求值永远先于循环体执行（零轮循环的根源），循环体的终点是跳回条件处；轮内对条件变量的修改本轮不生效，下一轮判定时才被感知。
