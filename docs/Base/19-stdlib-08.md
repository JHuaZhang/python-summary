## 1. 介绍

### 1.1 什么是捕获组

在正则表达式中，**分组（grouping）** 指的是用圆括号 `(...)` 把一段子模式包起来，使它被视为一个整体。被 `(...)` 包裹的子模式，在匹配过程中不仅参与匹配，还会把自身匹配到的文本"记住"，留待匹配完成后单独提取——这种"被记住的子匹配"就叫做**捕获组（capture group）**。

Python 的 `re` 模块在每次匹配成功后，会返回一个 `Match` 对象，捕获组的内容就挂在这个对象上，通过 `match.group(n)`、`match.groups()`、`match.group("name")`、`match.groupdict()` 等方法取出。可以说，捕获组是正则从"只判断是否匹配"走向"结构化提取文本"的关键能力。

举个最直观的例子：解析 `key=value` 形式的配置行。如果不分组，正则只能告诉你"这一行符合 `key=value` 格式"：

```python
import re

line = "host=127.0.0.1"
match = re.match(r"\w+=\S+", line)
print(match.group(0))   # 整体匹配
# 输出：host=127.0.0.1
```

加上了捕获组，就能把 `key` 和 `value` 分别拿出来：

```python
match = re.match(r"(\w+)=(\S+)", line)
print(match.group(1))   # 第 1 个组：键
print(match.group(2))   # 第 2 个组：值
# 输出：
# 127.0.0.1
# host
# 127.0.0.1   ← 注意 group(1)=host, group(2)=127.0.0.1
```

这就是捕获组的本质：**在不拆分整体匹配的前提下，把整体中"我们关心的若干片段"分别保存下来**。

### 1.2 基础语法与最小用法

捕获组最基础的语法只有一个：一对圆括号 `(...)`。

- 每个 `(...)` 自动机编号，编号从 1 开始。
- 编号规则：**按左括号 `(` 在 pattern 中出现的先后顺序，从左到右依次递增**。
- `group(0)` 是一个特殊编号，始终代表"整体匹配"（整个正则匹配到的完整文本），它不占用编号位，真正的捕获组从 1 开始。
- `(...) ` 内可以是任意子模式，包括量词、字符类、嵌套的 `(...)`。

最小可运行示例：

```python
import re

# 用一个捕获组提取日期中的年份
m = re.search(r"(\d{4})-\d{2}-\d{2}", "发布日期：2024-03-15，已上线")
print(m.group(0))   # 整体匹配
print(m.group(1))   # 第 1 个组：年份
# 输出：
# 2024-03-15
# 2024
```

如果整个 pattern 根本没有任何 `(...)`，那么 `Match` 对象上只有 `group(0)` 可用，`group(1)` 会抛 `IndexError`：

```python
m = re.search(r"\d{4}", "2024年")
print(m.group(0))   # 输出：2024
print(m.group(1))   # 抛出 IndexError: no such group
```

理解了 `group(0)` 与 `group(n)` 的区别，就掌握了捕获组用法的骨架。后续各节在此基础上展开：命名组、非捕获组、反向引用、`re.sub` 中的引用、`findall` 返回元组列表的规则等。

## 2. 核心内容

### 2.1 捕获组的编号规则

**编号顺序：按左括号出现顺序自增**

这是捕获组最容易出错，也最需要一开始就讲清楚的规则。一条正则里可能有多个 `(...)`，它们的编号 1、2、3……并不是按右括号位置、也不是按"谁先匹配完"决定的，而是**严格按左括号 `(` 从左到右出现的先后顺序**编号。

```python
import re

# 三个捕获组，编号按 ( 出现顺序
m = re.match(r"(\d+)-(\w+)-(\s+)", "123-abc-   ")
print(m.group(1), m.group(2), m.group(3))
# 输出：123 abc
```

哪怕某个组在视觉上是"嵌套在里面"，只要它的左括号先出现，就先编号。嵌套组的编号示例见 2.8 节。

**group(0) 是整体匹配，不占编号**

`group(0)` 始终返回整个正则匹配到的完整子串，它不在 1、2、3……的编号序列中。换句话说，你的 pattern 有 N 个 `(...)`，那么 `group(1)` 到 `group(N)` 可用，`group(0)` 额外可用。

```python
m = re.search(r"(a)(b)(c)", "abc")
print(m.group(0))        # 整体
print(m.group(1), m.group(2), m.group(3))
# 输出：
# abc
# a b c
```

**group(n) 传整数或字符串数字都行**

`group(n)` 的参数 `n` 既可以传 `int`，也可以传表示数字的 `str`——`group(1)` 和 `group("1")` 等价。这在一些动态生成编号的场景下很方便，但日常代码里还是推荐传 `int`，可读性更好。

```python
m = re.match(r"(\w+)@(\w+)", "bob@host")
print(m.group(1) == m.group("1"))   # True
# 输出：True
```

### 2.2 match.groups()：取全部组

`Match.groups(default=None)` 返回一个元组，元素依次是第 1 组到第 N 组的捕获内容。它**不包含 `group(0)`**，所以长度等于捕获组数量。

```python
import re

m = re.match(r"(\w+)=(\d+)", "count=42")
print(m.groups())
# 输出：('count', '42')
```

**default 参数：用于"组参与了匹配但内容为空"或"组未参与匹配"的情况**

当一个可选捕获组没有实际匹配到内容（例如 `(\d+)?` 没匹配到数字）时，`group(n)` 返回 `None`，`groups()` 对应位置也是 `None`。传 `default` 可以把这个 `None` 替换成你指定的占位值。

```python
m = re.match(r"(\w+)(?::(\d+))?", "localhost")
print(m.groups())              # 第二组未参与匹配
print(m.groups(default="N/A"))
# 输出：
# ('localhost', None)
# ('localhost', 'N/A')
```

**区分"匹配到空串"与"未参与匹配"**

这两种情况在 Python 中表现不同：

```python
# 情况一：组匹配到了空串（合法匹配，只是长度为 0）
m1 = re.match(r"(a*)(b)", "b")
print(m1.group(1), m1.group(2))   # ('', 'b')

# 情况二：组在某个未被走的分支里，根本没参与匹配
m2 = re.match(r"(a)|(b)", "b")
print(m2.group(1), m2.group(2))   # (None, 'b')
# 输出：
#  b
# None b
```

可以看到，情况一返回的是空字符串 `''`，情况二返回的是 `None`。`groups(default=...)` 的 `default` 只会替换 `None`（未参与匹配的情况），不会替换空串——因为空串本身就是一次"真实但为空"的匹配。

### 2.3 match.group(n)：取单个组

`Match.group(n)` 按编号取单个捕获组。它比 `groups()` 更灵活：

- 传 `0`：取整体匹配。
- 传 `1..N`：取对应捕获组。
- 一次传多个编号：`group(1, 2, 3)` 返回元组，等价于 `(group(1), group(2), group(3))`。

```python
import re

m = re.search(r"(\d{4})-(\d{2})-(\d{2})", "2024-03-15")
print(m.group(0))                # 整体
print(m.group(1))                # 年
print(m.group(2))                # 月
print(m.group(3))                # 日
print(m.group(1, 2, 3))          # 一次性取多组，返回元组
# 输出：
# 2024-03-15
# 2024
# 03
# 15
# ('2024', '03', '15')
```

**越界访问会报错**

给的编号超过捕获组数量，或传了 `0` 以外的负数，会抛 `IndexError`：

```python
m = re.search(r"(\d{4})", "2024")
print(m.group(2))   # IndexError: no such group
```

**用 span / start / end 定位捕获组在原串中的位置**

除了取出捕获到的文本，`Match` 对象还能告诉你每个组匹配在**原串**中的起止位置：`m.span(n)` 返回 `(start, end)` 元组，`m.start(n)` / `m.end(n)` 分别返回起、止下标，`n` 的含义与 `group(n)` 一致（`0` 表示整体匹配）。这在需要回原串做高亮、截取上下文、记录列号时很有用。

```python
m = re.search(r"(?P<year>\d{4})-(\d{2})", "日志 2024-03 完成")
print(m.span(0))            # 整体匹配在原串中的位置
print(m.start("year"), m.end("year"))
print(m.span(2))            # 第二组（月份）的位置
# 输出：
# (3, 10)
# 3 7
# (8, 10)
```

未参与匹配的组调用 `start` / `end` / `span` 返回 `(-1, -1)`，不会抛异常——这是与 `group(n)` 返回 `None` 对应的设计：

```python
m = re.match(r"(\d+)(?:-(\d+))?", "42")
print(m.span(2))            # 第二组未参与匹配
print(m.group(2))           # None
# 输出：
# (-1, -1)
# None
```

**逐位捕获 vs 整体捕获的取舍**

当你需要拆分一个固定格式字段（如日期、时间、身份证号）时，每个片段用一个组是最直接的写法。但组多了，`group(1)`、`group(2)`、…… 的语义会变弱——读者得数括号才知道哪个是月份。这时应优先用命名组（见 2.5）。

### 2.4 组内量词与贪婪/非贪婪对捕获内容的影响

捕获组记录的是"该组这一轮实际匹配到的文本"。当组内带量词（如 `(\d+)`、`(\w*)`、`(\d{2,4})`）时，对于像 `+`、`*` 这样可以匹配多个字符的量词,**捕获组最终保存的是整个量词匹配完之后的完整子串,而不是"最后一次匹配的单个字符"**。

这是一个常被误解的点：有人以为 `(\d)+` 会只保存最后一个数字，其实 `(\d)+` 的捕获组保存的是整串数字。区别在于量词的位置——量词在组内还是组外，会影响捕获行为。

```python
import re

# 量词在组内：捕获整串
m1 = re.search(r"(\d+)", "abc12345def")
print(m1.group(1))   # 输出：12345

# 量词在组外：组反复匹配，只保留最后一次
m2 = re.search(r"(\d)+", "abc12345def")
print(m2.group(1))   # 输出：5  ← 不是 12345，是最后一次捕获的 "5"
# 输出：
# 12345
# 5
```

`(\d)+` 表示"一个组重复多次"，引擎每匹配一个数字就"刷新"该组的内容，循环结束后组里只剩最后一次匹配的 `5`。这是正则引擎的标准行为，Python 也遵守。

**贪婪 vs 非贪婪决定组的边界**

`(\d+)` 是贪婪的，会尽可能多匹配；`(\d+?)` 是非贪婪的，会尽可能少匹配。这直接改变捕获组的捕获内容：

```python
html = '<div class="box">content</div>'

# 贪婪：跨过中间的 > 一直吃到最后一个 <
greedy = re.search(r'<(.*)>', html)
print(greedy.group(1))
# 输出：div class="box">content</div

# 非贪婪：到第一个 > 就停
lazy = re.search(r'<(.*?)>', html)
print(lazy.group(1))
# 输出：div class="box"
```

**回溯会改变最终捕获内容**

当一个贪婪量词后面还有其他必须满足的模式时，引擎会让贪婪部分"回吐"字符，直到后续模式能匹配。回溯过程中捕获组的内容会被同步更新，最终保存的是回溯完成后的子串。

```python
# (\w+) 贪婪吃光所有单词字符，再回吐 3 个让 \w{3} 匹配
m = re.search(r"(\w+)\w{3}", "abcdefghij")
print(m.group(1))   # 输出：abcdefg  ← 回吐掉 hij
```

这一点在做"截取前 N 个之外的部分"类提取时要特别留意，捕获组的内容不是"匹配开始时的初值"，而是"整个正则匹配成功那一刻的终值"。

**分支中的捕获组：编号按左括号跨分支累加**

当 pattern 含 `|` 分支时，编号规则不变——仍按左括号在**整条 pattern 文本**中从左到右的顺序分配，而不是"哪个分支走了才分配"。结果就是：未走的那个分支里如果有捕获组，它的编号照样占着位，只是该组未参与匹配，值为 `None`。

```python
import re

# 两个分支各有捕获组，编号按 ( 出现顺序：第1组在左分支，第2组在右分支
m = re.search(r"(\d+)|([a-z]+)", "abc")
print(m.group(1))     # 左分支没走 → None
print(m.group(2))     # 右分支走了 → 'abc'
print(m.groups())     # (None, 'abc')
# 输出：
# None
# abc
# (None, 'abc')
```

这一点在写 `re.sub` 模板时要格外小心：如果模板里写 `\1`，而实际命中的是右分支，那么 `\1` 引用到的是 `None`，Python 会在替换时报错：

```python
try:
    re.sub(r"(\d+)|([a-z]+)", r"[\1]", "abc")
except re.error as e:
    print(e)
# 输出：unmatched group   ← 第 1 组未参与匹配，\1 无内容可引用
```

规避方法：要么确保所有分支中同号组都会被匹配到，要么用函数式替换在 `None` 时给默认值，要么把不同分支的结果合并到同一个组里（用非捕获组外包分支）。

### 2.5 命名捕获组：(?P<name>...)

当捕获组数量变多，纯数字编号会让代码很难维护——`group(3)` 到底是年、月还是日？得回去数括号。**命名捕获组**解决了这个问题。

语法：`(?P<name>pattern)`，其中 `name` 是组的名字（合法的 Python 标识符），`pattern` 是子模式。命名组同样自动获得一个数字编号（仍按左括号顺序），因此用编号也能访问，用名字也能访问。

```python
import re

m = re.search(r"(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})", "2024-03-15")
print(m.group("year"))     # 用名字取
print(m.group("month"))
print(m.group("day"))
print(m.group(1))          # 用编号取，等价于 group("year")
# 输出：
# 2024
# 03
# 15
# 2024
```

**命名约束与合法性**

`(?P<name>...)` 中的 `name` 必须符合 Python 标识符规则（字母/下划线开头，不含空格、无标点、不能以数字开头）。同一 pattern 内不允许出现重名组，否则 `re` 在编译时会抛 `re.error: redefinition of group name`。

```python
import re
try:
    re.compile(r"(?P<x>\d)(?P<x>\w)")   # 重名
except re.error as e:
    print(e)
# 输出：redefinition of group name 'x' as group 2; was group 1 at position ...
```

**为何命名组也保留数字编号**

Python 的命名组在内部仍然被编成一个序号（在所有捕获组——包括匿名组——的左括号序列中）。`(?P<name>...)` 等价于"给这个编号起个别名"。所以：

编译后的 `Pattern` 对象有一个只读属性 `groupindex`，是名字到编号的映射。可以用它在不实际匹配的情况下，确认命名组与编号的对应关系，便于调试复杂 pattern：

```python
m = re.search(r"(?P<key>\w+)=(?P<val>\d+)", "price=99")
print(m.group("key"), m.group("val"))
print(m.group(1), m.group(2))
print(m.groupdict())
p = re.compile(r"(?P<key>\w+)=(?P<val>\d+)")
print(p.groupindex)        # 名字 → 编号的只读映射
# 输出：
# price 99
# price 99
# {'key': 'price', 'val': '99'}
# {'key': 1, 'val': 2}
```

### 2.6 groupdict()：一次性取全部命名组

`Match.groupdict(default=None)` 返回一个 `dict`，**只包含命名组**（匿名组不会出现在这里）。键是组名，值是对应的捕获内容；未参与匹配的命名组值为 `None`，可被 `default` 替换。

```python
import re

m = re.search(r"(?P<host>\w+):(?P<port>\d+)(?P<path>/[\w/]*)?", "redis:6379")
print(m.groupdict())
# path 未参与匹配
print(m.groupdict(default=""))
# 输出：
# {'host': 'redis', 'port': '6379', 'path': None}
# {'host': 'redis', 'port': '6379', 'path': ''}
```

`groupdict()` 是命名组最大的工程价值所在：解析结果是一个自带语义键名的字典，下游代码可以直接 `info["host"]`、`info["port"]`，不必再 `info[0]`、`info[1]` 猜数字。

### 2.7 非捕获组：(?:...)

有时候我们用括号只是为了"把一段子模式当整体施加量词或做分支"，并不需要把它单独保存出来。例如想让 `http` 或 `https` 都能匹配，写 `(https?)` 会产生一个多余的捕获组，占用一个编号。**非捕获组 `(?:...)` 在保留"分组"语义的同时，不参与捕获、不占编号**。

```python
import re

# 用非捕获组把 http/https 包成整体，不产生捕获组
m = re.search(r"(?:https?)://(\S+)", "https://example.com/a/b")
print(m.group(1))        # 只有 1 个捕获组：域名+路径
print(m.groups())        # 只有 1 个元素
# 输出：
# example.com/a/b
# ('example.com/a/b',)
```

对比一下，如果写成 `(https?)://(\S+)`，就会有两个捕获组，第一个是你可能根本不关心的协议：

```python
m = re.search(r"(https?)://(\S+)", "https://example.com/a/b")
print(m.groups())
# 输出：('https', 'example.com/a/b')
```

**非捕获组对编号的影响**

非捕获组不进入捕获组编号序列。这意味着如果你的 pattern 是 `(?:A)(B)(?:C)(D)`，捕获组编号是：

- `(B)` → 第 1 组
- `(D)` → 第 2 组

```python
m = re.search(r"(?:x)(y)(?:z)(w)", "xyzw")
print(m.group(1), m.group(2))
# 输出：y w
```

**何时用非捕获组**

- 用括号仅为施加量词：`(?:abc)+` 表示 `abc` 整体重复。
- 用括号仅为分支分组：`(?:cat|dog|bird)` 匹配三选一，不想捕获具体是哪个。
- 你只关心整体匹配，不想让无意义的子模式污染 `groups()` 的结果序号。

一个常见的工程建议：**只要这个括号的内容你不会在后续 `group()` / `sub()` / 反向引用中用到，就一律用 `(?:...)`**。这样能保持捕获组编号紧凑、语义清晰。

### 2.8 嵌套组与组号编排

捕获组可以嵌套：一个 `(...)` 内部还可以再放 `(...)`。嵌套并不会创造特殊的编号维度，组号仍然**严格按左括号在整条 pattern 中从左到右出现的顺序**自增，外层和内层在同一个编号序列里排队。

```python
import re

# 外层组在前，内层组在后
m = re.search(r"((\d+)-(\w+))", "42-ok")
print(m.group(1))   # 外层：整体 "42-ok"
print(m.group(2))   # 内层第一个： "42"
print(m.group(3))   # 内层第二个： "ok"
# 输出：
# 42-ok
# 42
# ok
```

规律：**左括号先出现的先编号**。外层组的左括号总是先于它内部的任何左括号出现，所以外层组的编号一定比其内层组小。

再看一个稍复杂的例子，混用命名组：

```python
m = re.search(r"(?P<outer>(?P<inner>\w+)-(\d{3}))", "code-007")
print(m.group("outer"))    # 整体
print(m.group("inner"))    # 单词
print(m.group(3))          # 三位数字
print(m.groupdict())
# 输出：
# code-007
# code
# 007
# {'outer': 'code-007', 'inner': 'code'}
```

`groupdict()` 只包含命名组（`outer`、`inner`），匿名组 `(\d{3})` 虽然占编号 3，但不会出现在 `groupdict()` 中。

### 2.9 反向引用：在 pattern 内引用前组

捕获组不仅可以"事后取"，还能在**同一条 pattern 内**被引用——这叫**反向引用（backreference）**。语法是在 pattern 中写 `\1`、`\2`……，数字指向前面已经定义的捕获组编号。引擎在遇到 `\1` 时，会回查第 1 组到目前为止捕获的内容，要求此处必须出现一模一样的文本。

**经典场景：匹配成对引号**

```python
import re

# 要求左右引号必须一致
for s in ['"hello"', "'hi'", '"oops\'']:
    m = re.search(r"""(["'])(\w+)\1""", s)
    print(s, "->", m.group(2) if m else None)
# 输出：
# "hello" -> hello
# 'hi' -> hi
# "oops' -> None   ← 左右引号不一致，匹配失败
```

这里 `(["'])` 是第 1 组，捕获了开头的引号字符；`\1` 要求结尾必须出现同样的引号。如果开头是 `"` 结尾是 `'`，`\1` 匹配失败，整个正则失败。

**经典场景：重复单词检测**

```python
# 检测文本里连续出现的重复单词
m = re.search(r"\b(\w+)\s+\1\b", "the table is is broken")
print(m.group(0))
print(m.group(1))
# 输出：
# is is
# is
```

`(\w+)` 捕获第一个单词，`\1` 要求紧接着再出现同一个单词，从而定位到重复词。

**命名组的反向引用：(?P=name)**

对命名组，反向引用既可以用编号 `\1`，也可以用专门的命名形式 `(?P=name)`：

```python
m = re.search(r"(?P<quote>['\"])\w+(?P=quote)", '"sym"')
print(m.group("quote"))
# 输出："
```

**反向引用引用的是"已捕获的文本"，不是"模式"**

`\1` 不是"重复第 1 组的模式"，而是"重复第 1 组已经匹配到的文本"。这是反向引用与"重复子模式"的本质区别：

```python
# 反向引用：要求内容一致
re.search(r"(\d)\1", "33")   # 匹配成功：第一组是 3，\1 要求再来一个 3
re.search(r"(\d)\1", "36")   # 匹配失败：第一组是 3，\1 处需要一个 3，但这里是 6
```

如果只是想"重复模式"，应该直接把那份模式再写一遍或用非捕获组括起来量词，而不要用反向引用。

**反向引用只能引用"已经出现的"组**

正则引擎是按顺序扫描 pattern 的，`\N` 出现时，第 N 组必须已经被定义（左括号在 `\N` 之前出现过）。引用后面还没定义的组在 Python 中会抛错或按转义处理，不会得到预期效果。

### 2.10 re.sub 中的反向引用：\1 与 \g<name>

捕获组在替换文本中同样能被引用，这是 `re.sub` / `re.subn` 非常强大的能力。语法有两种：

- **`\1`、`\2`……**：在 replacement 字符串里引用第 N 个捕获组。注意写法上 `\g<1>` 更稳妥（见下）。
- **`\g<name>`**：用命名组名字引用，适合复杂替换模板。

```python
import re

# 交换 key 和 value 的位置
line = "name=Alice"
swapped = re.sub(r"(\w+)=(\w+)", r"\2=\1", line)
print(swapped)
# 输出：Alice=name

# 用命名组引用
result = re.sub(r"(?P<k>\w+):(?P<v>\d+)", r"\g<v>- port of \g<k>", "redis:6379")
print(result)
# 输出：6379- port of redis
```

**为什么推荐 \g<1> 而不是 \1**

当用 `\1` 这种写法且后面紧跟数字时，会产生歧义：`r"\12"` 到底是"第 12 组"还是"第 1 组 + 字符 2"？Python 规定 `\12` 表示第 12 组（最多两位）。但你只有 2 个组时这会报错。用 `\g<1>` 或显式写 `\g<1>` 形式可以杜绝歧义：

```python
# 想输出 "group1 + 字符 0"
re.sub(r"(\d)", r"\g<1>0", "5")
# 输出：50

# \10 会被解释为"第 10 组"，如果不存在则报错
# re.sub(r"(\d)", r"\10", "5")  # re.error: invalid group reference 10
```

所以在替换模板里，**只要组号后面还有数字字符，一律用 `\g<N>` 或 `\g<name>`**。

**用函数作为 replacement**

`re.sub` 的 `repl` 参数也可以是一个函数，接收 `Match` 对象、返回替换字符串。这时捕获组通过 `m.group(...)` 取，比模板字符串更灵活：

```python
# 把每个数字扩大 10 倍后替换回去
result = re.sub(r"\d+", lambda m: str(int(m.group(0)) * 10), "a1 b22 c333")
print(result)
# 输出：a10 b220 c3330
```

函数式替换在需要做进一步转换（查表、计算、校验）时几乎总是比模板字符串更可控。

**re.subn：同时返回替换次数**

`re.subn` 与 `re.sub` 用法一致，但返回 `(新字符串, 替换次数)` 元组：

```python
new, n = re.subn(r"(\w+)=(\w+)", r"\2=\1", "a=1;b=2;c=3")
print(new, n)
# 输出：1=a;2=b;3=c 3
```

### 2.11 findall 与捕获组的交互（承接 07 篇）

`re.findall` 的返回值有一个"坑",但它其实是捕获组语义的必然结果,这里和 07 篇(查找函数)呼应一下:**当 pattern 里没有任何捕获组时，findall 返回字符串列表；当 pattern 里有捕获组时，findall 返回"元组列表"，每个元组对应一次匹配的 groups()**。

```python
import re

# 无捕获组：返回字符串列表
print(re.findall(r"\d+", "a1 b22 c333"))
# 输出：['1', '22', '333']

# 有 1 个捕获组：返回单元素元组列表
print(re.findall(r"(\d+)", "a1 b22 c333"))
# 输出：[('1',), ('22',), ('333',)]

# 有 2 个捕获组：返回二元元组列表
print(re.findall(r"(\w+)=(\d+)", "a=1;b=22"))
# 输出：[('a', '1'), ('b', '22')]
```

注意"有 1 个组"时返回的依然是**元组列表**，元素是 `('1',)` 而不是 `'1'`——这是新人最容易踩的点。如果想保持返回字符串列表，又不想要组，应直接去掉括号或用非捕获组 `(?:...)`：

```python
# 想要纯字符串列表，但又必须用括号做分组 → 用非捕获组
print(re.findall(r"(?:\d+)", "a1 b22"))
# 输出：['1', '22']
```

**finditer：更可控的替代**

当你既要遍历所有匹配，又想用 `Match` 对象的完整 API（`group(0)`、`groupdict()`、`span()` 等)，`re.finditer` 返回的是 `Match` 对象的迭代器，比 `findall` 更直观，不会受"有没有组"的规则干扰：

```python
for m in re.finditer(r"(?P<k>\w+)=(?P<v>\d+)", "a=1;b=22"):
    print(m.groupdict())
# 输出：
# {'k': 'a', 'v': '1'}
# {'k': 'b', 'v': '22'}
```

**findall 返回元组列表的一致性原理**

`findall` 本质上是"对所有匹配逐一调用 `groups()` 并收集结果"。当 pattern 无组时，`groups()` 是空元组，`findall` 就退化成收集 `group(0)`；当有组时，它收集的就是每个匹配的 `groups()` 元组。这条规则统一覆盖了所有情况。

### 2.12 split 与捕获组的交互

`re.split` 也有一个与捕获组相关的特性：**如果分隔符 pattern 里包含捕获组，那么"分隔符中各组匹配到的文本"会一并出现在结果列表中，穿插在被切开的各段之间**。

```python
import re

# 不带捕获组：只返回被切开的段
print(re.split(r"\s*,\s*", "a, b , c ,  d"))
# 输出：['a', 'b', 'c', 'd']

# 带捕获组：分隔符里匹配到的部分会被插入到结果中
print(re.split(r"\s*(,)\s*", "a, b , c ,  d"))
# 输出：['a', ',', 'b', ',', 'c', ',', 'd']
```

这个特性在你"既想要分隔后的字段，又想保留分隔符"时很有用。比如解析 CSV 行保留逗号位置，或解析带分隔符的 token 流。如果不希望分隔符出现在结果里，就用非捕获组 `(?:...)`。

**成对标签与反向引用的边界**

用反向引用匹配成对 HTML/XML 风格标签时，记住正则无法真正处理嵌套结构——`<(\w+)></\1>` 只能匹配空标签。需要匹配有内容的成对标签时，通常配合非贪婪 `.*?`：

```python
import re

html = '<b>粗体</b> <i>斜体</i> <b>又粗</b>'
for m in re.finditer(r"<(\w+)>(.*?)</\1>", html):
    print(m.group(1), "->", m.group(2))
# 输出：
# b -> 粗体
# i -> 斜体
# b -> 又粗
```

但一旦出现嵌套（如 `<div><b>x</b></div>`），这种单层正则会因为 `.*?` 无法正确配对而失配或错配。处理嵌套结构应使用专门的 HTML/XML 解析器，而不是正则——这是"正则不适合解析 HTML"这条经验的具体来源。

## 3. 最佳实践

**能命名就不要裸编号**

只要捕获组超过 2 个，或其中一个会被后续代码反复引用，就应优先用 `(?P<name>...)` + `group("name")` / `groupdict()`。命名组让代码自解释，半年后回来也不用数括号。对应的不推荐写法：

```python
# 不推荐：第 2 个是 port 还是 host？需要回去数括号
m = re.match(r"(\w+):(\d+):(\w+)", s)
host, port, user = m.group(1), m.group(2), m.group(3)

# 推荐：语义直接写在名字里
m = re.match(r"(?P<host>\w+):(?P<port>\d+):(?P<user>\w+)", s)
info = m.groupdict()
```

**不关心的括号一律用非捕获组**

任何"只是为了施加量词、分支、或优先级"而加的括号，只要不会被 `group()` / `sub` / 反向引用用到，一律写成 `(?:...)`。这能让 `groups()` 的结果只包含真正关心的字段，编号紧凑不跳跃。

```python
# 不推荐：协议这个括号语义上根本不关心，却占了 group(1)
m = re.match(r"(https?)://(\w+)(/.*)?", url)
path = m.group(3)   # 跳过协议、跳过域名才到 path

# 推荐：协议用非捕获组，path 直接是 group(2)
m = re.match(r"(?:https?)://(\w+)(/.*)?", url)
host, path = m.group(1), m.group(2)
```

**re.sub 里优先用 \g<name> 而不是 \1**

`re.sub` 替换模板里，只要编号后面可能紧跟数字字符，就一律用 `\g<N>` 或 `\g<name>`，避免 `\12` 被误读为"第 12 组"。命名组引用 `\g<name>` 还自带语义，是大型替换模板的首选。

**用 finditer 替代 findall 处理多组解析**

`findall` 在"有组返回元组列表、无组返回字符串列表"这条规则下，输出类型会随 pattern 变化，不利于下游代码稳定。需要解析结构化数据时，优先用 `re.finditer` 拿 `Match` 对象，再显式调 `group()` / `groupdict()`，类型更可控、字段更清晰。

**预编译大段正则**

同一条复杂正则会在循环里反复使用时，用 `re.compile` 预编译一次，既避免重复解析 pattern，也便于在编译阶段就暴露语法/命名错误。预编译后的 `Pattern` 对象的 `match`/`search`/`findall`/`sub` 等方法与模块级函数一一对应。

```python
LOG_LINE = re.compile(
    r"(?P<time>\d{2}:\d{2}:\d{2})\s+(?P<level>\w+)\s+(?P<msg>.*)"
)
for line in open("app.log"):
    if m := LOG_LINE.search(line):
        print(m.group("level"), m.group("msg"))
```

**反向引用慎用于大文本**

带反向引用的正则会阻止某些优化（引擎无法用简单字符类预扫），在大文本上可能明显变慢。如果只是为了"左右成对"这类校验，能改成前置字符类或两次独立匹配时，往往更快。

**警惕贪婪量词吃掉分隔符**

解析形如 `A;B;C` 的数据时，`(.+);` 之类贪婪写法可能把后面的分隔符一并吞掉，导致 `group(1)` 内容超出预期。改用非贪婪 `(.+?);` 或更精确的"非分隚符类"`([^;]+);` 更稳：

```python
# 不推荐
m = re.match(r"(.+);(.+);(.+)", "a;b;c")     # group(1) 可能是 "a;b"

# 推荐
m = re.match(r"([^;]+);([^;]+);([^;]+)", "a;b;c")   # 各组干净
```

**组未参与匹配时记得判空**

在 `|` 分支或 `?` 可选组中，某些捕获组可能未参与匹配，`group(n)` 返回 `None`。直接当字符串用会抛 `AttributeError`。养成"先判断 None 再用"的习惯，或用 `groups(default="")` 给默认值。

## 4. 原理

### 4.1 捕获组在正则状态机中的子匹配缓存

正则引擎在匹配一条 pattern 时，需要在内部维护一组"组状态"。Python 的 `re` 使用 CPython 内部的 `sre`（现在称 `_sre` / `re._compile`）作为引擎，核心是一个基于字节码的回溯式 NFA 回溯匹配机。

当编译阶段处理 pattern 时，`re` 把每对 `(...)` 翻译成一组字节码指令：`MARK 0`（在该组左括号处打一个开始标记）、`...子模式...`、`MARK 1`（在右括号处打一个结束标记）。这里的 `0`、`1` 实际是"组内两个边界点的索引"——第 N 个捕获组对应两个 mark 点，一个记录它开始的位置、一个记录它结束的位置。捕获组的"内容"，就是主串中从开始 mark 到结束 mark 的那段子串。

匹配过程中引擎维护一个"标记表（mark stack/space)"：每遇到 `MARK k` 指令，就把"当前扫描到的字符串位置"写进标记表的第 k 槽位。匹配成功后，第 N 组的开始/结束位置即可从标记表里取出来，再用 `string[start:end]` 切出捕获内容。`group(0)` 是一种特殊情形，它取的是整体匹配的开始与结束位置，与"编号 0 组"的 mark 点对应。

这就是为什么捕获组的提取几乎不会带来额外开销——边界位置在匹配过程中已被记录，`group(n)` 只是一次切片。

### 4.2 组号按左括号出现顺序自增分配

捕获组的编号在**编译期**就完全确定了，与具体待匹配文本无关。`re` 的编译器扫描 pattern 字节流时，每遇到一个"会捕获的左括号"，就给它分配下一个可用的组号。关键在于"会捕获的左括号"：`(?P<name>`、`(` 都会计数；而 `(?:`、`(?=`、`(?!`、`(?<=`、`(?<!` 等不会。

这解释了前文反复出现的规则：**编号严格按左括号从左到右出现顺序自增，非捕获组不占号，外层组的左括号先于内层组的左括号出现所以编号更小**。命名组的名字在编译时被绑定到一个序号上，存进 pattern 的 `groupindex` 属性：

```python
import re
p = re.compile(r"(?P<year>\d{4})-(\d{2})-(?P<day>\d{2})")
print(p.groupindex)
# 输出：{'year': 1, 'day': 3}
```

`groupindex` 是一个只读映射，把命名组的名字映射到它分到的整数编号。匿名组不在里面。反过来，引擎内部始终用数字编号定位组，`group("year")` 等价于"查 groupindex 得到 1，再调 group(1)"。

### 4.3 命名组把名字映射到组号

命名组 `(?P<name>pattern)` 的实现可以理解为"带别名的捕获组"。编译器在分配编号时，把它当作普通捕获组编一个号，再把 `name → 编号` 写进 `groupindex`。因此：

- 对同一命名组，`group("name")` 与 `group(编号)` 走的是同一段 mark 表查找逻辑，返回值恒等。
- `groupdict()` 的实现是遍历 `groupindex`，对每个 `(name, idx)` 调用 `group(idx)`，组装成字典。
- pattern 内的反向引用 `(?P=name)`，在编译时被翻译成等价于 `\编号` 的字节码，也就是"回查第 idx 组已捕获的内容"。

这也是命名组不能重名的原因：`groupindex` 是一个名字到编号的单射映射，同名会让编译器无法决定该名字指向哪个编号，于是在编译期直接抛 `re.error`。

### 4.4 非捕获组不进结果数组

非捕获组 `(?:...)` 在编译时不会被分配组号，也不产生对应的 `MARK` 槽位——它仅仅控制子模式的结合优先级和量词作用范围。引擎执行时，子模式仍然被完整地跑一遍（参与回溯、影响整体匹配），但因为没有 mark 点，它的边界不会被记录，`groups()` 里自然没有它的位置。

从字节码层面看，`(?:` 几乎可以理解成"只是一对用于分组的语法括号，不发射 mark 指令"。这就是它"只分组不捕获、不占号"的物理来源。

### 4.5 反向引用在匹配时回查已捕获内容

反向引用 `\1` 或 `(?P=name)` 在编译时被翻译成一条专门的字节码指令（在 `sre` 中是 `REF` 类指令，或等价的 `GROUPREF`）。引擎执行到这条指令时，做这件事：

1. 查标记表，取出第 N 组当前记录的开始/结束位置，切出子串 `captured`。
2. 把当前扫描位置与 `captured` 逐字符比对，长度必须相等、字符必须完全相同，否则该分支匹配失败，触发回溯。
3. 比对成功则前进扫描位置 `len(captured)` 步，继续执行后续指令。

注意"当前记录"四个字。如果第 N 组带量词或处于分支中，反向引用读到的是**到目前为止最近一次成功捕获**的内容。在 `(\d)+\1` 这种写法中，第 1 组在量词驱动下反复刷新，最后保存的是"最后一次匹配的那个数字"。当模式走到 `\1` 时，它要求下一个字符必须等于那个数字——这种语义直接来自"回查标记表当前值"的实现方式。

反向引用不能引用还未定义的组（编号大于当前已分配的最大组号），编译器会报 `re.error: bad group number` 或将其当作八进制转义处理，依上下文而定。这也是"反向引用只能向后看"的来源。

### 4.6 re.sub / findall 中引用捕获组的实现

`re.sub` 的替换阶段与匹配阶段是分离的：

1. 先用 pattern 像普通匹配一样扫描字符串，每找到一个匹配，得到一个 `Match` 对象（其标记表已填充完毕）。
2. 对 replacement 字符串解析其中的 `\N` / `\g<N>` / `\g<name>` 标记。每遇到一个引用，就查 `Match` 的标记表，取出对应组的捕获内容拼到结果里。
3. 用拼好的替换串替换原文中本次匹配覆盖的区间，继续向后扫描。

当 `repl` 是函数时，流程更简单：把每个 `Match` 对象传给函数，函数返回什么就用什么替换。这也解释了为什么函数式替换拿到的 `Match` 已经是完整对象，可以调用一切 `group()` 方法。

`re.findall` 的实现本质上等价于：

```python
def findall_equivalent(pattern, string):
    result = []
    for m in pattern.finditer(string):
        groups = m.groups()
        if not groups:
            result.append(m.group(0))      # 无组 → 字符串
        else:
            result.append(groups)          # 有组 → 元组
    return result
```

- pattern 无捕获组时，`m.groups()` 返回空元组 `()`，`findall` 退化成收集 `m.group(0)`，因此结果是字符串列表。
- pattern 有捕获组时，每个匹配的 `groups()` 都是元组，`findall` 收集成"元组列表"。
- 当只有一个组时，结果元素是单元素元组 `('1',)`，这也是 `groups()` 的直接结果。

这条统一规则覆盖了所有情形：**`findall` 返回的每个元素，就是对应那次匹配的 `groups()`（无组时用 `group(0)` 代替）**。理解了这一点，前文"有无捕获组导致返回类型变化"的现象就是必然的了。

### 4.7 贪婪/非贪婪回溯对捕获内容的传导

第 2.4 节提到捕获组保存的是"回溯完成后"的内容。其原理是：标记表在一次匹配过程中会被多次写入——每当引擎进入某组的开始或结束位置，就刷新对应槽位。在回溯发生时，引擎会把扫描位置退回，并恢复相关的标记槽位。因此，当整条 pattern 最终匹配成功那一瞬间，标记表里记录的就是"成功路径"上的组边界，而不是中途某次试探的边界。

对于 `(\w+)\w{3}` 这种写法，引擎先让 `(\w+)` 贪婪吃光所有字符，记下结束位置在串尾；随后 `\w{3}` 无法在末尾匹配，引擎回溯，把第 1 组的结束位置往回挪 3 格，再试 `\w{3}`。回溯成功后，第 1 组的结束位置就是倒数第 4 个字符处，于是 `group(1)` 返回去掉末尾 3 个字符后的前缀。捕获内容的"最终值"是回溯稳定后的状态，不是贪婪初值。

这个机制的直接推论是：**任何能影响回溯的因素（后续模式、量词类型、锚点）都会间接影响捕获组的内容**。写正则时不能只看捕获组自身的子模式，必须把它放在整条 pattern 的回溯语境里理解。

## 5. 总结

### 5.1 本文内容要点

- 捕获组用 `(...)` 创建，按左括号出现顺序自增编号，`group(0)` 是整体匹配、不占编号，`group(1..N)` 才是真正的捕获组。
- `Match.group(n)` 取单个组，可一次传多个编号返回元组；`Match.groups()` 返回全部组的元组（不含 `group(0)`），`default` 参数可替换未参与匹配组的 `None`。
- 命名组 `(?P<name>...)` 仍占数字编号，额外绑定名字到 `groupindex`；`group("name")` 与 `group(编号)` 等价；`groupdict()` 一次性返回所有命名组的字典。
- 非捕获组 `(?:...)` 只分组不捕获、不占编号，适合"仅为施加量词或分支"的括号，能保持 `groups()` 紧凑。
- 嵌套组的编号仍按左括号顺序排，外层先于内层。
- 反向引用 `\1` / `(?P=name)` 在 pattern 内回查已捕获的**文本**（不是模式），用于成对引号、重复单词等校验。
- `re.sub` 替换模板用 `\1` / `\g<N>` / `\g<name>` 引用捕获组，推荐 `\g<...>` 避免数字歧义；`repl` 也可以是函数，拿 `Match` 对象自行处理。
- `re.findall` 的返回类型随有无捕获组变化：无组返回字符串列表，有组返回"每次匹配 `groups()` 的元组列表"；改用 `re.finditer` 可规避这一规则。
- `re.split` 中分隔符内的捕获组会出现在结果列表中，穿插于切段之间。
- 贪婪/非贪婪与回溯会传导到捕获组内容；组外量词（`(\d)+`）只保留最后一次匹配。

### 5.2 读完本文你应能掌握

- 说明 `group(0)` / `group(n)` / `groups()` / `groupdict()` 各自返回什么，并能正确选用。
- 写出带 3 个以上捕获组的 pattern，准确预测每个组的编号，正确区分匿名组、命名组、非捕获组。
- 用命名组 + `groupdict()` 解析 `key=value`、日期、URL 等结构化字符串，得到带语义键的字典。
- 用 `(?:...)` 主动控制哪些括号参与捕获，让 `groups()` 结果干净紧凑。
- 用反向引用 `\1` / `(?P=name)` 匹配成对引号、成对标签、重复单词，并解释"引用文本而非模式"的语义。
- 在 `re.sub` 中用 `\g<name>` / 函数式替换完成模板转换，避免 `\1` 后跟数字的歧义错误。
- 解释 `findall` 为何在有组时返回元组列表，并能在"想要字符串列表"时改用 `finditer` 或非捕获组修正行为。
- 说出组号按左括号顺序分配、非捕获组不进 mark 表、反向引用回查标记表、回溯刷新捕获内容等原理要点。
